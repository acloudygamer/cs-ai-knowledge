# Node.js 与事件循环

## 核心定义：一个运行时栈的完整解剖

Node.js（2009 年由 Ryan Dahl 发布）把 JavaScript 从浏览器搬进服务器。它的构成是三层的组装，恰好是本部分前篇内容的交汇点：

```text
你的 JS 代码（全是回调）
  │
  ▼  V8：负责"算"——JS 编译与执行（03 的 JIT：Ignition 解释 + TurboFan 优化）
  │
  ▼  libuv：负责"等"——事件循环 + 线程池，
     对 epoll（Linux）/ kqueue（BSD）/ IOCP（Windows）的跨平台封装
  │
  ▼  OS 内核：网络 I/O 的真异步由 epoll 提供
     （《系统软件层》06 篇：事件通知而非轮询）
```

**它回应的约束**：典型服务器负载是 I/O 密集——请求的大部分时间在等数据库、等下游 API、等磁盘。为每个连接配一个线程（03 篇的 C10K 困境）意味着上万个线程多数时间在睡眠，栈内存和调度开销白烧。Node.js 把 OS 层的 epoll 答案（一个线程等一万个连接）直接提升为语言级的编程模型：**单线程跑事件循环，所有等待外包给内核，数据到了才叫你**。

## 事件循环：阶段与纪律

libuv 的事件循环每转一圈按序经过几个阶段，你的回调各归其一：

```text
timers          —— setTimeout/setInterval 到点的回调
  ▼
pending         —— 上一轮延后的系统回调（如 TCP 错误）
  ▼
poll（核心）     —— 等 I/O 事件（在这里睡眠等 epoll 通知），
                   执行到达的 I/O 回调
  ▼
check           —— setImmediate 的回调
  ▼
close           —— socket 关闭等收尾回调
  ▼ 转下一圈
```

两条容易踩的规矩：

- **微任务（microtask）不占循环阶段**：`Promise.then` 和 `process.nextTick` 的队列在**每个回调之间**就地清空，优先级高于循环推进。`async/await` 是 Promise 之上的语法糖：写法像同步，底下就是这个队列上的微任务。在微任务里无限递归注册微任务，事件循环会被永远饿死——这与阻塞循环一样致命。
- **poll 阶段是唯一的等待点**：所有"异步"的奥秘就是循环转到 poll 时调用 epoll 睡眠；事件来了被唤醒，回调在对应阶段执行。

## 线程池：没有真异步的地方

epoll 只管网络与管道。有两类活 OS 不提供异步接口，libuv 用**线程池**（默认 4 线程，`UV_THREADPOOL_SIZE` 可调）模拟异步：

- **文件 I/O**：Linux 上文件读写长期没有可用的真异步机制（io_uring 是 2019 年才出现的新答案，《系统软件层》06 篇），libuv 让线程池里的线程去做阻塞读，完成后把结果塞回事件循环——对 JS 主线程"假装"是异步。
- **DNS 解析与 crypto**：`getaddrinfo` 是阻塞的 libc 调用，PBKDF2/scrypt 这类计算密集加密同理。

看清这一点就看清了 Node 的"单线程"传说：**JS 主线程只有一个，但底下有四个默认线程在扛阻塞活**。所谓单线程，单的是"你的代码只在一条线程上跑"——这带来一个真实红利：JS 层没有共享内存并发，03 篇的锁与竞态在应用代码里不存在。

## 多核：一个进程一核，那就多开几个进程

JS 主线程只用得到一个核——32 核的服务器怎么办？答案是**多进程**：`cluster` 模块 fork 出 N 个 Node 进程，共享同一监听端口，连接在多个 accept 者之间分发（03 篇进程机制的直接复用）；更现代的做法是容器里跑 N 个实例、由前面的反向代理（Nginx、云 LB）负载均衡。Node 服务的水平扩展单元是**进程**而非线程——这与《软件工程概念》05 的容器编排天然咬合：无共享、无状态的服务实例，正是最容易编排的形状。

## Stream 与背压：数据流的形状

回调解决"等"，但数据本身怎么流？读一个 10GB 文件不能全载入内存——Node 的答案是 **Stream**：数据按块（chunk）流动，每块触发一次回调，内存占用与文件大小解耦。`fs.createReadStream`、socket、stdin 全是流。

流配对时有一个真实的力学问题：生产者快、消费者慢（读磁盘 700 MB/s、写网络 200 MB/s），缓冲区会无限膨胀。**背压（Backpressure）**是反向施压的机制：消费者的缓冲越过水位线就反过来暂停生产者（`write()` 返回 false → 停止再读），排空后恢复；`pipe()` 把这套压力传导自动化。背压不是 Node 专利——它是所有流式系统的通用约束，TCP 的滑动窗口就是同一思想在传输层的版本（《计算机网络》03）。

## 形状的边界：什么时候不能用 Node

同一形状决定它的死穴：**事件循环停摆 = 所有连接饿死**。一个 `JSON.parse(100MB)`、一段 while 重计算，把唯一的 JS 线程占住，一万个连接一起超时。出路按约束分流：

- 计算密集 → `worker_threads`（真线程，靠消息通信，不共享内存）或干脆交给别的服务；
- 大量文件/加密 → 调大线程池，或迁往 io_uring/专用服务；
- 回调内抛异常 → 进程级崩溃风险（未捕获异常直接拍死事件循环），需 `unhandledRejection` 兜底与进程守护。

## 收束：为什么这个形状赢了

把 Node.js 拆开看，没有一条原理是它发明的：JIT 来自 JVM 一脉（03），事件循环是 epoll 的软件包装（《系统软件层》06），线程池外包阻塞是操作系统课的老手法。它赢在三件事的咬合：V8 把 JS 推到可用的速度、libuv 把万级连接的等待压进一个线程、JS 社区让前后端同语言。约束（I/O 密集 + 高并发连接 + 快速迭代）给了形状，形状成就了生态——这正是本部分反复演示的推导方式：先看约束，机制的形状是自然推论。
