# 编译型与解释型语言

## 解决什么问题

将人类可读的高级语言翻译成机器可执行的指令。理解编译器有助于阅读汇编代码、优化程序性能、定位奇怪的编译器行为。

## 核心概念

- 编译器将源代码翻译成目标代码（机器码或字节码）
- 编译流程：词法分析→语法分析→语义分析→优化→代码生成
- 编译器生成特定CPU指令集（x86/ARM/RISC-V）的机器码
- 生成平台可执行文件格式（Linux: ELF, Windows: PE, macOS: Mach-O）
- 现代编译器通过中间表示(IR)解耦前端和后端

## 怎么用

### GCC 编译流程

```bash
# 四步流程：预处理 → 编译 → 汇编 → 链接
gcc -E source.c -o source.i  # 预处理：展开宏、包含头文件
gcc -S source.i -o source.s  # 编译：生成汇编代码
gcc -c source.s -o source.o  # 汇编：生成机器码目标文件
gcc source.o -o program       # 链接：合并目标文件，生成可执行文件

# 一步到位（常用）
gcc -O2 source.c -o program   # -O2 二级优化，-O3 更激进优化，-Os 大小优化
```

### 编译阶段详解

```c
// source.c 示例
#define MAX 100

int square(int x) {
    return x * x;
}

int main() {
    int result = square(MAX);
    return result - MAX;
}
```

**预处理后** (`source.i`)：宏被展开，`#include` 被插入
**汇编后** (`source.s`)：生成汇编指令，对应 `int square(int x) { return x * x; }` 的汇编为 `imull %edi, %edi; movl %edi, -4(%rbp)`
**目标文件** (`source.o`)：机器码 + 符号表 + 重定位表（未链接的地址）

## LLVM 架构（现代编译器标杆）

```
源代码 → [Clang 前端] → LLVM IR （中间表示）
                                ↓
              ┌─────────────────┼─────────────────┐
              ▼                 ▼                  ▼
        [PASS 1]           [PASS 2]          [PASS N]    ← 优化 passes
              └─────────────────┼─────────────────┘
                                ▼
                    [X86/ARM 后端] → 机器码
```

**LLVM IR** 是编译器的"通用语言"：
- 无限寄存器
- 静态单赋值（SSA）形式
- 平台无关

```bash
# 查看 LLVM IR（通过 Clang）
clang -S -emit-llvm source.c -o source.ll
cat source.ll
```

## 编译器种类

| 编译器 | 特点 | 适用场景 |
|--------|------|----------|
| GCC | 开源，支持多语言多平台 | Linux 默认 |
| Clang/LLVM | 模块化设计，诊断信息友好 | macOS Xcode |
| MSVC | Windows 原生，优化好 | Visual Studio |
| javac | Java 专用 | Java 开发 |
| rustc | Rust 官方编译器，编译时检查内存所有权（ownership） | Rust 开发 |

## 静态链接 vs 动态链接

```bash
# 静态链接：库代码直接打包进可执行文件
gcc -static source.c -o program    # 文件大（MB级），但部署简单

# 动态链接：运行时加载共享库
gcc source.c -o program           # 文件小（KB级），共享库可更新

# 查看可执行文件的动态依赖
ldd program                       # Linux
otool -L program                  # macOS
dumpbin /dependents program       # Windows/MSVC
# 跨平台替代：objdump -p program | grep DLL
```

**动态库在 Linux 上是 `.so` 文件，Windows 上是 `.dll`，macOS 上是 `.dylib`。**

**动态链接优缺点**：
- 优点：可执行文件小、共享库更新不需要重新编译、节省内存（多个进程共享）
- 缺点：运行时依赖库、可能遇到" DLL hell "、部署复杂

## 交叉编译

在一台机器上编译另一平台的可执行文件：

```bash
# ARM 交叉编译（从 x86 编译 ARM 程序）
aarch64-linux-gnu-gcc source.c -o program

# macOS 上交叉编译 Linux 二进制
x86_64-linux-gnu-gcc source.c -o program

# Windows 上交叉编译 Linux
x86_64-linux-gnu-gcc source.c -o program
```

**为什么需要交叉编译**：
- 嵌入式设备（ARM/MIPS）资源有限，无法本地编译
- 开发者在强大机器上编译，部署到多个目标平台
- 加速编译（编译服务器远比目标设备快）

## 编译优化等级

| 选项 | 优化内容 | 编译时间 | 适用场景 |
|------|----------|----------|----------|
| `-O0` | 无优化 | 最快 | 调试 |
| `-O1` | 基本优化，减小代码大小 | 快 | 平衡 |
| `-O2` | 激进优化，不牺牲调试 | 中等 | 生产默认 |
| `-O3` | +向量化、函数内联 | 慢 | 性能关键 |
| `-Os` | 优先减小大小 | 中等 | 嵌入式 |
| `-Ofast` | +浮点优化（违反标准） | 慢 | 科学计算 |

# 解释器

## 解决什么问题

直接执行源代码，无需预先编译。解释器逐行读取代码并立即执行，适合快速开发和交互式环境。

## 核心概念

- 解释器逐行读取源代码，直接执行对应操作
- 执行时依赖运行时提供环境（内存管理、库函数）
- 大多数解释器先将源码解析成抽象语法树(AST)再执行
- 解释执行速度慢于编译执行，但启动快、调试方便
- 某些语言混合编译和解释（如Python先编译成字节码再由VM执行）

## 怎么用

```bash
# Python 解释器执行脚本
python script.py

# 查看 Python 字节码
python -c "import dis; dis.dis(lambda x: x + 1)"
```

## 解释执行 vs 编译执行

| 特性 | 解释执行 | 编译执行 |
|------|----------|----------|
| 执行速度 | 慢（每次都要翻译） | 快 |
| 启动速度 | 快（不需要编译） | 慢 |
| 跨平台 | 源代码跨平台（如有解释器） | 需要针对平台编译 |
| 调试 | 容易（可直接修改） | 需要重新编译 |

## Python 解释器

Python 是典型的解释型语言，但有多种实现：

```bash
# CPython：官方实现，C语言编写
python script.py

# PyPy：JIT 编译，速度更快
pypy script.py

# Jython：运行在 JVM 上，可与 Java 互操作
jython script.py

# IronPython：运行在 .NET CLR 上
ironpython script.py

# 查看 Python 解释器路径
which python
python --version

# 查看当前 Python 实现
python -c "import sys; print(sys.implementation.name)"
```

### CPython 内部执行流程

```
.py 源代码 → Parser（解析）→ AST（抽象语法树）
                               ↓
                    Compiler（编译）→ .pyc 字节码
                                           ↓
                              Python Virtual Machine 执行字节码
```

### 查看 Python 字节码

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
# 输出：
#   1           0 LOAD_FAST                0 (a)
#               2 LOAD_FAST                1 (b)
#               4 BINARY_ADD
#               6 RETURN_VALUE
```

## REPL

**Read-Eval-Print Loop**：交互式解释器环境，循环读取用户输入、求值并打印结果

```python
# Python REPL
$ python
>>> 1 + 1
2
>>> for i in range(3):
...     print(i)
...
0
1
2
>>> def factorial(n):
...     return 1 if n <= 1 else n * factorial(n - 1)
...
>>> factorial(5)
120
```

```javascript
// Node.js REPL
$ node
> 1 + 1
2
> const fs = require('fs');
undefined
> .help
.break    .clear    .exit    .help    .load    .save    .editor
```

```bash
# 常用 REPL 工具
python       # Python
node         # JavaScript/Node.js
python -i    # 交互模式运行脚本后保持 REPL
bpython      # 增强版 Python REPL（语法高亮、自动补全）
ptpython     # 另一个增强版 REPL
```

## 字节码解释

有些语言（如 Python、Java）将源代码先编译成**字节码**，再由虚拟机解释执行：

```
源代码 → 编译器 → 字节码 → 虚拟机(解释执行)
                              ↓
                         JIT 编译(热点代码优化)
```

**为什么需要字节码？**
- 编译一次，多次执行（比纯解释快）
- 跨平台：只要有对应平台的虚拟机即可运行
- 比源码更紧凑，解析更快

### Java 字节码示例

```java
// 源码
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
```

```bash
# 编译成字节码
javac Hello.java

# 查看字节码（使用 javap）
javap -c Hello
# 输出：
# public static void main(java.lang.String[]);
#   Code:
#    0: getstatic     #2
#    3: ldc           #3
#    5: invokevirtual #4
#    8: return
```

## JIT 编译（Just-In-Time）

JIT 是解释器和静态编译的折中：**运行时**将热点代码编译成机器码：

```
源代码 → 解释执行（同时记录热点代码执行频率）
                ↓
          热点代码达到阈值（调用计数/循环回边）
                ↓
          JIT 编译器将热点代码编译成本地机器码
                ↓
          后续执行直接运行机器码（跳过解释）
```

**JIT vs 解释**：
- 解释：启动快，执行慢（每条指令都需要翻译）
- JIT：启动慢（需预热收集热点信息），执行快
- AOT（Ahead-Of-Time）：编译好再执行，启动最快，执行速度取决于优化程度

```bash
# JVM JIT 默认启用，可通过参数调优
java -XshowFlags -version  # 查看 JIT 相关 flag
java -XX:+PrintCompilation  # 打印 JIT 编译日志
```
