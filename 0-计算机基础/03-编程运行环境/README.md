# 编程运行环境

> **版本基准**: universal

## 定义

编程运行环境是程序从源码到可执行、再到 CPU 指令流的完整支撑体系，包括编译器/解释器的翻译层、加载器/链接器的加载层、以及内存管理与线程调度的运行时层。

$$
\text{源码} \xrightarrow{\text{翻译层}} \text{中间表示} \xrightarrow{\text{加载层}} \text{进程内存布局} \xrightarrow{\text{运行时层}} \text{CPU 指令流}
$$

**归约视角**：从最底层看，所有编程运行环境最终都归约为 **操作系统系统调用**和 **CPU 硬件指令**。层次的增加（即"运行时"的加厚）并不创造新能力，只是以性能换便利性和安全性。

## 学习路径

1. **先编译型与解释型语言**：理解源代码如何被翻译和执行，DFA/LR分析、寄存器分配、链接重定位的数学原理
2. **再运行时与虚拟机**：了解程序运行时的加载、链接和内存管理，GC 算法的时间复杂度，虚拟机分类
3. **后Node.js运行时**：深入理解 V8 引擎和事件循环，epoll/kqueue 的 O(1) 等待模型，投机优化的概率性本质

## 核心概念地图

```
编程运行环境
├── 翻译层
│   ├── 编译型：源码 → 机器码（构建时一次性）
│   ├── 解释型：源码 → 字节码（运行时每次）
│   └── JIT型：字节码 + 运行时编译（热点路径优化）
├── 加载层
│   ├── ELF/PE 段映射 → 虚拟地址空间
│   ├── 符号解析与重定位
│   └── 动态链接 (PLT/GOT)
└── 运行时层
    ├── 内存管理：栈/堆/arena/bump-pointer/空闲链表
    ├── 线程调度：内核线程 / 协程 / Go GMP / BEAM
    ├── GC：引用计数 / 标记-清除 / 分代 / 三色标记
    └── I/O：epoll/kqueue/IOCP + 线程池
```
