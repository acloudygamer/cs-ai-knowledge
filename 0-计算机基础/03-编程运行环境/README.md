# 编程运行环境

> **版本基准**: universal

本部分回答一个问题：**源码如何一步步变成运行中的程序**。它夹在语言（2~6 各语言文件夹）与操作系统（02-系统软件层）之间：编译/解释把源码变成二进制，链接与装载把二进制变成进程，运行时与虚拟机在进程内垫付语言级服务，Node.js 作为完整实例收束。

组织逻辑沿真实因果链：源码 →(翻译)→ 二进制 →(装订+装载)→ 进程 →(垫付服务)→ 完整运行时栈。

## 目录

### [01-编译与解释](./01-编译与解释.md)
同一语义兑现的两种时机（AOT vs 解释）、编译器三段结构（前端/中端/后端与 LLVM）、解释器谱系（树遍历→字节码 VM→JIT）、启动速度/峰值性能/跨平台的账本

### [02-链接与装载](./02-链接与装载.md)
符号解析与重定位、静态 vs 动态链接的约束账、PIC 与 PLT/GOT 惰性绑定、ELF 的 section/segment 双视角、execve 的完整装载链

### [03-运行时与虚拟机](./03-运行时与虚拟机.md)
运行时 = 进程内语言垫付的服务层；VM 谱系（JVM/CLR/V8/CPython/BEAM）、JIT 分层编译与去优化、GC 可达性分析、分代假说与写屏障、收集器压缩停顿的演进

### [04-Node.js与事件循环](./04-Node.js与事件循环.md)
完整运行时栈实例：V8 + libuv + epoll 的组装、事件循环各阶段与微任务、线程池模拟异步、单线程形状的红利与死穴
