# 垃圾回收

## 概念

**垃圾回收 (Garbage Collection, GC)** 是自动管理内存的技术,自动回收不再使用的内存。

```
┌─────────────────────────────────────────────────────────┐
│                    内存生命周期                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  分配 ──────► 使用 ──────► 变成垃圾 ──────► 回收        │
│    │                    │                   │           │
│    │                    │                   │           │
│  new/malloc        不再引用              GC 识别并释放   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 关系

**关键连接**:
- GC → **堆内存**: 回收堆上的对象
- GC → **可达性分析**: 通过 GC Roots 判断对象是否存活
- 逃逸分析 → **栈分配**: 决定对象在栈还是堆分配
- 分代假说 → **分区回收**: 不同年龄对象采用不同策略

## GC 算法分类

### 引用计数法

每个对象维护一个引用计数,引用为 0 时立即回收:

```python
# 引用计数示意
class Node:
    def __init__(self):
        self.ref_count = 0
        self.value = None
        self.next = None

# 引用时计数+1, 解除时计数-1
def add_ref(node):
    node.ref_count += 1

def release(node):
    node.ref_count -= 1
    if node.ref_count == 0:
        # 递归释放后续节点
        if node.next:
            release(node.next)
        # 立即回收
        free(node)
```

| 优点 | 缺点 |
|------|------|
| 回收立即 | 计数器占用空间 |
| 无暂停 | 无法处理循环引用 |
| 实现简单 | 并发开销大 |

**循环引用问题**:
```
A ──引用──► B
│              │
│              │
└────◄─引用────┘

即使 A 和 B 不可达 (从 GC Root 出发),
由于 A.ref_count=1, B.ref_count=1, 永远不会被回收!
```

### 标记-清除 (Mark-Sweep)

分两阶段:先标记所有可达对象,再清除未标记对象:

```python
# 标记-清除算法
class GC:
    def __init__(self):
        self.heap = []
        self.roots = []

    def mark(self):
        """从 GC Roots 出发,标记所有可达对象"""
        marked = set()
        stack = list(self.roots)

        while stack:
            obj = stack.pop()
            if obj not in marked:
                marked.add(obj)
                # 将子对象加入待处理栈
                for child in obj.get_references():
                    stack.append(child)

        return marked

    def sweep(self, marked):
        """回收未标记的对象"""
        for obj in self.heap:
            if obj not in marked:
                free(obj)  # 释放内存
            else:
                # 取消标记,准备下一轮
                obj.marked = False
```

```
标记-清除示意图:

标记阶段:              清除阶段:
┌───────────┐        ┌───────────┐
│  Root ──┐ │        │  Root ──┐ │
└─────────│─┘        └─────────│─┘
          │                  │
    ┌─────▼────┐        ┌─────▼────┐
    │可达对象 A │        │ 已回收   │
    └─────┬────┘        └──────────┘
          │
    ┌─────▼────┐
    │可达对象 B │        ┌───────────┐
    └──────────┘        │ 回收 B   │
                         └──────────┘
```

### 标记-整理 (Mark-Compact)

在标记-清除基础上,整理存活对象到一端:

```
┌─────────────────────────────────┐
│ 整理前          │  整理后        │
├─────────────────────────────────┤
│ [A] [B] [C]    │  [A] [B] [C]   │
│ [ ] [ ] [D]    │  [D] [ ] [ ]   │
│ [E] [F] [ ]    │  [E] [F] [ ]   │
└─────────────────────────────────┘
```

### 复制算法 (Copying)

将内存分为两半,只使用一半,回收时复制存活对象到另一半:

```python
# 复制算法
class CopyingGC:
    def __init__(self, size):
        self.from_space = allocate(size)
        self.to_space = allocate(size)
        self.alloc_ptr = self.from_space

    def allocate(self, size):
        if self.alloc_ptr + size > self.from_space.end:
            self.collect()
        obj = self.alloc_ptr
        self.alloc_ptr += size
        return obj

    def collect(self):
        # 复制存活对象到 to_space
        new_ptr = self.to_space
        for obj in self.heap:
            if is_reachable(obj):
                new_obj = copy(obj, new_ptr)
                new_ptr += obj.size
                update_reference(obj, new_obj)

        # 交换空间
        self.from_space, self.to_space = self.to_space, self.from_space
        self.alloc_ptr = self.from_space.begin
```

```
复制算法示意:

       ┌───────────────────────┐
 From  │ [A] [B] │ [ ] [ ]   │  ──►  复制 A,B 到 To
 Space │  存活   │  空闲     │
       └───────────────────────┘
                 │
                 ▼
       ┌───────────────────────┐
  To   │ [A] [B] │ [ ] [ ]   │  ──►  交换 From/To
 Space │  存活   │  空闲     │
       └───────────────────────┘
```

## GC Roots (GC 根集)

GC Roots 是无需通过其他对象即可直接访问的引用:

```java
// GC Roots 示例 (Java)
public class GC Roots {
    // 1. 静态变量引用
    static Object staticObj = new Object();

    // 2. 栈上的局部变量
    public void method() {
        Object localVar = new Object();  // localVar 是 GC Root
    }

    // 3. JNI 引用
    // Native 方法中的对象引用
}
```

| GC Roots 类型 | 说明 |
|--------------|------|
| 栈帧中的局部变量 | 方法栈上的对象引用 |
| 静态变量 | 类静态成员持有的对象 |
| JNI 引用 | Native 代码中的 Java 对象引用 |
| 运行中的线程 | 正在执行的线程对象 |
| 监视器对象 | 持有对象锁的线程 |

## 分代回收

基于分代假说:大多数对象朝生夕死

```
┌─────────────────────────────────────────────────────────┐
│                    分代内存模型                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  年轻代 (Young Generation)                              │
│  ┌──────────────────────────────────────────────────┐  │
│  │ Eden │  Survivor 0 │  Survivor 1                  │  │
│  │  80% │     10%     │     10%                     │  │
│  └──────────────────────────────────────────────────┘  │
│                                                         │
│  老年代 (Old/Tenured Generation)                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │                                                   │  │
│  │              长期存活的对象                       │  │
│  │                                                   │  │
│  └──────────────────────────────────────────────────┘  │
│                                                         │
│  永久代/元空间 (Perm/Metaspace)                         │
│  ┌──────────────────────────────────────────────────┐  │
│  │         类信息、常量池、 JIT 编译缓存              │  │
│  └──────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 各代回收策略

| 代 | 回收频率 | 算法 | 原因 |
|----|----------|------|------|
| 年轻代 | 高 | 复制算法 | 大多数对象死亡 |
| 老年代 | 低 | 标记-整理 | 对象长期存活 |
| 元空间 | 极低 | Full GC | 类卸载 |

### 对象晋升

```java
// 对象晋升流程
// 1. 新对象在 Eden 区分配
// 2. Minor GC 后,存活对象复制到 Survivor
// 3. 对象在 Survivor 之间复制,年龄+1
// 4. 年龄达到阈值(默认15)后晋升到老年代
// 5. 老年代满时触发 Full GC
```

```bash
# JVM 分代配置
java -Xmx512m -Xms512m \
    -XX:NewRatio=2 \          # 老年代/年轻代比例
    -XX:SurvivorRatio=8 \     # Eden/Survivor 比例
    -XX:MaxTenuringThreshold=15  # 晋升阈值
```

## 常见 GC 算法实现

### G1 (Garbage First)

面向服务器的垃圾回收器,采用分区思想:

```
G1 堆分区:

┌─────────────────────────────────────────────────────┐
│  Region 大小可变,每个 region 可独立回收              │
├────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┤
│ E  │ E  │ S  │ S  │ O  │ O  │ O  │ O  │ O  │ H  │ U  │
│ Eden│   │Survivor│ Old │ Humongous│                   │
└────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘
```

### ZGC

低延迟垃圾回收器,停顿时间不超过 1ms:

```bash
# 启用 ZGC
java -XX:+UseZGC -Xmx16g -Xms16g MyApp
```

### Shenandoah

红帽开发的低暂停 GC,与 ZGC 类似但实现不同:

```bash
# 启用 Shenandoah
java -XX:+UseShenandoahGC -Xmx16g -Xms16g MyApp
```

## 逃逸分析

分析对象的动态作用域,决定在栈还是堆分配:

```java
// 逃逸分析示例
public class EscapeAnalysis {

    // 不逃逸 - 可以在栈上分配
    public void method1() {
        int[] arr = new int[100];  // 栈上分配
        arr[0] = 1;
        // 方法返回后,arr 自动回收
    }

    // 逃逸 - 必须在堆上分配
    public int[] method2() {
        int[] arr = new int[100];
        arr[0] = 1;
        return arr;  // 返回引用,逃逸到堆
    }

    // 线程级别逃逸
    public static Object shared;

    public void method3() {
        synchronized(shared) {
            // shared 被多个线程访问,线程逃逸
        }
    }
}
```

| 逃逸类型 | 说明 | 分配位置 |
|----------|------|----------|
| 不逃逸 | 只在方法内使用 | 栈 |
| 方法逃逸 | 作为返回值传出 | 堆 |
| 线程逃逸 | 被多线程共享 | 堆 |

## 内存管理语言对比

| 语言 | GC 策略 | 特点 |
|------|---------|------|
| Java | 分代收集 | G1/ZGC/Shenandoah |
| Go | 三色标记并发 | 低延迟 |
| Python | 引用计数+循环检测 | 实时回收,但有 GIL |
| JavaScript | 标记清除 | 增量回收 |
| Rust | 所有权+生命周期 | 编译时保证,无 GC |

```rust
// Rust 的所有权系统 (无 GC 示例)
fn main() {
    let s1 = String::from("hello");  // s1 拥有所有权
    let s2 = s1;                    // 所有权转移到 s2
    // println!("{}", s1);          // 编译错误! s1 已无效
    println!("{}", s2);              // 正确
}
```

## GC 调优

### 常见问题

| 问题 | 症状 | 解决方案 |
|------|------|----------|
| Full GC 频繁 | 老年代快速满 | 增大堆,优化对象生命周期 |
| Minor GC 频繁 | Eden 区小 | 增大年轻代 |
| 内存泄漏 | GC 后内存不降 | 分析堆快照 |
| 停顿时间长 | 应用卡顿 | 使用 G1/ZGC |

### 调优参数

```bash
# 基础参数
-Xms4g                 # 初始堆大小
-Xmx4g                 # 最大堆大小

# 年轻代
-Xmn2g                 # 年轻代大小
-XX:SurvivorRatio=6    # Eden:Survivor

# 元空间
-XX:MaxMetaspaceSize=256m

# GC 日志
-XX:+PrintGCDetails
-XX:+PrintGCDateStamps
-Xloggc:gc.log
```
