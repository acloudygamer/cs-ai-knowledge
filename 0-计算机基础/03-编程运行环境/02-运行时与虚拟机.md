# 运行时与虚拟机

## 定义

运行时是程序执行时赖以生存的**抽象层**，位于硬件与程序之间，提供内存管理、线程调度和系统调用抽象。虚拟机是以软件模拟硬件指令集或完整计算机系统的运行时形态。

$$
\text{程序} \xrightarrow{\text{加载}} \text{运行时} \xrightarrow{\text{系统调用}} \text{操作系统} \xrightarrow{\text{驱动}} \text{CPU/内存/外设}
$$

$$
T_{运行时损耗} = \underbrace{T_{内存分配}}_{堆管理/GC} + \underbrace{T_{调度切换}}_{线程/协程} + \underbrace{T_{解释分发}}_{字节码解释器}
$$

## 数学模型

### 内存分配模型

堆分配时间取决于分配策略：

$$
T_{alloc}(s) =
\begin{cases}
O(1) & \text{顺序分配 (栈式)} \\
O(\log n) & \text{空闲链表有序查找} \\
O(1) \sim O(k) & \text{多隔间空闲列表 (碎片化程度影响)} \\
O(n) & \text{空闲链表无序查找}
\end{cases}
$$

现代分配器（jemalloc, tcmalloc）采用多隔间 + 空闲列表，将最坏情况降低到近似 $O(1)$。

### 垃圾回收停顿时间

GC 停顿来自三阶段：

$$
T_{GC} = \underbrace{T_{mark}}_{O(|可达对象|)} + \underbrace{T_{sweep}}_{O(|总对象|)} + \underbrace{T_{compact}}_{O(|存活对象| \times 移动距离)}
$$

分代假设：大多数对象朝生夕死。年轻代回收代价 $O(|年轻代|)$，老年代回收代价 $O(|整个堆|)$。

### 栈 vs 堆分配

| 维度 | 栈分配 | 堆分配 |
|------|--------|--------|
| 时间复杂度 | $O(1)$ 指针移动 | $O(1) \sim O(n)$ 取决于分配器 |
| 空间回收 | 函数返回自动释放 | 手动 free / GC 自动回收 |
| 生命周期 | 严格词法作用域 | 动态，由所有者决定 |
| 容量限制 | 受栈大小约束 (通常 1-8MB) | 受物理内存 + 交换区约束 |

### 虚拟机性能分类

| 类型 | 代表 | 虚拟化开销 | 适用场景 |
|------|------|-----------|---------|
| 系统虚拟机 (Hypervisor Type 1) | KVM, VMware ESXi, Hyper-V | 10-30% | 服务器虚拟化, 云计算 |
| 系统虚拟机 (Hypervisor Type 2) | VirtualBox, VMware Workstation | 15-50% | 桌面虚拟化, 开发测试 |
| 语言虚拟机 (JIT 型) | JVM, CLR, V8 | 0-50% (JIT 可弥补) | 托管代码执行 |
| 纯解释型虚拟机 | CPython, Ruby 1.8 | 50-100x | 跨平台脚本执行 |

### 协程调度模型 (Go GMP)

<pre>
G (Goroutine) ←→ M (Machine/内核线程) ←→ P (Processor)
    │
    ├─ G 在 P 的本地队列中循环
    ├─ M 阻塞 → G 窃取其他 P 的 G
    └─ 上下文切换: ~200-300ns (vs 线程 ~2-5μs)
</pre>

吞吐量模型：

$$
\text{吞吐量} = \frac{\text{G 数}}{\text{M 数} + \text{阻塞时间} / \text{切换时间}}
$$

## 数据流

### 程序加载与运行时初始化

<pre>
可执行文件 (ELF/PE/Mach-O)
    │
    ▼ [内核加载器 — execve / CreateProcess]
映射段到虚拟地址空间:
├─ .text (代码段, r-x)
├─ .data (已初始化数据, rw-)
├─ .bss  (未初始化数据, rw-)
├─ .rodata (只读数据, r--)
└─ heap/stack (运行时扩展)
    │
    ▼ [运行时初始化序列]
├─ CRT 初始化 (C/C++ 运行库)
├─ 堆管理器初始化 (malloc 池 / GC 数据结构)
├─ 线程系统初始化 (TLS, 线程-local storage)
├─ GC 初始化 (GC 根集, 屏障注册)
├─ 动态链接器解析 (符号重定位)
└─ 入口点调用 (main / _start)
    │
    ▼
主线程启动 → 进入程序入口
</pre>

### 运行时内存布局模型

<pre>
┌────────────────────────────────────────────┐
│  代码区 (Code Segment)                      │
│    ├─ 可执行指令 (r-x)                      │
│    └─ 只读常量 (r--)                        │
├────────────────────────────────────────────┤
│  堆 (Heap) — 动态分配, GC 管理              │
│    ├─ 托管对象                              │
│    └─ 编译器分配的临时对象                   │
├────────────────────────────────────────────┤
│  栈 (Stack) — 每线程独立                   │
│    └─ 栈帧: [返回地址][参数][局部变量][上下文]│
├────────────────────────────────────────────┤
│  全局数据区                                 │
│    ├─ .data: 已初始化全局变量               │
│    └─ .bss: 未初始化变量 (零初始化)         │
├────────────────────────────────────────────┤
│  本地方法区 / 元空间 (JVM/CLR)               │
│    └─ 类元数据, 方法表, 字符串常量池         │
└────────────────────────────────────────────┘
</pre>

> **JVM/CLR 差异**：JVM 将方法区和字符串常量池划为独立的"元空间"（JDK 8 前为永久代）；CLR 将其置于"托管堆"内。但逻辑分区一致。

### 垃圾回收数据流

<pre>
标记阶段 (Mark):
GC Roots (栈引用, 静态字段, 寄存器)
    │
    ▼ [三色标记]
白色 ← 未标记对象
灰色 ← 待处理 (已发现但未遍历子对象)
黑色 ← 已处理 (自身和子对象均已标记)
    │
    ▼ [可达性遍历]
递归标记 → 所有可达对象变为黑色
时间复杂度: O(|可达对象|)

清除阶段 (Sweep):
扫描整个堆 → 回收白色对象 → 更新空闲列表
时间复杂度: O(|总对象|)

整理阶段 (Compact):
移动存活对象 → 消除内存碎片 → 更新所有引用
时间复杂度: O(|存活对象| × 平均移动距离)
</pre>

### 分代回收数据流

<pre>
新对象分配 → Eden 区 (Survivor Space S0/S1)
    │
    ▼ [Minor GC 后存活]
年龄 +1 → 复制到 Survivor 区
    │
    ▼ [年龄 ≥ 阈值 (通常 15) 或 Survivor 满]
Promote → 老年代
    │
    ▼ [老年代满 → Full GC]
标记-整理 → 回收 / 整理
</pre>

分代假设的数学依据：研究表明大多数对象在创建后迅速成为不可达（`weak generational hypothesis`）。

### 语言虚拟机执行流 (JIT 型)

<pre>
字节码加载 → 验证器检查合法性
    │
    ▼ [解释执行阶段]
解释器循环: fetch → decode → dispatch → execute
    │
    ▼ [热点检测]
调用计数 ≥ CompileThreshold (如 1500)
循环回边计数触发 OSR (On-Stack Replacement)
    │
    ▼ [JIT 编译]
IR 生成 → 平台无关优化 → 平台相关优化
    │
    ▼ [生成优化机器码]
类型特化 / 内联 / 逃逸分析 / 向量化
    │
    ▼ [假设验证]
类型稳定 → 继续执行优化码
类型变化 → 去优化 → 回退字节码
</pre>

## 机制

### 运行时的核心职责

运行时位于程序与操作系统之间，提供**高级抽象**：

**内存管理**：
- 分配：程序请求内存 → 运行时调用系统 API → 管理进程地址空间
- 回收：手动 (free/delete) 或自动 (GC)
- 约束：堆内存有限，分配失败必须处理

**线程调度**：
- 内核线程：OS 抢占式调度，时间片耗尽强制切换
- 用户线程（协程）：运行时协作式调度，切换代价 ~200ns
- Go GMP：协程在 P 上复用 M，阻塞时让出 P 而不阻塞 M

**系统调用封装**：
- 程序通过运行时发起 I/O、进程管理等操作
- 运行时将系统调用封装为高级 API (read/write vs fread/fwrite)
- 运行时处理信号和异常

**违规后果**：
- 内存泄漏：分配后未释放 → 堆耗尽 → OOM
- 悬空指针：释放后使用 → 未定义行为 (可能 segfault)
- 栈溢出：递归过深或大局部变量 → stack overflow

### 垃圾回收机制

#### 引用计数法

每对象维护引用计数，计数归零立即回收：

$$
\text{refcount}(obj) = \sum_{ref \in \text{references}} 1
$$

**优点**：回收及时，无 STW (Stop-The-World) 停顿。
**缺点**：无法处理循环引用；计数更新有性能开销。

循环引用泄漏示例：
```python
a = Node()
b = Node()
a.ref = b  # refcount(b) = 2
b.ref = a  # refcount(a) = 2
del a; del b  # refcount 均降至 1，永远无法回收
```

#### 标记-清除法

从 GC Roots 出发标记所有可达对象：

$$
\text{Reachable} = \text{DFS}(\text{GC Roots})
$$

未标记对象视为垃圾。

**约束**：需要 STW 停顿；全堆扫描代价高。

#### 分代收集法

基于弱分代假设：大多数对象朝生夕死。

| 分代 | 对象年龄 | 回收算法 | 回收频率 |
|------|---------|---------|---------|
| 年轻代 (Eden + S0 + S1) | 0-15 | 复制算法 | 高 (90% 对象死亡) |
| 老年代 | > 阈值 | 标记-整理 | 低 |

复制算法代价：$O(存活对象)$，无碎片，但浪费 50% 空间。

#### 并发标记 (三色标记 + 读写屏障)

$$
\text{白色} \xrightarrow{\text{发现}} \text{灰色} \xrightarrow{\text{遍历}} \text{黑色}
$$

并发标记需要**读写屏障**维护正确性：

- **SATB (Snapshot-At-The-Beginning)**：标记开始时的快照，保留所有快照时可达对象
- **增量更新**：标记结束后，脏写将对象加入待处理队列

**违规后果**：
- 标记遗漏 → 存活对象被回收 → 悬空指针
- 屏障性能开销 → GC 吞吐量下降

### 虚拟机机制

#### 系统级虚拟机 (Hypervisor)

**Type 1 (裸金属)**：直接运行在硬件上，自身是轻量级操作系统。
- KVM (Linux 内核模块): 硬件辅助虚拟化 (VT-x/AMD-V)
- VMware ESXi: 裸金属 hypervisor
- Hyper-V: Windows Server 虚拟化

**Type 2 (宿主)**：运行在宿主机操作系统上。
- VirtualBox: 依赖宿主 OS 的驱动程序栈
- VMware Workstation: 用户态虚拟化

虚拟化开销来源：CPU 模拟 (二进制翻译或硬件辅助)、内存虚拟化 (影子页表或EPT/NPT)、I/O 虚拟化 (半虚拟化或 VFIO)。

#### 语言虚拟机

**JVM / CLR (基于线程的 JIT 型)**：
- 类/程序集加载 → 字节码验证 → 解释/JIT 执行
- JIT 编译热点代码 → 本地机器码
- GC 管理托管堆

**BEAM (Erlang/Elixir，基于 Actor)**：
- 每个 Actor 是独立轻量级进程
- 基于 reduction counting 的抢占式调度
- 进程间消息传递，无共享内存

> **关键对比**：JVM/CLR 是"共享地址空间的线程模型"，BEAM 是"基于消息传递的 Actor 模型"。前者靠锁/原子操作处理数据竞争，后者通过进程隔离从根本上避免竞争。

### JIT 编译器与运行时关系

JIT 编译器是运行时的一部分，在运行时动态编译字节码：

$$
\text{字节码} \xrightarrow{\text{JIT}} \text{IR} \xrightarrow{\text{优化}} \text{机器码}
$$

**编译时决策 vs 运行时决策**：
- 编译时：函数调用约定、栈帧布局、符号解析
- 运行时：热点识别、类型特化、去优化触发

**约束**：JIT 编译时间计入程序运行时间，过度 JIT 会导致程序停顿。

**违规后果**：
- JIT 编译错误：优化假设不成立 → 去优化回退
- 编译时间过长：程序响应延迟 (JVM 预热问题)

## 参考存根

### C 手动内存管理

```c
int *alloc_array(int n) {
    int *p = malloc(n * sizeof(int));
    for (int i = 0; i < n; i++) p[i] = i;
    return p;
}
```

### Go 协程

```go
ch := make(chan int)
go func() { ch <- 42 }()
result := <-ch
```

### Python 引用计数

```python
class RefCounted:
    def __init__(self): self.refcount = 1
    def add_ref(self): self.refcount += 1
    def release(self):
        self.refcount -= 1
        if self.refcount == 0: self._free()
```
