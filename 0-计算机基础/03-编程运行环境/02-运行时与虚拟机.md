# 运行时与虚拟机

# 运行时

## 概念

**运行时**是程序执行时依赖的环境，包括内存管理、垃圾回收、线程调度、库函数等。运行时在程序启动时加载，在程序结束时释放，是程序与操作系统之间的桥梁。

```
源代码 → 编译器/解释器 → 可执行文件/字节码 → [运行时] → 操作系统 → 硬件
```

## 关系

**关键连接**：
- 运行时 → **操作系统**：通过系统调用请求资源（内存、文件、网络）
- 运行时 → **内存管理**：分配/释放堆内存，执行垃圾回收
- 运行时 → **线程调度**：管理协程/线程的创建、切换、销毁
- 编译器 → 运行时：编译时决定生成什么类型的运行时依赖
- 运行时 → **JIT编译器**：热点代码的运行时编译（Java、JavaScript、V8）

## 各语言的运行时

| 语言 | 运行时 | 特点 |
|------|--------|------|
| C | C RunTime (CRT) | 最小化，主要初始化代码，malloc/free 手动管理 |
| C++ | 与C共享CRT运行时 | 通常编译进可执行文件，RAII 自动管理 |
| Java | JVM (Java Runtime) | 包含GC、JIT、类加载，多线程并发 |
| Go | Go Runtime | 协程调度（GMP模型）、并发GC、栈管理 |
| Python | CPython 运行时 | 解释器内置（CPython），GIL限制，动态类型 |
| JavaScript | JS Engine (V8/SpiderMonkey) | JIT编译、GC、事件循环 |
| Rust | 几乎无运行时 | 内存管理在编译时通过 ownership 确定 |

## 内存管理

运行时负责**堆内存分配和回收**：

```python
# Python：自动垃圾回收
x = [1, 2, 3]    # 堆上分配对象
y = x            # 引用计数 +1
del x             # 引用计数 -1，x 不再引用该对象
import gc
gc.collect()      # 手动触发GC（通常不需要）
```

```go
// Go：堆上分配，GC 自动回收
var slice []int = make([]int, 100)  // 堆上分配
ptr := new(int)                     // 堆上分配
```

```c
// C：手动分配和释放
int *p = malloc(sizeof(int) * 10);  // 堆上分配
free(p);                              // 手动释放
p = NULL;                             // 避免悬空指针
```

## 垃圾回收 (GC)

**常见GC算法**：

| 算法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 引用计数 | 每个对象记录引用数量，为0时立即回收 | 及时回收、无STW | 无法处理循环引用、计数更新开销 |
| 标记-清除 | 标记所有可达对象，清除不可达对象 | 处理循环引用 | STW停顿（Stop-The-World） |
| 分代收集 | 新对象放年轻代（频繁回收）、老对象放老年代（少回收） | 效率高，符合对象生命周期 | 需要调整参数，内存碎片 |
| 标记-整理 | 标记后移动存活对象，整理内存 | 无碎片 | 移动开销 |

### G1GC（Java 默认）

将堆划分为多个 Region，优先回收垃圾最多的 Region：

```bash
# JVM G1GC 调优参数
java -XX:+UseG1GC -XX:MaxGCPauseMillis=200 -jar app.jar
```

## 栈 vs 堆

| 区域 | 用途 | 分配方式 | 大小 | 速度 |
|------|------|----------|------|------|
| 栈 | 函数调用、局部变量、返回地址 | 编译器自动管理（压栈/弹栈） | 较小（MB级） | 快（~纳秒级） |
| 堆 | 动态分配内存、对象 | 运行时手动（malloc/new）或自动（GC） | 大（受物理内存限制） | 慢（~微秒级） |

```python
# 栈：函数调用
def foo():
    x = 10        # x 是栈上的引用，指向堆上的整数对象
    bar(x)        # 调用结束，x 栈帧弹出

# 堆：动态分配
data = [1, 2, 3]  # 堆上分配列表对象，data 是栈上的引用
```

```c
// 栈 vs 堆 对比
void example() {
    int local_var = 5;      // 栈：函数返回时自动释放
    int *heap_var = malloc(sizeof(int));  // 堆：需要手动 free
    *heap_var = 10;
    free(heap_var);         // 忘记会导致内存泄漏
}
```

## 运行时库

提供程序运行所需的基础库函数：

- **libc** (Linux)：C标准库，提供malloc、printf、open等
- **glibc** (GNU C Library)：Linux 默认 C 库，POSIX 兼容
- **MSVCRT** (Windows)：旧版 C Run-Time（Windows 10+ 已废弃，由 UCRT 替代）
- **libstdc++** (C++)：C++ 标准库容器、算法

## 线程 vs 协程

| 模型 | 调度 | 切换成本 | 适用场景 |
|------|------|----------|----------|
| 线程（内核级） | OS 调度，抢占式 | 大（KB级栈 + 上下文切换） | CPU 密集型、IO 阻塞 |
| 协程（用户级） | 用户代码调度，Go 协程为抢占式 | 小（栈帧切换） | 高并发 IO、异步编程 |

```go
// Go 协程示例
func main() {
    go func() {  // 轻量级协程
        fmt.Println("并发执行")
    }()
    time.Sleep(time.Second)
}
```


# 虚拟机

## 概念

**虚拟机**是通过软件模拟的计算机系统，可以运行操作系统的完整实例，或运行特定语言的字节码。虚拟机将物理资源虚拟化，提供隔离的运行环境。

```
物理机 → [虚拟机管理器(Hypervisor)] → 多个虚拟机 → 各自运行操作系统
物理机 → [语言虚拟机] → 字节码程序
```

## 关系

**关键连接**：
- 虚拟机 → **操作系统**：系统级虚拟机需要宿主OS（Type 2）或直接运行在硬件上（Type 1）
- 虚拟机 → **硬件**：虚拟化硬件资源（CPU、内存、磁盘、网络）
- 虚拟机 ← **编译器**：编译器生成字节码，虚拟机解释/JIT执行
- 容器 → **Linux内核**：共享宿主机内核，通过 namespace 和 cgroup 隔离

## 两类虚拟机

### 1. 系统级虚拟机（Hypervisor）

模拟完整计算机，运行操作系统：

| 类型 | 代表 | 特点 | 运行环境 |
|------|------|------|----------|
| Type 1 (裸金属) | VMware ESXi, KVM, Hyper-V | 直接运行在硬件上 | 服务器、企业 |
| Type 2 (宿主) | VirtualBox, VMware Workstation | 运行在宿主机OS上 | 桌面、开发 |

| 虚拟机 | 特点 | 用途 |
|--------|------|------|
| VMware | 商业级，性能好 | Windows/Mac运行Linux |
| VirtualBox | 开源，跨平台 | 开发测试环境 |
| KVM | Linux内核模块（提供CPU/内存虚拟化加速），QEMU + KVM 构成 Type 1 | 服务器虚拟化 |
| Hyper-V | Windows内置 | Windows服务器 |

### 2. 语言虚拟机

运行特定语言的字节码：

| 虚拟机 | 语言 | 特点 |
|--------|------|------|
| JVM | Java, Kotlin, Scala | JIT编译，跨平台（Write Once Run Anywhere） |
| CLR | C#, F#, VB.NET | .NET平台，托管代码 |
| BEAM | Elixir, Erlang | Actor模型，并发强大 |
| BPF VM | BPF (Berkeley Packet Filter) | 网络/跟踪程序，安全沙箱 |
| WASM Runtime | WebAssembly | 浏览器/服务端沙箱执行 |

## BEAM（Erlang/Elixir 虚拟机）

BEAM 是 Erlang 的虚拟机，以** Actor 模型**和**轻量级进程**著称：

```erlang

# 垃圾回收

### 解决什么问题
手动管理内存容易出错（内存泄漏、释放后使用）。垃圾回收自动识别不再使用的对象并回收，简化内存管理、减少bug。

### 核心概念
- GC自动回收不再使用的内存，无需程序员手动free
- 通过GC Roots（栈变量、静态变量等）判断对象是否可达
- 引用计数法简单但无法处理循环引用
- 分代回收基于"大多数对象朝生夕死"的假设优化性能
- 标记-清除、复制、标记-整理是三种基本算法

### 怎么用
```python
# Python 引用计数示意
import sys
x = [1, 2, 3]  # refcount = 1
y = x           # refcount = 2
del x           # refcount = 1
del y           # refcount = 0, 对象被回收
```

## GC 算法分类

### 引用计数法

每个对象维护一个引用计数,引用为 0 时立即回收:

```python
# 引用计数示意
class Node:
    def __init__(self):
        self.ref_count = 0
        self.value = None
        self.next = None

# 引用时计数+1, 解除时计数-1
def add_ref(node):
    node.ref_count += 1

def release(node):
    node.ref_count -= 1
    if node.ref_count == 0:
        # 递归释放后续节点
        if node.next:
            release(node.next)
        # 立即回收
        free(node)
```

| 优点 | 缺点 |
|------|------|
| 回收及时（计数为0即回收） | 计数器占用空间 |
| 无全堆扫描 | 无法处理循环引用 |
| 实现简单 | 并发开销大 |

**循环引用问题**:
```
A ──引用──► B
│              │
│              │
└────◄─引用────┘

即使 A 和 B 不可达 (从 GC Root 出发),
由于 A.ref_count=1, B.ref_count=1, 永远不会被回收!
```

### 标记-清除 (Mark-Sweep)

分两阶段:先标记所有可达对象,再清除未标记对象:

```python
# 标记-清除算法
class GC:
    def __init__(self):
        self.heap = []
        self.roots = []

    def mark(self):
        """从 GC Roots 出发,标记所有可达对象"""
        marked = set()
        stack = list(self.roots)

        while stack:
            obj = stack.pop()
            if obj not in marked:
                marked.add(obj)
                # 将子对象加入待处理栈
                for child in obj.get_references():
                    stack.append(child)

        return marked

    def sweep(self, marked):
        """回收未标记的对象"""
        for obj in self.heap:
            if obj not in marked:
                free(obj)  # 释放内存
            else:
                # 取消标记,准备下一轮
                obj.marked = False
```

```
标记-清除示意图:

标记阶段:              清除阶段:
┌───────────┐        ┌───────────┐
│  Root ──┐ │        │  Root ──┐ │
└─────────│─┘        └─────────│─┘
          │                  │
    ┌─────▼────┐        ┌─────▼────┐
    │可达对象 A │        │ 已回收   │
    └─────┬────┘        └──────────┘
          │
    ┌─────▼────┐
    │可达对象 B │        ┌───────────┐
    └──────────┘        │ 回收 B   │
                         └──────────┘
```

### 标记-整理 (Mark-Compact)

在标记-清除基础上,整理存活对象到一端:

```
┌─────────────────────────────────┐
│ 整理前          │  整理后        │
├─────────────────────────────────┤
│ [A] [B] [C]    │  [A] [B] [C]   │
│ [ ] [ ] [D]    │  [D] [ ] [ ]   │
│ [E] [F] [ ]    │  [E] [F] [ ]   │
└─────────────────────────────────┘
```

### 复制算法 (Copying)

将内存分为两半,只使用一半,回收时复制存活对象到另一半:

```python
# 复制算法
class CopyingGC:
    def __init__(self, size):
        self.from_space = allocate(size)
        self.to_space = allocate(size)
        self.alloc_ptr = self.from_space

    def allocate(self, size):
        if self.alloc_ptr + size > self.from_space.end:
            self.collect()
        obj = self.alloc_ptr
        self.alloc_ptr += size
        return obj

    def collect(self):
        # 复制存活对象到 to_space
        new_ptr = self.to_space
        for obj in self.heap:
            if is_reachable(obj):
                new_obj = copy(obj, new_ptr)
                new_ptr += obj.size
                update_reference(obj, new_obj)

        # 交换空间
        self.from_space, self.to_space = self.to_space, self.from_space
        self.alloc_ptr = self.from_space.begin
```

```
复制算法示意:

       ┌───────────────────────┐
 From  │ [A] [B] │ [ ] [ ]   │  ──►  复制 A,B 到 To
 Space │  存活   │  空闲     │
       └───────────────────────┘
                 │
                 ▼
       ┌───────────────────────┐
  To   │ [A] [B] │ [ ] [ ]   │  ──►  交换 From/To
 Space │  存活   │  空闲     │
       └───────────────────────┘

复制完成后，From Space 和 To Space 角色互换
（原 To Space 变为新的 From Space，原 From Space 变为新的 To Space）
```

## GC Roots (GC 根集)

GC Roots 是无需通过其他对象即可直接访问的引用:

```java
// GC Roots 示例 (Java)
public class GC Roots {
    // 1. 静态变量引用
    static Object staticObj = new Object();

    // 2. 栈上的局部变量
    public void method() {
        Object localVar = new Object();  // localVar 是 GC Root
    }

    // 3. JNI 引用
    // Native 方法中的对象引用
}
```

| GC Roots 类型 | 说明 |
|--------------|------|
| 栈帧中的局部变量 | 方法栈上的对象引用 |
| 静态变量 | 类静态成员持有的对象 |
| JNI 引用 | Native 代码中的 Java 对象引用 |
| 运行中的线程 | 正在执行的线程对象 |
| 监视器对象 | 持有对象锁的线程 |

## 分代回收

基于分代假说:大多数对象朝生夕死

```
┌─────────────────────────────────────────────────────────┐
│                    分代内存模型                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  年轻代 (Young Generation)                              │
│  ┌──────────────────────────────────────────────────┐  │
│  │ Eden │  Survivor 0 │  Survivor 1                  │  │
│  │  80% │     10%     │     10%  (默认比例)          │  │
│  └──────────────────────────────────────────────────┘  │
│                                                         │
│  老年代 (Old/Tenured Generation)                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │                                                   │  │
│  │              长期存活的对象                       │  │
│  │                                                   │  │
│  └──────────────────────────────────────────────────┘  │
│                                                         │
│  元空间 (Metaspace)                     │
│  ┌──────────────────────────────────────────────────┐  │
│  │ Java 8+：元空间（本地内存，非堆）                │  │
│  │ Java 7及之前：永久代（PermGen，堆内存，已移除）  │  │
│  │ 存储：类信息、常量池、JIT 编译缓存                 │  │
│  └──────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘

> 注意：PermGen 是堆内存的一部分，受 GC 管理；Metaspace 是本地内存（os_alloc），不受堆 GC 管理。这是两者最根本的区别。

### 各代回收策略

| 代 | 回收频率 | 算法 | 原因 |
|----|----------|------|------|
| 年轻代 | 高 | 复制算法 | 大多数对象死亡 |
| 老年代 | 低 | 标记-整理 | 对象长期存活 |
| 元空间 | 极低 | Full GC | 类卸载 |

### 对象晋升

```java
// 对象晋升流程
// 1. 新对象在 Eden 区分配
// 2. Minor GC 后,存活对象复制到 Survivor
// 3. 对象在 Survivor 之间复制,年龄+1
// 4. 年龄达到阈值(默认15)后晋升到老年代
// 5. 老年代满时触发 Full GC
```

```bash
# JVM 分代配置
java -Xmx512m -Xms512m \
    -XX:NewRatio=2 \          # 老年代/年轻代比例
    -XX:SurvivorRatio=8 \     # Eden/Survivor 比例
    -XX:MaxTenuringThreshold=15  # 晋升阈值
```

## 常见 GC 算法实现

### G1 (Garbage First)

面向服务器的垃圾回收器,采用分区思想:

```
G1 堆分区:

┌─────────────────────────────────────────────────────┐
│  Region 大小可变,每个 region 可独立回收              │
├────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┤
│ E  │ E  │ S  │ S  │ O  │ O  │ O  │ O  │ O  │ H  │ U  │
│ Eden│   │Survivor│ Old │ Humongous│                   │
└────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘
```

### ZGC

低延迟垃圾回收器，设计目标为停顿时间不超过 1ms：

```bash
# 启用 ZGC
java -XX:+UseZGC -Xmx16g -Xms16g MyApp
```

### Shenandoah

红帽开发的低暂停 GC,与 ZGC 类似但实现不同:

```bash
# 启用 Shenandoah
java -XX:+UseShenandoahGC -Xmx16g -Xms16g MyApp
```

## 逃逸分析

分析对象的动态作用域,决定在栈还是堆分配:

```java
// 逃逸分析示例
public class EscapeAnalysis {

    // 不逃逸 - 可以在栈上分配
    public void method1() {
        int[] arr = new int[100];  // 栈上分配
        arr[0] = 1;
        // 方法返回后,arr 自动回收
    }

    // 逃逸 - 必须在堆上分配
    public int[] method2() {
        int[] arr = new int[100];
        arr[0] = 1;
        return arr;  // 返回引用,逃逸到堆
    }

    // 线程级别逃逸
    public static Object shared;

    public void method3() {
        synchronized(shared) {
            // shared 被多个线程访问,线程逃逸
        }
    }
}
```

| 逃逸类型 | 说明 | 分配位置 |
|----------|------|----------|
| 不逃逸 | 只在方法内使用 | 栈 |
| 方法逃逸 | 作为返回值传出 | 堆 |
| 线程逃逸 | 被多线程共享 | 堆 |

## 内存管理语言对比

## GC 调优

### 常见问题

| 问题 | 症状 | 解决方案 |
|------|------|----------|
| Full GC 频繁 | 老年代快速满 | 增大堆,优化对象生命周期 |
| Minor GC 频繁 | Eden 区小 | 增大年轻代 |
| 内存泄漏 | GC 后内存不降 | 分析堆快照 |
| 停顿时间长 | 应用卡顿 | 使用 G1/ZGC |

### 调优参数

```bash
# 基础参数
-Xms4g                 # 初始堆大小
-Xmx4g                 # 最大堆大小

# 年轻代
-Xmn2g                 # 年轻代大小
-XX:SurvivorRatio=6    # Eden:Survivor

# 元空间
-XX:MaxMetaspaceSize=256m

# GC 日志
-XX:+PrintGCDetails
-XX:+PrintGCDateStamps
-Xloggc:gc.log
```
