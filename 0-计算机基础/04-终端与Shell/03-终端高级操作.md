# 终端高级操作

## 定义

终端多路复用器在单个终端进程内管理多个独立会话(Session)，通过分离控制终端与实际终端实现会话持久化：用户可以断开会话（detach）后重新连接（attach），会话内的进程树和状态完整保留。

## 数学模型

### 三级层级结构的状态空间

tmux/screen维护严格的三级嵌套结构：

$$
S_{\text{tmux}} = \{(s_i, w_{i,j}, p_{i,j,k})\ |\ i \in [0, N_s), j \in [0, N_w), k \in [0, N_p)\}
$$

其中 $N_s$ 为会话数，$N_w$ 为会话 $i$ 的窗口数，$N_p$ 为窗口 $j$ 的面板数。

**会话状态持久化**：当tmux server收到`detach`信号时，将所有Pane的像素缓冲区写入磁盘分区（默认`/tmp/tmux-$(id)/`）：

$$
\text{持久化条件} = \text{detach} \lor \text{服务器重启} \lor \text{显式} \verb|socket| \text{断开}
$$

恢复时重新attach，server从磁盘读取快照重建Pane内容。

### 同步面板的广播延迟

开启同步面板后，所有Pane接收完全相同的输入，广播延迟为：

$$
T_{\text{broadcast}} = T_{\text{网络}} + T_{\text{tmux处理}} + T_{\text{终端渲染}}
$$

在本地socket场景下，$T_{\text{broadcast}} \approx O(1)$，人类感知不到延迟。

**数据形态变换**：

| 阶段 | 数据形态 | 编码方式 |
|------|----------|----------|
| tmux client→server | 客户端命令 (如`switch-client`) | 文本协议 |
| tmux server内部 | 结构化Pane状态 | 进程内存 |
| 持久化文件 | 二进制会话快照 | msgpack/MessageDB格式 |
| 渲染到屏幕 | ANSI转义序列 | 终端控制码 |

## 机制

### 会话生命周期的资源语义

tmux server进程启动时创建Unix domain socket监听连接：

```
tmux new -s name
    │
    ▼
socket("~/.tmux.socket") 创建
    │
    ▼
fork() → exec("tmux", "new-session", "-s", "name")
    │
    ▼
server进程 ──forkpty()──► shell进程 (pts/N)
    │
    ▼
client通过socket连接server，操作被转发为server进程调用
```

**约束**：tmux server是常驻进程，kill命令不接`-server`只kill client。`tmux kill-server`强制终止server，**所有会话立即丢失**（除非已detach并持久化到磁盘）。

**违规后果**：
- 不detach直接断连：会话继续运行但无法交互，进程处于不可达状态
- `kill-server`无确认：所有会话进程收到`SIGHUP`而终止

### 窗口与面板的进程边界

tmux中关闭窗口意味着向该窗口内所有Pane的进程发送`SIGHUP`：

```
关闭Pane 0
    │
    ▼
bash进程收到SIGHUP
    │
    ▼
bash默认行为: 终止
```

**关闭Window vs 关闭Pane**：

| 操作 | 影响范围 | 进程行为 |
|------|----------|----------|
| 关闭Pane | 仅该Pane | 该Pane的进程收到SIGHUP |
| 关闭Window | Window内所有Pane | Window内所有进程收到SIGHUP |
| 关闭Session | 所有Window | 所有会话进程收到SIGHUP |

**约束**：Pane关闭后，Window仍存活（如果还有>=1个Pane）；Window关闭后，Session仍存活。

**违规后果**：在有多个Pane的Window中误关一个Pane会导致该Pane进程终止，已输入未处理的数据丢失。

### 复制模式的缓冲区语义

tmux/scrollback buffer是tmux维护的循环缓冲区，大小由`history-limit`控制（默认2000行/Pane）：

```
Pane输出 ──► 循环缓冲区 (固定大小)
                  │
                  ├── 新行入缓冲，溢出行丢弃
                  │
                  └── Ctrl+b [ 进入复制模式
                          │
                          ▼
                      copy-mode: 只读遍历缓冲区
```

**约束**：
- 复制模式是只读状态，终端不处理任何输入
- `q`或`Escape`退出复制模式，恢复正常输入状态
- 缓冲区有上限，旧行自动丢弃

**违规后果**：长会话的早期输出会被自动裁剪，无法检索。

### 同步面板的广播语义

`synchronize-panes on`命令改变tmux的输入路由：

```
正常模式：
  按键 → 当前Pane → 该Pane进程

同步模式：
  按键 → 所有Pane（同时接收相同输入）
```

**约束**：
- 同步仅对**同一Window内**的Pane生效，不同Window的Pane不受影响
- 同步开启后，单次按键会在所有Pane产生相同的bash历史记录
- 如果某个Pane正在运行交互式程序（如vim），同步输入可能导致所有Pane都接收到vim命令

**违规后果**：在同步模式下对vim等交互式程序输入，会导致vim命令被广播到所有Pane，可能破坏其他Pane的状态。

### 会话命名与唯一性约束

tmux会话通过`-s name`指定的名称标识，具有全局唯一性：

```
tmux new -s dev      # 创建名为dev的会话
tmux new -s dev      # 错误: 会话已存在
tmux new -s dev2     # 正确: 不同名称
tmux attach -t dev   # 附加到已存在的dev会话
```

**约束**：
- 会话名称在同一tmux server内唯一
- 不同server（不同用户、不同socket路径）可以有同名会话
- attach已存在的会话会在现有client外再创建一个client，多client共享同一会话状态

## 对比参照

| 维度 | tmux | screen |
|------|------|--------|
| 会话持久化 | 需detach才持久化；server重启丢失 | 需detach才持久化 |
| 状态存储 | 磁盘持久化(attach时重建) | 磁盘持久化(attach时重建) |
| 窗口层级 | Session→Window→Pane (三级) | Session→Window (两级，无Pane) |
| 分割方式 | 水平/垂直Pane | 水平分割(Regions)，无垂直分割 |
| 复制模式 | Ctrl+b [ | Ctrl+a [ |
| 配置语法 | set -g option value | set option value |
| 远程支持 | -CCC协议(支持多client) | 仅本地socket |

## 参考存根

```bash
tmux new -s session -d     # 后台创建会话
tmux ls                   # 列出所有会话
tmux attach -t session    # 附加到会话
tmux splitw -h -p 50       # 水平分割当前Pane，50%
tmux send-keys "cmd" C-m   # 发送命令到Pane
```
