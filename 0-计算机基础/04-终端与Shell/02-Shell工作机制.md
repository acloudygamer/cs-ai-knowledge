# Shell 工作机制

## 核心定义：一个没有任何特权的普通进程

shell（bash、zsh、fish）不是内核的一部分，也不是特权程序——它就是 03-进程与线程 里的一个普通用户态进程，stdin/stdout 接着 pty（01 篇），干一个循环：**读一行 → 解析 → 执行 → 打印提示符，等下一行**。它能"管理"系统，靠的不是特权，而是它替你调用系统调用：fork、execve、pipe、dup2、open——《系统软件层》02 的那些门，shell 是它们最勤奋的用户。

## 执行外部命令：fork + exec 的流水线

你敲 `ls -l /tmp`，shell 做的事：

1. **解析与展开**（下文细说）：把这行字节变成参数数组 `["ls", "-l", "/tmp"]`；
2. **fork**：复制一个自己（03 的 COW，开销极小）；
3. 子进程里：按 `PATH` 逐个目录找可执行文件 `/bin/ls`；
4. **execve**：换脑子（02-链接与装载 的装载链在此启动）；
5. 父进程（shell 自己）`wait()` 等待，收退出码，打印下一个提示符。

执行脚本多一层内核机制：脚本首行 `#!/bin/bash`（shebang）被内核的 binfmt_script 识别——`execve` 一个文本文件时，内核读 `#!` 后的解释器路径，改为执行"解释器 + 脚本路径作参数"。所以 `./script.sh` 等价于 `/bin/bash script.sh`，这是内核级机制，不是 shell 的魔法。前提：文件有执行权限位（05-文件系统 的 inode 元数据）。

## 展开：一行命令被改写的精确顺序

执行前，shell 先把这行文字按固定顺序改写一遍。bash 的顺序：花括号展开 → 波浪号（`~`）→ 变量（`$x`）→ 算术（`$(( ))`）与命令替换（`$( )`，左到右）→ **分词**（按空白把展开结果切成参数）→ 通配符展开（`*` `?`）→ 引号移除。

分词在展开**之后**，这是大量 shell bug 的根源：

```bash
files="a.txt b.txt"
cat $files      # 展开后分词 → cat a.txt b.txt（两个参数）
cat "$files"    # 加引号阻止分词 → cat "a.txt b.txt"（一个参数，报错）
```

引号的语义由此清晰：**单引号是强引用**（内部什么都不展开），**双引号是弱引用**（只放行 `$`、反引号、`\`，但阻止分词和通配）。"什么时候加引号"不是风格问题，是在控制这条展开流水线在哪一步停。

再钉一句通配符的归属：**展开由 shell 完成，不是命令**。`rm *.txt` 里 rm 收到的是已经展开好的文件名列表，`*` 永远到不了 rm。两个直接推论：你的程序想支持 `*` 不用自己写匹配；想把字面 `*` 传给程序（比如 `find -name "*.txt"`），必须加引号阻止 shell 动手。

## 管道与重定向：fork 之后的 fd 手术

管道和重定向不是程序的功能，是 shell 在 `fork` 与 `execve` 之间对子进程文件描述符表做的手术（文件描述符与 `pipe()` 见《系统软件层》02/05）：

- **`cmd > out.txt`**：子进程 fork 后，先 `open("out.txt")` 拿到 fd，再 `dup2` 把它盖到 fd 1（stdout）上，然后 exec——新程序的 stdout 天生就指向文件，程序自己毫无知觉。
- **`a | b`**：shell 先 `pipe()` 造一根内核管道（一对 fd），fork 两次：a 的 stdout dup2 到管道写端，b 的 stdin dup2 到读端。两个进程**并发**跑，数据流在内核缓冲区里接力——管道不是"a 跑完把结果给 b"，是边产边消，写端满了 a 被阻塞、读端空了 b 被阻塞（03 的状态机在管道两端上班）。

**stderr 是独立的第三条流**：fd 0 是 stdin、1 是 stdout、2 是 stderr——错误信息走单独通道，所以 `cmd > out.txt` 之后错误照样打在终端上。`2> err.txt` 单独重定向它；`2>&1` 的意思是"把 2 号盖到 1 号当前指向的地方"。顺序敏感：`cmd > out.txt 2>&1`（先把 1 盖到文件，再把 2 盖到 1 现在的位置=文件）是全捕获的正确写法；反过来 `2>&1 > out.txt` 里 2 号盖到的是 1 号**当时**的指向（还是终端）——fd 手术按书写顺序逐步生效，这个经典写法的全部机制就在这里。

**内建命令是例外**：`cd`、`exit`、`export`、`alias` 必须由 shell 自己执行，不能 fork——约束很硬：**子进程改不了父进程的状态**（cwd 是每进程属性，环境变量在 fork 时复制）。`cd` 若做成外部命令，改的是子进程的 cwd，子进程退出后 shell 还在原地。判断一个命令是不是内建，就问它改的状态在谁身上。

## 作业控制：进程组与前台

shell 以**进程组**为单位管理作业：一条管道线上的所有进程进同一个组。pty 前的**前台进程组**只有一个——01 篇里 tty 驱动发 SIGINT 的目标就是它。`Ctrl-Z`（SIGTSTP）把前台组暂停并交还 shell；`bg` 发 SIGCONT 让它在后台续跑；`fg` 把它拉回前台；命令尾部加 `&` 直接后台启动。`jobs` 列的就是 shell 记着的进程组清单。

## 退出码：一切控制流的货币

每个进程退出时交回一个 0~255 的整数：**0 表示成功，非 0 表示失败**（约定，具体值各家自定义）。shell 把它放在 `$?` 里，而 `&&`、`||`、`if`、`while` 全部只认退出码：

```bash
grep -q root /etc/passwd && echo 有   # grep 找到=退出 0
if [ -f a.txt ]; then ...             # [ 是个命令！它返回退出码，if 只读码
```

`if`/`while` 不判断"真假"，判断的是**命令的退出码**——`[`（即 `test`）是个普通命令，表达式求值后以退出码交卷。管道的退出码默认取最后一个命令的，`set -o pipefail` 改为任一环节失败即整体失败。退出码是 shell 世界里唯一的布尔类型，03 篇的所有控制流都建立在这一个整数上。
