# Shell 编程

## 核心定位：粘合系统调用的最短路径

Shell 脚本的合法身份是**粘合剂**：把现成的命令（每个都是别人写好的完整程序）用管道和退出码粘成一条数据流。02 篇给了机制，本篇给使用规则与边界——包括何时停手换 Python。

## 变量与环境：继承规则决定可见性

- 赋值 `x=1` 两边**不能有空格**（有空格会被解析成"以环境变量 x=1 运行命令"，这不是风格是语法）。
- shell 变量默认是 shell 进程私有的；`export x=1` 把它标记进**环境变量**——fork+exec 时环境被复制进子进程（execve 的 envp，经 02-链接与装载 的装载链压在新进程栈上）。所以"子进程看得到"等价于"export 过"；反过来，子进程改环境永远影响不了父进程（02 的内建命令约束）。
- 命令替换 `$(cmd)` 捕获的是 stdout 文本：词尾换行被剥掉，内容参与展开与分词——`n=$(ls | wc -l)` 整条链是"子 shell 里跑管道 → 输出变文本 → 赋值"。

## 控制流：退出码驱动的 if 与循环

02 篇确立的原则在这里兑现：`if`、`while`、`until` 判断的全部是**退出码**。

```bash
if [ -f "$f" ] && [ -r "$f" ]; then ...   # [ 是命令，-f/-r 是它的参数
while IFS= read -r line; do               # 逐行读文件的标准写法
  echo "$line"
done < input.txt
```

 `[ ]` 两侧必须有空格——因为 `[` 是命令名，空格是分隔参数的语法，不是美观要求。bash 扩展的 `[[ ]]` 不做分词和通配展开、支持 `=~` 正则，写 bash 时优先用它。

## 管道组合模式：三个主角的边界

Unix 文本处理的惯例是**小工具各管一段，管道串联**。三个主角的分工：

- **grep：选行**。按正则留下匹配的行（`-v` 反选、`-c` 计数）。
- **sed：改流**。逐行编辑，`s/old/new/g` 是主体（`-i` 原地改文件）。
- **awk：按列处理**。默认按空白分列，`$1 $2` 引用列；内建累加、关联数组，是"行式表格"的处理器。

组合范式：`grep 选出要的行 | awk 取要用的列 | sort | uniq -c | sort -nr`——日志统计、Top-N 这类任务的骨架。判断该用谁，就问数据此刻的形状：按行过滤 grep，按行改写 sed，按列计算 awk。

两个配角的定位：**find** 按属性选文件（`find . -name "*.log" -mtime +7`——按名字、时间、大小），产出文件名单；**xargs** 是管道与参数之间的桥——有些命令（rm、cp）不读 stdin 只收参数，`find ... | xargs rm` 把上游的字节流切成一批批参数喂给命令。文件名带空格会把 xargs 切碎，配套写法是 `find -print0 | xargs -0`（改用 NUL 字节分隔）——又回到 02 的分词问题。

## 防御性写法与常见陷阱

脚本开头的一行三件套：

```bash
set -euo pipefail
# -e：任何命令失败（退出码非 0）立即终止脚本
# -u：引用未定义变量即报错（而不是静默展开成空串）
# pipefail：管道任一环节失败即整体失败（02 篇）
```

调试时再加 `set -x`：每条命令执行前把**展开之后**的样子打印出来——排错时直接看见展开流水线的产物，不用再猜 shell 到底执行了什么。

高频陷阱，全部能从 02 的展开机制推导出来：

| 陷阱 | 机制根源 |
|------|---------|
| `rm -rf $dir/` 在 `$dir` 为空时删根目录 | 未加引号的空变量展开后分词出**零个参数**，剩 `rm -rf /` |
| `if [ $x = 1 ]` 在 `$x` 为空时报语法错 | 展开后变成 `[ = 1 ]`，`[` 收到残缺参数 |
| `for f in $(ls)` 遇到带空格的文件名就碎 | 命令替换结果要过分词 |
| 脚本里 `cd` 进目录，外面没变化 | 正确：这是子 shell/脚本进程的 cwd（02 的约束） |
| 管道里 `while read` 改的变量，出来就没了 | 管道每一段都是子进程（02 的 fd 手术），子进程改不了父进程的变量 |

对策几乎永远是同一个动作：**给变量加双引号**（`"$dir"`、`"$x"`），让展开停在分词之前。

## 边界：何时放下 shell

shell 的账到某个复杂度就还不上了，信号清单：需要**数据结构**（嵌套的 dict/list——shell 只有字符串和字符串数组）、需要**错误处理**（try/catch 级别，退出码不够用）、需要**可测试**、逻辑超过一屏。过线就换 Python（2-Python 文件夹）——它同样能调子进程（`subprocess`），但换来真实的类型、异常和测试设施。判断准则一句话：**shell 管粘合，Python 管逻辑**；让命令之间流动的归 shell，让判断和状态生长的归 Python。
