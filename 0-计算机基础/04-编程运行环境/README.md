# 编程运行环境

> **版本基准**: universal（Windows 11 / Ubuntu 24.04；运行时锚点 CPython 3.12 / V8 13.6（Node 24）/ Go 1.27 / OpenJDK 21）

本章建立在 01-计算机体系 与 02-操作系统 之上，回答一个单向问题：**一份 `.c` 源文件如何逐级变成一个正在运行的进程，以及一个函数被调用时栈上究竟落了哪些字节。**

本章消费哪些前置机制（不再重推）：

- 01 卷 03 的取指-译码-执行三段式、变长解码代价、ROB 顺序退休与精确异常、`call/ret` 与 RSB —— 决定后端编码约束、缺页陷入时机、去优化点必须落在指令边界。
- 01 卷 04 的 ISA/微架构分界、CISC/RISC 寄存器模型、SIMD 寄存器宽度 —— 决定指令选择与 JIT 向量化的上限。
- 01 卷 02 的 64B 缓存行、指令缓存取指带宽、MSHR 与 TLB 覆盖率墙 —— 代码尺寸因此也是性能量，代码页大页收益由此而来。
- 02 卷 04 的 mmap/VMA、缺页、写时复制、保留与提交之差 —— 装载与托管堆向 OS 要页的唯一通道。
- 02 卷 05、06 的页缓存、inode 与 fd 路径 —— 决定首次缺页是 minor 还是 major，也是 `execve` 与动态链接器读文件的实际开销所在。
- 02 卷 03 的线程与调度实体 —— 运行时的线程/协程封装都建立在其上。

三篇构成一条严格单向链：**01 产出目标文件 → 02 把目标文件铺成进程映像 → 03 在映像内建立栈帧、解释器主循环与 GC**。

## 学习路径

1. **先 01-编译与解释**：从字符流走到目标汇编与字节码，建立"变换链每站只增删信息、不回头"的单向直觉；AOT/JIT 分水岭在此立账。
2. **再 02-链接与装载**：把 01 的 `.o` 逐级拼成进程映像——符号解析先于地址回填，地址回填先于重定位，装载只改 VMA 元数据，物理页由缺页按需给。
3. **后 03-运行时与虚拟机**：在已就位的映像内接管栈与堆，落出调用约定、栈帧、解释器循环、JIT 回退与 GC 停顿——链路终点即"函数被调用时栈上发生了什么"。

顺序不可交换：02 的重定位依赖 01 的节区划分，03 的栈帧与 GC 根集依赖 02 的装载结果与 01 的指令边界语义。
