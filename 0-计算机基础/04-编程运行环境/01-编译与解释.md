# 编译与解释

## 一、变换链总览：六站单向流水与每站的产物落点

### 1.1 六站主干：一条不回溯的漏斗

```text
        ┌──────────────── 回边 A：宏调用点文本替换 / 头文件递归包含 ────────────────┐
        │                                                                          │
 源文件 │
 .c ────┴─► [1 预处理] ─► [2 词法] ─► [3 语法] ─► [4 IR+优化] ─► [5 后端] ─► [6 汇编/编码]
              │ .i           │ token 流     │ AST          │ CFG/SSA        │ .s          │ .o
              │ 丢注释/空白   │ 丢空白/注释   │ 丢语法糖      │ 丢控制结构形状   │ 选定 ISA     │ 留重定位
              ▼              ▼              ▼              ▼                ▼             ▼
          文本流          二元组序列        树              图（基本块）      汇编文本      节区+符号表
        └──────────────── 回边 B：内联 / 循环展开（站 4 内部重写） ────────────────┘
```

六站构成一条不回溯的漏斗：每一站的输出是下一站的唯一输入，每一站也都能单独落盘。图中每个节点的上排是物化产物，下排是该站丢弃的信息——丢弃项下游无法再取回，因此「产物形态 + 丢弃项」才是这一站的完整契约。

- **站 1 预处理**：字符流进、字符流出。宏体在调用点被文本替换，替换完成后源码里不再保留任何「这是一次宏调用」的边界；未选中的条件编译分支连字节都不进入后续流水。
- **站 2 词法**：把 `.i` 切成 `(类别码, 词素)` 二元组。空白与注释在此彻底消失（只留行号供诊断），保留字被折叠为单一类别码——源码的排版信息从此不可恢复。
- **站 3 语法**：token 流按文法产生式在归约栈上归约成 AST。括号与语法糖的具体写法被抹平，`a[i]` 与 `*(a + i)` 归约为同一棵子树；留下的是优先级与结合性已解算完毕的父子边。
- **站 4 IR 与优化**：AST 降为控制流图，再转静态单赋值形式。`for` 与 `while` 的源级形状消失，同一张图上前端不可见的等价性（公共子表达式、循环不变量）才第一次可见。
- **站 5 后端**：图落到具体指令集，依次完成指令选择、寄存器分配与调度。虚拟寄存器编号被物理寄存器或栈槽取代，抽象宽度坍缩为真实寄存器宽度。
- **站 6 汇编与编码**：汇编文本按 ISA 编码规则压成二进制节区，未解析符号与重定位项留给链接侧。这一步是纯投影，不再做任何语义决策。

量级上，站 1 到站 3 都是对输入的线性单遍扫描，复杂度为 $O(n)$ 的字节级推进；站 4 是唯一超线性的站（数据流方程按迭代轮数反复扫全图）；站 6 的编码时间占比通常不足 5%，但它的字节布局决定了第 7 节要观测的全部落点。

### 1.2 每站契约：产物可单独落盘

| 站 | 输入 | 产物与落盘开关 | 扫描复杂度 | 可逆性 |
| --- | --- | --- | --- | --- |
| 1 预处理 | `.c` 源文件 + 头文件树 | `.i` 展开文本，`gcc -E` | 展开后文本的 $O(n)$ 单遍替换 | 不可逆：宏边界已丢失 |
| 2 词法 | `.i` 字符流 | token 流，词法错误即停 | $O(n)$ 的 DFA（Deterministic Finite Automaton，确定型有限自动机）逐字节推进 | 不可逆：注释与空白已丢弃 |
| 3 语法 | token 流 | AST，`clang -Xclang -ast-dump` | $O(n)$ 的下推栈单遍归约 | 近似可逆：反打印会丢括号写法 |
| 4 IR 与优化 | AST | CFG（Control Flow Graph，控制流图）/ SSA，`-emit-llvm -S` 得 `.ll` | 超线性：每轮 $O(n)$ 扫描，轮数不定 | 不可逆：语义等价写法被合并 |
| 5 后端 | IR | `.s` 汇编，`gcc -S` | 指令选择近似 $O(n)$ 规模，分配为 NP-hard 的启发式 | 不可逆：物理化后无虚拟寄存器 |
| 6 汇编编码 | `.s` | `.o` 节区，`gcc -c` / `as` | $O(n)$ 的逐行编码 | 近似可逆：`objdump -d` 丢符号与注释 |

三站前端的 $O(n)$ 是「按字节计」的线性，不是「按源码行」的线性：站 1 的真正输入是展开后的文本，头文件递归包含使同一份 100 KB 源码在 `-E` 之后常达 1~10 MB，膨胀 10~100 倍。因此前端耗时对包含深度敏感，而对其后各站的耗时没有同阶影响。

token 数是这一流水上第一个可数的中间量，经验上约为源码字节数的 1/3 到 1/5；AST 节点数又约为 token 数的 0.3~0.6 倍——被合并掉的差额正是语法糖在归约时消失的那部分。两个比值都随语言与缩进风格漂移，但量级稳定，可作为估算中间产物规模的锚点。

可单独落盘带来一个可直接利用的性质：整条链可以在任意站的出口切片观测，`.i`、token 流、AST、`.ll`、`.s`、`.o` 六个切片分别是同一份输入的不同投影。第 7 节把这六个切片按同一函数对齐，本节的契约就是那张对照表的行定义。

### 1.3 两条回边与代价守恒

| 阶段 | `-O0` 时间占比 | `-O2` 时间占比 | 主要成本项 |
| --- | --- | --- | --- |
| 前端三站（含预处理） | 35%~50% | 20%~30% | 字符扫描、符号表插入 |
| 中端优化 | < 5% | 30%~50% | 数据流迭代、内联与展开 |
| 后端（选择/分配/调度） | 40%~55% | 20%~30% | 图覆盖、着色冲突、溢出重写 |
| 汇编编码 | < 5% | < 5% | 文本解析与字节发射 |

上表给的是典型量级与排序，具体比例随语言前端与 ISA 漂移，但方向稳定：`-O0` 的编译时间由前端与后端对半分，优化几乎免费；`-O2` 把最大的一块时间搬到了中端，优化 > 语法分析 > 代码生成的排序即由此成立。

两条回边都不跨站，这是「单向」的准确含义：

- **回边 A（站 1 内部）**：宏调用点替换与头文件递归包含都是文本级的就地重写，展开结果仍从站 1 出口流出。它抬高的是站 1 的输入规模，膨胀 10~100 倍，代价直接体现为前端耗时同阶增长。
- **回边 B（站 4 内部）**：内联与循环展开在 IR 上重写函数体，重写结果仍在站 4 内继续迭代。内联按函数体语句数截断，典型阈值是数十条语句，超阈值即放弃——放弃的理由是代码尺寸（进而指令缓存占用）会反向抵消内联收益。

回边 B 的账本方向明确：以编译时间为代价换执行指令数。`-O2` 相对 `-O0` 的指令条数落在 0.4~0.8 倍，代价是编译时间放大 3~10 倍；两侧都随优化等级单调变化，因此「最优点」不存在于编译侧，只存在于第 6 节的运行次数维度上。

## 二、词法与语法：字符流被 DFA 与归约栈逐级切分

### 2.1 词法站：DFA 逐字节推进，最长匹配只回退一格

```text
              ┌──── 字母/数字/下划线 ────┐
              │                          ▼
   q0(起始) ──字母──► q1(标识符) ──'='──► q2(运算符) ──'='──► q3(判等)
      │                  │                  │
      └──数字──► q4(数值) └──其他──► 回退 1 字节，发射 (IDENT, lexeme)

   输入字节:  t o t a l   =   =   0   ;
   状态轨迹:  q1 q1 q1 q1 q1 q2 q3  q4  q0
   发射序列:  (IDENT,total) (EQ,==) (NUM,0) (SEMI,;)
```

每个字节只被读一次并查一次转移表，因此主循环是单遍的 $O(n)$ 推进。唯一的前瞻发生在最长匹配的边界上：读到 `=` 之后必须先看下一字节才能决定发射 `=` 还是 `==`，回退量至多 1 字节，总读入次数不超过 2n。关键字识别放在 DFA 之后，用完美哈希对词素做一次 $O(1)$ 判定，失败即回落到标识符类别——这一步不引入第二次扫描。

词法站真正决定的是「保留什么」：类别码 1~2 B，词素本身不复制，只留一个指向源缓冲的指针（8 B 档）。行号必须保留供诊断，列号可以丢弃。于是同一段源码进入内存后的 token 流体积约为源文本的 2~4 倍——变大的原因是每个 token 都补齐了定长头部，不是因为保留了更多信息。

### 2.2 语法站：移进-归约栈，每次归约净减 k−1 格

```text
 步  符号栈（自底向上）                  读入    动作
 1  [ ]                                IDENT   shift
 2  [ IDENT ]                          =       reduce  IDENT → Primary   (k=1, 净 0)
 3  [ Primary ]                        =       shift
 4  [ Primary = ]                      NUM     shift
 5  [ Primary = NUM ]                  +       reduce  NUM → Expr        (k=1, 净 0)
 6  [ Primary = Expr + Expr ]          ;       reduce  Expr + Expr → Expr (k=3, 净 −2)
 7  [ Stmt ]                           EOF     accept
```

移进压入 1 个状态与 1 个符号；归约弹出产生式右部的 k 个符号、压入 1 个非终结符，栈深净变化为 1−k。每个 token 至多触发一次移进，归约链的长度平均 1~2 步，因此总动作数与 token 数同阶，语法站仍是 $O(n)$ 档——但常数比词法站高一个档位，因为每一步都要查 ACTION/GOTO 表并申请一个 AST 节点。

错误恢复走恐慌模式：栈无法归约时丢弃 token 直到同步集（`;`、`}`、EOF 一类 FOLLOW 集元素），已归约完成的子树原样保留、不回退重算。恢复代价等于被丢弃 token 的数量乘以每 token 的 $O(1)$ 跳过成本，与已解析部分的规模无关——这正是「丢弃到同步集」而不是「回退到上一个可行状态」的原因：后者会把代价重新拉回已解析子树的大小。

AST 节点数约为 token 数的 0.3~0.6 倍。差额来自归约时的合并：括号、逗号分隔符、以及 `a[i]` 与 `*(a + i)` 这类等价写法在树上只留一份。

### 2.3 token 类别对照：谁被保留、谁在词法层消失

| token 类别 | 例 | 保留的信息 | 丢弃的信息 | 下游消费者 |
| --- | --- | --- | --- | --- |
| 关键字 | `while` | 类别码（独占一个编号） | 拼写、大小写形式 | 语法站，直接进产生式选择 |
| 标识符 | `total` | 类别码 + 符号表索引 | 出现次数、原始拼写 | 语法站建叶子，语义站查符号表 |
| 字面量 | `0x1F`、`"abc"` | 类别码 + 已解码的值 | 进制、下划线分隔、转义写法 | 常量折叠（第 3 节） |
| 运算符/分隔符 | `==`、`;` | 类别码（复合运算符单列） | 前后空白、行内位置 | 语法站决定移进或归约 |
| 注释 | `/* ... */` | 无（可选的文档注释除外） | 全部字节 | 无——在站 2 出口即消失 |
| 空白/换行 | 空格、`\n` | 通常无 | 全部字节；行号另存 | 无（诊断表除外） |
| 行标记 | `#line 42` | 逻辑行号与文件名 | 物理行号 | 诊断与调试信息 |

这张表的例外恰好标出「空白并非总是可丢」的边界：Python 用缩进定界，换行与行首空格必须先折叠成 INDENT/DEDENT 两个虚拟 token 才能进入语法站；JavaScript 的自动分号插入使换行携带 1 bit 的「前一个 token 可结束语句」状态。两处的处理方向一致——不保留空白字节，只保留空白所承载的定界语义，且该语义被压缩成一个 token 或一个标志位。

词法错误与语法错误的停止条件也不同：前者是 DFA 停在非终态（未闭合字符串、非法字符），栈尚未参与；后者是栈顶状态在该 token 上没有合法动作（缺 `;`、括号不配对），此时 DFA 早已成功。两类错误的分界就是第 1 节六站的分界。

## 三、中间表示与优化：SSA、支配树与不动点迭代

### 3.1 AST → CFG → SSA：φ 节点只落在支配边界

```text
            ┌────────────────────────────┐
            │ B0:  x1 = 1                │
            └───────┬───────────┬────────┘
             true   │           │  false
                    ▼           ▼
        ┌────────────────┐  ┌────────────────┐
        │ B1: x2 = x1+1  │  │ B2: x3 = x1*2  │
        └───────┬────────┘  └───────┬────────┘
                └────────┬──────────┘
                         ▼
            ┌────────────────────────────┐
            │ B3: x4 = φ(x2, x3)         │
            └────────────────────────────┘

  dom:  B0 ≺ B1, B0 ≺ B2, B0 ≺ B3
  DF(B1) = {B3}，DF(B2) = {B3}  ⇒  φ 只在 B3 插入一次
```

AST 降为控制流图后，每个基本块是一段无分支的指令序列，块间的边就是跳转。支配树由「从入口到该块的所有路径都经过它」定义，支配边界 DF 则是「该块的定义能到达、但该块并不支配」的第一批汇合点——φ 节点必须且只需插在 DF 上，插多处会产生冗余 φ，插少处会切断 def-use 链。

量化差距在查找方式上：非 SSA 形式下，一条 use 要找它的 def，需沿支配树回溯扫描可达定义，单次最坏 $O(n)$，全函数累计到 $O(n^{2})$ 档；SSA 形式下每个变量名只有一个 def，def-use 是显式双向边，单次访问 $O(1)$，边总数与变量数同阶（典型 2~4 倍）。这一步的收益方向是把「搜索」换成「存储」：内存占用上升，分析时间从平方档降到线性档。

### 3.2 数据流方程：有限格上的最小/最大不动点

```math
\begin{aligned}
\mathrm{IN}[B] &= \bigcup_{P \in \mathrm{pred}(B)} \mathrm{OUT}[P] \\
\mathrm{OUT}[B] &= \mathrm{GEN}[B] \cup \left( \mathrm{IN}[B] \setminus \mathrm{KILL}[B] \right)
\end{aligned}
```

```math
\mathrm{LIVE}_{\mathrm{in}}[B] = \mathrm{USE}[B] \cup \left( \mathrm{LIVE}_{\mathrm{out}}[B] \setminus \mathrm{DEF}[B] \right)
```

上两式是同一条模板的两个方向：到达定值沿前向边求并集（may 分析，汇合符为 $\cup$），活跃变量沿后继反向求并集（同样是 may，但传播方向相反）。汇合符选并集还是交集，决定了分析回答的是「可能」还是「必然」——可用表达式取交集才是 must 分析，取并集只会得到保守的空集。

迭代在有限格上进行：每次迭代把每个块的 IN/OUT 朝不动点推进一步，格高度有限保证终止，每轮扫全图 $O(n)$，轮数典型 2~5，最坏上界是格高度乘以图直径。worklist 算法把每轮的 $O(n)$ 压到「只重算输入发生变化的块及其后继」，实际总成本接近线性——这是优化器在百万行级函数上仍能跑完的原因。

### 3.3 优化档位：变换集 × 指令倍率 × 编译时间倍率

| 档位 | 新增开启的变换（GCC 13.2 口径） | 指令条数（相对 `-O0`） | 编译时间（相对 `-O0`） |
| --- | --- | --- | --- |
| `-O0` | 无，变量全部落栈，便于逐句调试 | 1.00× | 1× |
| `-O1` | 窥孔、常量折叠/传播、CSE、死代码删除、尾调用 | 0.7~0.9× | 1.5~2.5× |
| `-O2` | 上述 + 内联、循环不变量外提、强度削弱、very-cheap 代价模型的自动向量化 | 0.4~0.8× | 3~10× |
| `-O3` | 上述 + 激进向量化、循环交换与分布、函数克隆、循环展开 | 0.35~0.75× | 5~20× |

倍率的走向并不单调：`-O2` 到 `-O3` 的指令条数还能再降约一成，代码尺寸却可能涨到 1.2~2 倍，指令缓存压力反向抵消收益；内联的收益同样在函数体超过数十条语句的阈值后转为负值，因此阈值截断不是保守，而是收益曲线本身在那里过零。

变换顺序影响最终结果：内联放在常量传播之前，被调者内部能看到调用点传入的常量并据此折叠分支；反过来则只能看到已经折叠完的调用点实参，被调者内部的死分支仍然留下。同一组变换、两种顺序，走的是两条不同的不动点路径，落到的指令条数可以相差数个百分点。

## 四、后端：指令选择、寄存器分配与调度

### 4.1 四步主干与溢出回边

```text
  IR（SSA，虚拟寄存器无限）
    │
    ▼
[4.1 指令选择]  DAG 覆盖：每个 IR 节点匹配一条目标指令模板
    │           代价模型：先压指令条数，再看寄存器压力
    ▼
[4.2 寄存器分配]  活跃区间 → 冲突图 → k 着色（k = 物理寄存器数）
    │      ▲
    │      └── 溢出回边：着色失败 → 插入 store/load → 重算活跃区间
    ▼
[4.3 指令调度]  在数据依赖与延迟约束下重排，填充分支与访存延迟
    │
    ▼
   .s 汇编（物理寄存器已定，栈帧已定）
```

四步都是对同一张图的连续重写，只有 4.2 带一条回到自身的回边。指令选择把「一条 IR 节点」映射为「一条或多条目标指令」，选择结果直接决定寄存器压力；分配失败时不是退回 4.1 重选，而是在 4.2 内部把某个变量溢出到栈槽，用两条访存指令换一个空闲寄存器，然后重新着色。这条回边每转一圈，栈帧就多 4~8 B，函数的访存次数随之上升——所以它的终止条件不是「一定能着色」，而是「溢出次数不再下降」。

### 4.2 指令选择：两套 ISA 的编码与寻址对照

| 维度 | x86-64（CISC） | AArch64（RISC） |
| --- | --- | --- |
| 指令编码 | 变长 1~15 B，常见 3~7 B | 定长 4 B，字对齐 |
| 译码入口 | 必须先解出长度才能定位下一条 | `pc + 4` 恒定，可并行预取 |
| 寻址模式 | 基址 + 索引×比例 + 位移，一条指令可含 2 个内存操作数 | 基址 + 立即数偏移，装载与运算分离 |
| 通用寄存器 | 16 个（含栈指针） | 31 个 |
| 同一函数代码尺寸 | 基准 1.0× | 1.1~1.4×（指令条数多，但每条定长） |
| 向量宽度 | SSE/AVX2/AVX-512，128/256/512 bit 分档 | NEON 128 bit，SVE 可变长 |

同一段源码在两套 ISA 上的指令条数差可达 1.5~2 倍，代码字节数的差距却小得多：x86-64 用变长编码把常用操作压进 3~5 B，AArch64 用更多条定长指令换译码的确定性。方向很明确——CISC 把复杂度放在译码器，RISC 把它放在指令条数。前端优化在两侧是同一套 IR 变换，差别只在 4.1 的模板库与代价模型。

自动向量化只在目标 ISA 提供对应宽度的向量寄存器时触发：同一段循环在 AVX-512 上可一次处理 16 个 32 位元素，在只有 NEON 128 bit 的机器上只能处理 4 个，指令条数的下降幅度按宽度线性缩放，但前提是循环体的访存对齐与别名分析都通过。宽度本身由 01 章 03 §四.1 给定，本篇只消费这个前提。

### 4.3 寄存器分配与调度：NP-hard 的启发式与溢出账本

```text
 活跃区间:   a ├──────────┤          b     ├──────┤      c        ├────┤
 冲突边:     a—b（区间重叠）   b—c（区间重叠）   a 与 c 不重叠
 k = 2:      a→R1  b→R2  c→R1        （a、c 复用同一寄存器，零溢出）
 k = 1:      b 无处可去 → 溢出 b → store/load 环绕 b 的每次引用 → 重着色
```

冲突图的 k 着色是 NP-hard，实际编译器用 Chaitin 式简化（反复删除度数小于 k 的节点，删不动即溢出）或线性扫描（按区间起点排序，一次扫描， $O(n \log n)$）。图着色质量更好但编译成本高一个档，线性扫描快但溢出更多；`-O2` 及以上走图着色，`-O0` 干脆把变量全落栈，跳过分配。

溢出的代价可直接计价：一个被溢出的变量，在每个定义点加 1 条 store，在每个使用点加 1 条 load；若该变量位于内层循环，每条访存按 L1 命中 4~5 拍的档位计入，循环体指令数可能因此上涨 10%~30%。典型函数的溢出次数落在 0~3 次，超过这个范围通常说明函数体内的同时活跃变量数已经超出物理寄存器预算，该由内联阈值或函数拆分来处理，而不是继续加压给分配器。

调度在分配之后进行，只允许在不改变数据依赖的前提下重排：把长延迟操作（除法、访存）提前发射，用独立的算术指令填满等待窗口。x86-64 由硬件乱序执行兜底，静态调度收益有限；顺序发射的核（部分嵌入式 AArch64、GPU）上，调度质量直接决定 IPC 的一半。

## 五、字节码：栈式与寄存器式的指令格式投影

### 5.1 位标尺：一条字节码的字节切分

```text
 CPython 3.12（定长 2 B）
 ┌──────────┬──────────┐
 │  opcode  │  oparg   │   pc += 2 恒定
 │  [7:0]   │  [7:0]   │   oparg 超 255 时前置 EXTENDED_ARG，拼成 16/24 bit
 └──────────┴──────────┘

 V8 13.6 Ignition（变长 1~7 B）
 ┌──────────┬────────────────────┐
 │  opcode  │  operand(s)        │   pc 前进量由 opcode 隐含，先查表
 │   1 B    │   0~6 B            │   寄存器索引按 1/2/4 B 三档变长编码
 └──────────┴────────────────────┘

 JVM 21（1~5 B）
 ┌──────────┬──────────────────────┐
 │  opcode  │  operands（按指令定宽）│   `aload` 2 B，`invokevirtual` 3 B
 └──────────┴──────────────────────┘
```

定长编码把「下一条指令在哪」变成一次加法，代价是每个操作数固定吃掉 1 B，小整数与大索引一视同仁；变长编码把这两件事都交给 opcode 隐含的宽度表，省下的是体积，付出的是每条指令都要先解宽度。CPython 3.12 的 `EXTENDED_ARG` 是第三条路：定长主干 + 前缀逃逸，只有常量索引超过 255 时才多花 1 B，绝大多数指令保持 2 B。

指令条数口径必须声明，否则跨运行时无法比较：CPython 的一条字节码对应一次栈操作（`LOAD_FAST`、`BINARY_OP`），V8 的一条对应一次累加器或寄存器操作，JVM（Java Virtual Machine，Java 虚拟机）的一条对应一次栈或局部变量槽操作。三者都按「一条指令 = 一次操作数栈/寄存器动作」计。

### 5.2 三运行时对照：编码、操作数模型与分派

| 运行时 | 指令编码 | 操作数模型 | 分派方式 | 单条体积档 | 相对机器码体积 |
| --- | --- | --- | --- | --- | --- |
| CPython 3.12 | 定长 2 B + 前缀扩展 | 纯栈式，操作数在值栈上 | 计算跳转 switch，按 opcode 特化 | 2 B | 1/4~1/2 |
| V8 13.6 | 变长 1~7 B | 累加器 + 寄存器操作数 | switch + 内联缓存 | 1~7 B | 1/3~1/2 |
| JVM 21 | 1~5 B，按指令定宽 | 纯栈式 + 局部变量槽 | 跳转表 / 直接线程化可选 | 1~5 B | 1/4~1/2 |

字节码体积约为等价机器码的 1/4~1/2，这个比例是拿执行速度换来的：体积小意味着同一段 I-cache 里能装下更多逻辑，分发性好意味着同一份字节码可以喂给解释器、基线编译器或优化编译器三种消费者。代价在 5.3 的分派开销上，也在「一条字节码在机器码侧要展开成 1~3 条指令」的扩展比上——这个扩展比就是解释器的结构性劣势，AOT 直接产出机器码时它根本不存在。

### 5.3 分派：三种实现各自付什么

| 分派方式 | 每条指令的分支数 | 代码体积 | 分支预测友好度 | 适用 |
| --- | --- | --- | --- | --- |
| 计算跳转 switch | 1 次间接跳转 | 最小，主循环只有一份 | 差：所有 opcode 共享一个 BTB 表项 | 指令多、缓存小的场景 |
| 跳转表 | 1 次间接跳转 + 一次表索引 | 中 | 同上 | opcode 编号连续时 |
| 直接线程化 | 每个 opcode 一条直接跳转 | 大，主循环按 opcode 复制 N 份 | 好：每个 opcode 有独立分支历史 | 热点解释器，如 CPython 3.12 的可选构建 |

三者的取舍方向一致：用代码体积换分支预测。switch 版本的主循环只有一份，所有 opcode 抢同一个 BTB 表项，间接跳转的目标在几十个地址间跳动，预测器几乎必然失败；直接线程化把每个 opcode 的处理尾复制一份并以直接跳转相接，分支历史按 opcode 分开，代价是主循环体积膨胀数倍到十几倍，I-cache 压力随之上升。CPython 3.12 的自适应特化是另一条正交的优化：第一次执行某条指令时把它改写成针对实际类型的专用形式，用一次写回的代价省掉后续的类型判断。

## 六、AOT 与 JIT 的分水岭：预热曲线与代价账本

### 6.1 交点 N*：编译成本摊到多少次调用

```text
 单次调用
 时间
  │  解释执行  t_i ────────────────────────────
  │                              ╲
  │  摊销成本  C/N + t_n           ╲___
  │  原生执行  t_n ────────────────────╲────────
  └──────────────────┬─────────────────────────► N
                     N* = C / (t_i − t_n)
       N < N*: 解释更划算          N > N*: 编译更划算
```

```math
\bar{t}(N) = \frac{C_{\mathrm{compile}}}{N} + t_{\mathrm{native}}, \qquad
N^{\ast} = \frac{C_{\mathrm{compile}}}{t_{\mathrm{interp}} - t_{\mathrm{native}}}
```

代入典型档位：单函数编译成本 $C_{\mathrm{compile}}$ 取 1 ms（基线 JIT 的下沿到优化 JIT 的上沿之间），解释执行 $t_{\mathrm{interp}}$ 取 100 ns/次，原生执行 $t_{\mathrm{native}}$ 取 10 ns/次，交点落在 $N^{\ast} \approx 1.1 \times 10^{4}$ 次。方向由分母决定：解释与原生差距越大，交点越靠左；编译越贵，交点越靠右。在 $N = 10^{3}$ 时摊销成本约 1010 ns/次，比纯解释还慢一个档；在 $N = 10^{5}$ 时摊销成本降到 20 ns/次，只剩原生的 2 倍。

这条曲线解释了为什么 JIT 必须分层：单层 JIT 只有「不编译」和「编译到最优」两档，交点被推到万次量级，短命进程全部落在左侧；分层编译在中间插入一个便宜得多的基线档，用几十微秒的编译成本把交点压到百次量级，热点函数再升级到优化档。

### 6.2 四档执行模型的对照

| 模型 | 启动延迟 | 峰值吞吐（相对原生） | 内存税 | 行为可预测性 |
| --- | --- | --- | --- | --- |
| 纯解释（CPython 3.12） | 20~40 ms | 0.01~0.1× | 低，< 10 MB | 高：无编译决策，逐句确定 |
| 基线 JIT（Sparkplug / C1） | < 50 ms 额外 | 0.2~0.5× | 数十 MB | 中：编译点由计数阈值决定 |
| 优化 JIT（Turbofan / C2） | 100 ms~1 s 额外 | 0.5~1.0× | 数十~数百 MB | 低：去优化使执行路径随输入变化 |
| 纯 AOT（Go 1.27） | < 5 ms | 1.0× | 低，代码段常驻 | 高：无运行时编译 |

四列的排序在启动与峰值之间严格反向：启动每往右一档，峰值就往上抬一档，内存税同步上升。纯 AOT 的启动延迟由动态链接与页错误决定，静态二进制可以压到 5 ms 以内；纯解释的峰值吞吐由 5.3 的分派开销锁死；JIT 两档的位置由 6.1 的交点决定，而不是由语言特性决定。

### 6.3 去优化回退：优化假设失效时的落点

```text
 冷启动 ──► 解释执行 ──► 热点计数达阈值 ──► 基线编译 ──► 优化编译
              ▲                │                │             │
              │                │ 未达阈值        │ 类型/形状变化 │ 内联假设失效
              └────────────────┴────────────────┴─────────────┘
                        去优化：在 safepoint 重建解释器帧，局部变量逐个还原
```

优化编译的每一处投机都要留一条退路：内联假设被调者不再被替换、类型反馈假设实参的类型不变、数组假设长度与元素类型不变。任一假设在运行期被推翻，执行流必须在最近的 safepoint 落回解释器帧，把机器寄存器里的值按栈布局逐个写回，再从对应的字节码偏移继续。这个还原点的密度直接决定去优化的代价：safepoint 越密，单次还原越便宜，但每个循环回边都要多存一份映射表。

去优化的存在把「峰值吞吐」与「行为可预测性」解耦：优化 JIT 的峰值可以逼近原生，代价是同一函数在不同输入下可能走编译路径或解释路径，尾延迟因此出现长尾。代码缓存是这笔账的物理上限——常驻数十到数百 MB，填满后触发 flush，被清掉的函数退回解释执行，等待下一次热点计数重新升温。

## 七、同一函数的五次字节投影

### 7.1 五格并排：一条共享前端与两条出口

```text
  源文本（5 行，≈120 B）
    │  预处理展开（§一）
    ▼
  token 流   ≈30 项 (类别码, 词素)          每项 2~16 B
    │  归约（§二）
    ▼
  AST        ≈15 个节点                      每节点 40~80 B
    │
    ├── GCC 路径：降为 CFG / SSA（§三）──► 机器码  ≈10 条 / 30~50 B（x86-64，-O2）
    │
    └── CPython 路径：AST 直接编译（§五）──► 字节码  ≈12 条 × 2 B = 24 B（3.12 定长）
```

五格不是一条直线：字节流到 AST 是两条路径共享的前端，AST 之后才分叉——GCC 走 CFG/SSA 到机器码，CPython 从 AST 直接落字节码。因此「字节码 vs 机器码」比的不是上下游，而是同一个前端的两个出口；它们的可比性正来自共享的那段前端。

体积沿链并不单调：内存态先膨胀，磁盘态才收缩。同一函数在 token 流、AST、SSA 三种内存表示上分别是源文本的 2~4 倍、5~8 倍、4~8 倍（每项定长头部加指针），而落到机器码或字节码时压回源文本的 1/5~1/3。方向由此分成两段：前三站用空间换结构，后两站用结构换密度。

### 7.2 体量与信息增减：五格逐行对照

| 投影 | 观测手段 | 单函数体量档 | 新增信息 | 丢弃信息 |
| --- | --- | --- | --- | --- |
| token 流 | `gcc -E` 后逐词，或自写 lexer | ≈30 项，每项 2~16 B | 类别码、行号、词素边界 | 空白、注释、原始排版 |
| AST | `clang -ast-dump`、Python `ast.parse` | ≈15 节点，每节点 40~80 B | 父子边、优先级已解算 | 括号、语法糖写法、token 顺序 |
| SSA | `-emit-llvm -S` 得 `.ll` | ≈12 条指令 + 1 个 φ，每指令 32~64 B | def-use 边、支配关系 | 控制结构形状、源级变量名 |
| 机器码 | `objdump -d`，加 `-g` 后 `-dS` 交错 | ≈10 条，30~50 B（1~15 B/条） | 物理寄存器、寻址模式、编码 | 虚拟寄存器、类型、源级结构 |
| 字节码 | CPython `dis` | ≈12 条 × 2 B = 24 B | 平台中立、可分发、名字索引 | 类型精度、寄存器分配、块边界 |

三处比值把这张表钉在量级上：token 到 AST 是 0.3~0.6 倍（差额是归约时被合并的括号与分隔符）；AST 到 SSA 指令是 0.8~1.2 倍（一条表达式语句摊成 1~3 条 IR 指令）；SSA 到机器码的条数是 0.7~1.1 倍，但每条指令要乘 3~5 B 的编码宽度，于是字节数反而回升。

小函数上「字节码约为机器码 1/4~1/2」的比值会偏高：序言、尾声、栈帧调整固定占 5~8 条机器指令，而字节码侧没有对应的固定开销，此时两者体积接近 1:1；函数体越长，固定开销被摊薄，比值才回落到 §五 给的区间。定长编码则给出另一条硬约束：CPython 3.12 的 `dis` 偏移恒为偶数，`co_code` 的指令序号与字节偏移严格按 2 B 一格对齐，任何一条指令的地址都能用序号乘 2 直接算出。

### 7.3 可逆性剖面：只有优化站能回退

| 站 | 丢弃项 | 可回退 | 回退边界 |
| --- | --- | --- | --- |
| 词法 | 空白、注释、拼写 | 否 | 源字节已不在缓冲中 |
| 语法 | 括号、语法糖写法 | 否 | 反打印只能近似还原，token 顺序已丢 |
| 优化 | 源级控制结构形状，语义保留 | 是 | 仅在语义等价内，且不恢复原写法 |
| 后端 | 虚拟寄存器、类型信息 | 否 | 物理化后无虚拟编号可还原 |
| 字节码 | 类型精度、块边界 | 否 | 只能靠运行时反馈重建 |

唯一能回退的是 §三 的优化站，理由不是它丢得少，而是它的 pass 契约是语义保持：每轮迭代结束都可以留一份 IR 快照，换一个 pass 顺序就从快照重跑，不动点保证同样的输入收敛到同一个结果。这条回退通道只在 IR 内部成立，边界是语义等价——它能还原「哪条指令在哪个块里」，不能还原「源码当初写的是 `for` 还是 `while`」。

其余四站的丢弃都是单向的：词法站之后源字节不存在，语法站之后括号写法不存在，后端之后虚拟寄存器不存在，字节码站之后类型只剩运行时反馈。§二 的恐慌恢复与 §六 的去优化都是在各自站内用保留的信息重建一个可继续执行的最小帧，而不是回退到上一站重编译——这条分界正是「可逆」与「可恢复」的差别。

机器码这一格的落盘形态是 `.o` 的 `.text` 节区加上符号表与重定位项，它作为链接器的输入离开本章；同一函数的五次投影到此收敛为五个可分别取出的字节序列。
