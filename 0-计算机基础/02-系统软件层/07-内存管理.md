# 内存管理

## 定义

内存管理通过**虚拟地址空间**实现进程间隔离，并通过**页表**实现虚拟地址到物理地址的翻译。核心目标：在有限物理内存上为每个进程提供看似无限的地址空间，同时通过页面置换在内存与磁盘之间迁移数据。

**归约视角**：虚拟内存将"地址空间大小 > 物理内存大小"的矛盾归约为"缺页率 vs 磁盘 I/O 延迟"的权衡。页面置换算法研究的是如何最小化缺页率，数学上可建模为最优化问题。

## 数学模型

**x86_64 四级页表翻译（48 位虚拟地址）：**

$$
\text{VA[47:0]} = \underbrace{[\text{PGD}_9][\text{PUD}_9][\text{PMD}_9][\text{PTE}_9][\text{Offset}_{12}]}_{\text{5级索引}}
$$

$$
\text{PA} = \underbrace{\text{PTE}[\text{PFN}]}_{\text{物理页框号}} \times 2^{12} + \text{VA}[11:0]
$$

页表项结构（PTE，64位）：

| 位 | 内容 | 说明 |
|----|------|------|
| [0] | P (Present) | 页是否存在物理内存 |
| [1] | R/W | 读/写权限 |
| [2] | U/S | 用户/超级用户权限 |
| [5] | A (Accessed) | 访问过（被 CPU 或软件设置） |
| [6] | D (Dirty) | 脏页（被写） |
| [12:51] | PFN | 物理页框号 |

虚拟地址高 16 位为符号扩展位，必须与第 47 位相同，否则触发 #GP（Canonical Address Check 失败）。

**页面置换的数学约束（Belady 异常）：**

Belady 证明：FIFO 置换算法在增加页框数时可能增加缺页率，LRU 则不会。这说明**置换算法的选择直接影响缺页率**。

$$
\text{缺页率}} = f(|\text{working set}|, \text{内存总量})
$$

当 $|\text{working set}| > \text{内存总量}$ 时，系统进入抖动（thrashing）。

**归约视角**：抖动是 working set 大小超过可用物理页框数时的必然结果。数学上，thrashing 等价于 $P_{\text{页面置换}} \gg P_{\text{计算}}$，导致系统时间被磁盘 I/O 主导。

数据形态变换：
- 虚拟地址 → 页表查找 → 物理地址（TLB 命中时 O(1)）
- TLB 未命中 → 4 级页表查找（内存访问 × 4，延迟显著）
- P=0 → 缺页异常 → 内核决定换入或分配新页

## 机制

### 页面置换算法

| 算法 | 决策函数 | 缺页率特征 | 实现开销 |
|------|----------|------------|----------|
| OPT | 最远未来访问 | 理论最低（下界） | 需预知未来（不可实现） |
| FIFO | 最早进入内存 | 简单，但可能有 Belady 异常 | O(1) |
| LRU | 最近最少使用 | 近似 OPT | O(n) 或 O(log n)（堆实现） |
| CLOCK | R=1 清除，R=0 置换 | LRU 近似 | O(n) 环形链表 |
| Working Set | 时间内访问过的页面 | 自适应 | 需跟踪每个进程历史 |

CLOCK 算法（第二次机会）的精确行为：
```
扫描环形缓冲区：
  - R=1 → 清除R，下一格
  - R=0 → 置换该页，下一格
  - 循环直到找到置换页
```

**约束条件**：
- 页面置换代价高（磁盘 I/O 毫秒级 vs 内存访问纳秒级，差距约 10^5-10^6 倍）
- 抖动：换页比计算更快时，系统退化

**违反约束的后果**：
- 内存泄漏（未释放 malloc） → 可用内存减少 → OOM Killer 触发
- OOM Killer 按 score 杀死最"坏"进程，score = 页面数 + oom_score_adj 调整

### 伙伴系统（内核内存分配）

物理页框分配（以 2^k 页为单位）：

$$
\text{buddy}[k] = \text{大小为}2^k\text{页的空闲块链表}, \quad k \in [0, 10]
$$

分配算法（阶 k=5 为例）：
1. 在 buddy[5] 查找
2. 找到 → 分配
3. 未找到 → 在 buddy[6] 分裂为两个 buddy[5]
4. 一个分配，另一个加入 buddy[5]
5. 若 buddy[6] 也无，递归向 buddy[7] 查找

释放算法：
1. 释放 buddy[5]
2. 检查其伙伴（物理地址连续、大小相同）是否也空闲
3. 空闲 → 合并为 buddy[6]
4. 递归向上合并直到最大阶或遇到非空闲伙伴

**约束条件**：
- 只能分配 2 的幂次方页数（内部碎片）
- 碎片化可能导致大块请求失败（外部碎片）

**违反约束的后果**：
- 内存碎片化 → 明明总空闲量够但分配失败（外部碎片）
- 解决方案：slab 分配器（基于伙伴系统的对象缓存，减少碎片）

### 内存映射（mmap）

mmap 将文件或匿名区域映射到进程地址空间：

$$
\text{文件映射} = \underbrace{\text{页缓存}}_{\text{磁盘 ↔ 内存}} \xleftarrow{\text{read/write}} \text{用户虚拟地址}
$$

映射类型：
- **文件映射**：页缓存关联文件，支持持久化
- **匿名映射**（MAP_ANONYMOUS）：无后端文件，swap 空间作为备份
- **私有映射**（MAP_PRIVATE）：写时复制（CoW）
- **共享映射**（MAP_SHARED）：修改直接落磁盘（对文件）或跨进程共享（对匿名）

**归约视角**：mmap 将文件 I/O 归约为内存读写。磁盘块到虚拟页的映射由页面置换子系统管理，对用户程序透明。

**约束条件**：
- MAP_FIXED 会覆盖已有映射，可能导致原有映射丢失
- 匿名映射需要 swap 空间备份，swap 耗尽时分配失败

**违反约束的后果：**
- MAP_FIXED 覆盖 → 原映射中的数据若未同步会丢失
- swap 耗尽 → 分配失败（返回 MAP_FAILED），程序可能崩溃

## 参考存根

```c
// 页面分配（Linux 内核）
struct page* alloc_pages(gfp_t gfp_mask, unsigned int order);
// order=0: 4KB, order=2: 16KB, order=10: 4MB

// 用户空间 mmap
void* mmap(void* addr, size_t length, int prot, int flags, int fd, off_t offset);
// prot: PROT_READ|PROT_WRITE|PROT_EXEC
// flags: MAP_PRIVATE|MAP_ANONYMOUS|MAP_FIXED

// 伙伴系统分配（简化）
void* buddy_alloc(int order) {
    for (int o = order; o <= MAX_ORDER; o++) {
        if (!list_empty(&free_area[o])) {
            struct page* page = list_pop(&free_area[o]);
            split_page(page, o, order);
            return page_to_virt(page);
        }
    }
    return NULL;  // 分配失败
}
```
