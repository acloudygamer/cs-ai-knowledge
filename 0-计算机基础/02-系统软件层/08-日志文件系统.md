# 日志文件系统

## 概念

**日志文件系统（Journaling File System）** 是一种通过记录操作日志来保证文件系统一致性和快速恢复的文件系统类型。相比传统的非日志文件系统（如ext2），日志文件系统可以在系统崩溃或突然断电后快速恢复，而不需要漫长的fsck扫描。

```
┌─────────────────────────────────────────────────────────────┐
│                    日志文件系统架构                            │
├─────────────────────────────────────────────────────────────┤
│                      应用程序                                 │
│                         ↓                                   │
│                    系统调用层                                 │
│                         ↓                                   │
│              VFS (虚拟文件系统)                               │
│                         ↓                                   │
│    ┌────────────────────────────────────────┐               │
│    │           日志文件系统层                 │               │
│    │  ┌──────────┐    ┌──────────────────┐ │               │
│    │  │ 日志区域  │    │   实际文件系统区域  │ │               │
│    │  │ (Journal)│    │   (Data/Metadata) │ │               │
│    │  └──────────┘    └──────────────────┘ │               │
│    └────────────────────────────────────────┘               │
│                         ↓                                   │
│                   块设备层                                   │
└─────────────────────────────────────────────────────────────┘
```

## 为什么需要日志

### 传统文件系统的问题

**非日志文件系统（如ext2）的问题**：
- 系统崩溃后，磁盘上的数据结构可能处于不一致状态
- 元数据更新可能被中断，导致文件系统损坏
- 恢复需要扫描整个文件系统（fsck），非常耗时

```bash
# ext2文件系统崩溃后的典型恢复过程
$ fsck /dev/sda1
e2fsck 1.46.5 (15-Dec-2021)
/dev/sda1 was not cleanly unmounted, check forced.
Pass 1: Checking inodes, blocks, and sizes...
Pass 2: Checking directory structure...
Pass 3: Checking directory connectivity...
Pass 4: Checking reference counts...
Pass 5: Checking group summary information...
# 这个过程可能需要数分钟到数小时，取决于文件系统大小
```

### 日志文件系统的优势

1. **快速恢复**：崩溃后只需重放日志，几秒钟内恢复
2. **一致性保证**：通过日志确保操作要么完全完成，要么完全回滚
3. **避免长时间fsck**：不需要扫描整个文件系统

## 日志原理

### 日志工作流程

```
┌──────────────────────────────────────────────────────────────┐
│                    日志操作的三阶段模式                         │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  1. Journal (日志写入阶段)                                   │
│     ┌─────────────────────────────────┐                     │
│     │  Write Buffer:                  │                     │
│     │    - txh: Transaction Header    │                     │
│     │    - blk[0..n]: Data blocks     │                     │
│     │    - metablk[0..m]: Meta blocks │                     │
│     └─────────────────────────────────┘                     │
│                        ↓                                     │
│  2. Commit (提交阶段)                                        │
│     ┌─────────────────────────────────┐                     │
│     │  Commit Block:                  │                     │
│     │    - txh: Commit Header (JBD2)  │                     │
│     └─────────────────────────────────┘                     │
│                        ↓                                     │
│  3. Checkpoint (检查点阶段)                                  │
│     ┌─────────────────────────────────┐                     │
│     │  将已提交的操作应用到主文件系统   │                     │
│     │  更新superblock, inode等元数据   │                     │
│     └─────────────────────────────────┘                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 日志区域结构

```
┌─────────────────────────────────────────────────────────────┐
│                    日志区域布局                               │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────┬─────────┬─────────┬─────────┬─────────┐        │
│  │Journal  │Journal  │Journal  │ ...     │ Oldest  │        │
│  │Super    │Header   │Records  │         │Transaction│      │
│  │Block    │         │         │         │         │        │
│  └─────────┴─────────┴─────────┴─────────┴─────────┘        │
│       ↑                                                        │
│       └── 环形缓冲区，允许覆盖旧事务                            │
│                                                              │
│  每条Journal Record格式:                                      │
│  ┌──────────┬──────────┬──────────┐                           │
│  │ Tag      │ Block    │ Content  │                           │
│  │ (12B)   │ Number   │ (Data)   │                           │
│  └──────────┴──────────┴──────────┘                           │
└─────────────────────────────────────────────────────────────┘
```

## ext4 日志详解

### 日志模式

ext4提供三种日志模式，权衡性能与安全性：

| 模式 | 数据保护 | 性能 | 说明 |
|------|----------|------|------|
| `journal` | 完整 | 最慢 | 元数据和数据都记录日志 |
| `ordered` | 中等 | 中等 | 只记录元数据，数据写入在元数据提交后 |
| `writeback` | 最低 | 最快 | 只记录元数据，不保证数据顺序 |

```bash
# 创建带日志的ext4文件系统
mkfs.ext4 -j /dev/sdb1
# -j 表示启用日志（默认journal模式）

# 指定日志模式
mkfs.ext4 -O journal_data /dev/sdb1    # journal模式
mkfs.ext4 -O journal_data_ordered /dev/sdb1  # ordered模式（默认）
mkfs.ext4 -O journal_data_writeback /dev/sdb1 # writeback模式

# 查看当前文件系统日志模式
dumpe2fs -h /dev/sda1 | grep journal
# Journal inode: 8
# Journal backup: inode blocks
# Journal version: 2
```

### ext4 日志数据结构

```c
// ext4日志头结构（简化）
struct ext4_journal_header_s {
    __le32 h_magic;           // 日志魔数 0xC03B3998
    __le32 h_blocktype;       // 块类型
    __le32 h_sequence;        // 事务序列号
};

// ext4事务头结构
struct ext4_journal_block_tag_s {
    __le32 t_blocknr;         // 目标块号
    __le32 t_flags;           // 标志位
};

// ext4提交头结构
struct ext4_journal_commit_header_s {
    struct ext4_journal_header_s h;
    __le32 h_chksum;          // 校验和
    __le32 h_revoke_seq;      // 撤销序列号
};
```

### 日志恢复过程

```bash
# 手动恢复ext4日志
e2fsck -fy /dev/sda1
# -f 强制检查
# -y 回答所有问题为"是"

# 禁用日志（不建议，可能导致数据丢失）
tune2fs -o ^has_journal /dev/sda1

# 启用日志
tune2fs -j /dev/sda1
```

## XFS 日志详解

### XFS 日志特点

XFS是高性能企业级文件系统，其日志特性包括：
- **延迟分配**：写入先在内存中缓存，合并后批量写入磁盘
- **条带化日志**：可配置日志存储在独立设备
- **实时光快照**：支持在线快照和恢复

```bash
# 创建XFS文件系统
mkfs.xfs /dev/sdb1

# 创建带外部日志的XFS
mkfs.xfs -l logdev=/dev/sdc1,size=10g /dev/sdb1

# 查看XFS日志信息
xfs_info /dev/sda1
# meta-data=/dev/sda1           isize=512    agcount=4
#         ag_size=127991808 blks
#         =                  sectsz=512   attr=2
#         =                  crc=1        finobt=1
# data     =                  bsize=4096   blocks=511967232
#         =                  imaxpct=25   sunit=0
#         =                  swidth=0
# log      =/dev/sda2          bsize=4096   blocks=5048
#         =                  sectsz=512   sunit=1
```

### XFS 日志恢复

```bash
# 卸载并检查XFS
umount /dev/sda1
xfs_repair /dev/sda1

# 严重损坏时使用日志重放
xfs_repair -L /dev/sda1
# -L 强制日志重置（可能丢失数据）

# 查看XFS日志统计
xfs_logprint /dev/sda1
```

## Btrfs 日志与写时复制

### 写时复制（Copy-on-Write）

Btrfs采用COW机制，不原地修改数据：

```
┌─────────────────────────────────────────────────────────────┐
│                    写时复制(Copy-on-Write)                    │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  初始状态:                                                   │
│  ┌─────────┐        ┌─────────┐                             │
│  │ File    │ ──────→│ Block A │  (数据块A被两个引用共享)    │
│  │ (ref=2) │        └─────────┘                             │
│  └─────────┘                                                 │
│                                                              │
│  修改后:                                                    │
│  ┌─────────┐        ┌─────────┐        ┌─────────┐         │
│  │ File1   │ ──────→│ Block A │        │ Block A'│         │
│  └─────────┘        └─────────┘        └─────────┘         │
│       ↓                                                     │
│  ┌─────────┐        ┌─────────┐                             │
│  │ File2   │ ──────→│ Block A │  (旧引用保持不变)          │
│  └─────────┘        └─────────┘                             │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Btrfs 日志模式

```bash
# 查看Btrfs挂载选项
mount -o remount,commit=300 /dev/sdb1
# commit参数控制数据写入磁盘的频率（秒）

# 启用压缩
mount -o compress=zstd /dev/sdb1 /mnt

# 启用只读快照日志
mount -o ro,subvol=/snapshots/snap1 /dev/sdb1 /mnt/snap
```

### Btrfs 事务与快照

```bash
# 创建子卷（类似独立文件系统）
btrfs subvolume create /mnt/data

# 创建快照
btrfs subvolume snapshot /mnt/data /mnt/snapshots/$(date +%Y%m%d)

# 查看子卷
btrfs subvolume list /mnt

# 删除子卷（自动回收空间）
btrfs subvolume delete /mnt/data
```

## F2FS：闪存优化的日志文件系统

### F2FS 特点

F2FS（Flash-Friendly File System）是专为闪存（NAND Flash）设计的日志文件系统：
- **追加写入**：适合闪存的擦除前写入特性
- **区域感知**：利用闪存的并行性
- **冷热数据分离**：区分频繁访问和不常访问的数据

```bash
# 创建F2FS文件系统
mkfs.f2fs /dev/sdc1

# 挂载选项
mount -o f2fs /dev/sdc1 /mnt/usb

# 查看F2FS统计
dump.f2fs /dev/sdc1
```

### F2FS 数据结构

```
┌─────────────────────────────────────────────────────────────┐
│                    F2FS 段结构                                │
├─────────────────────────────────────────────────────────────┤
│  ┌────────┬────────┬────────┬────────┬────────┬─────────┐  │
│  │ Segment│ Segment│ Segment│ ...    │ Segment│ Segment │  │
│  │   0    │   1    │   2    │        │   n-1  │   n     │  │
│  └────────┴────────┴────────┴────────┴────────┴─────────┘  │
│       ↑                                                         │
│  ┌────────┬────────┬────────┐                                 │
│  │  Node  │  Data  │  SSA   │                                 │
│  │  Area  │  Area  │  Area  │                                 │
│  └────────┴────────┴────────┘                                 │
│                                                              │
│  每个Segment = 2MB (512 * 4KB blocks)                         │
│  支持多线程写入（Multi-threaded checkpointing）               │
└─────────────────────────────────────────────────────────────┘
```

## 日志文件系统性能调优

### ext4 调优

```bash
# 调整commit间隔（默认5秒）
mount -o commit=10 /dev/sda1 /mnt

# 禁用访问时间更新（提升性能）
mount -o noatime /dev/sda1 /mnt

# 增加块组大小
mkfs.ext4 -g 32768 /dev/sdb1

# 禁用日志（最快，但不安全）
mkfs.ext4 -O ^has_journal /dev/sdb1
```

### XFS 调优

```bash
# 调整日志大小
mkfs.xfs -l size=10g /dev/sdb1

# 调整inode大小
mkfs.xfs -i size=512 /dev/sdb1

# 设置inode分配组
mkfs.xfs -i perdir=16384 /dev/sdb1

# 实时子卷（用于数据库）
mkfs.xfs -r rtdev=/dev/sdc1 /dev/sdb1
```

### I/O 调度器选择

```bash
# 查看当前调度器
cat /sys/block/sda/queue/scheduler
# noop [deadline] cfq

# SSD推荐noop或deadline
echo noop > /sys/block/sda/queue/scheduler

# 调整调度器参数
echo 2000 > /sys/block/sda/queue/iosched/read_expire
echo 2000 > /sys/block/sda/queue/iosched/write_expire
```

## 日志与数据一致性

### fsck 的演进

现代日志文件系统大幅减少fsck需求：

| 文件系统 | 日志类型 | 崩溃恢复时间 |
|----------|----------|--------------|
| ext2 | 无 | 数分钟-数小时 |
| ext3 | 写回日志 | 秒级 |
| ext4 | 日志+延迟分配 | 秒级 |
| XFS | 日志+延迟分配 | 秒级 |
| Btrfs | COW+快照 | 秒级 |
| ZFS | COW+事务组 | 秒级 |

### 数据安全级别

```bash
# 确保数据写入磁盘
sync  # 强制所有缓存写入磁盘

# 对于重要数据，使用journal模式
mount -o data=journal /dev/sda1 /mnt

# 定期检查文件系统
tune2fs -c 30 /dev/sda1  # 每30次挂载后检查
```

## 常见问题与解决方案

### 日志损坏

```bash
# ext4日志损坏修复
umount /dev/sda1
e2fsck -fy /dev/sda1

# 如果e2fsck无法修复，重建日志
tune2fs -E test_fsck /dev/sda1
# 或
mkfs.ext4 -S /dev/sda1  # 重建日志，保留数据
```

### 空间不足

```bash
# 查看日志是否占用大量空间
df -h /mnt

# 查看大文件
du -sh /var/* | sort -rh | head -10

# 清理日志文件
journalctl --vacuum-size=500M
```

### 性能下降

```bash
# 检查碎片
filefrag -v file.txt

# ext4碎片整理
e4defrag /dev/sda1

# XFS碎片整理
xfs_fsr /dev/sda1
```

## 关系

**关键连接**：
- 日志文件系统 → **VFS**：通过VFS接口提供统一抽象
- 日志 → **事务**：类比数据库事务的ACID特性
- COW → **快照**：写时复制是快照实现的基础
- 日志区域 → **块设备**：日志最终存储在块设备上
