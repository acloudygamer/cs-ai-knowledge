# 内存管理

## 定义

内存管理通过虚拟地址空间实现进程间隔离，并通过页表实现虚拟地址到物理地址的翻译。

## 数学模型

x86_64 四级页表翻译：

$$
\text{虚拟地址} \xrightarrow{\text{split}} [\text{PGD}[9]][\text{PUD}[9]][\text{PMD}[9]][\text{PTE}[9]][\text{Offset}[12]]
$$

$$
\text{物理地址} = \text{PTE}[\text{PFN}] + \text{Offset}
$$

其中 PFN（页帧号）指向物理页框。

## 数据流

<pre>
虚拟地址 (进程A)                    物理内存
┌────────────────┐                ┌────────────────┐
│ VPN │ Offset   │                │ Frame 0│       │
└───────┬────────┘                │ Frame 1│       │
        ▼                        │ ...    │       │
  ┌──────────┐                    └────────┴───────┘
  │  页表查找  │                         ▲
  └────┬─────┘                         │
       ▼                               │
  PTE: [PFN|权限|状态] ─────────────────┘
       │
       ├── P=1,权限够 ──► 物理地址
       │
       └── P=0 ──► 缺页异常 ──► 页面置换 ──► 重新查找
</pre>

数据形态变换：
- 虚拟地址（进程私有） → 物理地址（全局共享）
- 磁盘文件 → 内存页（按需调入）

## 机制

### 页面置换算法

| 算法 | 决策 | 开销 |
|------|------|------|
| FIFO | 最早进入内存 | O(1) |
| LRU | 最近最少使用 | O(n) 或 O(log n) |
| CLOCK | R=1 给机会，R=0 换出 | O(n) |
| working set | 活跃页面集合 | 跟踪开销大 |

**约束条件**：
- 页面置换需要磁盘I/O，代价高昂
- 频繁置换导致抖动（thrashing）

**违规后果**：
- 内存泄漏 → 可用内存耗尽 → OOM Killer 介入

### 伙伴系统（Linux 内核）

$$
\text{分配} = 2^k \text{页}, \quad k \in [0, 10]
$$

- 分配：从合适大小的块分裂
- 释放：检查伙伴块是否也空闲，是则合并

**约束条件**：
- 只能分配 2 的幂次方页数
- 碎片化可能导致分配失败
