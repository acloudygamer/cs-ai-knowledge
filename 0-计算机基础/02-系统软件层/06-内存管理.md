# 内存管理

## 概念

**内存管理**是操作系统分配和回收内存资源的技术，包括物理内存和虚拟内存的管理。

```
┌─────────────────────────────────────────────────────────┐
│                    虚拟地址空间                          │
│  ┌─────────────────────────────────────────────────┐   │
│  │ 内核空间 (kernel)              大小取决于架构和配置   │   │
│  ├─────────────────────────────────────────────────┤   │
│  │ 栈 (stack) - 函数调用，向下增长                  │   │
│  ├─────────────────────────────────────────────────┤   │
│  │ 内存映射区 (mmap) - 动态库、内存映射文件          │   │
│  ├─────────────────────────────────────────────────┤   │
│  │ 堆 (heap) - 动态分配，向上增长                   │   │
│  ├─────────────────────────────────────────────────┤   │
│  │ BSS - 未初始化全局变量                          │   │
│  ├─────────────────────────────────────────────────┤   │
│  │ 数据段 - 已初始化全局变量                        │   │
│  ├─────────────────────────────────────────────────┤   │
│  │ 代码段 (text) - 只读程序代码                    │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
                          ↓ 页表翻译
┌─────────────────────────────────────────────────────────┐
│                    物理内存                             │
│  ┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐  │
│  │Frame│Frame│Frame│Frame│Frame│Frame│Frame│Frame│...│  │
│  │  0  │  1  │  2  │  3  │  4  │  5  │  6  │  7  │   │  │
│  └────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘  │
└─────────────────────────────────────────────────────────┘
```

## 关系

**关键连接**：
- 虚拟内存 → **页表**：地址翻译
- 物理内存 → **CPU 缓存**：热点数据缓存
- 堆分配 → **内存分配器**：glibc 的 ptmalloc2，jemalloc（FreeBSD默认，Redis等高性能应用常用）
- OOM → **OOM Killer**：内存耗尽时的进程终止机制

## 内存分配方式

### 静态分配 vs 动态分配

```c
// 静态分配 - 编译时确定大小
int arr[100];              // 栈上分配
static int global[100];   // 数据段

// 动态分配 - 运行时确定
int* ptr = malloc(100 * sizeof(int));  // 堆上分配
free(ptr);

// C++ new/delete
int* ptr = new int[100];
delete[] ptr;
```

### 栈分配

```c
// 栈帧结构
void function(int param) {
    int local_var;              // 栈上分配
    int* heap_ptr = malloc(sizeof(int));  // 堆上分配

    // 栈帧: [返回地址][旧EBP][保存寄存器][参数][局部变量]
}
```

| 特性 | 栈 | 堆 |
|------|----|----|
| 分配速度 | 快 | 慢 |
| 释放方式 | 自动 (函数返回) | 手动 (free/delete) |
| 大小限制 | 小 (Linux默认8MB，由ulimit -s控制) | 受物理内存和swap限制 |
| 碎片 | 无 (LIFO) | 有 (内存碎片) |
| 线程安全 | 各线程独立 | 需加锁 |

```bash
# 查看进程内存映射
```


## 虚拟内存

### 地址翻译

```
虚拟地址                    物理地址
┌────────────────┐         ┌────────────────┐
│ VPN (页号)│OFFSET│       │ PFN (页帧号)│OFFSET│
└───────┬────────┘         └───────┬────────┘
        │                          │
        ▼                          │
  ┌──────────┐                      │
  │  页表    │                      │
  │ VPN→PFN  │                      │
  └──────────┘                      │
        │                          │
        ▼                          │
   页表项 (PTE)                     │
   ┌────────────────┐              │
   │ PFN │ 权限 │状态│─────────────►│
   └────────────────┘              │
                                  │
   页未命中 ──► 页表遍历 ──► 缺页异常 ──► 调入物理页
```

### 多级页表

Linux 使用四级页表减少内存占用。当前x86_64实现使用48位虚拟地址（高16位需为符号扩展）：

```
虚拟地址:
┌────────┬────────┬────────┬────────┬────────────┐
│ PGD    │ PUD    │ PMD    │ PTE    │ Offset     │
│  9位   │  9位   │  9位   │  9位   │   12位     │
│        │        │        │        │ (4KB页)    │
└────────┴────────┴────────┴────────┴────────────┘
 (共36位用于页号)              (12位页内偏移)

地址翻译:
PGD → PUD → PMD → PTE → 物理页帧 + Offset
```

```bash
# 查看进程页表
cat /proc/self/pagemap    # 需要 root
cat /proc/self/smaps       # 详细内存映射
```

## 内存分配算法

### 首次适配 (First Fit)

```c
// 按地址顺序找到第一个足够大的空闲块
void* first_fit(size_t size) {
    for (block = free_list; block != NULL; block = block->next) {
        if (block->size >= size) {
            return allocate_from_block(block, size);
        }
    }
    return NULL;  // 内存不足
}
```

### 最佳适配 (Best Fit)

```c
// 找到最小的足够大的空闲块
void* best_fit(size_t size) {
    void* best = NULL;
    for (block = free_list; block != NULL; block = block->next) {
        if (block->size >= size) {
            if (best == NULL || block->size < best->size) {
                best = block;
            }
        }
    }
    return best ? allocate_from_block(best, size) : NULL;
}
```

### 伙伴系统 (Buddy System)

Linux 内核使用的内存分配算法：

```
初始: 2^5 = 32 页的连续块

分割:
32 → 16 + 16 → 8 + 8 + 16 → 4 + 4 + 8 + 16

合并:
4 + 4 → 8 (伙伴块都空闲时)
8 + 8 → 16
...
```

```bash
# 查看伙伴系统状态
cat /proc/buddyinfo
# Node 0, zone      DMA      1      0      1      1      2     ...
# Node 0, zone    DMA32    123    456    789   1023   2048   ...
```

## 页替换算法

当物理内存不足时，需要将页面换出到磁盘。

### LRU (最近最少使用)

```python
# LRU 近似实现 - 使用 OrderedDict 维护访问顺序
class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.pages = {}  # page_id -> data

    def access(self, page_id):
        if page_id in self.pages:
            # 移到末尾表示最近使用
            self.pages.move_to_end(page_id)
            return True
        return False

    def replace(self):
        # 驱逐最旧的页面（链表头部）
        if self.pages:
            self.pages.popitem(last=False)
```

### CLOCK 算法

```
┌─────────────────────────────────────┐
│ CLOCK 算法 (二次机会)                │
├─────────────────────────────────────┤
│ 1. 页面排成环形链表                  │
│ 2. 每页有引用位 (R)                  │
│ 3. 选择页面时:                       │
│    - R=1 → 清除 R，继续查找          │
│    - R=0 → 选择此页换出               │
└─────────────────────────────────────┘
```

### 页面置换策略

| 算法 | 特点 | 开销 |
|------|------|------|
| FIFO | 简单，最早进入先换出 | Belady 异常 |
| LRU | 最近最少使用 | O(n) 开销 |
| CLOCK | LRU 近似，低开销 | 可能不准确 |
| 工作集 | 基于访问集合 | 跟踪开销大 |

```bash
# pgfault    - 所有页面错误 (次要)
# pgmajfault - 需要从磁盘读取的页面错误 (主要)
```

## 内存映射 (mmap)

```c
#include <sys/mman.h>

// 文件映射
void* mmap(void* addr, size_t length, int prot, int flags, int fd, off_t offset);

// 匿名映射 (相当于 malloc)
void* ptr = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
                 MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

// 释放映射
munmap(ptr, 4096);
```

```
mmap 映射类型:

┌─────────────────────────────────────┐
│ MAP_ANONYMOUS     │ 匿名映射，无后备文件 │
│ MAP_PRIVATE       │ 写时复制，进程私有    │
│ MAP_SHARED        │ 映射区域内修改可见   │
│ MAP_FIXED         │ 使用指定地址         │
└─────────────────────────────────────┘
```

## OOM (Out of Memory)

当物理内存和交换空间都耗尽时，触发 OOM Killer：

```
OOM 触发条件:
内存申请 → 页面分配失败 → out_of_memory() → OOM Killer 选择进程 → 杀死进程
                                                            ↓
                                                    释放其占用的内存
```

```bash
# 查看 OOM 分数 (越高越容易被杀，范围 0-1000)
cat /proc/self/oom_score
# 输出: 0

# 调整 OOM 分数 (范围 -1000 到 +1000，越低越不容易被杀)
echo -1000 > /proc/self/oom_score_adj

# 查看 OOM 历史
dmesg | grep -i "out of memory"
dmesg | grep -i "killed process"
```

### OOM 常见原因

| 原因 | 表现 | 解决方案 |
|------|------|----------|
| 内存泄漏 | 进程内存持续增长 | 修复泄漏代码 |
| 突发请求 | 短期大量申请 | 限流/扩容 |
| swap 太小 | 频繁换页 | 增大 swap |
| cgroup 限制 | 容器内 OOM | 调整 limits |

## 内存安全

### 缓冲区溢出

```c
// 溢出示例
char buf[10];
strcpy(buf, "This string is too long!");  // 溢出

// 安全版本
strncpy(buf, "This string is too long!", sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';
```

### 堆安全

```bash
# AddressSanitizer 检测内存错误
gcc -fsanitize=address -g program.c
./a.out

# Valgrind 检测内存泄漏
valgrind --leak-check=full ./program
```

| 错误类型 | 检测工具 | 后果 |
|----------|----------|------|
| 缓冲区溢出 | ASan | 写入越界 |
| 双重释放 | ASan | 堆破坏 |
| 内存泄漏 | Valgrind | 内存耗尽 |
| 使用未初始化 | Valgrind | 不确定行为 |
