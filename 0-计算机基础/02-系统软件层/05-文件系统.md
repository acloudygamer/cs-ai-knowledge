# 文件系统

## 定义

文件系统是将块设备上的物理存储组织为**命名文件层次结构**的逻辑抽象，提供按名访问、持久化存储和权限控制。核心约束：**文件名到数据块的映射关系必须在系统崩溃后仍可恢复**。

## 数学模型

inode 直接/间接块寻址（ext4，块大小 4KB）：

$$
\text{最大文件大小} = \underbrace{12 \times 4\text{KB}}_{\text{直接块}} + \underbrace{256 \times 4\text{KB}}_{\text{一级间接}} + \underbrace{65536 \times 4\text{KB}}_{\text{二级间接}} + \underbrace{16777216 \times 4\text{KB}}_{\text{三级间接}} \approx 16\text{TB}
$$

inode 最大寻址块数 $= 12 + 256 + 65536 + 16777216 = 16843020$，每个块 4KB，总大小约 64GB（受 ext4 文件大小限制 16TB 约束）。

VFS 抽象接口代数：

$$
\text{file\_operations} = \{open, read, write, mmap, fsync, lock, \ldots\}
$$

所有文件系统（ext4/xfs/btrfs）必须实现同一组函数指针，内核通过函数指针调用，屏蔽实现差异。

目录项缓存（dentry cache）加速路径查找：

$$
\text{路径解析} = O(\text{路径深度}) \xrightarrow{\text{dcache缓存}} O(1)
$$

dentry 维护父目录指针和孩子链表，查找时先查缓存，缓存命中则跳过 VFS 层直接获取 inode。

数据形态变换：
- 字节偏移 → 块号（offset / blocksize）
- 块号 → 扇区号（块对齐到设备物理扇区）
- 扇区 → NAND Flash 页或磁盘磁道（物理寻址）

## 机制

### inode 结构与硬链接

inode（index node）是文件元数据的容器，不包含文件名：

| 字段 | 说明 | 约束 |
|------|------|------|
| mode | 文件类型 + 权限位 | 权限检查依据 |
| uid/gid | 所有者 | 访问控制 |
| size | 文件大小（字节） | - |
| atime/mtime/ctime | 访问/修改/变更时间 | 文件系统一致性 |
| block[15] | 直接/间接块指针 | extents 替代方案 |
| i_links_count | 硬链接计数 | 归零时释放 inode |

**硬链接本质**：多个目录项指向同一 inode，共享 i_links_count。删除文件（unlink）时递减计数，仅当归零时释放数据块和 inode。

**约束条件**：
- 硬链接不能跨文件系统（inode 编号仅在本分区唯一）
- 硬链接不能指向目录（防止循环引用）

**违规后果**：
- 删除正在打开的文件 → 目录项立即移除，数据块保留（文件描述符仍有效）直至最后引用关闭
- 硬链接跨分区 → 指向错误的 inode，数据损坏

### 日志文件系统（ext4）

ext4 journal 保证一致性，崩溃后通过重放或回滚恢复：

$$
\text{write} \xrightarrow{\text{JBD}} \begin{cases}
\text{TXN\_BEGIN} \rightarrow \text{metadata blocks} \rightarrow \text{TXN\_COMMIT} \rightarrow \text{数据块写入} \\
\text{或} \\
\text{数据块写入} \rightarrow \text{TXN\_BEGIN} \rightarrow \text{metadata blocks} \rightarrow \text{TXN\_COMMIT}
\end{cases}
$$

ext4 journal 模式：
- **journal 模式**：所有数据+元数据都写日志（最安全，最慢）
- **ordered 模式**（默认）：元数据写日志，数据写入在 commit 之前（平衡安全与性能）
- **writeback 模式**：仅元数据日志，不保证数据顺序（最快，可能丢失数据）

崩溃恢复流程：
1. 文件系统 mount 时检测 journal 是否有未完成事务
2. 有 → 读取 journal，重复所有 TXN_COMMIT（重放）或撤销 TXN_BEGIN（回滚）
3. 恢复完成，正常挂载

**约束条件**：
- journal 本身需日志一致性保护（日志块环形写入）
- journal 空间有限，需定期 checkpoint 回收

**违规后果**：
- 日志损坏 → mount 失败，需 fsck 完整扫描
- 未正常 unmount → journal 重放，可能丢失最后几秒数据

### 页面缓存与回写

Linux 页面缓存机制：

$$
\text{物理页框} \xrightarrow{\text{address_space}} \text{文件偏移} \xrightarrow{\text{radix树}} \text{缓存页}
$$

读文件时，数据先进入页面缓存；写文件时，数据写入缓存页并标记 dirty，延迟回写到磁盘（一般 30 秒或内存压力时）。

**约束条件**：
- dirty 页过多会触发内存回收（回收算法决定哪些页被换出）
- 强制回写：sync()/fsync() 确保数据落盘

**违规后果**：
- 程序异常退出且未 fsync → 最近写入的数据可能丢失
- 电源故障 → ext4 ordered 模式最多丢失一个事务的数据

## 参考存根

```c
// ext4 inode extent 结构（替代间接块指针，更高效）
struct ext4_extent {
    __le32  ee_block;   // 逻辑块号
    __le16  ee_len;    // 连续块数
    __le16  ee_start_hi; // 物理块号高16位
    __le32  ee_start_lo; // 物理块号低32位
};

// 系统调用示例：读取文件
fd = open("/tmp/data", O_RDONLY);
read(fd, buf, 4096);
close(fd);
```
