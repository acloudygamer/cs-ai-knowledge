# 文件系统

## 核心定义：从扇区数组到字节流

块设备（磁盘、SSD）能提供的只是一样东西：**一个巨大的定长扇区数组**，按编号读写。而程序想要的是另一样东西：**按名字存取、可伸可缩的字节流**——`/home/a.txt`，第 0 到第 10239 字节。文件系统（File System）就是把前者垫成后者的那层软件：它维护"名字 → 哪些扇区"的映射，以及每个文件的大小、权限、时间戳等元数据。

这层抽象的约束来自两端。下方：磁盘以块（典型 4KB）为最小读写单位，写一个字节也要整塊读改写。上方：程序不接受"把数据放在 7 号扇区"这种接口——名字要稳定、文件要能被多个程序按权限共享、机器重启后数据还在（持久化）。文件系统同时回应这两端。

## VFS：所有文件系统共用的一张接口

Linux 同时存在几十种文件系统实现（ext4、XFS、Btrfs、NFS、procfs……），但程序只用一套 `open/read/write`。中间这层是**虚拟文件系统（Virtual File System，VFS）**：它定义四个核心对象，具体文件系统按接口注册实现。

| 对象 | 对应什么 | 说明 |
|------|---------|------|
| superblock（超级块） | 一个挂载的文件系统 | 块大小、总容量、空闲统计——挂载时读入 |
| inode（索引节点） | **一个文件本身** | 元数据 + 数据块指针；不含文件名 |
| dentry（目录项） | **一个名字** | 把路径名的一节映射到 inode；内存中有 dentry 缓存（dcache）加速路径解析 |
| file | **一次打开** | `open()` 的返回：当前偏移量、打开模式。同一文件被打开两次就有两个 file 对象 |

四个对象把三组关系拆开：**一个文件一个 inode**（实体唯一），**一个 inode 可以有多个名字**（dentry 多对一——硬链接的全部含义），**一个文件可以被打开多次**（file 多对一——各自持有独立的读写偏移）。程序手里的文件描述符（fd）就是进程文件表（03 的 `files_struct`）里指向某个 file 对象的下标。

路径解析沿对象链走：`open("/home/a.txt")` → 从根 dentry 出发，逐级查 dcache（未命中则读目录文件）→ 拿到 `a.txt` 的 inode → 建 file 对象 → fd 入进程文件表。

### 挂载：多设备拼成一棵目录树

VFS 之上，全系统只有**一棵目录树**：不同分区、不同设备各自是一个文件系统，通过**挂载（mount）**接到树的某个节点上——把 `/dev/sda1` 挂到 `/mnt/data` 之后，访问 `/mnt/data/x` 就落进那个分区。superblock 正是挂载时读入的：一个挂载点对应一个文件系统实例。

而 `/proc`、`/sys`、`/dev` 这些目录背后**不是磁盘文件系统**：procfs/sysfs 是内核状态的文件化——读 `/proc/cpuinfo` 时内容是内核现场生成的（04 篇的 `minflt`/`majflt` 计数器就住在这里）；`/dev` 里的设备文件由内核与 udev 维护（06 篇）。这是"一切皆文件"的第二面：不只磁盘数据有文件接口，内核状态与设备也借文件接口暴露——`cat` 和 `echo` 因此成了最通用的系统检查与配置工具。

## inode 与 ext4：文件在磁盘上的真实样子

inode 是文件的身份证加藏宝图。以 ext4 为例，一个 inode（默认 256 字节）里装着：大小、权限、属主、三个时间戳、链接计数，以及最关键的——**数据块的位置信息**。文件名不在 inode 里：目录本身也是文件，其内容就是一张"名字 → inode 号"的列表。

元数据里的**权限**值得单独展开——它是文件系统对 01 篇"多用户共享"约束的回应。每个文件有三类主体 × 三种操作共九个位：属主 / 同组 / 其他人，各自能否读（r）、写（w）、执行（x）。`chmod 755` 的每个数字就是一组 rwx 的二进制读数（7=rwx、5=r-x）。对目录，x 的含义是"可进入"（cd 与访问其内容的资格），r 是"可列出名字"——所以"能列出文件名却读不了内容"与"能读文件却列不出目录"都是合法配置。执行位还兼任 shebang 的开关（04-终端与Shell 02：脚本没有 x 位，`./script.sh` 直接被权限拒绝）。

链接的语义也由"文件名不在 inode 里"推出：

- **硬链接**：在另一个目录里加一行"新名字 → 同一个 inode 号"。两个名字完全平等，删到链接计数归零才释放数据。
- **软链接（符号链接）**：一个独立的小文件，内容是目标路径的字符串。目标删掉后它就悬空（打开报 ENOENT）。

**藏宝图怎么画，有过一次结构换代。** ext2/3 用间接指针：inode 里 12 个直接块指针，之后是单级、双级、三级间接块——每 K 个指针占用一个块。4KB 块下访问大文件尾部，要先沿指针树读两三层纯索引块，随机读性能塌方。ext4（2008 年）换成 **extent**：不再逐块登记，而是记录"连续区段"——（起始块，长度）一对值覆盖最多 128MB 连续数据。inode 里放 4 个 extent，放不下再长成一棵 extent 树（深度最多 5 层）。连续大文件——数据库数据文件、视频——一个 extent 就描述完，索引开销和寻道次数一起消失。

## 日志：断电那一秒怎么办

**约束**：一次"写文件"在磁盘上是多次独立写——数据块、inode、目录项、空闲块位图，各自落在不同位置。断电发生在中间任何一步，磁盘上都是半个文件系统：块标了已用但没人指向它、inode 指向的块里还是旧数据……块设备不保证这组写的原子性，文件系统只能自己造。

**日志（Journaling）**的方案与数据库的 redo log 同构：**先写意图，再动真身**。

1. 把这组修改的整体意图完整写入磁盘上一块专用区域（journal）并落盘；
2. 然后才把修改写到各自的正式位置；
3. 全部写完后，在 journal 里标记该事务完成。

崩溃后重启：扫 journal，已登记未完成的事务重放一遍——文件系统要么回到事务前，要么前进到事务后，绝不停在中间。ext4 提供三档模式，默认 **data=ordered**：只给元数据记日志，但强制数据块先于元数据提交落盘——用一点顺序约束换来既不全量双写数据、又不让新元数据指向旧数据的折中。

## 页面缓存与回写：文件 I/O 其实先过内存

文件读写与 04 的内存管理共用同一批物理页——**页面缓存（Page Cache）**：

- **read 的路径**：先查页面缓存。命中：内存复制给调用者，磁盘根本不碰（这就是"第二次 cat 一个大文件飞快"的原因）。未命中：分配缓存页，经块层发磁盘读（06 的 DMA），数据进缓存页后再复制给调用者。
- **write 的路径**：默认不写盘——数据复制进缓存页、标记为脏，系统调用即返回。后台 flusher 线程把脏页批量写回磁盘；`fsync()` 是调用者强制"现在落盘"的闸门。写因此很快，但断电会丢最近一批未落盘的写——日志保文件系统结构，保不了你最后几秒的数据，这是两个不同的保证。
- **mmap**：把文件直接映射进进程地址空间（04 的 VMA），访问时走缺页异常从磁盘填页——读写文件变成了普通内存访问，页面缓存就是那个被映射的实体。

页面缓存使"内存"和"文件"两个抽象共享同一池物理页：文件页干净时可直接丢弃（要用再读），脏时先回写——04 的回收表里"文件页"一行说的就是它。内存紧张时 kswapd 压缩缓存，这就是"内存满了，磁盘 I/O 突然变多"的因果链。
