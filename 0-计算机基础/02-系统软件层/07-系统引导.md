# 系统引导

## 核心定义：从加电脉冲到第一个进程

系统引导（Boot）回答一个时序问题：加电那一刻内存里是空的，而前六篇讲的全部机制——内核、进程、虚拟内存、文件系统——都是内存里的代码和数据。**它们是怎么从无到有长出来的？**

答案是一条接力链，每一级只做一件事：把下一级从存储搬进内存、验证（可选）、移交控制权。

```text
加电 → 固件（BIOS/UEFI）→ Bootloader → 内核 + initramfs → 挂载真根 → PID 1 → 各服务进程
```

这条链的每一环都被同一个约束塑造——**先有鸡还是先有蛋**：程序在磁盘上，但读磁盘需要驱动，驱动本身也是磁盘上的程序。整条引导链就是对这个约束的逐层解套。

## 第一环：固件——CPU 醒来看见的第一段代码

x86 CPU 加电复位后，指令指针被硬件钉在一个固定地址（复位向量，物理地址 `0xFFFFFFF0`），那里映射着主板闪存里的固件代码。固件于是成为唯一"不需要被加载就存在"的程序——鸡与蛋的第一层解套：第一段代码不在磁盘上，在 ROM 里。

但在固件正常跑起来之前还有更底层的零号环：**此刻连内存都还没初始化**。DRAM 颗粒需要内存控制器先做训练（校准信号时序与电平，物理细节见《硬件组成》的内存章）才可读写，而训练代码自己也是程序、也需要地方跑。解套：固件的前几行把 **CPU 缓存临时当内存用**（Cache-as-RAM，CAR），在缓存里执行内存初始化代码；DRAM 点亮之后，才轮到真正的固件流程。引导链的第一环不是点亮磁盘，是先把内存本身造出来。

固件有新旧两代：

| | BIOS（基本输入输出系统） | UEFI（统一可扩展固件接口） |
|---|---|---|
| 出身 | 1981 年 IBM PC | 2005 年前后取代 BIOS |
| 运行模式 | **16 位实模式**——为了兼容 1978 年的 8086，现代 CPU 加电时先假装自己是块古董芯片，这是教科书级的历史遗物 | 32/64 位保护模式 |
| 找下一级的方式 | 读启动盘第一个扇区（MBR，512 字节）到内存 `0x7C00`，校验结尾签名 `0x55AA`，跳进去 | 直接读 ESP 分区（FAT32 格式）里的 `.efi` 程序——固件自己就能读文件系统 |
| 磁盘上限 | MBR 分区表：2TB、4 个主分区 | GPT 分区表：64 位扇区号、默认 128 个分区 |

**BIOS 的 512 字节困境**本身就是一次鸡与蛋：512 字节（还扣掉 64 字节分区表和 2 字节签名）装不下任何像样的磁盘驱动，所以它的全部使命是把"更大的下一级"（GRUB 的核心镜像，藏在 MBR 之后的磁盘间隙里）搬进来。UEFI 把这层尴尬直接删掉——固件会读文件系统，加载器就是一个普通文件。

**Secure Boot** 给接力链加上验证：固件用预置密钥（db）校验 bootloader 的数字签名，bootloader 再校验内核——每一级确认下一级没被篡改才移交。信任链从固件一路延伸到内核。Linux 发行版通过微软签名的 shim 小加载器挤进这条链。

## 第二环：Bootloader——把内核请进内存

GRUB 是 Linux 世界的标准 bootloader。它干三件事：

1. 按配置文件找到**内核镜像**（`vmlinuz`，一个压缩包）和 **initramfs 镜像**，都搬进内存；
2. 把内核命令行参数（`root=`、`quiet`、`numa_balancing=disable` 这类《硬件组成》NUMA 一节见过的开关）放在约定位置；
3. 跳到内核入口，控制权交出，bootloader 使命结束。

## 第三环：内核自举

内核接手后先给自己做手术：自解压镜像、建立第一批页表（至此虚拟内存机制才生效——04 的全部故事从这刻起有了载体）、切入 64 位长模式，然后 `start_kernel()` 初始化各子系统：内存管理（伙伴系统建空闲链表）、调度器（第一棵红黑树）、中断（IDT 填好，02 的门开张）、按硬件清单逐个初始化驱动。清单从哪来？也是固件交接的：x86 平台是 **ACPI 表**（固件留在内存里的一组表，写明有哪些设备、占什么资源），ARM 与嵌入式平台是**设备树**（Device Tree，随内核镜像一起装载的硬件描述文件）。内核不猜硬件——硬件名单是固件递过来的。最后 `rest_init()` 创建两个始祖进程：**PID 1**（`kernel_init`，将变成用户态 init）和 **PID 2**（`kthreadd`，所有内核线程的父亲）。

## 第四环：initramfs——临时的根

内核要挂载真正的根文件系统（`/`），又撞上一次鸡与蛋：挂载根需要存储驱动和文件系统驱动，而这些驱动模块**就存放在根文件系统里**。发行版不可能把世上所有存储驱动都编译进内核镜像。

解套方案是 **initramfs**：bootloader 一并搬进内存的一个小压缩包，内核把它解到内存文件系统（tmpfs）里当临时根——里面备齐主流存储驱动和一段 init 脚本。脚本加载本机需要的驱动模块、找到并挂载真正的根分区，然后 `switch_root` 换家：内存里的临时根功成身退。

注意这一环的结构与第一环完全同构：**一段不依赖磁盘的代码（ROM 固件 / 内存文件系统）负责把磁盘能力点亮**。同一个约束，同一解法，在引导链上出现两次。

## 第五环：PID 1——用户态的起点

内核最后一个动作是执行 `/sbin/init`（当代发行版是 systemd），PID 1 就此成为第一个用户态进程。之后的一切都是它的后代或它启动的服务：

- 挂载其余文件系统、起网络、按 unit 依赖图拉起各服务（sshd、数据库、容器运行时……）；
- 承担 03 说的树根职责：孤儿进程过继给它，僵尸进程由它收割。

**休眠是引导的变体**：suspend（挂起到内存）只给内存供电、现场留在 RAM 里，唤醒不经过引导链；hibernate（休眠到磁盘）把整份内存镜像写进 swap（04 的交换区），下次开机时内核直接恢复镜像，跳过五环节拍的大半。笔记本合盖与冷启动的差别，就在这两条路上。

引导到此结束——从复位向量到登录提示符，每一环都只依赖上一环交付的能力：固件给"读磁盘的最小能力"，bootloader 给"内核在内存"，initramfs 给"驱动在手"，内核给"四大职能"，PID 1 给"用户态"。下次按下电源键时，这条五环节拍在几秒内无声走完。
