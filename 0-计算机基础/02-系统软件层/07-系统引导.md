# 系统引导

## 概念

**系统引导 (Boot)** 是计算机启动的过程，从按下电源键到操作系统完全加载。

```
┌─────────────────────────────────────────────────────────┐
│                    计算机启动流程                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  电源开启 → POST → BIOS/UEFI → 引导程序 → 内核 → init  │
│     │        │        │          │        │         │   │
│     ▼        ▼        ▼          ▼        ▼         ▼   │
│  硬件自检  固件初始化  固件     Bootloader  加载内核  用户空间
│                      查找启动设备   │
│                                 ↓
│                         加载内核到内存
│                                 ↓
│                         初始化系统服务
└─────────────────────────────────────────────────────────┘
```

## 关系

**关键连接**：
- POST → **BIOS/UEFI**：硬件自检后进入固件
- BIOS/UEFI → **Bootloader**：固件读取启动设备
- Bootloader → **内核**：加载内核到内存并启动
- init → **系统服务**：启动系统服务，进入用户空间

## BIOS vs UEFI

| 特性 | BIOS | UEFI |
|------|------|------|
| 启动协议 | MBR | GPT (新) |
| 最大磁盘 | 2TB | 16EB |
| 启动速度 | 慢 | 快 |
| 驱动支持 | 固件内置 | 模块化 (CSM) |
| 安全启动 | 无 | Secure Boot |
| 硬件初始化 | 16位模式 | 32/64位模式 |

```bash
# 查看固件类型
[ -d /sys/firmware/efi ] && echo "UEFI" || echo "BIOS"
```

## POST (加电自检)

```
POST 执行流程:

1. 硬件初始化
   - CPU 复位，寄存器初始化
   - 内存检测 (POST 内存测试)
   - 键盘、显示器等基本设备检测

2. 显示诊断
   - 屏幕显示 POST 码
   - 内存计数

3. 设备枚举
   - PCI 设备扫描
   - 即插即用设备检测

4. 查找启动设备
   - 按启动顺序尝试
   - 光驱 → 硬盘 → USB → 网络
```

## MBR 启动

### MBR 结构 (512 字节)

```
┌─────────────────────────────────────────────────────┐
│ MBR (Master Boot Record) - 512 字节                 │
├─────────────────────────────────────────────────────┤
│ 偏移        内容                大小                 │
│ 0x000-0x1BD │ 引导代码           │ 446 字节          │
│ 0x1BE-0x1CD │ 分区表项 1         │ 16 字节           │
│ 0x1CE-0x1DD │ 分区表项 2         │ 16 字节           │
│ 0x1DE-0x1ED │ 分区表项 3         │ 16 字节           │
│ 0x1EE-0x1FD │ 分区表项 4         │ 16 字节           │
│ 0x1FE-0x1FF │ 结束标志 (0x55AA)  │ 2 字节            │
└─────────────────────────────────────────────────────┘
```

### 分区表项结构

```
┌─────────────────────────────────────────┐
│ 分区表项 (16 字节)                      │
├─────────────────────────────────────────┤
│ 0x00: 分区状态 (0x80=可启动)            │
│ 0x01-0x03: 起始 CHS 地址                │
│ 0x04: 分区类型                          │
│ 0x05-0x07: 结束 CHS 地址                │
│ 0x08-0x0B: 起始 LBA (小端序)            │
│ 0x0C-0x0F: 分区大小 (扇区数)            │
└─────────────────────────────────────────┘
```

### 常见分区类型

| 类型值 | 文件系统 | 说明 |
|--------|----------|------|
| 0x07 | NTFS | Windows NT |
| 0x0B | FAT32 | Windows |
| 0x83 | Linux | Linux 原生 |
| 0x82 | Linux swap | 交换分区 |
| 0xEE | GPT protective | GPT 分区表 |

## GPT 分区

```
┌─────────────────────────────────────────────────────────┐
│ GPT (GUID Partition Table)                              │
├─────────────────────────────────────────────────────────┤
│ 位置          内容                    大小               │
│ LBA 0         保护 MBR              512 字节           │
│ LBA 1         GPT 头                512 字节           │
│ LBA 2-33      分区条目              128 字节 × 128 (16KB) │
│ LBA 34+       分区数据              ...                │
└─────────────────────────────────────────────────────────┘
```

### GPT 分区条目结构

```
┌─────────────────────────────────────────┐
│ GPT 分区条目 (128 字节)                 │
├─────────────────────────────────────────┤
│ 0x00-0x0F: 分区类型 GUID               │
│ 0x10-0x1F: 唯一分区 GUID               │
│ 0x20-0x27: 起始 LBA (小端序)           │
│ 0x28-0x2F: 结束 LBA                    │
│ 0x30-0x37: 属性标志                    │
│ 0x38-0x7F: 分区名称 (UTF-16LE)         │
└─────────────────────────────────────────┘
```

## Bootloader

### GRUB2 工作流程

```
GRUB2 启动阶段:

┌─────────────────────────────────────────┐
│ Stage 1: MBR 中的引导代码               │
│ ROM 中跳转，加载 Stage 1.5              │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ Stage 1.5: 文件系统驱动                 │
│ 识别 /boot 分区文件系统                  │
│ 加载 Stage 2 或内核                    │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ Stage 2: GRUB 主程序                    │
│ 显示引导菜单，加载内核                   │
└─────────────────────────────────────────┘
```

### GRUB2 配置文件

```bash
# /boot/grub2/grub.cfg 示例
menuentry 'Fedora Linux' {
    load_video
    set gfxpayload=keep
    insmod gzio
    insmod part_gpt
    insmod ext2

    # 指定根分区
    linux /boot/vmlinuz-5.14.0 root=/dev/sda1 ro rhgb quiet
    initrd /boot/initramfs-5.14.0.img
}
```

### GRUB2 命令行

```bash
# 进入 GRUB 命令行
# 启动时按 'c' 键

# 常用命令
ls                              # 列出设备
ls (hd0,gpt1)/boot              # 查看目录
cat (hd0,gpt1)/boot/grub2/grub.cfg   # 查看配置
linux /boot/vmlinuz root=/dev/sda1   # 加载内核
initrd /boot/initramfs.img      # 加载 initrd
boot                             # 启动
```

## initramfs (初始 RAM 文件系统)

initramfs 是在内核启动早期挂载的临时文件系统：

```
内核启动早期流程:

1. 内核解压 initramfs
2. 执行 /init 程序
3. /init 挂载真正的根文件系统
4. pivot_root 切换根文件系统
5. 执行 /sbin/init
```

### initramfs 内容

```bash
# 解压 initramfs 查看内容
mkdir initramfs_contents
cd initramfs_contents
zcat /boot/initramfs-5.14.0.img | cpio -id
ls -la
```

典型目录结构:
```
├── bin/        # 基础命令 (busybox)
├── sbin/       # 系统命令
├── etc/        # 配置文件
├── lib/        # 库文件
├── lib64/      # 64位库
├── dev/        # 设备文件
├── proc/       # proc 文件系统
├── sys/        # sys 文件系统
├── tmp/        # 临时文件
└── init        # 入口脚本
```

### 自定义 initramfs

```bash
# 创建简单的 initramfs
mkdir -p initramfs/{bin,sbin,etc,proc,sys,lib}
cp /bin/busybox initramfs/bin/
ln -s busybox initramfs/bin/sh

# 创建 init 脚本
cat > initramfs/init << 'EOF'
#!/bin/sh
mount -t proc none /proc
mount -t sysfs none /sys
echo "Booting from initramfs..."
exec /sbin/init
EOF

# 打包
cd initramfs
find . -print0 | cpio -ov --null | gzip > /boot/custom.img
```

## UEFI 引导

### UEFI 启动流程

```
UEFI 启动阶段:

┌─────────────────────────────────────────┐
│ SEC (Security) - 安全验证               │
│ 平台初始化，可信根                       │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ PEI (Pre-EFI Initialization)           │
│ 内存初始化，加载 DXE                    │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ DXE (Driver Execution Environment)      │
│ 硬件驱动，执行启动策略                   │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ BDS (Boot Device Selection)              │
│ 选择启动设备，加载 Bootloader            │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ TSL (TSL > OS Shell)                    │
│ 启动菜单或 Shell                         │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│ RT (Runtime)                            │
│ 操作系统运行时服务                        │
└─────────────────────────────────────────┘
```

### UEFI 应用程序

```bash
# 查看 EFI 分区
efibootmgr -v

# 创建启动项
efibootmgr --create --disk /dev/sda --part 1 \
    --label "My Linux" \
    --loader "\EFI\ubuntu\grubx64.efi"

# 删除启动项
efibootmgr -b 0001 -B
```

### Secure Boot

```
┌─────────────────────────────────────────┐
│ Secure Boot 验证流程                    │
├─────────────────────────────────────────┤
│ 1. 固件包含受信任的 DB (数据库)          │
│ 2. 固件包含 DBX (吊销数据库)            │
│ 3. 固件包含 KEK (密钥交换密钥)          │
│ 4. 所有启动组件必须签名验证              │
└─────────────────────────────────────────┘
```

```bash
# 查看 Secure Boot 状态
mokutil --sb-state
# SecureBoot enabled

# 查看已加载的签名
mokutil --list-enrolled
```

## Linux 内核启动

### 内核解压

```
内核镜像结构 (zImage/bzImage):

┌─────────────────────────────────────────┐
│ 实时解压代码                            │
├─────────────────────────────────────────┤
│ 压缩内核 (vmlinux.gz)                   │
│  包含: setup 代码 + 实际内核            │
└─────────────────────────────────────────┘
```

### 内核初始化流程

```c
// 内核启动流程简化

start_kernel()
    ↓
setup_arch()           // 架构特定初始化
    ↓
spawn_init()           // 启动第一个进程 (PID 1)
    ↓
kernel_init()          // 执行 init 程序
    ↓
rest_init()            // 创建 kernel_thread
```

### 启动参数

```bash
# 查看内核参数
cat /proc/cmdline
# BOOT_IMAGE=/boot/vmlinuz-5.14.0 root=/dev/sda1 ro quiet

# 常用内核参数:
# root=        根文件系统设备
# ro           以只读方式挂载根分区
# quiet        抑制内核消息
# splash       显示启动画面
# nomodeset    禁用内核模式设置
# systemd.unit=  指定启动的 systemd target
```

```bash
# 临时修改启动参数 (GRUB)
# 启动时按 'e' 编辑
# 在 linux 行添加参数

# 永久修改
vim /etc/default/grub
# GRUB_CMDLINE_LINUX="quiet splash"
grub2-mkconfig -o /boot/grub2/grub.cfg
```

## init 系统

### systemd 初始化

```bash
# systemd 启动流程
# 1. 加载 kernel command line
# 2. 初始化 basic.target (基础目标)
# 3. 启动 sysinit.target (系统初始化)
# 4. 启动 multi-user.target (多用户模式)
# 5. 启动 getty.target (登录终端)

# 查看启动时间
systemd-analyze
# startup finished in 2.123s

# 查看各服务启动时间
systemd-analyze blame
```

### 传统 SysV init

```bash
# 运行级别 (SysV)
# 0 = 关机
# 1 = 单用户
# 2 = 多用户无网络
# 3 = 多用户命令行
# 4 = 保留
# 5 = 图形界面
# 6 = 重启

# 切换运行级别
init 3    # 切换到命令行
init 5    # 切换到图形界面
```

### 启动故障排查

```bash
# 查看启动日志
dmesg                     # 内核环缓冲区
journalctl -b             # systemd 本次启动日志
cat /var/log/boot.log     # 传统启动日志

# 常见启动问题
# 1. 文件系统错误 - 进入单用户模式 fsck
# 2. 内核 panic - 检查内核参数，查看 panic 信息
# 3. 服务启动失败 - journalctl -u <service>
```

## Bootloader 比较

| 特性 | GRUB2 | systemd-boot | rEFInd |
|------|-------|--------------|--------|
| 支持平台 | x86, ARM | x86, ARM (UEFI) | x86, ARM (UEFI) |
| 配置文件 | grub.cfg | loader.conf | refind.conf |
| 启动速度 | 慢 | 快 | 中 |
| 特性 | 功能全面 | 简单 | 自动检测 |
| 维护难度 | 复杂 | 简单 | 简单 |
