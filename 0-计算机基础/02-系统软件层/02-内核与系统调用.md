# 内核与系统调用

## 定义

内核是操作系统中**唯一运行在特权模式（Ring 0）的软件组件**，持有全部硬件资源的所有权。系统调用是用户态进程进入内核态的唯一入口，通过专用指令（syscall/sysenter）实现特权级跨越。内核的设计目标是在有限硬件上支持多个并发进程，并保证故障隔离——一个进程的崩溃不能导致另一个进程或内核本身崩溃。

**归约视角：** 系统调用的本质是将用户态的**受限资源请求**归约为内核态的**特权操作序列**。从数学上讲，这是从用户空间函数集合到内核空间函数集合的一个偏序映射，约束条件由硬件特权级机制 enforce。

## 数学模型

**系统调用的本质是受控函数查找：**

$$
\text{内核函数指针} = \text{sys\_call\_table}[\text{syscall\_number}]
$$

sys_call_table 是内核中的一张函数指针数组，系统调用号是数组索引。查找过程在 O(1) 时间内完成。

**参数传递约定（x86_64 System V ABI）：**

| 寄存器 | 参数1 | 参数2 | 参数3 | 参数4 | 参数5 | 参数6 |
|--------|-------|-------|-------|-------|-------|-------|
| x86_64 | RDI | RSI | RDX | R10 | R8 | R9 |

返回值写入 RAX：非负值表示成功，负值（-errno）表示错误。

**快速系统调用的性能差异：**

| 机制 | 指令 | 上下文保存量 | 典型延迟 |
|------|------|-------------|---------|
| 传统中断 | `int 0x80` | 完整中断帧（压栈 CS/IP/FLAGS/SP 等 10+ 寄存器） | ~300-500 周期 |
| 快速系统调用 | `syscall` | 仅保存 RIP/RFLAGS/CR3/SP（4 寄存器） | ~100-150 周期 |

syscall 之所以快，是因为它避免了解码中断向量表和压栈中断帧的通用逻辑，专用硬件（MSR）直接跳转到内核指定入口。

**特权级检查的数学形式：**

$$
\text{有效特权级} = \max(\text{CPL}, \text{RPL}), \quad \text{访问许可} = (\text{CPL} \leq \text{DPL}) \land (\max(\text{CPL}, \text{RPL}) \leq \text{DPL})
$$

数据段访问要求 $\max(\text{CPL}, \text{RPL}) \leq \text{DPL}$；代码段（门描述符）访问要求 $\text{CPL} \leq \text{DPL}$。

## 数据流

<pre>
用户空间

└────────────┘                                       │

                         ▼

┌──────────────────────────────────────────────────────┐

│  │ syscall_entry    │──►│ sys_call_table[NR]   │   │
│  │ (保存用户上下文)  │   │ = do_sys_write()    │   │
│  └──────────────────┘   └──────────┬───────────┘   │
│                                     │                │
│                         ┌───────────▼───────────┐   │

│                         │ 3. fd 权限检查        │   │
│                         │ 4. 文件系统操作        │   │
│                         │ 5. RAX = 返回值       │   │

└──────────────────────────────────────────────────────┘
                         │
                         │ sysret 指令 (CPL=0 → CPL=3)
                         ▼

</pre>

参数验证是安全关键步骤：用户态传入的指针必须经过 `access_ok()` 检查，确认指向用户地址空间。若跳过此检查，恶意程序可利用内核函数读写任意物理地址——这是特权升级漏洞的常见根因。

**数据所有权变换：**
- 用户态 buffer（`buf`）→ 内核态临时复制（`copy_from_user`）→ 设备驱动 DMA 缓冲区 → 磁盘控制器
- 每一次复制都隐含一次从用户态到内核态的数据所有权转移

## 机制

### 特权级与保护

CPU 通过 CS 寄存器的 RPL（请求特权级）和 CPL（当前特权级）字段，以及段描述符的 DPL（描述符特权级）字段实现三维保护。这是硬件 enforce 的访问控制矩阵，不是软件约定。

**约束条件：**
- 用户态执行 `cli`（清除中断标志）→ CPU 查 CPL=3 > 0，触发 #GP
- 用户态访问内核线性地址（如直接映射区 0xFFFF880000000000 以上）→ 页表权限位检查失败，触发 #PF

**违反约束的后果：** #GP 异常递达内核，内核可选择发送 SIGSEGV 杀死进程，或在内核 Bug 情况下 panic。#PF 发生在内核态本身时，内核无法恢复（double fault → panic）。

### 中断/异常向量

| 向量 | 类型 | 触发条件 | 用途 |
|------|------|----------|------|
| 0x00 | 异常 | 除零 | CPU 内部错误 |
| 0x0D (#GP) | 异常 | 权限检查失败 | 越权访问 |
| 0x0E (#PF) | 异常 | 页表 P=0 或权限不足 | 缺页/越页访问 |
| 0x80 | 中断 | `int 0x80` | Linux 32-bit syscalls（旧） |
| syscall | 中断 | `syscall` 指令 | Linux 64-bit syscalls |

页面错误（#PF）的二次分发决定进程命运：
- **P=0，进程 VA 范围内** → 分配物理页（demand paging / COW）
- **P=0，进程 VA 范围外** → SIGSEGV（非法访问）
- **P=1，权限不足** → SIGSEGV（写只读内存，CoW 除外）

### 系统调用号与表查找

Linux 系统调用号定义在 `arch/x86/entry/syscalls/syscall_64.tbl`，每个架构有独立编号表。查找路径：

$$
\text{用户 RAX (syscall 号)} \xrightarrow{\text{aligned\_array}} \text{函数指针} \xrightarrow{\text{call}} \text{内核函数}
$$

**约束条件：**
- syscall 号必须有效（< NR_syscalls），否则返回 -ENOSYS
- 指针参数必须通过 access_ok()，未验证指针导致内核读取任意用户态地址

**违反约束的后果：**
- 无效 syscall 号 → `-ENOSYS` 返回用户态（进程不会崩溃，但不执行任何操作）
- 未验证指针 → 内核信息泄露（读取用户态内存作为内核数据返回）或死机（如果内核尝试解引用无效指针）

### 内核地址空间布局（x86_64）

```
[0x0000000000000000, 0x00007FFFFFFFFFFF]  用户空间（128TB）
[0xFFFF800000000000, ...]                  内核直接映射区（物理页直接映射）
[0xFFFF880000000000, ...]                  内核 vmalloc/模块区域
[0xFFFFFFFF80000000, ...]                  内核 text 段（恒等映射）
```

用户态地址和内核态地址在 x86-64 上从不重叠，这是有意设计，防止内核数据泄露到用户态（KAISER/KPTI 缓解 Meltdown 的基础）。

**归约视角**：内核直接映射区的物理地址和虚拟地址存在线性关系 $\text{VA} = \text{PA} + 0xFFFF880000000000$，使内核可以 O(1) 访问任意物理页而不需要页表查找。

### 常见系统调用解析

**openat 系统调用流程：**

```c
// 用户态
fd = openat(dirfd, "/path/to/file", O_RDONLY);

// 内核态 (sys_openat)
1. copy_from_user(pathname, user_path);
2. struct path path;
3. path_lookupat(dirfd, pathname, LOOKUP_FOLLOW, &path);
4. struct inode *inode = path.dentry->d_inode;
5. check permissions(inode, MAY_READ);
6. alloc file descriptor (fd);
7. allocate file* and link;
8. return fd;
```

**read 系统调用流程：**

```c
// 用户态
ssize_t n = read(fd, buf, count);

// 内核态 (sys_read)
1. struct fd f = fdget(fd);
2. struct file *file = f.file;
3. check file->f_mode & FMODE_READ;
4. loff_t *pos = &file->f_pos;
5. ssize_t ret = file->f_op->read(file, buf, count, pos);
6. fdput(f);
7. return ret;
```

## 参考存根

```c
// Linux 系统调用号（arch/x86/entry/syscalls/syscall_64.tbl）
// 每行格式: number ABI NAME
__NR_read    EQU 0
__NR_write   EQU 1
__NR_openat  EQU 56
__NR_clone3  EQU 435

// access_ok() 实现（简化版）
static inline bool access_ok(const void __user *ptr, size_t size) {
    unsigned long addr = (unsigned long)ptr;
    // 检查地址是否在用户空间范围内
    return addr < TASK_SIZE_MAX && (addr + size) < TASK_SIZE_MAX;
}
```

```bash
# 查看系统调用表
cat /usr/src/linux/arch/x86/entry/syscalls/syscall_64.tbl | head -20

# strace 跟踪系统调用
strace -e trace=read,write,openat ls /tmp

# 查看进程系统调用
cat /proc/[pid]/syscall
```
