# TCP 与 UDP

> **版本基准**: universal

## 骨架要点（正文按此展开，完成后删除本骨架块）

- **定位**：消费 01 的 IP 逐跳投递与端口复用、02-操作系统 的进程与 socket 缓冲区；产出"端到端可靠性的来源与代价"，供 05-HTTP（请求-响应语义）与 07-Socket（编程接口）消费。
- **核心拓扑流**：状态机（TCP 有限状态机：CLOSED → SYN_SENT/ LISTEN → … → ESTABLISHED → TIME_WAIT）为主干；数学推演流（拥塞控制 AIMD 锯齿、带宽延迟积决定窗口下限）按需挂载，推导终点落回"窗口必须 ≥ 带宽×RTT 才能打满链路"的量化断言。
- **必备图**：①TCP 头 20 B 起的位标尺切分图（seq/ack/窗口/标志位）；②三次握手与四次挥手的时序 ASCII 图（双侧泳道，每条箭头标注标志位与状态迁移）；③AIMD 拥塞窗口锯齿图；④TCP 有限状态机主干 mermaid 或 ASCII（分支密度超 ASCII 可读上限时用 mermaid）。
- **量化锚点**：RTT 档位（同城毫秒级、跨洲几十至百毫秒级）、带宽延迟积算例、MSS 1460、RTO 指数退避、初始拥塞窗口 10 MSS（锚定 RFC 6928）。

### 一、UDP：最小多路复用与责任转移

- 8 B 头位标尺切分（源端口、目的端口、长度、校验和）；它只做"进程间分发 + 可选校验"，其余全部推给应用——成本转移方向写明：省下的连接状态/重传/排序开销由不需要它们的应用（DNS、实时音视频）独享。
- UDP 的正确场景不是"不可靠也行"，而是"应用自己能更好地管可靠性"（如 QUIC 在 06 与 05-HTTP 中回收）。

### 二、TCP 状态机：连接是两端各自推进的状态栈

- 三次握手的排除法辩护：两次不够——服务端无法区分"新连接的 SYN"与"迟到重发的旧 SYN"，会为幽灵连接分配状态；第三次 ACK 让客户端确认双方收发能力四项全通。
- 四次挥手与 TIME_WAIT：主动关闭方等 2MSL 的两个理由（最后一 ACK 丢失可重发、旧报文自然消亡）；大量 TIME_WAIT 的实战观察（`ss -s`）。

### 三、可靠性的四件套与它们的代价

- 发送缓冲 → 段序号 → 接收端排序去重 → 累积确认：重传（超时 RTO 指数退避 / 三次重复 ACK 触发快速重传）、排序、流控（滑动窗口 = 接收缓冲余量通告）、拥塞控制（慢启动指数 → 丢包后 AIMD 线性加性增、乘性减）。
- 数学推演挂载点：$吞吐量 \le 窗口/RTT$ 的守恒式 → 跨洲高带宽链路必须大窗口；AIMD 稳定性（加性增乘性减才收敛）一句点破即可。
- 量级与方向纪律：重传代价排序、拥塞控制牺牲瞬时吞吐换全网公平——动作归因写具体机制，不写"为了提高性能"。
