# HTTP 协议

> **版本基准**: universal

## 骨架要点（正文按此展开，完成后删除本骨架块）

- **定位**：消费 03 的字节流可靠投递、04 的域名解析；产出"应用语义层"的报文结构与演进，供 06-HTTPS与TLS（在其下加安全层）与 06-软件工程概念 06-架构分层（API 契约）消费。
- **核心拓扑流**：信息投影流为主——HTTP 报文按行切分的文本协议（start line / headers / body），与 01 的二进制位标尺同构但切分单位是行与空行；空间事务环（请求-响应往返生命周期）为闭环。
- **必备图**：①请求/响应报文逐行切分图（每行标注归属段与职责）；②HTTP/1.1 队头阻塞示意 → HTTP/2 帧化多路复用 → HTTP/3 QUIC 流独立恢复的三段演进对照 ASCII 图；③方法 × 安全性 × 幂等性真值矩阵表。
- **锚定来源**：RFC 9110（语义）/9112（1.1）/9113（2）谱系；方法与状态码语义按规范陈述为既定前提。

### 一、报文切分：文本协议的行标尺

- 请求报文 = 请求行（方法 URL 版本）+ 头部（`Key: Value` 逐行）+ 空行 + 体；响应 = 状态行（版本 状态码 短语）+ 头 + 体——位标尺换成"行标尺"逐行吞噬。
- 与二进制协议的对照：文本可读可手写（telnet/nc 可核验），代价是解析器与体积——为 2 的二进制化埋线。
- 长度与边界：`Content-Length` 与 `Transfer-Encoding: chunked` 两种定界方式，粘包/截断的因果链。

### 二、方法、状态码与头部语义：无状态协议如何携带状态

- 方法语义表（GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS × 安全性 × 幂等性 × 可缓存）——真值矩阵补齐全部单元格。
- 状态码分档（1xx 信息 / 2xx 成功 / 3xx 重定向 / 4xx 客户端错 / 5xx 服务端错），方向归因：4xx 与 5xx 的责任分界即"重试有无意义"的分界。
- 无状态的代价转移：服务器不存会话 → 可任意负载均衡，状态由 Cookie/Token 由客户端携带回来——这是无状态换扩展性的明码标价。

### 三、HTTP/1.1 → 2 → 3：每一步在消除什么税

- 1.1 的税：文本解析 + 队头阻塞（一条连接一次一个请求的串行化；浏览器开 6 连接绕行是典型补丁）。
- 2 的动作：二进制帧化 + 单连接多路复用 + 头部压缩 HPACK——消除了 HTTP 层队头阻塞，但 TCP 层丢包阻塞仍在（单连接上所有流共担一次丢包重传）。
- 3 的动作：QUIC 基于 UDP 自建可靠流，流间独立恢复——消除传输层队头阻塞；连接迁移（用 Connection ID 而非四元组标识连接）。
- 每步演进 = 消除一层阻塞税 + 引入一层新复杂度（加密强制、UDP 被中间设备限速的部署税），取舍账本收尾。
