# 网络分层模型

## 一、分层的成因：异构互联逼出统一网络层

### 1. 约束显明：两端异构与组合爆炸

约束从两端同时施加。物理链路一端是异构的：以太网用 48 位地址编址、帧载荷上限 1500 B、双绞线误码率低到可以整帧信任；Wi-Fi（IEEE 802.11）的帧里要额外承载信道与功率管理控制、无线误码率要求逐帧确认重传；点对点协议（Point-to-Point Protocol，PPP）架在串行线上，两端一线，连媒体访问控制地址（Media Access Control address，MAC 地址）都不需要。帧怎么编址、一帧最多装多少字节、帧坏了怎么办，每种链路技术各答一套。

应用一端同样异构：HTTP 按请求-响应一问一答，DNS 一次查询一次应答就够，实时音视频宁可丢包也不能等重传。报文的语义、长度分布、时延容忍度，每个应用各是一套。

两端夹出的问题是：报文从应用语义出发，最终必须落到某一种链路的帧格式上，中间的翻译由谁承担。排除法先看直连方案——让每个应用协议直接面对每种链路技术、各自写一份完整实现。设链路技术 $N$ 种、应用协议 $M$ 种，直连适配需要 $N \times M$ 份实现：HTTP-over-以太网、HTTP-over-Wi-Fi、DNS-over-PPP……每一份都要把报文切分、编址、差错处理从零组合一遍。更致命的是两个方向的持续膨胀：链路技术在换代（双绞线、光纤、无线一代一代换），应用协议在增殖，任何一侧新增一项，都要在对面重写一整排。物理链路的异构由布线与电磁环境决定、不可消除；应用语义的差异由需求决定、同样不可消除——两个不可消除的异构源直接相乘，工程上不可维护，直连方案排除。

### 2. IP 细腰：最小契约与责任边界

分层的解法是在两端之间插入一个统一网络层，把 $N \times M$ 份实现压成 $N + M$ 份：全部应用协议只面对网络层这一个契约，全部链路技术也只被网络层这一个契约消费。新增一种链路技术只需写一份"网络层 over 新链路"的适配，新增一种应用协议只需写一份"新应用 over 网络层"的适配——组合爆炸的乘法被拆成两个加法，改动被层的边界拦在本层之内。

网际协议（Internet Protocol，IP）就是这个统一网络层，形状是细腰：上层（传输控制协议 TCP、用户数据报协议 UDP 与各应用协议）与下层（任何链路技术）都收敛到它，它自身只承诺一个最小契约——尽力而为（best effort）的分组投递：不保证送达、不保证按序、不保证去重，只负责把分组沿逐跳路径往目的地方向推。契约刻意做到最小，排除法再砍一次：若网络层承诺可靠按序，不稀罕这些保证的应用（实时音视频、DNS 查询）也被迫为重传状态与排序缓冲付账；若网络层额外关心链路细节， $N \times M$ 的乘法原样复辟。契约最小化的成本转移方向由此写明：把可靠性、有序性这些"有人要、有人不要"的保证，从全网每一跳的常驻成本，转移到真正需要它们的端点上——这是传输层（03 篇）存在的全部空间。

层边界即责任边界的运行纪律有两条。第一，每层只读写自己的头：从下层收到载荷，先剥本层头再上交，载荷对本层是完全不透明的字节块；切分、校验、改写只动本层头加载荷，不碰相邻层的头。第二，每层只与对端的同层对话：发送端传输层写进头里的端口对，只有接收端传输层读得懂，中间经过的路由器既不读也不写——每个头在逻辑上是一条端到端的直连信道，物理上却要穿过全部下层，这就是分层模型"逻辑信道叠在物理路径上"的结构含义。责任由此可审计：链路上传错的字节找链路层，主机间丢的分组找网络层，进程间乱序的字节流找传输层。

### 3. TCP/IP 四层与 OSI 七层对照

锚定来源：TCP/IP 四层不是先设计后实施，而是对既成事实的追认——RFC 1122 谱系把已经在互联网上跑通的协议整理为链路层、网络层、传输层、应用层四层。OSI（Open Systems Interconnection，开放系统互连）七层由 ISO 在实施之前定义，工程上没有整体落地，但作为教学参照系沿用至今：日常叙事里的"三层设备""七层负载均衡"，层号都出自 OSI。两套体系的对照如下表，本篇之后全部按 TCP/IP 四层叙事。

| TCP/IP 层 | OSI 对应 | 职责一句话 | PDU 名称 |
| --- | --- | --- | --- |
| 链路层 | 数据链路层（第 2 层）+ 物理层（第 1 层） | 同一段链路上的帧编址、差错校验与比特上线 | 帧（frame） |
| 网络层 | 网络层（第 3 层） | 主机间逐跳投递与路由选择 | 分组（packet） |
| 传输层 | 传输层（第 4 层） | 主机内进程间分发、端到端可靠性 | 段（TCP）/ 数据报（UDP） |
| 应用层 | 会话（第 5 层）+ 表示（第 6 层）+ 应用（第 7 层） | 报文语义与交互节奏 | 报文（message） |

OSI 的第 5、6 层在工程上并入应用层：会话与表示的职能由应用协议自带——传输安全协议 TLS（06 篇展开）就住在传输层之上、报文语义之下的位置，却没有为它单设一层。协议数据单元（Protocol Data Unit，PDU）一词在此挂牌：每层加上自己的头之后的整体，就是该层的 PDU；它向下一层交出时，整体充当下一层的载荷。表里四个 PDU 名称将在下一节的封装瀑布中逐一就位——对照表先立住四层骨架，瀑布再灌进报文。

## 二、TCP/IP 四层与层层封装

### 1. 四层职责对照与封装瀑布

全章的目录索引先行——四层各自的寻址单位、地址形态、典型协议与 PDU 名称，全部单元格补齐如下：

| 层 | 寻址单位 | 地址形态 | 典型协议 | PDU 名称 |
| --- | --- | --- | --- | --- |
| 应用层 | 一次交互（请求 / 响应 / 查询） | 域名 + 路径（URL） | HTTP、DNS、TLS、SMTP | 报文（message） |
| 传输层 | 主机内进程 | 16 位端口号，成对使用（端口对） | TCP、UDP | 段（segment，TCP）；数据报（datagram，UDP） |
| 网络层 | 主机 | 32 位 IPv4 地址，成对使用（地址对） | IP、ICMP | 分组（packet） |
| 链路层 | 同段链路上的相邻网卡 | 48 位 MAC 地址，成对使用（MAC 对） | 以太网、Wi-Fi、PPP | 帧（frame） |

寻址单位自上而下逐层收缩：网络层把分组送到主机，传输层在主机内把段送到进程，应用层在进程内定位资源；链路层视野最窄，只认相邻一跳的网卡。四层之下还有物理层托底——它不认任何地址，只负责把比特变成电或光信号送上介质。

现在把一个报文放进结构里，走完整封装瀑布。发送端进程调用系统调用把一段应用数据交给内核——协议栈整体住在内核态，进程借文件描述符（file descriptor，fd）触碰内核对象（02-操作系统的结论就地复述：进程通过小整数 fd 索引内核对象表，socket 与普通文件共用同一套系统调用面），数据进入内核后才走上下面的路径。发送方向自上而下逐级加头，接收方向自下而上逐级剥头，好比一封信套进信封、信封再套进更大的信封，每级信封只写那一跳才需要的地址——类比到此为止。

```text
封装/解封装瀑布（发送方向自上而下逐级加头，接收方向自下而上逐级剥头）

 ── 发送端主机 ─────────────────────────────────────────────────────
 应用层  消息
    │ ① write 进内核 → 传输层加头：端口对                    PDU = 段
    ▼
 段     [TCP 头 20 B 起 │ 消息]
    │ ② 网络层加头：地址对                                   PDU = 分组
    ▼
 分组   [IP 头 20 B 起 │ TCP 头 │ 消息]
    │ ③ 链路层加帧头帧尾：MAC 对 + FCS                       PDU = 帧
    ▼
 帧     [帧头 14 B │ IP 头 │ TCP 头 │ 消息 │ FCS 4 B]
    │ ④ 物理层逐位上线
    ▼
 比特   11101001 00101101 …… ════════► 物理链路 ════════►
                                                     │
 ── 接收端主机 ────────────────────────────────────── ▼
 帧     [帧头 │ IP 头 │ TCP 头 │ 消息 │ FCS 4 B]
    ▲ ⑤ 收帧：FCS 校验通过 → 剥帧头帧尾，类型字段指路上交
 分组   [IP 头 │ TCP 头 │ 消息]
    ▲ ⑥ 网络层：目的 IP = 本机 → 剥 IP 头，协议号指路上交
 段     [TCP 头 │ 消息]
    ▲ ⑦ 传输层：目的端口 = 本进程 → 剥 TCP 头
 应用层  read 返回消息
```

图自上而下逐边遍历。边①：传输层拿到裸消息，加上 TCP 头——端口对（源端口、目的端口）此刻写入，PDU 由报文变成段。边②：网络层加上 IP 头——地址对（源 IP、目的 IP）写入，PDU 升级为分组；网络层对头下的段整体不透明。边③：链路层加帧头与帧尾——帧头写入 MAC 对（目的 MAC、源 MAC）与类型字段，帧尾写入 4 B 的帧校验序列（Frame Check Sequence，FCS），PDU 成为帧；全链路唯一加在尾部的一级就在这里，其余各级都只加头。边④：帧被逐位串行化为比特流送上介质，叙事交给物理定律。

接收方向是同一条链的逆向遍历（步骤 ⑤⑥⑦），剥头的下一步永远由刚剥掉的头自己指路——依赖的是每个头里都有一个"载荷是什么协议"的开关字段，三级开关串成解封装链，每个开关的确切字节位置在 2.3 位标尺上就位。三级全部命中，接收端进程的 read 才拿到发送端 write 的原始消息，两端进程看到的字节序列完全一致，中间四级头在途中被逐级剥净。这条链同时是复用与解复用的现场：发送端多进程的数据共用一个 IP 地址向下复用，接收端按端口对向上分发——分发的完整机制（端口如何分配、无人监听怎么办）由 03 篇展开。瀑布走完，还剩一道长度闸门没过：每级装不下载荷怎么办。

### 2. MTU 1500 与分段/分片

锚定常数：最大传输单元（Maximum Transmission Unit，MTU）是一帧载荷的上限，以太网定为 1500 B——这是以太网帧规格钦定的既定常数，不是物理必然；Wi-Fi 与 PPP 的常见档位与它对齐，一条路径各段 MTU 相近，1500 由此成为互联网路径的事实口径。

传输层若把大报文整块交给网络层，分组就会超出出接口的 MTU。TCP 的对策是在传输层先切，切分线由最大段长度（Maximum Segment Size，MSS）给出——从 MTU 里扣掉 IP 头（20 B 起，取最短形态）与 TCP 头（20 B 起），得

$$\mathrm{MSS} = 1500 - 20 - 20 = 1460$$

单位字节。为什么传输层先切而不是留给网络层分片——成本归因：IP 分片丢一片则整组作废重传；分片里只有第一片携带传输层头（端口对），中间设备无法对后续分片做过滤与统计；接收端还要为重组付出缓存与等待。按 MSS 切段后，正常路径上每个分组恰好装进一帧，IP 分片机制退为兜底：当分组不是本机产生（路由器转发别人的分组）且出接口 MTU 更小时，路由器按 IP 头里预先备好的标识、标志、片偏移三个字段（位标尺见 2.3）把分组切片，每片自带完整 IP 头，接收端按标识同组重组。标志里的 DF（Don't Fragment，不分片）位置 1 时分片被禁止，超 MTU 的分组直接丢弃并回送 ICMP 差错报文，探测路径最小 MTU 的机制（路径 MTU 发现）就建立在这条回执上——ICMP 的角色 02 篇展开。

"每层只能看到自己负责的那段长度"收拢为一张表：

| 层 | 长度责任 | 长度字段 | 典型锚点 |
| --- | --- | --- | --- |
| 传输层 | 段长 ≤ MSS，使正常路径无需分片 | 由 IP 头总长度减去 TCP 头数据偏移间接给出 | MSS $1500 - 20 - 20 = 1460$ |
| 网络层 | 分组 ≤ 出接口 MTU | IP 头总长度（16 位，上限 65535 B） | MTU 1500 |
| 链路层 | 帧载荷 ≤ MTU | 帧边界由前导码与帧间隔隐式定界 | 以太网 1500 |

传输层算 MSS 时只扣自己的头加 IP 头，IP 只核对分组不超 MTU，以太网只核对帧载荷不超 1500——超出自己职责的长度，各层既看不见也不操心。一个 5820 B 的应用报文按这条规则走完瀑布：传输层切成 4 个段（ $5820 = 1460 \times 3 + 1440$），每段独立成组、成帧，接收端传输层按序号还原原序——序号在 TCP 头里，它的坐标体系 03 篇展开。长度闸门过完，横向视角接手：一帧之内的字节究竟怎么切。

### 3. 协议头位标尺：逐头切分

封装瀑布是纵向视角，现在换横向视角。全局字节标尺先行——标准以太网帧从第 0 字节到第 N 字节的完整切分，一帧就是一条完整封装链的横截面：

```text
以太网帧全局字节标尺（载荷 ≤ MTU 1500）

字节  0                 13 14             33 34             53 54                          N-4 N-3      N
      ◄─── 帧头 14 B ───►◄── IP 头 20 B 起 ──►◄── TCP 头 20 B 起 ──►◄──────── 应用数据 ≤ 1460 B ──────►◄ FCS 4 B ►
      ┌──────────────────┬────────────────────┬────────────────────┬──────────────────────────────┬──────────┐
      │ 目的MAC │ 源MAC │类型│      IPv4 头       │       TCP 头       │             数据             │  CRC32   │
      └──────────────────┴────────────────────┴────────────────────┴──────────────────────────────┴──────────┘
吞噬   ◄── 链路层（逐跳重写）──►◄─ 网络层（端到端不变）─►◄─ 传输层（端到端）─►◄────────── 端到端载荷 ──────────►◄ 链路层尾 ►
```

标尺读法：链路层吞噬 [0:13] 的帧头与帧尾的 FCS；帧头类型字段指认第 14 字节起是 IP 分组；IP 头吞到自己的 IHL 声明的长度为止（最短 20 B），载荷交给协议号指认的 TCP；TCP 头吞掉数据偏移声明的长度（最短 20 B）；剩下的 [54:N-4] 是应用数据。标尺上所有多字节字段按网络序读取——01-计算机体系 05 的端序结论在此兑现：主机内存多按小端摆放，网络报文的多字节字段统一按大端编码上线，发送方先发最高有效字节；端口号 8080 = 0x1F90，上线时先发高字节 0x1F，接收端按同一顺序还原。

再放大一步，对三级头逐一列切分。每个头从自身第 0 字节重新计偏移，字段宽度合计等于头宽：


对图逐头遍历。以太网帧头 14 B 固定：目的 MAC 6 B、源 MAC 6 B、类型 2 B。MAC 对回答"这一跳从哪块网卡到哪块网卡"——逐跳有效，跨段即换（逐跳重写的现场 02 篇走一遍）。类型字段是解封装链第一级开关，以太网规格只钦定少数取值：0x0800 上交 IP，0x0806 上交 ARP。帧尾 FCS 4 B 是对整帧（帧头到载荷）的 CRC32 校验——帧头每跳重写一次，FCS 就逐跳重算一次。

IPv4 头 20 B 起：版本/IHL 1 B（低 4 位 IHL 以 4 B 为单位声明头长，取 5 即 20 B——"20 B 起"的起字落在这里，选项字段再往上加）、服务类型 1 B、总长度 2 B、标识 2 B、标志/片偏移 2 B（2.2 的分片兜底机制在这里备料）、生存时间 1 B（Time to Live，TTL，每过一台路由器减 1，防分组在路由环路里永生）、协议 1 B（第二级开关：6 上交 TCP、17 上交 UDP、1 上交 ICMP）、头校验和 2 B（只覆盖头自身，TTL 每跳减 1 都连带一次重算——这笔联动账 02 篇逐跳走）、源地址 4 B、目的地址 4 B。地址对是全帧唯一全程不变的坐标——源与目的从第一跳到最后一跳不改动，逐跳选路与对端回包全靠它。

TCP 头 20 B 起：源端口 2 B、目的端口 2 B（第三级开关——端口对把段交给主机内的进程）、序号 4 B、确认号 4 B（可靠性四件套的坐标系，03 篇展开）、数据偏移/标志 2 B（SYN、FIN、ACK 等控制位集中于此）、窗口 2 B（接收缓冲余量通告，流控用）、校验和 2 B（覆盖伪首部加整段——伪首部把 IP 头里的地址对借来一并校验，端到端数据完整性的锚点）、紧急指针 2 B。UDP 头 8 B 与它同位置二选一：源端口、目的端口、长度、校验和各 2 B，长度字段连自身 8 B 一起计入——同一套端口解复用、同一张校验和配方的最小实现，没有序号、没有确认、没有窗口，03 篇按"省下什么、谁在用"展开它的取舍。

三级开关在字节层面收口：类型在帧头偏移 12~13，协议号在 IP 头偏移 9（全局第 23 字节），端口对在 TCP 头偏移 0~3（全局第 34~37 字节）——解封装链落到字节层面就是三次查表，每次用刚剥掉的头里的两字节决定下一步剥谁。纵向瀑布与横向标尺在此对齐：瀑布的每一级加头，就是标尺上从右向左多吞掉的一段；每一级剥头，就是标尺上从左向右退还一段。分层结构与帧结构至此互为投影，剩下的裁决是：每个功能到底放在哪一层。

## 三、各层边界与功能放置

### 1. 功能放置对照

四层结构立住之后，剩下的是裁决：一个功能到底放哪一层。放错层的代价不是慢一点，而是功能失效或成本翻倍。四个经典裁决——差错校验、寻址、复用、路由——逐一对齐：

| 功能 | 放置的层 | 机制动作 | 归因（成本方向 / 排除法） |
| --- | --- | --- | --- |
| 差错校验·逐跳 | 链路层 FCS | 每段链路收帧即验 CRC32，坏帧当跳丢弃、不转发 | 误码是介质属性，链路一坏当跳处理最便宜；放端到端则坏帧先被转发完一整条路径才被丢弃，中间各跳白付带宽与排队 |
| 差错校验·端到端 | 传输层校验和 | 仅最终两端核对伪首部与载荷 | 逐跳校验管不住两处差错源：路由器转发途中的内存搬运位翻转、校验算法自身的漏检残留；只有端到端能闭合 |
| 寻址·逐跳 | 链路层 MAC 对 | 帧头每跳重写 | MAC 解析只在同段广播域内有效，跨段无意义；段间衔接交给 IP |
| 寻址·端到端 | 网络层地址对 | 源 / 目的 IP 全程不变 | 全帧唯一全程不变的坐标，逐跳查表与对端回包都指向它 |
| 复用 | 传输层端口对 | 端口对区分同主机多进程 | 多进程共享一个 IP 地址，IP 层无法也不应感知进程； $2^{16} = 65536$ 个端口号即复用容量 |
| 路由 | 网络层查表 | 每跳按目的地址查路由表选下一跳 | 全网拓扑只有网络层可见；链路层只见邻接，应用层不应背转发状态 |

两张差错校验行值得单独展开，因为它们覆盖的差错源互补而非重复。FCS 拦介质误码：电与光的物理层天然有误码率，帧一旦在一段链路上被传坏，当跳丢弃重传（或任其丢失，交给上层）最便宜。传输层校验和拦"逐跳全对、端到端仍错"的残留差错：分组在路由器内存里搬运时可能翻转一个位，这一跳的 FCS 已经验过、下一跳的 FCS 验的是新帧，谁也没错，错的只有中间——只有把校验放在最终两端，才能闭合这类缝隙。两级缺一不可：只留端到端，坏帧会占满中间带宽；只留逐跳，最后一段之后的差错无人认账。

### 2. 端到端原则与逐跳原则：中间节点的角色分级

表格背后是一条通用分水岭：功能放在端点还是中间节点。端到端原则的判据：只有端点知道功能是否被需要、实现是否正确——可靠传输若放进路由器，每个中间节点都要为它付状态与缓冲，而真正要它的只有两端，所以放端点。逐跳原则的判据：功能的有效范围天生只有一跳——介质误码、帧编址、同段投递，出了这段链路语义即失效，所以必须放在跳内。两条原则落到中间节点上，产生角色分级，判据是"中间节点动不动本层以上的头"：

| 中间节点 | 参与解析到的层 | 对 IP 头的动作 | 角色 |
| --- | --- | --- | --- |
| 二层交换机 | 链路层，未到网络层 | 完全不可见，按 MAC 表转发帧 | 纯转发 |
| 路由器 | 网络层 | 剥帧头、查路由表、TTL 减 1、重算头校验和、重写帧头 | 参与解析 |
| NAT 网关 | 传输层 | 连地址对带端口对一起改写，重算两级校验和 | 参与解析（改写型） |
| 端系统 | 全部四层 | 剥净全部头，上交进程 | 端点 |

分级为后续各篇定了位置：02-IP与路由走路由器的逐跳事务环——查表怎么查、帧头每跳怎么重写、TTL 与校验和怎么联动；03-TCP与UDP走端系统两端的状态机与可靠性四件套；NAT 网关这类改写型参与解析节点是 02 篇第三节的主角。端到端原则在工程上的另一面也随之可见：凡想在中间节点加功能（过滤、缓存、改写），都要以破坏"层只读写自己的头"的纪律为代价——破坏一次的账单怎么记，02 篇逐笔算。分层模型给了这张分级表一个不变的地基：无论中间节点多复杂，端系统两端的应用进程看到的永远是同一条解封装链。

### 3. 可实操核验

本篇的机制断言多数可亲手验证，集中列全：

| 观察点 | Linux 命令 | Windows 命令 | 预期观察 |
| --- | --- | --- | --- |
| 本机 MTU | `ip link show eth0` | `netsh interface ipv4 show interfaces` | `mtu 1500`：既定常数原样可见 |
| 四级头逐级展开 | `tcpdump -i eth0 -e -nn -X` | Wireshark 抓任意一个包 | 从外向内依次是帧头 → IP 头 → TCP 头 → 应用数据，各头宽度与本篇位标尺一致 |
| 端口与地址 | `ss -tlnp` | `netstat -ano` | 监听行的端口列即端口对的目的端，地址列即地址对的本机侧 |

`tcpdump -e` 把链路层头打出来，每行开头就是目的 MAC 与源 MAC 一对；`-nn` 不做名字解析，直接显示协议号与端口号，三级开关的取值（协议 6、端口 80 等）原样可见；`-X` 附十六进制与 ASCII 对照，帧头前 6 字节即目的 MAC，第 12~13 字节是 08 00——位标尺上类型字段的位置在此现身。Wireshark 的字节面板把同一帧按协议分层高亮，鼠标点到哪一级、下方就点亮对应的字节区间，与 2.3 的标尺逐段吻合。

分层模型到此交付完毕：分层的成因（两端异构逼出 $N + M$ 的细腰）、封装瀑布（逐级加头与三级解封装开关）、长度闸门（MTU 1500 与 MSS 1460）、逐头切分的位标尺、功能放置的裁决与中间节点角色分级。下一跳自底向上逐层进内核：02-IP与路由从链路层剥头之后的位置接手——分组凭 32 位地址对如何逐跳跨网、路由表怎么查、帧头每跳怎么重写，那里是细腰真正的受力现场。
