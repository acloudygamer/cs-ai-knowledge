# 计算机网络

> **版本基准**: universal

本部分回答一个问题：两个进程跑在两台不同的机器上，中间隔着一张不可靠、共享、异构的网络，怎么交换字节？答案是分层——每层只回答一个约束。按数据包的真实旅程从下往上组织。

## 目录

### [01-网络分层模型](./01-网络分层模型.md)
四层框架与每层回答的约束、封装与头部即分发器、MTU 的传导、端到端原则（智能留在边缘）

### [02-IP与路由](./02-IP与路由.md)
网络层：IP 尽力投递的四个"不保证"、前缀路由与最长匹配、BGP 是 AS 之间的共识、NAT 补丁、ping/traceroute 的 ICMP 机制

### [03-TCP与UDP](./03-TCP与UDP.md)
传输层：UDP 原样上交、TCP 四机制补四个不保证、三次握手与四次挥手的真实理由、拥塞控制是对网络容量的分布式探测、QUIC 的由来

### [04-DNS域名系统](./04-DNS域名系统.md)
命名层：层级委托（根→TLD→权威）的分布式数据库、递归与迭代、TTL 缓存的交易、记录类型分工

### [05-HTTP协议](./05-HTTP协议.md)
应用层语义：方法与状态码的分工、无状态与 Cookie、1.1→2→3 演进全是传输层约束的反推、WebSocket

### [06-HTTPS与TLS](./06-HTTPS与TLS.md)
信任层：加密/完整性/身份三件套、混合加密的约束账、证书链与 Secure Boot 同构、TLS 1.3 的 1-RTT

### [07-Socket编程](./07-Socket编程.md)
接口层：socket 是 OS 的门、五元组、listen/accept 双 fd 分工、粘包的真相（字节流无消息边界）、与 epoll 衔接

## 阅读顺序

严格按编号——正是数据包从下往上的旅程。前置依赖是 02-系统软件层（系统调用、epoll）与 04-终端与Shell（诊断命令的使用场景）。
