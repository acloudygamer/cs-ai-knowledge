# HTTPS 与 TLS

## 核心定义：在不安全的链路上建三个保证

HTTP 是明文，且 02 篇讲过：包要经过十几个你完全不认识的路由器。链路上的任何中间人都可以**看**（嗅探）、**改**（篡改）、**冒充**（伪造服务器）。TLS（Transport Layer Security，SSL 的正式后继）在 TCP 之上、HTTP 之下垫一层，把三个问题分别解决：

| 威胁 | 对策 | 工具 |
|------|------|------|
| 被看 | 加密：内容只有两端能读 | 对称加密（AES-GCM、ChaCha20） |
| 被改 | 完整性校验：改动可被检测 | AEAD（加密与完整性一体） |
| 被冒充 | 身份认证：对端拿出可信凭证 | 证书 + 非对称签名 |

HTTPS = HTTP 跑在 TLS 之上，除此之外的语义完全不变。

## 混合加密：两种加密各管一段

**约束**：对称加密快（AES 有硬件指令加速），但密钥要先安全地交到对方手里——在网络上直接发密钥等于裸奔；非对称加密（公钥加密、私钥解密）能解决分发，但慢两个数量级，扛不住数据流。

TLS 的标准解法——**混合加密**：握手阶段用非对称机制协商出一个一次性的**会话密钥**，之后全部数据用对称加密传输。非对称只在开头付一次，数据流享受对称的速度。注意 TLS 1.3（2018）起，密钥协商只留**迪菲-赫尔曼族**（ECDHE）：双方的会话密钥由临时参数算出来、从不离开内存——即使将来私钥泄露，历史流量也无法解密（前向安全）。旧式"用服务器公钥加密会话密钥"的 RSA 传输被彻底删除：它不具备前向安全。

## 证书与 CA：信任从哪来

加密防住了窃听，但防不了"你加密的对方就是个骗子"。握手时服务器出示**证书**：一张写着"此公钥属于 example.com"的数字文件，由**证书颁发机构（CA）**用私钥签名。验证链：

```text
服务器证书 ←（签名）— 中间 CA 证书 ←（签名）— 根 CA 证书
                                              ↑
                              浏览器/操作系统出厂内置的百来个根
```

浏览器逐层验签，最后落在出厂内置的根上——**信任不是凭空来的，是从一个预先安装好的锚点传递出来的**。这套"信任链逐级验签"与《系统软件层》07 篇 Secure Boot（固件验 bootloader、bootloader 验内核）完全同构：一个预置根 + 逐级签名。攻击面也同构：任何一个 CA 沦陷，就能给任意域名签假证书——所以 CA 有审计日志（Certificate Transparency，所有签发记录公开可查），出错即被浏览器除名（2016 年沃通、2017 年赛门铁克的后尘）。

## 握手与 TLS 1.3 的提速

TLS 1.2 握手要 2 个 RTT（协商算法 → 交换密钥与验证书），叠在 TCP 握手的 1 个 RTT 上，建一个 HTTPS 连接先花 3 个 RTT。TLS 1.3 把密钥协商与算法协商合并成 **1-RTT**：客户端第一条消息就带上自己的 DH 参数和算法候选，服务端一条消息完成密钥与认证；对近期访问过的站点还支持 0-RTT 恢复。0-RTT 的代价要知道：早期数据可被**重放**（攻击者原样重发捕获的包）——只适合幂等请求（05 篇的 GET），涉及状态变更的操作必须等握手完成。同时删掉了一批已被破解的历史算法（RC4、3DES、SHA-1 签名……），规则改为"白名单制"——只留少数现代套件， downgrade 攻击的空间被结构性地铲除。

## 边界：TLS 管不到的地方

TLS 保证的是**链路上**的安全：数据离开两端之后呢？服务端的明文存在数据库里（那是《软件工程概念》09 的存储安全与口令哈希问题）；客户端被植入木马，加密毫无意义。此外 TLS 暴露元信息——SNI（要访问的域名，ESNI/ECH 在补）、流量大小与时序特征。**传输层安全是全栈安全的一层，不是全部**——这个边界感本身就是安全素养的一部分。
