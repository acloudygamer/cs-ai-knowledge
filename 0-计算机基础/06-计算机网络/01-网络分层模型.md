# 网络分层模型

## 核心定义：每层只回答一个约束

计算机网络的根本问题：**两个进程跑在两台不同的机器上，中间隔着一张不可靠、被共享、设备五花八门的网络，怎么交换字节？** 这个问题太大，工程的解法是拆——把问题切成四层，每层只回答一个约束，且只与上下相邻层对话：

| 层 | 回答的约束 | 主要协议 | 交付物 |
|----|-----------|---------|--------|
| 链路层 | 同一根线/同一个局域网内，帧给谁 | Ethernet、Wi-Fi | 帧（Frame） |
| 网络层 | 跨异构网络，包往哪条路走 | IP | 包（Packet） |
| 传输层 | 进程到进程，数据可靠吗、给谁 | TCP、UDP | 段（Segment） |
| 应用层 | 字节的语义是什么 | HTTP、DNS | 消息（Message） |

教科书里还有七层的 OSI 模型——它是标准化委员会的产物，实际互联网跑的是上面这个四层（TCP/IP）模型；OSI 的会话层、表示层在现实中被并进了应用层。本篇按真实部署讲四层。

四层与设备的对位顺手钉死：**交换机工作在链路层**（看 MAC 地址转发帧，同一个局域网内）；**路由器工作在网络层**（看 IP 前缀跨网选路，02 篇）；家用"无线路由器"其实是路由器 + 交换机 + 无线接入点三合一。防火墙与负载均衡器工作在传输层及以上（看端口、看 HTTP 内容）。

分层的回报（为什么是这个形状）：**链路层有千百种实现**（双绞线、光纤、Wi-Fi、5G），若应用要感知每种介质，任何新介质都要重写全部应用；分层后，IP 层只认"给我一个能发包的链路"，新介质实现链路层接口即接入全球网络。每一层都是对下一层差异性的屏蔽。

## 封装：数据向下穿层的过程

你的数据从应用层出发，每过一层就被包上一个头部——头部是本层协议干活所需的全部信息：

```text
应用层：  [HTTP 报文]                          ← 方法、路径、头部
传输层：  [TCP 头 | HTTP 报文]                  ← 端口、序号、校验（+20B）
网络层：  [IP 头 | TCP 头 | HTTP 报文]          ← 源/目的 IP（+20B）
链路层：  [以太头 | IP 头 | TCP 头 | HTTP 报文 ] ← MAC 地址（+14B，MTU 1500 限制）
```

接收方反着拆：网卡收帧 → 链路层校验并剥以太头 → 按类型字段上交 IP → IP 剥头按协议号上交 TCP → TCP 按端口交给进程（07 篇的 socket）。**每个头部里的"类型/协议号/端口"字段就是层与层之间的分发器**——剥层时回答"这个包该交给上层的谁"。

以太帧的 MTU（最大传输单元，以太网典型 1500 字节）是链路层向上传导的硬约束：IP 包超了要分片，TCP 因此按 MSS（1500 − 20 − 20 = 1460 字节）切段——链路层的尺寸限制一路传导到传输层的切包策略，这是层间约束传导的实例。

## 端到端原则：智能留在边缘

四层里有个深刻的设计选择：**网络内部（链路层、网络层）只做最简单的尽力投递，可靠性、顺序、重传全部放在端点的传输层**。理由（约束）：中间节点要处理全网的流量，每加一个功能（比如帮你保证不丢包），转发成本就乘上全网流量；而端点只关心自己的连接。把复杂留在边缘，核心保持愚蠢——这是互联网能从几十台主机长到几十亿台的根本原因，也是 TCP（03 篇）存在的位置：**可靠性不是在网络里买的，是在端点上造出来的**。
