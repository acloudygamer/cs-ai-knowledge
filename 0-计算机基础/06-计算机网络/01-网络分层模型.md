# 网络分层模型

## 定义

网络分层模型是将通信系统划分为若干有序层次，每层通过接口向上层提供服务，向下层请求服务，层间交互仅限接口，以局部协议机制换取全局系统复杂度的可管理性。

## 数学模型

层间交互可建模为接口函数调用序列。设第 $n$ 层协议为 $P_n$，相邻层接口为 $I_n$（从 $n$ 层向 $n+1$ 层）：

$$
\text{通信系统} = \bigcup_{i=1}^{7} P_i,\quad \text{约束}: \forall i, P_i \xleftrightarrow{I_i} P_{i+1}
$$

封装过程：第 $n$ 层将第 $n+1$ 层数据 $D_{n+1}$ 封装为 $D_n = \text{Header}_n \parallel D_{n+1}$，其中 $\parallel$ 为拼接操作。设原始应用数据为 $M$，则封装后:

$$
\text{PDU}_{\text{物理层}} = \text{Header}_1 \parallel \text{Header}_2 \parallel \cdots \parallel \text{Header}_7 \parallel M
$$

OSI与TCP/IP模型对应关系：

| OSI层 | 功能 | TCP/IP层 | PDU名称 |
|-------|------|----------|---------|
| 7 应用层 | 应用进程间交换 | 应用层 | 消息 |
| 6 表示层 | 数据表示、加密 | — | 消息 |
| 5 会话层 | 会话管理 | — | 消息 |
| 4 传输层 | 端到端可靠传输 | 传输层 | 段/数据报 |
| 3 网络层 | IP寻址与路由 | 网络层 | 包 |
| 2 数据链路层 | 帧传输、MAC | 网络接口层 | 帧 |
| 1 物理层 | 比特传输 | 网络接口层 | 比特 |

## 数据流

<pre>
发送端封装：

应用层          [数据 M]                              → 消息
                ↓ 挂载HTTP头                          数据不变
传输层          [TCP头 | M]                          → 段
                ↓ 挂载IP头                            长度增加
网络层          [IP头 | TCP头 | M]                   → 包
                ↓ 挂载Ethernet头+FCS                  长度增加
数据链路层       [Eth头 | IP头 | TCP头 | M | FCS]    → 帧
                ↓ 转为电/光/射频信号                   形态完全改变
物理层          010101111000...                      → 比特流

传输介质（网络）
                ↓
接收端解封装：

物理层          比特流                               → 帧
                ↓ 剥离Eth头，验证FCS                  数据不变
数据链路层       [IP头 | TCP头 | M]                   → 包
                ↓ 剥离IP头                           数据不变
网络层          [TCP头 | M]                          → 段
                ↓ 剥离TCP头                           数据不变
传输层          [M]                                 → 消息
                ↓ 交付应用                           数据不变
应用层          M
</pre>

PDU名称与封装层次关系：

```
M (消息)
  ↓ + TCP头 → 段 (Segment)
    ↓ + IP头 → 包 (Packet)
      ↓ + Eth头+FCS → 帧 (Frame)
        ↓ 转为比特 → 比特流 (Bits over medium)
```

## 机制

**为什么分层**：将网络通信的端到端可靠性、路由选择、介质访问控制、信号编码等问题在各自层面独立解决，任一层改动不影响其他层。

**约束**：
- 层间只能通过接口交互，禁止跨层直接调用
- 每层只需知道如何与上下层交互，无需了解其他层内部实现

**违规后果**：
- 跨层耦合导致变更传播，难以独立演进
- 例如：HTTP直接嵌入传输层细节（如TCP拥塞窗口）会失去HTTP层独立性

**层间标识传递**：
- 源IP/目标IP：网络层（全局端到端寻址）
- 源Port/目标Port：传输层（主机内部进程寻址）
- MAC地址：数据链路层（局域网局部寻址）

**常见协议归属**：

| 协议 | 层次 |
|------|------|
| HTTP/DNS/FTP/SMTP | 应用层 (7) |
| TCP/UDP | 传输层 (4) |
| IP/IPv6/ICMP | 网络层 (3) |
| Ethernet/Wi-Fi/PPP | 数据链路层 (2) |
| 10BASE-T/光纤 | 物理层 (1) |

## 参考存根

```python
# TCP/IP四层模型socket创建
import socket

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)  # SOCK_STREAM = TCP
# 内部流程：应用层→传输层socket API→网络层IP→网络接口层Ethernet
```

```bash
# 查看本机网络接口（网络接口层）
ip link show          # Linux
Get-NetAdapter        # Windows PowerShell

# 查看路由表（网络层）
ip route              # Linux
route print           # Windows

# 查看端口监听（传输层）
ss -tulnp             # Linux 显示TCP/UDP监听
netstat -ano | findstr "LISTENING"  # Windows
```
