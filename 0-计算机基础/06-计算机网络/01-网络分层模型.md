# 网络分层模型

## 概念

计算机网络通过分层架构管理复杂性，每层负责特定功能，层间通过接口通信。

```
OSI七层模型                          TCP/IP四层模型
┌─────────────────────────────────┐  ┌───────────────────────┐
│ 7 应用层 (Application)          │  │                       │
├─────────────────────────────────┤  │  应用层               │
│ 6 表示层 (Presentation)         │  │                       │
├─────────────────────────────────┤  ├───────────────────────┤
│ 5 会话层 (Session)              │  │                       │
├─────────────────────────────────┤  │  传输层               │
│ 4 传输层 (Transport)      TCP/UDP │  ├───────────────────────┤
├─────────────────────────────────┤  │                       │
│ 3 网络层 (Network)        IP     │  │  网络层               │
├─────────────────────────────────┤  ├───────────────────────┤
│ 2 数据链路层 (Data Link)  Ethernet│ │  网络接口层           │
├─────────────────────────────────┤  │                       │
│ 1 物理层 (Physical)             │  └───────────────────────┘
└─────────────────────────────────┘
```

## 关系

**关键连接**：
- 传输层 → **网络层**：TCP/UDP在IP协议之上传输数据
- DNS → **传输层**：DNS查询通常使用UDP端口53
- HTTP → **传输层**：HTTP/1.1和HTTP/2基于TCP，HTTP/3基于QUIC(UDP)
- 套接字 → **传输层**：应用程序通过Socket API使用TCP/UDP

## 各层职责

| 层级 | 协议 | 核心功能 | 数据单位 |
|------|------|---------|---------|
| 应用层 | HTTP, DNS, SMTP, FTP | 应用程序协议 | 消息/流 |
| 传输层 | TCP, UDP | 端到端可靠传输 | 段(TCP)/数据报(UDP) |
| 网络层 | IP, ICMP, BGP | 路由与寻址 | 包(Packet) |
| 数据链路层 | Ethernet, Wi-Fi, ARP | 局域网内传输 | 帧(Frame) |
| 物理层 | 光纤/铜缆/无线电 | 比特流传输 | 比特 |

## 协议数据单元 (PDU)

```
应用层:     消息 (HTTP请求/响应)
传输层:     段 (TCP Segment) / 数据报 (UDP Datagram)
网络层:     包 (IP Packet)
数据链路层: 帧 (Ethernet Frame)
物理层:     比特 (Bits)
```

## 封装与解封装

数据在网络中传输时，每层都会添加自己的头部信息：

```
发送过程（封装）：
┌─────────────────────────────────┐
│  应用层：HTTP请求               │  ← 原始数据
├─────────────────────────────────┤
│  传输层：TCP头 + HTTP数据        │  ← TCP段
├─────────────────────────────────┤
│  网络层：IP头 + TCP段            │  ← IP包
├─────────────────────────────────┤
│  数据链路层：Ethernet头 + IP包   │  ← 以太网帧
├─────────────────────────────────┤
│  物理层：转换为电/光信号         │
└─────────────────────────────────┘

接收过程（解封装）：
逐层剥离头部，还原原始数据
```

## TCP vs UDP

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接性 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠（重传、排序） | 不可靠 |
| 拥塞控制 | 有 | 无 |
| 传输速度 | 较慢 | 快 |
| 数据边界 | 字节流，无边界 | 数据报，有边界 |
| 适用场景 | HTTP、邮件、文件传输 | DNS、视频、语音 |

### TCP三次握手

```
客户端                              服务端
   │                                  │
   │─────── SYN (seq=x) ────────────▶│  1. 客户端发送SYN
   │                                  │
   │◀────── SYN-ACK (seq=y, ack=x+1) ─│  2. 服务器返回SYN-ACK
   │                                  │
   │─────── ACK (ack=y+1) ──────────▶│  3. 客户端发送ACK
   │                                  │
   │         建立完成                  │
```

### TCP四次挥手

```
客户端                              服务端
   │                                  │
   │─────── FIN (seq=x) ────────────▶│  1. 主动关闭方发送FIN
   │                                  │
   │◀────── ACK (ack=x+1) ───────────│  2. 被动方发送ACK
   │                                  │  （可能还有数据要发送）
   │                                  │
   │◀────── FIN (seq=y) ─────────────│  3. 被动方发送FIN
   │                                  │
   │─────── ACK (ack=y+1) ──────────▶│  4. 主动方发送ACK
   │                                  │
   │         连接关闭                  │
```

### TCP状态转换

```python
# TCP连接状态
tcp_states = {
    # 客户端状态
    "CLOSED": "无连接",
    "SYN_SENT": "已发送SYN",
    "ESTABLISHED": "连接建立",
    "FIN_WAIT_1": "已发送FIN",
    "FIN_WAIT_2": "收到ACK，等待被动方FIN",
    "TIME_WAIT": "等待2MSL后关闭",

    # 服务端状态
    "LISTEN": "监听中",
    "SYN_RECEIVED": "收到SYN，发送SYN-ACK",
    "CLOSE_WAIT": "收到FIN，等待应用关闭",
    "LAST_ACK": "等待最后ACK"
}
```

## IP协议

IP是网络层的核心协议，负责寻址和路由：

```python

```

**IPv4 vs IPv6**：

| 特性 | IPv4 | IPv6 |
|------|------|------|
| 地址长度 | 32位 | 128位 |
| 地址格式 | 192.168.1.1 | 2001:0db8::1 |
| 地址数量 | ~40亿 | 无限 |
| 头部大小 | 可变 | 固定40字节 |
| 安全 | 无内置 | IPsec内置 |

## ARP协议

地址解析协议，将IP地址解析为MAC地址：

```
┌──────────────────────────────────────────────────┐
│ 主机A (IP: 192.168.1.10) 想要发送数据给           │
│ 主机B (IP: 192.168.1.20)                         │
│                                                  │
│ 1. A检查ARP缓存是否有B的MAC                      │
│ 2. 没有，广播ARP请求："谁是192.168.1.20？"       │
│ 3. 主机B收到后单播ARP响应："192.168.1.20是我，    │
│    MAC地址是 aa:bb:cc:dd:ee:ff"                   │
│ 4. A缓存B的MAC地址                                │
│ 5. 发送数据帧                                     │
└──────────────────────────────────────────────────┘
```

```bash
# 查看ARP缓存
arp -a                  # Windows/Linux
ip neigh                # Linux

# 静态添加ARP条目
arp -s 192.168.1.20 aa:bb:cc:dd:ee:ff
```

## HTTP协议

HTTP是应用层协议，浏览器和服务器通信的基础：

### HTTP请求结构

```
┌─────────────────────────────────────┐
│ GET /index.html HTTP/1.1            │  ← 请求行
│ Host: www.example.com               │  ← 请求头
│ User-Agent: Mozilla/5.0             │
│ Accept: text/html                  │
│                                     │
│                                     │  ← 空行
│                                     │  ← 请求体（POST/PUT时）
└─────────────────────────────────────┘
```

### HTTP响应结构

```
┌─────────────────────────────────────┐
│ HTTP/1.1 200 OK                      │  ← 状态行
│ Content-Type: text/html             │  ← 响应头
│ Content-Length: 1234                │
│                                     │
│                                     │  ← 空行
│ <html>...</html>                    │  ← 响应体
└─────────────────────────────────────┘
```

### HTTP方法

| 方法 | 用途 | 幂等性 | 安全性 |
|------|------|--------|--------|
| GET | 获取资源 | 幂等 | 安全 |
| POST | 创建资源 | 非幂等 | 不安全 |
| PUT | 更新/替换资源 | 幂等 | 不安全 |
| PATCH | 部分更新 | 非幂等 | 不安全 |
| DELETE | 删除资源 | 幂等 | 不安全 |
| HEAD | 获取响应头 | 幂等 | 安全 |
| OPTIONS | 获取支持的方法 | 幂等 | 安全 |

### HTTP状态码

| 类别 | 范围 | 含义 |
|------|------|------|
| 1xx | 100-199 | 信息性响应 |
| 2xx | 200-299 | 成功 |
| 3xx | 300-399 | 重定向 |
| 4xx | 400-499 | 客户端错误 |
| 5xx | 500-599 | 服务器错误 |


### HTTP/1.1 vs HTTP/2 vs HTTP/3

| 特性 | HTTP/1.1 | HTTP/2 | HTTP/3 |
|------|----------|--------|--------|
| 传输协议 | TCP | TCP | QUIC (UDP) |
| 多路复用 | 无（管线化有局限） | 有（stream） | 有 |
| 头部压缩 | 无 | HPACK | QPACK |
| 服务器推送 | 无 | 有 | 有 |
| 队头阻塞 | 有 | 无（TCP层） | 无 |
| 连接复用 | 需新建 | 复用同一连接 | 复用同一连接 |

## WebSocket

WebSocket提供全双工通信，比HTTP更高效：

```javascript
// 客户端
const ws = new WebSocket('wss://example.com/ws');

ws.onopen = () => {
    console.log('Connected');
    ws.send('Hello');  // 主动发送消息
};

ws.onmessage = (event) => {
    console.log('Received:', event.data);
};

ws.onclose = () => {
    console.log('Disconnected');
};

// 服务端 (Node.js ws库)
const { WebSocketServer } = require('ws');
const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (ws) => {
    ws.on('message', (message) => {
        console.log('Received:', message.toString());
        ws.send('Echo: ' + message);  // 回复消息
    });
});
```

**WebSocket vs HTTP**：

| 特性 | WebSocket | HTTP |
|------|-----------|------|
| 方向 | 全双工 | 请求-响应 |
| 连接 | 持久连接 | 短连接 |
| 首部开销 | 小（7-13字节） | 大 |
| 服务器推送 | 支持 | 需轮询/SSE |
| 适用场景 | 实时应用、游戏 | REST API |

## 网络安全基础

### 对称加密 vs 非对称加密

```python
# 对称加密：加密解密用同一密钥
# 算法：AES, DES, 3DES, ChaCha20
# 问题：密钥分发困难

# 非对称加密：公钥加密，私钥解密
# 算法：RSA, ECC, Ed25519
# 问题：计算慢
# 用途：密钥交换、数字签名

# 混合加密方案（HTTPS使用）：
# 1. 用非对称加密交换会话密钥
# 2. 用会话密钥（对称加密）加密实际数据
```

### SSL/TLS握手

```
客户端                              服务器
   │                                  │
   │─────── ClientHello ────────────▶│  支持的TLS版本、加密套件
   │                                  │
   │◀────── ServerHello ─────────────│  选定加密套件
   │◀────── Certificate ─────────────│  服务器证书（含公钥）
   │◀────── ServerHelloDone ────────│
   │                                  │
   │─────── ClientKeyExchange ───────▶│  预主密钥（用公钥加密）
   │─────── ChangeCipherSpec ────────▶│
   │─────── Finished ───────────────▶│
   │                                  │
   │◀────── ChangeCipherSpec ────────│
   │◀────── Finished ────────────────│
   │                                  │
   │     加密通信开始                  │
```

```bash
# 查看证书信息
openssl s_client -connect example.com:443 -showcerts
echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates -issuer

# 查看证书链
echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -issuer -subject -chain
```
