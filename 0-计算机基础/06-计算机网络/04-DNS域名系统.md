# DNS 域名系统

## 核心定义：一个层级委托的分布式缓存数据库

DNS（Domain Name System）回答一个问题：**把 `www.example.com` 变成 `203.0.113.10`**。为什么需要它（约束）：IP 地址是给路由器的（层级前缀，见 02 篇），不适合人记，且会变（换机房换 IP）；名字是给人的，要稳定。名字与地址之间必须有一层映射服务。

这个服务的约束极苛刻：全球每一台联网设备都依赖它、查询量每秒以亿计、还不能有单点故障。DNS 的形状全部由这些约束推出：**层级化 + 委托 + 缓存**。

## 层级委托：没有谁有全表

域名从右往左读层级：`www.example.com.` = 根（`.`，通常省略）→ 顶级域（`com`）→ 权威域（`example.com`）→ 主机名（`www`）。每一级由不同的服务器群负责，每级只知道自己下一级的地址：

```text
递归解析器问根服务器：  "www.example.com 在哪？"
  根：不知道，但 .com 的服务器在那几个地址 ──┐
解析器问 .com 服务器：   "www.example.com 在哪？"│ 迭代
  .com：不知道，去问 example.com 的权威服务器 ──┤
解析器问权威服务器：     "www.example.com 在哪？"│
  权威：203.0.113.10 ◄──────────────────────────┘
```

- **根服务器**：全球 13 组逻辑节点（anycast 出数百个物理实例），只做一件事：告诉你各顶级域（.com/.org/.cn）的服务器在哪。
- **权威服务器**：域名持有者自己（或托管商）维护的服务器，是某个域名的**唯一真相来源**——你买的域名改解析，改的就是它。

任何人查任何域名，最终都由这三段接力完成。没有全表，没有中心——这就是它能扛住全球规模的结构原因。

## 递归与缓存：你的电脑从不亲自迭代

应用只发一次请求给**递归解析器**（运营商提供的、或 `8.8.8.8`/`114.114.114.114` 这类公共解析器），迭代查询的苦活由递归解析器代劳。然后是最关键的一层：**缓存**。

每个 DNS 记录带 **TTL**（存活时间）。递归解析器把结果缓存 TTL 时长，期间相同查询直接回——`com` 服务器的地址、热门域名的解析，几乎永远在缓存里，迭代极少真的发生。你电脑里还有本机缓存和 hosts 文件（最先查，优先级最高——所以改 hosts 能劫持本机解析）。

TTL 是全局一致性与变更速度的交易：TTL 长则缓存命中率高、权威服务器压力小，但改解析后生效慢；运维实践是**变更前先把 TTL 调小，变更后再调回**。

## 记录类型：同一个数据库装多种答案

DNS 不止答 IP，一张表分清用途：

| 记录 | 回答 | 用途 |
|------|------|------|
| A / AAAA | 域名 → IPv4 / IPv6 | 基本解析 |
| CNAME | 域名 → 另一个域名 | 别名（`www` → CDN 域名），只能指向名字不能指向 IP |
| MX | 域名 → 邮件服务器 | 邮件投递路由 |
| TXT | 域名 → 任意文本 | 域名所有权验证、SPF 反垃圾邮件 |
| NS | 域名 → 权威服务器 | 委托的依据 |

排障工具一句：`dig example.com`（或 `nslookup`）直接发起一次解析并展示各段答案；加 `+trace` 参数可亲眼看到从根到权威的完整迭代链。怀疑 DNS 先 dig，再查本机缓存与 hosts 文件。

DNS 本身是 UDP 的应用（一问一答正好一个报文——03 篇"丢了重问"的场景），报文超 512 字节或区域传送时才退回 TCP。它不加密的年代缺陷（明文、可篡改）催生了 DoH/DoT（把 DNS 包进 HTTPS/TLS，见 06 篇），那是安全层补的课。
