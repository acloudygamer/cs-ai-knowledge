# 字节序与位运算

## 定义

字节序定义多字节数据（uint16/uint32/uint64）在内存中的字节排列顺序；位运算是对整数二进制位的逐位操作，包括按位与、或、异或、取反及移位。字节序决定了多字节数据的物理存储视角，位运算决定了数据的逻辑变换能力。两者共同构成计算机底层数据表示的完整图景。

字节序的选择本质上是"字节地址"与"数值权重"的映射问题：给定一个多字节数值，其最低有效字节是存在低地址还是高地址，决定了是大端还是小端。

## 数学模型

**字节序的数学定义：**

给定一个 $N$ 字节无符号整数 $V$：
$$
V = \sum_{i=0}^{N-1} b_i \times 2^{8i}
$$

其中 $b_i$ 是第 $i$ 字节（$i=0$ 为最低字节）。内存地址 $[A, A+N)$ 中字节排列为：

- **大端序**：$[A] = b_{N-1}, [A+1] = b_{N-2}, \ldots, [A+N-1] = b_0$
- **小端序**：$[A] = b_0, [A+1] = b_1, \ldots, [A+N-1] = b_{N-1}$

大端序的字节序与数值的自然书写顺序一致（最高字节在低地址），小端序的字节序与数值的二进制权重顺序一致（最低字节在低地址）。

**位掩码的精确提取：**

$$
\text{提取第 } n \text{ 位（从 0 开始）} = (v \gg n) \& 1
$$

$$
\text{提取第 } [l, r] \text{ 位区间} = (v \gg l) \& ((1 \ll (r-l+1)) - 1)
$$

**有符号移位的语义：**

- 逻辑右移（无符号）：高位补 0
- 算术右移（有符号）：高位补符号位

算术右移等价于除以 $2^n$ 并向负无穷取整（对负数）。

**字节序转换（网络序/主机序）：**

$$
V_{network} = \text{hton}(V_{host}) = \sum_{i=0}^{N-1} b_{N-1-i} \times 2^{8i}
$$

## 数据流

<pre>
大端序 (0x12345678):
地址:   0x00   0x01   0x02   0x03
字节:   0x12  0x34   0x56   0x78
        MSB                         LSB
        ↑ 高位字节在低地址，符合"人类阅读顺序"

小端序 (0x12345678):
地址:   0x00   0x01   0x02   0x03
字节:   0x78  0x56   0x34   0x12
        LSB                         MSB
        ↑ 低位字节在低地址，利于"低位优先"算术运算

字节序转换（0x12345678 小端 → 网络序）:
字节序列 [0x78, 0x56, 0x34, 0x12] → [0x12, 0x34, 0x56, 0x78]
</pre>

## 机制

### 大端序

大端序的优势是符号位的快速判断——最高字节在最低地址，比较符号只需检查 $[A]$ 一个字节。

**约束条件：**
- 字符串比较可直接按内存顺序（ASCII 字符串自然是大端序存储）
- 网络字节序（TCP/IP）统一使用大端序
- 某些 RISC 架构（早期 MIPS/SPARC）默认大端序

**违反后果：**
- x86 系统向网络发送数据前未调用 `htonl/htons` → 接收方解析出错误数值
- 文件格式（如 PDF 1.2 规定大端）跨平台读取时字节序不匹配

### 小端序

小端序的优势是数值运算的自然进位——整数加法的进位从最低字节向最高字节传播，而小端序中最低字节在最低地址，内存访问序列与算术进位方向一致。

**约束条件：**
- x86/x64、ARM（大多数，ARMv8 默认小端）默认小端序
- 整数算术从低位向高位进位/借位
- 强制类型转换（uint32* → uint8*）首地址即为最低字节

**违反后果：**
- 跨平台网络编程必须转换字节序
- 二进制文件格式若未规定字节序，跨平台读取会出错
- 多字节数据（如 uint32、float）跨端解析时必须考虑字节序，单字节数据（char）无此问题

### 位运算安全规则

位运算是无符号整数的"自然语言"，但 C/C++ 对有符号整数的位运算有定义陷阱。

**规则 1：移位宽度必须小于类型宽度**

```c
uint32_t x;
x >> 32;  // UB：移位宽度 >= 类型宽度（32）
x >> 31;  // OK：移位宽度 < 类型宽度
```

**约束：** 移位超过类型宽度是未定义行为（Undefined Behavior），编译器可能将其优化为任意值。

**规则 2：有符号数算术右移是实现定义**

```c
int8_t y = -1;
y >> 1;  // 实现定义：可能是 -1（算术右移）或 127（逻辑右移）
```

**约束：** C++ 标准规定算术右移对负数是实现定义的。实际中，MSVC/Clang/GCC 在 x86 上都用算术右移，但代码可移植性不能依赖此行为。

**规则 3：有符号整数溢出是未定义行为**

```c
int32_t z = INT32_MAX;
z + 1;  // UB：溢出
```

**约束：** 编译器假定了有符号溢出不会发生，可能将其优化掉。例如 `if (x+1 > x)` 可能被优化为 `true`（即使 x=INT32_MAX）。

**规则 4：位运算优先使用无符号类型**

```c
// 不安全：负数右移是实现定义
int flags = -1;
if (flags & 0x80)  // UB 或实现定义

// 安全：显式无符号
uint8_t flags = 0xFF;
if (flags & 0x80)  // 明确：检查最高位
```

### 字节序检测与转换

```c
// 运行时检测
bool is_little_endian = (*(uint16_t*)"\xFF\x00" == 0xFF);

// 网络编程标准 API
uint32_t htonl(uint32_t x);  // host to network long
uint16_t htons(uint16_t x);  // host to network short
uint32_t ntohl(uint32_t x);  // network to host long
uint16_t ntohs(uint16_t x);  // network to host short
```

```c
// 权限检查（位掩码）
#define READ  0x04
#define WRITE 0x02
#define EXEC  0x01
int has_perm(int p, int req) { return (p & req) == req; }
```

```c
// 跨平台字节序转换
uint32_t swap_endian(uint32_t x) {
    return ((x & 0x000000FF) << 24) |
           ((x & 0x0000FF00) <<  8) |
           ((x & 0x00FF0000) >>  8) |
           ((x & 0xFF000000) >> 24);
}
```
