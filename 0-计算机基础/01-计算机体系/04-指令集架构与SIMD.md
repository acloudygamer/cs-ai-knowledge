# 指令集架构（ISA）与 SIMD 向量并行计算

### 4.1 软硬件的分界线：ISA、汇编与微架构

计算机系统之所以能够实现“同一份 Windows 或 Linux 程序，既能在 Intel 酷睿上运行，也能在 AMD 锐龙上运行，甚至在十年前的老 CPU 上也能跑”，全靠 **ISA（指令集架构）** 与 **微架构（Microarchitecture）** 的严格解耦：

* **ISA（架构规范，What it does）**：定义了软件能看到的抽象机器——有哪些寄存器、支持哪些机器码指令、每条指令执行后寄存器和内存会变成什么状态。
* **微架构（硬件实现，How it is done）**：芯片设计师在硅片上如何用流水线、乱序执行引擎、分支预测器和高速缓存把这套规范造出来。Intel 的 Golden Cove 和 AMD 的 Zen 4 是截然不同的**微架构**，但它们都实现了 **x86-64 ISA**。

```text
+-----------------------------------------------------------------------+
|  高级语言源码 (C / C++ / Rust)        for (i=0; i<N; i++) c[i]=a[i]+b[i] |
+-----------------------------------------------------------------------+
                                   |
                                   v  [ 编译器 Compiler (前端优化 + 后端代码生成) ]
+-----------------------------------------------------------------------+
|  汇编语言 (Assembly Language)         vaddps ymm0, ymm1, ymm2         |
|  * 人类可读的助记符 (Mnemonics)，包含少量伪指令与语法糖               |
+-----------------------------------------------------------------------+
                                   |
                                   v  [ 汇编器 Assembler (近乎 1:1 编码映射) ]
+=======================================================================+

|                                                                       |
|  =================> 【 指令集架构 (ISA) 软硬件契约层 】 <=============== |
|  规定：1. 架构寄存器集合 (GPR / SIMD Vector)   2. 指令二进制编码格式  |
|        3. 内存寻址与一致性模型                 4. 异常与特权级接口    |
+=======================================================================+

+-----------------------------------------------------------------------+

```

### 4.2 指令集的设计哲学：CISC（Complex Instruction Set Computer，复杂指令集）与 RISC（Reduced Instruction Set Computer，精简指令集）

在 ISA 的演进史上，围绕“指令应该设计得复杂还是简单”，诞生了两大阵营：

#### 1. CISC（复杂指令集，以 x86-64 为代表）

* **设计初衷**：在早期内存极其昂贵的年代，力求用最少的指令条数、最紧凑的代码体积完成复杂任务。
* **核心特征**：
  * **变长指令编码**：一条 x86 指令最短只有 1 字节（如 `nop`、`ret`），最长可达 15 字节（包含各种前缀、操作码、寻址方式和立即数）。
  * **寄存器-内存架构（Register-Memory）**：允许一条算术指令直接读取内存并做加法，例如 `add eax, [rbx + rcx*4 + 0x10]`。



#### 2. RISC（精简指令集，以 ARM64、RISC-V 为代表）

* **设计初衷**：遵循“让常见的情况跑得最快”原则，简化硬件译码器复杂度，把省下来的晶体管用来堆更多的寄存器和更深的流水线。
* **核心特征**：
  * **定长指令编码**：绝大多数指令固定为 32 位（4 字节），硬件可以极其轻松地在一个周期内并行切分并译码 4~8 条指令。
  * **加载-存储架构（Load-Store）**：算术指令（如 `add`）只能操作寄存器，绝对不能直接访问内存；访问内存必须显式使用专门的 `ld`（加载）和 `st`（存储）指令。



```text
[ RISC 定长编码示例：RISC-V 32-bit R-Type 指令 (固定 4 字节，硬件译码极简) ]
 31         25 24     20 19     15 14   12 11      7 6           0
+-------------+---------+---------+-------+---------+-------------+
|   funct7    |   rs2   |   rs1   |funct3 |   rd    |   opcode    |
|   (7 bits)  | (5 bits)| (5 bits)|(3bits)| (5 bits)|  (7 bits)   |
+-------------+---------+---------+-------+---------+-------------+
       |           |         |        |        |           |
       |           |         |        |        |           +--> 操作码主类
       |           |         |        |        +--------------> 目标寄存器
       |           |         |        +-----------------------> 运算子类型
       |           |         +--------------------------------> 源寄存器 1
       |           +------------------------------------------> 源寄存器 2
       +------------------------------------------------------> 扩展功能码

[ CISC 变长编码示例：x86 指令格式 (1 ~ 15 字节不等，边界需串行扫描识别) ]
+----------+------------+--------+--------+-----+------------+------------+
| Prefixes | VEX/EVEX   | Opcode | ModR/M | SIB | Displace-  | Immediate  |
| (可选前缀)| (SIMD前缀) | (操作码)|(寻址模)|(比例| ment(偏移) | (立即数)   |

```

> **现代微架构的殊途同归**：如今的 x86 处理器实际上是“披着 CISC 外衣的 RISC 内核”。当一条复杂的 x86 指令进入 CPU 前端后，硬件译码器会瞬间将其拆解为一条或多条定长的、类似 RISC 的**微操作（Micro-operations, $\mu\text{ops}$）**，再送入后端的乱序执行引擎中处理。

### 4.3 从标量 ISA 到向量 ISA：为什么需要 SIMD？

在传统的标量指令集（**SISD，单指令单数据流**）中，一条指令只能处理一对标量数据（比如两个 32 位整数相加）。

假设我们要给一张 $1920 \times 1080$ 的图片调高亮度，需要对约 200 万个像素执行完全相同的加法运算。在标量 ISA 下，CPU 必须把【取指 -> 译码 -> 寄存器重命名 -> 发射 -> 执行 -> 写回】这套繁琐的流水线重复执行 200 万次！此时，**CPU 超过 70% 的功耗都浪费在了前端“反复读取和解析同一条加法指令”的控制逻辑上**，真正花在加法器（ALU）上的能量微乎其微。

为了打破这一僵局，体系结构师对 ISA 进行了革命性扩容——引入 **SIMD（Single Instruction, Multiple Data，单指令多数据流）**。

```text
================== 1. SISD (传统标量指令流：逐个击破) ==================

   指令流 (Instruction)          数据流 (Data)             计算结果
  +--------------------+        +-------------+         +-------------+
  | add s0, s1, s2     | -----> |  A0  +  B0  | ------> |   C0 = A0+B0|  (周期 1)
  +--------------------+        +-------------+         +-------------+
  | add s3, s4, s5     | -----> |  A1  +  B1  | ------> |   C1 = A1+B1|  (周期 2)
  +--------------------+        +-------------+         +-------------+
  | add s6, s7, s8     | -----> |  A2  +  B2  | ------> |   C2 = A2+B2|  (周期 3)
  +--------------------+        +-------------+         +-------------+
  | add s9, s10, s11   | -----> |  A3  +  B3  | ------> |   C3 = A3+B3|  (周期 4)
  +--------------------+        +-------------+         +-------------+
  * 缺陷：4 次取指、4 次译码、4 次发射，前端控制开销极大。


================== 2. SIMD (单指令多数据流：一次广播，并行吞吐) =========

   单一向量指令                  多通道数据阵列 (Lanes)     并行输出向量
                                +---------------------+   +-----------+
                         +----> | Lane 0:  A0  +  B0  |-->| C0 = A0+B0|
                         |      +---------------------+   +-----------+
  +--------------------+ |      | Lane 1:  A1  +  B1  |-->| C1 = A1+B1|
  | vadd v0, v1, v2    |-+----> +---------------------+   +-----------+  (仅需 1 个
  | (仅取指与译码 1 次)| |      | Lane 2:  A2  +  B2  |-->| C2 = A2+B2|   执行周期)
  +--------------------+ |      +---------------------+   +-----------+
                         +----> | Lane 3:  A3  +  B3  |-->| C3 = A3+B3|
                                +---------------------+   +-----------+
  * 优势：1 次取指译码控制开销被 4 个数据通道均摊 (Amortized)，吞吐量翻 4 倍！

```

### 4.4 SIMD 对 ISA 的三大核心架构扩展

为了让 CPU 支持 SIMD，必须在 ISA 契约层面进行以下三项核心扩展：

#### 扩展一：寄存器位宽扩展与“数据通道（Lanes）”切分

传统的通用寄存器（如 x86 的 `RAX`、RISC-V 的 `x1`）只有 64 位宽。SIMD 扩展在 ISA 中专门开辟了一组超宽的**向量寄存器（Vector Registers）**。

以 x86 架构为例，它的向量寄存器经历了三代平滑扩充，且低位完全复用：

* **SSE 时代（128-bit）**：引入 `XMM0 ~ XMM15`（可打包 4 个 32 位浮点数 `float`）。
* **AVX/AVX2 时代（256-bit）**：扩宽为 `YMM0 ~ YMM15`（可打包 8 个 `float`）。
* **AVX-512 时代（512-bit）**：扩宽为 `ZMM0 ~ ZMM31`（可打包 16 个 `float` 或 64 个 `int8`）。

```text
|<----------------------------------- ZMM0 (512 bits, AVX-512) ---------------------------------->|
                                  |<----------------- YMM0 (256 bits, AVX2) --------------------->|
                                                                    |<--- XMM0 (128 bits, SSE) -->|
+---------------------------------+---------------------------------+-----------------------------+
|        Bit 511 ... 256          |         Bit 255 ... 128         |        Bit 127 ... 0        |
+---------------------------------+---------------------------------+-----------------------------+

当把一个 256 位的 YMM 寄存器按不同数据类型“打包 (Packed)”解释时，硬件通道 (Lanes) 切分如下：

1) 8 x 32-bit 单精度浮点 (Packed Single-Precision, 后缀 ps)：
+--------+--------+--------+--------+--------+--------+--------+--------+
| FP32_7 | FP32_6 | FP32_5 | FP32_4 | FP32_3 | FP32_2 | FP32_1 | FP32_0 |  (8 个并行通道)
+--------+--------+--------+--------+--------+--------+--------+--------+

2) 4 x 64-bit 双精度浮点 (Packed Double-Precision, 后缀 pd)：
+-----------------+-----------------+-----------------+-----------------+
|     FP64_3      |     FP64_2      |     FP64_1      |     FP64_0      |  (4 个并行通道)
+-----------------+-----------------+-----------------+-----------------+

3) 32 x 8-bit 字节整数 (Packed Byte Integer, 常用于图像/AI量化)：
+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+
|B31|30|..|..|..|..|..|..|..|..|..|..|..|..|..|..|..|..|..|..|B3|B2|B1|B0|  (32 个并行通道)
+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+

```

> **定长 SIMD vs. 可变长向量（VLA）**：
> x86 AVX 和 ARM NEON 属于**定长 SIMD**，寄存器宽度写死在指令名里，每次硬件加宽都要发明一套新指令。而最新的 **RISC-V Vector (RVV)** 和 **ARM SVE** 采用了更先进的**向量长度无关（Vector-Length Agnostic）**设计——指令不关心寄存器到底是 128 位还是 1024 位，硬件在运行时自动告知当前芯片单次能吞吐多少个元素，同一份机器码可以在不同宽度的芯片上自动跑满算力。

#### 扩展二：专属向量操作码（广播、纵向运算、横向归约）

SIMD 指令集定义了丰富的通道操控指令：

1. **纵向对位运算（Vertical Operations）**：两个向量寄存器对应通道独立计算（如 `vaddps`、`vmulps`），互不干扰，单周期吞吐率最高。
2. **融合乘加（FMA, Fused Multiply-Add）**：一条指令在单周期内同时完成 $A \times B + C$，且中间乘法不进行浮点数舍入，精度更高、算力直接翻倍。
3. **标量广播（Broadcast）**：将一个标量常数瞬间复制填满向量寄存器的所有通道。
4. **跨通道重排与横向归约（Shuffle / Horizontal Reduction）**：打乱通道顺序，或将所有通道的值累加到一个标量中（由于需要跨通道布线传输，硬件开销高于纵向运算）。

#### 扩展三：分支发散的救星——谓词掩码（Predication / Masking）

在循环中一旦遇到 `if (x[i] > 0)` 这样的条件判断，传统标量指令会使用条件跳转指令（`jne` / `beq`）改变程序计数器（PC）。但在 SIMD 中，**8 个通道共享同一个 PC，不可能让通道 0 跳转，而通道 1 不跳转**（这被称为**控制流发散 Branch Divergence**）。

为了解决这个问题，现代 SIMD ISA 引入了**谓词掩码寄存器（Mask Registers，如 AVX-512 的 `k0~k7`）**：所有通道全部顺序执行，但只有掩码位为 `1` 的通道才允许写入结果，掩码为 `0` 的通道直接屏蔽丢弃！

```text
代码逻辑：for (i=0; i<4; i++) { if (A[i] > 0) C[i] = A[i] + B[i]; else C[i] = B[i]; }

步骤 1: 向量比较指令 (vcmpgtps) 生成掩码位 (Mask)
        向量 A      : [  5.0  | -2.0  |  3.0  | -8.0  ]
        条件 (A > 0): [ True  | False | True  | False ]
                         |        |       |       |
                         v        v       v       v
        掩码寄存器 k1: [   1   |   0   |   1   |   0   ]

步骤 2: 带掩码的向量加法指令 vaddps ymm_c {k1}, ymm_a, ymm_b (默认用向量 B 打底)
        向量 A      : [  5.0  | -2.0  |  3.0  | -8.0  ]
        向量 B      : [  1.0  |  4.0  |  2.0  |  6.0  ]
        -------------------------------------------------
        硬件算术单元: [  6.0  |  2.0  |  5.0  | -2.0  ]  (全部通道实际上都算了 A+B)
        掩码开关 k1 : [ 导通1 | 拦截0 | 导通1 | 拦截0 ]  (k1=0 的通道保持原值 B[i])
                         |        |       |       |
                         v        v       v       v
        最终输出 C  : [  6.0  |  4.0  |  5.0  |  6.0  ]  (全程无任何分支跳转，流水线零停顿！)

```

### 4.5 实战贯通：从 C 代码到标量汇编与 SIMD 汇编

为了把“高级语言 $\rightarrow$ 汇编语言 $\rightarrow$ ISA 寄存器与机器码行为”彻底串联起来，我们来看一段对两个长度为 1024 的浮点数组相加的代码：

```c
void vec_add(const float * restrict a, const float * restrict b, float * restrict c) {
    for (int i = 0; i < 1024; i++) {
        c[i] = a[i] + b[i];
    }
}

```

假设在 x86-64 Linux 环境下，数组指针 `a`、`b`、`c` 分别通过寄存器 `rdi`、`rsi`、`rdx` 传入：

#### 对比 1：禁用 SIMD 生成的标量汇编（SISD 模式）

编译器只能每次移动 4 字节（1 个 `float`），使用标量指令 `addss`（Add Scalar Single-precision），只用到 `xmm0` 最低的 32 位，其余高位全部闲置浪费，**循环必须执行 1024 次**：

```nasm
.L_scalar_loop:
    movss   xmm0, DWORD PTR [rdi + rax*4]   ; 从内存加载 1 个 float (a[i]) 到 xmm0 低 32 位
    addss   xmm0, DWORD PTR [rsi + rax*4]   ; 标量相加：仅将低 32 位与 b[i] 相加 (SISD)
    movss   DWORD PTR [rdx + rax*4], xmm0   ; 将 1 个 float 结果写回内存 c[i]
    add     rax, 1                          ; 循环索引 i += 1
    cmp     rax, 1024                       ; 比较 i 是否达到 1024
    jne     .L_scalar_loop                  ; 若未达到则跳回继续 (共需循环 1024 次)

```

#### 对比 2：开启 AVX2 生成的向量汇编（SIMD 模式）

当开启 `-O3 -mavx2` 编译选项后，编译器利用 256 位的 `ymm0` 寄存器和打包向量指令 `vaddps`（Vector Add Packed Single-precision），每次迭代一口气吞吐 32 字节（8 个 `float`），**循环次数骤降至 128 次，指令条数减少为原来的 1/8**：

```nasm
.L_simd_loop:
    vmovups ymm0, YMMWORD PTR [rdi + rax]   ; 一次加载 8 个连续 float (a[i..i+7]，共32字节)
    vaddps  ymm0, ymm0, YMMWORD PTR [rsi + rax] ; 8 通道并行相加：ymm0 的 8 个 float 与 b[i..i+7] 同时相加！
    vmovups YMMWORD PTR [rdx + rax], ymm0   ; 一次将 8 个 float 结果写回内存 c[i..i+7]
    add     rax, 32                         ; 字节偏移量每次前进 32 字节 (8 * 4 Bytes)
    cmp     rax, 4096                       ; 比较是否处理完 4096 字节 (1024 * 4 Bytes)
    jne     .L_simd_loop                    ; 若未完成则跳回 (总共只需循环 128 次！)
    vzeroupper                              ; 清空 YMM 高位状态，避免与旧版 SSE 指令混用产生微架构惩罚

```
