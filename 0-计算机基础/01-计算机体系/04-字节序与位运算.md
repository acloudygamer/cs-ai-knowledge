# 字节序与位运算

> **版本基准**: universal

## 定义

字节序定义多字节数据（uint16/uint32/uint64）在内存中的字节排列顺序；位运算是对整数二进制位的逐位操作，包括按位与、或、异或、取反及移位。字节序决定了多字节数据的物理存储视角，位运算决定了数据的逻辑变换能力。两者共同构成计算机底层数据表示的完整图景。

字节序的本质是地址映射问题：给定一个 $N$ 字节数值，其字节在 $[A, A+N)$ 地址范围内的排列顺序，取决于"权重大的字节放低地址还是高地址"这一设计选择。

**归约终点**：字节序可归约为"字节权重与地址序的映射关系"。大端序是权重序与地址序同构（权重大的字节地址小），小端序是权重序与地址序反构（权重大的字节地址大）。

## 数学模型

### 字节序的数学定义

给定一个 $N$ 字节无符号整数 $V$：
$$
V = \sum_{i=0}^{N-1} b_i \times 2^{8i}
$$

其中 $b_i$ 是第 $i$ 字节（$i=0$ 为最低字节）。内存地址 $[A, A+N)$ 中字节排列为：

- **大端序**：$[A] = b_{N-1}, [A+1] = b_{N-2}, \ldots, [A+N-1] = b_0$
- **小端序**：$[A] = b_0, [A+1] = b_1, \ldots, [A+N-1] = b_{N-1}$

**地址-权重的对应关系**：

| 字节序 | 低地址字节 | 高地址字节 | 自然阅读顺序 |
|--------|------------|------------|--------------|
| 大端 | 高权重（MSB） | 低权重（LSB） | 符合 |
| 小端 | 低权重（LSB） | 高权重（MSB） | 不符合 |

### 位掩码的精确提取

$$
\text{提取第 } n \text{ 位（从 0 开始）} = (v \gg n) \& 1
$$

$$
\text{提取第 } [l, r] \text{ 位区间（闭区间）} = (v \gg l) \& ((1 \ll (r-l+1)) - 1)
$$

### 有符号移位的数学语义

- 逻辑右移（无符号）：$v \gg_{逻辑} k = \left\lfloor \frac{v}{2^k} \right\rfloor$
- 算术右移（有符号）：对负数，高位补 1，等价于除以 $2^n$ 向负无穷取整：
$$
v \gg_{算术} k = \left\lfloor \frac{v}{2^k} \right\rfloor \quad (v \ge 0)
$$
$$
v \gg_{算术} k = -\left\lfloor \frac{|v|}{2^k} \right\rfloor \quad (v < 0)
$$

### 字节序转换（网络序/主机序）

$$
V_{network} = \text{hton}(V_{host}) = \sum_{i=0}^{N-1} b_{N-1-i} \times 2^{8i}
$$

### 比特位翻转（Bit Reversal）数学

$$
\text{reverse}_k(v) = \sum_{i=0}^{k-1} ((v \gg i) \& 1) \times 2^{k-1-i}
$$

用于 FFT 等算法。

### 格雷码的数学性质

相邻整数的格雷码仅相差 1 位：
$$
G(n) = n \oplus (n \gg 1)
$$
$$
G^{-1}(g) = \sum_{i=0}^{\lfloor \log_2 g \rfloor} (g \gg i) \& 1
$$

**格雷码的物理意义**：在旋转编码器中，格雷码避免了二进制计数中多位同时变化导致的暂态错误（如 0111 → 1000 中，中间可能出现任意值）。

### CRC（Cyclic Redundancy Check）的数学模型

CRC 将比特串视为 GF(2)（有限域 0/1）上的多项式，模 2 除法验证余数为零。设消息多项式为 $M(x)$，生成多项式为 $G(x)$（度为 $r$）：
$$
CRC(M) = \text{余数}\left(\frac{M(x) \cdot x^r}{G(x)}\right)
$$

接收端验证：
$$
(M(x) \cdot x^r - CRC) \bmod G(x) = 0
$$

CRC 的检错能力由 $G(x)$ 的选择决定：
- 任何长度 $\le r$ 的突发错误均可检测
- 任何奇数个比特错误可检测（若 $G(x)$ 包含因子 $x+1$）

### 汉明码（Hamming Code）的纠错数学

对于 $m$ 位数据位，添加 $r$ 位校验位，满足 $2^r \ge m + r + 1$。校验位位置为 $2^i$（$i=0,1,\ldots,r-1$）。接收端通过 syndrome 计算纠正的比特位置：
$$
s = \sum 2^i \quad \text{（对应 syndrome 中为 1 的位）}
$$

汉明码可以纠正单个比特错误，检测（但不纠正）双比特错误。

## 数据流

<pre>
大端序 (0x12345678 在地址 0x00):
地址:   0x00   0x01   0x02   0x03
字节:   0x12  0x34   0x56   0x78
        MSB                         LSB
        ▲ 高位字节在低地址，与"阅读顺序"一致
        地址递增方向 = 权重递减方向

小端序 (0x12345678 在地址 0x00):
地址:   0x00   0x01   0x02   0x03
字节:   0x78  0x56   0x34   0x12
        LSB                         MSB
        ▲ 低位字节在低地址，与"算术进位方向"一致
        地址递增方向 = 权重递增方向

字节序转换（0x12345678 小端 → 网络序大端）:
字节序列 [0x78, 0x56, 0x34, 0x12]
         ↓ reverse
     [0x12, 0x34, 0x56, 0x78]

uint32 小端序在内存中的二进制权重重排:
地址:   A      A+1     A+2     A+3
小端:   ×2⁰   ×2⁸    ×2¹⁶   ×2²⁴
大端:   ×2²⁴  ×2¹⁶   ×2⁸    ×2⁰
</pre>

**位运算的数据流**：

<pre>
uint32 v = 0x12345678

v & 0xFF = 0x78          (提取最低字节)
v >> 8 = 0x00123456      (右移8位)
v ^ (v >> 1) = ...       (格雷码转换)
(v & 0xF0) >> 4          (半字节交换)
</pre>

**位域提取数据流**：

<pre>
原始: 0xBAAA CDRS (32bit)
     [BBBB][AAAA][AAAA][CCCC][DDDD][RRRR][SSSS]
      31-28 27-24 23-20 19-16 15-12 11-8  7-0

提取 DDDD (bit 15-12):
  v >> 12 = 0x0000 BAAA
  & 0xF   = 0x0000 000D

提取 RRRR_SSSS (bit 11-4, 合并两个4位域):
  v >> 4  = 0x0BAA ACDR
  & 0xFF  = 0x0000 00RS
</pre>

**CRC 计算数据流**：

<pre>
消息比特: [b_{n-1} ... b_1 b_0]
           │
           ├──► 乘 x^r: [b_{n-1} ... b_1 b_0 0 ... 0] (r 个零)
           │
           ├──► 模 2 除法 by G(x)
           │    ├─── 每个 1 位商翻转被除数
           │    └─── XOR 而不是减法
           │
           └──► 余数 (r 位) = CRC

模 2 除法的特殊性：
  - 不借位，不进位
  - XOR 既是加法也是减法
  - 商仅当最高位为 1 时才为 1
</pre>

## 机制

### 大端序

大端序的优势是符号位的快速判断——最高字节在最低地址，比较符号只需检查 $[A]$ 一个字节。

**历史渊源**：

早期 IBM 主机（System/360）和网络协议（TCP/IP）采用大端序，因此大端序也称"网络字节序"。

**约束条件**：
- 字符串比较可直接按内存顺序（ASCII 字符串自然是大端序存储）
- 网络字节序（TCP/IP）统一使用大端序
- 某些 RISC 架构（早期 MIPS/SPARC）默认大端序

**违反后果**：
- x86 系统向网络发送数据前未调用 `htonl/htons` → 接收方解析出错误数值
- 文件格式（如 PDF 1.2 规定大端）跨平台读取时字节序不匹配
- 数值比较（尤其有符号数）必须考虑字节序

### 小端序

小端序的优势是数值运算的自然进位——整数加法的进位从最低字节向最高字节传播，而小端序中最低字节在最低地址，内存访问序列与算术进位方向一致。

**x86 的选择理由**：

x86 选择小端序因为它使低位字节的读取更容易（地址不变）。在现代微处理器中，大小端的选择主要由生态系统决定（向后兼容）。

**约束条件**：
- x86/x64、ARM（大多数，ARMv8 默认小端）默认小端序
- 整数算术从低位向高位进位/借位
- 强制类型转换（uint32* → uint8*）首地址即为最低字节
- 阅读多字节十六进制常量时，书写顺序与小端内存顺序相反

**违反后果**：
- 跨平台网络编程必须转换字节序
- 二进制文件格式若未规定字节序，跨平台读取会出错
- 多字节数据（如 uint32、float）跨端解析时必须考虑字节序，单字节数据（char）无此问题

### 字节序与多精度运算

多精度加减法（超过机器字长的整数运算）依赖于字节序进行逐字进位传播。

**uint128 加法的字节级实现（假设 64 位字长）**：

```c
// 假设小端序，uint64_t a, b 组成 uint128
uint128_add(a_hi, a_lo, b_hi, b_lo):
    carry = a_lo >> 63 & b_lo >> 63  // 进位标志
    lo_sum = a_lo + b_lo
    hi_sum = a_hi + b_hi + carry
```

小端序使低位字位于低地址，进位传播方向与内存增长方向一致，算法自然。大端序则需要反向处理。

### 位运算安全规则

位运算是无符号整数的"自然语言"，但 C/C++ 对有符号整数的位运算有定义陷阱。

**规则 1：移位宽度必须小于类型宽度**

```c
uint32_t x;
x >> 32;  // UB：移位宽度 >= 类型宽度（32）
x >> 31;  // OK：移位宽度 < 类型宽度
```

**约束**：移位超过类型宽度是未定义行为（Undefined Behavior），编译器可能将其优化为任意值。

**规则 2：有符号数算术右移是实现定义**

```c
int8_t y = -1;     // 二进制：11111111
y >> 1;            // 可能结果：11111111（算术右移，-1）
                    //         或 01111111（逻辑右移，127）
                    // 取决于平台和编译器
```

**约束**：C++ 标准规定算术右移对负数是实现定义的。实际中，MSVC/Clang/GCC 在 x86 上都用算术右移，但代码可移植性不能依赖此行为。

**规则 3：有符号整数溢出是未定义行为**

```c
int32_t z = INT32_MAX;   // 2147483647
z + 1;                   // UB：溢出，可能是 -2147483648
                         // 也可能被编译器优化掉
```

**约束**：编译器假定了有符号溢出不会发生，可能将其优化掉。例如 `if (x+1 > x)` 可能被优化为 `true`（即使 x=INT32_MAX），因为编译器认为溢出不会发生。

**规则 4：位运算优先使用无符号类型**

```c
// 不安全：负数右移是实现定义
int8_t flags = -1;        // 11111111
if (flags & 0x80)         // UB 或实现定义

// 安全：显式无符号
uint8_t flags = 0xFF;
if (flags & 0x80)        // 明确：检查最高位
```

### 常见位运算技巧

**交换两个整数（不用临时变量）**：

```c
// XOR 交换：仅当 a 和 b 内存不重叠时正确
a = a ^ b;
b = a ^ b;  // b = (a^b)^b = a
a = a ^ b;  // a = (a^b)^a = b
```

原理：$a \oplus b \oplus b = a$（异或的消去律）。约束：a 和 b 不能指向同一地址（此时会清零）。

**找出最右边的 1 位（tzcnt）**：

$$
\text{lowbit}(v) = v \& (-v)
$$

对于 $v \neq 0$，$v$ 与 $-v$ 的 AND 结果只保留最低的 1 位，其余位为 0。原理：$-v = \tilde{v} + 1$（二补数），最低的 1 位右侧全是 0，加 1 后产生进位传播到第一个 1 处。

**汉明权重（Population Count）**：

$$
\text{popcnt}(v) = \sum_{i=0}^{31} (v \gg i) \& 1
$$

使用 SWAR（SIMD Within A Register）算法可在 $O(\log \text{字长})$ 步内完成：
```c
// 16-way SWAR popcount
v = (v & 0x55555555) + ((v >> 1) & 0x55555555);
v = (v & 0x33333333) + ((v >> 2) & 0x33333333);
v = (v & 0x0F0F0F0F) + ((v >> 4) & 0x0F0F0F0F);
v = (v * 0x01010101) >> 24;  // 8 个半字节之和
```

### 字节序检测与转换

**编译期检测**：

```c
// 使用 _Static_assert（C11）
_Static_assert(sizeof(int) == 4, "32-bit int required");
_Static_assert(CHAR_BIT == 8, "8-bit byte required");

// 检测字节序
#if defined(__BYTE_ORDER__) && __BYTE_ORDER__ == __ORDER_LITTLE_ENDIAN__
    #define IS_LITTLE_ENDIAN 1
#else
    #define IS_LITTLE_ENDIAN 0
#endif
```

**运行时检测**：

```c
// 利用联合体或指针强制转换
bool is_little_endian = (*(uint16_t*)"\xFF\x00" == 0x00FF);
```

**网络编程标准 API**：

```c
uint32_t htonl(uint32_t x);  // host to network long (32-bit)
uint16_t htons(uint16_t x);  // host to network short (16-bit)
uint32_t ntohl(uint32_t x);  // network to host long
uint16_t ntohs(uint16_t x);  // network to host short
```

## 参考存根

```c
// 权限检查（位掩码）
#define READ  0x04
#define WRITE 0x02
#define EXEC  0x01
int has_perm(int p, int req) {
    return (p & req) == req;  // 所有 req 位都被设置
}
```

```c
// 跨平台字节序转换（标准方法）
uint32_t swap_endian(uint32_t x) {
    return ((x & 0x000000FF) << 24) |
           ((x & 0x0000FF00) <<  8) |
           ((x & 0x00FF0000) >>  8) |
           ((x & 0xFF000000) >> 24);
}

// 或使用标准库
#include <arpa/inet.h>
uint32_t x = htonl(original_value);  // 小端 → 大端
```

```c
// 提取位域（bit field extraction）
uint32_t extract_bits(uint32_t v, int hi, int lo) {
    return (v >> lo) & ((1u << (hi - lo + 1)) - 1);
}
```

```c
// CRC-32 计算（标准方法）
#include <stdint.h>
uint32_t crc32(uint32_t crc, const uint8_t *data, size_t len) {
    // 生成多项式：0xEDB88320 (反向表示)
    for (size_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (int j = 0; j < 8; j++) {
            crc = (crc >> 1) ^ (0xEDB88320 & -(crc & 1));
        }
    }
    return ~crc;
}
```

```c
// 汉明权重（popcount）—— GCC 内建函数
int pop = __builtin_popcount(v);   // 32 位
int popll = __builtin_popcountll(v); // 64 位
```
