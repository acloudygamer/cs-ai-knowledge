# 指令集架构与 SIMD

## 一、ISA 与微架构：软件能依赖的那条分界线

一份 x86-64 Linux 可执行文件，在支持相应扩展的 Intel 核心与 AMD 核心上都能原样运行；两片硅的微架构可以截然不同。把"软件写成什么样"和"硅片怎么造"隔开的，是指令集架构（Instruction Set Architecture，ISA）；各厂商按这份契约自由设计微架构，只要逐条兑现，内部结构不受约束。

这份可移植性有前提：目标核实现了该二进制用到的全部 ISA 扩展。只用早期指令的程序能跑在十年前的老芯片上；用到新向量扩展（如 AVX-512）的二进制，在老核上以非法指令异常中止。跨芯片、跨年代跑同一份编译产物，条件是共同的 ISA 子集覆盖它的每一条指令。

ISA 与微架构的解耦，划定了二进制软件跨微架构复用的边界。契约自身要规定寄存器、编码与访存语义；数据并行的供给压力把契约扩展出向量寄存器、lane 与掩码；编译器最终把这些规则落成汇编。

### 1. 一份二进制能跑在哪里：契约的适用边界

"同一份程序到处能跑"成立有条件，缺一条即失效：

* 同一条 ISA：目标核的译码器必须认识这份机器码。ARM 二进制在 x86 核上无法执行。
* 同一套调用约定：参数用哪些寄存器传、栈怎么对齐、结构体怎么排布，链接与装载按同一约定解释二进制。
* 同一个操作系统接口：程序经系统调用请求服务，调用号与参数约定随 OS 而变。

反例最能划清边界：同在 x86-64 上，Windows 可执行文件也不能直接在 Linux 上运行——ISA 相同，调用约定与系统调用接口不同。把可移植性笼统归为"ISA 相同"是过度概括。

```text
+-------------------------------------------------------------------+
| 高级语言源码      for (i = 0; i < N; i++) c[i] = a[i] + b[i];      |
+-------------------------------------------------------------------+
        |   编译器：前端优化 + 后端代码生成
        v
+-------------------------------------------------------------------+
| 汇编语言（助记符 + 少量伪指令）      vaddps ymm0, ymm1, ymm2       |
+-------------------------------------------------------------------+
        |   汇编器：助记符到字节的近乎一一映射
        v
+===================================================================+
| 机器码（十六进制字节流）             C5 F4 58 C2                   |
|                                                                   |
| =======>>>   ISA 契约层：软件可见、硬件必须兑现   <<<=======       |
|  1. 架构寄存器集合（GPR / 向量寄存器 / PC / 标志位）               |
|  2. 指令编码与每条指令执行后的精确状态变化                         |
|  3. 内存视图：地址空间、访存行为、一致性模型                       |
|  4. 异常与特权级接口：执行模式、特权分层、陷入规则                 |
+===================================================================+
        |   硬件译码器与执行引擎（兑现手段任意）
        v
+-------------------------------------------------------------------+
| 微架构实现：分支预测、乱序引擎、多级缓存、向量运算阵列             |
+-------------------------------------------------------------------+
```

契约层以上，编译器与汇编器按 ISA 编码指令，产物还要符合调用约定与系统调用接口才能运行；契约层以下，微架构只对 ISA 负责。两侧各自演化：同一代 ISA 可以造出性能取向与功耗取向完全不同的核；同一份编译产物能否跑在多年前的芯片上，取决于那些芯片是否实现了它用到的扩展集。

### 2. 契约的四项内容

| 契约维度 | 写死的内容 | 软件侧的消费者 |
| --- | --- | --- |
| 架构寄存器 | 软件可见寄存器的数量与位宽：x86-64 有 16 个 64 位 GPR，向量寄存器位宽随扩展增至 512 位 | 编译器的寄存器分配、汇编器的操作数编码 |
| 指令编码与语义 | 每条机器码的位模式、操作数位置、执行后寄存器与内存的状态变化 | 汇编器、反汇编器、调试器、二进制翻译 |
| 内存视图 | 虚拟地址空间、访存粒度与顺序语义；一致性模型写在架构手册里 | 编译器的访存代码生成、锁与屏障的实现 |
| 异常与特权级接口 | 执行模式、特权分层、越权与故障时的控制流转移规则 | 操作系统内核的陷入、上下文切换与隔离 |

内存视图的强弱之分及其微架构成因，见同章《指令执行》§五.3。那里说明 Store Buffer 如何形成 Store→Load 的可见性窗口，这里用它限定 ISA 必须规定的顺序语义。

### 3. 执行模式：实模式与长模式

x86 手册定义多种执行模式，复位后从实模式起步：

* **实模式**：兼容早期 8086 的 16 位形态。取指与访存都先拼"段基址加偏移"——段寄存器值左移 4 位，加上 16 位偏移，得到 20 位物理地址。长模式打开前，每条取指都先过这道拼接。
* **保护模式**：32 位形态。分段必然启用，分页可选，特权检查生效。
* **长模式**：64 位形态，分页必须开启，多数段机制被扁平化为单一平坦地址空间。运行 32 位遗留代码用长模式内的兼容模式，由代码段描述符逐段选择，整机不必退出长模式。

ISA 规定机制，不规定时机。进入长模式要按手册顺序执行一串特权操作：打开保护模式、置相关控制寄存器、加载页表基址、开启分页、远跳切换代码段。路径上每个动作都是某段特权代码执行的指令；开机路径上执行它的是固件，操作系统内核也能执行同样的序列。硬件只定义各动作的语义，不主动切换。把模式切换当作硬件自动完成的行为，是常见误解。

### 4. 特权级与异常接口：CPL 与 EL 不可按层号对齐

不是每条指令在任何状态下都能执行。x86 用当前特权级（Current Privilege Level，CPL）分四层，CPL 0 最高、CPL 3 最低；AArch64 用异常级（Exception Level，EL）分四层，EL0 最低、EL3 最高。主流操作系统各取两层：内核在 x86 的 CPL 0、AArch64 的 EL1 运行，用户程序在 CPL 3、EL0 运行。

两边都是四层，语义不能一一对应。x86 的 CPL 1、2 长期空置，主流 OS 只用首尾两级；AArch64 的 EL2 专属虚拟化监控层，EL3 绑定安全监控固件，每层都有明确分工。比较两种体系结构，要按"谁有权执行哪类指令、访问哪类资源"对齐，而不是按层号对齐。

特权检查落在两条通路上。执行通路限定敏感指令：写控制寄存器、刷新 TLB 只能在最高特权级（x86 的 CPL 0、AArch64 的 EL1 及以上）执行。访存通路由页表项的用户/特权标志配合 CPL/EL 判定（页表项的位段见同章《硬件组成》§二）。越权的后果写在契约里。以 x86 的典型路径为例：触发异常后，硬件把返回所需的规定现场（指令指针、标志位、栈指针等少量寄存器）压入目标特权级的栈，按向量号查中断描述符表取出处理入口并跳转；完整上下文由处理程序自己保存。AArch64 用按异常类型分区的向量表加向量基址寄存器，同样只由硬件保存规定现场。两套细节各自写在手册里，不能按同一幅画面理解。接管者运行在更高特权级——用户态缺页后接手的是内核。重排序缓冲区（Reorder Buffer，ROB）到头部才交付异常的微架构机制见同章《指令执行》§六；这里只取"契约规定了异常入口与特权切换方式"这一结论。

## 二、指令编码的两条路径：CISC 与 RISC

复杂指令集计算机（Complex Instruction Set Computer，CISC）以 x86 为代表，精简指令集计算机（Reduced Instruction Set Computer，RISC）以 ARM64、RISC-V 为代表。分野不在指令"聪明与否"，而在编码契约的形状：指令边界怎样确定、算术指令能否直接操作内存。这个形状决定前端译码器要做什么，也影响编译产物的形态。

### 1. 定长与变长：指令边界怎么找

主流 RISC 指令集的基础指令定长 4 字节。取指后按固定边界切片，各字段的位置与宽度写死，译码器并行开工即可。以 RISC-V 的 R-Type 为例：

```text
[ RISC 定长编码示例：RISC-V 32-bit R-Type 指令（固定 4 字节，字段位置写死） ]

 31         25 24     20 19     15 14   12 11      7 6           0
+-------------+---------+---------+-------+---------+-------------+
|   funct7    |   rs2   |   rs1   |funct3 |   rd    |   opcode    |
|   (7 bits)  | (5 bits)| (5 bits)|(3bits)| (5 bits)|  (7 bits)   |
+-------------+---------+---------+-------+---------+-------------+
       |           |         |        |        |           |
       |           |         |        |        |           +--> 操作码主类
       |           |         |        |        +--------------> 目标寄存器
       |           |         |        +-----------------------> 运算子类型
       |           |         +--------------------------------> 源寄存器 1
       |           +------------------------------------------> 源寄存器 2
       +------------------------------------------------------> 扩展功能码
```

x86 指令变长，最短 1 字节、最长 15 字节：前缀、操作码、寻址方式、偏移量、立即数按需出现，字段位置不固定。

```text
[ CISC 变长编码示例：x86 指令格式（1 ~ 15 字节，边界需顺序扫描识别） ]

+----------+------------+--------+--------+-----+------------+------------+
| Prefixes | VEX/EVEX   | Opcode | ModR/M | SIB | Displace-  | Immediate  |
| (可选前缀)| (SIMD前缀) | (操作码)|(寻址模)|(比例 | ment(偏移) | (立即数)   |
| 0~4 Byte | 0~4 Byte   |1~3 Byte| 0~1 B  |0~1 B| 0,1,2,4 B  | 0,1,2,4 B  |
+----------+------------+--------+--------+-----+------------+------------+
```

变长的代价落在译码器：切出第 2 条指令前，必须先算出第 1 条在哪里结束，多个译码单元无法简单按固定位置切片。同章《指令执行》§二.2 说明微操作缓存如何复用译码结果，这里用它定位变长编码增加的前端供给成本。

### 2. 内存操作数与微操作的归属

CISC 允许算术指令直接以内存为操作数：`add eax, [rbx + rcx*4 + 0x10]` 一条指令完成取数与相加。RISC 的算术指令只操作寄存器，访存由专用的加载、存储指令完成，即加载-存储架构。同一段数组加法，典型 x86 编译产物指令条数更少——内存操作数把访存合并进了算术指令；RISC 产物条数更多、每条职责更窄。这是常见形态的倾向，不是定义：x86 大部分指令同样只操作寄存器。

x86 硬件译码时把指令翻译成一条或多条定长的类 RISC 微操作，再送进乱序引擎：简单指令一对一，访存与算术合一的复杂指令拆成取数、运算等多条，个别指令走微码路径。翻译条数随指令而异，不是每条都拆。微操作是微架构的内部表示，不属于 ISA 契约：软件看不到它，汇编清单里也没有它。CISC 与 RISC 的编码差异因此主要体现在前端译码环节，并不直接等于性能优劣。

## 三、SIMD 的动机：重复计算的供给账

`c[i] = a[i] + b[i]` 对 N 个元素执行 N 次完全相同的加法。单指令多数据（Single Instruction, Multiple Data，SIMD）要减少的正是这类重复指令供给。标量 ISA 下，每次加法都要经过取指译码、分配、发射与写回，换来的只是 4 字节结果。

### 1. 标量重复的供给成本

指令的供给成本与它处理的数据量无关：加一次占一个 ROB 坑位，加八次占八个。该循环形态下每元素约 6 条动态指令（取数、相加、存回、索引、比较、跳转各一）。设发射宽度为每周期 $W$ 条（典型 4~8，见同章《指令执行》§二），供给 $6N$ 条指令的周期下限就是 $6N / W$；代入 $N = 1024$、 $W = 8$，发射这 6144 条指令的周期下限约 768。数据并行度超过指令供给能力后，瓶颈在指令供给本身。

判据由此给出：不是 ALU 太慢，而是为每 4 字节数据单独付一条完整指令的成本太高。

### 2. 把并行写进指令语义

SIMD 对契约的改动只有一条：指令的操作数从单个标量改成一组数据通道（lane）。一次取指译码、一个 ROB 坑位、一次发射，操作的数据量随 lane 数倍增；供给按指令条数计费，数据吞吐按 lane 数扩展，两条曲线由此解耦。

```text
============ 1. 标量指令流：每个元素一条完整指令 ============

   指令流 (Instruction)        数据流 (Data)            计算结果
  +--------------------+      +-------------+          +-------------+
  | add s0, s1, s2     | ---> |  A0  +  B0  | -------> | C0 = A0+B0  |  (周期 1)
  +--------------------+      +-------------+          +-------------+
  | add s3, s4, s5     | ---> |  A1  +  B1  | -------> | C1 = A1+B1  |  (周期 2)
  +--------------------+      +-------------+          +-------------+
  | add s6, s7, s8     | ---> |  A2  +  B2  | -------> | C2 = A2+B2  |  (周期 3)
  +--------------------+      +-------------+          +-------------+
  | add s9, s10, s11   | ---> |  A3  +  B3  | -------> | C3 = A3+B3  |  (周期 4)
  +--------------------+      +-------------+          +-------------+
  * 每 4 字节结果付一整条指令：取指、译码、发射、写回各一次。


============ 2. SIMD：一条指令供给多个 lane ============

   单一向量指令               多通道数据阵列 (Lanes)      并行输出向量
                             +---------------------+    +-----------+
                      +----> | Lane 0:  A0  +  B0  |--->| C0 = A0+B0|
                      |      +---------------------+    +-----------+
  +----------------+  |      | Lane 1:  A1  +  B1  |--->| C1 = A1+B1|
  | vadd v0, v1, v2|-+----> +---------------------+    +-----------+  (一次供给)
  | (取指译码一次) |  |      | Lane 2:  A2  +  B2  |--->| C2 = A2+B2|
  +----------------+  |      +---------------------+    +-----------+
                      +----> | Lane 3:  A3  +  B3  |--->| C3 = A3+B3|
                             +---------------------+    +-----------+
  * 一次供给的成本被多个 lane 均摊，数据吞吐随 lane 数扩展。
```

定宽扩展里 lane 数由契约写死，等于寄存器位宽除以元素位宽；可变长扩展由硬件向量长度与软件设置的 VL 共同决定本次处理的元素数（§四.1）。"一次能并行多少"在定宽扩展里是 ISA 问题，"峰值能到多少"是微架构问题；收益能不能兑现还取决于数据供给与依赖条件，第五节用真实汇编算这笔账。

## 四、SIMD 对契约的三项扩展

SIMD 不是一条指令，而是一组契约扩展。各家 ISA 路径不同，都要解决三件事：寄存器怎么扩容，操作怎么按 lane 定义，分支怎么表达。

### 1. 向量寄存器与 lane：位宽写进契约

定宽 SIMD 扩展新增一组向量寄存器，位宽写死在契约里。x86 按代际逐级加宽，低位完全复用：SSE 定义 128 位的 XMM0~XMM15；AVX 扩到 256 位的 YMM0~YMM15，YMM 的低 128 位就是同名 XMM；AVX-512 再扩到 512 位的 ZMM0~ZMM31，并新增 k0~k7 掩码寄存器。

```text
|<--------------------------------- ZMM0 (512 bits, AVX-512) ----------------------------------->|
                                 |<---------------- YMM0 (256 bits, AVX) ----------------------->|
                                                                 |<------- XMM0 (128 bits, SSE) -->|
+--------------------------------+--------------------------------+-------------------------------+
|        Bit 511 ... 256         |         Bit 255 ... 128        |         Bit 127 ... 0         |
+--------------------------------+--------------------------------+-------------------------------+
```

寄存器是容器，lane 是容器按元素位宽的切分。同一条 256 位寄存器，装 FP32 是 8 个 lane，装 FP64 是 4 个，装 INT8 是 32 个。

```text
256 位寄存器按数据类型的 lane 切分（lane 数 = 寄存器位宽 ÷ 元素位宽）：

1) 8 x 32-bit 单精度浮点（后缀 ps）：
+--------+--------+--------+--------+--------+--------+--------+--------+
| FP32_7 | FP32_6 | FP32_5 | FP32_4 | FP32_3 | FP32_2 | FP32_1 | FP32_0 |   8 个 lane
+--------+--------+--------+--------+--------+--------+--------+--------+

2) 4 x 64-bit 双精度浮点（后缀 pd）：
+-----------------+-----------------+-----------------+-----------------+
|     FP64_3      |     FP64_2      |     FP64_1      |     FP64_0      |   4 个 lane
+-----------------+-----------------+-----------------+-----------------+

3) 32 x 8-bit 字节整数（常用于图像与量化）：
+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+
|B31|B30|B29|B28|B27|B26|B25|B24|B23|B22|B21|B20|B19|B18|B17|B16|B15|B14|B13|B12|B11|B10| B9| B8| B7| B6| B5| B4| B3| B2| B1| B0|   32 个 lane
+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+--+
```

逐代翻倍的家谱是 x86 自己的路径，不是通则。ARM 的 NEON 自始固定 128 位，AArch64 上 v0~v31 共 32 个寄存器不随代际加宽；要更长向量得换扩展。ARM 的 SVE（Scalable Vector Extension）把向量长度做成硬件相关，128 位至 2048 位、以 128 位为步进；RISC-V 的 RVV（RISC-V Vector）同样长度无关：应用给出要处理的元素数，vsetvli 指令按硬件上限折算出本次实际向量长度 VL 并写入标量寄存器，后续向量指令都按这个 VL 执行，同一份机器码可跑满不同宽度的实现。x86 的固定位宽演进不能套到 NEON 上，反过来也不成立。

### 2. 操作语义：lane 内独立，lane 间另付代价

SIMD 指令的语义按 lane 定义：

* **纵向运算**：两个向量寄存器对应 lane 独立计算（`vaddps`），lane 内语义与同宽标量指令一致，无跨 lane 进位。
* **广播**：把一个标量复制到全部 lane，是常数参与逐 lane 运算的前置动作。
* **FMA**：每 lane 的乘与加融合为单条指令，中间结果少一次舍入（舍入与精度的账见同章《数据表示与字节序》§二.2）。
* **水平归约**：跨 lane 求和得到一个标量，需要跨通道布线与多条指令，代价高于纵向运算。

纵向运算是吞吐主力；凡是要跨 lane 搬运结果的归约与重排，都另付布线代价。

### 3. 谓词掩码：用数据选择代替控制跳转

循环里出现 `if (a[i] > 0)` 时，标量代码用条件跳转改变 PC。SIMD 下所有 lane 共享一个 PC，无法让一部分 lane 跳转、另一部分不跳——这就是分支发散问题。契约层的解法是把分支改成按位选择：先算比较结果向量，再让写回按位生效。

x86 在 AVX-512 引入专用掩码寄存器 k0~k7。比较指令（如 `vcmpps`）把各 lane 的比较结果写进掩码的对应位：512 位寄存器按 32 位 lane 比较，产出 16 位掩码。后续向量指令带掩码执行。活跃 lane（掩码位为 1）执行并提交结果；被掩 lane 不更新目的值。带掩码的访存指令抑制被掩 lane 的访存，相应访存异常一并抑制。写回有两种契约：默认的合并语义保持目的寄存器原值；EVEX 加 `{z}` 修饰的清零语义把被掩 lane 置 0。ISA 只规定架构结果，被掩 lane 在实现里是否计算不在契约之内。整套机制取代的是分支指令。

```text
代码逻辑：for (i = 0; i < 4; i++) { if (A[i] > 0) C[i] = A[i] + B[i]; else C[i] = B[i]; }

步骤 1：向量比较产出掩码
  向量 A          [  5.0  | -2.0  |  3.0  | -8.0  ]
  比较 A[i] > 0   [  真   |  假   |  真   |  假   ]
                      |        |       |       |
                      v        v       v       v
  掩码寄存器 k1   [   1   |   0   |   1   |   0   ]

步骤 2：目标寄存器用 B 打底，全 lane 相加后按 k1 合并写回
  目标 C（打底）  [  1.0  |  4.0  |  2.0  |  6.0  ]   (等价 else 分支)
  向量 A          [  5.0  | -2.0  |  3.0  | -8.0  ]
  -------------------------------------------------
  全 lane 相加    [  6.0  |  2.0  |  5.0  | -2.0  ]   (所有 lane 都完成了加法)
  合并选择 k1     [ 导通1 | 拦截0 | 导通1 | 拦截0 ]   (k1=0 的 lane 保留目标原值)
                      |        |       |       |
                      v        v       v       v
  最终 C          [  6.0  |  4.0  |  5.0  |  6.0  ]   (无分支指令，无分支误预测)

* 图中画的是合并语义的示例序列：先算全 lane 加法，再按 k1 选择写回；
  这是代码组织方式，不代表被掩 lane 在硬件里一定计算。
  换 {z} 清零语义时被掩 lane 直接写 0，不需要"打底"步骤。
```

各家 ISA 的谓词能力不同，x86 的形态不是唯一标准：

| ISA 扩展 | 掩码载体 | 被掩 lane 的语义 |
| --- | --- | --- |
| x86 AVX-512 | 专用 k0~k7 掩码寄存器 | 合并（默认）或清零（`{z}`），带掩码访存抑制访存异常 |
| ARM NEON | 无专用谓词寄存器，`bsl` 等位选择指令拼出 | 全 lane 计算后按位选结果，指令条数更多 |
| ARM SVE | 专用谓词寄存器 p0~p15 | 谓词长度随硬件向量长度伸缩，与长度无关设计配合 |
| RISC-V RVV | 用向量寄存器 v0 作掩码操作数 | 掩码存于普通向量寄存器，长度随硬件向量长度伸缩 |

## 五、从 C 循环到标量与向量汇编

契约最终落在编译产物上。同一段 C 循环，开关向量化生成两份汇编，差距记在三个账上：迭代次数、指令供给、数据供给。

```c
void vec_add(const float * restrict a, const float * restrict b, float * restrict c) {
    for (int i = 0; i < 1024; i++) {
        c[i] = a[i] + b[i];
    }
}
```

x86-64 Linux 下，三个指针参数依次由 `rdi`、`rsi`、`rdx` 传入（System V 调用约定）。

### 1. 同一段循环的两份汇编

标量版本每轮处理 1 个 float：`addss` 只写 `xmm0` 的低 32 位，高位闲置，循环 1024 轮。

```nasm
.L_scalar_loop:
    movss   xmm0, DWORD PTR [rdi + rax*4]   ; 从内存加载 1 个 float (a[i]) 到 xmm0 低 32 位
    addss   xmm0, DWORD PTR [rsi + rax*4]   ; 标量相加：低 32 位与 b[i] 相加
    movss   DWORD PTR [rdx + rax*4], xmm0   ; 将 1 个 float 结果写回 c[i]
    add     rax, 1                          ; 循环索引 i += 1
    cmp     rax, 1024                       ; 比较是否到达 1024
    jne     .L_scalar_loop                  ; 共需循环 1024 轮
```

向量版本每轮用 256 位 `ymm0` 吞吐 8 个 float，循环降到 128 轮。

```nasm
.L_simd_loop:
    vmovups ymm0, YMMWORD PTR [rdi + rax]   ; 一次加载 8 个连续 float（a[i..i+7]，共 32 字节）
    vaddps  ymm0, ymm0, YMMWORD PTR [rsi + rax] ; 8 个 lane 并行相加
    vmovups YMMWORD PTR [rdx + rax], ymm0   ; 一次写回 8 个 float 结果
    add     rax, 32                         ; 字节偏移每次前进 32 字节（8 x 4 字节）
    cmp     rax, 4096                       ; 比较是否处理完 4096 字节（1024 x 4 字节）
    jne     .L_simd_loop                    ; 共需循环 128 轮
    vzeroupper                              ; 通知硬件 ymm 高位已闲置，避免与旧 SSE 指令混用的状态合并开销
```

`vmovups` 不假设对齐；编译器能证明对齐时会改用 `vmovaps`。

### 2. 供给账与收益条件

迭代与供给合并算：该循环形态下，标量版动态指令约 $6 \times 1024$ 条，向量版约 $5 \times 128$ 条。向量版每元素摊到的指令数显著下降，但“发射宽度不再是天花板”仍需以实际核心验证。同章《指令执行》§二说明前端供给，这里用它限定指令数下降能消除的只是发射压力。

数据供给按字节算：每轮向量迭代取 2 份 32 字节、写 1 份 32 字节，共 96 字节流量。该核每周期能执行的加载、存储次数与缓存带宽，必须覆盖这份流量；端口分工见同章《指令执行》§四.2。工作集超出缓存、受主存带宽约束时，lane 增多也不能消除等待。同章《缓存与存储层次》§三给出访存事务，这里用它把指令供给与数据供给分开记账。

收益成立还需三个条件，缺一个就要重算：

* **无跨迭代依赖**：`c[i]` 只依赖 `a[i]`、`b[i]`，各轮独立。若改成 `c[i] = c[i-1] + a[i]`，每轮依赖上一轮结果，循环携带依赖使它不能按本例的逐元素独立方式向量化。
* **长度可整除**：1024 能被 8 整除；一般长度 N 的余数段要补标量循环，或用谓词掩码收尾（掩码语义见 §四.3）。
* **对齐可控**：典型 x86 微架构上，落在单个缓存行内的未对齐访问多数情况不罚，跨 64 字节行边界（line split）时才产生可见的额外代价，具体惩罚随微架构而异（对齐与行边界的账见同章《数据表示与字节序》§四.3）。
