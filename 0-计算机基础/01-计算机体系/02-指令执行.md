# 指令执行

程序如何被CPU执行？理解指令执行有助于优化代码性能、排查崩溃问题、理解编译器行为。

## 指令执行周期

CPU执行指令遵循五级流水阶段，每条指令必须顺序经过各阶段：

```
┌─────────────┐
│   取指(Fetch)  │ ← 从内存获取指令
└──────┬──────┘
       ▼
┌─────────────┐
│   译码(Decode) │ ← 解析指令操作码和操作数
└──────┬──────┘
       ▼
┌─────────────┐
│   执行(Execute) │ ← ALU算术逻辑运算
└──────┬──────┘
       ▼
┌─────────────┐
│   访存(Memory) │ ← 访问内存（仅必要时）
└──────┬──────┘
       ▼
┌─────────────┐
│   写回(WriteBack)│ ← 结果写回寄存器
└─────────────┘
```

**取指阶段**：程序计数器（PC）指向内存地址，总线接口单元从该地址读取指令字，PC自动递增或被分支指令修改。**译码阶段**：指令译码器解析操作码识别指令类型，从寄存器文件读取操作数。**执行阶段**：ALU执行算术逻辑运算，或计算内存有效地址。**访存阶段**：仅在加载/存储指令时访问数据缓存。**写回阶段**：运算结果写回目的寄存器。

### 指令类型

| 指令类型 | 示例 | 功能 |
|----------|------|------|
| 算术指令 | ADD, SUB, MUL, DIV | 加减乘除 |
| 逻辑指令 | AND, OR, XOR, NOT | 逻辑运算 |
| 数据传输 | MOV, LOAD, STORE | 寄存器/内存间传输 |
| 控制流 | JMP, JZ, CALL, RET | 跳转、调用、返回 |
| I/O指令 | IN, OUT | 与外设交互 |

指令的执行涉及控制单元对操作码的解析、运算单元对数据的处理、以及寄存器对中间结果的暂存。x86架构采用变长指令设计，指令长度从1字节到15字节不等，通过指令译码器的微程序或硬件逻辑识别指令边界。

### 参考样例

```asm
; x86 汇编示例：计算 1 + 2
section .text
global _start

_start:
    mov eax, 1      ; 将1加载到EAX寄存器
    mov ebx, 2      ; 将2加载到EBX寄存器
    add eax, ebx    ; EAX = EAX + EBX = 3

    ; 退出程序 (Linux x86-64 syscall)
    mov rax, 60     ; syscall number: exit
    mov rdi, 0      ; exit code 0
    syscall
```

```python
# Python 字节码示例
import dis
dis.dis(lambda x: x + 1)
# LOAD_FAST    # 加载局部变量
# BINARY_ADD   # 加法操作
# RETURN_VALUE  # 返回结果
```

## 指令集架构 (ISA)

CPU指令集定义了软件与硬件的接口，是编译器的目标。

| 架构 | 类型 | 特点 | 代表产品 |
|------|------|------|----------|
| x86/x64 | CISC | 指令长度可变，微码实现 | Intel/AMD PC/服务器 |
| ARM | RISC | 加载-存储架构，功耗效率高 | 移动端、嵌入式 |
| RISC-V | RISC | 开源免费，模块化设计 | 学术、物联网 (<latest>) |
| MIPS | RISC | 经典五级流水线 | 路由器、嵌入式 |

## 编译执行全过程

源代码到可执行文件的转换经历多个阶段，每个阶段输出作为下一阶段的输入：

```
源码 (.c) → 预处理 → 编译 → 汇编 → 链接 → 可执行文件
```

**预处理**：展开宏定义和头文件。**编译**：生成平台相关的汇编代码。**汇编**：将汇编指令转换为机器码目标文件（ELF/PE/Mach-O）。**链接**：合并目标文件，重定位符号引用，生成最终可执行文件。

### 参考样例

```c
// 源码
int add(int a, int b) {
    return a + b;
}

// 编译后的汇编 (x86-64)
add:
    push ebp
    mov ebp, esp
    mov eax, [ebp+8]    ; 取出参数a
    add eax, [ebp+12]   ; 加上参数b
    pop ebp
    ret
```

```bash
# 查看CPU架构
cat /proc/cpuinfo | grep "model name"  # Linux
wmic cpu get name                      # Windows
```

## 流水线技术

流水线通过重叠执行多条指令来提高指令吞吐量。理想情况下，每个时钟周期可完成一条指令（吞吐率 = 1/周期），而非流水线的 1/5。

**流水线冒险**阻碍理想流水线效率：

| 类型 | 原因 | 经典解决方案 |
|------|------|-------------|
| 结构冒险 | 硬件资源冲突 | 增加独立硬件资源 |
| 数据冒险 | 指令间数据依赖 | 转发(Forwarding)、暂停(Stall) |
| 控制冒险 | 分支指令改变PC | 分支预测、延迟分支 |

**分支预测**降低控制冒险影响：静态预测（总是预测不分支）简单但效果有限；动态预测（2位饱和计数器）根据历史记录调整，现代Intel处理器结合全局历史、局部历史和目标缓冲实现高准确率。

## 进程调度

操作系统通过调度决定哪个进程的指令在何时获得CPU时间片。**时间片轮转**给每个就绪进程分配固定时间片，轮流执行，造成并发假象。

```
进程状态转换：
创建 → 就绪 ──调度──→ 运行 ──exit──→ 终止
         ↑       ↓
         └─阻塞─┘
```

**就绪态**：等待CPU时间片。**运行态**：正在执行指令。**阻塞态**：等待I/O或其他资源。
