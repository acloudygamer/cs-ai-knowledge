# 指令执行

## 定义

指令执行是 CPU 按照指令周期（取指→译码→执行→访存→写回）对存储在内存中的指令序列进行解码并完成数据变换的过程。每一指令是 CPU 硬件能完成的最原子操作——它要么完成一次数据移动，要么完成一次算术逻辑运算，要么完成一次控制流跳转。CPU 的全部功能都是这三类指令的组合。

## 数学模型

**流水线吞吐率（IPC 的倒数）：**

$$
TP = \frac{指令数}{周期数} = \frac{1}{CPI} = \frac{f}{CPI}
$$

其中 $f$ 为时钟频率，$CPI$ 为每指令周期数。五级流水线的理想 CPI = 1。

**分支预测错误惩罚（吞吐率损失）：**

$$
P_{错误} = f_{分支} \times r_{错误} \times \delta_{惩罚}
$$

其中 $f_{分支}$ 为分支指令频率（~20%），$r_{错误}$ 为预测错误率，$\delta_{惩罚}$ 为流水线清空代价（周期数）。

**数据冒险检测（WAR/WAW 冲突）：**

两条相邻指令 $i$（先执行）和 $j$（后执行）存在数据冒险当且仅当：
$$
\text{Write}(i) \cap \text{Read}(j) \neq \emptyset \quad \text{（RAW 冒险）}
$$
$$
\text{Write}(i) \cap \text{Write}(j) \neq \emptyset \quad \text{（WAW 冒险）}
$$
$$
\text{Read}(i) \cap \text{Write}(j) \neq \emptyset \quad \text{（WAR 冒险）}
$$

超标量流水线中 RAW/WAR/WAW 均需检测。

## 数据流

<pre>
PC（程序计数器）──→ 内存地址生成
    │
    ↓
[取指阶段 IF]  从 I-cache 读取指令字（32/64bit）→ IR
    │
    ↓
[译码阶段 ID] 操作码 → 控制单元 → 控制信号序列
                │
                ├──→ 寄存器文件读取（源操作数）
                └──→ 立即数符号扩展
    │
    ↓
[执行阶段 EX] ALU 运算 / 地址计算 / 分支目标计算
    │
    ├──→ 算术指令：结果 = ALU_out
    ├──→ Load/Store：有效地址 = Base + SignExt(imm)
    └──→ 分支：PC 更新 = 条件成立 ? 目标地址 : PC+4
    │
    ↓
[访存阶段 MEM] 数据 cache 访问（仅 load/store）
    │
    ├──→ Load：DRAM/cache → 寄存器
    └──→ Store：寄存器 → DRAM/cache
    │
    ↓
[写回阶段 WB] 结果 → 目的寄存器 / PC 更新
</pre>

## 机制

### 五级流水线

流水线通过重叠执行多条指令提升吞吐。理想情况下，每个周期完成一条指令，CPI = 1。但三条冒险会导致流水线暂停或清空。

**约束条件：**
- 各阶段延迟需大致均衡（否则最慢阶段成为瓶颈）
- 指令间无数据依赖才能并行执行
- 条件分支在译码阶段无法确定目标

**违规后果：**
- **数据冒险（Data Hazard）**：RAW（读后写）、WAR（写后读）、WAW（写后写）导致数据相关指令不能并行
- **结构冒险（Structural Hazard）**：硬件资源不足（如单端口 register file 同时读写）
- **控制冒险（Control Hazard）**：分支指令在取下一条指令前无法确定 PC

### 指令类型

| 类型 | 格式 | 操作 | 访存 |
|------|------|------|------|
| R 型 | `opcode rd, rs1, rs2` | ALU 寄存器-寄存器运算 | 否 |
| I 型 | `opcode rd, rs1, imm12` | ALU 立即数运算、load | load |
| S 型 | `opcode rs2, rs1, imm12` | store | store |
| B 型 | `opcode rs1, rs2, imm13` | 条件分支 | 否 |
| U 型 | `opcode rd, imm20` | lui, auipc | 否 |
| J 型 | `opcode rd, imm21` | jal（直接跳转） | 否 |

### 分支预测

分支预测降低控制冒险影响。现代 CPU 采用两级自适应分支预测器（Alpha 21264 风格）或 TAGE 预测器。

**约束条件：**
- 静态预测：总是假设不分支（BPT/NT 模式），或根据跳转方向（向后跳认为循环更可能）
- 动态预测：需历史信息（PHT/BHT/GHT），短期历史 0-12 位，长期历史可达历史全局历史
- 预测器状态机：2 位饱和计数器（Strongly/Weakly Taken/NotTaken）

**违规后果：**
- 错误预测导致流水线清空（flush），浪费 10-20 周期（深度流水线）
- 错误率每上升 1%，CPI 增加约 0.2（取决于分支频率）
- 恶意分支喷射（Branch Target Injection）可绕过预测器

### 乱序执行（Out-of-Order Execution）

超标量 CPU 在流水线内部实现乱序执行，通过寄存器重命名消除 WAR/WAW 冒险。

**约束条件：**
- 重排缓冲区（ROB）维持指令顺序提交
- 寄存器映射表（RAT）追踪物理寄存器
- 发射队列（IQ）动态调度 Ready 指令

**违规后果：**
- 乱序执行的内存访问需严格按序提交（Load Store Queue）
- 推测执行（Speculative Execution）可能导致 Meltdown/Spectre 侧信道攻击

## 参考存根

```asm
; x86-64 计算 1+2（AT&T 语法）
mov $1, %eax        ; eax = 1
mov $2, %ebx        ; ebx = 2
add %ebx, %eax      ; eax = eax + ebx
```

```asm
; RISC-V 等价实现
li t0, 1            ; t0 = 1
li t1, 2            ; t1 = 2
add a0, t0, t1      ; a0 = t0 + t1
```
