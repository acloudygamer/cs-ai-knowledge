# 指令执行

## 定义

指令执行是 CPU 按照指令周期（取指→译码→执行→访存→写回）对存储在内存中的指令序列进行解码并完成数据变换的过程。每一指令是 CPU 硬件能完成的最原子操作——它要么完成一次数据移动，要么完成一次算术逻辑运算，要么完成一次控制流跳转。CPU 的全部功能都是这三类指令的组合。

指令执行的核心矛盾在于：指令流是串行的（PC 顺序递增），而计算资源（流水线、ALU、寄存器文件）可以并行。CPU 架构设计者的任务就是最大化指令级并行（ILP），同时保持程序员的指令执行模型（顺序语义）的可见性。

**归约视角**：从数学上讲，指令执行是一个有限状态自动机（FSA）：状态是寄存器/内存的内容，输入是下一条指令，转移函数是 ALU/控制单元定义的运算。流水线将这个 FSA 的执行重叠在时间维度上，但状态转移的逻辑顺序不变。

## 数学模型

**流水线吞吐率与加速比：**

理想五级流水线每个周期完成一条指令，CPI = 1：
$$
TP = \frac{指令数}{周期数} = \frac{1}{CPI} = \frac{f}{CPI}
$$

实际 CPI 受冒险损失影响：
$$
CPI_{实际} = CPI_{理想} + \sumHazards
$$

流水线的理论加速比（相对于单周期非流水线）为流水线级数 $N_{stage}$：
$$
S_{流水线} = \frac{T_{非流水}}{T_{流水}} = N_{stage} \quad (\text{忽略冒险})
$$

但由于流水线寄存器延迟（Setup + Hold time）和时钟 skew，实际加速比略低。

**分支预测错误惩罚（吞吐率损失）：**

$$
P_{错误} = f_{分支} \times r_{错误} \times \delta_{惩罚}
$$

其中 $f_{分支}$ 为分支指令频率（~15-20%），$r_{错误}$ 为预测错误率（~5-10%），$\delta_{惩罚}$ 为流水线清空代价（10-20 周期，取决于流水线深度）。

**流水线停顿周期数：**

$$
Cycles_{stall} = \sum_{i} \left( \text{RAW}_i \times \text{转发代价}_i \right) + \text{分支错误预测损失}
$$

数据冒险若通过转发（Forwarding）解决，可消除大部分停顿。

**分支预测错误率的经验公式（TAGE 预测器）：**

对于具有 $H$ 位全局历史的 TAGE 预测器，预测错误率近似：
$$
r_{错误} \approx \frac{1}{\sqrt{H}} \quad (\text{对于重复性分支模式})
$$

但对于混合工作负载，真实错误率取决于分支行为可预测性。

**数据冒险检测（WAR/WAW/RAW）：**

两条相邻指令 $i$（先执行）和 $j$（后执行）存在数据冒险当且仅当：
$$
RAW: \quad \text{Write}(i) \cap \text{Read}(j) \neq \emptyset \quad \text{（先写后读）}
$$
$$
WAW: \quad \text{Write}(i) \cap \text{Write}(j) \neq \emptyset \quad \text{（先写后写）}
$$
$$
WAR: \quad \text{Read}(i) \cap \text{Write}(j) \neq \emptyset \quad \text{（先读后写）}
$$

超标量流水线中 RAW/WAR/WAW 均需检测。在顺序执行流水线中，WAR 和 WAW 不可能发生（因为顺序发射→顺序完成），但乱序执行流水线中需要寄存器重命名来消除这些冒险。

## 数据流

<pre>
指令 i       指令 i+1      指令 i+2      指令 i+3
   │             │             │             │
IF ──────► ID ──────► EX ──────► MEM ──────► WB    (指令 i)
   │        IF ──────► ID ──────► EX ──────► MEM ──► WB   (指令 i+1)
   │        │        IF ──────► ID ──────► EX ──────► MEM  (i+2)
   │        │        │        IF ──────► ID ──────► EX    (i+3)
   │        │        │        │              ↑
   │        │        │        │         分支预测错误时
   │        │        │        │         这里开始清空流水线
   └────────┴────────┴────────┘

转发路径（Data Forwarding）：
   EX/MEM 流水线寄存器 ──→ EX 阶段输入 （解决 RAW 冒险）
   MEM/WB 流水线寄存器 ──→ EX 阶段输入
</pre>

**完整五级流水线数据流：**

<pre>
PC（程序计数器）
    │
    ├──→ 指令缓存（I-cache）读取 32/64bit 指令字
    │        ↓
    │    IF/ID 流水线寄存器（保存 PC, IR）
    │        ↓
    │    译码阶段（ID）
    │    ├──→ 操作码 → 控制单元 → 控制信号
    │    ├──→ 寄存器文件读取（2-3 个源操作数）
    │    └──→ 立即数符号扩展
    │        ↓
    │    ID/EX 流水线寄存器（保存操作数、控制信号）
    │        ↓
    │    执行阶段（EX）
    │    ├──→ ALU 执行（算术/逻辑）
    │    ├──→ 有效地址计算（load/store）
    │    └──→ 分支条件判断 + 目标计算
    │        ↓
    │    EX/MEM 流水线寄存器（保存结果、分支决策）
    │        ↓
    │    访存阶段（MEM）
    │    ├──→ 数据缓存（D-cache）访问
    │    │    ├──→ Load：cache → 寄存器
    │    │    └──→ Store：寄存器 → cache
    │    └──→ 分支目标 PC 更新（若分支决策在 EX 做出）
    │        ↓
    │    MEM/WB 流水线寄存器
    │        ↓
    │    写回阶段（WB）
    │    └──→ 结果写回寄存器文件
</pre>

**乱序执行（Out-of-Order）数据流：**

<pre>
顺序发射队列（Issue Queue）
    │
    ├──→ 指令1 (ready) ──► EX (ALU)
    ├──→ 指令2 (waiting for operand) ──► 等待
    ├──→ 指令3 (ready) ──► EX (ALU)
    └──→ 指令4 (waiting for mem) ──► 等待

寄存器重命名：
    架构寄存器 (x0-x31) ──→ 物理寄存器 (物理寄存器堆 128 项)
    │
    ├──→ 每条指令发射时分配新物理寄存器
    ├──→ 重排缓冲区（ROB）维持顺序提交
    └──→ 指令完成后标记 ROB 项为完成
    │
    └──→ 按顺序提交（Commit），释放旧物理寄存器
</pre>

## 机制

### 五级流水线

流水线通过重叠执行多条指令提升吞吐。理想情况下，每个周期完成一条指令，CPI = 1。但三条冒险会导致流水线暂停或清空。

**流水线各级功能：**
- **IF（Instruction Fetch）**：从 I-cache 取指令，更新 PC
- **ID（Instruction Decode）**：译码 + 读取寄存器
- **EX（Execute）**：ALU 运算或地址计算
- **MEM（Memory Access）**：数据 cache 访问（仅 load/store）
- **WB（Write Back）**：结果写回寄存器文件

**约束条件：**
- 各阶段延迟需大致均衡（否则最慢阶段成为瓶颈）
- 指令间无数据依赖才能并行执行
- 条件分支在译码阶段无法确定目标（需等待 EX 阶段条件码）

**违规后果：**
- **数据冒险（Data Hazard）**：RAW 导致数据相关指令不能并行
- **结构冒险（Structural Hazard）**：硬件资源不足（如单端口 register file 同时读写）
- **控制冒险（Control Hazard）**：分支指令在取下一条指令前无法确定 PC

### 指令类型（RISC-V 格式）

| 类型 | 格式 | 操作 | 访存 |
|------|------|------|------|
| R 型 | `opcode rd, rs1, rs2` | ALU 寄存器-寄存器运算 | 否 |
| I 型 | `opcode rd, rs1, imm12` | ALU 立即数运算、load | load |
| S 型 | `opcode rs2, rs1, imm12` | store | store |
| B 型 | `opcode rs1, rs2, imm13` | 条件分支 | 否 |
| U 型 | `opcode rd, imm20` | lui, auipc | 否 |
| J 型 | `opcode rd, imm21` | jal（直接跳转） | 否 |

### 分支预测

分支预测降低控制冒险影响。现代 CPU 采用两级自适应分支预测器（TAGE）或神经网络分支预测器。

**分支目标缓冲器（BTB）：**
- 记录已知分支指令的跳转目标地址
- 取指时用 PC 查询 BTB，预测本次是否跳转及目标地址
- 未在 BTB 中的地址默认为非分支（fall-through）

**分支历史表（BHT）/模式历史表（PHT）：**
- 记录分支指令的历史跳转情况
- 2 位饱和计数器：Strongly Taken → Weakly Taken → Weakly Not Taken → Strongly Not Taken
- 混合预测器使用多组计数器，根据历史长度选择最优计数器组

**约束条件：**
- 动态预测需历史信息（PHT/BHT/GHT），短期历史 0-12 位
- 分支方向和目标分别预测
- 错误预测后需回滚寄存器状态（ROB）

**违规后果：**
- 错误预测导致流水线清空（flush），浪费 10-20 周期
- 错误率每上升 1%，CPI 增加约 0.2-0.3
- Spectre 变种可通过恶意分支模式操纵预测器

### 乱序执行（Out-of-Order Execution）

超标量 CPU 在流水线内部实现乱序执行，通过寄存器重命名消除 WAR/WAW 冒险。

**寄存器重命名机制：**
- 程序员可见的架构寄存器（如 x86 的 16 个通用寄存器）映射到物理寄存器
- 每条指令发射时分配新的物理寄存器
- 重排缓冲区（ROB）维持指令顺序提交，保证精确中断

**发射队列（Issue Queue/IQ）：**
- 指令译码后进入 IQ，等待操作数就绪
- 操作数就绪后发射到功能单元
- IQ 仲裁器选择可发射指令（通常选择最老的 Ready 指令）

**乱序执行的内存 ordering 问题：**
- 加载和存储指令的顺序可能被打乱（Store-to-Load 转发除外）
- 内存 ordering 由 Load Store Queue（LSQ）维护
- x86 使用强内存模型（程序顺序 + store_forward），ARM/RISC-V 使用弱内存模型

**违规后果：**
- 乱序执行的内存访问需严格按序提交
- 推测执行（Speculative Execution）可能导致 Meltdown/Spectre 侧信道攻击
- 乱序执行增加了验证复杂度（内存 ordering violations）

### 内存ordering与屏障

**Store Buffer 与 Load Forwarding：**
Store 指令的结果先写入 Store Buffer，后续同地址的 Load 可直接从 Buffer 转发，绕过 cache。

**内存屏障（Memory Barrier/Fence）：**
- **写屏障（Store Barrier）**：确保在屏障前的所有 store 在屏障后的 store 之前完成
- **读屏障（Load Barrier）**：确保在屏障前的所有 load 在屏障后的 load 之前完成
- **全屏障（Full Barrier）**：同时包含读写屏障

```c
// x86 MFENCE 指令
asm volatile("mfence" : : : "memory");
```

## 参考存根

```asm
; x86-64 计算 1+2（AT&T 语法）
mov $1, %eax        ; eax = 1
mov $2, %ebx        ; ebx = 2
add %ebx, %eax      ; eax = eax + ebx
; 结果：eax = 3
```

```asm
; RISC-V 等价实现
li t0, 1            ; t0 = 1
li t1, 2            ; t1 = 2
add a0, t0, t1      ; a0 = t0 + t1
; 结果：a0 = 3
```

```c
// 观察流水线停顿（x86 UOPS）
// clang -O2 -march=native 编译后观察
int sum(int* arr, int n) {
    int s = 0;
    for (int i = 0; i < n; i++)
        s += arr[i];
    return s;
}
```

```c
// 内存屏障示例（Linux kernel）
#define smp_mb()    asm volatile("mfence" : : : "memory")
#define smp_rmb()   asm volatile("lfence" : : : "memory")
#define smp_wmb()   asm volatile("sfence" : : : "memory")
```
