# 数据表示与字节序

## 一、定宽模环：补码、符号扩展与溢出判据

当核心计算 `0xFF + 0x01` 时，8 位加法器只输出 `0x00` 和一组标志。软件可以把它读成无符号的 255 加 1，也可以读成补码的 -1 加 1。加法器不保存类型；类型决定软件怎样解释同一串位。

n 位状态共有 $2^n$ 个，加法按模 $2^n$ 回绕。无符号读法与补码读法在低半环相同。到了高半环，补码读法比无符号读法小 $2^n$。改变解释只改数值，不改位串。

```text
8 位模 256 环的展开（上排无符号读法，下排补码读法）：

  状态     0x00  0x01  0x02  ...  0x7E  0x7F  0x80  0x81  ...  0xFE  0xFF
  无符号     0     1     2        126   127   128   129        254   255
  补码       0     1     2        126   127  -128  -127         -2    -1
                                             ▲
                                    符号位 bit7 在此由 0 翻 1

  0xFF + 0x01 ──► 0x00   无符号回绕，CF=1，OF=0
  0x00 - 0x01 ──► 0xFF   x86 无符号借位，CF=1
  0x7F + 0x01 ──► 0x80   有符号越界，CF=0，OF=1
```

### 1. 环上的加与减：CF 与 OF 的分工

进位标志（Carry Flag，CF）记录无符号运算是否越过环的端点。溢出标志（Overflow Flag，OF）记录补码结果是否越过有符号值域。加法器同时给出两种判据，软件按需消费。

对加法及由取补实现的减法，OF 可由两级进位判定：

$$\text{OF} = C_n \oplus C_{n-1}$$

其中 $C_n$ 是符号位向外的进位， $C_{n-1}$ 是次高位向符号位的进位。二者不同，说明低位进位改变了预期的符号。CF 在 x86 加法中取 $C_n$；x86 减法遇到无符号借位时置 1。其他 ISA 的减法借位编码可以不同，不能把 x86 的 CF 规则直接搬过去。

这些标志不是 C 的自动越界检查。C 的无符号算术按模 $2^n$ 定义，回绕本身合法。有符号溢出则是未定义行为，不能等硬件置 OF 后再补救。编译器可以用标志实现某次比较，但语言语义不等于“无符号看 CF，有符号看 OF”。

| 位宽 | 无符号值域 | 补码值域 | 加 1 回绕点 | 典型宿主 |
| --- | --- | --- | --- | --- |
| 8 | 0 ~ 255 | -128 ~ 127 | 0xFF 回到 0x00 | 字节、协议字段 |
| 16 | 0 ~ 65535 | -32768 ~ 32767 | 0xFFFF 回到 0x0000 | 短整型、16 位文本码元 |
| 32 | 0 ~ 4294967295 | -2147483648 ~ 2147483647 | 全 1 回到 0 | 常见 `int`、32 位浮点位容器 |
| 64 | 0 ~ $2^{64}-1$ | $-2^{63}$ ~ $2^{63}-1$ | 全 1 回到 0 | 指针、通用寄存器、x86-64 Linux 的 `long` |

### 2. 宽度扩展：movsx 与 movzx 的分岔

把 8 位值装进 64 位寄存器时，高 56 位由转换语义填充。`movzx` 补 0，把 `0xFF` 读成 255。`movsx` 复制 bit7，把 `0xFF` 读成 -1。后续比较和地址计算继承这个差异。

```text
0xFF 装入 64 位寄存器的两条路径（bit63 在左）：

  RAX = 0000 0000 0000 0000 ... 0000 0000 1111 1111   movzx → 255
  RAX = 1111 1111 1111 1111 ... 1111 1111 1111 1111   movsx → -1

  与 64 位常量 -1 比较：
    movzx 路径：255 ≠ 0xFFFF_FFFF_FFFF_FFFF，比较为假
    movsx 路径：两边同为全 1，比较为真
```

在常见编译器中，有符号小整数转宽时使用符号扩展，无符号小整数转宽时使用零扩展。C 规定的是转换后的值，不规定必须生成哪条指令。`uint8_t` 提升到 `int` 仍是零扩展，因为目标 `int` 能装下 0 ~ 255。

负数转无符号类型时，模数由目标类型宽度决定。`int32_t` 的 -1 转成 `uint32_t` 得 $2^{32}-1$，不是固定变成 $2^{64}-1$。位宽、源符号性和目标类型必须一起确定转换结果。

### 3. 取负、除法与未定义行为

补码取负可按“按位取反再加 1”实现。环上唯一没有正数对称点的是最负值。8 位的 `0x80` 取负后仍是 `0x80`，因为 +128 不在 8 位补码值域内。

硬件回绕不意味着语言允许该运算。C 的 `-INT_MIN`、`abs(INT_MIN)` 和 `INT_MIN / -1` 都涉及不可表示结果。前两者属于未定义行为；最后一项在 C 层同样是未定义行为，x86 `idiv` 实际执行时会触发除法错误异常 #DE。

有符号溢出的未定义性也给优化让路。编译器可在该假设下把 `x + 1 > x` 折叠为恒真。需要模回绕时，应直接使用无符号类型。需要检测有符号溢出时，可使用编译器的溢出内建函数。把无符号回绕结果再转成装不下的有符号值，并不是可移植的通用补救。

## 二、IEEE 754 字段切分：偏置指数、隐含位与次正规数

浮点数算术标准（IEEE Standard for Floating-Point Arithmetic，IEEE 754）规定字段编码。单精度格式 binary32（FP32）把小数点位置编码进指数域。它用 32 位装符号、指数和尾数。读取时先切字段，再按指数类别还原数值。

正规数的有效数字以隐含位 1 开头。次正规数没有这个隐含 1。特殊值又走另一条解释路径，因此不能对所有位模式套用同一个公式。

```text
FP32（32 位）字段标尺：

  31 30              23 22                                    0
 ┌──┬──────────────────┬──────────────────────────────────────┐
 │s │   指数 e（8 位）  │           尾数 f（23 位）             │
 └──┴────────┬─────────┴──────────────────┬───────────────────┘
             │ 正规数：E = e - 127         │ 正规数有效数字：1.f
             ▼                            ▼
      正规数值 = (-1)^s × 1.f × 2^(e-127)

双精度格式 binary64（FP64）：s(1) | e(11) | f(52)，偏置 1023，有效精度 53 位
```

### 1. 指数偏置与值域分段

偏置满足 $e = E + 127$，把有符号指数编进非负字段。对正规数，e 的无符号比较顺序与 E 的大小顺序一致，并非二者数值相等。完整的浮点排序还要处理符号、尾数、零、无穷和非数（Not a Number，NaN），不能只比较指数域。

FP32 的 e=0 与 e=255 被留给特殊类别。正规数只使用 1 ~ 254，所以 E 的范围是 -126 ~ 127。全 1 指数与尾数共同区分无穷（Infinity，Inf）和 NaN。

| 指数域 e | 尾数域 f | 类别 | 数值或行为 |
| --- | --- | --- | --- |
| 0 | 0 | 有符号零 | +0 或 -0，符号可参与除法结果 |
| 0 | ≠0 | 次正规数 | $(-1)^s \times 0.f \times 2^{-126}$ |
| 1 ~ 254 | 任意 | 正规数 | $(-1)^s \times 1.f \times 2^{e-127}$ |
| 255 | 0 | 无穷 | +Inf 或 -Inf |
| 255 | ≠0 | NaN | 携带载荷，不按数值排序 |

次正规数让最小正规数附近保持等间距。FP32 的最小正规数是 $2^{-126}$。最大次正规数是 $(1-2^{-23}) \times 2^{-126}$。二者之差为 $2^{-149}$。最小次正规数到零的距离也为 $2^{-149}$，因此不会出现从最小正规数直接跳到零的大空洞。

这段渐进下溢有硬件代价。在部分 x86 微架构上，次正规输入或结果会进入微码辅助路径，延迟可升至百拍档。次正规数刷零（flush-to-zero）用稳定吞吐换取极小值附近的精度损失，是否启用由运行环境控制。

### 2. 有效精度、间距与结合律的失效

FP32 有 24 位有效精度，约合 7.22 位十进制相对精度。FP64 有 53 位，约合 15.95 位。这个量级不保证十进制小数可被精确表示。在正规数范围内，同一二进区间内的相邻值间距固定，进入下一个二进区间时翻倍。次正规数的间距固定为 $2^{-149}$，不随指数翻倍。

以 FP32 默认的就近、偶数优先舍入为例。`16777216.0f + 1.0f` 会回到 `16777216.0f`。在 $[2^{24},2^{25})$ 内，相邻值间距为 2。精确结果 $2^{24}+1$ 是 $2^{24}$ 与 $2^{24}+2$ 的中点。按偶数末位规则，结果舍回 $2^{24}$。于是两种加法顺序得到不同结果：

```text
(16777216.0f + 1.0f) - 16777216.0f  → 0.0f
16777216.0f + (1.0f - 16777216.0f)  → 1.0f

第二条路径先得到 -16777215.0f；它仍在 FP32 的精确整数范围内。
```

对长度为 n 的累加，朴素顺序求和的常规误差界随 n 增长。成对求和把这部分增长压到 $\log_2 n$ 档。Kahan 补偿保存被舍掉的小量，通常能进一步压低误差，但不能改变浮点间距，也不保证精确结果。

默认的就近舍入在正中点时选择偶数末位，避免固定方向的统计偏置。向零、向正无穷和向负无穷服务于有向误差界。IEEE 754 要求基本算术按目标精度正确舍入。FMA 把 $a \times b + c$ 的中间乘积保持到最终一次舍入，因此少一次舍入误差。其实际吞吐仍由微架构决定。

### 3. 特殊值、零的符号与转换边界

+0 与 -0 的相等比较为真，但符号会传入除法等运算。NaN 的 `==`、`<`、`>`、`<=` 和 `>=` 都为假，`!=` 为真。可移植代码用 `isnan` 检测；启用“假定无 NaN”的优化后，`x != x` 可能被折叠掉。

静默 NaN 通常在浮点运算中传播。信号 NaN 作为会检查它的算术或比较操作的操作数时，会请求无效操作异常。异常未屏蔽时可陷入；被屏蔽时置状态标志，浮点算术结果通常变为静默 NaN。普通算术不会主动制造信号 NaN，但外部位串或手工载荷都可能带来它。

整数转浮点也会丢精度。`16777217` 超出 FP32 的连续精确整数范围，会舍入为 `16777216`。反向转换先截去小数；若整数部分超出目标范围，C 层是未定义行为。

x86 `cvttss2si` 的哨兵只属于硬件异常路径。使用 32 位目标且无效操作异常被屏蔽时，非法转换返回 `0x80000000`。异常未被屏蔽时会走异常处理。这个“整数不定值”不改变 C 的未定义行为判据。

## 三、字节车道与端序：主机序、网络序与位序的正交性

把 `0x11223344` 写入内存，寄存器里的一个整数变成四个字节的地址映射。端序回答“哪一端落在低地址”。它不改变位串的数值，也不规定字节内部各位的编号。

x86-64 使用小端。常见 AArch64 桌面与服务器系统也多使用小端数据面。传统 Internet 协议的多字节字段统一使用大端，协议边界因此需要显式转换。

```text
把 32 位值 0x11223344 存入地址 0x1000（字节车道映射）：

  地址        0x1000  0x1001  0x1002  0x1003
  小端         44      33      22      11    低有效字节 → 低地址
  大端         11      22      33      44    高有效字节 → 低地址

  按 8 位读 0x1000：小端得 0x44，大端得 0x11
  按相同端序的 32 位读回：两种布局都还原出 0x11223344
```

### 1. 车道映射与跨边界读取

同宽度、同端序的写读是自洽的。差异在按字节观察、跨端序传输和逐字段序列化时暴露。接收方必须知道字段宽度与端序，才能把四个字节还原成原来的整数。

```text
主机整数到网络字段的转换链：

  主机 uint32_t ──► htonl ──► 网络序值 ──► 拷贝 4 字节到报文 ──► 网卡发送
                    │
                    └─ 小端主机重排字节；大端主机不变

  接收方向：报文 4 字节 ──► 取出网络序值 ──► ntohl ──► 主机 uint32_t
```

`htonl` 处理 32 位字段，`htons` 处理 16 位字段。它们保证目标字节序，不是永远执行字节反转。`ntohl` 与 `ntohs` 在接收侧做反向映射。网卡不会替应用载荷猜测哪些字节需要交换。

网络序不是另一个算术值，而是同一值的传输排布。绕过转换，直接把主机整数写进报文，会在异端序接收方得到错误数值。若直接写入整个结构体，还会叠加成员偏移与填充问题。

### 2. 端序的适用边界：标量有、字节流无

端序只描述多字节对象内部的字节排布。统一码转换格式（Unicode Transformation Format，UTF）把码点编成编码单元。`uint8_t` 数组和 UTF-8 字节流没有端序。UTF-16、UTF-32 的编码单元由多个字节组成，需要声明码元端序。

UTF-16 与 UTF-32 可用字节序标记（Byte Order Mark，BOM）声明端序。UTF-8 不需要用 BOM 声明端序，即使文件允许出现 UTF-8 BOM。协议也可以不使用 BOM，改由格式规范固定端序。

网际协议（Internet Protocol，IP）的多字节首部字段使用网络序。传输控制协议（Transmission Control Protocol，TCP）也遵守这一约定。文本、目标文件和设备寄存器则各有自己的格式契约。

| 边界 | 约定端序 | 转换点 | 忽略约定的后果 |
| --- | --- | --- | --- |
| x86-64 数据面 | 小端 | 同端序直接读写 | 异端序数据会被误读 |
| IP、TCP 首部的多字节字段 | 大端 | `htonl`、`ntohl` 等 | 端口号或长度值错误 |
| PCIe 配置空间 | 小端 | 驱动按规范编解码 | 多字节寄存器值错误 |
| UTF-16、UTF-32 文本 | BOM 或外部规范声明 | 解码器读取码元 | 码元拼接方向错误 |
| ELF 目标文件 | 文件头 `EI_DATA` 声明 | 链接器与装载器 | 字段解析错误 |
| Windows PE 映像 | 小端 | 装载器按格式解析 | 用大端假设会读错字段 |

可执行与可链接格式（Executable and Linkable Format，ELF）把端序声明放在文件头。可移植可执行格式（Portable Executable，PE）则固定小端。目标文件端序只是格式契约的一部分，字段宽度和偏移仍须分别遵守。

### 3. 位序与字节序的正交

最高有效位（Most Significant Bit，MSB）与最低有效位描述位编号。端序描述字节地址。前者不决定后者，字节交换也不会自动反转每个字节内部的位。

一个协议字段可能同时受两套规则约束。32 位总长度字段需要大端解码；同一个首部中的位图还要定义各位编号。先按端序还原多字节对象，再按掩码取位，才不会把两条轴混在一起。

判断步骤因此是两问，而不是二选一：字段是否由多个字节组成？字段内部是否还划分位段？前一个答案决定是否处理端序，后一个答案决定是否处理位编号。线路发送顺序或循环冗余校验（Cyclic Redundancy Check，CRC）的位序若另有规定，也属于独立约定。

## 四、结构体布局：偏移标尺、对齐填充与 64B 行边界

在 x86-64 Linux 的 LP64 数据模型下，`long` 与指针为 8 字节，`int` 为 4 字节。编译器按声明顺序安排成员，并按对齐要求插入填充。最后把结构体大小补齐，保证数组中下一个元素仍满足对齐。

```text
LP64 下 struct { char c; long l; int i; short s; } 的偏移标尺：

  偏移    0    1  2  3  4  5  6  7    8 ... 15   16 17 18 19   20 21   22 23
        ┌────┬───────────────────────┬────────────┬───────────┬───────┬───────┐
        │ c  │      填充（7 B）       │     l      │     i     │   s   │ 填充  │
        └────┴───────────────────────┴────────────┴───────────┴───────┴───────┘
         1 B           无成员              8 B          4 B       2 B     2 B

  本例对齐：char=1，long=8，int=4，short=2
  最大成员对齐为 8，因此结构体总大小从 22 B 补到 24 B
  按 { long; int; short; char; } 重排后，总大小为 16 B
```

### 1. 对齐规则与填充洞

未加打包属性时，本例的 `long l` 必须从 8 的倍数开始。`char c` 占据偏移 0，于是偏移 1 ~ 7 成为填充。`int i` 落在 16，`short s` 落在 20，末尾再补 2 字节。

对齐是应用程序二进制接口（Application Binary Interface，ABI）的约定。它也可能减少分裂访问。一个自然对齐的 8 字节对象不会跨越 64B 缓存行。非对齐对象则可能跨行，需要访问两行。跨页访问还涉及两页的权限与地址翻译，不能简单统称为“两次总线事务”。

| 成员 | 类型 | 偏移 | 大小（B） | 对齐（B） | 前置填充（B） |
| --- | --- | --- | --- | --- | --- |
| `c` | `char` | 0 | 1 | 1 | 0 |
| `l` | `long` | 8 | 8 | 8 | 7 |
| `i` | `int` | 16 | 4 | 4 | 0 |
| `s` | `short` | 20 | 2 | 2 | 0 |

填充字节不承载成员值，其内容可能随执行历史变化。`memcmp` 比较两个逻辑相等的结构体，可能因填充不同而失败。直接 `write` 整个结构体还会写出填充中的旧数据。持久化与传输应逐字段编码，而不是复用进程内布局。

### 2. 重排、数组布局与 64B 行

把成员按对齐降序排列，本例可从 24 B 降到 16 B。百万元素数组仅元素体就减少 8,000,000 B。若结构体属于公开 ABI，成员顺序已是兼容性契约，不能为了省空间随意重排。

结构体数组（Array of Structures，AoS）把同一元素的字段连续放置。结构体拆分数组（Structure of Arrays，SoA）把各字段分别放成数组。二者对缓存行的消费不同。

若每个 AoS 元素为 64 B，而流式循环只读其中一个 8 B 字段，每行只有 1/8 的字节被使用。改成 SoA 后，同一字段可连续填满缓存行，理想有效载荷接近 1。这个比例假定被带入的数据没有后续复用，不代表所有遍历都应改用 SoA。

同章《缓存与存储层次》把缓存与主存间的搬运单位定为 64B 行。这里用这个单位核算布局的有效载荷。若两个核高频写同一行中的不同变量，还会产生一致性流量；按 64B 边界对齐并填充可减少这种冲突，代价是更多内存占用。

### 3. packed、位域与非对齐访问

`#pragma pack(1)` 或 `__attribute__((packed))` 可压掉填充。代价是成员可能失去自然对齐。x86 的许多普通访存指令允许非对齐地址；跨 64B 行时通常要访问两行，具体代价由微架构决定，不能固定写成“吞吐减半”。

AArch64 对普通内存的非对齐支持取决于访问类型与系统配置。设备内存和许多原子指令有更严格的对齐要求。跨页非对齐访问也不存在统一的“内核必定修补”规则，可能正常完成，也可能触发异常。

`packed` 只改变布局，不统一端序，也不消除编译器间的 ABI 差异。线协议应使用字节缓冲区、显式偏移和端序转换。只有在布局与访问代价都已受控时，才把 `packed` 当作空间优化。

位域的可移植性更弱。分配方向、跨存储单元方式和普通 `int` 位域的符号性都依赖实现。端序还会叠加到位域所在的存储单元上。位域适合受控 ABI 内的空间压缩，不应直接充当跨平台报文格式；报文位段应显式使用移位与掩码。

## 五、位运算到指令选择：掩码、位扫描与布尔函数压缩

一行位运算先经过编译器模式匹配，再落到标量或向量指令，最后由微架构决定代价。操作数是否为常量、位段是否连续、目标是否支持扩展，都会改变指令选择。位操作指令集（Bit Manipulation Instruction Set，BMI）是 x86 的一组扩展。BMI1 与 BMI2 覆盖不同操作。

| 操作 | x86 标量 | x86 向量（AVX-512） | AArch64 | 典型延迟或实现 |
| --- | --- | --- | --- | --- |
| 掩码与、或、异或 | `AND`、`OR`、`XOR` | `vpandd`、`vpord`、`vpxord` | `AND`、`ORR`、`EOR` | 一拍档 |
| 三输入布尔函数 | 通常需 2 ~ 3 条 | `vpternlogd` 一条 | 通常需 2 ~ 3 条 | 每条一拍档 |
| 逻辑左、右移 | `SHL`、`SHR` | `vpsllvd`、`vpsrlvd` | `LSL`、`LSR` | 一拍档 |
| 算术右移 | `SAR` | `vpsravd` | `ASR` | 一拍档 |
| 循环移位 | `ROL`、`ROR` | `vprold`、`vprord` | `ROR`，反向旋转换移位量 | 一拍档 |
| 位段提取 | `BEXTR`（BMI1） | 移位与掩码组合 | `UBFX`、`SBFX` | 数拍档 |
| 位压缩、展开 | `PEXT`、`PDEP`（BMI2） | 无通用单指令对应 | 无通用单指令对应 | 数拍或微码慢路径 |
| 统计置位数 | `POPCNT` | `vpopcntd` | 向量 `CNT` 按字节统计；FEAT_CSSC 另有标量 `CNT` | 数拍档 |
| 前导、尾随零 | `LZCNT`、`TZCNT` | `vplzcntd` | `CLZ`；`CTZ` 需 FEAT_CSSC，否则通常用 `RBIT + CLZ` | 数拍档 |

表中的 AVX-512 指令还分属不同子集。例如 `vpopcntd` 需要 VPOPCNTDQ，`vplzcntd` 需要 AVX-512CD。只检测到 AVX-512F，不能推断整表都可用。

### 1. 移位量的取模与未定义边界

x86 的 64 位移位指令取移位量低 6 位，32 位指令取低 5 位。因此对实际机器指令 `shl r64, cl`，`CL=64` 会产生不移位的结果。这个硬件规则不能反推 C 的 `x << 64`；后者已经是有定义域之外的未定义行为。

需要模 64 的移位语义时，可先对无符号移位量执行 `k &= 63`，再移位。C 的负数左移、超宽移位以及不可表示的有符号左移结果也有独立边界，不能只靠屏蔽移位量全部解决。

算术右移与逻辑右移的分岔仍在符号位。`SAR` 复制符号位，对补码负数相当于向负无穷取整的除 2 幂。`SHR` 补零，适用于无符号位串。可移植 C 代码不能假定所有实现都用同一种方式右移负数。

### 2. 专用指令：POPCNT、PEXT/PDEP 与位图分配

`POPCNT` 用一条指令统计置位数。`LZCNT` 与 `TZCNT` 把前导零、尾随零计数变成位扫描原语。`BEXTR` 合并右移与掩码，`PEXT` 与 `PDEP` 按掩码压缩或展开位。

后两者的代价不能只看 ISA。Zen 1、Zen 2 上的 `PEXT`、`PDEP` 走明显较慢的微码路径。Zen 3 起回到数拍档，常见 Intel 实现也在数拍档。同章《指令集架构与SIMD》把 ISA 语义与微架构实现分开，这里用该分界解释同指令的跨代代价。

编译器还能识别无符号惯用式。`x & -x` 可映射为 `BLSI`，取出最低置位。`x & (x - 1)` 可映射为 `BLSR`，清掉最低置位。目标不支持 BMI1 时，编译器会保留等价指令序列。

位图分配可直接组合这些原语。若位 1 表示空闲，`TZCNT(free)` 给出最低空闲位的下标。`BLSI(free)` 给出对应掩码，`BLSR(free)` 把该位置 0，完成一次分配。`free=0` 时没有可分配位，必须先处理这个分支。

### 3. 向量侧的位操作：掩码寄存器与布尔函数压缩

SIMD 把相同操作按通道（lane）并行化。对 512 位的 `vpternlogd`，每条指令处理 16 个 32 位 lane。它用 8 位立即数编码三输入真值表，把任意三输入布尔函数压成一条指令。`vpsllvd` 则允许每个 lane 使用独立移位量。

AVX-512 比较指令可直接把 lane 结果写进 `k` 掩码寄存器。512 位的 32 位比较产生 16 位掩码，`kmov` 可把它搬到通用寄存器。较早向量指令集中的 `vpmovmskb` 是另一条路径。它提取各字节 lane 的最高位，不应当作 AVX-512 比较的唯一出口。

```text
向量比较到标量处理的掩码链：

  向量比较 ──► k 掩码 ──► kmov 到通用寄存器 ──► TZCNT ──► 处理首个命中 lane
                              │
                              └─ 掩码为 0 ──► 结束或进入下一批
```

这条链把逐元素分支改成批量比较加一次位扫描。若目标是寻找“不满足条件”的 lane，扫描前还要按有效 lane 范围取反掩码，避免把尾部无效位当成命中。

## 六、宽度转换：模截断、饱和与重解释

缩窄转换要回答两个问题：数值是否必须保留，装不下时如何处理。模截断与饱和钳位给出两种不同答案。重解释只换类型标签，不属于数值转换。

```text
缩窄的输入为 32 位 0x000001B6（十进制 438）：

  ① 模截断到低 8 位    0xB6  → 182    vpmovdb 等
  ② 有符号饱和到 int8  0x7F  → 127    vpmovsdb
     若源值小于 -128，则输出 0x80，即 -128
```

### 1. 模截断与数值边界

模截断直接丢弃高位，等价于对 $2^n$ 取模。C 的无符号窄化保证这一语义。有符号窄化若原值可由目标类型表示，值保持不变。只有超出目标范围时才由实现定义，实现还可定义相应信号。主流补码平台通常对越界结果保留低位，但可移植代码不能把该结果当成普遍保证。

浮点转整数的饱和也不能从模截断推出。需要饱和时，必须显式使用有饱和语义的指令、内建函数或软件钳位。

### 2. 饱和与打包：AVX-512 的窄化指令族

向量窄化把多个宽 lane 压进较窄的目标。传统打包可用 `vpackssdw` 等指令完成饱和，但结果按 lane 块交错，常需额外的 `vperm` 重排。具体指令数取决于源寄存器数量与目标布局。

AVX-512 提供三类窄化指令。`vpmovdb` 截断，`vpmovsdb` 做有符号饱和，`vpmovusdb` 做无符号饱和。它们把结果写入连续目标 lane，省去传统的块内重排。截断仍丢高位，饱和则把越界值钳到目标端点，两者不能互换。

这条出口也可能限制整条向量流水。若窄化单元的每拍处理能力低于前端乘加阵列，积累的结果会在转换处排队。判断瓶颈要看对应微架构的吞吐与端口，不能只看指令条数。

### 3. 重解释与数值转换的边界

C++20 的 `std::bit_cast` 在同宽、可平凡复制类型之间重解释值表示，不执行数值换算。目标对象的填充位内容不作保证。位模式还必须能形成目标类型的有效值。C 可用 `memcpy` 把对象表示复制到同宽目标，但读成目标类型同样要求该表示有效。二者可用于位模式检查、哈希或显式编解码。

数值转换则按目标值域生成新位串。把 `float` 的位模式重解释为 `int32_t`，得到的是 IEEE 754 字段组成的整数。把任意 `int32_t` 位串重解释为 `float`，可能得到正规数、次正规数、零、无穷或 NaN。结果完全由原位模式决定。

binary16（FP16）和 bfloat16（BF16）都是低位宽浮点格式。FP32 到它们的转换属于数值转换，不是 `bit_cast` 加模截断。转换需要选择舍入并处理溢出。即使某种 BF16 实现复用了部分高位，也不能把这种实现技巧推广成所有浮点窄化的语义。

任何跨边界的二进制数据都要同时声明宽度、端序、对齐与转换语义。宽度决定能装什么。端序决定字节怎样落盘。对齐决定对象放在哪里。转换语义决定越界与精度损失由谁承担。缺一项，接收方就可能得到位串相同而含义不同的数据。
