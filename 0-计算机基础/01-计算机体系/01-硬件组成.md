# 硬件组成

## 一、核心定义：指令与数据同池的“执行引擎”

现代存储程序式计算机（冯·诺依曼架构）的本质，是**指令与数据以同一种物理形式——无差别的二进制位模式（Bit Patterns）——同处同一存储空间**。程序（内存中的原生硬件指令序列）常驻于内存；CPU 内部只有其流经时的瞬态电平与缓存副本。CPU 在时钟驱动下不断从内存中载入二进制编码。这组编码走哪条硬件通路，就获得哪种语义解释：

| 通路 | 地址来源 | 位模式去向 | 语义角色 |
| --- | --- | --- | --- |
| **取指通路** | 程序计数器（PC） | 指令译码器 | 作为指令解析，驱动控制逻辑 |
| **访存通路** | 访存指令计算 | 寄存器（取数）/ 内存（存数） | 作为数据处理 |

在软件视角下，看似具备不同抽象层级的“程序”，在物理层面同样都是无差别的二进制位模式。C++ 等编译型语言的源码由编译器直接翻译为硬件指令集对应的原生机器码（Machine Code）并写入可执行文件；程序运行时，机器码被载入内存，CPU 的取指通路依据程序计数器（PC）给出的地址抓取并作为硬件指令执行。Python 等解释型语言则多一层抽象：解释器先把源码编译为面向虚拟机指令集的字节码（Bytecode，常缓存于 `.pyc` 文件中），再由解释器自身的取指-执行循环逐条解释——在物理硬件看来，字节码始终只是解释器处理的数据，真正驱动硬件运转的只有解释器自身的原生机器码。

* **部件与循环**：这是机器的最小逻辑模型——静态上由 CPU（执行引擎）与内存（状态容器）构成，动态上由取指-执行循环持续驱动。

  * **CPU（执行引擎）**：包含寄存器组、缓存、算术逻辑单元（ALU）与控制逻辑。寄存器中一部分随程序流转动态更新（如 PC）。引擎驱动经典五级处理：取指、译码、执行、访存、写回。运算与分支在执行阶段完成；取数在访存阶段自缓存读出并于写回阶段写入寄存器；存数在访存阶段将数据排入存储缓冲区（Store Buffer），随后更新 L1D，仅当该行被逐出缓存层级时才逐级回写 DRAM；写回阶段只更新内部寄存器，不访存。

  * **内存（状态容器）**：独立于 CPU 之外，以统一的二进制位模式容纳所有指令与数据。CPU 内部的多级缓存是内存局部的镜像副本。

  * **动态驱动（取指-执行循环与流水线冲突）**：各阶段在时钟节拍下重叠推进（时钟周期为相邻上升沿间隔；各部件频率各异、同源倍频，不存在全机统一周期）。由于流水线深度重叠，流水线填满时每一拍都有取指阶段在读指令；一旦有访存指令走到访存阶段，同一拍还需读写数据。若两者共用单一存储阵列与端口，同拍争抢必然引发结构冲突（Structural Hazard），导致流水线气泡。

* **微架构破局（基于访问频次的端口分化）**：根据各层级承受的访问频次与并发冲突概率，缓存在微架构上呈现出物理形态的分化：

  * **L1 的分裂（微架构哈佛）**：物理拆分为 L1I（指令）与 L1D（数据）两个独立阵列与独立端口，使取指与访存彻底并行，根除这一级的结构冲突。硬约束在于**同拍并发的端口需求**：流水线填满时，取指通路每拍必占一次访问；而访存通路依指令流中访存指令的疏密，呈**多拍一次（运算指令流经时）或连续每拍一次（密集访存指令流经时）**。由于单端口阵列每拍只能服务一次请求，只要某拍有访存指令抵达访存阶段，单端口下就必然与取指发生同拍争抢。这种常态化的峰值冲突无法靠调度弥补，只能靠拆分阵列、独立端口来保障吞吐。

  * **L2/L3 的汇合（回归冯·诺依曼）**：由于 L1 极高的命中率过滤了绝大多数请求，真正穿透到 L2、L3 的缺失（Miss）访问频次骤降一至两个数量级（往往数十拍才发生一次）。在如此稀疏的访问频次下，取指缺失与数据缺失在同拍发生碰撞的概率微乎其微；即便撞上，输家也只是推迟一拍启动（阵列流水，每拍可接收一次新访问，占用只在启动那一拍，不是占满整个命中延迟），而它的下一次到达远在数十拍之后，这一拍不会累积成队列。偶发的单拍排队完全可以容忍，根本没有必要再维持物理拆分与多端口的高昂硬件开销。因此，下级缓存直接合并为统一的单一缓存（Unified Cache），两条通路在此排队复用同一端口；而统一混装带来的指令与数据容量动态共享、空间利用率提升，则是顺水推舟的额外收益。

## 二、 虚拟地址到物理介质的全链路拓扑与 DDR5 物理驻留机制

在现代 x86 计算体系中，软件视角的内存是一片平坦、连续的虚拟字节数组；而在硅片与电路板构成的物理世界里，不存在抽象的“内存池”。**数据在写入的那一刻，其比特流即通过硬件页表转换与 $\text{GF}(2)$ 线性散列，刚性落位在某根特定 DIMM、某组特定颗粒内部的微小电容阵列里。**

### 1. 全链路纵览：从虚拟地址到物理介质的十二级穿透

当 CPU 核心（Core）执行一条访存指令（如 `MOV`）时，64 位虚拟地址（VA）严格遵循以下十二级硬件路径向底层物理介质穿透：

$$\text{Core} \rightarrow \text{Cache (L1/L2/L3)} \xrightarrow{\text{Ring/Mesh 选路}} \text{IMC (MC0/MC1)} \rightarrow \text{Channel} \rightarrow \text{Sub-channel} \rightarrow \text{DIMM Slot} \rightarrow \text{Rank} \rightarrow \text{Bank Group} \rightarrow \text{Bank} \rightarrow \text{Row} \rightarrow \text{Column} \leftrightarrow \text{SSD}$$

1. **Core（处理器核心与 MMU/TLB）**：执行指令并生成虚拟地址（VA）。核心先经 **MMU（Memory Management Unit，内存管理单元）** 查旁路 **TLB（Translation Lookaside Buffer，地址转换速查表）**；未命中时，由页表遍历器（Page Miss Handler，PMH）检索进程私有页表，将 VA 转换为系统物理地址（PA）。遍历成功（各级 `Present = 1`）即把翻译填入 TLB 并继续；只有当某级 `Present = 0` 时，才升级为缺页异常（`#PF`）陷入 OS——此时才可能由操作系统调度链路末端的 **SSD** 换入 4KB 页面。换入并更新 PTE 后，指令重试，再走一次 Page Walk。
2. **Cache（L1 $\rightarrow$ L2 $\rightarrow$ L3 缓存层级）**：获得 PA 后，硬件以 **64 Bytes（Cache Line）** 为粒度，使用物理地址标签（Physical Tag）依次检索 L1D、L2 与共享 L3（LLC）。仅当三级缓存全部未命中（Miss）或发生脏行写回（Write-back）时，访存请求才穿透缓存边界进入片上互连网络。
3. **片上互连与 IMC（CHA/TAD 译码器 $\rightarrow$ MC0 / MC1）**：请求在 L3 出口处经 **CHA（Caching and Home Agent，缓存与归宿代理）** 与 **TAD（Target Address Decoder，目标地址译码器）** 的多比特异或散列计算主通道归属，通过片上网络（Ring/Mesh）路由至独立内存控制器 **MC0** 或 **MC1**，随后分发至 Sub-channel A 或 Sub-channel B 的独立读写队列（RPQ/WPQ，构成 4 个独立的 $M/D/1$ 硬件服务台）。
4. **Channel（内存主通道）**：主板 PCB 上物理隔离的传输通道。主流双通道平台配置 **2 个 64-bit Channel（Channel 0 与 Channel 1）**，由 MC0 与 MC1 一对一管辖。
5. **Sub-channel（DDR5 独立子通道）**：单个 64-bit Channel 在出 CPU 引脚时即被硬切分为 **2 个完全独立的 32-bit Sub-channel（Sub-channel A 与 Sub-channel B）**。全平台共形成 **4 个独立 Sub-channel**，各自具备专属的命令/地址总线（CA Bus）与 32-bit 数据总线（DQ Bus）。
6. **DIMM Slot（板级物理插槽）**：每个 32-bit Sub-channel 总线上通过 Fly-by 菊花链串联挂载 **2 个物理插槽（Slot 0 与 Slot 1，即 2DPC 布局）**。每根物理内存条的左、右两个半区分别服务于所属通道的 Sub-channel A 与 Sub-channel B。
7. **Rank（条内颗粒群逻辑面 / Package Rank）**：在选定插槽的单个 32-bit Sub-channel 半区内，由同一根片选信号（`CS#`）同步唤醒的一组 DRAM 颗粒。以 $\times 8$ 位宽颗粒为例，每 **4 颗 $\times 8$ 颗粒并联**（ $4 \times 8\text{-bit} = 32\text{-bit}$）构成服务于该子通道的 **1 个物理 Rank**（单面条 1Rx8 含 `Rank 0`，双面条 2Rx8 含正反面 `Rank 0/1`）。
8. **Bank Group（存储体组，BG）**：DRAM 颗粒晶圆（Die）内部的第一级并行分区。DDR5 包含 **8 个 Bank Group（BG0 ~ BG7）**，跨 BG 连续访问可跑满短列延迟（ $`t_{\text{CCD\_S}} = 8\text{ 拍} = 2.5\text{ ns}`$ ），同 BG 内连续访问则受制于长列延迟（ $`t_{\text{CCD\_L}} = 12 \sim 16\text{ 拍}`$ ）。
9. **Bank（存储体）**：每个 BG 内部含 **4 个独立 Bank**（单颗芯片共 32 个 Bank）。每个 Bank 拥有一套完全独立的行缓冲（Row Buffer / Sense Amplifiers）与状态机。
10. **Row（水平字线，Wordline）**：Bank 二维矩阵的水平坐标。`ACT` 命令附上 16-bit 行地址导通字线，单颗 $\times 8$ 颗粒激活 $1\text{KB}$，单子通道 Rank 内 **4 颗并联颗粒同步激活 $4 \times 1\text{KB} = \mathbf{4\text{KB}}$ 电荷**，锁存至该 Bank 的 Row Buffer 中。
11. **Column（垂直位线，Bitline）**：Bank 二维矩阵的垂直坐标。当目标 Row 已驻留 Row Buffer 时，`RD`/`WR` 命令通过列地址从 $4\text{KB}$ 行缓冲（含 64 个 Cache Line）中选通目标列，驱动 **BL16（Burst Length 16）** 在 32-bit 总线上连续突发传输 16 拍，吐出 $32\text{ bits} \times 16 = \mathbf{64\text{ Bytes}}$。
12. **SSD（非易失性块存储边界）**：位于 DRAM 寻址链路之外的后备存储。发生缺页或换出时，OS 通过 NVMe/PCIe 总线以 **4KB Page** 为粒度执行 DMA 块搬移。

### 2. 虚拟页号到物理框号的映射机制（ $f: \text{VPN} \rightarrow \text{PFN}$）：页内恒等直通、软件级/硬件级离散、稀疏基数树与 TLB 端点缓存

在硬件寻址体系中，地址转换**从不作用于完整地址**。无论是 48 位虚拟地址（`VA[47:0]`）还是 36 位系统物理地址（`PA[35:0]`，对应 64GB 物理内存），在硬件结构上均被严格切分为 **“高位的页号/框号（大地址） + 低 12 位页内偏移（小地址，`off[11:0]`）”** 两部分：

```text
          VA (48 bits)                                        PA (36 bits, 64GB)
   ┌──────────────┬────────────┐                       ┌──────────────┬────────────┐
   │   VPN (36b)  │  off (12b) │                       │   PFN (24b)  │  off (12b) │
   │   VA[47:12]  │  VA[11:0]  │                       │   PA[35:12]  │  PA[11:0]  │
   └──────┬───────┴─────┬──────┘                       └──────┬───────┴─────┬──────┘
          │             │                                     ▲             ▲
          │             └──────────────────┬──────────────────┴─────────────┘
          │                                │    低 12 位小地址旁路直通 (PA[11:0] ≡ VA[11:0])
          ▼                                │    (自始至终从未进入页表与 TLB)
   ┌───────────────────────────────────────┴───────────────────────────────────────┐
   │  映射函数 f: VPN (36b) ──► PFN (24b)    • 多级页表 = 函数 f 的稀疏基数树表示   │
   │                                         • 核心 TLB = 函数 f 的端点求值结果缓存 │
   └───────────────────────────────────────────────────────────────────────────────┘

```

页表与 TLB 只翻译高位**大地址**——唯一输入是高 36 位 **虚拟页号（VPN，Virtual Page Number）**，唯一输出是高 24 位 **物理框号（PFN，Physical Frame Number）**；低 12 位**小地址**自始至终在页表体系之外旁路直通。因此，**页表不是 $\text{VA} \rightarrow \text{PA}$ 的中间项，而是函数 $f: \text{VPN} \rightarrow \text{PFN}$ 的中间表示：**

$$f: \underbrace{\\{0,1\\}^{36}}_{\text{定义域：}2^{36}\text{ 个虚拟页 (VPN)}} \longrightarrow \underbrace{\\{0,1\\}^{24}}_{\text{值域：}2^{24}\text{ 个物理框 (PFN)}}$$

#### 1. 连续的地址空间与软件级/硬件级离散：从虚拟指针到 DRAM 坐标的访存因果链

**地址空间连续性基准**：虚拟地址空间（`VA`）与物理地址空间（`PA`）作为线性整数编号域，在架构定义上均严格连续：

* **`VA` 空间（编译器与架构定义的连续整数轴）**：指针算术 `ptr[i] = base + i * sizeof(T)` 本质是字节编号上的线性加法。
* **`PA` 空间（固件根据装机容量划定的连续整数轴）**：开机阶段 UEFI MRC 枚举在位 DIMM 后，将全部可用物理内存编码为一段线性连续的整数区间（如 64GB 对应 `PA[35:0]`，128GB 对应 `PA[36:0]`）。
   * **模型边界**：本节采用**无 MMIO 空洞的简化模型**——假设 64GB 恰好填满 `PA[35:0]`、PFN 为 24 位。真实平台的 MMIO 空洞会把 DRAM 切成数段，并把部分 RAM 重映射到 4GB 以上；最高物理地址会超过装机容量（64GB 机器约到 65GB，覆盖它需要 25 位 PFN）。这不改变本节 `VPN → PFN` 的离散性结论。

访存链路中的“连续”与“离散”分化，并非源于地址空间本身的不连续，而是连续地址在跨越硬件层级时经历的**一段页内恒等直通**与**软件级、硬件级离散映射**：

```text
 【虚拟地址空间 VA：架构定义的线性连续整数轴】
   指针算术保持缓冲区连续: ptr[i] = base + i*sizeof(T)
   步长 sizeof(T)=64B (1 Cache Line) 时，递进仅改变 VA[47:6]，VA[5:0] 恒为行内字节偏置
   CPU 核心 AGU 在访存指令执行周期计算出完整 48-bit VA = { VPN, off }
         │
         │ (按页粒度边界 2^N 切分：常规页 N=12 即 4KB；大页 N=21 即 2MB)
         ├─────────────────────────────────────────────────────────────┐
         ▼ 高位页号 VA[47:N] (VPN)                                     ▼ 低位页内偏移 VA[N-1:0] (off)
 【软件级离散映射：页间 VPN -> PFN】                           【页内恒等直通：VA[N-1:0] ≡ PA[N-1:0]】
   • PA 空间本身是由固件 MRC 划定的连续整数编号区间              • OS 分配物理内存的最小粒度为整页 (4KB 或 2MB)；
     (如 64GB 对应 PA[35:0])                                     页内字节作为刚性整体映射，相对偏移恒定不变
   • 页表为每个连续 VPN 独立指派当时空闲的物理框 PFN；           • 页内包含的全部 Cache Line (VA[N-1:6]) 及行内字节
     连续 VPN 映射出的 PFN 在 PA 编号轴上呈离散分布                (VA[5:0]) 严格连续，免查表直通并实现页表空间压缩
         │                                                             │
         └──────────────────────────────┬──────────────────────────────┘
                                        ▼
 【MMU 出口汇合：拼接生成完整 36-bit 物理地址 PA = { PFN, off }】
   至此“页/框 (Page/Frame)”软件管理边界终止；
   下半场 L1/L2/L3 与 IMC 全面转为 (PA[35:6] 物理缓存行地址, 64B 载荷) 二元硬件事务
                                        │
                                        ▼
 【硬件级离散映射：PA[35:6] -> DRAM 物理坐标 (Channel / Sub-channel / DIMM Slot / Rank / Bank Group / Bank)】
   • 即便 PA[35:6] 严格连续，CHA/TAD 与 IMC 仍以 64B Cache Line 为粒度将其离散映射至物理单元
   • 通过融合高低位 (含 N>=12 的高位 2^N) 的 GF(2) 异或散列树，同时满足三项硬件约束：
     1) 多通道并发带宽均衡    2) 跨 Bank Group 轮转以命中短列延迟 (tCCD_S)    3) 消除 2^N 步长同余冲突

```

##### 1.1 页内恒等直通（`VA[N-1:0] ≡ PA[N-1:0]`）：低位连续性的刚性继承与页表压缩

CPU 核心的地址生成单元（**AGU**）执行访存指令时，按 `VA = base + index × scale + disp` 计算有效地址（对 `ptr[i]` 即 `base = ptr`、`index = i`、`scale = sizeof(T)`、`disp = 0`）；完整的 48 位 `VA` 在进入 MMU/TLB 前即已生成。硬件随后以页大小 $2^N$ 字节为边界（常规页 $N=12$ 即 $4\text{KB}$，大页 $N=21$ 即 $2\text{MB}$），将 `VA` 切分为高位虚拟页号 `VPN` 与低位页内偏移 `off`。

在 `Bit N` 以下的页内尺度中，映射关系保持 **1:1 恒等连续（`VA[N-1:0] ≡ PA[N-1:0]`）**：

* **页内两层严格连续**：无论是页内排列的 Cache Line 编号（`VA[N-1:6]`，4KB 页内含 $2^6 = 64$ 行，2MB 大页内含 $2^{15} = 32,768$ 行），还是单个 64B Cache Line 内部的字节偏置（`VA[5:0]`， $0 \sim 63$ 字节），均由 `VA` 直接直通继承至 `PA`，在物理地址轴上严格连续。
* **页表与 TLB 的空间压缩比（64:1 与 32,768:1）**：由于页内全部 Cache Line 在 `PA` 编号轴上连续排列，页表只需 **1 个 8B 叶表项（Leaf Entry）记录 1 个基址 `PFN`**，即可与直通的 `VA[N-1:6]` 组合寻址整页内的所有 Cache Line。这里的“叶表项”随页大小换级：4KB 页是 `PTE`，2MB 页是置 `PS=1` 的 `PDE`，1GB 页是置 `PS=1` 的 `PDPTE`。4KB 页粒度下，单条叶表项 / TLB 词条统管 64 个缓存行（**64:1 压缩**）；启用 2MB 大页（`VA[20:0] ≡ PA[20:0]`）时，一张置 `PS=1` 的 `PDE` 直接终结：原本需要 **1 张 `PT` 页（内含 512 个 `PTE`）** 才能覆盖的 2MB 区间，现在由这 1 个 PDE 直接覆盖；单条叶表项的覆盖范围从 4KB 扩大 512 倍到 2MB，统管 32,768 个缓存行（**32,768:1 压缩**）。若直接以 64B Cache Line（`Bit 6`）作为映射粒度，仅按表项数计页表体积将膨胀 64 倍，单条 TLB 词条的地址覆盖范围也将缩减至 $1/64$。

##### 1.2 软件级离散映射（页间 `VPN → PFN`）：操作系统分配导致的 `PA` 编号离散

在 `Bit N` 以上的高位页号区间，连续的 `VPN` 经由页表映射至离散的 `PFN`，构成软件级离散映射：

* **页间编号解耦**：系统运行过程中，伙伴分配器（Buddy Allocator）管理的空闲物理框在 `PA` 整数轴上呈非连续分布。操作系统为每个 `VPN` 独立分配空闲 `PFN`，相邻虚拟页（`VPN` 与 `VPN + 1`）对应的物理框号因此**没有连续性约束**——通常呈离散分布，低碎片时也可能恰好相邻。
* **内存碎片化与大页连续化的物理边界**：系统软件层面的“消除内存碎片”或“启用 2MB/1GB 大页”，其作用边界严格限定于本层映射——即将 `VA → PA` 发生离散跳转的位宽边界从 `Bit 12`（4KB）推高至 `Bit 21`（2MB）或 `Bit 30`（1GB）。其本质不是改变 `VPN → PFN` 的映射法则，而是**改变叶表项的映射粒度**：4KB 页时，一条叶表项只锁 1 个物理框；大页时，一条叶表项直接锁一整段物理连续的框。同样大小的 TLB 因此能覆盖更大的工作集，TLB Miss 与 Page Walk 次数下降。
   * **对 64B 预取流的直接效应**：预取器以 **64B Cache Line** 为单位提前发请求，但每条请求都要先完成地址翻译，而 TLB 是按页记账的——4KB 页下，**一条 TLB 项只覆盖 `VA[11:6]` 的 64 个 Cache Line**。页内预取可一路复用这条翻译；跨过 4KB 边界时，下一行属于另一个虚拟页（`VPN` 变了），必须先拿到新页的翻译，分支处置如下：

```text
预取器发出跨页请求（目标行属于新 VPN）
        │
        ▼
  新页的 TLB 项是否已在？
        │
   ┌────┴────────────────────┐
   ▼ 已在                     ▼ 不在
预取照常发出            硬件不为猜测走页表，
（复用既有翻译）         也不触发缺页
                           │
                           ▼
                    直接丢弃这条预取
                           │
                           ▼
             真实访问把新页翻译带进 TLB
                           │
                           ▼
             预取在新页内恢复推进
```

启用 2MB 大页后，同一条 TLB 项覆盖 `VA[20:6]` 的 32,768 个 Cache Line；原先每 4KB 就要换一次 `VPN` 的 512 个块，现在全部落进同一大页的页内偏移，64B 预取流无需新的翻译即可继续前进。

##### 1.3 硬件级离散映射（`PA[35:6] → DRAM 坐标`）：面向并发带宽与 $t_{\text{CCD\\_S}}$ 的硬件交织

`PFN` 与 `off` 在 MMU 出口拼接为完整 36-bit `PA` 后，页级管理边界终止；L1/L2/L3 缓存及 IMC（集成内存控制器）的片上路由与调度均以 **`(PA[35:6] 物理缓存行地址, 64B 数据载荷)`** 为基本事务单元。

即便输入的 `PA[35:6]` 严格连续（如落在同一 4KB 页或 2MB 大页内），**CHA/TAD 与 IMC 的成对译码**仍会在 **64B** 粒度上将其打散：**CHA 先以异或树选定 L3 切片与归宿代理，TAD 再逆向解构出目标 Sub-channel**；**IMC 最后译出 DIMM Slot / Rank / Bank Group / Bank**，以满足以下硬件时序与拓扑约束：

* **多通道（Channel / Sub-channel）并发带宽**：将相邻的 64B 缓存行交织（Interleave）至多个独立的 DDR4 Channel 或 DDR5 Sub-channel，使单次连续流式读写能够并发占用全部物理数据总线。
* **Bank Group 循环轮转与短列延迟（ $t_{\text{CCD\\_S}}$）**：在 DDR4/DDR5 内部阵列中，连续两次列访问（CAS）若落入**同一 Bank Group**，必须承受长列延迟（**$t_{\text{CCD\\_L}}$**）；若落入**同一 Bank 的不同行**，则会触发行缓冲冲突（Row Buffer Conflict，需额外承受 $t_{\text{RP}} + t_{\text{RCD}}$ 预充电与激活开销）。通过将连续的 `PA[35:6]` 交错映射至**不同的 Bank Group** 循环轮转，IMC 得以按最短的短列延迟（**$t_{\text{CCD\\_S}}$**）背靠背（Back-to-Back）发射列读写命令，跑满数据总线吞吐。

#### 2. 四级 512 叉稀疏基数树（Radix Tree）：同构表项、按需生长与四步位拼接算术

由于映射函数 $f$ 的定义域高达 $2^{36}$ 条 `VPN`，若采用一维平坦数组存储页表，单个进程仅页表就需消耗 $2^{36} \times 8\text{B} = \mathbf{512\text{GB}}$ 物理内存——在 64GB 的机器上连一张表都装不下。为消除未分配地址的空间开销，硬件将 36 位 `VPN` 等分为 **4 段 9-bit 索引**（ $36 \div 9 = 4$ 级；57 位虚拟地址 LA57 则为 $45 \div 9 = 5$ 级），构建出按需生长的 **512 叉稀疏基数树（`PML4 -> PDPT -> PD -> PT`）**：

* **单张表页的 4KB 自相似尺寸**：每一级表页本身固定占用 **1 个 4KB 物理框**，内含 $512 \text{ 项（9 bits 索引）} \times 8\text{ Bytes/项（3 bits 字节偏移）} = 4096\text{ Bytes}$（恰好满足 $9\text{b} + 3\text{b} = 12\text{b}$ 框内偏移）。
* **64 位表项的同构位布局与两类语义（非叶路由指针 vs. 叶节点函数值）**：
所有层级的 64-bit 表项（`PML4E / PDPTE / PDE / PTE`）共享完全相同的硬件位段，且**低 12 位 `Bit[11:0]` 与虚拟地址、物理地址坐标均无关**（因所有 4KB 物理框的起始地址低 12 位恒为 `0`，硬件直接复用这 12 个比特存放 `Present`、`R/W`、`PS` 等控制标志）：

```text
 63          62 59    52 51       36 35                       12 11  9 8  7  6  5  4  3  2  1  0
┌───────────┬────────┬───────────┬───────────────────────────┬─────┬──┬──┬──┬──┬──┬──┬──┬──┬──┐
│    NX     │ 保护键 │ 保留(全0) │      PFN (PA[35:12])      │ AVL │G │PS│D │A │P │P │U │R │P │
│ (禁执行)  │ (PKEY) │ (64GB系统)│ • 非叶表项: 下级表框的PFN │     │  │  │  │  │C │W │/ │/ │  │
│           │        │           │ • 叶表项  : 目标数据框PFN │     │  │  │  │  │D │T │S │W │  │
└───────────┴────────┴───────────┴───────────────────────────┴─────┴──┴──┴──┴──┴──┴──┴──┴──┴──┘
                                                ▲                        ▲                    ▲
                                   24-bit 物理框号 (核心载荷)      PS=1 提前终结为大页叶节点  P=Present (在位判据)

```

| 表项类别 | 涵盖层级与条件 | `Bit[35:12]`（24-bit PFN 字段）的硬件语义 |
| --- | --- | --- |
| **1. 非叶表项（路由指针）** | `PML4E` / `PDPTE` / `PDE`（当 `PS = 0` 时） | 存放 **下一级 4KB 页表所在物理框的 `PFN`**（回答“下一张表在哪”）。 |
| **2. 叶表项（函数结果）** | 第 4 级 `PTE`（4KB 标准页）；或 `PDE`（`PS=1`，2MB 大页）/ `PDPTE`（`PS=1`，1GB 大页） | 存放 **最终目标业务数据所在物理框的 `PFN_Data`**（回答“目标数据框是哪一个”）。 |

* **稀疏树的按需生长与页间离散实证（追踪进程先后触碰 A、B、C、D 四个虚拟页）**：
进程启动时，内核仅分配 1 张顶级 `PML4` 表页（由 `CR3` 指向），其中 512 个槽位全部置 `Present (P) = 0`。当进程依次触碰 4 个虚拟页——**页 A `(1, 2, 3, 4)`**、与 A 在虚拟空间紧邻的 **页 B `(1, 2, 3, 5)`**、在第 3 级分叉的 **页 C `(1, 2, 7, 0)`**、以及在第 2 级分叉的 **页 D `(1, 8, 0, 0)`** 时，基数树仅沿着被触碰的分支在物理内存中动态生长：

```text
  【初始状态】 仅 CR3 指向 1 张全空的 PML4 表页 (512 个槽位全部 P=0)

  ① 触碰页 A: VPN = 0x0_8080_604, 四级索引 (1, 2, 3, 4) ──► 沿途全为 P=0，级联新建 3 张下级表页 + 1 个数据框
     PML4[1](P=0->1) ──► 新建 PDPT#1[2](P=0->1) ──► 新建 PD#1[3](P=0->1) ──► 新建 PT#1[4] := PFN_A (0x1A2B3C)

  ② 触碰页 B: VPN = 0x0_8080_605, 四级索引 (1, 2, 3, 5) ──► 与页 A 虚拟相邻 (VPN 仅差 1)，前三级 P=1 全部复用!
     PML4[1](复用)   ──► 复用 PDPT#1[2](复用)   ──► 复用 PD#1[3](复用)   ──► 填入 PT#1[5] := PFN_B (0x0007FF)
     (新建 0 张表页；伙伴分配器随手给出当时空闲的 PFN_B = 0x0007FF)

  ③ 触碰页 C: VPN = 0x0_8080_E00, 四级索引 (1, 2, 7, 0) ──► 前两级复用，在 PD#1[7] 处分叉，新建 1 张叶表 PT#2
  ④ 触碰页 D: VPN = 0x0_8200_000, 四级索引 (1, 8, 0, 0) ──► 仅第一级复用，在 PDPT#1[8] 处分叉，新建 PD#2 与 PT#3

  【生长完结后的 DRAM 物理页表树拓扑】 (未列出的槽位一律保持 P=0，下级表页耗费 0 字节):
   CR3 ──► PML4
            └─ [1] ──► PDPT#1
                        ├─ [2] ──► PD#1
                        │           ├─ [3] ──► PT#1
                        │           │           ├─ [4] ──► PFN_A = 0x1A2B3C  (PA_A ≈ 6.54 GiB) ┐ VA 紧邻 (差 4KB)
                        │           │           └─ [5] ──► PFN_B = 0x0007FF  (PA_B ≈ 8.00 MiB) ┘ PA 相隔 6.53 GiB!
                        │           └─ [7] ──► PT#2
                        │                       └─ [0] ──► PFN_C = 0x9C3000
                        └─ [8] ──► PD#2
                                    └─ [0] ──► PT#3
                                                └─ [0] ──► PFN_D = 0x000012

```

这一生长过程直接揭示了基数树的两大物理本质：

1. **页间完全解耦（印证软件级离散映射）**：页 A 与页 B 在 `VA` 上首尾相接（`VPN` 相差 1），共享同一张叶表 `PT#1` 的相邻槽位 `[4]` 与 `[5]`；但 `PFN_B` 并非由 `PFN_A` 推算得出，而是伙伴分配器当时手头恰好空出的物理框。两者左移 12 位还原出的物理基址分别为 `PA_A = 0x1A2B3C000`（约 $6.54\text{ GiB}$）与 `PA_B = 0x0007FF000`（约 $8.00\text{ MiB}$），在 `PA` 编号空间中足足相隔 **`0x1A233D000`（约 $6.53\text{ GiB}$）**。
2. **按需稀疏压缩（ $28\text{ KB}$ vs. $512\text{ GB}$）**：映射这 4 个跨度极大的虚拟页，系统仅分配了 `PML4` + `PDPT#1` + `PD#1` + `PT#1` + `PT#2` + `PD#2` + `PT#3` 共 **7 张页表框（ $7 \times 4\text{KB} = 28\text{KB}$）**，连同 4 个业务数据框（ $16\text{KB}$）合计仅消耗 **44KB** 物理内存。其余未触碰的槽位（如 `PML4` 剩余的 511 项、`PDPT#1` 剩余的 510 项）因 `P = 0` 而无需分配任何下级表页，相比 $512\text{GB}$ 的一维平坦数组实现了约 **1900 万倍** 的空间压缩。

* **页表遍历器（PMH）的四步位拼接算术（以访问页 A 内 `VA = 0x0000_0080_8060_4ABC` 为例）**：
当页表遍历器（PMH）检索上述页表树中的页 A（四级索引 `1, 2, 3, 4`，页内偏移 `off = 0xABC`）时，每走完一级，当前 9-bit 索引即被消耗丢弃；硬件将上一级表项吐出的 **`24-bit PFN`** 与下一级的 **`9-bit VPN_slice`** 及 **`3'b000`（8 字节表项对齐）** 直接拼接为 36-bit 物理地址（ $24 + 9 + 3 = 36\text{ bits}$）发起内存读取：


```text

          │

  【Step 3: 查第 3 级 PD#1 表 (消耗 VPN_2 = 3)】
```

##### 核心硬件事实澄清

1. **命名规范与缓存的实际内容（到底是存 8B 完整表项 `E`，还是 24-bit 框号 `PFN`？）**
   * **命名不一致问题**：原表中写的是 `PML4 / PDPTE / PDE Cache`，这里 `PML4` 漏了 `E`（Entry）。按照 Intel SDM（卷 3 第 4.10.3 节 *Paging-Structure Caches*）的官方标准命名，前三级的缓存严格对应各自的**表项（Entry）**，即：**`PML4E Cache`**、**`PDPTE Cache`**、**`PDE Cache`**。
   * **底层存储内容**：它在硬件 SRAM 阵列中缓存的**不是原始的 64-bit (8B) 内存字节流**，而是 PMH 从 8B 表项中**已经剥离并解析出**的核心字段：**【24-bit 下一级页表物理框号 `PFN` + 累积的访问权限位（如 `R/W`、`U/S`、`XD`）】**。
   * **为什么必须存权限位？** 因为 x86 页表权限是“沿树向下求交集（最严格限制生效）”的。如果 `PDE Cache` 只存第 4 级页表的 `PFN_PT` 而不存前三级累积下来的读写权限，跳级查表时硬件就会丢失上级目录施加的只读或内核态限制。

2. **PMH 查找 `Paging-Structure Caches` 的真实流水线（前缀最长匹配，而非从根往下走）**
   * 当 `L1 dTLB` 和 `L2 sTLB` 双双 Miss 唤醒 PMH 时，PMH **并不是**先去读 `CR3` 从第 1 级往下走，而是拿着高 27 位虚拟前缀，按从深到浅（`PDE Cache` $\rightarrow$ `PDPTE Cache` $\rightarrow$ `PML4E Cache`）的优先级去匹配页结构缓存！
   * **命中 `PDE Cache`（匹配高 27 位 `VPN[35:9]`）**：直接吐出第 4 级页表基址 `PFN_PT`，跳过 Step 1~3，**仅需 1 次内存表读**（直接执行 Step 4 读 `PTE`）。（这是 90% 以上 `TLB Miss` 的真实归宿）。
   * **命中 `PDPTE Cache`（匹配高 18 位 `VPN[35:18]`）**：吐出第 3 级基址 `PFN_PD`，跳过 Step 1~2，**仅需 2 次内存表读**（Step 3 $\rightarrow$ Step 4）。
   * **命中 `PML4E Cache`（匹配高 9 位 `VPN[35:27]`）**：吐出第 2 级基址 `PFN_PDPT`，跳过 Step 1，**仅需 3 次内存表读**（Step 2 $\rightarrow$ Step 4）。
   * **全未命中（All Miss 冷遍历）**：才不得不从 `CR3.PFN_PML4` 出发，老老实实走完完整的 **4 次串行内存表读**（Step 1 $\rightarrow$ Step 4）。

#### 3. 多进程“一进程一树”隔离、核心旁 `TLB` 分级形态与 `CR3 + PCID` 无清空切换

在现代操作系统中，DRAM 内存中的多棵进程页表树与 CPU 核心旁唯一的硬件 TLB 阵列通过 `CR3` 寄存器与 `PCID`（进程上下文标识符）协同工作：

1. **DRAM 内存中：一进程一棵独立基数树**
   系统并发运行 N 个进程时，DRAM 中独立驻留 N 棵四级页表树。进程私有隔离通过将不同进程的同号 `VPN` 映射至不同 `PFN_Data` 实现；多进程零拷贝共享（如共享动态库或大模型只读权重）则通过将多个进程各自私有 `PT` 叶表中的 `PTE` 指向同一个 `PFN_Data` 实现，物理电容中仅存唯一一份数据。

2. **核心旁 `TLB` 的真实形态：拍平路径的端点键值表（只存叶表项，不存树路径）**
   四级遍历路径（`1 -> 2 -> 3 -> 4`）在进入 TLB 时被彻底抹平。TLB 不记录中间级表框指针，而是将 4 个 9-bit 索引重新折叠回完整的 36-bit `VPN` 作为 Key，将叶表项输出的 24-bit `PFN_Data` 作为 Value，压成一条平坦的端点键值对（大页在 `PD / PDPT` 提前终结时，TLB 仅需匹配高 27 位或 18 位 `VPN` 前缀，单条 TLB 词条覆盖范围直接放大 512 倍或 262,144 倍）：

```text
  TLB 硬件词条结构 (将四级路径 1/2/3/4 彻底折叠为 VPN -> PFN 端点映射):
 ┌──────────────────────────────┬───────────────┬─────────────────────────────────────────┐
 │   Tag (Key 1): 完整 VPN      │ Key 2: PCID   │   Value: 目标数据框 PFN_Data + 权限标志  │
 │   0x0_8080_604 (36 bits)     │ 0x001 (12b)   │   0x1A2B3C (24 bits) + R/W/X/U/G/D/A    │
 └──────────────────────────────┴───────────────┴─────────────────────────────────────────┘
```

3. **MMU 内部的三类专用硬件缓存层级（严格独立于 L1/L2/L3 数据缓存）**
   在 CPU 核心的 MMU 单元内部，地址转换专用硬件按速度与职责分为两级 **TLB**（缓存第 4 级终局叶表项 `PTE` 映射）与一组 **页结构缓存**（缓存前 3 级非叶表项 `PML4E / PDPTE / PDE` 映射）：

| MMU 内部硬件结构 | 硬件层级与官方名称 | 典型规模与命中延迟 | 缓存内容（Key $\rightarrow$ Value）与核心职责 |
| --- | --- | --- | --- |
| **一级地址速查表** | **`L1 dTLB`**（数据 TLB） / `L1 iTLB`（指令 TLB） | $64 \sim 96$ 项；**$0.5 \sim 1$ 周期** | 缓存最热的 **第 4 级叶表项 (`PTE`) 解析结果**（`PCID + VPN[35:0] -> 24b PFN_Data + 权限标志`），紧贴核心 AGU。 |
| **二级地址速查表** | **`L2 sTLB`** *(Second-Level Shared TLB)* | $1024 \sim 3072$ 项；**$7 \sim 8$ 周期** | 缓存次热的 **第 4 级叶表项 (`PTE`) 解析结果**。仅当 `L1 dTLB` 与 `L2 sTLB` **均未命中**时，才触发 **`TLB Miss`** 并唤醒硬件状态机 **PMH**。 |
| **页结构缓存** *(PMH 内部跳级加速器)* | **`Paging-Structure Caches`**<br>(`PDE / PDPTE / PML4E Cache`) | 每级数十项<br>*(内嵌于 PMH 硬件单元)* | 缓存从 **前三级 8B 非叶表项中剥离出的子树基址与累积权限**：<br>• **`PDE Cache`**：`VPN[35:9] -> PFN_PT (24b) + 权限`<br>• **`PDPTE Cache`**：`VPN[35:18] -> PFN_PD (24b) + 权限`<br>• **`PML4E Cache`**：`VPN[35:27] -> PFN_PDPT (24b) + 权限`<br>当发生 `TLB Miss` 时，PMH 先按最长前缀匹配此缓存，命中哪一级就直接拿到下一级页表框号 `PFN`，将原本最坏 4 次的串行查表缩短为 **$1 \sim 3$ 次**！ |

---

4. **`CR3` 寄存器结构与多进程 `PCID` 混居免清空切换**

单颗核心的 `TLB`（`L1 dTLB + L2 sTLB`）同时混居着多个活跃进程的热点叶表项。现代 x86 架构（开启 `CR4.PCIDE = 1`）通过 64 位 `CR3` 寄存器实现多进程安全隔离与零开销切换：

```text
  64-bit CR3 核心控制寄存器布局:
  63                   52 51                                      12 11               0
 ┌───┬──────────────────┬────────────────────────────────────────┬──────────────────┐
 │ 1 │   保留位 (全 0)   │  当前进程顶级 PML4 表框基址 (PFN_PML4)  │ 当前进程号 PCID  │
 └───┴──────────────────┴────────────────────────────────────────┴──────────────────┘
   ▲                                         ▲                              ▲
 Bit 63 = 1 (切换进程时不清空 TLB)     TLB Miss 时供 PMH 从根部查表     TLB 查找时比对进程身份
```

* **切换瞬间免清空（No-Flush）**：OS 从进程 A（`PCID=1`）切换至进程 B（`PCID=2`）时，仅执行一条写 `CR3` 指令更新 `{PFN_PML4_B, PCID=2}` 并保持 `Bit[63] = 1`，硬件不清空 TLB。
* **硬件双键匹配防串台**：每次访存查 TLB 时，硬件比较器强制要求 `(TLB.PCID == CR3.PCID) && (TLB.VPN == VA[47:12])` 同时成立方判定为 `TLB Hit`。进程 A 遗留的词条因 `PCID` 不匹配而对进程 B 天然隐身，而进程 B 上一轮时间片留下的热点词条则可直接命中。

#### 4. 地址转换域（`TLB Miss`）与物理数据缓存域（`Cache Miss`）的正交状态机

在全链路硬件执行中，**阶段 A（MMU 地址转换域：求值 `VPN -> PFN_Data`）** 与 **阶段 B（片上数据缓存域：按 `PA` 检索 `64B` 业务数据）** 是严格串行、职责完全正交的两个独立阶段：

1. **阶段 A 边界（`TLB Hit / Miss`、PMH 阶梯跳级查表与 SSD 缺页拦截）**：
   核心发出 `VA` 后，高 36 位 `VPN` 进入 `L1 dTLB -> L2 sTLB` 检索。若两级 TLB 均未命中（**`TLB Miss`**），硬件立即唤醒 **PMH（Page Miss Handler）** 执行页表遍历（Page Walk）。**注意：PMH 绝非每次都傻傻地从 `CR3` 根部连读 4 次内存，而是先查询内嵌的 `Paging-Structure Caches` 进行跳级裁剪**：
   * **第一步：PMH 查页结构缓存（最长前缀优先裁减步数）**
     PMH 将 `VPN` 的高 27 位、18 位、9 位并行送入 `PDE / PDPTE / PML4E Cache` 比对（同样受 `PCID` 隔离约束）：
     * 若命中 **`PDE Cache`**（如刚访问完页 `(1,2,3,4)` 紧接着访问相邻页 `(1,2,3,5)`）：直接获得第 4 级页表框号 `PFN_PT` 及前三级累积权限，**跳过 Step 1\~3，仅需执行 Step 4（共 1 次内存表读）**。
     * 若仅命中 **`PDPTE Cache`** 或 **`PML4E Cache`**：分别获得 `PFN_PD` 或 `PFN_PDPT`，从 Step 3 或 Step 2 切入（**需 2 次或 3 次内存表读**）。
     * 若 **`Paging-Structure Caches` 全部未命中（All Miss 冷遍历）**：PMH 才被迫从 `CR3.PFN_PML4` 根部出发，执行最坏情况下的 **4 次串行内存表读（Step 1 $\rightarrow$ Step 4）**。

   * **第二步：PMH 对真实内存页表的微操作（地址拼接 $\rightarrow$ 读 8B 表项 $\rightarrow$ 剥离 24b PFN 并回填）**
     在任何需要访问真实内存页表的步骤 $k \in \\{1,2,3,4\\}$ 中，PMH 硬件遵循完全一致的定长拆箱流水线（以冷遍历 Step 1 查 `PML4` 表为例）：
     ```text
     【PMH 单步查表微操作示例 — Step 1: 查第 1 级 PML4 表 (消耗 VPN_4 = 1)】
      • 拼接表项物理地址 : PA_Step1 (36b) = { CR3.PFN_PML4 (24b), VPN_4=1 (9b), 3'b000 }
                          (低 12 位为页内字节偏移 = 槽位号 × 8B 表项宽度，末三位 3'b000 强制 8B 对齐)
      • 发起缓存一致性读 : PMH 将 PA_Step1 送入 L1D -> L2 -> L3 -> DRAM 数据通路读回 8B 原始表项 PML4E[1]
      • 硬件剥离与回填   : 校验 Bit[0] (P==1) 与权限位后，剥离低 12 位标志，抽出 Bit[35:12] 获得下一级
                          24-bit 框号 PFN_PDPT#1；同时将该映射写入 PML4E Cache 供后续访存跳级复用！
     ```

     (注：由于页表页本身驻留在物理内存中，PMH 发起的 `PA_Step1~4` 物理读请求在硬件连线上会自然流经 `L1D/L2/L3` 数据缓存层级——如果某个 8B 页表项恰好缓存在 `L1D` 中，单步查表仅需约 $4$ 个周期；若穿透至 DRAM 则需约 $65\text{ ns}$。但这属于 PMH 查表内部的微操作，与阶段 B 的业务数据检索在状态机上完全正交。)
   * **第三步：终局叶表项 `PTE` 校验与 `#PF` 缺页异常拦截**
     **TLB 与页结构缓存铁律只存 `Present = 1` 的有效映射**。当 PMH 最终读出第 4 级 8B 叶表项 `PTE`（或中途任意一级表项）发现 **`Bit[0] (Present) == 0`** 时，CPU 才确知目标数据框尚未分配或已换出至外存，当即中止流水线并抛出 `#PF` 缺页异常。随后由 OS 伙伴分配器分配空闲物理框 `PFN_New`（若为换页则启动 NVMe DMA 从 **SSD** 搬入 4KB 数据），将 `PFN_New` 写回 `PTE` 并置 `P = 1`，最后重新执行指令完成 TLB 回填。

2. **阶段 B 边界（`L1D / L2 / L3 Data Cache Hit / Miss`）**：
   仅当阶段 A 成功输出 24-bit `PFN_Data`，并与旁路直通的 12-bit `off` 拼装成完整的 36-bit 业务物理地址 **`PA = {PFN_Data, off}`** 后，4KB 页的使命正式终结，请求进入 **L1D $\rightarrow$ L2 $\rightarrow$ L3 数据缓存金字塔**，以 `PA[35:6]` 比对物理 Tag，提取 64B 业务数据。

```text
                       ╔═══════════════════════════════════════════════════════════╗
```

| **4. `TLB Miss` + `Data Cache Miss`** | 最坏组合：若连 `Paging-Structure Caches` 与数据缓存中的页表项也全部未命中（冷遍历），PMH 需先赴 DDR5 串行读 **4 次** 8B 页表项算出 `PFN_Data`，再赴 DDR5 读 **1 次** 64B 业务数据（共 **5 次** DRAM 访问；若 `P=0` 则触发 `#PF` 异常及 SSD 换页）。 | **$100 \sim 350\text{ ns}$**<br>(SSD 换页约 $50\text{ }\mu\text{s}$) |

### 3. 物理地址（PA）的 $\text{GF}(2)$ 异或散列与通道交织收敛

请求因 `Cache Miss` 穿透至内存控制器（IMC）后，硬件通过多比特异或散列网络将一维系统物理地址（PA）打散映射至多维并发单元（4 个独立 Sub-channel 的 $M/D/1$ 服务台与 32 个存储体组 BG），以消除 $2^N$ 幂次访问步长引发的队列坍缩与行冲突。

#### 1. 纯低位直映的局部坍缩与硬件多比特异或树模型

若硬件直接将低位 `PA[7:6]` 作为子通道选择位、`PA[10:8]` 作为存储体组（BG）选择位，当程序以 $\Delta = 2^N\text{ Bytes}$（ $N \ge 8$，如矩阵列遍历常见的 $256\text{B} \sim 64\text{KB}$ 步长）访问时，二进制加法 $\text{PA} + 2^N$ 仅改变第 $N$ 位及更高位，低位 `PA[10:6]` 恒定锁死。全部访存流将 100% 集中砸向单一 Sub-channel 的单一 BG，其余 3 个子通道闲置，有效带宽坍缩至 $1/4$，且因高位 Row 频繁翻转触发严重的同 Bank 行冲突（Row Thrashing）。

为打破 $2^N$ 步长驻波，现代 x86 处理器在 CHA/TAD 与 IMC 内部通过掩码寄存器（如 `CHANNEL_HASH` / `AMAP`）将中高位物理地址折叠注入低位选择器。不同代际 CPU 与 BIOS 配置的具体抽头位号存在差异，但代数结构完全同构。面向主流 **16Gb $\times 8$ DDR5 颗粒（64GB `PA[35:0]` / 128GB `PA[36:0]`）** 的标准硬件参考模型定义如下：

```math
\begin{aligned} \text{Ch\_Sel} &= \text{PA}_{7} \oplus \text{PA}_{14} \oplus \text{PA}_{15} \oplus \text{PA}_{18} \\ \text{SubCh\_Sel} &= \text{PA}_{6} \oplus \text{PA}_{13} \oplus \text{PA}_{16} \oplus \text{PA}_{17} \\ \text{BG}_{i} &= \text{PA}_{8+i} \oplus \text{PA}_{13+i} \oplus \text{PA}_{16+i} \qquad (i \in \{0, 1, 2\}) \\ \text{BA}_{j} &= \text{PA}_{13+j} \oplus \text{PA}_{15+j} \oplus \text{PA}_{20+j} \qquad (j \in \{0, 1\}) \end{aligned}
```

#### 2. $\text{GF}(2)$ 有限域线性代数体系与全局零碰撞双射证明

硬件异或散列并非软件工程中的“有损压缩哈希”，而是定义在 **二元伽罗瓦域 $\text{GF}(2)$** 上的严格满秩线性变换，在数学上保证 100% 零碰撞。

##### （1） $\text{GF}(2)$ 算术法则与地址空间的向量化

$\text{GF}(2) = (\\{0, 1\\}, \oplus, \cdot)$ 是仅包含 `0` 和 `1` 两个元素的有限域（模 2 算术体系），其运算规则直接对应数字逻辑门：

* **域加法（ $\oplus$，模 2 加 / 硬件 XOR 门）**：无进位加法， $0 \oplus 0 = 0$， $1 \oplus 0 = 1$， $1 \oplus 1 = 0$。其核心代数性质是**任何元素均为自身的加法逆元（ $a \oplus a = 0$）**，即对任意比特 $x$ 连续异或同一个掩码 $h$ 两次必然无损还原自身： $(x \oplus h) \oplus h = x \oplus (h \oplus h) = x \oplus 0 = x$。
* **域乘法（ $\cdot$，模 2 乘 / 硬件 AND 门）**： $1 \cdot 1 = 1$，其余均为 $0$。

在普通整数加法中，“进位（Carry）”会导致比特位之间产生非线性耦合；而在 $\text{GF}(2)$ 下，各个比特位严格解耦。因此，36 位物理地址 `PA[35:0]` 在数学上严格构成 **36 维线性向量空间 $\text{GF}(2)^{36}$ 中的一个列向量 $\mathbf{PA}$**，IMC 内部的异或门译码网络则等价于有限域上的**矩阵乘法 $\mathbf{Y} = \mathbf{M} \cdot \mathbf{PA}$**。

##### （2）分块单位上三角矩阵与对合自逆性（Involution）证明

将物理地址列向量 $\mathbf{PA}$ 划分为两部分：**待散列的低位路由段 $\mathbf{L}$**（如通道选择位 `PA[7:6]`）与 **提供散列熵的高位寻址段 $\mathbf{H}$**（如 `PA[35:8]`）。硬件遵循 **“低位 $\mathbf{L}$ 异或高位线性组合 $\mathbf{A}\mathbf{H}$ 定路由，高位 $\mathbf{H}$ 原样保留做寻址”** 的准则（其中 $\mathbf{A}$ 为右上角异或抽头掩码矩阵， $\mathbf{I}$ 为单位矩阵）。其分块矩阵通式与 4-bit 简化展开式（令 $L_1' = L_1 \oplus H_1, L_0' = L_0 \oplus H_0$）如下：

```math
\begin{bmatrix} \mathbf{L}' \\ \mathbf{H}' \end{bmatrix} = \begin{bmatrix} \mathbf{I} & \mathbf{A} \\ \mathbf{0} & \mathbf{I} \end{bmatrix} \begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} \mathbf{L} \oplus \mathbf{A}\mathbf{H} \\ \mathbf{H} \end{bmatrix} \quad \Longleftrightarrow \quad \underbrace{\begin{bmatrix} L_1' \text{ (Ch\_Sel)} \\ L_0' \text{ (SubCh\_Sel)} \\ H_1' \text{ (DRAM 高位)} \\ H_0' \text{ (DRAM 高位)} \end{bmatrix}}_{\text{变换后的硬件物理坐标 } \mathbf{Y}} = \underbrace{\begin{bmatrix} \mathbf{1} & 0 & 1 & 0 \\ 0 & \mathbf{1} & 0 & 1 \\ 0 & 0 & \mathbf{1} & 0 \\ 0 & 0 & 0 & \mathbf{1} \end{bmatrix}}_{\text{单位上三角变换矩阵 } \mathbf{M}} \cdot \underbrace{\begin{bmatrix} L_1 \\ L_0 \\ H_1 \\ H_0 \end{bmatrix}}_{\text{原始物理地址 } \mathbf{PA}}
```

该矩阵结构在数学上直接锁定了三条硬件属性：

1. **行列式恒为 1（满秩性）**：由于仅用高位 $\mathbf{H}$ 单向异或低位 $\mathbf{L}$，而绝不用低位去污染最高位 Row，无论右上角抽头矩阵 $\mathbf{A}$ 如何配置，变换矩阵 $\mathbf{M}$ 的左下角恒为全零矩阵 $\mathbf{0}$，主对角线恒为全 $1$。因此 $\mathbf{M}$ 是标准的**单位上三角矩阵**，其行列式恒等于主对角线元素乘积： $\det(\mathbf{M}) = 1 \neq 0$。
2. **对合自逆性（ $\mathbf{M}^{-1} = \mathbf{M}$，全局严格双射）**：在 $\text{GF}(2)$ 下将矩阵 $\mathbf{M}$ 连续乘两次，利用异或自消律 $\mathbf{A}\mathbf{H} \oplus \mathbf{A}\mathbf{H} = \mathbf{0}$，可得：

```math
\mathbf{M}^2 \cdot \begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} \mathbf{I} & \mathbf{A} \\ \mathbf{0} & \mathbf{I} \end{bmatrix} \begin{bmatrix} \mathbf{L} \oplus \mathbf{A}\mathbf{H} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} (\mathbf{L} \oplus \mathbf{A}\mathbf{H}) \oplus \mathbf{A}\mathbf{H} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix} \implies \mathbf{M}^2 = \mathbf{I} \implies \mathbf{M}^{-1} = \mathbf{M}
```

矩阵可逆（且自身即逆矩阵）证明映射 $\mathbf{Y} = \mathbf{M} \cdot \mathbf{PA}$ 是严格的**双射（Bijection）**：任意两个不同的输入物理地址 $\mathbf{PA}_A \neq \mathbf{PA}_B$，其输出的硬件物理坐标必然不同（ $\mathbf{Y}_A \neq \mathbf{Y}_B$），64GB（ $2^{36}$ 字节）空间与底层电容阵列 100% 一一对应，绝无碰撞。
3. **原位剥离（Bit-Stripping）零容量浪费**：当请求依据 2-bit 路由结果 $\mathbf{L}' = (L_1', L_0')$ 进入选定的目标 Sub-channel 后， $\mathbf{L}'$ 的信息已物化为当前所处的物理通道编号。子通道内部直接剥离 `PA[7:6]`，仅用原样保留的 28-bit 高位 $\mathbf{H} = \text{PA}[35:8]$ 与 6-bit 块内偏移 `PA[5:0]`（合计 34 bits，寻址单子通道独占的 16GB）译码内部坐标：

* **当两地址高位相同（ $\mathbf{H}_A = \mathbf{H}_B$，但低位 $\mathbf{L}_A \neq \mathbf{L}_B$）**：两侧异或同一个常数向量 $\mathbf{A}\mathbf{H}$，必有 $\mathbf{L}_A' \neq \mathbf{L}_B'$，两请求必然进入**不同的物理 Sub-channel**，物理走线完全隔离；
* **当两地址高位不同（ $\mathbf{H}_A \neq \mathbf{H}_B$）**：即便异或后碰巧 $\mathbf{L}_A' = \mathbf{L}_B'$（落入同一 Sub-channel），由于通道内部完整保留了 $\mathbf{H}_A \neq \mathbf{H}_B$，后续必然译码出**不同的 `Slot / Rank / BG / Bank / Row / Col` 坐标**，落在完全不同的物理电容上。

### 4. 虚拟地址（VA）到物理通道的交织传递机制与代数闭环

将物理地址构成式 $\text{PA} = \\{\text{PA}, \text{VA}[11:0]\\}$ 代入第 3 节的 IMC 异或方程，并以 **`Bit 12`（4KB 页表映射边界）** 为界拆分为“页内免查表直通项”与“页表映射项”：

```math
\begin{aligned} \text{Ch\_Sel} &= \underbrace{\mathbf{VA_{7}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{14} \oplus \text{PA}_{15} \oplus \text{PA}_{18} \right)}_{\text{页表映射出的物理页框常数 } c_{\text{ch}}} \\ \text{SubCh\_Sel} &= \underbrace{\mathbf{VA_{6}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{13} \oplus \text{PA}_{16} \oplus \text{PA}_{17} \right)}_{\text{页表映射出的物理页框常数 } c_{\text{sub}}} \\ \text{BG}_{i} &= \underbrace{\mathbf{VA_{8+i}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{13+i} \oplus \text{PA}_{16+i} \right)}_{\text{页表映射出的物理页框常数 } c_{\text{bg}, i}} \quad (i \in \{0, 1, 2\}) \end{aligned}
```

将上述 5 个选择器输出合并为 5-bit 硬件并发单元坐标向量 $\mathbf{S} = [\text{Ch\\_Sel}, \text{SubCh\\_Sel}, \text{BG}_2, \text{BG}_1, \text{BG}_0]^T \in \text{GF}(2)^5$，即得到虚拟地址（VA）到物理并发单元的直接代数传递方程：

$$\mathbf{S}(\text{VA}) = \underbrace{\text{VA}[10:6]}_{\text{软件直控的虚拟页内坐标}} \oplus \underbrace{\mathbf{c}\big(\text{PageTable}(\text{VA})\big)}_{\text{页表映射决定的 5-bit 相位向量 } \mathbf{c}}$$

该传递方程证明：**物理地址层面的通道与存储体组交织特性，通过 $\text{GF}(2)^5$ 向量加法被完整传递至虚拟地址空间。**

#### 1. 页内访问（ $\Delta \lt 4\text{KB}$）： $\text{GF}(2)^5$ 仿射平移置换与 32 路确定性均摊

当程序在任意单个 $4\text{KB}$ 虚拟页内部访问时，虚拟页号 `VA[47:12]` 恒定不变，由 TLB 或第 4 级页表输出的物理页框基址 `PA[35:12]` 为固定常数，右侧相位向量 $\mathbf{c} \in \text{GF}(2)^5$ 随之锁死为常向量：

* **仿射平移不改变分布均匀性**：在有限域向量空间 $\text{GF}(2)^5$ 中，常向量加法 $\mathbf{S}(\mathbf{x}) = \mathbf{x} \oplus \mathbf{c}$ 是一次严格的**仿射平移置换（Affine Coset Permutation）**。页表映射（无论分配到哪个物理页框）仅改变了该 4KB 页面在硬件通道上的**起始轮询相位 $\mathbf{c}$**，而完全保持页内各 Cache Line 之间的互斥交织拓扑。
* **软件直控的 32 路并发平铺**：虚拟地址 `VA` 在页内每递增 $64\text{B}$，直通位 `VA[7:6]` 翻转一次，经过 $\text{VA}[7:6] \oplus [c_{\text{ch}}, c_{\text{sub}}]^T$ 洗牌后，必然**无碰撞地依次轮询全部 4 个 Sub-channel**；每递增 $256\text{B}$，直通位 `VA[10:8]` 翻转一次，必然**依次轮询全部 8 个 Bank Group**。任何 $4\text{KB}$ 虚拟页内的 64 个 Cache Line，在物理上恒定以每个单元 2 个 Cache Line 的配额，绝对均匀地平铺在全平台 $4\text{ SubCh} \times 8\text{ BG} = 32$ 个并发硬件单元上。

#### 2. 跨页访问（ $\Delta \ge 4\text{KB}$）：大页直通锁定与物理页框熵散列

当程序以 $\Delta = 4\text{KB}, 8\text{KB}, 32\text{KB}$ 等跨页步长访问时，页内偏移 `VA[10:6]` 恒定为常数 $\mathbf{v}_0$，此时 $\mathbf{S}(\text{VA}) = \mathbf{v}_0 \oplus \mathbf{c}(\text{PA})$，交织效果由跨页时不断切换的相位向量 $\mathbf{c}$ 驱动：

1. **2MB 大页（HugePage）下的确定性代数交织**：
开启 2MB 大页（ $2^{21}\text{B}$）后，页表映射在第 3 级（`PD` 表）终止，**免查表直通位从 `VA[11:0]` 直接扩展至 `VA[20:0]`（即 $\text{PA}[20:0] \equiv \text{VA}[20:0]$）**。此时相位向量 $\mathbf{c}$ 所依赖的 `PA[18:13]` 全部转化为免查表直通的虚拟地址位 `VA[18:13]`，传递方程直接退化为纯虚拟地址异或：

$$\mathbf{S}(\text{VA}) = \text{VA}[10:6] \oplus \mathbf{c}(\text{VA})$$

在 $2\text{MB}$ 虚拟地址跨度内，任意 $2^N$ 跨页步长均由硬件异或门 100% 确定性地按 $1:1:1:1$ 分流至 4 个 Sub-channel。

2. **标准 4KB 页下的物理页框散列交织**：
在标准 4KB 分页下，若 OS 伙伴分配器（Buddy Allocator）分配了连续物理页框，则 `PA[18:13]` 随虚拟页号同步线性递增，同样触发确定性异或分流；若物理内存碎片化导致分配了离散物理页框，不同物理页框号（PFN）在 `PA[18:13]` 位段上携带的比特熵经异或树折叠后，使得跨页虚拟地址流在统计上仍以 $1/4$ 的等概率均匀收敛至 4 路 Sub-channel 队列中。

## 三、 内存墙：400 MHz 阵列极限、PISO 预取与多核闭环排队论

现代多核架构中，处理器算力与主存数据供给之间的失衡体现为三个物理边界：延迟受限于电容充放电 RC 常数与跨时钟域同步开销，长期停留在 $\sim 80\text{ ns}$ 量级；带宽受限于封装与主板布线的引脚密度上限，通道扩展速度远低于核心数量增长；容量受限于单通道高速信号完整性对挂载双列直插式内存模块（DIMM, Dual In-line Memory Module）数量的物理限制。

通过将空载基准延迟、动态随机存取存储器（DRAM, Dynamic Random-Access Memory）内部 $400\text{ MHz}$ 阵列并入串出（PISO, Parallel-In Serial-Out）预取守恒、上游行填充缓冲（LFB, Line Fill Buffer）信用窗口约束以及下游 $C \times \text{M/G/1}$ 排队方程联立，可以从数学上严格推演带宽与延迟在空载稳态下的正交性，以及多核高并发负载下的闭环耦合规律。

### 1. 引脚密度边界、空载延迟构成与带宽-延迟静态正交性

#### 1.1 物理互连的引脚密度边界与系统峰值带宽

穿透 L1/L2/L3 缓存的末级缓存未命中请求（LLC Miss, Last Level Cache Miss）必须跨越 CPU 封装边界访问主存。物理链路的峰值带宽由并行数据线位宽 $W_{\text{bits}}$ 与单线传输率 $f_{\text{transfer}}$ 的乘积决定（ $B_{\text{peak}} = W_{\text{bits}} \times f_{\text{transfer}} / 8$）。受限于不同物理层级的引脚密度与信号完整性，系统互连带宽自上而下逐级收敛：

* **片上网络（NoC, Network on Chip）**：单跳带宽达 $\text{TB/s}$ 级；
* **嵌入式多芯片互连桥接（EMIB, Embedded Multi-die Interconnect Bridge）/ 晶圆基底芯片封装（CoWoS, Chip-on-Wafer-on-Substrate）**：带宽为数百 $\text{GB/s}$ 级；
* **超路径互连（UPI, Ultra Path Interconnect）/ 全局内存互连（xGMI, external Global Memory Interconnect）**：单链路带宽为数十 $\text{GB/s}$ 级；
* **主存物理通道（DRAM Channel）**：受限于印制电路板（PCB, Printed Circuit Board）布线密度、过孔串扰与 DIMM 金手指引脚数，单根 DDR4/DDR5 内存条的数据总线总位宽固定为 $64\text{-bit}$（DDR5 拆分为 $2 \times 32\text{-bit}$ 子通道）。同一物理通道若挂载多根内存条（如每通道两根内存，2 DPC, 2 DIMMs Per Channel），容性负载增加与阻抗不连续会迫使 I/O 时钟 $f_{\text{clk}}$ 降频（如从 $3200\text{ MHz}$ 降至 $2400\text{ MHz}$），使单通道峰值带宽下降约 $25\\%$。

由于 CPU 访存的最小粒度为 64B 缓存行，单个 64B 请求经硬件地址译码后仅路由至唯一的目标通道（或子通道）处理，不会拆分至多条通道并行传输。设单个独立通道/子通道服务台的位宽为 $W_{\text{sub}}$，全系统包含 $C$ 个物理隔离的独立服务台，则系统总峰值带宽为单服务台峰值带宽 $B_{\text{peak, sub}}$ 的 $C$ 倍：

$$B_{\text{peak}} = C \times B_{\text{peak, sub}} = C \times \frac{W_{\text{sub}} \times f_{\text{transfer}}}{8}$$

#### 1.2 空载延迟 $T_0$ 的物理构成与静态正交推论

单次 64B 访存事务从核心发出到数据就绪的端到端总延迟 $T_{\text{total}}$，由空载基准延迟 $T_0$ 与集成内存控制器（IMC, Integrated Memory Controller）队列中的纯等待延迟 $T_{\text{queue}}$ 串联构成（请求在数据总线与控制器队列中的总耗时即为 $T_{\text{trans}} + T_{\text{queue}}$）：

$$T_{\text{total}} = \underbrace{T_{\text{on-chip}} + T_{\text{array\\_rc}} + T_{\text{trans}}}_{\text{端到端空载基准延迟 } T_0 \ (\approx 80\text{ ns})} + T_{\text{queue}}$$

空载延迟 $T_0$ 横跨核心、片上互连、内存控制器、物理层总线与 DRAM 核心阵列五个异步时钟域，其物理耗时由三大模块串联构成：

```math
\begin{cases} \text{片上路由与跨时钟域交叉（CDC, Clock Domain Crossing）同步耗时 } T_{\text{on-chip}} \approx 30 \sim 35\text{ ns} & (\text{占比 } \sim 41\%) \\ \text{DRAM 1T1C 电容阵列模拟寻址（} t_{\text{RCD}} + t_{\text{CL}} + t_{\text{RP}} \text{）耗时 } T_{\text{array\_rc}} \approx 40 \sim 45\text{ ns} & (\text{占比 } \sim 56\%) \\ \text{64B 数据总线纯突发传输耗时 } T_{\text{trans}} = \mathbf{2.5\text{ ns}} & (\text{占比 } \mathbf{3.1\%}) \end{cases}
```

**静态正交推论**：在空载稳态（ $T_{\text{queue}} = 0$）下，并行服务台数量 $C$ 不进入单笔请求的时间求和式，且占 $T_0$ 超过 $96\\%$ 的模拟寻址与片上同步耗时不受外部数据总线频率影响（I/O 频率翻倍对 $T_{\text{trans}}$ 的削减不足 $2\text{ ns}$，且被高频控制器 Gear 2/4 分频与片内纠错码 On-Die ECC, Error Correcting Code 校验延迟抵消），因此**系统峰值带宽 $B_{\text{peak}}$ 与空载延迟 $T_0$ 在数学上完全解耦（静态正交）**。

### 2. $400\text{ MHz}$ 阵列极限、PISO 预取守恒与服务台裂变必然性

受限于 1T1C 微型电容电荷泄放速率与灵敏放大器（Sense Amplifier）检测的 RC 物理极限，DRAM 内部存储阵列（Core Array）的放电工作频率自 DDR4 起便难以逾越，锁死在 $`f_{\text{array}} = 400\text{ MHz}`$ （阵列最小列访问周期恒为 $`T_{\text{array}} = t_{\text{CCD\_S}} = 2.5\text{ ns}`$）。相比之下，外部数据引脚（DQ）的电路传输频率 $`f_{\text{transfer}} = 2f_{\text{clk}}`$ 仍可随工艺演进持续翻倍。

为了弥合“内部阵列放电慢、外部引脚传输快”的频率鸿沟，DRAM 必须扩大 PISO（并入串出）预取缓冲器的位宽 $N$，将内部阵列每 $2.5\text{ ns}$ 一次性并行读取的 $N\text{ bit}$ 数据，转化为外部高频引脚下连续突发长度（ $\text{BL} = N$ ）的高速串行流。同时，受 CPU 缓存架构约束，单个独立调度队列（单服务台）的数据位宽 $W_{\text{sub}}$ 在一次突发（ $\text{BL} = N$ ）中传输的数据量必须严格匹配 64B（ $512\text{ bit}$ ）缓存行粒度。

将**阵列物理极限**、**PISO 时间守恒**与 **64B 粒度空间守恒**联立：

```math
\begin{cases} \text{阵列物理极限：} & f_{\text{array}} = 400\text{ MHz} \implies T_{\text{array}} = t_{\text{CCD\_S}} = \mathbf{2.5\text{ ns}} \\ \text{PISO 时间守恒：} & f_{\text{transfer}} = 2f_{\text{clk}} = \dfrac{N}{T_{\text{array}}} \implies \mathbf{T_{\text{trans}} = \frac{\text{BL}}{f_{\text{transfer}}} \equiv T_{\text{array}} = 2.5\text{ ns}} \quad (\text{BL} = N) \\ \text{64B 粒度守恒：} & \dfrac{W_{\text{sub}} \times \text{BL}}{8} = 64\text{ B} \implies \mathbf{W_{\text{sub}} = \frac{512\text{ bit}}{N}} \end{cases}
```

将上述 $W_{\text{sub}}$ 与 $f_{\text{transfer}}$ 代入第 1.1 节的单队列物理峰值带宽公式 $B_{\text{peak, sub}} = \frac{W_{\text{sub}} \times f_{\text{transfer}}}{8}$，预取深度 $N$ 在分子与分母中发生**严格代数约分**：

$$\boxed{B_{\text{peak, sub}} = \frac{W_{\text{sub}} \times f_{\text{transfer}}}{8} = \frac{1}{8} \cdot \underbrace{\left(\frac{512\text{ bit}}{N}\right)}_{W_{\text{sub}}} \cdot \underbrace{\left(\frac{N}{T_{\text{array}}}\right)}_{f_{\text{transfer}}} = \frac{64\text{ B}}{T_{\text{trans}}} = \frac{64\text{ B}}{2.5\text{ ns}} \equiv \mathbf{25.6\text{ GB/s}}}$$

这一约分过程深刻揭示了 DDR4 向 DDR5 演进的**底层数学必然性与服务台裂变机制**：

1. **单服务台效率的绝对锁死**：由于 $N$ 在公式中被严格约去，只要内部电容放电周期 $T_{\text{array}} = 2.5\text{ ns}$ 无法突破，无论外部引脚频率 $f_{\text{transfer}}$ 如何拉升，**单个服务台的纯突发传输周期（ $T_{\text{trans}} \equiv 2.5\text{ ns}$ ）、最大服务率（ $\mu_{\text{sub}} = 1/T_{\text{trans}} \equiv 0.4\text{ 请求/ns}$ ）以及峰值吞吐量子（ $B_{\text{peak, sub}} \equiv 25.6\text{ GB/s}$ ）均被物理定律绝对锁死**。单服务台根本无法消纳外部引脚提速带来的带宽红利。
2. **引脚提速向服务台数量（ $C$ ）的唯一收敛**：当外部数据线速率从 DDR4-3200 翻倍至 DDR5-6400 时，为填满恒定 $T_{\text{array}}$ 下翻倍的外部时钟沿，预取与突发长度必须从 $N = \text{BL} = 8$ 翻倍至 $16$；受 64B 粒度约束（ $W_{\text{sub}} = 512\text{ bit} / N$ ），单服务台位宽被迫从 $64\text{ bit}$ 折半为 $32\text{ bit}$。在单根 DIMM 物理总位宽恒定（ $W_{\text{total}} = 64\text{ bit}$ ）的前提下，位宽减半直接引发**服务台裂变**——独立队列数从 $C = W_{\text{total}} / W_{\text{sub}} = 1$（M/G/1）必然扩张为 $C = 2$ 个 32-bit 子通道（2×M/G/1 并发）。**简言之，DRAM 外部引脚速率的提升，在数学上被唯一地转化为独立服务台数量 $C$ 的成倍增加（总峰值带宽 $B_{\text{total}} = C \times 25.6\text{ GB/s}$ ）。**

### 3. 动态耦合（一）：上游 LFB 窗口约束与管道自然容量 $K_0$

每个穿透 L1 Cache 发往主存的 64B 读未命中事务，必须在核心的 LFB（单核最大深度 $N_{\max} = 16$）中占用 1 个信用槽位，直至经历端到端延迟 $T_{\text{total}}$ 数据返回后才释放。

考察单个通道/子通道服务台（峰值吞吐量子 $B_{\text{peak, sub}} = 64\text{ B} / T_{\text{trans}}$）。设该服务台分摊 $M$ 个核心，链路上的全局并发在途请求总数为 $K = M \cdot N_{\text{in-flight}}$（满窗口下 $K = M \cdot N_{\max} = 16M$）。由利特尔法则（Little's Law， $B_{\text{achieved}} = K \times 64\text{ B} / T_{\text{total}}$）除以单服务台峰值吞吐量子 $B_{\text{peak, sub}}$，完成无量纲归一化，直接导出受上游信用窗口制约的**上游窗口方程**：

$$\rho = \frac{B_{\text{achieved}}}{B_{\text{peak, sub}}} = \frac{K \cdot 64\text{ B} / T_{\text{total}}}{64\text{ B} / T_{\text{trans}}} \implies \boxed{\text{上游窗口方程：} \ T_{\text{total}} = \frac{K \cdot T_{\text{trans}}}{\rho} \quad \left(\text{即 } \rho = \frac{K \cdot T_{\text{trans}}}{T_{\text{total}}}\right)}$$

代入空载延迟 $T_{\text{total}} = T_0 = 80\text{ ns}$，自然定义无量纲的**单通道带宽延迟积（物理管道自然容量 $K_0$）**：

$$\boxed{K_0 \triangleq \frac{T_0}{T_{\text{trans}}} = \frac{B_{\text{peak, sub}} \times T_0}{64\text{ B}} = \frac{80\text{ ns}}{2.5\text{ ns}} = \mathbf{32\text{ 个在途请求}}}$$

在空载无排队极限（ $T_{\text{total}} \approx T_0$）下，总线利用率简化为 $\rho \approx K / K_0$，由此直接锁定单核访存的两条硬件边界：

* **串行指针追逐（ $K = 1$，如链表遍历 `p = p->next`）**： $\rho = 1 / 32 = 3.125\\%$，单核提取带宽仅为 $B_{\text{core}} = 25.6\text{ GB/s} \times 3.125\\% = \mathbf{0.80\text{ GB/s}}$；
* **单核满窗口并发（ $K = N_{\max} = 16$）**： $\rho = 16 / 32 = 50\\%$，单核提取带宽上限为 $B_{\text{core}} = 25.6\text{ GB/s} \times 50\\% = \mathbf{12.80\text{ GB/s}}$。

由于单核最大窗口深度小于物理管道自然容量（ $N_{\max} = 16 < K_0 = 32$），**单个核心最多只能喂饱半条内存子通道**；必须依赖多核并发（ $M \ge 2 \implies K \ge K_0$）才能使通道趋近饱和，而多核汇聚将不可避免地触发下游控制器排队。

### 4. 动态耦合（二）：下游 $C \times \text{M/G/1}$ 排队方程与 DDR5 靶向优化

当多核并发流量涌入包含 $C$ 个通道/子通道的内存子系统时，由 Pollaczek–Khinchine（P-K）公式与利特尔法则，第 $i \in \\{1, \dots, C\\}$ 个独立队列服务台（总线利用率 $\rho_i = B_{\text{demand, sub}}^{(i)} / B_{\text{peak, sub}}$）的纯排队等待时间 $T_{\text{queue}}^{(i)}$ 与端到端总延迟 $T_{\text{total}}^{(i)}$ 由**下游排队方程**刻画：

$$\boxed{\text{下游排队方程：} \ T_{\text{total}}^{(i)} = T_0 + \underbrace{\alpha \cdot T_{\text{trans}} \cdot \frac{\rho_i}{1 - \rho_i}}_{T_{\text{queue}}^{(i)}} \quad \left(0 \le \rho_i < 1, \ \alpha \in [0.5, 1.0]\right)}$$

式中的 $T_{\text{trans}} \equiv 2.5\text{ ns}$ 为硬件固定的纯数据突发周期，而系统拓扑特征与控制器调度效率则完全收敛于 **$\rho_i$（单队列利用率）** 与 **$\alpha$（排队波动系数）** 两个无量纲参数中：

1. **队列隔离拓扑与负载分流参数 $\rho_i$（对应 DDR5 子通道拆分与散列偏斜）**：
物理地址归属的通道由硬件译码静态固定，空闲子通道无法跨物理通路读取其他子通道颗粒电容中的数据，故系统严格为 **$C$ 个相互隔离的独立 $\text{M/G/1}$ 队列**。
   * **DDR5 倍增服务台数 $C$**：单根 DDR4 仅有 $C=1$ 个 64-bit 队列，队头发生未掩蔽行冲突时整条总线停顿；单根 DDR5 拆分为 $C=2$ 个独立的 32-bit 子通道队列，消除了跨子通道线头阻塞（HOL Blocking, Head-of-Line Blocking）。
   * **均匀散列与碰撞偏斜**：当硬件多比特异或散列（XOR Hashing）将流量均匀分发至 $C$ 个队列时，通道数 $C$ 分子分母约分，单队列利用率等同于全局利用率 $\rho_i \equiv B_{\text{demand}} / B_{\text{peak}}$；若访存步长（如 $2^N$）击穿散列掩码导致负载偏斜，则不可全局约分，热点队列在 $\rho_1 \to 1$ 时将按 $\frac{\rho_1}{1-\rho_1}$ 独立发散并阻塞全局计算。

2. **排队波动系数 $\alpha$（M/G/1 的 P-K 系数；对应 M/D/1 至 M/M/1 包络、DDR5 32 Banks 与同 Bank 刷新）**：
由 P-K 公式， $\alpha = \frac{C_a^2 + C_s^2}{2}$。本模型取 M（泊松到达， $C_a^2 = 1$），故 $\alpha = \frac{1 + C_s^2}{2}$：其中 $0.5$ 是到达侧常量， $C_s^2/2$ 才是处理侧（控制器实际发车间隔相对固定突发周期 $T_{\text{trans}} = 2.5\text{ ns}$ 的波动）。无冲突连续突发对应 **M/D/1（泊松到达 + 确定性服务， $C_s^2 = 0 \implies \alpha = 0.5$，排队系数 $1.25\text{ ns}$）**——此 $0.5$ 并非零抖动，而是服务完全确定后仍残留的泊松到达排队；频繁行冲突、读写切换气泡与刷新锁死对应 **M/M/1 悲观包络上界（ $C_s^2 = 1 \implies \alpha = 1.0$，排队系数 $2.50\text{ ns}$）**。DDR5 通过两项微架构革新将 $\alpha$ 从 $1.0$ 压向 $0.5$：
   * **独立 CA 总线 + $8\ t_{\text{CK}}$（BL16）窗口 + 32 Banks 掩蔽行冲突**：利用翻倍的数据突发周期与翻倍的 32 Banks（8 Bank Groups）在后台并行穿插预充电/激活指令，消除行冲突引起的发车间隔抖动；
   * **同 Bank 刷新（Same-Bank Refresh）消除长尾停顿**：替代 DDR4 锁死整根内存条的全 Bank 刷新（All-Bank Refresh），每次仅刷新每个 Bank Group 中的 1 个指定 Bank，其余 $3/4$ 的 Bank 正常响应读写，消除周期性长尾停顿，使排队延迟回归 $\alpha = 0.5$ 的 $\text{M/D/1}$ 确定性服务基准。

### 5. 动态耦合（三）：多核闭环不动点解析解与过饱和线性发散

在真实硬件中，下游排队延迟 $T_{\text{queue}}$ 升高会拉长 $T_{\text{total}}$，进而通过上游窗口方程反过来压低 LFB 槽位周转率，抑制核心发射新请求的速率。联立第 3 节**上游窗口方程**与第 4 节**下游排队方程**消去 $T_{\text{total}}$，并两边同除以 $T_{\text{trans}}$（代入 $K_0 = T_0 / T_{\text{trans}}$）：

$$\frac{K \cdot T_{\text{trans}}}{\rho} = T_0 + \alpha \cdot T_{\text{trans}} \cdot \frac{\rho}{1 - \rho} \implies (K_0 - \alpha)\rho^2 - (K + K_0)\rho + K = 0$$

舍去大于 $1$ 的非物理根，得到任意全局在途并发度 $K = M \cdot N_{\max}$ 下的闭环不动点（Fixed-Point）解析解：

```math
\boxed{\rho^\ast(K) = \frac{(K + K_0) - \sqrt{(K + K_0)^2 - 4(K_0 - \alpha)K}}{2(K_0 - \alpha)}}, \qquad \begin{cases} B_{\text{achieved}}^\ast = \rho^\ast \cdot B_{\text{peak, sub}} \\ T_{\text{total}}^\ast = \dfrac{K \cdot T_{\text{trans}}}{\rho^\ast} \\ T_{\text{queue}}^\ast = T_{\text{total}}^\ast - T_0 \end{cases}
```

代入硬件基准常数 $T_0 = 80\text{ ns}$、 $T_{\text{trans}} = 2.5\text{ ns}$、 $B_{\text{peak, sub}} = 25.6\text{ GB/s}$、 $K_0 = 32$、 $N_{\max} = 16$（取 $\text{M/D/1}$ 基准 $\alpha = 0.5$），单服务台分摊不同并发核心数 $M$ 时的闭环平衡点演进如下：

| 并发核心数 $M$（单服务台分摊） | 全局在途窗口 $K = 16M$ | 闭环稳态利用率 $\rho^\ast$ | 闭环实际带宽 $B_{\text{achieved}}^\ast$ | 闭环稳态总延迟 $T_{\text{total}}^\ast$ | 纯排队等待 $T_{\text{queue}}^\ast$ |
| --- | --- | --- | --- | --- | --- |
| **$M = 1$ 核**（欠饱和窗口受限 $K < K_0$） | $16$ | $49.26\\%$ | $12.61\text{ GB/s}$ | $81.21\text{ ns}$ | $1.21\text{ ns}$ |
| **$M = 2$ 核**（临界负反馈拐点 $K = K_0$） | $32$ | $88.91\\%$ | $22.76\text{ GB/s}$ | $89.98\text{ ns}$ | $9.98\text{ ns}$ |
| **$M = 4$ 核**（过饱和积压初期 $K = 2K_0$） | $64$ | $98.48\\%$ | $25.21\text{ GB/s}$ | $162.47\text{ ns}$ | $82.47\text{ ns}$ |
| **$M = 8$ 核**（深度过饱和线性区 $K = 4K_0$） | $128$ | $99.48\\%$ | $25.47\text{ GB/s}$ | $321.67\text{ ns}$ | $241.67\text{ ns}$ |

上表清晰地刻画出多核闭环排队系统的三阶段物理相变：当 $K < K_0$（ $M=1$）时，队列基本无积压，吞吐受限于上游 LFB 窗口（ $\rho^\ast \approx K / K_0$）；当到达临界点 $K = K_0 = 32$（ $M=2$）时， $9.98\text{ ns}$ 的排队延迟通过拉长往返周期触发闭环负反馈节流，将稳态利用率钳制在 $\rho^\ast = 88.91\\%$，避免了开环模型的无限发散；而当进入深度过饱和区 $K \gg K_0$（ $M \ge 4$）时， $\rho^\ast \to 1$（实际带宽锁死于上限 $25.6\text{ GB/s}$），此时物理飞行管道（ $T_0$）最多容纳 $K_0 = 32$ 个请求，**超出管道容量的在途信用点全部转化为控制器内的静态排队积压 $N_q^\ast \approx K - K_0$**，使上游窗口方程直接退化为并发核数 $M$ 的渐近线性函数：

$$\boxed{T_{\text{total}}^\ast(K \gg K_0) \approx K \cdot T_{\text{trans}} = M \cdot N_{\max} \cdot T_{\text{trans}} = \mathbf{40M\text{ (ns)}} \implies T_{\text{queue}}^\ast(K \gg K_0) \approx (K - K_0) \cdot T_{\text{trans}}}$$

在过饱和区内，每向单通道追加 $1$ 个满窗口流式核心，不仅无法带来任何有效带宽收益，反而会使端到端延迟刚性激增 $16 \times 2.5\text{ ns} = 40\text{ ns}$。这正是现代服务器处理器引入硬件服务质量（QoS, Quality of Service，如英特尔内存带宽分配 MBA, Memory Bandwidth Allocation），通过限制嘈杂邻居核的并发在途信用点 $K$ 使其回落至物理管道自然容量以内（ $K \le K_0$），从而在不损失主体带宽的前提下斩断线性排队尾延迟的底层数学依据。

## 四、 缓存的空间拓扑：L3 共享域、物理封装与 NUMA

### 1. L3 共享域与物理封装形态

* **L3 共享域（L3 Allocation Domain，简称共享域）**：在多级缓存体系中，L1 与 L2 采用每核私有设计以换取最低访问延迟，L3 则是核心群的数据汇聚中枢。共享域界定了哪些计算核心对当前 L3 拥有**分配**（*Allocation*，划定并占用缓存行空间）、**脏数据回写接纳**（*Dirty Line Writeback*，接收并保存上级私有缓存下刷的被修改行）与**逐出**（*Eviction*，根据替换策略移出旧缓存行）的排他性权限。域外核心无权在别域的 L3 中分配新的**缓存行**（*Cache Line*，64 字节标准数据搬运单元）或逐出旧行；域外核心若需使用该域中的数据，只能通过**全局一致性探针**（*Probe/Snoop*，跨核心索取缓存行副本的请求）拉取至自身私有 L1/L2 暂存。**缓存一致性**是全系统刚性维持的协议契约，而**共享域**是物理容量分配上的排他性边界，二者在架构上互不绑定。按具体微架构设计，共享域的物理划界分为两类：

  * **全核共享（Intel 切片与归宿代理体系）**：封装内全部计算核心共享同一池域内 L3。物理上，域内 L3 均匀切分为若干**切片**（*Slice*——硅片内部的散列结构单元，常按一核一切片配置，故 6、12、18 等非 2 的幂次均会出现；勿与封装级硅片 Die 混淆），每个切片与对应的缓存及归宿代理（CHA）捆绑并挂接在环形总线（Ring Bus）或二维网格（2D Mesh）节点上。缓存行落入哪一个切片由系统物理地址（SPA）经硬件异或散列（XOR Hash）唯一决定，核心无法挑选。
  * **分组共享（AMD CCX 体系）**：核心以固定群组为单位共享域内 L3，该群组称为**核心复合体（Core Complex，CCX）**。桌面与服务器端 Zen 1 / Zen 2 每域含 4 核，自 Zen 3 起演进为每域 8 核，L3 分配权限严格绑定于发起请求的核心所属的 CCX。

* **物理封装分类与两轴正交映射**：整颗处理器为单一裸片的称**单片封装（Monolithic Die）**，拆分为多块小芯片再互联组装的称**多片封装（Chiplet / Tile-based）**。封装内的硅片（AMD 称 Die，Intel 客户端称 Tile、服务器端称 Die）按**是否承载域内 L3** 分为两类：承载 L3 的计算硅片参与容量记账（AMD 专称 **CCD**，Intel 称 **Compute Tile / Compute Die**）；不承载 L3 的辅助硅片（AMD 的 IOD，Intel 的 Graphics / SoC / IO / Base Tile）不参与记账。注意“承载计算核心”不等于“承载 L3”——例如 Meteor Lake 的 SoC Tile 带有 2 个低功耗 E 核（LP-E），但该硅片无 L3，这 2 个核心完全落在共享域外。
多片封装将逻辑记账维度（按共享域）**与**物理记账维度（按承载 L3 的硅片）彻底解耦：一块硅片内可切出两个域（Zen 1），三块硅片也可跨硅桥拼成一个统一大域（Granite Rapids）。在对称设计下，两套账本满足守恒关系式：

$$\text{L3 总量} = \text{共享域数} \times \text{域内 L3 容量} = \text{承载 L3 的硅片数} \times \text{每硅片 L3 容量}$$

当整颗芯片仅有一个共享域时，域内 L3 容量与 L3 总量直接相等。

### 2. UMA 与 NUMA：架构实质与两条判定门槛

**均匀访存（Uniform Memory Access，UMA）**下所有核心共享前端总线与单一内存控制器，访存代价对等，但受限于并行总线的电气负载与引脚位宽，总带宽存在物理上限。现代处理器将**集成内存控制器（IMC）**收入 CPU 封装内部，插槽间改走高频点对点串行链路（Intel UPI / AMD xGMI），使内存带宽与容量随插槽数线性扩展。由此，核心访问本封装 IMC 挂载的本地内存路径极短，访问远端插槽内存则必须穿越慢速串行链路。这种**不同核心访问同一物理地址存在系统性延迟与带宽差异**的体系结构即**非均匀访存（Non-Uniform Memory Access，NUMA）**。

现代多片封装与大型片上网格将物理距离差引入了单颗封装内部。但硬件存在物理距离差并不直接等价于架构级 NUMA，构成 NUMA 必须同时满足两条刚性判据：

1. **量级显著**：核心群之间的访存延迟差价 $\Delta$ 通常需达到 **20 ns** 以上（跨插槽可达 **50\~70 ns**），或跨界带宽存在显著瓶颈，足以让操作系统的拓扑亲和调度（Affinity Scheduling）获得净收益；片内纳秒级的走线跳数差（**3\~6 ns**）在统计上直接被乱序执行掩盖。
2. **地址空间可定域**：延迟差价必须与宏观、连续的物理地址（PA）区间强绑定，而非在 **64 B** 缓存行粒度上被硬件散列打散：
   * **全片散列摊平差价（回归 UMA）**：硬件异或散列以 64 B 为粒度将连续物理地址均匀打散至全片 $N$ 个 L3 切片（CHA）与所有内存通道（IMC）。设某核心到各站点的物理延迟为 $L_1, L_2, \dots, L_N$，其访存统计期望延迟恒为 $\mathbb{E}[\text{Latency}] = \frac{1}{N} \sum_{k=1}^{N} L_k$。在大数定律下，任意核心命中近端与远端站点的比例完全相同，期望延迟与可用带宽均等，OS 无法按页帧做亲和调度，体系结构严格收敛为 UMA。
   * **宏观定域确立 NUMA**：唯有通过顶层系统地址译码器（System Address Decoder，SAD）将物理地址按宏观大段划界（如以 **64 MiB** 为刻度切分出数十 GiB 区间），强制令该段内的缓存行 100% 锁定在本地切片与本地 IMC 上，近端与远端核心群访问同一地址的系统性差价才正式确立，OS 也才获得按物理页帧（PFN）执行就近分配的抓手。

| --- | --- | --- | --- | --- | --- |

### 3. 物理寻址的四级硬件流水与空间编织（UMA vs. SNC3）

物理上只存在插在各槽位上、内部从 `0x0` 独立编址的离散内存条（DIMM）。**通道交织（SAD/TAD）**的本质是**“空间构建”**，通过跨通道穿插将离散内存条的**通道物理地址（CPA）**拼接为连续的**系统物理地址（SPA）**；**切片散列（CHA）**的本质是**“流量负载均衡”**，在连续 SPA 上通过异或树打散片上缓存与目录查找压力。

#### 3.1 四级硬件译码流水线

当核心私有 L1/L2 未命中、发出携带 52 位物理地址 `SPA[51:0]`（常见实现为 46 位 `PA[45:0]`）的请求时，硬件按 **SAD $\rightarrow$ CHA $\rightarrow$ TAD $\rightarrow$ IMC** 四级流水逐层译码：

1. **第一级 SAD（系统地址译码器）**：抽头监测 `PA[51:26]`（64 MiB 对齐刻度），比对级联 Limit 寄存器（及多 Die 下的 `Mod-3` 算子），裁决目标插槽（Socket）与目标计算硅片（Compute Die）。SAD 仅读取高位做路由，**完整物理地址继续向下游传递，绝不截断**。
2. **第二级 CHA（缓存与归宿代理）**：在目标硅片内通过多抽头异或树将 `PA[51:6]` 折叠为归宿切片（Home CHA）坐标，查询本地 L3 Tag 与分布式目录（Directory）。命中则直接供数；未命中（Miss）则放行进入本硅片 TAD。
3. **第三级 TAD（目标地址译码器）**：执行空间逆向解构——用多抽头异或选定本硅片内的物理通道号（Target IMC Channel），从 `SPA` 中扣除段基址（及跨 Die 除 3 紧缩），**抽除（Strip）通道交织位**后右移紧缩，拼回行内偏移 `PA[5:0]`，还原出连续的通道物理地址 **CPA**。
4. **第四级 IMC（RIR 与 AMAP 译码）**：依据 SPD 参数，将完整 `CPA` 切分为 Rank 片选（CS#）、Bank Group、Bank、Row 与 Column，完成 DRAM 阵列寻址。

> **注**：`PA[51:26]` 对应的 **64 MiB**（ $2^{26}\text{ B}$）是 SAD 范围寄存器的**硬件对齐刻度**（Resolution）而非交织粒度。任何宏观地址段的起止边界均须对齐 64 MiB 的整数倍，使硬件仅用 26-bit 比较器即可完成上百 GiB 地址段的单周期判定。

以下以 **Granite Rapids（3 块 Compute Die，每 Die 含 168 MB L3 与 4 条通道，共 12 通道）** 为例，对比两种空间编织法则：

#### 3.2 方案 A：全局 12 通道交织（UMA 模式 / “3×4 二维拉链式”拼接与 $2^N$ 步长免疫）

由于 $12 = 3 \times 4$ 不是 2 的幂次，硬件采用 **“跨 3 Die 的 Mod-3 / Div-3 算子 + Die 内 4 通道多抽头异或”** 的正交双维法则，将 12 根内存条的 CPA 编织为单一全局 SPA，满足 $\frac{d(\text{SPA})}{d(\text{CPA})} = 12$：

1. **第一维（跨 3 Die 的 Mod-3 同源定域与 Div-3 紧缩）**：
   每个 Die 的 4 条通道横向拼成 **256 B** 的 Die 级条带，高位定义为**全局条带流水号 $\text{GSI} = \text{PA}[51:8]$**。硬件定点数电路对 `GSI` 同步执行：
   * **Mod-3 选 Die（CHA 与 IMC 同 Die 绑定 + 免疫 $2^N$ 步长）**：计算 $`\text{Target\_Die} = (\text{GSI} \oplus \text{Hash\_Die}) \bmod 3`$。该结果**同时锁定归宿 L3 切片所在 Die（Home CHA）与目标内存控制器所在 Die（Target IMC）**，确保 L3 未命中后直接在同 Die 内就近访存，消除跨 EMIB 硅桥的折返开销。同时因 $\gcd(2^N, 3) = 1$，任何 $2^N$（ $N \ge 8$）跨步循环在 `Mod-3` 下天然以周期 3 遍历全部 3 个 Die，不会锁死在单 Die 上。
   * **Div-3 紧缩空洞**：计算**本地条带索引 $\text{LSI} = \lfloor \text{GSI} / 3 \rfloor$**。全局连续的 3 个条带（如 $\text{GSI} = 0, 1, 2$）分派至 3 个 Die 后，整除 3 的商均为 $\text{LSI} = 0$（对应各 Die 本地第 0 行条带），消除跨 Die 轮询空洞。

2. **第二维（Die 内 4 通道多抽头 XOR 与剥离还原 CPA）**：
   在目标 Die 的 TAD 内，以 `PA[7:6]` 承载 4 通道选择。为防止 $S = 2^N$ 步长令 `PA[7:6]` 恒定锁死导致 3 条通道闲置，硬件采用**多抽头异或树**：

$$\text{Local\\_Ch} = \text{PA}[7:6] \oplus \text{PA}[9:8] \oplus \text{PA}[11:10] \oplus \text{PA}[13:12] \oplus \cdots$$

选定通道后，直接**抽除（Strip）`PA[7:6]` 两位**，将 `LSI` 左移 6 位拼接行内偏移，还原出单条内存内连续的 `CPA = (LSI << 6) | PA[5:0]`。

```
[底层物理实在：3 块 Compute Die，共 12 根独立内存条 (Ch 0~11)，每条内部均从 CPA = 0x0 连续编址]

[第一步：首站 CHA / SAD 顶层 Mod-3 同源定域 (锁定归宿 Die：Home CHA 与 Target IMC 同驻一 Die)]
  │  • 提取全局条带号 GSI = PA[51:8]，计算 Target_Die = (GSI ⊕ Hash_Die) mod 3
  │    ├─ 1/3 概率命中本地 Die (零硅桥开销)
  │    └─ 2/3 概率经 EMIB 硅桥路由至相邻两个远端 Die (跨桥开销 +20~25 ns)
  ▼
[第二步：目标 Die 内 CHA 切片散列 (全封装 504 MB L3 合为单一全局共享域)]
  │  • 在 Target_Die 内部经多抽头 XOR 找到归宿 Home CHA，查询 L3 Tag 与一致性目录
  │  • 若 L3 未命中 (Miss)，无需再次跨 Die，直接下沉至本 Die 内部的本地 TAD！
  ▼
[第三步 & 第四步：目标 Die 内 TAD 4 路解构还原 CPA ──► 本地 IMC 驱动 DRAM 读写]

```

* **拓扑呈现**：任意核心访存落入本地 Die（4 通道）的概率为 $1/3$，跨 EMIB 硅桥落入远端两 Die（8 通道）的概率为 $2/3$。该模式汇聚 12 通道总带宽与 504 MB 统一 L3，抹平各核期望延迟，固件在 ACPI SRAT 中仅暴露 **1 个 Proximity Domain 0（UMA 视图）**。

### 4. 固件阶段演进：从 UEFI/MRC 到 ACPI 表构建

硬件比较器与异或树电路在流片后固定，但整机采用何种交织模式、如何分段，由主板固件在开机流程中动态决定：

**UEFI 引导（SEC / PEI） $\longrightarrow$ MRC 执行内存训练与四级寄存器编排 $\longrightarrow$ DXE 阶段生成 ACPI（Advanced Configuration and Power Interface，高级配置与电源接口）SRAT / SLIT 表移交 OS。**

1. **SEC（安全阶段）**：平台上电复位，执行微码加载与硬件鉴权。
2. **PEI（预 EFI 初始化阶段）与 CAR 状态**：此时 DRAM 尚未激活，CPU 将片内 L3 缓存配置为“只命中不逐出”的临时内存，即 **CAR（Cache-as-RAM）**。在 CAR 栈环境下，UEFI 加载执行芯片原厂提供的保密二进制模块——**MRC（Memory Reference Code）**。MRC 依次完成物理探测训练与 SAD / CHA / TAD / IMC 四级寄存器注入，打通主存寻址后拆除 CAR，并在 DXE 阶段构建 ACPI 表：


#### SAD 级联 Limit 比较器与 ACPI SRAT / SLIT 换算

硬件 SAD 规则寄存器（如 `DRAM_RULE_CFG`）**不设 `Base` 字段，仅存储 26-bit 的上界块号 `Limit`（以 64 MiB 即 `PA[51:26]` 为刻度）**。硬件采用级联优先比较器：Rule 0 默认以 `0` 为下界，Rule $i$ 自动以前一条规则的上界 `Limit_{i-1}` 为隐式下界，单周期并行锁定首条满足 `PA[51:26] < Limit_i` 的规则：

由于底层寄存器属厂商私有定义，UEFI 将其转化为标准 **ACPI 表**移交 OS：

* **SRAT（系统资源亲和性表）**：建立抽象节点号 **Proximity Domain**，通过 `Processor Local x2APIC Affinity` 与 `Memory Affinity` 结构体，将逻辑核心及显式字节跨度（`Base Address` 与 `Address Length`）绑定至对应 Domain。
* **SLIT（系统局部距离信息表）**：量化节点间相对访存代价，规范固定本地域距离为 `10`（跨 EMIB 硅桥通常为 `13~14`，跨 UPI 插槽为 `21~28`），供 Linux 构建内存回退链表（`zonelist`）。

| 物理内存节点区间 | 硬件 SAD 寄存器配置（硅片控制面）<br>（粒度：64 MiB 块，比较 `PA[51:26]`，**仅存 Limit**） | ACPI SRAT 描述结构体（OS 抽象面）<br>（粒度：1 字节，64 位无符号整数，**显式 Base + Length**） | 软硬件区间映射实质 |
| --- | --- | --- | --- |
| **Node 0 区间**<br>（**0 ~ 64 GiB**） | • **Rule 0 Limit**：`0x0400`（ $1024 \times 64\text{ MiB} = 64\text{ GiB}$）<br>• **硬件判决**：`PA[51:26] < 0x0400` $\rightarrow$ `Node 0` | • **Proximity Domain**：`0`<br>• **Base Address**：`0x0000_0000_0000_0000`（0 B）<br>• **Address Length**：`0x0000_0010_0000_0000`（64 GiB） | Rule 0 以 `0` 为隐式下界，匹配第 `0 ~ 1023` 块；固件左移 26 位转为字节长度填入 SRAT。 |
| **Node 1 区间**<br>（**64 ~ 192 GiB**） | • **Rule 1 Limit**：`0x0C00`（ $3072 \times 64\text{ MiB} = 192\text{ GiB}$）<br>• **硬件判决**：Rule 0 未命中且 `PA[51:26] < 0x0C00` $\rightarrow$ `Node 1` | • **Proximity Domain**：`1`<br>• **Base Address**：`0x0000_0010_0000_0000`（64 GiB）<br>• **Address Length**：`0x0000_0020_0000_0000`（128 GiB） | 硬件以 Rule 0 的 `0x0400` 为隐式下界；固件计算出差值（`0x0C00 - 0x0400 = 0x0800` 块 $= 128\text{ GiB}$），向 OS 显式呈报基址与长度。 |

#### 在操作系统中核验 SRAT / SLIT

* **Linux 环境**：使用 `numactl --hardware` 查看节点拓扑，或通过 `acpica-tools` 反编译 `/sys/firmware/acpi/tables/` 下的二进制表：

### 5. 经典双插槽（两路 NUMA）全链路路由

在双路服务器（Intel 切片体系）中，每颗 CPU 封装的 2D Mesh 上挂载着**计算站点**（Core + 私有 L1/L2 + L3 切片 + **CHA**）与**独立 I/O 站点**（IMC、**KTIA** 即 UPI 端口控制器、PCIe/IIO）。当插槽 0 核心访问插槽 1 的远端物理地址时，端到端路由如下：

```
┌────────────────────【 插槽 0（Socket 0：请求发起方本地封装） 】────────────────────────────────────────┐
│ ① 请求核：私有 L1/L2 未命中，MMU/TLB 已将虚拟地址 VA 翻译为系统物理地址 SPA                           │
│    │                                                                                                  │
│    ▼                                                                                                  │
│  首站 CHA（请求核所在网格站点的本地代理）                                                             │
│  内置【第一级：SAD 系统地址译码器】：抽头比对 PA[51:26] 级联 Limit 寄存器                             │
│  （例如双槽各插 64 GiB 内存时，PA[36] = 0 归属插槽 0，PA[36] = 1 归属插槽 1）                         │
│    │                                                                                                  │
│    ├─► [判定为本地地址 (Socket 0)]                                                                    │
│    │     └─► 首站 CHA 运行 XOR 算得本封装归宿 CHA 坐标 ──► 经本地 2D Mesh 转发至目标 CHA              │
│    │           ├─ 命中本地 L3 切片或片内目录（单播探针从本槽其他核索回脏行）──► 返回请求核            │
│    │           └─ L3 未命中 ──► 本地 TAD (剥离交织位还原 CPA) ──► 本地 IMC ──► 本地 DRAM              │
│    │                                                                                                  │
│    └─► [判定为跨槽远端地址 (Socket 1)]                                                                │
│        （本地免检：不作归宿、不查本地 L3 Tag、不碰本地 TAD/IMC）                                      │
│          │                                                                                            │
│          ▼ [沿插槽 0 片内 2D Mesh 单播走线直达边缘网关]                                               │
│        KTIA 0（插槽 0 的 UPI 出站控制器 / 协议网关）                                                  │
│          │                                                                                            │
│          ├─► 打包为 UPI 协议 Flit 报文，封装【4 大核心载荷】：                                        │
│          │   ┌────────────────────────────────────────────────────────────────────┐                   │
│          │   │ 1. SrcNode   = Socket 0 (源插槽号，指明数据回传的收件方)           │                   │
│          │   │ 2. DstNode   = Socket 1 (目的插槽号，指明跨槽路由大方向)           │                   │
│          │   │ 3. ReqOpcode = RdData / RdInvOwn (事务意图：共享只读 / 独占写失效) │                   │
│          │   │ 4. SPA       = 0x10_0040_... (未经截断的完整系统物理地址)          │                   │
│          │   └────────────────────────────────────────────────────────────────────┘                   │
│          ▼                                                                                            │
│        PHY 物理层并转串发送驱动器（SerDes Tx）                                                        │
└──────────┼────────────────────────────────────────────────────────────────────────────────────────────┘
           │
           │ ② 跨插槽物理链路（主板差分串行走线，支付跨界延迟税，往返约 60~70 ns）
           │
┌──────────┼────────────────────────────────────────────────────────────────────────────────────────────┐
│          ▼                                                                                            │
│        PHY 物理层接收解串器（SerDes Rx）                                                              │
│          │                                                                                            │
│        KTIA 1（插槽 1 的 UPI 入站控制器 / 对端协议网关）                                              │
│          │                                                                                            │
│          ├─►【硬件解析 SPA】：提取完整 SPA，运行 KTIA 1 内部集成的【第二级：CHA XOR】散列逻辑，       │
│          │                    在对端切片空间中直接解出归宿坐标：如 CHA 5 的 (X, Y)                    │
│          │                                                                                            │
│          ▼ [向插槽 1 片内 2D Mesh 网格发起点对点单播注入]                                             │
│        对端归宿 CHA（Home CHA，例如插槽 1 的 CHA 5）：查对端 L3 Tag 与分布式一致性目录 (Directory)    │
│          ├─► [命中 L3 或目录]：对端 L3 切片供数 ／ 目录指向对端某核持有私有脏副本，单播探针索回       │
│          └─► [L3 未命中 Miss]：目录登记状态并放行 ──►【第三级：对端 TAD】──►【第四级：对端 IMC】      │
│                                                                                   │                   │
│          ┌────────────────────────────────────────────────────────────────────────┘                   │
│          ▼ (从对端 L3 或对端 DRAM 取得 64B 缓存行数据)                                                │
│        ③ 64B 数据行汇聚至 KTIA 1 封装出站 ──经 UPI 跨槽链路返回──► KTIA 0 ──片内 Mesh──► 填入请求核   │
│          的私有 L1/L2 缓存（不写入插槽 0 的 L3 切片）                                                 │
└────────────────────【 插槽 1（Socket 1：内存归属方对端封装） 】────────────────────────────────────────┘

```

* **首站 SAD 裁决与本地免检**：每个核所在站点的 CHA 均内置 SAD 镜像寄存器。请求进入首站 CHA 即比对高位地址裁决归属；一旦判定为跨槽远端地址，硬件立即免除本地 L3 查找，直接经片内 Mesh 单播送往 KTIA 0 打包上 UPI 链路。
* **对端归宿 CHA 目录拦截**：跨槽请求抵达插槽 1 后，不能直接发往对端 IMC，而必须先到对端归宿 CHA 查分布式目录（Directory）。这是因为对端 DRAM 数据可能已过期（最新脏副本可能正驻留在插槽 1 某核的私有 L1/L2 中）；唯有查完目录确认无脏副本且对端 L3 未命中后，才放行至对端 TAD / IMC。
* **全网 XOR 确定性单播**：两颗插槽的所有 CHA 与 KTIA 共享同一套 XOR 散列方程，任意 SPA 对应的归宿 CHA 坐标全网唯一确定。查目录、发失效探针与索回副本全程在 `请求核 <-> 归宿 CHA <-> 持有核` 间按坐标单播完成，避免了广播嗅探耗尽 UPI 带宽。
* **跨插槽 L3 容量排他隔离**：双路系统中，每颗插槽（Socket）构成一个独立的 L3 共享域硬边界。插槽 0 的 CHA 仅对本地物理地址段建账；插槽 0 核心跨 UPI 拉回的远端数据仅暂存于该核的私有 L1/L2 中，一旦被 L2 逐出（若为脏行则跨 UPI 写回插槽 1 的归宿 CHA / IMC），绝不在插槽 0 的 L3 中分配空间，在硬件底层严格兑现了第 1 节定义的共享域排他性边界。
