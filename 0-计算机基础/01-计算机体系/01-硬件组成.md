# 硬件组成

## 定义

计算机是存储程序式电子计算机，其本质是通过指令序列对二进制数据进行变换的机器。冯·诺依曼架构将指令与数据统一存储在同一个读写存储器中，CPU 通过显式的取指-执行周期驱动所有计算。这一设计的深远影响在于：程序本身成为可以被读写、修改、甚至自生成的数据——图灵完备性的物理载体。

## 数学模型

**冯·诺依曼瓶颈的定量描述：**

$$
B_{瓶颈} = \min\left(\frac{W_{总线}}}{T_{周期}}, \quad N_{CPU} \times \frac{W_{内存带宽}}{T_{周期}}\right)
$$

带宽争用时整机性能受限于最窄总线或内存通道，而非 CPU 算力。

**局部性原理的缓存命中率模型：**

$$
H = \frac{\sum_{i=0}^{L} h_i \cdot C_i}{\sum_{i=0}^{L} C_i}
$$

其中 $h_i$ 为第 $i$ 层命中率，$C_i$ 为第 $i$ 层访问代价（周期数）。真实系统性能由加权命中时间决定：
$$
T_{有效} = (1 - M) \times T_{命中} + M \times T_{未命中}
$$
$M$ 为未命中率。

**存储层次容量-延迟积（Area-Latency Product）：**

$$
AP_i = S_i \times L_i
$$

第 $i$ 层的面积-延迟积反映其"数据缓存能力"。L1 的 AP 最小（32KB × 4周期），L3 的 AP 最大（64MB × 40周期）。

## 数据流

<pre>
用户程序（文本） 
    ↓ 编译（clang/gcc） 
可执行文件（ELF/PE）─→ 加载器（OS） 
    ↓ 
内存空间 [代码段 | 数据段 | 堆 | 栈]
    ↓ 取指 
CPU 控制单元 ──→ 指令寄存器（IR） 
    ↓ 译码 
控制信号 ──→ ALU / 寄存器文件 
    ↓ 执行 
结果 ──→ 写回（寄存器堆或 cache） 
    ↓ 
Cache 层级（L1d → L2 → L3 → 主存）──→ I/O 设备（DMA）
</pre>

关键路径延迟对比（典型 x86-64）：
- L1d 命中：4 周期
- L2 命中：12 周期
- L3 命中：40 周期
- 主存访问：200+ 周期
- NVMe SSD：~10,000 周期
- HDD 寻道：~10,000,000 周期

## 机制

### 冯·诺依曼架构

程序与数据共存于同一内存，CPU 通过共享总线访问。这一设计在 1945 年是天才之举，但它创造了一个根本矛盾：CPU 与内存之间的语义不对等——CPU 以 GHz 运行，内存带宽以 GB/s 计量，两者相差 2-3 个数量级。

**约束条件：**
- 内存访问带宽决定整机性能上限，CPU 算力无法完全发挥
- 总线争用导致 CPU 与 I/O 设备竞争访问权
- 指令流和数据流共享同一物理通道

**违反后果：**
- 当缓存命中率低于 95% 时，CPU 大部分时间在等待数据
- DMA 设备与 CPU 并发访问内存时，若无一致性协议协调，会导致缓存脏数据问题
- 多核时代缓存一致性协议（MESI/MESIF）成为性能瓶颈——核间通信延迟可达 100+ 周期

### 内存层级

容量与速度的物理折中由硅片面积和 DRAM 访问原理决定：SRAM 每个 bit 需要 6 个晶体管，DRAM 只需要 1 个电容+1个晶体管，但 DRAM 需周期性刷新且访问更慢。

**约束条件：**
- L1/L2/L3 延迟逐级递增（4/12/40 周期典型值）
- 容量逐级递增（32KB/1MB/64MB 典型值）
- 包含策略：当前 CPU 多用Inclusive cache（Ivy Bridge 之前）或 Exclusive cache（AMD Zen）

**违反后果：**
- 数据局部性差导致缓存未命中——每次未命中需从下级存储加载整个 cache line（通常 64 字节）
- 伪共享（False Sharing）：两个核修改同一 cache line 的不同字节，导致 MESI 协议下的写穿透

### 存储层次

速度/容量/成本构成不可能三角：SSD 的延迟是 DRAM 的 1000 倍，HDD 的延迟是 SSD 的 1000 倍，但每 GB 成本也相应降低 1000 倍。

**约束条件：**
- HDD 机械寻道限制吞吐量（~100MB/s 顺序读，~1MB/s 随机读）
- SSD 无机械部件但写入寿命有限（TBW：500 TBW/1TB 典型）
- NVMe PCIe 直连消除协议开销（5-7 GB/s vs SATA SSD 的 550 MB/s）

**违反后果：**
- 数据库等随机访问场景用 HDD 导致性能灾难——1 次查询需要 10+ ms 寻道
- 写入密集型应用（日志、缓存淘汰）忽略 TBW 导致固态衰减到只读

## 参考存根

```bash
# Linux 查看 CPU 信息（WSL/Linux）
cat /proc/cpuinfo | grep "model name"
uname -m

# Linux 查看内存层次
cat /proc/meminfo | head -5
lscpu | grep -E "L1d|L2|L3"
```

```powershell
# Windows 查看 CPU
Get-CimInstance Win32_Processor | Select-Object Name

# Windows 查看系统架构
[System.Environment]::GetEnvironmentVariable("PROCESSOR_ARCHITECTURE")
```
