# 硬件组成

## 一、核心定义：指令与数据共处存储器

存储程序式计算机（冯·诺依曼架构）把指令与数据都编码为二进制位模式，存入同一个可寻址存储空间。二者的区别不在存储形式，而在中央处理器（Central Processing Unit，CPU）怎样使用它：程序计数器（Program Counter，PC）给出地址时，取指通路把位模式送入译码器；访存指令生成地址时，数据通路把位模式作为数据读写。

| 通路 | 地址来源 | 位模式去向 | 获得的语义 |
| --- | --- | --- | --- |
| 取指 | PC | 指令译码器 | 作为指令解析，驱动后续操作 |
| 访存 | 访存指令计算 | 寄存器或存储器 | 作为数据读取或写入 |

位模式本身不预设语义，通路与当前操作才决定解释方式。这个区分也解释了解释器的位置。C++ 源码经编译器生成原生机器码（Machine Code），运行时由 CPU 直接取指执行。以 CPython 为例，Python 源码先生成字节码（Bytecode），再由解释器逐条处理；CPU 执行的是解释器的原生机器码，字节码在这条硬件路径中是数据。

因此，最小逻辑模型由两部分组成：CPU 提供寄存器、算术逻辑单元（Arithmetic Logic Unit，ALU）与控制逻辑，存储器保存指令和数据。缓存保存其中一部分副本，取指—执行循环则不断改变机器状态。经典五级模型把这个循环拆成五种职责：

```text
取指             译码             执行             访存             写回
按 PC 取指令 ──► 解释指令编码 ──► 运算或判定分支 ──► 读取或写入数据 ──► 结果写寄存器
```

这是理解单条指令职责与顺序的模型，现代 CPU 则让多条指令重叠推进。乱序执行允许已就绪的指令先执行，但退休仍按程序顺序提交结果。Load 在访存阶段取得数据，在写回阶段更新目的寄存器；Store 先进入存储缓冲区（Store Buffer），在指令退休并取得缓存行写权限后更新 L1D，脏行逐出时再沿缓存层级写回动态随机存取存储器（Dynamic Random-Access Memory，DRAM）。这里的“写回阶段”只写寄存器，不等于把 Store 写回内存。

这些阶段在流水线中重叠后，取指与数据访问可能同拍发生。若两者共享单端口存储阵列，同一拍只能服务一个请求，另一个请求必须等待，形成结构冲突（Structural Hazard）。一级缓存因此拆成独立的指令缓存（L1I）与数据缓存（L1D），用两套阵列和端口支持取指与访存并行，消除这一级的取指—访存端口冲突。

L2、L3 接收的是经 L1 过滤后的未命中请求，访问频次已经显著降低，取指缺失与数据缺失很少同拍争用。即使发生碰撞，仲裁也只需让一个请求稍后发起；流水线阵列在下一拍仍能接收新请求，这次等待不会占满整个缓存命中延迟。在稀疏到达下，偶发排队不会持续积压，因此无须为峰值冲突常驻两套阵列和端口。指令与数据在 L2、L3 重新汇合，共享容量并按需分配空间。由此形成现代处理器的常见结构：软件面对统一的指令与数据空间，L1 为高频并发访问分离，下级缓存以少量偶发排队换取统一组织。

## 二、虚拟地址到物理介质的全链路拓扑与 DDR5 物理驻留机制

只要驻留内存，业务数据与操作系统建立的页表树就必占 DRAM 物理阵列，必有真实的系统物理地址（PA）。VA 只是软件看到的地址视图；PMH 的页表读取、缓存的物理标签比较和 IMC 的内存寻址，最终都依赖 PA。

PA 空间按字节连续编号，但不要求页表树在物理上连续。按 4 KB 边界将物理地址空间整齐切分后，**内存中一切皆有物理地址，必然导致内存中一切皆驻留于“物理页”**：

* **高 24 位为物理页号（Physical Page Number，PPN；也常写作 Physical Frame Number，PFN）**：唯一标识物理内存中的哪一张 4 KB 物理页。只要前 24 位一致，字节就落在同一张物理页上。本文统一使用 PPN。
* **低 12 位为页内偏移（Page Offset）**：页基址的低 12 位全为 `0`，页内偏移从 `0x000` 增至 `0xFFF`；越过这一页，物理页号加 1，偏移归零。

```text
36 位 PA = {24 位 PPN（物理页号）, 12 位页内偏移}

  {PPN=N,   12'h000} ─► 物理页 N 的第 0 字节：页基址，低 12 位全为 0
  {PPN=N,   12'h001} ─► 第 1 字节
            ……               同一物理页内（前 24 位一致）逐字节递增
  {PPN=N,   12'hFFF} ─► 第 4095 字节
  {PPN=N+1, 12'h000} ─► 物理页 N+1 的第 0 字节：页号进位，进入下一张物理页

```

**页表的本质也是物理页。** 无论中间级页表还是终端业务数据，在物理内存中都是由操作系统分配的 4 KB 空闲物理页，仅靠 24 位物理页号即可定位哪一页，再靠 **VA 提供的位段**定位页内字节：

* **页表项的 PA**：由 `CR3` 或上一级页表项提供的 **24 位物理页号**（锁定当前页表页），与 **VA 中对应层级的 9 位索引**（补齐低 3 位 `000` 作为页内偏移）逐级拼接算出。
* **业务数据的 PA**：由叶页表项给出的 **24 位数据页物理页号**（操作系统为业务数据分配的空闲物理页），与 **VA 最低的 12 位页内偏移**拼接而成。

两类 PA 请求都先查询缓存；缓存未命中时，IMC 再把 PA 映射为 Channel、Sub-channel、Bank 等 DRAM 阵列坐标。地址散列把访问流分散到可并行的物理资源，目标是在统计上均衡利用它们，而不是改变 PA 与字节之间的一一对应。

以下采用 4 KB 页、64 B 缓存行和双通道 DDR5（Double Data Rate 5，第五代双倍数据率）平台，沿一次需要访问主存的读请求追踪这条路径。

### 1. 全链路纵览：从虚拟地址到 DRAM 坐标

```text
[虚拟视图]  Core 生成 VA
              │
              ▼
            MMU 地址翻译 ──► TLB 命中 ──► 直接产出业务数据 PA
              │               │
              │               └─ TLB 未命中 ─► PMH 逐级计算表项 PA 并查页表 ──► 映射缺失 ─► #PF（OS 分配物理页 / SSD 换入）
              │                                  │
              │   ┌──────────────────────────────┘（页表项 PA 与业务数据 PA 汇入同一物理访存链路）
              ▼   ▼
[物理地址]  L1 / L2 / L3 缓存（64 B Cache Line） ──► 命中：直接返回 Core（或给 PMH 推进下一级）
              │
              ▼ 末级缓存未命中（LLC Miss）
            片上互连与 IMC（将 PA 散列译码为硬件坐标）
              │
              ▼
[DRAM坐标]  Channel ────► Sub-channel ─► DIMM Slot ─► Rank      （板级通道与模组拓扑）
              │
              ▼
            Bank Group ─► Bank ────────► Row ───────► Column    （DRAM 颗粒内部阵列）
              │
              ▼
            突发读出 64 B 缓存行，沿原路回填 Cache 并返回 Core

```

1. **Core 与 MMU/TLB**：核心执行访存指令，生成 64 位虚拟地址（Virtual Address，VA）。操作系统为各级页表与业务数据分配空闲物理页，并在页表项中填入对应的 24 位物理页号。地址转换后备缓冲器（Translation Lookaside Buffer，TLB）命中时直接给出业务数据页的物理页号；未命中时，页表遍历器（Page Miss Handler，PMH）利用 VA 的各级 9 位索引逐级读取页表，最终将 VA 转换为系统物理地址（Physical Address，PA）。映射不存在或权限检查失败会触发缺页异常（`#PF`）；操作系统分配物理页并更新页表后，原指令重新执行。
2. **Cache（L1/L2/L3）**：硬件以 64 B 缓存行（Cache Line）为数据搬运单位，业务数据行与页表行都可以在这里留下副本。PMH 的页表读取也经过这条缓存层级。对业务数据的访问中，L1D 用 VA 的页内位选组，同时等待 TLB 提供物理页号进行标签比较；L2 与共享 L3 再按 PA 查询。只有缓存无法满足请求，或脏行需要写回主存时，事务才进入片上互连。
3. **片上互连与 IMC**：片上路由与地址译码选择归宿缓存切片和内存控制器（Integrated Memory Controller，IMC）。IMC 再把事务分发到目标 Channel 和 Sub-channel 的读写队列。
4. **Channel（内存主通道）**：本例配置两个 64-bit Channel，各自连接独立的内存控制通路。Channel 决定请求使用哪一组主板数据线与命令线。
5. **Sub-channel（DDR5 子通道）**：每个 DDR5 Channel 分成两个 32-bit Sub-channel，各自拥有独立的命令/地址总线与数据总线。双通道平台因此形成四个可独立调度的子通道。
6. **DIMM Slot（内存插槽）**：双列直插式内存模块（Dual In-line Memory Module，DIMM）插入主板插槽。本例采用每通道两根内存的 2DPC 布局，命令/地址信号通过 Fly-by 拓扑依次到达颗粒；每根 DDR5 DIMM 的两个半区分别服务 Sub-channel A 与 B。
7. **Rank（颗粒群逻辑面）**：在同一 Sub-channel 内，Rank 是由同一根片选信号（`CS#`）选中、协同响应命令的一组 DRAM 颗粒。本例采用 16 Gb ×8 颗粒，四颗并联提供 32-bit 数据宽度，构成一个 Rank。`1R`/`2R` 表示 Rank 数量，不直接等同于内存条的物理单双面。
8. **Bank Group（存储体组，BG）**：DDR5 颗粒内部包含八个 Bank Group。连续列访问落在不同 BG 时使用较短的列间隔，落在同一 BG 时受较长的列间隔约束。以 DDR5-6400 为例，跨 BG 的 `tCCD_S` 可为 8 个时钟周期，即 2.5 ns。
9. **Bank（存储体）**：每个 BG 内有四个 Bank，单颗芯片共 32 个。每个 Bank 都有行缓冲（Row Buffer）与状态机，控制器可以在不同 Bank 之间交错安排激活、预充电和列访问。
10. **Row（行）**：`ACT` 命令携带行地址，打开目标 Bank 中的一行。本例单颗 ×8 颗粒的一页为 1 KB，同一 Rank 的四颗颗粒并行激活，在子通道侧形成 4 KB 行缓冲。
11. **Column（列）**：目标行打开后，`RD`/`WR` 命令通过列地址选择数据位置。DDR5 的 BL16 在 32-bit 子通道上连续进行 16 次数据传输，合计 32 bit × 16 = 64 B，正好返回一个缓存行。

固态硬盘（Solid-State Drive，SSD）不在 DRAM 寻址链中。缺页或换页时，操作系统通过高速外设互连（Peripheral Component Interconnect Express，PCIe）和直接存储器访问（Direct Memory Access，DMA）在 SSD 与分配好的 DRAM 物理页之间搬移页面；页面就绪后，原来的访存指令才重新进入上述路径。

### 2. 虚拟页号到物理页号：页表自生长、页内直通与稀疏映射

页表（Page Table）保存虚拟页到物理页的映射，内存管理单元（Memory Management Unit，MMU）用它取得 PA。即使请求最终命中片上缓存、不访问 DRAM，也需要这次转换：L1D 可以先用页内位选组，但仍要用物理页号核对标签；L2、L3、一致性请求与 IMC 同样使用 PA。

以下以 48 位 VA、36 位 PA 和 4 KB 页为例。VA 的高 36 位是虚拟页号（Virtual Page Number，VPN），低 12 位是页内偏移；PA 的高 24 位是**物理页号（PPN）**，低 12 位仍来自原 VA。

```text
          VA（48 bits）                                 PA（36 bits）
   ┌──────────────┬────────────┐                 ┌──────────────┬────────────┐
   │  VPN（36b）  │ off（12b） │                 │  PPN（24b）  │ off（12b） │
   │  VA[47:12]   │ VA[11:0]   │                 │  PA[35:12]   │ PA[11:0]   │
   └──────┬───────┴─────┬──────┘                 └──────▲───────┴─────▲──────┘
          │             │                               │             │
          ▼             └───────────────────────────────┼─────────────┘
   查页表得到物理页号                                    │    页内偏移直通
          └─────────────────────────────────────────────┘

```

#### 1. 万物皆页：24 位定物理页，VA 的 9 位索引挑槽位“长”出页表树

之所以 36 位 VPN 被均分为四段 9 位索引（ $9 \times 4 = 36$），根本原因在于**页表本身也是一张 4 KB 物理页，且每一级页表项的 PA 都要靠 VA 的 9 位索引参与拼接**：

1. **24 位锁定当前物理页**：操作系统从空闲内存中分配一张 4 KB（ $2^{12}\text{ B}$）物理页作为页表。上一级（`CR3` 或上级页表项）给出的 24 位物理页号（PPN）唯一锁定这张页表所在的物理页。
2. **VA 的 9 位索引拼出页表项 PA**：每个页表项占 8 字节（ $2^3\text{ B}$），一张 4 KB 页表页恰好切分为 $2^{12} / 2^3 = 2^9 = 512$ 个槽位。硬件从 **VA** 中抽取当前层级的 **9 位**作为槽位号（`0`～`511`），左移 3 位补齐页内字节偏移 `3'b000`，与当前页表的 24 位 PPN 拼接，合成该页表项自身的 36 位物理地址：

$$\text{PA}_{\text{entry}} = \\{\text{PPN}_{\text{table}}[23:0],\ \text{VA\\_Index}[8:0],\ 3\text{'b}000\\}$$


3. **非叶节点生长页表，叶节点落地数据页**：当软件在原本空缺的槽位中填入新分配的 24 位物理页号时，就从该槽位“长”出了一张下一级页表页；到了最后一级，**叶页表项（Leaf PTE）**里记录的 24 位物理页号不再指向页表，而是指向操作系统为业务数据分配的那张**数据物理页**，再与 VA 最低的 12 位页内偏移拼接，合成最终业务数据的 36 位物理地址：

$$\text{PA}_{\text{Data}} = \\{\text{PPN}_{\text{leaf}}[23:0],\ \text{VA}[11:0]\\}$$



```text
[CR3 / 上级页表项的 24 位 PPN] ──► 锁定当前 4 KB 页表物理页（含 512 个 8B 槽位）
                                         │
[VA 当前层级的 9-bit 索引]    ──► 拼成页内偏移 {VA_Index, 3'b000}，合成页表项 PA 并读出该项
                                         │
                                         ├─► 中间页表项：给出下级页表 24 位 PPN ──► “长”出下一级页表页
                                         └─► 叶页表项  ：给出数据页 24 位 PPN   ──► 锁定业务数据物理页
                                                                                       │
[VA 最低的 12-bit 页内偏移]   ─────────────────────────────────────────────────────────┴─► 合成数据 PA

```

#### 2. 映射口径与稀疏表示

在末端叶节点完成转换后，完整数据地址的合成规则是 `PA = {f(VPN), off}`。页表树通过上述“24 位定页 + VA 9 位索引选槽”的逐级寻址实现映射 $f$，TLB 则直接缓存从 36 位 VPN 到末端 24 位数据页 PPN 的端点结果。对已经建立映射的虚拟页集合 $D$，本例的函数口径为：

$$f:D\longrightarrow\\{0,1\\}^{24},\qquad D\subseteq\\{0,1\\}^{36}$$

未建立映射的 VPN 不属于 $D$，硬件按 VA 的 9 位索引去对应页表页挑槽位时，会读到空缺（Present 位为 0），立即触发缺页异常（`#PF`）交给操作系统处理。正是因为只有被 VA 实际用到的 9 位槽位才会分配空闲物理页、向下“长”出新页表或数据页，稀疏页表树无须为全部 $2^{36}$ 个潜在 VPN 预先分配物理存储。

#### 3. 页内恒等，页间独立：虚拟连续不等于物理连续

地址生成单元（Address Generation Unit，AGU）按 `VA = base + index × scale + disp` 算出 VA。硬件按页大小 $2^N$ 字节切分地址，高位用于查找 PPN，低 $N$ 位直接拼到物理页号之后。这个规则保留了两种连续性：

* **页内连续**：页内第几个缓存行、行内第几个字节的相对位置不变，所以 `VA[N-1:0] ≡ PA[N-1:0]`。
* **页间独立**：操作系统为每个 VPN 分配当时可用的 PPN。相邻虚拟页可以落入相距很远的物理页，虚拟连续性不要求物理页连续。

页型变化只改变遍历在哪一级结束，以及多少位地址作为页内偏移直通：

| 页型 | 页内偏移位 | 终结页表遍历的叶表项 | 一条映射覆盖的缓存行 |
| --- | --- | --- | --- |
| 4 KB | 12 位 | `PTE` | $2^{12-6}=64$ 行 |
| 2 MB | 21 位 | `PS=1` 的 `PDE` | $2^{21-6}=32,768$ 行 |
| 1 GB | 30 位 | `PS=1` 的 `PDPTE` | $2^{30-6}=1,048,576$ 行 |

大页让一条端点映射覆盖更大的地址范围，同容量 TLB 因而能保留更大工作集的翻译。无论页型如何，页表最终都给出数据页的 PPN，页内偏移再定位页内字节；取得 PA 后，硬件才能按物理地址查找或访问数据。

#### 4. 四级 512 叉稀疏页表树：按需分配、逐级定位与表项缓存

若用一维数组直接保存全部潜在 VPN 的映射，仅表项就需 $2^{36}\times8\text{ B}=512\text{ GB}$。四级页表把 36 位 VPN 分成四段 9 位索引，每一段只在需要时分配一张下一级页表，形成 `PML4 → PDPT → PD → PT` 的稀疏树。57 位 VA 的 LA57 模式再增加一级，主链不变。

每张表页都占一个 4 KB 物理页，都有 512 个 8 B 槽位。非叶表项与 4 KB 页的 PTE 都把 PPN 放在 `Bit[35:12]`，低位保存 `P`、`R/W` 等标志；非叶表项还用 `PS` 区分“指向下一级页表”与“直接映射大页”。

```text
 63                                      36 35                       12 11                    0
┌──────────────────────────────────────────┬───────────────────────────┬──────────────────────┐
│       NX、保留位及其他属性                │      PPN（PA[35:12]）     │ P、R/W、U/S、PS 等  │
└──────────────────────────────────────────┴───────────────────────────┴──────────────────────┘
                                             │
                         ┌───────────────────┴───────────────────┐
                         ▼                                       ▼
               非叶表项：下一级页表页号                   叶表项：数据页号
```

| 表项类别 | 层级与条件 | PPN 指向 | 本次查找得到什么 |
| --- | --- | --- | --- |
| 非叶表项 | `PML4E`、`PDPTE`、`PS=0` 的 `PDE` | 下一级 4 KB 页表页 | 下一级页表基址 |
| 4 KB 页叶表项 | `PTE` | 4 KB 数据页 | 最终数据页基址 |
| 大页叶表项 | `PS=1` 的 `PDE` 或 `PDPTE` | 2 MB 或 1 GB 数据页 | 提前终结遍历，PPN 与更多 VA 低位共同定位数据 |

**操作系统沿访问路径分配页表页。** 在按需分配策略下，进程先有一张由 `CR3` 指向的 PML4 表页。首次访问尚未建立映射的虚拟页会触发缺页异常；内核分配所需的下级表页与数据页，写表项并把 `P` 置为 1。下面追踪四个虚拟页，四元组依次是四级索引：

```text
初始：CR3 ─► PML4，512 个槽位均为 P=0

页 A（1,2,3,4）
  新建 PDPT#1、PD#1、PT#1 和数据页 A
  PML4[1] → PDPT#1；PDPT#1[2] → PD#1；PD#1[3] → PT#1；PT#1[4] → PPN_A

页 B（1,2,3,5）
  与 A 共用前三级和 PT#1，只需分配数据页 B，再写 PT#1[5] → PPN_B

页 C（1,2,7,0）
  与 A、B 共用 PML4 和 PDPT#1；新建 PT#2，写 PD#1[7] → PT#2

页 D（1,8,0,0）
  只共用 PML4；新建 PD#2、PT#3，写 PDPT#1[8] → PD#2

最终页表树：
  CR3 ─► PML4[1] ─► PDPT#1
                      ├─ [2] ─► PD#1
                      │         ├─ [3] ─► PT#1 ─┬─ [4] ─► PPN_A
                      │         │               └─ [5] ─► PPN_B
                      │         └─ [7] ─► PT#2 ── [0] ─► PPN_C
                      └─ [8] ─► PD#2 ─► PT#3 ──── [0] ─► PPN_D
```

A 与 B 的 VPN 相邻，所以 PTE 也相邻；它们的数据页号却分别独立分配。这个例子共分配 7 张页表页，即 $7\times4\text{ KB}=28\text{ KB}$，而不是为全部潜在 VPN 预备 512 GB 数组。`P=0` 的非叶槽位没有下一级页表，这正是稀疏树节省空间的来源。

**业务数据要做 VA→PA，PMH 的页表遍历则只使用 PA 读取内存。** CR3 保存根表的物理页号 `PPN_PML4`，不是 PML4E，也不是某个表项的完整 PA。根表基址是 `PA_PML4 = {CR3.PPN_PML4, 12'b0}`；PMH 再用 VA 的第一段索引定位根表项。此后每一级都由上级表项给出下一级页表的 PPN，再算出下一级表项的 PA。

以页 A 中的 `VA = 0x0000_0080_8060_4ABC` 为例，四级索引是 `1,2,3,4`，页内偏移是 `0xABC`。下面把每个表项自身的地址单独命名，避免与表项内容中的 PPN 混淆：

```text
输入 VA = {VPN_4=1, VPN_3=2, VPN_2=3, VPN_1=4, off=0xABC}

Step 1：CR3 给出根表 PPN，定位 PML4E
  PA_PML4E = {CR3.PPN_PML4, VA[47:39]=1, 3'b000}
  读取 PML4E[1] = {标志位, PPN_PDPT#1}
                         │
Step 2：PML4E 给出 PDPT 的 PPN，定位 PDPTE
  PA_PDPTE = {PML4E.PPN_PDPT#1, VA[38:30]=2, 3'b000}
  读取 PDPTE[2] = {标志位, PPN_PD#1}
                         │
Step 3：PDPTE 给出 PD 的 PPN，定位 PDE
  PA_PDE = {PDPTE.PPN_PD#1, VA[29:21]=3, 3'b000}
  读取 PDE[3] = {标志位（含 PS=0）, PPN_PT#1}
                         │
Step 4：PDE 给出 PT 的 PPN，定位 PTE
  PA_PTE = {PDE.PPN_PT#1, VA[20:12]=4, 3'b000}
  读取 PTE[4] = {标志位, PPN_A=0x1A2B3C}
                         ▼
  PA_Data = {PTE.PPN_A, VA[11:0]=0xABC} = 0x1A2B3C_ABC
```

`PA_PDE` 指向 PDE 这个 8 B 表项，`PDE.PPN_PT` 则指向一张 4 KB PT；`PA_PTE` 指向 PTE，`PTE.PPN_A` 才指向业务数据页。完整地址链因此是 `PA_PML4E → PA_PDPTE → PA_PDE → PA_PTE → PA_Data`。页表树提供各级的 PPN，PMH 用 PPN 与 VA 索引算出这些 PA，而不是从树里直接读出五个现成地址。

**原始表项进入数据缓存有两条路径。** 第一条是操作系统建表：内核用普通存储指令清零页表页、写入表项，这些写入经过数据缓存，相关行可能暂时留有副本。第二条是 PMH 遍历：表项读经数据缓存层级查询，未命中时从 DRAM 读回包含该表项的 64 B 行，并在缓存层级留下副本。此后无论来自哪条路径，缓存行都可能因容量替换而逐出；“页表在物理内存中”不等于“页表行当前在缓存中”。

数据缓存与地址转换缓存使用不同的查找键。PMH 读取原始页表行时，以当前表项 PA 的缓存行地址定位数据缓存，例如使用 `PA_PDE[35:6]` 查找包含 PDE 的原始行。命中只能省去这次 DRAM 读取，不能倒推出前级表项的内容。`PA_PDE` 必须等 PDPTE 给出 `PPN_PD` 后才能算出，所以即使 PDE 原始行早已在 L1D，也仍要先取得这条地址。

PDE Cache 不走这条依赖链。它以 `PCID + VA[47:21]` 为键，直接返回 `PPN_PT` 与累计权限，于是前三个表项地址及其内存读取都被跳过，PMH 从 `PA_PTE` 接着计算。各结构的职责对比如下：

| 结构 | 查找键 | 保存的内容 | 能省去什么 |
| --- | --- | --- | --- |
| L1D/L2/L3 数据缓存 | 表项或业务行的 PA，按缓存行地址比较物理标签 | 原始 64 B 行；页表行含相邻 8 个表项 | 该行未命中时才需要的 DRAM 读取；不跳级 |
| `PML4E Cache` | `PCID + VA[47:39]` | `PPN_PDPT` 与权限 | `PA_PML4E` 及 PML4E 的内存读取 |
| `PDPTE Cache` | `PCID + VA[47:30]` | `PPN_PD` 与累计权限 | 前两级表项地址及内存读取 |
| `PDE Cache` | `PCID + VA[47:21]` | `PPN_PT` 与累计权限 | 前三级表项地址及内存读取；仍须计算 `PA_PTE` 并读取 PTE |
| TLB | `PCID + VA[47:12]`（即 VPN） | 数据页的 `PPN_Data` 与权限 | 全部四级表项地址及内存读取 |

页结构缓存保存沿路径累计的权限，跳级后不会丢失上级目录的限制。原始行中的另外 7 个表项虽然一同进入数据缓存，却不会仅因同行就自动变成 7 条 TLB 或页结构缓存词条；专用缓存保存的是实际解析出的路径信息。

用 A 之后访问 B 就能把三本账算清。A 的翻译完成后，TLB 留下 A 的端点映射，PDE Cache 留下 `PPN_PT#1`；如果原始 PT 行仍在数据缓存，它还同时含有 `PTE[4]` 与 `PTE[5]`。

```text
访问 B（1,2,3,5）
  TLB：B 是新 VPN，未命中
       │
  PDE Cache：VA[47:21] 与 A 相同，命中，直接得到 PPN_PT#1
       │       不再计算 PA_PML4E、PA_PDPTE、PA_PDE，也不读这三项
       ▼
  计算 PA_PTE = {PPN_PT#1, VA[20:12]=5, 3'b000}
       │
  仍须按 PA_PTE 读取 PTE[5]
       ├─ 原 PT 行仍在缓存：0 次 DRAM，取得 PPN_B
       └─ 原 PT 行已经逐出：1 次 DRAM，读回该行，再取得 PPN_B
       ▼
  回填 B 的 TLB 词条，拼出 PA_Data，再查询业务数据行
```

因此，**PDE Cache 命中只把表项读降为一次，并不单独决定 DRAM 次数。** 翻译阶段还要检查所需页表行的缓存状态；业务数据阶段则另算一次数据行是否命中。0 次 DRAM 要求本次涉及的所有页表行与业务数据行都能由缓存满足。

#### 5. 多进程“一进程一树”隔离、核心旁 `TLB` 分级形态与 `CR3 + PCID` 无清空切换

在现代操作系统中，DRAM 内存中的多棵进程页表树与 CPU 核心旁唯一的硬件 TLB 阵列通过 `CR3` 寄存器与 `PCID`（进程上下文标识符）协同工作：

1. **DRAM 内存中：一进程一棵独立基数树**
   系统并发运行 N 个进程时，DRAM 中独立驻留 N 棵四级页表树。进程私有隔离通过将不同进程的同号 `VPN` 映射至不同 `PPN_Data` 实现；多进程零拷贝共享（如共享动态库或大模型只读权重）则通过将多个进程各自私有 `PT` 叶表中的 `PTE` 指向同一个 `PPN_Data` 实现，物理电容中仅存唯一一份数据。

2. **核心旁 `TLB` 的真实形态：拍平路径的端点键值表（只存叶表项，不存树路径）**
   四级遍历路径（`1 -> 2 -> 3 -> 4`）在进入 TLB 时被彻底抹平。TLB 不记录中间级表页指针，而是将 4 个 9-bit 索引重新折叠回完整的 36-bit `VPN` 作为 Key，将叶表项输出的 24-bit `PPN_Data` 作为 Value，压成一条平坦的端点键值对（大页在 `PD / PDPT` 提前终结时，TLB 仅需匹配高 27 位或 18 位 `VPN` 前缀，单条 TLB 词条覆盖范围直接放大 512 倍或 262,144 倍）：

```text
  TLB 硬件词条结构 (将四级路径 1/2/3/4 彻底折叠为 VPN -> PPN 端点映射):
 ┌──────────────────────────────┬───────────────┬─────────────────────────────────────────┐
 │   Tag (Key 1): 完整 VPN      │ Key 2: PCID   │   Value: 目标数据页 PPN_Data + 权限标志  │
 │   0x0_8080_604 (36 bits)     │ 0x001 (12b)   │   0x1A2B3C (24 bits) + R/W/X/U/G/D/A    │
 └──────────────────────────────┴───────────────┴─────────────────────────────────────────┘
```

3. **MMU 内部的地址转换缓存：两级 TLB 与页结构缓存（转换结果缓存独立于数据缓存；被缓存的页表行仍以 64B 行驻留 L1D/L2/L3）**
   在 CPU 核心的 MMU 单元内部，地址转换专用硬件按速度与职责分为两级 **TLB**（缓存第 4 级终局叶表项 `PTE` 映射）与一组 **页结构缓存**（缓存前 3 级非叶表项 `PML4E / PDPTE / PDE` 映射）：

| MMU 内部硬件结构 | 硬件层级与官方名称 | 典型规模与命中延迟 | 缓存内容（Key $\rightarrow$ Value）与核心职责 |
| --- | --- | --- | --- |
| **一级地址速查表** | **`L1 dTLB`**（数据 TLB） / `L1 iTLB`（指令 TLB） | $64 \sim 96$ 项；**$0.5 \sim 1$ 周期** | 缓存最热的 **第 4 级叶表项 (`PTE`) 解析结果**（`PCID + VPN[35:0] -> 24b PPN_Data + 权限标志`），紧贴核心 AGU。 |
| **二级地址速查表** | **`L2 sTLB`** *(Second-Level Shared TLB)* | $1024 \sim 3072$ 项；**$7 \sim 8$ 周期** | 缓存次热的 **第 4 级叶表项 (`PTE`) 解析结果**。仅当 `L1 dTLB` 与 `L2 sTLB` **均未命中**时，才触发 **`TLB Miss`** 并唤醒硬件状态机 **PMH**。 |
| **页结构缓存** *(PMH 内部跳级加速器)* | **`Paging-Structure Caches`**<br>(`PDE / PDPTE / PML4E Cache`) | 每级数十项<br>*(内嵌于 PMH 硬件单元)* | 缓存从 **前三级 8B 非叶表项中剥离出的子树基址与累积权限**：<br>• **`PDE Cache`**：`VPN[35:9] -> PPN_PT (24b) + 权限`<br>• **`PDPTE Cache`**：`VPN[35:18] -> PPN_PD (24b) + 权限`<br>• **`PML4E Cache`**：`VPN[35:27] -> PPN_PDPT (24b) + 权限`<br>当发生 `TLB Miss` 时，PMH 先按最长前缀匹配此缓存，命中哪一级就直接拿到下一级页表页号 `PPN`，将原本最坏 4 次的串行查表缩短为 **$1 \sim 3$ 次**！ |

* 上表按 Intel 的 `Paging-Structure Caches` 叙述（按 VPN 位段索引、每级独立）。AMD 的 `Page Walk Cache` 把各级页表项按物理地址统一索引成单组结构，命中后同样跳级；两家取表都经数据缓存层级，但 AMD 10h 一代只到 `L2`、不命中 `L1d`。本文后续以 Intel 路径为主线。

4. **`CR3` 寄存器结构与多进程 `PCID` 混居免清空切换**

单颗核心的 `TLB`（`L1 dTLB + L2 sTLB`）同时混居着多个活跃进程的热点叶表项。现代 x86 架构（开启 `CR4.PCIDE = 1`）通过 64 位 `CR3` 寄存器实现多进程安全隔离与零开销切换。`CR3.PPN_PML4` 只给根表物理页号；PMH 再计算 `PA_PML4E = {CR3.PPN_PML4, VA[47:39], 3'b000}`，不会把 CR3 当成根表项：

```text
  64-bit CR3 核心控制寄存器布局:
  63                   52 51                                      12 11               0
 ┌───┬──────────────────┬────────────────────────────────────────┬──────────────────┐
 │ 1 │   保留位 (全 0)   │  当前进程 PML4 物理页号 (PPN_PML4)      │ 当前进程号 PCID  │
 └───┴──────────────────┴────────────────────────────────────────┴──────────────────┘
   ▲                                         ▲                              ▲
 Bit 63 = 1 (切换进程时不清空 TLB)     TLB Miss 时供 PMH 从根部查表     TLB 查找时比对进程身份
```

* **切换瞬间免清空（No-Flush）**：OS 从进程 A（`PCID=1`）切换至进程 B（`PCID=2`）时，仅执行一条写 `CR3` 指令更新 `{PPN_PML4_B, PCID=2}` 并保持 `Bit[63] = 1`，硬件不清空 TLB。
* **硬件双键匹配防串台**：每次访存查 TLB 时，硬件比较器强制要求 `(TLB.PCID == CR3.PCID) && (TLB.VPN == VA[47:12])` 同时成立方判定为 `TLB Hit`。进程 A 遗留的词条因 `PCID` 不匹配而对进程 B 天然隐身，而进程 B 上一轮时间片留下的热点词条则可直接命中。

#### 6. 地址转换与数据访问：页表行、业务行与 DRAM 结算

在全链路硬件执行中，**阶段 A（MMU 地址转换域：求值 `VPN -> PPN_Data`）** 与 **阶段 B（业务数据访问：按 `PA` 检索 `64B` 数据行）** 职责不同，但并非完全独立：阶段 A 的页表读也使用数据缓存，L1D 的 VIPT 查询还能让页内选组与 TLB 翻译重叠；只有物理标签比较和业务数据的最终访问必须等待 PA。

1. **阶段 A 边界（`TLB Hit / Miss`、PMH 阶梯跳级查表与 SSD 缺页拦截）**：
   核心发出 `VA` 后，高 36 位 `VPN` 进入 `L1 dTLB -> L2 sTLB` 检索。若两级 TLB 均未命中（**`TLB Miss`**），硬件立即唤醒 **PMH（Page Miss Handler）** 执行页表遍历（Page Walk）。**注意：PMH 绝非每次都傻傻地从 `CR3` 根部连读 4 个表项，而是先查询内嵌的 `Paging-Structure Caches` 进行跳级裁剪**：
   * **第一步：PMH 查页结构缓存（最长前缀优先裁减步数）**
     PMH 将 `VPN` 的高 27 位、18 位、9 位并行送入 `PDE / PDPTE / PML4E Cache` 比对（同样受 `PCID` 隔离约束）：
     * 若命中 **`PDE Cache`**（如刚访问完页 `(1,2,3,4)` 紧接着访问相邻页 `(1,2,3,5)`）：直接获得第 4 级页表页号 `PPN_PT` 及前三级累积权限，**跳过 Step 1\~3，仅需执行 Step 4（共 1 次表项读）**。
     * 若仅命中 **`PDPTE Cache`** 或 **`PML4E Cache`**：分别获得 `PPN_PD` 或 `PPN_PDPT`，从 Step 3 或 Step 2 切入（**需 2 次或 3 次表项读**）。
     * 若 **`Paging-Structure Caches` 全部未命中（All Miss 冷遍历）**：PMH 才被迫从 `CR3.PPN_PML4` 根部出发，执行最坏情况下的 **4 次串行表项读（Step 1 $\rightarrow$ Step 4）**。

   * **第二步：PMH 对真实内存页表的微操作（地址拼接 $\rightarrow$ 读 8B 表项 $\rightarrow$ 剥离 24b PPN 并回填）**
     在任何需要访问真实内存页表的步骤 $k \in \\{1,2,3,4\\}$ 中，PMH 硬件遵循完全一致的定长拆箱流水线（以冷遍历 Step 1 查 `PML4` 表为例）：
     ```text
     【PMH 单步查表微操作示例 — Step 1: 查第 1 级 PML4 表 (消耗 VPN_4 = 1)】
      • 拼接表项物理地址 : PA_PML4E (36b) = { CR3.PPN_PML4 (24b), VA[47:39]=1, 3'b000 }
                          (低 12 位为页内字节偏移 = 槽位号 × 8B 表项宽度，末三位 3'b000 强制 8B 对齐)
      • 发起缓存一致性读 : PMH 将 PA_PML4E 送入 L1D -> L2 -> L3 -> DRAM 数据通路读回 8B 原始表项 PML4E[1]
      • 硬件剥离与回填   : 校验 Bit[0] (P==1) 与权限位后，剥离低 12 位标志，抽出 Bit[35:12] 获得下一级
                          24-bit 页号 PPN_PDPT#1；同时将该映射写入 PML4E Cache 供后续访存跳级复用！
     ```

     `PA_PML4E`、`PA_PDPTE`、`PA_PDE`、`PA_PTE` 都是表项自身的物理地址，读取经过 `L1D/L2/L3`。缓存行在片上时，一次表项读不访问 DRAM；只有该行未命中才进入 IMC。四次表项读因而对应 0～4 次 DRAM 读取，不能直接画等号。
   * **第三步：终局叶表项 `PTE` 校验与 `#PF` 缺页异常拦截**
     **TLB 与页结构缓存铁律只存 `Present = 1` 的有效映射**。当 PMH 最终读出第 4 级 8B 叶表项 `PTE`（或中途任意一级表项）发现 **`Bit[0] (Present) == 0`** 时，CPU 才确知目标数据页尚未分配或已换出至外存，当即中止流水线并抛出 `#PF` 缺页异常。随后由 OS 伙伴分配器分配空闲物理页 `PPN_New`（若为换页则启动 NVMe DMA 从 **SSD** 搬入 4KB 数据），将 `PPN_New` 写回 `PTE` 并置 `P = 1`，最后重新执行指令完成 TLB 回填。

**命中路径的合并结算：0 次 DRAM 与冷遍历**

把三步合并看，两条轴各自独立：**PSC 决定读几个表项**（1~4 个），**缓存层级决定每一级表读在哪截获**（L1D / L2 / L3 / DRAM）。页表页取自普通 RAM，MTRR 默认 WB，8B 表项所在的 64B 行与业务数据行同处 `L1D/L2/L3`，受同一套标签与一致性协议管理——这是“表读可以 0 次 DRAM”的全部物理前提。

```text
【一次 TLB Miss 的表读链路：PSC 决定读几次，缓存决定每步在哪截获】

  L1 dTLB → L2 sTLB 双 Miss
        │
        ▼
  PMH 拿 VPN 前缀查 PSC（Intel：PML4E / PDPTE / PDE 三级）
        ├── 命中最深一级 ──► 跳过 1~3 级非叶表读
        └── 全未命中     ──► 从 CR3.PPN_PML4 起逐级读
        │
        ▼
  每一级都发同一种物理读: PA = { PPN_k (24b), VPN_k (9b), 3'b000 }
  （8B 表项落在 64B 对齐的页表行上，与业务数据行共用 L1D/L2/L3 标签）
        │
        ├── 该行在片上 ──► 命中 L1D/L2/L3，直接取出 8B 表项（DRAM 0 次）
        └── 该行不在   ──► 穿透 IMC 读回 64B 行（本级 DRAM 1 次）
        │
        ▼
  叶表项 PTE 的 P 位校验 → 回填 (PCID, VPN → PPN) → 重执原访存
```

* **非叶节点被 PSC 吸收（省的是表读次数）**：命中 `PDE Cache` 只剩 PTE 一读；只命中 `PML4E Cache` 则还剩三读。这里省去的是内存页表读取，不是直接省去 DRAM。
* **页表行由数据缓存截获（省的才是 DRAM 次数）**：PSC 不缓存 4 KB 页的 PTE，命中 `PDE Cache` 后仍须读取 PTE。包含该表项的 64 B 行在缓存中才是 0 次 DRAM；该行已逐出就要读 1 次 DRAM。
* **回填与重执**：`PPN` 与权限位写入 TLB，原访存重放并取得业务数据 PA。业务数据行能否命中缓存，是另一笔账。

| 翻译段状态 | 表项读次数 | 其中落到 DRAM 的读取 |
| --- | ---: | ---: |
| `PDE Cache` 命中，PTE 行在缓存 | 1 | 0 |
| `PDE Cache` 命中，PTE 行不在缓存 | 1 | 1 |
| 页结构缓存全未命中，四级页表行都在缓存 | 4 | 0 |
| 页结构缓存全未命中，四级页表行都不在缓存 | 4 | 4 |

设页结构缓存裁剪后还需 $r$ 次表项读，其中有 $k$ 条页表行不在缓存，则翻译段有 $k$ 次 DRAM 读取，且 $0\leq k\leq r\leq4$。业务数据行不在缓存时，再加上 1 次；不能只用 `TLB Hit/Miss` 推断总次数。

2. **阶段 B 边界（`L1D / L2 / L3 Data Cache Hit / Miss`）**：
   阶段 A 输出 24-bit `PPN_Data`，与直通的 12-bit `off` 拼成 **`PA = {PPN_Data, off}`**。L1D 可以提前用页内位选组，但物理标签比较要等 PA 完成；L2、L3 再按 PA 继续查询，最终提取 64 B 业务数据。

### 3. 物理地址（PA）的 $\text{GF}(2)$ 异或散列与通道交织收敛

请求因 `Cache Miss` 穿透至内存控制器（IMC）后，硬件通过多比特异或散列网络将一维系统物理地址（PA）打散映射至多维并发单元（4 个独立 Sub-channel 的 $M/D/1$ 服务台与 32 个存储体组 BG），以消除 $2^N$ 幂次访问步长引发的队列坍缩与行冲突。

---

#### 1. 纯低位直映的局部坍缩与硬件多比特异或树模型

在 64GB 物理地址空间（`PA[35:0]`）中，最低 6 位 `PA[5:0]` 固定作为 64B 缓存行块内偏移（Line Offset）由 PHY 直接消费，实际参与 IMC 路由与颗粒寻址的为核心 **30 位地址向量** `PA[35:6]`。

若硬件直接拉铜线将低位 `PA[7:6]` 接至 2-to-4 通道译码器、将 `PA[10:8]` 接至 3-to-8 存储体组（BG）译码器，当程序以 $\Delta = 2^N\text{ Bytes}$（ $N \ge 8$，如矩阵列遍历常见的 $256\text{B} \sim 64\text{KB}$ 步长）访问时，二进制加法 $\text{PA} + 2^N$ 仅翻转第 $N$ 位及更高位，低位 `PA[10:6]` 电平恒定锁死。全部访存流将 100% 集中砸向单一 Sub-channel 的单一 BG，其余 3 个子通道闲置，有效带宽坍缩至 $1/4$，且因高位 Row 频繁翻转触发严重的同 Bank 行冲突（Row Thrashing）。

为打破 $2^N$ 步长驻波，现代 x86 处理器在 CHA/TAD 与 IMC 内部通过掩码寄存器（如 `CHANNEL_HASH` / `MAD_INTER_CHANNEL`）将中高位物理地址折叠注入低位译码器。抽头位的选取严格遵循三大微架构物理边界：

1. **保序突发吞吐**：低位驱动位（如 `PA[6]`）必须单次直连参与异或，确保连续 $+64\text{B}$ 顺序流在通道间严格执行 Round-Robin 轮询；
2. **跨越页与缓存驻波区**：抽头密集分布在 **`PA[12:21]`（ $4\text{KB} \sim 2\text{MB}$ 滑动窗口）**，一方面跨越 4KB 操作系统虚实页边界（`PA[11]`）打散页分配碎片，另一方面精准覆盖 L1D/L2 Cache Set 冲突步长；同时避免使用过高位（如 `PA[28+]`），防止在局部工作集内因高位恒定不变而退化为低位直映；
3. **1-Cycle 时序收敛**：受限于 IMC 仲裁流水线关键路径延迟，单个选择位的异或树逻辑深度严格控制在 $1 \sim 2$ 级（即 $2 \sim 4$ 个抽头输入）。

面向主流 **16Gb $\times 8$ DDR5 颗粒（64GB `PA[35:0]`）**，路由段 `PA[10:6]` 的 5 组硬件异或门电路方程定义如下：

```math
\begin{aligned} Y_6\ (\text{SubCh\_Sel}) &= \text{PA}_{6} \oplus \text{PA}_{13} \oplus \text{PA}_{16} \oplus \text{PA}_{17} \\ Y_7\ (\text{Ch\_Sel}) &= \text{PA}_{7} \oplus \text{PA}_{14} \oplus \text{PA}_{15} \oplus \text{PA}_{18} \\ Y_8\ (\text{BG}_{0}) &= \text{PA}_{8} \oplus \text{PA}_{13} \oplus \text{PA}_{16} \\ Y_9\ (\text{BG}_{1}) &= \text{PA}_{9} \oplus \text{PA}_{14} \oplus \text{PA}_{17} \\ Y_{10}\ (\text{BG}_{2}) &= \text{PA}_{10} \oplus \text{PA}_{15} \oplus \text{PA}_{18} \end{aligned}
```

其余 25 根高位地址线 `PA[35:11]` 不经过异或门，直接由直通铜线（Pass-through）原样透传至下游译码器用于生成 `Bank / Row / Col` 颗粒内部坐标：

$$Y_k = \text{PA}_k \qquad (k \in \\{11, 12, \dots, 35\\})$$

#### 2. 从逻辑门网表到 $\text{GF}(2)$ 线性矩阵的代数升维

##### （1） $\text{GF}(2)$ 算术法则与单行点积等价性

二元伽罗瓦域 $\text{GF}(2) = (\\{0, 1\\}, \oplus, \cdot)$ 是直接对应数字逻辑门的模 2 算术体系：

* **域加法（ $\oplus$，硬件 XOR 门）**：无进位加法， $0 \oplus 0 = 0,\\; 1 \oplus 0 = 1,\\; 1 \oplus 1 = 0$。其核心代数定律是**自消律（任何元素均为自身的加法逆元， $x \oplus x = 0$）**。
* **域乘法（ $\cdot$，硬件 AND 门 / 物理走线通断）**： $1 \cdot x = x$（导线连通，信号接入 XOR 门）， $0 \cdot x = 0$（导线断开，信号绝缘）。

利用域乘法表示物理连线的“通断”，上述每一条多输入异或门方程均可严格展开为对全部 30 根输入地址线 `PA[35:6]` 的线性内积。以 $Y_6$（Sub-channel 选择位）为例：

```math
\begin{aligned} Y_6 &= (\mathbf{1}\cdot\text{PA}_6) \oplus (0\cdot\text{PA}_7) \oplus \dots \oplus (\mathbf{1}\cdot\text{PA}_{13}) \\ &\quad \oplus (0\cdot\text{PA}_{14}) \oplus (0\cdot\text{PA}_{15}) \oplus (\mathbf{1}\cdot\text{PA}_{16}) \oplus (\mathbf{1}\cdot\text{PA}_{17}) \oplus \dots \oplus (0\cdot\text{PA}_{35}) \end{aligned}
```

同理，任意一根直通导线 $Y_k\ (k \ge 11)$ 等价于仅在第 $k$ 位系数为 $1$、其余系数全为 $0$ 的平凡内积：

$$Y_k = (0\cdot\text{PA}_6) \oplus \dots \oplus (\mathbf{1}\cdot\text{PA}_k) \oplus \dots \oplus (0\cdot\text{PA}_{35})$$

##### （2） $30 \times 30$ 完整网表方阵组装

将 5 条异或路由方程与 25 条高位直通方程纵向堆叠，电路网表即在 $\text{GF}(2)^{30}$ 向量空间上严格收敛为矩阵乘法 $\mathbf{Y} = \mathbf{M} \cdot \mathbf{PA}$。

为直观展示硬件接线拓扑，重点展开核心抽头所在的 `PA[18:6]` 子空间（矩阵空白处与点 $\cdot$ 均代表 `0`，代表物理绝缘； $\mathbf{1}$ 代表主对角线基准线；普通 $1$ 代表高位异或抽头接入）：

```math
\left[\begin{array}{c} Y_6\ (\text{SubCh\_Sel}) \\ Y_7\ (\text{Ch\_Sel}) \\ Y_8\ (\text{BG}_0) \\ Y_9\ (\text{BG}_1) \\ Y_{10}\ (\text{BG}_2) \\ \hline Y_{11} \\ Y_{12} \\ Y_{13} \\ \vdots \\ Y_{35} \end{array}\right] = \left[\begin{array}{ccccc|ccccccccc} \mathbf{1} & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & 1 & \cdot & \cdot & 1 & 1 & \cdot & \cdots \\ \cdot & \mathbf{1} & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & 1 & 1 & \cdot & \cdot & 1 & \cdots \\ \cdot & \cdot & \mathbf{1} & \cdot & \cdot & \cdot & \cdot & 1 & \cdot & \cdot & 1 & \cdot & \cdot & \cdots \\ \cdot & \cdot & \cdot & \mathbf{1} & \cdot & \cdot & \cdot & \cdot & 1 & \cdot & \cdot & 1 & \cdot & \cdots \\ \cdot & \cdot & \cdot & \cdot & \mathbf{1} & \cdot & \cdot & \cdot & \cdot & 1 & \cdot & \cdot & 1 & \cdots \\ \hline \cdot & \cdot & \cdot & \cdot & \cdot & \mathbf{1} & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdots \\ \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \mathbf{1} & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdots \\ \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \mathbf{1} & \cdot & \cdot & \cdot & \cdot & \cdot & \cdots \\ \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \ddots \\ \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \cdot & \mathbf{1} \end{array}\right]_{30 \times 30} \cdot \left[\begin{array}{c} \text{PA}_6 \\ \text{PA}_7 \\ \text{PA}_8 \\ \text{PA}_9 \\ \text{PA}_{10} \\ \hline \text{PA}_{11} \\ \text{PA}_{12} \\ \text{PA}_{13} \\ \vdots \\ \text{PA}_{35} \end{array}\right]
```

将 30 维输入向量按分隔线划分为 **5 维低位待散列段 $\mathbf{L} = \text{PA}[10:6]$** 与 **25 维高位寻址段 $\mathbf{H} = \text{PA}[35:11]$**，该 $30 \times 30$ 方阵可写成分块矩阵标准式：

$$\underbrace{\begin{bmatrix} \mathbf{L}' \\ \mathbf{H}' \end{bmatrix}}_{\mathbf{Y}_{30 \times 1}} = \underbrace{\begin{bmatrix} \mathbf{I}_{5 \times 5} & \mathbf{A}_{5 \times 25} \\ \mathbf{0}_{25 \times 5} & \mathbf{I}_{25 \times 25} \end{bmatrix}}_{\mathbf{M}_{30 \times 30}} \cdot \underbrace{\begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix}}_{\mathbf{PA}_{30 \times 1}} = \begin{bmatrix} \mathbf{L} \oplus \mathbf{A}\mathbf{H} \\ \mathbf{H} \end{bmatrix}$$

其中：

* **$`\mathbf{I}_{5 \times 5}`$ 与 $`\mathbf{I}_{25 \times 25}`$ 为单位对角矩阵**：代表 `PA[10:6]` 的自身基准输入与 `PA[35:11]` 的 25 根直通铜线；
* **$\mathbf{0}_{25 \times 5}$ 为全零矩阵**：代表硬件严格禁止用低位地址反向污染高位地址；
* **$\mathbf{A}_{5 \times 25}$ 为右上角抽头掩码矩阵**：对应硬件寄存器中的 XOR 掩码位（有抽头处为 $1$，无抽头处为 $0$）。由于主对角线全为 $1$，且主对角线下方（ $i > j$ 区域）严格全为 $0$，无论 $\mathbf{A}$ 内部包含多少个 $0$，整体方阵 $\mathbf{M}$ 在代数上严格构成**单位上三角矩阵（Unit Upper Triangular Matrix）**，其行列式恒等于主对角线元素乘积： $\det(\mathbf{M}) = 1^{30} = 1 \neq 0$。

#### 3. 全局零碰撞双射证明：正向与反向映射的严格唯一性

硬件异或散列并非软件中多对一的“有损压缩哈希”，而是 $\text{GF}(2)^{30} \to \text{GF}(2)^{30}$ 的严格**双射（Bijection）**。以下从正反两个方向严格证明**每一个 $\mathbf{PA}$ 到 $\mathbf{Y}$ 的正向映射，以及每一个 $\mathbf{Y}$ 到 $\mathbf{PA}$ 的反向逆映射均是绝对单一且唯一的**。

##### （1） 正向单一性证明（ $\mathbf{PA} \to \mathbf{Y}$ 单射 / 零哈希碰撞）

**命题**：给定任意两个不同的输入物理地址 $\mathbf{PA}^{(1)} \neq \mathbf{PA}^{(2)}$，其映射出的硬件坐标必然不同（ $\mathbf{Y}^{(1)} \neq \mathbf{Y}^{(2)}$），绝不存在“两个不同物理地址落入同一电容单元”的碰撞。

**严格证明（反证法与核空间分析）**：
假设存在两个物理地址 $\mathbf{PA}^{(1)} = [\mathbf{L}_1, \mathbf{H}_1]^T$ 与 $\mathbf{PA}^{(2)} = [\mathbf{L}_2, \mathbf{H}_2]^T$，在经过硬件异或门网络后产生了完全相同的硬件物理坐标 $\mathbf{Y}^{(1)} = \mathbf{Y}^{(2)}$，即：

$$\begin{bmatrix} \mathbf{L}_1 \oplus \mathbf{A}\mathbf{H}_1 \\ \mathbf{H}_1 \end{bmatrix} = \begin{bmatrix} \mathbf{L}_2 \oplus \mathbf{A}\mathbf{H}_2 \\ \mathbf{H}_2 \end{bmatrix}$$

1. **比对下半部高位向量**：由方程组第二行直接得出 $\mathbf{H}_1 = \mathbf{H}_2$；
2. **代入上半部低位向量**：将 $\mathbf{H}_1 = \mathbf{H}_2$ 代入第一行，得：

$$\mathbf{L}_1 \oplus \mathbf{A}\mathbf{H}_1 = \mathbf{L}_2 \oplus \mathbf{A}\mathbf{H}_1$$


3. **两边同时异或 $\mathbf{A}\mathbf{H}_1$**：利用 $\text{GF}(2)$ 下的异或自消律（ $\mathbf{V} \oplus \mathbf{V} = \mathbf{0}$），等式两侧消去公共项：

$$(\mathbf{L}_1 \oplus \mathbf{A}\mathbf{H}_1) \oplus \mathbf{A}\mathbf{H}_1 = (\mathbf{L}_2 \oplus \mathbf{A}\mathbf{H}_1) \oplus \mathbf{A}\mathbf{H}_1 \implies \mathbf{L}_1 \oplus \mathbf{0} = \mathbf{L}_2 \oplus \mathbf{0} \implies \mathbf{L}_1 = \mathbf{L}_2$$



综合 $\mathbf{H}_1 = \mathbf{H}_2$ 且 $\mathbf{L}_1 = \mathbf{L}_2$，必然推导出 $\mathbf{PA}^{(1)} = \mathbf{PA}^{(2)}$。这与“两输入地址不同”的前提矛盾，证毕：

* **当两地址高位不同（ $\mathbf{H}_1 \neq \mathbf{H}_2$）时**：即便散列后碰巧落入同一 Sub-channel 和同一 BG（ $\mathbf{L}_1' = \mathbf{L}_2'$），由于直通铜线完整保留了 $\mathbf{H}_1 \neq \mathbf{H}_2$，颗粒内部必然译码出不同的 `Row / Col` 坐标；
* **当两地址高位相同（ $\mathbf{H}_1 = \mathbf{H}_2$，故必有 $\mathbf{L}_1 \neq \mathbf{L}_2$）时**：两侧异或同一个常数掩码向量 $\mathbf{A}\mathbf{H}_1$，结果必然满足 $\mathbf{L}_1' \neq \mathbf{L}_2'$，两笔事务被物理切分至不同的 Sub-channel 或不同的 BG，物理走线完全隔离。

##### （2） 反向单一性证明（ $\mathbf{Y} \to \mathbf{PA}$ 满射且唯一可逆 / 零容量盲区）

**命题**：对于底层 DRAM 阵列中任意一个合法的硬件物理坐标 $\mathbf{Y} = [\mathbf{L}', \mathbf{H}']^T \in \text{GF}(2)^{30}$，必然存在**唯一**的系统物理地址 $\mathbf{PA} = [\mathbf{L}, \mathbf{H}]^T$ 与之对应，且反向解码电路就是正向电路本身（对合自逆性， $\mathbf{M}^{-1} = \mathbf{M}$）。

**严格证明（显式构造唯一逆解）**：
给定任意目标硬件坐标 $\mathbf{Y} = [\mathbf{L}', \mathbf{H}']^T$，求解线性方程组 $\mathbf{M} \cdot \mathbf{PA} = \mathbf{Y}$：

$$\begin{cases} \mathbf{L} \oplus \mathbf{A}\mathbf{H} = \mathbf{L}' & \text{--- (式 1)} \\ \mathbf{H} = \mathbf{H}' & \text{--- (式 2)} \end{cases}$$

1. **唯一确定高位 $\mathbf{H}$**：由（式 2）直接锁定高位唯一解 $\mathbf{H} = \mathbf{H}'$；
2. **唯一反解低位 $\mathbf{L}$**：将 $\mathbf{H} = \mathbf{H}'$ 代入（式 1），得 $\mathbf{L} \oplus \mathbf{A}\mathbf{H}' = \mathbf{L}'$。在等式两边同时异或已知向量 $\mathbf{A}\mathbf{H}'$：

$$\mathbf{L} \oplus (\mathbf{A}\mathbf{H}' \oplus \mathbf{A}\mathbf{H}') = \mathbf{L}' \oplus \mathbf{A}\mathbf{H}' \implies \mathbf{L} = \mathbf{L}' \oplus \mathbf{A}\mathbf{H}'$$



将唯一解整理为矩阵形式：

$$\underbrace{\begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix}}_{\mathbf{PA}} = \begin{bmatrix} \mathbf{L}' \oplus \mathbf{A}\mathbf{H}' \\ \mathbf{H}' \end{bmatrix} = \underbrace{\begin{bmatrix} \mathbf{I}_{5 \times 5} & \mathbf{A}_{5 \times 25} \\ \mathbf{0}_{25 \times 5} & \mathbf{I}_{25 \times 25} \end{bmatrix}}_{\mathbf{M}} \cdot \underbrace{\begin{bmatrix} \mathbf{L}' \\ \mathbf{H}' \end{bmatrix}}_{\mathbf{Y}} \implies \mathbf{M}^2 = \begin{bmatrix} \mathbf{I} & \mathbf{A} \oplus \mathbf{A} \\ \mathbf{0} & \mathbf{I} \end{bmatrix} = \mathbf{I} \implies \mathbf{M}^{-1} = \mathbf{M}$$

**物理意义总结**：

* **$\mathbf{PA} \to \mathbf{Y}$ 单一性**：保证了 CPU 发出的 $2^{30}$ 个 64B 缓存行请求在物理上**绝不发生写覆盖碰撞**；
* **$\mathbf{Y} \to \mathbf{PA}$ 单一性**：保证了底层 DRAM 颗粒上的 $2^{30}$ 个物理存储块都有唯一的系统物理地址能够寻址访问，**绝不存在无法被操作系统触达的“幽灵容量盲区”**；且当请求依据 5-bit 路由结果 $\mathbf{L}'$ 进入指定通道与 BG 后， $\mathbf{L}'$ 的信息已物化为当前所处的物理队列位置，硬件可直接剥离 `PA[10:6]`（Bit-Stripping），仅凭 25-bit 高位 $\mathbf{H}'$ 与 6-bit 块内偏移完成颗粒内部寻址，实现 100% 零容量浪费。

### 4. 虚拟地址（VA）到物理通道的交织传递机制与代数闭环

将物理地址构成式 $\text{PA} = \\{\text{PA}, \text{VA}[11:0]\\}$ 代入第 3 节的 IMC 异或方程，并以 **`Bit 12`（4KB 页表映射边界）** 为界拆分为“页内免查表直通项”与“页表映射项”：

```math
\begin{aligned} \text{Ch\_Sel} &= \underbrace{\mathbf{VA_{7}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{14} \oplus \text{PA}_{15} \oplus \text{PA}_{18} \right)}_{\text{页表映射出的物理页常数 } c_{\text{ch}}} \\ \text{SubCh\_Sel} &= \underbrace{\mathbf{VA_{6}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{13} \oplus \text{PA}_{16} \oplus \text{PA}_{17} \right)}_{\text{页表映射出的物理页常数 } c_{\text{sub}}} \\ \text{BG}_{i} &= \underbrace{\mathbf{VA_{8+i}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{13+i} \oplus \text{PA}_{16+i} \right)}_{\text{页表映射出的物理页常数 } c_{\text{bg}, i}} \quad (i \in \{0, 1, 2\}) \end{aligned}
```

将上述 5 个选择器输出合并为 5-bit 硬件并发单元坐标向量 $\mathbf{S} = [\text{Ch\\_Sel}, \text{SubCh\\_Sel}, \text{BG}_2, \text{BG}_1, \text{BG}_0]^T \in \text{GF}(2)^5$，即得到虚拟地址（VA）到物理并发单元的直接代数传递方程：

$$\mathbf{S}(\text{VA}) = \underbrace{\text{VA}[10:6]}_{\text{软件直控的虚拟页内坐标}} \oplus \underbrace{\mathbf{c}\big(\text{PageTable}(\text{VA})\big)}_{\text{页表映射决定的 5-bit 相位向量 } \mathbf{c}}$$

该传递方程证明：**物理地址层面的通道与存储体组交织特性，通过 $\text{GF}(2)^5$ 向量加法被完整传递至虚拟地址空间。**

#### 1. 页内访问（ $\Delta \lt 4\text{KB}$）： $\text{GF}(2)^5$ 仿射平移置换与 32 路确定性均摊

当程序在任意单个 $4\text{KB}$ 虚拟页内部访问时，虚拟页号 `VA[47:12]` 恒定不变，由 TLB 或第 4 级页表输出的物理页基址 `PA[35:12]` 为固定常数，右侧相位向量 $\mathbf{c} \in \text{GF}(2)^5$ 随之锁死为常向量：

* **仿射平移不改变分布均匀性**：在有限域向量空间 $\text{GF}(2)^5$ 中，常向量加法 $\mathbf{S}(\mathbf{x}) = \mathbf{x} \oplus \mathbf{c}$ 是一次严格的**仿射平移置换（Affine Coset Permutation）**。页表映射（无论分配到哪个物理页）仅改变了该 4KB 页面在硬件通道上的**起始轮询相位 $\mathbf{c}$**，而完全保持页内各 Cache Line 之间的互斥交织拓扑。
* **软件直控的 32 路并发平铺**：虚拟地址 `VA` 在页内每递增 $64\text{B}$，直通位 `VA[7:6]` 翻转一次，经过 $\text{VA}[7:6] \oplus [c_{\text{ch}}, c_{\text{sub}}]^T$ 洗牌后，必然**无碰撞地依次轮询全部 4 个 Sub-channel**；每递增 $256\text{B}$，直通位 `VA[10:8]` 翻转一次，必然**依次轮询全部 8 个 Bank Group**。任何 $4\text{KB}$ 虚拟页内的 64 个 Cache Line，在物理上恒定以每个单元 2 个 Cache Line 的配额，绝对均匀地平铺在全平台 $4\text{ SubCh} \times 8\text{ BG} = 32$ 个并发硬件单元上。

#### 2. 跨页访问（ $\Delta \ge 4\text{KB}$）：大页直通锁定与物理页熵散列

当程序以 $\Delta = 4\text{KB}, 8\text{KB}, 32\text{KB}$ 等跨页步长访问时，页内偏移 `VA[10:6]` 恒定为常数 $\mathbf{v}_0$，此时 $\mathbf{S}(\text{VA}) = \mathbf{v}_0 \oplus \mathbf{c}(\text{PA})$，交织效果由跨页时不断切换的相位向量 $\mathbf{c}$ 驱动：

1. **2MB 大页（HugePage）下的确定性代数交织**：
开启 2MB 大页（ $2^{21}\text{B}$）后，页表映射在第 3 级（`PD` 表）终止，**免查表直通位从 `VA[11:0]` 直接扩展至 `VA[20:0]`（即 $\text{PA}[20:0] \equiv \text{VA}[20:0]$）**。此时相位向量 $\mathbf{c}$ 所依赖的 `PA[18:13]` 全部转化为免查表直通的虚拟地址位 `VA[18:13]`，传递方程直接退化为纯虚拟地址异或：

$$\mathbf{S}(\text{VA}) = \text{VA}[10:6] \oplus \mathbf{c}(\text{VA})$$

在 $2\text{MB}$ 虚拟地址跨度内，任意 $2^N$ 跨页步长均由硬件异或门 100% 确定性地按 $1:1:1:1$ 分流至 4 个 Sub-channel。

2. **标准 4KB 页下的物理页散列交织**：
在标准 4KB 分页下，若 OS 伙伴分配器（Buddy Allocator）分配了连续物理页，则 `PA[18:13]` 随虚拟页号同步线性递增，同样触发确定性异或分流；若物理内存碎片化导致分配了离散物理页，不同物理页号（PPN）在 `PA[18:13]` 位段上携带的比特熵经异或树折叠后，使得跨页虚拟地址流在统计上仍以 $1/4$ 的等概率均匀收敛至 4 路 Sub-channel 队列中。

## 三、 内存墙：400 MHz 阵列极限、PISO 预取与多核闭环排队论

现代多核架构中，处理器算力与主存数据供给之间的失衡体现为三个物理边界：延迟受限于电容充放电 RC 常数与跨时钟域同步开销，长期停留在 $\sim 80\text{ ns}$ 量级；带宽受限于封装与主板布线的引脚密度上限，通道扩展速度远低于核心数量增长；容量受限于单通道高速信号完整性对挂载双列直插式内存模块（DIMM, Dual In-line Memory Module）数量的物理限制。

通过将空载基准延迟、动态随机存取存储器（DRAM, Dynamic Random-Access Memory）内部 $400\text{ MHz}$ 阵列并入串出（PISO, Parallel-In Serial-Out）预取守恒、上游行填充缓冲（LFB, Line Fill Buffer）信用窗口约束以及下游 $C \times \text{M/G/1}$ 排队方程联立，可以从数学上严格推演带宽与延迟在空载稳态下的正交性，以及多核高并发负载下的闭环耦合规律。

### 1. 引脚密度边界、空载延迟构成与带宽-延迟静态正交性

#### 1.1 物理互连的引脚密度边界与系统峰值带宽

穿透 L1/L2/L3 缓存的末级缓存未命中请求（LLC Miss, Last Level Cache Miss）必须跨越 CPU 封装边界访问主存。物理链路的峰值带宽由并行数据线位宽 $W_{\text{bits}}$ 与单线传输率 $f_{\text{transfer}}$ 的乘积决定（ $B_{\text{peak}} = W_{\text{bits}} \times f_{\text{transfer}} / 8$）。受限于不同物理层级的引脚密度与信号完整性，系统互连带宽自上而下逐级收敛：

* **片上网络（NoC, Network on Chip）**：单跳带宽达 $\text{TB/s}$ 级；
* **嵌入式多芯片互连桥接（EMIB, Embedded Multi-die Interconnect Bridge）/ 晶圆基底芯片封装（CoWoS, Chip-on-Wafer-on-Substrate）**：带宽为数百 $\text{GB/s}$ 级；
* **超路径互连（UPI, Ultra Path Interconnect）/ 全局内存互连（xGMI, external Global Memory Interconnect）**：单链路带宽为数十 $\text{GB/s}$ 级；
* **主存物理通道（DRAM Channel）**：受限于印制电路板（PCB, Printed Circuit Board）布线密度、过孔串扰与 DIMM 金手指引脚数，单根 DDR4/DDR5 内存条的数据总线总位宽固定为 $64\text{-bit}$（DDR5 拆分为 $2 \times 32\text{-bit}$ 子通道）。同一物理通道若挂载多根内存条（如每通道两根内存，2 DPC, 2 DIMMs Per Channel），容性负载增加与阻抗不连续会迫使 I/O 时钟 $f_{\text{clk}}$ 降频（如从 $3200\text{ MHz}$ 降至 $2400\text{ MHz}$），使单通道峰值带宽下降约 $25\\%$。

由于 CPU 访存的最小粒度为 64B 缓存行，单个 64B 请求经硬件地址译码后仅路由至唯一的目标通道（或子通道）处理，不会拆分至多条通道并行传输。设单个独立通道/子通道服务台的位宽为 $W_{\text{sub}}$，全系统包含 $C$ 个物理隔离的独立服务台，则系统总峰值带宽为单服务台峰值带宽 $B_{\text{peak, sub}}$ 的 $C$ 倍：

$$B_{\text{peak}} = C \times B_{\text{peak, sub}} = C \times \frac{W_{\text{sub}} \times f_{\text{transfer}}}{8}$$

#### 1.2 空载延迟 $T_0$ 的物理构成与静态正交推论

单次 64B 访存事务从核心发出到数据就绪的端到端总延迟 $T_{\text{total}}$，由空载基准延迟 $T_0$ 与集成内存控制器（IMC, Integrated Memory Controller）队列中的纯等待延迟 $T_{\text{queue}}$ 串联构成（请求在数据总线与控制器队列中的总耗时即为 $T_{\text{trans}} + T_{\text{queue}}$）：

$$T_{\text{total}} = \underbrace{T_{\text{on-chip}} + T_{\text{array\\_rc}} + T_{\text{trans}}}_{\text{端到端空载基准延迟 } T_0 \ (\approx 80\text{ ns})} + T_{\text{queue}}$$

空载延迟 $T_0$ 横跨核心、片上互连、内存控制器、物理层总线与 DRAM 核心阵列五个异步时钟域，其物理耗时由三大模块串联构成：

```math
\begin{cases} \text{片上路由与跨时钟域交叉（CDC, Clock Domain Crossing）同步耗时 } T_{\text{on-chip}} \approx 30 \sim 35\text{ ns} & (\text{占比 } \sim 41\%) \\ \text{DRAM 1T1C 电容阵列模拟寻址（} t_{\text{RCD}} + t_{\text{CL}} + t_{\text{RP}} \text{）耗时 } T_{\text{array\_rc}} \approx 40 \sim 45\text{ ns} & (\text{占比 } \sim 56\%) \\ \text{64B 数据总线纯突发传输耗时 } T_{\text{trans}} = \mathbf{2.5\text{ ns}} & (\text{占比 } \mathbf{3.1\%}) \end{cases}
```

**静态正交推论**：在空载稳态（ $T_{\text{queue}} = 0$）下，并行服务台数量 $C$ 不进入单笔请求的时间求和式，且占 $T_0$ 超过 $96\\%$ 的模拟寻址与片上同步耗时不受外部数据总线频率影响（I/O 频率翻倍对 $T_{\text{trans}}$ 的削减不足 $2\text{ ns}$，且被高频控制器 Gear 2/4 分频与片内纠错码 On-Die ECC, Error Correcting Code 校验延迟抵消），因此**系统峰值带宽 $B_{\text{peak}}$ 与空载延迟 $T_0$ 在数学上完全解耦（静态正交）**。

---

### 2. $400\text{ MHz}$ 阵列极限、PISO 预取守恒与服务台裂变必然性

受限于 1T1C 微型电容电荷泄放速率与灵敏放大器（Sense Amplifier）检测的 RC 物理极限，DRAM 内部存储阵列（Core Array）的放电工作频率自 DDR4 起便难以逾越，锁死在 $`f_{\text{array}} = 400\text{ MHz}`$ （阵列最小列访问周期恒为 $`T_{\text{array}} = t_{\text{CCD\_S}} = 2.5\text{ ns}`$）。相比之下，外部数据引脚（DQ）的电路传输频率 $`f_{\text{transfer}} = 2f_{\text{clk}}`$ 仍可随工艺演进持续翻倍。

为了弥合“内部阵列放电慢、外部引脚传输快”的频率鸿沟，DRAM 必须扩大 PISO（并入串出）预取缓冲器的位宽 $N$，将内部阵列每 $2.5\text{ ns}$ 一次性并行读取的 $N\text{ bit}$ 数据，转化为外部高频引脚下连续突发长度（ $\text{BL} = N$ ）的高速串行流。同时，受 CPU 缓存架构约束，单个独立调度队列（单服务台）的数据位宽 $W_{\text{sub}}$ 在一次突发（ $\text{BL} = N$ ）中传输的数据量必须严格匹配 64B（ $512\text{ bit}$ ）缓存行粒度。

将**阵列物理极限**、**PISO 时间守恒**与 **64B 粒度空间守恒**联立：

```math
\begin{cases} \text{阵列物理极限：} & f_{\text{array}} = 400\text{ MHz} \implies T_{\text{array}} = t_{\text{CCD\_S}} = \mathbf{2.5\text{ ns}} \\ \text{PISO 时间守恒：} & f_{\text{transfer}} = 2f_{\text{clk}} = \dfrac{N}{T_{\text{array}}} \implies \mathbf{T_{\text{trans}} = \frac{\text{BL}}{f_{\text{transfer}}} \equiv T_{\text{array}} = 2.5\text{ ns}} \quad (\text{BL} = N) \\ \text{64B 粒度守恒：} & \dfrac{W_{\text{sub}} \times \text{BL}}{8} = 64\text{ B} \implies \mathbf{W_{\text{sub}} = \frac{512\text{ bit}}{N}} \end{cases}
```

将上述 $W_{\text{sub}}$ 与 $f_{\text{transfer}}$ 代入第 1.1 节的单队列物理峰值带宽公式 $B_{\text{peak, sub}} = \frac{W_{\text{sub}} \times f_{\text{transfer}}}{8}$，预取深度 $N$ 在分子与分母中发生**严格代数约分**：

$$\boxed{B_{\text{peak, sub}} = \frac{W_{\text{sub}} \times f_{\text{transfer}}}{8} = \frac{1}{8} \cdot \underbrace{\left(\frac{512\text{ bit}}{N}\right)}_{W_{\text{sub}}} \cdot \underbrace{\left(\frac{N}{T_{\text{array}}}\right)}_{f_{\text{transfer}}} = \frac{64\text{ B}}{T_{\text{trans}}} = \frac{64\text{ B}}{2.5\text{ ns}} \equiv \mathbf{25.6\text{ GB/s}}}$$

这一约分过程深刻揭示了 DDR4 向 DDR5 演进的**底层数学必然性与服务台裂变机制**：

1. **单服务台效率的绝对锁死**：由于 $N$ 在公式中被严格约去，只要内部电容放电周期 $T_{\text{array}} = 2.5\text{ ns}$ 无法突破，无论外部引脚频率 $f_{\text{transfer}}$ 如何拉升，**单个服务台的纯突发传输周期（ $T_{\text{trans}} \equiv 2.5\text{ ns}$ ）、最大服务率（ $\mu_{\text{sub}} = 1/T_{\text{trans}} \equiv 0.4\text{ 请求/ns}$ ）以及峰值吞吐量子（ $B_{\text{peak, sub}} \equiv 25.6\text{ GB/s}$ ）均被物理定律绝对锁死**。单服务台根本无法消纳外部引脚提速带来的带宽红利。
2. **引脚提速向服务台数量（ $C$ ）的唯一收敛**：当外部数据线速率从 DDR4-3200 翻倍至 DDR5-6400 时，为填满恒定 $T_{\text{array}}$ 下翻倍的外部时钟沿，预取与突发长度必须从 $N = \text{BL} = 8$ 翻倍至 $16$；受 64B 粒度约束（ $W_{\text{sub}} = 512\text{ bit} / N$ ），单服务台位宽被迫从 $64\text{ bit}$ 折半为 $32\text{ bit}$。在单根 DIMM 物理总位宽恒定（ $W_{\text{total}} = 64\text{ bit}$ ）的前提下，位宽减半直接引发**服务台裂变**——独立队列数从 $C = W_{\text{total}} / W_{\text{sub}} = 1$（M/G/1）必然扩张为 $C = 2$ 个 32-bit 子通道（2×M/G/1 并发）。**简言之，DRAM 外部引脚速率的提升，在数学上被唯一地转化为独立服务台数量 $C$ 的成倍增加（总峰值带宽 $B_{\text{total}} = C \times 25.6\text{ GB/s}$ ）。**

---

### 3. 动态耦合（一）：上游 LFB 窗口约束与管道自然容量 $K_0$

每个穿透 L1 Cache 发往主存的 64B 读未命中事务，必须在核心的 LFB（单核最大深度 $N_{\max} = 16$）中占用 1 个信用槽位，直至经历端到端延迟 $T_{\text{total}}$ 数据返回后才释放。

考察单个通道/子通道服务台（峰值吞吐量子 $B_{\text{peak, sub}} = 64\text{ B} / T_{\text{trans}}$）。设该服务台分摊 $M$ 个核心，链路上的全局并发在途请求总数为 $K = M \cdot N_{\text{in-flight}}$（满窗口下 $K = M \cdot N_{\max} = 16M$）。由利特尔法则（Little's Law， $B_{\text{achieved}} = K \times 64\text{ B} / T_{\text{total}}$）除以单服务台峰值吞吐量子 $B_{\text{peak, sub}}$，完成无量纲归一化，直接导出受上游信用窗口制约的**上游窗口方程**：

$$\rho = \frac{B_{\text{achieved}}}{B_{\text{peak, sub}}} = \frac{K \cdot 64\text{ B} / T_{\text{total}}}{64\text{ B} / T_{\text{trans}}} \implies \boxed{\text{上游窗口方程：} \ T_{\text{total}} = \frac{K \cdot T_{\text{trans}}}{\rho} \quad \left(\text{即 } \rho = \frac{K \cdot T_{\text{trans}}}{T_{\text{total}}}\right)}$$

代入空载延迟 $T_{\text{total}} = T_0 = 80\text{ ns}$，自然定义无量纲的**单通道带宽延迟积（物理管道自然容量 $K_0$）**：

$$\boxed{K_0 \triangleq \frac{T_0}{T_{\text{trans}}} = \frac{B_{\text{peak, sub}} \times T_0}{64\text{ B}} = \frac{80\text{ ns}}{2.5\text{ ns}} = \mathbf{32\text{ 个在途请求}}}$$

在空载无排队极限（ $T_{\text{total}} \approx T_0$）下，总线利用率简化为 $\rho \approx K / K_0$，由此直接锁定单核访存的两条硬件边界：

* **串行指针追逐（ $K = 1$，如链表遍历 `p = p->next`）**： $\rho = 1 / 32 = 3.125\\%$，单核提取带宽仅为 $B_{\text{core}} = 25.6\text{ GB/s} \times 3.125\\% = \mathbf{0.80\text{ GB/s}}$；
* **单核满窗口并发（ $K = N_{\max} = 16$）**： $\rho = 16 / 32 = 50\\%$，单核提取带宽上限为 $B_{\text{core}} = 25.6\text{ GB/s} \times 50\\% = \mathbf{12.80\text{ GB/s}}$。

由于单核最大窗口深度小于物理管道自然容量（ $N_{\max} = 16 < K_0 = 32$），**单个核心最多只能喂饱半条内存子通道**；必须依赖多核并发（ $M \ge 2 \implies K \ge K_0$）才能使通道趋近饱和，而多核汇聚将不可避免地触发下游控制器排队。

---

### 4. 动态耦合（二）：下游 $C \times \text{M/G/1}$ 排队方程与 DDR5 靶向优化

当多核并发流量涌入包含 $C$ 个通道/子通道的内存子系统时，由 Pollaczek–Khinchine（P-K）公式与利特尔法则，第 $i \in \\{1, \dots, C\\}$ 个独立队列服务台（总线利用率 $\rho_i = B_{\text{demand, sub}}^{(i)} / B_{\text{peak, sub}}$）的纯排队等待时间 $T_{\text{queue}}^{(i)}$ 与端到端总延迟 $T_{\text{total}}^{(i)}$ 由**下游排队方程**刻画：

$$\boxed{\text{下游排队方程：} \ T_{\text{total}}^{(i)} = T_0 + \underbrace{\alpha \cdot T_{\text{trans}} \cdot \frac{\rho_i}{1 - \rho_i}}_{T_{\text{queue}}^{(i)}} \quad \left(0 \le \rho_i < 1, \ \alpha \in [0.5, 1.0]\right)}$$

式中的 $T_{\text{trans}} \equiv 2.5\text{ ns}$ 为硬件固定的纯数据突发周期，而系统拓扑特征与控制器调度效率则完全收敛于 **$\rho_i$（单队列利用率）** 与 **$\alpha$（排队波动系数）** 两个无量纲参数中：

1. **队列隔离拓扑与负载分流参数 $\rho_i$（对应 DDR5 子通道拆分与散列偏斜）**：
物理地址归属的通道由硬件译码静态固定，空闲子通道无法跨物理通路读取其他子通道颗粒电容中的数据，故系统严格为 **$C$ 个相互隔离的独立 $\text{M/G/1}$ 队列**。
   * **DDR5 倍增服务台数 $C$**：单根 DDR4 仅有 $C=1$ 个 64-bit 队列，队头发生未掩蔽行冲突时整条总线停顿；单根 DDR5 拆分为 $C=2$ 个独立的 32-bit 子通道队列，消除了跨子通道线头阻塞（HOL Blocking, Head-of-Line Blocking）。
   * **均匀散列与碰撞偏斜**：当硬件多比特异或散列（XOR Hashing）将流量均匀分发至 $C$ 个队列时，通道数 $C$ 分子分母约分，单队列利用率等同于全局利用率 $\rho_i \equiv B_{\text{demand}} / B_{\text{peak}}$；若访存步长（如 $2^N$）击穿散列掩码导致负载偏斜，则不可全局约分，热点队列在 $\rho_1 \to 1$ 时将按 $\frac{\rho_1}{1-\rho_1}$ 独立发散并阻塞全局计算。

2. **排队波动系数 $\alpha$（M/G/1 的 P-K 系数；对应 M/D/1 至 M/M/1 包络、DDR5 32 Banks 与同 Bank 刷新）**：
由 P-K 公式， $\alpha = \frac{C_a^2 + C_s^2}{2}$。本模型取 M（泊松到达， $C_a^2 = 1$），故 $\alpha = \frac{1 + C_s^2}{2}$：其中 $0.5$ 是到达侧常量， $C_s^2/2$ 才是处理侧（控制器实际发车间隔相对固定突发周期 $T_{\text{trans}} = 2.5\text{ ns}$ 的波动）。无冲突连续突发对应 **M/D/1（泊松到达 + 确定性服务， $C_s^2 = 0 \implies \alpha = 0.5$，排队系数 $1.25\text{ ns}$）**——此 $0.5$ 并非零抖动，而是服务完全确定后仍残留的泊松到达排队；频繁行冲突、读写切换气泡与刷新锁死对应 **M/M/1 悲观包络上界（ $C_s^2 = 1 \implies \alpha = 1.0$，排队系数 $2.50\text{ ns}$）**。DDR5 通过两项微架构革新将 $\alpha$ 从 $1.0$ 压向 $0.5$：
   * **独立 CA 总线 + $8\ t_{\text{CK}}$（BL16）窗口 + 32 Banks 掩蔽行冲突**：利用翻倍的数据突发周期与翻倍的 32 Banks（8 Bank Groups）在后台并行穿插预充电/激活指令，消除行冲突引起的发车间隔抖动；
   * **同 Bank 刷新（Same-Bank Refresh）消除长尾停顿**：替代 DDR4 锁死整根内存条的全 Bank 刷新（All-Bank Refresh），每次仅刷新每个 Bank Group 中的 1 个指定 Bank，其余 $3/4$ 的 Bank 正常响应读写，消除周期性长尾停顿，使排队延迟回归 $\alpha = 0.5$ 的 $\text{M/D/1}$ 确定性服务基准。

---

### 5. 动态耦合（三）：多核闭环不动点解析解与过饱和线性发散

在真实硬件中，下游排队延迟 $T_{\text{queue}}$ 升高会拉长 $T_{\text{total}}$，进而通过上游窗口方程反过来压低 LFB 槽位周转率，抑制核心发射新请求的速率。联立第 3 节**上游窗口方程**与第 4 节**下游排队方程**消去 $T_{\text{total}}$，并两边同除以 $T_{\text{trans}}$（代入 $K_0 = T_0 / T_{\text{trans}}$）：

$$\frac{K \cdot T_{\text{trans}}}{\rho} = T_0 + \alpha \cdot T_{\text{trans}} \cdot \frac{\rho}{1 - \rho} \implies (K_0 - \alpha)\rho^2 - (K + K_0)\rho + K = 0$$

舍去大于 $1$ 的非物理根，得到任意全局在途并发度 $K = M \cdot N_{\max}$ 下的闭环不动点（Fixed-Point）解析解：

```math
\boxed{\rho^\ast(K) = \frac{(K + K_0) - \sqrt{(K + K_0)^2 - 4(K_0 - \alpha)K}}{2(K_0 - \alpha)}}, \qquad \begin{cases} B_{\text{achieved}}^\ast = \rho^\ast \cdot B_{\text{peak, sub}} \\ T_{\text{total}}^\ast = \dfrac{K \cdot T_{\text{trans}}}{\rho^\ast} \\ T_{\text{queue}}^\ast = T_{\text{total}}^\ast - T_0 \end{cases}
```

代入硬件基准常数 $T_0 = 80\text{ ns}$、 $T_{\text{trans}} = 2.5\text{ ns}$、 $B_{\text{peak, sub}} = 25.6\text{ GB/s}$、 $K_0 = 32$、 $N_{\max} = 16$（取 $\text{M/D/1}$ 基准 $\alpha = 0.5$），单服务台分摊不同并发核心数 $M$ 时的闭环平衡点演进如下：

| 并发核心数 $M$（单服务台分摊） | 全局在途窗口 $K = 16M$ | 闭环稳态利用率 $\rho^\ast$ | 闭环实际带宽 $B_{\text{achieved}}^\ast$ | 闭环稳态总延迟 $T_{\text{total}}^\ast$ | 纯排队等待 $T_{\text{queue}}^\ast$ |
| --- | --- | --- | --- | --- | --- |
| **$M = 1$ 核**（欠饱和窗口受限 $K < K_0$） | $16$ | $49.26\\%$ | $12.61\text{ GB/s}$ | $81.21\text{ ns}$ | $1.21\text{ ns}$ |
| **$M = 2$ 核**（临界负反馈拐点 $K = K_0$） | $32$ | $88.91\\%$ | $22.76\text{ GB/s}$ | $89.98\text{ ns}$ | $9.98\text{ ns}$ |
| **$M = 4$ 核**（过饱和积压初期 $K = 2K_0$） | $64$ | $98.48\\%$ | $25.21\text{ GB/s}$ | $162.47\text{ ns}$ | $82.47\text{ ns}$ |
| **$M = 8$ 核**（深度过饱和线性区 $K = 4K_0$） | $128$ | $99.48\\%$ | $25.47\text{ GB/s}$ | $321.67\text{ ns}$ | $241.67\text{ ns}$ |

上表清晰地刻画出多核闭环排队系统的三阶段物理相变：当 $K < K_0$（ $M=1$）时，队列基本无积压，吞吐受限于上游 LFB 窗口（ $\rho^\ast \approx K / K_0$）；当到达临界点 $K = K_0 = 32$（ $M=2$）时， $9.98\text{ ns}$ 的排队延迟通过拉长往返周期触发闭环负反馈节流，将稳态利用率钳制在 $\rho^\ast = 88.91\\%$，避免了开环模型的无限发散；而当进入深度过饱和区 $K \gg K_0$（ $M \ge 4$）时， $\rho^\ast \to 1$（实际带宽锁死于上限 $25.6\text{ GB/s}$），此时物理飞行管道（ $T_0$）最多容纳 $K_0 = 32$ 个请求，**超出管道容量的在途信用点全部转化为控制器内的静态排队积压 $N_q^\ast \approx K - K_0$**，使上游窗口方程直接退化为并发核数 $M$ 的渐近线性函数：

$$\boxed{T_{\text{total}}^\ast(K \gg K_0) \approx K \cdot T_{\text{trans}} = M \cdot N_{\max} \cdot T_{\text{trans}} = \mathbf{40M\text{ (ns)}} \implies T_{\text{queue}}^\ast(K \gg K_0) \approx (K - K_0) \cdot T_{\text{trans}}}$$

在过饱和区内，每向单通道追加 $1$ 个满窗口流式核心，不仅无法带来任何有效带宽收益，反而会使端到端延迟刚性激增 $16 \times 2.5\text{ ns} = 40\text{ ns}$。这正是现代服务器处理器引入硬件服务质量（QoS, Quality of Service，如英特尔内存带宽分配 MBA, Memory Bandwidth Allocation），通过限制嘈杂邻居核的并发在途信用点 $K$ 使其回落至物理管道自然容量以内（ $K \le K_0$），从而在不损失主体带宽的前提下斩断线性排队尾延迟的底层数学依据。

## 四、 缓存的空间拓扑：L3 共享域、物理封装与 NUMA

### 1. L3 共享域与物理封装形态

* **L3 共享域（L3 Allocation Domain，简称共享域）**：在多级缓存体系中，L1 与 L2 采用每核私有设计以换取最低访问延迟，L3 则是核心群的数据汇聚中枢。共享域界定了哪些计算核心对当前 L3 拥有**分配**（*Allocation*，划定并占用缓存行空间）、**脏数据回写接纳**（*Dirty Line Writeback*，接收并保存上级私有缓存下刷的被修改行）与**逐出**（*Eviction*，根据替换策略移出旧缓存行）的排他性权限。域外核心无权在别域的 L3 中分配新的**缓存行**（*Cache Line*，64 字节标准数据搬运单元）或逐出旧行；域外核心若需使用该域中的数据，只能通过**全局一致性探针**（*Probe/Snoop*，跨核心索取缓存行副本的请求）拉取至自身私有 L1/L2 暂存。**缓存一致性**是全系统刚性维持的协议契约，而**共享域**是物理容量分配上的排他性边界，二者在架构上互不绑定。按具体微架构设计，共享域的物理划界分为两类：

  * **全核共享（Intel 切片与归宿代理体系）**：封装内全部计算核心共享同一池域内 L3。物理上，域内 L3 均匀切分为若干**切片**（*Slice*——硅片内部的散列结构单元，常按一核一切片配置，故 6、12、18 等非 2 的幂次均会出现；勿与封装级硅片 Die 混淆），每个切片与对应的缓存及归宿代理（CHA）捆绑并挂接在环形总线（Ring Bus）或二维网格（2D Mesh）节点上。缓存行落入哪一个切片由系统物理地址（SPA）经硬件异或散列（XOR Hash）唯一决定，核心无法挑选。
  * **分组共享（AMD CCX 体系）**：核心以固定群组为单位共享域内 L3，该群组称为**核心复合体（Core Complex，CCX）**。桌面与服务器端 Zen 1 / Zen 2 每域含 4 核，自 Zen 3 起演进为每域 8 核，L3 分配权限严格绑定于发起请求的核心所属的 CCX。

* **物理封装分类与两轴正交映射**：整颗处理器为单一裸片的称**单片封装（Monolithic Die）**，拆分为多块小芯片再互联组装的称**多片封装（Chiplet / Tile-based）**。封装内的硅片（AMD 称 Die，Intel 客户端称 Tile、服务器端称 Die）按**是否承载域内 L3** 分为两类：承载 L3 的计算硅片参与容量记账（AMD 专称 **CCD**，Intel 称 **Compute Tile / Compute Die**）；不承载 L3 的辅助硅片（AMD 的 IOD，Intel 的 Graphics / SoC / IO / Base Tile）不参与记账。注意“承载计算核心”不等于“承载 L3”——例如 Meteor Lake 的 SoC Tile 带有 2 个低功耗 E 核（LP-E），但该硅片无 L3，这 2 个核心完全落在共享域外。
多片封装将逻辑记账维度（按共享域）**与**物理记账维度（按承载 L3 的硅片）彻底解耦：一块硅片内可切出两个域（Zen 1），三块硅片也可跨硅桥拼成一个统一大域（Granite Rapids）。在对称设计下，两套账本满足守恒关系式：

$$\text{L3 总量} = \text{共享域数} \times \text{域内 L3 容量} = \text{承载 L3 的硅片数} \times \text{每硅片 L3 容量}$$

当整颗芯片仅有一个共享域时，域内 L3 容量与 L3 总量直接相等。

### 2. UMA 与 NUMA：架构实质与两条判定门槛

**均匀访存（Uniform Memory Access，UMA）**下所有核心共享前端总线与单一内存控制器，访存代价对等，但受限于并行总线的电气负载与引脚位宽，总带宽存在物理上限。现代处理器将**集成内存控制器（IMC）**收入 CPU 封装内部，插槽间改走高频点对点串行链路（Intel UPI / AMD xGMI），使内存带宽与容量随插槽数线性扩展。由此，核心访问本封装 IMC 挂载的本地内存路径极短，访问远端插槽内存则必须穿越慢速串行链路。这种**不同核心访问同一物理地址存在系统性延迟与带宽差异**的体系结构即**非均匀访存（Non-Uniform Memory Access，NUMA）**。

现代多片封装与大型片上网格将物理距离差引入了单颗封装内部。但硬件存在物理距离差并不直接等价于架构级 NUMA，构成 NUMA 必须同时满足两条刚性判据：

1. **量级显著**：核心群之间的访存延迟差价 $\Delta$ 通常需达到 **20 ns** 以上（跨插槽可达 **50\~70 ns**），或跨界带宽存在显著瓶颈，足以让操作系统的拓扑亲和调度（Affinity Scheduling）获得净收益；片内纳秒级的走线跳数差（**3\~6 ns**）在统计上直接被乱序执行掩盖。
2. **地址空间可定域**：延迟差价必须与宏观、连续的物理地址（PA）区间强绑定，而非在 **64 B** 缓存行粒度上被硬件散列打散：
   * **全片散列摊平差价（回归 UMA）**：硬件异或散列以 64 B 为粒度将连续物理地址均匀打散至全片 $N$ 个 L3 切片（CHA）与所有内存通道（IMC）。设某核心到各站点的物理延迟为 $L_1, L_2, \dots, L_N$，其访存统计期望延迟恒为 $\mathbb{E}[\text{Latency}] = \frac{1}{N} \sum_{k=1}^{N} L_k$。在大数定律下，任意核心命中近端与远端站点的比例完全相同，期望延迟与可用带宽均等，OS 无法按页做亲和调度，体系结构严格收敛为 UMA。
   * **宏观定域确立 NUMA**：唯有通过顶层系统地址译码器（SAD）将物理地址按宏观大段划界（如以 **64 MiB** 为刻度切分出数十 GiB 区间），强制令该段内的缓存行 100% 锁定在本地切片与本地 IMC 上，近端与远端核心群访问同一地址的系统性差价才正式确立，OS 也才获得按物理页（PPN）执行就近分配的抓手。

| 档位 | 物理拓扑边界 | 业界代表架构 | 延迟差价 ($\Delta$) 与跨界带宽特征 | 架构判定 | 机制实质与判据落点 |
| --- | --- | --- | --- | --- | --- |

### 3. 物理寻址的四级硬件流水与空间编织（UMA vs. SNC3）

物理上只存在插在各槽位上、内部从 `0x0` 独立编址的离散内存条（DIMM）。**通道交织（SAD/TAD）**的本质是**“空间构建”**，通过跨通道穿插将离散内存条的**通道物理地址（CPA）**拼接为连续的**系统物理地址（SPA）**；**切片散列（CHA）**的本质是**“流量负载均衡”**，在连续 SPA 上通过异或树打散片上缓存与目录查找压力。

#### 3.1 四级硬件译码流水线

当核心私有 L1/L2 未命中、发出携带 52 位物理地址 `SPA[51:0]`（常见实现为 46 位 `PA[45:0]`）的请求时，硬件按 **SAD $\rightarrow$ CHA $\rightarrow$ TAD $\rightarrow$ IMC** 四级流水逐层译码：

1. **第一级 SAD（系统地址译码器）**：抽头监测 `PA[51:26]`（64 MiB 对齐刻度），比对级联 Limit 寄存器（及多 Die 下的 `Mod-3` 算子），裁决目标插槽（Socket）与目标计算硅片（Compute Die）。SAD 仅读取高位做路由，**完整物理地址继续向下游传递，绝不截断**。
2. **第二级 CHA（缓存与归宿代理）**：在目标硅片内通过多抽头异或树将 `PA[51:6]` 折叠为归宿切片（Home CHA）坐标，查询本地 L3 Tag 与分布式目录（Directory）。命中则直接供数；未命中（Miss）则放行进入本硅片 TAD。
3. **第三级 TAD（目标地址译码器）**：执行空间逆向解构——用多抽头异或选定本硅片内的物理通道号（Target IMC Channel），从 `SPA` 中扣除段基址（及跨 Die 除 3 紧缩），**抽除（Strip）通道交织位**后右移紧缩，拼回行内偏移 `PA[5:0]`，还原出连续的通道物理地址 **CPA**。
4. **第四级 IMC（RIR 与 AMAP 译码）**：依据 SPD 参数，将完整 `CPA` 切分为 Rank 片选（CS#）、Bank Group、Bank、Row 与 Column，完成 DRAM 阵列寻址。

```
                                │ (与旁路透传的 PA[5:0] 汇合拼接)           │
                                ▼◄──────────────────────────────────────────┘
  ┌──────────────────────────────────────────────────────────────────────┐
  │       生成单根内存条内从 0x0 连续编址的【通道物理地址 CPA】          │
  │              CPA = (紧缩后的本地条带号 LSI << 6) | PA[5:0]           │
  └─────────────────────────────┬────────────────────────────────────────┘
                                │ (送入目标 IMC 通道控制器)
                                ▼

```

> **注**：`PA[51:26]` 对应的 **64 MiB**（ $2^{26}\text{ B}$）是 SAD 范围寄存器的**硬件对齐刻度**（Resolution）而非交织粒度。任何宏观地址段的起止边界均须对齐 64 MiB 的整数倍，使硬件仅用 26-bit 比较器即可完成上百 GiB 地址段的单周期判定。

以下以 **Granite Rapids（3 块 Compute Die，每 Die 含 168 MB L3 与 4 条通道，共 12 通道）** 为例，对比两种空间编织法则：

---

#### 3.2 方案 A：全局 12 通道交织（UMA 模式 / “3×4 二维拉链式”拼接与 $2^N$ 步长免疫）

由于 $12 = 3 \times 4$ 不是 2 的幂次，硬件采用 **“跨 3 Die 的 Mod-3 / Div-3 算子 + Die 内 4 通道多抽头异或”** 的正交双维法则，将 12 根内存条的 CPA 编织为单一全局 SPA，满足 $\frac{d(\text{SPA})}{d(\text{CPA})} = 12$：

1. **第一维（跨 3 Die 的 Mod-3 同源定域与 Div-3 紧缩）**：
   每个 Die 的 4 条通道横向拼成 **256 B** 的 Die 级条带，高位定义为**全局条带流水号 $\text{GSI} = \text{PA}[51:8]$**。硬件定点数电路对 `GSI` 同步执行：
   * **Mod-3 选 Die（CHA 与 IMC 同 Die 绑定 + 免疫 $2^N$ 步长）**：计算 $`\text{Target\_Die} = (\text{GSI} \oplus \text{Hash\_Die}) \bmod 3`$。该结果**同时锁定归宿 L3 切片所在 Die（Home CHA）与目标内存控制器所在 Die（Target IMC）**，确保 L3 未命中后直接在同 Die 内就近访存，消除跨 EMIB 硅桥的折返开销。同时因 $\gcd(2^N, 3) = 1$，任何 $2^N$（ $N \ge 8$）跨步循环在 `Mod-3` 下天然以周期 3 遍历全部 3 个 Die，不会锁死在单 Die 上。
   * **Div-3 紧缩空洞**：计算**本地条带索引 $\text{LSI} = \lfloor \text{GSI} / 3 \rfloor$**。全局连续的 3 个条带（如 $\text{GSI} = 0, 1, 2$）分派至 3 个 Die 后，整除 3 的商均为 $\text{LSI} = 0$（对应各 Die 本地第 0 行条带），消除跨 Die 轮询空洞。

2. **第二维（Die 内 4 通道多抽头 XOR 与剥离还原 CPA）**：
   在目标 Die 的 TAD 内，以 `PA[7:6]` 承载 4 通道选择。为防止 $S = 2^N$ 步长令 `PA[7:6]` 恒定锁死导致 3 条通道闲置，硬件采用**多抽头异或树**：

$$\text{Local\\_Ch} = \text{PA}[7:6] \oplus \text{PA}[9:8] \oplus \text{PA}[11:10] \oplus \text{PA}[13:12] \oplus \cdots$$

选定通道后，直接**抽除（Strip）`PA[7:6]` 两位**，将 `LSI` 左移 6 位拼接行内偏移，还原出单条内存内连续的 `CPA = (LSI << 6) | PA[5:0]`。

```
[底层物理实在：3 块 Compute Die，共 12 根独立内存条 (Ch 0~11)，每条内部均从 CPA = 0x0 连续编址]
  │  • Die 0: Ch 0, 1, 2, 3 (含 168MB L3)   • Die 1: Ch 4, 5, 6, 7   • Die 2: Ch 8, 9, 10, 11
  ▼ (MRC 按 3×4 正交二维法则向上编织：以 12×64B = 768B 为全通道大周期，满足 d(SPA)/d(CPA) = 12)
[向上呈现的全局连续系统物理地址空间 SPA: 0 ~ Total_Size - 1]
  │  ┌─ SPA 0x000 ~ 0x0FF (前 4 个 64B, 共 256B) ──► 全局条带 GSI = 0 (PA[51:8] = 0)
  │  │    • GSI mod 3 = 0 ──► 归属 Die 0 (对应 Die 0 的 Ch 0~3 第 0 块，LSI = ⌊0/3⌋ = 0, CPA = 0x000)

  │  │    • GSI mod 3 = 2 ──► 归属 Die 2 (对应 Die 2 的 Ch 8~11 第 0 块，LSI = ⌊2/3⌋ = 0, CPA = 0x000)

  │       • GSI mod 3 = 0 ──► 绕回 Die 0！此时本地条带号推进为 LSI = ⌊3/3⌋ = 1 (CPA 推进至 0x040!)
  │
  ▼ (CPU 核心运行时按 SPA 发起访存，硬件按四级流水执行逆向二维拆解)
[第一步：首站 CHA / SAD 顶层 Mod-3 同源定域 (锁定归宿 Die：Home CHA 与 Target IMC 同驻一 Die)]
  │  • 提取全局条带号 GSI = PA[51:8]，计算 Target_Die = (GSI ⊕ Hash_Die) mod 3
  │    ├─ 1/3 概率命中本地 Die (零硅桥开销)
  │    └─ 2/3 概率经 EMIB 硅桥路由至相邻两个远端 Die (跨桥开销 +20~25 ns)
  ▼
[第二步：目标 Die 内 CHA 切片散列 (全封装 504 MB L3 合为单一全局共享域)]
  │  • 在 Target_Die 内部经多抽头 XOR 找到归宿 Home CHA，查询 L3 Tag 与一致性目录
  │  • 若 L3 未命中 (Miss)，无需再次跨 Die，直接下沉至本 Die 内部的本地 TAD！
  ▼
[第三步 & 第四步：目标 Die 内 TAD 4 路解构还原 CPA ──► 本地 IMC 驱动 DRAM 读写]
     • 选定本 Die 内存通道：Local_Ch = PA[7:6] ⊕ Hash_MultiTap(GSI)  (免疫 2^N 步长驻波)
     • 紧缩并剥离 PA[7:6] ：LSI = ⌊GSI / 3⌋ ──► 还原连续 CPA = (LSI << 6) | PA[5:0]
     • 送入 Target_Die 的 Local_Ch 对应 IMC (RIR/AMAP)，完成 DRAM 颗粒寻址

```

* **拓扑呈现**：任意核心访存落入本地 Die（4 通道）的概率为 $1/3$，跨 EMIB 硅桥落入远端两 Die（8 通道）的概率为 $2/3$。该模式汇聚 12 通道总带宽与 504 MB 统一 L3，抹平各核期望延迟，固件在 ACPI（Advanced Configuration and Power Interface，高级配置与电源接口）的 SRAT（System Resource Affinity Table，系统资源亲和表）中仅暴露 **1 个 Proximity Domain 0（UMA 视图）**。

### 4. 固件阶段演进：从 UEFI/MRC 到 ACPI 表构建

硬件比较器与异或树电路在流片后固定，但整机采用何种交织模式、如何分段，由主板固件在开机流程中动态决定：

**UEFI 引导（SEC / PEI） $\longrightarrow$ MRC 执行内存训练与四级寄存器编排 $\longrightarrow$ DXE 阶段生成 ACPI SRAT / SLIT 表移交 OS。**

1. **SEC（安全阶段）**：平台上电复位，执行微码加载与硬件鉴权。
2. **PEI（预 EFI 初始化阶段）与 CAR 状态**：此时 DRAM 尚未激活，CPU 将片内 L3 缓存配置为“只命中不逐出”的临时内存，即 **CAR（Cache-as-RAM）**。在 CAR 栈环境下，UEFI 加载执行芯片原厂提供的保密二进制模块——**MRC（Memory Reference Code）**。MRC 依次完成物理探测训练与 SAD / CHA / TAD / IMC 四级寄存器注入，打通主存寻址后拆除 CAR，并在 DXE 阶段构建 ACPI 表：


#### SAD 级联 Limit 比较器与 ACPI SRAT / SLIT 换算

硬件 SAD 规则寄存器（如 `DRAM_RULE_CFG`）**不设 `Base` 字段，仅存储 26-bit 的上界块号 `Limit`（以 64 MiB 即 `PA[51:26]` 为刻度）**。硬件采用级联优先比较器：Rule 0 默认以 `0` 为下界，Rule $i$ 自动以前一条规则的上界 `Limit_{i-1}` 为隐式下界，单周期并行锁定首条满足 `PA[51:26] < Limit_i` 的规则：


由于底层寄存器属厂商私有定义，UEFI 将其转化为标准 **ACPI 表**移交 OS：

* **SRAT（系统资源亲和性表）**：建立抽象节点号 **Proximity Domain**，通过 `Processor Local x2APIC Affinity` 与 `Memory Affinity` 结构体，将逻辑核心及显式字节跨度（`Base Address` 与 `Address Length`）绑定至对应 Domain。
* **SLIT（系统局部距离信息表）**：量化节点间相对访存代价，规范固定本地域距离为 `10`（跨 EMIB 硅桥通常为 `13~14`，跨 UPI 插槽为 `21~28`），供 Linux 构建内存回退链表（`zonelist`）。

以 Node 0 配置 **64 GiB**、Node 1 配置 **128 GiB**（共 **192 GiB**）为例，软硬件表项换算关系如下：

| 物理内存节点区间 | 硬件 SAD 寄存器配置（硅片控制面）<br>（粒度：64 MiB 块，比较 `PA[51:26]`，**仅存 Limit**） | ACPI SRAT 描述结构体（OS 抽象面）<br>（粒度：1 字节，64 位无符号整数，**显式 Base + Length**） | 软硬件区间映射实质 |
| --- | --- | --- | --- |
| **Node 0 区间**<br>（**0 ~ 64 GiB**） | • **Rule 0 Limit**：`0x0400`（ $1024 \times 64\text{ MiB} = 64\text{ GiB}$）<br>• **硬件判决**：`PA[51:26] < 0x0400` $\rightarrow$ `Node 0` | • **Proximity Domain**：`0`<br>• **Base Address**：`0x0000_0000_0000_0000`（0 B）<br>• **Address Length**：`0x0000_0010_0000_0000`（64 GiB） | Rule 0 以 `0` 为隐式下界，匹配第 `0 ~ 1023` 块；固件左移 26 位转为字节长度填入 SRAT。 |
| **Node 1 区间**<br>（**64 ~ 192 GiB**） | • **Rule 1 Limit**：`0x0C00`（ $3072 \times 64\text{ MiB} = 192\text{ GiB}$）<br>• **硬件判决**：Rule 0 未命中且 `PA[51:26] < 0x0C00` $\rightarrow$ `Node 1` | • **Proximity Domain**：`1`<br>• **Base Address**：`0x0000_0010_0000_0000`（64 GiB）<br>• **Address Length**：`0x0000_0020_0000_0000`（128 GiB） | 硬件以 Rule 0 的 `0x0400` 为隐式下界；固件计算出差值（`0x0C00 - 0x0400 = 0x0800` 块 $= 128\text{ GiB}$），向 OS 显式呈报基址与长度。 |

### 5. 经典双插槽（两路 NUMA）全链路路由

在双路服务器（Intel 切片体系）中，每颗 CPU 封装的 2D Mesh 上挂载着**计算站点**（Core + 私有 L1/L2 + L3 切片 + **CHA**）与**独立 I/O 站点**（IMC、**KTIA** 即 UPI 端口控制器、PCIe/IIO）。当插槽 0 核心访问插槽 1 的远端物理地址时，端到端路由如下：

```
┌────────────────────【 插槽 0（Socket 0：请求发起方本地封装） 】────────────────────────────────────────┐
│ ① 请求核：私有 L1/L2 未命中，MMU/TLB 已将虚拟地址 VA 翻译为系统物理地址 SPA                           │
│    │                                                                                                  │
│    ▼                                                                                                  │
│  首站 CHA（请求核所在网格站点的本地代理）                                                             │
│  内置【第一级：SAD 系统地址译码器】：抽头比对 PA[51:26] 级联 Limit 寄存器                             │
│  （例如双槽各插 64 GiB 内存时，PA[36] = 0 归属插槽 0，PA[36] = 1 归属插槽 1）                         │
│    │                                                                                                  │
│    ├─► [判定为本地地址 (Socket 0)]                                                                    │
│    │     └─► 首站 CHA 运行 XOR 算得本封装归宿 CHA 坐标 ──► 经本地 2D Mesh 转发至目标 CHA              │
│    │           ├─ 命中本地 L3 切片或片内目录（单播探针从本槽其他核索回脏行）──► 返回请求核            │
│    │           └─ L3 未命中 ──► 本地 TAD (剥离交织位还原 CPA) ──► 本地 IMC ──► 本地 DRAM              │
│    │                                                                                                  │
│    └─► [判定为跨槽远端地址 (Socket 1)]                                                                │
│        （本地免检：不作归宿、不查本地 L3 Tag、不碰本地 TAD/IMC）                                      │
│          │                                                                                            │
│          ▼ [沿插槽 0 片内 2D Mesh 单播走线直达边缘网关]                                               │
│        KTIA 0（插槽 0 的 UPI 出站控制器 / 协议网关）                                                  │
│          │                                                                                            │
│          ├─► 打包为 UPI 协议 Flit 报文，封装【4 大核心载荷】：                                        │
│          │   ┌────────────────────────────────────────────────────────────────────┐                   │
│          │   │ 1. SrcNode   = Socket 0 (源插槽号，指明数据回传的收件方)           │                   │
│          │   │ 2. DstNode   = Socket 1 (目的插槽号，指明跨槽路由大方向)           │                   │
│          │   │ 3. ReqOpcode = RdData / RdInvOwn (事务意图：共享只读 / 独占写失效) │                   │
│          │   │ 4. SPA       = 0x10_0040_... (未经截断的完整系统物理地址)          │                   │
│          │   └────────────────────────────────────────────────────────────────────┘                   │
│          ▼                                                                                            │
│        PHY 物理层并转串发送驱动器（SerDes Tx）                                                        │
└──────────┼────────────────────────────────────────────────────────────────────────────────────────────┘
           │
           │ ② 跨插槽物理链路（主板差分串行走线，支付跨界延迟税，往返约 60~70 ns）
           │
┌──────────┼────────────────────────────────────────────────────────────────────────────────────────────┐
│          ▼                                                                                            │
│        PHY 物理层接收解串器（SerDes Rx）                                                              │
│          │                                                                                            │
│        KTIA 1（插槽 1 的 UPI 入站控制器 / 对端协议网关）                                              │
│          │                                                                                            │
│          ├─►【硬件解析 SPA】：提取完整 SPA，运行 KTIA 1 内部集成的【第二级：CHA XOR】散列逻辑，       │
│          │                    在对端切片空间中直接解出归宿坐标：如 CHA 5 的 (X, Y)                    │
│          │                                                                                            │
│          ▼ [向插槽 1 片内 2D Mesh 网格发起点对点单播注入]                                             │
│        对端归宿 CHA（Home CHA，例如插槽 1 的 CHA 5）：查对端 L3 Tag 与分布式一致性目录 (Directory)    │
│          ├─► [命中 L3 或目录]：对端 L3 切片供数 ／ 目录指向对端某核持有私有脏副本，单播探针索回       │
│          └─► [L3 未命中 Miss]：目录登记状态并放行 ──►【第三级：对端 TAD】──►【第四级：对端 IMC】      │
│                                                                                   │                   │
│          ┌────────────────────────────────────────────────────────────────────────┘                   │
│          ▼ (从对端 L3 或对端 DRAM 取得 64B 缓存行数据)                                                │
│        ③ 64B 数据行汇聚至 KTIA 1 封装出站 ──经 UPI 跨槽链路返回──► KTIA 0 ──片内 Mesh──► 填入请求核   │
│          的私有 L1/L2 缓存（不写入插槽 0 的 L3 切片）                                                 │
└────────────────────【 插槽 1（Socket 1：内存归属方对端封装） 】────────────────────────────────────────┘

```

* **首站 SAD 裁决与本地免检**：每个核所在站点的 CHA 均内置 SAD 镜像寄存器。请求进入首站 CHA 即比对高位地址裁决归属；一旦判定为跨槽远端地址，硬件立即免除本地 L3 查找，直接经片内 Mesh 单播送往 KTIA 0 打包上 UPI 链路。
* **对端归宿 CHA 目录拦截**：跨槽请求抵达插槽 1 后，不能直接发往对端 IMC，而必须先到对端归宿 CHA 查分布式目录（Directory）。这是因为对端 DRAM 数据可能已过期（最新脏副本可能正驻留在插槽 1 某核的私有 L1/L2 中）；唯有查完目录确认无脏副本且对端 L3 未命中后，才放行至对端 TAD / IMC。
* **全网 XOR 确定性单播**：两颗插槽的所有 CHA 与 KTIA 共享同一套 XOR 散列方程，任意 SPA 对应的归宿 CHA 坐标全网唯一确定。查目录、发失效探针与索回副本全程在 `请求核 <-> 归宿 CHA <-> 持有核` 间按坐标单播完成，避免了广播嗅探耗尽 UPI 带宽。
* **跨插槽 L3 容量排他隔离**：双路系统中，每颗插槽（Socket）构成一个独立的 L3 共享域硬边界。插槽 0 的 CHA 仅对本地物理地址段建账；插槽 0 核心跨 UPI 拉回的远端数据仅暂存于该核的私有 L1/L2 中，一旦被 L2 逐出（若为脏行则跨 UPI 写回插槽 1 的归宿 CHA / IMC），绝不在插槽 0 的 L3 中分配空间，在硬件底层严格兑现了第 1 节定义的共享域排他性边界。
