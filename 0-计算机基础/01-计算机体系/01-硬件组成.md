# 硬件组成

## 一、核心定义：指令与数据同池的“执行引擎”

现代存储程序式计算机（冯·诺依曼架构）的本质，是**指令与数据以同一种物理形式——无差别的二进制位模式（Bit Patterns）——同处同一存储空间**。程序（内存中的原生硬件指令序列）常驻于内存；CPU 内部只有其流经时的瞬态电平与缓存副本。CPU 在时钟驱动下不断从内存中载入二进制编码；这组编码走哪条硬件通路，就获得哪种语义解释：在取指通路上，地址由程序计数器（PC）给出，位模式送入指令译码器，作为指令解析并驱动控制逻辑；在访存通路上，地址由访存指令计算给出，位模式作为操作数载入处理器（或作为运算结果写入内存），作为数据处理。

在软件视角下，看似具备不同抽象层级的“程序”，在物理层面同样都是无差别的二进制位模式。C++ 等编译型语言的源码由编译器直接翻译为硬件指令集对应的原生机器码（Machine Code）并写入可执行文件；程序运行时，机器码被载入内存，CPU 的取指通路依据程序计数器（PC）给出的地址抓取并作为硬件指令执行。Python 等解释型语言则多一层抽象：解释器先把源码编译为面向虚拟机指令集的字节码（Bytecode，常缓存于 `.pyc` 文件中），再由解释器自身的取指-执行循环逐条解释——在物理硬件看来，字节码始终只是解释器处理的数据，真正驱动硬件运转的只有解释器自身的原生机器码。

* **部件与循环**：这是机器的最小逻辑模型——静态上由 CPU（执行引擎）与内存（状态容器）构成，动态上由取指-执行循环持续驱动。

  * **CPU（执行引擎）**：包含寄存器组、缓存、算术逻辑单元（ALU）与控制逻辑。寄存器中一部分随程序流转动态更新（如 PC）。引擎驱动经典五级处理：取指、译码、执行、访存、写回。运算与分支在执行阶段完成；取数在访存阶段自缓存读出并于写回阶段写入寄存器；存数在访存阶段将数据排入存储缓冲区（Store Buffer），随后更新 L1D，仅当该行被逐出缓存层级时才逐级回写 DRAM；写回阶段只更新内部寄存器，不访存。

  * **内存（状态容器）**：独立于 CPU 之外，以统一的二进制位模式容纳所有指令与数据。CPU 内部的多级缓存是内存局部的镜像副本。

  * **动态驱动（取指-执行循环与流水线冲突）**：各阶段在时钟节拍下重叠推进（时钟周期为相邻上升沿间隔；各部件频率各异、同源倍频，不存在全机统一周期）。由于流水线深度重叠，流水线填满时每一拍都有取指阶段在读指令；一旦有访存指令走到访存阶段，同一拍还需读写数据。若两者共用单一存储阵列与端口，同拍争抢必然引发结构冲突（Structural Hazard），导致流水线气泡。

* **微架构破局（基于访问频次的端口分化）**：根据各层级承受的访问频次与并发冲突概率，缓存在微架构上呈现出物理形态的分化：

  * **L1 的分裂（微架构哈佛）**：物理拆分为 L1I（指令）与 L1D（数据）两个独立阵列与独立端口，使取指与访存彻底并行，根除这一级的结构冲突。硬约束在于**同拍并发的端口需求**：流水线填满时，取指通路每拍必占一次访问；而访存通路依指令流中访存指令的疏密，呈**多拍一次（运算指令流经时）或连续每拍一次（密集访存指令流经时）**。由于单端口阵列每拍只能服务一次请求，只要某拍有访存指令抵达访存阶段，单端口下就必然与取指发生同拍争抢。这种常态化的峰值冲突无法靠调度弥补，只能靠拆分阵列、独立端口来保障吞吐。

  * **L2/L3 的汇合（回归冯·诺依曼）**：由于 L1 极高的命中率过滤了绝大多数请求，真正穿透到 L2、L3 的缺失（Miss）访问频次骤降一至两个数量级（往往数十拍才发生一次）。在如此稀疏的访问频次下，取指缺失与数据缺失在同拍发生碰撞的概率微乎其微；即便撞上，输家也只是推迟一拍启动（阵列流水，每拍可接收一次新访问，占用只在启动那一拍，不是占满整个命中延迟），而它的下一次到达远在数十拍之后，这一拍不会累积成队列。偶发的单拍排队完全可以容忍，根本没有必要再维持物理拆分与多端口的高昂硬件开销。因此，下级缓存直接合并为统一的单一缓存（Unified Cache），两条通路在此排队复用同一端口；而统一混装带来的指令与数据容量动态共享、空间利用率提升，则是顺水推舟的额外收益。

## 二、 虚拟地址到物理介质的全链路拓扑与 DDR5 物理驻留机制

在现代 x86 计算体系中，软件视角的内存是一片平坦、连续的虚拟字节数组；而在硅片与电路板构成的物理世界里，不存在抽象的“内存池”。**数据在写入的那一刻，其比特流即通过硬件页表转换与 $\text{GF}(2)$ 线性散列，刚性落位在某根特定 DIMM、某组特定颗粒内部的微小电容阵列里。**

### 1. 全链路纵览：从虚拟地址到物理介质的十二级穿透

当 CPU 核心（Core）执行一条访存指令（如 `MOV`）时，64 位虚拟地址（VA）严格遵循以下十二级硬件路径向底层物理介质穿透：

$$\text{Core} \rightarrow \text{Cache (L1/L2/L3)} \xrightarrow{\text{Ring/Mesh 选路}} \text{IMC (MC0/MC1)} \rightarrow \text{Channel} \rightarrow \text{Sub-channel} \rightarrow \text{DIMM Slot} \rightarrow \text{Rank} \rightarrow \text{Bank Group} \rightarrow \text{Bank} \rightarrow \text{Row} \rightarrow \text{Column} \leftrightarrow \text{SSD}$$

1. **Core（处理器核心与 MMU/TLB）**：执行指令并生成虚拟地址（VA）。核心通过查询旁路 **TLB（地址速查表）** 或由硬件页表遍历器（PMH）检索进程私有页表，将 VA 转换为系统物理地址（PA）。若页表项未驻留（`Present = 0`），则触发缺页异常（`#PF`），由操作系统调度链路末端的 **SSD** 换入 4KB 页面。
2. **Cache（L1 $\rightarrow$ L2 $\rightarrow$ L3 缓存层级）**：获得 PA 后，硬件以 **64 Bytes（Cache Line）** 为粒度，使用物理地址标签（Physical Tag）依次检索 L1D、L2 与共享 L3（LLC）。仅当三级缓存全部未命中（Miss）或发生脏行写回（Write-back）时，访存请求才穿透缓存边界进入片上互连网络。
3. **片上互连与 IMC（CHA/TAD 译码器 $\rightarrow$ MC0 / MC1）**：请求在 L3 出口处（CHA/TAD 译码器）经多比特异或散列计算主通道归属，通过片上网络（Ring/Mesh）路由至独立内存控制器 **MC0** 或 **MC1**，随后分发至 Sub-channel A 或 Sub-channel B 的独立读写队列（RPQ/WPQ，构成 4 个独立的 $M/D/1$ 硬件服务台）。
4. **Channel（内存主通道）**：主板 PCB 上物理隔离的传输通道。主流双通道平台配置 **2 个 64-bit Channel（Channel 0 与 Channel 1）**，由 MC0 与 MC1 一对一管辖。
5. **Sub-channel（DDR5 独立子通道）**：单个 64-bit Channel 在出 CPU 引脚时即被硬切分为 **2 个完全独立的 32-bit Sub-channel（Sub-channel A 与 Sub-channel B）**。全平台共形成 **4 个独立 Sub-channel**，各自具备专属的命令/地址总线（CA Bus）与 32-bit 数据总线（DQ Bus）。
6. **DIMM Slot（板级物理插槽）**：每个 32-bit Sub-channel 总线上通过 Fly-by 菊花链串联挂载 **2 个物理插槽（Slot 0 与 Slot 1，即 2DPC 布局）**。每根物理内存条的左、右两个半区分别服务于所属通道的 Sub-channel A 与 Sub-channel B。
7. **Rank（条内颗粒群逻辑面 / Package Rank）**：在选定插槽的单个 32-bit Sub-channel 半区内，由同一根片选信号（`CS#`）同步唤醒的一组 DRAM 颗粒。以 $\times 8$ 位宽颗粒为例，每 **4 颗 $\times 8$ 颗粒并联**（ $4 \times 8\text{-bit} = 32\text{-bit}$）构成服务于该子通道的 **1 个物理 Rank**（单面条 1Rx8 含 `Rank 0`，双面条 2Rx8 含正反面 `Rank 0/1`）。
8. **Bank Group（存储体组，BG）**：DRAM 颗粒晶圆（Die）内部的第一级并行分区。DDR5 包含 **8 个 Bank Group（BG0 ~ BG7）**，跨 BG 连续访问可跑满短列延迟（ $`t_{\text{CCD\_S}} = 8\text{ 拍} = 2.5\text{ ns}`$ ），同 BG 内连续访问则受制于长列延迟（ $`t_{\text{CCD\_L}} = 12 \sim 16\text{ 拍}`$ ）。
9. **Bank（存储体）**：每个 BG 内部含 **4 个独立 Bank**（单颗芯片共 32 个 Bank）。每个 Bank 拥有一套完全独立的行缓冲（Row Buffer / Sense Amplifiers）与状态机。
10. **Row（水平字线，Wordline）**：Bank 二维矩阵的水平坐标。`ACT` 命令附上 16-bit 行地址导通字线，单颗 $\times 8$ 颗粒激活 $1\text{KB}$，单子通道 Rank 内 **4 颗并联颗粒同步激活 $4 \times 1\text{KB} = \mathbf{4\text{KB}}$ 电荷**，锁存至该 Bank 的 Row Buffer 中。
11. **Column（垂直位线，Bitline）**：Bank 二维矩阵的垂直坐标。当目标 Row 已驻留 Row Buffer 时，`RD`/`WR` 命令通过列地址从 $4\text{KB}$ 行缓冲（含 64 个 Cache Line）中选通目标列，驱动 **BL16（Burst Length 16）** 在 32-bit 总线上连续突发传输 16 拍，吐出 $32\text{ bits} \times 16 = \mathbf{64\text{ Bytes}}$。
12. **SSD（非易失性块存储边界）**：位于 DRAM 寻址链路之外的后备存储。发生缺页或换出时，OS 通过 NVMe/PCIe 总线以 **4KB Page** 为粒度执行 DMA 块搬移。

### 2. 虚拟页号到物理框号的映射机制（ $f: \text{VPN} \rightarrow \text{PFN}$）：稀疏基数树与 TLB 端点缓存

在硬件寻址体系中，地址转换**从不作用于完整地址**。无论是 48 位虚拟地址（`VA[47:0]`）还是 36 位系统物理地址（`PA[35:0]`，对应 64GB 物理内存），在硬件结构上均被严格切分为 **“页号/框号 + 12 位页内偏移（`off[11:0]`）”** 两部分：

```text
         VA (48 bits)                                        PA (36 bits, 64GB)
   ┌──────────────┬────────────┐                       ┌──────────────┬────────────┐
   │   VPN (36b)  │  off (12b) │                       │   PFN (24b)  │  off (12b) │
   │   VA[47:12]  │  VA[11:0]  │                       │   PA[35:12]  │  PA[11:0]  │
   └──────┬───────┴─────┬──────┘                       └──────┬───────┴─────┬──────┘
          │             │                                     ▲             ▲
          │             └──────────────────┬──────────────────┴─────────────┘
          │                                │    低 12 位偏移量旁路直通 (PA[11:0] === VA[11:0])
          ▼                                │    (从未进入页表与 TLB)
   ┌───────────────────────────────────────┴───────────────────────────────────────┐
   │  映射函数 f: VPN (36b) ──► PFN (24b)    • 多级页表 = 函数 f 的稀疏基数树表示   │
   │                                         • 核心 TLB = 函数 f 的端点求值结果缓存 │
   └───────────────────────────────────────────────────────────────────────────────┘

```

页表与 TLB 的唯一输入是高 36 位 **虚拟页号（VPN，Virtual Page Number）**，唯一输出是高 24 位 **物理框号（PFN，Physical Frame Number）**；低 12 位偏移量自始至终在页表体系之外旁路直通。因此，**页表不是 $\text{VA} \rightarrow \text{PA}$ 的中间项，而是函数 $f: \text{VPN} \rightarrow \text{PFN}$ 的中间表示。**

$$f: \underbrace{\\{0,1\\}^{36}}_{\text{定义域：}2^{36}\text{ 个虚拟页 (VPN)}} \longrightarrow \underbrace{\\{0,1\\}^{24}}_{\text{值域：}2^{24}\text{ 个物理框 (PFN)}}$$

#### 1. 为什么需要虚拟内存？低 12 位何时诞生？为什么以 4KB 物理框实现 64:1 压缩？

| 核心概念 / 字段 | 硬件位段（以 64GB 为例） | 物理意义与硬件生成机制 |
| --- | --- | --- |
| **VPN（虚拟页号）** | `VA[47:12]`（36 bits） | 软件视角的连续 4KB 虚拟页编号。解决两大硬件刚需：(1) **编译期地址隔离**（不同进程可使用相同的虚拟起始地址而不撞车）；(2) **碎片化内存连续化**（将 C++ 大数组或 PyTorch 张量的连续 `VPN` 映射至物理上离散的 `PFN` 空洞）。 |
| **PFN（物理框号）** | `PA[35:12]`（24 bits） | DRAM 物理空间中按 $4\text{KB}$（ $2^{12}\text{B}$）对齐的真实物理槽位编号（Frame Number）。64GB 内存共含 $2^{24} = 16,777,216$ 个 4KB 物理框。 |
| **off（页内/框内偏移）** | `VA[11:0]` $\equiv$ `PA[11:0]`<br>（12 bits，直通） | **诞生时刻**：在请求进入 MMU/TLB **之前**，由 CPU 核心的地址生成单元（AGU）在执行访存指令（如计算指针 `base + 0xABC`）的瞬间直接算出。<br>**直通原因**：OS 分配物理内存的最小单位是整块 4KB 物理框。当虚拟页映射到物理框时，框内 4,096 个字节作为刚性整体搬移，相对字节座位号（`0x000 ~ 0xFFF`）恒定不变，故 `PA[11:0]` 直接继承 `VA[11:0]`。 |

* **为什么叶表项只管到 4KB 物理框（`PFN`），而不直接映射 64B Cache Line？（64:1 压缩率与二元事务边界）**
  1. **页表与 TLB 的 64:1 空间压缩**：一个 4KB 物理框内部连续排列着 **$64\text{ 个 Cache Line} \times 64\text{B} = 4096\text{B}$**。直通的 12 位偏移 `VA[11:0]` 被硬件自然切分为两半：**`VA[11:6]`（6 bits，定位框内第 $0 \sim 63$ 号 Cache Line）** 与 **`VA[5:0]`（6 bits，定位行内第 $0 \sim 63$ 号字节）**。由于这 64 个 Cache Line 在物理框内绝对连续，页表叶节点只需用 **1 个 8B 表项（PTE）记录 1 个 24-bit `PFN`**，即可与直通的 `VA[11:6]` 组合寻址全部 64 个 Cache Line。若改为直接映射每个 64B Cache Line（仅直通 `VA[5:0]`），页表体积将暴涨 **64 倍**，单条 TLB 词条的覆盖范围也将缩水 **64 倍**。
  2. **越过 MMU 后的二元事务退化**：一旦 `PFN`（24b）在 MMU 出口处与直通的 `VA[11:0]`（12b）完成拼接生成 36-bit `PA`，“4KB 页/框”的软件管理使命即刻终结。在下半场的 L1/L2/L3 数据缓存与 IMC 内存控制器中，硬件不再感知“4KB 页”，所有片上路由与缓存存取均退化为纯粹的 **`(PA[35:6] 物理行地址, 64B 数据载荷)` 二元硬件事务**。

#### 2. 四级稀疏基数树（Radix Tree）：表项二元分类与四步位拼接算术

由于映射函数 $f$ 的定义域高达 $2^{36}$ 条 `VPN`，若采用一维平坦数组存储页表，单个进程仅页表就需消耗 $2^{36} \times 8\text{B} = \mathbf{512\text{GB}}$ 物理内存。为消除空白地址开销，硬件将 36 位 `VPN` 切分为 **4 段 9-bit 索引**（ $36 \div 9 = 4$ 级；57 位虚拟地址 LA57 则为 $45 \div 9 = 5$ 级），构建出按需分配的 **512 叉稀疏基数树（`PML4 -> PDPT -> PD -> PT`）**：

* **单张表页的固定尺寸**：每一级表页本身固定占用 **1 个 4KB 物理框**，内含 $512 \text{ 项（9 bits 索引）} \times 8\text{ Bytes/项（3 bits 字节偏移）} = 4096\text{ Bytes}$（注意 $9\text{b} + 3\text{b} = 12\text{b}$）。进程未申请的虚拟地址分支在高层级表项中直接置 `Present = 0`，下级表页在物理内存中根本无需分配。
* **64 位表项的同构位布局与两类语义（非叶指针 vs. 叶节点函数值）**：
所有层级的 64-bit 表项（`PML4E / PDPTE / PDE / PTE`）共享完全相同的硬件位段，且**低 12 位 `Bit[11:0]` 与虚拟地址、物理地址坐标均无关**（因所有 4KB 框的起始物理地址低 12 位恒为 `0`，硬件利用这 12 个比特存放 `Present`、`R/W`、`PS` 等控制标志）：

```text
 63        62 59    52 51       36 35                       12 11  9 8  7  6  5  4  3  2  1  0
┌───────────┬────────┬───────────┬───────────────────────────┬─────┬──┬──┬──┬──┬──┬──┬──┬──┬──┐
│    NX     │ 保护键 │ 保留(全0) │      PFN (PA[35:12])      │ AVL │G │PS│D │A │P │P │U │R │P │
│ (禁执行)  │ (PKEY) │ (64GB系统)│ • 非叶表项: 下级表框的PFN │     │  │  │  │  │C │W │/ │/ │  │
│           │        │           │ • 叶表项  : 目标数据框PFN │     │  │  │  │  │D │T │S │W │  │
└───────────┴────────┴───────────┴───────────────────────────┴─────┴──┴──┴──┴──┴──┴──┴──┴──┴──┘
                                               ▲                        ▲                    ▲
                                   24-bit 物理框号 (核心载荷)      PS=1 提前终结为巨页叶节点  P=Present (在位判据)

```

| 表项类别 | 涵盖层级与条件 | `Bit[35:12]`（24-bit PFN 字段）的硬件语义 |
| --- | --- | --- |
| **1. 非叶表项（路由指针）** | `PML4E` / `PDPTE` / `PDE`（当 `PS = 0` 时） | 存放 **下一级 4KB 页表所在物理框的 `PFN`**（回答“下一张表在哪”）。 |
| **2. 叶表项（函数结果）** | 第 4 级 `PTE`（4KB 标准页）<br>或 `PDE`（`PS=1`，2MB 巨页）/ `PDPTE`（`PS=1`，1GB 巨页） | 存放 **最终目标业务数据所在物理框的 `PFN_Data`**（回答“目标数据框是哪一个”）。 |

* **硬件查表器（PMH）的四步位拼接算术（以算例 `VA = 0x0000_0080_8060_4ABC` 为例）**：
设输入虚拟地址的 4 个 9-bit 索引依次为 `VPN_4 = 1`、`VPN_3 = 2`、`VPN_2 = 3`、`VPN_1 = 4`，低 12 位偏移为 `off = 0xABC`。每走完一级，当前 9-bit 索引即被消耗丢弃，硬件将上一级表项吐出的 **`24-bit PFN`** 与下一级的 **`9-bit VPN_slice`** 及 **`3'b000`（8 字节对齐）** 直接拼接为 36-bit 物理地址（ $24 + 9 + 3 = 36\text{ bits}$）发起读取：

```text
输入 VA = 0x0000_0080_8060_4ABC ──► 切分为: VPN_4=1 (9b) | VPN_3=2 (9b) | VPN_2=3 (9b) | VPN_1=4 (9b) | off=0xABC (12b)

  【Step 1: 查第 1 级 PML4 表 (消耗 VPN_4 = 1)】
   • 拼接表项物理地址 : PA_Step1 (36b) = { CR3.PFN_PML4 (24b), VPN_4=1 (9b), 3'b000 }
   • 读取 PML4E[1]    : 剥离低 12 位标志，抽出 Bit[35:12] ──► 获得第 2 级表框号 PFN_PDPT (24b)  [VPN_4 用毕丢弃]
          │
          ▼
  【Step 2: 查第 2 级 PDPT 表 (消耗 VPN_3 = 2)】
   • 拼接表项物理地址 : PA_Step2 (36b) = { PFN_PDPT (24b), VPN_3=2 (9b), 3'b000 }
   • 读取 PDPTE[2]    : 剥离低 12 位标志，抽出 Bit[35:12] ──► 获得第 3 级表框号 PFN_PD (24b)    [VPN_3 用毕丢弃]
          │
          ▼
  【Step 3: 查第 3 级 PD 表 (消耗 VPN_2 = 3)】
   • 拼接表项物理地址 : PA_Step3 (36b) = { PFN_PD (24b), VPN_2=3 (9b), 3'b000 }
   • 读取 PDE[3](PS=0): 剥离低 12 位标志，抽出 Bit[35:12] ──► 获得第 4 级叶表框号 PFN_PT (24b)  [VPN_2 用毕丢弃]
          │
          ▼
  【Step 4: 查第 4 级 PT 叶表 (消耗 VPN_1 = 4，抵达树叶)】
   • 拼接表项物理地址 : PA_Step4 (36b) = { PFN_PT (24b), VPN_1=4 (9b), 3'b000 }
   • 读取叶表项 PTE[4]: 校验 Bit[0](Present)==1，抽出 Bit[35:12] ──► 获得最终函数值 PFN_Data = 0x1A2B3C (24b)
          │
          ▼
  【终局拼装: 在页表外部与旁路直通的 off = 0xABC 汇合】
   • PA_Data (36b) = (PFN_Data << 12) | off = { 0x1A2B3C (24b), 0xABC (12b) } = 0x1A2B3C_ABC

```

#### 3. 多进程“一进程一树”隔离、核心旁 `TLB` 分级形态与 `CR3 + PCID` 无清空切换

在现代操作系统中，DRAM 内存中的**多棵进程页表树**与 CPU 核心旁唯一的**硬件 TLB 阵列**通过 **`CR3` 寄存器**与 **`PCID`（进程上下文标识符）** 协同工作：

1. **DRAM 内存中：一进程一棵独立基数树**
系统并发运行 $N$ 个进程时，DRAM 中独立驻留 $N$ 棵四级页表树。**进程私有隔离**通过将不同进程的同号 `VPN` 映射至不同 `PFN_Data` 实现；**多进程零拷贝共享**（如共享动态库或大模型只读权重）则通过将多个进程各自私有 `PT` 叶表中的 `PTE` 指向**同一个 `PFN_Data`** 实现，物理电容中仅存唯一一份数据。
2. **核心旁 `TLB` 的真实形态：拍平路径的端点键值表（只存叶表项，不存树路径）**
四级遍历路径（`1 -> 2 -> 3 -> 4`）在进入 TLB 时被彻底抹平。TLB 不记录中间级指针，而是将 4 个 9-bit 索引重新折叠回完整的 **36-bit `VPN` 作为 Key**，将叶表项输出的 **24-bit `PFN_Data` 作为 Value**，压成一条平坦的端点键值对（巨页在 `PD/PDPT` 提前终结时，TLB 仅需匹配高 27 位或 18 位 VPN 前缀，单条 TLB 词条覆盖范围直接放大 **512 倍** 或 **262,144 倍**）：

```text
  TLB 硬件词条结构 (将四级路径 1/2/3/4 彻底折叠为 VPN -> PFN 端点映射):
 ┌──────────────────────────────┬───────────────┬─────────────────────────────────────────┐
 │   Tag (Key 1): 完整 VPN       │ Key 2: PCID   │   Value: 目标数据框 PFN_Data + 权限标志  │
 │   0x0_8080_604 (36 bits)     │ 0x001 (12b)   │   0x1A2B3C (24 bits) + R/W/X/U/G/D/A    │
 └──────────────────────────────┴───────────────┴─────────────────────────────────────────┘

```

3. **MMU 内部的三类专用硬件缓存层级（严格独立于 L1/L2/L3 数据缓存）**
在 CPU 核心的 MMU 单元内部，地址转换专用硬件按速度与职责分为两级 **TLB** 与一组 **页结构缓存**：

| MMU 内部硬件结构 | 硬件层级与真实名称 | 典型规模与命中延迟 | 缓存内容与核心职责 |
| --- | --- | --- | --- |
| **一级地址速查表** | **`L1 dTLB`**（数据 TLB）<br>`L1 iTLB`（指令 TLB） | $64 \sim 96$ 项<br>**$0.5 \sim 1$ 周期** | 缓存最热的 **叶表项结果**（`VPN + PCID -> PFN_Data`），紧贴核心 AGU。 |
| **二级地址速查表** | **`L2 sTLB`**<br>*(Second-Level Shared TLB)* | $1024 \sim 3072$ 项<br>**$7 \sim 8$ 周期** | 缓存次热的 **叶表项结果**（`VPN + PCID -> PFN_Data`）。仅当 `L1 dTLB` 与 `L2 sTLB` **均未命中**时，才触发真正的 **`TLB Miss`**。 |
| **页结构缓存**<br>*(查表加速器)* | **`Paging-Structure Caches`**<br>(`PML4 / PDPTE / PDE Cache`) | 每级数十项<br>*(位于 PMH 内部)* | 缓存 **前三级非叶表项（子树指针）**（如 `VPN[35:9] -> PFN_PT`）。发生 `TLB Miss` 时，直接跳过前三级查表，从第 4 级 `PT` 起步！ |

4. **`CR3` 寄存器结构与多进程 `PCID` 混居免清空切换**
单颗核心的 `TLB`（`L1 dTLB + L2 sTLB`）同时混居着多个活跃进程的热点叶表项。现代 x86 架构（开启 `CR4.PCIDE = 1`）通过 64 位 **`CR3` 寄存器**实现多进程安全隔离与零开销切换：

```text
  64-bit CR3 核心控制寄存器布局:
  63                  52 51                                    12 11               0
 ┌───┬──────────────────┬────────────────────────────────────────┬──────────────────┐
 │ 1 │   保留位 (全 0)   │  当前进程顶级 PML4 表框基址 (PFN_PML4)  │ 当前进程号 PCID  │
 └───┴──────────────────┴────────────────────────────────────────┴──────────────────┘
   ▲                                        ▲                              ▲
 Bit 63 = 1 (切换进程时不清空 TLB)     TLB Miss 时供 PMH 从根部查表     TLB 查找时比对进程身份

```

* **切换瞬间免清空（No-Flush）**：OS 从进程 A（`PCID=1`）切换至进程 B（`PCID=2`）时，仅执行一条写 `CR3` 指令更新 `{PFN_PML4_B, PCID=2}` 并保持 `Bit[63] = 1`，硬件**不清空 TLB**。
* **硬件双键匹配防串台**：每次访存查 TLB 时，硬件比较器强制要求 **`(TLB.PCID == CR3.PCID) && (TLB.VPN == VA[47:12])`** 同时成立方判定为 `TLB Hit`。进程 A 遗留的词条因 `PCID` 不匹配而对进程 B 天然隐身，而进程 B 上一轮时间片留下的热点词条则可直接命中。

#### 4. 地址转换域（`TLB Miss`）与物理数据缓存域（`Cache Miss`）的正交状态机

在全链路硬件执行中，**阶段 A（MMU 地址转换域：求值 `VPN -> PFN`）** 与 **阶段 B（片上数据缓存域：按 `PA` 检索 `64B` 业务数据）** 是严格串行、职责完全正交的两个独立阶段：

1. **阶段 A 边界（`TLB Hit / Miss` 与 SSD 缺页拦截）**：
核心发出 `VA` 后，高 36 位 `VPN` 进入 `L1 dTLB -> L2 sTLB` 检索。若两级 TLB 均未命中（**`TLB Miss`**），则唤醒硬件查表器 **PMH**（利用 `Paging-Structure Caches` 加速）去读取内存中的进程页表树，直至拿到第 4 级叶表项 `PTE`（*注：由于页表页本身驻留在物理内存中，PMH 发起的 `PA_Step1~4` 物理读请求在硬件连线上会自然流经片上缓存层级，但这属于查表内部微操作，与阶段 B 的业务数据检索相互独立*）。
   * **TLB 铁律只存 `Present = 1` 的词条**。当 PMH 读出叶表项 `PTE` 发现 **`Bit[0] (Present) == 0`** 时，CPU 才确知目标数据框不在 DRAM 内存中，当即抛出 `#PF` 缺页异常，由 OS 分配空闲物理框 `PFN_New` 并启动 NVMe DMA 从 **SSD** 搬入 4KB 数据，更新 `PTE` 后回填 TLB。


2. **阶段 B 边界（`L1D / L2 / L3 Data Cache Hit / Miss`）**：
仅当阶段 A 成功输出 24-bit `PFN_Data`，并与旁路直通的 12-bit `off` 拼装成完整的 36-bit 业务物理地址 **`PA = {PFN_Data, off}`** 后，请求才正式进入 **L1D $\rightarrow$ L2 $\rightarrow$ L3 数据缓存金字塔**，以 `PA[35:6]` 比对物理 Tag，提取 64B 业务数据。

```text
                       ╔═══════════════════════════════════════════════════════════╗

                ┌────────────────────────────────────┴────────────────────────────────────┐
```

| **4. `TLB Miss` + `Data Cache Miss`** | PMH 遍历页表算出 `PFN_Data` 后，目标业务数据亦未命中数据缓存，再去 DDR5 读取 64B 业务行（若叶表项 `P=0` 则触发 SSD 换页）。 | **$100 \sim 300\text{ ns}$**<br><i>(SSD 换页 $\sim 50\text{ }\mu\text{s}$)</i> |

### 3. 物理地址（PA）的 $\text{GF}(2)$ 异或散列与通道交织收敛

请求因 `Cache Miss` 穿透至内存控制器（IMC）后，硬件通过多比特异或散列网络将一维系统物理地址（PA）打散映射至多维并发单元（4 个独立 Sub-channel 的 $M/D/1$ 服务台与 32 个存储体组 BG），以消除 $2^N$ 幂次访问步长引发的队列坍缩与行冲突。

#### 1. 纯低位直映的局部坍缩与硬件多比特异或树模型

若硬件直接将低位 `PA[7:6]` 作为子通道选择位、`PA[10:8]` 作为存储体组（BG）选择位，当程序以 $\Delta = 2^N\text{ Bytes}$（ $N \ge 8$，如矩阵列遍历常见的 $256\text{B} \sim 64\text{KB}$ 步长）访问时，二进制加法 $\text{PA} + 2^N$ 仅改变第 $N$ 位及更高位，低位 `PA[10:6]` 恒定锁死。全部访存流将 100% 集中砸向单一 Sub-channel 的单一 BG，其余 3 个子通道闲置，有效带宽坍缩至 $1/4$，且因高位 Row 频繁翻转触发严重的同 Bank 行冲突（Row Thrashing）。

为打破 $2^N$ 步长驻波，现代 x86 处理器在 CHA/TAD 与 IMC 内部通过掩码寄存器（如 `CHANNEL_HASH` / `AMAP`）将中高位物理地址折叠注入低位选择器。不同代际 CPU 与 BIOS 配置的具体抽头位号存在差异，但代数结构完全同构。面向主流 **16Gb $\times 8$ DDR5 颗粒（64GB `PA[35:0]` / 128GB `PA[36:0]`）** 的标准硬件参考模型定义如下：

```math
\begin{aligned} \text{Ch\_Sel} &= \text{PA}_{7} \oplus \text{PA}_{14} \oplus \text{PA}_{15} \oplus \text{PA}_{18} \\ \text{SubCh\_Sel} &= \text{PA}_{6} \oplus \text{PA}_{13} \oplus \text{PA}_{16} \oplus \text{PA}_{17} \\ \text{BG}_{i} &= \text{PA}_{8+i} \oplus \text{PA}_{13+i} \oplus \text{PA}_{16+i} \qquad (i \in \{0, 1, 2\}) \\ \text{BA}_{j} &= \text{PA}_{13+j} \oplus \text{PA}_{15+j} \oplus \text{PA}_{20+j} \qquad (j \in \{0, 1\}) \end{aligned}
```

#### 2. $\text{GF}(2)$ 有限域线性代数体系与全局零碰撞双射证明

硬件异或散列并非软件工程中的“有损压缩哈希”，而是定义在 **二元伽罗瓦域 $\text{GF}(2)$** 上的严格满秩线性变换，在数学上保证 100% 零碰撞。

##### （1） $\text{GF}(2)$ 算术法则与地址空间的向量化

$\text{GF}(2) = (\\{0, 1\\}, \oplus, \cdot)$ 是仅包含 `0` 和 `1` 两个元素的有限域（模 2 算术体系），其运算规则直接对应数字逻辑门：

* **域加法（ $\oplus$，模 2 加 / 硬件 XOR 门）**：无进位加法， $0 \oplus 0 = 0$， $1 \oplus 0 = 1$， $1 \oplus 1 = 0$。其核心代数性质是**任何元素均为自身的加法逆元（ $a \oplus a = 0$）**，即对任意比特 $x$ 连续异或同一个掩码 $h$ 两次必然无损还原自身： $(x \oplus h) \oplus h = x \oplus (h \oplus h) = x \oplus 0 = x$。
* **域乘法（ $\cdot$，模 2 乘 / 硬件 AND 门）**： $1 \cdot 1 = 1$，其余均为 $0$。

在普通整数加法中，“进位（Carry）”会导致比特位之间产生非线性耦合；而在 $\text{GF}(2)$ 下，各个比特位严格解耦。因此，36 位物理地址 `PA[35:0]` 在数学上严格构成 **36 维线性向量空间 $\text{GF}(2)^{36}$ 中的一个列向量 $\mathbf{PA}$**，IMC 内部的异或门译码网络则等价于有限域上的**矩阵乘法 $\mathbf{Y} = \mathbf{M} \cdot \mathbf{PA}$**。

##### （2）分块单位上三角矩阵与对合自逆性（Involution）证明

将物理地址列向量 $\mathbf{PA}$ 划分为两部分：**待散列的低位路由段 $\mathbf{L}$**（如通道选择位 `PA[7:6]`）与 **提供散列熵的高位寻址段 $\mathbf{H}$**（如 `PA[35:8]`）。硬件遵循 **“低位 $\mathbf{L}$ 异或高位线性组合 $\mathbf{A}\mathbf{H}$ 定路由，高位 $\mathbf{H}$ 原样保留做寻址”** 的准则（其中 $\mathbf{A}$ 为右上角异或抽头掩码矩阵， $\mathbf{I}$ 为单位矩阵）。其分块矩阵通式与 4-bit 简化展开式（令 $L_1' = L_1 \oplus H_1, L_0' = L_0 \oplus H_0$）如下：

```math
\begin{bmatrix} \mathbf{L}' \\ \mathbf{H}' \end{bmatrix} = \begin{bmatrix} \mathbf{I} & \mathbf{A} \\ \mathbf{0} & \mathbf{I} \end{bmatrix} \begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} \mathbf{L} \oplus \mathbf{A}\mathbf{H} \\ \mathbf{H} \end{bmatrix} \quad \Longleftrightarrow \quad \underbrace{\begin{bmatrix} L_1' \text{ (Ch\_Sel)} \\ L_0' \text{ (SubCh\_Sel)} \\ H_1' \text{ (DRAM 高位)} \\ H_0' \text{ (DRAM 高位)} \end{bmatrix}}_{\text{变换后的硬件物理坐标 } \mathbf{Y}} = \underbrace{\begin{bmatrix} \mathbf{1} & 0 & 1 & 0 \\ 0 & \mathbf{1} & 0 & 1 \\ 0 & 0 & \mathbf{1} & 0 \\ 0 & 0 & 0 & \mathbf{1} \end{bmatrix}}_{\text{单位上三角变换矩阵 } \mathbf{M}} \cdot \underbrace{\begin{bmatrix} L_1 \\ L_0 \\ H_1 \\ H_0 \end{bmatrix}}_{\text{原始物理地址 } \mathbf{PA}}
```

该矩阵结构在数学上直接锁定了三条硬件属性：

1. **行列式恒为 1（满秩性）**：由于仅用高位 $\mathbf{H}$ 单向异或低位 $\mathbf{L}$，而绝不用低位去污染最高位 Row，无论右上角抽头矩阵 $\mathbf{A}$ 如何配置，变换矩阵 $\mathbf{M}$ 的左下角恒为全零矩阵 $\mathbf{0}$，主对角线恒为全 $1$。因此 $\mathbf{M}$ 是标准的**单位上三角矩阵**，其行列式恒等于主对角线元素乘积： $\det(\mathbf{M}) = 1 \neq 0$。
2. **对合自逆性（ $\mathbf{M}^{-1} = \mathbf{M}$，全局严格双射）**：在 $\text{GF}(2)$ 下将矩阵 $\mathbf{M}$ 连续乘两次，利用异或自消律 $\mathbf{A}\mathbf{H} \oplus \mathbf{A}\mathbf{H} = \mathbf{0}$，可得：

```math
\mathbf{M}^2 \cdot \begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} \mathbf{I} & \mathbf{A} \\ \mathbf{0} & \mathbf{I} \end{bmatrix} \begin{bmatrix} \mathbf{L} \oplus \mathbf{A}\mathbf{H} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} (\mathbf{L} \oplus \mathbf{A}\mathbf{H}) \oplus \mathbf{A}\mathbf{H} \\ \mathbf{H} \end{bmatrix} = \begin{bmatrix} \mathbf{L} \\ \mathbf{H} \end{bmatrix} \implies \mathbf{M}^2 = \mathbf{I} \implies \mathbf{M}^{-1} = \mathbf{M}
```

矩阵可逆（且自身即逆矩阵）证明映射 $\mathbf{Y} = \mathbf{M} \cdot \mathbf{PA}$ 是严格的**双射（Bijection）**：任意两个不同的输入物理地址 $\mathbf{PA}_A \neq \mathbf{PA}_B$，其输出的硬件物理坐标必然不同（ $\mathbf{Y}_A \neq \mathbf{Y}_B$），64GB（ $2^{36}$ 字节）空间与底层电容阵列 100% 一一对应，绝无碰撞。
3. **原位剥离（Bit-Stripping）零容量浪费**：当请求依据 2-bit 路由结果 $\mathbf{L}' = (L_1', L_0')$ 进入选定的目标 Sub-channel 后， $\mathbf{L}'$ 的信息已物化为当前所处的物理通道编号。子通道内部直接剥离 `PA[7:6]`，仅用原样保留的 28-bit 高位 $\mathbf{H} = \text{PA}[35:8]$ 与 6-bit 块内偏移 `PA[5:0]`（合计 34 bits，寻址单子通道独占的 16GB）译码内部坐标：

* **当两地址高位相同（ $\mathbf{H}_A = \mathbf{H}_B$，但低位 $\mathbf{L}_A \neq \mathbf{L}_B$）**：两侧异或同一个常数向量 $\mathbf{A}\mathbf{H}$，必有 $\mathbf{L}_A' \neq \mathbf{L}_B'$，两请求必然进入**不同的物理 Sub-channel**，物理走线完全隔离；
* **当两地址高位不同（ $\mathbf{H}_A \neq \mathbf{H}_B$）**：即便异或后碰巧 $\mathbf{L}_A' = \mathbf{L}_B'$（落入同一 Sub-channel），由于通道内部完整保留了 $\mathbf{H}_A \neq \mathbf{H}_B$，后续必然译码出**不同的 `Slot / Rank / BG / Bank / Row / Col` 坐标**，落在完全不同的物理电容上。

### 4. 虚拟地址（VA）到物理通道的交织传递机制与代数闭环

将物理地址构成式 $\text{PA} = \\{\text{PA}, \text{VA}[11:0]\\}$ 代入第 3 节的 IMC 异或方程，并以 **`Bit 12`（4KB 页表映射边界）** 为界拆分为“页内免查表直通项”与“页表映射项”：

```math
\begin{aligned} \text{Ch\_Sel} &= \underbrace{\mathbf{VA_{7}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{14} \oplus \text{PA}_{15} \oplus \text{PA}_{18} \right)}_{\text{页表映射出的物理页框常数 } c_{\text{ch}}} \\ \text{SubCh\_Sel} &= \underbrace{\mathbf{VA_{6}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{13} \oplus \text{PA}_{16} \oplus \text{PA}_{17} \right)}_{\text{页表映射出的物理页框常数 } c_{\text{sub}}} \\ \text{BG}_{i} &= \underbrace{\mathbf{VA_{8+i}}}_{\text{VA 页内直通位}} \oplus \quad \underbrace{\left( \text{PA}_{13+i} \oplus \text{PA}_{16+i} \right)}_{\text{页表映射出的物理页框常数 } c_{\text{bg}, i}} \quad (i \in \{0, 1, 2\}) \end{aligned}
```

将上述 5 个选择器输出合并为 5-bit 硬件并发单元坐标向量 $\mathbf{S} = [\text{Ch\\_Sel}, \text{SubCh\\_Sel}, \text{BG}_2, \text{BG}_1, \text{BG}_0]^T \in \text{GF}(2)^5$，即得到虚拟地址（VA）到物理并发单元的直接代数传递方程：

$$\mathbf{S}(\text{VA}) = \underbrace{\text{VA}[10:6]}_{\text{软件直控的虚拟页内坐标}} \oplus \underbrace{\mathbf{c}\big(\text{PageTable}(\text{VA})\big)}_{\text{页表映射决定的 5-bit 相位向量 } \mathbf{c}}$$

该传递方程证明：**物理地址层面的通道与存储体组交织特性，通过 $\text{GF}(2)^5$ 向量加法被完整传递至虚拟地址空间。**

#### 1. 页内访问（ $\Delta \lt 4\text{KB}$）： $\text{GF}(2)^5$ 仿射平移置换与 32 路确定性均摊

当程序在任意单个 $4\text{KB}$ 虚拟页内部访问时，虚拟页号 `VA[47:12]` 恒定不变，由 TLB 或第 4 级页表输出的物理页框基址 `PA[35:12]` 为固定常数，右侧相位向量 $\mathbf{c} \in \text{GF}(2)^5$ 随之锁死为常向量：

* **仿射平移不改变分布均匀性**：在有限域向量空间 $\text{GF}(2)^5$ 中，常向量加法 $\mathbf{S}(\mathbf{x}) = \mathbf{x} \oplus \mathbf{c}$ 是一次严格的**仿射平移置换（Affine Coset Permutation）**。页表映射（无论分配到哪个物理页框）仅改变了该 4KB 页面在硬件通道上的**起始轮询相位 $\mathbf{c}$**，而完全保持页内各 Cache Line 之间的互斥交织拓扑。
* **软件直控的 32 路并发平铺**：虚拟地址 `VA` 在页内每递增 $64\text{B}$，直通位 `VA[7:6]` 翻转一次，经过 $\text{VA}[7:6] \oplus [c_{\text{ch}}, c_{\text{sub}}]^T$ 洗牌后，必然**无碰撞地依次轮询全部 4 个 Sub-channel**；每递增 $256\text{B}$，直通位 `VA[10:8]` 翻转一次，必然**依次轮询全部 8 个 Bank Group**。任何 $4\text{KB}$ 虚拟页内的 64 个 Cache Line，在物理上恒定以每个单元 2 个 Cache Line 的配额，绝对均匀地平铺在全平台 $4\text{ SubCh} \times 8\text{ BG} = 32$ 个并发硬件单元上。

#### 2. 跨页访问（ $\Delta \ge 4\text{KB}$）：巨页直通锁定与物理页框熵散列

当程序以 $\Delta = 4\text{KB}, 8\text{KB}, 32\text{KB}$ 等跨页步长访问时，页内偏移 `VA[10:6]` 恒定为常数 $\mathbf{v}_0$，此时 $\mathbf{S}(\text{VA}) = \mathbf{v}_0 \oplus \mathbf{c}(\text{PA})$，交织效果由跨页时不断切换的相位向量 $\mathbf{c}$ 驱动：

1. **2MB 巨页（HugePage）下的确定性代数交织**：
开启 2MB 巨页（ $2^{21}\text{B}$）后，页表映射在第 3 级（`PD` 表）终止，**免查表直通位从 `VA[11:0]` 直接扩展至 `VA[20:0]`（即 $\text{PA}[20:0] \equiv \text{VA}[20:0]$）**。此时相位向量 $\mathbf{c}$ 所依赖的 `PA[18:13]` 全部转化为免查表直通的虚拟地址位 `VA[18:13]`，传递方程直接退化为纯虚拟地址异或：

$$\mathbf{S}(\text{VA}) = \text{VA}[10:6] \oplus \mathbf{c}(\text{VA})$$


在 $2\text{MB}$ 虚拟地址跨度内，任意 $2^N$ 跨页步长均由硬件异或门 100% 确定性地按 $1:1:1:1$ 分流至 4 个 Sub-channel。
2. **标准 4KB 页下的物理页框散列交织**：
在标准 4KB 分页下，若 OS 伙伴分配器（Buddy Allocator）分配了连续物理页框，则 `PA[18:13]` 随虚拟页号同步线性递增，同样触发确定性异或分流；若物理内存碎片化导致分配了离散物理页框，不同物理页框号（PFN）在 `PA[18:13]` 位段上携带的比特熵经异或树折叠后，使得跨页虚拟地址流在统计上仍以 $1/4$ 的等概率均匀收敛至 4 路 Sub-channel 队列中。



## 三、 内存墙：供需模型、预取机制与带宽-延迟排队论耦合

现代多核架构下，CPU 算力与内存供给之间的失衡被称为“内存墙（Memory Wall）”，体现在三个面向：**延迟**——一次访存花多少纳秒，几十年受电容物理限制基本不动；**带宽**——每秒能搬多少字节，在涨但涨速远落后于算力；**容量**——大规模模型与数据集受限于单机物理插槽上限。通过将“供需平衡边界”、“DRAM 内部预取与时钟域物理限制”以及“多核排队论与闭环负反馈”统一建模，可以完整揭示带宽与延迟在静态规格上的正交性及动态负载下的深度耦合。

### 1. 宏观供需漏斗模型与五级时钟域边界

数据通路自上而下为：核心 $\rightarrow$ 多级缓存（L1/L2/L3） $\rightarrow$ 内存控制器（IMC） $\rightarrow$ 物理内存通道（Channel） $\rightarrow$ DIMM。其中**缓存层级决定需求侧**（多少请求会漏到内存），**物理内存通道数量与频率决定供给侧**（内存每秒最多能搬多少字节）。

#### 1. 供给侧（物理通道的绝对吞吐上限）与漏斗层级

带宽度量单位时间内通过物理链路截面的数据总量，由**并行有效数据线位宽** $W_{\text{bits}}$ 与**单线每秒传输速率** $f_{\text{transfer}}$ 的乘积决定：

$$
\text{理论峰值带宽 } B_{\text{peak}} = \frac{W_{\text{bits}} \times f_{\text{transfer}}}{8}
$$

在系统多层拓扑中，带宽受限于各物理边界的**引脚密度墙（Pin Wall）**，呈现逐级收敛的漏斗结构：

* **片内网络（NoC Mesh / Ring）**：光刻工艺允许铺设超宽金属走线（如 512-bit 数据总线），单跳吞吐可达 TB/s 级；

* **片间硅桥（如 EMIB / CoWoS）**：依赖数十微米级的微凸点（Micro-bumps）互连，链路带宽收敛至数百 GB/s 级；

* **跨插槽链路（如 UPI / xGMI）**：受限于封装基板与 Socket 针脚，单链路通常仅有数十对差分线，依靠高频串行 SerDes 维持在数十 GB/s 级；

* **内存物理通道（DRAM Channel）**：受限于主板布线与 DIMM 金手指针脚，标准 DDR4/DDR5 单通道维持 64-bit（DDR5 拆为 $2 \times 32\text{-bit}$ 子通道）的物理总位宽。

内存控制器为每条通道驱动一个 I/O 时钟 $f_{\text{clk}}$（MHz）。DDR（Double Data Rate）在时钟上升沿与下降沿各传输一次，故每线传输率 $f_{\text{transfer}} = 2 f_{\text{clk}}$（MT/s，内存条标签“DDR5-6400”标的是 6400 MT/s，而 CPU-Z 显示的“DRAM 频率”标的是时钟频率 $f_{\text{clk}} = 3200\text{ MHz}$）。全系统的**聚合内存供给带宽**为：

$$
\boxed{B_{\text{supply}} = N_{\text{channel}} \times \underbrace{f_{\text{clk}} \times 2}_{\text{MT/s}} \times \underbrace{\frac{64\text{ bit}}{8\text{ bit/Byte}}}_{8\text{ Byte}}}
$$

其中 $N_{\text{channel}}$ 是 CPU 架构与主板布线焊死的物理主通道数，不随插入的 DIMM 数量改变。以双通道 DDR5-6400 为例，单通道峰值 $6400 \times 8 = 51.2\text{ GB/s}$（每个 32-bit 子通道为 $25.6\text{ GB/s}$），双通道聚合供给 $B_{\text{supply}} = 102.4\text{ GB/s}$；8 通道服务器则为 $8 \times 51.2 = 409.6\text{ GB/s}$。同一通道挂载的 DIMM 越多（如 2 DPC 插满 4 根），电气负载越重，迫使 $f_{\text{clk}}$ 降频（如降至 2400 MHz / 4800 MT/s），容量翻倍但峰值带宽反降约 25%（其收益在于消除落入 SSD Swap 区的微秒级卡顿）。

#### 2. 需求侧（多级缓存漏斗）与临界核数

真正消耗主存带宽的，只有穿透 L1/L2/L3 三道防线走出 CPU 封装的末级未命中（LLC Miss）请求。设单核全速发射访存请求的极限速率为 $R_{\text{core max}}$，各级缓存的局部未命中率分别为 $M_1, M_2, M_3$，则全局末级未命中率为 $M_{\text{rate}} = M_1 M_2 M_3$。全机 $N_{\text{CPU}}$ 个核心的开环总需求带宽及顶满供给时的**临界核数** $N_{\text{critical}}$ 为：

$$
B_{\text{demand}} = N_{\text{CPU}} \times R_{\text{core max}} \times M_{\text{rate}} \implies \boxed{N_{\text{critical}} = \frac{B_{\text{supply}}}{R_{\text{core max}} \times M_{\text{rate}}}}
$$

假设单核全速产生 $100\text{ GB/s}$ 原始需求，经 $M_1 = 10\\%$、 $M_2 = 20\\%$、 $M_3 = 50\\%$ 层层拦截后（ $M_{\text{rate}} = 1\\%$），单核漏到主存的带宽仅 $1\text{ GB/s}$，双通道 DDR5-6400（ $102.4\text{ GB/s}$）可支撑约 102 个核心；反之若遭遇大步长随机访存导致缓存命中率崩溃（如 $M_{\text{rate}} = 20\\%$），仅需 6 个核心就会打爆主存通道。推迟撞墙唯有两条路：**做大分子**（增加物理通道数 $N_{\text{channel}}$）与**做小分母**（优化数据空间局部性以压低 $M_{\text{rate}}$）。

#### 3. 物理延迟的拆解、五级时钟域穿越与带宽-延迟静态正交性

单次 64B 访存事务从核心发出到完整数据校验就绪所经历的端到端延迟 $T_{\text{total}}$，由**空载基准延迟** $T_0$ 与**控制器排队等待延迟** $T_{\text{queue}}$ 串联构成：

$$
T_{\text{total}} = \underbrace{T_{\text{prop}} + T_{\text{proto}} + T_{\text{route}} + T_{\text{trans}}}_{\text{端到端空载基准延迟 } T_0 \ (\approx 80\text{ ns})} + T_{\text{queue}}
$$

这四个空载分量对应着访存请求依次穿越的**五个独立时钟域**（全机以主板 100 MHz 晶振 BCLK 为基准，由各部件锁相环 PLL 独立倍频，域间通过格雷码异步 FIFO 执行时钟域交叉 CDC 同步）：

| 时钟域层级 | 典型频率（周期） | 域内核心部件与操作 | 跨域与物理耗时归属（对应 $T_0$ 分量） | 
| ----- | ----- | ----- | ----- | 
| **1. 核心域 (Core)** | $\sim 5.0\text{ GHz}$ ($0.2\text{ ns}$) | 流水线、MMU/TLB、私有 L1/L2 | 请求源头；L1/L2 查找未命中 | 
| **2. 互连/L3 域 (Uncore)** | $\sim 3.2\text{ GHz}$ ($0.31\text{ ns}$) | Ring/Mesh 总线、CHA、共享 L3 | $T_{\text{route}}$ **(片上部分)**：CDC 异步 FIFO 同步（ $\sim 1\text{ ns}$）+ Mesh 跳数路由与 L3 Tag/目录查询（合计约 $15\sim 20\text{ ns}$） | 
| **3. 内存控制器域 (IMC)** | $1600\text{ MHz}$ ($0.625\text{ ns}$) | TAD/AMAP 译码、FR-FCFS 调度器 | $T_{\text{route}} + T_{\text{proto}}$：CDC 同步 + 控制器流水线译码（DDR4 为 Gear 1 同频；DDR5-6400 跑不动 3200 MHz，采用 **Gear 2 半速分频**，每 2 个 $t_{\text{CK}}$ 发一令） | 
| **4. 内存 PHY/总线域** | $1600\sim 3200\text{ MHz}$ | PHY SerDes、PCB 走线、DQ 总线 | $T_{\text{prop}} + T_{\text{trans}}$：板级电磁波飞行 $T_{\text{prop}}$（ $\sim 1\text{ ns}$）+ 64B 纯数据突发传输 $T_{\text{trans}}$（**固定** $2.5\text{ ns}$） | 
| **5. DRAM 核心阵列域** | $400\text{ MHz}$ **（ $2.5\text{ ns}$ ）** | 1T1C 电容阵列、灵敏放大器 | $T_{\text{route}}$ **(阵列模拟死时间)**：行激活 $t_{\text{RCD}}$、列选通 $t_{\text{CL}}$、预充电 $t_{\text{RP}}$（合计约 $40\sim 45\text{ ns}$，占 $T_0$ 半壁江山） | 

**为什么“单事务空载延迟** $T_0$**”与“系统带宽** $B_{\text{peak}}$**”在物理上正交？**

1. **多通道并发不压缩单次传输**：无论系统有 2 通道还是 12 通道，单个 64B 访存事务只会被映射到唯一的单条物理通道（或 32-bit 子通道）上处理，绝不会拆开跨通道传输。增加通道数只提升并发度（Concurrency），不缩短单次传输时间 $T_{\text{trans}}$。

2. **模拟物理底噪占绝对主导**：在总计约 $80\text{ ns}$ 的空载读延迟 $T_0$ 中，64B 纯数据突发传输耗时 $T_{\text{trans}}$ 仅占 $2.5\text{ ns}$（约 $3\\%$），而 DRAM 电容充放电模拟死时间（ $40\sim 45\text{ ns}$）与片上路由/CDC 同步开销（ $30\sim 35\text{ ns}$）构成了占比超 $96\\%$ 的固定底噪。即便单线频率翻倍将 $T_{\text{trans}}$ 压缩一半，对整体 $T_0$ 的改善也微乎其微；反而高频引入的 Gear 2/Gear 4 分频、更深的控制器流水线及 SerDes/ECC 校验还会反向推高 $T_{\text{proto}}$。

### 2. $400\text{ MHz}$ 阵列时钟墙、PISO 预取机制与 DDR5 双 32-bit 子通道的诞生

为什么从 DDR3 到 DDR4 再到 DDR5，I/O 传输率翻了几倍，单次 64B 突发传输耗时 $T_{\text{trans}}$ 却始终锚定在 $2.5\text{ ns}$？为什么 DDR5-6400 必须把单根内存条拆成 **2 个独立的 32-bit 子通道**？这一切都源于 DRAM 硅片底层的 $400\text{ MHz}$**（**$2.5\text{ ns}$**）核心阵列时钟墙**。

#### 1. PISO（并入串出）预取等式：用空间并行换取外部高频

受限于微型电容泄放电荷与灵敏放大器检测的 RC 模拟特性，DRAM 内部存储阵列（Core Array）的工作频率自 DDR4 以来便被死死钉在 $400\text{ MHz}$（阵列最小列选通周期 $`T_{\text{array\_cycle}} = t_{\text{CCD\_S}} = \frac{1}{400\text{ MHz}} = \mathbf{2.5\text{ ns}}`$）。为了在内部阵列维持 $2.5\text{ ns}$ 慢速周期的前提下让外部 DQ 引脚速率逐代翻倍，每根 DQ 引脚背后都配置了一个**预取缓冲（PISO，并入串出移位寄存器）**：

```
【DRAM 颗粒内部：400 MHz 核心阵列（空间域：每隔 2.5 ns 一次性并行抓取 N bit）】

   Bit 0    Bit 1    Bit 2   ...   Bit (N-1)
     │        │        │               │
     ▼        ▼        ▼               ▼
┌──────────────────────────────────────────┐
│  预取缓冲（PISO 并入串出移位寄存器）        │ ◄── 1 次内部阵列列访问（耗时 2.5 ns）并行装填 N bit
└───────────────────┬──────────────────────┘
                    ▼
          高速输出驱动器（以 I/O 时钟 f_clk 双沿逐位移出）
                    │
                    ▼
            外部引脚 DQ0 ───► 连续突发传输 BL 次（每个时钟沿吐出 1 bit，BL = N）
                              （时间域：耗时恰好 2.5 ns 串行喷完，无缝衔接下一拍阵列抓取）

```

PISO 确立了严格的**时空转换守恒等式**（其中预取深度 $N$ 等于外部突发长度 $\text{BL}$）：

$$
\underbrace{1\text{ 根外部引脚} \times \text{BL}\text{ 次串行传输}}_{\text{时间域（外部高频 I/O，耗时 } T_{\text{trans}} = 2.5\text{ ns}\text{）}} \equiv \underbrace{N\text{ 个内部存储单元} \times 1\text{ 次并行抓取}}_{\text{空间域（内部低频阵列，周期 } T_{\text{array}} = 2.5\text{ ns}\text{）}}
$$

由于内部阵列每 $2.5\text{ ns}$ 才能向单根引脚供出 $N\text{ bit}$，单引脚所能支撑的最大传输率被锁定为 $f_{\text{transfer}} = \frac{N}{2.5\text{ ns}} = N \times 400\text{ MT/s}$。**在** $400\text{ MHz}$ **阵列时钟钉死后，将外部引脚传输率从** $3200\text{ MT/s}$**（DDR4）翻倍至** $6400\text{ MT/s}$**（DDR5）的唯一物理途径，就是将预取宽度** $N$**（即突发长度** $\text{BL}$**）从** $8n$**（BL8）强制翻倍为** $16n$**（BL16）！**

#### 2. 64B 缓存行粒度守恒：为什么 BL16 迫使 DDR5 劈裂为 $2 \times 32\text{-bit}$ 子通道？

当 DDR5 为提速将突发长度翻倍至 **BL16（连续传输 16 拍）** 后，如果依然维持 DDR4 的 **64-bit 单一通道位宽**，那么一条读/写命令在 16 拍内吐出的数据量将变成 $64\text{ bit} \times 16 = 1024\text{ bit} = \mathbf{128\text{ Bytes}}$——足足是 CPU 标准 **64B Cache Line** 的两倍！在随机访存下，每次读取 64B 都要顺带捆绑传输无用的 64B，浪费一半带宽。

为此，DDR5 顺理成章地采用“预取翻倍（ $16n/\text{BL16}$）+ 通道位宽折半（ $2 \times 32\text{-bit}$）”的正交设计：将单根 DIMM 的 64 根数据线硬切分为 **2 个独立的 32-bit 子通道（Sub-channel A 与 B，各由 4 颗** $\times 8$ **颗粒拼成）**。如此一来，单个子通道执行一次 BL16 突发传输的数据量恰好回归 $32\text{ bit} \times 16 = 512\text{ bit} = \mathbf{64\text{ Bytes}}$，且喷完耗时依然严丝合缝地等于 $16 \div 6.4\text{ GT/s} = 2.5\text{ ns}$！

| 代际规格 | 内部阵列周期（物理原点） | 每线传输率 $f_{\text{transfer}}$ | 预取深度 $N$（单颗单次抓取） | 突发长度 $\text{BL}$ | 单队列通道拼装（ $\times 8$ 颗粒数 $\times$ 位宽） | 单条命令传输量（位宽 $\times \text{BL}$） | 纯传输耗时 $T_{\text{trans}}$ | 
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | 
| **DDR3-1600** | $5.0\text{ ns}$ ($200\text{ MHz}$) | $1600\text{ MT/s}$ | $8n$ ($64\text{ bit}$) | BL8 | $8\text{ 颗} \times 8 = 64\text{ bit}$ (单通道) | $64\text{ bit} \times 8 = \mathbf{64\text{ B}}$ | $5.0\text{ ns}$ | 
| **DDR4-3200** | $2.5\text{ ns}$ **（ $400\text{ MHz}$ ）** | $3200\text{ MT/s}$ | $8n$ ($64\text{ bit}$) | BL8 | $8\text{ 颗} \times 8 = 64\text{ bit}$ (单通道) | $64\text{ bit} \times 8 = \mathbf{64\text{ B}}$ | $2.5\text{ ns}$ | 
| **DDR5-6400** | $2.5\text{ ns}$ **（ $400\text{ MHz}$ ）** | $6400\text{ MT/s}$ | $16n$ **（ $128\text{ bit}$ ）** | **BL16** | $4\text{ 颗} \times 8 = 32\text{ bit}$ **(单子通道)** | $32\text{ bit} \times 16 = \mathbf{64\text{ B}}$ | $2.5\text{ ns}$ | 

**子通道拆分在稳态与非稳态下的双重意义**：

* **首先是 64B 粒度维持装置**：在无空泡的理想稳态下，单根 DDR5 的峰值带宽（ $2 \times 32\text{ bit} \times 6.4\text{ GT/s} = 51.2\text{ GB/s}$）完全来自频率翻倍，拆分本身不改变稳态峰值乘积。

* **其次是非稳态下的“空泡消除器”**：

  1. **数据总线侧解耦队列（消除线头阻塞 HOL Blocking）**：DDR4 单通道只有 1 个队列，前一笔请求若遇行冲突停顿，整条 64-bit 总线利用率为 0%；DDR5 拆为两个独立子通道队列，子通道 A 因局部行冲突等待（约 90 个 $t_{\text{CK}}$）时，子通道 B 照常独立吐数。

  2. **命令总线侧调度窗口翻倍**：DDR4 每 4 个时钟周期（ $t_{\text{CK}}$）就必须发出一条数据命令才能喂饱总线；DDR5 每条子通道独享 CA 命令总线，且单笔 BL16 传输持续 8 个 $t_{\text{CK}}$，命令调度从容度翻倍，配合 **32 Banks（8 BG）** 与**同 Bank 刷新（Same-Bank Refresh，仅锁死局部 Bank 而非全阵列）**，将非稳态总线气泡（ $T_{\text{bubble}}$）压缩至极限。

### 3. 动态耦合机制（一）：延迟约束带宽（发射端滑动窗口 LFB）

在连续访存场景下，单核可提取的有效带宽受限于核心内部用于跟踪未决（In-Flight）访存事务的硬件状态寄存器——如 L1 Cache 的 **LFB（Line Fill Buffer，行填充缓冲，典型深度** $N_{\max} = 16$ **项）**。

每一个发往主存的 64B 读请求必须独占 1 个 LFB 槽位，直到经历完整的端到端往返时延 $T_{\text{total}}$ 返回数据后槽位才能重用。因此，单核本质上是一个**基于信用点（Credit-based）的固定容量闭环流水线**，其最大可提取带宽遵循利特尔法则（Little's Law）：

$$
B_{\text{achieved}} = \frac{N_{\text{in-flight}} \times 64\text{ B}}{T_{\text{total}}}
$$

* **串行依赖访存（**$N_{\text{in-flight}} = 1$**，如链表指针追逐 `p = p->next`）**：每次访存依赖前次结果，并发度锁死为 1：

  * 命中本地 L3（ $T = 12\text{ ns}$）： $B_{\text{achieved}} = 64\text{ B} / 12\text{ ns} \approx \mathbf{5.33\text{ GB/s}}$；

  * 访问本地 DRAM（ $T = 80\text{ ns}$）： $B_{\text{achieved}} = 64\text{ B} / 80\text{ ns} = \mathbf{0.80\text{ GB/s}}$；

  * 跨槽访问远端 DRAM（ $T = 160\text{ ns}$）： $B_{\text{achieved}} = 64\text{ B} / 160\text{ ns} = \mathbf{0.40\text{ GB/s}}$。

* **流式并发访存（满槽位流水，**$N_{\text{in-flight}} = N_{\max} = 16$**，最大在途数据量** $1024\text{ B}$**）**：

  * 访问本地 DRAM（ $T = 80\text{ ns}$）：单核提取带宽上限 $= 1024\text{ B} / 80\text{ ns} = \mathbf{12.8\text{ GB/s}}$；

  * 跨槽访问远端 DRAM（ $T = 160\text{ ns}$）：往返延迟翻倍导致槽位周转率减半，单核带宽上限腰斩为 $1024\text{ B} / 160\text{ ns} = \mathbf{6.4\text{ GB/s}}$。

### 4. 动态耦合机制（二）：带宽反噬延迟（ $C \times \text{M/D/1}$ 排队论与非线性发散）

当多个核心并发向内存下发请求，聚合流量逼近物理通道吞吐极限时，系统由“上游发射窗口受限”转入“下游控制器排队受限”。

#### 1. 物理拓扑定性：为什么多通道/双子通道是 $C \times \text{M/D/1}$ 而非 $\text{M/D/C}$？

在排队论中，共享队列多服务台系统（ $\text{M/D/C}$，如 $\text{M/D/2}$）成立的前提是**所有请求进入同一个公共队列，任意空闲服务台都能跨界代工队头的任意请求**。然而，由于第二章所述的**内存硬件静态物理归属铁律**，物理地址一旦生成，其目标 Channel 与 Sub-channel 便已死锁——即便 Sub-channel B 完全闲置，也绝无可能隔空去读取焊在 Sub-channel A 颗粒电容里的电荷。

因此，拥有 $C$ 个独立服务台（例如双通道 DDR4 的 $C=2$ 个 64-bit 通道，或双通道 DDR5 的 $C=4$ 个 32-bit 子通道）的内存子系统，**在物理本质上严格是** $C$ **个相互隔离的单服务台排队系统（**$C \times \text{Independent M/D/1}$**）**。

#### 2. 单服务台排队：从 M/D/1 真实基准到 M/M/1 悲观包络

考察任意一个独立的通道/子通道服务台 $i \in \\{1, \dots, C\\}$（以单条 DDR4-3200 64-bit 通道或单条 DDR5-6400 32-bit 子通道为统一基准，二者单服务台峰值带宽均为 $B_{\text{peak, sub}} = 25.6\text{ GB/s}$）：

1. **信道等效服务时间** $T_{\text{service}}$ **与变异系数** $C_s^2$：
   单个 64B 事务独占该服务台数据总线的有效时间 $T_{\text{service}} = T_{\text{trans}} + T_{\text{bubble}}$，其中纯突发传输时间恒为 $T_{\text{trans}} = 2.5\text{ ns}$，总线气泡 $T_{\text{bubble}}$ 来自读写转向（ $t_{\text{RTW}}/t_{\text{WTR}}$）、跨 Rank 切换（ $t_{\text{RTRS}}$）或局部未掩蔽的 Bank 冲突。设服务时间的随机方差为 $\sigma^2$，定义无量纲的**服务时间平方变异系数** $C_s^2 = \frac{\sigma^2}{T_{\text{service}}^2}$：

   * **理想无冲突基准（M/D/1，**$C_s^2 = 0$**）**：在多 Bank 充分交错且无气泡（ $T_{\text{bubble}} = 0$）的极限下， $T_{\text{service}} = T_{\text{trans}} = 2.5\text{ ns}$ 为恒定常数，方差 $\sigma^2 = 0 \implies C_s^2 = 0$（确定性服务 D）。此时硬件最大服务率 $\mu_{\text{sub}} = 1 / 2.5\text{ ns} = 0.4\text{ 请求/ns}$，对应单台峰值吞吐 $B_{\text{peak, sub}} = \mu_{\text{sub}} \times 64\text{ B} = 25.6\text{ GB/s}$。

   * **含随机冲突与调度抖动的悲观包络（M/M/1，**$C_s^2 = 1$**）**：当存在控制器重排序抖动与偶发冲突气泡时， $C_s^2 > 0$。工程上常以指数服务分布（ $C_s^2 = 1$，M/M/1 模型）作为包络复杂调度抖动的**悲观上界（Pessimistic Upper Bound）**。

   **物理边界声明**：在固定 $2.5\text{ ns}$ 传输的理想前提下，直接套用 M/M/1 公式在数学上是不自洽的；但在真实内存控制器中，由于读写转向、优先级抢占、可变长度事务合并以及偶发的局部 Bank 冲突抖动，单次信道服务占用会产生显著的随机方差（令等效 $C_s^2 > 0$）。因此，**M/M/1 公式不能代表无冲突固定传输下的物理真实解，而是工程上用于包络控制器复杂调度抖动与局部冲突惩罚的悲观上界**。

2. **泊松到达过程（M）与单服务台利用率** $\rho_i$：
   由 Palm–Khintchine 定理，片上众多乱序核心异步汇聚的缓存未命中流在统计上渐近收敛于无记忆的**泊松过程（M）**。设分流至第 $i$ 个服务台的平均到达率为 $\lambda_i = B_{\text{demand, sub}}^{(i)} / 64\text{ B}$，则该服务台的总线利用率 $\rho_i$ 为：

$$
\rho_i = \frac{\lambda_i}{\mu_{\text{sub}}} = \lambda_i \cdot T_{\text{service}} = \frac{B_{\text{demand, sub}}^{(i)}}{B_{\text{peak, sub}}} \quad (0 \le \rho_i < 1)
$$

3. **P-K 空间积压与利特尔法则时间剥离（避免** $T_{\text{trans}}$ **双重计算）**：
   对于泊松到达、一般独立服务分布的单服务台系统（M/G/1），由嵌入马尔可夫链推导出的 **Pollaczek–Khinchine（P-K）公式**给出稳态下控制器缓冲区内的**纯排队等待任务数期望** $N_q$（已从子系统总任务数 $N_{\text{total}}$ 中扣除正在总线上接受服务的平均任务数 $\rho_i$，即 $N_q = N_{\text{total}} - \rho_i$）：

$$
N_q = \frac{\rho_i^2}{1 - \rho_i} \cdot \frac{1 + C_s^2}{2}
$$

   由于前文定义的空载延迟 $T_0$ 中**已经包含了一次必经的传输耗时** $T_{\text{trans}}$，根据利特尔法则，单次请求在缓冲区内的**纯排队等待时间** $T_{\text{queue}}$**（即** $W_q = W - T_{\text{service}}$**）** 严格等于 $N_q / \lambda_i$。代入 $\lambda_i = \rho_i / T_{\text{service}}$ 消去 $\lambda_i$，即得自洽的端到端延迟方程：

$$
\boxed{T_{\text{queue}}^{(i)} = \frac{N_q}{\lambda_i} = T_{\text{service}} \cdot \frac{\rho_i}{1 - \rho_i} \cdot \frac{1 + C_s^2}{2}} \implies T_{\text{total}}^{(i)} = T_0 + \frac{1 + C_s^2}{2} \cdot T_{\text{service}} \cdot \frac{\rho_i}{1 - \rho_i}
$$

   由此可见：**在无冲突固定传输（**$T_{\text{service}} = 2.5\text{ ns}$**）下，M/D/1 物理真实解（**$C_s^2 = 0$**）的排队延迟严格只有 M/M/1 悲观上界（**$C_s^2 = 1$**）的一半**：

$$
T_{\text{queue}}^{\text{M/D/1}} = \frac{1}{2} T_{\text{service}} \cdot \frac{\rho_i}{1 - \rho_i} = \mathbf{1.25\text{ ns} \cdot \frac{\rho_i}{1 - \rho_i}}, \qquad T_{\text{queue}}^{\text{M/M/1}} = T_{\text{service}} \cdot \frac{\rho_i}{1 - \rho_i} = \mathbf{2.50\text{ ns} \cdot \frac{\rho_i}{1 - \rho_i}}
$$

   * **轻载线性区（**$\rho_i \le 0.5$**）**：当 $\rho_i = 0.5$ 时， $T_{\text{queue}}^{\text{M/D/1}} = 1.25\text{ ns}$（M/M/1 为 $2.5\text{ ns}$），完全淹没在 $T_0 = 80\text{ ns}$ 的背景底噪中。

   * **雪崩发散区（**$\rho_i \to 0.8 \sim 0.98$**）**：当 $\rho_i = 0.8$ 时， $T_{\text{queue}}^{\text{M/D/1}} = 5.0\text{ ns}$；当 $\rho_i = 0.9$ 时翻倍至 $11.25\text{ ns}$；当 $\rho_i = 0.98$ 时，分母 $(1-\rho_i) = 0.02$ 趋近于零， $T_{\text{queue}}^{\text{M/D/1}}$ 飙升至 $61.25\text{ ns}$（总延迟 $141.25\text{ ns}$），若伴随冲突抖动逼近 M/M/1 上界则高达 $122.5\text{ ns}$（总延迟突破 $202.5\text{ ns}$），排队拥塞彻底反超原生空载物理延迟。

#### 3. 多通道系统的两种计算范式：均匀约分 vs. 偏斜独立计算

将单服务台公式应用于 $C$ 个独立子通道（如 $C=4$ 个 DDR5 Sub-channel，系统总峰值带宽 $B_{\text{peak}} = C \cdot B_{\text{peak, sub}}$）时，呈现两种截然不同的工程图景：

1. **范式一：均匀散列下的“**$C$ **合一”全局约分与单根 DDR5 的拓扑等价性**
   当程序大块连续访存，或通过第二章所述的**多比特异或散列（XOR Hashing）**将任意步长流量均匀打散时，根据**泊松分流定理（Poisson Splitting）**，每个子通道分摊的到达率严格为 $\lambda_i = \lambda_{\text{sys}} / C$（即 $B_{\text{demand, sub}}^{(i)} = B_{\text{demand}} / C$）。代入利用率公式，分子分母的 $1/C$ 直接约分抵消：

$$
\rho_i = \frac{B_{\text{demand}} / C}{B_{\text{peak}} / C} = \frac{B_{\text{demand}}}{B_{\text{peak}}} \equiv \rho_{\text{sys}}
$$

   这带来两个极其重要的推论：

   * **全局等效计算**：只要负载均衡，在计算单队列利用率 $\rho$ 时，**完全可以直接用全系统总需求带宽除以全系统总峰值带宽（**$B_{\text{demand}} / B_{\text{peak}}$**）一步算出** $\rho$，再代入单服务台 $T_{\text{service}} = 2.5\text{ ns}$ 的 P-K 公式求得排队延迟！

   * **三种** $51.2\text{ GB/s}$ **架构的延迟对比与 DDR5 的演进实质**：对比同为 $51.2\text{ GB/s}$ 峰值带宽的三种方案，可以看出受 $400\text{ MHz}$ 核心时钟锁死的 $T_{\text{service}} = 2.5\text{ ns}$ 如何决定了一阶延迟标尺，以及 DDR5 如何通过消除气泡实现二阶逼近：

| 架构指标与排队参数 | 路线一：双通道 DDR4-3200  ($2 \times 64\text{-bit}$, BL8) | 路线二：假想单通道 6400  ($1 \times 64\text{-bit}$, BL8) | 路线三：单根真实 DDR5-6400  ($2 \times 32\text{-bit}$ 子通道, BL16) | 
| ----- | ----- | ----- | ----- | 
| **DRAM 内部阵列时钟要求** | $400\text{ MHz}$ ($2.5\text{ ns}$) | $800\text{ MHz}$ ($1.25\text{ ns}$，物理不可行) | $400\text{ MHz}$ ($2.5\text{ ns}$) | 
| **排队论真实拓扑分类** | $2 \times \text{独立 M/D/1}$ | $1 \times \text{高速 M/D/1}$ | $2 \times \text{独立 M/D/1}$ | 
| **单队列利用率** $\rho$ **(均匀负载)** | $B_{\text{demand}} / 51.2\text{ GB/s}$ | $B_{\text{demand}} / 51.2\text{ GB/s}$ | $B_{\text{demand}} / 51.2\text{ GB/s}$ | 
| **单次物理服务时间** $T_{\text{service}}$ | $2.5\text{ ns}$ (8 拍 @ 3.2G) | $1.25\text{ ns}$ (8 拍 @ 6.4G) | $2.5\text{ ns}$ (16 拍 @ 6.4G) | 
| **理想无冲突排队延迟 （ $C_s^2 = 0$ ）** | $1.25\text{ ns} \cdot \frac{\rho}{1-\rho}$ | $0.625\text{ ns} \cdot \frac{\rho}{1-\rho}$ | $1.25\text{ ns} \cdot \frac{\rho}{1-\rho}$ | 
| **悲观包络排队延迟 （ $C_s^2 = 1$ ）** | $2.50\text{ ns} \cdot \frac{\rho}{1-\rho}$ | $1.25\text{ ns} \cdot \frac{\rho}{1-\rho}$ | $2.50\text{ ns} \cdot \frac{\rho}{1-\rho}$ | 

* **两级硬件优化**：现代内存控制器首先靠 **FR-FCFS（就绪优先）乱序调度**在队列高负载时越过后台正在充电开行的阻塞请求，将延迟死死守在 M/M/1 悲观上界（ $C_s^2 \le 1$，前置系数 $2.50\text{ ns}$）以内；在此基础上，**DDR5 通过双 32-bit 独立子通道 + 32 Banks + 同 Bank 刷新**，在坚守 $400\text{ MHz}$ 阵列底线的前提下，仅凭一根内存条就复刻了双通道 DDR4 的 $2 \times \text{M/D/1}$ 拓扑，并将残余气泡 $T_{\text{bubble}}$ 与抖动方差 $C_s^2$ 双双压向 0，将真实运行轨迹从 M/M/1 悲观包络线强力拉回 **M/D/1（**$C_s^2 \to 0$**，前置系数** $1.25\text{ ns}$**）的理想基准线**！

2. **范式二：散列失效或** $2^N$ **步长碰撞导致的负载偏斜（必须分通道独立计算）**
   若硬件未开启高阶异或散列，或程序访存步长恰好击穿了异或掩码周期，导致 $C$ 个子通道分摊的流量严重失衡（ $B_{\text{demand, sub}}^{(1)} \gg B_{\text{demand, sub}}^{(2)}$），由于通道间绝对不可借道，此时**严禁使用全局总带宽约分**，必须对每个子通道独立计算 $\rho_i = B_{\text{demand, sub}}^{(i)} / B_{\text{peak, sub}}$。一旦某个热点子通道的 $\rho_1 \to 1$，即便全系统平均带宽利用率只有 $25\\%$（其余 3 个子通道 $\rho = 0$），热点子通道的排队延迟 $T_{\text{queue}}^{(1)}$ 也会按 $\frac{\rho_1}{1-\rho_1}$ 指数级爆炸，独自卡死整个核心群的计算进度。

### 5. 动态耦合机制（三）：闭环负反馈平衡与多核并发不动点（Fixed-Point）解析求解

在开环泊松假设下，当并发核数增加使 $\rho \to 1$ 时， $T_{\text{queue}} \to \infty$。但在真实硬件中，**访存延迟绝不会发散至无穷大，总线利用率** $\rho$ **也永远无法真正触及** $100\\%$。因为 CPU 核心的 LFB 窗口与内存控制器共同构成了一个**有限容量的闭环排队网络（Closed Queueing Network）**：下游排队延迟一旦抬头，就会反向延长上游 LFB 槽位的周转周期，主动扼杀核心发射新请求的速率。

#### 1. 双向耦合方程组与闭环平衡点（Fixed-Point）解析解

设单条物理通道（或子通道）分摊服务 $M$ 个并发核心，每个核心最大在途窗口为 $N_{\max} = 16$，则整条通道链路上同时存在的全局最大在途事务总数（Total In-Flight Credits）为硬件常数 $K = M \times N_{\max}$。联立上游窗口约束与下游 P-K 排队方程（记抖动系数 $\alpha = \frac{1 + C_s^2}{2}$，M/D/1 下 $\alpha = 0.5$，M/M/1 下 $\alpha = 1.0$）：

$$
\begin{cases}
\text{上游窗口吞吐约束：} & T_{\text{total}} = \dfrac{K \cdot T_{\text{service}}}{\rho} \\[6pt]
\text{下游 P-K 排队约束：} & T_{\text{total}} = T_0 + \alpha \cdot T_{\text{service}} \cdot \dfrac{\rho}{1 - \rho}
\end{cases}
$$

引入无量纲的**单通道带宽延迟积槽位数（管道自然容量** $K_0$**）**：

$$
K_0 = \frac{T_0}{T_{\text{service}}} = \frac{B_{\text{peak}} \times T_0}{64\text{ B}}
$$

以 $T_0 = 80\text{ ns}$、 $T_{\text{service}} = 2.5\text{ ns}$（ $B_{\text{peak}} = 25.6\text{ GB/s}$）为例，管道自然容量 $K_0 = 80 / 2.5 = \mathbf{32\text{ 个在途请求}}$（恰好对应 $M = 2$ 个满载核心的 LFB 总深度 $2 \times 16 = 32$）。将两式联立并同除以 $T_{\text{service}}$，化简得关于稳态利用率 $\rho$ 的一元二次代数方程：

$$
(K_0 - \alpha)\rho^2 - (K + K_0)\rho + K = 0
$$

舍去大于 1 的非物理根，即得任意并发度 $K$ 下的**稳态总线利用率精确解析解** $\rho^\ast$ 及对应的实际带宽 $B_{\text{achieved}}^\ast$ 与稳态总延迟 $T_{\text{total}}^\ast$：

$$
\boxed{\rho^\ast = \frac{(K + K_0) - \sqrt{(K + K_0)^2 - 4(K_0 - \alpha)K}}{2(K_0 - \alpha)}}, \qquad \begin{cases} B_{\text{achieved}}^\ast = \rho^\ast \cdot B_{\text{peak}} \\ T_{\text{total}}^\ast = \dfrac{K \cdot T_{\text{service}}}{\rho^\ast} \\ T_{\text{queue}}^\ast = T_{\text{total}}^\ast - T_0 \end{cases}
$$

#### 2. 从“窗口饥饿”到“队列饱和”的三阶段相变规律

代入基准参数 $T_0 = 80\text{ ns}$、 $T_{\text{service}} = 2.5\text{ ns}$、 $B_{\text{peak}} = 25.6\text{ GB/s}$、 $K_0 = 32$、 $N_{\max} = 16$，随着单通道分摊并发核心数 $M$ 增加，闭环系统的精确平衡点演进如下：

| 并发核心数 $M$ (单通道分摊) | 全局在途窗口 $K = 16M$ | 理想开环预测利用率 $\rho_{\text{open}} = K/K_0$ | **闭环真实利用率** $\rho^\ast$ (M/D/1 $\alpha=0.5$) | **闭环实际带宽** $B_{\text{achieved}}^\ast$ (M/D/1) | **闭环稳态总延迟** $T_{\text{total}}^\ast$ (M/D/1) | **纯排队等待** $T_{\text{queue}}^\ast$ (M/D/1) | *对照：M/M/1 悲观平衡点* $(\rho^\ast, B^\ast, T_{\text{total}}^\ast)$ | 
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | 
| $M = 1$ **核** | $16$ | $50.0\\%$ | $49.26\\%$ | $12.61\text{ GB/s}$ | $81.21\text{ ns}$ | $1.21\text{ ns}$ | $(48.55\\%, \ 12.43\text{ GB/s}, \ 82.39\text{ ns})$ | 
| $M = 2$ **核** *(临界点* $K=K_0$*)* | $32$ | $100.0\\%$ *(开环发散)* | $88.91\\%$ | $22.76\text{ GB/s}$ | $89.98\text{ ns}$ | $9.98\text{ ns}$ | $(84.60\\%, \ 21.66\text{ GB/s}, \ 94.56\text{ ns})$ | 
| $M = 3$ **核** | $48$ | $150.0\\%$ *(超载)* | $96.98\\%$ | $24.83\text{ GB/s}$ | $123.74\text{ ns}$ | $43.74\text{ ns}$ | $(94.39\\%, \ 24.16\text{ GB/s}, \ 127.13\text{ ns})$ | 
| $M = 4$ **核** | $64$ | $200.0\\%$ *(超载)* | $98.48\\%$ | $25.21\text{ GB/s}$ | $162.47\text{ ns}$ | $82.47\text{ ns}$ | $(97.07\\%, \ 24.85\text{ GB/s}, \ 164.83\text{ ns})$ | 
| $M = 8$ **核** | $128$ | $400.0\\%$ *(重度超载)* | $99.48\\%$ | $25.47\text{ GB/s}$ | $321.67\text{ ns}$ | $241.67\text{ ns}$ | $(98.97\\%, \ 25.34\text{ GB/s}, \ 323.33\text{ ns})$ | 

1. **阶段一：欠饱和窗口受限区（**$K < K_0$**，如** $M = 1$ **核）**
   全局在途数 $K = 16 < K_0 = 32$，总线几乎不排队（ $T_{\text{queue}}^\ast = 1.21\text{ ns}$），实际带宽 $12.61\text{ GB/s}$ 极接近理想无排队值 $12.80\text{ GB/s}$，系统纯粹受制于上游单核 LFB 信用点数量。

2. **阶段二：拐点阻尼与自发节流区（**$K = K_0$**，如** $M = 2$ **核）**
   线性外推认为 2 个核心（ $K = 32 = K_0$）能打满 $100\\%$ 带宽，而开环排队论认为 $\rho = 100\\%$ 延迟无穷大。在闭环真实图景中，当流量升至 $85\\%\sim 90\\%$ 时，约 $10\text{ ns}$ 的排队延迟将往返总耗时拉长至 $\sim 90\text{ ns}$，自动压低了 32 个 LFB 槽位的周转率，将稳态工作点锚定在 $\rho^\ast = 88.91\\%$**（**$22.76\text{ GB/s}$**）**——硬件闭环通过牺牲约 $11\\%$ 的理论带宽，实现了免于无限发散的**自发负反馈节流（Self-Throttling）**。

3. **阶段三：过饱和队列转移与重负载线性延迟律（**$K \gg K_0$**，如** $M \ge 4$ **核）**
   当 $K \gg K_0$ 时， $\rho^\ast \to 1$，吞吐量触顶锁死在 $25.6\text{ GB/s}$。由于物理飞行与寻址管道（ $T_0$）最多只能容纳 $K_0 = 32$ 个在途请求，**所有超出** $K_0$ **的冗余信用点（**$K - K_0$**）全部被迫转化为控制器缓冲区内的静态排队积压** $N_q^\ast \approx K - K_0$！代入上游窗口约束方程，立即得到深度饱和区的**渐近线性延迟定律**：

$$
T_{\text{total}}^\ast(K \gg K_0) \approx K \cdot T_{\text{service}} = M \cdot N_{\max} \cdot T_{\text{service}} \implies T_{\text{queue}}^\ast(K \gg K_0) \approx (K - K_0) \cdot T_{\text{service}}
$$

   此时队列处于确定性的“满灌状态”，M/D/1 与 M/M/1 的差异完全消失；继续成倍增加并发访存核数 $M$，**系统总吞吐量毫无增益，而端到端延迟** $T_{\text{total}}^\ast$ **严格随核数** $M$ **呈线性成倍恶化**（4 核 $\sim 162\text{ ns}$，8 核 $\sim 322\text{ ns}$）。这正是现代服务器必须通过硬件 QoS（如 Intel MBA / AMD QoS）限制单核或单容器并发在途信用点 $K$ 以遏制尾延迟爆炸的底层数学依据。

## 四、 缓存的空间拓扑：L3 共享域、物理封装与 NUMA

### 1. L3 共享域与物理封装形态

* **L3 共享域（L3 Allocation Domain，简称共享域）**：在多级缓存体系中，L1 与 L2 采用每核私有设计以换取最低访问延迟，而 L3 则是核心群的数据汇聚中枢。共享域在本质上是一份明确的容量控制权清单，它界定了哪些核心对当前 L3 拥有**分配**（*Allocation*，划定并占用缓存行空间）、**脏数据回写接纳**（*Dirty Line Writeback*，接收并保存上级私有缓存下刷的被修改行）与**逐出**（*Eviction*，根据替换策略移出旧缓存行）的权限——域外核心绝对无权在别域的 L3 中分配新的**缓存行**（*Cache Line*，即缓存与内存间标准的 64 字节数据搬运单元），亦无权逐出其中的旧行；域外核心若需要使用该域中的数据，只能通过**全局一致性探针**（*Probe/Snoop*，跨核心索取缓存行副本的请求）进行拉取。**缓存一致性**是全芯片必须维持的刚性协议契约，而**共享域**仅是物理容量分配上的排他性硬边界，二者在架构上互不绑定。每个域私有一份供该域内全部核心共用的 L3 空间，整颗封装内所有域内 L3 之和即为 **L3 总量**，而域的物理边界则取决于具体的处理器架构设计：

  * **全核共享（Intel 传统）**：全部核心共享同一份域内 L3。逻辑上任意核心可映射任意物理地址；物理上域内 L3 均匀切分为若干切片（Slice——Die 内部的散列结构单元，数量随产品而变，Intel 自 Nehalem 起常见一核一切片，故 6、12、18 等非 2 的幂都会出现；勿与封装级硅片 Die 混淆）挂在环形总线（Ring Bus）或二维网格（Mesh）的节点上，请求落在哪一个切片由地址散列（Hash：确定算法、结果统计均匀的映射）决定、核心无法挑选。

  * **分组共享（AMD CCX 哲学）**：核心以组为单位共享域内 L3，组称核心复合体（Core Complex，CCX）；桌面端 Zen 1/Zen 2 每域 4 核，Zen 3 起每域 8 核。

* **物理封装的命名与分类**：封装基板上装着若干块独立硅片——工业亦通称裸片；Intel 在其分解式设计（tile-based design）中另称 Tile（客户端官方用词；服务器端业界多称 Die）。硅片按**是否承载域内 L3** 分两类：承载域内 L3 的参与记账——AMD 专称核心复合体裸片（Core Complex Die，CCD），Intel 称 Compute Tile（客户端）/ Compute Die（服务器）；不承载的（AMD 的 IOD、Intel 的 Graphics/SoC/IO/Base Tile）不参与。注意“承载 L3”与“承载计算核心”是两回事——Meteor Lake 的 SoC Tile 上就带着两个低功耗 E 核，但它们没有 L3 可依附，整个落在域外。

* **单片封装与多片封装**：封装按内部硅片总数另分两类——整颗处理器就是一块大裸片（Monolithic Die）的称**单片封装**，拆成多块小芯片（Chiplet）再组装的称**多片封装**；芯片化演进即是从前者走向后者。

* **两轴的组合映射**：承载 L3 的硅片数与域数无关——一块硅片上可以并存两个域（Zen 1 桌面），三块硅片上也可以维持一个统一大域（Granite Rapids）。L3 容量按硅片记账、归属按域记账，在对称设计下（每域、每硅片容量均匀）关系式为：

$$
\text{L3 总量} = \text{共享域数} \times \text{域内 L3 容量} = \text{承载 L3 的硅片数} \times \text{每硅片 L3 容量}
$$

  当整颗芯片只有一个域时，域内 L3 与 L3 总量直接相等。

### 2. UMA 与 NUMA：架构实质与两条判定门槛

均匀访存（Uniform Memory Access，UMA）是早期多处理器的形态：所有核心共享单条并行总线与单个内存控制器，访存代价对等。其瓶颈在于并行总线的物理极限：挂载的核心增多导致电气负载加剧，工作频率被迫受限，叠加引脚数量对位宽的物理约束，总带宽存在固定上限。出路是将内存控制器（Integrated Memory Controller，IMC）集成至每颗 CPU 封装内部，封装安装于插槽中，插槽间改走高频点对点串行链路。每颗封装内的 IMC 分别经独立内存通道连接主板 DIMM 插槽，本地内存即插于其上；带宽与容量随插槽数量扩展。物理地址空间按插槽/封装分区：核心访问本地内存时，仅经过本封装内的 IMC 与本地内存通道，不跨越插槽间互连；访问远端内存则必须穿越插槽间互连。访存延迟因请求核心与目标地址的物理拓扑距离不同而产生差异，即非均匀访存（Non-Uniform Memory Access，NUMA）。

#### NUMA 的实质与两条刚性判据

NUMA 的本质是访存延迟的不对称（Asymmetry）：不同核心访问同一物理地址的延迟，存在系统性差价。但硬件拓扑存在物理距离差，并不等价于体系结构被界定为 NUMA。构成架构级 NUMA 必须同时通过两条判定门槛：

1. **量级显著**：延迟差价通常达到约 $20\text{ ns}$ 以上（经典跨插槽可达数十纳秒），足以让操作系统的拓扑就近调度（Affinity Scheduling）换取可观的应用性能收益；微架构走线差与纳秒级片内跳数差在统计上直接被掩盖。

2. **地址空间可定域**：系统性访存差价必须与宏观、确定的物理地址（PA）区间强绑定，而非在缓存行粒度上被散列打散。

   * **全片散列摊平差价（回归 UMA）**：在片内，硬件异或散列以 64 字节缓存行为粒度将物理地址全域打散，任意核心访问任意地址，落入全片 $N$ 个切片的概率均为 $1/N$。设某个核心到各切片的物理延迟分别为 $L_1, L_2, \dots, L_N$，则该核心访存的统计期望延迟为：

$$
\mathbb{E}[\text{Latency}] = \frac{1}{N} \sum_{k=1}^{N} L_k
$$

   在大数定律作用下，核心 A 与核心 B 命中近端和远端切片的比例完全相同，两者的统计期望延迟一致。微观走线上的跳数差被全域散列彻底摊平，物理地址对所有核心完全平权，体系结构依然是 UMA。切片对 OS 不可见、不可分区，OS 无法在切片粒度上做拓扑调度。

   * **宏观定域确立 NUMA**：唯有通过顶层系统地址译码器（SAD）将物理地址按大段划界（如 $64\text{ MiB}$ 粒度或按槽切分 $64\text{ GiB}$），强制让该段内的所有缓存行 100% 锁定在本地切片与本地 IMC 上。此时，本地核心群访问该物理段全在近端；远端核心群访问同一个物理段则必须跨越 UPI（Ultra Path Interconnect）或 EMIB 硅桥，承担确定性的高延迟。核心间访问同一地址的系统性差价由此确立，操作系统也才获得了按物理页帧（PFN）执行亲和调度的抓手。

### 3. 固件阶段演进：从 UEFI 到 MRC 再到 ACPI 表构建

硬件电路在流片后，比较器和异或门逻辑就已经固定。但整机如何分段、使用何种掩码、是否开启交织，完全由主板底层固件在开机初始化流程中动态决定。整个过程遵循一条明确的时间轴与因果链：
**UEFI 启动引导** $\longrightarrow$ **MRC 执行内存训练与寄存器编排（Orchestrate）** $\longrightarrow$ **固件生成 ACPI SRAT / SLIT 表移交 OS。**

在现代 x86 体系结构下，服务器启动早期主要经历两个关键阶段：

1. **SEC（Security Phase，安全阶段）**：平台刚上电，执行硬件鉴权与基础环境重置。

2. **PEI（Pre-EFI Initialization，预 EFI 初始化阶段）**：核心特征是主存尚未可用。由于 DRAM 尚未探测与初始化，系统利用 CPU 缓存（通常为 L3 Cache）建立临时执行栈，即进入 **CAR（Cache-as-RAM）** 状态。在此环境下，UEFI 从 SPI Flash 固件卷（或 FSP-M）中解包并执行一段由 CPU 厂商提供的保密二进制模块——**MRC（Memory Reference Code，内存参考代码）**。

MRC 通过 MMIO 或专用 Sideband 边带互联总线，向未初始化的各级内存控制器及 PHY 硬件寄存器写入拓扑参数、训练规则与时序校准值，从而完成电气特性校准，正式激活底层硬件的物理寻址通路：


1. **探测拓扑与电气时钟训练（SPD 探测与链路校验）**：

   * 固件通过 I2C/I3C 总线扫描主板插槽上的 **SPD**（Serial Presence Detect）EEPROM，读取已插入 **DIMM** 的容量、Rank 数量、Bank Group 组织结构以及行列位宽（Row/Column Bits）等原始几何参数。

   * 发送测试码流进行 DDR 物理层信号眼图校准、阻抗匹配与时序训练；同时校验插槽间高速互联总线（Intel **UPI** / AMD **xGMI**）或 Die 间硅桥的电气通路。

2. **配置宏观路由规则——SAD（System Address Decoder，系统地址译码器）寄存器**：

   * 硬件的范围比较器是硬连线逻辑（Hardwired Logic），但比较的“起始地址、终止地址及跳转目标”在上电时处于空值。

   * MRC 根据探测到的总容量与 UEFI 设定的 NUMA/SNC 模式，计算出各段物理地址范围，**将 Base、Limit 以及对应的转发目标（发往本地 IMC 还是经由 UPI/硅桥发往远端）写入各 CHA 的 SAD 配置寄存器中**。这从宏观上确立了物理地址的“定域边界”。

3. **配置微观打散、通道交织与颗粒映射参数——CHA 散列、TAD 空间拼接与 IMC 地址译码**：

   > **第一性原理本质剖析**：
   > 连续的系统物理地址（SPA）并非天然存在，物理上只有插在各槽位上独立编址的离散内存条实物。**通道交织（SAD/TAD）**的本质是**“空间构建”**，通过跨通道拉链式穿插，将离散的局部实物容量拼接为上层可见的统一 SPA；而 **Slice 散列（CHA）**的本质是**“流量负载均衡”**，它不提供底层容量，仅在已构建好的连续 SPA 上通过硬件异或树（XOR Tree）做无损计算与流向分发，打散片上缓存与目录访问压力。

   * **配置 CHA 切片散列参数（片上流量均衡）**：系统物理地址（SPA）的高阶拓扑位经由硬化异或树（XOR Tree）降维折叠为虚拟切片索引；为兼容晶圆良率熔断（Fused-off）或固件禁用的瑕疵切片，MRC 读取物理存活状态（CAPID）后向各 CHA 注入**存活切片散列掩码（Hash Mask）与切片重定向表（Defect LUT / Remap Table）**，将流量保偏映射至实际存活切片。

   * **配置 TAD（Target Address Decoder）通道交织参数（实物空间逆向还原）**：针对脱离缓存层落入主存的读写请求，MRC 将交织路数、多抽头异或散列掩码及段基址偏移（Base Offset）写入 TAD 寄存器。TAD 负责执行逆向解构——**通过多抽头异或算出目标通道号，随后从地址中剥离（Strip）交织特征位**，扣除基址偏移，将全局 SPA 还原为该通道内部从 0 开始连续编址的**通道物理地址（CPA, Channel Physical Address）**。

   * **配置 IMC 内部的 RIR（Rank Interleave Register）与 AMAP（Address Map）（颗粒阵列坐标映射）**：锁定单一物理通道后，MRC 依据 SPD 解析出的 DIMM 几何拓扑，向 IMC 写入 RIR 与 AMAP 寄存器，定义通道物理地址向 **Rank 片选（CS#）、Bank Group、Bank、Row、Column** 的分配映射（即第二章第 2 节详述的位段表），完成物理寻址向 DRAM 内部 1T1C 存储单元的电路级闭环。

#### 方案 A：全局 12 通道交织（UMA 模式 / All-to-All “4×3 二维拉链式”全局拼接与 $2^N$ 步长免疫）

以 Granite Rapids（3 块 Compute Die，每 Die 4 条通道，全封装共 12 条通道）为例。由于 **12 不是 2 的幂次**（ $12 = 4 \times 3$），二进制硬件无法直接从地址中切出整比特位来完成模 12 运算。MRC 采用 **“Die 内 4 路异或位拼接 + 跨 Die 3 路模 3 算子拼接”的正交双维法则**，将全部 12 根内存条各自的**通道物理地址（CPA）**横向编织为单一、连续的**全局系统物理地址空间（SPA）**，其地址推进率严格满足 $\frac{d(\text{SPA})}{d(\text{CPA})} = 12$：

1. **第一维（Die 内 4 通道拼成 256B 条带 + 多抽头 XOR 散列免疫** $2^N$ **步长）**：每个 Die 内部拥有 **4 条通道（**$2^2=4$**，2 的幂次）**。MRC 规定以 `PA[7:6]` 两个比特位承载每 Die 内的 4 路交织，将一个 Die 内 4 根内存条各自的 64B 实物块横向拼成 **256B 宽度的 Die 级条带（Stripe）**。

   * **关键纠偏（防止** $2^N$ **步长坍缩）**：如第二章所述，由于 4 是 2 的幂次，若直接用原始 `PA[7:6]` 选通道，任何步长 $S = 2^N$（ $N \ge 8$，如 $256\text{ B}$、 $1024\text{ B}$、 $4096\text{ B}$）的循环都会令 `PA[7:6]` 恒定不变，导致每个 Die 内部的 4 条通道只有 1 条工作、其余 3 条闲置（总带宽暴跌 $75\\%$）！更进一步，哪怕只与单一高位（如 `PA[9:8]`）做简单异或，当步长恰好为 $S = 2^{10} = 1024\text{ B}$ 时，`PA[7:6]` 与 `PA[9:8]` 依然双双锁死！因此，硬件 TAD 采用**多抽头线性反馈异或树（Multi-tap XOR Hash）**：

$$
\text{Local\\_Ch} = \text{PA}[7:6] \oplus \text{PA}[9:8] \oplus \text{PA}[13:12] \oplus \text{PA}[19:18] \oplus \dots
$$

   确保无论程序采用何种 $2^N$ 幂次步长，只要高阶条带号变化，`Local_Ch` 就会在 `0, 1, 2, 3` 之间均匀轮转。

2. **第二维（跨 3 个 Die 模 3 轮询 + 除 3 空间紧缩）**：沿着 `PA[8]` 往上的高位地址段定义为**全局条带流水号（**$\text{GSI} = \text{PA}[51:8]$**）**，依次从 Die 0（Ch0\~3）、Die 1（Ch4\~7）、Die 2（Ch8\~11）轮流抽取 256B 条带向上叠放。硬件 CHA/TAD 在逆向还原时，通过硅片硬化的定点数乘法逆元电路（Mod-3 & Div-3 算子）对 `GSI` 同时执行两步操作：

   * **模 3 选 Die（天然与** $2^N$ **互质）**：由于 $\gcd(2^N, 3) = 1$（任意 2 的幂次除以 3 的余数永远在 $1$ 和 $2$ 之间交替，绝不为 $0$），任何 $2^N$ 步长（ $N \ge 8$）在 $\text{GSI} \bmod 3$ 下**天然会以周期 3 遍历全部 3 个 Die（`0 -> 1 -> 2` 或 `0 -> 2 -> 1`），绝不会锁死在单个 Die 上**！再辅以高位异或微调 $\text{Target\\_Die} = (\text{GSI} \oplus \text{Hash}) \bmod 3$，实现跨 Die 完美均衡。

   * **除 3 紧缩与剥离 `PA[7:6]` 还原 CPA**：计算**本地条带索引（**$\text{LSI} = \lfloor \text{GSI} / 3 \rfloor$**）**。因为全局连续的 3 个条带（如 $\text{GSI} = 0, 1, 2$）被分别派发到了 3 个不同的 Die，它们整除 3 后的商均为 $\text{LSI} = 0$——对应各自 Die 内部的**本地第 0 行条带**，消除了跨 Die 轮询的地址空洞；最后**剥离（Strip）`PA[7:6]` 这两个比特位的位置**，将 `LSI` 左移 6 位拼接行内偏移 `PA[5:0]`，即可严丝合缝地还原出单根内存条内连续致密的 `CPA = (LSI << 6) | PA[5:0]`。

### 4. 固件移交拓扑视图：ACPI SRAT / SLIT 与 OS 的软硬交接

MRC 完成硬件寄存器（SAD / TAD / 切片掩码）配置后，由于底层寄存器定义属芯片厂商私有实现，固件（UEFI）将其转化为工业界标准硬件说明书——**ACPI（Advanced Configuration and Power Interface）表**交付给操作系统：

* **SRAT（System Resource Affinity Table，系统资源亲和性表）——“归属绑定清单”**：确立抽象编号 **Proximity Domain（亲和域 / NUMA 节点编号）**。其中 `Processor Local x2APIC Affinity` 结构体声明逻辑核心归属哪个 Domain；`Memory Affinity` 结构体声明物理地址段（`Base ~ Base + Length`）归属哪个 Domain。

* **SLIT（System Locality Distance Information Table，系统局部距离信息表）——“相对开销矩阵”**：量化跨界访问代价，规范强制规定本地域访问自身内存的基准值恒为 `10`（例如跨硅桥为 `13~14`，跨主板 UPI 插槽为 `21~28`）。Linux 伙伴系统依据该矩阵构建内存分配回退链表（Zonelist）。

**硬件 SAD（Base/Limit）与 ACPI SRAT（Base/Length）实质换算矩阵**：

| 连续内存物理区间 | 硬件 SAD 寄存器配置（硅片控制面）  （粒度：64 MiB 块，存储 `PA[51:26]`） | ACPI SRAT 描述结构（OS 抽象面）  （粒度：字节，无符号 64 位整数） | 软硬件区间映射的物理实质 | 
| ----- | ----- | ----- | ----- | 
| **区间 0**  ($0 \sim 64\text{ MiB}$) | \- **Base 块号**：`0`  \- **Limit 块号**：`0`  \- **硬件判决规则**：`PA[51:26] <= 0` | \- **Base Address**：`0x0000_0000`  \- **Address Length**：`0x0400_0000` ($64\text{ MiB}$) | 硬件判决为包含第 0 块，OS 记录基址为 0、长度为 $64\text{ MiB}$ 的连续页帧。 | 
| **区间 1**  ($64 \sim 192\text{ MiB}$) | \- **Base 块号**：`1`  \- **Limit 块号**：`2`  \- **硬件判决规则**：`PA[51:26] <= 2` | \- **Base Address**：`0x0400_0000`  \- **Address Length**：`0x0800_0000` ($128\text{ MiB}$) | 硬件前向链自增作为 Base，包含第 1、2 块；OS 记录基址偏移 $64\text{ MiB}$、跨度 $128\text{ MiB}$。 | 

#### 在操作系统中核验 SRAT / SLIT

* **Linux 环境**：ACPI 表映射在 `/sys/firmware/acpi/tables/`。可使用 `numactl --hardware` 或 `cat /sys/devices/system/node/node0/distance` 查看拓扑与距离，或通过 `acpica-tools` 反编译二进制表：

  ```
  sudo cp /sys/firmware/acpi/tables/SRAT ./SRAT.dat
  sudo cp /sys/firmware/acpi/tables/SLIT ./SLIT.dat
  iasl -d SRAT.dat && iasl -d SLIT.dat
  cat SRAT.dsl
  
  ```

* **Windows 环境**：通过 PowerShell 执行 `Get-WmiObject -Class Win32_PerfFormattedData_PerfOS_NUMANodeMemory`，或在内核调试器 WinDbg 中执行 `!acpi -s` 与 `!acpi -t srat`。

* **为什么第一站是本地 CHA**：每个核所在站点的 CHA 内部装有 SAD 地址地图，比对高位地址即可瞬间裁决该行数据归本地管还是对端管。若是远端地址，本地硬件立即判定“免检”——不在本地 L3 浪费时间查表，直接打包扔上 UPI 跨槽链路。

* **为什么跨槽后必须先敲对端归宿 CHA，而非直接找对端 IMC**：因为对端 DRAM 里的数据可能过期（对端某核可能正把该地址的最新脏副本扣在私有 L1/L2 里）。跨槽请求必须先到对端归宿 CHA 查分布式目录（Directory）：有脏副本则点对点索回最新数据；无缓存命中才放行让对端 IMC 去 DRAM 捞数据。

* **为什么是点对点单播而非广播**：通过将每块内存的“管辖权”经 XOR 固定散列到具体的归宿 CHA 切片上，查目录、发失效探针、交还副本全都是 `请求核 <-> 归宿 CHA <-> 持有核` 之间的精准单播，避免了广播嗅探随核数平方级膨胀而淹没 UPI 链路。

> **注：关于 SAD “64 MiB 步进粗粒度”的准确工程释义**
> `PA[45:26]` 的 $64\text{ MiB}$（ $2^{26}\text{ B}$）并非交织粒度，而是 SAD 范围寄存器（Limit Register）的**硬件对齐刻度（Resolution）**。无论系统将内存划分为 1 个全局大段（UMA）还是按 Die 划分为 3 个连续大段（SNC3），每个大段的起始与结束边界都必须是 $64\text{ MiB}$ 的整数倍。这样硬件仅需一个 20-bit 比较器（监测 `PA[45:26]`）即可完成上百 GiB 宏观地址段的瞬时判定，省去了低 26 位无意义的比较电路。
