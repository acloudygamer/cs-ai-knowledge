# 数据库基础

## 核心定义：为什么文件不够用

应用的状态不能随进程生死，要持久化。直接写文件不行，约束有三：**并发**（几十个进程同时改同一份数据，文件锁的粒度太粗）、**查询**（"找出上月消费前 100 的用户"= 全文件扫描）、**崩溃恢复**（写一半的订单就是账目错误）。数据库管理系统（DBMS）就是为同时接住这三条而生的软件。它的内部机制——WAL 日志、LSM-Tree、Buffer Pool——全部已在《硬件组成》存储层次一节作为软件对策讲过；本篇讲它对上的抽象与取舍。

## 关系模型：表、约束与声明式查询

关系型数据库（MySQL、PostgreSQL）把数据组织成**表**：行是记录、列是字段，schema 预先钉死每列的类型与约束（非空、唯一、外键——数据完整性由数据库强制，而不是靠每个应用自觉）。查询用 SQL：**声明式**语言——你描述要什么（`WHERE amount > 100`），不描述怎么取；优化器根据统计信息选择执行路径（走哪个索引、以什么顺序连接表）。

**索引**的结构是 B+ 树，形状由磁盘约束直接决定（《硬件组成》存储层次：磁盘/SSD 按页读写）：树极矮极胖（扇出数百），三层即可索引上亿行；叶子页按序链接，范围扫描顺着叶子走。没有索引的查询 = 全表扫描 = 每页一次 I/O；索引把"按某列查找"从 $O(N)$ 压到 $O(\log N)$ 次页读。代价：每个索引是一份额外的有序结构，写入时要同步维护——**索引加速读、征税写**，加不加索引是读写比的账。

ORM 层还有一个高频坑：**N+1 问题**——一次查询取出 100 个订单，再逐个访问每个订单的用户字段，触发 100 次追加查询。解法是预加载（eager loading / join）；识别方法很简单：数一次页面渲染发出了几条 SQL。

## ACID：四个字母各管一种故障

- **原子性（Atomicity）**：事务的多步操作要么全生效要么全不生效。机制是 WAL 重做/回滚日志（硬件层讲过：先写日志再写数据，崩溃后重放或撤销）。
- **一致性（Consistency）**：事务不破坏完整性约束（外键、唯一、余额不为负）——由约束检查保证。
- **隔离性（Isolation）**：并发事务互不看见中间态。实现两路线：**锁**（悲观，读写互斥）与 **MVCC**（多版本并发控制——每行数据保留多个版本，读旧版本不阻塞写新版本，PostgreSQL/MySQL InnoDB 默认）。隔离级别（读未提交 → 读已提交 → 可重复读 → 串行化）是性能与正确性之间的明码标价。三个异常名词对应三种"看见了不该看的"：**脏读**——看到别的事务还没提交的写；**不可重复读**——同事务内两次读同一行结果不同（被别人改了）；**幻读**——同事务内两次按条件查询行数不同（被别人插入）。级别每升一级消灭一种：读已提交灭脏读、可重复读灭不可重复读、串行化灭幻读；代价方向相反——级别越高，锁与版本协调越重。
- **持久性（Durability）**：提交成功即落盘（或至少日志落盘）——`fsync` 的位置，见《系统软件层》05 的回写一节。

## NoSQL：放松哪个约束换什么

NoSQL 不是"新数据库"，而是**各自放松关系模型的一条约束，换取某项能力**：

| 类型 | 放松了什么 | 换来 | 代表 |
|------|-----------|------|------|
| 键值（KV） | 查询能力（只能按键取） | 极致速度、天然分片 | Redis、DynamoDB |
| 文档 | schema 刚性（每条记录字段可不同） | 开发灵活性、对象直通 | MongoDB |
| 列族 | 行式存储 | 海量稀疏数据的水平扩展 | Cassandra、HBase |
| 图 | 表结构 | 多跳关系查询（社交关系、路径） | Neo4j |

关系模型的两张王牌——**Join**（数据可以规范化存放、查询时拼接）和**事务**——在分布式环境下价格高昂（跨机器 Join 与分布式事务的协调开销），NoSQL 普遍选择反范式（数据按查询形状冗余存放）与最终一致性。选型的正确问法不是"哪个先进"，而是"我的数据形状、查询模式、一致性要求各是什么"。

## 边界：与缓存的分工

数据库是状态的最终权威。读多写少的热数据前面常垫 Redis——它是 03 篇测试金字塔式的层级思想在存储上的重演：快的层小、挡在前面。引入缓存就引入一致性问题（先写库还是先删缓存——Cache Aside 是默认答案），这层权衡在《系统软件层》与硬件篇的缓存层级里是同一思想的不同高度。
