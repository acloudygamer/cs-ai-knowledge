# Git版本控制

## 定义

Git是分布式版本控制系统，通过内容寻址存储和快照模型记录文件变更历史，使多人并行协作成为可能。

## 数学模型

分支合并复杂度：

- Fast-forward：$O(1)$，指针移动
- 3-way merge：$O(n)$，需比较三个提交
- 冲突解决：$O(n)$，人工介入

SHA-1 哈希空间：$2^{160}$ 个唯一对象，碰撞概率可忽略。

## 数据流

<pre>
工作目录                    暂存区                    本地仓库                    远程仓库
    │                          │                          │                          │
    │── 修改文件 ─────────────►│                          │                          │
    │   (状态: Modified)       │                          │                          │
    │                          │── git add ─────────────►│                          │
    │                          │   (状态: Staged)         │                          │
    │                          │                          │                          │
    │                          │── git commit ──────────►│                          │
    │                          │   (状态: Committed)      │                          │
    │                          │                          │                          │
    │                          │                          │── git push ────────────►│
    │                          │                          │◄── 远程更新 ────────────│
</pre>

数据形态变换：`工作目录文件(工作副本)` → `暂存区快照(index)` → `本地仓库对象(objects)` → `远程仓库(共享)`

## 机制

### 核心约束

1. **对象不可变**：一旦创建，对象内容永不改变，新提交创建新对象
2. **分支轻量**：分支只是指向提交的40字节指针，创建/删除代价极低
3. **分布式对等**：每个克隆都是完整仓库，无单点依赖

### 违规后果

- 修改已推送历史导致他人工作基线破坏
- 分支命名冲突或删除他人分支导致协作混乱
- 强制推送覆盖他人提交导致工作丢失

### 分支策略

| 策略 | 特点 | 适用场景 |
|------|------|----------|
| GitHub Flow | 简单，主干开发 | 持续部署 |
| Git Flow | 复杂，多环境 | 正式发布 |
| Trunk-based | 单分支，特性开关 | 大型团队 |
