# 前端与后端

## 定义

前后端分离是一种架构范式，将用户界面（前端）与业务逻辑及数据管理（后端）解耦为独立服务，通过标准化协议通信。

## 数学模型

前后端交互延迟构成端到端延迟的主体：

$$
T_{total} = T_{network} + T_{server} + T_{render}
$$

其中：
- $T_{network}$：网络往返时间（受物理距离、带宽、丢包率影响）
- $T_{server}$：服务端处理时间（数据库查询、业务计算、IO）
- $T_{render}$：前端渲染时间（DOM 操作、JS 执行）

## 数据流

<pre>
用户浏览器                    前端服务                    后端服务                    数据库
    │                           │                           │                           │
    │──── HTTP Request ─────────►│                           │                           │
    │     (JSON/HTML/CSS/JS)    │                           │                           │
    │                           │──── REST/gRPC Request ──►│                           │
    │                           │     (JSON)                │                           │
    │                           │                           │──── SQL Query ────────────►│
    │                           │                           │     (结构化查询)           │
    │                           │                           │◄─── Result Set ───────────│
    │                           │◄─── JSON Response ───────│                           │
    │◄─── HTML/JSON ───────────│                           │                           │
    │     (渲染指令)             │                           │                           │
    │                           │                           │                           │
    ▼                           ▼                           ▼                           ▼
  DOM更新                   状态管理                   业务逻辑                   数据持久化
</pre>

数据形态变换：`用户操作` → `HTTP请求(JSON)` → `路由解析` → `业务处理(SQL)` → `JSON响应` → `DOM更新`

## 机制

### 核心约束

1. **接口契约**：前后端通过 API 协议通信，接口变更需协调
2. **无状态设计**：后端不应依赖前端状态，确保独立扩展
3. **跨域限制**：浏览器 CORS 策略限制前端直接访问不同源后端

### 违规后果

- 接口不兼容导致 400/500 错误
- 后端耦合前端状态导致扩展困难
- CORS 配置错误导致前端无法获取数据

### 设计权衡

| 方案 | 优点 | 缺点 |
|------|------|------|
| REST | 简单、缓存友好 | 多次请求、大量数据传输 |
| GraphQL | 按需获取、一次请求 | 复杂度高、缓存困难 |
| gRPC | 高性能、二进制协议 | 浏览器支持差 |
