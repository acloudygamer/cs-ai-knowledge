# 容器化基础

## 概念

**容器化**是将应用及其依赖打包为轻量级、可移植的单元的技术,实现"构建一次,运行多处"。

```
┌─────────────────────────────────────────────────────────┐
│                    虚拟机 vs 容器                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  虚拟机:                        容器:                   │
│  ┌─────────────────┐            ┌─────────────────┐    │
│  │    App 1        │            │    App 1        │    │
│  ├─────────────────┤            ├─────────────────┤    │
│  │    App 2        │            │    App 2        │    │
│  ├─────────────────┤            ├─────────────────┤    │
│  │    App N        │            │    App N        │    │
│  ├─────────────────┤            └─────────────────┘    │
│  │   Guest OS      │                   │                │
│  ├─────────────────┤            ┌─────────────────┐    │
│  │   Hypervisor    │            │   Container     │    │
│  ├─────────────────┤            │   Runtime       │    │
│  │   Host OS       │            ├─────────────────┤    │
│  └─────────────────┘            │   Host OS       │    │
│                                └─────────────────┘    │
│                                                         │
│  启动: 分钟级                   启动: 秒级               │
│  大小: GB 级                   大小: MB 级               │
│  隔离: 强                      隔离: 依赖内核命名空间、cgroups、AppArmor/SELinux   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 关系

**关键连接**:
- 容器 → **镜像**: 容器的基础模板
- 镜像 → **Dockerfile**: 定义镜像构建过程
- 容器 → **命名空间**: 资源隔离
- 编排 → **Kubernetes**: 多容器管理

## Docker 核心概念

### 镜像 (Image)

```
镜像结构:

┌─────────────────────────────────────────┐
│         容器层 (Container Layer)        │
├─────────────────────────────────────────┤
│         镜像层 3 (依赖层)                 │
├─────────────────────────────────────────┤
│         镜像层 2 (应用依赖)              │
├─────────────────────────────────────────┤
│         镜像层 1 (基础系统)              │
└─────────────────────────────────────────┘

- 镜像只读,容器在顶层读写
- 多个容器共享底层镜像
- 节省存储空间
```

### 容器 (Container)

```bash
# 容器是镜像的运行实例
# 容器 = 镜像 + 容器层 (读写)

# 运行容器
docker run -it ubuntu:24.04 bash
# -i: 交互模式
# -t: 分配伪终端

# 后台运行
docker run -d --name myapp nginx:latest
# -d: 后台运行
# --name: 指定容器名

# 列出容器
docker ps              # 运行中的
docker ps -a           # 所有容器
docker ps -l           # 最近创建的
```

### 镜像命令

```bash
# 拉取镜像
docker pull ubuntu:24.04

# 列出本地镜像
docker images
docker images -a

# 删除镜像
docker rmi ubuntu:24.04

# 构建镜像
docker build -t myapp:1.0.0 .

# 镜像打标签
docker tag myapp:1.0.0 myregistry.com/myapp:1.0.0

# 推送镜像
docker push myregistry.com/myapp:1.0.0

# 清理未使用的镜像
docker image prune -a
```

## Dockerfile

### 基础指令

```dockerfile
# Dockerfile 示例
# 基础镜像
FROM ubuntu:24.04

# LABEL maintainer
LABEL maintainer="author@example.com"
LABEL version="1.0"
LABEL description="My application"

# 复制文件
COPY package*.json /app/
COPY . /app/

# 设置工作目录
WORKDIR /app

# 环境变量
ENV NODE_ENV=production
ENV PORT=3000

# 安装依赖
RUN npm ci --only=production

# 暴露端口
EXPOSE 3000

# 创建非 root 用户
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

# 启动命令
CMD ["node", "index.js"]
```

### 多阶段构建

```dockerfile
# 多阶段构建示例
# 第一阶段: 构建
FROM node:26 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 第二阶段: 运行
FROM node:26-alpine AS runner
WORKDIR /app

# 从 builder 阶段复制构建产物
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules

# 使用最小化用户
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

EXPOSE 3000
CMD ["node", "dist/index.js"]
```

### .dockerignore

```bash
# .dockerignore 示例

.git
.gitignore

```

### Dockerfile 最佳实践

| 实践 | 说明 |
|------|------|
| 使用官方基础镜像 | 安全性和稳定性更好 |
| 顺序优化 | 变化少的放前面 |
| 合并 RUN 指令 | 减少镜像层数 |
| 多阶段构建 | 减小最终镜像大小 |
| 使用 .dockerignore | 排除无关文件 |
| 非 root 用户 | 提高安全性 |
| 最小化基础镜像 | alpine/distroless |
| 利用构建缓存 | 依赖放前面 |

## Docker 网络

### 网络模式

```bash
# bridge (默认)
docker run --network bridge myapp

# host - 共享主机网络
docker run --network host myapp

# none - 无网络
docker run --network none myapp

# container - 共享另一容器网络
docker run --network container:other-container myapp
```

### 自定义网络

```bash
# 创建网络
docker network create mynetwork

# 容器连接到网络
docker network connect mynetwork myapp

# 容器间通信 (通过容器名 DNS)
# myapp 可以通过 http://db:5432 访问 db 容器
```

## Docker 数据管理

### 数据卷 (Volume)

```bash
# 创建数据卷
docker volume create myvolume

# 列出数据卷
docker volume ls

# 查看数据卷信息
docker volume inspect myvolume

# 运行容器时挂载卷
docker run -v myvolume:/app/data myapp
docker run -v /host/path:/container/path myapp

# 清理未使用的卷
docker volume prune
```

### 绑定挂载

```bash
# 绑定主机目录
docker run -v $(pwd)/data:/app/data myapp

# 只读挂载
docker run -v $(pwd)/data:/app/data:ro myapp

# 内存文件系统
docker run --tmpfs /app/cache myapp
```

## Docker Compose

### 基础使用

```yaml
# docker-compose.yml
version: '3.8'

services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgres://db:5432/myapp
    depends_on:
      - db
      - redis
    networks:
      - app-network

  db:
    image: postgres:17-alpine
    volumes:
      - db-data:/var/lib/postgresql/data
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
    networks:
      - app-network

  redis:
    image: redis:7-alpine
    networks:
      - app-network

volumes:
  db-data:

networks:
  app-network:
    driver: bridge
```

```bash
# 启动服务
docker-compose up -d

# 查看日志
docker-compose logs -f web

# 停止服务
docker-compose down

# 停止并删除数据卷
docker-compose down -v

# 重新构建
docker-compose up -d --build

# 扩缩容
docker-compose up -d --scale web=3
```

### Kubernetes 对象

```yaml
# Pod - 最小调度单元
apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
spec:
  containers:
    - name: myapp
      image: myapp:1.0.0
      ports:
        - containerPort: 3000
      resources:
        limits:
          memory: "256Mi"
          cpu: "500m"
      livenessProbe:
        httpGet:
          path: /health
          port: 3000
        initialDelaySeconds: 5
        periodSeconds: 10

---
# Deployment - 应用部署
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
        - name: myapp
          image: myapp:1.0.0
          ports:
            - containerPort: 3000

---
# Service - 服务发现和负载均衡
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
spec:
  selector:
    app: myapp
  ports:
    - port: 80
      targetPort: 3000
  type: LoadBalancer
```

### kubectl 常用命令

## 容器安全

### 安全最佳实践

```bash
# 1. 定期更新镜像
docker pull ubuntu:24.04  # 使用最新标签要谨慎

# 2. 扫描漏洞
trivy image myapp:latest
docker scout cves myapp:latest

# 3. 资源限制
docker run --memory="256m" --cpus="0.5" myapp

# 4. 非 root 用户
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

# 5. 只读文件系统
docker run --read-only myapp

# 6. 限制能力
docker run --cap-drop=ALL myapp
docker run --cap-add=NET_BIND_SERVICE myapp
```

### 安全工具

| 工具 | 功能 |
|------|------|
| Trivy | 镜像漏洞扫描 |
| Docker Scout | Docker 官方安全 |
| Falco | 运行时安全监控 |
| AppArmor/SELinux | 强制访问控制 |

## Docker vs 容器运行时

| 组件 | 说明 |
|------|------|
| Docker | 完整的容器平台 |
| containerd | CNCF 标准的容器运行时 |
| Podman | 无守护进程,rootless |
| cri-o | Kubernetes CRI 实现 |
| nerdctl | containerd CLI |

```bash
# Docker vs Podman 命令对比
# 大部分命令兼容
docker run myapp
podman run myapp

# 构建镜像
docker build -t myapp .
podman build -t myapp .

# 无守护进程
# Docker: dockerd 进程
# Podman: 无守护进程,更安全
```

## 常见问题

### 容器无法解析 DNS

```bash
# 检查 DNS 配置
cat /etc/resolv.conf

# 指定 DNS
docker run --dns=8.8.8.8 myapp

# 排查网络
docker exec myapp ping db
docker exec myapp nslookup db
```

### 容器退出的原因

```bash
# 查看退出原因
docker ps -a
docker logs myapp

# 常见原因
# 1. 应用报错退出
# 2. 内存不足被 OOM Killer 杀死
# 3. 进程收到信号
```

### 镜像构建失败

```bash
# 查看构建日志
docker build -t myapp . --progress=plain --no-cache

# 常见问题
# 1. 网络问题 - 配置镜像加速
# 2. 缓存问题 - --no-cache
# 3. 权限问题 - 检查 Dockerfile
```
