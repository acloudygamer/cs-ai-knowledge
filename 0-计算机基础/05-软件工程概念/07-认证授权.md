# 认证授权

## 概念

**认证 (Authentication)** 验证用户身份,确认"你是谁"。**授权 (Authorization)** 决定用户权限,确认"你能做什么"。

```
┌─────────────────────────────────────────────────────────┐
│                    认证与授权流程                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  用户 ──► 认证 ──► 授权 ──► 访问资源                    │
│          │         │                                    │
│          │         └── 角色: admin/user/guest          │
│          │                                          │
│          └── 验证凭证: 密码/令牌/证书                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 关系

**关键连接**:
- 认证 → **密码/令牌**: 验证身份的凭证
- 授权 → **角色/权限**: 决定资源访问级别
- OAuth2 → **第三方登录**: 委托认证
- JWT → **无状态认证**: 令牌验证

## 认证方式

### 密码认证

```bash
# 密码存储 - 永远不要明文存储!
# 正确方式: bcrypt 哈希

# 密码哈希示例 (Node.js)
const bcrypt = require('bcrypt');
const saltRounds = 10;

async function hashPassword(password) {
    return await bcrypt.hash(password, saltRounds);
}

async function verifyPassword(password, hash) {
    return await bcrypt.compare(password, hash);
}
```

| 哈希算法 | 特点 | 用途 |
|----------|------|------|
| bcrypt | 自适应慢哈希 | 密码存储 |
| scrypt | 内存硬算法 | 密码存储 |
| Argon2 | 最新的密码哈希 | 密码存储 |
| SHA-256 | 快速哈希 | 非密码场景 |

### 多因素认证 (MFA)

```bash
# MFA 类型
# 1. 知识因素 - 知道的 (密码)
# 2. 持有因素 - 拥有的 (手机,硬件令牌)
# 3. 生物因素 - 是的 (指纹,面部识别)

# TOTP (基于时间的一次性密码)
# 生成: TOTP = HMAC-SHA1(secret, counter)
# 验证: 服务端用相同密钥计算并比对

# 示例: Google Authenticator
# 用户扫描二维码获取 secret
# 每 30 秒生成 6 位数字
```

### 令牌认证

#### JWT (JSON Web Token)

```javascript
// JWT 结构: header.payload.signature
// eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEyM30.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

// JWT 签发
const jwt = require('jsonwebtoken');

const token = jwt.sign(
    {
        userId: 123,
        role: 'admin',
        email: 'alice@example.com'
    },
    process.env.JWT_SECRET,
    {
        expiresIn: '7d',      // 过期时间
        issuer: 'my-app',      // 签发者
        audience: 'api-users'  // 受众
    }
);

// JWT 验证
try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    console.log(decoded.userId);  // 123
} catch (err) {
    if (err.name === 'TokenExpiredError') {
        // 令牌过期
    } else if (err.name === 'JsonWebTokenError') {
        // 令牌无效
    }
}
```

#### OAuth 2.0

```
OAuth 2.0 授权码流程:

┌─────────────────────────────────────────────────────────┐
│                                                         │
│  用户 ──► 第三方应用 ──► 授权服务器 ──► 用户确认授权    │
│                    │                      │              │
│                    │◄─────────────────────┘              │
│                    │  返回授权码                        │
│                    │                                     │
│                    ▼                                     │
│          授权码 ──► 第三方应用 ──► 令牌服务器           │
│                                       │                  │
│                                       ▼                  │
│                          access_token ◄──────────────│
│                          refresh_token                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

```bash
# OAuth 2.0 授权请求
GET /oauth/authorize?
    response_type=code&
    client_id=your-client-id&
    redirect_uri=https://your-app.com/callback&
    scope=read%20write&
    state=random-state

# 令牌交换请求
POST /oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&
code=authorization-code&
client_id=your-client-id&
client_secret=your-client-secret&
redirect_uri=https://your-app.com/callback

# 响应
{
    "access_token": "eyJhbGciOiJIUzI1NiJ9...",
    "token_type": "Bearer",
    "expires_in": 3600,
    "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2ggdG9rZW4..."
}
```

### OAuth 2.0 授权类型

| 授权类型 | 场景 | 说明 |
|----------|------|------|
| authorization_code | 服务器端应用 | 最安全,使用授权码 |
| implicit | SPA/移动端 | 直接返回令牌 (已弃用) |
| client_credentials | 服务间通信 | 无用户参与 |
| password | 可信应用 | 用户直接提供密码 |

## 授权模型

### RBAC (基于角色的访问控制)

```
RBAC 模型:

┌─────────┐     ┌─────────┐     ┌─────────┐
│  用户   │────►│  角色   │────►│  权限   │
└─────────┘     └─────────┘     └─────────┘
                     │
                     ├── admin ──── 所有权限
                     ├── editor ──── 读写
                     └── viewer ──── 只读
```

```sql
-- RBAC 数据库表设计
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50),
    password_hash VARCHAR(255)
);

CREATE TABLE roles (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE permissions (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    resource VARCHAR(50),
    action VARCHAR(50)
);

CREATE TABLE user_roles (
    user_id INT,
    role_id INT,
    PRIMARY KEY (user_id, role_id)
);

CREATE TABLE role_permissions (
    role_id INT,
    permission_id INT,
    PRIMARY KEY (role_id, permission_id)
);
```

### ABAC (基于属性的访问控制)

```javascript
// ABAC 策略示例
{
    "condition": {
        "and": [
            { "attribute": "user.role", "operator": "equals", "value": "manager" },
            { "attribute": "resource.department", "operator": "equals", "value": "user.department" },
            { "attribute": "action", "operator": "in", "value": ["read", "write"] }
        ]
    },
    "effect": "allow"
}
```

### 常见权限模型对比

| 模型 | 特点 | 适用场景 |
|------|------|----------|
| DAC | 资源所有者决定访问 | 协作场景 |
| MAC | 强制访问,安全标签 | 军事,政府 |
| RBAC | 基于角色 | 企业应用 |
| ABAC | 基于属性,灵活 | 复杂权限需求 |

## 会话管理

### Session vs Token

| 特性 | Session | JWT |
|------|---------|-----|
| 存储位置 | 服务端 (Redis/数据库) | 客户端 |
| 扩展性 | 需共享 session | 无状态 |
| 撤销能力 | 可立即撤销 | 需黑名单 |
| 数据量 | 小 | 可存储更多 |
| 适用场景 | 有状态服务 | 微服务,跨域 |

```javascript
// Express Session
const session = require('express-session');
const RedisStore = require('connect-redis');

app.use(session({
    store: new RedisStore({ client: redisClient }),
    secret: 'your-secret',
    resave: false,
    saveUninitialized: false,
    cookie: {
        secure: true,      // HTTPS only
        httpOnly: true,    // JS 无法访问
        maxAge: 1000 * 60 * 60 * 24  // 24 小时
    }
}));

// 使用 session
app.post('/login', (req, res) => {
    req.session.userId = user.id;
    req.session.role = user.role;
    res.json({ success: true });
});
```

### Cookie 安全

```bash
# Cookie 属性
Set-Cookie: session_id=abc123;
    Path=/;                    # 作用域
    HttpOnly;                  # 禁止 JS 访问
    Secure;                    # 仅 HTTPS
    SameSite=Strict;           # 同源策略
    Max-Age=3600;              # 过期时间
```

| SameSite 值 | 说明 |
|-------------|------|
| Strict | 仅同站点请求发送 |
| Lax | GET 请求同站点发送 |
| None | 所有请求都发送 (需 Secure) |

## API 安全性

### 签名验证

```bash
# HMAC 签名示例
# 请求签名: HMAC-SHA256(secret, method + path + timestamp + body)

# 请求头
X-Signature: sha256=xxxxx
X-Timestamp: 1640995200

# 服务端验证
1. 检查 timestamp 不超过 5 分钟
2. 计算期望签名
3. 比较签名
```

### CORS (跨域资源共享)

```javascript
// CORS 配置
const cors = require('cors');

app.use(cors({
    origin: ['https://example.com'],  // 允许的源
    methods: ['GET', 'POST'],         // 允许的方法
    allowedHeaders: ['Content-Type', 'Authorization'],
    credentials: true,                 // 允许携带 cookie
    maxAge: 86400                     // 预检请求缓存 24 小时
}));
```

