# 容器化基础

## 定义

容器化是将应用及其全部依赖打包为轻量级、可移植的运行时单元的技术，通过操作系统级虚拟化实现进程级隔离。容器与虚拟机的本质区别是：虚拟机虚拟化硬件（提供"机器"），容器虚拟化操作系统（提供"进程"）。

## 数学模型

### 容器启动时间模型

容器启动时间由以下因素决定：

$$
T_{start} = T_{pull} + T_{create} + T_{run}
$$

其中：

- $T_{pull}$：镜像拉取时间，取决于镜像大小和网络带宽
- $T_{create}$：容器创建时间，约 100-500ms（cgroup/namespace 配置）
- $T_{run}$：应用启动时间，取决于应用本身

相较于虚拟机（需启动完整 Guest OS，数分钟级），容器启动快 100-1000 倍。

### 镜像层存储效率

镜像层共享使存储空间大幅节省。设 $n$ 个镜像，各自大小为 $S_i$，共享层大小为 $L$：

$$
Storage_{without\_share} = \sum_{i=1}^{n} S_i
$$

$$
Storage_{with\_share} = \sum_{i=1}^{n} (S_i - |shared_i|) + L \approx \max(S_i) + \sum layer_i
$$

实际中，10 个基于 alpine 的镜像可能只占用 ~5MB 而非 10 × ~5MB。

### cgroups 资源限制公式

cgroups 通过层级控制组限制资源使用：

| 资源 | 限制参数 | 默认值 |
|------|----------|--------|
| CPU | cpu.cfs_quota_us / cpu.cfs_period_us | 无限制 |
| 内存 | memory.limit_in_bytes | 无限制 |
| IO | blkio.throttle.read_bps_device | 无限制 |

数据形态变换链路：

1. `Dockerfile（文本）` → `指令解析` → `层构建计划`
2. `层构建计划` → `上下文打包（tar）` → `流传输`
3. `Dockerfile 指令` → `执行器（docker build）` → `只读镜像层`
4. `只读镜像层` → `镜像注册` → `可共享镜像`
5. `镜像 + 可写层` → `容器创建` → `容器层（Copy-on-Write）`
6. `容器层` → `进程启动` → `运行中的应用`

## 机制

### 单进程模型的设计约束

单进程模型（PID 1 是应用主进程）的约束来自**容器生命周期与进程生命周期绑定**：

- 容器设计哲学：容器 = 应用 + 运行环境
- PID 1 退出 → 容器退出（exit code 即容器 exit code）

违反此约束（多进程容器，如 systemd）会导致：

- 主进程无法监控子进程生命周期
- 信号传播问题：SIGTERM 只发给 PID 1
- 容器退出时子进程成为孤儿（orphan）

正确做法：一个容器一个进程，通过 `supervisord` 等 init 系统管理多进程是反模式。

### 无状态容器的实现约束

无状态容器要求**容器内容不可变**，配置通过外部注入。实现方式：

1. **环境变量**：运行时注入配置
2. **挂载卷**：数据持久化到宿主机
3. **配置映射（ConfigMap/Secret）**： Kubernetes 模式

违反此约束的后果：**重建后状态丢失**。容器镜像重新拉取后，所有运行时修改消失。

### 最小镜像的工程价值

最小镜像（alpine/distroless）优先的理由：

| 维度 | debian (活镜像) | alpine (最小) |
|------|----------------|--------------|
| 镜像大小 | ~120MB | ~5MB |
| 攻击面 | 数千包 | 数百包 |
| 拉取时间 | 10s+ | <1s |
| CVE 数量 | 多 | 少 |

distroless 进一步移除 shell，进一步减少攻击面。

### 容器 vs 虚拟机的隔离边界

容器通过 Linux namespace 实现隔离：

- **PID namespace**：隔离进程树
- **Network namespace**：隔离网络栈
- **Mount namespace**：隔离文件系统视图
- **User namespace**：隔离用户 ID 映射
- **UTS namespace**：隔离主机名/域名

虚拟机通过硬件虚拟化（Intel VT-x / AMD-V）实现更强隔离， Guest OS 运行在独立 ring -1 特权级。容器的隔离边界是进程，虚拟机是硬件。
