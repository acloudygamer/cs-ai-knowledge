# 微服务架构

## 概念

微服务架构是将大型应用拆分为一组小型服务的架构风格，每个服务运行在独立进程中，通过轻量级协议通信。

```
┌─────────────────────────────────────────────────────────┐
│                    微服务架构                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐   │
│   │用户服务  │  │订单服务 │  │支付服务 │  │商品服务 │   │
│   │ :8001   │  │ :8002   │  │ :8003   │  │ :8004   │   │
│   └────┬────┘  └────┬────┘  └────┬────┘  └────┬────┘   │
│        │             │             │             │        │
│        └─────────────┴──────┬──────┴─────────────┘        │
│                             │                              │
│                    ┌────────▼────────┐                    │
│                    │   API Gateway   │                    │
│                    │    (入口)        │                    │
│                    └────────┬────────┘                    │
│                             │                              │
│                    ┌────────▼────────┐                    │
│                    │  Load Balancer  │                    │
│                    └─────────────────┘                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 关系

**关键连接**：
- 微服务 → **容器化**：服务独立部署
- API Gateway → **微服务**：统一入口，路由转发
- 服务发现 → **微服务**：动态注册与发现
- 分布式事务 → **微服务**：跨服务数据一致性

## 微服务 vs 单体架构

| 特性 | 单体架构 | 微服务架构 |
|------|----------|------------|
| 部署 | 整体部署 | 独立部署 |
| 扩展 | 整体扩展 | 按需扩展 |
| 开发 | 统一代码库 | 独立代码库 |
| 故障 | 影响全局 | 影响局部 |
| 技术栈 | 统一 | 多样化 |
| 复杂度 | 低 | 高 |
| 团队要求 | 较低 | 较高 |

## 服务拆分

### 拆分策略

| 策略 | 说明 | 示例 |
|------|------|------|
| 按业务能力 | 按业务领域拆分 | 用户、订单、支付 |
| 按子域 | 按 DDD 子域拆分 | 库存子域、供应链子域 |
| 按团队 | 按团队边界拆分 | Team A、Team B |
| 按读写 | 按 CQRS 拆分 | 查询服务、命令服务 |

### 拆分原则

```
┌─────────────────────────────────────────────────────────┐
│                    拆分原则                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  高内聚：相关功能放在同一服务                             │
│    ↓                                                    │
│  低耦合：服务间依赖最小化                                 │
│    ↓                                                    │
│  独立部署：服务可独立发布升级                             │
│    ↓                                                    │
│  团队自治：服务由独立团队负责                             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 避免过度拆分

- 服务数量过多导致运维复杂
- 分布式事务开销
- 服务间通信延迟

### 自实现 Gateway (Go)

```go
package main

import (
    "net/http"
    "time"
    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()

    // 中间件
    r.Use(loggingMiddleware())
    r.Use(authMiddleware())
    r.Use(rateLimitMiddleware())

    // 路由
    r.Any("/api/*path", proxyHandler)

    r.Run(":8080")
}

func proxyHandler(c *gin.Context) {
    path := c.Param("path")

    // 根据路径路由到对应服务
    var target string
    switch {
    case strings.HasPrefix(path, "/users"):
        target = "http://user-service:8001"
    case strings.HasPrefix(path, "/orders"):
        target = "http://order-service:8002"
    default:
        c.JSON(http.StatusNotFound, gin.H{"error": "not found"})
        return
    }

    // 代理请求
    proxy := httputil.NewSingleHostReverseProxy(target)
    c.Request.URL.Path = path
    proxy.ServeHTTP(c.Writer, c.Request)
}
```

### 客户端发现 vs 服务端发现

| 模式 | 优点 | 缺点 | 工具 |
|------|------|------|------|
| 客户端发现 | 低延迟、无中间层 | 客户端复杂 | Eureka, Consul |

### 同步通信 (REST/gRPC)

```go
// gRPC 服务定义 (proto/user.proto)
syntax = "proto3";

package user;

service UserService {
    rpc GetUser (GetUserRequest) returns (User);
    rpc ListUsers (ListUsersRequest) returns (ListUsersResponse);
}

message GetUserRequest {
    string id = 1;
}

message User {
    string id = 1;
    string name = 2;
    string email = 3;
}

// 生成 Go 代码后实现服务
package main

type UserServer struct {
    db *sql.DB
}

func (s *UserServer) GetUser(ctx context.Context, req *pb.GetUserRequest) (*pb.User, error) {
    user, err := s.db.GetUser(req.Id)
    if err != nil {
        return nil, err
    }
    return &pb.User{
        Id:    user.ID,
        Name:  user.Name,
        Email: user.Email,
    }, nil
}
```

### 异步通信 (消息队列)

```python
# RabbitMQ 消息生产者
import pika

connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
channel = connection.channel()

channel.queue_declare(queue='order_created', durable=True)

def publish_order_created(order_id, user_id):
    message = f'{{"order_id": "{order_id}", "user_id": "{user_id}"}}'
    channel.basic_publish(
        exchange='',
        routing_key='order_created',
        body=message,
        properties=pika.BasicProperties(delivery_mode=2)  # 持久化
    )

# 消费者
def callback(ch, method, properties, body):
    print(f"Received: {body}")
    # 处理消息
    ch.basic_ack(delivery_tag=method.delivery_tag)

channel.basic_consume(queue='order_created', on_message_callback=callback)
channel.start_consuming()
```

## 分布式事务

### CAP 定理

```
┌─────────────────────────────────────────────────────────┐
│                      CAP 定理                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│           Consistency (一致性)                           │
│                ╱      ╲                                  │
│               ╱        ╲                                 │
│              ╱   CAP    ╲                                │
│             ╱      ╲     ╲                               │
│            ╱        ╲     ╲                              │
│           ╱──────────────╲                             │
│    Availability           Partition Tolerance            │
│    (可用性)                 (分区容错性)                 │
│                                                         │
└─────────────────────────────────────────────────────────┘

一致性 + 分区容错性 → CP (放弃可用性)
可用性 + 分区容错性 → CA (放弃分区容错性)
```

### Saga 模式

将大事务拆分为多个小事务，通过事件驱动协调。

```python
# Saga 编排器
class OrderSaga:
    def __init__(self):
        self.steps = [
            self.create_order,
            self.reserve_inventory,
            self.process_payment,
            self.confirm_order
        ]

    async def execute(self, order):
        completed_steps = []
        try:
            for step in self.steps:
                await step(order)
                completed_steps.append(step)
        except Exception as e:
            # 补偿已完成的步骤
            await self.compensate(completed_steps, order)
            raise

    async def compensate(self, steps, order):
        for step in reversed(steps):
            compensation = self.get_compensation(step)
            await compensation(order)
```

### TCC (Try-Confirm-Cancel)

```python
class PaymentTCC:
    async def try_pay(self, order):
        # 冻结金额
        await payment.freeze(order.user_id, order.amount)
        return "try_success"

    async def confirm_pay(self, order):
        # 确认扣款
        await payment.capture(order.user_id, order.amount)

    async def cancel_pay(self, order):
        # 释放冻结金额
        await payment.unfreeze(order.user_id, order.amount)
```

### Prometheus 指标

```go
import (
    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promhttp"

var (
    httpRequests = prometheus.NewCounterVec(
        prometheus.CounterOpts{
            Name: "http_requests_total",
            Help: "Total HTTP requests",
        },
        []string{"method", "endpoint", "status"},
    )

    httpDuration = prometheus.NewHistogramVec(
        prometheus.HistogramOpts{
            Name:    "http_request_duration_seconds",
            Buckets: prometheus.DefBuckets,
        },
        []string{"method", "endpoint"},
    )
)

func init() {
    prometheus.MustRegister(httpRequests, httpDuration)
}

func middleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        timer := prometheus.NewTimer(httpDuration.WithLabelValues(r.Method, r.URL.Path))
        defer timer.ObserveDuration()

        next.ServeHTTP(w, r)
    })
}
```

## 微服务安全

### JWT 认证

```go
import (
    "github.com/golang-jwt/jwt/v5"
)

type Claims struct {
    UserID string `json:"user_id"`
    jwt.RegisteredClaims
}

func GenerateToken(userID string) (string, error) {
    claims := &Claims{
        UserID: userID,
        RegisteredClaims: jwt.RegisteredClaims{
            ExpiresAt: jwt.NewNumericDate(time.Now().Add(24 * time.Hour)),
        },
    }

    token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
    return token.SignedString([]byte("secret"))
}

func ValidateToken(tokenString string) (*Claims, error) {
    token, err := jwt.ParseWithClaims(tokenString, &Claims{}, func(token *jwt.Token) (interface{}, error) {
        return []byte("secret"), nil
    })

    if claims, ok := token.Claims.(*Claims); ok && token.Valid {
        return claims, nil
    }
    return nil, err
}
```

### OAuth2 + JWT

```go
// OAuth2 资源服务器验证
func validateOAuth2Token(token string) (*Claims, error) {
    // 验证 JWT 签名
    claims, err := ValidateToken(token)
    if err != nil {
        return nil, err
    }

    // 验证 Audience
    if !claims.VerifyAudience("my-api") {
        return nil, errors.New("invalid audience")
    }

    return claims, nil
}
```
