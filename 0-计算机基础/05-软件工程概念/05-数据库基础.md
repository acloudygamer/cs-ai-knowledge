# 数据库基础

## 概念

**数据库**是组织、存储和管理数据的系统,提供数据持久化和查询能力。

```
┌─────────────────────────────────────────────────────────┐
```

## 关系

**关键连接**:
- 关系型 → **SQL**: 使用结构化查询语言
- NoSQL → **文档/键值**: 非结构化存储
- ACID → **事务**: 保证数据一致性
- 索引 → **查询优化**: 加速数据检索

## ACID 特性

ACID 是事务的四个基本特性:

```
┌─────────────────────────────────────────────────────────┐
│                    ACID 特性                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  A - Atomicity (原子性)                                 │
│     事务要么全部成功,要么全部失败                        │
│                                                         │
│  C - Consistency (一致性)                               │
│     事务前后数据库状态都是有效的                         │
│                                                         │
│  I - Isolation (隔离性)                                │
│     并发事务相互隔离,不互相干扰                         │
│                                                         │
│  D - Durability (持久性)                               │
│     事务提交后,结果永久保存                             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 不可能 | 可能 | 可能 |
| REPEATABLE READ | 不可能 | 不可能 | 可能 |
| SERIALIZABLE | 不可能 | 不可能 | 不可能 |

```sql
-- 设置隔离级别
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- MySQL InnoDB 默认 REPEATABLE READ，通过 MVCC + Next-Key Lock 实现完整的 REPEATABLE READ 隔离级别，可防止幻读
-- PostgreSQL 默认 READ COMMITTED
```

## SQL 基础

### 数据定义 (DDL)

```sql
-- 创建表
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE,
    age INT DEFAULT 18,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 修改表结构
ALTER TABLE users ADD COLUMN phone VARCHAR(20);
ALTER TABLE users MODIFY COLUMN age INT NOT NULL;
ALTER TABLE users DROP COLUMN phone;

-- 删除表
DROP TABLE users;

-- 创建索引
CREATE INDEX idx_name ON users(name);
CREATE UNIQUE INDEX idx_email ON users(email);
CREATE INDEX idx_age_name ON users(age, name);

-- 外键约束
CREATE TABLE orders (
    id INT PRIMARY KEY,
    user_id INT,
    FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
```

### 数据操作 (DML)

```sql
-- 插入数据
INSERT INTO users (name, email, age) VALUES
    ('Alice', 'alice@example.com', 25),
    ('Bob', 'bob@example.com', 30);

-- 更新数据
UPDATE users SET age = 31 WHERE name = 'Bob';

-- 删除数据
DELETE FROM users WHERE id = 1;

-- 查询数据
SELECT * FROM users;
SELECT name, email FROM users WHERE age > 20;
SELECT * FROM users ORDER BY age DESC LIMIT 10;
```

### 聚合查询

```sql
-- 计数
SELECT COUNT(*) FROM users;
SELECT COUNT(*) FROM users WHERE age > 25;

-- 分组
SELECT age, COUNT(*) as cnt
FROM users
GROUP BY age
HAVING cnt > 1;

-- 聚合函数
SELECT
    AVG(age),           -- 平均值
    SUM(age),           -- 总和
    MIN(age),           -- 最小值
    MAX(age),           -- 最大值
    GROUP_CONCAT(name) -- 字符串连接
FROM users;
```

### 多表查询

```sql
-- 内连接
SELECT u.name, o.order_id
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- 左连接
SELECT u.name, o.order_id
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

-- 右连接
SELECT u.name, o.order_id
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- 子查询
SELECT * FROM users
WHERE age > (SELECT AVG(age) FROM users);

-- EXISTS
SELECT * FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
);
```

## 索引原理

### B+ 树索引

```
B+ 树结构 (每个节点包含多个键值):

        [50, 70]
       /    |    \
    [20]  [50]  [70, 90]
     ↓      ↓      ↓
   叶节点  叶节点   叶节点
   ↓ ↓ ↓   ↓ ↓    ↓ ↓ ↓
  数据指针  指向下一级,最终指向数据
```

| 操作 | 时间复杂度 |
|------|------------|
| 查找 | O(log n) |
| 插入 | O(log n) |
| 删除 | O(log n) |
| 范围查询 | O(log n + k) |

### 索引类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| 主键索引 | 值唯一,非空 | 主键 |
| 唯一索引 | 值唯一,可空 | 邮箱,手机号 |
| 普通索引 | 值可重复 | 常见查询字段 |
| 全文索引 | 文本内容搜索 | 文章搜索 |
| 组合索引 | 多列组合 | 多条件查询 |

```sql
-- 组合索引最左前缀原则
CREATE INDEX idx_name_age ON users(name, age);

-- 查询可以使用索引
SELECT * FROM users WHERE name = 'Alice';
SELECT * FROM users WHERE name = 'Alice' AND age = 25;

-- 查询无法使用索引
SELECT * FROM users WHERE age = 25;
```

## 事务控制

```sql
-- 开启事务
START TRANSACTION;

-- 或者
BEGIN;

-- 提交事务
COMMIT;

-- 回滚事务
ROLLBACK;

-- 设置保存点
SAVEPOINT sp1;

-- 回滚到保存点
ROLLBACK TO SAVEPOINT sp1;
```

### 事务隔离实现

```sql
-- 脏读示例 (READ UNCOMMITTED)
-- T1: UPDATE users SET age = 31 WHERE id = 1;
-- T2: SELECT age FROM users WHERE id = 1;  -- 读到未提交的 31
-- T1: ROLLBACK;  -- T2 读到了脏数据
```

## MVCC（多版本并发控制）

MVCC 通过维护数据的多个版本来实现并发控制，每个事务看到的是特定时间点的数据快照。

```
┌─────────────────────────────────────────────────────────┐
│                    MVCC 工作原理                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  时间线                                                │
│  ──────────────────────────────────────────────────►   │
│                                                         │
│  T1                    T2                    T3          │
│  开始                     │                     │        │
│   │                      │                     │        │
│   │◄─── 读取快照 A ──────┤                     │        │
│   │                      │                     │        │
│   │                修改数据 A → A'              │        │
│   │                      │                     │        │
│   │                      │◄──── 读取快照 A ────┤        │
│   │                      │                     │        │
│   │                      │               提交 A' │        │
│   │                      │                     │        │
│   │                      │              ◄─── 读取 A'   │
│                                                         │
│  每个事务看到的是开始时的数据版本                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### InnoDB MVCC 实现

```sql
-- MySQL InnoDB 隐藏列
-- 每行数据包含:
--   DB_TRX_ID: 事务ID
--   DB_ROLL_PTR: 回滚指针
--   DB_ROW_ID: 行ID (聚簇索引)

-- 查看 InnoDB 行结构
SELECT * FROM information_schema.innodb_sys_tables;
SELECT * FROM information_schema.innodb_sys_columns WHERE table_id = ?;
```

### 快照读 vs 当前读

```sql
-- 快照读：读取历史版本（普通 SELECT）
SELECT * FROM users WHERE id = 1;  -- 不加锁，读取快照

-- 当前读：读取最新版本（加锁）
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE;  -- 共享锁
SELECT * FROM users WHERE id = 1 FOR UPDATE;           -- 排他锁

-- 插入/更新/删除也是当前读
INSERT INTO users (name) VALUES ('Alice');  -- 排他锁
UPDATE users SET name = 'Bob' WHERE id = 1; -- 排他锁
DELETE FROM users WHERE id = 1;             -- 排他锁
```

### 事务可见性规则

```
┌─────────────────────────────────────────────────────────┐
│                 事务可见性判断流程                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 比较事务ID:                                         │
│     - 数据事务ID > 当前事务ID → 不可见（未来事务）      │
│     - 数据事务ID <= 当前事务ID → 可能可见               │
│                                                         │
│  2. 检查 undo log:                                     │
│     - 数据在 undo log 中 → 读取历史版本                 │
│     - 不在 undo log → 读取当前数据                      │
│                                                         │
│  3. 检查提交状态:                                       │
│     - 未提交事务的修改 → 不可见                          │
│     - 已提交事务的修改 → 可见                          │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 查询优化器

查询优化器分析 SQL 语句，选择最优执行计划。

### 执行计划分析

```sql
-- MySQL EXPLAIN
EXPLAIN SELECT * FROM users u
JOIN orders o ON u.id = o.user_id
WHERE u.age > 25;

-- 输出字段说明:
-- id: SELECT 序号
-- select_type: 查询类型 (SIMPLE/PRIMARY/SUBQUERY)
-- table: 表名
-- type: 访问类型 (ALL/INDEX/RANGE/REF/EQ_REF)
-- possible_keys: 可用索引
-- key: 实际使用索引
-- key_len: 索引长度
-- rows: 预计扫描行数
-- Extra: 附加信息 (Using index/Using filesort)

-- 更详细的分析
EXPLAIN ANALYZE SELECT * FROM users WHERE age > 25;
-- ANALYZE 会实际执行并显示真实代价
```

### 常见访问类型

| type | 说明 | 性能 |
|------|------|------|
| ALL | 全表扫描 | 最差 |
| INDEX | 索引全扫描 | 较差 |
| RANGE | 索引范围扫描 | 一般 |
| REF | 索引等值查询 | 较好 |
| EQ_REF | 主键/唯一索引 | 好 |
| CONST/SYSTEM | 常量查询 | 最好 |

### 索引选择策略

```sql
-- 查看索引使用情况
SHOW INDEX FROM users;

-- 强制使用索引
SELECT * FROM users USE INDEX (idx_age) WHERE age > 25;

-- 忽略索引
SELECT * FROM users IGNORE INDEX (idx_age) WHERE age > 25;

-- 强制不使用索引（当需要全表扫描时）
SELECT * FROM users FORCE INDEX (idx_age) WHERE age > 25;
```

### 查询优化技巧

```sql
-- 避免 SELECT *
SELECT u.id, u.name FROM users u WHERE u.id = 1;

-- 使用覆盖索引（索引覆盖查询所有字段）
CREATE INDEX idx_name_age ON users(name, age);
-- SELECT name, age FROM users WHERE name = 'Alice'; -- 使用覆盖索引

-- 减少函数在索引列上使用
-- 错误: WHERE YEAR(created_at) = 2024
-- 正确: WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01'

-- 使用延迟关联
SELECT * FROM users ORDER BY id LIMIT 100000, 10;
-- 优化: 先分页获取ID，再关联
SELECT u.* FROM users u
INNER JOIN (SELECT id FROM users ORDER BY id LIMIT 100000, 10) t
ON u.id = t.id;
```

## 分布式数据库

分布式数据库将数据分散存储在多个节点上，提供高可用和横向扩展能力。

### 分布式架构类型

```
┌─────────────────────────────────────────────────────────┐
│                    分布式架构类型                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  主从复制 (Master-Slave)                                │
│  ┌────────┐                                            │
│  │ Master │ ←── 复制 ──→ ┌────────┐                   │
│  │ (写/读) │            │ Slave  │                   │
│  └────────┘            │(读/备写)│                   │
│                        └────────┘                    │
│                                                         │
│  主主复制 (Multi-Master)                                │
│  ┌────────┐            ┌────────┐                     │
│  │ Master1│◄──复制───►│ Master2│                     │
│  │ (写/读) │            │ (写/读) │                     │
│  └────────┘            └────────┘                    │
│                                                         │
│  分片 (Sharding)                                       │
│  ┌────────┐  ┌────────┐  ┌────────┐                   │
│  │ Shard1 │  │ Shard2 │  │ Shard3 │                   │
│  │ 0-33%  │  │ 34-66% │  │ 67-99% │                   │
│  └────────┘  └────────┘  └────────┘                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 分片策略

| 策略 | 说明 | 示例 |
|------|------|------|
| 范围分片 | 按ID范围划分 | 0-1000 → Shard1 |
| 哈希分片 | Hash(ID) % N | 均衡分布 |
| 目录分片 | 查表获取分片位置 | 灵活但有单点 |
| 地理位置 | 按地域划分 | 用户就近访问 |

```sql
-- 哈希分片示例 (MySQL Cluster)
CREATE TABLE users (
    id INT,
    name VARCHAR(100)
) ENGINE=NDBCLUSTER;

-- 按用户ID哈希分片
-- 对 1000 取模决定分片
-- 分片 = hash(user_id) % 1000
```

### 一致性协议

#### CAP 定理

```
分布式系统最多同时满足两个特性:
- Consistency (一致性): 所有节点看到相同数据
- Availability (可用性): 每个请求都有响应
- Partition Tolerance (分区容错): 网络分区时仍可运行

CP 系统: ZooKeeper, etcd, HBase, MongoDB
AP 系统: Cassandra, DynamoDB, CouchDB
```

#### BASE 理论

```
BASE = Basically Available + Soft State + Eventually Consistent

- Basically Available: 保证可用性
- Soft State: 状态可能不同步
- Eventually Consistent: 最终一致
```

### 分布式事务

#### 两阶段提交 (2PC)

```
┌─────────────────────────────────────────────────────────┐
│                    两阶段提交                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Phase 1: Prepare                                      │
│  ┌────────┐                                            │
│  │ TM     │ ← 协调者                                   │
│  │发送投票│                                            │
│  └───┬───┘                                            │
│      │                                                │
│  ┌───▼───┐ ┌───▼───┐                                 │
│  │ P1    │ │ P2    │ ← 参与者                         │
│  │ Prepare│ │ Prepare│                                 │
│  └───┬───┘ └───┬───┘                                 │
│      │YES      │YES                                   │
│      └────┬────┘                                      │
```

### 数据分区 (Partitioning)

```sql
-- MySQL 表分区
CREATE TABLE orders (
    id INT,
    order_date DATE,
    amount DECIMAL(10,2)
) PARTITION BY RANGE (YEAR(order_date)) (
    PARTITION p2020 VALUES LESS THAN (2021),
    PARTITION p2021 VALUES LESS THAN (2022),
    PARTITION p2022 VALUES LESS THAN (2023),
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION pmax VALUES LESS THAN MAXVALUE
);

-- PostgreSQL 表分区
CREATE TABLE orders (
    id INT,
    order_date DATE,
    amount DECIMAL(10,2)
) PARTITION BY RANGE (order_date);

CREATE TABLE orders_2023 PARTITION OF orders
    FOR VALUES FROM ('2023-01-01') TO ('2024-01-01');

-- 查询分区信息
SELECT * FROM information_schema.partitions
WHERE table_name = 'orders';
```
