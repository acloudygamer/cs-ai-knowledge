# 数据库基础

> **版本基准**: universal

## 定义

数据库是自描述的、逻辑相关的持久化数据集合，支持高效存取和事务语义。数据库系统的核心抽象是**数据独立性**：应用程序不应感知物理存储细节，通过逻辑模型与物理存储的映射实现隔离。

**归约内核**：数据库的本质是**持久化的键值存储 + 事务语义**。键值存储提供基本的读写能力，事务语义在此基础上增加了原子性、一致性、隔离性、持久性的保证。

## 数学模型

### B+树索引复杂度

B+树是数据库索引的标准结构，其查询复杂度为：

$$
T_{search} = O(\log_{fanout}(N)) = O\left(\frac{\log N}{\log B}\right)
$$

其中 $fanout$ 取决于页大小和键长度， $B$ 是出度。典型值：页大小 16KB，键 8 字节，指针 8 字节，fanout ≈ 1000。

对于 $N = 10^6$ 条记录， $T_{search} = \log_{1000}(10^6) \approx 2$ 次 I/O。

### 事务隔离级别的形式化

隔离级别定义了并发事务之间的可见性规则：

| 现象 | 描述 | 根因 |
|------|------|------|
| 脏读（Dirty Read） | 读取另一事务未提交的数据 | 写锁释放时机过早 |
| 不可重复读（Non-repeatable Read） | 同一事务两次读取同一数据结果不同 | 读锁未覆盖整个事务 |
| 幻读（Phantom Read） | 同一事务两次查询结果集不同 | 范围锁缺失 |

隔离级别与并发度的关系：

$$
Throughput \propto \frac{1}{Isolation_{level}}
$$

更弱的隔离级别允许更多并发，但引入更多异常风险。

**隔离级别的偏序关系**：

$$
\text{SERIALIZABLE} > \text{REPEATABLE READ} > \text{READ COMMITTED} > \text{READ UNCOMMITTED}
$$

### 规范化与查询代价

设关系模式 $R$ 分解为 $\{R_1, R_2, ..., R_n\}$ ，无损耗分解要求：

$$
R \Join_{\bowtie} \pi_{R_1}(R) = R
$$

**规范化范式的包含关系**：

$$
1NF \subset 2NF \subset 3NF \subset BCNF
$$

每层规范化消除特定类型的依赖和异常。

### 日志 Write-Ahead 的数学约束

WAL（Write-Ahead Logging）协议要求：

$$
\text{日志 flush} \Rightarrow \text{数据 page flush}
$$

即日志必须先于数据写入磁盘。

**数据形态变换链路**：

1. `SQL 文本` → `词法分析器` → `Token 流`
2. `Token 流` → `语法分析器` → `AST（抽象语法树）`
3. `AST` → `语义分析器` → `逻辑计划（关系代数）`
4. `逻辑计划` → `查询优化器` → `物理计划（操作符树）`
5. `物理计划` → `执行器` → `数据页读取`
6. `数据页` → `结果集` → `网络传输`

## 机制

### ACID 语义的本质约束

**原子性（Atomicity）**：事务是最小执行单位，全有或全无。实现机制是**回滚日志（Undo Log）**：事务修改前记录旧值，失败时逆向恢复。

**一致性（Consistency）**：事务执行前后，数据库状态均满足所有完整性约束。一致性是**应用属性**而非数据库属性——数据库只能检测约束违反，无法保证业务逻辑一致性。

**隔离性（Isolation）**：并发事务的执行效果与串行执行相同。实现机制包括：
- **两阶段锁（2PL）**：扩展阶段只加锁，收缩阶段只释放锁
- **MVCC（多版本并发控制）**：每个事务看到特定时间点的数据快照

**持久性（Durability）**：事务提交后，结果不因系统故障丢失。实现机制是**重做日志（Redo Log）** + **检查点（Checkpoint）**。

### 两阶段锁的数学约束

两阶段锁（2PL）分为扩展阶段和收缩阶段：

$$
\forall T_i: \text{Growing}_i \land \text{Shrinking}_i \quad \text{（必须先增长后收缩）}
$$

**可串行化性证明**：若所有事务遵守 2PL，则调度是可串行化的。

### MVCC 的版本链管理

MVCC 中每次更新产生新版本，版本通过指针链连接：

$$
\text{Version}_k \rightarrow \text{Version}_{k-1} \rightarrow \cdots \rightarrow \text{Version}_0
$$

事务 $T$ 读取时，遍历版本链找到第一个满足以下条件的版本：

$$
\text{Version}_i.start\_ts \leq T.snapshot\_ts \land \text{Version}_i.end\_ts > T.snapshot\_ts
$$

### 索引维护的代价

每次写操作（INSERT/UPDATE/DELETE）需要更新所有相关索引。设表有 $k$ 个索引，写放大因子：

$$
W_{amplification} = 1 + k
$$

对于 10 个索引的表，每次写入代价是单索引的 11 倍。

### 查询优化的成本模型

查询优化器选择执行计划的依据是**成本估算**：

$$
Cost = \sum_{op} (N_{page\_reads} \times T_{disk\_read} + N_{cpu\_ops} \times T_{cpu})
$$

## 参考存根

```sql
-- 创建 B+树 索引
CREATE INDEX idx_user_name ON users(name);

-- 事务示例
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE user_id = 1;
UPDATE accounts SET balance = balance + 100 WHERE user_id = 2;
COMMIT;

-- MVCC 版本查询（PostgreSQL）
SELECT * FROM users WHERE xmin = (SELECT xmin FROM users WHERE id = 1);
```

```python
# SQLAlchemy 事务示例
with session.begin():
    user1 = session.query(User).filter_by(id=1).one()
    user2 = session.query(User).filter_by(id=2).one()
    user1.balance -= 100
    user2.balance += 100
```
