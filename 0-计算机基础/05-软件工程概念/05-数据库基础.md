# 数据库基础

## 概念

**数据库**是组织、存储和管理数据的系统,提供数据持久化和查询能力。

```
┌─────────────────────────────────────────────────────────┐
│                    数据库系统架构                        │

│                                                         │

│                            │                           │
│                      ┌─────▼─────┐                     │

│  ┌─────────────┐     ┌─────▼─────┐     ┌────────────┐ │

│  └─────────────┘     └───────────┘     └──────┬─────┘│
│                                                 │      │
```

## 关系

**关键连接**:
- 关系型 → **SQL**: 使用结构化查询语言
- NoSQL → **文档/键值**: 非结构化存储
- ACID → **事务**: 保证数据一致性
- 索引 → **查询优化**: 加速数据检索

## 数据库类型

### 关系型数据库 (RDBMS)

| 数据库 | 特点 | 典型场景 |
|--------|------|----------|
| MySQL | 开源,最流行 | Web 应用 |

### 非关系型数据库 (NoSQL)

| 类型 | 数据模型 | 示例 |
|------|----------|------|
| 键值存储 | Key-Value 对 | Redis, Memcached |

| 图数据库 | 节点和边 | Neo4j |

```bash
# 键值存储示例 (Redis)
```

## ACID 特性

ACID 是事务的四个基本特性:

```
┌─────────────────────────────────────────────────────────┐
│                    ACID 特性                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  A - Atomicity (原子性)                                 │
│     事务要么全部成功,要么全部失败                        │
│                                                         │
│  C - Consistency (一致性)                               │
│     事务前后数据库状态都是有效的                         │
│                                                         │
│  I - Isolation (隔离性)                                │
│     并发事务相互隔离,不互相干扰                         │
│                                                         │
│  D - Durability (持久性)                               │
│     事务提交后,结果永久保存                             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 不可能 | 可能 | 可能 |
| REPEATABLE READ | 不可能 | 不可能 | 可能 |
| SERIALIZABLE | 不可能 | 不可能 | 不可能 |

```sql
-- 设置隔离级别
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- MySQL 默认 REPEATABLE READ
-- PostgreSQL 默认 READ COMMITTED
```

## SQL 基础

### 数据定义 (DDL)

```sql
-- 创建表
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE,
    age INT DEFAULT 18,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 修改表结构
ALTER TABLE users ADD COLUMN phone VARCHAR(20);
ALTER TABLE users MODIFY COLUMN age INT NOT NULL;
ALTER TABLE users DROP COLUMN phone;

-- 删除表
DROP TABLE users;

-- 创建索引
CREATE INDEX idx_name ON users(name);
CREATE UNIQUE INDEX idx_email ON users(email);
CREATE INDEX idx_age_name ON users(age, name);

-- 外键约束
CREATE TABLE orders (
    id INT PRIMARY KEY,
    user_id INT,
    FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
```

### 数据操作 (DML)

```sql
-- 插入数据
INSERT INTO users (name, email, age) VALUES
    ('Alice', 'alice@example.com', 25),
    ('Bob', 'bob@example.com', 30);

-- 更新数据
UPDATE users SET age = 31 WHERE name = 'Bob';

-- 删除数据
DELETE FROM users WHERE id = 1;

-- 查询数据
SELECT * FROM users;
SELECT name, email FROM users WHERE age > 20;
SELECT * FROM users ORDER BY age DESC LIMIT 10;
```

### 聚合查询

```sql
-- 计数
SELECT COUNT(*) FROM users;
SELECT COUNT(*) FROM users WHERE age > 25;

-- 分组
SELECT age, COUNT(*) as cnt
FROM users
GROUP BY age
HAVING cnt > 1;

-- 聚合函数
SELECT
    AVG(age),           -- 平均值
    SUM(age),           -- 总和
    MIN(age),           -- 最小值
    MAX(age),           -- 最大值
    GROUP_CONCAT(name) -- 字符串连接
FROM users;
```

### 多表查询

```sql
-- 内连接
SELECT u.name, o.order_id
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- 左连接
SELECT u.name, o.order_id
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

-- 右连接
SELECT u.name, o.order_id
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- 子查询
SELECT * FROM users
WHERE age > (SELECT AVG(age) FROM users);

-- EXISTS
SELECT * FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
);
```

## 索引原理

### B+ 树索引

```
B+ 树结构 (每个节点包含多个键值):

        [50, 70]
       /    |    \
    [20]  [50]  [70, 90]
     ↓      ↓      ↓
   叶节点  叶节点   叶节点
   ↓ ↓ ↓   ↓ ↓    ↓ ↓ ↓
  数据指针  指向下一级,最终指向数据
```

| 操作 | 时间复杂度 |
|------|------------|
| 查找 | O(log n) |
| 插入 | O(log n) |
| 删除 | O(log n) |
| 范围查询 | O(log n + k) |

### 索引类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| 主键索引 | 值唯一,非空 | 主键 |
| 唯一索引 | 值唯一,可空 | 邮箱,手机号 |
| 普通索引 | 值可重复 | 常见查询字段 |
| 全文索引 | 文本内容搜索 | 文章搜索 |
| 组合索引 | 多列组合 | 多条件查询 |

```sql
-- 组合索引最左前缀原则
CREATE INDEX idx_name_age ON users(name, age);

-- 查询可以使用索引
SELECT * FROM users WHERE name = 'Alice';
SELECT * FROM users WHERE name = 'Alice' AND age = 25;

-- 查询无法使用索引
SELECT * FROM users WHERE age = 25;
```

## 事务控制

```sql
-- 开启事务
START TRANSACTION;

-- 或者
BEGIN;

-- 提交事务
COMMIT;

-- 回滚事务
ROLLBACK;

-- 设置保存点
SAVEPOINT sp1;

-- 回滚到保存点
ROLLBACK TO SAVEPOINT sp1;
```

### 事务隔离实现

```sql
-- 脏读示例 (READ UNCOMMITTED)
-- T1: UPDATE users SET age = 31 WHERE id = 1;
-- T2: SELECT age FROM users WHERE id = 1;  -- 读到未提交的 31
-- T1: ROLLBACK;  -- T2 读到了脏数据
```

## 关系型 vs 非关系型

| 特性 | 关系型 | 非关系型 |
|------|--------|----------|
| 数据模型 | 表,行,列 | 键值,文档,列族,图 |
| 事务 | ACID | BASE (最终一致) |
| 查询语言 | SQL | 各不相同 |
| 扩展性 | 垂直扩展 | 水平扩展 |
| 适用场景 | 结构化数据 | 半/非结构化数据 |
| 完整性 | 强 | 弱 |

```javascript
// MongoDB 文档示例
{
    "_id": ObjectId("..."),
    "name": "Alice",
    "email": "alice@example.com",
    "friends": [
        { "name": "Bob", "since": 2020 },
        { "name": "Carol", "since": 2021 }
    ],
    "settings": {
        "notifications": true,
        "theme": "dark"
    }
}

// Redis 键值示例
user:1000 -> { name: "Alice", email: "alice@example.com" }
user:1000:friends -> Set ["Bob", "Carol"]
user:1000:settings -> Hash { notifications: "true", theme: "dark" }
```

## 数据库设计

### 规范化

| 范式 | 要求 | 示例 |
|------|------|------|
| 1NF | 原子性,无重复列 | 地址拆分为省/市/区 |
| 2NF | 满足1NF,非主键列完全依赖主键 | 订单表拆分 |
| 3NF | 满足2NF,非主键列不传递依赖 | 学院→学生→课程 |

```sql
-- 反规范化示例 (为了性能)
-- 订单表冗余存储用户信息
CREATE TABLE orders (
    id INT PRIMARY KEY,
    user_id INT,
    user_name VARCHAR(100),    -- 冗余:避免连表查询
    user_email VARCHAR(255),   -- 冗余
    total_amount DECIMAL(10,2)
);
```

## 常见问题与优化

### SQL 注入

```sql
-- 危险: 用户输入直接拼接
SELECT * FROM users WHERE name = '" + userInput + "'";

-- 安全: 使用参数化查询
SELECT * FROM users WHERE name = ?;
```

### 查询优化

```sql
-- 避免 SELECT *
SELECT id, name FROM users WHERE id = 1;

-- 使用 EXPLAIN 分析查询
EXPLAIN SELECT * FROM users WHERE name = 'Alice';

-- 创建适当索引
CREATE INDEX idx_name ON users(name);

-- 避免函数在索引列上
-- 慢: WHERE YEAR(created_at) = 2024
-- 快: WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01'
```

```bash
# PostgreSQL EXPLAIN
EXPLAIN ANALYZE SELECT * FROM users WHERE name = 'Alice';
# Index Scan using idx_name on users (cost=0.43..8.45 rows=1)
#   Index Cond: (name = 'Alice')
#   Execution Time: 0.184 ms
```
