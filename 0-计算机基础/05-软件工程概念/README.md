# 软件工程概念

> **版本基准**: universal

本部分讲"代码写出来之后"的工程层：如何组织代码、验证正确、管理变更、交付运行，以及系统形态如何随规模切分。主线约束是**复杂度与协作**——代码量超出一个头脑的容量、团队超出一个人的协调半径之后，每一篇回应这个约束的一个侧面。

本部分只讲与语言无关的概念层；具体工具实现见各语言文件夹（如 2-Python 的测试与设计模式）。

测试金字塔的约束（速度×信心×成本）、集成层守接缝、可测性是设计属性、覆盖率是工具不是目标

内容寻址对象库（blob/tree/commit）、分支与 HEAD 是指针、merge vs rebase 的历史观、分布式的结构含义

集成地狱与发布仪式的约束、流水线阶段与快失败、不可变产物、滚动/蓝绿/金丝雀部署

部署单元对齐业务边界、康威定律、分布式税清单（延迟/事务/观测/契约）、先单体后拆分的时机共识

## 阅读顺序

01→05 沿工件的生命周期（组织代码 → 验证 → 管变更 → 交付 → 运行形态）；06→08 沿系统形态的切分粒度（前后端 → 数据 → 服务）；09 贯穿全部，任何时候读都不算晚。
