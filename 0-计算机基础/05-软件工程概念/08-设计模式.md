# 设计模式

## 定义

设计模式是针对特定上下文中常见问题的可重用解决方案，通过建立对象间明确的职责边界和通信契约来管理复杂性。

## 数学模型

模式应用前后耦合度变化：

$$
C_{before} = \frac{E}{N(N-1)/2}, \quad C_{after} = \frac{E'}{N'(N'-1)/2}
$$

使用适配器模式将 $N$ 个类与 $M$ 个接口的直接耦合 $O(NM)$ 转换为 $O(N+M)$。

## 数据流

<pre>
客户端                    目标接口                    适配器                    被适配者
   │                          │                          │                          │
   │── request() ───────────►│                          │                          │
   │   (期望接口)              │                          │                          │
   │                          │── request() ───────────►│                          │
   │                          │                          │── specific_request() ──►│
   │                          │                          │◄── result ─────────────│
   │                          │◄── transformed ─────────│                          │
   │◄── result ──────────────│                          │                          │
</pre>

数据形态变换：`客户端请求(目标格式)` → `适配器(接口转换)` → `被适配者调用(原有格式)` → `结果转换` → `客户端接收(目标格式)`

## 机制

### 核心约束

1. **开闭原则**：对扩展开放，对修改关闭，通过抽象和解耦实现
2. **依赖倒置**：依赖抽象而非具体实现，降低耦合度
3. **最小接口**：接口应小而专注，实现者只需关心相关行为

### 违规后果

- 违反开闭原则导致修改扩散，影响面不可控
- 依赖具体类而非抽象导致测试困难、扩展受限
- 大接口造成实现负担，引入不必要的依赖

### 模式分类

| 类型 | 解决的问题 | 代表模式 |
|------|-----------|----------|
| 创建型 | 对象创建解耦 | 单例、工厂、建造者 |
| 结构型 | 对象组合形成更大结构 | 适配器、装饰器、代理 |
| 行为型 | 对象间职责分配 | 观察者、策略、命令 |

## 参考存根

```python
class Adapter(Target):
    def __init__(self, adaptee):
        self._adaptee = adaptee
    def request(self):
        return self._adaptee.specific_request()[::-1]
```
