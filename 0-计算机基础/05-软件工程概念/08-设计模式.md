# 设计模式

> **版本基准**: universal

## 定义

设计模式是针对特定上下文中常见问题的可重用解决方案，通过建立对象间明确的职责边界和通信契约来管理复杂性。模式的本质是**经验封装**：将经过验证的设计决策抽象为可描述、可传授的结构。GoF 模式按目的分为创建型、结构型、行为型三类。

**归约内核**：设计模式的本质是**对组件间依赖关系的规范约束**。每种模式定义了一种特定的依赖结构，通过限制组件间的连接方式，降低系统复杂度，提高可维护性。

$$

**数据形态变换链路**（以适配器为例）：

1. `客户端请求（目标格式）` → `适配器接口`
2. `适配器接口` → `适配器实现（接口转换逻辑）`
3. `适配器实现` → `被适配者调用（原有格式）`
4. `被适配者返回` → `结果转换（格式逆向转换）`
5. `转换后结果` → `客户端接收（目标格式）`

## 机制

### 开闭原则的约束边界

开闭原则的实现依赖**抽象层**的存在。约束表述：
- 必须存在稳定的抽象接口
- 变化部分必须封装为可替换的实现

违反此约束的情况是**强行扩展而不抽象**：直接在原有类上添加新方法，导致修改扩散。

### 依赖倒置的具体形式

依赖倒置（Dependency Inversion）的约束是：
- 高层模块不应依赖低层模块，两者都应依赖抽象
- 抽象不应依赖细节，细节应依赖抽象

具体实现是**控制反转（IoC）**：对象的创建权从使用方转移到外部容器。

### 最小接口的组合价值

接口隔离原则（ISP）要求接口小而专注。其约束是：

$$
\forall c \in C, \exists I \subseteq Methods: \text{client uses only } I
$$

即每个客户端只应看到它使用的方法。

### 创建型模式的本质差异

| 模式 | 解耦目标 | 实例化方式 | 适用场景 |
|------|----------|-----------|----------|
| 单例 | 全局唯一 | 类自己控制 | 共享资源、配置 |
| 工厂方法 | 对象创建延迟 | 子类决定创建什么 | 对象类型可扩展 |
| 抽象工厂 | 产品族创建 | 客户代码不依赖具体类 | 多产品族切换 |
| 建造者 | 复杂对象构造 | 链式构造，分步构建 | 可选参数多 |

**单例的约束**：单例实例必须在整个程序生命周期唯一。这使其成为**隐式依赖**——模块间通过全局状态耦合，难以测试。

### 结构型模式的组合语义

| 模式 | 组合方式 | 运行时行为 |
|------|----------|-----------|
| 适配器 | 包装被适配者 | 接口转换 |
| 装饰器 | 层层包裹 | 动态增强 |
| 代理 | 表面替代 | 控制访问 |
| 组合 | 树形结构 | 递归组合 |
| 外观 | 统一入口 | 简化子系统 |

**装饰器的数学表示**：

$$
(D_n \circ D_{n-1} \circ \cdots \circ D_1)(x) = D_n(D_{n-1}(...D_1(x)...))
$$

### 行为型模式的对象职责分配

| 模式 | 职责分配 | 扩展方向 |
|------|----------|----------|
| 观察者 | 一对多通知 | 新观察者 |
| 策略 | 算法可替换 | 新算法 |
| 命令 | 请求封装 | 新命令 |
| 责任链 | 请求传递 | 新处理器 |
| 状态 | 状态驱动的行为 | 新状态 |

**观察者模式的状态同步约束**：

$$
\forall s \in S, \forall o \in Observers: o.update(s)
$$

即当主体状态 $s$ 变化时，所有观察者必须被通知并更新。 变化时，所有观察者必须被通知并更新。

```python
def log_calls(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Called {func.__name__}, result: {result}")
        return result
    return wrapper
```
