# 系统调用与中断

## 一、四段式分派：从 `syscall` 指令到系统调用表项的固定路径

系统调用是三条入口里唯一由程序主动发起的一条，路径上没有可选分支：调用号装哪个寄存器、入口地址从哪读、现场压成什么结构、由哪张表决定下一步，全部由 ABI 与硬件固定。整条路切成四段，分界不在代码归属，而在「谁有权改写下一段要读的数据结构」——用户段改不动 MSR，入口桩改不动调用号，分派器改不动帧布局。01 篇「判据存放在被检查者无权改写的介质里」在入口处第一次兑现。

```text
 用户平面（CPL=3）                      内核平面（CPL=0）
 ──────────────────────────────────────────────────────────────────────
 ① 装号【转发】libc 桩 / ntdll!Nt* 桩
    rax = 39（__NR_getpid）      NT: mov r10, rcx ; mov eax, SSN
    rdi/rsi/rdx/r10/r8/r9 传参    NT: rcx/rdx/r8/r9 传参，第 5 个起走栈
    syscall ────────────┐
                        │ ② 换态【解析】不读内存，只读 3 个 MSR
                        ├─ RIP    ← IA32_LSTAR（0xC0000082）
                        ├─ CS:SS  ← IA32_STAR（0xC0000081）
                        ├─ RFLAGS &= ~IA32_FMASK（0xC0000084）
                        ├─ RCX ← 下一条 RIP，R11 ← 原 RFLAGS
                        └─ RSP 不动，仍是用户栈指针
                        ▼
 ③ 建帧【转发】entry_SYSCALL_64 / KiSystemCall64
    swapgs：GS.base 由用户 TLS 切到每 CPU 控制区
    RSP ← 本核 TSS 的内核栈顶（每 CPU 变量，非 MSR）
    21 次压栈 = 168 B：15 个 GPR + ss/sp/flags/cs/ip/orig_ax
                        │
                        ▼
 ④ 查表【解析】唯一读调用号的节点
    Linux：nr = rax（bit30 判 x32）→ 上界判定 → sys_call_table[nr]（8 B 指针）
    NT   ：eax = SSN → KiServiceTable[nr]（4 B 相对偏移）→ 目标地址
                        │
                        ▼
 ⑤ 回落【解析】判快慢出口
    Linux：sysretq（RCX 规范且 R11 合法）／否则 iretq 走完整帧
    NT   ：KiSystemServiceReturn，同一判据
    返回值 → rax（Linux 负值即 -errno；NT 为 NTSTATUS，高位是严重性字段）
```

### 1. 四段的边界由「谁能写下一段要读的东西」划出

① 的全部输入是寄存器，而寄存器由用户态任意摆布，所以它不能承担任何裁决：把 39 装进 `RAX` 与装完再跳去别处，在内核看来没有区别。让这次跳转有效的 ② 把目标地址放在 `IA32_LSTAR` 里，写 MSR 的 `WRMSR` 是 `CPL=0` 指令——入口地址因此是用户态不可写的常量，这是整条路径的安全底座。

③ 的输入是硬件没保存的那部分寄存器。`syscall` 只存了 `RCX`/`R11` 两个值并换掉了 `CS`/`SS`，其余 12 个通用寄存器仍是用户值，入口桩得趁 C 代码踩坏它们之前一次性落栈：15 个 GPR 加 `ss/sp/flags/cs/ip/orig_ax` 共 21 槽、168 B，即 `pt_regs`。168 B 是贯穿全篇的常数，它跨 3 条 64 B 缓存行，每次调用至少 2 次行填充——`getpid` 一类高频调用的一半便宜来自这几行始终留在内核栈热区。NT 的 `KTRAP_FRAME` 同思路但更宽，约为 `pt_regs` 的 2 倍档，额外记录 `PreviousMode`（决定参数能否被直接解引用）、异常链与调试状态。

### 2. 逐段遍历：两个解析点、两个转发点、一个判定点

**边 ①（转发）。** 桩只搬寄存器：Linux 把第 4 个参数从 `RCX` 挪到 `R10`，因为 `syscall` 会覆写 `RCX`；NT 反过来把第 1 个参数从 `RCX` 挪到 `R10`，把 `RCX` 让给返回地址。同一个硬件行为，两个 ABI 给出方向相反的补丁，这是双平台差异中唯一不涉及内核代码的一处。转发点的可观测后果是：内核能看到的只有 `RAX` 里的整数与 6 个参数寄存器。

**边 ②（解析）。** 换态是 4 个互不依赖的读：`IA32_LSTAR` 给 `RIP`、`IA32_STAR` 给 `CS`/`SS`、`IA32_FMASK` 给要清的标志位，外加把当前 `RIP`/`RFLAGS` 存入 `RCX`/`R11`。这 4 个读都不访存——MSR 是核内寄存器，个位数拍。`int 0x80` 必须按 `IDTR.base + 0x80 × 16` 读 16 B 门描述符，任一缺失就是数百拍罚金。

**边 ③（转发）。** 顺序不可交换，原因是 KPTI：用户页在内核页表里不可见，所以必须先把用户 `RSP` 存进每 CPU 的 `TSS_sp2`，再切 `CR3`，最后装内核栈顶。若先切 `CR3`，那条存 `RSP` 的 `mov` 自己就 `#PF`，而此刻栈上还没有可用帧。`swapgs` 到 `mov %rsp` 之间还有 3~5 条指令的空窗：`GS` 已是内核值、`RSP` 仍是用户值，NMI 若在此到达，硬件不换栈（`CPL` 未变），帧会写给用户栈——这是 NMI/`#DF`/`#MC` 必须走 IST 的直接原因（§3.3）。

**边 ④（解析）。** `do_syscall_64` 取 `RAX`、判上界、间接调用；上界判定后还有一道 `array_index_nospec` 掩码，把推测执行下的越界索引压回 0，让猜错的路径读不到东西。越界槽位统一指向 `__x64_sys_ni_syscall`，返回 `-ENOSYS`，故错号不崩内核。x32 复用同一张表，靠 `RAX` 的 bit30（`__X32_SYSCALL_BIT`）分流——用调用号自身位段携带 ABI 信息，不占额外寄存器。

**边 ⑤（判定）。** `sysretq` 只从 `RCX`/`R11` 恢复 `RIP`/`RFLAGS`，不回读栈帧、不恢复 `RSP`，成立条件是 `RCX` 规范、`R11` 不触发特权检查、返回目标确为用户 `CS`；任一不满足即退到 `iretq` 走完整帧。非规范 `RCX` 在部分实现上会让 `sysret` 在 `CPL=0` 抛 `#GP`，构成提权面，现代内核因此在 `sysret` 前显式校验，或对可疑目标改走 `iretq`。

调用密度决定这段路径值不值得优化。空载 `getpid` 落在 $50 \sim 80\ \text{ns}$ 档（约 150~300 拍），缓解全开（KPTI 两次 `CR3` 写 + 分派点序列化）后升至百纳秒档，约为基线 2 倍；单核上限由每秒 $10^{7}$ 次档跌到 $10^{6}$ 次档。判据由此成立：只有每秒 $10^{6}$ 次以上的密度（逐条 `read` 的小包收发、逐次自旋探测）才会把 CPU 打到 10% 以上，此时有效方向是减少次数（`vDSO`、批处理、`io_uring`），而非把单次从 80 ns 压到 60 ns。

### 3. 表项格式决定调用号能不能当 ABI

| 段 | 特权级 | 关键数据结构 | 双平台差异项 |
| --- | --- | --- | --- |
| ① 装号 | `CPL=3` | 无（纯寄存器约定） | Linux 6 个参数寄存器含 `R10`；NT 4 个，第 1 个让位返回地址后搬进 `R10` |
| ② 换态 | 硬件完成，落 `CPL=0` | `IA32_LSTAR`/`IA32_STAR`/`IA32_FMASK` | 两侧同一组 MSR；NT 用 `IA32_STAR` 同时编码内核与用户 `CS`/`SS` |
| ③ 建帧 | `CPL=0` | `pt_regs`（168 B）／`KTRAP_FRAME`（2 倍档） | NT 多存 `PreviousMode`、异常链、调试状态；Linux 帧尾是 `orig_ax` |
| ④ 查表 | `CPL=0` | `sys_call_table`：8 B 函数指针／`KiServiceTable`：4 B 相对偏移 | Linux 表项是绝对地址，可直接打印符号；NT 表项要加表基址才能定位 |
| ⑤ 回落 | 硬件完成，回 `CPL=3` | 无（`RCX`/`R11` 或 `iret` 帧） | 两侧都以 `sysret` 为快路径；`ptrace`/`seccomp` 改写返回值后强制 `iretq` |

第 4 行是唯一影响「用户程序怎么写」的一行。Linux 的调用号被冻结成 ABI：`getpid` 恒为 39、`openat` 恒为 257，表项只往表尾追加，1990 年代的二进制在 6.x 上仍能跑。NT 的 SSN 随构建漂移，同一个 `NtOpenFile` 在不同补丁级上编号可能不同，微软从不承诺稳定。后果是 Windows 侧只认 `ntdll!Nt*` 符号、不认数字（桩由系统随行重编，符号名是唯一契约），Linux 侧可以内联 `syscall` 并硬编码数字——Go 运行时不走 libc，正是这么做的。

可观测面也随之分岔：Linux 的表是地址数组，`/proc/kallsyms` 能列出每槽函数名，eBPF 可按号挂探针；NT 的表是偏移数组，拿到表地址仍需重定位，追踪工具改在 `ntdll` 桩上挂钩子。同一四段结构，只因第 4 段表项从 8 B 变 4 B，观测点就从内核侧整体移到用户侧。

## 二、入口指令对照：`syscall`/`sysenter`/`int 0x80` 与 `swapgs` 的栈切换

三条入口指令的差别只有一处：进内核时栈指针从哪来。换态本身（改 `RIP`、改 `CS`、屏蔽标志）三者都要做，机制大同小异；真正分岔的是谁把 `RSP` 换成内核栈——硬件代劳的要先读门描述符与 TSS，软件代劳的要先 `swapgs` 找到每 CPU 区、再从里面取栈顶。这个分工决定了指令条数、可嵌套性与安全边界。

```text
 ┌─ 路径 A：int n / 异常 / 外部中断（硬件换栈）────────────────────────┐
 │ 用户 RSP ──┐ 硬件读 IDTR.base + n×16 → 门描述符                    │
 │            │ 特权级变化？→ 读 TSS.RSP0（或表项 IST 的独立栈）        │
 │            ▼                                                       │
 │      内核栈：push SS, RSP, RFLAGS, CS, RIP（异常另压错误码）        │
 │            │ 入口桩按帧里 CS.RPL 判定：来自用户态才 swapgs          │
 │            ▼                                                       │
 │      iretq：从同一帧弹出 5 字段，RSP 回到用户值                     │
 └────────────────────────────────────────────────────────────────────┘

 ┌─ 路径 B：syscall（不换栈，软件补三步）──────────────────────────────┐
 │ 用户 RSP ──┐ syscall 不碰 RSP，只写 RCX/R11/RIP/CS/SS/RFLAGS       │
 │            │ ① swapgs：GS.base ← MSR_KERNEL_GS_BASE（0xC0000102）  │
 │            │ ② 存用户 RSP 进 TSS_sp2（必须早于切 CR3）             │
 │            │ ③ RSP ← 每 CPU 变量里的内核栈顶                        │
 │            ▼                                                       │
 │      内核栈：21 次压栈 → pt_regs（15 GPR + 6 字段）                 │
 │            ▼                                                       │
 │      sysretq：RIP←RCX、RFLAGS←R11；RSP 不从栈取，用用户 RSP 变量   │
 └────────────────────────────────────────────────────────────────────┘
```

### 1. 三条入口的四维对照与两条栈来源

| 入口指令 | 引入位宽/年代 | 栈指针来源 | 配对返回 | 单次开销档 | x64 上的现状 |
| --- | --- | --- | --- | --- | --- |
| `int 0x80` | 16 位 `int n` 的延续；Linux 自 1991 | 硬件读 `TSS.RSP0`，压 5 字段 | `iret`/`iretq` | 数百纳秒档 | 保留为 32 位 ABI 门，DPL（Descriptor Privilege Level，描述符特权级）=3，强制 32 位传参 |
| `int 0x2E` | 32 位 NT（1993 起） | 同上，`TSS.RSP0` | `iret` | 数百纳秒档 | 仅 32 位 NT 原生；WoW64 已改走 64 位 `syscall` |
| `sysenter` | P6（1997），32 位 | `IA32_SYSENTER_ESP`（单值 MSR） | `sysexit`（EDX/ECX 给用户 RSP/EIP） | 百纳秒档 | 64 位模式不可用（进入兼容模式），已废弃 |
| `syscall` | AMD64（2003），64 位 | 软件从每 CPU 区取（`swapgs` 后） | `sysret`（RCX/R11） | 数十纳秒档 | Linux 与 NT 在 x64 上的唯一主路径 |

`sysenter` 的栈来自单个 MSR，一个核只有一个值，因此表达不了「已在内核又被打断」的嵌套：中断在 `sysenter` 栈上到来时硬件改读 `TSS.RSP0`，同核出现两套栈来源，任务切换还得重写该 MSR。`syscall` 把栈顶放进每 CPU 变量，读它是一次普通内存读（通常命中 L1），代价是引入 `swapgs`。硬件换栈那条则把「读哪个栈」写进 `IDT` 表项的 IST 与 `TSS`，代价是每次进入至少两次访存。

### 2. `swapgs` 之后的空窗：不换栈换来的三步补偿

`syscall` 的取舍很干脆：不换栈，把换栈责任全推给软件，代价是软件必须先找到「内核能读、用户改不了」的地方拿到栈顶。`GS` 基址就是这个地方，但 `GS` 同时属于用户态——Linux 允许 `arch_prctl(ARCH_SET_GS)` 把它设成任意规范地址，NT 在 `CR4.FSGSBASE=1` 时允许 `wrgsbase` 直接改。入口桩若不执行 `swapgs` 就读 `gs:` 偏移，读到的是攻击者选定的地址，第一次解引用就是 `CPL=0` 下的任意读写。

`swapgs` 无操作数，只把 `GS.base` 与 `IA32_KERNEL_GS_BASE` 互换：进入时指向每 CPU 控制区（Linux `per_cpu`、NT `KPCR`），返回前再换回用户值。指令本身个位数拍，两条边却都不安全——执行前 `GS` 是用户值，执行后 `RSP` 还是用户值。于是入口序列被迫排成 `swapgs` → 存用户 `RSP` → 切 `CR3` → 装内核 `RSP`，四步之间任何一次异常都落在半切换状态上。

推测执行又加一层：分支可越过 `swapgs` 继续做 `gs:` 访存，用用户基址算出内核地址并带进缓存（CVE-2019-1125 一类）。两侧缓解都是在 `swapgs` 附近插序列化屏障——Linux 入口桩用 `LFENCE`，NT 的 `KiSystemCall64` 同样加了屏障序列。代价是每次进入多出数十拍的序列化，方向明确：把可推测窗口压成必须等屏障，用固定成本换掉一整类旁路。

### 3. 32 位门留在 IDT 里：`int 0x80`、`int 0x2E` 与 x32 的位标记

`int 0x80` 在 64 位内核上没消失，因为 32 位二进制还要跑。它占 `IDT` 第 0x80 项，陷阱门、DPL=3，入口桩 `entry_INT80_compat`。进入后参数按 32 位约定摆：`eax` 装号，`ebx`/`ecx`/`edx`/`esi`/`edi`/`ebp` 装 6 个参数，指针是 32 位。内核必须对每个指针做 `compat_ptr` 零扩展、把 `long` 截成 32 位、按 32 位解释 `time_t`——这些转换才是它比 `syscall` 慢约 1 个数量级档的主因，门本身只多两次访存。

这条门还给出量化边界：32 位进程地址空间上限 4 GiB，指针零扩展后必然落在低 4 GiB，内核可无条件信任「高 32 位为 0」；64 位路径没有这份免费判据，每个用户指针都要走 `access_ok` 范围检查。这是位宽带来的固定成本差，不随实现优化消失。

NT 的对应物是向量 `0x2E` 上的调用门，入口 `KiSystemService`。x64 NT 不再用它：64 位进程直接 `syscall`；WoW64 的 32 位进程也不走 `int 0x2E`，而由 `wow64cpu` 的 thunk 切到 64 位代码段执行 `syscall`，再把 `NTSTATUS` 翻回 32 位结构。于是同一系统里同时存在「32 位 ABI + 64 位入口」，正是 Linux 用 `entry_INT80_compat` 所解决问题的另一解法：Linux 保留 32 位入口、在入口处转换，NT 统一到 64 位入口、在返回后转换。两条路都绕不开那次转换，差别只在转换点落在内核还是用户态 thunk。

## 三、中断与异常：向量号到 IDT 表项再到中断框架的汇流

中断与异常没有调用号，只有 8 位向量。向量是唯一索引：乘 16 得表项偏移，表项里 5 个字段决定用什么特权级、进哪个栈、跳到哪条指令。这条路径没有可替换的桩，也没有 ABI 协商——硬件按表项办事，表项由内核在启动时一次写好（07 篇的 IDT 接管），此后只读。

```text
 IDT 表项：16 B 门描述符（64 位中断门/陷阱门）
 bit  63      48 47 46 45 44 43    40 39   35 34 32 31     16 15       0
     ┌──────────┬──┬─────┬──┬────────┬───────┬─────┬──────────┬──────────┐
     │Off[63:48]│P │ DPL │0 │  Type  │   0   │ IST │ Selector │ Off[15:0]│
     └──────────┴──┴─────┴──┴────────┴───────┴─────┴──────────┴──────────┘
      高 32 位偏移 │   │     │  1110 中断门（入口清 IF）
                   │   │     │  1111 陷阱门（不清 IF）
                   │   │     └─ 必须为 0：系统描述符标志 S=0
                   │   └─ DPL：仅约束软件 int n，CPL ≤ DPL 才放行
                   └─ P：存在位，为 0 则访问即 #NP(11)
                    IST[2:0]：0 = 不换栈；1~7 = TSS 里的独立栈

 向量分区（IDTR.limit = 0x0FFF，即 256 项 × 16 B = 4 KiB）
   0        31 32                          255
   ├──────────┼──────────────────────────────┤
   │ 0~31 异常│ 32~255 设备 / 软件保留       │
   └──────────┴──────────────────────────────┘
    0 #DE   6 #UD   13 #GP   14 #PF   18 #MC（IST）
    1 #DB   8 #DF（IST）  2 NMI（IST）  21 #CP
    特殊落点：0x2E = NT 系统调用门，0x80 = Linux int 0x80 门
```

### 1. 16 字节里的五个判据：从向量到入口地址

解码是纯算术：`offset = IDTR.base + vector × 16`。16 整除 64，任何表项都不跨缓存行——4 KiB 表恰占 64 行、每行 4 项，查表延迟因此稳定为 1 次 L1 命中（数十拍）或 1 次缺行（数百拍），没有跨行撕裂的额外分支。字段按判定顺序排列，每一步都可能把投递挡回去或换一条路：

| 位段 | 字段 | 取值 | 判定作用 |
| --- | --- | --- | --- |
| 47 | `P` | 0/1 | 0 则访问即 `#NP`（向量 11），用于标记该向量未安装 |
| 46:45 | `DPL` | 0~3 | 仅软件 `int n` 受约束；硬件投递的异常与外部中断不受限 |
| 43:40 | `Type` | `0xE`/`0xF` | `0xE` 中断门入口清 `IF`，ISR（Interrupt Service Routine，中断服务例程）不可被同级可屏蔽中断打断；`0xF` 陷阱门不清 |
| 34:32 | `IST` | 0~7 | 非 0 时从 `TSS.IST[n]` 取栈顶替换 `TSS.RSP0`，用于坏栈上的二次故障 |
| 31:16 | `Selector` | `GDT` 索引 | 决定入口 `CS` 与 `CPL`；选择子与门 `DPL` 不匹配即 `#GP` |

第 3 行那 1 个比特决定整棵中断树的并发形状。中断门清 `IF`，ISR 一进入就把同级与低优先级中断挡在 `LAPIC` 待决位，直到 `iretq` 恢复 `RFLAGS` 才补投；陷阱门不清，`#BP`/`#OF` 这类「指令执行完后报告」的异常因此可在处理器内部被后续中断打断。Linux 把 `#BP`、`#OF` 与 `int 0x80` 配成 DPL=3 的陷阱门，正是要用户态能主动触发它们，又不让触发延长关中断窗口。

IST 是唯一会换掉整条栈的字段。`#DF`（8）、`#MC`（18）、NMI（2）配了 IST：它们处理的正是「当前栈已不可用」的场景——`#DF` 本身是「处理异常时又出异常」的产物，若继续用坏掉的 `RSP0` 栈，压帧二次失败会让处理器进入 `Shutdown` 状态。IST 栈由内核启动时按 CPU、按级静态分配，故这三条向量在任何上下文里都有可用栈。

### 2. 从设备断言到入口桩：三级控制器，两次解析，一次纯转发

```text
 [设备] ──断言──► [IOAPIC 重定向表] ──► [LAPIC] ──► [CPU 核]
   或 MSI 写 ────────────┐                │
                         │                │ 参与解析：IRR（Interrupt Request Register，中断请求寄存器）/ISR/TPR 裁决与待决排队
   纯转发：消息里带        │                ▼
   vector 直达 LAPIC       │       [IDT 索引：vector×16]
                          │                │ 参与解析：P/DPL/Type/IST/Selector
                          │                ▼
                          │       [入口桩 asm_exc_*/KiInterruptDispatch]
                          │                │ 纯转发：压帧、切栈、调 C
                          │                ▼
                          └──────► [框架：generic_irq / KINTERRUPT 链]
                                          参与解析：hwirq→virq 映射、共享链遍历
```

五个节点里只有两个半参与解析。`IOAPIC` 的重定向表把 24 个管脚之一映射到 8 位向量，这是一次映射而非判定：`vector[7:0]`、`dest[63:56]`、`mask[16]`、`trigger[15]`、`polarity[13]`、`delivery mode[10:8]` 在启动时写好，中断到达时按表项原样打包，不做任何判断。MSI 更进一步：设备直接写 `0xFEE00000 | dest << 12`，数据低 8 位就是向量，`IOAPIC` 被整个绕过，映射从「表项」变成「设备配置空间的两个字段」。

`LAPIC` 是第一个真正解析的节点：维护 256 位 `IRR`（待决）与 `ISR`（In-Service Register，在服务寄存器），收到消息先比对 `TPR` 门槛——向量号高 4 位即优先级类，共 16 档，低于门槛只置 `IRR` 位不投递。这一步是「中断能否插队」的唯一裁决点，也是屏蔽窗口的物理载体：`cli` 清 `RFLAGS.IF`，`TPR` 抬的是另一道闸，两者叠加才构成完整屏蔽层级（§6 展开）。收尾是 `EOI`：ISR 必须向 `LAPIC` 的 `EOI` 寄存器写一次，否则 `ISR` 位不清、同级中断永远排在后面。

`CPU` 核做第二次解析（上节 5 个字段），按 `IST`/`RSP0` 选栈、按门类型决定是否清 `IF`、压 5 字段（异常另压错误码）跳到入口桩。入口桩纯转发：Linux 的 `asm_exc_*` 与 NT 的 `KiInterruptDispatch` 都只补齐硬件没压的寄存器、对齐栈、调 C，不改向量语义。最后一站重新开始解析：Linux 的 `generic_irq` 把 `hwirq` 经 `irq_domain` 映射成 `virq`，再在共享线上遍历 `irq_desc` 的动作链；NT 的把向量对应的 `KINTERRUPT` 从 `KiInterruptList` 摘下逐个调用，并把 `IRQL` 抬到该向量的级别。

延迟在这条链上分布极不均匀。`IDT` 解码本身只有数十纳秒档（1 次 16 B 读 + 1 次 `TSS`/`IST` 读），而「设备断言到 ISR 第一条指令」典型落在 $1 \sim 10\ \text{μs}$ 档，两个数量级的差距几乎全来自屏蔽窗口与 C-state 退出。这条不等式给出方向：把延迟从 5 µs 降到 2 µs 靠缩短关中断区间与减少共享线轮询，不靠把表项挪进缓存行——它本来就在一行里。反过来，每秒 $10^{6}$ 次的中断密度（万兆网卡小包）会把单核全部时间花在入口与出口上，此时唯一方向是合并投递（NAPI、MSI-X 多队列）。

### 3. 异常与中断的分岔：同步性、屏蔽性与栈来源

| 类别 | 同步性 | 可否屏蔽 | 返回地址语义 | 内核栈来源 | 双平台框架入口 |
| --- | --- | --- | --- | --- | --- |
| 故障（`#PF`/`#GP`/`#DE`/`#UD`） | 同步，指令执行失败时 | 否 | 出错指令本身，可重试 | 当前栈 | Linux `exc_*`；NT `KiTrap*` |
| 陷阱（`#BP`/`#OF`/`#DB`） | 同步，指令执行完后 | 否 | 下一条指令 | 当前栈；`#DB` 可配 IST | 同上，门类型为陷阱门 |
| 中止（`#MC`/`#DF`） | 同步 | 否 | 不可重试 | 强制 IST（`#MC`=18、`#DF`=8） | Linux `machine_check`；NT `KiMachineCheck` |
| 外部中断（32~255） | 异步 | 是（`IF` + `TPR`） | 下一条指令 | 当前栈 | Linux `generic_irq`；NT `KINTERRUPT` 链 |
| NMI（2） | 异步 | 否（`IF` 无效） | 下一条指令 | 强制 IST | Linux `nmi` 入口；NT `KiNmiInterrupt` |
| SMI | 异步 | 否 | OS 不可见 | 独立 SMRAM 栈 | 无（固件域，OS 无入口） |

第 2 列把三条路径压成两类：同步的异常与产生它的指令有确定因果，返回地址要么指向该指令（可重试）、要么指向下一条（已生效）；异步中断与被打断的指令没有因果，返回地址永远是下一条。这条语义差直接决定内核能否做「改页表再重试」——`#PF` 处理程序改完 PTE 后 `iretq`，硬件重执那条访存，整个动作依赖「异常现场是精确的」（01 卷 03 篇的退休期语义）。

第 3 列的分岔更隐蔽。异常不可屏蔽，意味着内核处理外部中断时随时可能被 `#PF` 打断——ISR 自己也要访存。反过来不成立：`#PF` 处理期间到达的外部中断会被 `IF` 或 `TPR` 挡住。这条不对称是「ISR 上半部只允许有限动作」的物理原因：上半部运行在中断上下文，不能睡眠、不能等锁、不能碰可能缺页的地址，否则形成「异常中再异常」的嵌套，第二次失败即 `#DF`，只能靠 IST 兜底。

Windows 把这套约束翻译成 `IRQL`：向量投递前被映射成 0~31 的级别（`PASSIVE_LEVEL`=0、`APC_LEVEL`=1、`DISPATCH_LEVEL`=2、`HIGH_LEVEL`=31），ISR 在 `DISPATCH_LEVEL` 以上运行，触碰可分页内存即蓝屏；耗时后半段排进 `DPC`（Deferred Procedure Call，延迟过程调用）队列，等 `IRQL` 降回 `DISPATCH_LEVEL` 以下再跑。Linux 的对应切分是硬中断上半部与 `softirq`/线程化中断：上半部只应答与唤醒，剩余工作交给可抢占上下文。两侧机制名不同，切分点落在同一处——「能不能睡眠」正是第 3 列「可否屏蔽」在软件层的投影。

## 四、返回路径：从待办标志位到 `sysretq` 的出口收尾

入口是单向的，出口不是：返回用户态之前，内核手里还握着一个已建好的 `pt_regs`，而这帧可能还要再改——信号要往用户栈另压一帧、APC 要把帧里的 `RIP` 改到 `ntdll`、可重启的调用要把 `orig_ax` 与 `RIP` 一起回退、FPU 状态要确认属于本任务。四类待办清完才轮到选返回指令，而选哪条又由它们是否改过帧决定。

```text
 内核处理完毕（pt_regs 已在栈上，168 B）
   │
   ├─① 待决位图【解析】NEED_RESCHED / SIGPENDING / NOTIFY_RESUME / UPROBE
   │      任一位非 0 → 处理一位，回到 ① 重测（自旋，不是一次 if）
   │      └─ NEED_RESCHED 命中 → 不回用户态，转 §五 的切换分支
   ├─② 信号帧 / APC【解析】判是否被 sigmask 屏蔽、handler 是否装 SA_RESTART
   │      Linux：内核在用户栈上写约 1 KiB 的 rt_sigframe
   │      NT   ：只改帧内 RIP，指向 ntdll!KiUserApcDispatcher
   ├─③ 重启【解析】RIP 回退 2 B、orig_ax 复位 → 重执 syscall 指令
   ├─④ FPU 归属【转发】NEED_FPU_LOAD → XRSTOR 本任务 XSAVE 区
   ▼
 选返回边【解析】
   sysretq：RCX 仍规范、R11 合法、帧未被 ②/③ 改写（数十拍档）
   iretq  ：帧已被改写、或目标 CS 不是用户 64 位（百拍档）
```

### 1. 出口是一段自旋，不是一段顺序代码

Linux 把这段写成 `exit_to_user_mode_loop`：每轮读一次标志位图，命中一位处理一位，处理完回到循环头重测。写成自旋而非顺序 `if` 的理由是处理本身会引入新位——投递信号时 handler 若踩到未驻留页，缺页处理可能唤醒另一个任务并置回 `NEED_RESCHED`，一轮清完再看才不会带着新位返回。空载 `getpid` 在这段上的成本是几次位测试（数十拍档），标志位与 `task_struct` 同处一条热缓存行。

②是四类里唯一写用户内存、也是唯一可能「异常套异常」的一步。写信号帧走带异常表的 `copy_to_user` 变体：用户栈不可写或越过栈上限时，缺页处理的返回值被就地解释为投递失败，转而强投 `SIGSEGV`（`force_sigsegv`）。后果可测：冷栈首次投递要跨两次缺页档（栈扩展加帧落页），落在 $1 \sim 5\ \text{μs}$ 档；热栈只有数百纳秒档，一个数量级的差全来自那 1 KiB 帧所踩的页。

### 2. 信号帧：两侧只差「谁写用户栈」这一处

| 环节 | Linux（`rt_sigframe`） | NT（APC） |
| --- | --- | --- |
| 帧由谁构造 | 内核按 ABI 在用户栈上写出整帧 | 内核只改帧内 `RIP`，帧由 `ntdll` 在用户态构造 |
| 内核是否碰用户内存 | 是，`copy_to_user` 写约 1 KiB | 否，只写内核栈上的 `KTRAP_FRAME` |
| 触发条件 | 待决信号通过 `sigmask` 与 `SA_NODEFER` 判定 | `IRQL` 低于 `APC_LEVEL` 且线程处于可提醒状态 |
| 回程动作 | handler 返回即执行 `rt_sigreturn`，整帧读回 | `KiUserApcDispatcher` 调完回调后执行 `NtContinue` |
| 一次投递的系统调用数 | 2（进入加 `rt_sigreturn`） | 1（`NtContinue`） |

第 2 行是唯一的结构差异。Linux 替用户态把帧写好，代价是把「写用户栈可能缺页」拉进内核的返回路径；NT 只改一个 8 B 返回地址，帧构造与状态恢复全在 `ntdll`，代价是回程多一次 `NtContinue` 的完整陷入。两种解法把成本放在不同侧。

### 3. 重启与返回指令：待办状态直接决定走哪条返回边

可重启的阻塞调用（空管道上的 `read`、`wait4`、`nanosleep`）被信号打断时返回 `-ERESTARTSYS`，这个负值不进 `errno`：它在返回前最后一刻被 `restart_block` 消费——handler 装了 `SA_RESTART` 且信号不被拦截时，内核把 `RIP` 回退 2 B、`orig_ax` 复位，`sysretq` 回到 `syscall` 指令本身，用户态看不到这次打断；否则 `RAX` 改写为 `-EINTR`。NT 没有这个内核态协议：`NtWaitForSingleObject` 被 APC 打断时返回 `STATUS_USER_APC`，由 `ntdll` 桩在用户态循环重发。

返回指令由同一组待办反推：`sysretq` 的前提是 `RCX` 与 `R11` 的旧值仍有效，因此只要 ②或③ 改过帧、`ptrace`/`seccomp` 动过寄存器、或目标 `CS` 不是用户 64 位，就得退到 `iretq` 弹 5 个字段。差额可测：`sysretq` 数十拍，`iretq` 加可能的 `CR3` 往返落在百拍档。

## 五、上下文切换账本：从抢占检查到 `CR3` 写入的三段成本

出口处还有一个不返回的分支：`NEED_RESCHED` 命中时，内核把这帧留在自己的内核栈上、切到另一个任务。它把「一次系统调用」改写成「两次返回」——先返回调度器，再返回到被选中的任务；真正执行那条 `sysretq` 时，`RSP` 已指向另一个任务的栈，弹的是别人的帧。

```text
 出口检查 NEED_RESCHED（Linux）／IRQL 已降到 DISPATCH_LEVEL 之下（NT）
   │
   ├─ 不命中 → 直接 sysretq / iretq（帧属于自己）
   └─ 命中 ──► schedule() / KiSwapThread
                ├─ 解析：pick_next_task（就绪队列位图、优先级、亲和性）
                ├─ 转发：switch_to / KiSwapContext
                │    ① 存 6 个 callee-saved 与 RSP → prev 的内核栈
                │    ② 载入 next 的同 6 个与 RSP
                │    ③ current（GS 相对偏移）改指 next 的 task_struct
                ├─ 解析：switch_mm
                │    ① 同 mm → 不写 CR3（同进程线程切换）
                │    ② 异 mm → 写 CR3（PCID 保条目／无 PCID 整表失效）
                ▼
        回到 next 上次被切走的位置（它自己的 schedule() 调用点）
           └─ 它继续走自己的出口路径，弹自己的帧
```

### 1. 三段成本与一项不属于任何一段的第四项

| 段 | 具体动作 | 性质 | 单次成本档 |
| --- | --- | --- | --- |
| 寄存器 | 6 个 callee-saved 加 `RSP`，FPU 状态按需惰性换 | 纯转发，无判定 | 数十纳秒档 |
| 内核栈与 `current` | 一次 `RSP` 写、一次 `GS` 相对写 | 纯转发 | 数十拍 |
| 地址空间 | 写 `CR3`，硬件据此走页表 | 硬件解析 | 数十拍（PCID）／数百至千拍（整表失效） |
| 缓存与 TLB 冷启动 | 新任务工作集不在本核 `L1`/`L2` | 切换的后果，不在切换指令内 | 微秒档，随工作集增大 |

前两段合计数十纳秒档，第三段是它的十倍档，第四段又与第三段同量级——这条递增顺序决定了方向：减少切换次数比压薄 `switch_to` 划算。`switch_to` 只存 6 个寄存器，是因为调用约定已规定其余寄存器由被调用者保存、编译器在调用点就压过了。

`CR3` 这一段的成本全在 TLB 语义上。PCID 关闭时一次写让全核条目失效，之后每个首次访存都要走一次页表遍历（数十至数百拍）；PCID 开启时低 12 位携带 ASID，旧条目标成非当前、留着等下次切回，代价压到数十拍。KPTI 打开后每次切换写两次 `CR3`，这是旁路缓解的固定税：不随工作集缩小而消失，只随切换次数线性叠加。

### 2. 抢占点的三条入口共用一个每 CPU 整数

切换由三处入口之一触发：系统调用出口、中断出口（`irqentry_exit` 里的 `preempt_schedule_irq`）、内核显式让出（`cond_resched` 与各阻塞原语）。三处判据是同一个每 CPU 整数：抢占深度为 0 才允许切换。这个整数的最高位另存 `PREEMPT_NEED_RESCHED`，于是「减一层深度」与「读出是否要调度」由同一条 `dec` 完成，计数归零与调度请求可见因此成为不可分割的一步。

NT 不用计数，用 `IRQL`：只有降到 `DISPATCH_LEVEL` 之下才允许切换，`KiDispatchInterrupt` 在这个降级点上运行调度器。两侧形制不同、承载物相同，区别在 NT 的那个整数同时兼任中断屏蔽等级（§六），Linux 的只记抢占深度、屏蔽另由 `IF` 承担。后果是 NT 的「不可抢占区间」与「不可被打断区间」天然重合；Linux 的两者可分开——`local_irq_disable` 挡中断而仍允许抢占，`preempt_disable` 挡抢占而仍响应中断。

### 3. 三档切换成本与时间片的下限

| 场景 | 是否写 `CR3` | 附加成本 | 单次成本档 |
| --- | --- | --- | --- |
| 同进程线程切换 | 否 | 无 | $1 \sim 3\ \text{μs}$ |
| 跨进程同核 | 是 | TLB 冷启动 | $3 \sim 10\ \text{μs}$ |
| 跨核迁移 | 是 | 目标核 TLB 与缓存全冷、一次核间中断 | 十微秒档以上 |
| 上述任一叠加 KPTI | 是，写两次 | 每次多一次用户页表往返 | 各档加数十至百纳秒 |

时间片的下限由这张表反推：

```math
\eta = \frac{T_{\text{slice}}}{T_{\text{slice}} + T_{\text{switch}}}
```

代入时间片 $4\ \text{ms}$、切换成本 $3\ \text{μs}$，利用率约 99.93%，开销在量级上可忽略；把时间片压到 $100\ \text{μs}$ 档，同一式给出约 97%，每 33 次切换就烧掉一个完整时间片。方向明确：为缩短交互延迟而压缩时间片时，必须先压薄第三、第四段（PCID、缓存亲和），否则省下的响应时间会被切换本身吃回去。

## 六、屏蔽层级：`IF`、`TPR`、`IRQL` 三道闸与延迟不等式

第三节里说的两道闸只是可屏蔽中断这一路上的两级；与「谁都不挡」那层并排，才看得到完整裁决。四层的区别不在「更严」，而在作用对象与范围：`IF` 挡本核全部可屏蔽中断却挡不住一条异常；`TPR` 只挡外部中断且按优先级分类；`IRQL` 把前两者绑成一个软件可见的整数，并额外管住 DPC 与 APC 派发；NMI、SMI、`#MC` 谁都不挡。

```text
  事件源                  闸门（串联，全部放行才投递）        载体
  ──────────────────────────────────────────────────────────────────
  NMI(2) / SMI / #MC      （无闸，任何软件状态都挡不住）        —
  异常 #PF/#GP/#UD        （无闸；同步，只受 IDT 表项约束）      IDT 表项
  外部中断 32~255          IF ──► TPR ──► IRQL，三者同时放行    RFLAGS.9
   （IOAPIC / MSI-X）                                           LAPIC / CR8
  DPC / APC（软件派发）   只受 IRQL 约束                        每 CPU 队列
  软件 int n              只受 IDT 门 DPL 约束                  IDT 表项
```

### 1. 三道闸的载体、作用域与成本

| 闸 | 物理载体 | 关/开动作 | 作用域 | 单次成本档 | 挡不挡异常 |
| --- | --- | --- | --- | --- | --- |
| `IF` | `RFLAGS` bit 9 | `cli`／`sti` | 本核全部可屏蔽中断 | 个位数拍 | 挡不住 |
| `TPR` | LAPIC `TPR`（x2APIC 走 MSR `0x808`） | 写 `TPR` | 本核外部中断，按 16 个优先级类 | 十几拍（MSR）／数十拍（MMIO） | 挡不住 |
| `IRQL` | `CR8`（x64 上即 `TPR` 高 4 位的影子） | `KfRaiseIrql`／`KeLowerIrql` | 本核中断加 DPC/APC 派发 | 十几拍 | 挡不住 |
| 无闸层 | — | — | NMI／SMI／`#MC` | — | — |

第 2、3 行在 x64 上是同一个物理寄存器：`CR8` 低 4 位直接映射到 `TPR` 的优先级类字段。NT 的 `IRQL` 抬升与 Linux 的 `TPR` 抬升写的是同一处，差异全在软件语义——NT 把 `IRQL` 当一等公民，同步对象、DPC 派发、可分页性检查全按它分级，`PASSIVE_LEVEL` 到 `HIGH_LEVEL` 的 32 级是一套完整调度契约；Linux 基本不用 `TPR` 分级，屏蔽靠 `IF` 与 `irq_desc` 的 mask 位。

`IF` 低到可以逐条指令开关，这是它被用得最滥的原因，也是延迟账的主要来源；`TPR` 贵一个档（一次 MSR 或 MMIO 写），换来只挡低优先级、放行高优先级——屏蔽不再是全有全无。一块网卡的 ISR 不该被一块键盘挡住，`IF` 做不到这个区分。

### 2. 关闸与排干：两种屏蔽语义差三个数量级

「屏蔽一个中断」有两种截然不同的意思，混用会直接死锁。

- 关闸：`local_irq_disable`（Linux）或提到该向量之上的 `IRQL`（NT）。立即生效，不等任何在执行的 handler；新到中断在 `IRR` 堆着，`sti` 或降 `IRQL` 时补投。成本纳秒档，只写一个寄存器。
- 排干：`disable_irq`（Linux）或 `IoDisconnectInterrupt`（NT）。先标记该线禁用，再等当前在服务的 handler 返回，保证此后无并发执行。成本由被等的 handler 决定，微秒到毫秒档。

差三个数量级对应两种正确性需求。关闸只保证本核此后不再被这条线打断，先前已在执行的 handler 照旧跑完；若此时释放 handler 要访问的设备结构，那个 handler 会踩到已释放内存。排干才保证不再有并发 handler，代价是等待。判据很硬：要独占设备状态才排干，只是不想被本核打断就关闸。

排干还有自反陷阱：在某条线的 handler 内部对同一条线调 `disable_irq`，等的正是自己——自死锁。Linux 为此留了 `disable_irq_nosync`：只标记不等待。它等待的实体是「在服务的 handler 实例」，不是「这条线」。

### 3. 延迟不等式：三段相加，只有第一段归内核管

```text
 一次外部中断：从设备断言到 ISR 第一条指令
   ├─ W_off    最长关闸窗口（cli 临界区 / 高 IRQL 区间）
   ├─ T_hp     所有更高优先级 ISR 的执行时间之和
   └─ T_queue  同级已在 IRR 排队的条目，先到先服务，不抢占
```

```math
L_{\text{IRQ}} = W_{\text{off}} + \sum_{i \in \text{hp}} T_i + T_{\text{queue}}
```

三项量级差得很开。关闸窗口在骨干路径上被压到亚微秒档，但驱动的坏路径可以把它拉到百微秒档；高优先级项由硬件工作量决定，典型落在 $1 \sim 10\ \text{μs}$ 档；排队项同级不抢占，队列长度随设备密度线性增长——万兆网卡小包场景下单核每秒 $10^{6}$ 次中断意味着平均每微秒一次投递。所以中断风暴的表现是延迟线性爆炸而非吞吐下降：第三项没有上限。

三项里只有第一项归内核管。要把总延迟从十微秒档压到五微秒档，唯一有效的动作是缩短关闸窗口——拆临界区、把长 handler 移出硬中断、用 `local_irq_save` 收窄范围而非整段 `cli`；高优先级项由更高优先级中断的业务量决定，排队项由设备密度决定。对后两项能做的只是分流：`MSI-X` 多队列拆线、`NAPI` 把逐包中断合并成轮询、线程化中断把长 handler 移出硬中断——改的都是「有多少工作留在硬中断里」，而不是不等式的形状。
