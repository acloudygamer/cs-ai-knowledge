# 架构分层与前后端

> **版本基准**: universal（前端框架演进以"组件树 + 状态"为锚点，不绑定具体框架版本；后端分层以通用三层为锚点）

## 骨架要点（正文按此展开，完成后删除本骨架块）

- **定位**：消费 05-计算机网络 的 HTTP/TLS 请求生命周期与 03 的 socket、06-HTTPS、02-测试/03-设计的边界思想；产出"系统级分层边界"，供 07-数据库（数据层内部机制）与 08-微服务（层边界的水平放大）消费。
- **核心拓扑流**：空间事务环为主——一次用户操作从前端到数据库再返回的端到端生命周期闭环（浏览器组件状态 → HTTP 请求 → TLS → 负载均衡 → 应用分层 → 数据库 → 原路返回，逐节点标注"参与处理"还是"纯转发"）；时序因果链为辅。
- **必备图**：①前后端请求全链路 ASCII 图（这是本章最大的一张事务环图，把 05 的 TCP/HTTP/TLS 结论作为已知节点直接引用）；②纵向三层（表现/业务/数据）与横向按域切分的网格图（每格标注变化速率档位）；③API 契约变更影响表（字段增删改 × 新旧客户端兼容矩阵）。
- **量化锚点**：各跳延迟档位引用 05 的量级结论（DNS 命中/未命中、TLS 握手 RTT、RTT 档位），本篇不重复标数，只做单句引用——同一机制全篇仅一处展开。

### 一、分层的约束：变化速率与团队边界

- 约束显明：UI 变化最快（周级）、业务规则居中、存储模式最慢（年级）——变化速率不同的事物绑在一起，每改一次快层都要碰慢层；分层即按变化速率切（这与 01-网络分层 的"按抽象层级切"对照：切线依据不同，形式相同）。
- 团队边界与康威定律（锚定来源，1968）：模块边界会复刻沟通结构——分层同时是代码切分与团队分工；横向按业务域切层（用户域/订单域）服务独立演进——为 08-微服务 埋线。
- 前后端分离的成因：前端消费方（浏览器/移动端）形态多样逼出"统一 HTTP API + 各端独立渲染"，服务端不再拼 HTML。

### 二、前后端分离的请求生命周期：端到端事务环

- 全链路图先行，正文逐节点遍历：用户事件 → 前端状态变更与请求发起（JSON 序列化）→ TLS 通道（引用 06 结论）→ 负载均衡（终止 TLS、转发）→ API 网关（路由/鉴权/限流三职能）→ 应用层业务对象 → 数据层持久化 → 响应原路反序列化回状态。
- 每个节点标注数据形态转换：对象 ↔ JSON ↔ 字节流 ↔ 帧——与 01-网络分层 的封装瀑布同构，此处复用结论不重画。
- 无状态服务的落地：会话状态外置（引用 05-HTTP 的 Cookie/Token 结论）→ 任意实例可处理任意请求 → 水平扩展成立（因果链收口）。

### 三、API 契约：边界上的承诺

- 契约 = 前后端各自独立开发的前提：schema（字段名/类型/必选性）即接口——消费 03 的依赖倒置（双方都依赖契约而非彼此实现，单句引用）。
- 版本化与兼容矩阵：加字段（旧客户端忽略 = 兼容）、删字段/改语义（破坏性，需版本号或灰度）；表格补齐变更类型 × 影响单元格。
- 错误契约：状态码分档（引用 05-HTTP）+ 业务错误体的统一结构——前端据契约做重试/提示分支。
- 收尾落在下一跳：链路终点是数据层——数据如何组织、索引与事务保证交给 07-数据库基础。
