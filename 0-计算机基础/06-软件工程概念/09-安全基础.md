# 安全基础

> **版本基准**: universal（机制锚定 OWASP Top 10 谱系与 OAuth 2.0/JWT 规范，按既定前提使用）

## 骨架要点（正文按此展开，完成后删除本骨架块）

- **定位**：本章收口。消费 05-计算机网络 06-HTTPS与TLS（传输安全已闭合）、05-HTTP（状态码/Cookie 语义）、06-架构分层（请求生命周期的每个节点即潜在攻击面）、07-数据库（注入的终点是数据层）；产出"应用层威胁模型与纵深防御"，用对抗视角回看全章与全卷链路。
- **核心拓扑流**：空间事务环为主——每种攻击都是"把恶意输入沿正常请求环送进信任边界内"（注入沿 SQL 环、XSS 沿页面渲染环、CSRF 沿浏览器自动携带凭证环）；每条攻击因果链与其防御的阻断点一一对应。
- **必备图**：①攻击面地图 ASCII 图（在 06-架构分层 的全链路图上叠加标注：DNS/网络入口/API 网关/应用/数据库/浏览器各节点对应哪类攻击）；②三条攻击因果链图（注入/XSS/CSRF 各一条：恶意输入 → 穿过的层 → 到达的解释器 → 防御阻断点反标）；③认证 vs 授权分界表 + session vs JWT 对照表（存储位置/验证方式/吊销能力/扩展性——真值矩阵补齐单元格）。

### 一、威胁建模：按资产与信任边界列清单

- 方法概述：资产（要护什么）→ 入口（从哪进）→ 每入口枚举威胁（STRIDE 六类作检查表：仿冒/篡改/抵赖/信息泄露/拒绝服务/提权）——不展开方法论长篇，给一张入口 × 威胁表即可。
- 信任边界是核心概念：数据每跨一次边界（网络 → 应用、应用 → SQL 解释器、其他用户 → 本页 DOM）都需重新验证——攻击的本质是让数据被解释器误当指令。
- 防御默认姿势：最小权限、默认拒绝（白名单优于黑名单的方向归因：黑名单枚举不完）。

### 二、认证与授权：两个独立问题的机制链

- 分界表先行：认证回答"你是谁"（凭证验证），授权回答"你能干什么"（权限判定）——混为一谈是越权缺陷的源头（水平越权：换 ID 直取他人资源）。
- session 机制环：登录发凭证 → 服务端存会话表 → 每请求携 Cookie 验证；JWT 机制：凭证自包含声明 + 签名，服务端免查表——代价是吊销困难（签名有效即有效，黑名单另建）。对照表落格。
- 授权模型一笔带过：RBAC（角色即权限集合）作默认形态；密码存储落一个动作归因（加盐慢哈希 = 拉高离线爆破成本，方向写死）。

### 三、三条高发攻击因果链与阻断点

- SQL 注入：输入拼进 SQL 字符串 → 解释器把数据当指令 → 防御 = 参数化查询（预编译把结构与数据分离，阻断点在"拼接"环节）；ORM 是封装，不改变因果。
- XSS：恶意脚本随内容入库/入参 → 混入他人页面 DOM 执行 → 防御 = 输出编码（按 HTML 属性/JS/URL 上下文分别转义）+ CSP（声明可执行脚本来源白名单）+ HttpOnly Cookie（即使脚本执行也偷不走凭证）。
- CSRF：浏览器对目标域自动携带 Cookie → 攻击页伪造跨站请求"借"用户身份 → 防御 = SameSite Cookie / CSRF Token（请求携带攻击者拿不到的随机值）；与 XSS 的分水岭：CSRF 借身份不读响应、XSS 直接在其上下文执行。
- 每条链共用同一句收口：攻击沿正常请求环行进，防御在解释边界阻断——不是"更复杂的协议"而是"已有环路上的数据/指令分离"。

### 四、纵深防御：层层独立防线

- 防线表落格：网络（TLS/防火墙，引用 05-06 结论）→ 网关（限流/鉴权）→ 应用（输入验证/参数化/输出编码）→ 数据（最小权限账号/加密存储）→ 监控审计（异常告警与追溯）——每层假设上一层已被突破（这就是"纵深"的定义）。
- 与 08 的衔接点：限流与熔断同样服务可用性防护（DoS 是资源耗尽型威胁）——单句引用。
- 收尾：全章在威胁模型处闭合——计算机网络给了链路，软件工程给了交付，安全给了对抗视角；最后技术节点解析完毕直接收尾，不设延伸节。
