# 设计模式与设计原则

> **版本基准**: universal

## 骨架要点（正文按此展开，完成后删除本骨架块）

- **定位**：消费 04-编程运行环境 的虚表/动态分发（多态的运行时底座）与 02 的静态/动态链接边界（接口契约的编译期投影）；产出"代码结构级解耦的工具箱"，供 06-架构分层（层间边界即模式化接口）与 08-微服务（服务间解耦的同构放大）消费。
- **核心拓扑流**：信息投影流（接口 = 调用方可见方法集的投影，实现藏在虚表之后）为主；"模式 = 在调用方与实现之间插入可替换层"的插入点分析为骨架。本篇量化单位换轨：间接层数、类型数量、修改波及面。
- **必备图**：①耦合来源分类表（具体/继承/可变性 × SOLID 五原则各自消解哪一项——真值矩阵补齐单元格）；②三个代表模式的插入点 ASCII 图（策略：算法可替换；观察者：一对多通知；装饰器：纵向叠加职责），每图标注调用方、接口、实现三方。
- **锚定来源**：GoF 23 模式（1994）与 SOLID（Robert Martin 谱系）为历史路径依赖，按给定前提使用。

### 一、耦合的来源与 SOLID 的对症表

- 先立病灶：耦合 = 修改一处被迫改多处；三大来源——依赖具体实现（不可替换）、依赖具体数据结构（内部暴露）、职责混杂（一处多因变更）。
- SOLID 逐条对症：单一职责（一个类只有一个变更理由）、开闭（加代码不改旧代码）、里氏替换（子类可无感顶替父类）、接口隔离（小接口按消费者切）、依赖倒置（双方都依赖抽象）——每条写清"消解哪个耦合来源 + 付出的间接层代价"。
- 方向纪律：SOLID 是耦合的减法不是性能的加法——每条原则都新增一层间接，运行时开销与可读性代价明码标价。

### 二、模式谱系：三族按插入点划分

- 创建族（单例/工厂/建造者）：把"对象如何构造"封装起来，调用方只见接口；工厂方法的插入点 ASCII 图先行。
- 结构族（适配器/装饰器/代理/外观）：在既有对象外包裹或桥接——统一不兼容接口、叠加职责、控制访问；装饰器与继承的对偶（组合优于继承的落地处）。
- 行为族（策略/观察者/命令/模板方法）：封装"行为如何变化与通知"；策略替换 if-else 分支树、观察者反转通知方向——各自给一条最小代码链路。
- 澄清框：23 模式不是清单任务，多数模式在动态语言中已内化（一等函数/信号槽/鸭子类型），按语言特性取舍（语言/软件域标尺）。

### 三、模式的取舍账本：间接层的价格

- 每个模式都是"加一层间接换一种变化自由"：变化未发生时间接层是纯负债（多跳转、多文件、多名字）；用"未来变更概率 × 变更收益 > 间接成本"的账本式判断，反对预先套模式。
- 过度设计的识别：为唯一实现建接口、为不存在的扩展留钩子——账本两边的具体动作写明。
- 收尾落在下一跳：单类粒度的解耦工具已齐；系统粒度的分层边界（表现/业务/数据）与团队协作约束——交给 06-架构分层与前后端。
