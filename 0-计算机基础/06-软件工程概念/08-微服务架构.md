# 微服务架构

> **版本基准**: universal（机制锚定通用：REST/消息队列/熔断器/分布式追踪；不绑定具体框架）

## 骨架要点（正文按此展开，完成后删除本骨架块）

- **定位**：消费 05-计算机网络 的 TCP/HTTP/TLS（服务间通信的物理底座）、06-架构分层 的横向切分埋线、07-数据库 的单库机制、05-容器化 的部署单元；产出"服务级拆分与其分布式税"，是本章体系性收口之一。
- **核心拓扑流**：空间事务环为主——一次跨服务请求（含消息队列异步支线）的端到端生命周期闭环，逐跳标注同步等待/异步解耦点；数学推演流按需挂载（可用性串联相乘、扇出请求的尾延迟放大），推导终点落回"串联服务越多可用性越低"的量化断言。
- **必备图**：①单体 → 微服务的边界对照 ASCII 图（进程内函数调用 → 跨网络请求，标出新增的序列化/网络/部分失败三笔税）；②同步调用链与异步消息支线对照图（请求-等待环 vs 发布-订阅环）；③分布式追踪 span 树图（一次入口请求展开为多服务 span，trace 即事务环的投影）。
- **量化锚点**：进程内函数调用纳秒/亚微秒级 < 跨机 HTTP 请求毫秒级（方向不等式，引用 05 的 RTT 档位）；可用性串联公式 $A_{总}=\prod A_i$ 保留代入算例（如 4 个 99.9% 服务串联 → 99.6%）。

### 一、拆分的约束：为什么付分布式税

- 约束显明：单体在团队规模与发布耦合上的失效点——所有变更共享同一个发布周期、一处错误全站重部署、无法按负载差异独立扩容（订单服务 CPU 密集 vs 推荐服务内存密集）。
- 代价明码标价（与收益对照列出）：网络延迟替代函数调用、部分失败替代异常传播、数据一致性替代事务、运维面从 1 台到 N 台——拆分是"用运维复杂度换组织扩展性"的交易。
- 拆分依据 = 业务域边界（引用 06-架构分层 的康威定律与横向切分结论，单句引用不重推）；拆细的下限：数据自治（每服务私有存储，跨库无联合事务）。

### 二、服务间通信：同步与异步的两条环

- 同步环：REST/RPC 请求-响应——调用方阻塞等待，被调方失败即部分失败向上传导；超时/重试/熔断/舱壁四件套的动作归因（各自防哪种失败级联），熔断器状态机（闭合→打开→半开）小图。
- 异步环：消息队列发布-订阅——生产者不等待、消费者按自身节奏拉取；解耦了时间（双方不必同时在线）与容量（削峰填谷），代价是最终一致与消息语义（至少一次 → 消费端幂等）。
- 同步 vs 异步决策表（时延要求/依赖方向/数据一致性需求 × 选哪条环）——真值矩阵补齐。

### 三、分布式的代价：一致性与可观测性

- CAP 取向一句话立骨：网络分区必然发生，P 必选，剩下是在 C 与 A 间按请求取舍——多数业务选最终一致，不展开共识算法证明。
- 幂等性与对账：至少一次投递下，重复消息靠业务键去重；跨服务事务的落地是 Saga（本地事务序列 + 补偿动作）而非两阶段提交——机制概述即止。
- 可观测性三支柱：日志（离散事件）/指标（聚合时序）/追踪（单次请求的跨服务事务环投影）；trace 树与 ①② 图的 span 对应关系点明——没有追踪，部分失败无法定位（因果链收口）。
