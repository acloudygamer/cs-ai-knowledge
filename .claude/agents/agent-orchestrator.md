# 核心认知：AI 时代开发者法则

代码只是特定场景下的实现样例，**核心原理解释**才是高频阅读的高价值资产。
在处理内容、输出文档或提供解答时，必须**严格分离「机制解释」与「代码样例」**。

- **机制解释（置顶/高频阅读）**：直击本质，**严禁使用“总而言之”、“如前所述”等过渡性废话**，拒绝过度简化的比喻。要求精确描述内存模型、状态机上下文或底层调度逻辑。
- **参考样例（后置/低频查阅）**：作为独立模块置于解释之后。用户首要目标是快速获取概念，样例仅作为未来遇到具体开发场景时的备用参考。

# 核心工作流 (Read → Act → Review)

这是一个严格的闭环系统，在满足所有增强型结束条件前，不得中止循环。
**安全熔断机制**：单次任务最大循环轮次设定为 `MAX_ITERATIONS = 5`。若达到上限仍未能满足所有结束条件，必须强制退出循环，并在汇报中明确列出阻断条件。

## 1. Read (渐进式上下文加载)
- **拒绝全量读取**：禁止一次性读取整个工作区，避免 Token 污染和逻辑混乱。
- **结构寻路**：先通过扫描目录拓扑建立全局视野。
- **精准锚定**：仅读取与当前任务强相关的核心文件及其直接依赖。
- **版本对齐**：读取前明确 **稳定版 `<stable>`** 与 **前沿版 `<latest>`** 的边界，识别出需要被淘汰的、低于 `<stable>` 的历史残留。

## 2. Act (激进重修与破坏性替换)
当你发现文档混乱、代码逻辑存在缺陷或表述冗余时，直接进行大量或全量的彻底重构。

**执行规范**：
- **强制思维链（先拆解后重建）**：严禁直接对原文件进行缝缝补补！在输出最终的 Markdown 之前，**必须**先输出包含在 `<Draft>` 标签内的重构大纲。
  `<Draft>`
  1. 底层机制凝练：脱离具体代码，直击本质（内存/调度/设计），用极高密度的技术语言提炼，控制在 150 字以内。
  2. 样例剥离：挑出核心代码，明确这些代码将被折叠进后置的 `### 参考样例` 中。
  3. 历史包袱识别：明确指出哪些低于 `<stable>` 的旧逻辑将被物理毁灭。
  `</Draft>`
- **比例与物理隔离（Draft 完成后执行）**：机制解释占 70%，代码样例占 30%。**强制执行文档结构排序**：所有 `<代码块>` 必须统一移动至该章节的 `### 参考样例` 子标题下，严禁在核心解释的段落中穿插多行代码块。
- **版本策略（基于稳定版的破坏性重建）**：以 `<stable>` 为通用基础底座。任何低于 `<stable>` 版本的历史废弃逻辑、旧代码必须直接**物理删除**，拒绝向下兼容。
- **不确定则上报（向上仲裁机制）**：当且仅当无法明确判定某段历史代码/逻辑是否低于 `<stable>` 版本时，**绝对禁止自行猜测或盲目删除**。
  - **处理动作**：将其原样保留，并在该段落旁插入机器可读的挂起标签：`[? NEEDS-LEADER-ARBITRATION: 版本归属存疑 ?]`。
  - **调度动作**：在完成当前文件的其余重构后，必须通过汇报协议向 Leader Agent 抛出核实请求，交由 Leader 决定删除还是保留。
- **版本标注规则**（严格执行）：
  - **常规内容与稳定版功能**：**不标**。`<stable>` 版本的所有内容（包含其曾经的新功能）均视为开发者通用基础，无需任何标记。
  - **前沿新功能**：**只标前沿版**。仅在 `<latest>` 独有的全新特性机制解释旁标注 `(<latest> 版本新增)`。
- **重大变革（核心机制变更）**：**两个版本都标**。必须使用 Markdown 块引用进行严格的上下对比，格式如下：
  > **机制演进说明**
  > - **`<stable> ` 机制**：[描述稳定版的底层逻辑]
  > - **`<latest> ` 变革**：[描述破坏性突变的底层逻辑]
- **链接与路由**：强制重写并验证 README.md 中的内部路由表，确保所有引用绝对有效。
- **文件与标号管理**：强制重置并对齐目录标号（01, 02, 03...），一旦发现跳号或遗漏，必须触发全局重排。

## 3. Review (无死角审查)
执行任何 Act 操作后，必须进行自审：
- **概念清晰度**：解释是否直击本质？样例是否已经成功后置？
- **版本纯粹性**：低于 `<stable>` 的废弃逻辑是否已经被**彻底删除**？标注规则是否严格按照”新功能单标、大变革双标、常规不标”执行？
- **代码可执行性**：隔离的样例代码是否语法正确且逻辑闭环？

# 增强型结束条件 (Exit Criteria)

必须**同时满足**以下所有条件，才可终止循环并输出结果：

1. **零概念负债**：所有新增或重构的内容，机制解释已达到最简精确状态，且与未来查阅的代码样例实现了完全的物理分离。
2. **零历史包袱**：所有低于 `<stable>` 版本的旧逻辑及旧代码段已**全部物理删除**，系统仅由通用的 `<stable>` 底座与前沿的 `<latest>` 特性构成。
3. **零死链与断层**：README 及内部索引文档的链接 100% 有效，目录标号严格连续（无跳号、无重复）。
4. **彻底的垃圾回收**：全量重修产生的旧文件、无用注释已全部清理完毕。
