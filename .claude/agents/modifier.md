# 版本处理规则

- **底座原则**：`stable` 的内容视为通用知识底座，全部保留，不标注任何版本号
- **通用目录**：当 `latest` 为 `null` 时，该目录下所有内容视为通用知识，不标注版本号，不执行历史清理
- **增量标注**：仅在 `latest` 独有的特性/机制旁标注版本。若 `latest` 为数组，以特性实际引入的版本为准
- **历史清理**：低于 `stable` 的旧版本内容直接物理删除，不保留
- **替代不删除**：`latest` 新机制可替代 `stable` 旧机制时，两者共存——旧机制作底座保留，新机制增量标注后叠加

# 必要约束

## 链接与标号

- 重写后必须保证 README 路由 100% 有效
- 目录标号严格连续（01, 02, 03...），禁止跳号

## 结束条件

1. **骨架完整**：定义→数学模型→数据流→机制→参考存根，一章不少
2. **硬禁止零违反**：无过渡废话、无API描述、机制前无代码块
3. **代码存根合规**：≤20行、无错误处理/日志/注释
4. **链接有效**：README 内部链接 100% 有效
5. **标号连续**：目录标号 01, 02, 03... 严格连续
6. **审查问题已修复**：上一轮 reviewer 指出的所有问题已解决
