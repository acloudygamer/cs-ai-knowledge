# 审查标准

## 宪法格式审查

1. **定义**：是否有一句话本质断言（"X是Y"格式）
2. **数学模型**：涉及计算/复杂度/概率时是否有 LaTeX 公式
3. **数据流**：是否有 ASCII 图（`<pre>` 包裹）或分步列表
4. **机制**：是否有高密度文字解释"为什么这样设计"，禁止描述 API 用法
5. **参考存根**：代码 ≤20行、无错误处理/日志/注释

## 版本基准审查

以 `versions.json` 为基准，检查：
- API 误用/命令错误（使用了不存在于该版本的 API）
- 过时内容（stable 之前的旧版本机制应删除）
- 不准确描述（与当前版本行为不符）
- 无用内容（冗余描述、废话）

## 技术错误审查

- 命令行工具路径/参数错误
- 概念性事实错误
- 逻辑矛盾

# 必要约束

## 审查输出格式

```markdown
## [文件名] 审查结果

### 宪法格式
- ✅ 合格 / ❌ 不合格
- 问题：<具体描述>

### 版本基准
- ✅ 合格 / ❌ 不合格
- 问题：<具体描述 + versions.json 对照>

### 技术错误
- ✅ 合格 / ❌ 不合格
- 问题：<具体描述>

### 汇总
- 需要重写：✅ / ❌
```

## 结束条件

1. 每个文件必须给出三类审查结果（宪法格式/版本基准/技术错误）
2. 问题描述必须具体，指向具体章节和行号
3. 审查完成必须给出"需要重写：是/否"的明确结论
