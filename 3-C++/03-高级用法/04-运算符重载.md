# 运算符重载

> **版本关系**：C++98（基础）→ C++11（移动语义）→ C++20（三路比较）→ C++23/26

## 定义

**运算符重载是让自定义类型通过值语义语法参与运算的语法糖，本质是命名函数调用伪装成运算符记号。** 它不创造新语义，仅改变表达形式——运算符的语义完全由重载实现定义。

**核心约束**：运算符重载不能改变运算符的**优先级**、**结合性**、**目数**（二元/一元）。`+` 始终是二元运算符，左结合。

## 数学模型

### 代数结构与运算符重载

自定义类型实现运算符时，实际上是在构造一个**代数结构**：

- **半群（Semigroup）**：闭合（ $\forall a,b: a+b \in S$）+ 结合律（ $(a+b)+c = a+(b+c)$） ）+ 结合律（ $(a+b)+c = a+(b+c)$））
- **幺半群（Monoid）**：半群 + 单位元（ $\exists e: a+e = a$） ）
- **群（Group）**：Monoid + 逆元（ $\forall a, \exists a^{-1}: a+a^{-1} = e$） ）

```cpp
// 验证半群：闭合性 + 结合律由类型系统保证，实现由程序员保证
struct Vec2 {
    Vec2 operator+(const Vec2& rhs) const { return {x + rhs.x, y + rhs.y}; }
    // 结合律：(a+b)+c = a+(b+c) 由实现保证
};
```

**三路比较（`<=>`）的代数意义**：

`<=>` 返回一个**比较类别类型**（comparison category），定义了一个**严格弱序**（Strict Weak Ordering）：

 $\forall a,b,c \in S: \quad a \prec b \implies \neg(b \prec a) \quad \text{（非对称）}$ 
 $\forall a,b,c \in S: \quad a \prec b \land b \prec c \implies a \prec c \quad \text{（传递）}$ 

### 隐式转换的格（Lattice）结构

C++ 的隐式转换构成一个**格**：

 $\text{类型A} \prec \text{类型B} \iff \text{A 可隐式转换为 B}$ 

用户定义的转换（`operator T()`）和标准转换（整型提升、浮点提升）在这个格中有明确定义的优先级。

**`explicit operator bool` 的语义**：将布尔转换约束为仅在**上下文布尔转换**（`if`、`while`、`!`、`&&`、`||`）中允许，防止意外的类型滥用。

### 运算符函数的查找规则

1. **成员运算符**（`a op b`）：在 `a` 的类作用域查找 `a.operator op(b)`
2. **友元/普通函数**（`a op b`）：在普通命名空间查找 `operator op(a, b)`
3. **内建运算符**：若两个候选都存在，选择更特殊的（成员 > 友元 > 内建）

```cpp
struct Vec {
    double x, y;
    Vec(double x, double y) : x(x), y(y) {}

    // 成员：a + b → Vec::operator+(b)
    Vec operator+(const Vec& rhs) const { return {x + rhs.x, y + rhs.y}; }
};

// 友元：a * scalar → operator*(a, scalar)
friend Vec operator*(double s, const Vec& v) { return {s * v.x, s * v.y}; }
friend Vec operator*(const Vec& v, double s) { return s * v; }
```

## 机制

### 成员 vs 友元运算符的选择

**左操作数必须是自身**是成员运算符的本质限制。决定标准：

| 情况 | 推荐形式 |
|------|----------|
| `a + b`，`a` 是自定义类型 | 成员或友元皆可 |
| `scalar * Vec`（左操作数是内置类型） | **必须友元**，内置类型无法添加成员 |
| `a == b`（需要对称性） | **推荐友元**，保证 `a == b` 和 `b == a` 调用同一函数 |
| `a += b`（修改左操作数） | **成员**，因为修改 `this` |

### operator bool 的危险域

`operator bool` 允许类型隐式转换为 `bool`，这在以下场景造成问题：

```cpp
struct Ptr {
    T* p;
    operator bool() { return p != nullptr; }
};

Ptr ptr = ...;
if (ptr) { }        // 预期：检查指针
int x = ptr;        // 灾难：隐式转为 0/1，可参与算术运算！
ptr + 1;           // 同样灾难
```

**`explicit operator bool`（C++11 起）** 限制转换仅在**上下文布尔转换**中发生：

```cpp
explicit operator bool() const { return ptr != nullptr; }

if (ptr) { }        // OK：上下文布尔转换
// int x = ptr;    // 错误：explicit 禁止隐式转换
// ptr + 1;        // 错误
bool b = ptr;      // 错误：需要显式转换
```

### 三路比较的数学完备性

传统比较的问题：六个比较运算符（`==`、`!=`、`<`、`>`、`<=`、`>=`）容易不一致：

```cpp
// 可能的不一致（违反数学性质）
struct Broken {
    int a, b;
    bool operator==(const Broken& o) const { return a == o.a; }  // 只比较 a
    bool operator<(const Broken& o) const { return b < o.b; }  // 只比较 b
    // Broken{1, 0} == Broken{1, 1} → true
    // Broken{1, 0} < Broken{1, 1}  → true
    // !(a < b) && !(b < a) ≠ a == b  ← 数学不一致！
};
```

** spaceship 操作符（`<=>`）保证等价关系**：

```cpp
struct Fixed {
    int a, b;
    auto operator<=>(const Fixed&) const = default;  // 成员逐个比较
};
// 生成的等价关系：(a == o.a) && (b == o.b)
// 保证：!(x < y) && !(y < x)  ⟺  x == y
```

### 移动语义与运算符

移动语义改变了运算符实现的效率边界：

```cpp
// 传统拷贝赋值
Vec& operator=(const Vec& rhs) {
    x = rhs.x;
    y = rhs.y;
    return *this;
}

// 移动赋值（C++11）
Vec& operator=(Vec&& rhs) noexcept {
    x = std::move(rhs.x);
    y = std::move(rhs.y);
    return *this;
}
```

**移动语义允许"窃取"资源**（指针、文件句柄等），而不是深拷贝。在运算符重载中，这使得**交换（swap）** 操作可以 O(1) 实现：

```cpp
void swap(Vec& a, Vec& b) noexcept {
    using std::swap;
    swap(a.x, b.x);  // 移动而非拷贝
    swap(a.y, b.y);
}
```

## 不可重载的运算符

以下运算符**语义上依赖上下文**，或涉及语言基础设施，无法语义独立：

| 运算符 | 不可重载原因 |
|--------|-------------|
| `::` | 作用域解析，语言级名称查找 |
| `.*` | 成员指针解引用，无法绑定到用户定义类型 |
| `.` | 成员访问，涉及 ADL 最内层作用域 |
| `?:` | 三目运算符的短路语义无法通过函数模拟 |
| `sizeof` | 编译期大小查询，涉及语言元理论 |
| `typeid` | 运行时类型查询，涉及 RTTI |
| `dynamic_cast` | 类型强制转换的运行时检查 |
| `static_cast` | 编译期强制类型转换 |
| `reinterpret_cast` | 位级重解释 |
| `const_cast` | 移除/添加 const |

```cpp
// 三路比较的完整实现
struct Vec2 {
    double x, y;

    // C++20：三路比较生成所有六个比较运算符
    auto operator<=>(const Vec2&) const = default;
};

// 表达式模板（C++98 遗留模式，用于延迟求值）
template<typename LHS, typename RHS, typename Op>
struct Expression {
    LHS lhs;
    RHS rhs;
    double operator[](size_t i) const { return Op::apply(lhs[i], rhs[i]); }
};

template<typename LHS, typename RHS>
Expression<LHS, RHS, AddOp> operator+(const LHS& l, const RHS& r) {
    return {l, r};
}

// 使用
Matrix a, b, c;
// c = a + b;  // 延迟到赋值时才计算
```
