## std::execution：发送方-接收方接口（C++26）

### 解决什么问题
C++20 协程和 Concurrency TS 提供的异步编程模型互不兼容，第三方库（Boost.Fiber、CppCoro）各有实现，难以统一。std::execution 提供标准的发送方-接收方接口，统一所有异步和并行编程场景。

### 核心概念

```cpp
#include <execution>

// 发送方（Sender）：产生值或错误
// 接收方（Receiver）：消费值或处理错误
// 调度器（Scheduler）：决定任务在哪里执行
```

### 发送方/接收方模式

`std::execution` 的核心是发送方（Sender）和接收方（Receiver）的组合：

```cpp
#include <execution>
#include <iostream>

// 发送方工厂：创建产生值的发送方
auto sender = std::execution::just(1, 2, 3, 4, 5);

// 使用管道操作组合
auto processed = sender
    | std::execution::then([](int x) { return x * 2; })  // 转换值
    | std::execution::then([](int x) { return x + 1; });
```

### 调度器（Scheduler）

调度器决定任务在哪里执行。C++26 标准库提供的是概念和算法，具体调度器实现由库提供：

```cpp
#include <execution>
#include <iostream>

// std::execution 提供的工厂函数创建发送方
auto sender = std::execution::just(1, 2, 3, 4, 5);

// std::execution::then 转换值
auto doubled = sender | std::execution::then([](int x) { return x * 2; });

// std::execution::when_all 组合多个发送方
auto combined = std::execution::when_all(
    std::execution::just(1),
    std::execution::just(2),
    std::execution::just(3)
);

// 注意：C++26 标准库提供的是 sender/receiver 概念和算法
// 具体的调度器（如 inline_scheduler、thread_pool_scheduler）由实现库提供
```

### 发送方算法组合

```cpp
#include <execution>
#include <vector>

// then：转换值
auto doubled = std::execution::just(42)
    | std::execution::then([](int x) { return x * 2; });

// when_all：组合多个发送方
auto combined = std::execution::when_all(
    std::execution::just(1),
    std::execution::just(2),
    std::execution::just(3)
);

// let_error：错误处理
auto with_error_handling = std::execution::just(1, 2, 3)
    | std::execution::let_error([](auto) {
        return std::execution::just(0);  // 出错时返回默认值
    });
```

### 实际应用：并行计算

```cpp
#include <execution>
#include <vector>
#include <numeric>
#include <iostream>

std::vector<int> data(1000);
std::iota(data.begin(), data.end(), 1);

// 使用执行策略进行并行归约（C++17）
int sum = std::reduce(std::execution::par_unseq, data.begin(), data.end(), 0);

std::cout << "Sum: " << sum << "\n";

// 并行排序
std::sort(std::execution::par_unseq, data.begin(), data.end());
```

### 与 C++20/C++23 对比

| 特性 | std::async | C++20 协程 | std::execution |
|------|------------|------------|----------------|
| 组合性 | 差 | 好 | 最好 |
| 错误处理 | future.get() | co_await | sender/receiver |
| 调度控制 | 有限 | 自定义 | 完全可控 |
| 标准支持 | C++11 | C++20 | C++26 |

## std::meta：反射（实验性）

C++26 引入了编译期反射能力，可以通过 `std::meta::info` 查询类型信息，支持编译期元编程。

> **注意**：`std::meta` 是实验性功能，编译器支持有限。GCC 不支持，Clang 19+ 有实验性支持。

### 基础反射查询

```cpp
#include <meta>

struct Point {
    int x;
    int y;
};

int main() {
    // 反射获取类型信息
    constexpr auto info = std::meta::info_of<Point>();

    // 获取成员变量
    constexpr auto members = std::meta::members_of(info);

    // 编译期验证
    static_assert(members.size() == 2);
}
```

### 类型名称反射

```cpp
#include <meta>

struct MyStruct {
    int value;
    double data;
};

int main() {
    // 获取类型的名字（编译期字符串）
    constexpr auto type_name = std::meta::name_of(std::meta::info_of<MyStruct>);

    // 编译期验证
    static_assert(std::meta::name_of(std::meta::info_of<MyStruct>) == "MyStruct");
}
```

### 编译期代码生成模式

```cpp
#include <meta>

// 编译期获取成员名称列表
template<typename T>
constexpr auto get_member_names() {
    constexpr auto members = std::meta::members_of(std::meta::info_of<T>);
    std::array<std::string_view, members.size()> names;
    // 编译期填充 names
    return names;
}

// 使用反射生成代码（伪代码示例）
template<typename T>
void serialize(const T& obj) {
    // 传统方式需要手动列出每个成员
    // 未来可以用反射自动完成：
    // for each member in T:
    //     output member.name() << ": " << obj.member
}
```

### 限制与注意事项

```cpp
// 反射的当前限制：
// 1. 无法通过反射修改原始类型定义
// 2. 私有成员访问受限
// 3. 函数指针和静态成员需要特殊处理
// 4. 编译器支持有限（实验性）

// 推荐使用场景：
// - 自动化代码生成（序列化、日志）
// - 调试和诊断工具
// - 领域特定语言（DSL）实现
```

## 改进的 constexpr 支持

### constexpr new/delete（C++26）

C++26 改进了 constexpr 上下文中使用 new/delete 的能力：

```cpp
constexpr int* allocate_and_init() {
    int* p = new int(42);
    int val = *p;
    delete p;
    return val;  // 可以 return 堆分配的值
}

constexpr int x = allocate_and_init();  // 编译时执行
```

## std::not_fn 改进（C++26）

`std::not_fn` 现在支持静态调用运算符：

```cpp
#include <functional>
#include <iostream>

struct Pred {
    bool operator()(int x) const { return x > 0; }
};

int main() {
    auto not_pred = std::not_fn(Pred{});

    std::cout << std::boolalpha;
    std::cout << not_pred(5) << "\n";   // false
    std::cout << not_pred(-5) << "\n";  // true
}
```

## 合约（Contracts）

### 解决什么问题
在函数调用前后验证前置条件和后置条件，在代码中嵌入可执行的规格说明，提升代码健壮性和可维护性。

### 核心概念
- `[[expects]]` 声明前置条件（参数约束）
- `[[ensures]]` 声明后置条件（返回值约束）
- `[[assert]]` 声明断言语句
- 四种语义：`ignore`（非检查）、`observe`、`enforcement`、`quick_enforcement`

### 怎么用

```cpp
// 前置条件：参数必须满足的条件
int divide(int a, int b) [[expects b != 0]] {
    return a / b;
}

// 后置条件：返回前的状态约束
int allocate(int size) [[ensures result: result > 0]] {
    int* p = new int(size);
    return size;  // 假设返回分配的大小
}

// 断言：代码执行到此处必须满足的条件
void critical_operation() [[assert: some_condition]] {
    // ...
}

// 组合使用
int safe_divide(int a, int b)
    [[expects b != 0]]
    [[ensures result: result >= 0]]
{
    return a / b;
}
```

### 语义模式

```cpp
// 契约有四种求值语义（由实现选择或运行时标志决定）
// ignore: 不检查（发布版本）
// observe: 检查但不终止
// enforcement: 检查并终止
// quick_enforcement: 快速检查模式

// 编译器标志控制行为：
// -fcontract-level=default (enforcement)
// -fcontract-level=ignore
// -fcontract-level=observe
```

> **注意**：Contracts 在 C++ 委员会内部存在争议（Bjarne Stroustrup 等人曾表示反对），但最终仍被纳入 C++26 标准。

### 属性改进

## 与 C++23 的关系

C++26 在 C++23 基础上继续发展：

| 特性 | C++23 | C++26 |
|------|-------|-------|
| std::expected | 基础版 | + monadic 操作（and_then, transform 等） |
| std::generator | 非标准提案 | 标准化 |
| std::print | 支持 | 改进 |
| std::execution | 提案 | 合并标准 |
| Contracts | 无 | 新增（[[expects]]/[[ensures]]/[[assert]]） |

```cpp
// C++23 std::expected
std::expected<int, Error> parse_int(const std::string& s);

// C++26 添加了 monadic 操作，链式调用更方便
auto result = parse_int(s)
    .transform([](int x) { return x * 2; })      // 转换值
    .and_then([](int x) { return process(x); }); // 链式处理
```

## 迁移指南

### 从 C++23 迁移到 C++26

1. **合约编程**：使用 `[[expects]]`/`[[ensures]]`/`[[assert]]` 增强代码健壮性
2. **异步代码**：考虑使用 `std::execution` 替代自定义协程框架或第三方库
3. **错误处理**：`std::expected` 的 monadic 操作让链式错误处理更简洁
4. **反射**：使用 `std::meta` 简化编译期元编程（实验性，慎用）
5. **编译期计算**：C++26 改进了 constexpr new/delete 等特性

```cpp
// C++26 改进了 constexpr new/delete
constexpr int* allocate_and_init() {
    int* p = new int(42);  // C++26 改进
    int val = *p;
    delete p;              // C++26 改进
    return val;
}
```
