# C++26 新特性

> **版本关系**：C++26（latest，前沿标准）

**C++26 的核心特性是 std::execution 发送方-接收方并发模型，以及 Contracts 契约编程。这些特性代表了 C++ 并发和软件工程实践的重大飞跃。**

## 定义

| 特性 | 本质操作 | 约束边界 |
|------|----------|----------|
| std::execution | 发送方-接收方接口，用管道操作符组合异步/并行任务 | C++26 仅 MSVC 支持，GCC/Clang 实验性 |
| Contracts | 可执行的规格说明，前置/后置/断言条件 | 广泛支持但语义未最终确定 |
| std::meta | 编译期反射能力，代码生成 | 仅 Clang 19+ 实验性 |
| `static_assert(true)` 改进 | `static_assert(false)` 不再硬错误（延迟诊断） | C++26 |

C++26 的设计目标：**统一异步/并行编程模型**（std::execution）和**提升软件正确性**（Contracts）。

## 数学模型

### std::execution 的代数结构

Sender-Receiver 模型是 **响应式流（Reactive Streams）** 的变体：

$$
S \xrightarrow{\text{set_value(v)}} R \quad \text{或} \quad S \xrightarrow{\text{set_error(e)}} R \quad \text{或} \quad S \xrightarrow{\text{set_done()}} R
$$

三种信令互斥，发送后不可撤销。

**Sender 的组合子** 形成 **Monoid** 结构：

$$
\text{Sender} \xrightarrow{\text{then}} \text{Sender} \quad (\text{结合律})
$$
$$
\text{just}(v) \xrightarrow{\text{then}(f)} \text{just}(f(v)) \quad (\text{单位元})
$$

`when_all` 组合多个 Sender，形成扇入（fan-in）结构。

### std::execution 的调度器语义

Scheduler 决定了 Sender 在哪里执行：

$$
\text{Scheduler} \times \text{Sender} \rightarrow \text{Sender}
$$

- **inline_scheduler**：当前线程同步执行
- **thread_pool_scheduler**：在线程池中异步执行
- **system_scheduler**：系统级异步（类似 ASIO）

调度器的选择影响 **数据流的拓扑排序** 和 **资源竞争条件**。

### Contracts 的语义

Contracts 本质上是 **可执行的不变量**：

$$
P(x) \ \text{前置条件} \Rightarrow \text{函数体} \ \Rightarrow \ Q(x) \ \text{后置条件}
$$

$$
\text{assert}(I) \ \text{检查点}
$$

- `[[expects]]`：函数入口检查
- `[[ensures]]`：函数出口检查
- `[[assert]]`：代码内部检查

**违反后果** 由语义决定（可能崩溃、可能返回错误）。

## 数据流

<pre>
std::execution 模型：
Sender ────────────────────────────→ Receiver
   │                                     │
   ├─ just(1, 2, 3)  ───────────────→  ├─ set_value(1, 2, 3)
   │                                     │
   ├─ then([](int x) { }) ────────→   管道组合（lazy）
   │                                     │
   ├─ when_all(a, b, c) ───────────→   扇入结构
   │                                     │
   ├─ let_error([](auto) { })  ────→   错误处理
   │                                     │
   └─ on(sched, sender)  ──────────→   调度器绑定
           │
           ▼
     Scheduler
     ├─ inline_scheduler  ── 同步执行
     ├─ thread_pool_scheduler  ── 线程池
     └─ system_scheduler  ── 系统级异步

Contracts 模型：
调用者 ──[[expects]]──→ 函数入口 ──[[assert]]──→ 函数体 ──[[ensures]]──→ 函数出口
     │                      │                    │                    │
     │                      ▼                    ▼                    ▼
     │                  违反：崩溃           违反：崩溃           违反：崩溃
     │                  / 返回错误           / 立即终止           / 返回错误
     ▼                  /                    /                    /
   调用点              默认行为              默认行为              默认行为
</pre>

**所有权流转**：
- Sender 持有数据的**发送权**，Receiver 持有数据的**消费权**
- Sender 在 connect 时与 Receiver 建立连接（不是复制数据）
- 数据的生命周期由 Sender 和 Receiver 协调管理

## 机制

### std::execution 为什么重要

C++20 协程和 Concurrency TS 的异步模型互不兼容：
- `std::future`/`std::promise` 缺乏组合性
- ASIO 用自己的 `spawn`/`async_result`
- Folly 用自己的 `Future`/`Promise`

std::execution 提供**统一的接口**：

```cpp
// 管道风格组合
auto result = std::execution::just(1, 2)
    | std::execution::then([](int a, int b) { return a + b; })
    | std::execution::then([](int sum) { return sum * 2; });

std::execution::sync_wait(result);  // 在当前线程同步执行
```

`when_all` 实现并行等待：

```cpp
auto [a, b, c] = std::execution::sync_wait(
    std::execution::when_all(task_a(), task_b(), task_c())
);
```

### std::execution 的惰性求值

Sender 在 `sync_wait` 或 `start_detached` 被调用前**不执行**。这是惰性求值（lazy evaluation）：

$$
\text{lazy\_eval}(S) \Rightarrow \begin{cases}
\text{执行} & \text{当调用 sync\_wait} \\
\text{不执行} & \text{仅当链接}
\end{cases}
$$

对比 `std::future`：构造即执行，无法组合。

### Contracts 的设计目标

Contracts 将运行时检查编译进代码，提供**可执行的规格说明**：

```cpp
int divide(int a, int b) [[expects b != 0]] [[ensures r: r * b == a]] {
    return a / b;
}
```

**vs assert**：
- `assert`：运行时宏，发布版本可能被禁用
- `[[assert]]`：语言级语义，不可禁用（除非特殊编译标志）

**vs exception**：
- Exception：用于异常情况，需要 try/catch
- Contract violation：用于"不应该发生"的情况，违反表示 Bug

### std::meta 编译期反射

std::meta 让编译器在编译期提供类型信息：

```cpp
consteval {
    auto info = std::meta::info_of(int);
    // info.name() → "int"
    // info.size() → sizeof(int)
}
```

用途：
- 代码生成：`std::meta::generate` 生成序列化/反序列化代码
- 反射驱动开发：减少手写样板代码

**约束**：目前仅 Clang 19+ 实验性支持，语义可能变化。

### static_assert(false) 的延迟诊断（C++26）

C++26 前，`static_assert(false)` 在模板定义时立即诊断，即使模板未被实例化：

```cpp
template<typename T>
void f() { static_assert(false); }  // 立即错误

f<int>();  // 永远不会触发，因为定义时就错了
```

C++26 改进了这一点：`static_assert(false)` 的诊断被**延迟**到实例化点：

```cpp
template<typename T>
void f() { static_assert(false); }  // C++26：仅在实例化时报错

f<int>();  // 实例化点 → 报错
```

## 参考存根

```cpp
#include <execution>
#include <iostream>

// std::execution 管道风格（实验性，MSVC 支持）
auto task = std::execution::just(1, 2)
    | std::execution::then([](int a, int b) { return a + b; })
    | std::execution::then([](int sum) {
        std::print("Sum: {}\n", sum);
        return sum;
    });

std::execution::sync_wait(task);

// Contracts（广泛支持，语义未最终确定）
int safe_div(int a, int b) [[expects b != 0]] [[ensures r: r * b == a]] {
    return a / b;
}

int main() {
    [[assert] sizeof(int) == 4];  // C++26：保证检查
    return 0;
}
```

## 编译器支持

| 特性 | GCC | Clang | MSVC |
|------|-----|-------|------|
| std::execution | 不支持 | 18+（实验性） | 19.29+（实验性） |
| Contracts | 14+（部分） | 18+ | 19.28+ |
| std::meta | 不支持 | 19+（实验性） | 不支持 |
| static_assert 改进 | 14+ | 14+ | 2019+ |

---

**归约终点**：std::execution 可归约为 **惰性求值的响应式流**，Sender 是数据的生产方，Receiver 是消费方，Scheduler 决定执行上下文。Contracts 可归约为 **可执行的不变量**（前置/后置/断言），将运行时检查提升为语言级语义。std::meta 是 **编译期 introspection**（内省）能力。
