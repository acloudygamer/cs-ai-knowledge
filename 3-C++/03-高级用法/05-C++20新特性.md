# C++20 新特性

> **版本关系**：C++20（基础）→ C++23（模块完善）→ C++26（std::execution）

**C++20 是现代 C++ 的转折点：概念约束模板、惰性组合视图、三路比较、编译期求值全面升级。**

## 定义

| 特性 | 一句话断言 |
|------|-----------|
| Concepts | 模板参数的显式约束，让编译错误从"无法实例化"变为"不满足 X" |
| Ranges | 惰性求值的可组合视图，算法不再需要迭代器对 |
| Modules | 替换头文件的编译防火墙，消除宏污染和重复编译 |
| `<=>` | 返回三态比较结果（less/equal/greater）的三路运算符 |
| consteval | 强制函数必须在编译期求值 |
| constexpr | 扩展至支持动态分配和虚拟调用（C++20） |

## 机制

**Concepts 为什么改善错误信息**：传统模板错误是"无法实例化"的级联效应，编译器报告第 47 层嵌套调用中某个类型缺少某个成员。Concepts 在声明处明确约束条件，违反时直接报告"类型 T 不满足 Hashable"。

**Ranges 的惰性优势**：传统算法 `std::filter + std::transform` 需要创建中间容器（两次拷贝）。Ranges 视图是惰性的，遍历时才计算，零额外内存。

**Modules 消除宏污染的原理**：头文件每次 inclusion 都展开宏，模块只暴露 export 的符号，宏在模块边界消失。

**三路比较的数学完备性**：`a < b`、`a == b`、`a > b` 三个运算符必须保持数学一致（C++20 前可能 `!(a < b) && !(a > b)` 不等于 `a == b`）。`<=>` 统一推导关系。

## 参考存根

```cpp
#include <concepts>
template<std::integral T>
T add(T a, T b) { return a + b; }

#include <ranges>
auto r = std::views::iota(1) | std::views::take(10);

#include <compare>
struct Point { int x, y; auto operator<=>(const Point&) const = default; };
```
