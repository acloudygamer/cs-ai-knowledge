# 内存管理

> **版本关系**：C++11（智能指针）→ C++17（make_unique）→ C++20 → C++23（ arenas）→ C++26

## 定义

**内存管理是在堆上分配、持有、释放对象生命周期的艺术，RAII 将资源生命周期绑定到词法作用域。** C++ 的内存管理摒弃垃圾回收，通过确定性析构保证资源释放时机可预测。

**所有权（Ownership）** 是理解现代 C++ 内存管理的核心概念：每个堆对象有且仅有**一个明确的 owner**，owner 负责在适当时候释放对象。所有权可以通过移动语义转移，但从不共享（除非通过引用计数共享所有权）。

## 数学模型

### shared_ptr 引用计数状态机

引用计数 $rc$ 的生命周期可建模为**有限状态自动机（FSM）**：

$M = (Q, \Sigma, \delta, q_0, F)$

- **状态集** $Q = \{ \text{Alive}(rc > 0),\ \text{Destroying}(rc = 0),\ \text{Released} \}$
- **输入字母表** $\Sigma = \{ +\text{copy},\ -\text{copy},\ \text{reset},\ \text{move} \}$
- **转移函数** $\delta: Q \times \Sigma \to Q$

状态转移图：

```
         ┌──────────────────────────────────────────┐
         │                                          │
    copy ─┤                                          │
         ▼                                          │
    ┌─────────┐  -copy / rc>1   ┌──────────┐  -copy / rc=1   ┌────────────┐
────│ rc = N  │ ──────────────► │ rc = N-1 │ ────────────────► │ rc = 1     │
    └─────────┘                 └──────────┘                  └─────┬──────┘
         ▲                                                          │
         │                       reset / move                        │
         └──────────────────────────────────────────────────────────┘
                                       │
                                       ▼
                              ┌────────────────┐  destroy   ┌───────────┐
                              │  Destroying    │ ──────────► │ Released  │
                              │  (rc → 0)      │            │ (delete)  │
                              └────────────────┘            └───────────┘
```

**转移规则形式化**：

$\delta(\text{Alive}(rc = n), +\text{copy}) = \text{Alive}(rc = n + 1),\quad n \geq 1$
$\delta(\text{Alive}(rc = n), -\text{copy}) = \begin{cases} \text{Alive}(rc = n-1) & n > 1 \\ \text{Destroying} & n = 1 \end{cases}$
$\delta(\text{Destroying}, \_) = \text{Released}$

### 引用计数收敛定理

设 $rc(t)$ 为时刻 $t$ 的引用计数， $T_{\text{destroy}}$ 为析构时刻。引用计数是**单调递减的离散序列**，满足：

$\forall t < T_{\text{destroy}}: rc(t) \in \mathbb{N}^+,\quad rc(t+1) \leq rc(t)$

**收敛性**：
$\lim_{t \to T_{\text{destroy}}^-} rc(t) = 1,\quad rc(T_{\text{destroy}}) = 0$

weak_ptr 持有**弱引用** $wc$ ，不参与 $rc$ 的计数：

$rc' = rc \quad \text{（weak_ptr 操作不影响 } rc \text{）}$

### 对象图与循环引用

设对象图 $G = (V, E)$ ，其中 $V$ 是堆对象集合， $E \subseteq V \times V$ 是 `shared_ptr` 强引用边。

**强连通分量（SCC）**： $C \subseteq V$ 是 SCC 当且仅当  $\forall u, v \in C: u \rightsquigarrow v$（存在路径）。

**循环引用问题**：若 $C$ 是 SCC 且无外部入边，则 $\forall x \in C: rc(x) \geq 1$ （内部循环维持计数）。

**weak_ptr 打破环**：引入弱边 $E_w$ （weak_ptr），弱边不计入入度。设 $C$ 的外部入度：

$\text{in}_{E_w}(C) = |\{ (v, w) \in E_w \mid v \notin C, w \in C \}|$

若 $\text{in}_{E_w}(C) > 0$ 且外部强引用消失，则 $C$ 中对象可被析构。

### RAII 有限状态自动机

RAII 对象的状态转移：

```
     构造                   作用域终点
┌──────────┐ ────────────────────────────────────► ┌──────────┐
│ Uninitialized │                                  │ Released  │
└──────────┘                                      └──────────┘
     │                                                  ▲
     │ 构造（获取资源）                                     │
     └──────────────────────────────────────────────────┘
```

**关键保证**：无论控制流如何退出（正常返回、异常、`longjmp`），RAII 对象都进入 Released 状态。这由 C++ 的栈展开（stack unwinding）机制保证。

### 内存分配器的形式约束

**Arena 分配器**：预分配内存块集合 $M = \{m_0, m_1, \dots, m_{n-1}\}$ ，满足：

$\forall i: |m_i| = 2^k \text{（幂等大小）},\quad \sum_i |m_i| \leq \text{ARENA\_SIZE}$

**Buddy 系统**：分配时找到最小的 $2^k$ 满足请求大小 $s$ ：
$k = \lceil \log_2 s \rceil$

合并条件：两个大小为 $2^k$ 的块 $b_1, b_2$ 可合并当且仅当：
1. $b_1$ 和 $b_2$ 地址相邻
2. $b_1$ 的起始地址是 $2 \times 2^k$ 的倍数（对齐约束）

## 对比参照

### RAII vs GC（手动管理 vs 自动回收）

| 属性 | RAII（C++） | GC（Java/Go） |
|------|-------------|----------------|
| 释放时机 | 确定性（析构函数，词法作用域结束时） | 非确定性（依赖 GC 调度） |
| 内存泄漏风险 | 低（栈展开保证析构） | 中（循环引用无法回收） |
| 性能开销 | 零（编译期确定） | 停顿时间（STW 暂停） |
| 适用场景 | 实时系统、资源管理 | 通用内存管理 |

**归约终点**：RAII 将资源生命周期绑定到对象作用域，GC 将内存回收延迟到堆压力触发时。

### 智能指针对比

| 属性 | unique_ptr | shared_ptr | weak_ptr |
|------|------------|-------------|----------|
| 所有权 | 独占（移动转移） | 共享（引用计数） | 不参与计数 |
| 循环引用 | 无（独占） | 需 weak_ptr 打破 | 用于打破循环 |
| 开销 | 零（仅模板） | 原子引用计数（原子操作） | 少量（控制块） |
| 适用场景 | 唯一所有者 | 共享所有权 | 观察者、缓存 |

### 分配器策略对比

| 策略 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 空闲链表 | 灵活 | 碎片化 | 变长分配 |
| Buddy 系统 | 合并简单 | 内部碎片 | 固定幂次大小 |
| Arena | 批量释放快 | 无法单独释放 | 游戏/实时系统 |
| 对象池 | 复用率高 | 内存浪费 | 高频短生命周期对象 |

## 数据流

<pre>
堆对象生命周期
     │
     ├─ make_shared / make_unique  ◄─── 分配 + 构造
     │
     ▼
shared_ptr / unique_ptr 持有
     │
     ├── unique_ptr: 独占所有权（移动语义转移）
     │
     ├── shared_ptr: 引用计数 +1（拷贝构造）
     │                   │
     │                   ├── weak_ptr: 观察（不增加计数）
     │                   │
     │                   └── shared_ptr 析构：计数 -1
     │                       │
     │                       ▼
     │                   rc == 0 ? 析构对象 : 继续持有
     │                       │
     ▼                       ▼
控制块（独立分配）        控制块引用计数 == 0 ? 释放控制块
</pre>

### RAII 的控制流等价

```cpp
{
    std::lock_guard<std::mutex> lk(mtx);
    // 锁在作用域终点自动释放
} // 析构函数调用

{
    auto file = std::fstream("data.txt");
    // 文件在作用域终点自动关闭
} // RAII 确保析构
```

RAII 等价于**有限状态自动机**：对象构造进入"已获取"状态，析构无论通过何种路径（正常返回、异常、longjmp）都进入"已释放"状态。

## 机制

### unique_ptr 的零开销原理

unique_ptr 仅包含一个裸指针（通常 8 字节），不包含任何簿记信息。移动构造时，指针所有权的转移是**编译期确定的**，无需运行时代码：

$\text{sizeof}(\text{unique\_ptr}<T>) = \text{sizeof}(T*) = 8\ (\text{64-bit})$

这与 shared_ptr 对比：

$\text{sizeof}(\text{shared\_ptr}<T>) = 2 \times \text{sizeof}(T*) + \text{sizeof}(\text{control\_block})$

控制块包含引用计数、弱计数、deleter、allocator，通常 16-32 字节。

### shared_ptr 的线程安全性

引用计数的增减是**原子的**（`std::atomic_increment`），保证线程安全。但**对象本身的访问**需要外部同步——shared_ptr 保证引用计数安全，但多个线程同时读写对象仍需锁。

```cpp
// 线程安全：引用计数操作是原子的
std::shared_ptr<T> p1 = p2;  // 原子：计数 +1
p1.reset();                   // 原子：计数 -1，可能触发析构

// 线程不安全：需要外部同步
p1->do_something();  // 多个线程同时调用未定义行为
```

### weak_ptr 打破循环的机制

```cpp
class Node {
public:
    std::string name;
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;  // 弱引用，不增加计数
};
```

当最后一个 shared_ptr 离开作用域，计数归零，Node 被析构。prev 是 weak_ptr，它不阻止析构，因此循环被打破：

$\text{prev.lock()} \Rightarrow \text{nullptr} \iff \text{对象已析构}$

### 自定义分配器与 arena 分配

**arena（内存池）分配器**预先分配一大块内存，按需切割：

$M_{arena} = \{m_0, m_1, m_2, \dots, m_{n-1}\},\quad \sum |m_i| \leq \text{预分配总量}$

优点：消除频繁 `new/delete` 的系统调用开销；缺点：内存碎片（已释放块无法重用于大于它的请求）。

**buddy 系统分配器**：将内存按 $2^k$ 大小分割，分配时找到最小的 $2^k$ 满足请求。合并时，只有大小相等且地址相邻的块才能合并（buddy 关系）。

### 内存泄漏的场景

**泄漏的数学定义**：分配的有效内存地址集合 $A$ ，释放的地址集合 $F$ ，泄漏量 $|A \setminus F|$ 。

常见泄漏模式：
1. **异常安全缺失**：构造函数抛出异常时，RAII 栈展开会调用已构造对象的析构，但动态分配的资源可能未捕获
2. **循环引用未打破**：两个 shared_ptr 互相引用
3. **容器持有原始指针**：`std::vector<T*> v; v.push_back(new T);` 容器析构不释放 T*
4. **`new` 数组缺少 `delete[]`**：内存泄漏 + 可能调用错误析构函数

## 参考存根

```cpp
// 自定义分配器示例（简化）
template<typename T>
struct ArenaAllocator {
    static constexpr size_t BLOCK_SIZE = 4096;
    char* pool = nullptr;
    size_t offset = 0;

    T* allocate(size_t n) {
        size_t bytes = n * sizeof(T);
        if (offset + bytes > BLOCK_SIZE) throw std::bad_alloc();
        T* p = reinterpret_cast<T*>(pool + offset);
        offset += bytes;
        return p;
    }

    void deallocate(T*, size_t) {}  // arena 不释放，程序结束时一并归还
};

// unique_ptr 用于工厂模式的资源管理
std::unique_ptr<Base> create() {
    std::unique_ptr<Derived> p = std::make_unique<Derived>();
    return p;  // 移动语义，零拷贝转移所有权
}
```
