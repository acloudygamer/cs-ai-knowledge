# 内存管理

> **版本关系**：C++11（智能指针）→ C++17（make_unique）→ C++20

**内存管理是用所有权契约替代手动释放的艺术，RAII 将资源生命周期绑定到对象析构函数。**

## 定义

| 概念 | 一句话断言 |
|------|-----------|
| 堆 | 手动申请手动释放的动态内存 |
| 栈 | 函数作用域结束时自动回收的线性内存 |
| RAII | 资源获取即初始化，析构函数自动释放 |
| unique_ptr | 独占所有权的智能指针 |
| shared_ptr | 引用计数共享所有权的智能指针 |
| weak_ptr | shared_ptr 的观察者，不增加引用计数 |

## 数据流

<pre>
栈对象                    堆对象
   │                         │
   ├─ 函数入口构造            ├─ new 申请
   │                         │
   ├─ 函数出口自动析构        ├─ 指针传递（复制/移动）
   │                         │    │
   └─ 无需干预               ├─ unique_ptr 独占转移
                             │    │
                             ├─ shared_ptr 引用计数++
                             │    │
                             ├─ 最后 shared_ptr 析构
                             │    │
                             └─ delete 释放
</pre>

## 机制

**RAII 为什么安全**：构造时获取资源，析构时释放。无论函数如何退出（正常返回、异常、goto），析构函数都会被调用，C++ 保证栈展开时调用所有局部对象的析构函数。

**unique_ptr 为什么高效**：独占所有权意味着只有一个 owner，无需引用计数开销。移动语义让所有权转移零拷贝，编译期确定释放路径，无运行时间接访问。

**shared_ptr 为什么需要引用计数**：允许多个 owner 共享所有权，需要在最后一个 owner 销毁时释放内存。控制块独立于对象，引用计数原子操作保证线程安全。

**weak_ptr 解决什么问题**：循环引用（ A→shared_ptr→B→shared_ptr→A）导致引用计数永远不为零。weak_ptr 不增加计数，观察 shared_ptr 是否仍存活。

## 参考存根

```cpp
auto up = std::make_unique<int>(42);
auto sp = std::make_shared<int>(100);
std::weak_ptr<int> wp = sp;
if (auto locked = wp.lock()) { }
```
