# 并发与异步

> **版本关系**：C++20（基础）→ C++23 → C++26（std::execution）

C++11 开始提供完善的并发支持，C++20 和 C++23 继续增强。本章深入讲解现代 C++ 的并发编程，包括线程管理、内存模型、同步原语、并发设计模式和异步编程。

## std::jthread：自动管理的线程（C++20）

`std::jthread` 是 C++20 引入的智能线程，会在析构时自动 join，避免忘记调用 `join()` 导致的悬挂线程。`std::jthread` 支持协作式停止，通过 `std::stop_token` 实现。

### 参考样例

```cpp
#include <thread>
#include <iostream>
#include <chrono>
#include <vector>

void worker(int id) {
    std::cout << "Worker " << id << " running\n";
}

int main() {
    // 普通 thread：需要手动 join
    std::thread t1(worker, 1);
    t1.join();

    // jthread：自动 join
    std::jthread t2(worker, 2);

    // 协作式停止
    auto infinite_loop = [](std::stop_token token, int id) {
        int count = 0;
        while (!token.stop_requested()) {
            std::cout << "Task " << id << " running\n";
            std::this_thread::sleep_for(std::chrono::milliseconds(100));
        }
    };

    std::vector<std::jthread> workers;
    for (int i = 0; i < 4; ++i) {
        workers.emplace_back(infinite_loop, i);
    }

    std::this_thread::sleep_for(std::chrono::seconds(2));
    // workers 析构时会自动调用 request_stop() 并 join
}
```

## 内存顺序与原子操作

C++ 的内存模型定义了六种内存顺序，控制多线程间的可见性和排序：

| 内存顺序 | 说明 | 使用场景 |
|----------|------|----------|
| `std::memory_order_seq_cst` | 顺序一致（默认） | 严格要求顺序 |
| `std::memory_order_acquire` | 获取 | 读操作，后续读写不能重排 |
| `std::memory_order_release` | 释放 | 写操作，之前读写不能重排 |
| `std::memory_order_acq_rel` | 获取-释放 | 读-改-写操作 |
| `std::memory_order_relaxed` | 松弛 | 仅保证原子性，无顺序保证 |
| `std::memory_order_consume` | 消费（已废弃） | 数据依赖的读 |

顺序一致（seq_cst）所有线程看到相同的操作顺序。获取-释放（acquire-release）通过 release 之前的写入对 acquire 之后的读取可见。松弛（relaxed）仅保证原子性，不保证顺序。

### 参考样例

```cpp
#include <atomic>
#include <thread>

// 顺序一致
std::atomic<int> x(0), y(0);
void seq_cst_writer() {
    x.store(1, std::memory_order_seq_cst);
    y.store(1, std::memory_order_seq_cst);
}

// 获取-释放（生产者-消费者）
std::atomic<int*> ptr(nullptr);
std::atomic<int> data(0);

void producer() {
    int local_data = 42;
    data.store(local_data, std::memory_order_relaxed);
    ptr.store(new int(local_data), std::memory_order_release);
}

void consumer() {
    int* expected_ptr = nullptr;
    while (!ptr.compare_exchange_strong(expected_ptr, nullptr,
                                       std::memory_order_acquire,
                                       std::memory_order_relaxed)) {
        expected_ptr = nullptr;
    }
    // 此时 ptr 指向非空，data 也已经被写入
}

// 松弛操作（计数器）
std::atomic<int> counter(0);
void increment() {
    counter.fetch_add(1, std::memory_order_relaxed);
}
```

## std::atomic 深入

### atomic_flag 与 atomic_wait

`atomic_flag` 是最简单的锁实现。`atomic_wait`/`atomic_notify`（C++20）提供阻塞等待机制。

### 参考样例

```cpp
#include <atomic>
#include <thread>

// 自旋锁
class SpinLock {
    std::atomic_flag flag = ATOMIC_FLAG_INIT;
public:
    void lock() {
        while (flag.test_and_set(std::memory_order_acquire)) {
            std::this_thread::yield();
        }
    }
    void unlock() {
        flag.clear(std::memory_order_release);
    }
};

// atomic_wait / notify（C++20）
std::atomic<int> counter(0);

void waiter() {
    counter.wait(0);  // 阻塞直到 counter != 0
}

void notifier() {
    counter.store(42);
    counter.notify_one();  // 唤醒一个等待者
}
```

## std::latch 与 std::barrier（C++20）

`std::latch` 是一次性屏障，计数只能减不能增。`std::barrier` 是可重置的屏障，可以重复使用。C++23 将 `arrive()` 声明为 `noexcept`。

### 参考样例

```cpp
#include <latch>
#include <barrier>
#include <thread>
#include <vector>

// std::latch 示例
std::latch start_latch(3);
std::vector<std::thread> workers;

for (size_t i = 0; i < 3; ++i) {
    workers.emplace_back([&, id = i]() {
        // 准备工作
        start_latch.count_down();  // 计数减一
    });
}
start_latch.wait();  // 等待所有 worker 就绪

// std::barrier 示例
std::barrier phase_barrier(3);
for (size_t i = 0; i < 3; ++i) {
    workers.emplace_back([&, id = i]() {
        for (size_t phase = 0; phase < 3; ++phase) {
            // 做工作
            phase_barrier.arrive_and_wait();  // 等待其他 worker
        }
    });
}
```

## 线程局部存储

`thread_local` 关键字为每个线程提供独立的变量副本。

### 参考样例

```cpp
#include <thread>
#include <vector>

thread_local int thread_id = 0;
thread_local std::vector<int> local_data;

void worker(int id) {
    thread_id = id;
    local_data.push_back(id * 10);
}

// 每个线程有独立的随机数生成器
thread_local std::mt19937 rng(std::hash<std::thread::id>{}(std::this_thread::get_id()));
```

## 同步原语与死锁避免

### 死锁的四个必要条件

1. **互斥**：资源一次只能被一个线程持有
2. **持有并等待**：线程持有资源同时等待其他资源
3. **非抢占**：资源不能被强制夺走
4. **循环等待**：形成线程间的循环等待链

### 避免死锁的策略

固定加锁顺序、使用 `std::lock` 同时锁定多个互斥量、使用 `std::scoped_lock`（C++17）自动处理顺序。

### 参考样例

```cpp
#include <mutex>

// 固定加锁顺序
class FixedOrderLock {
    std::mutex mutex_a_;
    std::mutex mutex_b_;
public:
    void operation_ab() {
        std::lock_guard lock_a(mutex_a_);
        std::lock_guard lock_b(mutex_b_);  // 始终先 a 后 b
    }
};

// std::lock 避免死锁
class MultiLock {
    std::mutex mutex_a_;
    std::mutex mutex_b_;
public:
    void operation_ab() {
        std::lock(mutex_a_, mutex_b_);
        std::lock_guard lock_a(mutex_a_, std::adopt_lock);
        std::lock_guard lock_b(mutex_b_, std::adopt_lock);
    }
};

// std::scoped_lock（C++17）
class ScopedLockExample {
    std::mutex mutex_a_;
    std::mutex mutex_b_;
public:
    void operation() {
        std::scoped_lock lock(mutex_a_, mutex_b_);  // 自动推导顺序
    }
};
```

## std::async 与 std::future

`std::async` 启动异步任务，`std::future` 获取结果。`std::launch::async` 立即在新线程执行，`std::launch::deferred` 延迟到调用 `get` 或 `wait` 时执行。`std::shared_future` 可以复制，多个线程可等待同一结果。

### 参考样例

```cpp
#include <future>
#include <iostream>
#include <chrono>

int compute(int x) {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    return x * x;
}

int main() {
    // 启动异步任务
    std::future<int> fut_async = std::async(std::launch::async, compute, 10);
    std::future<int> fut_deferred = std::async(std::launch::deferred, compute, 20);

    std::cout << "Main continues\n";
    std::cout << "Async result: " << fut_async.get() << "\n";
    std::cout << "Deferred result: " << fut_deferred.get() << "\n";
}
```

## 条件变量深入

条件变量用于线程间同步，需防范虚假唤醒。使用带谓词的 `wait` 必须满足条件才返回。

### 参考样例

```cpp
#include <condition_variable>
#include <mutex>
#include <queue>

template<typename T>
class ThreadSafeQueue {
    std::queue<T> queue_;
    mutable std::mutex mutex_;
    std::condition_variable cv_;
public:
    void push(T value) {
        {
            std::lock_guard lock(mutex_);
            queue_.push(std::move(value));
        }
        cv_.notify_one();
    }

    bool pop(T& value) {
        std::unique_lock lock(mutex_);
        cv_.wait(lock, [this] { return !queue_.empty(); });
        value = std::move(queue_.front());
        queue_.pop();
        return true;
    }

    bool pop_with_timeout(T& value, std::chrono::milliseconds timeout) {
        std::unique_lock lock(mutex_);
        if (!cv_.wait_for(lock, timeout, [this] { return !queue_.empty(); })) {
            return false;  // 超时
        }
        value = std::move(queue_.front());
        queue_.pop();
        return true;
    }
};
```

## 常见并发问题

### 数据竞争

多个线程同时访问共享数据，至少一个线程写操作。解决：使用原子操作或锁保护。

### 竞态条件

检查然后操作不是原子操作。解决：使用内存顺序或原子操作。

### 参考样例

```cpp
#include <atomic>
#include <mutex>

// 数据竞争：错误
int counter = 0;
void bad_increment() {
    for (int i = 0; i < 10000; ++i) {
        ++counter;  // 数据竞争！
    }
}

// 正确：使用原子操作
std::atomic<int> safe_counter(0);
void good_increment() {
    for (int i = 0; i < 10000; ++i) {
        safe_counter.fetch_add(1);
    }
}

// 竞态条件：错误
bool flag = false;
int data = 0;
void writer() {
    data = 42;
    flag = true;  // 可能被编译器优化重排
}

// 正确：使用内存顺序
std::atomic<bool> safe_flag(false);
std::atomic<int> safe_data(0);
void safe_writer() {
    safe_data.store(42, std::memory_order_relaxed);
    safe_flag.store(true, std::memory_order_release);  // 屏障
}
void safe_reader() {
    while (!safe_flag.load(std::memory_order_acquire)) {}
    // 此时 safe_data 一定已经被写入
}
```

## std::execution（C++26）

> **机制演进说明**
> - **`std::future` 机制**：基于线程池或系统调度器，但 when_all 等功能需第三方库实现
> - **`std::execution` 变革**：提供标准的发送方-接收方接口，统一所有异步和并行编程场景

C++26 引入了 `std::execution` 库，提供发送方-接收方模型。发送方（Sender）产生值或错误，接收方（Receiver）消费值或处理错误，调度器（Scheduler）决定任务在哪里执行。

详见 [C++26 新特性](./15-C++26新特性.md)。
