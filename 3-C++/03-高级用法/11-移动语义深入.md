# 移动语义深入

> **版本关系**：C++11（基础）→ C++17（guaranteed copy elision）→ C++20（移动语义与三路比较）→ C++23（move_only_function）

**移动语义通过"窃取"临时对象资源（指针、文件句柄、锁）替代深拷贝，将拷贝操作的 O(n) 数据复制降为 O(1) 指针交换，是 C++ 性能优化的核心工具。其本质是资源所有权的转移。**

## 定义

| 概念 | 本质操作 | 约束边界 |
|------|----------|----------|
| 左值（lvalue） | 有持久身份（地址），可以取地址 | 可以出现在赋值左侧 |
| 右值（rvalue） | 即将销毁的临时对象，无持久地址 | 不能取地址（纯右值） |
| 将亡值（xvalue） | 通过 std::move 转换的左值，资源即将被移动 | 仍可取地址，但语义上"即将死亡" |
| 移动构造函数 | 窃取源对象资源的构造函数 | 源对象必须处于可析构状态 |
| 完美转发 | 保持参数原始值类别的转发 | 依赖引用折叠规则 |
| guaranteed copy elision | 某些场景下强制省略拷贝（C++17起） | 仅适用于满足特定条件的临时对象 |

移动语义的核心洞察：**很多资源的所有权可以转移而非复制**。堆内存（vector、string）、文件句柄、锁等资源，"移动"比"拷贝"便宜得多。

## 数学模型

### 左值/右值分类的形式化

C++ 值类别（Value Categories）是正交的两个维度：**是否拥有身份（identity）** 和 **是否可被移动**。

$$
\text{Value} = \text{GLValue} \mid \text{RValue}
$$

$$
\text{GLValue} = \text{LValue} \mid \text{XValue}
$$

$$
\text{RValue} = \text{PRValue} \mid \text{XValue}
$$

- **LValue**：有身份，不可移动（持久存在）
- **PRValue**：无身份，纯右值（临时对象）
- **XValue**：有身份，可移动（将亡值）

### 移动操作的复杂度

设元素类型 T 的移动构造函数复杂度为 $O(1)$，拷贝构造为 $O(n)$ （ $n$ 为元素大小）： ，拷贝构造为 $O(n)$ （ $n$ 为元素大小）： （ $n$ 为元素大小）： 为元素大小）：

$$
T_{\text{copy}}(n) = O(n) \quad T_{\text{move}} = O(1)
$$

对于容器类型（如 vector<T>）：

$$
T_{\text{copy-vector}}(n) = n \cdot T_{\text{copy-element}} = O(n^2)
$$

$$
T_{\text{move-vector}}(n) = n \cdot T_{\text{move-element}} = O(n)
$$

差距在 $n$ 倍。 倍。

### 引用折叠规则

转发引用 `T&&` 的折叠规则（RFC 2462）：

$$
(T\& \&) \Rightarrow T\& \quad (T\& \&) \Rightarrow T\& \quad (T\&\& \&) \Rightarrow T\& \quad (T\&\&\&) \Rightarrow T\&\&
$$

结合 `std::forward<T>`：

`forward<T>(arg)` 的语义：若 $T$ 是左值引用则为 `static_cast<T&>(arg)`，若 $T$ 是右值引用则为 `static_cast<T&&>(arg)`。

这保证了左值转发为左值引用，右值转发为右值引用。

## 数据流

<pre>
左值 (lvalue)            右值 (rvalue)            将亡值 (xvalue)
   │                         │                        │
   ├─ 有名称              ├─ 临时对象               ├─ std::move(lvalue)
   │   `int x = 5;`         │   `func()` 返回值        │   `std::move(x)`
   │                         │                        │
   ├─ 可取地址             ├─ 即将销毁               ├─ 仍可取地址
   │   `&x` 合法             │   作用域结束时析构        │   但语义上"即将死亡"
   │                         │                        │
   └─ 类型：LValue         └─ 类型：PRValue           └─ 类型：XValue

移动构造的数据流：
源对象 S                    目标对象 T                转移后
   │                           │                       │
   ├─ [ptr = new T[n]]      ├─ [空]                  ├─ [接管 ptr]
   │   [size = n]            │   [空]                 │   [size = n]
   │   [capacity = n]        │   [capacity = 0]        │   [capacity = n]
   │                         │                        │
   └─ 析构函数：             └─ 移动构造：             └─ S 的析构：
     不 delete（已转移）       接管资源                 无操作（空指针）
</pre>

**所有权流转**：
1. `std::move(s)` 返回 `s` 的右值引用（不移动任何东西）
2. 编译器选择移动构造函数（而非拷贝构造函数）
3. 移动构造函数**窃取**源对象的资源（指针、句柄等）
4. 源对象被析构时，其持有的指针已被置空，不会 delete 已转移的资源

## 机制

### std::move 为什么不移动任何东西

`std::move` 的实现：

```cpp
template<typename T>
constexpr std::remove_reference_t<T>&& move(T&& arg) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(arg);
}
```

它只是 `static_cast<T&&>(arg)`，将任意值类别转为右值引用。**真正的移动发生在移动构造函数/赋值运算符中**。如果没有自定义移动操作，编译器会退化到拷贝。

**数学本质**：`move` 是恒等函数在右值引用空间上的提升：

$$
\text{move} : \forall T. T \rightarrow T\&\&
$$

它不改变值的语义，只改变类型的名义分类，从而影响重载决议。

### 移动操作的 noexcept 约束

容器（如 `std::vector`）在 reallocate 时会移动元素。**强异常安全**要求：如果移动操作抛出异常，数据必须保持原状。

```cpp
// vector::reallocate 伪代码
void reallocate() {
    new_capacity = ...;
    T* new_data = allocator.allocate(new_capacity);
    for (size_t i = 0; i < size_; ++i) {
        new (new_data + i) T(std::move_if_noexcept(data_[i]));
        // 若移动失败（抛异常），使用拷贝
    }
    deallocate(data_);
}
```

`std::move_if_noexcept`：如果移动构造函数是 noexcept，用移动；否则退化到拷贝。

**约束**：如果移动操作可能抛异常且没有拷贝后备，vector reallocate 时抛出异常后数据可能损坏。

### Guaranteed Copy Elision（C++17）

C++17 强制省略以下情况的拷贝：

```cpp
T func() { return T{}; }  // 不拷贝也不移动，直接构造
T x = func();              // 在 x 的存储中直接构造
```

这称为 **Return Value Optimization (RVO)** 的强制版本。即使 T 有拷贝构造函数，编译器也必须直接在前述位置构造对象。

**约束**：仅适用于"返回临时对象"的场景，且要求返回类型与函数返回类型完全匹配。

### 移动语义与三路比较（spaceship operator）

C++20 引入 `<=>` 运算符，与移动语义交互：

```cpp
class Widget {
    int* data_;
public:
    auto operator<=>(const Widget&) const = default;  // 默认三路比较
};
```

编译器生成的 `<=>` 会正确处理资源的移动和比较。

### move_only_function（C++23）

> **latest 预览**：本节使用 C++23 特性（`std::move_only_function`），stable（C++20）等价用 `std::function`，但语义有差异（`std::function` 要求可拷贝，不贴合只移 callable）。

`std::function` 要求类型可拷贝构造。`std::move_only_function`（C++23）只要求可移动构造，允许不可拷贝的可调用对象：

```cpp
// C++20 等价：std::function（要求 callable 可拷贝）
std::function<int()> f = []{ return 42; };  // OK：普通 lambda 可拷贝
// 注：若 callable 只可移动（如持有 unique_ptr 的 lambda），C++20 的 std::function 无法包装；
//     C++23 的 std::move_only_function 才支持只移 callable，语义更贴合资源所有权。
```

## 违反约束的后果

| 违反场景 | 系统行为 | 后果严重程度 |
|----------|----------|--------------|
| 对 const 对象调用移动构造函数 | 退化到拷贝 | 性能未优化，可能非预期 |
| 移动构造函数抛异常且无拷贝后备 | 数据损坏或终止 | 严重：可能导致数据丢失 |
| 对 stack-only 类型（如 unique_ptr) 使用拷贝 | 编译错误 | 代码无法编译 |
| 移动后继续使用源对象 | 悬垂访问 | 未定义行为，可能崩溃 |
| 对数组类型使用移动语义（而非移动元素） | 编译错误或部分移动 | 取决于具体实现 |
| 在 noexcept(false) 的移动操作中 reallocate | 拷贝而非移动 | 性能退化 |
| 移动赋值给自己 | 自赋值检查失效 | 数据被意外修改或崩溃 |

## 对比参照

| 属性 | 拷贝语义 | 移动语义 |
|------|----------|----------|
| 操作类型 | 深拷贝（逐元素复制） | 资源窃取（指针交换） |
| 时间复杂度 | O(n)（复制所有数据） | O(1)（仅交换指针） |
| 源对象状态 | 保持不变 | 进入"可析构"状态（指针置空） |
| 适用场景 | 需要原始副本 | 临时对象、工厂返回值 |
| 异常安全性 | 拷贝通常安全 | 移动可能抛异常，需 noexcept 保证 |

## 参考存根

```cpp
#include <utility>
#include <vector>
#include <memory>

class Resource {
    int* data_;
public:
    Resource(size_t n) : data_(new int[n]) {}
    ~Resource() { delete[] data_; }

    // 移动构造函数
    Resource(Resource&& other) noexcept : data_(other.data_) {
        other.data_ = nullptr;  // 窃取资源，置空源对象
    }

    // 移动赋值
    Resource& operator=(Resource&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            other.data_ = nullptr;
        }
        return *this;
    }

    // 禁用拷贝
    Resource(const Resource&) = delete;
    Resource& operator=(const Resource&) = delete;
};

// 完美转发
template<typename T>
void wrapper(T&& arg) {
    process(std::forward<T>(arg));  // 保持原始值类别
}
```

---

> **洞察**：移动语义可归约为 **资源所有权的指针交换**，移动构造函数是资源的盗窃者而非复制者。移动操作的 O(1) 复杂度来源于只交换指针，不进行数据复制。
