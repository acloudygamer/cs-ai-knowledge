# 链接与 ABI 基础

> **版本关系**：C++98（基础）→ C++11（extern template）→ C++17（inline 变量）→ C++20（模块）

**链接是将多个编译单元合并为可执行文件的过程，ABI 定义了二进制接口的约定。**

## 定义

| 概念 | 一句话断言 |
|------|-----------|
| 翻译单元 | 预处理后的单个 .cpp 文件 |
| 外部链接 | 可被其他翻译单元访问 |
| 内部链接 | 仅当前翻译单元可见 |
| 名字修饰 | 编译器对重载函数名进行编码 |
| ABI | 应用程序二进制接口，约定调用约定、对齐、符号可见性 |

## 数据流

<pre>
编译              链接              加载
   │                │                │
   ├─ .cpp ────→ ├─ .o 文件        │
   │   (预处理)    │   (符号表)      │
   │              │                 │
   ├─ #include ──→ │   (未定义引用)  │
   │   (文本替换)  │                 │
   │              ├─ 解析符号        │
   │              │   (强/弱符号)    │
   │              │                 │
   │              ├─ 合并节          │
   │              │   (text/data)   │
   │              │                 │
   │              └─ 重定位 ───────→ ├─ 可执行文件
                                               │
                                               └─ 动态链接（.so/.dll）
</pre>

## 机制

**为什么需要 extern "C"**：C++ 支持函数重载，编译器通过名字修饰（mangling）区分不同签名的同名函数。`extern "C"` 告诉编译器使用 C 的符号命名规则，不进行修饰，从而实现 C++ 调用 C 函数或被 C 调用。

**强符号与弱符号规则**：初始化全局变量和函数定义是强符号，未初始化全局变量是弱符号。链接时两个强符号冲突报错（ODR 违反），一个强符号加多个弱符号选择强符号。

**为什么 inline 变量需要 C++17**：C++11/14 中 inline 只用于函数，头文件定义变量会导致每个 TU 都有定义，违反 ODR。C++17 inline 变量允许头文件定义，全局唯一实例由链接器保证。

**LTO 的原理**：LTO（链接时优化）在链接阶段将目标文件中的中间表示合并，让编译器可以跨翻译单元进行内联、死代码消除等优化，生成更高效的可执行文件。
