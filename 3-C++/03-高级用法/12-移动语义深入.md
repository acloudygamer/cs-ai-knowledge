# 移动语义深入

> **版本关系**：C++11（基础）→ C++17（ guaranteed copy elision）→ C++20（移动语义与三路比较）→ C++23（move_only_function）

**移动语义通过"窃取"临时对象资源替代深拷贝，是 C++ 性能优化的核心工具。**

## 定义

| 概念 | 一句话断言 |
|------|-----------|
| 左值 | 有名称、可取地址的表达式 |
| 右值 | 即将销毁的临时对象 |
| 将亡值 | 通过 std::move 转换的左值（即将被移动） |
| 纯右值 | 字面量、临时对象、lambda |
| 移动构造函数 | 窃取源对象资源的构造函数 |
| 完美转发 | 保持参数原始值类别的转发 |

## 数据流

<pre>
左值                    右值                    将亡值
   │                      │                       │
   ├─ 有名称            ├─ 临时对象              ├─ std::move(x)
   │                      │                       │
   ├─ 可取地址          ├─ 即将销毁              ├─ 仍可取地址
   │                      │                       │
   └─ &x                └─ &&rref              └─ &&rref
</pre>

## 机制

**为什么移动语义快**：拷贝构造函数需要分配内存并复制数据（O(n)）。移动构造函数只复制指针（所有权转移），源对象置空，复杂度 O(1)。对于大 vector、string 等容器差异巨大。

**std::move 不移动任何东西**：它只是一个 `static_cast<T&&>(arg)`，将左值转为右值引用。真正的移动发生在移动构造函数/赋值运算符中。如果没有自定义移动操作，编译器会退化到拷贝。

**完美转发的原理**：模板参数 `T&&` 不是右值引用，而是"转发引用"——它绑定到任何值类别。`std::forward<T>(arg)` 根据 T 是否为引用类型决定转换为左值引用还是右值引用，保持原始参数的值类别。

**为什么移动操作要 noexcept**：容器（如 `std::vector`）在重新分配时会移动元素。如果移动操作可能抛异常，容器为保证强异常安全会选择拷贝（效率低）。标记 noexcept 让容器放心使用移动操作。

    Resource(Resource&&) noexcept;
    Resource& operator=(Resource&&) noexcept;
};
