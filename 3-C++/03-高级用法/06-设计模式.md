# 设计模式

> **版本关系**：C++98（基础）→ C++11（智能指针、lambda）→ C++20（概念）→ C++23/26

## 定义

**设计模式是针对特定问题结构的抽象解法，是对软件设计中**反复出现的问题**的**可复用方案**。模式本身是**关系**而非代码，是**约束**而非实现。

**核心洞察**：设计模式的价值不在于模式本身，而在于**模式选择**——知道何时用、何时不用，以及多个模式如何组合。

## 数学模型

### 模式的图论表示

令 $G = (V, E)$ 为对象关系图，$V$ 是对象集合，$E$ 是对象间关系。模式是 $G$ 的**子结构**：

| 模式 | 子结构特征 |
|------|-----------|
| 装饰器 | $E$ 动态增长，接口不变 |
| 策略 | $E$ 在运行时替换 |
| 观察者 | $E$ 描述发布-订阅 |
| 工厂 | 对象创建与使用的解耦 |

### 开闭原则的量化

**开闭原则（OCP）**：软件实体应对扩展开放，对修改关闭。

设 $C$ 为实体集合，$M$ 为修改操作集合，$E$ 为扩展操作集合：

$$\text{OCP 满足} \iff \forall m \in M, \forall c \in C: m(c) \text{ 不改变 } c \text{ 的行为}$$

$$\exists e \in E: \forall c \in C: e(c) \text{ 增加新行为}$$

装饰器模式是 OCP 的直接实现：扩展行为而不修改原有类。

## 数据流

<pre>

    │
    ├─ Adapter ──► 接口转换（不改变接口语义）
    │
    ├─ Decorator ──► 动态添加职责

### 装饰器的链式结构

```
Component (接口)
    │
    ├─ ConcreteComponent
    │
    └─ Decorator
        │
        └─ ConcreteDecoratorA
            │
            └─ ConcreteDecoratorB  ← 可叠加多个装饰器
```

每个装饰器持有对 Component 的引用，可以在调用前/后添加行为。

## 机制

### 单例与双重检查锁定

**为什么要双重检查**（DCLP）：

```cpp
Singleton& get_instance() {
    if (instance == nullptr) {          // 第一次检查：无锁快速路径
        std::lock_guard<std::mutex> lk(mtx);
        if (instance == nullptr) {     // 第二次检查：持有锁后确认
            instance = new Singleton();
        }
    }
    return *instance;
}
```

**问题分析**：若没有第二次检查，多线程可能：
1. 线程 A 进入临界区，创建实例
2. 线程 B 在外层检查 `instance == nullptr`，认为已创建
3. 但 A 的 `new` 尚未完成（指令重排），B 看到**未构造的对象**

**memory_order_acq_rel 的作用**：

```cpp
std::atomic<Singleton*> instance;
Singleton* tmp = new Singleton();  // 1. 分配内存
instance.store(tmp, std::memory_order_release);  // 2. 发布
```

`release` 确保构造函数在 store 之前完成所有内存写入，后续 `acquire` 读取观察到完整的已构造对象。

### 装饰器 vs 继承

**继承（静态组合）**：

```cpp
class CoffeeWithMilk : public Coffee { };
class CoffeeWithSugar : public Coffee { };
// 3 种基础 × 5 种配料 = 15 个子类
```

**装饰器（动态组合）**：

```cpp
auto c = std::make_unique<MilkDecorator>(
    std::make_unique<SugarDecorator>(
        std::make_unique<BasicCoffee>()
    )
);
// 运行时组装，无类爆炸
```

装饰器的约束：
- 装饰器和被装饰对象必须**共享同一接口**（里氏替换）
- 装饰器可以嵌套，但**顺序敏感**（`Milk(Sugar(coffee))` ≠ `Sugar(Milk(coffee))`）

### 策略模式与 Lambda

**传统策略模式**：

```cpp
class SortStrategy {
public:
    virtual ~SortStrategy() = default;
    virtual void sort(std::vector<int>&) = 0;
};

class QuickSort : public SortStrategy { ... };
class MergeSort : public SortStrategy { ... };
```

**Lambda 简化**：

```cpp
std::vector<int> data;
std::sort(data.begin(), data.end(), [](int a, int b) { return a < b; });
// std::function 统一类型
std::function<bool(int, int)> strat = [](int a, int b) { return a < b; };
```

**何时用类 vs Lambda**：
- 算法复杂、需要状态 → 类
- 简单回调、无状态 → Lambda

### 观察者与 weak_ptr

**悬挂问题**：若 Observer 析构后 Subject 仍持有其引用，通知时访问已释放对象。

```cpp
class Subject {
    std::vector<std::weak_ptr<Observer>> observers_;  // weak_ptr
    void notify() {
        for (auto it = observers_.begin(); it != observers_.end(); ) {
            if (auto obs = it->lock()) {  // 检查是否有效
                obs->update();
                ++it;
            } else {
                it = observers_.erase(it);  // 清理无效的 weak_ptr
            }
        }
    }
};
```

**手动 detach 的问题**：容易遗漏，尤其是在异常路径上。`weak_ptr` 的自动失效提供安全网。

### 现代 C++ 对模式的影响

| 模式 | C++98 实现 | 现代 C++ 实现 |
|------|------------|--------------|
| 单例 | DCLP + mutex | `static` 局部变量（线程安全初始化） |
| 策略 | 类继承 | Lambda + `std::function` |
| 命令 | 类层次 | Lambda + `std::bind` |
| 装饰器 | 继承层次 | `std::variant` + 访问器 |
| 工厂 | `new` + 指针 | `std::unique_ptr` + `make_unique` |

## 参考存根

```cpp
// 现代单例（C++11 保证线程安全）
class Singleton {
public:
    static Singleton& instance() {
        static Singleton inst;  // 初始化完全线程安全（MSVC2015+ 保证）
        return inst;
    }

private:
    Singleton() = default;
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
};

// 装饰器模式的现代实现
#include <variant>
#include <memory>

struct Base { virtual ~Base() = default; };
struct Decorator : Base {
    std::unique_ptr<Base> inner;
    Decorator(std::unique_ptr<Base> p) : inner(std::move(p)) {}
};

using UPtr = std::unique_ptr<Base>;
UPtr make_decorated(UPtr base) {
    return std::make_unique<Decorator>(std::move(base));
}

// 观察者模式
#include <memory>
#include <vector>

class Subject {
    std::vector<std::weak_ptr<class Observer>> obs_;
public:
    void add_observer(std::weak_ptr<class Observer> o) { obs_.push_back(o); }
    void notify() {
        for (auto& w : obs_)
            if (auto o = w.lock()) o->on_update();
    }
};
```
