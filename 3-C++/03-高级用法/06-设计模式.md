# 设计模式

> **版本关系**：C++98（基础）→ C++11（智能指针、lambda）→ C++20（概念）→ C++23/26

**设计模式是针对特定问题结构的抽象解法，模式本身是稳定的，但实现随语言特性演进。**

## 定义

| 模式类型 | 核心意图 |
|---------|---------|
| 创建型 | 解耦对象创建与使用 |
| 结构型 | 组合对象形成新功能 |
| 行为型 | 封装行为变化点 |

## 数据流

<pre>
创建型： Product ←─── Factory ──── Builder
                │         │
                └─── Singleton（全局唯一实例）

结构型： Component ─┬─ Adapter（接口转换）
                    ├─ Decorator（动态添加职责）
                    └─ Proxy（访问控制）

行为型： Subject ─── Observer（一对多通知）
        Context ─── Strategy（算法替换）
        Command ─── execute/undo
</pre>

## 机制

**为什么单例需要双重检查锁定**：直接加锁每次访问都竞争锁，性能差。DCLP 先用轻量级检查（acquire barrier）跳过加锁，只有在实例为空时才加锁创建。关键是用 `memory_order_acquire` 确保指令重排不导致其他线程看到半构造对象。

**为什么装饰器优于继承**：继承在编译时静态添加职责，装饰器在运行时动态组合。装饰器遵循开闭原则（对扩展开放，对修改关闭），但继承可能导致类爆炸（3种咖啡 × 5种配料 = 15个子类）。

**为什么策略模式用 lambda 更简洁**：策略接口需要抽象类、派生类、工厂函数。lambda 直接捕获上下文，省去类定义和继承层级，`std::function<>` 统一类型。

**为什么观察者用 weak_ptr**：Subject 持有 `weak_ptr<Observer>` 而不是 `shared_ptr`，避免Observer 析构后 Subject 仍持有悬挂引用。手动 detach 也容易遗漏。

## 参考存根

```cpp
auto Singleton::get_instance() -> Singleton& {
    static Singleton inst;
    return inst;
}
```

现代 C++ 用 lambda + `std::function` 简化策略/命令模式，用 `std::make_unique` 替代 `new`。
