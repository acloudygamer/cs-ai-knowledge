# 05-并发与协程

> 前置：[04-时间与日期](04-时间与日期.md)（超时参数全是 duration）、[03-函数与Lambda](../01-语言核心/03-函数与Lambda.md)（线程入口与任务都是可调用对象） · 后续：[06-工具组件](06-工具组件.md)

> **版本基准**：C++20；C++23/26 特性行内标注。示例实测环境：GCC 14.2（MinGW-w64），`-std=c++20`。

并发的全部困难来自一个硬件事实：多核各自带缓存，一个核的写入不会自动按程序顺序被另一个核看到（背景见 [0-计算机基础](../../0-计算机基础/README.md)）。标准库的对策分三层：**执行流**（thread）负责创建并发；**同步原语**（mutex、条件变量、atomic）负责在共享数据上重建顺序；**结果通道**（future 一族）负责把值和异常跨线程送回来。协程（C++20）是另一条路线：不换线程，把函数本身切成可挂起的片段。

## 本质

- **thread**：对 OS 线程的薄包装。构造即启动，所有权语义——可移动不可拷贝。
- **mutex**：一块共享数据的准入凭证，同一时刻一个持有者。锁的不是内存，是**协议**：所有访问者都遵守"先拿锁再碰数据"才有效。
- **atomic**：对单个变量的硬件级原子操作，不带互斥协议；内存序参数决定它顺带向其他线程承诺多少可见性。
- **future/promise**：一次性结果通道的两端——promise 写端塞值或异常，future 读端阻塞取用。
- **协程**：编译器把含 `co_await`/`co_yield`/`co_return` 的函数改写为状态机：挂起点存进堆上的协程帧，恢复时从断点继续。切换在用户态完成，不陷内核。

## 机制

### thread 与 jthread：RAII 加在 OS 线程上

`std::thread` 析构时若仍处于 joinable 状态（没 join 也没 detach），直接 `std::terminate`——这是刻意设计：一个没人等的线程持有着谁的栈上引用，析构点说不清，不如立刻暴露。`std::jthread`（C++20）补上缺口：析构自动 `request_stop()` + `join()`，并内置 `stop_token` 协作式停止——令牌是请求而非强杀，线程体需在循环里检查 `stop_requested()`。优先用 `jthread`。

### mutex 家族与 RAII 锁

锁永远不裸调 `lock()`/`unlock()`（异常路径会漏 unlock），一律走 RAII 包装：

- `lock_guard`：单锁最小包装；
- `scoped_lock`（C++17）：可变参数同时拿多把锁，内部按死锁避免算法（`std::lock` 的地址序轮流尝试）加锁——**多锁场景防死锁的标准答案**；
- `unique_lock`：可手动 unlock/转移所有权，体积稍大，是条件变量的指定搭档（cv 等待时要临时放锁）。

死锁的经典破法就两条：全局固定加锁顺序，或一次性全拿（`scoped_lock`）。

### 条件变量：虚假唤醒与谓词

`condition_variable` 解决"等某个条件成立"的问题。它有一个反直觉的契约：**允许虚假唤醒**——没有 notify 也可能从 `wait` 返回（POSIX 许可实现这么做， C++ 继承）。原因在实现层：把"唤醒必为真"的责任压给内核同步原语代价高且仍堵不住竞态窗口，不如让等待方醒来重查条件。因此正确形态永远是谓词版 `cv.wait(lock, pred)`——其语义就是 `while (!pred()) wait(lock);`，虚假唤醒落回循环重查。手写裸 `wait` 几乎必是 bug。

### atomic 与内存序三档：各付什么价

`atomic<T>` 保证单次读写的原子性（无撕裂）；`memory_order` 参数决定**此外**还承诺什么：

| 档位 | 承诺 | 硬件代价（x86-64 口径） |
|---|---|---|
| `relaxed` | 仅原子性，无跨线程顺序 | 零额外指令；只适合计数器这类不承载数据的场景 |
| `release`/`acquire` | 配对使用：release 之前的写，对读到该值的 acquire 方全部可见（建立 happens-before 边） | store 免费，load 免费（x86 的 TSO 内存模型自带）；ARM 上需单向栅栏指令 |
| `seq_cst`（默认） | 全局单一修改顺序，所有线程观察一致 | x86 上 seq_cst 的 store 编译为 `XCHG`（锁总线级），最贵；推理最简 |

纪律：**默认 seq_cst，确认是瓶颈再降级**；降到 acquire/release 的前提是能把"谁发布、谁订阅、保护哪些普通变量"说清；relaxed 只用于统计计数。

### future/promise/packaged_task/async：结果通道

`promise`/`future` 是通道裸件；`packaged_task` 把一个可调用对象包成 promise（返回值自动塞进通道）；`async` 是一键全包——`std::async(std::launch::async, f, args)` 起线程、执行任务、返回 future。通道一次性：`get()` 只能调一次，异常也会沿通道传递（在 `get()` 处重抛）。C++20 起优先用 `packaged_task` + `jthread` 的组合：`async` 的启动策略由实现拍板（不带 `launch::async` 可能退化为惰性求值），且返回的 future 析构会隐式阻塞 join，这两个坑都写在标准里。

### 协程（C++20）：骨架而非库

标准只给了**机制三件套**，没给成品类型——这是"库骨架而非库"的现实：

- **promise_type**（承诺对象）：协程行为的配置点，编译器按名字找它。`initial_suspend()` 决定创建即挂起还是立即执行；`final_suspend()` 决定结束时帧是否保留（保留才能让调用者取结果）；`return_value(v)`/`return_void()` 接收 `co_return` 的值；`unhandled_exception()` 兜底异常；`get_return_object()` 产出让回调用者的东西。
- **coroutine_handle**：协程帧的遥控器——`resume()` 恢复、`destroy()` 销毁、`promise()` 访问承诺对象。帧在堆上，销毁责任在持有者（RAII 类型必须包它）。
- **awaiter**（等待器）：`co_await expr` 时对 `expr` 的三连问——`await_ready()` 已就绪？（是则跳过挂起）；`await_suspend(handle)` 挂起时做什么（返回另一个 handle 可实现任务链切换）；`await_resume()` 恢复后 `co_await` 表达式的值是什么。

`co_yield v` 是 `co_await promise.yield_value(v)` 的语法糖。事件来源（IO 完成、定时器）到 `resume()` 的接线全部要自己写或用第三方库（asio、cppcoro 血统）。（C++23 增量）`std::generator<T>` 是标准库给的第一个成品协程类型：惰性序列生成器，GCC 14 起可用（本篇实测 `-std=c++23` 通过）。

## 连接

- 同步原语的超时参数（`wait_for`/`wait_until`/`sleep_for`）全是 [04-时间与日期](04-时间与日期.md) 的 duration/time_point。
- RAII 包装锁与句柄的一般原理见 [04-类与资源管理](../01-语言核心/04-类与资源管理.md)。
- 协程 awaiter 的定制点写法依赖模板机制，见 [06-模板与Concepts](../01-语言核心/06-模板与Concepts.md)。

## 示例

（GCC 14.2 MinGW 实测，`-std=c++20`。注：本机 PATH 中混有另一发行版的旧 `libstdc++-6.dll`，动态链接 `<future>` 会在加载期失败；静态链接 `-static` 或将工具链 bin 目录前置 PATH 即正常——属环境配置问题，非库缺陷。）

```cpp
#include <atomic>
#include <chrono>
#include <condition_variable>
#include <coroutine>
#include <future>
#include <iostream>
#include <mutex>
#include <queue>
#include <thread>
using namespace std::chrono_literals;

// 协程骨架：最小 Task，promise_type 是全部行为的配置点
struct Task {
    struct promise_type {
        int value{};
        Task get_return_object() {
            return Task{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() noexcept { return {}; } // 创建即挂起
        std::suspend_always final_suspend() noexcept { return {}; }   // 帧留给调用者取值
        void return_value(int v) { value = v; }
        void unhandled_exception() { std::terminate(); }
    };
    std::coroutine_handle<promise_type> h;
    ~Task() { if (h) h.destroy(); }          // 帧销毁责任归持有者
    int get() { h.resume(); return h.promise().value; }
};
Task compute() { co_return 42; }             // 编译器改写为状态机

int main() {
    // jthread：析构自动 request_stop + join
    std::atomic<int> ticks{0};
    {
        std::jthread w([&](std::stop_token st) {
            while (!st.stop_requested()) { ++ticks; std::this_thread::sleep_for(1ms); }
        });
        std::this_thread::sleep_for(10ms);
        w.request_stop();
    }
    std::cout << "ticks>0: " << (ticks > 0) << '\n';    // 1

    // 条件变量：谓词版 wait 一体处理虚假唤醒
    std::queue<int> q; std::mutex m; std::condition_variable cv;
    std::jthread consumer([&] {
        std::unique_lock lk(m);
        cv.wait(lk, [&] { return !q.empty(); });
        std::cout << "got " << q.front() << '\n';       // got 7
        q.pop();
    });
    { std::lock_guard lk(m); q.push(7); }
    cv.notify_one();
    consumer.join();

    // release/acquire 配对：普通变量 payload 被 happens-before 边保护
    std::atomic<bool> ready{false};
    int payload = 0;
    std::jthread pub([&] { payload = 42; ready.store(true, std::memory_order_release); });
    std::jthread sub([&] {
        while (!ready.load(std::memory_order_acquire)) {}
        std::cout << "payload=" << payload << '\n';     // payload=42
    });
    pub.join(); sub.join();

    // packaged_task + future：返回值跨线程的一次性通道
    std::packaged_task<int(int)> task([](int x) { return x * 2; });
    std::future<int> fut = task.get_future();
    std::jthread(std::move(task), 21).detach();
    std::cout << "fut=" << fut.get() << '\n';           // fut=42

    // 协程：拿到 Task 时不执行，resume 才进函数体
    Task t = compute();
    std::cout << "coro=" << t.get() << '\n';            // coro=42
}
```
