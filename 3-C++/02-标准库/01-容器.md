# 01-容器

> 前置：[05-移动语义与拷贝控制](../01-语言核心/05-移动语义与拷贝控制.md)（扩容迁移靠移动构造） · 后续：[02-迭代器与算法](02-迭代器与算法.md)（容器只通过迭代器把元素交给算法）

> **版本基准**：C++20；C++23/26 特性行内标注。示例实测环境：GCC 14.2（MinGW-w64，libstdc++），`-std=c++20`；动态链接因环境 DLL 冲突加载失败（exit 127）时，加 `-static` 静态链接。

STL 容器是同一件事的三到四种物理实现：一块内存加上一套元素布局规则。选容器不是背接口，是算两笔账——**复杂度账**（各操作的渐近代价）和**缓存账**（内存布局决定的访存局部性，背景见 [0-计算机基础](../../0-计算机基础/README.md)）。本篇按内存布局把容器分成三族，族内差异是参数，族间差异是结构。

## 本质

容器（container）是**拥有其元素的对象**：值语义——拷贝容器即深拷贝全部元素；析构容器即析构全部元素。容器之间的本质差异只有一个维度：**元素在内存里怎么摆**，它同时钉死了两笔账：

- 连续摆放 → 随机访问 $O(1)$、缓存友好，但中间插入要搬动后继元素， $O(n)$；
- 节点散布（每个元素单独分配、指针相连）→ 任意位置插入 $O(1)$（已知位置时），但放弃随机访问，每跳一个节点可能是一次缓存未命中；
- 哈希桶（按键的散列值分桶）→ 平均 $O(1)$ 查找，但失去顺序，最坏退化为 $O(n)$。

没有万能容器，因为这三条诉求——随机访问、任意位置插入、有序遍历——在内存布局层面互相排斥。

## 机制

### 三族分类

| 族 | 成员 | 内存布局 | 找元素的代价 |
|---|---|---|---|
| 连续族 | `vector`、`array`、`string`；特例 `deque` | 元素紧排在一大块内存里 | 下标 $O(1)$ |
| 节点族 | `list`、`forward_list`、`map`/`set`（红黑树） | 每元素一个堆节点，指针相连 | 按值/键 $O(\log n)$（树）或 $O(n)$（链） |
| 哈希族 | `unordered_map`/`unordered_set` | 桶数组 + 桶内短链 | 平均 $O(1)$，最坏 $O(n)$ |

`deque` 是连续族的特例：分段连续（多块定长缓冲区 + 一张块索引表），换来两端 $O(1)$ 插入，代价是随机访问多一次间接。`array` 则把"连续"推到底：大小编译期固定、元素直接嵌在对象内，栈上分配，零堆开销。

### vector 扩容：几何增长与均摊账

`vector` 预留容量（capacity）与已用大小（size）分离。`push_back` 在 `size == capacity` 时扩容：分配更大的新块、把元素**移动**过去、释放旧块。增长是几何级而非固定步长——这是被复杂度账钉死的：若每次只加常数容量，插 $n$ 个元素总迁移代价 $O(n^2)$；按因子 $k$ 翻倍，第 $i$ 次扩容迁移 $k^i$ 个元素，总代价

$$
\sum_{i=0}^{\lfloor \log_k n \rfloor} k^i = \frac{k^{\lfloor \log_k n \rfloor + 1}-1}{k-1} \leq \frac{k}{k-1}\\, n = O(n)
$$

均摊到每次 `push_back` 是 $O(1)$。实测：libstdc++（GCC 14.2） $k=2$，capacity 序列 1→2→4→8→16→32；MSVC 取 $k=1.5$（旧块更可能被复用，峰值内存更低）。

扩容迁移走移动构造，但有一个前文立下的契约在起作用：元素移动构造必须标 `noexcept`，否则 `vector` 为保证强异常安全**退化为逐元素拷贝**（机制见 [05-移动语义与拷贝控制](../01-语言核心/05-移动语义与拷贝控制.md)）。

### 迭代器失效：布局决定的规则

迭代器本质是"指向元素所在内存位置的凭证"，内存布局一变，凭证就作废：

| 容器 | 插入后 | 删除后 |
|---|---|---|
| `vector` | 若扩容：**全部**失效；未扩容：插入点及之后失效 | 删除点及之后失效 |
| `deque` | 首尾插入：迭代器全失效、引用有效；中段插入：迭代器与引用全失效 | 中段删除全部失效，首尾删除仅被删者失效 |
| `list`、`map`、`set` | 不失效 | 仅被删元素失效 |
| `unordered_*` | 若 rehash：全部失效 | 仅被删元素失效 |

纪律只有一条：**结构性修改之后重取迭代器**，或用 `erase` 的返回值（后继迭代器）接着走。

### map = 红黑树 vs unordered_map = 哈希桶

| 维度 | `map`（红黑树） | `unordered_map`（哈希桶） |
|---|---|---|
| 查找/插入/删除 | $O(\log n)$，稳定 | 平均 $O(1)$，最坏 $O(n)$（哈希碰撞全撞一桶） |
| 有序性 | 按键有序，遍历即中序 | 无序 |
| 范围查询（lower_bound） | $O(\log n)$ | 不支持 |
| 每元素开销 | 3 指针 + 颜色位（libstdc++ 节点 40 字节，`pair<const int, int>`，GCC 14.2 实测） | 1 指针 + 缓存哈希值，另有桶数组 |
| 键的要求 | 可比较（`<`） | 可哈希 + 可判等 |

`map` 的有序性不是赠品，是结构的副产品：平衡二叉搜索树的中序遍历天然有序，这让范围查询（`lower_bound`/`upper_bound`）成为可能。哈希桶用有序换常数因子：一次散列直达桶，省掉 $\log n$ 次比较——但桶内退化成短链，且 rehash（负载因子超阈值时桶数组扩容重散列）与 `vector` 扩容同理，使全部迭代器失效。

（C++23 增量）`std::flat_map`/`flat_set` 走第三条路：键、值各存一个连续 `vector`，二分查找 $O(\log n)$、缓存局部性同 `vector`，适合读多写少。GCC 14.2 无 `<flat_map>`（libstdc++ 15 起提供），本篇不实测。

### 适配器：接口收窄而非新容器

`stack`、`queue`、`priority_queue` 不持有新结构，是包在既有容器上的接口收窄：`stack`/`queue` 默认垫 `deque`（两端 $O(1)$），`priority_queue` 垫 `vector` 并用堆算法维护堆序（上浮/下沉各 $O(\log n)$）。接口收窄本身是设计：不暴露迭代器，使用者就破坏不了堆序。

## 连接

选型判据（先问访问模式，再查表）：

| 首要诉求 | 选 |
|---|---|
| 按下标访问、尾部增删、遍历性能 | `vector`（默认答案） |
| 大小编译期固定、零堆开销 | `array` |
| 两端高频增删 | `deque` |
| 中段高频插入删除且**不需要**随机访问 | `list`（多数场景 `vector` 仍更快，先测） |
| 有序键、范围查询 | `map` / `set` |
| 只要快速查找，不要顺序 | `unordered_map` / `unordered_set` |
| 读远多于写的有序映射 | `flat_map`（C++23 增量） |

- 容器与算法之间的唯一接口是迭代器，能力层级与失效的算法侧后果见 [02-迭代器与算法](02-迭代器与算法.md)。
- `string` 的连续布局与小字符串优化见 [03-字符串与格式化](03-字符串与格式化.md)。
- 缓存局部性为什么值 10~100 倍差距，硬件账见 [0-计算机基础](../../0-计算机基础/README.md)。

## 示例

（GCC 14.2 MinGW 实测，`-std=c++20`）

```cpp
#include <vector>
#include <map>
#include <unordered_map>
#include <string>
#include <iostream>

int main() {
    // vector 几何增长：capacity 序列实测 1 2 4 8 16 32（libstdc++ 因子 k=2）
    std::vector<int> v;
    std::size_t last = 0;
    for (int i = 0; i < 17; ++i) {
        v.push_back(i);
        if (v.capacity() != last) { std::cout << v.capacity() << ' '; last = v.capacity(); }
    }
    std::cout << '\n';

    // 扩容使迭代器失效：结构性修改后必须重取
    std::vector<int> w{1, 2, 3};
    auto it = w.begin();
    w.push_back(4);          // 若扩容，it 已悬垂，再解引用是 UB
    it = w.begin();          // 重取

    // map：遍历按键有序（红黑树中序）
    std::map<std::string, int> m{{"b", 2}, {"a", 1}, {"c", 3}};
    for (auto& [k, val] : m) std::cout << k;   // abc
    std::cout << '\n';

    // unordered_map：平均 O(1) 查找，无顺序承诺
    std::unordered_map<std::string, int> um{{"b", 2}, {"a", 1}};
    std::cout << um.count("a") << um.count("z") << '\n';   // 10

    // emplace：容器内原位构造，省一次临时对象的构造+移动
    std::vector<std::pair<int, int>> ps;
    ps.emplace_back(1, 2);
    std::cout << ps[0].second << '\n';         // 2
}
```
