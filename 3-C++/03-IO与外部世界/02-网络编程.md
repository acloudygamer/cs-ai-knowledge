# 02-网络编程

> 前置：[01-文件操作](01-文件操作.md) · 后续：[03-序列化与JSON](03-序列化与JSON.md)（字节流之上需要格式）

> **版本基准**：C++20；C++23/26 特性行内标注。标准库示例实测环境：GCC 14.2（MinGW-w64，Windows）；动态链接因环境 DLL 冲突加载失败（exit 127）时，加 `-static` 静态链接。

网络编程是程序经操作系统协议栈（TCP/IP）与另一台主机的进程交换字节流。先交代一个反直觉的现实：**C++ 标准库没有任何网络设施**——截至 C++26，没有 socket、没有 HTTP 客户端。这是历史遗留而非设计决断：以 Asio 为底的 Networking TS 在 WG21 推进了十余年始终未并入国际标准，卡点在于"异步模型如何标准化"未收敛；委员会的转向是把异步底座本身先标准化——sender/receiver（`std::execution`，C++26 增量），网络设施仍在门外。现实后果：C++ 网络编程分两层——必懂的地基是 OS socket API，生产答案在第三方库。

## 本质

socket 是内核暴露给进程的网络端点句柄，语义与文件描述符同构：创建（`socket`）、命名（`bind`）、连接（`connect`/`listen`+`accept`）、读写（`send`/`recv`）、关闭。与文件的差异在三个约束上：

- **延迟与不可靠**：一次本地文件读以微秒计，一次跨网往返（RTT）以毫秒计且可能丢包重传——吞吐与延迟都不再稳定。
- **字节序**：多字节整数在线格式统一大端（网络字节序），主机端 x86-64 是小端，`htons`/`ntohs` 族负责转换。这与 [03-序列化与JSON](03-序列化与JSON.md) 的端序问题是同一个问题的两个现场。
- **流无边界**：TCP 是字节流不是报文流，`send` 一次的 100 字节可能被对方两次 `recv` 各收 50——应用层协议（如 HTTP 的 `Content-Length`）负责重新切出消息边界。

## 机制

### 选型：四个层级的答案

| 库 | 定位 | 形态 | 何时用 |
|---|---|---|---|
| Asio（standalone 或 Boost.Asio） | 异步 IO 底座：socket、定时器，`io_context` 事件循环 | 回调 / C++20 协程 `co_await` | 长连接服务、自己掌握协议、需要高并发底座 |
| cpp-httplib | 单头文件 HTTP 客户端 + 服务器 | 阻塞同步 | 发几个请求、起个调试/内部 HTTP 服务 |
| cpr | libcurl 的 C++ 封装，Python requests 风格 | 阻塞同步（另有异步接口） | HTTP 客户端日常需求：认证、超时、表单 |
| libcurl | C 库，协议覆盖面最广（HTTP/FTP/SMTP…） | easy 同步 / multi 异步 | 需要 HTTP 之外的协议，或精细控制传输 |

判据轴：**要不要并发**（同步库一把梭 vs 异步底座）×**要不要 HTTP 之外的东西**（专用 vs 全能）。

### 同步 vs 异步：代码形态的分岔

- **同步**：调用即阻塞，结果即返回值，控制流就是代码顺序。并发靠堆线程，一个连接一个线程；连接数上千后线程切换与栈内存成为瓶颈。
- **异步**：`async_read` 发起即返回，完成时由 `io_context` 调回调；单线程事件循环驱动万级连接。代价是控制流被切碎——回调嵌套，或 C++20 起用协程把异步写回顺序形态（`co_await socket.async_read(...)`，见 [05-并发与协程](../02-标准库/05-并发与协程.md)）。

选型判据：并发连接数与延迟预算。几十个连接的客户端工具用 cpr/cpp-httplib 同步写法足够；连接数上几千、或延迟预算卡到毫秒级的服务端，才付得起异步的复杂度税。

## 连接

socket 之下是 TCP/IP 协议栈与三次握手，背景见 [0-计算机基础/06-计算机网络/07-Socket编程](../../0-计算机基础/06-计算机网络/07-Socket编程.md)；字节流之上需要消息格式，见 [03-序列化与JSON](03-序列化与JSON.md)；并发底座的语言机制见 [05-并发与协程](../02-标准库/05-并发与协程.md)。

## 示例

**实测**（GCC 14.2 MinGW，`-std=c++20 -lws2_32`）：Windows socket（Winsock）在 127.0.0.1 回环上自建连接自收自发，演示 socket 生命周期与字节序转换：

```cpp
#include <winsock2.h>
#include <iostream>
#include <string>

int main() {
    WSADATA wd;
    if (WSAStartup(MAKEWORD(2, 2), &wd) != 0) return 1;   // Winsock 要求显式初始化

    SOCKET ls = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    sockaddr_in addr{};
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK);  // 127.0.0.1；htonl：主机小端→网络大端
    addr.sin_port = 0;                              // 0 = 内核分配空闲端口
    bind(ls, (sockaddr*)&addr, sizeof addr);
    listen(ls, 1);
    int len = sizeof addr;
    getsockname(ls, (sockaddr*)&addr, &len);        // 读回实际端口
    std::cout << "port " << ntohs(addr.sin_port) << '\n';  // 内核分配，每次运行不同

    SOCKET cs = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    connect(cs, (sockaddr*)&addr, sizeof addr);     // 回环 + backlog：accept 前即可成功
    SOCKET ss = accept(ls, nullptr, nullptr);

    const char* msg = "ping";
    send(cs, msg, 4, 0);
    char buf[16]{};
    int n = recv(ss, buf, sizeof buf, 0);
    std::cout << std::string(buf, buf + n) << '\n'; // ping

    closesocket(cs); closesocket(ss); closesocket(ls);
    WSACleanup();
}
```

实测输出（端口号由内核随机分配，逐次不同）：

```text
port 29101
ping
```

**骨架示意（未实测，本机未装第三方库）**：cpp-httplib 的同步 HTTP 客户端形态——

```cpp
#include <httplib.h>
httplib::Client cli("http://example.com");   // 阻塞同步：调用即等结果
auto res = cli.Get("/api/item/1");
if (res && res->status == 200)
    process(res->body);                       // body 是 std::string
```

同一件事用 cpr 是 `auto r = cpr::Get(cpr::Url{"..."});`，形态相同；用 Asio 则拆成 `async_connect` → `async_write` → `async_read` 的回调链或协程，底座换来的并发能力见上文形态分岔。
