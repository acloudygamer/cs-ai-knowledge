# 01-文件操作

> 前置：[02-标准库](../02-标准库/README.md)（容器、字符串） · 后续：[02-网络编程](02-网络编程.md)

> **版本基准**：C++20；C++23/26 特性行内标注。示例实测环境：GCC 14.2（MinGW-w64，Windows）。

文件是操作系统内核维护的命名字节序列。C++ 标准库提供两层抽象去碰它：`<fstream>` 负责把字节读进来、写出去（流），`std::filesystem`（C++17）负责找到文件、看清文件（路径与元数据）。本篇沿一次写文件的数据流组织：定位（path）→ 打开（流 + 模式）→ 缓冲读写 → 安全落盘（原子写）。

## 本质

- **流（stream）**：对"有序字节序列"的抽象。`std::ifstream`、`std::ofstream`、`std::fstream` 是同一台机器的三种开合方向，底下各挂一个 `filebuf` 用户态缓冲区；缓冲区满或显式 flush 时才发起一次系统调用。缓冲存在的原因：系统调用有用户态/内核态切换的固定代价，聚批写入把它摊薄。
- **路径与元数据**：`std::filesystem::path` 是结构化路径而不是字符串；`directory_iterator` 遍历目录，`status`、`file_size`、`last_write_time` 查询元数据。

fstream 对象是 RAII 句柄：构造打开文件，析构 flush 并关闭，异常抛出或提前 `return` 都不会漏关——确定性析构（[04-类与资源管理](../01-语言核心/04-类与资源管理.md)）在 IO 上的直接应用。推论：正常路径里不应出现显式 `close()`；唯一的合理例外是需要在某个时点关闭并检查写错误——析构忽略错误，`close()` 是拿到"写盘失败"通知的最后机会。

## 机制

### 文本/二进制模式：换行翻译的平台差异

`std::ios::binary` 的含义不是"用二进制方式读写"，而是**关掉换行翻译**。Windows 的 CRT（含 MinGW 使用的 UCRT）在文本模式下把写出的 `\n` 翻译成 `\r\n`、读入时反向翻译；Linux 下两种模式完全等价。实测（GCC 14.2 MinGW）：写出 8 个字符 `"one\ntwo\n"`，文本模式落盘 10 字节，二进制模式落盘 8 字节。

后果链：同一份代码跨平台行为不同 → 凡是字节本身有含义的文件（序列化数据、图片、协议包）必须显式加 `binary`；文本模式下 `\n` 与磁盘字节数不再一一对应，`seekg`/`tellg` 的字节偏移也随之不可靠。

其余常用模式位：`app`（追加写）、`trunc`（截断清空，`ofstream` 默认隐含）、`ate`（打开即定位到末尾）。

### std::filesystem：路径是结构，不是字符串

- **拼接用 `/=`**：`dir / "sub" / "f.txt"` 由库按平台补分隔符；手写 `"dir\\sub"` 把平台假设焊死进代码。
- **遍历**：`directory_iterator` 走一层，`recursive_directory_iterator` 递归；元素是 `directory_entry`，自带 `is_regular_file()`、`file_size()` 等查询。
- **错误处理两形态**：同一函数有抛 `std::filesystem_error` 与收 `std::error_code` 两组重载。探测性操作（文件可能不存在）用 error_code 形态，避免把正常控制流走成异常；硬依赖的路径用异常形态——判据与 [07-错误处理](../01-语言核心/07-错误处理.md) 一致。

### 原子写：临时文件 + rename

约束需要辩护：直接打开目标文件覆写，写到一半崩溃，旧内容已毁、新内容不全——两种状态都不是用户要的。解法利用 rename 的原子性：同目录下的 `std::filesystem::rename` 是目录项替换，读者要么看到旧文件、要么看到新文件，不存在中间态。

1. 完整写入 `data.txt.tmp`，让流析构（字节离开用户态缓冲）；
2. `fs::rename(tmp, target)` 一步替换（GCC 14.2 MinGW 实测可覆盖已存在的目标文件）；
3. 崩溃审计：rename 之前崩溃 → 目标完好，残留一个临时文件；rename 之后崩溃 → 新内容已生效。

"同目录"是硬条件：跨文件系统的 rename 可能退化为拷贝加删除，原子性消失。

## 连接

| 需求 | 用谁 |
|---|---|
| 读配置、写日志、逐行文本 | `fstream` 文本模式 |
| 序列化数据、图片、任何"字节即含义"的文件 | `fstream` + `binary`；线上格式的设计见 [03-序列化与JSON](03-序列化与JSON.md) |
| 遍历目录、查大小与时间、拼路径 | `std::filesystem` |
| 崩溃安全的配置/数据落盘 | 原子写惯用法（上文） |
| 超大文件随机访问、进程间共享 | 内存映射文件——标准库未覆盖，走 OS API（`mmap`/`MapViewOfFile`） |

## 示例

（GCC 14.2 MinGW 实测，`-std=c++20`）

```cpp
#include <filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::filesystem;

int main() {
    fs::path dir = fs::temp_directory_path() / "cpp_io_demo";  // path 拼接，不管分隔符
    fs::create_directories(dir);

    {   // 文本模式：MinGW 下 '\n' 落盘翻译为 "\r\n"
        std::ofstream out(dir / "a.txt");
        out << "one\ntwo\n";
    }   // 析构即 flush + close（RAII），无需显式 close
    {   // 二进制模式：字节原样落盘
        std::ofstream out(dir / "b.bin", std::ios::binary);
        out << "one\ntwo\n";
    }
    std::cout << fs::file_size(dir / "a.txt") << ' '
              << fs::file_size(dir / "b.bin") << '\n';  // 10 8：翻译差异实测

    for (const auto& e : fs::directory_iterator(dir))   // 遍历 + 状态查询
        std::cout << e.path().filename().string() << ' '
                  << (e.is_regular_file() ? "file" : "other") << '\n';

    // 原子写：临时文件写完整后 rename 替换目标
    fs::path target = dir / "data.txt", tmp = dir / "data.txt.tmp";
    { std::ofstream out(target); out << "old"; }
    { std::ofstream out(tmp);    out << "new"; }
    fs::rename(tmp, target);                            // 同目录原子替换
    std::cout << std::ifstream(target).rdbuf() << '\n'; // new

    fs::remove_all(dir);
}
```

实测输出（GCC 14.2 MinGW）：

```text
10 8
a.txt file
b.bin file
new
```
