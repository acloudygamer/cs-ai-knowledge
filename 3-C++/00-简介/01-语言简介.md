# C++ 语言简介

## 定义

C++ 是系统级编程语言，其核心设计原则是**零成本抽象**——高级抽象机制的运行时开销应不高于手工编写的等价代码。这一原则可形式化为：对于任意高级特性 $F$ 及其等价的手写代码 $C$，必有 $T(F) \leq T(C)$ 且 $M(F) \leq M(C)$，其中 $T$ 为时间开销，$M$ 为空间开销。

C++ 起源于 C（1972），以 `++` 运算符暗示" C 的下一阶段"，继承 C 的硬件控制能力（裸指针、位操作、寄存器访问），同时通过类和模板引入类型安全与泛型抽象。

## 数学模型

### 零成本抽象的形式化

设 $\mathcal{A}$ 为所有抽象机制的集合，$\mathcal{C}$ 为等价手写代码的集合。零成本原则要求：
$$\forall A \in \mathcal{A}, \exists C \in \mathcal{C} : T(A) \leq T(C) \land M(A) \leq M(C)$$

**归约终点**：C++ 的所有高级特性最终归约为三个底层原语：
1. **内存操作**：`malloc`/`free`、placement new
2. **函数调用**：跳转 + 栈帧操作
3. **指令序列**：编译器生成的机器码

虚函数表是这一原则的典型案例——多态的运行时分派开销仅为一次指针间接寻址 ($O(1)$)，而非解释器式的模式匹配。

### C++ 抽象机器的时间模型

C++ 程序的行为由**抽象机器**定义，程序员的代码在抽象机器上执行，编译器负责将抽象机器的操作映射到具体硬件操作：

$$T_{\text{抽象}} = \sum_{i=1}^{n} T_{\text{操作}_i} + \sum_{j=1}^{m} T_{\text{序间}_j}$$

其中 $T_{\text{序间}_j}$ 是序列点（sequence point）之间的操作代价。标准保证：允许的优化不能改变**有争议值**（gl_value）的值计算顺序之外的可观察行为。

**序列点边界**：
- `;` 语句结束
- `&&`、`||`、`,` 运算符处
- `?:` 条件表达式完整求值后

### 内存顺序的同步模型

C++11 引入的多线程内存模型基于**先行关系**（happens-before）：

$$\text{hb}(x, y) \implies \text{程序顺序中 } x \text{ 在 } y \text{ 前，且 } y \text{ 能观察到 } x \text{ 的全部效果}$$

**六种内存序的包含关系**：

| 内存序 | 允许重排 | 同步代价 |
|--------|---------|---------|
| `memory_order_relaxed` | 任意重排 | 无同步，仅保证原子性 |
| `memory_order_acquire` | 前->后禁止重排 | 屏障指令（x86: MFENCE） |
| `memory_order_release` | 后->前禁止重排 | 屏障指令（x86: SFENCE） |
| `memory_order_acq_rel` | 两向禁止重排 | 组合屏障 |
| `memory_order_seq_cst` | 全序一致（默认） | 最贵，x86 上需 LOCK 前缀 |

**SC-DRF 定理**：若程序是数据竞争自由（DRF）的，顺序一致（SC）执行的程序其所有执行都是 SC 的。

**所有权变换**：
- 源代码 → Token 流：文本到语素的变换，所有权不变
- Token 流 → AST：符号表记录名字到实体的映射
- AST → IR：控制流图（CFG）构建，活跃变量分析
- IR → 目标代码：寄存器分配（着色算法或线性扫描）

### C++26 关键特性深度

**编译期反射**（Reflection）：

反射的本质是将程序的**自描述能力**从运行时移到编译期：
$$R : \text{类型} \times \text{成员列表} \rightarrow \text{元信息}$$
$$\text{反射类型} \vdash \text{成员名} \rightarrow \text{偏移量} \times \text{类型}$$

C++26 反射消除了宏的力量，使以下模式在编译期完成：
```cpp
constexpr auto fields = reflexpr(MyStruct).members;
// fields 是一个编译期 tuple，包含每个成员的元信息
```

**std::execution**：

并行算法的执行策略构成一个格（lattice）：
$$\text{Sequential} \sqsubseteq \text{Parallel} \sqsubseteq \text{Parallel + Vectorized}$$

- `seq`：顺序执行，无并行
- `par`：并行分区，线程本地归约
- `par_unseq`：向量化 + 并行（最激进）

## 机制

### 零成本抽象的物理实现

C++ 的零成本抽象通过**编译期多态**实现：
- **模板**：在编译期展开为具体类型的代码，运行时无间接层
- **内联**：将函数调用替换为函数体，消除调用开销
- **constexpr**：编译期求值，消除运行时计算

**约束条件**：模板实例化产生的代码膨胀（code bloat）是零成本抽象的代价。标准要求"不高于手写代码"，而非"无代码"。

### 智能指针的所有权语义

智能指针将**资源所有权**形式化为类型：

| 类型 | 所有权语义 | 数学模型 |
|------|-----------|----------|
| `unique_ptr<T>` | 独占：所有者唯一 | 线性逻辑 $!x \otimes x$ |
| `shared_ptr<T>` | 共享：引用计数 $|ref|$ | $ref$ 维护 $\mathbb{N}$ 上的递减计数 |
| `weak_ptr<T>` | 观察：非拥有 | 不改变引用计数，仅观测 |

RAII 的核心不变式：资源获取与释放**严格绑定于对象生命周期**。
$$\text{Constructor} \vdash \text{acquire}(R) \land \text{Destructor} \vdash \text{release}(R)$$

**shared_ptr 的线程安全性**：引用计数本身是原子操作，但对象的访问需要额外同步：
$$\text{shared_ptr 本身} : \text{原子 refcount} \times \text{原始指针}$$
$$\text{对象访问} : \text{需外部同步（锁或原子）}$$

**weak_ptr 打破循环引用**：
$$A \xrightarrow{ref} B \xrightarrow{ref} A \implies \text{泄漏}$$
$$A \xrightarrow{ref} B \xrightarrow{weak} A \implies \text{可释放}$$

违反后果：若析构函数抛出异常，RAII 栈展开被中断，剩余析构函数不会被调用，导致资源泄漏。

### lambda 的闭包语义

Lambda 表达式编译后生成为一个**匿名闭包类**：
$$\lambda x . e \mapsto \text{class } C \{ \text{env}, \text{operator()}(x) \{ \text{return } e[\text{env}/x] \}\}$$

捕获机制决定 env 的形式：
- `[=]`：按值捕获，env 包含变量拷贝（$O(1)$ 捕获代价，$O(n)$ 闭包大小）
- `[&]`：按引用捕获，env 包含指针（$O(1)$ 捕获代价，但引入悬挂引用风险）

**约束条件**：若 lambda 捕获局部变量且超出作用域后被调用，形成悬挂引用（dangling reference），解引用行为未定义。

**泛型 lambda（C++14）**的数学形式：
$$\Lambda . \lambda x . e \mapsto \text{template<typename T> operator()(T x)}$$

### auto 与 decltype 的类型推断

类型推断的本质是** Hindley-Milner 系统**的受限版本：
$$\Gamma \vdash e : t \implies \Gamma \vdash \text{auto } x = e : \text{drop-ref-cv}(t)$$

| 表达式 | 推断结果 |
|--------|----------|
| `auto x = expr` | 移除 expr 类型的引用和 cv 限定符 |
| `decltype(expr)` | 保留 expr 的原始类型（含引用、含 cv） |
| `decltype((expr))` | 双括号永远是引用（即使 expr 是纯右值） |

`decltype(auto)` 的设计动机：函数返回 `auto` 时应用上述规则丢弃引用，返回 `decltype(auto)` 则保留原始类型。

### Coroutines 的状态机归约

C++20 协程是**有限状态自动机**的具体实现：
$$S = \{ \text{初始}, \text{挂起}, \text{运行}, \text{完成}, \text{销毁} \}$$
$$\delta : S \times \Sigma \rightarrow S \times \Gamma$$

其中 $\Sigma$ 是协程帧上的事件（co_await、co_yield、co_return），$\Gamma$ 是副作用（返回值、异常传播）。

**协程帧的内存布局**：
<pre>
协程帧（堆分配）：
┌──────────────────────────────────────┐
│ promise_type 对象                    │
│ 参数副本                             │
│ 局部变量                             │
│ 挂起点标识（resume 时恢复位置）      │
│ 浮点寄存器保存区                      │
│ 通用寄存器保存区                      │
└──────────────────────────────────────┘
</pre>

**约束**：协程帧默认在堆上分配，`std::coroutine_handle::from_address` 可用于栈上分配（需手动管理生命周期）。

## 参考存根

```cpp
#include <memory>
#include <algorithm>
#include <vector>
#include <thread>
#include <atomic>

// 移动语义演示：所有权转移
std::unique_ptr<int> p1 = std::make_unique<int>(42);
std::unique_ptr<int> p2 = std::move(p1);  // p1 变为空，p2 接管资源
// p1 不再拥有资源，析构时无操作

// shared_ptr 引用计数
std::shared_ptr<int> p3 = std::make_shared<int>(42);
std::weak_ptr<int> w = p3;  // 观察，不增加计数
// weak_ptr 用于打破循环引用

// lambda 与泛型算法
std::vector<int> v{1, 2, 3, 4, 5};
auto it = std::find_if(v.begin(), v.end(), [](int n) { return n > 3; });

// 原子操作演示
std::atomic<int> counter{0};
std::thread t1([&] { counter.fetch_add(1, std::memory_order_relaxed); });
std::thread t2([&] { counter.fetch_add(1, std::memory_order_relaxed); });
t1.join(); t2.join();
// counter == 2
```

## 适用场景

<pre>
性能敏感 → 游戏引擎、实时交易、数据库内核、图形渲染
                ↑
         热路径优化：每帧数百万次调用，零抽象开销至关重要

资源受限 → 嵌入式实时系统、操作系统内核、设备驱动
                ↑
         无运行时（no-JVM/no-GC），直接操作硬件寄存器

混合范式 → 热路径（低层次手写汇编）+ 业务逻辑（高层次抽象）
                ↑
         按需切换抽象层级，不强制统一
</pre>

**不适用场景**：
- 快速原型（Python）：动态类型 + REPL 优先
- Web 后端（Go/Java）：GC + 并发原生支持优先
- 数据分析（Python/R）：交互式 + 库生态优先
