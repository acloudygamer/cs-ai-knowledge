# C++ 语言简介

## 定义

C++ 是系统级编程语言，其核心设计原则是**零成本抽象**——高级抽象机制的运行时开销应不高于手工编写的等价代码。这一原则可形式化为：对于任意高级特性 $F$ 及其等价的手写代码 $C$，必有 $T(F) \leq T(C)$ 且 $M(F) \leq M(C)$，其中 $T$ 为时间开销，$M$ 为空间开销。

C++ 起源于 C（1972），以 `++` 运算符暗示" C 的下一阶段"，继承 C 的硬件控制能力（裸指针、位操作、寄存器访问），同时通过类和模板引入类型安全与泛型抽象。

## 数学模型

### 零成本抽象的形式化

设 $\mathcal{A}$ 为所有抽象机制的集合，$\mathcal{C}$ 为等价手写代码的集合。零成本原则要求：
$$\forall A \in \mathcal{A}, \exists C \in \mathcal{C} : T(A) \leq T(C) \land M(A) \leq M(C)$$

**归约终点**：C++ 的所有高级特性最终归约为三个底层原语：
1. **内存操作**：`malloc`/`free`、placement new
2. **函数调用**：跳转 + 栈帧操作
3. **指令序列**：编译器生成的机器码

虚函数表是这一原则的典型案例——多态的运行时分派开销仅为一次指针间接寻址 ($O(1)$)，而非解释器式的模式匹配。

## 机制

### 零成本抽象的物理实现

C++ 的零成本抽象通过**编译期多态**实现：
- **模板**：在编译期展开为具体类型的代码，运行时无间接层
- **内联**：将函数调用替换为函数体，消除调用开销
- **constexpr**：编译期求值，消除运行时计算

**约束条件**：模板实例化产生的代码膨胀（code bloat）是零成本抽象的代价。标准要求"不高于手写代码"，而非"无代码"。

### 智能指针的所有权语义

智能指针将**资源所有权**形式化为类型：

| 类型 | 所有权语义 | 数学模型 |
|------|-----------|----------|
| `unique_ptr<T>` | 独占：所有者唯一 | 线性逻辑 $!x \otimes x$ |
| `shared_ptr<T>` | 共享：引用计数 $|ref|$ | $ref$ 维护 $\mathbb{N}$ 上的递减计数 |
| `weak_ptr<T>` | 观察：非拥有 | 不改变引用计数，仅观测 |

RAII 的核心不变式：资源获取与释放**严格绑定于对象生命周期**。
$$\text{Constructor} \vdash \text{acquire}(R) \land \text{Destructor} \vdash \text{release}(R)$$

违反后果：若析构函数抛出异常，RAII 栈展开被中断，剩余析构函数不会被调用，导致资源泄漏。

### lambda 的闭包语义

Lambda 表达式编译后生成为一个**匿名闭包类**：
$$\lambda x . e \mapsto \text{class } C \{ \text{env}, \text{operator()}(x) \{ \text{return } e[\text{env}/x] \}\}$$

捕获机制决定 env 的形式：
- `[=]`：按值捕获，env 包含变量拷贝（$O(1)$ 捕获代价，$O(n)$ 闭包大小）
- `[&]`：按引用捕获，env 包含指针（$O(1)$ 捕获代价，但引入悬挂引用风险）

**约束条件**：若 lambda 捕获局部变量且超出作用域后被调用，形成悬挂引用（dangling reference），解引用行为未定义。

### auto 与 decltype 的类型推断

类型推断的本质是** Hindley-Milner 系统**的受限版本：
$$\Gamma \vdash e : t \implies \Gamma \vdash \text{auto } x = e : \text{drop-ref-cv}(t)$$

| 表达式 | 推断结果 |
|--------|----------|
| `auto x = expr` | 移除 expr 类型的引用和 cv 限定符 |
| `decltype(expr)` | 保留 expr 的原始类型（含引用、含 cv） |
| `decltype((expr))` | 双括号永远是引用（即使 expr 是纯右值） |

`decltype(auto)` 的设计动机：函数返回 `auto` 时应用上述规则丢弃引用，返回 `decltype(auto)` 则保留原始类型。

## 参考存根

```cpp
#include <memory>
#include <algorithm>
#include <vector>

// 移动语义演示：所有权转移
std::unique_ptr<int> p1 = std::make_unique<int>(42);
std::unique_ptr<int> p2 = std::move(p1);  // p1 变为空，p2 接管资源
// p1 不再拥有资源，析构时无操作

// shared_ptr 引用计数
std::shared_ptr<int> p3 = std::make_shared<int>(42);
std::weak_ptr<int> w = p3;  // 观察，不增加计数
// weak_ptr 用于打破循环引用

// lambda 与泛型算法
std::vector<int> v{1, 2, 3, 4, 5};
auto it = std::find_if(v.begin(), v.end(), [](int n) { return n > 3; });
```

## 适用场景

<pre>
性能敏感 → 游戏引擎、实时交易、数据库内核、图形渲染
                ↑
         热路径优化：每帧数百万次调用，零抽象开销至关重要

资源受限 → 嵌入式实时系统、操作系统内核、设备驱动
                ↑
         无运行时（no-JVM/no-GC），直接操作硬件寄存器

混合范式 → 热路径（低层次手写汇编）+ 业务逻辑（高层次抽象）
                ↑
         按需切换抽象层级，不强制统一
</pre>

**不适用场景**：
- 快速原型（Python）：动态类型 + REPL 优先
- Web 后端（Go/Java）：GC + 并发原生支持优先
- 数据分析（Python/R）：交互式 + 库生态优先
