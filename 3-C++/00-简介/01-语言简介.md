# C++ 语言简介

## 定义

**C++ 是系统级编程语言，通过零成本抽象在性能与表达力之间取得平衡。**

C++ 溯源于 C，以 `++` 运算符暗示" C 的下一阶段"，同时保留 C 的硬件控制能力。设计者 Bjarne Stroustrup 的核心洞察是：高级抽象不应带来运行时开销。这一原则贯穿所有现代特性。

## 数据流

<pre>
源代码 (.cpp)
    ↓ 编译器（clang/gcc/msvc）
目标代码 (.o)
    ↓ 链接器
可执行文件
    ↓ 操作系统加载
进程 → 内存中的指令与数据
</pre>

| 年份 | 标准 | 关键机制 |
|------|------|----------|
| 1983 | C++ 诞生 | 类、虚函数、引用——将 OOP 引入 C 的骨架 |
| 1998 | C++98 | STL——容器与算法的泛型抽象，零成本复用 |
| 2003 | C++03 | 缺陷修复，无新特性 |
| 2011 | C++11 | 移动语义消除拷贝开销，lambda 压缩匿名函数语法，nullptr 替代 unsafe NULL |
| 2014 | C++14 | 泛型 lambda 扩展参数推导，变量模板简化常量表达式 |
| 2017 | C++17 | if constexpr 编译期分支，optional/variant 提供类型安全的结果封装 |
| 2020 | C++20 | Concepts 约束模板参数，协程简化异步逻辑，ranges 延迟求值链式变换 |
| 2023 | C++23 | std::expected 替代异常，constexpr 更多限制解除 |
| 2026 | C++26 | 编译期反射减少重复代码，std::execution 并行算法接口 |

## 机制

### 为什么 C++ 保留与 C 的兼容性

C++ 在 1983 年诞生时面临一个关键决策：完全另起炉灶，还是站在 C 的遗产上演进。选择后者意味着继承 C 的内存模型（裸指针、数组）和调用约定，使现有 C 代码库可直接作为 C++ 编译。但兼容性是有界的——C++ 的 `class` 关键字、引用类型、模板语法在 C 中不存在；反过来，C 的 `void*` 隐式转换、隐式 `int` 返回值在 C++ 中被禁用。这不是因为设计失误，而是因为 C++ 选择在兼容基础上强制类型安全。

### 为什么智能指针解决手动内存管理问题

手动 `malloc/free` 的问题是所有权不明确——谁该释放、何时释放没有语言层面的约束。RAII（Resource Acquisition Is Initialization）通过构造函数获取资源、析构函数释放资源，将生命周期与作用域绑定。`std::unique_ptr` 用移动语义转移独占所有权，`std::shared_ptr` 用引用计数追踪共享所有权，`weak_ptr` 打破循环引用。编译器在编译期插入析构调用，无需垃圾回收，因此没有 GC 暂停。

### 为什么 lambda 重要

函数指针曾是 C 回调的唯一手段，但无法捕获上下文。lambda 将匿名函数对象具名化：捕获列表决定如何绑定环境，参数列表声明接口，返回类型推导消除冗余语法。在 STL 算法中这尤其关键——`std::find_if`、`std::transform` 接收可调用对象，lambda 使内联短回调无需单独定义函数。

### 为什么 auto 推断是安全的

C++ 是强类型语言，`auto` 不代表"动态类型"，而是让编译器根据初始化表达式推断静态类型。`decltype` 补充推断保留引用和 cv 限定符。推断结果在编译期确定，无运行时开销。唯一陷阱是 `auto x = {1, 2, 3}` 推断为 `std::initializer_list`，而非 `std::vector`。

## 参考代码

```cpp
#include <memory>
#include <algorithm>
#include <vector>

std::unique_ptr<int> p1 = std::make_unique<int>(42);
std::shared_ptr<int> p2 = std::make_shared<int>(42);
std::weak_ptr<int> p3 = p2;

std::vector<int> v{1, 2, 3, 4, 5};
auto it = std::find_if(v.begin(), v.end(), [](int n) { return n > 3; });
```

## 适用场景

<pre>
性能敏感 → 游戏引擎、实时交易、数据库内核、图形渲染
资源受限 → 嵌入式实时系统、操作系统内核、设备驱动
混合范式 → 需要同时优化热路径（低层次）与业务逻辑（高层次）
</pre>

不适用：快速原型（Python）、Web 后端（Go/Java）、数据分析（Python/R）
