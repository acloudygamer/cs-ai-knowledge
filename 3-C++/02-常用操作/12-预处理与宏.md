# 预处理与宏

## 定义

预处理是 C++ 编译的**词法分析阶段**（translation phase 4），运行于语法分析之前。它的本质是**纯文本替换系统**：预处理指令（`#define`, `#if`, `#include` 等）对 Token 流进行操作，输出仍是 Token 流但内容已被改写。宏是文本替换的符号标记，通过参数化实现**编译期计算**和**代码生成**。

**关键约束**：预处理器的输入和输出都是 **Token 流**，不是 AST（抽象语法树）。它不理解 C++ 语法，因此文本替换可能在语义层面产生意外结果。

## 数学模型

**宏作为符号替换系统（SSS）**：

宏系统本质上是 **Chomsky 0型文法**（无限制文法）的工程实现——它允许任意 Token 序列替换为另一个 Token 序列，没有任何语法约束。

形式化定义：
$$\text{SSS} = (T, M, \text{expand})$$

其中 $T$ 是 Token 集合，$M$ 是宏定义集合，$\text{expand}$ 是替换函数。这与形式语言的关系：

| 文法类型 | 产生式形式 | 与宏的关系 |
|----------|-----------|-----------|
| 3型（正则） | $A \rightarrow aB$ 或 $A \rightarrow a$ | 不够表达宏参数替换 |
| 2型（上下文无关） | $A \rightarrow \alpha$ | 参数替换的简化模型 |
| 1型（上下文敏感） | $\alpha A \beta \rightarrow \alpha \gamma \beta$ | 宏替换可近似此形式 |
| 0型（无限制） | $\alpha \rightarrow \beta$ | 宏替换等价于 0型文法 |

**宏展开的递归形式化**：

设宏系统为 $\text{Macro}: \text{Token}^* \rightarrow \text{Token}^*$。宏定义 $M$ 将参数替换为函数体：

$$\text{expand}(M(a_1, a_2, \ldots, a_n)) = \text{subst}(\text{body}(M), \{p_1 \mapsto a_1, p_2 \mapsto a_2, \ldots\})$$

**Token 替换的语义与未定义行为**：

`#define SQUARE(x) ((x)*(x))` 展开为：
- 输入：`SQUARE(5)` → 输出：`((5)*(5))`
- 输入：`SQUARE(x++)` → 输出：`((x++)*(x++))` → **未定义行为（UB）**

**为什么 `SQUARE(x++)` 是 UB**：

表达式 `x++` 的求值顺序在 C++ 标准中**未指定**（unspecified，不是未定义）。宏的参数是**Token 替换**，不是值传递：

1. 展开为 `((x++)*(x++))`
2. C++ 标准不保证 `x++` 的副作用在 `*` 运算前完成
3. 两个 `x++` 可能在同一个序列点上求值，导致 `x` 被递增两次或结果不确定
4. 编译器可以自由重排、合并或消除此表达式

正确写法应使用临时变量或内联函数（C++11 constexpr）。

**条件编译的布尔代数**：

`#if` 表达式是整数常量表达式，遵循 C++ 整数算术规则：

$$\text{expr} \in \mathbb{Z}, \quad \text{defined}(M) \in \{0, 1\}$$

$$\text{true} \iff \text{expr} \neq 0$$

多条件组合：
$$\text{#if } A \land B \iff \text{#if } A \text{ && } B$$
$$\text{#if } A \lor B \iff \text{#if } A \text{ || } B$$

**字符串化和 `##` 拼接的约束**：

- `#x`：将 Token 序列 `x` 转换为字符串字面量
- `a ## b`：将两个 Token 拼接为一个 Token（不可跨宏边界）

**VA_ARGS 的展开规则**：

C++20 `__VA_OPT__(, )` 解决空参数列表问题：

$$\text{LOG(fmt, ...)} \rightarrow \text{fprintf(stderr, fmt __VA_OPT__(,) __VA_ARGS__)}$$

若 `__VA_ARGS__` 为空，`__VA_OPT__(,)` 展开为空，而非产生悬挂逗号。

**`#include` 的搜索路径**：

```
#include <header>    → 系统路径搜索
                     CPLUS_INCLUDE_PATH / 默认系统路径

#include "header"    → 当前目录优先
                     → 未找到则按 <header> 处理
```

**宏展开的时机与编译阶段模型**：

预处理是编译的**第一阶段**（Translation Phase 4），发生在所有语义分析之前：

```
源代码字符流
      │
      ▼ Phase 1-2: 字符编码 + Token化
Token 流
      │
      ▼ Phase 3: 预处理 ← 宏在这里展开
预处理后 Token 流（仍是 Token 流，不是 AST！）
      │
      ▼ Phase 4-11: 编译（Parser → AST → IR → 目标代码）
可执行文件
```

**宏展开时机的影响**：

因为宏在语义分析**之前**展开，所以：

1. **可用于编译期常量上下文**：
   ```cpp
   #define ARRAY_SIZE 100
   int arr[ARRAY_SIZE];  // 合法：宏展开后是常量
   ```

2. **`#if` 条件分支**：
   ```cpp
   #if __cplusplus >= 202002L  // 宏展开后变成整数常量比较
   // C++20 代码
   #endif
   ```

3. **不受类型约束**：宏参数可以是任何 Token 序列，不一定是类型正确的 C++ 表达式。

**宏展开的递归时机**：

宏展开是**惰性的**：只在展开后的 Token 流再次遇到宏调用时才继续展开。

```
#define A 1
#define B A  // B 定义为 Token "A"

int x = B;  // 展开为 A → 再展开为 1 → 结果：int x = 1;
```

这称为**延迟替换**（deferred substitution）。

**与模板实例化的对比**：

| 维度 | 宏 | 模板 |
|------|-----|------|
| 展开时机 | 预处理（Phase 3，词法阶段） | 编译（Phase 7+，语义阶段） |
| 类型检查 | 无 | 有（SFINAE、约束检查） |
| 实例化结果 | 文本替换 | 类型推导 + 代码生成 |
| 调试信息 | 展开后位置（#line 可调） | 模板定义位置 |

**为什么模板不能完全替代宏**：

- 宏可以构造**Token**（`##` 拼接），模板只能操作**类型/值**
- 宏可用于 `#if` 条件编译，模板不行
- 宏可用于 `case` 标签，模板不行
- 宏可以构造**标识符名称**（`CONCAT(a, b)` 产生新的标识符）

## 机制

**宏与模板的本质区别**：

| 维度 | 宏 | 模板 |
|------|-----|------|
| 展开时机 | 预处理（词法阶段） | 编译（语义阶段） |
| 类型感知 | 无（纯文本替换） | 有（依赖 C++ 类型系统） |
| 调试信息 | 展开后位置（#line 可调整） | 模板实例化位置 |
| 递归支持 | 受限于展开深度 | 支持 SFINAE/折叠表达式 |

**do-while(0) 的必要性（形式化证明）**：

宏在 `if-else` 中的使用产生语法歧义：

```cpp
#define BAD(x) if (x) do_something();

// 展开后（else 悬挂）
if (x)
    do_something();
else  // ❌ else 无对应 if
    do_other();
```

**为什么不能用空语句 `{}`**：

```cpp
#define BAD2(x) if (x) {}

// if (x); ← 空语句 if
// else ← else 悬挂
```

**为什么不能用 `while(0)` 不带 do**：

```cpp
#define BAD3(x) while(0) {}

// while(0) { } ← 循环体只执行一次，但后缀分号产生语法错误
// if(x) while(0) { }; ← 分号使 if 语句结束，else 悬挂
```

**形式化证明：do-while(0) 是唯一正确的模式**

设宏展开结果为 $S$，期望在 `if (cond) S; else ...` 中使用。

要求：
1. $S$ 是一个**完整语句**（statement），不是语句序列
2. $S$ 后面不能有悬挂的分号问题

do-while(0) 的结构：
```cpp
do { /* body */ } while(0)
// 展开后等价于单个语句：{ /* body */ };
```

在 `if (cond) do { } while(0);` 中：
- `do { } while(0);` 是**一个语句**（do-while 是单一语法结构）
- 末尾分号属于 `while(0);` 的一部分，不是悬挂分号
- `if (cond) do { } while(0); else ...` 语法正确

**为什么不用 `({ ... })`**（GNU 扩展）：

`({ })` 是**表达式**，不是语句，不能在所有需要语句的上下文中使用（如 `if` 后面）。

**do-while(0) 的展开保证**：

无论宏参数是什么，`do { } while(0)` 始终展开为一个完整语句，且不在末尾留下悬挂的分号问题。

**`#` 字符串化规则的微妙之处**：

`#x` 发生在宏展开**之后**，再进行字符串化：

```cpp
#define STRINGIFY(x) #x
#define VALUE 42

STRINGIFY(VALUE)      // "42"（宏已展开，再字符串化）
STRINGIFY(VALUE + 1)  // "42 + 1"（而非 "43"）
```

**字符串化的数学形式化**：

设 Token 序列为 $t_1, t_2, ..., t_n$，字符串化操作 $S$：
$$S(t_1 t_2 ... t_n) = \text{"} t_1 \text{ } t_2 \text{ } ... \text{ } t_n \text{"}$$

其中空格是 Token 间的分隔符。

**`##` 拼接的约束**：

`##` 在宏展开**之后**执行，且不能拼接产生无效 Token：

```cpp
#define CONCAT(a, b) a ## b
CONCAT(vec, tor)      // 拼接为 vector（有效）
CONCAT(+, >>)         // 拼接为 >>（有效，但罕见用法）
```

**拼接的类型论意义**：

`##` 是 Token 层面的拼接，不考虑 C++ 语法或类型系统。拼接结果必须是有效的 Token 序列，但不一定是有效的 C++ 代码。

**条件编译的典型应用**：

```cpp
// 跨平台检测
#if defined(_WIN32)
    #define PLATFORM_NAME "windows"
#elif defined(__linux__)
    #define PLATFORM_NAME "linux"
#endif

// C++ 版本检测
#if __cplusplus >= 202302L
    #define HAS_CXX23 1
#elif __cplusplus >= 202002L
    #define HAS_CXX20 1
#endif

// 调试辅助
#ifdef DEBUG
    #define LOG(fmt, ...) fprintf(stderr, "[DEBUG] " fmt, __VA_ARGS__)
#else
    #define LOG(...)      // 空宏
#endif
```

**`__FILE__` / `__LINE__` 的实现**：

编译器在 Token 化时注入特殊 Token：
- `__FILE__`：替换为 `"filename"` 字符串字面量
- `__LINE__`：替换为当前行号（整数常量）

两者常用于**自检断言**：

```cpp
#define STATIC_ASSERT(expr, msg) \
    _Static_assert(expr, msg)  // C11/C++17

#define ASSERT(expr) \
    ((expr) ? void(0) : abort())
```

**约束条件与违反后果**：

- **宏参数重复求值导致未定义行为**：
  ```cpp
  #define SQUARE(x) ((x)*(x))
  int a = 5;
  int b = SQUARE(a++);  // UB：((a++)*(a++))
  // 正确做法：使用临时变量或 constexpr 函数
  ```
  原因：宏是纯文本替换，`a++` 被替换两次，产生两个递增副作用，在 C++ 的"未指定行为"规则下，同一序列点内的副作用顺序未定义。

- **宏与作用域**：宏的作用域是文件级别，无法限制在命名空间或类内。解决方案：用 `inline` 函数或 `constexpr` 函数替代。

- **`#include` 循环**：`a.h` 包含 `b.h`，`b.h` 又包含 `a.h` → 预处理死递归（实际会因头文件 guards 而终止）。

- **宏的命名冲突**：宏无命名空间，与第三方库的宏可能冲突（如 Windows 的 `min`/`max` 宏）。解决方案： `#undef min` 后使用 `std::min`，或使用编译选项 `-DNOMINMAX`。

- **宏展开导致语法冲突**：
  ```cpp
  #define if(x) if (x)  // 危险！
  if (x) do_something();  // 展开后：if (x) do_something();
  ```
  宏可以重定义语言关键字，但这会导致灾难性的语义混淆。编译器不保护这类误用。

## 参考存根

```cpp
// 标准断言宏（标准库）
#include <cassert>
static_assert(sizeof(int) >= 4, "int must be at least 32 bits");

// 条件编译与宏结合
#define CONCAT_IMPL(a, b) a##b
#define CONCAT(a, b) CONCAT_IMPL(a, b)

#ifdef __cplusplus
    extern "C" {
#endif
        void legacy_c_func(int);
#ifdef __cplusplus
    }
#endif

// C++20 引入 __VA_OPT__
#define LOG(fmt, ...) \
    fprintf(stderr, fmt __VA_OPT__(,) __VA_ARGS__)

LOG("info: %s", "hello");    // fprintf(stderr, "info: %s", "hello");
LOG("info: %s");            // fprintf(stderr, "info: %s");  // 无悬挂逗号
```
