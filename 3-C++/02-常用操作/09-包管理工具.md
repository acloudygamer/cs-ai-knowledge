# 包管理工具

## 定义

C++ 包管理工具解决**第三方库发现、下载、编译和链接的自动化问题**。包管理器维护一个**依赖图**（节点=包，边=版本约束），通过**约束求解**确定兼容的版本组合，解决依赖冲突，最终产出可集成到构建系统的工件（头文件、库文件、元数据）。

## 数学模型

**版本约束的数学表示**：

 $c \in \{[l, u] \mid l, u \in \mathbb{V} \cup \{-\infty, +\infty\}\}$ 

其中 $\mathbb{V}$ 是版本空间。多个约束的合取： 是版本空间。多个约束的合取：

 $\bigwedge_i c_i = \bigcap_i c_i$

**Conan SAT 求解器的形式化**：

Conan 的依赖求解可建模为布尔可满足性问题（SAT）：

1. **变量**：每个包版本 $P_v$ 对应布尔变量 对应布尔变量
2. **子句**：约束条件转换为 CNF 子句
3. **求解**：CDCL（Conflict-Driven Clause Learning）求解器

约束转换示例：
```
requires: pkg/1.0.0  →  (pkg_1_0_0)
conflicts: pkg/[>1.0.0]  →  (!pkg_1_0_0 ∨ !pkg_1_1_0 ∨ !pkg_1_2_0 ∨ ...)
```

## 机制

**vcpkg 的 triplet 机制**：

Triplet 是 vcpkg 的目标平台抽象，包含三个维度：CPU 架构（`x64`, `arm64`）、操作系统（`windows`, `linux`, `mac`）、链接方式（`static`, `dynamic`）。每个 triplet 决定库的编译配置和安装路径。

```
${VCPKG_ROOT}/triplets/
  ├── x64-linux.cmake
  ├── x64-windows-static.cmake
  └── arm64-windows.cmake
```

Triplet 的数学表示：
 $T = (arch, os, linkage)$ 

其中 $arch \in \{\text{x64}, \text{x86}, \text{arm64}, \dots\}$ ， $os \in \{\text{windows}, \text{linux}, \text{mac}\}$,  $linkage \in \{\text{static}, \text{dynamic}\}$。 ， $os \in \{\text{windows}, \text{linux}, \text{mac}\}$ ,  $linkage \in \{\text{static}, \text{dynamic}\}$。,  $linkage \in \{\text{static}, \text{dynamic}\}$ 。。

**Conan 的远程仓库与冲突**：

Conan 支持多个远程仓库（`conan remote add`），搜索顺序由用户控制。当两个包声明冲突的版本约束时，Conan 的求解器尝试分支定界搜索：

1. 选择一个冲突包，尝试不同版本
2. 递归求解
3. 若所有分支无解，报告冲突

**冲突的数学定义**：

 $\nexists v_P \in V_P, v_Q \in V_Q: v_P \models C_P \land v_Q \models C_Q \land \text{compatible}(v_P, v_Q)$

**vcpkg 依赖图的构建过程**：

vcpkg 的依赖解析是**贪心爬山法**（Hill Climbing）：

1. 从项目 `vcpkg.json` 的直接依赖开始
2. 对每个未解析的包，选择满足约束的**最新版本**
3. 递归解析该包的传递依赖
4. 若遇到版本冲突，尝试次新版本

这与 SAT 求解器不同——vcpkg 不做全局最优搜索，只做局部最优选择。因此在某些复杂依赖场景下，vcpkg 可能无法找到解，而 Conan 的 SAT 求解器保证全局最优。

**贪心求解的局限性**：

```
场景：
  A 需要 B>=1.0, C>=2.0
  B 最新=1.5，需要 D<1.5
  C 最新=2.5，需要 D>=1.5

  vcpkg 贪心：
    1. A: 选择 B=1.5, C=2.5
    2. B=1.5 需要 D<1.5 → 选择 D=1.4
    3. C=2.5 需要 D>=1.5 → 冲突！

  SAT 求解：
    1. 尝试 B=1.5, C=2.5 → 冲突
    2. 回溯：尝试 B=1.5, C=2.0 → D=1.4 满足两者
    3. 解：B=1.5, C=2.0, D=1.4
```

**Conan 的依赖求解器架构**：

Conan 使用 **CDCL（Conflict-Driven Clause Learning）** SAT 求解器：

```python
# 伪代码：Conan 依赖求解
def solve(dependencies):
    clauses = []  # CNF 子句集
    for pkg, version_constraint in dependencies:
        clauses.extend(to_cnf(pkg, version_constraint))
    return sat_solver.solve(clauses)  # 返回所有满足的版本组合
```

冲突回溯：当求解器遇到矛盾（如 Pkg A 要求 B≥2.0 但 C 要求 B<2.0），它学习一个阻止该组合的子句，并回溯到上一个分支点。

**约束条件与违反后果**：

- **vcpkg**：若目标 triplet 未预配置，需交叉编译时可能失败；源码依赖 git 可能受网络限制。
- **Conan**：二进制制品与编译器版本强耦合（`GCC 11.2` 编译的制品不能用于 `GCC 12.1`），需正确配置 `settings`。
- **共同问题**：传递依赖的版本回溯可能引入不兼容（"diamond dependency"），通常依赖求解器自动降级解决。
