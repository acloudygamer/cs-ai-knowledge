# 文件操作

## 定义

文件操作是将程序内存中的数据类型转换为字节序列并持久化到存储介质的机制。其本质是**字节序列与内存数据结构之间的双向同构映射**，通过操作系统内核的系统调用接口和虚拟内存子系统完成数据形态的跨越。

### C++23 版本的格式化输出

> **latest 预览**：本节介绍 C++23 的 `std::print`。stable（C++20）等价写法为 `std::cout << std::format("...\n", ...)`。

**[C++23]** `std::print` 是 C++23 引入的格式化输出函数，相比 `std::format` + `std::cout` 更简洁：

```cpp
std::print("Name: {}, Age: {}\n", name, age);  // 直接输出，自动刷新
std::print(stderr, "Error: {}\n", msg);         // 可指定输出流
```

`std::print` 的核心优势：
- 自动调用 `std::flush`，避免缓冲导致的输出丢失
- 语法比 `std::cout << std::format(...)` 更紧凑
- 性能与 `printf` 相当（无运行时格式化开销解析）

## 数据流

### 流式文件I/O的数据形态变换

<pre>
内存（程序变量）          流缓冲区（内核）           页面缓存（内核）         磁盘块（存储介质）
+---------------+       +----------------+       +----------------+       +---------------+
| int x = 42;   | write | [字节序列]      | flush | [脏页]          | 同步  | [磁盘块]       |
| 4字节          |  ───> | 未刷出的数据    | ────> | 待回写          | ────> | 持久化数据     |
+---------------+       +----------------+       +----------------+       +---------------+
         │                      │                        │
         └── 所有权：程序写入 ──┘ 所有权：内核缓冲 ───────┘ 所有权：设备驱动
</pre>

**步骤**：
1. 程序调用 `operator<<` 将数据序列化到用户态流缓冲区。
2. 缓冲区满或显式 `flush()` 时，触发 `write()` 系统调用（用户态→内核态切换）。
3. 内核将数据拷贝到页面缓存（page cache）的脏页。
4. `fsync()` 或内核周期回刷（通常 30 秒）将脏页写入磁盘块设备。
5. 磁盘控制器通过 DMA 将数据持久化到 NAND Flash 或磁盘盘片。

**所有权转移**：程序变量 → 流缓冲区 → 页面缓存 → 磁盘块。撤销发生在 `fclose` 或 `fflush` 时。

## 机制

### 流缓冲区的设计约束

**为什么需要缓冲区**：每次系统调用（`read`/`write`）都涉及用户态→内核态的上下文切换，代价约为 $0.5\!-\!2\,\mu s$。若无缓冲区，写入 1 字节需要一次系统调用；4096 字节的缓冲区使每 4096 次内存写才触发一次系统调用。 。若无缓冲区，写入 1 字节需要一次系统调用；4096 字节的缓冲区使每 4096 次内存写才触发一次系统调用。

**缓冲区满刷新的触发条件**：
- 显式调用 `flush()` 或 `fclose()`
- 缓冲区已满（写入第 $B$ 个字节时） 个字节时）
- 程序正常结束（析构函数自动调用 `fclose`）
- 进程收到信号（部分实现会刷新缓冲区）

**违反约束的后果**：
- 缓冲区未刷新时程序崩溃，数据停留在流缓冲区，未写入磁盘（数据丢失）。
- 多线程同时写入同一 `fstream` 未使用同步机制，写入序列交错（数据竞争）。

### seek的字节偏移量映射

`seekg/tellg` 本质上操作的是**字节偏移量**（file offset），与物理磁盘块无关。偏移量是逻辑地址，通过文件系统地址翻译（inode → extent → 物理块）映射到物理位置。

- `seekg(pos)` 将读指针设置为相对于文件开头的第 `pos` 字节。
- `seekg(off, dir)` 将读指针设置为相对于 `dir`（`beg`/`cur`/`end`）的第 `off` 字节。
- `tellg()` 返回当前读指针相对于文件开头的偏移量，类型为 `std::streampos`。

**约束**：`seekg` 可跳转到任意位置（随机访问），但对管道设备（如 `std::cin`）调用 `seek` 会设置失败标记。

### mmap的写入语义

mmap 的 `PROT_WRITE` + `MAP_SHARED` 使对映射内存的写入直接进入页面缓存，修改后的页标记为"脏"。脏页在以下时机回写磁盘：

1. `msync(addr, len, MS_SYNC)` 同步回写（阻塞直到完成）。
2. `msync(addr, len, MS_ASYNC)` 异步回写（不阻塞）。
3. 内核周期回刷（默认 30 秒）。
4. 页面被淘汰（LRU）时。
5. `munmap` 或进程退出时。

**约束**：若在 `msync` 完成前回写磁盘之前访问已修改的页，读到的是页面缓存中的新数据（一致性保证）。但若磁盘写入完成前系统崩溃，数据可能丢失。

### flock的咨询锁语义

flock 是**咨询锁**（advisory lock）：内核仅维护锁状态，不阻止未经授权的进程直接 `write()` 文件。这意味着所有访问文件的进程必须合作使用锁才能实现互斥。

**锁类型**：
- `LOCK_EX`（排他锁）：同一时刻仅一个进程持有，写操作使用。
- `LOCK_SH`（共享锁）：多个进程可同时持有，读操作使用。
- `LOCK_NB`（非阻塞）：立即返回而非阻塞等待。

**死锁条件**：若进程 A 持有排他锁并等待进程 B 持有的另一个锁，而进程 B 反过来等待进程 A 的锁，则死锁。flock 不支持嵌套（同一文件描述符第二次 `flock` 会导致锁升级或失败）。

### rename原子性的底层保证

POSIX `rename()` 保证：若新文件名已存在，则**新文件名和旧文件名在 rename 完成前不可同时指向有效数据**。这是通过目录条目的原子替换实现的——内核通过单个 inode 引用计数的修改完成两个名字的切换，无中间态。

**违反约束的后果**：
- 若 rename 前崩溃：临时文件残留，原文件不变（可恢复）。
- 若 rename 后崩溃：rename 已完成，数据已在目标路径（已持久化）。
- 不使用 rename 而直接写入：若写入时崩溃，可能同时损坏原文件和临时文件。

// mmap 读文件（展示按需分页机制）
int fd = open("data.bin", O_RDONLY);
struct stat sb;
fstat(fd, &sb);
void* addr = mmap(nullptr, sb.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
// 首次访问任意页触发 page fault，物理页从磁盘读入
char c = static_cast<char*>(addr)[0];
munmap(addr, sb.st_size);
close(fd);
