# 01-C++视角的设计模式

> 前置：[04-类与资源管理](../01-语言核心/04-类与资源管理.md)（RAII 与拷贝控制）、[06-模板与Concepts](../01-语言核心/06-模板与Concepts.md)（模板机制） · 后续：[03-链接与ABI](../04-性能与底层/03-链接与ABI.md)（Pimpl 的 ABI 背景）

> **版本基准**：C++20；C++23/26 特性行内标注。示例实测环境：GCC 14.2（MinGW-w64，Windows）。

GoF（1994）的 23 个模式写于 C++98/Smalltalk 的语境，回应的是当时语言的缺口：没有 `std::function`、没有 `variant`、没有 lambda、拷贝语义混乱。现代 C++（11 起）陆续把这些缺口填进语言与标准库，于是一批模式**隐形**——退化为一次拷贝构造、一个 `std::function` 形参——另一批的复杂度是问题本质自带的，语言帮不上，**仍然活着**。本篇按这个判决组织，而不是按 GoF 的三类目录复述。

## 本质

模式是**语言缺口的补丁**：同一问题在不同语言里是模式还是语法，取决于语言给了什么机制（同一判据在 Python 侧的展开见 [2-Python 设计模式](../../2-Python/05-设计模式/01-Python视角下的设计模式.md)）。C++ 的三根支柱各自吃掉一批模式：

- **值语义 + RAII**：对象是值、确定性析构、拷贝由拷贝构造/赋值运算符定义——"复制对象"与"托管资源"不再需要专门的模式。
- **模板（编译期多态）**：行为替换可以在编译期完成，不付虚表间接跳转——"换算法"可以是模板参数而不是接口继承。
- **`std::function`/lambda/`variant`（标准库的一等抽象）**：回调与"几种类型之一"成为内建概念，命令与访问者的手写骨架消失。

## GoF 23 判决表

| 判决 | 模式 | 现代 C++ 对应物 |
|---|---|---|
| 语言/标准库内建 | 原型 | 拷贝构造函数（[05-移动语义与拷贝控制](../01-语言核心/05-移动语义与拷贝控制.md)） |
| | 命令 | `std::function` + lambda（可排队、可撤销时退化为函数对象） |
| | 访问者 | `std::variant` + `std::visit`（编译期穷尽性检查，比虚函数版更严） |
| | 迭代器 | 迭代器概念本身即标准库地基（[02-迭代器与算法](../02-标准库/02-迭代器与算法.md)） |
| | 模板方法 | CRTP（静态绑定版，见下）或普通虚函数 |
| | 享元 | `std::shared_ptr` 共享不可变对象 |
| 仍活着（复杂度是本质的） | 工厂 | 创建逻辑与使用解耦；返回 `std::unique_ptr` 表达所有权转移 |
| | 观察者 | 一对多通知 + 生命周期管理（`weak_ptr` 防悬挂） |
| | 适配器 | 接口不匹配永远存在；C++ 里常用薄包装类或 lambda 转调 |
| | 装饰器 | 运行时叠加职责仍需持有同一接口的指针链 |
| | 组合、状态、责任链、中介者、代理、建造者、抽象工厂、桥、外观、备忘录、解释器 | 结构复杂度是问题自带的，照 GoF 写，用智能指针换掉手工 `delete` |
| 通常不需要 | 单例的旧形态 | DCLP + 互斥锁已被 Meyers 单例取代（见下） |

读法：左两类是"知道对应物即可"——写代码时不要再搭 GoF 骨架；中间一类才有真实复杂度要管理。

## 机制

### 策略的分野：模板参数（编译期）vs 函数对象（运行时）

策略模式的核心是"算法可替换"，C++ 有两个替换时机，约束是**绑定时机决定代价与灵活性**：

| | 模板参数 | `std::function` 函数对象 |
|---|---|---|
| 绑定时机 | 编译期：`apply_all(v, MyStrategy{})` 实例化出专用代码 | 运行时：赋值即换策略 |
| 代价 | 零间接（可内联） | 一次间接调用 + 可能的堆分配 |
| 灵活性 | 策略在类型里写死，不同策略是不同对象类型 | 同一变量可持任意可调用物 |
| 主场 | 策略在编译期已知（排序比较器、分配器） | 策略来自运行时输入（用户配置、脚本回调） |

判据：换策略的需求发生在编译前还是运行中。STL 的排序比较器走第一条路（`std::sort` 的比较器是模板参数），GUI 事件回调走第二条。

### CRTP：静态多态

奇异递归模板模式（CRTP，Curiously Recurring Template Pattern）：**基类以派生类为模板参数**，基类通过 `static_cast<Derived*>(this)` 下行调用派生类实现：

```cpp
template <typename Derived>
class Shape {
public:
    void draw_twice() const {   // 基类复用派生类的 draw()
        static_cast<const Derived*>(this)->draw();
        static_cast<const Derived*>(this)->draw();
    }
};
class Circle : public Shape<Circle> {
public:
    void draw() const { /* ... */ }
};
```

机制：模板实例化 `Shape<Circle>` 时，`Circle` 的完整定义已可见（实例化点在使用处，此时派生类已定义完毕——这就是"奇异递归"合法的原因），`static_cast` 与调用都在编译期定案。对比虚函数：虚表指针占对象 8 字节（x86-64）、调用经一次间接跳转、运行期才能换实现；CRTP 三者皆无，代价是每个派生类实例化一份基类代码、且 `Shape<Circle>` 与 `Shape<Square>` 是**无共同基类的两个类型**——异构对象无法放进同一容器。约束：需要运行时异构多态（容器混装不同形状）时退回虚函数或 `variant`。

### Pimpl：编译防火墙

Pimpl（Pointer to Implementation，指针实现的惯用法）：公开类的头文件里只放一个指向实现类的不透明指针，实现类的完整定义收进 `.cpp`：

```cpp
// widget.h —— 编译防火墙的"墙"
class Widget {
    class Impl;                    // 前置声明，不完整类型
    std::unique_ptr<Impl> p_;      // unique_ptr 可持不完整类型（析构在 .cpp 定义）
public:
    Widget();
    ~Widget();                     // 必须声明在头、定义在 .cpp（Impl 完整处）
    void draw();
};
```

它回应的约束是**编译以翻译单元为单位、头文件是文本粘贴**（[01-语言定位与编译模型](../00-概览/01-语言定位与编译模型.md)）：实现细节写在头里，改一行私有成员就重编译全部包含者；收进 `.cpp` 后，改实现只重编一个单元。附带收益是 ABI 稳定——公开类的布局只剩一个指针，实现演进不破坏二进制兼容（机制展开见 [03-链接与ABI](../04-性能与底层/03-链接与ABI.md)）。代价：每次访问多一跳指针间接，对象从栈值变成堆分配。

### 单例的正当形态：Meyers Singleton

```cpp
class Registry {
    Registry() = default;
public:
    static Registry& instance() { static Registry r; return r; }
    Registry(const Registry&) = delete;
    Registry& operator=(const Registry&) = delete;
};
```

约束来自多线程首次访问的竞态：函数局部 `static` 的初始化必须恰好发生一次。C++11 起标准担保局部静态变量的初始化线程安全（并发到达时一个线程执行初始化、其余阻塞等待），于是旧形态的 DCLP（双重检查锁定）+ 互斥锁 + `memory_order` 三板斧整体作废。两个 `= delete` 封掉拷贝，全局唯一性由构造私有 + 删除拷贝共同担保。注意边界：Meyers 单例管"唯一与线程安全初始化"，不管"全局状态本身是不是好设计"——单例引入的隐式耦合依然存在，能传依赖注入就别用单例。

## 连接

模式的选择是质量权衡，而权衡要靠测试兜底：本篇所有"替换"（策略、注入、Pimpl）都以测试套件为安全网，见 [01-测试与调试](../05-测试与质量/01-测试与调试.md)。虚函数与模板的运行时代价对比（虚表布局、内联机会）见 [02-性能优化](../04-性能与底层/02-性能优化.md)。

**反模式提醒：模式癖**——模式的成本是间接层。只有一个实现的"策略接口"、永远不换的"工厂"，都是为模式而模式。判据倒过来用：先写直白代码，重复第二次、变化第三次出现时再提取模式。

## 示例

四个机制一篇跑通（GCC 14.2 MinGW 实测编译运行，`g++ -std=c++20 -static`）：

```cpp
#include <cstdio>
#include <functional>
#include <variant>
#include <vector>

template <typename Derived>                     // CRTP：基类以派生类为模板参数
class Shape {
public:
    void draw_twice() const {
        static_cast<const Derived*>(this)->draw();
        static_cast<const Derived*>(this)->draw();
    }
};
class Circle : public Shape<Circle> {
public:
    void draw() const { std::printf("circle\n"); }
};

template <typename Strategy>                    // 策略：编译期绑定
int apply_all(const std::vector<int>& v, Strategy s) {
    int acc = 0;
    for (int x : v) acc += s(x);
    return acc;
}

class Registry {                                // Meyers 单例
    Registry() = default;
public:
    static Registry& instance() { static Registry r; return r; }
    Registry(const Registry&) = delete;
    Registry& operator=(const Registry&) = delete;
    int count = 0;
};

struct Add { int delta; };                      // 访问者：variant + visit
struct Reset {};
using Command = std::variant<Add, Reset>;

int main() {
    Circle c; c.draw_twice();                   // circle circle

    std::vector<int> v{1, 2, 3};
    std::printf("%d\n", apply_all(v, [](int x) { return x * 2; }));   // 12：模板参数
    std::function<int(int)> rt = [](int x) { return x * 3; };
    std::printf("%d\n", apply_all(v, rt));                            // 18：函数对象

    Registry::instance().count = 41;
    std::printf("%d\n", Registry::instance().count + 1);              // 42

    int state = 10;
    for (Command cmd : {Command{Add{5}}, Command{Reset{}}})
        std::visit([&](auto c) {
            if constexpr (std::is_same_v<decltype(c), Add>) state += c.delta;
            else state = 0;
        }, cmd);
    std::printf("%d\n", state);                 // 0
}
```
