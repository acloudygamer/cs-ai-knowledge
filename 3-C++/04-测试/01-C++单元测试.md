# C++ 单元测试

## 本质断言

**单元测试是代码正确性的形式化证明手段，通过在隔离环境下执行受控输入并验证实际输出是否匹配预期，来排除回归错误并建立行为文档。**

## 为什么需要形式化验证

代码的正确性无法通过目测保证——人脑无法穷举所有执行路径。单元测试将"这段代码在边界条件下表现正确"这一命题，转化为可自动执行、可重复的机械检查。

```
测试失败 = 证明代码存在 bug
测试通过 = 在已覆盖路径上暂时无 bug 发现
```

### 回归防护

每次修改代码后，测试套件充当安全网。底层重构（替换算法实现而不改变接口）或新增功能（向后兼容的扩展）若破坏已有行为，测试立即捕获。

### 行为文档

测试即规格说明。`EXPECT_EQ(add(2, 2), 4)` 比注释"add 函数做加法"更精确——它不可欺骗地记录了预期行为。

## 核心机制

### 断言宏的语义

断言宏不是布尔检查的简单包装。GoogleTest 的 `EXPECT_*` 和 `ASSERT_*` 区别在于失败时的控制流：

```
EXPECT_EQ(a, b): 失败 → 当前测试函数继续执行
ASSERT_EQ(a, b): 失败 → 当前测试函数立即返回
```

这意味着 `ASSERT_*` 适用于不可恢复的前置条件（如 nullptr 检查），而 `EXPECT_*` 适用于验证点分散的测试。

### 测试夹具（Fixtures）的本质

Fixtures 是 RAII 资源管理的测试适配：构造时分配资源，析构时释放。GoogleTest 的 `SetUp()`/`TearDown()` 之所以优于手工 `new`/`delete`，是因为 C++ 保证析构函数即使测试异常退出也会执行——防止资源泄漏。

```cpp
class DatabaseTest : public testing::Test {
protected:
    ~DatabaseTest() override {
        // 即使测试崩溃，db_ 也会被释放
    }
    Database* db_{nullptr};
};
```

### 参数化测试的组合爆炸

参数化测试将测试数据与测试逻辑分离。用 $n$ 组参数实例化测试，时间复杂度从 $O(n)$ 降至 $O(1)$——每组参数只是测试函数的输入，不引入新代码路径。

```
INSTANTIATE_TEST_CASE_P(AddTests, AddTest,
    testing::Values(
        std::make_tuple(1, 2, 3),    // 3 组参数 → 3 次测试执行
        std::make_tuple(0, 0, 0),
        std::make_tuple(-1, 1, 0)
    )
);
```

## 数据流：测试执行生命周期

<pre>
[测试发现] → [Fixture构造] → [SetUp] → [测试体] → [TearDown] → [Fixture析构]
     ↑              一次性           每次         单次执行       每次        一次性
</pre>

- **测试发现**：链接时由 `gtest_discover_tests()` 提取所有 `TEST*` 宏，运行时动态注册
- **Fixture 构造/析构**：每个测试套件共享一次（构造在首个测试前，析构在末个测试后）
- **SetUp/TearDown**：每个测试用例前后执行，用于重置共享状态

## 框架对比

| 维度 | GoogleTest | Catch2 |
|------|-----------|--------|
| 头文件 | 多文件（需编译） | 单头文件（仅包含） |
| 断言风格 | `EXPECT_EQ` / `ASSERT_EQ` | `REQUIRE` / `CHECK` |
| 参数化 | `TEST_P` + `GetParam()` | `TEST_CASE_METHOD` +模板 |
| 测试发现 | `gtest_discover_tests()` | 编译期宏 |

**GoogleTest 适合大型项目**——丰富的生态、XML/JSON 输出、死亡测试；
**Catch2 适合快速引入**——零配置、语法更接近自然语言。

## CMake 集成

<pre>
cmake_minimum_required(VERSION 3.16)
project(MyProject)
enable_testing()

include(FetchContent)
FetchContent_Declare(googletest GIT_REPOSITORY ...)
FetchContent_MakeAvailable(googletest)

add_executable(tests test_main.cpp)
target_link_libraries(tests PRIVATE GTest::gtest GTest::gtest_main)

include(GoogleTest)
gtest_discover_tests(tests)  ← 将测试注册到 CTest
</pre>

`gtest_discover_tests()` 在**构建后**扫描已编译的测试二进制，将发现的测试注入 CTest——无需硬编码测试名称。

## 参考存根

```cpp
// GoogleTest 基础
#include <gtest/gtest.h>
TEST(MathTest, Addition) {
    EXPECT_EQ(2 + 2, 4);
}

// Catch2 基础
#define CATCH_CONFIG_MAIN
#include <catch2/catch_test_macros.hpp>
TEST_CASE("Math operations", "[math]") {
    REQUIRE(2 + 2 == 4);
}

// Fixture
class DatabaseTest : public testing::Test {
protected:
    void SetUp() override { db_ = new Database("test.db"); }
    void TearDown() override { delete db_; }
    Database* db_{nullptr};
};
TEST_F(DatabaseTest, Insert) {
    EXPECT_TRUE(db_->insert("key", "value"));
}

// 参数化
class AddTest : public testing::TestWithParam<std::tuple<int, int, int>> {};
TEST_P(AddTest, Values) {
    auto [a, b, expected] = GetParam();
    EXPECT_EQ(add(a, b), expected);
}
INSTANTIATE_TEST_CASE_P(AddTests, AddTest,
    testing::Values(std::make_tuple(1, 2, 3)));
```

> 所有代码 ≤20 行，无错误处理/日志/注释。
