# 调试与诊断

## GDB 基础

GDB 是 Linux 下主要的 C++ 调试器，支持源码级调试。

### 编译调试版本

```bash
# 编译时添加 -g 选项
g++ -g -O0 -Wall -o myapp myapp.cpp

# -g：生成调试信息
# -O0：关闭优化（避免代码被优化导致调试困难）
# -Wall：启用所有警告
```

### 启动与基本命令

```bash
# 启动程序
gdb ./myapp

# 带参数启动
gdb --args ./myapp --input file.txt

# 附加到运行中的进程
gdb -p <pid>

# 命令行直接运行
gdb -batch -ex "run" -ex "bt" -ex "quit" ./myapp
```

### 断点

```gdb
# 设置断点
break main
break myapp.cpp:42
break function_name

# 条件断点
break myapp.cpp:50 if count > 10

# 列出断点
info breakpoints

# 删除断点
delete 1
delete 2 3

# 禁用/启用
disable 1
enable 1

# 临时断点（命中断点后自动删除）
tbreak function_name
```

### 执行控制

```gdb
# 运行
run [args]

# 继续执行
continue

# 单步执行（进入函数）
step

# 单步执行（跳过函数）
next

# 单步执行（机器指令）
stepi
nexti

# 运行到指定位置
until 100

# finish：执行完当前函数
finish

# 杀死程序
kill
```

### 检查程序状态

```gdb
# 打印变量
print x
print *ptr
print array[0]@10  # 打印数组
print/x x          # 十六进制格式
print/d x          # 十进制格式
print/s str        # 字符串格式

# 打印局部变量
info locals

# 打印寄存器
info registers

# 查看内存
x/10x &array       # 10个十六进制字
x/10d &array       # 10个十进制字
x/s &str           # 字符串

# 查看调用栈
backtrace
bt                 # 简写
bt 5               # 只显示前5层

# 切换栈帧
frame 2
info frame
```

### 监视点（Watchpoints）

```gdb
# 监视变量变化
watch x

# 监视表达式
watch *(int*)0x12345678

# 读取监视（只停止读取）
rwatch x

# 访问监视（读取或写入都停止）
awatch x

# 列出监视点
info watchpoints
```

### 调试多线程

```gdb
# 列出线程
info threads

# 切换线程
thread 2

# 线程特定断点
break function_name thread 2

# 所有线程都停止
set scheduler-locking on

# 只在当前线程执行
set scheduler-locking step
```

### 调试 Core Dump

```bash
# 启用 core dump
ulimit -c unlimited

# 运行程序（崩溃后）
gdb ./myapp core

# 查看崩溃位置
bt
```

### 调试优化代码

```bash
# 混合源码和汇编
disassemble /s

# 显示调用约定
info args
info registers

# 查看内联函数
info frame
```

## LLDB（macOS/Linux）

## Valgrind

Valgrind 是内存调试工具，可检测内存泄漏和越界访问。

### 安装与运行

```bash
# Ubuntu/Debian
sudo apt install valgrind

# 运行 memcheck（默认工具）
valgrind --leak-check=full ./myapp

# 生成详细报告
valgrind --show-leak-kinds=all --track-origins=yes ./myapp
```

### 常见选项

```bash
# 内存泄漏检查
--leak-check=full

# 显示泄漏详情
--show-leak-kinds=all

# 跟踪内存来源
--track-origins=yes

# 输出到文件
--log-file=valgrind.out

# 细粒度检测
--freelist-vol=100000000
```

### 报告解读

```
==12345== Memcheck, a memory error detector
==12345== Copyright (C) 2002-2022, and GNU GPL'd, by Julian Seward et al.
==12345== Using Valgrind-3.19 and LibVEX

==12345== Invalid write of size 4
==12345==    at 0x...: main (myapp.cpp:50)
==12345==  Address 0x... is 0 bytes after a block of size 40 alloc'd
==12345==    at 0x...: malloc (vg_replace_malloc.c:...)

# 含义：
# Invalid write of size 4 - 在 myapp.cpp:50 写入4字节越界
```

## AddressSanitizer（ASAN）

ASAN 是编译器集成的内存错误检测工具，比 Valgrind 更快。

### 编译

```bash
# GCC/Clang
g++ -fsanitize=address -g -O1 myapp.cpp -o myapp

# 建议同时启用
g++ -fsanitize=address -fsanitize=undefined -g -O1 myapp.cpp -o myapp
```

### 常见错误类型

```bash
# 启用所有 sanitizer
-fsanitize=address
-fsanitize=undefined    # 未定义行为
-fsanitize=thread       # 数据竞争（需要单独启用）
-fsanitize=memory       # MSAN（内存顺序）
-fsanitize=leak         # 泄漏检测（退出时）
```

### 输出示例

```
=================================================================
==12345== ERROR: AddressSanitizer: heap-buffer-overflow on address 0x...
Write of size 4 at 0x... by thread T0:
    #0 0x... in main myapp.cpp:50

Heap left redzone:
    [<shadow memory>]
```

## ThreadSanitizer（TSAN）

检测数据竞争：

```bash
g++ -fsanitize=thread -g -O1 myapp.cpp -o myapp
```

## 性能分析工具

### gprof

```bash
g++ -pg -g -O1 myapp.cpp -o myapp
./myapp
gprof ./myapp gmon.out | less
```

### perf（Linux）

```bash
# 性能采样
perf record -g ./myapp

# 生成报告
perf report

# 特定事件
perf record -e cycles -g ./myapp
perf report --symbol-filter=my_function
```

### 火焰图

```bash
# 生成火焰图（使用 perf + flamegraph）
perf record -F 99 -g -- ./myapp
perf script | stackcollapse-perf.pl | flamegraph.pl > profile.svg
```

## 断言与日志

### 静态断言（编译期）

```cpp
static_assert(sizeof(int) == 4, "int must be 4 bytes");
static_assert(std::is_pointer_v<T>, "T must be a pointer");
```

### 运行时断言

```cpp
#include <cassert>

void process(int* ptr) {
    assert(ptr != nullptr && "ptr must not be null");
    // ...
}
```

### 条件编译调试

```cpp
#ifdef DEBUG_MODE
    #define LOG_DEBUG(msg) std::cerr << "[DEBUG] " << msg << std::endl
#else
    #define LOG_DEBUG(msg)
#endif

LOG_DEBUG("Value: " << x);
```

### 调试宏

```cpp
// 文件名和行号
#define FILE_LINE __FILE__ ":" + std::to_string(__LINE__)

// 断言并打印值
#define ASSERT_EQ(a, b) assert((a) == (b) && #a " != " #b)

// 断点（IDE 调试）
#if defined(_MSC_VER)
    #define DEBUG_BREAK() __debugbreak()
#else
    #define DEBUG_BREAK() __builtin_trap()
#endif
```

## CMake 配置调试构建

```cmake
# 调试构建
set(CMAKE_BUILD_TYPE Debug)

# 发布构建（带调试信息）
set(CMAKE_BUILD_TYPE RelWithDebInfo)

# 自定义编译选项
target_compile_options(myapp PRIVATE
    $<$<CONFIG:Debug>:-O0 -g -Wall>
    $<$<CONFIG:Release>:-O3 -DNDEBUG>
)

# sanitizer
target_compile_options(myapp PRIVATE
    -fsanitize=address
    -fsanitize=undefined
)
```

## 常见问题诊断

### 段错误（Segmentation Fault）

```bash
# 1. 使用 gdb 运行
gdb ./myapp
run
bt  # 查看崩溃时的调用栈

# 2. 使用 ASAN 重新编译
g++ -fsanitize=address -g myapp.cpp -o myapp
./myapp

# 3. 检查野指针
valgrind --leak-check=full ./myapp
```

### 内存泄漏

```bash
# Valgrind
valgrind --leak-check=full ./myapp

# ASAN
g++ -fsanitize=address -g myapp.cpp -o myapp

# MSAN（检测未初始化内存）
g++ -fsanitize=memory -g myapp.cpp -o myapp
```

### 线程安全问题

```bash
# TSan
g++ -fsanitize=thread -g myapp.cpp -o myapp

# Helgrind（Valgrind 工具）
valgrind --tool=helgrind ./myapp
```
