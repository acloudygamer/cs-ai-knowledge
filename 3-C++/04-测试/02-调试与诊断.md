# 调试与诊断

## 本质断言

**调试是通过控制程序执行流程并在暂停点观察状态来定位缺陷源头的过程，其核心是 GDB/LLDB 的"暂停-检查-恢复"循环；诊断工具（Valgrind/SANITIZER）通过程序插桩在运行时检测内存安全违规和数据竞争，在不修改源码的前提下暴露隐藏错误。**

## 调试的机制：GDB 暂停-检查-恢复循环

调试器的本质不是"看代码"，而是**控制 CPU 执行**。GDB 通过操作系统提供的调试接口（Linux: `ptrace`）附着到目标进程，在特定指令地址（断点）或条件满足时将 CPU 暂停，并接管其寄存器/内存视图。

```
[断点命中] → [CPU 暂停，寄存器/栈快照到 GDB] → [检查内存/变量] → [恢复执行或单步]
     ↑                                                          |
     └──────────────────── next/step ───────────────────────────┘
```

### 断点的底层原理

设置断点时，GDB 将目标地址的原始指令保存，并替换为 trap 指令（Linux: `int3`，x86 单字节 0xCC）。CPU 执行到此处时触发调试异常，操作系统将控制权转交给 GDB——GDB 恢复原始指令、恢复寄存器状态，然后等待下一步命令。

```
源代码地址 0x401020:  mov eax, [ebp+8]
                        ↑
                   GDB 在此处插入 0xCC（trap）

CPU 执行到 0x401020 → 触发 #DB 异常 → OS 通知 GDB → 暂停
```

条件断点只是在 trap 触发后多一层 `if (!condition) resume` 的判断——断点仍然每次都命中，只是未必暂停。

### 符号表与行号映射

`-g` 生成的 DWARF 信息将每个机器指令地址映射回源文件+行号。`print x` 之所以知道局部变量 `x` 在栈上的位置，正是因为符号表记录了 `x` 相对于栈帧指针（RBP）的偏移量：`x @ [RBP - 0x10]`。

优化级别 `-O2` 及以上会导致代码重排、内联和寄存器分配，调试信息可能不准确——这就是为什么调试代码用 `-O0`。

## 诊断工具的机制

### Valgrind 的动态二进制插桩

Valgrind 不编译时插桩，而是在**运行时**用 JIT 重新解释目标二进制。它将每条指令翻译为等价的中间表示（IR），在 IR 层面插入检查：

```
原始指令:  mov [eax], ebx
     ↓ Valgrind 翻译
IR:  store_MemEb(Addr(eax), G ebx)
     ↓ Valgrind 插入检查
IF addr not in valid_heap_range THEN report_invalid_write
```

这意味着 Valgrind 能检测**任何内存访问**，无论源码是否有 debug 信息——但代价是 10-50x 性能损失。

### AddressSanitizer 的编译时插桩

ASAN 在编译时在每个内存访问点前后插入检查，而非运行时解释。它使用**影子内存**（shadow memory）：每 8 字节应用内存映射到 1 字节影子值，标记该范围的状态（可访问/栈-redzone/堆-redzone/毒药）。

```
实际内存: [0x....8] [0x....0][0x....1][0x....2][0x....3]...
影子内存:   [0/1/2]  ← 每 8 字节一个字节标记

访问 addr=0x7fff0004 时:
  影子地址 = addr/8 = 0xFFFFFF000
  读取影子值 = 2 (heap-left-redzone) → ASAN 报告 heap-buffer-overflow
```

asan 检测比 valgrind 快 2-5x，因为没有 IR 翻译开销，只是额外的内存访问。

### ThreadSanitizer 的数据竞争检测

TSAN 使用**矢量时钟**（vector clock）算法。每个人线程持有自己的逻辑时钟，每次同步时交换并取最大值。每次内存访问记录 `(地址, 值, 线程ID, 时钟)`。若两个线程对同一地址的未同步访问满足以下条件之一，则为数据竞争：

```
没有 happens-before 关系（无锁、无 mutex、无原子操作）
AND 至少有一个访问是写入
```

## 工具对比

<pre>
场景                GDB/LLDB          Valgrind           ASAN/TSAN
─────────────────────────────────────────────────────────────────────
内存越界             需断点+手动         ✅ 自动化             ✅ 自动化
内存泄漏             ❌                ✅ 精确               ✅ (leak sanitizer)
数据竞争             ❌                Helgrind 部分        ✅ TSAN 精确
未定义行为           ❌                ❌                  ✅ UBSAN
性能开销             无（运行时）       10-50x              2-5x
无需源码             ❌                ✅                   ❌ (需重新编译)
</pre>

## 编译配置

<pre>
Debug 构建（调试信息，关优化）:
  g++ -g -O0 -Wall -o myapp myapp.cpp

ASAN 构建（检测内存错误）:
  g++ -g -fsanitize=address -fsanitize=undefined -O1 -o myapp myapp.cpp

TSAN 构建（检测数据竞争）:
  g++ -g -fsanitize=thread -O1 -o myapp myapp.cpp

CMake 配置:
  target_compile_options(myapp PRIVATE
      $<$<CONFIG:Debug>:-O0 -g -Wall>
      $<$<CONFIG:RelWithDebInfo>:-O2 -g>
      $<$<CONFIG:ASAN>:-fsanitize=address -fsanitize=undefined>
  )
</pre>

## 常见问题诊断流程

### 段错误（Segmentation Fault）

<pre>
1. gdb ./myapp → run → bt          # 定位崩溃位置和调用栈
2. g++ -fsanitize=address -g ...    # 重新编译，若 ASAN 报告 heap-buffer-overflow
3. valgrind --leak-check=full ...   # 若 ASAN 无果，Valgrind 提供更详细信息
</pre>

### 内存泄漏

<pre>
Valgrind:  valgrind --leak-check=full --show-leak-kinds=all ./myapp
ASAN:      编译时加 -fsanitize=leak（退出时报告）
MSAN:      g++ -fsanitize=memory -g ...（检测未初始化内存读取）
</pre>

### 数据竞争

<pre>
TSAN:  g++ -fsanitize=thread -g -O1 ... → 运行 ./myapp
       TSan 报告格式: "Write of size N at 0x... by thread T1;
                       Previous write of size N at 0x... by thread T0"
Helgrind: valgrind --tool=helgrind ...（Valgrind 工具，精度低于 TSan）
</pre>

## 参考存根

```bash
# GDB 基础
gdb ./myapp
break main
break myapp.cpp:42
condition 1 count > 10
run
bt
print x
next / step / continue
watch x
delete 1

# LLDB（macOS）
lldb ./myapp
breakpoint set --name main
thread step-over
frame variable

# Valgrind
valgrind --leak-check=full --show-leak-kinds=all --track-origins=yes ./myapp

# ASAN
g++ -g -fsanitize=address -fsanitize=undefined -O1 myapp.cpp -o myapp

# TSan
g++ -g -fsanitize=thread -O1 myapp.cpp -o myapp

# perf + 火焰图
perf record -g -- ./myapp
perf script | stackcollapse-perf.pl | flamegraph.pl > profile.svg

# 静态断言
static_assert(sizeof(int) == 4, "int must be 4 bytes");

# 运行时断言
assert(ptr != nullptr);

# 调试宏
#if defined(_MSC_VER)
    #define DEBUG_BREAK() __debugbreak()
#else
    #define DEBUG_BREAK() __builtin_trap()
#endif
```

> 所有代码/命令 ≤20 行，无错误处理/日志/注释。
