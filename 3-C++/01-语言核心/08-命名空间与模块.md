# 08-命名空间与模块

> 前置：[07-错误处理](07-错误处理.md) · 后续：[09-预处理与宏](09-预处理与宏.md)

> **版本基准**：C++20；C++23/26 特性行内标注。示例实测环境：GCC 14.2（MinGW-w64，Windows）。

命名空间解决的是编译期的**名字冲突**，模块解决的是构建期的**接口分发**。前者是名字分区，后者是对 `#include` 文本包含机制的重做。

## 本质

命名空间（namespace）是**名字分区机制**：给名字加一层前缀，让不同代码域的同名符号共存。它只作用于编译期的名字查找，不改变产物的运行时结构——符号进目标文件时前缀已被编进修饰名（name mangling，见 [03-链接与ABI](../04-性能与底层/03-链接与ABI.md)）。

模块（module，C++20）是**接口分发机制**的重做：把"文本粘贴"（`#include`）换成"编译产物导入"（`import`），接口的解析成本付一次而不是每个包含点付一次（文本包含的三条代价见 [01-语言定位与编译模型](../00-概览/01-语言定位与编译模型.md)）。

## 机制

### 名字查找与 ADL

无限定名字从当前作用域逐层向外找，找到即停（内层遮蔽外层）。函数调用额外多一条规则：**ADL**（实参依赖查找，Argument-Dependent Lookup）——除普通查找外，还到每个实参类型**所属的命名空间**里补查同名函数。`std::cout << x` 能成立，是因为 `operator<<` 定义在 `std`，而实参的类型属于 `std`。

ADL 的坑对称存在：实参命名空间里任何同名函数都会静默挤进重载集，可能劫走你以为会命中全局函数的调用。对应的防御惯例是 `swap` 用法——先 `using std::swap;` 引入兜底，再无限定调用 `swap(a, b)`：ADL 找到的类型专属版本优先，标准版本保底。

### 内联命名空间：版本化

`inline namespace` 的成员对父命名空间**透明可见**——`lib::v2::f` 可直接写作 `lib::f`——但修饰名里仍带 `v2`。库作者用它做版本化：新版本升 inline 成为默认，旧版本保留原符号名，已编译的老目标文件链接照旧。

### 匿名命名空间 = 内部链接

匿名命名空间给成员**内部链接**：符号不进全局符号表，其他翻译单元看不见，各单元同名的私有符号互不冲突。地位等价于 C 的 `static`，但能包裹类型与模板（`static` 不能），是 `.cpp` 里私有助手的标准写法。

### using 纪律

- `using N::name`（using 声明）：把单个名字导入当前作用域，与已有名字冲突即编译错误——安全。
- `using namespace N`（using 指示）：让 N 的全体名字参与查找，不报错、只静默扩大重载集——**头文件里禁用**。头文件被 `#include` 文本粘贴进每个使用者的每个位置，using 指示会把整个命名空间倒进无法预知的上下文，名字冲突全部爆在无辜的下游代码里。`.cpp` 中、函数体内按需使用可以接受。

### 模块（C++20）

三块语法：`export module M;` 声明模块接口单元并导出符号；`import M;` 导入——获得导出声明，但**不获得宏与非导出符号**，宏不再穿越边界，这是对文本包含最实质的修复。编译时接口单元先被编成 **BMI**（二进制模块接口：MSVC `.ifc`、GCC `gcm.cache/*.gcm`、Clang `.pcm`），import 方读 BMI 而非重解析头文件源码。

支持现状（2026 年，cppreference 编译器支持页口径）：**MSVC 最完整，GCC 与 Clang 部分支持**。本机实测（GCC 14.2 MinGW）：最小具名模块可编译运行，但需手动两步——接口单元加 `-fmodules-ts -x c++` 先编出 BMI，`.cppm` 扩展名默认不被识别（见示例）。普及慢的三个结构性原因：

1. **构建系统**：import 关系在编译中才出现，构建器须先扫描依赖再定编译顺序——CMake 到 3.28（2023-12）才支持具名模块（Ninja 生成器）。
2. **标准库模块化**：`import std;` 是 C++23 才补的特性，支持度更新（cppreference 口径：MSVC/Clang 先行，GCC 15 起部分支持）。
3. **存量生态**：海量头文件库不因模块出现而重写，混合形态将长期存在。

## 示例

ADL、内联命名空间版本化、匿名命名空间（GCC 14.2，`-std=c++20 -Wall` 实测）：

```cpp
#include <cstdio>

namespace geo {
    struct Point { int x, y; };
    double dist2(Point a, Point b);   // 声明即可，ADL 照常工作
}
double geo::dist2(Point a, Point b) {
    int dx = a.x - b.x, dy = a.y - b.y;
    return dx * dx + dy * dy;
}

namespace lib {
    inline namespace v2 { int version() { return 2; } }   // 对 lib:: 透明可见
    namespace v1 { int version() { return 1; } }
}

namespace {                  // 匿名命名空间：本翻译单元私有（内部链接）
    int helper() { return 7; }
}

int main() {
    geo::Point a{0, 0}, b{3, 4};
    std::printf("%g\n", dist2(a, b));                 // 25——没写 geo::，ADL 补查参数命名空间
    std::printf("%d %d\n", lib::version(), lib::v1::version());  // 2 1
    std::printf("%d\n", helper());                    // 7
}
```

最小具名模块（本机 GCC 14.2 实测可跑，属 GCC 部分支持范围；跨编译器编译方式未统一，MSVC 用 `/interface`，Clang 另有 BMI 流程）：

```cpp
// math.cppm —— 模块接口单元
export module math;
export int add(int a, int b) { return a + b; }

// main.cpp —— 导入方：读 BMI，不发生文本粘贴，宏不穿越边界
import math;
int main() { return add(1, 2); }
```

```bash
g++ -std=c++20 -fmodules-ts -x c++ -c math.cppm -o math.o  # 产 BMI：gcm.cache/math.gcm
g++ -std=c++20 -fmodules-ts main.cpp math.o -o main
./main; echo $?   # 3
```
