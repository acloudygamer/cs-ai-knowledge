# 05-移动语义与拷贝控制

> 前置：[04-类与资源管理](04-类与资源管理.md)（五法则的另一半在这里展开） · 后续：[06-模板与Concepts](06-模板与Concepts.md)（万能引用是模板推演的主场）

> **版本基准**：C++20；C++23/26 特性行内标注

C++ 默认值语义：赋值即拷贝。对持有堆资源的类，拷贝是深复制——`vector` 有 100 万个元素就复制 100 万个。移动语义（C++11）补上了被浪费的那一半：**临时对象的资源反正随它一起死，不如把资源直接过户**。本篇按因果链展开：先建值类别坐标系（决议的依据），再讲移动操作的窃取语义，最后是支撑转发的两条规则（引用折叠、`std::forward`）与返回值优化。

## 本质

移动语义回答的是一个资源账问题：拷贝语义的复杂度与被拷贝数据成正比（ $O(n)$），而很多场景里源对象马上就要析构——资源的所有权可以**转移**而非复制，代价降为交换几个指针（ $O(1)$）。要让编译器替你选这条路，它必须能区分"还会被用到的对象"与"将死的对象"——这就是值类别存在的第一理由（坐标系在 [01-类型系统与值类别](01-类型系统与值类别.md) 已立，此处展开）。

## 机制

### 值类别：身份 × 可移动的两维五类

每个表达式属于且只属于一个类别，由两个正交问题决定：**有身份吗**（能取地址、能在表达式之外再见到它）？**可被移动吗**（资源可被合法窃取）？

| | 有身份 | 无身份 |
|---|---|---|
| 不可移动 | **左值（lvalue）**：变量名、`*p`、返回 `T&` 的调用 | —— |
| 可移动 | **将亡值（xvalue）**：`std::move(x)`、返回 `T&&` 的调用 | **纯右值（prvalue）**：字面量、`a+b`、返回 `T` 的调用 |

两类别名做归并：**泛左值（glvalue）= 左值 + 将亡值**（有身份），**右值（rvalue）= 将亡值 + 纯右值**（可移动）。重载决议只看这张表：`const T&` 什么都能绑，`T&&` 只绑右值——于是给类写一对 `f(const T&)` / `f(T&&)` 重载，左值进拷贝路径、右值进移动路径。

### 移动构造/移动赋值：窃取语义

移动构造的实现模式固定三步：把源对象的资源指针**抄过来**、把源对象的指针**置空**、走人。源对象的析构函数随后看到空指针，`delete nullptr` 无操作——资源没有两份主人，双重释放无从发生。

窃取之后源对象处于**合法但未指定状态**（valid but unspecified）：标准只担保它可析构、可重新赋值，不担保任何具体内容。`vector` 被移动后实测为空（GCC 14.2 libstdc++），但那是实现细节；纪律是**移后即弃**——除非立刻赋新值，否则别再读它。

一个直接影响性能的约束：移动操作要标 `noexcept`。`vector` 扩容迁移元素时要求强异常保证——若元素移动构造是 `noexcept` 就移动，否则**退化为逐元素拷贝**（移动半途抛异常无法回滚，拷贝可以）。不写 `noexcept` 的移动构造等于自动放弃容器里的移动红利。

### std::move 不移动任何东西

`std::move(x)` 的全部实现是一次 `static_cast<T&&>(x)`：它只做**类型层面**的值类别改写，把左值标成"可移动"，让重载决议选中移动构造；真正的资源转移发生在被选中的移动构造/赋值里。推论：`std::move` 之后没有移动操作接收，等于白标——`const` 对象尤其常见，`const` 左值转出来的 `const T&&` 绑不上 `T&&`，静默退回调用拷贝构造。

### 引用折叠与完美转发

模板形参 `T&&` 不是右值引用，是**转发引用**（万能引用）：推演时实参的值类别被编码进 `T`——左值实参把 `T` 推成 `U&`，右值推成 `U`。折叠规则把叠出来的双引用压回一个：

| 组合 | 折叠结果 |
|---|---|
| `T& &`、`T& &&`、`T&& &` | `T&` |
| `T&& &&` | `T&&` |

一句话：**只要带一个左值引用就折叠成左值引用**。但形参 `arg` 在函数体内永远是有名字的左值——值类别信息存在 `T` 里。`std::forward<T>(arg)` 按 `T` 里存的类别做一次条件 cast，把原始类别还原回去：`T` 是 `U&` 转左值、是 `U` 转右值。这对组合（转发引用 + `forward`）就是完美转发：包装层把实参的值类别原封不动递给内层，`make_unique`、`emplace_back` 全靠它在目标位置直接构造。

### RVO 与 C++17 保证拷贝省略

返回值的常规出路有两条优化：

- **RVO/NRVO**（命名返回值优化）：`R r; return r;` ——编译器把局部 `r` 直接构造在调用方准备的返回槽里，拷贝/移动一次都不发生。GCC 14.2 `-O0` 也默认做。
- **保证拷贝省略（C++17 起）**：`return R{};` 返回纯右值时不再是优化、是**语言保证**——纯右值的语义改写为"用于初始化目标的材料"，即使拷贝/移动构造被 `= delete` 也合法。

由此得返回值纪律：**不要 `return std::move(局部变量)`**。`return r;` 走 NRVO，零次移动；裹上 `std::move` 后表达式变成 xvalue，不再满足 NRVO 的形状，反而强制走一次移动构造（若移动被删，C++20 之前甚至直接编译错误）。移动语义是编译器够不着时的人工作业，够得着的地方它自己做得更好。

## 示例

（GCC 14.2 MinGW 实测，`-std=c++20`）

```cpp
#include <iostream>
#include <utility>
#include <vector>

struct R {
    int* p;
    R() : p(new int(0))              { std::cout << "ctor "; }
    R(const R& o) : p(new int(*o.p)) { std::cout << "copy "; }
    R(R&& o) noexcept : p(o.p)       { o.p = nullptr; std::cout << "move "; }
    ~R() { delete p; }
};

R make()       { R r; return r; }    // NRVO：r 直接构造进返回槽
R make_prval() { return R{}; }       // C++17 保证省略：prvalue 即目标本身

void take(R&)  { std::cout << "lvalue\n"; }
void take(R&&) { std::cout << "rvalue\n"; }

template<typename T>
void relay(T&& arg) { take(std::forward<T>(arg)); }  // 转发引用 + forward 保类别

int main() {
    R a;  std::cout << '\n';         // ctor
    R b = make();  std::cout << '\n';// ctor —— 无拷贝无移动（NRVO）
    R c = make_prval();  std::cout << '\n';  // ctor —— 保证省略
    R d = std::move(c);  std::cout << '\n';  // move：std::move 改类别，移动构造窃取

    relay(a);                        // lvalue：左值进、左值出
    relay(R{});                      // ctor rvalue：纯右值进、右值出

    std::vector<int> v1{1,2,3}, v2;
    v2 = std::move(v1);              // O(1)：交换内部指针
    std::cout << v1.size() << ' ' << v2.size() << '\n';
    // 0 3：移后对象"合法但未指定"（libstdc++ 实测为空），正确纪律是移后即弃
}
```
