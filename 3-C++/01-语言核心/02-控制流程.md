# 02-控制流程

> 前置：[01-类型系统与值类别](01-类型系统与值类别.md) · 后续：[03-函数与Lambda](03-函数与Lambda.md)、[07-错误处理](07-错误处理.md)

> **版本基准**：C++20；C++23/26 特性行内标注

控制流语句决定指令指针的走向。本篇按"源码形态 → 编译后的机器形态"的对应关系过一遍：分支与循环编译成条件跳转，switch 可能编译成跳转表；范围 for 是迭代器循环的语法重写；`if constexpr` 把分支从运行期搬到编译期。

## 本质

CPU 的默认行为是顺序取指，**控制流 = 对指令指针的显式改写**。所有控制语句编译到底层只有两类机器形态：条件跳转（`je`/`jne` 家族，依据标志位决定是否跳）与无条件跳转（`jmp`）。`if`、`while`、`for`、`switch` 乃至函数的调用与返回，都是这两类的组合。

分支的成本不对称：现代 CPU 用流水线预取下一段指令，跳转会让已预取的指令作废。顺序执行与可预测的分支几乎免费，**不可预测的跳转**才付流水清空的代价——编译器优化与 `[[likely]]` 标注（见下文）都在围绕这条事实做文章。CPU 侧的分支预测机制见 [0-计算机基础](../../0-计算机基础/README.md)。

## 机制

### if/else：条件跳转

`if (cond) A else B` 编译为：求值 `cond` 置标志位 → 一条条件跳转指令（条件不成立时跳到 B 的地址）→ A 的代码 → 无条件跳转越过 B。`cond` 求值顺序无捷径可言；`&&`/`||` 的短路语义就是靠给每个子条件各生成一条跳转实现的。

`[[likely]]` / `[[unlikely]]`（C++20）是挂在分支上的布局提示：编译器把"可能"的路径放在顺序下落的位置、把"不可能"的路径挪远（减少指令缓存污染、给预测器一个静态倾向）。它不改变语义，只改代码布局；提示写错不会出错，只会反向劣化。CPU 有动态分支预测器，规律明显的分支本来就能预测准——这个属性只对冷热极端（如错误处理路径）有意义。

### switch：跳转表或比较链，由 case 分布决定

switch 的编译形态不是语法决定的，是 case 值分布决定的：

| case 分布 | 编译形态 | 单分支代价 |
|---|---|---|
| 值连续或近连续、数量足够（编译器启发式阈值，GCC 约 4 个以上） | **跳转表**：case 值作索引查地址数组，`jmp *table[i]` 一次间接跳转 | $O(1)$，与 case 数无关 |
| 稀疏但有序 | 比较链或二分比较树 | $O(\log n)$ |
| 全部分支可折叠为查常量表 | 直接索引常量数组（GCC 会把 `switch` 折成 `table[i]`，连跳转都省掉） | $O(1)$ |

GCC 14.2 `-O2` 实测：8 个 case 各调用不同函数的 switch，汇编里出现地址表加 `jmp *%rax` 间接跳转；而分支体只是返回不同常量的 switch 被进一步折叠成常量表索引。约束：case 只能是整型/枚举常量表达式——跳转表的索引必须是整数。

fallthrough 规则：case 不自带 break，控制流会贯穿到下一 case；`[[fallthrough]];`（C++17）显式声明"我就是要贯穿"，压住编译器警告。

### 循环：条件跳转加回跳

`for (init; cond; step) body` 等价于 `init` 后接"判断 → body → step → 回跳"的循环结构。编译器的两个标准优化：**循环不变式外提**（体内不依赖迭代变量的表达式挪到循环外，只算一次）与**循环展开**（一次迭代处理多份，摊薄跳转次数）。这些是优化器的行为，不进入语言语义。

`[[likely]]` 也可标注循环分支，但热循环里的分支通常被预测器抓得很准。

### 范围 for：迭代器协议的语法重写

`for (T x : range) body` 不是新机制，是编译器的固定展开：

```cpp
auto&& __r = range;              // 整个范围先绑定一次（临时量也因此延寿）
auto __b = std::begin(__r);
auto __e = std::end(__r);
for (; __b != __e; ++__b) { T x = *__b; body }
```

接口契约因此明确：`range` 只需提供 `begin`/`end`（成员或经 ADL 找到的自由函数），返回的东西支持 `!=`、`++`、`*` 三件套即可——自定义类型满足这三点就自动获得范围 for 语法。陷阱从展开式直接读出：`T x = *__b` 是**拷贝**，写 `for (const auto& x : v)` 才避免逐元素复制；`__r` 只绑定一次，循环体内对 range 增删元素导致的迭代器失效照样是未定义行为（容器失效规则见 [01-容器](../02-标准库/01-容器.md)）。

### 初始化语句与结构化绑定：把名字收窄到它活着的地方（C++17）

两个语法改动同向：**名字的作用域收窄到它被消费的区间**，误用面随之缩小。

- `if (auto it = m.find(k); it != m.end())`：分号前的初始化语句先于条件执行，变量只在整个 if-else 块内可见。`switch`、`while` 同样支持。
- **结构化绑定** `auto [a, b] = pair;`：把聚合体/pair/tuple 解包成一组名字——名字绑定的是一个**隐藏对象 e 的成员**，而 e 的形态由 `auto`/`auto&` 决定：不带 `&` 时 e 是初始化式的副本（左值初始化即拷贝），改绑定名不动原对象；带 `&` 时 e 是原对象的引用，绑定名直接别名原对象的成员（绑定数组、struct 成员、`std::tuple` 各有规则）。GCC 14.2 实测：`auto [x, y] = p;` 后 `x = 99`，`p.first` 仍为 1；换成 `auto& [x, y] = p;` 才改得动原对象。

### if constexpr：编译期分支，被弃分支不实例化（C++17）

普通 `if` 的两个分支**都要通过编译**：类型检查、模板实例化全部发生，只是运行时走一边。模板里按类型分流时这是死路——`T` 是 `int` 时，分支里的 `v.to_string()` 照样要编译。

`if constexpr (条件)` 把分支提到编译期：条件必须是常量表达式，**模板实例化时被丢弃的分支不参与实例化**（非模板上下文里两个分支仍都要编译，只是死代码被优化掉）。它是模板元编程里"按类型选实现"的常规手段，与模板特化的关系见 [06-模板与Concepts](06-模板与Concepts.md)。

### goto 的位置

`goto` 仍是合法语句，唯一的现代用途是从深层嵌套跳出到统一的清理出口。两条硬约束：不能跳进变量作用域（会跳过初始化，编译器直接报错）；在 RAII 已成标配的代码里（[04-类与资源管理](04-类与资源管理.md)），清理出口由析构函数承担，goto 的最后一块阵地也随之收缩。

## 示例

本篇机制一次跑完（GCC 14.2 MinGW 实测，`-std=c++20`）：

```cpp
#include <iostream>
#include <map>
#include <string>
#include <type_traits>

// if constexpr：被丢弃的分支不参与实例化——T=int 时 <string> 分支里的
// v.size() 连编译都不发生，普通 if 在这里会直接编译失败
template<typename T>
std::string describe(const T& v) {
    if constexpr (std::is_integral_v<T>)
        return "int:" + std::to_string(v);
    else
        return "len:" + std::to_string(v.size());
}

int classify(int d) {
    switch (d) {                    // case 0..7 连续 → GCC -O2 可生成跳转表
        case 0: case 1: [[likely]] return 1;   // 标注热路径：影响代码布局，不影响语义
        case 2: case 3: case 4: case 5: return 2;
        case 6: case 7: return 3;
        default: return -1;
    }
}

int main() {
    std::map<std::string, int> m{{"a", 1}, {"b", 2}};
    for (const auto& [k, v] : m) std::cout << k << '=' << v << ' ';  // a=1 b=2
    std::cout << '\n';
    if (auto it = m.find("b"); it != m.end())   // it 只活到 if-else 结束
        std::cout << it->second << '\n';        // 2

    std::cout << describe(42) << ' ' << describe(std::string("abc")) << '\n';
                                                // int:42 len:3
    std::cout << classify(0) << classify(7) << classify(9) << '\n';   // 13-1
}
```
