# 迭代器

**迭代器的本质是算法与容器之间的抽象接口契约——它将"如何遍历容器"这一职责从算法剥离到容器自身，使同一份算法代码可以操作不同容器的元素。**

## 迭代器模式的核心价值

**没有迭代器抽象时，算法需要为每个容器类型单独实现**。有了迭代器抽象，算法只需定义对迭代器的操作集合，容器提供符合该集合的迭代器实现。**这是开闭原则（Open-Closed Principle）的典型应用。**

<pre>
算法（对迭代器操作，不依赖具体容器）:

template<Iterator it>
void sort(it begin, it end) { /* 仅依赖 ++, *, < 等迭代器操作 */ }

容器（提供迭代器实现）:
std::vector<int> vec;   sort(vec.begin(), vec.end());
std::list<int> lst;     sort(lst.begin(), lst.end());  // list 有自己的 sort
                                                           // 因为随机访问迭代器不可用
</pre>

## 五种迭代器类别

**迭代器类别（Iterator Categories）本质上是能力分层——每个类别定义了一组最小必需操作，算法据此推断自己能在该迭代器上做什么。**

| 类别 | 必需操作 | 能力描述 |
|------|---------|---------|
| 输入迭代器 | `++`, `*` (只读) | 单遍扫描，只读 |
| 输出迭代器 | `++`, `*` (只写) | 单遍扫描，只写 |
| 前向迭代器 | `++`, `*` (读写) | 多遍扫描，读写 |
| 双向迭代器 | `++`, `--`, `*` (读写) | 支持前后移动 |
| 随机访问迭代器 | `++`, `--`, `+`, `-`, `[]` | O(1) 跳转 |

**C++17 连续迭代器**（`std::contiguous_iterator_tag`）是随机访问迭代器的子集，保证元素在内存中连续存放，使得 `*(it + n)` 等价于 `*(it) + n` 且地址连续。

<pre>
std::vector<int> vec = {1, 2, 3, 4, 5};
auto it = vec.begin();

it + 2;       // 随机访问：O(1) 跳转
it - 1;       // 双向：O(n) 退
*(it + 3);    // 连续：*(it+3) 物理上等于基址 + 3*sizeof(int)

std::list<int> lst = {1, 2, 3, 4, 5};
auto lit = lst.begin();
++lit; --lit; // 双向：支持前后
// lit + 2;   // 编译错误！list 迭代器不支持算术运算
</pre>

## 迭代器辅助函数

**`std::advance` 修改迭代器本身，`std::next`/`std::prev` 返回新迭代器（原始不变）。设计动机：前者用于需要移动游标的场景，后者用于函数式风格（不修改原迭代器）。**

<pre>
std::vector<int> vec = {1, 2, 3, 4, 5};
auto it = vec.begin();

std::advance(it, 3);     // it 现在指向第4个元素，it 本身被修改

auto it2 = vec.begin();
auto it3 = std::next(it2, 2);  // it2 不变，it3 是 it2+2
</pre>

## 迭代器适配器

**迭代器适配器的本质是将一种迭代器行为转换为另一种——通过在 `operator*`/`operator++` 中注入转换逻辑，实现遍历行为的可组合修改。**

### 反向迭代器

**反向迭代器的 `++` 实际是递减底层正向迭代器，`rbegin()` 对应 `end()-1`**，使得 `*(rit + n)` 等价于访问倒数第 n+1 个元素。

<pre>
std::vector<int> vec = {1, 2, 3, 4, 5};
for (auto rit = vec.rbegin(); rit != vec.rend(); ++rit) {
    // ++rit 实际调用 --(rit.base())
    // rbegin() = end() - 1
}
// 输出：5 4 3 2 1
</pre>

### 插入迭代器

**插入迭代器的 `operator*` 不返回引用解引用后的值，而是返回代理对象，其 `operator=` 执行插入操作。设计动机：让算法向迭代器写入，但写入实际是插入而非覆盖。**

<pre>
std::vector<int> src = {1, 2, 3};
std::list<int> dest;
std::copy(src.begin(), src.end(), std::back_inserter(dest));
// std::copy 以为在向 dest 写入
// 实际是 back_inserter(dest) 将每次写入转为 push_back
</pre>

### 流迭代器

**流迭代器的本质是将流的输入/输出抽象为迭代器操作。`istream_iterator<T>` 在解引用时触发一次流读取，`ostream_iterator<T>` 在赋值时触发一次流输出。**

<pre>
std::vector<int> vec;
std::copy(
    std::istream_iterator<int>(std::cin),  // 解引用触发读取
    std::istream_iterator<int>(),            // 默认构造 = EOF 哨兵
    std::back_inserter(vec)
);

std::copy(vec.begin(), vec.end(),
    std::ostream_iterator<int>(std::cout, " "));  // 赋值触发输出
</pre>

## 迭代器失效

**迭代器失效的根本原因是容器重新分配或节点关系被破坏，导致迭代器持有的指针/索引不再指向有效元素。**

<pre>
vector 失效规则：
┌────────────────────────────────────────────┐
│ push_back 导致 capacity 翻倍               │
│ → 旧内存释放，新内存分配                   │
│ → 所有现有迭代器指向旧内存（悬垂）          │
│ → 迭代器全部失效                          │
├────────────────────────────────────────────┤
│ erase(it) 返回被删元素之后位置的迭代器    │
│ → 后续元素前移                             │
│ → erase 返回的迭代器有效，原 it 失效        │
└────────────────────────────────────────────┘

list 失效规则：
erase(it) → 仅被删元素的迭代器失效
           其他节点不受影响（节点内存不变）
</pre>

<pre>
正确删除偶数：
for (auto it = vec.begin(); it != vec.end(); ) {
    if (*it % 2 == 0) {
        it = vec.erase(it);  // erase 返回下一个有效迭代器
    } else {
        ++it;
    }
}
</pre>
