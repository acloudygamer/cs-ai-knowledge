# 命名空间

## 定义

**命名空间的本质是编译期符号可见性分域机制——通过在符号名上附加命名空间前缀，实现不同代码域中同名符号的共存，解决名字冲突（name collision）问题。**

## 数学模型

### 名字查找的域规则

命名空间的名字查找遵循**最近可见原则**（Nearest Visible Rule）：

$$\text{查找}(name, \text{作用域} S) = \begin{cases} \text{在 } S \text{ 中找到 name} & \text{返回} \\ \text{查找外层作用域} & \text{否则} \\ \text{未找到} & \text{编译错误} \end{cases}$$

**名字遮蔽（Name Hiding）**：
$$\text{若外层声明 } x, \text{内层声明 } x \implies \text{外层 } x \text{ 被遮蔽}$$

### ADL 的查找扩展

**ADL（Argument-Dependent Lookup，Koenig 查找）**是名字查找的扩展规则：

当调用无限定函数时，编译器在**参数的命名空间**中额外搜索同名函数：
$$\text{ADL}(f, \text{参数列表 } A) = \bigcup_{a \in A} \text{associated\_ns}(a)$$

**associated_ns 的定义**：
- 内置类型：无关联命名空间
- 类类型：类自身 + 基类 + 所在命名空间
- 指针/引用：指向类型的关联命名空间

## 数据流

### 符号解析的数据流

<pre>
源代码:
    namespace MyLib {
        void foo(int);
    }
    MyLib::foo(42);

符号表构建:
    MyLib::foo → { type: void(int), address: 0x401000, linkage: external }

解析过程:
    1. 查找 MyLib 符号 → 找到命名空间对象
    2. 在 MyLib 作用域内查找 foo
    3. 找到后验证参数类型匹配
    4. 生成调用指令
</pre>

### using 声明的作用域链

<pre>
namespace A { int x = 1; }
namespace B { int x = 2; }

void f() {
    using A::x;    // x 指向 A::x
    // 此处 x = 1

    {
        // using B::x;  // 编译错误：x 已被 A::x 遮蔽
    }

    // int x = 3;  // 编译错误：x 已在此作用域声明
}
</pre>

### inline namespace 的透明转发

<pre>
namespace MyLib {
    inline namespace v2 {
        void func() { /* v2 实现 */ }
    }
    namespace v1 {
        void func() { /* 旧版本 */ }
    }
}

MyLib::func();  // 解析为 MyLib::v2::func()
MyLib::v1::func();  // 显式调用旧版本
</pre>

## 机制

### 匿名命名空间的唯一性

匿名命名空间的成员获得**编译器生成的唯一前缀**：
```cpp
namespace {
    void helper() {}
}
// 编译器内部生成类似：
// namespace _Unique_1234 {
//     void _helper() {}
// }
```

**与 static 的区别**：

| 属性 | 匿名命名空间 | static |
|------|-------------|--------|
| 可见性 | 当前翻译单元 | 当前翻译单元 |
| 可包含类型 | 是 | 否 |
| 可包含模板 | 是 | 否 |
| 可包含 using | 是 | 否 |

### extern "C" 的链接约定

**Name Mangling 的差异**：
$$\text{C++ mangling} : f(int, double) \rightarrow \_Z1fid$$
$$\text{C mangling} : f \rightarrow \_f$$

**为什么 C++ 需要 name mangling**：
- 支持函数重载（同名不同参数）
- 支持命名空间作用域
- 支持参数类型编码

**为什么 extern "C" 存在**：
- C 代码不包含 name mangling
- C++ 编译器需要生成兼容 C 的符号名
- 链接器按裸符号名查找

### inline namespace 的版本透明切换

**设计动机**：库的版本演进中保持 ABI 兼容：
```cpp
namespace MyLib {
    inline namespace v3 {      // 当前默认版本
        inline namespace v2 {  // v2 包含 v3 的子集
            inline namespace v1 {
                // v1 实现
            }
        }
    }
}

// 用户代码无需修改
MyLib::func();  // 始终调用最新版本

// 显式使用旧版本
MyLib::v1::legacy_func();
```

## 对比参照

| 机制 | 作用域 | 编译/链接 | 典型用途 |
|------|--------|----------|---------|
| namespace | 编译期 | 编译期符号解析 | 代码模块化、避免名字冲突 |
| class/struct | 编译期 | 编译期符号解析 | 类型作用域 |
| block `{}` | 编译期 | 编译期符号解析 | 局部作用域 |
| static | 翻译单元 | 链接期符号解析 | 内部链接 |

## 参考存根

```cpp
#include &lt;iostream&gt;
#include &lt;string&gt;

// 命名空间声明
namespace MyLib {
    namespace Math {
        int add(int a, int b) { return a + b; }
    }
    namespace String {
        std::string capitalize(const std::string&amp; s) {
            std::string r = s;
            if (!r.empty()) r[0] = std::toupper(r[0]);
            return r;
        }
    }
}

// using 声明
void demo_using() {
    using MyLib::Math::add;
    std::cout &lt;&lt; add(1, 2) &lt;&lt; "\n";
}

// ADL 演示
namespace Vec {
    struct Vector {
        double x, y;
    };

    // 在 Vec 命名空间中定义运算符
    Vector operator+(const Vector&amp; a, const Vector&amp; b) {
        return {a.x + b.x, a.y + b.y};
    }
}

void demo_adl() {
    Vec::Vector a{1, 2}, b{3, 4};
    auto c = a + b;  // ADL 找到 Vec::operator+
}

// extern "C" 演示
extern "C" {
    void process_data(const char* data, int len);
}

// C++ 中使用 C 库
void use_c_lib() {
    process_data("hello", 5);
}
```

## 约束与违反后果

| 约束 | 违反后果 |
|------|----------|
| 命名空间别名必须在同一翻译单元内声明 | 编译错误 |
| inline namespace 必须是直接子命名空间 | 编译错误 |
| `using namespace std;` 不可在头文件中使用 | 可能引入名字冲突 |
| ADL 可能找到意外版本的函数 | 行为与预期不符（通常重载决议会选择更匹配的版本） |
| 匿名命名空间成员具有内部链接 | 不同翻译单元的同名符号不冲突，但不可跨翻译单元共享 |
