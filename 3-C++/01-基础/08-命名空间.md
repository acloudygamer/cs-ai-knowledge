# 命名空间

**命名空间的本质是编译期符号可见性分域机制——通过在符号名上附加命名空间前缀，实现不同代码域中同名符号的共存，解决名字冲突（name collision）问题。**

## 名字冲突与命名空间解决

**名字冲突的根源：两个库定义了同名的 `max` 函数或 `string` 类。链接器需要唯一符号，无法解决二义性。命名空间通过将符号隔离到各自的名字域，使 `MyLib::max` 和 `std::max` 成为两个不同符号。**

<pre>
namespace MyLib {
    int max(int a, int b) { return a > b ? a : b; }
}

namespace std {
    int max(int a, int b) { /* 标准库版本 */ }
}

// 使用时：
MyLib::max(1, 2);    // MyLib 版本
std::max(1, 2);       // 标准库版本
// 消除了名字冲突
</pre>

## using 声明的作用域机制

**`using` 声明的本质是在当前作用域引入一个符号别名，其作用域规则遵循普通名字遮蔽（name hiding）——内层作用域的声明遮蔽外层同名符号。**

<pre>
namespace A { int x = 1; }
namespace B { int x = 2; }

void f() {
    using A::x;
    // x 在此处可见，指代 A::x

    // int x = 3;  // 编译错误：x 已在此作用域声明

    using B::x;    // 编译错误：x 已被 A::x 遮蔽，不能再次引入
}
</pre>

## inline 命名空间的设计动机

**`inline namespace` 的本质是透明版本转发——内联命名空间的名称在父命名空间层级直接可见，无需额外限定符。设计动机是库的版本切换（如 ABI 兼容的 v1/v2）。**

<pre>
namespace MyLib {
    inline namespace v2 {
        void func() { /* v2 实现 */ }
    }
}

MyLib::func();  // 等价于 MyLib::v2::func()，但无需写 v2
// 升级版本只需改变 inline namespace
</pre>

## ADL（参数依赖查找）

**ADL（Argument-Dependent Lookup）的本质是 Koenig 查找——调用无限定函数时，编译器在参数的命名空间中额外搜索同名函数。这使得 `std::swap(a, b)` 可以写成 `swap(a, b)`（依赖 ADL 找到 `std::swap`）。**

<pre>
namespace Vec {
    class Vector { /* ... */ };
    void swap(Vector& a, Vector& b) { /* Vec 专属交换 */ }
}

Vec::Vector a, b;
swap(a, b);  // ADL 在 Vec 命名空间找到 swap
// 等价于 Vec::swap(a, b)
</pre>

**ADL 的设计动机**：让运算符（如 `<<`）的无限定调用也能正确找到重载版本，无需显式限定。这使得 `std::cout << x` 可以写成 `cout << x`（通过 `std::ostream` 参数找到 `operator<<`）。

## 匿名命名空间

**匿名命名空间的本质是为其中的名称生成一个唯一、不可见的符号前缀，使这些名称仅在当前翻译单元（.cpp 文件）内可见，不可被其他翻译单元链接访问。**

<pre>
namespace {
    int helper() { return 1; }  // 编译器生成唯一前缀 _Unique_123::helper()
}

int main() {
    helper();  // 仅在当前 .cpp 中可见
}
</pre>

**这比 `static` 函数更通用**：`static` 只能修饰函数和全局变量，匿名命名空间可以包含类、模板等所有命名空间级别的实体。

## extern "C" 的本质

**`extern "C"` 的本质是禁用 C++ 的名字修饰（name mangling），按 C 链接约定（cdecl）生成符号名，使 C++ 代码可以调用 C 库函数。**

<pre>
extern "C" {
    void process(int);  // 符号名 = _process（C 链接约定）
}

namespace mylib {
    void process(int);  // 符号名 = _myluml_process（C++ 修饰）
}
</pre>

**为什么需要 `extern "C"`**：C 编译器不生成带类型和命名空间修饰的符号名，链接器直接按裸函数名查找。C++ 编译器生成修饰名以支持重载和命名空间隔离。
