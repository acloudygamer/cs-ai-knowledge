# 命名空间

## 定义

**命名空间的本质是编译期符号可见性分域机制——通过在符号名上附加命名空间前缀，实现不同代码域中同名符号的共存，解决名字冲突（name collision）问题。** 命名空间将全局作用域划分为互不相交的子域，每个子域内的符号在其域内唯一，不同域的同名符号可以和平共处。

## 数学模型

### 名字查找的域规则

命名空间的名字查找遵循**最近可见原则**（Nearest Visible Rule）：

$$\text{查找}(name, \text{作用域} S) = \begin{cases}
\text{在 } S \text{ 中找到 name} & \text{返回} \\
\text{查找外层作用域} & \text{否则} \\
\text{未找到} & \text{编译错误}
\end{cases}$$

**名字遮蔽（Name Hiding）**：
$$\text{若外层声明 } x, \text{内层声明 } x \implies \text{外层 } x \text{ 被遮蔽}$$

**遮蔽的数学性质**：
$$\text{可见性}(x, S) = \begin{cases}
\text{true} & \text{若 } x \in \text{decls}(S) \\
\text{可见性}(x, \text{parent}(S)) & \text{否则}
\end{cases}$$

### ADL 的查找扩展

**ADL（Argument-Dependent Lookup，Koenig 查找）**是名字查找的扩展规则：

当调用无限定函数时，编译器在**参数的命名空间**中额外搜索同名函数：
$$\text{ADL}(f, \text{参数列表 } A) = \bigcup_{a \in A} \text{associated\_ns}(a)$$

**associated_ns 的定义**：
- 内置类型：无关联命名空间
- 类类型：类自身 + 基类 + 所在命名空间
- 指针/引用：指向类型的关联命名空间

**ADL 的数学本质**：
$$\text{ADL} = \text{普通查找} \cup \text{关联命名空间查找}$$
$$\text{关联命名空间} = f(\text{参数类型}) \rightarrow 2^{\text{命名空间}}$$

### 链接性的形式化

| 链接性 | 作用域 | 符号表可见性 |
|--------|--------|------------|
| 内部链接 | 翻译单元 | 仅当前 .o 文件 |
| 外部链接 | 全局 | 跨翻译单元 |
| 无链接 | 局部作用域 | 仅当前作用域 |

$$S_{\text{内部}} \subset S_{\text{外部}} \subset S_{\text{全局}}$$

**链接性的数学约束**：
$$\text{若符号 } s \text{ 在翻译单元 } T \text{ 有内部链接} \implies s \notin \text{全局符号表}$$
$$\text{若符号 } s \text{ 在翻译单元 } T \text{ 有外部链接} \implies s \in \text{全局符号表} \land \exists! T' \neq T : s \in \text{定义}(T')$$

## 数据流

### 符号解析的数据流

<pre>
源代码:
    namespace MyLib {
        void foo(int);
    }
    MyLib::foo(42);

符号表构建:
    MyLib::foo → { type: void(int), address: 0x401000, linkage: external }

解析过程:
    1. 查找 MyLib 符号 → 找到命名空间对象
    2. 在 MyLib 作用域内查找 foo
    3. 找到后验证参数类型匹配
    4. 生成调用指令
</pre>

### using 声明的作用域链

<pre>
namespace A { int x = 1; }
namespace B { int x = 2; }

void f() {
    using A::x;    // x 指向 A::x
    // 此处 x = 1

    {
        // using B::x;  // 编译错误：x 已被 A::x 遮蔽
    }

    // int x = 3;  // 编译错误：x 已在此作用域声明
}
</pre>

**using 声明的语义**：将命名空间成员导入当前作用域，等同于在该位置声明了同名符号。

### inline namespace 的透明转发

<pre>
namespace MyLib {
    inline namespace v2 {
        void func() { /* v2 实现 */ }
    }
    namespace v1 {
        void func() { /* 旧版本 */ }
    }
}

MyLib::func();  // 解析为 MyLib::v2::func()
MyLib::v1::func();  // 显式调用旧版本
</pre>

**inline namespace 的数学语义**：
$$\text{inline namespace } N \implies \forall name \in N : \text{可见性}(name, \text{parent}) = \text{可见性}(name, N)$$

inline 命名空间的内容在语义上等价于直接写在父命名空间中。

### ADL 的实际执行流

<pre>
无限定函数调用:
    Vec::Vector a{1, 2}, b{3, 4};
    auto c = a + b;  // ADL 找到 Vec::operator+

查找过程:
    1. 查找 operator+ 的普通作用域 → 未找到
    2. 对参数 a 的类型 Vec::Vector，associated_ns = { Vec }
    3. 在 Vec 命名空间中查找 operator+ → 找到
    4. 对参数 b 同理
    5. 重载决议：选择 Vec::operator+

注意:
    using Vec::operator+;  // 若使用 using，ADL 仍然生效
    // 这使得 a + b 可以找到 Vec::operator+
</pre>

## 机制

### 匿名命名空间的唯一性

匿名命名空间的成员获得**编译器生成的唯一前缀**：
```cpp
namespace {
    void helper() {}
}
// 编译器内部生成类似：
// namespace _Unique_1234 {
//     void _helper() {}
// }
```

**与 static 的区别**：

| 属性 | 匿名命名空间 | static |
|------|-------------|--------|
| 可见性 | 当前翻译单元 | 当前翻译单元 |
| 可包含类型 | 是 | 否 |
| 可包含模板 | 是 | 否 |
| 可包含 using | 是 | 否 |

**匿名命名空间的数学性质**：
$$\text{匿名命名空间 } N \implies \text{unique\_prefix}(N) = \text{编译器生成的 UUID}$$
$$\forall x \in N : \text{full\_name}(x) = \text{unique\_prefix}(N) + "::" + x$$

### extern "C" 的链接约定

**Name Mangling 的差异**：
$$\text{C++ mangling} : f(int, double) \rightarrow \_Z1fid$$
$$\text{C mangling} : f \rightarrow \_f$$

**为什么 C++ 需要 name mangling**：
- 支持函数重载（同名不同参数）
- 支持命名空间作用域
- 支持参数类型编码

**为什么 extern "C" 存在**：
- C 代码不包含 name mangling
- C++ 编译器需要生成兼容 C 的符号名
- 链接器按裸符号名查找

**extern "C" 的数学约束**：
$$\text{extern "C"} \implies \text{符号名} = \text{原始函数名} \quad \text{（无 mangling）}$$
$$\text{extern "C++"} \implies \text{符号名} = \text{mangled} \quad \text{（默认）}$$

### inline namespace 的版本透明切换

**设计动机**：库的版本演进中保持 ABI 兼容：
```cpp
namespace MyLib {
    inline namespace v3 {      // 当前默认版本
        inline namespace v2 {  // v2 包含 v3 的子集
            inline namespace v1 {
                // v1 实现
            }
        }
    }
}

// 用户代码无需修改
MyLib::func();  // 始终调用最新版本

// 显式使用旧版本
MyLib::v1::legacy_func();
```

**版本透明切换的约束**：
- 旧版本必须是新版本的子集（语义兼容）
- 用户代码不能依赖具体版本号

### 嵌套命名空间的简化语法（C++17）

```cpp
// 传统写法
namespace A {
    namespace B {
        namespace C {
            void foo();
        }
    }
}

// C++17 简化
namespace A::B::C {
    void foo();
}
```

### using 声明 vs using 指示

**using 声明**（导入单个名字）：
```cpp
using std::cout;  // cout 进入当前作用域
cout << 42;       // 直接使用
```

**using 指示**（导入整个命名空间）：
```cpp
using namespace std;  // std 的所有名字进入当前作用域
cout << 42;           // 直接使用（可能有名字冲突）
```

| 特性 | using 声明 | using 指示 |
|------|-----------|-----------|
| 名字遮蔽 | 遵循普通作用域规则 | 遵循普通作用域规则 |
| 导入范围 | 单个名字 | 命名空间所有名字 |
| 典型用途 | 选择性导入 | 过渡性兼容（如 std 后向兼容） |

**using 指示的数学性质**：
$$\text{using namespace } N \implies \forall name \in \text{decls}(N) : \text{可见性}(name, \text{current}) = \text{true}$$

但这可能导致名字冲突，因为 N 的所有名字都会导入。

## 对比参照

| 机制 | 作用域 | 编译/链接 | 典型用途 |
|------|--------|----------|---------|
| namespace | 编译期 | 编译期符号解析 | 代码模块化、避免名字冲突 |
| class/struct | 编译期 | 编译期符号解析 | 类型作用域 |
| block `{}` | 编译期 | 编译期符号解析 | 局部作用域 |
| static | 翻译单元 | 链接期符号解析 | 内部链接 |

## 参考存根

```cpp
#include <iostream>
#include <string>

// 命名空间声明
namespace MyLib {
    namespace Math {
        int add(int a, int b) { return a + b; }
    }
    namespace String {
        std::string capitalize(const std::string& s) {
            std::string r = s;
            if (!r.empty()) r[0] = std::toupper(r[0]);
            return r;
        }
    }
}

// using 声明
void demo_using() {
    using MyLib::Math::add;
    std::cout << add(1, 2) << "\n";
}

// ADL 演示
namespace Vec {
    struct Vector {
        double x, y;
    };

    // 在 Vec 命名空间中定义运算符
    Vector operator+(const Vector& a, const Vector& b) {
        return {a.x + b.x, a.y + b.y};
    }
}

void demo_adl() {
    Vec::Vector a{1, 2}, b{3, 4};
    auto c = a + b;  // ADL 找到 Vec::operator+
}

// extern "C" 演示
extern "C" {
    void process_data(const char* data, int len);
}

// C++ 中使用 C 库
void use_c_lib() {
    process_data("hello", 5);
}

// C++17 嵌套命名空间
namespace A::B::C {
    inline constexpr int value = 42;
}
```

## 约束与违反后果

| 约束 | 违反后果 |
|------|----------|
| 命名空间别名必须在同一翻译单元内声明 | 编译错误 |
| inline namespace 必须是直接子命名空间 | 编译错误 |
| `using namespace std;` 不可在头文件中使用 | 可能引入名字冲突 |
| ADL 可能找到意外版本的函数 | 行为与预期不符（通常重载决议会选择更匹配的版本） |
| 匿名命名空间成员具有内部链接 | 不同翻译单元的同名符号不冲突，但不可跨翻译单元共享 |
| `extern "C"` 不能用于函数体内部 | 编译错误 |
| using 指示符在头文件中引入名字冲突 | 可能导致难以调试的编译错误 |
| using 声明不能遮蔽外层同名符号 | 编译错误 |
| `namespace N = M` 要求 M 事先存在 | 编译错误 |
