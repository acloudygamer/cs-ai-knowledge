# 变量与类型

**类型是编译期对位模式的语义标注，其本质是告诉编译器如何解释一段内存以及能对它进行哪些操作。**

## 静态类型与类型推导

**`auto` 的本质是以表达式的求值结果初始化变量时，从该结果的类型中移除引用和 cv 限定符。`decltype` 的本质是推导表达式类型但不执行它，保留所有限定符。**

<pre>
int x = 10;
int& ref = x;

auto a = ref;       // auto = int → int（移除引用）
auto& b = ref;      // auto = int → int&（保留引用）

decltype(ref) c = x; // int&（保留原始类型，含引用）
decltype((x)) d = x; // int&（双括号永远是引用）
</pre>

**`decltype(auto)` 的设计动机**：函数返回 `auto` 时会丢弃引用，返回 `decltype(auto)` 则完整保留返回表达式的原始类型。

<pre>
int x = 10;
int& get_ref() { return x; }

auto r1 = get_ref();        // int（引用被丢弃）
decltype(auto) r2 = get_ref(); // int&（引用被保留）
</pre>

**`std::variant` 的本质是类型安全的 union**：编译期穷举可能类型，运行时通过 `std::visit` 分发到类型匹配的处理函数，消除裸 union 的未定义读写风险。

<pre>
#include <variant>
#include <string>

std::variant<int, double, std::string> v = 42;
v = 3.14;
v = "hello";

std::visit([](auto&& arg) {
    // arg 的类型在编译期确定
}, v);
</pre>

## 类型转换机制

**C++ 四种类型转换对应四种不同的语义层级，从安全到危险依次排列。**

| 转换 | 层级 | 检查时机 | 安全性 |
|------|------|---------|--------|
| `static_cast` | 编译期明确定义转换 | 编译期 | 较安全 |
| `dynamic_cast` | 继承层级间安全下行转换 | 运行时 | 安全的失败可检测 |
| `const_cast` | 仅移除/添加 cv 限定符 | 编译期 | 危险（修改 const 行为未定义） |
| `reinterpret_cast` | 位的重解释 | 无检查 | 最危险 |

**`static_cast` 的设计原因**：数值类型之间的转换（如 `double→int`）语义明确，编译期完成，不需要运行时检查。

**`dynamic_cast` 的设计原因**：当通过基类指针访问派生类时，运行时类型信息（RTTI）用于验证下行转换的安全性，失败时返回 `nullptr`。

**`reinterpret_cast` 的设计原因**：底层需要将一段位模式按另一种类型重新解释（如序列化、网络协议），这是一种对硬件的直接映射，不应被类型系统阻止。

<pre>
double d = 3.14;
int i = static_cast<int>(d);   // 截断小数，语义明确

class Base { virtual ~Base() {} };
class Derived : public Base {};
Base* base_ptr = new Derived();
Derived* derived_ptr = dynamic_cast<Derived*>(base_ptr);

const int ci = 10;
int* p = const_cast<int*>(&ci); // 移除 const（危险！）

int* ip = new int(42);
char* cp = reinterpret_cast<char*>(ip); // 位重解释，不做检查
</pre>

## 基本类型与大小

**基本类型的大小由编译器目标平台的内存对齐规则决定，而非语言本身。**

| 类型 | 通常大小 | C++ 标准保证 |
|------|---------|-------------|
| `char` | 1 字节 | 恰好 1 字节 |
| `short` | ≥2 字节 | ≥16 位 |
| `int` | ≥2 字节 | ≥16 位 |
| `long` | ≥4 字节 | ≥32 位 |
| `long long` | ≥8 字节 | ≥64 位 |

**为什么 `int` 是 4 字节而非 8 字节**：历史兼容性。早期 C++ 设计时，32 位是主流寄存器宽度，`int` 自然映射到寄存器宽度。

## 类型别名

**`typedef` 和 `using` 的本质相同——为类型创建一个同义词。但 `using` 支持模板别名，使类型抽象可参数化。**

<pre>
typedef unsigned int uint;           // C++98
using uint = unsigned int;          // C++11，更接近赋值语法

using Vec = std::vector<int>;      // 模板别名（C++14）
Vec v;
</pre>

## nullptr 的设计动机

**`nullptr` 的本质是一个编译期生成的 `std::nullptr_t` 类型的唯一常量。选择它而非 `0` 或 `NULL`，是因为整数 `0` 在重载解析中会匹配指针和整数类型，而 `nullptr` 只匹配指针类型。**

<pre>
void foo(int);
void foo(char*);

foo(nullptr);  // 仅匹配 foo(char*)，无歧义
foo(0);        // 匹配 foo(int)，存在歧义
foo(NULL);     // C++11 中定义为 0，同样存在歧义
</pre>

## 字符串视图（C++17）

**`std::string_view` 的本质是一个 `(ptr, length)` 对，不拥有所有权。设计动机是避免字符串拷贝——很多场景只需要读取字符串而不需要修改或拥有它。**

<pre>
std::string s = "hello world";
std::string_view sv = s;     // 不拷贝，共享同一 buffer
std::string_view sub = sv.substr(0, 5);  // 无拷贝，仅记录偏移和长度
</pre>

## 联合体的本质

**`union` 的本质是所有成员共享同一段内存，成员大小取最大值。这使得同一段位可以按不同类型重新解释，但修改一个成员会覆盖其他成员的位。**

<pre>
union Data {
    int i;
    double d;
    char c;
};
Data data;
data.d = 3.14;   // 写入 double，覆写全部位
data.i = 42;     // 覆写 data.d 的位（危险但合法）
</pre>
