# 安装与环境

## 定义

**编译器是将高级语言源码映射为机器指令的翻译器，其本质是一个**有限状态机驱动的代码变换管道**，通过词法分析、语法分析、语义分析、优化和代码生成五个阶段，将符合语言规范的源码转换为目标文件。**

## 数学模型

### 编译阶段的复杂度

编译器的五个阶段具有不同的计算复杂度：

| 阶段 | 复杂度 | 备注 |
|------|--------|------|
| 词法分析 | $O(n)$ | 线性扫描源码，$n$ 为字符数 |
| 语法分析 | $O(n)$ 或 $O(n^3)$ | LL/LALR 为 $O(n)$，一般解析可达 $O(n^3)$ |
| 语义分析 | $O(n \cdot d)$ | $d$ 为最大嵌套深度 |
| 优化 | $O(n \cdot P)$ | $P$ 为 Pass 数量，可并行化 |
| 代码生成 | $O(n)$ | 寄存器分配是 NP 完全问题，通常用启发式 |

**LLVM 的模块化设计**：将优化和代码生成组织为可插拔的 Pass 架构，使得 $T_{\text{总}} = T_{\text{前}} + \sum_{i=1}^{P} T_{\text{Pass}_i} + T_{\text{后}}$，可并行执行独立 Pass。

### 目标文件格式

| 格式 | 平台 | 结构 |
|------|------|------|
| ELF | Linux, Unix | .text/.data/.bss + 符号表 + 重定位表 |
| PE-COFF | Windows | .text/.data/.rdata + 导出/导入表 |
| Mach-O | macOS | .text/.data + dyld 信息 |

## 数据流

<pre>
源代码 (.cpp)
    │
    ▼ 词法分析 (Lexer) ─── 有限状态自动机
Token 流: [关键字][标识符][字面量][运算符][界符]
    │
    ▼ 语法分析 (Parser) ─── LL/LALR 解析器
AST（抽象语法树）: 节点 = {type, children, semantic_info}
    │
    ├──► 模板实例化 ─── 编译期求值
    ├──► 宏展开 ─── 文本替换
    │
    ▼ 语义分析 (Sema)
带类型标注的 AST + 符号表
符号表: Map<Name, {Type, Scope, Address}>
    │
    ▼ 优化 (Optimizer) ─── SSA 形式
┌─────────────────────────────────────┐
│ Pass 1: 常量折叠                       │
│ Pass 2: 内联                          │
│ Pass 3: 死代码消除                     │
│ Pass N: ...                           │
└─────────────────────────────────────┘
    │
    ▼ 代码生成 (CodeGen)
目标代码 (.o / .obj)
┌─────────────────────────────────────┐
│ 机器指令序列                          │
│ 符号表（导出/导入）                   │
│ 重定位信息                           │
└─────────────────────────────────────┘
    │
    ▼ 链接 (Linker)
可执行文件 / 共享库
</pre>

## 三大编译器对比

| 编译器 | 输出格式 | 平台特性 | 设计取舍 |
|--------|---------|---------|---------|
| g++ (GNU) | ELF / PE-COFF | 广泛兼容 | 优化保守，兼容优先；GCC 是自由软件 |
| clang (LLVM) | Mach-O / ELF / PE-COFF | 错误信息友好 | 模块化，Pass 可替换；Clang 前端 + LLVM 后端 |
| MSVC | PE-COFF | Windows 原生 | 链接 MSVC 运行时；PCH 支持 |

**编译器选择的本质**：不同编译器的优化策略和目标平台支持不同。游戏引擎常用 Clang/LLVM（优化好、错误信息清晰），Windows 原生项目用 MSVC（运行时集成）。

## 编译过程与构建系统

### 编译与链接的分离

<pre>
两遍式编译：

第一遍（编译，不链接）：
g++ -std=c++20 -c main.cpp -o main.o
g++ -std=c++20 -c foo.cpp -o foo.o
     │
     ├──► main.o: 未解析的外部符号 (_foo 函数)
     └──► foo.o: 导出的符号 (_foo)

第二遍（链接）：
g++ main.o foo.o -o app
     │
     └──► 链接器解析 _foo: main.o 的未定义引用 ↔ foo.o 的导出
          生成可执行文件 app
</pre>

**增量构建的数学模型**：设依赖图 $G=(V,E)$，$V$ 为翻译单元，$E$ 为 include 关系。当文件 $v_i$ 变化时，仅需重编译 $\{v_j \in V \mid \exists \text{路径 } v_i \rightarrow^* v_j\}$。

### CMake 工作流

<pre>
CMakeLists.txt（声明式构建描述）
    │
    ▼ cmake ..
配置阶段：检测编译器、平台、依赖
输出：生成器特定的构建文件（Makefile / Ninja / VS 项目）
    │
    ▼ cmake --build .
构建阶段：调用编译器逐单元构建
    │
    └──► 并行构建：cmake --build . -j N（N 个并行任务）
</pre>

```cmake
cmake_minimum_required(VERSION 3.20)
project(MyApp VERSION 1.0 LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
aux_source_directory(src SRCS)
add_executable(myapp ${SRCS})
```

## 包管理器

**包管理器的本质是编译期依赖解析器——将库的源码/头文件/元数据在首次构建时自动下载、编译并集成到项目。**

### vcpkg 工作流

<pre>
vcpkg install spdlog:x64-linux
    │
    ├──► 1. 查询 vcpkg_installed/ 目录
    ├──► 2. 克隆/解压 spdlog 源码
    ├──► 3. 配置：cmake -B build -DCMAKE_TOOLCHAIN_FILE=vcpkg.json
    └──► 4. 编译并安装到 vcpkg_installed/

使用：
CMakeLists.txt 中通过 find_package(spdlog CONFIG REQUIRED)
链接：target_link_libraries(myapp PRIVATE spdlog::spdlog)
</pre>

## 环境验证

```cpp
#include <iostream>
#include <vector>
#include <memory>

int main() {
    // unique_ptr 演示 RAII：自动释放
    auto p = std::make_unique<int>(42);
    std::cout << *p << std::endl;

    // vector + lambda 演示 C++20 特性
    std::vector<int> v{1, 2, 3, 4, 5};
    auto is_even = [](int n) { return n % 2 == 0; };
    auto count = std::ranges::count_if(v, is_even);
    std::cout << "偶数个数: " << count << std::endl;

    return 0;
}
```

## 约束与违反后果

| 约束 | 违反后果 |
|------|----------|
| 头文件改变时，所有依赖它的 .cpp 必须重编译 | 增量构建失效，完整重编译浪费时间 |
| 链接时所有未解析符号必须恰好有一个定义 | 链接错误：`undefined reference to ...` 或 `duplicate symbol` |
| C++ 标准库与编译器版本必须匹配 | 二进制不兼容，运行时崩溃或符号未找到 |
