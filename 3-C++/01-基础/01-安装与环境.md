# 安装与环境

**编译器是将高级语言源码映射为机器指令的翻译器，其本质是一个有限状态机驱动的代码变换管道。**

## 编译器是什么

<pre>
源代码 (.cpp)
    │
    ▼
┌─────────────────────────────┐
│  词法分析 (Lexer)            │  正则匹配 → Token 流
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  语法分析 (Parser)           │  LL/LALR → AST
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  语义分析 (Sema)             │  类型检查 → Annotated AST
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  优化 (Optimizer)           │  SSA / 机器无关优化
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│  代码生成 (CodeGen)          │  机器相关指令生成
└─────────────────────────────┘
    │
    ▼
目标文件 (.obj / .o)
</pre>

**编译器设计的核心取舍**：词法/语法/语义分析是顺序依赖的，但优化和代码生成是可并行化的——这解释了为何 LLVM 将后端设计为可插拔的 Pass 架构。

### 三大编译器对比

| 编译器 | 输出格式 | 平台特性 | 设计取舍 |
|--------|---------|---------|---------|
| g++ (GNU) | ELF / PE-COFF | 广泛兼容 | 优化保守，兼容优先 |
| clang (LLVM) | Mach-O / ELF / PE-COFF | 错误信息友好 | 模块化，Pass 可替换 |
| MSVC | PE-COFF | Windows 原生 | 链接 MSVC 运行时 |

<pre>
# MSVC — Windows 原生
cl /std:c++20 /EHsc main.cpp

# MinGW-w64 — GCC 移植到 Windows
g++ -std=c++20 -O2 -c main.cpp -o main.o

# Linux — GCC/Clang
g++ -std=c++20 -O2 main.cpp -o app
clang++ -std=c++20 -O2 main.cpp -o app
</pre>

## 编译过程与构建系统

**构建系统的本质是任务依赖图管理器，其目标是增量构建——仅重新编译受影响的翻译单元。**

<pre>
# 两遍式编译
g++ -std=c++20 -c main.cpp -o main.o    # 编译，不链接
g++            main.o -o app              # 链接，生成可执行文件

# 增量构建：当 header.h 改变
touch header.h
# → 仅重新编译依赖 header.h 的 .cpp
# → 其他 .o 文件复用（节省时间）
</pre>

### CMake 工作流

<pre>
CMakeLists.txt（声明式）
    │
    ▼  cmake ..
┌─────────────────────────────┐
│  Configure: 检测编译器/平台  │
└─────────────────────────────┘
    │
    ▼  cmake --build .
┌─────────────────────────────┐
│  Generate: 生成原生构建文件  │
│  (Makefile / Ninja / VS)    │
└─────────────────────────────┘
    │
    ▼  make / ninja / msbuild
┌─────────────────────────────┐
│  Build: 调用编译器逐单元构建 │
└─────────────────────────────┘
</pre>

**CMake 解决了什么**：不同平台的生成器（Make/Ninja/VS）和编译器路径不同，CMake 提供统一接口屏蔽这些差异。

<pre>
cmake_minimum_required(VERSION 3.20)
project(MyApp VERSION 1.0 LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
aux_source_directory(src SRCS)
add_executable(myapp ${SRCS})
</pre>

<pre>
mkdir build && cd build
cmake ..
cmake --build .
./myapp
</pre>

## 包管理器

**包管理器的本质是编译期依赖解析器——将库的源码/头文件/元数据在首次构建时自动下载并集成到项目。**

<pre>
vcpkg install spdlog:x64-linux
# 1. 克隆 spdlog 源码到 vcpkg_installed/
# 2. 暴露头文件路径给编译器
# 3. 链接预编译静态/动态库
</pre>

<pre>
git clone https://github.com/Microsoft/vcpkg.git
./bootstrap-vcpkg.sh
vcpkg install spdlog:x64-linux
vcpkg integrate install
</pre>
