# 面向对象

**类的本质是对数据和操作这些数据的函数的统一封装，其核心机制是访问控制——通过 `private`/`protected`/`public` 限定符将接口与实现分离，强制调用方只能通过公开契约访问内部状态。**

## 默认访问级别的设计动机

**C++ 中 `class` 默认 `private`、`struct` 默认 `public` 的设计原因**：struct 保留 C 的 POD 数据兼容性（无成员函数时即等价于 C struct），class 则服务于面向对象的数据抽象。默认值不同是历史兼容性与人机工程学的折中。

<pre>
class PointClass { int x; int y; };        // x, y 默认 private
struct PointStruct { int x; int y; };      // x, y 默认 public
</pre>

## 特殊成员函数与 RAII

**C++ 六大特殊成员函数（Big Six）构成对象生命周期的完整契约：构造（默认/拷贝/移动）→ 使用 → 析构。RAII（Resource Acquisition Is Initialization）的核心依赖是构造和析构的配对——在构造函数中获取资源，在析构函数中释放。**

<pre>
class Buffer {
    char* data_;
public:
    Buffer(size_t size) : data_(new char[size]) {}  // 构造函数获取资源
    ~Buffer() { delete[] data_; }                     // 析构函数释放资源
    // 移动语义：所有权转移
    Buffer(Buffer&& other) noexcept : data_(other.data_) {
        other.data_ = nullptr;
    }
};
</pre>

**`= default` 的本质是显式要求编译器生成隐式版本，保留默认语义。`= delete` 的本质是删除特定重载，使任何调用构成编译错误——用于强制禁止拷贝/移动等危险操作。**

<pre>
class NonCopyable {
    std::vector<int> data_;
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;  // 禁止拷贝构造
};
</pre>

## 继承与访问控制

**继承的本质是"是"（is-a）关系的编译期描述，派生类对象在内存中包含基类子对象。继承访问控制符决定基类成员在派生类中的可见性——实质是控制派生类向外部世界暴露多少基类接口。**

<pre>
class Base { public: void foo(); protected: void bar(); private: void baz(); };

class Pub : public Base {
    // foo() 仍是 public，外部可见
    // bar() 仍是 protected，派生类可见
    // baz() 不可见
};

class Pro : protected Base {
    // foo() 和 bar() 都变为 protected
    // 外部无法直接访问 Base 接口
};

class Pri : private Base {
    // foo() 和 bar() 都变为 private
    // 仅当前类内部可用，派生类不可见
};
</pre>

## 多态的实现机制

**多态的本质是虚函数表（vtable）动态分派。包含虚函数的类有一个隐藏的虚表指针（vptr），指向虚表（vtable）。虚函数调用通过 `vptr[vtable_offset]` 在运行时解析具体类型。**

<pre>
对象内存布局：

Dog 对象（通过 Animal* 指针访问）：
┌─────────────────────┐
│ Animal 部分          │
│   vptr ──────────┐  │
├─────────────────────┤  │
│ Dog 扩展部分       │  │
└─────────────────────┘  │
                          ↓
虚表（Dog）:           ┌──────────────┐
                    │ Animal::~()  │  offset 0
                    │ Animal::foo()│  offset 1
                    │ Dog::speak() │  offset 2 ← 动态分派
                    └──────────────┘

Animal* animal = new Dog(...);
animal->speak();  // 通过 vptr 查找 Dog::speak()，输出 "Woof"
</pre>

**基类析构函数必须为 virtual**：否则通过基类指针删除派生类对象时，只会调用基类析构函数，派生类资源泄漏。

**`override` 的本质是编译期断言——确保派生类的函数确实重写了基类的虚函数，而非定义了新函数。`final` 的本质是禁止进一步重写。**

<pre>
class Base { virtual void foo() const {} };
class Derived : public Base {
    void foo() const override {}  // 编译错误若基类无此虚函数
};
class NoOverride final { virtual void bar() final {} };  // 禁止重写和继承
</pre>

## 友元的本质

**友元的本质是绕过访问控制的开具——被授予友元权限的函数或类可以访问该类的所有 private/protected 成员。这是一种显式的特权授予，而非继承或包含关系。**

<pre>
class Person {
    std::string name_;
    int age_;
public:
    Person(const std::string& name, int age) : name_(name), age_(age) {}
    friend void print(const Person& p);  // 授予 print 访问权限
};

void print(const Person& p) {
    // 可访问 p.name_ 和 p.age_，尽管它们是 private
}
</pre>

## 虚继承解决菱形继承

**菱形继承的问题是：两个路径都包含 Base 子对象，导致 D 有两份 Base 成员。虚继承让派生类共享同一个基类子对象，消除二义性。**

<pre>
菱形继承（D 同时继承 A 和 B，A 又是 Base 的派生）：

class Base {};
class A : public Base {};
class B : public Base {};
class D : public A, public B {};
// D 有两份 Base 子对象（通过 A 路径和 B 路径各一份）

虚继承解决：
class A : virtual public Base {};
class B : virtual public Base {};
class D : public A, public B {};
// D 只有一份 Base 子对象（A 和 B 共享）
</pre>
