# 控制流程

## 定义

**控制流语句通过修改指令指针改变程序执行路径，其本质是 CPU 分支预测和流水线吞吐量的博弈——顺序执行 vs 跳转的代价差决定何时该避免分支。** 控制流的本质是将程序建模为**有向图**，其中节点是基本块（有单一入口、单一出口的连续指令序列），边是控制转移。

从形式语言理论角度看，程序控制流对应**有穷状态自动机**（FSM）的转移：每个基本块是状态，边是转移条件。循环对应**无限循环的自动机**，递归调用对应**栈帧上的状态机展开**。

## 数学模型

### 分支预测的代价模型

现代 CPU 采用**超标量流水线**，每个周期可发射多条指令。分支指令会导致：

$$T_{\text{分支失败}} = T_{\text{流水线深度}} + T_{\text{重新填充}}$$

典型值：
- 流水线深度：10-15 级
- 分支预测失败代价：10-20 个时钟周期

**分支预测准确率**：对于有序数据流（如数值遍历），静态预测（永远预测"不跳转"）准确率可达 90%+；对于分支条件随机（如哈希表查找），需要动态预测（TAGE、神经网络分支预测器）。

**分支目标缓冲器（BTB）的数学模型**：
$$\text{BTB} \subseteq \mathbb{N} \times \mathbb{N} \quad \text{（PC 值 → 目标地址）}$$

BTB 命中时，可预测跳转目标；BTB 未命中时，退化为静态预测。

### switch 的跳转表复杂度

$$\text{跳转表查找复杂度} = \begin{cases} O(1) & \text{case 值连续} \\ O(\log n) & \text{case 值稀疏（二分）} \\ O(n) & \text{case 值极稀疏（顺序）} \end{cases}$$

跳转表的生成条件：
- case 数量 $\geq 4$（编译器决定阈值）
- case 值分布连续或近似连续
- case 值类型为整数或枚举

**跳转表的数学形式**：
$$J[i] = \text{address\_of\_case\_i}$$

编译器生成一个函数指针数组，直接通过索引访问。

### 循环不变式的检测与外提

对于循环 `for (init; cond; inc) body`：
$$I \text{ 是循环不变式} \iff \forall \text{迭代 } k : I \text{ 在第 } k \text{ 次迭代前后值相同}$$

若 $I$ 是循环不变式且 $I$ 在循环外求值，则可外提：
$$\text{循环外提} \Rightarrow \text{减少 } n \times T_{\text{求值}} \text{ 的重复计算}$$

**循环不变式的数学检测**：
$$\text{Loop-Invariant}(I) \iff \text{def}(I) \cap \text{Loop} = \emptyset$$

即若 $I$ 的所有定义都在循环外，则 $I$ 是循环不变的。

### 异常传播的数学模型

异常传播可建模为**非局部控制流**：
$$E: \text{throw} \rightarrow \text{catch}$$

$$\text{栈展开} = \text{沿着调用栈向上传播异常，直到找到匹配的 catch}$$

**异常安全的数学形式化**：

| 保证等级 | 形式化定义 |
|---------|-----------|
| 无保证 | $\text{失败} \implies \text{可能有资源泄漏}$ |
| 基本保证 | $\text{失败} \implies \text{对象状态不变}$ |
| 强保证 | $\text{失败} \implies \text{状态如调用前}$ |
| 不抛出保证 | $\nexists e : \text{throw}(e)$ |

## 数据流

### if/else 的分支预测数据流

<pre>
源码:
    if (cond) {
        body_true;
    } else {
        body_false;
    }

编译后（x86 伪指令）:
    cmp cond, 0          ; 比较条件
    je  .L_else         ; 预测失败跳转到 else
    ; 预测成功：执行 body_true
    jmp .L_end
.L_else:
    ; 执行 body_false
.L_end:
    ; 继续执行

流水线状态:
    预测成功: [cmp] → [body_true] → [jmp] → ...
    预测失败: [cmp] → [flush] → [body_false] → ...

    flush = 丢弃已预取的错误路径指令
</pre>

**分支预测的训练**：CPU 记录每个分支的历史（taken/not taken），用于预测下次行为。

### 循环的数据流

<pre>
源码:
    for (int i = 0; i < n; i++) {
        body;
    }

编译后（三种优化级别）:

Level 0（无优化）:
    i = 0
.loop:
    if (!(i < n)) goto .end
    body
    i++
    goto .loop
.end:

Level 1（循环展开 4 次）:
    i = 0
.loop4:
    if (i+4 >= n) goto .loop1  ; 剩余处理
    body; i++  × 4
    goto .loop4
.loop1:
    if (i < n) { body; i++; goto .loop1; }
.end:

Level 2（SIMD 向量化）:
    ; body 被向量化为 4 元素并行操作
    ; 每次迭代处理 4 个元素
</pre>

**循环展开的数学效应**：
- 减少分支次数：$n$ 次迭代 → $\lceil n/k \rceil$ 次分支
- 启用指令级并行：多个 body 实例可同时执行
- 代码膨胀：$k$ 倍

### C++20 初始化语句的作用域隔离

```cpp
// C++17 及之前
auto it = m.find(key);
if (it != m.end()) {
    // it 在整个函数作用域可见，可能误用
}

// C++20
if (auto it = m.find(key); it != m.end()) {
    // it 仅在此 if-else 块内可见
}
// it 在此处不可见，无法误用
```

**作用域隔离的数学语义**：初始化语句创建的变量属于**保护子句**（guard clause），其作用域限于最近的 if-else 复合语句。

### try-catch 的栈展开数据流

<pre>
异常传播的数据流:
    try {
        throw 42;
    } catch (const int& e) {
        // 处理异常
    }

编译后的栈展开:
    1. throw 触发：编译器插入 std::terminate() 调用链
    2. 栈帧逐层弹出：每个析构函数被调用（RAII 保证）
    3. 异常对象被拷贝到 std::exception_ptr 管理的存储
    4. 匹配 catch 子句：按声明顺序匹配，第一个兼容类型被选中
    5. 匹配失败：栈展开继续直到 std::terminate()

异常安全等级:
    - 不抛出保证（noexcept）：若析构函数抛出，std::terminate 被调用
    - 强保证：操作要么成功，要么状态不变
    - 基本保证：操作可能失败，但无资源泄漏
</pre>

**栈展开的约束**：
- 若析构函数在栈展开期间抛出异常，`std::terminate` 被调用
- 这就是为什么析构函数不应抛出异常的铁律

## 机制

### 条件分支的 CPU 实现

**x86 条件分支指令**：
- `je/jz`：等于/为零跳转
- `jne/jnz`：不等于/非零跳转
- `jg/jl`：大于/小于跳转（带符号）
- `ja/jb`：高于/低于跳转（无符号）

**CPU 预测机制**：
1. **BTB（分支目标缓冲器）**：记录最近分支的跳转目标
2. **TAGE（Tagged Geometric History Predictor）**：基于分支历史模式
3. **神经网络分支预测器**：Intel Skylake+ 采用

**违反约束的后果**：分支预测失败时，CPU 必须 flush 流水线，丢弃已经预取的错误路径指令，导致 10-20 周期浪费。

### switch 跳转表的生成条件

跳转表不是无条件生成的，编译器基于以下启发式规则：

| 条件 | 阈值 | 说明 |
|------|------|------|
| case 数量 | $\geq 4$ | 太少不值得 |
| case 值连续性 | $\geq 80\%$ | 稀疏表空间效率低 |
| 跳转目标距离 | < 2KB | 短跳转编码效率高 |

**稀疏 switch 的退化为二分查找**：当 case 间隔大时（如 `case 1: case 1000: case 1000000:`），编译器生成二分查找树。

### 循环的 CPU 优化

**循环展开（Loop Unrolling）**：
- 减少分支指令数量：$n$ 次迭代 → $\lceil n/k \rceil$ 次分支
- 启用指令级并行：多个 body 实例可同时执行
- 代价：代码膨胀（$k$ 倍）

**寄存器分配的影响**：
$$\text{循环内变量存活周期} \Rightarrow \text{需同时在寄存器中保持的变量数}$$

若超过可用寄存器数，则发生寄存器溢出到栈，性能下降。

### goto 的约束与危害

**goto 的唯一合法用途**：
1. 跳出深层嵌套循环（单一 break/continue 无法做到）
2. 错误处理时的统一清理跳转点

**禁止跳入作用域**：跳入作用域会导致局部对象未构造，析构函数不会被调用：
```cpp
goto skip;
{
    std::mutex mtx;  // 构造函数已跳过
}
skip:
    ; // mtx 从未被构造，析构函数不会被调用
    // RAII 保证被破坏——资源泄漏
```

### C++23 循环标签

```cpp
outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (condition(i, j)) continue outer;  // 继续外层循环
        if (stop()) break outer;               // 跳出外层循环
    }
}
```

**标签语法**：标签后跟循环语句，用于 `break`/`continue` 指定目标层级。

### try-catch 的异常安全保证

| 保证等级 | 形式化 | 实现要求 |
|---------|--------|---------|
| 无保证 | 异常可能导致资源泄漏 | — |
| 基本保证 | $\text{失败} \implies \text{状态不变}$ | 复制语义或事务回滚 |
| 强保证 | $\text{失败} \implies \text{状态如调用前}$ | 两阶段提交或 rollback |
| 不抛出保证 | $\text{操作永不抛出}$ | noexcept + 措施保证 |

**noexcept 的约束**：
```cpp
void f() noexcept {
    // 若 f 内部抛出异常，std::terminate 被立即调用
    // 不进行栈展开，不调用 catch
}
```

**noexcept 的数学语义**：
$$\text{noexcept}(f) = \text{true} \implies \nexists e : \text{throw}(f, e)$$

### 范围 for 循环的等价变换

```cpp
for (auto x : container) {
    body;
}

// 编译器重写为：
auto __begin = container.begin();
auto __end = container.end();
for (; __begin != __end; ++__begin) {
    auto x = *__begin;
    body;
}
```

**约束**：container 必须提供 `begin()` 和 `end()`，且返回的迭代器必须支持 `!=`、`++`、`*` 操作。

## 参考存根

```cpp
#include <iostream>
#include <vector>
#include <stdexcept>

// 范围 for 循环的等价变换
void demo_range_for() {
    std::vector<int> vec = {1, 2, 3, 4, 5};

    // 编译器重写为：
    // for (auto __it = vec.begin(); __it != vec.end(); ++__it)
    //     int n = *__it;
    for (int n : vec) {
        std::cout << n << " ";
    }
    std::cout << "\n";
}

// switch 跳转表演示
enum class Day { Mon, Tue, Wed, Thu, Fri, Sat, Sun };

int day_type(Day d) {
    // 连续枚举值，编译器生成跳转表
    switch (d) {
        case Day::Mon: [[fallthrough]];
        case Day::Tue: [[fallthrough]];
        case Day::Wed: [[fallthrough]];
        case Day::Thu: [[fallthrough]];
        case Day::Fri: return 1;  // 工作日
        case Day::Sat: [[fallthrough]];
        case Day::Sun: return 0;  // 休息日
    }
}

// goto 用于错误处理
int process_with_cleanup() {
    int* p1 = nullptr;
    int* p2 = nullptr;

    p1 = new int[100];
    if (!init1(p1)) goto cleanup;

    p2 = new int[100];
    if (!init2(p2)) goto cleanup;

    // 正常流程
    return 0;

cleanup:
    delete[] p1;
    delete[] p2;
    return -1;
}

// 异常安全演示
class Transaction {
    bool committed_ = false;
public:
    void commit() { committed_ = true; }
    ~Transaction() {
        if (!committed_) rollback();
    }
};

void safe_operation() noexcept {
    Transaction t;
    // 操作...
    t.commit();
    // 若中间抛出异常，rollback 被自动调用
}
```

## 约束与违反后果

| 约束 | 违反后果 |
|------|----------|
| `continue` 只能在循环体内 | 编译错误 |
| `break` 只能跳出最近一层 switch/循环 | 编译错误 |
| `goto` 禁止跳入作用域 | RAII 被破坏，资源泄漏 |
| `case` 标签后无 `break` 则贯穿 | 可能导致逻辑错误（除非故意 fallthrough） |
| 循环内修改循环变量（非终止条件） | 不可预测行为 |
| noexcept 函数内抛出异常 | std::terminate，无栈展开 |
| 构造函数的异常 | 部分构造的对象被栈展开销毁（已构造的成员） |
| 析构函数抛出异常 + 栈展开中 | std::terminate |
| `[[fallthrough]]` 用于非 fallthrough 场景 | 编译警告 |
