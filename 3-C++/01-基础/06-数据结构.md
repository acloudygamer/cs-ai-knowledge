# 数据结构

## 定义

**数据结构是在内存中组织数据的方式，其本质是访问模式（随机 vs 顺序）与插入/删除代价的权衡——没有万能结构，只有在特定访问模式下的最优选择。** 数据结构的选择取决于三个因素：**访问模式**（随机 vs 顺序）、**操作频率**（读多写少 vs 写多读少）、**局部性特征**（时间局部性 vs 空间局部性）。

从信息论角度看，数据结构是**编码方案**——相同的逻辑信息可以有不同的物理表示。选择哪种表示，取决于对信息的操作模式。良好的数据结构设计使得**高频操作的代价最小化**，同时在多种操作之间取得平衡。

### vector 扩容的均摊分析

设增长因子 $k > 1$ （通常 $k = 2$），容量序列： （通常 $k = 2$），容量序列： ），容量序列：
 $c_{i+1} = \max(\lfloor k \cdot c_i \rfloor, 1)$ 

第 $i$ 次扩容时已有 $c_i$ 个元素，总移动代价： 次扩容时已有 $c_i$ 个元素，总移动代价： 个元素，总移动代价：
 $T(n) = \sum_{i=0}^{\lfloor \log_k n \rfloor} c_i = \sum_{i=0}^{\lfloor \log_k n \rfloor} k^i = \frac{k^{\lfloor \log_k n \rfloor + 1} - 1}{k - 1} \leq \frac{k \cdot n}{k - 1} = O(n)$ 

均摊到每次插入：
 $\bar{T}(n) = \frac{T(n)}{n} = O(1)$ 

### deque 的数学模型

Deque 采用**分段连续缓冲区**结构：
- 逻辑上连续，物理上分散
- 头部插入/删除： $O(1)$ （在当前缓冲区操作） （在当前缓冲区操作）
- 随机访问： $O(1)$ （计算缓冲区索引 + 偏移） （计算缓冲区索引 + 偏移）

内存增长策略：按需分配新缓冲区，不进行整体扩容。

**缓冲区映射表的大小增长**：
 $\text{map-size}_{i+1} = \begin{cases} 2 \times \text{map-size}_i & \text{当满时} \\ \text{原大小} & \text{否则} \end{cases}$ 

### 堆的性质

完全二叉堆的数组索引关系（从 0 开始）：
 $\text{parent}(i) = \lfloor (i - 1) / 2 \rfloor$ 
 $\text{left}(i) = 2i + 1$ 
 $\text{right}(i) = 2i + 2$ 

**堆序性**：对于最大堆，父节点 $\geq$ 子节点： 子节点：
 $\forall i : \text{heap}[parent(i)] \geq \text{heap}[i]$ 

堆的高度：
 $h = \lfloor \log_2 n \rfloor$ 

插入/删除的代价： $O(h) = O(\log n)$ 

### 迭代器失效的数学描述

| 容器 | 插入操作 | 删除操作 |
|------|---------|---------|
| vector | 所有迭代器失效（可能扩容） | 被删元素之后的所有迭代器失效 |
| deque | 仅首尾迭代器可能失效 | 被删元素迭代器失效 |
| list | 仅涉及节点的迭代器有效 | 仅被删元素的迭代器失效 |
| map/set | 所有迭代器保持有效 | 仅被删元素的迭代器失效 |

**失效条件的形式化**：
 $\text{失效}(it, op) \iff \text{op 改变了 it 指向的内存地址或容器结构}$ 

## 数据流

### vector 扩容的数据流

<pre>
初始状态 (cap=4, size=3):
堆内存: [ A ][ B ][ C ][ 空闲 ]
           ↑
         data 指针

触发扩容 (size == cap):
1. 分配新内存 (new_cap = 8)
堆内存: [ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ]

2. 移动元素到新内存
堆内存: [ A ][ B ][ C ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ]
              ↓（移动语义，无拷贝）

3. 释放旧内存
旧内存: [ 释放 ]
新内存: [ A ][ B ][ C ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ][ 空闲 ]
                ↑
              data 指针更新
</pre>

**所有权变换**：
1. 旧内存持有元素的所有权
2. 新内存通过移动构造获取元素所有权
3. 旧内存析构，释放所有权

### list 节点操作的指针变换

<pre>
插入节点 (已知 position):
    [A] <-> [B] <-> [C]
           ↑
      position = B

插入操作:
    node->prev = position
    node->next = position->next
    position->next->prev = node  (若 next 存在)
    position->next = node

结果:
    [A] <-> [B] <-> [X] <-> [C]
                ↑
             新节点 X

删除节点 (已知 it):
    it->prev->next = it->next
    it->next->prev = it->prev
    delete it->data
    delete it
</pre>

**指针操作的原子性**：list 的节点操作涉及多个指针修改，不是原子操作。多线程环境下需要额外同步。

### deque 的缓冲区管理

<pre>
逻辑视图:  E F G H I J K L
              ↑   ↑
            begin end

物理存储（3 个缓冲区，每区 4 元素）:
Buffer[0]: [ A ][ B ][ C ][ D ]   ← 头端
Buffer[1]: [ E ][ F ][ G ][ H ]
Buffer[2]: [ I ][ J ][ K ][ L ]   ← 尾端

逻辑索引计算:
    逻辑位置 4 (E) → Buffer[1], 偏移 0
    逻辑位置 7 (H) → Buffer[1], 偏移 3
    逻辑位置 8 (I) → Buffer[2], 偏移 0

跨缓冲区访问: 逻辑连续，物理需要缓冲区跳转
</pre>

### priority_queue 的 sift-up/sift-down

<pre>
sift-up (插入时):
    插入 95 到末尾:
    堆: [ 90 ][ 85 ][ 70 ][ 80 ][ 60 ][ 50 ][ 65 ][ 95 ]
                                    ↑
                                  新位置

    逐层上浮:
    位置 7: 95 > 父节点 80 (位置 3) → 交换
    位置 3: [ 90 ][ 85 ][ 70 ][ 95 ][ 60 ][ 50 ][ 65 ][ 80 ]
                                    ↑
                                  当前位置

    位置 1: 95 > 父节点 85 (位置 0) → 交换
    位置 0: [ 95 ][ 90 ][ 70 ][ 80 ][ 60 ][ 50 ][ 65 ][ 85 ]

sift-down (删除根时):
    用末尾 85 替换根 95:
    [ 85 ][ 90 ][ 70 ][ 80 ][ 60 ][ 50 ][ 65 ]

## 机制

### 缓存局部性的影响

**缓存行大小**：通常 64 字节

连续内存访问（vector）：
- 访问 `vec[0]` 时，CPU 加载包含 `vec[0..7]` 的整个缓存行（假设 int=8 字节）
- 后续 `vec[1..7]` 访问命中缓存， $O(1)$ 命中时间 命中时间

链式访问（list）：
- 每个节点的地址在运行时决定，CPU 无法 prefetch
- 每次 `node->next` 跳转可能导致缓存未命中
- $n$ 个节点的 list 访问代价： $\sum_{i=1}^{n} T_{\text{miss}}(i)$ 个节点的 list 访问代价： $\sum_{i=1}^{n} T_{\text{miss}}(i)$ 

**量化差异**：对于遍历操作，vector 比 list 快 10-100 倍，取决于元素大小。

**空间局部性原理**：
 $P(\text{访问 } x_{i+1} \mid \text{已访问 } x_i) \gg P(\text{访问任意元素})$ 

连续内存访问的概率远高于随机访问的概率。

### 适配器的实现约束

`std::stack` 和 `std::queue` 是**适配器**，不是独立容器：

| 适配器 | 必需接口 | 默认底层容器 |
|--------|---------|-------------|
| stack | `push_back`, `pop_back`, `back` | deque |
| queue | `push_back`, `pop_front`, `front` | deque |
| priority_queue | 无直接的容器操作 | vector（作为堆） |

**deque 被选为默认底层容器的原因**：
- `push_back` / `push_front` 均为 $O(1)$ 
- 支持随机访问
- 内存局部性优于 list

### priority_queue 的堆操作

**push（上浮）**：
```
1. 将新元素放到末尾
2. while (新元素 > 父节点) swap
3. 上浮到正确位置
代价: O(log n)
```

**pop（下沉）**：
```
1. 保存根（最大元素）
2. 将末尾元素放到根
3. while (根 < 子节点中最大) swap
4. 下沉到正确位置
5. 返回保存的根
代价: O(log n)
```

**堆的数组实现优势**：
- 无指针开销（vs list 的 prev/next 指针）
- 缓存局部性好（节点在内存中连续）
- 实现简单

### array 的栈分配语义

`std::array<T, N>` 是**栈分配**的固定大小容器：
 $|\text{array}| = N \times |\text{T}| \quad \text{编译期已知}$ 

```cpp
std::array<int, 4> arr = {1, 2, 3, 4};
// 编译期大小：4 * 4 = 16 字节
// 存储在栈上（若在函数作用域）
```

**与原始数组的差异**：
- `std::array` 是完整类型，支持拷贝赋值
- 原始数组退化为指针，丢失大小信息
- `std::array` 提供边界检查的 `at()` 方法（抛出异常）

### forward_list 的只读迭代器优势

单向链表 `std::forward_list` 提供：
- $O(1)$ 插入/删除（已知位置） 插入/删除（已知位置）
- 最小内存开销：无 `prev` 指针
- `before_begin()` 支持 `insert_after`

```cpp
std::forward_list<int> lst = {1, 2, 3, 4};
// 插入元素 99 到 3 之后
auto it = lst.begin();
++it; ++it;  // 指向 3
lst.insert_after(it, 99);
```

## 参考存根

```cpp
#include <vector>
#include <deque>
#include <list>
#include <stack>
#include <queue>
#include <priority_queue>
#include <array>
#include <forward_list>
#include <iostream>

// vector 扩容演示
void demo_vector_growth() {
    std::vector<int> v;
    std::cout << "cap: " << v.capacity() << "\n";
    for (int i = 0; i < 10; i++) {
        v.push_back(i);
        std::cout << "size: " << v.size()
                  << ", cap: " << v.capacity() << "\n";
    }
}

// deque 跨缓冲区访问
void demo_deque() {
    std::deque<int> dq = {1, 2, 3, 4, 5};
    dq.push_front(0);  // O(1)
    dq.push_back(6);   // O(1)
    std::cout << "dq[2] = " << dq[2] << "\n";  // O(1) 随机访问
}

// priority_queue 演示
void demo_priority_queue() {
    std::priority_queue<int> pq;
    pq.push(3);
    pq.push(1);
    pq.push(5);
    pq.push(2);
    pq.push(4);

    // 输出: 5 4 3 2 1
    while (!pq.empty()) {
        std::cout << pq.top() << " ";
        pq.pop();
    }
    std::cout << "\n";
}

// forward_list 演示
void demo_forward_list() {
    std::forward_list<int> flst = {1, 2, 3, 4};
    flst.insert_after(flst.before_begin(), 0);  // 插入到头部之前
    for (int x : flst) std::cout << x << " ";  // 输出: 0 1 2 3 4
}

// array 演示
void demo_array() {
    std::array<int, 5> arr = {1, 2, 3, 4, 5};
    // arr.at(10);  // 抛出 std::out_of_range
    for (auto it = arr.rbegin(); it != arr.rend(); ++it)
        std::cout << *it << " ";  // 输出: 5 4 3 2 1
}
```

## 约束与违反后果

| 约束 | 违反后果 |
|------|----------|
| vector 插入/删除后，原迭代器可能失效 | 迭代器悬空，访问崩溃 |
| deque 的迭代器不支持算术运算（需跳转缓冲区） | 编译错误或逻辑错误 |
| list 的 `erase(it)` 返回后继迭代器 | 未使用的返回值被忽略，迭代器失效 |
| priority_queue 不支持随机访问 | `pq[0]` 编译错误 |
| stack/queue 不支持迭代器遍历 | `for (auto x : s)` 编译错误 |
| forward_list 的 `erase_after` 返回后继 | 必须使用返回值继续迭代 |
| array 大小必须编译期已知 | `std::array<int, n>` 中 `n` 必须是常量表达式 |
| 堆的 `operator<` 必须与优先级语义一致 | 堆序性被破坏，行为未定义 |
| deque 跨缓冲区迭代时不能使用 `+`/`-` | 必须使用 `++`/`--` 逐个缓冲区跳转 |
