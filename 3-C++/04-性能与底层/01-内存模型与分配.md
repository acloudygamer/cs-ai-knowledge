# 01-内存模型与分配

> 前置：[04-类与资源管理](../01-语言核心/04-类与资源管理.md)（RAII 与智能指针：谁来调用 delete）· 后续：[02-性能优化](02-性能优化.md)、[03-链接与ABI](03-链接与ABI.md)

> **版本基准**：C++20；C++23/26 特性行内标注。示例实测环境：GCC 14.2（MinGW-w64，Windows），`-std=c++20 -static`。

C++ 里每个对象都回答两个问题：住在哪块存储上（存储期），地从谁手里批的（分配器）。本篇沿这两问展开：四族存储期决定生灭时机，堆与栈的成本结构决定分配该往哪儿放，operator new/delete 是语言留给自定义分配的挂接点，对齐与缓存行把分配问题接到硬件上。注意"内存模型"一词在 C++ 里还有另一义——并发下读写可见性的规则（内存序），那半在 [05-并发与协程](../02-标准库/05-并发与协程.md)，本篇只讲存储与分配。

## 本质

**存储期（storage duration）是对象的寿命规则**：从哪一刻有存储、到哪一刻回收。四族各由一条不同的机制驱动：

| 存储期 | 生灭时机 | 住在哪 | 成本结构 |
|---|---|---|---|
| 自动（automatic） | 进作用域生、出作用域灭 | 栈帧 | 栈指针加减，各一条指令 |
| 动态（dynamic） | `new` 生、`delete` 灭，程序员配对 | 堆 | 分配器记账：找块、改账本、还块 |
| 静态（static） | 首次经过定义（局部）/启动时（全局）生，程序终结灭 | 数据段 | 零分配成本；初始化线程安全由运行时担保（C++11 起） |
| 线程局部（thread_local） | 随线程生灭，每线程各一份 | 每线程的 TLS 段 | 访问多一次段基址查表，略贵于普通静态 |

四族的分工是寿命的分工：寿命跟作用域走的放栈上，跟程序走的放静态区，说不清的才上堆——堆是唯一"生灭时机由程序员说了算"的一族，自由与责任同源（配对失败的后果是泄漏与悬垂，回收纪律见 [04-类与资源管理](../01-语言核心/04-类与资源管理.md) 的 RAII）。

## 机制

### 栈 = 指针移动，堆 = 分配器账本

栈分配的全部工作是移动栈指针：函数入口把 `rsp` 减一个编译期算好的帧大小，出口加回来（x86-64 口径）。分配与释放各一条指令，没有簿记，这就是为什么"局部对象比堆对象便宜"是结构性事实而非经验。代价是容量钉死：Windows 桌面程序默认栈保留 1 MB（链接器 `/STACK` 可调）、Linux 默认 8 MB（`ulimit -s`），深递归或大局部数组直接栈溢出。

堆分配要找一块够大的空闲内存并记下这笔账。glibc 的 ptmalloc、Windows 的 HeapAlloc 都是同一类结构：向 OS 批发大块（`mmap`/`VirtualAlloc`，机制见 [0-计算机基础/内存管理](../../0-计算机基础/02-系统软件层/04-内存管理.md)），切成小块零售，账本（空闲块链表/红黑树）记录哪些块可用；多线程下账本本身还要上锁。一次 `new int` 的真实路径是：分配器查账本 → 命中空闲块则改账返回，未命中则向 OS 批发 → 调用构造函数。释放时回收记账、尝试与相邻空闲块合并——碎片（空闲块总量够但没有连续大块）是账本的结构性副产品。

### operator new/delete：与 malloc 的关系及挂接点

`new T` 展开为两步：调 `operator new(sizeof(T))` 拿地，再在拿到的地上调构造函数；`delete` 逆序：先析构，再 `operator delete` 还地。默认 `operator new` 的语义就是"malloc 加失败处理"：分配失败时反复调用 new-handler（可注册的回调，默认空）直到成功，handler 救不回来才抛 `std::bad_alloc`——所以裸 `new` 不检查返回值，失败路径是异常（见 [07-错误处理](../01-语言核心/07-错误处理.md)）。

挂接点有两个层级：**全局**可替换 `operator new`/`operator delete`（全程序生效，malloc 级自定义），**类级**可为某个类重载（该类的对象走专属分配器）。另有一个不分配内存的形态：**定位 new（placement new）**——`new (地址) T`，在既有缓冲上就地构造，等于把两步拆开只执行第二步；容器在预留容量上构造元素就靠它。

### 对齐：alignof/alignas 与缓存行

**对齐（alignment）**是对象地址必须满足的整除约束：`alignof(T)` 给出类型 T 的要求（64 位平台上基本类型等于其大小，结构体取成员最大者），`alignas(n)` 抬高它。约束来自硬件：x86-64 宽容（未对齐访问只是慢），部分 ARM/RISC 平台未对齐访问直接总线错误；原子与 SIMD 指令（如 AVX 的 32 字节对齐加载）则把对齐当作契约。

对齐真正的性能含义在缓存行：**缓存以行为单位搬运，不按字节**（背景见 [0-计算机基础/硬件组成](../../0-计算机基础/01-计算机体系/01-硬件组成.md)）。x86-64 主流桌面/服务器（Intel、AMD，2010 年代至今）缓存行 64 字节；跨行对象一次访问变两次搬运。C++17 起 `new` 对 over-aligned 类型（对齐要求超过 `__STDCPP_DEFAULT_NEW_ALIGNMENT__`，本机 16 字节）自动分发到对齐版 `operator new(size, align_val_t)`，此前得手写 `posix_memalign`/`_aligned_malloc`。

### 分配器与 PMR：换掉账本

**分配器（allocator）**是容器的内存来源接口：`allocate(n)` 拿地、`deallocate(p, n)` 还地。默认 `std::allocator` 转调 `operator new`。C++17 的 PMR（Polymorphic Memory Resources，`std::pmr`）把分配器改成运行期多态：容器持 `memory_resource*` 指针，换资源不换类型。标准给三种现货：

| 资源 | 行为 | 正当场景 |
|---|---|---|
| `monotonic_buffer_resource` | 在大缓冲上推进偏移记账，只进不退；deallocate 是空操作，整体析构一次归还 | 生命周期同生共灭的一批对象：每请求、每帧、每次解析 |
| `unsynchronized_pool_resource` | 按大小分池回收复用，无线程同步 | 单线程内高频分配释放同尺寸对象 |
| `synchronized_pool_resource` | 同上，加锁 | 多线程共享一个池 |

自定义 arena（预批一大块、内部切分、整批归还）的正当场景与 monotonic 资源相同：当分配次数多、单个对象小、且能指出一个"全体一起死"的时刻，账本成本可以整个删掉。代价对称：arena 内的对象不能单独释放，寿命不齐的对象放不进去。

### false sharing：账本之外的硬件税

两个核写**同一缓存行的不同字节**，变量本身无共享，但缓存一致性协议（MESI 类）以行为单位失效：每次写入都使对方核的整行副本作废，行在两个核的缓存间来回乒乓，吞吐显著塌掉——这就是伪共享（false sharing）。修法是让热变量独占缓存行：`alignas(std::hardware_destructive_interference_size)`（C++17，本机实测 64）。该常数是编译器给的"可能干扰的最大字节数"典型值，平台相关，跨平台代码应直接用它而非硬编 64。多线程计数器、每线程槽位的数组是经典中招点；并发语义的其余部分见 [05-并发与协程](../02-标准库/05-并发与协程.md)。

## 示例

（GCC 14.2 MinGW 实测，`g++ -std=c++20 -O2 -static`；动态链接在本机两套 MinGW 并存时会因 DLL 错配退出码 127，静态链接规避。）

```cpp
#include <array>
#include <cstddef>
#include <cstdint>
#include <iostream>
#include <memory_resource>
#include <new>
#include <vector>

int g_static = 1;            // 静态存储期：程序全程存活
thread_local int g_tls = 2;  // 线程局部存储期：每线程各一份

struct alignas(64) Line {    // 强制 64 字节对齐（x86-64 缓存行典型值）
    std::uint64_t seq;
};

int main() {
    int local = 3;                       // 自动存储期：随作用域生灭
    int* heap = new int(4);              // 动态存储期：new/delete 配对

    std::cout << "alignof(Line)=" << alignof(Line) << '\n';        // 64
    std::cout << "sizeof(Line)=" << sizeof(Line) << '\n';          // 64：对齐把尺寸补齐
    std::cout << "alignof(max_align_t)=" << alignof(std::max_align_t) << '\n';  // 16
    std::cout << "cache_line=" << std::hardware_destructive_interference_size << '\n';  // 64

    // PMR：monotonic 资源在既有缓冲上记账式分配，只进不退，整批归还
    std::array<std::byte, 4096> buf;
    std::pmr::monotonic_buffer_resource pool{buf.data(), buf.size()};
    std::pmr::vector<int> v{&pool};      // 元素内存取自 buf，全程不碰堆
    for (int i = 0; i < 100; ++i) v.push_back(i);
    long sum = 0;
    for (int x : v) sum += x;
    std::cout << "pmr_sum=" << sum << '\n';                      // 4950

    delete heap;
    std::cout << "locals=" << local + g_static + g_tls << '\n';  // 6
}
```
