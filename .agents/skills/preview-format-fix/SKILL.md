# 预览格式修复

目标只有一个：**让这份文件在这台机器的侧栏预览里显示正常**。

这里没有可援引的外部规范。预览器有自己的脾气，规则只能从它的实际行为里读出来；照别处的习惯改，很可能改错方向。下面每一条都标了来源和日期，没有来源的规则不该出现在这里。

## 一、对象是什么

预览由 `@deepseek-ai/dsh-client-ui-sidebar-documentpreview` 提供，渲染管线在 `dsh-web-frontend` 的打包文件里。从代码里读到的实现：

| 环节 | 实现 |
| --- | --- |
| 解析 | micromark → mdast |
| 表格 | 表格扩展，产出 `tableRow` / `tableCell` 节点 |
| 公式 | KaTeX，`inlineMath`（行内）与 `math`（块级）两种节点 |
| 内联 HTML | 正常渲染 |

记这些是为了出问题时能回到源头查，不是为了拿它们去推结论——结论一律以预览里的实际表现为准。

## 二、实测行为表

2026-10-28 在本机实测，来源是 `probe.md` 六项探针与两张预览截图。动手前先确认这张表还成立。

| 行为 | 实测结果 |
| --- | --- |
| 单元格内 `<br>` | 换行 |
| 正文内 `<br>` | 换行 |
| 行内 `$...$` | 渲染为数学体 |
| 块级 `$$...$$` | 独立成行居中 |
| 列表 3 空格缩进 | 层级正确 |
| 表格之间的空行 | **不断表，两表合并成一张** |
| 不以 `|` 开头的行 | 结束当前表格 |
| 分隔线列数 ≠ 表头列数 | **整块退化成纯文字** |
| 同一行出现成对的 `~` | 中间的文字变删除线；行内 `~` 为奇数时，最后一个 `~` 之后全被划掉 |

最后两行是这份文件里最要紧的：一旦表格被截断或列数对不上，结果不是「少一列」「少一行」，是整块变成普通段落，满屏竖线。

## 三、表格散架的两类真因

### 原因 A：分隔线列数与表头不一致

```markdown
| 三列 | 三列 | 三列 |
| --- | --- |
| 1 | 2 | 3 |
```

上例会整块渲染成一行带竖线的文字。修法：把分隔线补齐到与表头相同的列数。

### 原因 B：行内有以非 `|` 开头的续行

```markdown
| **Ⅰ 片内** | … 40~55 ns。<br>
                          ← 空行，无害，不必删
<br>**片内带宽：TB/s 级**   ← 不以 | 开头，表格到此结束
```

表格一断，后面的碎片既没有表头也没有分隔线，只能原样显示。修法：把这一行的全部内容并进一行，行内换行交给 `<br>`。

**空行不是元凶。** 这个预览器遇到空行会跳过、继续收后面的 `|` 行。删空行既解决不了问题，还会让源文件更难读。真正的边界是「这一行是不是以 `|` 开头」。

## 四、动手前先做探针

规则会随预览版本漂移，别凭记忆改正文。先写一个独立的 `probe.md`，只放要验证的项：

```markdown
## 1 表格内的换行标记

| 甲 | 乙<br>丙 |
| --- | --- |
| 1 | 2 |

## 2 表格之间隔空行

| A | B |
| --- | --- |

| C | D |
| --- | --- |

## 3 分隔线少于表头

| 三列 | 三列 | 三列 |
| --- | --- |
| 1 | 2 | 3 |
```

在侧栏打开看实际效果。三项足够区分「预览器变了」还是「这份文件写错了」。探针保持独立，别塞进正在改的正文。

## 五、修完怎么验

1. 表格块内每一行都以 `|` 开头，中间没有非 `|` 行。
2. 块内所有行的单元格数一致——表头、分隔线、每个数据行都算。
3. `\r\n` 与 `\n` 计数相等，不留混合行尾。
4. 只改出问题的那一块，用 `git diff` 复核；顺手重排全文会把真正的修复埋掉。
5. 回到预览看一眼，确认表头、分隔线、数据行连成一块，而不是散成几段。

## 六、这个 skill 自己会改

规则不是权威，是当前证据的摘要。出现下面任一情况，以新观察为准，回来改第二节：

- 探针结果与第二节对不上；
- 预览升级后原来的修法失效；
- 碰到第二节没收录的行为——某处显示异常，但试出来的改法有效。

改法固定三步：先在实测表里加一行或改一行，写明日期；再把受影响的修法段同步过去；最后在下面记一笔变更。不要把表悄悄改掉，后来的人需要知道它是怎么长出来的。

变更记录：

- 2026-10-28：建立。依据 `probe.md` 六项探针 + 两张预览截图。确认：`<br>` 在单元格与正文均有效；表格之间的空行不断表、两表会合并；分隔线列数与表头不符时整块降级为纯文字。
- 2026-10-28：补 `~` 一条。渲染器有 `delete` 节点（删除线），成对 `~` 生效；`Ch 0~3 … Ch 4~7 … Ch 8~11` 这种奇数个会让最后一个 `~` 之后的句子被划掉。修法是逐处写 `\~`，显示仍是 `~`。全文按「一行内是否存在两个及以上裸 `~`」筛，命中即转义。
