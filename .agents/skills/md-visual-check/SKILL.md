# 视觉检查

读文字看不出宽度问题：`|` 有没有对齐、框线是不是差一格、表格有没有退化成一段竖线，只有渲染出来才看得见。这个 skill 就干一件事：**出图，然后按清单看**。

## 一、被点名就直接跑

用户说「看看排版」「检查一下格式」时，不要问看哪一节、要不要装工具。默认按下面三步走完，把结论交上来。挑哪几页看，由线索决定，不由用户决定。

前置一次：控制台用 UTF-8，否则中文输出是乱码。

```powershell
chcp 65001 > $null; $env:PYTHONIOENCODING="utf-8"
```

## 二、三步

### 1. 出线索 + 出页

```powershell
python .agents\skills\md-visual-check\scripts\visual.py render "<文件.md>" --out .tmp_visual\out
```

整篇默认按 1400 px 高切页，每页顶部写着「第 N/M 页 ｜ 源 L120–L180」，截图可以直接对回行号。只想看一节时加 `--section "三、"`，只看几行加 `--lines 340-370`。

输出两份东西：页面 HTML，和一张线索表（同时写进 `<out>\report.txt`，控制台乱码时读它）。**先读线索，再决定截哪页**——不要逐页截图，一篇 1000 行的文档有三十多页。

命中 `--section` / `--lines` 时，线索仍按全篇扫描，落在选区外的会标「（选区外）」。这是故意的：改一节时别漏掉全篇的同类问题。

### 2. 截图

```text
browser_navigate  file:///<out>/page-03.html
browser_screenshot  fullPage: true   path: <out>/p03.png
```

`file:///` 用正斜杠。页面本身就是 1280 宽、1400 上下高，整页截下来不超过 1568 px，读图时不会被缩到看不清字。

### 3. 看，并说清楚坏在哪

`read_image` 打开图，按第三节清单过一遍。每条发现必须能指到行号；指不到行号的现象，多半是本机渲染的毛病，不是文档的问题。

## 三、看图清单

| 部位 | 坏的样子 | 说明 |
| --- | --- | --- |
| 表格 | 整块变成一行带竖线的文字 | 分隔线列数 ≠ 表头列数，预览器直接降级；别在截图里找，看线索 `table-ragged` |
| 表格 | 两张表粘成一张、缺表头 | 中间只隔空行；看线索 `table-glued` |
| 表格 | 某列被挤成竖排、单字换行 | 列宽分配失败，通常是某格有超长不换行的串 |
| `text` 图 | 右边框这一行缩进一格、框线断开 | 全角字当半角数了，多半是 `（`、`►`、`→` 附近差一格 |
| `text` 图 | 箭头落不到下一行的格子上 | 同上，宽度算错 |
| 公式 | 半个段落变成斜体、句子被吞 | `$` 奇数个；看线索 `math-dollar` |
| 代码块 | 右侧被切掉、看不到行尾 | 超过 100 格会横向滚动，截图里看不见；看线索 `code-long` |
| 图片 | 灰框里一个破图标 | 路径不存在；看线索 `img-missing` |
| 标题 | 三级标题和大标题一样大 | 层级跳级；看线索 `heading-jump` |

## 四、线索表怎么读

| code | 可信度 | 什么意思 |
| --- | --- | --- |
| `table-ragged` | 高 | 表格列数不一致，DSH 预览会把整块退成纯文字。**这是真错，必改** |
| `table-glued` | 高 | 两表之间只有空行，预览会合并。要么补一行正文，要么并成一张表 |
| `ascii-misaligned` | 中高 | 框线右边界偏离众数列。先看截图确认，再按「补一格 / 删一格」修 |
| `math-dollar` | 高 | 段内 `$` 奇数个。检查是不是漏写闭合，或者该写 `\$` |
| `code-long` | 高 | 显示宽度超 100 格，截图里会被横向滚动挡掉，别据此判断内容 |
| `img-missing` | 高 | 相对路径在磁盘上找不到 |
| `heading-jump` | 中 | 可能是故意的（比如用 `####` 当小标题），看上下文再定 |
| `fence-unclosed` | 高 | 代码围栏没闭合，后面整篇都会变成代码 |

`ascii-misaligned` 是启发式：它只比对「右边框正好在行尾」的行，树状图（`├── 文本` 结尾）不会误报；同一块里框线宽度本来就不一致的（多栏并排），可能仍会误报一次。截图能一眼分辨。

## 五、交回来的格式

```text
渲染：01-硬件组成.md 第 3/23 页（源 L214–L260）→ .tmp_visual/out/p03.png
发现：
1. L214 价格表右边框偏 1 格（该行 84 列，同组 4 行都在 83 列）→ 删掉「#PF（OS 分配新物理页）」前的一个空格
2. ……（每条都带行号、现象、改法）
没发现：表格散架、裂图、公式不闭合
```

只报看得见、指得到的。三件事不做：不改正文（用户没说要改就先只说）、不评价内容对错、不把「我觉得这样更好看」写成问题。

## 六、边界

- **这是 Chromium 渲染，不是 DSH 侧栏预览。** 预览器自己的两个脾气（表格跨空行合并、分隔线列数不符时整块降级）在浏览器里都不会复现，靠 `table-ragged` / `table-glued` 兜底；这两类不要用截图判断。
- **公式只显示源码**，不做 KaTeX 排版。能看出「这里是公式、括号成不成对」，看不出公式本身排得好不好。
- 字体是 Consolas 打底、全角字按两格固定宽度排（`scripts/visual.py` 里 `.g1/.g2` 那两行 CSS）。改成别的等宽字体后 CJK 比例不再是 2，框图会集体错位——那是渲染的错，不是文档的错。动这两行前先在浏览器里量一遍宽度。
- 一页里同时有 `--section` 和 `--lines` 时以 `--lines` 为准。

## 七、参数

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `--section "三、"` | — | 只渲染标题含该文字的节，到下一个同级标题为止 |
| `--lines A-B` | — | 只渲染该行区间，前后各留 2 行 |
| `--width N` | 960 | 正文栏宽。侧栏预览更窄时填 700 复现挤压 |
| `--page-height N` | 1400 | 每页目标高度；调小后单页更好读 |
| `--out DIR` | 系统临时目录 | HTML 与 report.txt 的去处 |
| `--max-pages N` | 0（全部） | 只要前几页 |
| `--json` | — | 只往 stdout 打 JSON；页面照常写出，不写 report.txt |

`node`、`npm`、`pandoc`、`python-markdown` 一概不需要：脚本只用标准库，截图借用 dsh-browser 自带的 Chromium。现成工具要么只给终端字符画（glow），要么得起一个 GitHub 风格的服务（grip），要么拖一整套 puppeteer（md-to-pdf），都被这一条排除。

## 八、扩展：别的视觉操作

接口空着，留给以后。约定只有一条：**脚本产出文件、自己打印结论，调用方只读路径**。

- **截一个网页 / 本地 HTML**：不用脚本，`browser_navigate` + `browser_screenshot` 就够。要稳定的元素截图，先 `browser_eval` 把 `getBoundingClientRect()` 取回来，再按坐标裁。
- **看别的文件类型**：`.docx`、`.xlsx` 走 `office-render` skill，不要在这里重造。
- **要新增图像后处理**（两张截图对比、裁一块放大、取某点颜色）：在 `scripts/` 下加独立脚本，Pillow 已装。

  ```text
  scripts/
    visual.py      渲染 + 线索（现在只有这个）
    render.py      兼容旧命令的转发壳
    <新命令>.py    输入路径 → 输出路径 + 一段结论
  ```

  新命令遵守同一份报告格式（第 5 节），这样「看图」这件事只有一种说法。写进这个文件之前先问一句：它会反复用吗？只为一次任务写的，就别进来。
