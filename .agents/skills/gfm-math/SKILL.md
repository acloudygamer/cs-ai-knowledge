# GFM 数学公式排版

GitHub 渲染管线的公式生死在**服务端判定**：活着 = 被包进 `<math-renderer>`（行内 `js-inline-math`、块级 `js-display-math`）；网页端 MathJax 只排版、不判定。

## 默认写法（照此写可避开绝大多数死法）

- **行内**：两端各留一个半角空格、内侧紧贴定界符——`值为 $x+y$ 个`。中文/全角标点紧贴 `$` 必死。
- **块级**：`$$` 独占段落——前后各留空行、块内无空行；或整段一行 `$$…$$`。表格/列表/引用里只写行内。
- **转义**：TeX 需要的 `\`+ASCII 标点一律双写（`\\%` `\\{` `\\_` `\\&` `\\,` 等），Markdown 会先吃掉一层。
- **兜底**（GitHub 专属，转义密集的复杂公式用）：行内 `` $`…`$ ``、块级 ```` ```math ```` 围栏——内部完全不双写、免疫配对与转义消耗。

## 写完含公式的文档，必跑脚本

```bash
python .agents/skills/gfm-math/math_fix.py <文件.md>
```

- 默认直接改原文件并调 GitHub API 验证；`--check` 只查不改，`--no-api` 跳过 API。
- 输出三段：
  - `[修复]` 已自动修好的（边界空格、内侧空白、转义双写、块级空行）——扫一眼确认即可；
  - `[检查]` 需要人工处理的（杀手子串、行内断行、表格裸 `|`、`$$` 同行退化等）——按提示逐条改；
  - `[API]` 计数比对——预期≠实际时列出死公式残留及源文件行号，按行号回去修。
- 脚本只覆盖机械问题；容器死活（em/b/a/code 包裹）、配对改写等语义问题查规范文档。

## 规则细节与排查

- **执行规范全文**（管线六站、容器死活表、排查路径）：同目录 `公式排版规范-工作版.md`——公式死了先定位死在哪一站，再查该站条款。
- **考据档案**（一般不需要看）：仓库根目录 `公式排版/` 下的完整版规范、`全量验证.md`、`Markdown渲染管线研讨.md`。
- 规范未覆盖的新现象：写一次性脚本调 `POST https://api.github.com/markdown`（gfm 模式，token 取 `gh auth token`）实测，结论补进规范；含反斜杠的测试输入必须写 Python 文件跑，不能用 bash heredoc（会吞反斜杠）。
