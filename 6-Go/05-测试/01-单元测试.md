# 单元测试

**单元测试是通过隔离验证每个代码单元正确性的机制。**

## 本质

Go 的 `testing` 包是标准库内置的测试框架，其核心约定是：以 `_test.go` 结尾的文件中，以 `Test` 开头的函数由 `go test` 自动发现并执行，失败时通过 `*testing.T` 报告。

## 机制

### 表驱动测试

单元测试的可维护性取决于测试用例的组织方式。Go 惯用表驱动模式：用结构体切片存储测试用例，在循环中执行每个子测试。

```
for _, tt := range cases {
    t.Run(tt.name, func(t *testing.T) {
        if got := Add(tt.a, tt.b); got != tt.expected {
            t.Errorf("Add(%d, %d) = %d; want %d", tt.a, tt.b, got, tt.expected)
        }
    })
}
```

子测试支持细粒度运行控制：
- `go test -run "TestAdd/正数"` 仅运行匹配的子测试
- 子测试树便于按名称过滤和批量执行

### Mock 与接口

单元测试需要隔离外部依赖。Go 通过接口达成这一点：被测代码依赖接口，测试时注入 Mock 实现。

```go
type Store interface { Get(id string) (string, error) }

type MockStore map[string]string

func (m MockStore) Get(id string) (string, error) {
    return m[id], nil
}
```

### Setup/Teardown

`TestMain(m *testing.M)` 提供包级别 setup/teardown：所有测试运行前执行一次初始化，所有测试完成后执行一次清理。

## 覆盖率

覆盖率衡量被执行到的代码比例，但**高覆盖率不等于高质量测试**。测试应优先覆盖关键路径和边界条件，而非追求百分比。

```
go test -coverprofile=coverage.out
go tool cover -func=coverage.out
```

## 验证标准

- 每个测试函数无状态、无副作用
- 测试间互不依赖，可任意顺序执行
- 失败信息包含实际值和期望值
