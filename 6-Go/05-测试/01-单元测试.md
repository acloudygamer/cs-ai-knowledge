# 单元测试

### 解决什么问题
Go 需要验证代码正确性，标准库提供内置 testing 包，无需第三方框架即可编写单元测试。

### 核心概念
- testing 包：标准库内置，支持 Test/Benchmark/Example 函数
- _test.go 命名：测试文件必须以 _test.go 结尾
- 表驱动测试：Go 惯用模式，用表结构组织测试用例
- 子测试：t.Run 创建命名子测试，支持精细化运行控制

### 怎么用

## 测试框架：testing

Go 标准库内置 `testing` 包，无需第三方框架即可写测试。

```go
import "testing"
```

## 命名规范

- 测试文件以 `_test.go` 结尾
- 测试函数以 `Test` 开头
- 基准测试函数以 `Benchmark` 开头
- 示例函数以 `Example` 开头

```bash
# 运行当前包所有测试
go test

# 运行指定测试
go test -run TestFunctionName

# 运行所有子目录测试
go test ./...

# 显示详细输出
go test -v

# 显示测试覆盖率
go test -cover

# 生成覆盖率报告
go test -coverprofile=coverage.out
go tool cover -html=coverage.out
```

## 表驱动测试（推荐）

表驱动测试是 Go 中最惯用的测试方式，将测试用例组织成表结构。

```go
func TestAdd(t *testing.T) {
    tests := []struct {
        name     string
        a, b     int
        expected int
    }{
        {"正数相加", 1, 2, 3},
        {"负数相加", -1, -2, -3},
        {"正负相加", 1, -1, 0},
        {"零相加", 0, 5, 5},
        {"大数相加", 1000000, 2000000, 3000000},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            result := Add(tt.a, tt.b)
            if result != tt.expected {
                t.Errorf("Add(%d, %d) = %d; want %d", tt.a, tt.b, result, tt.expected)
            }
        })
    }
}
```

### 子测试优势

```go
// 使用 -run 参数可以精确运行子测试
go test -v -run "TestAdd/正数相加"

// 运行所有名称包含"相加"的子测试
go test -v -run "TestAdd/.*相加"
```

## 使用 testing.T

### 常用方法

```go
func TestSomething(t *testing.T) {
    // 标记测试失败，继续执行
    t.Log("信息日志")

    // 标记测试失败，终止当前测试
    t.Errorf("格式化失败信息: %s", err)

    // 标记测试失败，跳过当前测试
    t.Skip("暂时跳过")

    // 标记测试失败，终止测试（用于不可恢复的错误）
    t.Fatal("致命错误")
    t.Fatalf("格式化致命错误: %d", code)

    // FailNow 系列（通常不推荐）
    t.FailNow()
}
```

### 失败信息格式化

```go
// 好的失败信息
t.Errorf("expected %d, got %d", expected, got)

// 包含更多上下文
t.Errorf("UserService.GetByID(%s) failed: %v", id, err)
```

## 断言封装（简化版）

Go 官方不推荐使用断言库，但可以自己封装常用断言：

```go
// assert.go
package assert

func Equal(t *testing.T, expected, actual any, msg ...string) {
    if expected != actual {
        if len(msg) > 0 {
            t.Fatalf("%s: expected %v, got %v", msg[0], expected, actual)
        }
        t.Fatalf("expected %v, got %v", expected, actual)
    }
}

func NoError(t *testing.T, err error, msg ...string) {
    if err != nil {
        if len(msg) > 0 {
            t.Fatalf("%s: %v", msg[0], err)
        }
        t.Fatalf("unexpected error: %v", err)
    }
}

func Nil(t *testing.T, obj any, msg ...string) {
    if obj != nil {
        if len(msg) > 0 {
            t.Fatalf("%s: expected nil, got %v", msg[0], obj)
        }
        t.Fatalf("expected nil, got %v", obj)
    }
}
```

```go
// 使用断言封装
func TestUserCreation(t *testing.T) {
    user, err := CreateUser("tom", "tom@example.com")
    assert.NoError(t, err, "CreateUser failed")
    assert.Equal(t, "tom", user.Name)
    assert.Nil(t, user.Password)  // 密码不应返回
}
```

## Setup 和 Teardown

```go
func TestMain(m *testing.M) {
    // Setup: 执行所有测试前运行一次
    setup()
    code := m.Run()  // 运行所有测试
    // Teardown: 所有测试后执行
    teardown()
    os.Exit(code)
}
```

### 每个测试的 Setup/Teardown

```go
func setupTestDB(t *testing.T) *DB {
    db := NewDB(":memory:")
    db.Exec("CREATE TABLE users (...)")
    return db
}

func TestUserQuery(t *testing.T) {
    db := setupTestDB(t)
    defer db.Close()

    // 测试逻辑...
}
```

## Mock 测试

### 接口 Mock

```go
// 定义接口
type UserStore interface {
    GetUser(id string) (*User, error)
    SaveUser(user *User) error
}

// Mock 实现
type MockUserStore struct {
    users map[string]*User
    err   error
}

func (m *MockUserStore) GetUser(id string) (*User, error) {
    if m.err != nil {
        return nil, m.err
    }
    return m.users[id], nil
}

func (m *MockUserStore) SaveUser(user *User) error {
    if m.err != nil {
        return m.err
    }
    m.users[user.ID] = user
    return nil
}
```

### 使用 Mock

```go
func TestUserService_GetUser(t *testing.T) {
    mockStore := &MockUserStore{
        users: map[string]*User{
            "1": {ID: "1", Name: "Tom"},
        },
    }
    svc := NewUserService(mockStore)

    user, err := svc.GetUser("1")
    assert.NoError(t, err)
    assert.Equal(t, "Tom", user.Name)
}

func TestUserService_GetUser_Error(t *testing.T) {
    mockStore := &MockUserStore{
        err: errors.New("database error"),
    }
    svc := NewUserService(mockStore)

    _, err := svc.GetUser("1")
    assert.Error(t, err)
    assert.Contains(t, err.Error(), "database error")
}
```

### 使用 testify/mock（可选）

```go
import "github.com/stretchr/testify/mock"

type MockStore struct {
    mock.Mock
}

func (m *MockStore) GetUser(id string) (*User, error) {
    args := m.Called(id)
    return args.Get(0).(*User), args.Error(1)
}

// 使用
mockStore := new(MockStore)
mockStore.On("GetUser", "1").Return(&User{Name: "Tom"}, nil)

svc := NewUserService(mockStore)
user, _ := svc.GetUser("1")

mockStore.AssertExpectations(t)
mockStore.AssertCalled(t, "GetUser", "1")
```

## 测试覆盖率

```bash
# 查看覆盖率
go test -cover

# 查看覆盖率的详细信息
go test -coverprofile=coverage.out
go tool cover -func=coverage.out

# 生成 HTML 报告
go tool cover -html=coverage.out -o coverage.html
```

### 覆盖率解读

```
total:   (statements)           75.5%
```

覆盖率高不等于测试质量高。关注关键路径和边界条件。

## Example 测试

Example 测试既是测试也是文档：

```go
func ExampleAdd() {
    sum := Add(2, 3)
    fmt.Println(sum)
    // Output:
    // 5
}

func ExampleListUsers() {
    users := ListUsers()
    for _, u := range users {
        fmt.Println(u.Name)
    }
    // Unordered output:
    // Alice
    // Bob
}
```

Example 测试会自动检查输出是否与 `// Output:` 注释匹配。
