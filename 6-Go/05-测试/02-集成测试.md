# 集成测试

## 定义

集成测试是通过**真实依赖**验证多个组件协作正确性的机制。单元测试用 Mock 隔离依赖，集成测试则使用真实依赖（数据库、HTTP 服务、消息队列）验证组件间交互的正确性。

集成测试的核心价值在于发现 Mock 无法暴露的问题：**组件边界处的协议不一致、资源竞争、序列化/反序列化 bug、事务边界错误**。这些 bug 的共同特征是：只在真实组件交互时才显现。

## 数学模型

### 隔离域模型

不同测试类型的隔离边界由 SUT 的依赖范围决定：

| 测试类型 | SUT + 依赖 | 隔离域大小 | 可发现的 bug |
|----------|------------|------------|--------------|
| 单元测试 | SUT + Mock | 完全隔离 | 单元逻辑错误 |
| 集成测试 | SUT + 部分真实组件 | 部分真实 | 接口不匹配、资源泄漏、事务边界错误 |
| 端到端测试 | 全系统 + 真实外部系统 | 最小隔离 | 部署配置错误、环境差异 |

**隔离域的包含关系**：
$$\text{Domain}_{\text{unit}} \subset \text{Domain}_{\text{integration}} \subset \text{Domain}_{\text{e2e}}$$

随着隔离域扩大，发现的 bug 类型从"逻辑错误"转向"集成错误"。

### 测试执行时间的成本模型

设单元测试执行时间为 $T_{\text{unit}}$，集成测试执行时间为 $T_{\text{integration}}$：
$$T_{\text{integration}} = \alpha \cdot T_{\text{unit}}, \quad \alpha \gg 1$$

典型值：$\alpha \in [10^2, 10^4]$（单元测试 ms 级，集成测试 s 级）。

总测试时间：
$$T_{\text{total}} = p \cdot T_{\text{integration}} + (1-p) \cdot T_{\text{unit}}$$

其中 $p$ 是集成测试占比。当 $p > 0.01$ 时，集成测试开始成为测试套件的主要时间成本。

### Testcontainers 的资源生命周期状态机

<pre>
状态机：ContainerLifecycle
────────────────────────────────────────
状态集：{CREATING, RUNNING, STOPPED, TERMINATED}
初始状态：CREATING

CREATING ──[docker pull/create/start]──► RUNNING
RUNNING ──[terminate]──► TERMINATED
TERMINATED ──[资源释放]──► 终态
</pre>

资源成本量化：
$$T_{\text{container\_start}} \approx 1\!-\!10\text{s} \gg T_{\text{unit}} \approx 1\text{ms}$$

### 事务回滚的隔离保证

设测试操作集合为 $O = \{o_1, o_2, \ldots, o_n\}$，每个测试在独立事务中执行且最终回滚：
$$\forall \text{test}_i, \text{test}_j : S_{\text{after}(\text{test}_i)} = S_{\text{after}(\text{test}_j)} = S_{\text{initial}}$$

即所有测试看到相同的初始状态 $S_{\text{initial}}$，测试间无状态污染。

### httptest 的请求-响应模型

`http.ResponseWriter` 是一个接口：
```go
type ResponseWriter interface {
    Header() Header
    Write([]byte) (int, error)
    WriteHeader(statusCode int)
}
```

`httptest.NewRecorder()` 实现了该接口，将所有 Write 操作重定向到内部 buf：
$$\text{Recorder} \models \text{ResponseWriter}$$

依赖反转原则（DIP）：
$$\text{Handler} \xrightarrow{\text{依赖}} \text{ResponseWriter (interface)}$$
$$\text{RealServer} \models \text{ResponseWriter} \quad \text{Recorder} \models \text{ResponseWriter}$$

## 数据流

### httptest 的请求处理流

<pre>
测试代码
    │
    ├── httptest.NewRequest(method, path, body)
    │       │
    │       └── 创建 *http.Request（只读对象）
    │
    ├── httptest.NewRecorder()
    │       │
    │       └── 创建 ResponseRecorder（实现了 http.ResponseWriter）
    │               │
    │               ├── Write() → 写入内部 buf
    │               ├── WriteHeader() → 记录状态码
    │               └── Header() → 返回可写 Header map
    │
    └── handler.ServeHTTP(recorder, request)
            │
            ├── handler 处理请求（不知道 recorder 是模拟的）
            │
            ├── 写入 recorder（模拟响应）
            │
            └── 验证 recorder.Body / recorder.Code
                    │
                    ▼
                断言 response
</pre>

### httptest.NewServer vs NewRecorder

| 模式 | 创建方式 | 网络调用 | 适用场景 |
|------|----------|----------|----------|
| `NewRecorder` | `httptest.NewRecorder()` | 无网络 | Handler 级别单元测试 |
| `NewServer` | `httptest.NewServer(handler)` | 真实网络（localhost） | HTTP 客户端集成测试 |

`NewServer` 的数据流：
<pre>
client.Do(ctx, req)
    │
    ├── HTTP 请求（真实 TCP/IP）
    │
    └── ts.Handler 接收并处理
            │
            └── ResponseRecorder 捕获响应
</pre>

ctx := context.Background()

### 事务回滚的隔离保证

<pre>
Test A：
begin transaction T_A
    ├── INSERT user (id=1, name="Alice")
    ├── 验证插入
    └── rollback T_A
        └── 所有更改撤销

Test B：
begin transaction T_B
    ├── INSERT user (id=1, name="Alice")  // 同一条记录可再次插入
    ├── 验证插入
    └── rollback T_B

保证：
  - 每个测试看到相同的初始状态
  - 测试间无状态污染
  - 测试执行顺序不影响结果
</pre>

### 数据库连接池的测试约束

<pre>
测试前配置：
    db.SetMaxOpenConns(10)
    db.SetMaxIdleConns(5)
    db.SetConnMaxLifetime(30 * time.Minute)

隔离约束：
    每个测试使用独立事务
    测试结束后回滚
    禁止测试间共享连接

泄漏检测：
    go test -race 可以检测连接泄漏
    连接数持续增长 → 存在连接泄漏
</pre>

## 机制

### 为什么集成测试比单元测试慢

| 测试类型 | 响应时间 | 内存占用 | 典型场景 |
|----------|----------|----------|----------|
| Mock（单元测试） | < 1ms | 微小 | 函数逻辑验证 |
| 真实 DB（集成测试） | 10-100ms | 中等 | SQL 正确性 |
| Docker 容器（集成测试） | 1-10s 启动 | 大 | 真实环境模拟 |

**数量级差异**：
$$T_{\text{unit}} : T_{\text{integration}} : T_{\text{e2e}} \approx 1 : 10^2 : 10^4$$

### Mock 无法发现的五类问题

1. **序列化/反序列化格式不一致**：JSON 字段名大小写、日期格式、精度丢失
2. **超时和重试逻辑错误**：超时设置过短、重试风暴
3. **连接池耗尽**：并发请求超过 MaxOpenConns
4. **事务边界错误**：嵌套调用跨越事务边界、分布式事务的 2PC 问题
5. **协议版本不匹配**：客户端和服务端字段不一致

### httptest 为什么能模拟 HTTP

Handler 只依赖 `http.ResponseWriter` 接口，不关心具体实现：
- 真实 server：ResponseWriter 写入 TCP 连接
- Recorder：ResponseWriter 写入内存 buf

Handler 的执行逻辑完全相同，区别仅在于输出的目的地。这体现了**依赖反转原则**：高层模块（Handler）依赖抽象（ResponseWriter 接口），而非具体低层模块。

**约束**：Handler 不能对 ResponseWriter 做类型断言（如 `resp.(*http.Response).Close`），否则 Recorder 会 panic。

### Testcontainers 的网络隔离

Testcontainers 创建独立的 Docker 网络：
<pre>
主机
  │
  ├── docker0 网桥
  │       │
  │       └── testcontainers-<id> 网络
  │               │
  │               ├── 容器A ←── 内部网络 ──→ 容器B
  │               │
  │               └── 通过 container.ConnectionString() 连接
  │
  └── localhost:5432 → 容器 5432（仅当显式端口映射）
</pre>

**隔离保证**：
- 测试数据库不暴露到主机网络（除非显式映射端口）
- 容器间通过内部网络通信
- 测试结束后容器销毁，网络自动清理

**安全价值**：测试数据库与生产数据库网络隔离，防止测试数据泄露或测试操作影响生产数据。

### 三种数据库测试隔离策略对比

| 策略 | DB 实例 | 事务管理 | 成本 | 隔离度 |
|------|---------|----------|------|--------|
| 独立 DB | 每个测试独立 | 独立生命周期 | 最高（资源密集） | 最干净 |
| 事务回滚 | 共享 DB | 每个测试 begin/rollback | 中等 | 依赖 DB 隔离 |
| 独立 Schema | 共享 DB | 每个测试独立 schema | 低 | 中等 |

**事务回滚的约束**：若测试中使用了 DDL（CREATE TABLE、DROP INDEX 等），部分数据库（MySQL 的某些存储引擎）对 DDL 执行的隐式 commit 会导致回滚失效。

### 测试金字塔与 ROI 分析

```
        ▲
       /E2E\          少量，耗时最长，发现部署/环境问题
      /──────\
     /Integration\     适量，发现组件边界问题
    /────────────\
   /  Unit Tests  \   大量，快速，发现逻辑错误
  /───────────────\
 /─────────────────────\
───────────────────────────► 测试数量
```

| 指标 | 单元测试 | 集成测试 | E2E 测试 |
|------|----------|----------|----------|
| 成本（执行时间） | 低 | 中 | 高 |
| Bug 发现率（边界错误） | 低 | 高 | 中 |
| 覆盖率 | 高 | 中 | 低 |

## 验证标准

- 使用 `httptest.NewServer` 模拟外部 HTTP 依赖
- 每个测试使用独立事务或独立数据库
- 慢测试通过 build tags 标记（`//go:build integration`）
- CI 中分阶段执行：先跑单元测试，再跑集成测试
- 关键路径做集成测试，非关键路径单元测试覆盖即可

```go
// httptest 用法
func TestHandler(t *testing.T) {
    handler := func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    }

    req := httptest.NewRequest("GET", "/api", nil)
    recorder := httptest.NewRecorder()

    handler.ServeHTTP(recorder, req)

    if recorder.Code != http.StatusOK {
        t.Errorf("status = %d; want %d", recorder.Code, http.StatusOK)
    }
    if recorder.Body.String() != "ok" {
        t.Errorf("body = %s; want ok", recorder.Body.String())
    }
}

// httptest.NewServer 用法
func TestClient(t *testing.T) {
    handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("hello"))
    })
    ts := httptest.NewServer(handler)
    defer ts.Close()

    client := NewClient(ts.URL)
    resp, err := client.Get()
    if err != nil {
        t.Fatal(err)
    }
    if resp != "hello" {
        t.Errorf("resp = %s; want hello", resp)
    }
}

    }

    // 测试逻辑...
```
