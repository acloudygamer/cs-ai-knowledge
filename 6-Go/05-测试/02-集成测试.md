# 集成测试

## 定义

集成测试是通过**真实依赖**验证多个组件协作正确性的机制。单元测试用 Mock 隔离依赖，集成测试则使用真实依赖（数据库、HTTP 服务、消息队列）验证组件间交互的正确性。集成测试的核心价值在于发现 Mock 无法暴露的问题：**组件边界处的协议不一致、资源竞争、序列化/反序列化 bug**。

## 数学模型

### 测试隔离的隔离域模型

```
不同测试类型的隔离边界：

单元测试：
  SUT（被测系统） + Mock（外部依赖）
  ──────────────────────────────────
  隔离域：完全隔离，mock 替代真实组件
  可发现的bug：单元逻辑错误

集成测试：
  SUT（被测系统） + 真实组件（部分或全部）
  ──────────────────────────────────
  隔离域：部分真实，组件间协作真实发生
  可发现的bug：接口不匹配、资源泄漏、事务边界错误

端到端测试：
  整个系统 + 真实外部系统
  ──────────────────────────────────
  隔离域：最小隔离，最大真实
  可发现的bug：部署配置错误、环境差异
```

**隔离域的包含关系**：从单元测试到端到端测试，隔离域逐渐扩大，发现的 bug 类型也逐渐从"逻辑错误"转向"集成错误"。

### Testcontainers 的资源生命周期

```
Testcontainers 启动真实容器：

1. 创建容器请求（镜像、网络、端口）
2. Docker API 创建容器
3. 容器启动（秒级，vs 单元测试的毫秒级）
4. 等待容器就绪（健康检查）
5. 获取连接信息（IP:Port）
6. 运行测试
7. 容器终止（资源清理）

时间成本：
  启动：3-10 秒
  测试执行：取决于逻辑
  清理：1-2 秒

vs 单元测试：
  Mock：< 1ms
  启动
```

**资源成本的数学模型**：设单元测试执行时间为 `T_unit`，集成测试执行时间为 `T_integration`，则 `T_integration >> T_unit`。若集成测试占比为 `p`，总测试时间为 `T_total = p × T_integration + (1-p) × T_unit`。当 `p > 0.01` 时，集成测试开始成为测试套件的主要时间成本。

### 数据库事务隔离的测试策略

```
集成测试中每个测试使用独立事务：

方式 1：每个测试独立数据库
  每个测试创建独立 DB 实例
  测试后销毁
  成本最高，但最干净

方式 2：每个测试独立事务 + rollback
  begin transaction
      测试操作
  rollback
  ───────────────
  DB 状态对每个测试都是干净的
  成本低，共享 DB 实例

方式 3：每个测试独立 schema
  共享 DB，但每个测试用不同 schema
  测试后 drop schema
```

**事务回滚的隔离保证**：方式 2 依赖数据库的 ACID 特性。设测试操作集合为 `O = {o₁, o₂, ..., oₙ}`，若每个测试在独立事务中执行且最终回滚，则数据库状态 `S` 满足：

$$\forall test_i, test_j: S_{after(test_i)} = S_{after(test_j)} = S_{initial}$$

即所有测试看到相同的初始状态。

### httptest 的请求-响应模型

```
httptest 的模拟能力边界：

Server ← → Handler ← → Request/Response

httptest.NewServer 创建一个真实的 HTTP 服务器：
  - 监听本地随机端口
  - 处理实际 HTTP 请求
  - 可用于端到端测试

httptest.NewRecorder 创建一个响应记录器：
  - 实现了 http.ResponseWriter 接口
  - 将响应写入内部 buf
  - 用于单元测试级别的 handler 测试

约束：
  - NewServer 是真实网络调用（可能有网络相关 bug）
  - NewRecorder 是内存操作（无网络开销）
```

### 事务回滚的隔离保证

<pre>
begin transaction
    │
    ├── INSERT user (id=1, name="Alice")
    │
    ├── TestXxx 验证插入
    │
    └── rollback
        │
        └── 事务内的所有操作被撤销

下一测试：重新 begin
    │
    ├── INSERT user (id=1, name="Alice")  // 同一条记录可再次插入
    │
    └── rollback

保证：
  - 每个测试看到相同的初始状态
  - 测试间无状态污染
  - 测试执行顺序不影响结果
</pre>

    │

## 机制

### 为什么集成测试比单元测试慢？

```
时间成本分解：

Mock（单元测试）：
  - Mock 实现：无网络/磁盘 I/O
  - 响应时间：< 1ms
  - 内存占用：微小

真实组件（集成测试）：
  - 数据库：网络往返 + 磁盘 I/O + 锁竞争
  - HTTP 服务：网络栈 + 处理逻辑
  - Docker 容器：进程启动 + 健康检查

数量级差异：
  单元测试：0.1-1ms / 测试
  集成测试：10ms-10s / 测试
  端到端测试：1s-60s / 测试

解决方案：
  - build tags 分离（unit vs integration）
  - CI 分阶段执行
  - 小范围集成（不启动全系统）
```

**为什么集成测试是必要的**：Mock 无法发现以下问题：
1. 序列化/反序列化格式不一致
2. 超时和重试逻辑的错误
3. 连接池耗尽
4. 事务边界错误
5. 协议版本不匹配

### httptest 为什么能模拟 HTTP？

```
http.ResponseWriter 接口：
  type ResponseWriter interface {
      Header() Header
      Write([]byte) (int, error)
      WriteHeader(statusCode int)
  }

httptest.NewRecorder() 实现了 ResponseWriter：
  - Write() 将数据写入内部 buf
  - WriteHeader() 记录状态码
  - Header() 返回可写的 Header map

handler.ServeHTTP(w, req)：
  handler 完全不知道 w 是真实还是模拟
  它只看到一个 http.ResponseWriter 接口

这是依赖反转（DIP）的应用：
  高层模块（handler）依赖抽象（ResponseWriter 接口）
  低层模块（真实 server / recorder）实现该抽象
```

**DIP 的形式化约束**：若模块 A 依赖模块 B 的接口 I，则：
1. A 不应直接创建 B 的实例（应用工厂模式或依赖注入）
2. B 的实现应通过接口 I 暴露能力
3. 测试时可用 Mock 替代 B

### Testcontainers 的网络隔离

```
Testcontainers 创建独立的 Docker 网络：
  容器 <─── Docker 网络 ───> 主机
                    │
                    └── 通过 pgContainer.ConnectionString() 连接

隔离保证：
  - 测试数据库不暴露到主机网络
  - 容器间通过内部网络通信
  - 测试结束后容器销毁，网络清理

可选配置：
  - 端口映射：主机 localhost:5432 → 容器 5432
  - 自定义网络：多个容器互联
  - 卷挂载：持久化数据（测试不建议）
```

**网络隔离的安全价值**：测试数据库与生产数据库网络隔离，防止测试数据泄露或测试操作影响生产数据。

### 数据库连接池的测试约束

```
集成测试中的数据库连接管理：

连接池配置（通常在测试前设置）：
  - MaxOpenConns: 10
  - MaxIdleConns: 5
  - ConnMaxLifetime: 30m

测试隔离约束：
  - 每个测试使用独立事务
  - 测试结束后回滚
  - 禁止测试间共享连接

连接泄漏检测：
  - go test -race 可以检测连接泄漏
  - 若测试后连接数持续增长 → 存在连接泄漏
```

## 参考存根

```go
// httptest 用法
func TestHandler(t *testing.T) {
    handler := func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    }

    req := httptest.NewRequest("GET", "/api", nil)
    recorder := httptest.NewRecorder()

    handler.ServeHTTP(recorder, req)

    if recorder.Code != http.StatusOK {
        t.Errorf("status = %d; want %d", recorder.Code, http.StatusOK)
    }
    if recorder.Body.String() != "ok" {
        t.Errorf("body = %s; want ok", recorder.Body.String())
    }
}

// httptest.NewServer 用法
func TestClient(t *testing.T) {
    handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("hello"))
    })
    ts := httptest.NewServer(handler)
    defer ts.Close()

    client := NewClient(ts.URL)
    resp, err := client.Get()
    if err != nil {
        t.Fatal(err)
    }
    if resp != "hello" {
        t.Errorf("resp = %s; want hello", resp)
    }
}

// 数据库事务回滚
func TestWithTx(t *testing.T) {
    db, _ := sql.Open("postgres", connStr)
    tx, _ := db.Begin()
    defer tx.Rollback()

    _, err := tx.Exec("INSERT INTO users VALUES($1, $2)", 1, "Alice")
    if err != nil {
        t.Fatal(err)
    }

    // 测试逻辑...

    // tx.Rollback() 自动执行，所有更改撤销
}

// Testcontainers
func TestWithDB(t *testing.T) {
    ctx := context.Background()
    req := postgres.WithImage("postgres:15-alpine")
    pgContainer, err := postgres.Run(ctx, req)
    if err != nil {
        t.Fatal(err)
    }
    defer pgContainer.Terminate(ctx)

    connStr := pgContainer.ConnectionString(ctx)
    db, err := sql.Open("postgres", connStr)
    if err != nil {
        t.Fatal(err)
    }
    defer db.Close()

    // 使用真实数据库测试
    _, err = db.Exec("CREATE TABLE ...")
    // ...
}
```

## 验证标准

- 使用 `httptest.NewServer` 模拟外部 HTTP 依赖
- 每个测试使用独立事务或独立数据库
- 慢测试通过 build tags 标记，在 CI 中分离执行

## 测试金字塔与集成测试定位

```
        ▲
       /E2E\          少量，耗时最长，发现部署/环境问题
      /──────\
     /Integration\     适量，发现组件边界问题
    /────────────\
   /  Unit Tests  \   大量，快速，发现逻辑错误
  /───────────────\
/─────────────────────\
──────────────────────────► 测试数量

集成测试的ROI（投资回报率）：
  - 成本：执行时间是单元测试的 10-1000 倍
  - 收益：发现单元测试无法覆盖的边界错误
  - 建议：关键路径做集成测试，非关键路径单元测试覆盖即可
```
