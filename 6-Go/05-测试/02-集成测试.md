# 集成测试

## 定义

集成测试是通过**真实依赖**验证多个组件协作正确性的机制。单元测试用 Mock 隔离依赖，集成测试则使用真实依赖（数据库、HTTP 服务）验证组件间交互的正确性。

## 数学模型

### 测试隔离的隔离域模型

```
不同测试类型的隔离边界：

单元测试：
  SUT（被测系统） + Mock（外部依赖）
  ──────────────────────────────────
  隔离域：完全隔离，mock 替代真实组件

集成测试：
  SUT（被测系统） + 真实组件（部分或全部）
  ──────────────────────────────────
  隔离域：部分真实，组件间协作真实发生

端到端测试：
  整个系统 + 真实外部系统
  ──────────────────────────────────
  隔离域：最小隔离，最大真实
```

### Testcontainers 的资源生命周期

```
Testcontainers 启动真实容器：

1. 创建容器请求（镜像、网络、端口）
2. Docker API 创建容器
3. 容器启动（秒级，vs 单元测试的毫秒级）
4. 等待容器就绪（健康检查）
5. 获取连接信息（IP:Port）
6. 运行测试
7. 容器终止（资源清理）

时间成本：
  启动：3-10 秒
  测试执行：取决于逻辑
  清理：1-2 秒

vs 单元测试：
  Mock：< 1ms
  启动
```

### 数据库事务隔离的测试策略

```
集成测试中每个测试使用独立事务：

方式 1：每个测试独立数据库
  每个测试创建独立 DB 实例
  测试后销毁
  成本最高，但最干净

方式 2：每个测试独立事务 + rollback
  begin transaction
      测试操作
  rollback
  ───────────────
  DB 状态对每个测试都是干净的
  成本低，共享 DB 实例

方式 3：每个测试独立 schema
  共享 DB，但每个测试用不同 schema
  测试后 drop schema
```

## 数据流

### httptest 的请求处理流

<pre>
测试代码
    │
    ├── httptest.NewRequest(method, path, body)
    │       │
    │       └── 创建 *http.Request
    │
    ├── httptest.NewRecorder()
    │       │
    │       └── 创建 ResponseRecorder（实现了 http.ResponseWriter）
    │
    └── handler.ServeHTTP(recorder, request)
            │
            ├── handler 处理请求
            ├── 写入 recorder（模拟响应）
            │
            └── 验证 recorder.Body / recorder.Code
                    │
                    ▼
                断言 response
</pre>

### 事务回滚的隔离保证

<pre>
begin transaction
    │
    ├── INSERT user (id=1, name="Alice")
    │
    ├── TestXxx 验证插入
    │
    └── rollback
        │
        └── 事务内的所有操作被撤销

下一测试：重新 begin
    │
    ├── INSERT user (id=1, name="Alice")  // 同一条记录可再次插入
    │
    └── rollback

保证：
  - 每个测试看到相同的初始状态
  - 测试间无状态污染
  - 测试执行顺序不影响结果
</pre>

## 机制

### 为什么集成测试比单元测试慢？

```
时间成本分解：

Mock（单元测试）：
  - Mock 实现：无网络/磁盘 I/O
  - 响应时间：< 1ms
  - 内存占用：微小

真实组件（集成测试）：
  - 数据库：网络往返 + 磁盘 I/O + 锁竞争
  - HTTP 服务：网络栈 + 处理逻辑
  - Docker 容器：进程启动 + 健康检查

数量级差异：
  单元测试：0.1-1ms / 测试
  集成测试：10ms-10s / 测试
  端到端测试：1s-60s / 测试

解决方案：
  - build tags 分离（unit vs integration）
  - CI 分阶段执行
  - 小范围集成（不启动全系统）
```

### httptest 为什么能模拟 HTTP？

```
http.ResponseWriter 接口：
  type ResponseWriter interface {
      Header() Header
      Write([]byte) (int, error)
      WriteHeader(statusCode int)
  }

httptest.NewRecorder() 实现了 ResponseWriter：
  - Write() 将数据写入内部 buf
  - WriteHeader() 记录状态码
  - Header() 返回可写的 Header map

handler.ServeHTTP(w, req)：
  handler 完全不知道 w 是真实还是模拟
  它只看到一个 http.ResponseWriter 接口

这是依赖反转（DIP）的应用：
  高层模块（handler）依赖抽象（ResponseWriter 接口）
  低层模块（真实 server / recorder）实现该抽象
```

### Testcontainers 的网络隔离

```
Testcontainers 创建独立的 Docker 网络：
  容器 <─── Docker 网络 ───> 主机
                    │
                    └── 通过 pgContainer.ConnectionString() 连接

隔离保证：
  - 测试数据库不暴露到主机网络
  - 容器间通过内部网络通信
  - 测试结束后容器销毁，网络清理

可选配置：
  - 端口映射：主机 localhost:5432 → 容器 5432
  - 自定义网络：多个容器互联
  - 卷挂载：持久化数据（测试不建议）
```

```go
// httptest 用法
func TestHandler(t *testing.T) {
    handler := func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    }

    req := httptest.NewRequest("GET", "/api", nil)
    recorder := httptest.NewRecorder()

    handler.ServeHTTP(recorder, req)

    if recorder.Code != http.StatusOK {
        t.Errorf("status = %d; want %d", recorder.Code, http.StatusOK)
    }
    if recorder.Body.String() != "ok" {
        t.Errorf("body = %s; want ok", recorder.Body.String())
    }
}

// 数据库事务回滚
func TestWithTx(t *testing.T) {
    db, _ := sql.Open("postgres", connStr)
    tx, _ := db.Begin()
    defer tx.Rollback()

    _, err := tx.Exec("INSERT INTO users VALUES($1, $2)", 1, "Alice")
    if err != nil {
        t.Fatal(err)
    }

    // 测试逻辑...

    // tx.Rollback() 自动执行，所有更改撤销
}

// Testcontainers
func TestWithDB(t *testing.T) {
    ctx := context.Background()
    req := postgres.WithImage("postgres:15-alpine")
    pgContainer, err := postgres.Run(ctx, req)
    if err != nil {
        t.Fatal(err)
    }
    defer pgContainer.Terminate(ctx)

    connStr := pgContainer.ConnectionString(ctx)
    db, err := sql.Open("postgres", connStr)
    if err != nil {
        t.Fatal(err)
    }
    defer db.Close()

    // 使用真实数据库测试
    _, err = db.Exec("CREATE TABLE ...")
    // ...
}
```

## 验证标准

- 使用 `httptest.NewServer` 模拟外部 HTTP 依赖
- 每个测试使用独立事务或独立数据库
- 慢测试通过 build tags 标记，在 CI 中分离执行
