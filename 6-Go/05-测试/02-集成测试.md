# 集成测试

## 定义

集成测试是通过**真实依赖**验证多个组件协作正确性的机制。单元测试用 Mock 隔离依赖，集成测试则使用真实依赖（数据库、HTTP 服务、消息队列）验证组件间交互的正确性。集成测试的核心价值在于发现 Mock 无法暴露的问题：**组件边界处的协议不一致、资源竞争、序列化/反序列化 bug**。

## 数学模型

### 测试隔离的隔离域模型

**不同测试类型的隔离边界**：

| 测试类型 | SUT + 依赖 | 隔离域 | 可发现的 bug |
|----------|-------------|--------|--------------|
| 单元测试 | SUT + Mock | 完全隔离 | 单元逻辑错误 |
| 集成测试 | SUT + 部分真实组件 | 部分真实 | 接口不匹配、资源泄漏、事务边界错误 |
| 端到端测试 | 全系统 + 真实外部系统 | 最小隔离 | 部署配置错误、环境差异 |

**隔离域的包含关系**：

$$
\text{Domain}_{\text{unit}} \subset \text{Domain}_{\text{integration}} \subset \text{Domain}_{\text{e2e}}
$$

从单元测试到端到端测试，隔离域逐渐扩大，发现的 bug 类型也逐渐从"逻辑错误"转向"集成错误"。

### Testcontainers 的资源生命周期

**Testcontainers 启动真实容器的状态机**：

```
创建容器请求
    │
    ├── docker pull <image>（首次）
    ├── docker create ...
    └── docker start ...
    │
    ▼
容器启动（秒级，vs 单元测试的毫秒级）
    │
    ▼
等待容器就绪（健康检查轮询）
    │
    ▼
获取连接信息（IP:Port）
    │
    ▼
运行测试
    │
    ▼
容器终止（资源清理）
    │
    ├── docker stop
    └── docker rm
```

**资源成本的数学模型**：

设单元测试执行时间为 $T_{\text{unit}}$，集成测试执行时间为 $T_{\text{integration}}$：

$$
T_{\text{integration}} >> T_{\text{unit}}
$$

总测试时间：

$$
T_{\text{total}} = p \times T_{\text{integration}} + (1-p) \times T_{\text{unit}}
$$

其中 $p$ 是集成测试占比。当 $p > 0.01$ 时，集成测试开始成为测试套件的主要时间成本。

### 数据库事务隔离的测试策略

**三种隔离策略的对比**：

| 策略 | DB 实例 | 事务管理 | 成本 | 隔离度 |
|------|---------|----------|------|--------|
| 独立 DB | 每个测试独立 | 独立生命周期 | 最高 | 最干净 |
| 事务回滚 | 共享 DB | 每个测试 begin/rollback | 中等 | 依赖 DB 隔离 |
| 独立 Schema | 共享 DB | 每个测试独立 schema | 低 | 中等 |

**事务回滚的隔离保证**：

设测试操作集合为 $O = \{o_1, o_2, \ldots, o_n\}$，若每个测试在独立事务中执行且最终回滚，则数据库状态 $S$ 满足：

$$
\forall \text{test}_i, \text{test}_j : S_{\text{after}(\text{test}_i)} = S_{\text{after}(\text{test}_j)} = S_{\text{initial}}
$$

即所有测试看到相同的初始状态。

### httptest 的请求-响应模型

**httptest 两种模式的对比**：

| 模式 | 创建方式 | 网络调用 | 适用场景 |
|------|----------|----------|----------|
| `NewServer` | `httptest.NewServer(handler)` | 真实网络（localhost） | 端到端测试 |
| `NewRecorder` | `httptest.NewRecorder()` | 无网络 | 单元测试级别 |

**`NewRecorder` 的工作原理**：

```
httptest.NewRecorder()
    │
    ├── 创建 ResponseRecorder（实现了 http.ResponseWriter）
    │       │
    │       ├── Write() 将数据写入内部 buf
    │       ├── WriteHeader() 记录状态码
    │       └── Header() 返回可写的 Header map
    │
    ▼
handler.ServeHTTP(recorder, request)
    │
    ├── handler 处理请求
    ├── 写入 recorder（模拟响应）
    │
    ▼
验证 recorder.Body / recorder.Code
```

**依赖反转（DIP）的应用**：

$$
\text{Handler} \xrightarrow{\text{依赖}} \text{ResponseWriter (interface)}
$$

$$
\text{RealServer} \models \text{ResponseWriter} \quad \text{Recorder} \models \text{ResponseWriter}
$$

高层模块（handler）依赖抽象（ResponseWriter 接口），低层模块（真实 server / recorder）实现该抽象。

### 事务回滚的隔离保证

<pre>
begin transaction
    │
    ├── INSERT user (id=1, name="Alice")
    │
    ├── TestXxx 验证插入
    │
    └── rollback
        │
        └── 事务内的所有操作被撤销

下一测试：重新 begin
    │
    ├── INSERT user (id=1, name="Alice")  // 同一条记录可再次插入
    │
    └── rollback

保证：
  - 每个测试看到相同的初始状态
  - 测试间无状态污染
  - 测试执行顺序不影响结果
</pre>

## 机制

### 为什么集成测试比单元测试慢？

**时间成本分解**：

| 测试类型 | 响应时间 | 内存占用 | 典型场景 |
|----------|----------|----------|----------|
| Mock（单元测试） | < 1ms | 微小 | 函数逻辑验证 |
| 真实 DB（集成测试） | 10-100ms | 中等 | SQL 正确性 |
| Docker 容器（集成测试） | 3-10s 启动 | 大 | 真实环境模拟 |

**数量级差异**：

$$
T_{\text{unit}}: T_{\text{integration}}: T_{\text{e2e}} \approx 1: 10^2: 10^4
$$

**解决方案**：
- Build tags 分离（`//go:build integration`）
- CI 分阶段执行
- 小范围集成（不启动全系统）

**为什么集成测试是必要的**：Mock 无法发现以下问题：
1. 序列化/反序列化格式不一致
2. 超时和重试逻辑的错误
3. 连接池耗尽
4. 事务边界错误
5. 协议版本不匹配

### httptest 为什么能模拟 HTTP？

**http.ResponseWriter 接口**：

```go
type ResponseWriter interface {
    Header() Header
    Write([]byte) (int, error)
    WriteHeader(statusCode int)
}
```

**httptest.NewRecorder() 实现了 ResponseWriter**：
- `Write()` 将数据写入内部 buf
- `WriteHeader()` 记录状态码
- `Header()` 返回可写的 Header map

**handler.ServeHTTP(w, req)**：
- Handler 完全不知道 `w` 是真实还是模拟
- 它只看到一个 `http.ResponseWriter` 接口

**DIP 的形式化约束**：若模块 A 依赖模块 B 的接口 I，则：
1. A 不应直接创建 B 的实例（应用工厂模式或依赖注入）
2. B 的实现应通过接口 I 暴露能力
3. 测试时可用 Mock 替代 B

### Testcontainers 的网络隔离

**Testcontainers 创建独立的 Docker 网络**：

```
主机
  │
  ├── docker0 网桥
  │       │
  │       └── Testcontainers 网络
  │               │
  │               ├── 容器 <─── 内部网络 ───> 容器
  │               │
  │               └── 通过 pgContainer.ConnectionString() 连接
  │
  └── localhost:5432 → 容器 5432（可选端口映射）
```

**隔离保证**：
- 测试数据库不暴露到主机网络（除非显式映射端口）
- 容器间通过内部网络通信
- 测试结束后容器销毁，网络清理

**网络隔离的安全价值**：测试数据库与生产数据库网络隔离，防止测试数据泄露或测试操作影响生产数据。

### 数据库连接池的测试约束

**集成测试中的数据库连接管理**：

连接池配置（通常在测试前设置）：
- `MaxOpenConns`: 10
- `MaxIdleConns`: 5
- `ConnMaxLifetime`: 30m

**测试隔离约束**：
- 每个测试使用独立事务
- 测试结束后回滚
- 禁止测试间共享连接

**连接泄漏检测**：
- `go test -race` 可以检测连接泄漏
- 若测试后连接数持续增长 → 存在连接泄漏

### Testcontainers 的资源管理

**资源生命周期管理**：

```go
func TestWithDB(t *testing.T) {
    ctx := context.Background()
    req := postgres.WithImage("postgres:15-alpine")
    pgContainer, err := postgres.Run(ctx, req)
    if err != nil {
        t.Fatal(err)
    }
    defer pgContainer.Terminate(ctx)  // 关键：确保清理

    // 测试逻辑...
}
```

**关键约束**：
- `defer` 必须在容器创建后立即设置
- 容器终止失败会导致资源泄漏
- 多个容器需要分别 terminate

## 测试金字塔与集成测试定位

```
        ▲
       /E2E\          少量，耗时最长，发现部署/环境问题
      /──────\
     /Integration\     适量，发现组件边界问题
    /────────────\
   /  Unit Tests  \   大量，快速，发现逻辑错误
  /───────────────\
 /─────────────────────\
──────────────────────────► 测试数量
```

**ROI（投资回报率）分析**：

| 指标 | 单元测试 | 集成测试 | E2E 测试 |
|------|----------|----------|----------|
| 成本（执行时间） | 低 | 中 | 高 |
| 覆盖率 | 高 | 中 | 低 |
| Bug 发现率（边界错误） | 低 | 高 | 中 |

**建议**：关键路径做集成测试，非关键路径单元测试覆盖即可。

## 验证标准

- 使用 `httptest.NewServer` 模拟外部 HTTP 依赖
- 每个测试使用独立事务或独立数据库
- 慢测试通过 build tags 标记，在 CI 中分离执行

## 版本基准

Go 1.24（stable）。本专题涉及的所有测试框架行为均基于该版本。

## 参考存根

```go
// httptest 用法
func TestHandler(t *testing.T) {
    handler := func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    }

    req := httptest.NewRequest("GET", "/api", nil)
    recorder := httptest.NewRecorder()

    handler.ServeHTTP(recorder, req)

    if recorder.Code != http.StatusOK {
        t.Errorf("status = %d; want %d", recorder.Code, http.StatusOK)
    }
    if recorder.Body.String() != "ok" {
        t.Errorf("body = %s; want ok", recorder.Body.String())
    }
}

// httptest.NewServer 用法
func TestClient(t *testing.T) {
    handler := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("hello"))
    })
    ts := httptest.NewServer(handler)
    defer ts.Close()

    client := NewClient(ts.URL)
    resp, err := client.Get()
    if err != nil {
        t.Fatal(err)
    }
    if resp != "hello" {
        t.Errorf("resp = %s; want hello", resp)
    }
}

// 数据库事务回滚
func TestWithTx(t *testing.T) {
    db, _ := sql.Open("postgres", connStr)
    tx, _ := db.Begin()
    defer tx.Rollback()

    _, err := tx.Exec("INSERT INTO users VALUES($1, $2)", 1, "Alice")
    if err != nil {
        t.Fatal(err)
    }

    // 测试逻辑...

    // tx.Rollback() 自动执行，所有更改撤销
}

// Testcontainers
func TestWithDB(t *testing.T) {
    ctx := context.Background()
    req := postgres.WithImage("postgres:15-alpine")

        t.Fatal(err)
    }

    connStr := pgContainer.ConnectionString(ctx)
    db, err := sql.Open("postgres", connStr)
    if err != nil {
        t.Fatal(err)
    }
    defer db.Close()

    // 使用真实数据库测试
    _, err = db.Exec("CREATE TABLE ...")
    // ...
}
```
