# 变量与类型

## 定义

Go 的类型系统是**静态编译时确定**的，通过类型推导简化声明，零值机制保证内存安全。核心设计：值类型（int、struct）直接存储数据，引用类型（slice、map、channel、pointer）存储数据的地址。逃逸分析决定变量分配在栈还是堆——栈分配满足 $O(1)$ 分配/释放，堆分配需要 GC 介入（ $O(n)$ 扫描）。

## 数学模型

### 逃逸分析的约束条件

Go 编译器通过**逃逸分析**决定变量的分配位置。逃逸分析是**过程间静态分析**，需要追踪指针的传递路径。

$\text{Escape}(var) = \begin{cases} \text{stack} & \text{如果 } \text{lifetime}(var) \leq \text{function\_return} \\ \text{heap} & \text{如果 } \text{lifetime}(var) > \text{function\_return} \end{cases}$

**逃逸分析的形式化规则**（满足任一即 heap 分配）：

| 规则 | 条件 | 原因 |
|------|------|------|
| R1 | 变量被 channel 引用 | 跨协程通信需要堆生命周期，channel 可能在接收者处理完之前不被 GC |
| R2 | 变量被 slice 引用且长度编译期未知 | `append` 可能触发重新分配，原 slice 的指针需保持有效 |
| R3 | 变量被 return 语句返回 | 调用者生命周期 > 被调者，返回指针必须指向堆上数据 |
| R4 | 变量被闭包捕获且超出创建作用域 | 闭包可能作为返回值持久化，生命周期不确定 |
| R5 | 变量被共享到全局变量 | 全局变量的生命周期 = 程序生命周期 |
| R6 | 变量大小超过栈阈值（编译估算） | 栈空间有限，大变量必须分配到堆 |

**指针传递的闭包性**：若变量 `v` 的地址被传递给函数 `f`，且 `f` 可能将指针持久化（如返回、存入全局、传给 channel），则 `v` 逃逸。

### 切片的扩容公式

切片扩容策略（Go 1.21+ 采用"double + 直至足够"策略）：

```go
// src/runtime/slice.go 核心逻辑（伪代码）
func growslice(et *elem, old slice, cap int) slice {
    newcap := old.cap
    doublecap := old.cap + old.cap
    if cap > doublecap {
        newcap = cap
    } else {
        if old.cap < 256 {
            newcap = doublecap
        } else {
            // 缓慢增长：每次 +25%
            for newcap < cap {
                newcap += (newcap + 3*256) / 4
            }
        }
    }
    // 内存对齐
    newcap = roundupsize(newcap)
    return slice{newarray(et, newcap), old.len, newcap}
}
```

**扩容公式的分段定义**：

$\text{newCap} = \begin{cases} 2 \times \text{oldCap} & \text{if } \text{oldCap} < 256 \\ \lfloor 1.25 \times \text{oldCap} + 0.75 \rfloor \text{（迭代直至足够）} & \text{if } \text{oldCap} \geq 256 \end{cases}$

**实际约束**：
- 内存对齐：按 8 字节对齐（64位系统），`roundupsize` 可能调整实际分配大小
- 溢出检测：`cap > maxSliceCap(通常 2^{48}-1)` 时限制
- 最小增长：至少 `oldCap + 1`

### 指针的代数语义

Go 指针满足**引用完整性约束**：

$\forall p: *T, \exists a: T, \text{使得 } *p = a \text{ 且 } \&a \text{ 是有效地址}$

**约束**：
- Go 不支持指针算术（`p + 1` 非法），保证内存安全
- 不同类型指针不能相互转换（除 `unsafe.Pointer`）
- `unsafe.Pointer` 是所有指针类型的中间形式，用于低层操作

**归约终点**：Go 指针归约为**确界安全的引用**，类型系统保证每次解引用都在对象边界内，不会像 C 那样产生未定义行为。

### 字符串的 Interning 机制

Go 编译器对**字符串字面量**执行 interning：相同内容的字面量共享同一底层字节数组。

$\text{Intern}(s) = \text{若 } \exists s' \text{ 使得 } s' = s \text{ 且 } \text{interned}(s') = \text{true，则返回 } s' \text{ 的指针；否则分配新内存并标记为 interned}$

**约束**：只有编译期可确定的字符串（字面量）会自动 intern。运行时拼接的字符串不 intern。

**应用**：相同内容的字符串比较 $O(1)$ （只需比较指针），而非 $O(n)$ 字节比较。

## 机制

### 值类型 vs 引用类型的本质差异

**值类型**赋值的深拷贝语义：
- 赋值时复制整个数据结构
- 修改副本不影响原值
- 适合小型独立数据（int、float、struct）

**引用类型**赋值的浅拷贝语义：
- 赋值时复制引用（指针），不复制数据
- 所有引用共享同一底层数据
- 适合大型数据或需要共享的数据

**所有权模型**：值类型传递时转移数据所有权，引用类型传递时共享所有权（借用）。

### slice 的 len 和 cap 分离设计

`len` 和 `cap` 分离提供**边界检查的科学依据**：

- `len` = 可读写元素数，`s[i]` 访问要求 $i < \text{len}$ ，越界触发 panic
- `cap` = 可扩展上限，`append` 时检查 $\text{len} + 1 \leq \text{cap}$ ，否则扩容

**数学约束**：
- `s[i:j]` 切片操作要求 $0 \leq i \leq j \leq \text{cap}$
- `s[i:j:k]` 切片操作要求 $0 \leq i \leq j \leq k \leq \text{cap}$
- `append` 操作后 $\text{len} \leq \text{cap}$

### string 不可变的设计约束

string 不可变的设计出于三个约束：

1. **并发安全约束**：不可变数据无需加锁，可安全共享
2. **复用约束**：相同内容的字符串可共享底层字节数组（interning）
3. **安全约束**：避免字符串被意外修改导致哈希值变化

**违反约束的代价**：频繁修改字符串会产生大量临时对象，应使用 `strings.Builder`（减少复制）或 `[]byte`（原地修改）。

### map 遍历的伪随机性

map 的哈希表实现导致遍历顺序**伪随机**：

- 每个 map 有一个随机种子（创建时确定），影响 tophash 计算
- 遍历从随机桶起始位置开始，按哈希桶顺序遍历
- 伪随机性防止程序对遍历顺序产生依赖（避免隐式顺序依赖 bug）

**约束**：若需要有序遍历，必须使用**切片**存储键并排序：

```go
keys := make([]string, 0, len(m))
for k := range m { keys = append(keys, k) }
sort.Strings(keys)
for _, k := range keys { fmt.Println(k, m[k]) }
```

### 类型别名 vs 自定义类型

`type ID = int`（类型别名）：
- 完全等价，可隐式互换
- 用于语义强调，不提供类型安全

`type ID int`（自定义类型）：
- 独立的类型，不能隐式互换
- 提供类型安全保护，防止误用

**数学本质**：类型别名是等价关系（ $\equiv$ ），自定义类型是不相交并集（  $\cup$）中的独立成员。

## 对比参照

| 属性 | 值类型 | 引用类型 |
|------|--------|----------|
| 内存位置 | 栈或堆（逃逸分析决定） | 堆（堆上数据）+ 栈（引用本身） |
| 赋值语义 | 深拷贝（复制数据） | 浅拷贝（复制引用） |
| 修改影响 | 修改副本不影响原值 | 修改影响所有引用 |
| 零值 | 各类型的零值（0, "", nil） | nil（空引用） |
| 典型类型 | int, float, bool, struct, array | slice, map, channel, pointer, interface |
