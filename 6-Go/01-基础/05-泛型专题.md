# 泛型专题

## 定义

Go 1.18 引入泛型，允许编写可复用且类型安全的代码，无需类型断言或反射。泛型的本质是**参数化多态**：类型参数在编译时实例化为具体类型，消除了运行时类型断言的开销，同时保留编译时类型检查。泛型特别适合数据结构（栈、队列、树）和算法实现（排序、搜索）。

### 类型约束的数学本质

类型约束是类型参数的**定义域**：

 $\text{Constraint}(T) = \text{允许的类型集合}$ 

若 $T$ 被约束为 `Number`，则： 被约束为 `Number`，则：

 $T \in \{\text{int}, \text{int64}, \text{float32}, \text{float64}\}$ 

`comparable` 约束要求类型支持 `==` 和 `!=`：

 $T \in \{x \mid x \text{ 可以使用 } == \text{ 和 } != \}$ 

**并集约束**：`int | int64 | float32 | float64` 表示联合类型。

### 类型推断的约束传播

类型推断基于**统一（unification）算法**：

设泛型函数 `func F[T any](a T, b []T)`，调用 `F(42, []int{1, 2})`：

```
约束收集：
  T = int              // 第一个参数类型
  T ∈ []int 的元素类型  // 第二个参数的泛型参数

统一：
  T = int ∧ T = int  // 统一成功

结果：T = int
```

**约束传播算法**：

```
function Infer(T, args):
    constraints = {}
    for each (type_param, arg) in zip(T, args):
        add constraint (type_param = arg.type)
        if arg is generic:
            add constraint (type_param ∈ arg.type_param)
    return unify(constraints)
```

## 机制

### 类型约束的本质

`any` 约束表示无限制，任何类型都满足：
 $\text{any} = \{x \mid x \text{ 是任意类型}\}$ 

`comparable` 约束要求类型支持相等性判断：
 $\text{comparable} = \{x \mid x \text{ 可以使用 } == \text{ 和 } != \}$ 

类型约束通过**并集语法**组合类型：

```go
type Number interface{
    int | int64 | float32 | float64
}
```

这里 `int | int64 | float32 | float64` 是**联合类型**，编译器在实例化时检查实际类型是否属于这个联合。

### 泛型函数类型推断

编译器在调用点推断类型实参：

```go
func Sum[T any](a, b []T) T

// 编译器推断 T = int（基于 a, b 的类型）
result := Sum(a, b)  // a, b 是 []int
```

推断基于**函数参数的类型**。若无法推断（如无参数），则必须显式指定类型实参：

```go
result := Sum[int](a, b)  // 显式指定 T=int
```

### 泛型方法的方法集

泛型结构体的方法可以有自己的类型参数，但方法集本身不因泛型参数而变化：

```go
type Container[T any] struct{ items []T }

// Map 是 Container[T] 的方法，U 是方法的独立类型参数
func (c *Container[T]) Map[U any](f func(T) U) *Container[U]
```

**约束**：方法的类型参数 `U` 与结构体的类型参数 `T` 无关，各自独立实例化。

### 自引用泛型的约束

链表等自引用结构需要接口作为中介：

```go
type LinkedList[T any] interface {
    Value() T
    Next() LinkedList[T]
}
```

`LinkedList[T]` 在定义中引用自身，必须通过接口间接定义。这避免了类型表达式无解的问题。

**形式化问题**：若直接定义 `type List[T any] struct { head *List[T] }`，类型表达式在语义上无解（递归定义无基例）。通过接口间接定义，接口本身是引用类型，解决了递归定义问题。

### 泛型与接口的能力边界

| 场景 | 泛型 | 接口 |
|------|------|------|
| 类型分发 | 编译时静态 | 运行时动态 |
| 异构类型集合 | 不可（同一集合元素类型必须相同） | 可（同一集合可放不同类型） |
| 插件架构 | 不适合 | 适合（接口的运行时多态） |
| 性能 | 最优（无装箱） | 需要接口装箱，有少量开销 |

**关键约束**：
- 泛型要求**编译时确定类型**，适合同质类型的数据结构和算法
- 接口适合需要**运行时多态**的插件架构

### 泛型的代码膨胀问题

泛型的代码膨胀（code bloat）是主要权衡：

```go
// 泛型函数被 100 种不同类型调用
func Min[T constraints.Ordered](a, b T) T { ... }

// 编译器生成 100 份机器码副本
Min_int, Min_float64, Min_string, ...
```

**缓解策略**：
- 对热点泛型代码使用接口而非泛型（牺牲性能减少代码量）
- Go 编译器会进行实例化去重（相同类型组合只生成一次）

## 参考存根

```go
// 泛型类型约束
type Ordered interface {
    int | int8 | int16 | int32 | int64 |
    uint | uint8 | uint16 | uint32 | uint64 |
    float32 | float64 | string
}

// 泛型最值函数
func Min[T Ordered](a, b T) T {
    if a < b { return a }
    return b
}

// 泛型栈
type Stack[T any] struct{ items []T }

func (s *Stack[T]) Push(item T) { s.items = append(s.items, item) }

func (s *Stack[T]) Pop() T {
    item := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return item
}

// 泛型 Filter-Map-Reduce
func Map[T, U any](s []T, f func(T) U) []U {
    result := make([]U, len(s))
    for i, v := range s { result[i] = f(v) }
    return result
}

func Filter[T any](s []T, pred func(T) bool) []T {
    result := make([]T, 0)
    for _, v := range s {
        if pred(v) { result = append(result, v) }
    }
    return result
}

func Reduce[T, U any](s []T, init U, f func(U, T) U) U {
    result := init
    for _, v := range s { result = f(result, v) }
    return result
}

// 自引用泛型（通过接口间接）
type List[T any] interface {
    Value() T
    Next() List[T]
}
```
