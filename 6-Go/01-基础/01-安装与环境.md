# 安装与环境

## 定义

Go 安装与环境是 Go 工具链的**物理布局与依赖解析机制**。通过 go mod 有向无环图（DAG）锁定依赖版本，通过 go workspace 协调多模块并行开发，通过 GOPROXY 代理网络获取模块。版本选择算法 MVS（最小版本选择）保证确定性构建：给定相同 go.mod，在任何机器上解析出相同的依赖图。

## 数学模型

### 依赖解析的 DAG 模型

go mod 依赖管理可建模为**有向无环图（DAG）**：

$$G = (V, E), \quad V = \text{模块集合}, \quad E = \text{require 依赖关系}$$

每条边 $e = (m, d)$ 表示模块 $m$ 依赖模块 $d$。版本约束函数 $C: V \to 2^{\text{Versions}}$ 将每个模块映射到其可用版本集合。

### 最小版本选择（MVS）算法

MVS 通过以下不动点算法求解依赖版本：

```
function SelectVersion(m, selected):
    if m in selected: return selected[m]
    candidates = {v ∈ Versions(m) | ∀d ∈ deps(m): v ≥ selected[d]}
    if candidates is empty: error "no valid version"
    v = min(candidates)  // 按语义版本排序的最小版本
    selected[m] = v
    for d in deps(m):
        SelectVersion(d, selected)
    return selected
```

**不动点存在性证明**：

设 $\mathcal{V} = \text{Versions}$ 为所有模块版本的集合，按语义版本排序构成**有限格**（每个模块的版本集合是全序集，整个版本空间是有限格的乘积）。定义单调算子 $F: \mathcal{V}^{|V|} \to \mathcal{V}^{|V|}$：

$$F(\mathbf{v})_m = \min \{ v \in C(m) \mid \forall d \in \text{deps}(m): v \geq \mathbf{v}_d \}$$

其中 $\mathbf{v}$ 是所有模块当前选择的版本向量。初始时 $\mathbf{v}_m = \min C(m)$（每个模块的最小版本）。

**单调性**：若 $\mathbf{v} \leq \mathbf{w}$（按分量序），则 $F(\mathbf{v}) \leq F(\mathbf{w})$。因为更大的下界只会排除更多候选版本。

**收敛性**：由于版本域是有限格，且 $F$ 单调，布劳威尔不动点定理保证迭代 $\mathbf{v}^{(k+1)} = F(\mathbf{v}^{(k)})$ 在有限步内收敛到最小不动点。

**唯一性**：设 $S_1, S_2$ 为两个不动点。对任意 $m \in V$，若 $S_1(m) \neq S_2(m)$，不妨设 $S_1(m) < S_2(m)$。由于 $S_2(m)$ 是满足所有依赖约束的版本，而 $S_1(m)$ 是满足约束的最小版本，矛盾。故不动点唯一。

### go build 并行编译模型

编译并行度受 DAG 的**关键路径**限制：

$$p_{\text{effective}} = \min\left(\text{GOMAXPROCS}, \frac{\sum_{e \in E} w_e}{\text{critical\_path\_length}}\right)$$

其中 $w_e$ 是边 $e$ 的权重（编译该包的时间）。对于完全无依赖的叶子包，并行度等于包的数量；对于深度依赖链，关键路径长度等于最长路径，并行度受限于深度。

## 机制

### MVS 的确定性构建保证

MVS 的核心性质是**可重现性**：给定相同的 go.mod 和 go.sum，在任何机器上执行 `go build` 得到相同的依赖图。

**攻击模型**：MVS 防止**依赖版本降级攻击**。攻击者发布旧版本恶意包时，由于 MVS 总是选择满足所有约束的最小版本，且 go.sum 记录了精确校验和，攻击包不会被使用。

### GOPROXY 的回退机制

GOPROXY 支持**链式回退**：

```
GOPROXY=https://proxy1.golang.org,https://proxy2.golang.org,direct
```

请求流程：
1. 按顺序尝试每个 proxy
2. 若 proxy 返回 404/410，且 proxy 标记为 `direct`，尝试下一个
3. 若 proxy 是真实服务器而非 `direct`，404 表示版本不存在（不尝试下一个）
4. 若所有 proxy 失败，使用 `direct` 模式直接从 VCS 获取

**off 模式**：`GOPROXY=off` 完全禁用网络下载，仅使用缓存。

### go mod tidy 的安全价值

go mod tidy 通过**传递依赖闭包扫描**防止**幽灵依赖攻击**：

```
攻击路径：
间接依赖 A（已知有漏洞，修复版本 v1.1） → 声明 A v1.0 在 go.mod
        │
        ▼
代码直接 import A → go mod tidy 发现 A 未被使用
        │
        ▼
自动从 go.mod 移除 A → go.sum 移除 A 的校验和
        │
        ▼
攻击者发布恶意 A v1.0.1（劫持旧版本）
        │
        ▼
下一位开发者运行 go mod tidy → 下载到恶意版本
```

**防御机制**：go mod tidy 扫描所有 `.go` 文件的 import 语句，计算传递依赖的闭包，仅保留实际被引用的包。

### go.sum 的完整性验证

go.sum 每行格式：`<module> <version> <kind> <checksum>`

```
github.com/gin-gonic/gin v1.9.1 h1:4idEAncQnU5cB7BeOkPtxjfCSye0AAm1R0RVIqJ+Jmg=
github.com/gin-gonic/gin v1.9.1/go.mod h1:hPrL7YrpYKXt5YId3A/Dn+qAyWCT1C0lqKKHLNcH1FA=
```

- `h1:` 行是模块整体的 SHA-256 哈希
- `/go.mod` 行是 go.mod 文件的 SHA-256 哈希

`go mod verify` 检查下载的模块是否与记录匹配。

### go workspace 的多模块协调

go workspace 解决**多模块同步修改**问题：

- 多个相关的 go.mod 需要同时修改（如微服务仓库的 API 和 client 同时升级）
- 不需要 `go mod edit -replace` 手动替换
- `go work sync` 同步所有模块的依赖视图到 `$GOPATH/pkg/mod`

**约束**：go.work 文件本身不应提交到版本控制（通常加入 .gitignore），因为它包含本地路径。

### 环境变量的约束

| 变量 | 约束/默认值 | 机制 |
|------|-------------|------|
| GOROOT | 自动检测 | Go 安装目录，go 命令行工具定位标准库 |
| GOPATH | `$HOME/go` | 旧模式工作区（已废弃，但仍影响模块缓存路径） |
| GOPROXY | `proxy.golang.org,direct` | 模块下载代理，支持 direct 和 off |
| GO111MODULE | `auto` | auto 模式下，目录有 go.mod 时启用模块模式 |
| GOMODCACHE | `$GOPATH/pkg/mod` | 模块缓存位置 |
| GOMAXPROCS | CPU 核数 | go build 并行编译的最大并行度 |

## 参考存根

```go
// go.mod 文件结构
module github.com/user/project

go 1.24

require (
    github.com/gin-gonic/gin v1.9.1
)

require github.com/pkg/errors v0.9.1 // indirect
```

```go
// go.work 文件结构
go 1.24

use (
    ./module1
    ./module2
)
```

```bash
# 核心命令
go mod init module_name      # 初始化
go mod tidy                  # 整理依赖（扫描 import 构建闭包）
go get package@version       # 添加依赖
go mod download              # 预下载到缓存
go mod verify               # 校验 go.sum 一致性
go work sync                # 同步 workspace 依赖

# 环境查看
go env GOROOT GOMODCACHE    # 查看关键环境变量
go version                  # 查看 Go 版本
```
