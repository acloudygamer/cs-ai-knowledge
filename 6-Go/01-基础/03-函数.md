# 函数

## 本质断言

Go 函数的独特价值在于多返回值机制——特别是 `(result, error)` 模式，使错误处理成为函数签名的显式组成部分而非异常机制。defer 关键字实现 LIFO 语义的资源清理，闭包则允许函数捕获并持久化外部变量状态。

## 数学模型

### 函数作为一等公民的 lambda 演算

Go 函数满足 **lambda 演算**的基本规则：
- 函数是值，可赋值给变量
- 函数可作为参数传递
- 函数可作为返回值

设函数类型为 $T \to U$（输入 T，输出 U），则 Go 的函数类型是**闭包**：
$$\text{Closure} = \lambda x. \text{body} + \text{captured\_variables}$$

### defer 的栈帧模型

defer 调用存储在**调用者栈帧**中，按 LIFO 顺序执行：

$$\text{DeferStack} = \{ d_1, d_2, \ldots, d_n \} \text{ where } d_i \text{ added at } i$$

执行顺序：$d_n, d_{n-1}, \ldots, d_1$

**时间复杂度**：defer 注册 $O(1)$，执行 $O(n)$。

### 闭包捕获的代数语义

闭包捕获变量时，被捕获变量的**引用**被闭包持有：

$$\text{Closure}(f, \text{captured}) = \lambda x. f(x, \text{captured})$$

这意味着：
- 闭包内部修改被捕获变量 → 影响外部
- 被捕获变量的生命周期 ≥ 闭包的生命周期

## 机制

### 为什么 Go 选择多返回值

多返回值的设计满足**错误传播**的组合律：

$$\text{Result} = \text{Ok} \oplus \text{Err}$$

其中 $\oplus$ 表示结果和错误的正交组合。相比异常机制：
- 错误必须被显式处理，不能忽略
- 错误路径和正常路径在代码中同等可见
- 错误可以逐层传播或就地处理

### 为什么 defer 执行顺序是 LIFO

defer 的 LIFO 执行顺序保证**资源释放的反向顺序**：

```go
defer file.Close()      // 后打开先关闭
defer mu.Unlock()       // 后加锁先解锁
```

这符合资源管理的**嵌套语义**：外层资源依赖内层资源，内层先释放。

### 为什么 defer 适合 panic recovery

defer 在 panic 时仍然执行，这使得：
- 即使程序崩溃，也能保证资源释放
- 可以用 `recover()` 捕获 panic，实现类似异常的处理

但过度使用 panic/recover 会破坏 Go 的**显式错误处理**哲学。

### 闭包 vs 函数指针

| 维度 | 函数指针 | 闭包 |
|------|----------|------|
| 捕获环境 | 否 | 是 |
| 状态持久化 | 否 | 是 |
| 内存分配 | 栈 | 堆（逃逸分析） |
| 适用场景 | 回调、插件 | 迭代器、工厂函数 |

## 多返回值

函数可返回多个值，error 作为最后一个返回值是 Go 的惯用约定。

```go
func divide(a, b int) (int, error) {
    if b == 0 { return 0, errors.New("div by zero") }
    return a / b, nil
}
result, err := divide(10, 2)
```

## 命名返回值

返回值作为命名变量在函数体中使用，return 省略变量名。

```go
func split(sum int) (x, y int) {
    x = sum * 4 / 9
    y = sum - x
    return
}
```

## 可变参数

`...T` 语法使函数接受同类型任意数量的参数，内部作为切片处理。

```go
func sum(nums ...int) int {
    total := 0
    for _, n := range nums { total += n }
    return total
}
sum(1, 2, 3)
```

传切片给可变参数需解包：

```go
vals := []int{1, 2, 3}
sum(vals...)
```

## 闭包

闭包是捕获了外部作用域变量的函数，变量状态在闭包调用间持久化。

<pre>
闭包捕获外部变量:
  sum := 0
  ┌─────────────────────┐
  │ func(x int) int    │
  │   sum += x         │────┼──→ 捕获 sum（持久化）
  │   return sum       │
  └─────────────────────┘
</pre>

```go
func adder() func(int) int {
    sum := 0
    return func(x int) int {
        sum += x
        return sum
    }
}
pos := adder()
pos(1)                       // 1
pos(2)                       // 3
```

## defer 延迟执行

defer 在函数退出前按 LIFO（后进先出）顺序执行。

<pre>
函数退出顺序:
  defer "3"  (最后定义)
  defer "2"
  defer "1"  (最先定义)
  输出: 3 → 2 → 1
</pre>

```go
defer fmt.Println("1")
defer fmt.Println("2")
defer fmt.Println("3")
// 输出: 3 2 1
```

defer 常用场景：文件关闭、锁解锁、连接关闭。

```go
file, _ := os.Open("test.txt")
defer file.Close()
mu.Lock()
defer mu.Unlock()
```

## 函数作为值

函数是一等公民，可作为参数、返回值和变量值。

```go
apply := func(fn func(int) int, x int) int {
    return fn(x)
}
apply(func(x int) int { return x * 2 }, 5)  // 10
```

## 函数式选项模式

用函数配置结构体，支持可选参数和默认值。

```go
type Option func(*Server)
func WithPort(port int) Option {
    return func(s *Server) { s.port = port }
}
func NewServer(opts ...Option) *Server {
    s := &Server{port: 8080}
    for _, opt := range opts { opt(s) }
    return s
}
server := NewServer(WithPort(9090))
```

## 错误处理约定

Go 约定返回 error 而非 panic，错误作为最后一个返回值。

```go
func DoSomething() error { return nil }
func Process() (Result, error) { return Result{}, nil }
```
