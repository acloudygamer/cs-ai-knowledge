# 性能优化

**Go 性能优化的核心是减少内存分配、避免不必要的反射和优化并发模型——这三者直接决定了 GC 压力和 CPU 利用率。**

## 性能测试基础

### 基准测试（Benchmark）

**`testing.B` 测量函数执行时间，`-benchmem` 显示内存分配统计，这两者是性能优化的基准线。**

### 参考样例

```go
func BenchmarkStringConcat(b *testing.B) {
    for i := 0; i < b.N; i++ {
        var s string
        for j := 0; j < 100; j++ {
            s += "hello"
        }
    }
}

func BenchmarkBuilderConcat(b *testing.B) {
    for i := 0; i < b.N; i++ {
        var builder strings.Builder
        for j := 0; j < 100; j++ {
            builder.WriteString("hello")
        }
        builder.String()
    }
}
```

### 基准测试结果解读

```

----------- -----------     -------   --------    --------    ----------
  name         iterations     ns/op    memory/op   allocs/op
```

## 切片操作优化

**切片是引用类型，append 时如果容量不足会触发 2 倍扩容（重新分配 + 拷贝）。预分配容量可避免多次扩容，减少内存分配和 GC 压力。**

### 参考样例

```go
func withoutPrealloc() []int {
    var s []int
    for i := 0; i < 1000; i++ {
        s = append(s, i)
    }
    return s
}

func withPrealloc() []int {
    s := make([]int, 0, 1000)
    for i := 0; i < 1000; i++ {
        s = append(s, i)
    }
    return s
}
```

## 字符串拼接优化

**字符串是不可变类型，`+` 拼接每次都分配新字符串。`strings.Builder` 通过可变缓冲区避免中间字符串分配，是大量拼接的首选。**

### 参考样例

```go
var builder strings.Builder
for i := 0; i < 1000; i++ {
    builder.WriteString("hello")
}
result := builder.String()

parts := []string{"hello", "world", "foo"}
result = strings.Join(parts, ", ")
```

## 反射优化

**反射比直接调用慢 10-100 倍，因为涉及类型检查和方法查找。在热路径上避免反射是性能优化的关键。**

### 替代方案优先级

1. **泛型**（Go 1.18+）——编译时确定，无运行时开销
2. **接口**——静态类型检查，快于反射
3. **代码生成**（如 `stringer`）——零反射，最高效
4. **map 缓存反射结果**——减少重复反射，但仍慢于静态调用

### 参考样例

```go
// 慢：每次反射
v := reflect.ValueOf(x)
v.FieldByName("Name").Interface()

// 快：直接访问
x.Name

// 最快：泛型
func Map[T, U any](s []T, fn func(T) U) []U

// 缓存反射结果
var typeCache = sync.Map{}

func getFieldIndex(t reflect.Type, name string) int {
    if cached, ok := typeCache.Load(t); ok {
        return cached.(map[string]int)[name]
    }
    fields := make(map[string]int)
    for i := 0; i < t.NumField(); i++ {
        fields[t.Field(i).Name] = i
    }
    typeCache.Store(t, fields)
    return fields[name]
}
```

## 并发优化

### Goroutine 池

**Worker Pool 预创建固定数量 goroutine 避免无限制创建，通过 channel 分发任务实现调度复用。**

```go
type Pool struct {
    work  chan func()
    sem   chan struct{}
}

func NewPool(size int) *Pool {
    p := &Pool{
        work: make(chan func()),
        sem:  make(chan struct{}, size),
    }
    for i := 0; i < size; i++ {
        go p.worker()
    }
    return p
}

func (p *Pool) worker() {
    for f := range p.work {
        f()
    }
}
```

### 高效 Channel 使用

```go
ch := make(chan int, 10)
defer close(ch)

select {
case v := <-ch:
    fmt.Println(v)
case <-time.After(5 * time.Second):
    fmt.Println("timeout")
}
```

## I/O 优化

### bufio 缓冲

**`bufio` 通过减少系统调用次数提升 I/O 效率：Reader 批量读取，Writer 批量写入。**

### 参考样例

```go
f, _ := os.Open("large.txt")
defer f.Close()

reader := bufio.NewReader(f)
for {
    line, _, err := reader.ReadLine()
    if err != nil {
        break
    }
}

file, _ := os.Create("output.txt")
defer file.Close()

writer := bufio.NewWriter(file)
for _, s := range lines {
    fmt.Fprintln(writer, s)
}
writer.Flush()
```

## 常见性能问题

| 问题 | 症状 | 解决方案 |
|------|------|----------|
| 内存泄漏 | 内存持续增长 | pprof heap, 检查全局变量、channel |
| GC 压力 | 延迟周期性增加 | 减少分配, sync.Pool, GOGC |
| 竞态条件 | 数据不一致 | -race, mutex/atomic |
| 锁竞争 | 并发性能差 | 减小锁粒度, lock-free 结构 |
| 过多 Goroutine | 内存占用高 | worker pool, semaphore |
| 频繁字符串拼接 | CPU 高, 内存碎片 | strings.Builder |
| 反射滥用 | 性能差 | 泛型, 接口, 代码生成 |
