# 网络编程专题

**网络编程是 Go 通过 `net` 包实现 TCP/UDP/HTTP 通信的能力——其本质是基于 epoll/kqueue 的 I/O 多路复用配合 goroutine per connection 模型，以少量 goroutine 处理大量并发连接。**

## 核心架构

**Go runtime 自动使用 epoll（Linux）或 kqueue（macOS/BSD）实现 I/O 多路复用，每个 goroutine 处理一个连接，阻塞时不占用 OS 线程。**

```
accept() → goroutine per connection
                ↓
         epoll/kqueue 监控可读事件
                ↓
         goroutine 被唤醒处理请求
                ↓
         conn.Read() / conn.Write()
```

## TCP 编程

### 连接生命周期

```
Client                              Server
  │─── dial("tcp", ":8080") ──────→│  listener.Accept()
  │◄─────── TCP 三次握手 ────────────│
  │
  ├─── conn.Write(b) ───────────────→│  reader.Read()
  │◄─────── 数据传输 ────────────────│
  │◄─────── conn.Read(b) ────────────│
  │
  │─── conn.Close() ────────────────→│  读到 io.EOF
  │◄─────── TCP 四次挥手 ─────────────│
```

### 粘包处理模式

**TCP 流式协议无消息边界，需要自定义分帧机制。**

```
定长分帧：      [DATA][DATA][DATA]（每帧固定 4KB）
分隔符分帧：    HELLO\nWORLD\n（基于 \n 或 \r\n）
长度前缀分帧：  [4B length][DATA]（TLV 格式，最常用）
```

### 参考实现

```go
// 服务端
listener, _ := net.Listen("tcp", ":8080")
for {
    conn, _ := listener.Accept()
    go func() {
        buf := make([]byte, 1024)
        for {
            n, _ := conn.Read(buf)
            if n == 0 {
                return
            }
            conn.Write(buf[:n])
        }
    }()
}
```

```go
// 客户端
conn, _ := net.Dial("tcp", "localhost:8080")
conn.Write([]byte("ping"))
buf := make([]byte, 1024)
n, _ := conn.Read(buf)
```

## UDP 编程

**UDP 是无连接协议，每个 ReadFromUDP/WriteToUDP 携带对端地址，无需粘包处理。**

```
UDP 通信模型：
Client                        Server
  │───── WriteToUDP(dat, addr) ────→│  ReadFromUDP(dat)
  │◄──── ReadFromUDP(dat) ←─────────│  WriteToUDP(dat, addr)
  │        （独立处理每条消息）          │
```

### 参考实现

```go
// 服务端
addr, _ := net.ResolveUDPAddr("udp", ":8080")
conn, _ := net.ListenUDP("udp", addr)
buf := make([]byte, 1024)
for {
    n, remote, _ := conn.ReadFromUDP(buf)
    conn.WriteToUDP(buf[:n], remote)
}
```

```go
// 客户端
conn, _ := net.Dial("udp", "localhost:8080")
conn.Write([]byte("ping"))
buf := make([]byte, 1024)
n, _ := conn.Read(buf)
```

## WebSocket

**WebSocket 是 HTTP 升级协议，握手后切换为全双工帧协议——解决了 HTTP 轮询的实时性问题。**

```
HTTP 请求（Upgrade: websocket）
    ↓
Server 返回 101 Switching Protocols
    ↓
全双工 WebSocket 帧交换
```

### 参考实现

```go
var upgrader = websocket.Upgrader{CheckOrigin: func(r *http.Request) bool { return true }}

func wsHandler(w http.ResponseWriter, r *http.Request) {
    conn, _ := upgrader.Upgrade(w, r, nil)
    defer conn.Close()
    for {
        _, msg, _ := conn.ReadMessage()
        conn.WriteMessage(websocket.TextMessage, msg)
    }
}
```

```go
// 客户端
conn, _, _ := websocket.DefaultDialer.Dial("ws://localhost:8080/ws", nil)
conn.WriteMessage(websocket.TextMessage, []byte("ping"))
_, msg, _ := conn.ReadMessage()
```

## HTTP 服务端

**Go 的 http.Handler 接口通过 ServeMux 路由分发，goroutine per request 模型处理并发。**

### 参考实现

```go
http.HandleFunc("/api", func(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("ok"))
})
http.ListenAndServe(":8080", nil)
```

```go
// 优雅关闭
server := &http.Server{Addr: ":8080", Handler: mux}
go server.ListenAndServe()
sig := <-make(chan os.Signal, 1)
server.Shutdown(context.Background())
```

## 连接池

**HTTP/TCP 连接池复用已建立的连接，避免频繁建连的开销（TCP 三次握手 + TLS 握手）。**

```
无池：  req1 → [建连→请求→断连] → req2 → [建连→请求→断连]
有池：  req1 → [建连→请求] → req2 → [请求] → req3 → [请求→断连]
```

### HTTP Transport 连接池

```go
client := &http.Client{
    Transport: &http.Transport{
        MaxIdleConns:        100,
        MaxIdleConnsPerHost:  10,
        IdleConnTimeout:      90 * time.Second,
    },
}
```

### 自定义 TCP 连接池

```go
type Pool struct {
    mu    sync.Mutex
    conns []*Conn
    max   int
    new   func() (*Conn, error)
}
```

## TLS 安全通信

**TLS 基于 TCP，在 TCP 三次握手后进行 TLS 握手——ECDHE 等 cipher suite 实现前向保密。**

```
TCP 三次握手 → TLS 握手 → 加密数据传输 → 密钥更新
```

### 参考实现

```go
cert, _ := tls.LoadX509KeyPair("cert.pem", "key.pem")
listener, _ := tls.Listen("tcp", ":8443", &tls.Config{Certificates: []tls.Certificate{cert}})
```

## 常见错误

```
1. 粘包未处理：TCP 流式数据需要自定义分帧
2. 未设置超时：Read/Write 可能永久阻塞
3. 连接泄露：defer conn.Close() 未配对
4. UDP 不可靠：丢包、乱序由应用层处理
```
