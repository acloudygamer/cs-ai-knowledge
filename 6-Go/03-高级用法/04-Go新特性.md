# Go 新特性

> **版本关系**：Go 1.24（stable）→ Go 1.26（<latest>）。Go 1.26 包含 `<latest>` 标注的前沿特性。

## 定义

Go 每个版本都带来了实用的新特性。Go 1.21 ~ 1.24 是稳定版主力，Go 1.26 包含前沿特性（标注 `<latest>`）。

**归约终点**：Go 版本演进可归约为**语言能力的渐进式扩展**，通过最小化破坏性变更实现向前兼容。

## 版本模型与生命周期

### 数学模型

**版本号语义**：Go 采用语义化版本（SemVer）：
$$Major.Minor.Patch$$

- Major：破坏性变更（Go 2.0 未发布，当前始终为 1）
- Minor：新功能（向后兼容）
- Patch：错误修复

**版本支持周期**：
- 当前稳定版：约 2 年
- 安全修复：当前稳定版 + 前一个 Minor 版本

## Go 1.21 新特性（stable）

### 内置 min/max/clear 函数

### 定义

内置函数无需 import，直接比较可排序类型——编译器内联，无函数调用开销。

### 数学模型

**内联优化**：编译器将 `min(a, b)` 直接替换为条件指令（如 `cmp + cmov`），无函数调用开销：
$$T_{min}(a, b) = O(1)$$

而非普通函数调用的 $O(1) + O(\text{call overhead})$。

**约束条件**：
- 参数类型必须可排序（实现了 `<` 运算符）
- 返回类型与参数类型相同

### 结构化日志 log/slog

### 定义

标准库内置结构化日志，支持 JSON/Text 两种格式，替代第三方日志库。

### 数据流

<pre>
slog 日志输出路径：

LogRecord{
    Time, Level, Message, Attrs...
}
    │
    ├─→ JSONHandler → json.Marshal → io.Writer
    └─→ TextHandler → 格式化字符串 → io.Writer
</pre>

## Go 1.22 新特性（stable）

### for range 循环变量作用域修复

### 定义

Go 1.22 修复了经典 bug：每次循环迭代创建新变量，而非共享同一个变量地址。

### 数学模型

**旧行为（Go 1.21 之前）**：
$$i_{shared} = \text{单一变量，所有 goroutine 共享同一地址}$$

设循环迭代变量为 $i$，在旧语义下：
$$\forall k \in [0, n): \text{addr}(i_k) = \text{addr}(i_{k+1})$$

**新行为（Go 1.22+）**：
$$i_n = \text{第 n 次迭代的独立变量}$$

在新语义下：
$$\forall k \in [0, n): \text{addr}(i_k) \neq \text{addr}(i_{k+1})$$

**修复的数学本质**：这是值捕获语义从"共享地址"到"独立拷贝"的转变，消除了数据竞争。

**数据竞争的形式化**：

旧行为下：
$$\exists k < j: \text{goroutine}_k \text{ 和 } \text{goroutine}_j \text{ 并发读 addr}(i) \implies \text{data race}$$

新行为下：
$$\forall k: \text{goroutine}_k \text{ 读 addr}(i_k) \implies \text{无 data race}$$

### 数据流

<pre>
Go 1.21 之前（bug）：
  for i := 0; i < 3; i++ {
      go func() { fmt.Println(i) }()
  }
  i 在每次迭代中被覆盖
  goroutine 读取时 i 已变为 3

Go 1.22（修复）：
  for i := 0; i < 3; i++ {
      go func() { fmt.Println(i) }()
  }
  每次迭代 i 是独立变量
  goroutine 读取时各自获得 0, 1, 2
</pre>

## Go 1.23 新特性（stable）

### iter 包（迭代器）

### 定义

`iter.Seq` 和 `iter.Seq2` 接口支持自定义迭代器，yield 模式替代闭包。

### 数学模型

**迭代器接口**：
```go
type Seq[T any] func(yield func(T) bool)
type Seq2[K, V any] func(yield func(K, V) bool)
```

**yield 语义的形式化**：

yield 函数返回 true 继续迭代，返回 false 提前终止：
$$\forall x \in S: yield(x) = true \implies \text{继续}$$
$$\exists x \in S: yield(x) = false \implies \text{终止}$$

这实现了**早期退出**的数学保证。

**终止条件的形式化**：

迭代器终止当：
1. 所有元素已 yield
2. yield 函数返回 false
3. 迭代器函数返回

**与闭包迭代器的对比**：

| 特性 | 闭包迭代器 | iter.Seq |
|------|-----------|---------|
| 内存分配 | 每次分配闭包 | 无分配 |
| 状态管理 | 闭包捕获变量 | 显式状态参数 |
| 早期退出 | 难实现 | 通过 yield 返回 false |
| 组合性 | 嵌套闭包复杂 | 函数组合简单 |

### unique 包（值内化）

### 定义

相同值返回同一 Handle（指针相等），用于节省内存。

### 数学模型

**值内化（Value Interning）**：
$$\forall x, y: x = y \Rightarrow unique.Make(x) = unique.Make(y)$$

通过维护字符串到指针的映射实现：
$$M: \text{string} \rightarrow \text{unsafe.Pointer}$$

查找时：
$$unique.Make(s) = \begin{cases} M[s] & \text{若 } s \in M \\ \text{insert}(s) & \text{若 } s \notin M \end{cases}$$

**内存节省**：若同一字符串出现 $N$ 次，内化后只存储一份，节省 $(N-1) \times |string|$ 字节。

**碰撞处理**：若 $x \neq y$ 但 $unique.Make(x) = unique.Make(y)$，则发生碰撞。Go 使用链地址法处理碰撞。

## Go 1.24 新特性（stable）

### weak 包（弱指针）

### 定义

弱指针不阻止 GC，用于构建缓存等内存敏感结构。

### 数学模型

**弱引用语义**：

| 引用类型 | GC 行为 |
|---------|--------|
| 强引用（普通指针） | 阻止 GC 对象 |
| 弱引用 | 不阻止 GC |

设对象 $O$ 只有弱引用指向它：
$$GC(O) \implies O \text{ 被回收}$$
$$GC(O) \text{ 后} \Rightarrow \text{弱引用返回 nil}$$

**弱指针的图灵等价性**：弱指针可用于构建**近似 LRU 缓存**，但不能实现精确 LRU（因为不知道对象何时被回收）。

**近似 LRU 的约束**：

由于无法精确知道对象何时被回收，近似 LRU 只能：
- 记录访问时间戳
- 在 GC 时清理最老的项
- 无法保证"最近最少使用"

### Swiss Table（map 引擎升级）

### 定义

Go 1.24 引入 Swiss Table 实现，CPU 开销降低 2-3%，无需改写代码。

### 数学模型

**Swiss Table 原理**：
- 传统 Go map：链表解决冲突（最坏 O(n)）
- Swiss Table：开放地址法 + robin hood hashing
- 查找复杂度：$O(1)$ 均摊，$O(\log n)$ 最坏

**Robin Hood Hashing 机制**：

核心思想：所有 key 按"到理想位置的距离"排序。

设：
- $h(k)$：key $k$ 的理想位置（哈希值模表大小）
- $d(i)$：slot $i$ 当前 key 的探测距离
- $probe(k, i)$：key $k$ 在 slot $i$ 的探测距离

探测序列：
$$probe(k, i) = (i - h(k)) \mod table\_size$$

插入时：
1. 计算当前 slot 的探测距离 $d_{current}$
2. 若新 key 距离更近，"窃取"当前 slot
3. 将旧 key 重新插入（继续探测）

**探查距离的数学约束**：

Robin Hood hashing 保证：
$$\forall \text{slot } i: d(i) \leq \log_2 n + c$$

其中 $n$ 是元素数量，$c$ 是常数。

实际观测：平均探查距离约 4-6 次。

**性能分析**：
| 指标 | 传统链表 map | Swiss Table (Robin Hood) |
|------|-------------|-------------------------|
| 平均查找次数 | $O(1)$ | $O(1)$ |
| 最坏查找次数 | $O(n)$ | $O(\log n)$（实际约 4-6 次）|
| 缓存友好性 | 差（指针跳转） | 好（连续内存） |
| 内存开销 | 指针 + 链表节点 | 仅表本身 |

**归约终点**：Swiss Table 将 map 查找问题归约为**开放地址探测**问题，robin hood 策略保证了探测距离的有界性。

## Go 1.26 新特性（<latest>）

### crypto/hpke（RFC 9180）

### 定义

混合公钥加密，结合传统公钥与后量子算法。

### 机制

**HPKE 的数学安全性**：基于 Diffie-Hellman 密钥交换的结合，提供前向安全和抗量子计算安全性。

**HPKE 的模式**：

| 模式 | KEM | 安全性 |
|------|-----|--------|
| mode_base | DHKEM(P-256) | 128-bit |
| mode_psk | DHKEM(P-256) + PSK | 128-bit |
| mode_auth | DHKEM(P-256) + 认证 | 128-bit |
| mode_auth_psk | DHKEM(P-256) + PSK + 认证 | 128-bit |

### errors.AsType（泛型错误解包）

```go
if err := errors.AsType[ValidationError](err); err != nil {
    fmt.Println(err.Field, err.Message)
}
```

**类型参数化的错误展开**：Go 1.26 通过泛型实现了类型安全的错误展开，避免了传统的 type assertion + error 类型断言模式。

**约束条件**：
- `err` 必须实现了 `As(ValidationError)` 方法
- 返回值 `err` 的类型是 `ValidationError`（而非 `error`）

| 包 | Go 1.21 | Go 1.22 | Go 1.23 | Go 1.24 | Go 1.26 |
|----|--------|---------|---------|---------|---------|
| 内置 | `min`, `max`, `clear` | `for range` 整数 | - | - | `new` 支持表达式 |
| `slices` | `Clone`, `Contains` | `Concat` | `Chunk`, `Backward` | - | - |
| `bytes` | - | - | - | `Lines` | `Buffer.Peek` |
| `maps` | `Clone`, `Copy`, `Equal` | - | `Collect`, `Insert` | - | - |
| `iter` | - | - | 新增 | 增强 | - |
| `weak` | - | - | - | 新增 | - |
| `testing` | - | - | - | `B.Loop` | `synctest` |
| `crypto` | - | - | - | `mlkem`, `hkdf` | `hpke` |

## 版本迁移决策

<pre>
选择 Go 版本时考虑因素：

稳定性优先 → 使用 Go 1.21 LTS
需要最新特性 → 使用 Go 1.26
需要平衡 → 使用 Go 1.24

版本升级检查清单：
  1. 跑完整测试套件
  2. 检查 deprecated API（go vet）
  3. 性能回归测试
  4. 检查第三方依赖兼容性
</pre>

## 新特性的稳定性分类

| 类别 | 说明 | 生产使用 |
|------|------|---------|
| Stable | 正式发布，稳定 API | 推荐 |
| Frozen | API 已锁定，仅修复 | 可用 |
| Exp | 实验性，可能变化 | 慎用 |
| Latest | 最新特性 | 评估后使用 |
