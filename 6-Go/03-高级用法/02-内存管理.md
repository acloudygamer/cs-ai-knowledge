# 内存管理

**Go 内存管理是自动的，但编译器通过逃逸分析决定变量分配到栈（极快，函数返回自动释放）或堆（GC 管理），这决定了程序的内存布局和 GC 压力。**

## 逃逸分析（escape analysis）

**逃逸分析是编译器静态判断变量应该分配在栈还是堆的过程：变量如果"逃逸"（其指针超出函数作用域），就必须分配在堆上，因为栈帧回收时会直接丢弃局部变量。**

### GC 工作原理

```
三色标记并发 GC：

  初始状态：所有对象白色
       │
       ▼
  ┌──────────────────────────────────────┐
  │  Root 扫描：全局变量、栈帧 → 灰色     │
  └──────────────────────────────────────┘
       │
       ▼
  ┌──────────────────────────────────────┐
  │  并发标记：                            │
  │    灰色对象引用的对象 → 灰色            │
  │    原灰色对象 → 黑色                  │
  │    （STW 仅在 Mark Start/Termination） │
  └──────────────────────────────────────┘
       │
       ▼
  ┌──────────────────────────────────────┐
  │  并发清扫：删除白色（不可达）对象       │
  └──────────────────────────────────────┘
```

Go 采用三色标记并发 GC，目标是暂停时间 < 100μs（而非传统的 100ms）。STW 仅发生在 Mark Start 和 Mark Termination 两个极短阶段。

### 参考样例

```go
func returnSliceLarge() []int {
    s := make([]int, 1000000)  // 大切片逃逸到堆
    return s
}

var global *int
func leakToHeap() {
    i := 42
    global = &i  // i 逃逸（指针超出函数作用域）
}
```

### 常见逃逸场景

```
指针逃逸：函数返回局部变量指针
  func foo() *int {
      i := 10
      return &i  // i 逃逸到堆
  }

接口逃逸：变量赋值给 interface{}
  var i interface{} = 42
  fmt.Println(i)  // i 逃逸（接口装箱）

切片增长：append 后返回切片
  func sliceGrowth() []int {
      s := make([]int, 0)
      for i := 0; i < 100; i++ {
          s = append(s, i)  // 扩容时整体逃逸
      }
      return s
  }
```

## 垃圾回收（GC）

### GC 阶段

| 阶段 | 说明 | STW |
|------|------|-----|
| Mark Start | 停止 Goroutine，准备标记 | 是（~10-100μs） |
| Mark | 并发标记可达对象 | 否 |
| Mark Termination | 完成标记，清理 | 是（~10-100μs） |
| Sweep | 并发清扫未使用对象 | 否 |

GOGC 环境变量控制 GC 触发时机：GOGC=100 表示内存增长到上次 GC 后的 2 倍时触发 GC。

### 参考样例

```go
import "runtime/debug"

debug.SetGCPercent(100)
runtime.GC()
debug.FreeOSMemory()
```

## 内存分配

### 栈 vs 堆

| 特性 | 栈 | 堆 |
|------|-----|-----|
| 分配速度 | 极快（移动栈指针） | 较慢（需要分配算法） |
| 释放 | 自动（函数返回） | GC 管理 |
| 大小 | 较小（KB 级） | 较大（GB 级） |
| 内存布局 | 连续 | 可能碎片化 |

### 分配策略

- **< 32KB**：先尝试栈，逃逸则堆分配
- **>= 32KB**：直接堆分配

### 内存分配器原理

```
TCMalloc 变体：
  每个 P（Processor）有本地分配缓存 mcache
  每个 size class 一个 mcentral
  全局堆 mheap

分配路径：
  小对象 → mcache → mcentral → mheap（从 size class span 分配）
  大对象 → mheap 直接分配
```

### 参考样例

```go
func stackAlloc() {
    arr := [64]int{}  // 小数组，栈上分配
}

func heapAlloc() {
    slice := make([]int, 10000)  // 大切片，堆上分配
}
```

## 减少分配技巧

### sync.Pool（对象池）

sync.Pool 通过缓存临时对象减少 GC 压力，对象在 GC 时可能被清除。

```go
var bufferPool = sync.Pool{
    New: func() any {
        return &bytes.Buffer{}
    },
}

func getBuffer() *bytes.Buffer {
    buf := bufferPool.Get().(*bytes.Buffer)
    buf.Reset()
    return buf
}

func putBuffer(buf *bytes.Buffer) {
    bufferPool.Put(buf)
}
```

### 预分配容量

```go
s := make([]int, 0, 1000)  // 预分配，避免多次扩容
```

## 内存分析（pprof）

**pprof 是 Go 内置的性能分析工具，通过采样收集 CPU、内存、goroutine 等信息，生成火焰图或文本报告。**

### 参考样例

```go
import "runtime/pprof"

f, _ := os.Create("cpu.prof")
pprof.StartCPUProfile(f)
defer pprof.StopCPUProfile()

f2, _ := os.Create("mem.prof")
pprof.WriteHeapProfile(f2)
f2.Close()
```

### pprof 分析命令

```bash
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=10
(pprof) top -10
(pprof) list funcName
(pprof) web  # 需要 Graphviz
```

## 内存监控

### runtime MemStats

```go
import "runtime"

var m runtime.MemStats
runtime.ReadMemStats(&m)

fmt.Printf("Alloc: %v KB\n", m.Alloc/1024)
fmt.Printf("HeapInuse: %v KB\n", m.HeapInuse/1024)
fmt.Printf("NumGC: %d\n", m.NumGC)
```

### GOGC 与内存限制

```go
debug.SetMemoryLimit(1024 * 1024 * 1024)  // 1GB
oldLimit := debug.SetMemoryLimit(-1)

// GOMEMLIMIT=8GB + GOGC=100 → 内存敏感场景
// GOGC=50 → 更积极回收，内存占用小
```
