# 插件系统

## 定义

Go 插件通过 `plugin` 包加载 `.so` 共享对象，实现运行时动态加载。其本质是** ELF（Linux）/ Mach-O（macOS）共享库的符号表查询**——主程序通过动态链接器在插件中查找符号（变量或函数），实现行为扩展。

受限于 Linux/macOS 且需与主程序 Go 版本一致，实际生产使用较少。

## 数学模型

### 插件加载的符号解析模型

```
插件文件：plugin.so（ELF/Mach-O 格式）
    │
    ├── .symtab：符号表（导出符号）
    ├── .dynsym：动态符号表（运行时解析）
    └── .text：机器码

Lookup("SymbolName") 执行：
  1. 在插件的 .dynsym 中查找 "SymbolName"
  2. 获取符号的地址（R_X86_64_JUMP_SLOT 等）
  3. 返回可用的函数/变量指针
  4. 类型断言验证接口匹配

关键约束：
  - 主程序和插件的 Go 版本必须完全一致
  - 插件使用 runtime 包会导致 panic
  - 插件中的 goroutine 无法被主程序调度器管理
```

### 插件接口契约

```
接口定义（主程序）：
  type Plugin interface {
      Name() string
      Execute(ctx context.Context) error
  }

插件实现：
  var PluginImpl = &MyPlugin{}

  func Register() (Plugin, error) {
      return PluginImpl, nil
  }

Lookup 契约：
  "Register" → func() (Plugin, error)  ← 必须返回接口类型
  类型断言：sym.(func() (Plugin, error))
```

## 数据流

### 插件加载的全链路

<pre>
plugin.so（磁盘文件）
    │
    │ dlopen(plugin_path)
    ▼
动态链接器加载共享库
    │
    ├── 映射 .text（代码段）到内存
    ├── 解析导入符号（主程序导出给插件的符号）
    ├── 重定位（relocations）
    │
    ▼
plugin.Open() 返回 *plugin.Plugin
    │
    │ p.Lookup("Register")
    ▼
符号查找（R_X86_64_JUMP_SLOT → 函数指针）
    │
    ├── 类型断言：fn.(func() (Plugin, error))
    │
    ▼
调用 fn() → 获取 Plugin 实例
    │
    ▼
Plugin.Execute(ctx) ← 插件逻辑在主程序调度下执行
</pre>

### 热加载的替换流程

<pre>
文件 mtime 变化
    │
    ├── 关闭现有插件：dlclose()（实际只是引用计数-1）
    │
    ├── 加载新版插件：dlopen(new_path)
    │
    ├── 重新 Lookup("Register")
    │
    ├── 新 Plugin 实例替换旧实例
    │
    ▼
新请求路由到新 Plugin
</pre>

## 机制

### 为什么 Go 插件系统实际很少使用？

**版本强耦合问题**：
- Go 的 runtime、GC、scheduler 版本必须与插件完全匹配
- 插件和主程序使用不同 Go 版本 → ABI 不兼容 → 运行时 panic
- 这意味着每次升级 Go 版本，所有插件必须重新编译

**功能限制**：
| 限制 | 原因 |
|------|------|
| 仅 Linux/macOS | Windows 不支持 `.so`/`.dylib` 加载 |
| 不能使用 runtime 包 | 运行时状态冲突 |
| 不能使用 cgo | 符号表复杂化 |
| goroutine 不受管理 | 插件的 goroutine 在主程序调度下，但 GC 不知道 |

**安全性问题**：
- 插件 panic 会传播到主程序
- 插件可以修改主程序的内存（通过 unsafe）
- 没有资源隔离（CPU/内存）

### 插件接口设计模式

```
推荐模式：
  主程序定义接口（不依赖插件代码）
  插件实现接口并导出 Register 函数

interface Plugin in main ──────► 插件实现 Plugin
       ▲                                 │
       │                                 │
       └── 动态加载时实现匹配 ────────────┘

这样主程序不依赖插件的任何类型声明，
插件只需要实现接口即可。
```

## 参考存根

```go
// 主程序
type Plugin interface {
    Name() string
    Execute(ctx context.Context) error
}

type Manager struct{ plugins map[string]Plugin }

func (m *Manager) Load(path string) error {
    p, err := plugin.Open(path)
    if err != nil { return err }
    sym, err := p.Lookup("Register")
    if err != nil { return err }
    fn := sym.(func() (Plugin, error))
    plug, err := fn()
    if err != nil { return err }
    m.plugins[plug.Name()] = plug
    return nil
}

// 插件实现
type MyPlugin struct{}

func (p *MyPlugin) Name() string { return "my-plugin" }
func (p *MyPlugin) Execute(ctx context.Context) error {
    // 插件逻辑
    return nil
}

var PluginImpl = &MyPlugin{}

func Register() (Plugin, error) { return PluginImpl, nil }
```

## 热加载实现

```go
// 热加载实现（基于 mtime 检测）
func (m *Manager) HotReload(path string) error {
    fi, err := os.Stat(path)
    if err != nil { return err }

    if m.mtimes[path] == fi.ModTime() {
        return nil // 未变化
    }

    // 关闭旧插件
    if old, ok := m.plugins[path]; ok {
        // 可选：调用 old.Close() 如果有
    }

    // 加载新插件
    if err := m.Load(path); err != nil {
        return err
    }

    m.mtimes[path] = fi.ModTime()
    return nil
}
```

## 限制总结

| 限制 | 说明 |
|------|------|
| 仅 Linux/macOS | Windows 不支持 |
| Go 版本必须一致 | 主程序和插件 |
| 编译标签必须一致 | 构建时指定 |
| 无真正卸载 | 只能替换，无法卸载 |
| 无资源隔离 | panic 传播、内存共享 |

## 替代方案

| 场景 | 替代方案 |
|------|----------|
| 配置热更新 | JSON/YAML 重载 |
| 算法可插拔 | 接口 + 工厂注册 |
| 业务扩展 | 微服务 RPC |
| WASM 沙盒 | golang.org/x/wasm |
