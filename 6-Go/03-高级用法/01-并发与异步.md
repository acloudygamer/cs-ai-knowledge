# 并发与异步

**Go 并发模型基于 CSP（Communicating Sequential Processes）理论：goroutine 通过 channel 通信而非共享内存——这解决了传统线程模型的高成本问题，万级并发下传统线程栈（MB 级）迅速耗尽内存，而 goroutine（KB 级栈）使轻量级并发成为可能。**

## goroutine（轻量级线程）

**goroutine 是由 Go runtime 采用 M:N 模型映射到少量 OS 线程的轻量级执行单元：创建成本约 ~2KB 初始栈，可同时运行数万个。**

### goroutine 与 WaitGroup

goroutine 启动后立即返回，调用者需通过同步机制等待完成。sync.WaitGroup 通过计数器协调一组 goroutine 的完成时机。

```
主线程
  ├─ wg.Add(1) → 计数器=1
  ├─ go work() → 新 goroutine
  │     └─ defer wg.Done() → 计数器-1
  └─ wg.Wait() → 阻塞，直到计数器归零
```

### 参考样例

```go
var wg sync.WaitGroup

for i := 0; i < 5; i++ {
    wg.Add(1)
    go func(id int) {
        defer wg.Done()
        fmt.Printf("goroutine %d 完成\n", id)
    }(i)
}

wg.Wait()
fmt.Println("所有 goroutine 完成")
```

## channel（goroutine 通信）

**channel 是 goroutine 之间的类型化管道：unbuffered channel 的 send 和 receive 必须 rendezvous（同时就绪），buffered channel 以 FIFO 队列解耦发送端和接收端。**

```
无缓冲 channel：
  goroutine A ──send──▶ ┌────────┐ ──receive──▶ goroutine B
                          └────────┘
                    （双方必须同时就绪）

有缓冲 channel：
  goroutine A ──send──▶ ┌─[buf]───────┐ ──receive──▶ goroutine B
                          └─────────────┘
                    （队列满时 send 阻塞，队列空时 receive 阻塞）
```

### 参考样例

```go
ch := make(chan int)       // 无缓冲
ch := make(chan int, 10)   // 缓冲容量 10

ch <- 42                   // send
v := <-ch                  // receive

close(ch)
for v := range ch {
    fmt.Println(v)
}

select {
case v := <-ch1:
    fmt.Println("ch1:", v)
case v := <-ch2:
    fmt.Println("ch2:", v)
case <-time.After(time.Second):
    fmt.Println("超时")
}
```

## 互斥锁和读写锁

**当需要共享状态而非通信时，sync.Mutex 强制互斥访问共享变量，sync.RWMutex 在读多写少场景下允许并发读但独占写——这避免了 channel 的额外簿记开销。**

### 参考样例

```go
var mu sync.Mutex
m := make(map[string]int)

mu.Lock()
m["key"] = 42
mu.Unlock()

var rwmu sync.RWMutex
rwmu.RLock()
v := m["key"]
rwmu.RUnlock()
```

## sync.Once 单次执行

**sync.Once 保证函数只执行一次——用于单例初始化时替代锁的双重检查模式，既安全又避免重复初始化的开销。**

### 参考样例

```go
var once sync.Once
var instance *DB

func getInstance() *DB {
    once.Do(func() {
        instance = &DB{}
    })
    return instance
}
```

## sync.Map（并发安全 map）

**sync.Map 内部采用读写分离优化（read + dirty 双结构），适合读多写少且 key 集合稳定的场景——大多数场景下用 sync.Mutex 保护普通 map 反而更快。**

### 参考样例

```go
var m sync.Map

m.Store("go", 30)
v, ok := m.Load("go")
m.Range(func(k, v any) bool {
    fmt.Printf("%s: %v\n", k, v)
    return true
})
m.Delete("go")
```

## context 上下文

**context 通过接口传递请求作用域的截止时间、取消信号和共享值——其本质是携带截止时间链和取消信号链的上下文容器，子 context 继承父 context 的 deadline 和 cancel 函数。**

详见 [Context 专题](./05-Context专题.md)。

## errgroup 协调多个 goroutine

**golang.org/x/sync/errgroup 将多个 goroutine 的错误汇聚：任一失败时通过 context cancel 其他 goroutine，实现"快速失败"语义。**

### 参考样例

```go
g, ctx := errgroup.WithContext(ctx)

for i, url := range urls {
    i, url := i, url
    g.Go(func() error {
        data, err := fetch(url)
        if err != nil {
            return err
        }
        results[i] = data
        return nil
    })
}

if err := g.Wait(); err != nil {
    return nil, err
}
```

## Worker Pool 模式

**Worker Pool 预创建固定数量 goroutine 从 job channel 消费任务——避免了无限制创建 goroutine 导致的调度负担和内存爆炸。**

### 参考样例

```go
func WorkerPool(jobs <-chan Job, results chan<- Result, numWorkers int) {
    var wg sync.WaitGroup

    for i := 0; i < numWorkers; i++ {
        wg.Add(1)
        go func(workerID int) {
            defer wg.Done()
            for job := range jobs {
                results <- processJob(workerID, job)
            }
        }(i)
    }

    wg.Wait()
    close(results)
}
```

## 优雅关闭（Graceful Shutdown）

**Graceful Shutdown 通过 signal.Notify 捕获 OS 信号，调用 server.Shutdown(ctx) 停止接受新请求并等待正在处理的请求完成——避免强制关闭导致的连接中断。**

### 参考样例

```go
quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit

ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

server.Shutdown(ctx)
```

## 避免 Goroutine 泄漏

**goroutine 无法被 GC 回收，只能通过 channel 或 context 取消——无缓冲 send 如果没有接收者会永久阻塞，这正是 goroutine 泄漏的根源。**

```
泄漏场景：
  ch := make(chan []byte)          // 无缓冲，无人接收
  go func() { ch <- fetch(url) }  // 永久阻塞

修复方案：
  ch := make(chan []byte, 1)      // 有缓冲
  select {
  case ch <- data:
  case <-ctx.Done():
  }
```

### 参考样例

```go
func leakyFetch(url string) <-chan []byte {
    ch := make(chan []byte)
    go func() {
        data, _ := fetch(url)
        ch <- data
    }()
    return ch
}

func safeFetch(ctx context.Context, url string) <-chan []byte {
    ch := make(chan []byte, 1)
    go func() {
        data, _ := fetch(url)
        select {
        case ch <- data:
        case <-ctx.Done():
        }
    }()
    return ch
}
```

## sync.Cond 条件变量

**sync.Cond 基于互斥锁实现条件等待：一个 goroutine 在 cond.Wait() 中自动释放锁并阻塞，另一个在满足条件时通过 Signal/Broadcast 唤醒等待者——这比轮询更高效。**

### 参考样例

```go
cond := sync.NewCond(&sync.Mutex{})
ready := false

go func() {
    cond.L.Lock()
    for !ready {
        cond.Wait()
    }
    cond.L.Unlock()
}()

cond.L.Lock()
ready = true
cond.Signal()
cond.L.Unlock()
```
