# 并发与异步

Go 并发模型基于 CSP（Communicating Sequential Processes）理论：goroutine 通过 channel 通信而非共享内存。这解决了传统线程模型的高成本问题——万级并发下，传统线程栈（MB 级）会迅速耗尽内存，而 goroutine（KB 级栈）使轻量级并发成为可能。

## goroutine（轻量级线程）

goroutine 由 Go 运行时管理，映射到少量 OS 线程（M:N 模型）。创建成本极低（~2KB 初始栈），可同时运行数万个。

### goroutine 与 WaitGroup

goroutine 启动后立即返回，调用者需通过同步机制等待完成。sync.WaitGroup 是标准模式。

### 参考样例

```go
import "sync"

// 启动 goroutine
go func() {
    fmt.Println("异步执行")
}()

// WaitGroup 等待一组 goroutine 完成
var wg sync.WaitGroup

for i := 0; i < 5; i++ {
    wg.Add(1)
    go func(id int) {
        defer wg.Done()
        fmt.Printf("goroutine %d 完成\n", id)
    }(i)
}

wg.Wait()  // 阻塞等待
fmt.Println("所有 goroutine 完成")
```

## channel（goroutine 通信）

channel 是 goroutine 之间的通信管道，类型化且阻塞操作。创建时指定容量（缓冲大小），不指定则为无缓冲。

### channel 核心操作

- `make(chan T)`：无缓冲 channel，发送和接收同步
- `make(chan T, n)`：缓冲 channel，容量 n
- `<-ch`：接收（阻塞直到有值）
- `ch <- value`：发送（阻塞直到被接收）

### 参考样例

```go
// 创建 channel
ch := make(chan int)           // 无缓冲
ch := make(chan int, 10)       // 有缓冲，容量10

// 发送和接收
ch <- 42        // 发送
value := <-ch   // 接收
<-ch            // 接收但不保存

// 关闭 channel
close(ch)

// for range 遍历 channel（自动检测关闭）
for v := range ch {
    fmt.Println(v)
}

// select 多路复用
select {
case v := <-ch1:
    fmt.Println("ch1:", v)
case v := <-ch2:
    fmt.Println("ch2:", v)
case <-time.After(time.Second):
    fmt.Println("超时")
}

// 单向 channel（用于函数参数限制方向）
func producer(out chan<- int) {  // 只能发送
    out <- 42
}
func consumer(in <-chan int) {   // 只能接收
    <-in
}
```

## 互斥锁和读写锁

当需要共享状态而非通信时，使用 sync 包中的锁机制。mutex 强制互斥访问，RWMutex 允许并发读但独占写。

### 参考样例

```go
var (
    mu   sync.Mutex
    m    = make(map[string]int)
)

// 互斥锁
mu.Lock()
m["key"] = 42
mu.Unlock()

// defer 更安全
mu.Lock()
defer mu.Unlock()
m["key"] = 42

// 读写锁（读多写少场景）
var rwmu sync.RWMutex

rwmu.RLock()  // 读操作加读锁
v := m["key"]
rwmu.RUnlock()

rwmu.Lock()   // 写操作加写锁
m["key"] = 43
rwmu.Unlock()
```

## sync.Once 单次执行

`sync.Once` 保证函数只执行一次，常用于单例模式。

### 参考样例

```go
var once sync.Once
var instance *DB

func getInstance() *DB {
    once.Do(func() {
        instance = &DB{}  // 只执行一次
    })
    return instance
}
```

## sync.Map（并发安全 map）

`sync.Map` 内部采用读写分离优化，适合读多写少场景。**注意**：大多数场景下，用 `sync.Mutex` 保护普通 `map` 性能更好。

### 参考样例

```go
var m sync.Map

m.Store("go", 30)
m.Store("py", 25)

value, ok := m.Load("go")
if ok {
    fmt.Println(value)
}

// 遍历
m.Range(func(k, v any) bool {
    fmt.Printf("%s: %v\n", k, v)
    return true  // 返回 false 停止遍历
})

m.Delete("go")
```

## errgroup 协调多个 goroutine

`golang.org/x/sync/errgroup` 将多个 goroutine 的错误汇聚，任一失败自动取消其他。

### 参考样例

```go
import "golang.org/x/sync/errgroup"

func FetchAll(ctx context.Context, urls []string) ([][]byte, error) {
    g, ctx := errgroup.WithContext(ctx)
    results := make([][]byte, len(urls))

    for i, url := range urls {
        i, url := i, url // 捕获循环变量
        g.Go(func() error {
            data, err := fetchWithTimeout(ctx, url)
            if err != nil {
                return err
            }
            results[i] = data
            nil
        })
    }

    if err := g.Wait(); err != nil {
        return nil, err // 任何一个失败都会取消其他 goroutine
    }
    return results, nil
}

func fetchWithTimeout(ctx context.Context, url string) ([]byte, error) {
    req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return nil, err
    }
    defer resp.Body.Close()
    return io.ReadAll(resp.Body)
}
```

## Worker Pool 模式

预先创建固定数量 worker，从 job channel 消费任务，避免无限创建 goroutine。

### 参考样例

```go
func WorkerPool(jobs <-chan Job, results chan<- Result, numWorkers int) {
    var wg sync.WaitGroup

    for i := 0; i < numWorkers; i++ {
        wg.Add(1)
        go func(workerID int) {
            defer wg.Done()
            for job := range jobs {
                results <- processJob(workerID, job)
            }
        }(i)
    }

    wg.Wait()
    close(results)
}

// 使用示例
func main() {
    jobs := make(chan Job, 100)
    results := make(chan Result, 100)

    go func() {
        defer close(jobs)
        for _, task := range tasks {
            jobs <- task
        }
    }()

    WorkerPool(jobs, results, 10) // 10 个 worker

    for result := range results {
        fmt.Println(result)
    }
}
```

## 优雅关闭（Graceful Shutdown）

收到 OS 信号后，平滑关闭 HTTP 服务器，等待正在处理的请求完成。

### 参考样例

```go
func GracefulShutdown(server *http.Server) {
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
    <-quit

    log.Println("Shutting down server...")

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    if err := server.Shutdown(ctx); err != nil {
        log.Fatalf("Server forced to shutdown: %v", err)
    }

    log.Println("Server exited")
}
```

## 避免 Goroutine 泄漏

goroutine 无法被 GC 回收，只能通过 channel 或 context 取消。无缓冲 send 如果没有接收者会永久阻塞。

### 参考样例

```go
// 差：如果没有接收者，goroutine 会泄漏
func leakyFetch(url string) <-chan []byte {
    ch := make(chan []byte)
    go func() {
        data, _ := fetch(url)
        ch <- data // 永远阻塞
    }()
    return ch
}

// 好：使用带缓冲的 channel 或 select
func safeFetch(ctx context.Context, url string) <-chan []byte {
    ch := make(chan []byte, 1) // 缓冲 channel
    go func() {
        data, err := fetch(url)
        if err != nil {
            return
        }
        select {
        case ch <- data:
        case <-ctx.Done():
            // context 取消时退出
        }
    }()
    return ch
}
```

## sync.Cond 条件变量

`sync.Cond` 实现条件等待：一个 goroutine 等待条件，另一个在满足条件时通知。

### 参考样例

```go
var mu sync.Mutex
cond := sync.NewCond(&mu)

ready := false

// 等待条件
go func() {
    mu.Lock()
    for !ready {
        cond.Wait() // 自动解锁并等待
    }
    mu.Unlock()
    fmt.Println("Ready!")
}()

// 通知等待者
mu.Lock()
ready = true
cond.Signal() // 通知一个
// 或 cond.Broadcast() 通知所有
mu.Unlock()
```
