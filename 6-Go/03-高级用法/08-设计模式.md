# 设计模式

**Go 没有类继承，惯用设计模式强调：组合优于继承、接口优于抽象类、函数优于类——这与传统 OOP 语言有本质区别。**

## 单例模式

**sync.Once 保证函数只执行一次——用于单例初始化时替代锁的双重检查模式。**

```go
var (
    instance *Manager
    once     sync.Once
)

func GetManager() *Manager {
    once.Do(func() {
        instance = &Manager{name: "default"}
    })
    return instance
}
```

## 工厂模式

**通过函数返回接口而非具体类型，实现解耦。**

```go
type Notification interface {
    Send(msg string) error
}

func NewNotification(t string) Notification {
    switch t {
    case "email":
        return &EmailNotification{}
    case "sms":
        return &SMSNotification{}
    }
    return nil
}
```

## 建造者模式

**链式调用构建复杂对象，避免构造函数参数爆炸。**

```go
type QueryBuilder struct {
    query Query
}

func (b *QueryBuilder) Table(name string) *QueryBuilder {
    b.query.table = name
    return b
}

func (b *QueryBuilder) Select(fields ...string) *QueryBuilder {
    b.query.fields = fields
    return b
}

query := (&QueryBuilder{}).
    Table("users").
    Select("id", "name").
    Where("age > 18").
    Build()
```

## 策略模式

**通过接口实现算法族替换，运行时决定使用哪个算法。**

```go
type PaymentStrategy interface {
    Pay(amount float64) error
}

type Checkout struct {
    strategy PaymentStrategy
}

func (c *Checkout) Pay(amount float64) error {
    return c.strategy.Pay(amount)
}
```

## 观察者模式

**通过接口定义事件订阅和通知机制。**

```go
type Observer interface {
    OnEvent(e Event)
}

type Subject struct {
    observers []Observer
    mu        sync.RWMutex
}

func (s *Subject) Subscribe(o Observer) {
    s.mu.Lock()
    defer s.mu.Unlock()
    s.observers = append(s.observers, o)
}

func (s *Subject) Notify(e Event) {
    s.mu.RLock()
    defer s.mu.RUnlock()
    for _, o := range s.observers {
        o.OnEvent(e)
    }
}
```

## 装饰器模式

**函数装饰器是 Go 的惯用模式，通过高阶函数包装行为。**

```go
type Handler func(req string) string

func Logger(h Handler) Handler {
    return func(req string) string {
        resp := h(req)
        return resp
    }
}

handler := Logger(Auth(func(req string) string {
    return "Response: " + req
}))
```

## 责任链模式

**通过 Chain 函数将多个 Middleware 组合成链式处理。**

```go
type Middleware func(next Handler) Handler

func Chain(h Handler, middlewares ...Middleware) Handler {
    for i := len(middlewares) - 1; i >= 0; i-- {
        h = middlewares[i](h)
    }
    return h
}
```

## 命令模式

**将请求封装为对象，支持撤销和日志。**

```go
type Command interface {
    Execute() error
}

type Editor struct {
    commands []Command
}

func (e *Editor) ExecuteCommand(cmd Command) {
    cmd.Execute()
    e.commands = append(e.commands, cmd)
}

func (e *Editor) Undo() {
    if len(e.commands) == 0 {
        return
    }
    e.commands = e.commands[:len(e.commands)-1]
}
```

## 适配器模式

**将不兼容接口适配成目标接口。**

```go
type LegacyStorage struct{}
func (ls *LegacyStorage) SaveData(data []byte) {}

type Storage interface {
    Save(key string, data []byte) error
}

type StorageAdapter struct {
    legacy *LegacyStorage
}

func (a *StorageAdapter) Save(key string, data []byte) error {
    a.legacy.SaveData(data)
    return nil
}
```

## 惯用 Go 模式小结

**Go 的设计模式强调：**

1. **组合优于继承** - 用嵌套结构体代替类继承
2. **接口优于抽象类** - 小接口定义行为（`io.Reader`、`http.Handler`）
3. **函数优于类** - 装饰器用函数实现
4. **显式依赖注入** - 构造函数传依赖
