# Go 设计模式

## 定义

Go 没有类继承，惯用设计模式强调：**组合优于继承**、**接口优于抽象类**、**函数优于类**。这与传统 OOP 语言有本质区别——Go 的模式是**行为组合**而非**类型层次**。

## 数学模型

### sync.Once 的正确性证明

`sync.Once.Do` 保证传入函数**恰好执行一次**（exactly-once semantics）。其正确性基于：

```
设 C 为执行计数器，初始 C = 0
Do(f) 的伪代码：

  if C == 0:
      mu.Lock()
      if C == 0:    // 双重检查
          f()
          C = 1
      mu.Unlock()

当 C = 1 时，后续所有 Do 调用直接跳过

关键属性：
  - 互斥锁保护 C 的写入
  - 双重检查避免重复执行（性能）
  - C 的值在锁外检查（无锁 fast path）
```

这等价于**once 语义**（一种特殊的互斥信号量），常用于单例、配置初始化。

### 接口组合的集合论

```
Go 接口是**行为集合**（而非类型层级）：
  io.Reader = { Read(p []byte) (n int, err error) }
  io.Writer = { Write(p []byte) (n int, err error) }
  io.ReadWriter = io.Reader ∪ io.Writer

类型实现接口 = 类型 ∈ 集合
  *os.File ∈ io.Reader  当且仅当 *os.File 实现了 Read 方法

接口组合满足分配律：
  (A ∪ B) ∪ C = A ∪ (B ∪ C)
```

## 数据流

### 单例模式（sync.Once）的执行流

<pre>
GetManager()
    │
    ├── C == 0？ ──► 否 ──► return instance（fast path，无锁）
    │
    ├── C == 0？ ──► 是 ──► mu.Lock()
    │                         │
    │                         ├── C == 0？ ──► 是 ──► f() 执行一次
    │                         │                      │
    │                         │                      ▼
    │                         │                  C = 1
    │                         │                      │
    │                         ├── C == 0？ ──► 否 ──► 跳过（已有线程完成）
    │                         │
    │                         ▼
    │                     mu.Unlock()
    │
    ▼
return instance
</pre>

### 装饰器模式（Middleware Chain）的数据流

<pre>
请求 string
    │
    ├── AuthMiddleware(request) ──► 验证/拒绝
    │        │ 通过
    │        ▼
    ├── LoggerMiddleware(request) ──► 记录日志
    │        │ 通过
    │        ▼
    ├── Handler(request) ──► 业务逻辑 ──► response string
    │        │ 返回
    │        ▼
    └── LoggerMiddleware(response) ──► 记录响应
             │
             ▼
         AuthMiddleware(response) ──► （如需）
             │
             ▼
         返回 client
</pre>

### 建造者模式的构造流

<pre>
QueryBuilder{}
    │
    ├── Table("users") ──► query.table = "users"
    │                     return *QueryBuilder
    │
    ├── Select("id", "name") ──► query.fields = ["id", "name"]
    │                           return *QueryBuilder
    │
    ├── Where("age > 18") ──► query.condition = "age > 18"
    │                         return *QueryBuilder
    │
    └── Build() ──► 返回不可变 Query 对象
                      │
                      ▼
                  SQL 生成：SELECT id, name FROM users WHERE age > 18
</pre>

## 机制

### 为什么 Go 选择组合优于继承？

继承的本质是**静态类型层次**，存在以下问题：

| 问题 | 继承中的表现 | Go 组合的解法 |
|------|------------|--------------|
| 脆弱的基类 | 基类改变破坏子类 | 显式接口依赖 |
| 菱形继承 | 方法解析顺序不确定 | 无多层继承 |
| 横切关注点 | AOP 需要继承层次 | 装饰器链显式组合 |
| 组合复用 | - | 嵌套结构体直接复用 |

Go 的组合是**命名组合**（通过字段嵌入），而非继承的**匿名子类型**。嵌入字段的方法会被提升到外包类型，但不改变外包类型的"是-一个"语义。

### 策略模式 vs 继承的运行时选择

```
继承（传统 OOP）：
  Payment ──► CreditCardPayment / AlipayPayment / WechatPayment
              在编译时决定类型

策略模式（Go）：
  Checkout{ strategy: PaymentStrategy }
              │
              ├── CreditCardStrategy{}
              ├── AlipayStrategy{}
              └── WechatStrategy{}
              在运行时决定使用哪个策略

本质：Go 将"选择哪个算法"从类型系统移到数据，
      运行时通过接口动态分派。
```

### 观察者模式的同步约束

观察者模式需要解决**并发安全**问题：

```go
// 问题：通知过程中 observer 可能被修改
// 解决：读写锁 + 快照

func (s *Subject) Notify(e Event) {
    s.mu.RLock()              // 读取期间禁止写入
    observers := s.observers  // 复制快照
    s.mu.RUnlock()

    for _, o := range observers {
        o.OnEvent(e)         // 通知期间 observer 列表不变
    }
}

func (s *Subject) Subscribe(o Observer) {
    s.mu.Lock()
    s.observers = append(s.observers, o)
    s.mu.Unlock()
}
```

这体现了**读写锁分离原则**：读操作可以并发，写操作必须独占。

## 参考存根

```go
// 单例
var (
    instance *Manager
    once     sync.Once
)
func GetManager() *Manager {
    once.Do(func() { instance = &Manager{name: "default"} })
    return instance
}

// 工厂 + 策略
type Notification interface { Send(msg string) error }
func NewNotification(t string) Notification {
    switch t {
    case "email": return &EmailNotification{}
    case "sms":   return &SMSNotification{}
    }
    return nil
}

// 建造者
type QueryBuilder struct { query Query }
func (b *QueryBuilder) Table(name string) *QueryBuilder {
    b.query.table = name; return b
}
func (b *QueryBuilder) Select(fields ...string) *QueryBuilder {
    b.query.fields = fields; return b
}
func (b *QueryBuilder) Build() Query { return b.query }

// 装饰器链
type Handler func(req string) string
func Logger(h Handler) Handler {
    return func(req string) string {
        resp := h(req); return resp
    }
}

// 观察者
type Subject struct {
    observers []Observer
    mu       sync.RWMutex
}
func (s *Subject) Notify(e Event) {
    s.mu.RLock(); obs := append([]Observer{}, s.observers...)
    s.mu.RUnlock()
    for _, o := range obs { o.OnEvent(e) }
}
```

## 惯用 Go 模式小结

| 原则 | 实现方式 | 解决的问题 |
|------|----------|----------|
| 组合优于继承 | 嵌套结构体 + 接口 | 类型层次脆弱性 |
| 接口优于抽象类 | 小接口（`io.Reader`） | 隐式实现解耦 |
| 函数优于类 | 高阶函数装饰器 | 行为组合灵活性 |
| 显式依赖注入 | 构造函数传参 | 测试可替换性 |
| 零依赖单例 | `sync.Once` | 初始化竞争 |
