# 文件操作

## 定义

文件操作是通过 OS 系统调用实现字节序列的持久化读写，Go 将其封装为 `os` 包与 `bufio` 缓冲层，前者处理原子系统调用，后者通过减少系统调用次数提升吞吐。

文件操作的本质是**字节流的持久化抽象**：应用程序通过文件描述符（整数句柄）向操作系统请求 I/O，数据从用户空间穿越内核缓冲区最终到达存储介质。

## 数学模型

### 系统调用次数模型

设文件大小为 $N$ 字节，缓冲区大小为 $B$ 字节：

- **无缓冲**（`os.Open`+`Read`）：调用次数 $= \lceil N / B \rceil$，每次 `read` 系统调用有固定开销 $C_{syscall}$
- **有缓冲**（`bufio.Reader`）：系统调用次数 $= \lceil N / B \rceil$，但 $B$ 增大 1000 倍（如 4KB → 4MB），调用次数降低 1000 倍

总时间：$T_{无缓冲} = \lceil N/B_{default} \rceil \times C_{syscall}$

$T_{有缓冲} = \lceil N/B_{large} \rceil \times C_{syscall} + N \times C_{copy}$

其中 $C_{copy}$ 是内核到用户的内存复制成本，通常比 $C_{syscall}$ 小 2 个数量级。

**归约终点**：缓冲 I/O 的本质是将 $N/B_{default}$ 次小开销 syscall 重排列为 $N/B_{large}$ 次大开销 syscall + $N$ 次 memcpy，由于 $C_{syscall} \gg C_{copy}$，总时间显著降低。

### 原子写入的数学保证

`os.WriteFile` 的原子性由内核的 **rename 系统调用**保证：

1. 写入临时文件 $f_{tmp}$：数据落盘（由 OS 决定何时 flush）
2. 调用 `rename(f_{tmp}, f_{target})$：这是原子文件系统操作（目录条目更新的原子性由文件系统保证）
3. 若写入过半时崩溃，原文件不受影响；若 rename 执行中崩溃，目录更新是原子性的（要么全有要么全无）

**原子性的形式化定义**：设文件内容为函数 $f: [0, L) \rightarrow \Sigma^*$，原子写入保证要么 $f = f_{old}$，要么 $f = f_{new}$，不存在中间状态。

**归约终点**：原子写入的代价归结为**两次文件系统操作**（写临时文件 + rename），而非单次原地写入。这避免了原地写入时崩溃导致文件损坏的风险。

### mmap 的数学本质

内存映射文件将磁盘块直接映射到进程虚拟地址空间：

$$T_{mmap} = T_{page\_fault} + N_{pages} \times T_{disk\_read}$$

其中 $N_{pages} = \lceil N / page\_size \rceil$。首次访问触发 page fault，之后是线性磁盘读取。

**page fault 开销分布**：首次访问时，$T_{page\_fault}$ 包含：
1. MMU 遍历页表（$O(1)$ 因 TLB）
2. 若 TLB miss，页表步行 $O(log\_2 PT\_size)$
3. 若页不在内存，触发磁盘 I/O（$T_{disk\_read} \approx 10ms$）

**约束**：mmap 适合大文件顺序访问，随机访问会导致频繁 page fault，开销反而高于缓冲 I/O。

## 数据流

### os.ReadFile 数据流

<pre>
磁盘页缓存（内核）
     │
     │ read(4KB) × N次
     ▼
用户空间 []byte
     │
     │ os.ReadFile = io.ReadAll
     ▼
返回完整文件内容
特点：无中间缓冲，整文件一次性加载
</pre>

**数据形态变换**：
- 磁盘 → 内核页缓存（操作系统管理）
- 内核页缓存 → 用户空间（一次 copy 系统调用）
- 用户空间 buffer → 调用者（内存直接传递）

### bufio.Reader 数据流

<pre>
磁盘
  │
  │ read(4KB syscall)
  ▼
内核页缓存
  │
  │ read(4KB syscall)
  ▼
bufio.Reader 缓冲区（默认 4KB）
  │
  │ 应用多次 Read()/Scan()
  ▼
用户空间
特点：减少 syscall 次数（N次 → N/1000次）
</pre>

**所有权流转**：
- 内核持有数据直到用户空间完成拷贝
- 用户空间 buffer 持有数据直到调用者处理完毕
- 缓冲区复用时所有权不跨调用保留

### 写操作原子性数据流

<pre>
应用程序
    │
    │ Write(data) → 临时文件
    ▼
临时文件 (.tmp 文件)
    │
    │ rename(tmp, target) 原子操作
    ▼
目标文件
特点：写入过程对目标文件不可见，只有 rename 完成瞬间可见
</pre>

**文件系统语义的物理保证**：
- ext4：`rename()` 在单个 inode 操作内完成目录条目更新
- NFS：语义弱化，取决于服务器实现的一致性模型
- FAT：不保证原子 rename

## 机制

### os.ReadFile vs bufio.Reader 的选择约束

**os.ReadFile 适用场景**：
- 文件 < 100MB（避免一次性加载占用过多内存）
- 需要完整内容后处理（如 JSON 解析整个配置）
- 简单一次性读取

**bufio.Reader 适用场景**：
- 大文件或流式数据（如日志文件行处理）
- 按行/按令牌处理，无需一次性加载
- 需要高吞吐量（减少 syscall 开销）

**违反约束后果**：
- 对大文件使用 `os.ReadFile` 可能导致内存压力 OOM
- 对需要多次扫描的文件使用无缓冲 I/O，CPU 时间浪费在 syscall 上

### bufio 缓冲区大小的工程权衡

默认 4KB 匹配 Linux 页缓存行大小。若文件 I/O 是随机访问（如数据库），增大缓冲区不显著提升性能；若是顺序扫描，缓冲区越大越好。

`bufio.Scanner` 默认令牌限制 64KB，若单行超过此值会报 `bufio.Scanner: token too long` 错误，需要手动 `scanner.Buffer()` 扩容。

**缓冲区过大的副作用**：
- 内存占用增加（每个 bufio.Reader 持有独立缓冲区）
- 首次 I/O 延迟增加（需填充整个缓冲区）
- 缓存污染（热点数据可能被不热点数据挤出）

### 文件描述符资源约束

每个 `os.Open` 返回一个文件描述符，是受限资源：
- Linux 默认 ulimit -n = 1024
- 大量并发文件操作需注意及时 `Close()`，否则泄漏文件描述符
- 连接池模式（如数据库连接）复用连接，文件操作无连接池（每次独立 Open/Close）

**文件描述符泄漏的数学描述**：
设打开速率 $R_{open}$（每秒 Open 数），关闭速率 $R_{close}$（每秒 Close 数），最大 fd 数 $F_{max}$：

- 稳态条件：$R_{close} \geq R_{open}$
- 泄漏条件：$\int_0^t (R_{open} - R_{close}) dt > F_{max}$ → 耗尽

### 直接 I/O 的绕过缓冲层

Linux 支持 O_DIRECT 标志绕过页缓存：

$$T_{direct\_io} = N_{syscalls} \times (C_{syscall} + T_{disk\_read})$$

绕过缓存避免了 "double copy"（磁盘→内核缓存→用户空间），但失去缓存收益。适用于：
- 数据库的预写日志（WAL）
- 大数据处理的一次性读取

## 参考存根

```go
// 完整文件读取（os.ReadFile）
data, err := os.ReadFile("file.txt")
if err != nil {
    log.Fatal(err)
}

// 原子写入
func atomicWrite(path string, data []byte) error {
    tmp, err := os.CreateTemp("", "atomic-*")
    if err != nil {
        return err
    }
    defer os.Remove(tmp.Name())
    if _, err := tmp.Write(data); err != nil {
        tmp.Close()
        return err
    }
    if err := tmp.Close(); err != nil {
        return err
    }
    return os.Rename(tmp.Name(), path)
}

// bufio.Scanner 行读取
file, _ := os.Open("large.log")
scanner := bufio.NewScanner(file)
for scanner.Scan() {
    line := scanner.Text()
    // 处理每一行
}

// mmap 随机访问
func mmapRead(path string, offset int64, length int) ([]byte, error) {
    f, err := os.Open(path)
    if err != nil {
        return nil, err
    }
    defer f.Close()

    f.Stat()
    data, err := syscall.Mmap(int(f.Fd()), offset, length, syscall.PROT_READ, syscall.MAP_PRIVATE)
    if err != nil {
        return nil, err
    }
    return data, nil
}
```

## 场景选择决策树

```
文件大小 < 100MB 且一次性读写?
├─ 是 → os.ReadFile / os.WriteFile
└─ 否 → 需要流式处理（按行/按令牌）?
       ├─ 是 → bufio.Reader / bufio.Writer
       └─ 否 → 需要随机访问?
              ├─ 是 → os.Open + bufio.Reader
              └─ 否 → mmap 或分片处理
```
