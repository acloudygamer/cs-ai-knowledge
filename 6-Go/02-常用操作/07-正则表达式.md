# 正则表达式

## 定义

正则表达式是通过 RE2 语法（Go 标准库 `regexp` 唯一支持）描述字符串匹配模式的有限状态自动机，其核心特性是**线性时间复杂度**——匹配过程无需回溯。

正则表达式的本质是**模式匹配的形式化语言**：通过正则语法描述字符序列的集合，引擎将其编译为有限状态自动机（DFA）进行匹配。

## 数学模型

### 复杂度分析

RE2 的时间复杂度：**$T(n) = O(n)$**，空间复杂度：**$S(n) = O(1)$**

其中 $n$ 为输入字符串长度。空间 $O(1)$ 是因为编译后的正则程序大小与输入无关。

**对比 PCRE/Perl 正则**：
- 支持回溯的引擎最坏情况 $T(n) = O(2^n)$
- 典型场景（如 `(a+)+b` 匹配 `"aaaa...a"` 无尾随 b）可导致指数级爆炸

### RE2 的形式语言层次

RE2 是**确定型有限状态自动机（DFA）**的子集：

- 正则表达式 → NFA（Thompson 构造）
- NFA → DFA（幂集构造）
- DFA 执行 → 线性扫描

RE2 不支持：
- 环视断言 `(?=)`、`(?!)`、`(?<=)`、`(?<!)`
- 捕获环视 `(?>...)`（原子分组）
- 递归正则

这些特性会导致非确定性，需要回溯支持。

**归约终点**：正则引擎的核心是**确定型有限状态自动机**，其识别能力被限制在正则语言集合（Chomsky 3 型文法），这是其可预测性能的本质来源。

### 贪婪匹配 vs 惰性匹配的数学本质

正则引擎的匹配策略：

**贪婪匹配**（Greedy）：优先匹配最多字符
- 策略：回溯尝试，从最长到最短
- 时间复杂度： $O(n \times m)$ ，其中 $m$ 为模式长度

**惰性匹配**（Lazy）：优先匹配最少字符
- 策略：逐步扩展，从最短到最长
- 时间复杂度： $O(n \times m)$

**注意**：RE2 本身不支持贪婪/惰性量词的回溯，但其实现中若使用 NFA 模拟，贪婪通过选择最长分支实现。

### 正则语言的 Chomsky 层次

| 层次 | 生成式规则 | 对应自动机 | 正则表达能力 |
|------|-----------|-----------|-------------|
| Type-3 (正则文法) | $A \rightarrow a$, $A \rightarrow aB$ | DFA/NFA | 有限状态模式 |
| Type-2 (上下文无关) | $A \rightarrow \alpha$ | PDA | 括号匹配、嵌套结构 |
| Type-1 (上下文敏感) | $\alpha A \beta \rightarrow \alpha \gamma \beta$ | LBA | 某些上下文依赖 |
| Type-0 (无限制) | $\alpha \rightarrow \beta$ | 图灵机 | 任意可计算模式 |

RE2 的表达能力限制在 Type-3（正则语言），这是其线性时间复杂度的理论保证。

## 数据流

### 正则编译与执行

<pre>
正则表达式字符串
        │
        │ regexp.MustCompile
        ▼
Regexp 对象（编译后的 DFA）
        │
        │ MatchString/Find/Replace
        ▼
输入字符串
        │
        │ 线性扫描
        ▼
匹配结果
</pre>

**数据形态变换**：
- 正则字符串 → 编译后的 DFA（静态，只编译一次）
- 输入字符串 → 匹配结果（动态，每次扫描）

### 回溯陷阱示意

<pre>
模式 `(a+)+b` 匹配 "aaaa...a"（无尾随 b）：

传统正则引擎（PCRE）:
├─ 尝试 a+ 匹配全部
├─ 再尝试 +（失败）
├─ 回溯，a+ 匹配部分
├─ 再尝试 +（失败）
├─ 继续回溯...
└─ 指数级尝试 → 指数级时间

RE2:
├─ 线性扫描 a
├─ 无回溯，继续匹配 +
├─ 匹配失败 → 返回不匹配
└─ O(n) 时间
</pre>

### 捕获组编号规则

<pre>
模式: `(?P<year>\d{4})-(?P<month>\d{2})`
输入: "2024-01"

匹配结果:
┌─────────────────────────────────────┐
│ 组0（整体）: "2024-01"             │
│ 组1（year）: "2024"                │
│ 组2（month）: "01"                │
└─────────────────────────────────────┘

编号规则：按左括号出现顺序，从外到内依次编号
</pre>

## 机制

### RE2 约束的工程意义

RE2 放弃回溯换来**可预测的性能**：

- **无正则表达式注入攻击**：ReDoS（正则表达式拒绝服务）利用回溯爆炸，RE2 免疫
- **可缓存**：同一正则编译一次，结果可安全并发使用
- **无指数级最坏情况**：适合用户输入驱动的匹配场景

**代价**：
- 环视断言需要用代码替代
- 不支持命名捕获组的某些高级用法

### 捕获组与命名分组

捕获组用于**提取匹配的子串**：

```go
re := regexp.MustCompile(`(\w+)@(\w+)\.(\w+)`)
m := re.FindStringSubmatch("user@example.com")
// m[0] = "user@example.com"
// m[1] = "user"
// m[2] = "example"
// m[3] = "com"
```

命名分组是编号分组的别名：

```go
re := regexp.MustCompile(`(?P<year>\d{4})-(?P<month>\d{2})`)
m := re.FindStringSubmatchIndex("2024-01")
re.SubexpIndex("year")  // 1
m[re.SubexpIndex("year"):re.SubexpIndex("year")+2]  // 提取位置
```

### 预编译的必要性与边界

**必须预编译**：
- 包初始化时编译正则
- 全局变量存储编译后的 `Regexp`
- 避免在热路径中重复编译

**重复编译的开销**：
- 每次 `MustCompile` 重新解析正则 → 重新编译为 DFA
- 对于复杂正则，编译时间可能超过匹配时间

```go
// 预编译（正确）
var emailRegex = regexp.MustCompile(`^[a-z]+@[a-z]+\.[a-z]+$`)

// 循环内编译（错误）
for _, s := range inputs {
    re := regexp.MustCompile(pattern)  // 每轮重新编译
}
```

### lookbehind 的替代方案

RE2 不支持 `(?<=prefix)` 后顾断言。若需要"前缀匹配后取后缀"：

**方法1：strings.HasPrefix**
```go
if strings.HasPrefix(s, "prefix") {
    suffix := s[6:]  // 截取后缀
}
```

**方法2：正则匹配后取子串**
```go
re := regexp.MustCompile(`^prefix(.*)`)
m := re.FindStringSubmatch(s)
if m != nil {
    suffix := m[1]
}
```

**性能差异**：`strings.HasPrefix` 是 O(1) 内存、O(n) 时间，比正则快 10-100 倍。

### 锚点优化

`^` 和 `$` 锚点允许引擎快速跳过不匹配位置：

| 模式 | 优化效果 |
|------|---------|
| `^abc` | 从字符串开头匹配，失败时跳过整个字符串 |
| `abc$` | 从字符串末尾向前匹配 |
| 无锚点 | 需扫描每个位置尝试匹配 |

## 参考存根

```go
// 预编译与匹配
var emailRegex = regexp.MustCompile(`^[a-z]+@[a-z]+\.[a-z]+$`)
emailRegex.MatchString("user@example.com")  // true

// 查找匹配
re := regexp.MustCompile(`(\w+)@(\w+)\.(\w+)`)
m := re.FindStringSubmatch("user@example.com")
// m = ["user@example.com" "user" "example" "com"]
m[1]  // "user"

// 命名分组
re := regexp.MustCompile(`(?P<year>\d{4})-(?P<month>\d{2})`)
m := re.FindStringSubmatchIndex("2024-01")
yearIdx := re.SubexpIndex("year")
year := s[m[yearIdx]:m[yearIdx+2]]  // "2024"

// 替换
re := regexp.MustCompile(`(\w+)@(\w+)\.(\w+)`)
result := re.ReplaceAllString("user@example.com", "$1 at $2 dot $3")
// "user at example dot com"

// 分割
re := regexp.MustCompile(`\s*,\s*`)
parts := re.Split("a, b, c", -1)
// ["a", "b", "c"]
```

## 性能最佳实践

| 实践 | 原因 |
|------|------|
| 预编译 `MustCompile` 包级变量 | 避免重复编译开销 |
| 锚定开头 `^pattern` | 允许引擎快速跳过不匹配位置 |
| 具体化分支 `a{2,5}` vs `a*` | 减少可选分支 |
| 非捕获 `(?:...)` vs `(...)` | 减少捕获开销 |
| 避免分组捕获（不需提取时） | 减少内存分配 |
| 使用 `strings` 替代正则 | 简单模式无需正则开销 |
