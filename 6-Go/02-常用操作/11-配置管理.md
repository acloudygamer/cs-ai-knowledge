# 配置管理

**定义**：配置管理是将程序行为参数与代码分离的过程，核心问题是**加载优先级**（命令行 > 环境变量 > 代码默认值 > 配置文件）和**热重载**（变更时无需重启进程）。

## Viper 配置优先级

### 定义断言
Viper 的配置来源按优先级从高到低：命令行 flags > 环境变量 > 配置文件 > 代码默认值。`AutomaticEnv()` 和 `SetEnvKeyReplacer` 使环境变量渗透到嵌套配置键。

### 数据流

<pre>
viper.Set("database.host", "override")  ← 优先级 3（代码）
                  ↑
APP_DATABASE_HOST=localhost             ← 优先级 2（环境变量，SetEnvKeyReplacer 映射）
                  ↑
config.yaml: database.host: file-host   ← 优先级 1（配置文件）
                  ↑
Set("database.host", "default")         ← 优先级 0（默认值）
</pre>

### 机制解释
`SetEnvKeyReplacer` 将嵌套键的 `.` 替换为 `_`：配置键 `database.host` 对应环境变量 `APP_DATABASE_HOST`。这是因为许多 shell 不支持点号变量名。

## 配置文件格式选择

| 格式 | 适用场景 | 优势 | 劣势 |
|------|---------|------|------|
| JSON | 跨语言配置 | 原生解析 | 不支持注释 |
| YAML | 配置文件 | 支持注释、嵌套 | 空格缩进敏感 |
| TOML | 配置文件 | 语义清晰 | 新格式、工具支持少 |
| ENV | 运行时覆盖 | docker/k8s 原生 | 不支持嵌套 |

## 热重载机制

### 定义断言
Viper 的 `WatchConfig()` 依赖 `fsnotify` 监听文件系统事件，变化时触发回调。但热重载的**可见性**需要程序主动查询——Viper 不自动更新内存中的值，需在回调中重新 `Unmarshal`。

### 参考存 stub

```go
viper.WatchConfig()
viper.OnConfigChange(func(e fsnotify.Event) {
    viper.Unmarshal(&cfg) // 重新加载到结构体
})
```

## 敏感配置

### 定义断言
密码、密钥等敏感配置**绝不**写入配置文件或日志。正确做法：运行时从环境变量或密钥管理服务（Vault/KMS）获取，内存中用后即清除。

### 参考存 stub

```go
type SafeConfig struct {
    Password string `json:"-"`
}
```
