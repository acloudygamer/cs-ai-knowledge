# 网络请求

## 定义

网络请求是客户端通过协议（HTTP/1.1、HTTP/2、gRPC）向服务端发起的数据交换，Go 标准库 `net/http` 提供基础实现，第三方库在其上提供更高层抽象。

网络请求的本质是**可靠字节流的有序交换**：TCP 保证有序可靠交付，应用层协议（HTTP）在其上定义请求-响应语义。

## 数学模型

### 连接建立延迟

$$T_{conn} = T_{DNS} + T_{TCP\_handshake} + T_{TLS\_handshake}$$

典型值（内网 1ms，广域网 50-100ms）：

| 阶段 | 内网 | 广域网 |
|------|------|--------|
| DNS | 0.1ms | 5-20ms |
| TCP握手 | 0.5ms | 20-30ms |
| TLS握手 | 1ms | 30-50ms |
| **总计** | **~2ms** | **~100ms** |

### HTTP/1.1 keep-alive 连接复用

$$T_{total} = N \times T_{conn} + N \times T_{request}$$

若连接复用，复用后 $T_{total} = T_{conn} + N \times T_{request}$

**节省比例**：$(N-1) \times T_{conn} / (T_{conn} + N \times T_{request})$

当 $T_{conn}$ 远大于 $T_{request}$（高延迟网络、大请求量），复用收益显著。

### HTTP/2 多路复用的并行增益

设单请求处理时间为 $T_{req}$，HTTP/1.1 串行执行 $N$ 个请求：

$$T_{HTTP/1.1} = N \times T_{req} + (N-1) \times T_{conn}$$

HTTP/2 多路复用下，$N$ 个请求时间重叠：

$$T_{HTTP/2} = T_{conn} + \max(T_{req,1}, T_{req,2}, \dots, T_{req,N})$$

**加速比**：

$$S = \frac{T_{HTTP/1.1}}{T_{HTTP/2}} \approx \frac{N \times T_{req}}{T_{req}} = N \quad (T_{req} \gg T_{conn})$$

理论上加速比可达 $N$，实际受 TCP 拥塞窗口限制。

**队首阻塞的残余**：HTTP/2 在 TCP 层仍受队首阻塞影响——TCP 保证有序交付，一个丢包会阻塞所有 stream。HTTP/3 (QUIC) 通过 UDP + stream 级别重传解决此问题：QUIC 的每个 stream 独立重传，丢包只影响该 stream，其他 stream 不受影响。

### 连接池容量模型

设目标主机数为 $H$，每主机空闲连接上限为 $M$：

- 总连接数上限：$H \times M$
- 若 $M$ 过小：高并发时大量连接重建，$T_{conn}$ 开销占比高
- 若 $M$ 过大：文件描述符资源浪费，高并发下可能耗尽 ulimit

**归约终点**：连接池的参数空间可归结为 $(H, M, T_{idle}, T_{conn})$ 四元组，其中 $T_{idle}$ 决定连接存活时间。

### 重试与退避的收敛性

网络请求失败时，指数退避是标准重试策略：

$$delay = min(base \times 2^{attempt}, max\_backoff)$$

- 基础延迟：通常 100ms-1s
- 最大延迟：通常 30s-60s
- 抖动（jitter）：$\pm 20\%$ 随机化，分散重试时间

**退避的数学本质**：指数退避将重试间隔的增长率从线性 $O(n)$ 压到对数 $O(\log n)$，避免在高负载下加剧拥塞。

## 数据流

### HTTP/1.1 keep-alive 连接复用

<pre>
请求1 ──┐
        │
请求2 ──┼──► TCP连接(keep-alive) ──► Server
        │     ↑ 连接池复用
请求3 ──┘     │
              │ 新请求时从池取空闲连接
              │ 若池空则新建
              │ 若池满则关闭
              ▼
         IdleConnQueue
</pre>

**连接生命周期状态机**：
```
空闲（Idle）→ 被取出（InUse）→ 请求完成 → 归还池（Idle）
                                        ↓
                                    超时关闭（Closed）
```

### HTTP/2 多路复用

<pre>
Stream 1 ─┐
           ├──► 单TCP连接 ──► Server
Stream 2 ─┤        ↑
           │     帧交错复用
Stream 3 ─┘        │
              无头阻塞（HOL blocking优化）
</pre>

**数据形态变换**：
- 应用层消息 → HTTP/2 帧（HEADERS/DATA）
- 帧交织写入同一 TCP 字节流
- 接收端根据 Stream ID 重组

### 请求体消费

<pre>
resp.Body (io.ReadCloser)
        │
        │ 第一次 Read() → 消耗数据
        ▼
    EOF 后不可再读
        │
        │ 若需多次读取
        ▼
    io.ReadAll(resp.Body) → 缓存到内存
        │
        ▼
    data []byte 可重复使用
</pre>

### HTTP/2 帧结构

<pre>
+---------------------------------------------------+
| Length (24 bits) | Type (8) | Flags (8) | Stream   |
|                  |          |          | ID (32)  |
+---------------------------------------------------+
|                  Frame Payload                    |
+---------------------------------------------------+

Type: 0x0=DATA, 0x1=HEADERS, 0x3=SETTINGS, etc.
Flags: END_STREAM, END_HEADERS, etc.
</pre>

**帧复用开销**：切换成本仅为解析 9 字节帧头的 O(1) 操作。

## 机制

### http.Client 的连接池管理

`http.Client` 的 Transport 层管理连接池：

- **MaxIdleConnsPerHost**：每个目标主机的最大空闲连接数，默认 2
- **IdleConnTimeout**：空闲连接存活时间，默认 90 秒
- **MaxConnsPerHost**：最大并发连接数（Go 1.26+）

连接状态机：
1. 请求到达 → 检查池中是否有空闲连接
2. 有 → 取出复用
3. 无且未达上限 → 新建连接
4. 无且已达上限 → 等待（阻塞）或失败（视配置）

**违反约束**：若忘记读取 resp.Body 或未调用 Close()，连接不会被释放回池，造成连接泄漏。

### fasthttp vs net/http 的设计权衡

| 维度 | net/http | fasthttp |
|------|----------|----------|
| 架构 | 基于标准库 net.Listen/conn | 自定义用户态网络栈 |
| goroutine 模型 | 每请求一个 goroutine | 单连接多请求复用 |
| 内存分配 | 每次请求分配 | 对象池复用 |
| HTTP/2 | 原生支持 | 不支持 |
| 适用场景 | 通用场景 | 高并发短连接 |

**fasthttp 的关键约束**：
- 不兼容标准 `http.Handler` 接口，需要迁移
- 不支持 HTTP/2 和 WebSocket
- 适合场景：代理服务器、高性能 API 网关

### 重试的幂等性约束

**什么请求可以重试**：
- GET、HEAD、PUT、DELETE：幂等，可安全重试
- POST、PATCH：非幂等，重试可能导致重复操作

**安全重试的条件**：
1. 请求具备幂等性（读取/删除/无副作用的更新）
2. 响应在处理前失败（服务器未收到请求）
3. 实现了幂等键（Idempotency-Key header）

### 超时控制的层次

```
Dialer.Timeout          // TCP 连接建立超时
Transport.ResponseHeaderTimeout // 读取响应头超时
Transport.TLSHandshakeTimeout  // TLS 握手超时
Client.Timeout                  // 整体请求超时（含 body）
```

**Timeout vs Deadline**：
- `Timeout`：相对时间，从请求开始计时
- `Deadline`：绝对时间点，绝对截止时刻

## 参考存根

```go
// 标准库 GET（正确顺序：先检查 err，再 defer 清理）
resp, err := http.Get("https://example.com")
if err != nil {
    log.Fatal(err)
}
defer resp.Body.Close()  // resp 非 nil 才执行此处
io.Copy(os.Stdout, resp.Body)

// 自定义连接池
tr := &http.Transport{
    MaxIdleConnsPerHost: 100,
    IdleConnTimeout: 90 * time.Second,
    ForceAttemptHTTP2: true,
}
client := &http.Client{Transport: tr}

// 多次读取响应体
func readMultipleTimes(resp *http.Response) ([][]byte, error) {
    data, err := io.ReadAll(resp.Body)
    if err != nil {
        return nil, err
    }
    // data 现在可以多次使用
    return [][]byte{data, data}, nil
}

// 指数退避重试
func withRetry(ctx context.Context, req *http.Request) (*http.Response, error) {
    baseDelay := 100 * time.Millisecond
    maxDelay := 30 * time.Second

    for attempt := 0; attempt < 3; attempt++ {
        resp, err := http.DefaultClient.Do(req)
        if err == nil {
            return resp, nil
        }
        if attempt == 2 {
            return nil, err
        }
        delay := baseDelay * time.Duration(1<<attempt)
        if delay > maxDelay {
            delay = maxDelay
        }
        time.Sleep(delay)
    }
    return nil, nil
}

// HTTP/2 多路复用示例
func http2Client() {
    tr := &http.Transport{
        ForceAttemptHTTP2: true,
    }
    client := &http.Client{Transport: tr}

    // 并发发起多个请求，复用同一连接
    var wg sync.WaitGroup
    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            resp, _ := client.Get("https://example.com/api/" + strconv.Itoa(id))
            if resp != nil {
                defer resp.Body.Close()
            }
        }(i)
    }
    wg.Wait()
}
```
