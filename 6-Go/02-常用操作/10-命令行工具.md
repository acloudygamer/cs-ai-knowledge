# 命令行工具

## 定义

命令行工具是程序通过 `flag`（标准库）解析用户输入的参数并执行业务逻辑的交互模式，核心问题是**参数验证**和**子命令树管理**（cobra）。

## flag 解析机制

### 定义
`flag.Parse()` 在调用时扫描 `os.Args[1:]`，将字符串形式的参数转换为对应类型的值并存入已注册变量。它必须在所有 flag 注册完成后调用，且只能调用一次。

### 数学模型

**参数解析状态机**：
- 状态空间 $S = \{正常, 已见flag, 已见位置参数\}$
- 初始状态 $s_0 = 正常$
- 转换函数 $T(s, token)$：
  - 若 token 以 `-` 开头且不是 `--`：$T(正常, token) = 已见flag$
  - 若 token == `--`：$T(已见flag, \text{--}) = 已见位置参数$
  - 否则：$T(*, token) = 已见位置参数$

**约束**：一旦开始处理位置参数（遇到非 flag 参数），后续所有参数都视为位置参数，即使以 `-` 开头。

**归约终点**：flag 解析是有限状态自动机，状态数有限，转换函数确定。

### 数据流

<pre>
os.Args[1:]: ["./app", "-port", "8080", "-v", "arg1"]

Token 0: "./app"        → 程序名，跳过
Token 1: "-port"        → 识别为 flag，查找 "port" 注册项
  ├─ 存在：尝试将下一 token "8080" 解析为 int
  ├─ 成功：存入 &portVar
  └─ 失败：panic / 退出
Token 2: "8080"         → 已作为 -port 的值处理
Token 3: "-v"           → 识别为 flag，查找 "v" 注册项
  └─ 存入 vVar = true
Token 4: "arg1"         → 不以 - 开头，存入位置参数列表

最终：
  portVar = 8080
  vVar = true
  positional = ["arg1"]
</pre>

### 机制

**为什么 flag.Parse() 只能调用一次**：解析过程中 flag 包维护内部状态（当前处理的 token 索引、已解析的 flag 集合）。多次调用会导致状态不一致，且 `os.Args` 不会重置。

**自定义类型 flag 的约束**：实现 `flag.Value` 接口时，`Set(string) error` 必须是可多次调用的——同一 flag 可以在命令行出现多次（如 `-v -v -v` 表示计数），每次调用 `Set` 追加而非替换。

### 自定义类型 flag

```go
// 实现 flag.Value 接口
type ipVal struct { val *net.IP }

func (i *ipVal) Set(s string) error {
    *i.val = net.ParseIP(s)
    return nil
}
func (i *ipVal) String() string { return i.val.String() }

var ip net.IP
flag.Var(&ipVal{&ip}, "server", "server IP")
flag.Parse()
```

### 参考存根

```go
var server string
flag.StringVar(&server, "server", "127.0.0.1", "server IP")

var port int
flag.IntVar(&port, "port", 8080, "server port")

flag.Parse()

fmt.Printf("server=%s, port=%d, args=%v\n", server, port, flag.Args())
```

## os/exec 安全

### 定义
`exec.Command` 的参数是**列表形式**（`exec.Command("ls", "-la")`），而非 shell 字符串（`exec.Command("ls -la")`）。后者会将整个字符串传给 shell，导致 shell 注入攻击。

### 数学模型

**注入攻击的数学本质**：令用户输入为 $U$，shell 命令构造为 $C(U) = "command " + U$。当 $U$ 包含 shell 元字符（如 `;`, `|`, `&`, `$()`）时，$C(U)$ 的语义发生变化。

**安全条件**：若参数以列表形式传递，shell 元字符不会被解释，$C(U)$ 的语义始终是 "执行 command，参数为 U 的字面值"。

### 数据流

<pre>
不安全方式：
  exec.Command("sh", "-c", "ls -la "+filename)
       │
       └── 传递给 sh 进程
            │
            └── filename = "a; rm -rf /" → sh 解析为两条命令

安全方式：
  exec.Command("ls", "-la", filename)
       │
       └── 直接 execve("ls", ["-la", "a; rm -rf /"])
            │
            └── ls 接收到的是字面值参数，; 等元字符无意义
</pre>

### 机制

**为什么不直接禁止 shell**：某些合法场景需要 shell 功能（管道、glob、重定向）。正确的做法是**显式启用**（通过 `exec.Command("sh", "-c", ...)`），而非隐式 shell 解释。

**最小特权原则**：程序不应承担不必要的 shell 解释能力。若只需执行单一命令，直接传递路径和参数是最小权限。

### 参考存根

```go
// 安全：参数分开
exec.Command("ls", "-la", filename)

// 安全但过度授权：启用 shell
exec.Command("sh", "-c", "ls -la "+filename)

// 安全：参数显式列表
exec.Command("sh", "-c", "ls -la $1", filename) // filename 作为 $1 传入
```

## cobra 命令树结构

### 定义
Cobra 命令树是**前缀树（Trie）**：每个 `Command` 可有 `Run` 或 `RunE` 回调和子命令 `AddCommand`。执行 `myapp serve api --port 8080` 时，前缀树从根向下匹配 `serve` → `api` → 到达目标命令。

### 数学模型

**Trie 匹配复杂度**：设命令路径深度为 $D$，命令查找时间 $T_{lookup} = O(D)$，与命令总数无关。这使大型 CLI 的子命令查找保持常数时间。

**参数绑定**：Cobra 使用反射将 flag 值绑定到 `RunE` 函数的参数上，绑定发生在 `cmd.ParseFlags(args)` 之后。

### 数据流

<pre>
输入：myapp serve api --port 8080

匹配过程：
  root.Children["serve"] → Command{RunE: serveAPI}
        │
        └─ serve.AddCommand(apiCmd)
              │
              └─ apiCmd.RunE(ctx, args)
                    │
                    └─ args = ["--port", "8080"]
                          │
                          └─ apiCmd.ParseFlags(args)
                                │
                                └─ bind to &port variable
                                    │
                                    └─ execute business logic

命令树结构（内存）：
  root
  └── serve (Command)
      └── api (Command)
          └── RunE: func(ctx context.Context, args []string) error
</pre>

### 机制

**为什么用 Trie 而非哈希表**：子命令需要支持前缀匹配（`myapp serve` 可以简写为 `myapp ser` 若无歧义）。哈希表无法处理歧义消解，Trie 通过最长前缀匹配自然支持命令补全和歧义检测。

**cobra 的 flag 继承**：子命令的 flag 会遮蔽父命令的同名 flag。这允许全局 flag（如 `--verbose`）在子命令中局部覆盖。

**PreRunE / PostRunE 链**：命令执行前后的钩子形成链式调用，从根命令到叶命令依次执行，用于统一的参数验证和日志记录。

## flag vs cobra 选择

| 场景 | 推荐 | 原因 |
|------|------|------|
| 单脚本工具、无子命令 | `flag` | 无依赖，零额外代码 |
| 需要子命令树（git-like） | `cobra` | 内置 Trie、flag 继承、帮助生成 |
| 复合场景 | `flag` 处理叶命令参数 + `cobra` 组织命令树 | 各取所长 |

### 参考存根

```go
// 最小 cobra 应用
package main

import (
    "github.com/spf13/cobra"
)

func main() {
    root := &cobra.Command{Use: "myapp", Short: "A CLI tool"}
    root.AddCommand(&cobra.Command{
        Use: "serve",
        RunE: func(cmd *cobra.Command, args []string) error {
            port, _ := cmd.Flags().GetInt("port")
            return serve(port)
        },
    })
    root.Execute()
}

func serve(port int) error { /* ... */ return nil }
```
