# 认证授权

**定义**：认证（Authentication）是证明"你是谁"的过程（`authn`），授权（Authorization）是决定"你能做什么"的过程（`authz`）。JWT 是认证结果的令牌格式，RBAC 是基于角色的授权模型，两者解决不同问题。

## JWT 签名验证流程

### 定义断言
JWT 的安全性基于**签名而非加密**——任何人都能解码 Header 和 Payload（Base64），但无法伪造有效签名。`HS256` 签名是 HMAC-SHA256，密钥泄漏等同于令牌伪造。

### 数据流

<pre>
签发：
payload（JSON）→ Base64URL(Header) + "." + Base64URL(Payload)
                                    ↓
                            用密钥做 HMAC-SHA256
                                    ↓
                           Signature = Base64URL(HMAC)
                                    ↓
                    Header.Payload.Signature（JWT 令牌）

验证：
收到 JWT → 分割三部分 → 用密钥重新计算 HMAC
                              ↓
                    与收到的 Signature 比较（恒定时间）
                              ↓
                    匹配 → 解析 Payload（Claims）
                    不匹配 → 拒绝（401）
</pre>

### 恒定时间比较原因
使用 `hmac.Equal` 而非 `==` 比较签名，防止时序攻击（Timing Attack）：攻击者通过测量响应时间猜测签名每一位的正确值。

## Access Token vs Refresh Token

### 定义断言
Access Token 是短期令牌（15min），泄露后影响窗口有限；Refresh Token 是长期令牌（7天），用于 Access Token 过期后获取新令牌，应存放在 HttpOnly Cookie 中防止 XSS 窃取。

### 关键约束
Refresh Token 应一次性使用（One-Time）—— 每次用 Refresh Token 换取新 Access Token 时，同时颁发新的 Refresh Token，旧 Token 立即作废。这防止 Refresh Token 被窃取后的持续滥用。

## RBAC vs ABAC

### 定义断言
RBAC（基于角色的访问控制）将权限归于角色，角色归于用户，适合权限层级相对固定的系统。ABAC（基于属性的访问控制）根据用户属性、资源属性、环境属性动态决策，适合细粒度、上下文相关的权限场景。

### RBAC 参考存 stub

```go
func (a *Authorizer) HasPermission(role Role, perm Permission) bool {
    perms := a.rolePermissions[role]
    for _, p := range perms { if p == perm { return true } }
    return false
}
```

## 密码存储

### 定义断言
密码必须使用 bcrypt（自适应哈希，Cost 参数控制计算时间，当前推荐 Cost=12）。MD5/SHA1/SHA256 不适合密码存储——它们设计为快速哈希，GPU 可在秒级完成数十亿次猜测。

### 参考存 stub

```go
hash, _ := bcrypt.GenerateFromPassword([]byte(pw), 12)
bcrypt.CompareHashAndPassword(hash, []byte(pw)) // 返回 nil 即匹配
```
