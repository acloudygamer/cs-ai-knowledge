# 数据库操作

**定义**：数据库操作是通过 DB-API 2.0 接口（`database/sql`）执行 SQL 语句并获取结果的过程，连接池管理由驱动层负责，应用层只需关注 SQL 构建和结果映射。

## 连接池核心机制

### 定义断言
`database/sql` 的连接池是按需创建的：请求到来时若池中有空闲连接则直接复用，没有则新建但不超过 `MaxOpenConns` 上限。连接生命周期由应用层通过 `SetConnMaxLifetime` 控制，而非驱动。

### 数据流（连接获取）

<pre>
Query/Exec 调用
        ↓
  有空闲连接？ ──是──→ 取出复用
        ↓否
  可新建连接？ ──是──→ 创建新连接
        ↓否
    等待（阻塞）直到超时或连接释放
</pre>

### 数学模型
连接泄漏检测：若 `db.Stats().OpenConnections` 持续接近 `MaxOpenConns` 且 `InUse` 等于 `OpenConnections`，则存在连接泄漏（未 Close）。

### SQL 注入防御

### 定义断言
Go 的 `?` 占位符使驱动自动进行 SQL 转义，切勿字符串拼接用户输入到 SQL 语句中。ORM（sqlx、GORM）底层同样使用占位符机制。

### 参考存 stub

```go
row := db.QueryRow("SELECT * FROM users WHERE id = ?", userID)
// 安全：userID 作为参数传递
```

## GORM vs sqlx vs 原生 database/sql

### 定义断言
`sqlx` 是 `database/sql` 的结构体映射扩展，保留原生 SQL 表达能力；`GORM` 是完整的 ORM，隐藏 SQL 并提供关联、迁移等功能；原生 `database/sql` 适合极致性能和控制权场景。

| 维度 | database/sql | sqlx | GORM |
|------|-------------|------|------|
| SQL 可见性 | 完整 | 完整 | 隐藏 |
| 学习曲线 | 低 | 低 | 中 |
| 性能开销 | 零 | 极低 | 低 |
| 迁移支持 | 无 | 无 | 原生 |
| 关联查询 | 手动 | 手动 | 自动 |

## Redis 分布式锁

### 定义断言
Redis 分布式锁的正确实现需要 `SET key value NX PX ttl` 原子命令 + 唯一值（UUID）+ 释放时值校验（Lua 脚本），三步缺一不可，否则可能导致锁被其他客户端释放。

### 参考存 stub

```go
ok, _ := client.SetNX(ctx, key, uuid, ttl).Result()
if ok { /* 获得锁 */ }
```

## 连接池调优参考值

| 场景 | MaxOpenConns | MaxIdleConns | ConnMaxLifetime |
|------|-------------|--------------|-----------------|
| 低并发 API | 25 | 5 | 5min |
| 高并发 API | 100 | 20 | 5min |
| 批量任务 | CPU核数×2 | 0（用完即关） | 1min |
