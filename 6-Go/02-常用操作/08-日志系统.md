# 日志系统

**定义**：日志是程序运行时产生的带时间戳的文本记录，结构化日志（slog、zap、zerolog）以键值对替代自由文本，使日志可被机器解析和查询，而不仅仅是人类可读。

## slog（Go 1.21+ 内置）

### 定义断言
`slog` 是 Go 标准库首次内置的结构化日志器，其核心设计是**处理器（Handler）决定输出格式**，Logger 只负责组织级别和键值对，`NewJSONHandler` 和 `NewTextHandler` 是两种内置处理器。

### 数据流

<pre>
logger.Info("request", "method", "GET", "path", "/api")
        ↓
Logger 检查 Level（Debug/Info/Warn/Error）
        ↓
传递给 Handler
        ↓
JSONHandler → {"time":"...","level":"INFO","msg":"request","method":"GET","path":"/api"}
TextHandler → 2024/01/15 10:30:45 INFO request method=GET path=/api
</pre>

### 机制解释
`slog` 的零依赖设计：标准库直接引入，无需第三方。`Logger` 本身无状态（无全局锁），性能关键路径无内存分配。JSON 输出时使用 `encoding/json`，但文本输出使用自定义格式化器。

### 参考存 stub

```go
slog.Info("hello", "key", "value")
slog.SetDefault(slog.New(slog.NewJSONHandler(os.Stdout)))
```

## 第三方库选择

### 定义断言
`slog` 适合无需极致性能的标准场景；`zap` 适合高吞吐服务（>10万 QPS），通过对象池实现零分配日志；`zerolog` 适合极致性能追求者，通过链式 API 减少接口调用次数。

### 性能对比

| 库 | 每次 Log 调用分配 | 100K QPS 额外 CPU |
|----|------------------|-------------------|
| log | 1-3次 | ~5% |
| slog | 1-2次 | ~3% |
| zap | 0次（对象池） | ~1% |
| zerolog | 0次 | ~1% |

## 日志级别语义

### 定义断言
日志级别是**过滤器**而非优先级：低于设置级别的日志被丢弃。常见错误是将 Info 当作"重要"、Warn 当作"不重要"，实际上应按可恢复性区分——Warn 是异常但可自动恢复，Info 是正常运行事件。

| 级别 | 含义 | 示例 |
|------|------|------|
| Debug | 开发调试 | "进入函数 X"、"变量 Y = 123" |
| Info | 正常运行 | "服务启动"、"处理请求 GET /api" |
| Warn | 异常可恢复 | "连接超时，重试"、"缓存未命中" |
| Error | 需要关注 | "数据库连接失败"、"认证失败" |
| Fatal | 程序终止 | "端口监听失败"、"数据损坏" |

## 敏感信息保护

### 定义断言
`slog` 的 `LogValuer` 接口允许类型自定义其日志表示，可用于防止密码、Token 等敏感值意外写入日志。

### 参考存 stub

```go
type Sensitive string
func (s Sensitive) LogValue() slog.Value { return slog.StringValue("***REDACTED***") }
slog.Info("auth", "password", Sensitive(pw))
// 输出：password=***REDACTED***
```
