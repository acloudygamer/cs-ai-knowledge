# 日志系统

## 定义

日志是程序运行时产生的带时间戳的文本记录，结构化日志（slog、zap、zerolog）以键值对替代自由文本，使日志可被机器解析和查询，而不仅仅是人类可读。

日志的本质是**运行时审计追踪**：记录程序执行路径、状态变化、错误信息，供人类调试和机器分析。

## 数学模型

### 日志性能模型

设每秒日志调用次数为 $R$，每次调用分配次数为 $A$：

- **log 标准库**：$A \approx 1-3$（字符串格式化 + io 操作）
- **slog**：$A \approx 1-2$（JSON 编码优化）
- **zap/zerolog**：$A \approx 0$（对象池 + 零分配设计）

CPU 占用估算：100K QPS 服务，假设日志大小 200 字节：

| 库 | 每次日志分配 | 100K QPS 额外 CPU |
|----|-------------|-------------------|
| log | 2次 | ~5% |
| slog | 1次 | ~3% |
| zap | 0次（对象池） | ~1% |
| zerolog | 0次 | ~1% |

### 日志级别的过滤模型

日志级别是**阈值过滤器**：

```go
if level >= config.level {
    output(log)
}
```

- Debug: 0
- Info: 1
- Warn: 2
- Error: 3
- Fatal: 4

**设计语义**：级别表示**严重性/可恢复性**，而非"重要性"。Info 是正常运行事件，即使它"重要"也不应用 Warn。

## 数据流

### slog 内部数据流

<pre>
logger.Info("request", "method", "GET", "path", "/api")
        │
        │ Logger.CheckLevel() 检查阈值
        ▼
低于阈值 → 直接丢弃
        │
        │ 高于阈值
        ▼
组装 LogRecord
        │
        │ 传递给 Handler
        ▼
JSONHandler:
  ├─ time=RFC3339
  ├─ level=INFO
  ├─ msg=request
  └─ method=GET, path=/api

TextHandler:
  └─ 2024/01/15 10:30:45 INFO request method=GET path=/api
</pre>

### 处理器链（Pipeline）

<pre>
Logger.Info(...)
        │
        ├─► Handler 1 (JSON → 文件)
        │
        ├─► Handler 2 (Text → stdout)
        │
        └─► Handler 3 (过滤 + 转发远程)
</pre>

Go 1.21+ slog 不支持多 Handler，需要自行实现 Fanout：

```go
type FanoutHandler struct {
    handlers []slog.Handler
}
func (h *FanoutHandler) Handle(ctx context.Context, r slog.Record) error {
    for _, h := range h.handlers {
        h.Handle(ctx, r)
    }
    return nil
}
```

### LogValuer 惰性求值

<pre>
slog.Info("auth", "token", Sensitive("secret"))
        │
        │ 记录时不立即求值
        ▼
LogValue() 在输出时才调用
        │
        │ 防止敏感信息意外泄露
        ▼
输出：token=***REDACTED***
</pre>

## 机制

### slog 的设计哲学

`slog`（Go 1.21+）是标准库首次内置的结构化日志，核心理念：

1. **Handler 决定格式**：Logger 只组织级别和键值对，Handler 决定如何输出
2. **零依赖**：标准库直接使用，无需第三方
3. **零分配目标**：LogRecord 在栈上分配，JSON 输出优化减少分配

### 日志级别的语义边界

| 级别 | 语义 | 触发条件 |
|------|------|----------|
| Debug | 开发调试信息 | 开发环境，开启 |
| Info | 正常运行事件 | 生产环境，默认开启 |
| Warn | 异常但可自动恢复 | 需要关注 |
| Error | 需要手动干预 | 记录但不终止 |
| Fatal | 程序终止 | 记录后 os.Exit(1) |

**常见错误**：将 Info 当作"重要日志"，Warn 当作"不重要"。实际上：
- Warn = 异常事件（连接超时、重试成功、缓存未命中）
- Info = 正常运行（收到请求、完成处理）

### zap 的对象池设计

zap 通过**sync.Pool**复用日志编码器：

```go
// zap 内部
var encoderPool = sync.Pool{
    New: func() interface{} {
        return zapcore.NewJSONEncoder(config)
    },
}

// 每次写日志时
enc := encoderPool.Get().(*jsonEncoder)
defer encoderPool.Put(enc)
// 使用 enc 编码
```

这使得 zap 在高吞吐量下**几乎零分配**，代价是编码器状态需要正确重置。

### 敏感信息保护

`LogValuer` 接口允许类型自定义日志输出：

```go
type Sensitive string
func (s Sensitive) LogValue() slog.Value {
    return slog.StringValue("***REDACTED***")
}

slog.Info("auth", "password", Sensitive(pw))
// 输出：auth password=***REDACTED***
```

**约束**：必须在记录时传入 `Sensitive` 类型，不能传入 `string`，否则反射会直接记录原值。

### 日志与结构化日志的对比

| 维度 | 传统日志 | 结构化日志 |
|------|---------|-----------|
| 格式 | 自由文本 | 键值对 |
| 查询 | 字符串搜索 | 字段查询 |
| 解析 | 正则提取 | 自动解析 |
| 可读性 | 人类友好 | 机器友好 |
| 工具 | grep/awk | ELK/Splunk/ClickHouse |

**最佳实践**：
- 生产环境：结构化日志（slog JSON / zap）
- 调试：文本日志（slog Text / zerolog）
- 敏感字段：LogValuer 包装

## 参考存根

```go
// slog 基本使用
slog.Info("hello", "key", "value")
slog.Warn("warning", "count", 42)

// 自定义 Handler
handler := slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
    Level: slog.LevelDebug,
})
logger := slog.New(handler)
slog.SetDefault(logger)

// Fanout Handler（多输出）
type FanoutHandler struct {
    handlers []slog.Handler
}
func (h *FanoutHandler) Handle(ctx context.Context, r slog.Record) error {
    for _, h := range h.handlers {
        h.Handle(ctx, r)
    }
    return nil
}

// LogValuer 敏感信息保护
type Sensitive string
func (s Sensitive) LogValue() slog.Value {
    return slog.StringValue("***REDACTED***")
}

// 上下文日志
logger := slog.With("service", "api", "version", "v1")
logger.Info("request received", "path", "/api")
```

## 库选择决策

| 场景 | 推荐 | 原因 |
|------|------|------|
| 标准库依赖 | slog | 零依赖，Go 内置 |
| 高吞吐量（>100K QPS） | zap/zerolog | 零分配 |
| 极致性能 | zerolog | 链式 API，开销最小 |
| 简单场景 | slog + TextHandler | 标准库足够 |
| 需持久化 | zap + file rotation | 成熟的文件轮转 |
