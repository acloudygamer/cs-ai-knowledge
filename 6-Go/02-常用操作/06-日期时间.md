# 日期时间

## 定义

`time.Time` 是 Go 的时间点类型，内部存储为 UTC 纳秒时间戳（自 0001-01-01 00:00:00 起），与时区无关；格式化/解析是输入输出转换，与内部存储分离。

时间处理的本质是**物理时间与人类时间的分离**：机器存储绝对时间戳，人类阅读相对时区的本地时间，两者通过时区规则转换。

## 数学模型

### 时间戳的数学结构

`time.Time` 内部结构：
```go
type Time struct {
    wall uint64   // |ss|hh:mmmmm|   秒数（31 bits）
    ext  int64    // 纳秒时间戳（64 bits）
    loc  *Location // 时区信息指针
}
```

设 $t$ 为 UTC 纳秒时间戳，则：
- $t = seconds \times 10^9 + nanoseconds$
- 范围：0001-01-01 00:00:00 UTC 至 9999-12-31 23:59:59.999999999 UTC

**归约终点**：时间戳的本质是有序整数，时间的比较和运算都可以归约为整数的比较和加减。

### 夏令时的数学陷阱

夏令时（DST）是**本地时间的社会性偏移**，不是物理时间：

```
2024-03-10 02:30:00 (本地 CST)
        │
        │ +24小时
        ▼
2024-03-11 03:30:00 (本地 CST)  ← 非 02:30！
        │
        │ 原因：02:00 → 03:00 跳过一小时
        ▼
正确做法：转 UTC，计算，再转回
```

**约束**：使用 `time.Add()` 对包含夏令时边界的时间进行运算可能产生非预期结果。

### 纳秒时间戳的表示范围

`time.Time` 使用 64 位纳秒表示：
- 若从 1970-01-01 起算，64 位有符号整数可表示 ±292,277,024,626 年
- 实际上 Go 使用 0001-01-01 作为纪元，纳秒精度可维持 ± 9,227 个世纪

## 数据流

### 时间存储与展示的分离

<pre>
time.Now().Unix() ──► int64 UTC 时间戳（时区无关）
        │
        │ 存储到数据库/传输
        ▼

t.In(time.Local) ──► 转换为本地时区时间点
        │
        │ 显示给用户
        ▼
"2024-01-15 14:30:00 CST"

t.In(time.FixedZone("CST", 8*60*60)) ──► 固定偏移量
</pre>

**数据形态变换**：
- 物理时间（纳秒整数）→ 不随时区变化
- 本地时间（年/月/日/时/分/秒）→ 依赖时区规则

### 格式化/解析流程

<pre>
"2024-01-15 15:04:05" (字符串)
        │
        │ time.Parse(layout, str)
        ▼
┌────────────────────────────────┐
│ layout = "2006-01-02 15:04:05"│
│  用参考时间的形状填充格式      │
└────────────────────────────────┘
        │
        │ 返回 time.Time（UTC 内部存储）
        ▼
time.Time{...}
</pre>

## 机制

### 参考时间的机制解释

Go 的时间格式化使用**参考时间**（Reference Time）：

```
Mon Jan 2 15:04:05 MST 2006
≡   ≡  ≡  ≡  ≡  ≡  ≡   ≡
1   2  3  4  5  6   7   8
```

每个数字 1-7 在参考时间中**唯一对应**一个时间组件：

| 数字 | 含义 | 参考时间中值 |
|------|------|-------------|
| 1 | 月份（Monday） | Mon |
| 2 | 日期（15号） | 2 |
| 3 | 小时（15时） | 15 |
| 4 | 分钟 | 04 |
| 5 | 秒数 | 05 |
| 6 | 月份（January） | Jan |
| 7 | 年份（2006） | 2006 |

**设计原理**：这是 Rob Pike 的"偷懒式"设计——复用已存在的字符串解析逻辑，无需引入新的格式语法。

### 时区处理的约束

`time.LoadLocation` 从以下来源加载时区数据：
1. 系统时区数据库（Linux: `/usr/share/zoneinfo`）
2. `$GOROOT/lib/time`
3. `$TZ` 环境变量

**容器环境陷阱**：若容器未安装 `tzdata` 包，`LoadLocation` 返回 UTC，而非预期的本地时区。

**最佳实践**：
- 内部存储使用 UTC 时间戳（`time.Now().UTC().Unix()`）
- 展示时转换到目标时区
- 跨时区系统间交换使用 UTC 或 IANA 格式（如 RFC3339）

### 闰秒的处理

闰秒是 UTC 偶尔插入的修正（通常在 6 月 30 日或 12 月 31 日 23:59:60）：

- `time` 包在内部正确处理闰秒（通过定时器补偿）
- `time.Now()` 返回的时间戳**不包含闰秒信息**（是连续的）
- 夏令时切换对 `time.Now()` 无影响（基于单调时钟）

### `time.Duration` 的算术

```go
// 正确：使用 Duration 进行时间运算
future := time.Now().Add(24 * time.Hour)  // 正确

// 错误：使用整数直接加
future := time.Now().Unix() + 24*60*60   // Unix 秒整数相加
```

`time.Duration` 是纳秒为单位的 `int64`，是**相对时间**；`time.Time` 是**绝对时间点**。

## 参考存根

```go
// 解析（layout 参数使用参考时间）
t, _ := time.Parse("2006-01-02 15:04:05", "2024-01-15 10:30:00")

// 格式化
str := t.Format("2006-01-02 15:04:05")

// 时区转换
utc := t.UTC()
local := t.In(time.Local)
cst := t.In(time.FixedZone("CST", 8*60*60))

// Duration 运算
later := time.Now().Add(24 * time.Hour)
diff := later.Sub(time.Now())

// Unix 时间戳
unix := time.Now().Unix()
unixNano := time.Now().UnixNano()

// 从时间戳重建
t = time.Unix(unix, 0)

// 夏令时安全的时间运算
t := time.Date(2024, 3, 10, 1, 30, 0, 0, time.Local)
later := t.Add(24 * time.Hour)
fmt.Println(later.Format("15:04:05"))
// 输出可能是 "03:30:00" 而非 "01:30:00"
```

## 时区处理最佳实践

| 场景 | 推荐 |
|------|------|
| 内部存储 | UTC 时间戳 (int64) |
| API 交换格式 | RFC3339 字符串 |
| 数据库存储 | TIMESTAMP WITH TIME ZONE 或 UTC 时间戳 |
| 日志 | UTC，避免时区歧义 |
| 用户展示 | 本地时区转换 |
| 跨时区调度 | 使用 UTC，存储本地时间和 UTC 的映射 |
