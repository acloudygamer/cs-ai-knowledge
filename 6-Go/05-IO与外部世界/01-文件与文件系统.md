# 文件与文件系统

> 前置：[01-语言核心](../01-语言核心/)、[02-标准库/02](../02-标准库/02-io与bufio.md)、[04-并发/04](../04-并发/04-context与取消传播.md) · 后续：[02-网络编程](./02-网络编程.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

**`*os.File` 是 `io.Reader`、`io.Writer`、`io.Seeker`、`io.Closer` 四个接口的合集**——它不是为文件专门设计的类型，而是"一个打开的文件描述符"在 Go 接口体系里的具体实现（[02-标准库/02](../02-标准库/02-io与bufio.md)）。

这个定位决定了本篇与 [02-网络编程](./02-网络编程.md) 的关系：**文件和 TCP 连接在 Go 里是同一类东西**——都是 `io.Reader`/`io.Writer`，因此 `io.Copy`、`bufio.Scanner`、`gzip.NewReader` 对两者一视同仁。

**边界**：`*os.File` 是**带缓冲的**吗？不是——`os.File` 的 `Read`/`Write` **直接对应系统调用**。要缓冲必须套 `bufio`（[02-标准库/02](../02-标准库/02-io与bufio.md) 给了实测：10001 次系统调用 → 4 次）。

## 机制

### 打开文件的三种方式

| 函数 | 标志 | 用途 |
|---|---|---|
| `os.Open(path)` | `O_RDONLY` | 只读打开 |
| `os.Create(path)` | `O_RDWR\|O_CREATE\|O_TRUNC` | 创建/清空 |
| `os.OpenFile(path, flag, perm)` | 自选 | 完整控制 |

```console
$ go run .
创建 err: <nil>
权限位: -rw-rw-rw-  Mode().Perm() = -rw-rw-rw- (Windows 上权限位不完整生效)
```

**`0600` 在 Windows 上得到 `-rw-rw-rw-`**——**Windows 不完整支持 Unix 权限位**。Go 会把 `0200`（写位）映射到 Windows 的只读属性，其余位被忽略。**跨平台代码不能依赖权限位做安全控制**——那是 Unix 的概念。

### `os.ReadFile` / `os.WriteFile`

```console
$ go run .
WriteFile err: <nil>
ReadFile: "第一行\n第二行\n第三行\n" (30 字节)
```

**这两个函数是便捷封装，内部会 `Open` + `ReadAll` + `Close`**。判据：

| | `os.ReadFile` | `os.Open` + 流式读 |
|---|---|---|
| 内存 | **整个文件进内存** | 只有缓冲区 |
| 适合 | 小文件、配置、模板 | 大文件、逐行处理、流式转发 |

**约束**：`os.ReadFile` **没有大小上限**——读一个 10 GB 的文件会直接 OOM。面向不可信路径时必须先 `os.Stat` 检查大小，或用 `io.LimitReader`（[02-标准库/02](../02-标准库/02-io与bufio.md)）。

### 逐行读：`bufio.Scanner`

```console
$ go run .
  行 1: 第一行
  行 2: 第二行
  行 3: 第三行
```

**`Scanner` 有 64 KiB 的行长上限**（[02-标准库/02](../02-标准库/02-io与bufio.md) 有实测），超长行会报 `token too long` 并停止。真实数据里超长行很常见（日志、JSON Lines），必须处理：

```go
sc.Buffer(make([]byte, 0, 1<<20), 1<<20)   // 调到 1 MiB
```

**约束**：`sc.Err()` 必须检查——`Scan()` 返回 `false` 可能是正常结束，也可能是出错。

### `defer f.Close()` 与错误处理

```go
func writeWithCloseCheck(path string) (err error) {
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	defer func() {
		if cerr := f.Close(); cerr != nil && err == nil {
			err = cerr        // 只在没有更早的错误时上报
		}
	}()
	_, err = f.WriteString("data")
	return err
}
```

**为什么要这么写**：`Write` 成功不代表数据落盘——**写操作会被操作系统缓冲**，真正的失败可能发生在 `Close` 时。**只读文件可以忽略 `Close` 的错误，写入文件不能。**

**惯用的简写 `defer f.Close()` 丢掉了这个错误**。上面的模式是标准解法：用命名返回值（[01-语言核心/05](../01-语言核心/05-函数.md)）让 `defer` 能改 `err`，且**不让 `Close` 的错误覆盖更具体的错误**。

### `filepath` vs `path`

```console
$ go run .
filepath.Join (平台分隔符): a\b\c.txt
filepath.Separator: \
Dir: a\b  Base: c.txt  Ext: .txt
```

| 包 | 分隔符 | 用途 |
|---|---|---|
| `path` | **总是 `/`** | URL 路径、`fs.FS` 内的路径 |
| `filepath` | **平台相关**（Windows `\`） | **本地文件系统路径** |

**判据**：**处理本地文件用 `filepath`，处理 URL 或虚拟文件系统用 `path`**。混用会在 Windows 上出错——`path.Join("a", "b")` 得到 `a/b`，Windows 的 API 多数能接受，但字符串比较与显示会不一致。

**`filepath.Join` 会自动 `Clean`**——它会消掉 `..` 和多余的斜杠：

```console
$ go run .
filepath.Clean("../../etc/passwd") = ..\..\etc\passwd
```

**注意 `Clean` 不会阻止路径遍历**——它只是规范化，`../../` 依然在结果里。**要防目录穿越必须自己校验**：把用户输入 `filepath.Join(root, userInput)` 之后检查结果是否仍在 `root` 下（用 `strings.HasPrefix` 或 `filepath.Rel`）。

### 错误判定：`fs.PathError`

```console
$ go run .
Stat 不存在: GetFileAttributesEx C:\...\不存在的文件.txt: The system cannot find the file specified.
os.IsNotExist: true
errors.Is(err, fs.ErrNotExist): true
errors.As(*fs.PathError): true
  Op="GetFileAttributesEx" Path="C:\\...\\不存在的文件.txt" Err=The system cannot find the file specified.
```

**文件操作的错误总是 `*fs.PathError`**，它带 `Op`（操作名）、`Path`（路径）、`Err`（底层错误）三个字段。

三种判定方式，**推荐顺序**：

| 方式 | 说明 |
|---|---|
| `errors.Is(err, fs.ErrNotExist)` | **推荐**——能穿透包装链（[01-语言核心/10](../01-语言核心/10-错误处理.md)） |
| `errors.As(err, &pathErr)` | 需要读取 `Op`/`Path` 时用 |
| `os.IsNotExist(err)` | 旧 API，**不穿透包装**，新代码不用 |

**约束**：`os.IsNotExist` 与 `errors.Is(err, fs.ErrNotExist)` 在**无包装**时等价，但一旦错误被 `fmt.Errorf("%w")` 包过，前者就失效了。

### `io/fs`：文件系统抽象

```console
$ go run .
os.DirFS 目录项数: 425
```

`fs.FS` 接口只有一个方法（[02-标准库/02](../02-标准库/02-io与bufio.md)），标准库提供三种实现：

| 实现 | 来源 | 用途 |
|---|---|---|
| `os.DirFS(dir)` | 真实目录 | 把目录当根 |
| `embed.FS` | **编译进二进制** | 静态资源、模板、默认配置 |
| `fstest.MapFS` | 内存 map | 测试（[07-测试与质量/02](../07-测试与质量/02-单元测试与mock.md)） |

**价值**：把函数的签名从 `func load(path string)` 改成 `func load(fsys fs.FS, path string)`，测试时传 `fstest.MapFS` 就不用碰真实磁盘，部署时传 `embed.FS` 就把资源打进了二进制。

**约束**：`fs.FS` 的路径**必须用 `/` 且不能以 `/` 开头**：

```console
$ go run .
fs.ValidPath("../x") = false
fs.ValidPath("a/b") = true
```

这条规则由 `fs.ValidPath` 定义，所有 `fs.FS` 实现都必须遵守。**这是跨平台一致的代价**——不能直接用 Windows 的 `\` 路径。

### 临时文件

```console
$ go run .
CreateTemp: C:\Users\zyq\AppData\Local\Temp\prefix-2290250431.txt <nil>
```

`os.CreateTemp(dir, pattern)` 的 `pattern` 里 `*` 会被替换成随机串。**`dir` 传空串时用系统临时目录**（`os.TempDir()`）。

**约束**：临时文件**不会被自动清理**——进程退出后仍在。需要清理就 `defer os.Remove(name)`。长期运行的服务如果频繁建临时文件，磁盘会被填满。

## 连接

**上游**：[02-标准库/02](../02-标准库/02-io与bufio.md) 的 `io.Reader`/`io.Writer` 接口族定义了 `*os.File` 的形状；[01-语言核心/10](../01-语言核心/10-错误处理.md) 的 `errors.Is`/`As` 是 `fs.PathError` 的判定手段。

**下游**：[02-网络编程](./02-网络编程.md) 的 `net.Conn` 与 `*os.File` 是同一套接口的两种实现；[03-HTTP服务与客户端](./03-HTTP服务与客户端.md) 的静态文件服务用 `http.FileServer` 包了 `os.DirFS`。

**与其它语言对照**：

| | 打开文件 | 关闭 | 错误 |
|---|---|---|---|
| Java | `new FileInputStream(f)` | `try-with-resources` | `IOException`（受检） |
| Python | `open(path)` | `with` 语句 | `OSError` |
| C | `fopen` | `fclose`（易忘） | 返回 NULL + `errno` |
| **Go** | **`os.Open`** | **`defer f.Close()`** | **`error` 返回值** |

**Go 与 Java/Python 的关键差别是 `Close` 的错误处理**：Java 的 try-with-resources 会把 `close` 抛出的异常作为 **suppressed exception** 附加到主异常上；Python 的 `with` 会**直接抛出** `close` 的异常（可能覆盖主异常）。**Go 的 `defer f.Close()` 默认丢弃它**——这让错误处理更显式，但要求写代码的人知道这件事（上面那个命名返回值的模式）。

**Windows 与 Unix 的另一处差别**：Windows 上**打开的文件不能被删除或重命名**（除非用 `FILE_SHARE_DELETE`），Unix 上可以。这导致"先写临时文件再 rename"这个在 Unix 上原子的操作，在 Windows 上必须先关文件。跨平台代码要注意。
