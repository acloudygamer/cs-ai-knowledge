# 正则表达式

> 前置：[03-日期与时间](./03-日期与时间.md) · 后续：[05-序列化与编码](./05-序列化与编码.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

`regexp` 包用的是 **RE2 引擎**，它保证**线性时间匹配**——匹配耗时与输入长度成正比，与正则的复杂度和输入内容无关。

**约束的由来**：这条保证的代价是**语法能力的削减**。RE2 不支持任何需要回溯才能实现的结构：

```console
$ go run .
反向引用 (a)\1 : error parsing regexp: invalid escape sequence: `\1`
环视 (?=x)     : error parsing regexp: invalid or unsupported Perl syntax: `(?=`
非贪婪 a+?     : <nil> （支持）
```

- **反向引用**（`(a)\1`）**不支持**——它是 NP 难的来源。
- **环视**（`(?=x)`、`(?<=x)`、`(?!x)`）**不支持**。
- **非贪婪量词**（`a+?`）**支持**——它不需要回溯。

**这条约束为什么值得**：回溯引擎（PCRE、Python 的 `re`、Java 的 `java.util.regex`）在遇到精心构造的输入时会**指数级爆炸**。经典例子是 `^(a+)+$` 匹配 `aaaa...aab`——回溯引擎要尝试所有分组方式，输入每加一个 `a`，耗时翻倍。这类正则叫 **ReDoS**（Regular expression Denial of Service），是真实的安全漏洞类别。

RE2 通过把正则编译成**有限自动机**来避免这个问题：自动机的状态数有上界，遍历输入一次即可判定。代价就是上面那些语法不支持。

**判据**：用户可控的正则或用户可控的输入，**必须用 RE2**。Go 没得选——`regexp` 就是 RE2。要 PCRE 能力得引第三方包（`github.com/dlclark/regexp2`），那等于自愿接受 ReDoS 风险。

## 机制

### 匹配与提取

```console
$ go run .
FindString: 123
FindAllString: [123 456]
FindStringIndex: [3 6]
全部子匹配: [2026-09-27 2026 09 27]
命名取值 year: 2026  month: 09
```

常用方法按"要不要分组"分两类：

| 无分组 | 有分组 |
|---|---|
| `FindString` | `FindStringSubmatch` |
| `FindAllString` | `FindAllStringSubmatch` |
| `FindStringIndex` | `FindStringSubmatchIndex` |

`FindStringSubmatch` 返回的切片**第 0 个元素是整体匹配**，之后才是各分组。`FindAllString(s, -1)` 的 `-1` 表示"不限个数"。

**命名捕获组** `(?P<name>...)` 用 `SubexpIndex(name)` 取下标——比数括号位置可靠得多，正则一改位置就错。

**约束**：`Find*` 系列在**无匹配时返回 `nil` 或空串**，不报错也不 panic。要判断"有没有匹配"用 `MatchString`（它只返回 bool，不需要构造结果，更快）。

### 替换与切分

```console
$ go run .
ReplaceAllString: a#b#
ReplaceAllStringFunc: a[1]b[22]
Expand: 27/09/2026
Split: [a b c d]
```

- `ReplaceAllString(src, repl)`：`repl` 里的 `$1`/`${name}` 会展开成分组。
- `ReplaceAllStringFunc(src, f)`：每个匹配交给 `f` 处理，**返回值不再展开**（要字面输出 `$` 就用它）。
- `Split`：按匹配切分，`-1` 表示不限段数。

**易错点**：`ReplaceAllString` 的替换串里 `$` 有特殊含义。要插入字面 `$` 得写 `$$`。不确定时用 `ReplaceAllLiteralString` 或 `ReplaceAllStringFunc`。

### 标志

```console
$ go run .
(?i) 大小写不敏感: true
(?m) 多行: [b b]
MatchString: true
```

标志写在正则开头，或用 `(?flags:...)` 限定作用域：

| 标志 | 含义 |
|---|---|
| `i` | 大小写不敏感 |
| `m` | 多行：`^`/`$` 匹配每行首尾 |
| `s` | 让 `.` 匹配换行 |
| `U` | 反转贪婪性（`a+` 变非贪婪） |

**`(?m)` 与 `(?s)` 常被搞混**：默认情况下 `^`/`$` 只匹配**整个文本**的首尾（不是行首尾），`.` 不匹配 `\n`。`(?m)` 放开前者，`(?s)` 放开后者。

### 编译开销：预编译是硬性要求

```console
$ go test -bench=. -benchmem -run=^$
BenchmarkPrecompiled-12        	 4254315	       278.2 ns/op	       0 B/op	       0 allocs/op
BenchmarkCompileEachTime-12    	  490759	      2434 ns/op	    3074 B/op	      31 allocs/op
```

**每次重新编译慢 8.7 倍，且每次分配 3 KB / 31 次**。编译正则要解析、构建语法树、编译成自动机——这是重量级操作。

**约束**：**正则必须在包级预编译一次**：

```go
var emailRe = regexp.MustCompile(`^\w+@\w+\.\w+$`)
```

`MustCompile` 在编译失败时 panic——包级变量初始化阶段 panic 会让程序启动即失败（[01-语言核心/11](../01-语言核心/11-包与可见性.md)），这对**写死的正则**是合适的：正则写错了应该立刻发现，而不是等到某次请求。

**动态正则**（从配置或用户输入构造）必须用 `regexp.Compile` 并处理 error：

```go
re, err := regexp.Compile(userPattern)
if err != nil {
	return fmt.Errorf("非法正则: %w", err)
}
```

**约束**：动态正则即使语法合法，也有**复杂度风险**——RE2 保证线性时间，但常数可能很大（比如 `a{1000}{1000}` 这类嵌套量词会让自动机状态数爆炸）。对不可信输入的正则，还要限制长度与嵌套深度。

### 常见错误

```console
$ go run .
非法正则       : error parsing regexp: missing closing ]: `[a-`
```

`Compile` 的报错会指出位置。几个高频错误：

| 写法 | 问题 |
|---|---|
| `[a-]` | 字符类里 `-` 在末尾，Go 认为是未闭合的区间 |
| `\d` 在字符类外 | 支持；但 `\d` 只匹配 ASCII 数字，不含全角数字 |
| `^` 与 `$` 的语义 | 默认匹配整个文本首尾，需要 `(?m)` 才是行首尾 |
| `.` 不匹配换行 | 需要 `(?s)` |
| `\w` | 只匹配 `[0-9A-Za-z_]`，**不含中文** |

**中文匹配要用 `\p{Han}`**：`regexp.MustCompile(`\p{Han}+`)` 匹配连续汉字。Go 支持完整的 Unicode 字符类（`\p{L}` 字母、`\p{N}` 数字、`\p{P}` 标点）。

**与其它语言对照**：

| | 引擎 | 时间保证 | 反向引用 | 环视 |
|---|---|---|---|---|
| Python `re` | 回溯 | **无（可指数爆炸）** | 支持 | 支持 |
| Java `java.util.regex` | 回溯 | 无 | 支持 | 支持 |
| JavaScript | 回溯 | 无 | 支持 | 支持 |
| **Go `regexp`** | **RE2（自动机）** | **线性** | **不支持** | **不支持** |

Go 是主流语言里唯一默认用 RE2 的。这也意味着**从 Python/JS 抄来的正则不一定能直接用**——遇到 `\1` 或 `(?=...)` 要改写。常见的改写手法：反向引用改用两次匹配 + 程序逻辑判断；环视改用在匹配到的更大范围上再筛一层。
