# 函数

> 前置：[04-控制流程](./04-控制流程.md) · 后续：[06-方法与接收者](./06-方法与接收者.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

**函数是 Go 里的一等值**——可以赋给变量、当参数传、当返回值返回。这一条是 [09-设计模式](../09-设计模式/) 里大部分模式能退化成"一行"的原因。

Go 的函数有四处与 C/Java 不同的规定：

| 特性 | Go | C/Java |
|---|---|---|
| 返回值个数 | **任意多个** | C 一个；Java 一个 |
| 可变参数 | 有（`...T`） | C 有（`va_list`，无类型检查）；Java 有 |
| 函数重载 | **没有** | 有 |
| 默认参数 | **没有** | 没有（C++/Python 有） |
| 函数是一等值 | 是 | C 是函数指针；Java 8+ 是 lambda |

**约束的由来**：没有重载、没有默认参数，是"一个名字对应一个东西"原则的延伸——同名函数有两份签名，读调用点时无法确定调的是哪个。替代方案是**不同的名字**（`NewServer` / `NewServerWithOptions`）或**可变选项**（函数式选项，见 [09-设计模式/02](../09-设计模式/02-创建型.md)）。

多返回值则补上了"没有异常"的缺口：`(T, error)` 是 Go 里失败传播的唯一形态（[10-错误处理](./10-错误处理.md)）。

## 机制

### 多返回值与命名返回值

```console
$ go run .
多返回值: 2 1
命名返回值 + defer 修改: 10
```

```go
func divmod(a, b int) (int, int) { return a / b, a % b }

func named() (n int) {
	defer func() { n *= 2 }()
	return 5        // 等价于 n = 5; return
}
```

**命名返回值让 `defer` 能改返回值**。`named()` 返回 10 而不是 5：`return 5` 先把 5 赋给 `n`，然后跑 `defer`，`n` 被改成 10，最后返回 `n`。

**约束**：命名返回值不是"文档"，它**改变了函数的控制流**。上面的写法在错误处理里有真实用途——`defer` 里能改 `err`：

```go
func writeFile(path string) (err error) {
	f, err := os.Create(path)
	if err != nil {
		return err
	}
	defer func() {
		if cerr := f.Close(); cerr != nil && err == nil {
			err = cerr        // 只在没有更早的错误时上报 Close 失败
		}
	}()
	_, err = f.WriteString("data")
	return err
}
```

```console
$ go run .
defer 与 Close 错误: <nil>
```

**判据**：`Close()` 的错误在**只读**文件上可以忽略，在**写入**文件上不能——缓冲区可能在这时才刷盘失败。上面的模式是标准解法：**不要让 Close 的错误覆盖掉更早、更具体的错误**。

### 可变参数

```console
$ go run .
可变参数: 和=6 / 空=0
```

```go
func sumAll(prefix string, nums ...int) string
```

`nums` 在函数内是 `[]int`。**传切片时要展开**：`sumAll("和=", s...)`，少了 `...` 是类型错误。

**约束**：`...T` 必须是**最后一个参数**，且一个函数只能有一个。

### `defer`：延迟执行

```console
$ go run .
defer 参数求值时机:
  函数体里的 x = 100
  defer 里的 x = 1
defer LIFO:
  defer 3
  defer 2
  defer 1
```

三条规则：

**一、`defer` 的参数在 `defer` 语句处求值**，函数体在返回时执行。上面的 `x` 在 `defer` 语句处是 1，所以打印 1——即使函数体后来把它改成 100。**要捕获最终值必须用闭包**（`defer func(){ fmt.Println(x) }()`）。

**二、多个 `defer` 按后进先出（LIFO）执行**。`defer 1` 最先注册、最后执行。这符合"资源获取与释放对称"的直觉——`open A; open B; defer close B; defer close A` 写起来就是自然的顺序。

**三、`defer` 在函数返回前执行，包括 panic 时**。这是 `recover` 唯一的落点（[10-错误处理](./10-错误处理.md)）。

**代价**：Go 1.14 起 `defer` 的常规开销降到了**约 1 纳秒**（开放编码优化，open-coded defers），所以在热路径上也不必回避。循环里的 `defer` 仍要小心——它们**全部累积到函数返回时才执行**，循环十万次就积压十万个延迟调用。循环内该用显式关闭或抽成函数。

### 闭包与捕获

```console
$ go run .
闭包计数: 1 2 3
```

```go
func counter() func() int {
	n := 0
	return func() int { n++; return n }
}
```

`n` 是局部变量，但闭包让它**逃逸到堆上**，生命周期跟着闭包走（[03-运行时与内存/02](../03-运行时与内存/02-内存分配与逃逸分析.md)）。

**闭包捕获的是变量本身，不是它的值**——多个闭包捕获同一个变量时共享它。

### 循环变量：Go 1.22 的语义变更

```console
$ go run .
循环变量捕获（1.22+ 每轮新建）: 0 1 2 
```

```go
for i := 0; i < 3; i++ {
	fs = append(fs, func() { fmt.Print(i, " ") })
}
```

**Go 1.22 之前，这段代码输出 `3 3 3`**——三个闭包捕获的是**同一个** `i`，循环结束时它是 3。1.22 起 `for` 循环变量**每轮新建一份**，输出 `0 1 2`。

这是 Go 历史上少见的**破坏性语义变更**，靠 `go.mod` 里的 `go` 指令控制：`go 1.21` 及以下的模块保持旧行为。老代码里"把 `i` 显式复制一份"（`i := i`）的写法在新语义下成了冗余，但保留它不会出错。

### 函数是一等值

```console
$ go run .
函数作参数: 25
方法值: func() string
方法表达式（*os.File).Name: func(*os.File) string
```

函数类型可以作参数、返回值、struct 字段、map 的值。方法也有两种"降级"形态：

| | 写法 | 类型 | 绑定 |
|---|---|---|---|
| **方法值** | `f.Name` | `func() string` | 绑定了接收者 `f` |
| **方法表达式** | `(*os.File).Name` | `func(*os.File) string` | 未绑定，接收者是第一个参数 |

方法值是 `http.HandlerFunc` 这类适配器的实现基础（[09-设计模式/03](../09-设计模式/03-结构型.md)）。

**与其它语言对照**：

| | 闭包捕获 | 循环变量 | 延迟执行 |
|---|---|---|---|
| Java | 要求 effectively final | 每轮新建（一直如此） | `try-with-resources` |
| Python | 捕获变量（同 Go 1.22 前） | **同一变量**（至今） | `with` |
| C++ | 显式 `[&]`/`[=]` 捕获 | 每轮新建 | RAII 析构 |
| **Go** | **捕获变量** | **1.22 起每轮新建** | **`defer`** |

Go 的 `defer` 与 C++ 的 RAII 解决同一个问题（"离开作用域时清理"），但**方向相反**：RAII 是**对象析构时**触发，`defer` 是**函数返回时**触发。差别在于作用域粒度——C++ 的 RAII 在离开**任意块**时生效，Go 的 `defer` 只在**函数**返回时生效。这也是为什么 Go 里"循环内打开文件"必须显式关或抽成函数，而 C++ 里块结束就自动关了。
