# 方法与接收者

> 前置：[05-函数](./05-函数.md) · 后续：[07-结构体与组合](./07-结构体与组合.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

**方法就是带接收者的函数**。这一句话是理解 Go 方法论的起点——Go 没有类，方法不属于类型定义体内部，而是和函数一样在包级声明，只是多了一个接收者参数：

```go
func (c Counter) Get() int   { return c.N }    // 方法
func Get(c Counter) int      { return c.N }    // 等价函数
```

两者的区别只在**调用语法**和**方法集**（下面讲）——`c.Get()` 与 `Get(c)` 编译后是同一次调用。

**约束：接收者必须是本包定义的类型**。不能给 `int`、`string` 或别的包的类型定义方法：

```go
func (i int) Twice() int { return i * 2 }   // 编译错误：cannot define new methods on non-local type int
```

这条禁令是**隐式的接口满足关系**能成立的前提（[08-接口](./08-接口.md)）。如果任何包都能给 `int` 加方法，那么"某个 `int` 值是否满足某个接口"就取决于**导入了哪些包**——类型检查将不再是局部的。

要扩展外部类型，只能定义一个新类型（`type MyInt int`）或嵌入它（[07-结构体与组合](./07-结构体与组合.md)）。

## 机制

### 值接收者 vs 指针接收者

```go
func (c Counter) IncVal() { c.N++ }    // 值接收者：拿到副本
func (c *Counter) IncPtr() { c.N++ }   // 指针接收者：改原值
```

```console
$ go run .
值接收者改不动: 0
指针接收者改得动: 1
```

值接收者拿到的是**副本**，改它不影响原值。这不是"传值 vs 传引用"的老问题，而是 Go 把这条规则**显式写在了签名里**——读方法签名就知道它会不会改调用者的数据。

### 自动取址与自动解引用

Go 允许 `c.IncPtr()` 这样的调用（`c` 是值不是指针），编译器自动插入 `(&c).IncPtr()`：

```console
$ go run .
再次: 2
```

但**自动取址要求值可寻址**。下面这行编译不过：

```go
m := map[string]C{"a": {}}
m["a"].Inc()          // 编译错误
```

```console
$ go build ./...
.\bad2.go:5:9: cannot call pointer method Inc on C
```

**map 元素不可寻址**——map 的底层是哈希表，元素在扩容时会搬位置，运行时不能给你一个稳定地址。同理，`C{}.Inc()` 也不行（字面量没有地址）。**切片元素可以**（底层是连续数组，地址稳定）：

```console
$ go run .
切片元素可寻址，Inc 生效: 1
```

**约束**：这个限制的实用后果是——**结构体不该放进 map 当"可变对象"用**。要改就存指针（`map[string]*C`），或者把 map 当只读索引。

### 方法集：决定接口满足关系的规则

| 类型 | 值方法（值接收者） | 指针方法（指针接收者） |
|---|---|---|
| `T` 的方法集 | ✅ 包含 | ❌ 不包含 |
| `*T` 的方法集 | ✅ 包含 | ✅ 包含 |

**只有 `*T` 的方法集包含指针方法**。所以：

```go
type Loud struct{ v int }
func (l *Loud) Speak() string { return "LOUD" }

var sp Speaker
// sp = Loud{}      // 编译错误：Loud does not implement Speaker
sp = &Loud{}        // ✅
```

```console
$ go run .
指针接收者方法，只有 *Loud 满足: LOUD
```

**约束**：这条规则是隐式接口满足关系的代价。Java 的 `implements` 是显式声明，编译器可以在类定义处检查；Go 的类型可能满足无数个接口，只能在**赋值给接口时**检查方法集。指针方法让"值不满足、指针满足"成为一个真实且常见的坑。

**实践建议**：一个类型的所有方法**要么全用值接收者、要么全用指针接收者**。混用会让方法集不对称，接口满足关系变得难推理。判据是——**类型里有需要修改的字段、或者有 `sync.Mutex` 之类的不可拷贝字段，就用指针接收者**；纯值语义的小类型（`time.Time` 那样）用值接收者。

### 接收者命名

惯例是**接收者名是类型名的首字母小写**（`func (c Counter)`、`func (s *Server)`），且同一类型的所有方法用同一个名字。不用 `this`/`self`——Go 社区认为那暗示了一个并不存在的对象模型。
