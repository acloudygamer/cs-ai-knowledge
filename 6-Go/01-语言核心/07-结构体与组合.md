# 结构体与组合

> 前置：[06-方法与接收者](./06-方法与接收者.md) · 后续：[08-接口](./08-接口.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

`struct` 是**字段的有序集合**，是 Go 里唯一的复合数据构造。它没有构造函数、没有析构函数、没有访问修饰符、没有继承——只有一个字段列表。

Go 用它替代类，靠的是**组合**：把一个 struct 嵌进另一个 struct，得到字段与方法的复用。

**嵌入不是继承。** 这是本篇要反复钉死的一条：

| | 继承（C++/Java） | 嵌入（Go） |
|---|---|---|
| 建立的连接 | 子类型关系：`Dog` **是** `Animal` | 字段关系：`Dog` **有一个** `Animal` |
| 能否出现在要 `Animal` 的位置 | 能 | **不能** |
| 方法调用分派 | 运行时按实际类型（虚函数） | **编译期定死** |
| 能否覆盖（override） | 是，动态分派到子类实现 | 只能**遮蔽**（shadow），不参与动态分派 |

**约束的由来**：Go 的设计者要的是"类型之间的连接可见且局部"。继承让"这个方法是哪来的"需要向上遍历整个类层次；嵌入让它在**同一处源码**可读——被提升的方法就是那个嵌入字段的方法。

## 机制

### 嵌入与方法提升

```go
type Animal struct{ Name string }
func (a Animal) Speak() string { return a.Name + " 发出声音" }
func (a Animal) Kind() string  { return "animal:" + a.Name }

type Dog struct {
	Animal            // 嵌入：字段名 Animal，可省略
	Breed  string
}
```

```console
$ go run .
提升的 Speak(): 旺财 发出声音
遮蔽的 Kind(): dog:柴犬
显式调嵌入者: animal:旺财
```

三行输出各对应一条规则：

1. **方法提升**：`Dog` 没有 `Speak` 方法，`d.Speak()` 被编译器改写成 `d.Animal.Speak()`。
2. **遮蔽**：`Dog` 自己定义了 `Kind`，外层的**遮蔽**嵌入者的。被遮蔽的方法没有消失，仍可用 `d.Animal.Kind()` 显式调用。
3. **字段名省略**：嵌入字段的名字就是类型名，`d.Animal` 是它的完整写法。

**遮蔽不是覆盖**。如果 `Animal` 有方法 `f` 调用了 `a.Kind()`，那么 `d.Speak()` 内部的 `a` 是 `Dog.Animal` 这个**具体的 Animal 值**，调的是 `Animal.Kind` 而非 `Dog.Kind`——没有虚函数表，不存在"回过头分派到外层"。这正是嵌入**不能**用来实现模板方法的原因。

### `Dog` 不是 `Animal`

```go
var a Animal = d        // 编译错误：cannot use d (type Dog) as type Animal
var s Speaker = d       // ✅ Dog 满足 Speaker 接口
```

```console
$ go run .
但 Dog 满足 Speaker 接口: 旺财 发出声音
```

`Dog` 因为方法提升而**恰好拥有** `Animal` 的方法集，因此满足 `Speaker` 接口。但类型系统里 `Dog` 与 `Animal` 之间没有任何关系。

**这条约束的实用含义**：想要多态，必须定义接口（[08-接口](./08-接口.md)）。嵌入提供的是**实现复用**，不是**类型替换**。C++ 程序员初写 Go 最常犯的错就是以为嵌入等于继承，然后发现传参传不过去。

### 字段与方法冲突

外层定义的同名字段或方法**总是**赢；两个嵌入者提供同名方法则**都不提升**——必须显式指定用哪一个：

```go
type A struct{}
func (A) F() string { return "A.F" }

type B struct{}
func (B) F() string { return "B.F" }

type C struct {
	A
	B
}

// c.F()        // 编译错误：ambiguous selector c.F
// c.A.F()      // ✅ 显式
```

**约束**：这是嵌入的设计代价——冲突在**使用处**报错而不是定义处。好处是不同层级的同名方法可以共存（外层遮蔽内层），坏处是深层次的嵌入链要读代码才知道方法来自哪。

### 零值可用性

Go 的惯例是**零值应当可用**。`var buf bytes.Buffer` 不需要初始化就能 `Write`；`var mu sync.Mutex` 直接 `Lock`。判据是：**类型的所有字段都有有意义的零值**。

违反这条的类型需要构造函数，惯例命名为 `NewXxx`：

```go
func NewServer(addr string) *Server {
	s := &Server{addr: addr}
	s.m = make(map[string]bool)   // map 零值是 nil，写入会 panic
	return s
}
```

`make` 出来的 `map`、`chan`、`slice` 是三个零值不可直接使用的类型（map 可读不可写，chan 收发永久阻塞，slice 可 append 但为 nil）。

### 字面量：带字段名与不带

```go
Dog{Animal{"旺财"}, "柴犬"}                    // 位置式：顺序必须与定义一致
Dog{Animal: Animal{Name: "旺财"}, Breed: "柴犬"} // 字段名式
```

**跨包使用的 struct 应当用字段名式**——位置式把字段顺序变成 API 的一部分，加一个字段就破坏所有调用方。`go vet` 的 `composites` 检查会对跨包的位置式字面量报警。

### 内存布局与对齐

struct 的字段按声明顺序排列，编译器插入填充字节让每个字段对齐到自身大小的整数倍：

```console
$ go run .
A{bool;int64;bool} Size=24 Align=8
  偏移: B1=0 I=8 B2=16
B{int64;bool;bool} Size=16 Align=8
  偏移: I=0 B1=8 B2=9
```

`A` 的 24 字节里只有 10 字节是数据：`I` 要求 8 字节对齐，所以 `B1` 后面填了 7 字节；整个 struct 的对齐是 8，所以 `B2` 后面又填了 7 字节。**把 `int64` 挪到最前（类型 `B`）就消掉全部填充，降到 16 字节。**

**但不要为了省内存随便调序**——字段顺序是给读者看的逻辑分组，省下的几字节很少值得牺牲可读性。真正的内存敏感场景（高频分配的小对象）才考虑，且要用 `unsafe.Offsetof` 验证，见 [03-运行时与内存/05](../03-运行时与内存/05-unsafe与内存布局.md)。

**可比较性**：所有字段可比较的 struct 可以用 `==`；含 `slice`/`map`/`func` 字段的 struct 不可比较（编译错误，不是运行时错误）。

## 连接

**上游**：[06-方法与接收者](./06-方法与接收者.md) 的方法集规则决定了嵌入时哪些方法被提升。

**下游**：[08-接口](./08-接口.md) 是 Go 里唯一的动态分派机制，嵌入解决不了的"多态"问题全部由它接管。

**与其它语言对照**：

| | 复用实现 | 多态 |
|---|---|---|
| C++ | 继承 | 虚函数 + 继承 |
| Java | 继承 | 接口 + 继承 |
| **Go** | **嵌入** | **接口（与嵌入无关）** |

Go 把这两件事**拆开**了。C++/Java 里继承同时提供这两样，所以"为了复用而继承"和"为了多态而继承"纠缠在一起；Go 里嵌入只管复用，接口只管多态，两者正交。这是"组合优于继承"这句口号在 Go 里的具体形态。
