# 类型与变量

> 前置：[01-安装与第一个程序](./01-安装与第一个程序.md) · 后续：[03-切片与映射](./03-切片与映射.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

**Go 是静态强类型语言，且不做任何隐式类型转换。**

"静态"指类型在编译期确定；"强"指不同类型的值不能直接混合运算——`int32` 与 `int64` 相加是编译错误，必须显式转换。这一条与 C/C++（隐式整型提升）、JavaScript（隐式装箱转换）、Python（动态类型）都相反。

**约束的由来**：隐式转换是 bug 的温床——C 里 `int` 与 `unsigned` 混算的规则让无数人栽过，JavaScript 的 `"1" + 1 === "11"` 是另一类。Go 的设计者选择了**让编译器拒绝一切有歧义的混合**，代价是代码里会出现大量 `int64(x)` 这样的显式转换。

**变量的本质是"名字绑定到值"**，而 **Go 的类型属于值，不属于名字**——但这与 JavaScript 不同：Go 的绑定在声明时类型就固定了，此后不能改。所以 Go 里"变量"是"一块有确定解释方式的内存"，更接近 Java/C++。

## 机制

### 零值：Go 没有"未初始化"

**每个类型都有一个零值**，声明而未赋值的变量自动取零值——不存在"未定义行为"：

```console
$ go run .
int=0 float=0 string="" bool=false
指针=<nil> 切片=[] map=map[] chan=<nil> 函数=<nil> error=<nil>
结构体={A:0}
```

零值表：

| 类型 | 零值 |
|---|---|
| 数值类型（`int`/`float64`/`complex128`…） | `0` |
| `string` | `""`（空串，**不是 nil**） |
| `bool` | `false` |
| 指针、`func`、`interface`、`chan`、`map`、`slice` | `nil` |
| `struct` | 每个字段各取零值 |
| `array` | 每个元素各取零值 |

**约束**：零值规则是"零值可用"惯例的基础（[07-结构体与组合](./07-结构体与组合.md)）——`var buf bytes.Buffer` 直接能用，`var mu sync.Mutex` 直接能锁。但 `map` 是例外：

```console
$ go run .
map 可读: 0  写入会 panic（nil map）
```

**nil map 可读不可写**。nil slice 则读写都行（`append` 会分配），见 [03-切片与映射](./03-切片与映射.md)。

### 声明：`var` 与 `:=`

| 写法 | 何时用 | 作用域 |
|---|---|---|
| `var x int = 1` | 显式类型 | 函数内或包级 |
| `var x = 1` | 类型推导 | 函数内或包级 |
| `x := 1` | 类型推导，**最常用** | **只能函数内** |
| `var x int` | 只声明，取零值 | 函数内或包级 |

**约束**：`:=` 不能用于包级——包级声明没有"执行"这个动作，只有初始化。另外 `:=` 要求左侧**至少有一个新变量**，其余可以是已存在的（此时是赋值）：

```go
a, b := 1, 2
a, c := 3, 4   // a 被赋值，c 是新变量
// a, b := 5, 6   // 编译错误：no new variables on left side of :=
```

### 常量与 `iota`

```console
$ go run .
iota: Sun=0 Mon=1 Tue=2 Wed=3
String(): 一 二
```

`iota` 在 `const` 块内从 0 开始，**每换一行加 1**。它是"枚举"在 Go 里的替身——Go 没有 `enum` 关键字。

**约束**：Go 的常量是**编译期常量**，只能是基本类型的字面量与常量表达式。不能是函数调用结果、不能是运行时值。因此 `iota` 生成的"枚举"**没有封闭性**——`Weekday(999)` 是完全合法的值，编译器不检查范围。需要校验时自己写 `Valid()` 方法。

`Weekday` 上的 `String()` 方法让它满足 `fmt.Stringer`（[08-接口](./08-接口.md)），因此 `fmt.Println(Mon)` 输出 `一` 而不是 `1`。这是 Go 枚举惯例：**自定义类型 + `iota` + `String()`**。

### 无类型常量

```console
$ go run .
无类型常量可赋任意类型: 10 10
```

`const c = 10` 声明的是**无类型常量**——它没有具体类型，可以赋给 `int32`、`float64` 或任何能容纳 10 的数值类型。这是 Go 常量系统的一个特例，用来让 `math.Pi` 这类常量能用在各种精度的上下文里。

**约束**：无类型常量转成具体类型时**必须精确**：

```console
$ go build ./...
.\main.go:63:32: cannot convert 3.9 (untyped float constant) to type int
```

`int(3.9)` 是编译错误，因为 3.9 无法精确表示为 `int`。但**变量**转就行，走的是截断：

```console
$ go run .
变量转换则截断: int(3.9) = 3  int(-3.9) = -3
```

**负数向零截断**（不是向下取整），这是 IEEE 754 与 Go 转换规则共同决定的。

### 类型别名 vs 自定义类型

```console
$ go run .
别名可赋给 int: 2
自定义类型要显式转换: 3
别名 Sizeof=8  自定义 Sizeof=8
```

| | 写法 | 与源类型的关系 | 能否定义方法 |
|---|---|---|---|
| **类型别名** | `type A = int` | **完全相同**，`A` 就是 `int` 的另一个名字 | **不能**（它就是 `int`） |
| **自定义类型** | `type N int` | 新类型，底层类型是 `int` | **能** |

两者 `unsafe.Sizeof` 都是 8——自定义类型**不增加存储开销**，只是让类型系统把它当作另一个类型。这带来的是编译期隔离：`NewInt(2) + 1` 编译不过，必须先 `int(n)`。

**约束**：只有自定义类型能定义方法（[06-方法与接收者](./06-方法与接收者.md)）。泛型的 `~int` 约束匹配的是"底层类型为 int"的类型，因此 `NewInt` 满足 `~int` 而 `AliasInt` 与 `int` 是同一个类型（[09-泛型](./09-泛型.md)）。

### 指针：没有算术

```console
$ go run .
指针解引用: 42 → 通过 *pp 改写后 v = 100
```

`&v` 取地址，`*pp` 解引用。**Go 指针不支持算术**——没有 `p+1`，没有指针与整数的加减。这是与 C/C++ 的关键分野，也是 Go 能在语言层面保证内存安全的原因之一（另一部分靠 GC 与切片边界检查）。

**约束**：取地址要求**值可寻址**。map 元素、函数返回值、字面量都不可寻址（[06-方法与接收者](./06-方法与接收者.md) 给了实测的报错）。要操作它们只能先存进变量。

**边界**：需要指针算术的场景（序列化、底层协议解析）用 `unsafe.Pointer`，代价是放弃内存安全保证（[03-运行时与内存/05](../03-运行时与内存/05-unsafe与内存布局.md)）。

**与其它语言对照**：

| | 隐式转换 | 零值 | 未初始化变量 |
|---|---|---|---|
| C/C++ | 大量（整型提升、指针隐式转换） | 不确定 | **未定义行为** |
| Java | 窄化需显式，宽化自动 | 有（对象是 null） | 成员变量有零值，局部变量报错 |
| JavaScript | 大量（`==` 与 `+`） | 有（`undefined`） | `undefined` |
| **Go** | **无** | **有，且类型确定** | **零值，无未定义行为** |

Go 在"零值"这一列与 C/C++ 差别最大：C 的局部变量不初始化，读它是未定义行为，这是无数安全漏洞的源头。Go 用"每个类型都有零值 + 声明即初始化"从语言层面消除了这一整类问题。
