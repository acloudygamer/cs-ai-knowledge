# 包与可见性

> 前置：[10-错误处理](./10-错误处理.md) · 后续：[02-标准库](../02-标准库/)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

**包（package）是 Go 的封装单位与编译单位**——它是可见性的边界、是编译并行的边界、是依赖图的节点。

Go 的可见性规则只有一条：

> **标识符首字母大写 = 导出（包外可见）；小写 = 不导出（仅包内可见）。**

**约束的由来**：这是 Go 里最反直觉的一条设计，值得单独交代。C++/Java/Python 用关键字或命名约定来**标记**可见性（`public`/`private`、`_name`），Go 把它**编码进了标识符本身**。换来的东西：

| | 关键字式 | Go 的字母大小写式 |
|---|---|---|
| 读代码时判断可见性 | 要看声明处 | **看名字就知道** |
| 能否局部放宽 | 可以（嵌套作用域） | 不能 |
| 与拼写的耦合 | 无 | **强耦合**——改可见性要改所有引用点 |

**代价是真实存在的**：把 `foo` 改成 `Foo` 会改变 API，且要改所有调用点。收益是**任何一处 `pkg.X` 都能立刻判断 X 是不是这个包的公开 API**，不需要跳转定义。

**边界**：可见性的粒度**只有两级**——导出与不导出。没有 `protected`、没有 `internal` 之外的分级、没有友元。需要更细的隔离时，只能靠**拆包**。

## 机制

### 导出规则

```go
package mathutil

func Add(a, b int) int { return addImpl(a, b) }   // 导出
func addImpl(a, b int) int { return a + b }        // 不导出

var Version = "1.0"     // 导出
var counter int         // 不导出

type helper struct{ n int }   // 不导出类型

type Calculator struct {
	Name string   // 导出字段
	seed int      // 不导出字段
}
```

包外访问非导出标识符的报错是两种：

```console
$ go build ./...
app\bad.go:6:11: name addImpl not exported by package mathutil
app\bad.go:7:15: undefined: mathutil.counter
```

**函数报"未导出"，变量报"未定义"**——后者是因为不导出的变量在包外**根本不进入符号表**，看起来就像不存在。这个差别对排查有帮助：`undefined` 说明名字不可见，`not exported` 说明名字可见但权限不够。

**约束**：字段级可见性独立于类型级。`Calculator` 是导出类型，但 `seed` 字段不导出——包外能拿到 `*Calculator`、能调 `Double()`，**不能直接读写 `seed`**。这是 Go 实现封装的主要手段：**用不导出字段 + 导出方法控制不变式**。

**边界**：不导出字段**不能参与**跨包的 struct 字面量构造（`mathutil.Calculator{seed: 1}` 编译不过），所以这类类型必须提供构造函数（`NewCalculator`，见 [09-设计模式/02](../09-设计模式/02-创建型.md)）。同时不导出字段也**不能**被 `encoding/json` 序列化（[02-标准库/05](../02-标准库/05-序列化与编码.md)）。

### 包名、导入路径、模块路径

三者是不同的东西，初学最易混淆：

```console
$ go list -f '{{.ImportPath}} -> package {{.Name}}' ./...
example/demo/app              -> package main
example/demo/internal/secret  -> package secret
example/demo/mathutil         -> package mathutil
```

| | 例子 | 是什么 | 谁决定 |
|---|---|---|---|
| **模块路径** | `example/demo` | 模块的全局唯一名 | `go.mod` 的 `module` 行 |
| **导入路径** | `example/demo/mathutil` | 模块路径 + 目录相对路径 | 目录结构 |
| **包名** | `mathutil` | 源码里 `package` 后的名字 | 源码第一行 |

**三者的默认关系是"包名 = 目录名"**，但这是**约定不是规则**——目录叫 `mathutil` 而包名是 `math` 完全合法。`import "example/demo/mathutil"` 之后，代码里用的是 `math.Add`。

**约定**：包名应当短、全小写、无下划线、无驼峰。因为**每次使用都要写**——`mathutil.Add` 不如 `math.Add`。标准库的包名都是单词（`fmt`、`io`、`http`、`json`）。

**别名与点导入**：

```go
import (
	mrand "math/rand"        // 别名，解决重名
	_ "github.com/lib/pq"    // 空白导入：只为副作用（驱动注册）
	. "fmt"                  // 点导入：不加前缀直接用
)
```

`_` 空白导入的用途是**触发包的 `init()`**——`database/sql` 的驱动就是靠这个注册自己（[05-IO与外部世界/04](../05-IO与外部世界/04-数据库访问.md)）。点导入破坏可读性，标准库自己从不使用。

### `internal/`：模块内的额外一层

**`internal` 是一个保留目录名**，它下面的包只能被**以 `internal` 的父目录为根的子树**导入：

```console
$ go build ./...        # 在另一个模块 example/outside 里
main.go:6:2: use of internal package example/demo/internal/secret not allowed
```

规则是：路径中最后一个 `internal` 之前的目录是可见性根，只有**该根目录下的代码**能导入它。

| 导入路径 | 谁能导入 |
|---|---|
| `example/demo/internal/secret` | 只有 `example/demo/` 子树内的包 |
| `example/internal/x` | 只有 `example/` 子树内的包 |

**约束**：`internal` 给的是**比"不导出标识符"粗、比"独立仓库"细**的一级隔离——整个包对外部隐藏，而不只是某些符号。这是 Go 唯一的分级可见性机制（见 [06-工程与工具链/04](../06-工程与工具链/04-项目布局.md) 里的目录布局建议）。

### 循环导入禁令

```console
$ go build ./...
package example/demo/cyc/a
	imports example/demo/cyc/b from a.go
	imports example/demo/cyc/a from b.go: import cycle not allowed
```

**Go 禁止循环导入**，编译期报错。报错信息会把整条环打出来。

**约束的由来**：这条禁令换来两样东西——

1. **编译顺序无歧义**：导入图是 DAG，可以直接拓扑排序后并行编译（[00-概览/01](../00-概览/01-Go全景.md) 里编译速度的来源之一）。
2. **包级初始化的顺序确定**（见下）。

**代价**：真实系统里确实存在双向依赖，只能靠**拆包**解决——把双方共同依赖的部分抽到第三个包，或者把一方改成接口（接口在 Go 里可以定义在**使用方**，天然打破环，[08-接口](./08-接口.md)）。

### `init()` 与初始化顺序

```console
$ go run ./initorder
  p1 变量初始化
  p1 init()
  p2 init()（导入 p1，V = 1 ）
  main()
```

顺序由规则确定，**从叶子到根**：

1. 被导入的包先于导入者初始化（`p1` 先于 `p2`，`p2` 先于 `main`）。
2. 同一个包内：**包级变量按声明顺序初始化**，然后才跑 `init()`。
3. 同一个包可以**有多个 `init()`**（甚至在多个文件里），按文件名的字典序执行。

**约束**：`init()` 不能被显式调用，也不接收参数、不返回错误。这意味着**它无法报告失败**——初始化失败只能 panic 或记日志。这就是为什么很多库宁可提供显式的 `Setup()` 函数也不写 `init()`：显式调用能返回 `error`。

**边界**：`init()` 的执行发生在 `main()` 之前，因此**它是单线程的**——在 `init()` 里起 goroutine 要小心，此时运行时的调度器已就绪但程序还没开始跑业务。

**与其它语言对照**：

| | 封装单位 | 可见性机制 | 分级 |
|---|---|---|---|
| Java | 类 | `public`/`protected`/包私有/`private` | 4 级 |
| C++ | 类 + 命名空间 | `public`/`protected`/`private` + 友元 | 3 级 + 友元 |
| Python | 模块 | 约定（`_` 前缀）+ `__all__` | 约定，无强制 |
| **Go** | **包** | **首字母大小写** | **2 级 + `internal`** |

Go 的封装单位是**包而不是类型**——这是它与 Java/C++ 最根本的差别。`private` 在 Java 里是"只有这个类能看"，在 Go 里对应的概念不存在：同一个包内的所有类型互相完全可见，没有类型级的私有。**包是 Go 里最小的封装单元**，这也是为什么 Go 项目里包的数量通常比 Java 项目里类的数量少得多、每个包也更大。
