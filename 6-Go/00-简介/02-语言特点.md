# Go 语言特点

## 本质断言

Go 是通过 CSP 模型和 GMP 调度器实现原生并发的静态类型语言——类型安全与简洁语法并存，协程间通信无需显式锁。

## 核心概念

1. **静态类型 + 类型推导** — 安全与简洁并存，编译器拦住类型错误
2. **goroutine 原生并发** — 轻量级协程，数十万并发轻松支持
3. **channel** — CSP 模型，goroutine 之间的通信桥梁，无需锁
4. **组合优于继承** — 显式依赖，小单元组合成大系统

## GMP 调度模型

<pre>
┌──────────────────────────────────────────────────────┐
│                      OS                              │
│  ┌────────┐  ┌────────┐  ┌────────┐                  │
│  │  M₁   │  │  M₂   │  │  M₃   │   M = Machine     │
│  └───┬────┘  └───┬────┘  └───┬────┘     (OS线程)   │
│      │           │           │                       │
│  ┌───▼────┐  ┌───▼────┐  ┌───▼────┐                 │
│  │  P₁   │  │  P₂   │  │  P₃   │   P = Processor  │
│  └───┬────┘  └───┬────┘  └───┬────┘     (上下文)    │
│      │           │           │                       │
│  ┌───▼──┐   ┌───▼──┐   ┌───▼──┐                     │
│  │G₁ G₂│   │G₃ G₄│   │G₅ G₆│   G = Goroutine    │
│  └─────┘   └─────┘   └─────┘                        │
└──────────────────────────────────────────────────────┘
</pre>

- **M（Machine）** — OS 线程，物理执行单元
- **P（Processor）** — Go 运行时上下文，管理 goroutine 队列
- **G（Goroutine）** — 轻量级协程，用户态调度

### 工作窃取

空闲 P 从其他 P 的队列尾部偷取 G，实现负载均衡。

## channel 机制

### 为什么 channel 无需锁

channel 的发送和接收在同一个 P 上串行执行，Go 运行时保证操作的原子性，无需程序员加锁。

```go
ch := make(chan int, 10)
go func() { ch <- 1 }()
v := <-ch
```

## 设计哲学

Go 偏好显式而非隐式，简洁而非复杂。"Go 的设计就是让程序员少做蠢事。" — Rob Pike

### 核心原则

| 原则 | 含义 |
|------|------|
| 简单 | 减少关键字，只保留必要特性 |
| 可读 | 代码即文档，注释辅助理解 |
| 显式 | 明确错误处理，拒绝隐藏行为 |
| 组合 | 小单元组合成大系统 |

### 争议与取舍

| 舍弃特性 | 设计原因 |
|----------|----------|
| 类继承 | 组合更灵活，避免菱形继承 |
| 异常 | 错误作为返回值，显式处理更安全 |
| 断言 | 避免运行时类型转换的隐患 |
| 泛型（早期） | 保持语法简洁（1.18 已加入） |

## 其他显著特点

- **编译极快** — 增量编译，秒级全量构建
- **垃圾回收** — 自动内存管理，告别手动分配/释放
- **标准库丰富** — net/http、encoding/json、os 等开箱即用
- **部署简单** — 静态编译，单个可执行文件，无依赖
