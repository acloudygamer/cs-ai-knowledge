# 你好，世界！

## 本质断言

Go 程序以 `package main` 声明入口包，`func main()` 定义程序执行起点，静态编译为单一可执行文件——运行时从 OS 加载二进制到 goroutine 调度，main goroutine 是用户代码的第一执行入口。

## 数学模型

### 程序启动时间的分解

Go 程序从执行到 main() 的总时间 $T_{start}$：

$$T_{start} = T_{load} + T_{link} + T_{runtime\_init} + T_{main\_init} + T_{main}$$

其中：
- $T_{load}$ = 二进制从磁盘加载到内存
- $T_{link}$ = 动态链接（静态编译模式下为 0）
- $T_{runtime\_init}$ = 运行时初始化（调度器、GC、netpoll 等）
- $T_{main\_init}$ = main 包级变量的初始化

**典型值**：Go 程序启动时间约 1-5ms，远低于 JVM 启动（~500ms）。

### 编译产物大小的约束

静态编译的二进制大小 $S_{binary}$ 由以下因素决定：
- 运行时（runtime）：~1.5MB（基础运行时）
- 反射（reflect）：~500KB
- 调试信息（-s -w 剥离后）：可忽略

总计：最小可执行文件 ~2MB。

## 机制

### 为什么 Go 强制格式化

Go 使用 gofmt 强制统一代码风格，消除了**风格争论**这一无意义的协作成本。

gofmt 的核心规则：
- 缩进使用 Tab（而非空格）
- 行宽 80 字符
- 保留注释风格

代码风格不是个人偏好，而是**协作基础设施**。强制格式化让 code review 聚焦于逻辑，而非格式。

### 为什么 Go 选择静态编译

Go 编译产物是**单一可执行文件**，这使得：

1. **部署极简**：无需关心目标机器是否安装了运行时
2. **Docker 镜像可极小**：`FROM scratch` 无需运行时层
3. **版本一致**：构建时确定的依赖，运行时不可变

**数学约束**：静态编译消除了运行时动态链接的**PLT/GOT 查找开销**，函数调用路径更短。

### 为什么入口必须是 package main

Go 以包为编译单元，`package main` 告诉编译器这个包需要生成**可执行文件**（而非库）。

其他包不能独立运行，只能作为依赖被 main 包引用。

main 包的存在使项目结构清晰：**可执行项目的入口必然是 main 包 + main 函数**。

### 为什么 Go 没有动态链接支持（默认）

Go 默认静态链接的好处：
- **安全**：无外部依赖，无 DLL 劫持风险
- **隔离**：运行时行为完全确定
- **简单**：部署就是复制文件

代价：
- 多个 Go 程序无法共享运行时内存
- 镜像体积较大（~5-10MB vs ~1MB 动态链接）

## 参考代码

```go
package main

import "fmt"

func main() {
    fmt.Println("你好，世界！")
}
```

运行：

```bash
go run hello.go
# 输出：你好，世界！
```

## 参考存根

```go
// 运行时入口：src/runtime/rt0_go.s
// _rt0_go 函数是真正的入口
TEXT _rt0_go(SB),NOSPLIT,$0
    CALL    runtime·check(SB)      // 类型检查
    CALL    runtime·args(SB)        // 命令行参数
    CALL    runtime·osinit(SB)       // OS 初始化
    CALL    runtime·schedinit(SB)    // 调度器初始化
    CALL    runtime·mstart(SB)       // 启动主线程

// main 包初始化后调用 main.main()
CALL    main·main(SB)
```
