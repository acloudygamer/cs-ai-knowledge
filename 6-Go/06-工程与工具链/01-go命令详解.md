# go 命令详解

> 前置：[01-语言核心](../01-语言核心/) · 后续：[02-模块与依赖管理](./02-模块与依赖管理.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

**`go` 是一个多合一工具，19 个子命令全部是同一个可执行文件。**

```console
$ go help
The commands are:

	bug         start a bug report
	build       compile packages and dependencies
	clean       remove object files and cached files
	doc         show documentation for package or symbol
	env         print Go environment information
	fix         apply fixes suggested by static checkers
	fmt         gofmt (reformat) package sources
	generate    generate Go files by processing source
	get         add dependencies to current module and install them
	install     compile and install packages and dependencies
	list        list packages or modules
	mod         module maintenance
	run         compile and run Go program
	telemetry   manage telemetry data and settings
	test        test packages
	tool        run specified go tool
	version     print Go version
	vet         report likely mistakes in packages
	work        workspace maintenance
```

**约束的由来**：这 19 个命令在其它语言里对应的是**至少四套独立的工具链**——

| 职责 | Go | Java | JavaScript |
|---|---|---|---|
| 构建 | `go build` | Maven / Gradle | webpack / vite |
| 测试 | `go test` | JUnit + Surefire | Jest / Vitest |
| 格式化 | `go fmt` | spotless / google-java-format | Prettier |
| 静态检查 | `go vet` | SpotBugs / Error Prone | ESLint |
| 依赖管理 | `go mod` | Maven / Gradle | npm / pnpm |
| 文档 | `go doc` | Javadoc | TypeDoc |
| 代码生成 | `go generate` | 各种插件 | 各种 codegen |

**Go 把它们全放进一个二进制**，因此不需要"配置构建工具"这一层——`go build` 在任何一个 Go 项目里都能工作，不依赖 `pom.xml`/`package.json` 里声明的插件版本。这是 [README](../README.md) 里"工具链是一个二进制"那条依据的具体形态。

**边界**：`go` 命令的**参数风格是"子命令 + 标志"**，且**标志位置有讲究**——`go build -o out ./...` 里 `-o` 必须在内核参数之前。这与多数 Unix 工具一致，但 `go test` 有特殊性：`go test -v ./...` 里的 `-v` 是 `go test` 自己的标志，而 `go test ./... -v` 会把 `-v` 传给**测试二进制**。

## 机制

### 三个最常用的命令

| 命令 | 产物 | 用途 |
|---|---|---|
| `go run .` | **无**（在 `GOCACHE` 里，用完不管） | 开发时快速试 |
| `go build -o app .` | 可执行文件 | 要拿到产物 |
| `go build ./...` | 无（只校验） | 检查整个模块能否编译 |

**`./...` 是包模式**——表示"当前目录及其所有子目录里的包"。`...` 可以出现在任何位置（`./internal/...`、`example.com/mod/...`）。

**约束**：**`go run` 不适合反复运行**——每次都要查构建缓存、命中就复制到临时文件。**反复跑同一个程序时 `go build` 一次再直接执行二进制更快**。

### `go vet`：35 个分析器

`go vet` 是**编译器的补充**——它检查编译器不管但几乎肯定是 bug 的写法。

```console
$ go vet ./...
bad.go:16:9: Bad passes lock by value: vet1.S contains sync.Mutex
bad.go:20:14: fmt.Printf format %d has arg "not a number" of wrong type string
bad.go:37:9: conversion from int to string yields a string of one rune, not a string of digits
bad.go:32:28: 2006-02-01 should be 2006-01-02
```

四条实测输出，各自对应一个分析器：

| 分析器 | 检查什么 | 上面命中的写法 |
|---|---|---|
| `copylocks` | 复制含锁的值 | 值接收者 `func (s S) Bad()`，`S` 含 `sync.Mutex` |
| `printf` | 格式串与参数匹配 | `fmt.Printf("%d\n", "not a number")` |
| `stringintconv` | `string(int)` 转换 | `string(i)` 得到的是**一个 rune**，不是数字字符串 |
| `timeformat` | 参考时间写错 | `2006-02-01` 应为 `2006-01-02` |

完整清单（`go tool vet help` 的 `Registered analyzers`，共 35 个）里几个高频的：

| 分析器 | 捕获 |
|---|---|
| `lostcancel` | `context.WithCancel` 的 cancel 没被调用（[04-并发/04](../04-并发/04-context与取消传播.md)） |
| `loopclosure` | 闭包捕获循环变量（Go 1.22 前是 bug，现在是提示） |
| `errorsas` | `errors.As` 传了非指针 |
| `unmarshal` | `json.Unmarshal` 传了非指针 |
| `structtag` | struct tag 格式错误 |
| `atomic` | `sync/atomic` 的常见误用 |
| `httpresponse` | HTTP 响应体没关 |
| `waitgroup` | `sync.WaitGroup` 误用 |
| `slog` | `log/slog` 调用不合法 |
| `stdversion` | **使用了比 `go.mod` 声明更新的标准库符号**（Go 1.27 起 `go test` 默认启用） |

**约束**：`go vet` **默认只跑"高置信度"的分析器**，且**不保证没有误报**——它的定位是"启发式检查"。因此 `go vet` 的失败**应当修**，但不该当成编译错误对待（有些项目会选择性忽略个别分析器）。

**`stdversion` 是 Go 1.27 的变化**：`go test` 现在默认运行它。这会在升级工具链但未升级 `go.mod` 指令时报警——是好事（防止无意中用新符号），但升级时需要批量处理。

### `go fmt` 与 `gofmt`

```console
$ gofmt -l .
ugly.go

$ gofmt -d ugly.go
-type  User  struct{
-Name string
-   Age    int
-}
+type User struct {
+	Name string
+	Age  int
+}
```

| 命令 | 范围 |
|---|---|
| `gofmt -w .` | 格式化当前目录的文件 |
| `go fmt ./...` | 格式化指定包里的文件（内部就是调 `gofmt`） |
| `gofmt -l .` | **只列出**需要格式化的文件（CI 用） |

**约束的由来**：Go **强制统一的代码风格**，且**不提供任何配置项**——没有缩进宽度选项、没有大括号位置选项、没有空行策略选项。这与 Prettier/ESLint（配置项成百上千）相反。

**收益**：任何 Go 代码在任何项目里看起来一样，代码评审不需要讨论格式。**代价**：团队无法保留自己的风格偏好——这是有意的取舍。

**`gofmt -l .` 的退出码是 0**（即使列出了文件），所以 CI 里要这样用：

```bash
test -z "$(gofmt -l .)" || { gofmt -l .; exit 1; }
```

**边界**：`gofmt` 只管**格式**，不管**风格**。`goimports`（`golang.org/x/tools/cmd/goimports`）在 `gofmt` 之上加了**导入的自动增删与分组**（标准库 / 第三方 / 本项目三段），是事实标准（[03-代码质量工具](./03-代码质量工具.md)）。

### `go fix`：自动迁移

```console
$ go fix ./...
```

`go fix` 会应用一批**已注册的现代化改写规则**（modernizers）。Go 1.27 的规则集包括：

| 规则 | 做什么 |
|---|---|
| `atomictypes` | 旧的 `atomic.AddInt64(&x, 1)` → 类型化的 `x.Add(1)` |
| `embedlit` | `//go:embed` 的写法现代化 |
| `slicesbackward` | 手写倒序循环 → `slices.Backward` |
| `unsafefuncs` | `reflect.StringHeader` 用法 → `unsafe.String`/`unsafe.Slice`（[03-运行时与内存/05](../03-运行时与内存/05-unsafe与内存布局.md)） |
| `waitgroupgo` | `wg.Add(1); go func(){...}()` → `wg.Go(...)`（Go 1.25 起，[04-并发/01](../04-并发/01-goroutine与生命周期.md)） |

**约束**：`go fix` **只做语义等价的改写**，不做重构。它是升级工具链时的第一批动作——**跑一遍 `go fix` 再跑测试**，能省掉大量手工替换。

**注意 Go 1.27 里 `fmtappendf` 被移除、`waitgroup` 改名为 `waitgroupgo`**——规则集本身也在演进。

### `go doc`：查文档

```console
$ go doc sync.WaitGroup
$ go doc -all encoding/json
$ go doc net/http.Handler
```

`go doc` **在本地从源码生成文档**，不需要网络。Go 1.27 新增两处能力：

- **`go doc package@version`**：查指定版本模块的文档（如 `go doc example.com/pkg@v1.2.3`）
- **`-ex` 标志**：列出并打印可执行示例

**判据**：查标准库用 `go doc` 比开浏览器快得多——它在终端里直接输出，且**版本与当前工具链完全一致**（网上文档可能对应别的版本）。

### `go list`：查询包与模块

```console
$ go list -deps . | wc -l
65
$ go list std | wc -l
385
$ go list -f '{{.ImportPath}} -> package {{.Name}}' ./...
example/demo/app              -> package main
example/demo/internal/secret  -> package secret
example/demo/mathutil         -> package mathutil
```

`go list` 是**结构化查询工具**——`-f` 接受 Go 的 `text/template` 语法，能提取任意字段。用途：

| 场景 | 命令 |
|---|---|
| 看依赖闭包大小 | `go list -deps . \| wc -l` |
| 找出所有测试文件 | `go list -f '{{.TestGoFiles}}' ./...` |
| 找没有测试的包 | `go list -f '{{if not .TestGoFiles}}{{.ImportPath}}{{end}}' ./...` |
| 看编译目标平台 | `go list -f '{{.Target}}' .` |

**约束**：`go list` 的输出是**给脚本用的**，格式在不同 Go 版本间可能变化（字段可能新增）。要稳定输出用 `go list -json`。

### `go generate`：代码生成入口

```go
//go:generate stringer -type=Weekday
//go:generate protoc --go_out=. api.proto
```

`go generate` 会**执行源码里的 `//go:generate` 指令**。

**约束**：`go generate` **不由 `go build` 触发**——必须显式运行。这是有意的：**构建不该有副作用**，代码生成是显式的开发动作，生成的文件应当被提交（或在 CI 里生成后校验一致性）。

**边界**：`go generate` 依赖注释里写的命令行工具，而**它不管理这些工具的安装**。`tools.go` 是常见解法——建一个只 import 工具包、带 `//go:build tools` 约束的文件，让 `go mod` 把它们记进依赖（[02-模块与依赖管理](./02-模块与依赖管理.md)）。

### `go clean` 与构建缓存

| 命令 | 清什么 |
|---|---|
| `go clean -cache` | **构建缓存**（`GOCACHE`） |
| `go clean -modcache` | 模块缓存（`GOMODCACHE`） |
| `go clean -testcache` | 测试结果缓存 |

**约束**：`go clean -cache` 会让下次构建从 0.677s 变成 5.382s（[00-概览/01](../00-概览/01-Go全景.md) 的实测）。**除非排查缓存导致的怪问题，否则不要清**。

**测试结果也会被缓存**——同一个包的测试在源码和依赖都没变时，`go test` 直接返回上次的结果（输出里带 `(cached)`）。`-count=1` 可以强制重跑。

### `go telemetry`

Go 1.23 起引入了遥测（默认关闭，本地记录，用户显式 `go telemetry on` 才上传）。`go telemetry status` 查看状态。

**约束**：**默认是 `local`**——数据只写在本地，不上传。要上传必须显式 `go telemetry on`。

**与其它语言对照**：

| | 工具数量 | 配置 |
|---|---|---|
| Java | Maven + Surefire + Spotless + SpotBugs + Javadoc | 每个都要 XML/插件配置 |
| JavaScript | npm + webpack + jest + prettier + eslint | 每个都要独立配置文件 |
| **Go** | **1 个二进制，19 个子命令** | **几乎零配置** |

**"几乎零配置"是 Go 工具链最关键的性质**。一个新项目只需要 `go mod init` 就能 `build`/`test`/`fmt`/`vet`——没有 `pom.xml`、没有 `package.json` 的 `scripts` 段、没有 `.eslintrc`。代价是**灵活性低**：想换测试框架、想改格式化规则、想加自定义构建步骤，都要绕过工具链自己实现。
