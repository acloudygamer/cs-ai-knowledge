# 创建型模式

> 前置：[01-设计模式总览](./01-设计模式总览.md) · 后续：[03-结构型](./03-结构型.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

创建型模式回答三个问题：**对象什么时候创建**（延迟到第一次用，还是启动时全建好）、**由谁创建**（调用方自己 `new`，还是交给一个工厂）、**创建多少个**（每次都要新的，还是全局只有一个、还是复用池子里的）。

这三个问题的答案在 Go 里都由**包级作用域**决定，而不是由类层次决定。C++ 的单例靠"私有构造 + 静态成员"把创建权锁进类里；Go 没有类，但**包级变量天然是私有的**——包外看不见，包内只有一个。这条差异让 Go 的创建型模式普遍比 C++ 短一半。

## 机制

### 单例：包级变量 + `sync.Once`

Go 的包级变量是**惰性**的吗？不是——包初始化时全部执行（[01-语言核心/11](../01-语言核心/11-包与可见性.md)）。要延迟到第一次使用，用 `sync.Once`：

```go
var (
	once     sync.Once
	instance *Config
	built    atomic.Int64
)

func GetConfig() *Config {
	once.Do(func() {
		built.Add(1)
		instance = &Config{Name: "prod"}
	})
	return instance
}
```

并发 100 次调用，构造函数只跑一次：

```console
$ go run .
once 构造次数 = 1
```

**`sync.Once` 保证的是"恰好一次"（exactly once），不是"至多一次"**：如果 `Do` 里的函数 panic，`Once` 会认为它没执行过，下次调用会重跑。这是有意的——否则一次失败的初始化会让整个程序永久不可用。

**约束**：`once.Do` 的第一个 goroutine 会持锁执行 `f`，其余全部阻塞等待。所以 `f` 里**不能调用 `GetConfig()` 自身**——会死锁。同理，`f` 里的耗时操作会阻塞所有调用方，初始化该快就快。

**边界**：全局单例的代价是**测试不可替换**。需要替换时用依赖注入（[08-生态与框架/05](../08-生态与框架/05-依赖注入.md)）——把 `*Config` 当参数传进去，而不是让每个函数去调 `GetConfig()`。

### 建造者：分步构造 + 链式返回

当一个对象有大量可选字段、且字段之间没有依赖顺序时，构造函数的参数列表会爆炸。建造者把"设置字段"和"取出对象"分开：

```go
func (b *QueryBuilder) Select(cols ...string) *QueryBuilder {
	b.q.cols = append(b.q.cols, cols...)
	return b
}
func (b *QueryBuilder) Build() Query { return b.q }
```

```console
$ go run .
建造者: SELECT id, name FROM users WHERE age > 18
建造者(无 where): SELECT * FROM logs
```

关键在 `Build()` **返回的是值不是指针**——`Query` 构造完就不可变了，建造者后续再改也不影响已产出的 `Query`。这是建造者与"暴露字段的 struct"的实质区别：前者能保证产出物不可变，后者不能。

**在 Go 里建造者用得比函数式选项少**（见 [总览](./01-设计模式总览.md) 的实测对比）。判据是：**字段之间有依赖或需要顺序时用建造者**（比如 SQL 必须先 `FROM` 再 `WHERE`），**只是"可选参数太多"时用函数式选项**。

### 工厂：一个返回接口的函数

```go
func NewStore(kind string) (Store, error) {
	switch kind {
	case "mem":
		return &memStore{m: map[string]bool{}}, nil
	case "file":
		return &fileStore{path: "/tmp/data"}, nil
	}
	return nil, fmt.Errorf("未知存储类型 %q", kind)
}
```

```console
$ go run .
工厂 mem: true <nil>
工厂 file:
  fileStore 落盘 -> /tmp/data
工厂 未知: 未知存储类型 "redis"
```

**返回 `Store`（接口）而不是 `*memStore`（具体类型）**，这是工厂的要点：调用方拿不到 `memStore` 的内部字段，也就无法绕过接口。代价是调用方也看不到具体类型特有的方法——这正是工厂想要的封装。

**注意返回的是 `(Store, error)` 而不是单个值**。Go 没有异常（[01-语言核心/10](../01-语言核心/10-错误处理.md)），"工厂无法产出对象"必须作为一个返回值显式交给调用方。C++ 里这可以抛异常，Go 里不行。

**约束**：工厂函数名惯例是 `NewXxx`，且**应该返回接口**——但这条不是铁律。Go 社区有一句反过来的忠告："*返回具体类型，接受接口*"（return concrete types, accept interfaces）。理由是调用方能用到具体类型的方法，接口可以在使用处再定义。两种做法都成立，分歧点是：**这个类型是否真的会被多种实现替换**。会，就用工厂返回接口；不会，就直接返回 struct。

### 对象池：`sync.Pool`

```go
var bufPool = sync.Pool{New: func() any { return new(strings.Builder) }}

func render(n int) string {
	b := bufPool.Get().(*strings.Builder)
	defer func() { b.Reset(); bufPool.Put(b) }()
	...
}
```

```console
$ go run .
Pool 结果: item-0;item-1;item-2;
```

`sync.Pool` 复用临时对象，减少 GC 压力。**但它不保证命中**——池里的对象随时可能在任意一次 GC 中被清空（[03-运行时与内存/03](../03-运行时与内存/03-垃圾回收.md)）。因此它只适合"**可重新构造、构造成本高于复用收益**"的临时缓冲，不能当缓存用。

**约束**：`Pool` 里存的对象**不能携带调用方可见的状态**——`Get` 到的对象可能是别人用过的。上面的 `defer` 里先 `Reset()` 再 `Put` 就是这个道理。忘了 `Reset` 会把上一位用户的数据泄漏给下一位。
