# 设计模式总览

> 前置：[01-语言核心](../01-语言核心/) · 后续：[02-创建型](./02-创建型.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64，Intel i7-10750H。

## 本质

**设计模式是语言的补丁集**——它记录的是"这门语言缺什么，所以只能这么绕"。

这个定义不是修辞。GoF 那本《设计模式》（1994）的 23 个模式，绝大多数是 **C++ 的补丁**：C++ 没有一等函数，所以"把算法当参数传"要写成策略模式的类层次；C++ 没有闭包，所以"给对象加行为"要写成装饰器模式的包装类；C++ 的 `for` 不认识自定义容器，所以"遍历聚合"要写成迭代器模式的 `First`/`Next`/`IsDone`。

**语言特性会吞掉模式。** 一条新特性进语言，对应的一批模式就退化成一行语法。Go 吞掉的尤其多，因为它在三处做了与 C++ 相反的选择：

| 模式 | 在 C++ 里是 | 在 Go 里退化成 | 依据 |
|---|---|---|---|
| 策略 | 抽象基类 + 子类族 | 一个函数值 | 函数是一等值 |
| 工厂方法 | 虚函数 + 子类覆盖 | 一个返回接口的函数 | 函数是一等值 |
| 迭代器 | `First`/`Next`/`IsDone` 协议 | `for range` / `iter.Seq` | 语言内建 |
| 模板方法 | 基类定义骨架 + 子类填洞 | 接受函数参数的高阶函数 | 函数是一等值 |
| 适配器 | 多重继承 + 包装类 | 一个只做转发的 struct | 接口隐式实现 |
| 装饰器 | 继承 + 组合的包装类 | 函数套函数 | 函数是一等值 |
| 单例 | 静态成员 + 私有构造 | 包级变量 + `sync.Once` | 包级作用域 |
| 观察者 | 接口 + 注册表 | channel | 并发原语 |

**边界**：这张表不是"Go 更好"的证明，是"模式与语言绑定"的证明。同一个问题在 C++ 里需要策略模式，是因为 C++ 的调用需要在编译期确定虚表入口；Go 里一个 `func(int) int` 就够，代价是**丢失了类型名**——`func(int) int` 说不出自己是"折扣策略"还是"税率策略"。可读性这笔账要另外算。

## 机制：Go 的三个模式生成器

上表右列反复出现"函数是一等值"。Go 把三个语言机制变成了模式工厂，本目录剩下的篇目全由它们派生：

### 一、函数是一等值

类型可以带方法（[01-语言核心/06](../01-语言核心/06-方法与接收者.md)），函数也可以存进变量、当参数、当返回值。**凡是"选一个算法"的问题，都不需要类层次。**

```go
type Option func(*Server)

func WithTimeout(d int) Option { return func(s *Server) { s.Timeout = d } }
func WithMaxConn(n int) Option { return func(s *Server) { s.MaxConn = n } }

func NewServer(addr string, opts ...Option) *Server {
	s := &Server{Addr: addr, Timeout: 30, MaxConn: 100}   // 默认值
	for _, o := range opts {
		o(s)
	}
	return s
}
```

```console
$ go run .
默认值被覆盖: {Addr::8080 Timeout:5 MaxConn:50}
不传选项保持默认: {Addr::9090 Timeout:30 MaxConn:100}
```

这就是 Go 生态里最广为人知的**函数式选项**（functional options）。对照建造者模式（[02-创建型](./02-创建型.md)）：建造者用一串方法调用链，每一步返回 `*Builder`；函数式选项用一串函数值，每个函数只改一个字段。后者在 Go 里更常见，因为它不需要 `Builder` 类型存在——**选项的类型就是函数类型本身**。

### 二、接口隐式实现

一个类型只要方法集匹配就满足接口，不需要声明（[01-语言核心/08](../01-语言核心/08-接口.md)）。**凡是"这里需要一个可替换的实现"的问题，都不需要抽象基类。**

这带来一个具体的性能问题值得实测。接口调用要走 itab 查表，直觉上比直接调用慢；但**编译器在能静态确定具体类型时会去虚化**（devirtualization），把它变回直接调用：

```console
$ go test -bench='Iface|Direct' -benchmem -run=^$
BenchmarkIface-12     	1000000000	         0.5087 ns/op	       0 B/op	       0 allocs/op
BenchmarkDirect-12    	1000000000	         0.5273 ns/op	       0 B/op	       0 allocs/op
```

两者**没有差别**——`var sh Shape = Sq{2}` 的具体类型在编译期就唯一确定，接口这一层被抹掉了。真正付代价的是**多态切片**，具体类型运行时才定，去虚化失效：

```console
$ go test -bench='Poly' -benchmem -run=^$
BenchmarkPolyIface-12       	135912253	         8.924 ns/op	       0 B/op	       0 allocs/op
BenchmarkPolyConcrete-12    	310748076	         3.803 ns/op	       0 B/op	       0 allocs/op
```

**2.35 倍**（8.924 / 3.803）。这是"用接口换可替换性"的真实价格，出现在热循环里才值得关心。注意 `0 allocs/op`——接口装箱在这里没有堆分配，因为 `Shape` 的实现都是单字长值类型，逃逸分析把 itab 指针的构造留在了栈上。

### 三、嵌入

struct 可以嵌入另一个 struct，被嵌入者的字段与方法被"提升"到外层（[01-语言核心/07](../01-语言核心/07-结构体与组合.md)）。**凡是"这里需要复用一份实现"的问题，都不需要继承。**

```console
$ go test -bench='Chain' -benchmem -run=^$
BenchmarkChain-12     	22927671	        54.98 ns/op	       0 B/op	       0 allocs/op
```

54.98 ns/op 是三层函数包装（`withA(withB(withC(f)))`）跑一次的开销。**0 allocs/op 是关键**：装饰器链在构造时就把闭包分配完了，调用路径上不再分配。

**嵌入不是继承**，这条要反复强调（[01-语言核心/07](../01-语言核心/07-结构体与组合.md) 给了完整约束）：嵌入是"字段名可省略 + 方法提升"的语法糖，外层类型与被嵌入类型之间**没有子类型关系**——`Dog` 嵌入了 `Animal`，`Dog` 不是 `Animal`。多态只能由接口提供。
