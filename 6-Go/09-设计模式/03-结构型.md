# 结构型模式

> 前置：[02-创建型](./02-创建型.md) · 后续：[04-行为型](./04-行为型.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

结构型模式回答"**怎么把两个已有的东西接起来**"——不改动它们，只加一层。在 C++ 里这一层通常是包装类加继承；在 Go 里有三种接法，各自绑定一个语言机制：

| 接法 | 机制 | 本节的形态 |
|---|---|---|
| 接口转发 | 接口隐式实现 | 适配器、代理 |
| 函数包装 | 函数是一等值 | 装饰器 |
| 字段嵌入 | struct 嵌入 | 组合 |

**Go 的接法普遍比 C++ 轻，因为不需要"让包装类继承被包装类"**。C++ 的装饰器必须继承同一个基类才能被当作原对象使用；Go 里只要方法集匹配，包装类型自动满足原接口（[01-语言核心/08](../01-语言核心/08-接口.md)）。

## 机制

### 适配器：让 `func` 变成 `io.Writer`

标准库有大量"只有一个方法"的接口（[02-标准库/02](../02-标准库/02-io与bufio.md)）。给它们配一个函数适配器，是 Go 里最短的模式实现——**四行**：

```go
type writerFunc func([]byte) (int, error)

func (f writerFunc) Write(p []byte) (int, error) { return f(p) }
```

`writerFunc` 的底层类型是函数，但它**有方法**，因此满足 `io.Writer`。任何函数只要签名对得上，套一层就变成 `io.Writer`：

```console
$ go run .
[适配器收到] hello
[适配器收到] world
累计写入 12 字节
```

标准库自己就在用这个手法：`http.HandlerFunc` 是 `func(ResponseWriter, *Request)` 的适配器，`sort.Slice` 是排序接口的适配器，`errors.As` 接受 `*error` 也是同一类。

**约束**：适配器是**零成本**的——`writerFunc` 是单字长的函数值，装箱成接口不产生堆分配（与 [总览](./01-设计模式总览.md) 里 `0 allocs/op` 的实测同理）。所以"为了适配而包一层"在 Go 里几乎没有性能顾虑，只该考虑可读性。

### 装饰器：函数套函数，与 `io` 的组合

装饰器在 Go 里的标准形态是**接受同类型参数、返回同类型值的函数**：

```go
func withA(h Handler) Handler { return func(s string) string { return "A(" + h(s) + ")" } }
```

三层套起来（`withA(withB(withC(f)))`）跑一次是 **54.98 ns/op，0 allocs/op**（实测数据见 [总览](./01-设计模式总览.md)）——构造时把闭包分配完，调用路径上不再分配。

标准库把这条做成了接口级的组合子，`io` 包里全是：

```console
$ go run .
扇出
sb 现在 = "扇出\n"
LimitReader 只放行 "01234"，底层还剩 11 字节
```

`io.MultiWriter(os.Stdout, &sb)` 把一份写入扇出到两个目的地；`io.LimitReader(src, 5)` 在底层 `Reader` 外面套一层闸门，放行 5 字节后返回 `io.EOF`——注意**底层还剩 11 字节**，装饰器没有消费它们，只是拒绝继续转发。同理还有 `bufio.Reader`（加缓冲）、`gzip.Reader`（加解压）、`io.TeeReader`（顺手抄一份）。

**约束**：装饰器链的**顺序有意义**。`withA(withB(f))` 的输出是 `A(B(...))`，交换顺序结果不同。这一点与 `io` 组合子一致：`gzip.NewReader(bufio.NewReader(f))` 与 `bufio.NewReader(gzip.NewReader(f))` 都能跑，但缓冲的位置不同，性能不同。

### 代理：同一接口，不同的实现

代理与装饰器在 Go 里**写法相同、意图不同**：

| | 装饰器 | 代理 |
|---|---|---|
| 对原对象 | 增强它 | 替代它 |
| 是否调用原实现 | 是（链式） | 可能不调用 |
| 典型用途 | 加日志、加缓冲、加重试 | 延迟加载、访问控制、远程调用 |

Go 标准库里的代理实例是 `net/http` 的 `ResponseWriter` 包装——中间件常常不调用内层 `ResponseWriter`，直接返回 403 或缓存响应（[05-IO与外部世界/03](../05-IO与外部世界/03-HTTP服务与客户端.md)）。

### 组合：嵌入的边界

嵌入（[01-语言核心/07](../01-语言核心/07-结构体与组合.md)）是 Go 里唯一的"结构复用"手段。它与继承的**实质区别**是：

- **继承**建立子类型关系：`Dog` **是** `Animal`，能出现在任何要 `Animal` 的地方。
- **嵌入**只做两件事：省略字段名、提升方法。`Dog` **不是** `Animal`，不能传给要 `Animal` 的函数。

```go
type Animal struct{ Name string }
func (a Animal) Speak() string { return a.Name + " 叫了一声" }

type Dog struct {
	Animal          // 嵌入：字段名 Animal 可省略，Speak 被提升
	Breed string
}
```

`Dog` 能调 `d.Speak()`，但**不能**把 `d` 传给 `func f(a Animal)`。要多态，必须定义接口（[01-语言核心/08](../01-语言核心/08-接口.md)）。

**约束**：外层同名方法**遮蔽**嵌入者的方法，且没有虚函数机制——调用哪个方法在编译期就定死了。这与继承的"运行时按实际类型分派"是根本差异，也是嵌入**不能**用来做模板方法的原因。
