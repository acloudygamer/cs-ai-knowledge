# Go 1.0 至 1.17

> 前置：[01-演进脉络与提案流程](./01-演进脉络与提案流程.md) · 后续：[03-Go 1.18 至 1.27](./03-Go1.18至1.27.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64；发布日取自 go.dev/doc/devel/release。

## 本质

**2012-03-28 到 2021-08-16，九年半，十七个版本。Go 在这段时间里从"并发好用的系统语言"变成"生产级系统语言"。**

这条线由三件事拉起来，**没有一件是语言语法**：

| 主线 | 起点 → 终点 | 为什么重要 |
|---|---|---|
| **运行时** | 1.5 并发 GC → 1.8 亚毫秒暂停；1.14 异步抢占 | 服务端愿意用 Go 的直接原因 |
| **工具链** | 1.5 vendor 试验 → 1.11 modules → 1.16 默认 | 依赖管理从"没有"到"有且唯一" |
| **标准库** | 1.7 `context` 入库 → 1.16 `io/fs` + `embed` | 把生态里已经达成共识的东西收编 |

**约束的由来**：**Go 1 承诺只增不减，所以这十七个版本的语言改动极少**——真正算语言变更的只有三处（类型别名、数字字面量、`//go:build`），其余全部是运行时、工具链和标准库。**这正是兼容承诺的形态**：语言冻结，能力在别处生长。

| 版本 | 发布日 | 标志性变化 |

## 机制

### 编译器自举：1.4 → 1.5

**1.5 是整个 Go 1 时代最重要的一版**，理由不是 GC 而是这个：

> The compiler and runtime are now written entirely in Go (with a little assembler). C is no longer involved in the implementation, and so the C compiler that was once necessary for building the distribution is gone.

编译器不是重写的，是**机器翻译**的——"It is in effect the same program in a different language"，所以预期不会引入新 bug。

**这个决定的三重后果**：

| 后果 | 说明 |
|---|---|
| **引导依赖出现** | 编译 Go 需要先有一个 Go：1.5 要求 Go 1.4 或 `gccgo`；这条链一路传到今天（1.27 要求 1.24.6+） |
| **工具合并** | `6g`/`8g`/`6l` 等按架构分立的工具合并为 `go tool compile` / `go tool link` / `go tool asm`，用 `$GOOS`/`$GOARCH` 选择目标 |
| **贡献门槛降低** | 改运行时不再需要同时会 C 和 Go |

**约束**：**自举是"每代工具链只能上溯有限步"的根源**——不能用一个 1.0 的工具链编译 1.27 的源码，因为中间隔了 27 代。这就是 `GOTOOLCHAIN`（[01-演进脉络与提案流程](./01-演进脉络与提案流程.md)）存在的意义：让工具链自己下载自己。

### 垃圾回收：从"停世界"到"并发"（1.5 → 1.8）

**1.5 的并发 GC**：

> The garbage collector is now concurrent and provides dramatically lower pause times by running, when possible, in parallel with other goroutines.

具体指标：

> The "stop the world" phase of the collector will almost always be under 10 milliseconds and usually much less.

**1.8 把暂停再压一档**，手段是消除标记终止阶段的"停世界重新扫描栈"：

> Garbage collection pauses should be significantly shorter than they were in Go 1.7, usually under 100 microseconds and often as low as 10 microseconds.

对应的设计文档是 `design/17503-eliminate-rescan.md`——**混合写屏障**。

**判据**：**这两次改动是 Go 被服务端采纳的分水岭**。1.5 之前 GC 暂停是百毫秒量级，1.8 之后是亚毫秒量级——**量级差不是优化，是"能不能用"的差别**。今天 Go 的 GC 调优（`GOGC`/`GOMEMLIMIT`）都在这个基础上做，见 [03-运行时与内存/03](../03-运行时与内存/03-垃圾回收.md)。

**边界**：**并发 GC 的代价是吞吐**——1.5 同时把 `GOMAXPROCS` 的默认值从 1 改成 CPU 数：

> By default, Go programs run with `GOMAXPROCS` set to the number of cores available; in prior releases it defaulted to 1.

官方明确警告这**可能破坏程序**："Programs that do not expect to run with multiple cores may break inadvertently."

### 调度器：从协作到异步抢占（1.2 → 1.14）

**协作式抢占**（1.2 起）在**函数入口**插入检查点——问题是**没有函数调用的循环无法被抢占**：

```go
for { /* 死循环，无函数调用 */ }   // 1.14 之前：这个 goroutine 会占住 P 不放
```

**1.14 用信号做异步抢占**（设计文档 `design/24543-non-cooperative-preemption.md`）——运行时向线程发信号，在信号处理器里完成抢占。

**约束**：**这是 GC 正确性的前提**——GC 需要所有 goroutine 到达安全点才能开始标记。**没有异步抢占，一个死循环 goroutine 会让整个进程的 GC 卡住**。**判据**：看到"某个版本的 GC 变快了"时，要问"它的抢占机制是什么"——GC 与调度器在 Go 里是同一件事的两面（[03-运行时与内存/01](../03-运行时与内存/01-运行时总览与调度器.md)）。

### 依赖管理：vendor → modules（1.5 → 1.16）

三段式演进，每一段都在解决上一段的问题：

| 版本 | 机制 | 解决的问题 | 留下的问题 |
|---|---|---|---|
| 1.5 | `vendor/` **试验** | 依赖随代码走，构建可复现 | 需要手工管理 `vendor/` 内容 |
| 1.6 | `vendor/` **转正**（默认开启） | — | 版本信息不在代码里，靠外部工具（dep、glide） |
| 1.11 | **modules 试验**（`GO111MODULE=on`） | 版本信息进 `go.mod`，可校验（`sumdb`） | 与 `GOPATH` 模式并存，两套规则 |
| 1.13 | `go` 行进入 `go.mod` | 模块声明最低 Go 版本 | 此时仍是"建议值" |
| 1.16 | **modules 默认开启** | 只剩一套规则 | — |

**约束**：**1.5 到 1.16 用了六年**——这段时间里 Go 项目同时存在 `GOPATH`、`vendor/`、`dep`、`modules` 四套依赖组织方式，是 Go 生态摩擦最大的时期。**判据**：**依赖管理的收敛速度决定了生态的规模上限**——在 1.16 之前，"这个项目怎么构建"是一个需要读 README 的问题；之后它是 `go build`。

**边界**：`syscall` 包在 1.4 就被**冻结**（设计文档 `freeze-syscall.md`）——不再新增、不再修改，新系统调用一律走 `golang.org/x/sys`。**原因是兼容承诺管不到平台差异**：Linux 加一个系统调用不该让 Go 出一次版本。

### 标准库的补课

标准库在这九年里主要做一件事：**把 `golang.org/x/` 里已经验证过的东西收编进 `std`**。

| 版本 | 收编的东西 | 原来的位置 |
|---|---|---|
| 1.7 | `context` | `golang.org/x/net/context` |
| 1.10 | `strings.Builder` | 手工 `bytes.Buffer` |
| 1.16 | `io/fs`、`embed` | `golang.org/x/…` 与第三方 embed 库 |

**1.7 的 `context` 是最关键的一次**——它把"取消传播"从第三方约定变成语言生态的公共契约，今天所有 Go 的 IO、数据库、HTTP 接口第一个参数都是 `ctx`（[04-并发/04](../04-并发/04-context与取消传播.md)）。

**1.16 的 `io/fs` 是最后一次大规模收编**——它用一个 `fs.FS` 接口把 `os`、`embed`、`testing/fstest`、`net/http` 的文件服务统一到同一套抽象上。

### 语言：只有三处改动（实测）

**Go 1 承诺让语言几乎不动**，这九年真正落地的语言变更只有三处：

```console
$ go run .
== 语言 ==
1.9  别名   MyInt     -> int
1.9  新类型 MyNewInt  -> main.MyNewInt
1.13 二进制 0b1010     = 10
1.13 八进制 0o17       = 15
1.13 十六进制浮点 0x1p-2 = 0.25
1.13 下划线 1_000_000  = 1000000

== 标准库 ==
1.13 errors.Is(err, ErrNotFound) = true
1.13 errors.As(err, &error)      = true
1.13 errors.Unwrap(err) == 哨兵  = true
1.13 完整链路                    = 查找 "k": not found
1.16 io/fs 遍历 embed.FS:
1.16   . (d---------)
1.16   data.txt (----------)
1.16 embed 内容 = "Go 1.16 起 embed 把文件编进二进制"
1.7  context 超时 = context deadline exceeded (errors.Is(err, context.DeadlineExceeded)=true)
```

**三处改动的分工**：

| 版本 | 改动 | 影响面 |
|---|---|---|
| **1.9** | **类型别名** `type T = U` | 只影响声明，`%T` 打出的是 `int` 而不是 `main.MyInt`——**别名不产生新类型** |
| **1.13** | **数字字面量**（`0b`/`0o`/`0x` 浮点/`_`） | 纯语法糖，零破坏性 |
| **1.17** | **`//go:build`** | 构建约束的语法换代 |

**`//go:build` 的迁移是兼容承诺的一次实演**——`gofmt` 会自动补写新语法，同时**保留旧行**给 1.17 之前的工具链：

```console
$ head -2 old.go
// +build linux,amd64

$ gofmt -w old.go
$ head -4 old.go
//go:build linux && amd64
// +build linux,amd64

package main
```

**旧语法是"注释 + 空格"，新语法是真指令**——`// +build` 靠约定解析，`//go:build` 用真正的布尔表达式（`&&`、`||`、`!`），语义清楚得多。**双写是过渡期的标准做法**：`//go:build` 给 1.17+ 看，`// +build` 给 1.16 及更早看。

**约束**：**别名（`=`）与新类型（无 `=`）的区别是这一版最容易踩的坑**——别名只是另一个名字，方法集与底层类型完全相同；新类型会切断所有方法集。上面的实测输出里 `%T` 分别打出 `int` 和 `main.MyNewInt`，就是这个差别的直接证据（[01-语言核心/02](../01-语言核心/02-类型与变量.md)）。

**与其它语言对照**：

| | 同期语言变更 | 同期运行时变更 |
|---|---|---|
| **Java 7→17**（2011–2021） | **多**（lambda、模块、记录、密封类…） | GC 从 CMS 到 G1 到 ZGC |
| **C++11→20**（2011–2020） | **极多**（几乎重写） | 无（无运行时） |
| **Python 3.2→3.10**（2011–2021） | 中（类型标注、海象、模式匹配） | GIL 未动 |
| **Go 1.0→1.17**（2012–2021） | **三处** | **GC 暂停降两个数量级** |

**Go 与同期的 Java、C++、Python 走了完全相反的路**：别人把精力放在语言语法上，Go 把精力放在运行时和工具链上。**结果是 Go 1.0 的代码在 1.17 上基本原样编译**，而 Java 7 的代码要在 17 上跑需要处理模块化、`sun.misc.Unsafe` 等一系列迁移。

**这个选择有代价**：Go 到 1.17 时语言表达力明显落后于同期语言——没有泛型、没有错误包装之外的错误处理手段、没有 `min`/`max`。**1.18 开始补这些课**，但补的方式仍然受兼容承诺约束（见 [03-Go 1.18 至 1.27](./03-Go1.18至1.27.md)）。
