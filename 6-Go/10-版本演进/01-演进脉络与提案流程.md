# 演进脉络与提案流程

> 前置：[00-概览/01-Go全景](../00-概览/01-Go全景.md) · 后续：[02-Go 1.0 至 1.17](./02-Go1.0至1.17.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64。

## 本质

**Go 的版本演进是三件事的组合：一份兼容承诺、一套提案流程、一个六个月的发条。**

三者互相支撑——**没有兼容承诺，六个月一版会撕裂生态；没有提案流程，兼容承诺会退化成"什么都不改"；没有固定节奏，前两者都只是纸面约定**。

| 支柱 | 起点 | 作用 |
|---|---|---|
| **Go 1 兼容性承诺** | 2012（Go 1.0 同时发布） | 语言与标准库的 API 只增不减 |
| **提案流程** | 2012 起（`golang/go` issue） | 变更的唯一入口 |
| **六个月节奏** | 2 月 / 8 月各一版 | 可预测的发布日 |

**约束的由来**：兼容承诺里要紧的只有一句——

> It is intended that programs written to the Go 1 specification will continue to compile and run correctly, unchanged, over the lifetime of that specification.

**注意它只承诺源码级兼容**：

> Compatibility is at the source level. Binary compatibility for compiled packages is not guaranteed between releases.

所以每次升级都必须重新编译——**Go 从不承诺 ABI 稳定**，[03-运行时与内存/06](../03-运行时与内存/06-CGO与跨语言调用.md) 里 cgo 的脆弱性正来自这里。

**支持窗口**（官方发布策略原文）：

> Each major Go release is supported until there are two newer major releases.

**实测**：写作时 go.dev/dl 上只有 `go1.27.1` 与 `go1.26.8` 两个次版本的安全修复版。**Go 1.25 的支持在 1.27 发布时终止**——这就是"没有 LTS"的具体含义，也是本库对 Go 只设单档版本口径的原因。

**边界**：兼容承诺有明确的例外清单（`go.dev/doc/go1compat`）。四条要记住的：

| 例外 | 后果 |
|---|---|
| **性能** | 不承诺版本间性能不变 |
| **`unsafe`** | 保留破坏的权利 |
| **`syscall`** | Go 1.4 起**冻结**（不再新增、不再修改） |
| **未键名的结构体字面量** | 跨包结构体加字段会让 `T{1, "x"}` 编译失败 |

最后一条可以主动规避：**跨包的结构体字面量一律写键名** `T{A: 1, B: "x"}`。

## 机制

### 提案流程：四个阶段

任何人（不限于 Go 团队成员）都能提案，入口是 `golang/go` 仓库的一个 issue——**打上 `Proposal` 标签就是提案**。

| 阶段 | 做什么 |
|---|---|
| 1. **提 issue** | "There is no need for a design document at this point."（语言类变更需用 Go 2 模板） |
| 2. **讨论分流** | 接受 / 拒绝 / **要求写设计文档** |
| 3. **写设计文档** | 提交为 `design/NNNN-shortname.md`，`NNNN` = **issue 号** |
| 4. **终审** | 接受或拒绝 |

**提案评审组**（Go 团队成员）每周开会，职责是**确保对的人参与**——cc 相关开发者、提出疑问、复活停滞的讨论；**实质争论留在 issue 里**，会议纪要发布在 `go.dev/s/proposal-minutes`。

**接受之后**：打 `Proposal-Accepted` 标签，issue 从 `Proposal` 里程碑移到工作里程碑（默认 `Backlog`），**并就地改造成实现跟踪单**。实现按普通贡献走。

**被拒的路径**分两种：

| 标签 | 含义 |
|---|---|
| `Likely Accept` / `Likely Decline` | 有一周最终评论期，之后才定 |
| `Declined as Duplicate / Infeasible / Retracted / Obsolete` | 快速拒绝，跳过前面两列 |

**共识无法达成时**：通常结果是拒绝。如果提案不该直接否掉但又没有共识，由 **Go 架构师**（gri、iant、rsc）决定；再不行由**仲裁者**（austin）拍板并在 issue 上记录理由。

**约束**：**语言变更的门槛明确高于库变更**。官方要求语言变更必须同时满足三条：

> address an important issue for many people / have minimal impact on everybody else / come with a clear and well-understood solution

**这三条解释了 Go 语言为什么变得慢**——泛型从 2009 年被反复讨论到 2022 年落地，`try` 内建（issue #32437，2019-06-04 由 griesemer 提出）被否。**语言特性是稀缺资源，库和工具不是**。

### `design/` 目录就是演进的地图

实测 `golang/proposal` 仓库的 `design/` 目录——**文件名前缀就是 issue 号**：

| 文件 | issue | 落地 |
|---|---|---|
| `40307-fuzzing.md` | #40307 | 1.18 模糊测试 |
| `43651-type-parameters.md` | #43651 | 1.18 泛型 |
| `45713-workspace.md` | #45713 | 1.18 workspace |
| `48409-soft-memory-limit.md` | #48409 | 1.19 `GOMEMLIMIT` |
| `55022-pgo.md` | #55022 | 1.21 PGO 转正 |
| `56345-structured-logging.md` | #56345 | 1.21 `log/slog` |
| `56986-godebug.md` | #56986 | 1.21 GODEBUG 机制正式化 |
| `57001-gotoolchain.md` | #57001 | 1.21 工具链版本化 |
| `60078-loopvar.md` | #60078 | 1.22 循环变量按迭代 |
| `74609-goroutine-leak-detection-gc.md` | #74609 | 1.26 试验 / 1.27 转正 |

**命名规则本身说明了流程**：设计文档以 **issue 号**命名，因为流程的起点就是一个 issue。**没有"先写文档再讨论"这一步**——第一步只是一个简短的 issue，文档是讨论要求写时才写的。

目录里也有**没落地**的：

| 文件 | 结局 |
|---|---|
| `32437-try-builtin.md` | **拒绝**（2019） |
| `12302-release-proposal.md` | **撤回**（2015，文档自身标注 `Withdrawn`） |
| `70257-memory-regions.md` | 内存区域（arena）试验，未进入稳定版 |

**判据**：**想查"某个特性是怎么定的"，去 `design/` 找对应 issue 号**——那里有取舍的全部理由，比 release notes 的信息量大一个数量级。

### 兼容机制：`go` 行决定语言版本与 GODEBUG 默认值

**这是 Go 1 兼容承诺能兑现的工程手段**——同一个工具链，按 `go.mod` 里的 `go` 行，编译出语义不同的程序。

实测：**同一份源码，同一个 go1.27.1 工具链，只改 `go.mod`**：

```console
$ printf 'module gate\n\ngo 1.25.0\n' > go.mod && go run .
工具链       = go1.27.1
url.Parse("http://::1/") -> http://::1/, err=<nil>

$ printf 'module gate\n\ngo 1.26.0\n' > go.mod && go run .
工具链       = go1.27.1
url.Parse("http://::1/") -> <nil>, err=parse "http://::1/": invalid port "::1" after host

$ printf 'module gate\n\ngo 1.26.0\n\ngodebug urlstrictcolons=0\n' > go.mod && go run .
工具链       = go1.27.1
url.Parse("http://::1/") -> http://::1/, err=<nil>
```

**三行 `go.mod`，三种行为**。`net/url` 在 1.26 收紧了主机里的冒号校验，但 `go 1.25` 的模块继续按老规则跑——**它不会被这次收紧波及**。第三行展示 `godebug` 指令（1.23 起）可以逐项覆盖。

**GODEBUG 默认值的来源**（官方文档原文）：

> When a GODEBUG setting is not listed in the environment variable, its value is derived from three sources: the defaults for the Go toolchain used to build the program, amended to match the Go version listed in `go.mod`, and then overridden by explicit `//go:debug` lines in the program.

**可以直接把这份清单打出来**：

```console
$ printf 'module gate\n\ngo 1.22\n' > go.mod && go list -f '{{.DefaultGODEBUG}}' .
containermaxprocs=0,cryptocustomrand=1,decoratemappings=0,gotestjsonbuildtext=1,
httpcookiemaxnum=0,httpservecontentkeepheaders=1,multipathtcp=0,randseednop=0,
rsa1024min=0,tlsmlkem=0,tlssecpkem=0,tlssha1=1,tracebacklabels=0,updatemaxprocs=0,
urlmaxqueryparams=0,urlstrictcolons=0,winreadlinkvolume=0,winsymlink=0,
x509negativeserial=1,x509rsacrt=0,x509sha256skid=0,x509sslcertoverrideplatform=0,
x509usepolicies=0                                   # 23 项

$ printf 'module gate\n\ngo 1.23.0\n' > go.mod && go list -f '{{.DefaultGODEBUG}}' .
containermaxprocs=0,cryptocustomrand=1,decoratemappings=0,gotestjsonbuildtext=1,
httpcookiemaxnum=0,multipathtcp=0,randseednop=0,rsa1024min=0,tlsmlkem=0,
tlssecpkem=0,tlssha1=1,tracebacklabels=0,updatemaxprocs=0,urlmaxqueryparams=0,
urlstrictcolons=0,x509rsacrt=0,x509sha256skid=0,x509sslcertoverrideplatform=0,
x509usepolicies=0                                   # 19 项
```

**差出的 4 项就是 1.23 的四处行为变更**：`httpservecontentkeepheaders`、`winsymlink`、`winreadlinkvolume`、`x509negativeserial`。`go 1.22` 的模块默认走老行为，`go 1.23` 的走新行为——**同一条 `go list` 命令的输出，就是"这个模块会按哪个版本的语义跑"的清单**。

### 语言版本与标准库版本是两套检查

`go` 行同时设定**语言版本**，由**编译器**强制：

```console
$ printf 'module langver\n\ngo 1.21\n' > go.mod
$ go build ./...
.\main.go:10:17: cannot range over 3 (untyped int constant): requires go1.22 or later (-lang was set to go1.21; check go.mod)
```

但**标准库符号不受编译器拦**——`reflect.TypeFor`（1.22 新增）在 `go 1.21` 模块里能编译通过：

```console
$ go build ./...        # 无输出：编译成功
$ go vet ./...
main.go:10:22: reflect.TypeFor requires go1.22 or later (module is go1.21)
```

**约束**：**语言特性由编译器拦，标准库符号由 `go vet` 的 `stdversion` 检查器拦**（该检查器的提案是 #46136）。1.27 起 `go test` 默认运行它（[07-测试与质量/01](../07-测试与质量/01-测试基础.md)），所以"用了新符号但忘了升 `go` 行"会在测试阶段暴露。

**判据**：**`go` 行应当写成"你实际用到的最高版本"，不是"你安装的版本"**——写高了会强迫所有下游用户升级工具链（1.21 起 `go` 行是硬性最低要求，工具链会拒绝加载 `go` 行高于自身的模块），写低了会被 `stdversion` 报出来。

### GODEBUG 的生命周期：四个版本

官方承诺：

> GODEBUG settings added for compatibility will be maintained for a minimum of two years (four Go releases).

**实测印证**：`asynctimerchan`（1.23 引入，用于回退 Timer 通道缓冲语义）在 **1.27 被永久移除**——四个版本，正好到期。所以在 1.27 上**无论 `go` 行写什么**，`cap(timer.C)` 都是 0：

```console
$ printf 'module gate\n\ngo 1.22\n' > go.mod && go run .
cap(timer.C)  = 0
cap(ticker.C) = 0

$ printf 'module gate\n\ngo 1.23.0\n' > go.mod && go run .
cap(timer.C)  = 0
cap(ticker.C) = 0
```

1.27 一次性移除了七个 GODEBUG：`asynctimerchan`、`tlsunsafeekm`、`tlsrsakex`、`tls3des`、`tls10server`、`x509keypairleaf`、`gotypesalias`。

**约束**：**GODEBUG 是"迁移窗口"，不是"永久豁免"**——它保证你有四个版本的时间改代码，到期就删。**判据**：**看到 `go vet` 或启动日志提示某个 GODEBUG 被用到时，要当成待办事项排期**，而不是当成可用的兼容开关。

**边界**：安全类的 GODEBUG 是例外——**"GODEBUGs introduced for security releases will have the new behavior apply to all versions"**。安全修复不给你回退的机会。

**与其它语言对照**：

| | 节奏 | 兼容承诺 | 变更入口 | 语义版本选择粒度 |
|---|---|---|---|---|
| **Java** | 6 个月（2021 起） | 无（靠 LTS 兜底） | JEP | — |
| **C++** | 3 年 | 无（ISO 标准，ABI 常破） | 委员会提案 | — |
| **Python** | 12–18 个月 | 无（2→3 断代） | PEP | — |
| **Rust** | 6 周 | 有 | RFC + Edition | **crate（Edition，3 年一次）** |
| **Go** | **6 个月** | **有** | **提案流程** | **模块（`go` 行 + 逐项 GODEBUG）** |

**Go 与 Rust 是主流语言里唯二有明确兼容承诺的**，但机制不同：Rust 用 **Edition**（每 3 年一次、按 crate 整体切换），Go 用 **`go` 行 + GODEBUG**（每个模块自己选语义版本）。**Go 的粒度更细**——Rust 的 edition 是整块切换，Go 的行为开关是逐项可覆盖的，代价是 GODEBUG 清单会随版本膨胀（当前 1.27 有 19–23 项）。

**C++ 与 Python 说明了没有承诺的代价**：C++ 的 ABI 是每次升级的赌注；Python 3 的断代让生态花了十年追赶。**Go 用"只增不减"换来十五年不需要断代**——代价是标准库里 `sort.Slice` 与 `slices.Sort` 长期并存，以及一批永远删不掉的 API。
