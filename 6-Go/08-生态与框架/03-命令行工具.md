# 命令行工具

> 前置：[02-gRPC与ProtocolBuffers](./02-gRPC与ProtocolBuffers.md) · 后续：[04-配置管理](./04-配置管理.md)

> **版本基准**：Go 1.27（stable = latest）。本篇示例实测环境：go1.27.1 windows/amd64，`github.com/spf13/cobra v1.10.2`。

## 本质

**标准库的 `flag` 包提供"扁平标志"，`cobra` 提供"子命令树"。**两者的差别是**命令的层次结构**：

| | `flag` | `cobra` |
|---|---|---|
| 结构 | 一层（全是标志） | **树**（命令 + 子命令 + 标志） |
| 帮助 | 自动生成（`PrintDefaults`） | 自动生成（含分组、示例、补全） |
| 依赖 | **0** | 2（cobra + pflag） |
| 适合 | 单一功能的工具 | **多子命令的工具**（`kubectl`、`docker`、`gh`） |

**约束的由来**：`flag` 没有子命令概念——`app serve -p 8080` 里的 `serve` 在 `flag` 眼里只是**第一个位置参数**，你要自己解析它。`cobra` 把"命令树"做成了框架的核心抽象。

**判据**：**工具只有一个功能用 `flag`，有多个子命令用 `cobra`**。判据是"用户会不会敲 `tool <动词>`"——会就说明需要子命令。

## 机制

### 标准库 `flag`

```console
$ ./demo.exe
hello world
剩余参数: []

$ ./demo.exe -name 张三 -n 2 -v -timeout 5s extra1 extra2
hello 张三 (第 1 次, timeout=5s)
hello 张三 (第 2 次, timeout=5s)
剩余参数: [extra1 extra2]

$ ./demo.exe --name=李四 --n=1
hello 李四
剩余参数: []
```

**要点**：

| 特性 | 说明 |
|---|---|
| 单横线与双横线等价 | `-name` 与 `--name` 都可以 |
| 两种赋值形式 | `-name 张三` 与 `-name=张三` |
| **标志必须在位置参数之前** | `demo.exe extra1 -name x` 里 `-name` 会被当成位置参数 |
| `-h` / `-help` | 自动处理（打印 Usage 并返回 `ErrHelp`） |
| 类型 | `String`/`Int`/`Bool`/`Duration`/`Float64` 等内置 |

**约束**：**`flag` 遇到第一个非标志参数就停止解析**——这是它最大的限制。要支持"标志与位置参数任意穿插"（像 `git commit -m x file`）必须用 `pflag`（cobra 的依赖）。

**`-h` 的输出**：

```console
$ ./demo.exe -h
用法: demo [选项] [参数...]

选项:
  -n int
    	重复次数 (default 1)
  -name string
    	要问候的名字 (default "world")
  -timeout duration
    	超时 (default 30s)
  -v	详细输出
```

自定义 `fs.Usage` 能覆盖默认输出——**这是 `flag` 唯一的外观定制点**。

**非法标志的处理**：

```console
$ ./demo.exe -unknown
flag provided but not defined: -unknown
用法: demo [选项] [参数...]
```

**注意退出码是 0**——上面实测里 `echo "exit=$?"` 显示 0，因为管道到 `head` 后 `$?` 是 `head` 的退出码。**真实场景要自己 `os.Exit(2)`**，上面的代码里 `fs.Parse` 出错后确实 `os.Exit(2)` 了。

### `cobra`：命令树

```console
$ ./app.exe -h
一个演示 cobra 结构的示例应用。

Usage:
  app [flags]
  app [command]

Available Commands:
  completion  Generate the autocompletion script for the specified shell
  config      配置管理
  help        Help about any command
  login       登录
  serve       启动服务

Flags:
  -h, --help      help for app
  -v, --verbose   详细输出

Use "app [command] --help" for more information about a command.
```

**自动生成的部分**：`Available Commands` 列表、`help` 子命令、`completion` 子命令（shell 补全脚本）、`-h` 标志、用法行。

**约束**：**`completion` 是自动加的**——这是 cobra 相对 `flag` 的一大优势，用户敲 `app <TAB>` 就能补全。

### 三种标志作用域

```console
$ ./app.exe serve -h
启动服务

Usage:
  app serve [addr] [flags]

Flags:
  -h, --help       help for serve
  -p, --port int   端口 (default 8080)

Global Flags:
  -v, --verbose   详细输出
```

| 方法 | 作用域 | 显示位置 |
|---|---|---|
| `root.PersistentFlags()` | **所有子命令** | `Global Flags` |
| `cmd.Flags()` | 仅当前命令 | `Flags` |
| `cmd.LocalFlags()` | 仅当前命令（不含继承的） | — |

**全局标志位置无关**：

```console
$ ./app.exe -v serve :9090
serve 在 :9090 启动, verbose=true
$ ./app.exe serve :9090 -v
serve 在 :9090 启动, verbose=true
```

**约束**：**全局标志应当放在 `PersistentFlags`**（如 `--verbose`、`--config`）；只在某个子命令有意义的放 `Flags`。混用会让 `-h` 输出里出现奇怪的标志。

### 参数校验与必填标志

```console
$ ./app.exe login
Error: required flag(s) "token" not set
Usage:
  app login [flags]

$ ./app.exe serve a b c
Error: accepts at most 1 arg(s), received 3
```

| 校验 | 写法 |
|---|---|
| 必填标志 | `cmd.MarkFlagRequired("token")` |
| 参数个数 | `Args: cobra.MaximumNArgs(1)` / `ExactArgs(n)` / `MinimumNArgs(n)` / `RangeArgs(a, b)` |
| 自定义 | `Args: func(cmd *cobra.Command, args []string) error {...}` |

**约束**：**`MarkFlagRequired` 的返回值是 error**（标志不存在时返回错误），通常被忽略——但标志名拼错会导致必填校验静默失效。**建议检查返回值**。

### `Run` 与 `RunE`

| | 签名 | 错误处理 |
|---|---|---|
| `Run` | `func(cmd, args)` | **无返回值**，出错要自己 `os.Exit` |
| `RunE` | `func(cmd, args) error` | **返回错误，cobra 统一处理** |

**判据**：**默认用 `RunE`**——返回的 error 会被 cobra 打印并设非零退出码，符合 Go 的错误处理惯例（[01-语言核心/10](../01-语言核心/10-错误处理.md)）。

**约束**：`RunE` 返回错误时 cobra **会同时打印 Usage**，这在业务错误（如"文件不存在"）时是噪音。可以设 `cmd.SilenceUsage = true` 抑制。

### 与 `os/exec` 的组合

CLI 工具常需要调用外部命令：

```go
cmd := exec.CommandContext(ctx, "git", "rev-parse", "HEAD")
out, err := cmd.Output()
```

**约束**：**必须用 `CommandContext`**（[04-并发/04](../04-并发/04-context与取消传播.md)）——`exec.Command` 起的进程在父进程取消时**不会自动终止**，会变成孤儿进程。

**边界**：`cmd.Output()` 只捕获 stdout；要同时捕获 stderr 用 `cmd.CombinedOutput()` 或自己设 `cmd.Stdout`/`cmd.Stderr`。**参数不要用字符串拼接**——`exec.Command` 的参数是分开传的，不经 shell，因此没有注入问题（这与 `sh -c "..."` 相反）。

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 一般错误 |
| 2 | **用法错误**（参数解析失败） |
| 126/127 | 命令不可执行/找不到（shell 惯例） |

**约束**：**用法错误应当返回 2**（`flag` 包的惯例），业务错误返回 1。这样脚本能区分"我调错了"与"程序执行失败"。

**`os.Exit` 不会执行 `defer`**——这是 Go 的一个硬性约束。需要清理时先做清理再退出，或者把 `main` 拆成 `main()` + `run() error`：

```go
func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "错误:", err)
		os.Exit(1)
	}
}

func run() error {
	// 这里可以有 defer
}
```

**这个模式是 Go CLI 的标准写法**——它让所有 `defer` 都能正常执行（[01-语言核心/05](../01-语言核心/05-函数.md)）。

**与其它语言对照**：

| | 标准库 CLI | 流行框架 |
|---|---|---|
| Python | `argparse`（**功能完整**） | Click / Typer |
| Java | 无 | picocli / JCommander |
| Node.js | `process.argv`（原始） | commander / yargs |
| **Go** | **`flag`（无子命令）** | **cobra** |

**Python 的 `argparse` 是四者中标准库最强的**——它支持子命令（`add_subparsers`）、类型转换、互斥组。**Go 的 `flag` 刻意做得极简**（只有扁平标志），把子命令留给第三方。

**这个取舍与 Go 的整体风格一致**：**标准库只提供最小可用集**（[00-概览/01](../00-概览/01-Go全景.md) 的"标准库是生产级的，生态是加法"）。`flag` 对一个 20 行的小工具够用，对 `kubectl` 那样的大型 CLI 就必须上 cobra——而 `kubectl`、`docker`、`gh`、`hugo`、`etcdctl` 全都用了 cobra，这让它成为事实标准。
