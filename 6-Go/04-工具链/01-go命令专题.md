# Go 命令专题

## 定义

`go` 命令是 Go 工具链的统一入口，通过子命令区分功能域：环境查看(`env`)、代码编译(`build`)、测试运行(`test`)、静态分析(`vet`)、代码格式化(`fmt`)、模块管理(`mod`)。其本质是一个**自举的构建系统**，Go 本身用 Go 编写，工具链与语言版本绑定。

## 数学模型

### go build 的编译管道

```
输入：.go 源文件集合
输出：可执行文件 / 共享库 / 插件

编译管道（数学形式）：
  Source = {f1.go, f2.go, ..., fn.go}

  AST_i = parse(fi)                          // 词法+语法分析
  AST'_i = typeCheck(AST_i)                   // 类型检查
  IR = compile(AST'_i)                        // 生成中间码（SSA）
  obj_i = codegen(IR)                         // 生成机器码（.o）

  binary = link(obj_1, obj_2, ..., obj_n)     // 链接
```

### go test 的覆盖率模型

```
覆盖率（Coverage） = 已执行的代码行数 / 总代码行数

分支覆盖率 = 已执行的分支数 / 总分支数

覆盖报告生成：
  go test -coverprofile=profile.out
  go tool cover -html=profile.out

Coverage 计算（插桩法）：
  编译器在每行代码前插入计数器++
  运行测试后统计每个计数器的值
  输出：profile.out（line:execution_count 格式）
```

### go mod 的版本解析约束

```
go.mod 声明：module github.com/user/project

require (
    dep1 v1.2.3
    dep2 v0.1.0
)

go.sum 每行：module@version h1:treehash

MVS（Minimal Version Selection）算法：
  从 root 开始，对每个依赖选择最小满足条件的版本
  保证：每次构建得到相同的依赖图（可重现构建）
```

<pre>

    ▼

## 机制

### go vet 为什么在 build 之后运行？

```
go build 成功后 → 意味着代码在语法和类型上是正确的
go vet 在此基础上做语义分析：
  - printf 的 format verb 与实参类型是否匹配
  - 是否有无效的类型转换
  - 是否有不可达的代码

这是二次检查的原因：
  1. 若 build 失败，不需要 vet（类型问题更基础）
  2. build 成功后，AST 已构建好，vet 可复用
  3. vet 结果不影响编译，继续输出二进制
```

### go test -race 的实现原理

```
race detector 使用 "shadow memory" 技术：

对每个字节的内存，用 shadow 字节追踪最后写入的 goroutine

内存访问插桩：
  每次 load：检查 shadow[addr] 是否属于当前 goroutine
  每次 store：更新 shadow[addr] = current_goroutine

若 load 发现 shadow 属于另一个 goroutine → race 报告

实现细节：
  - 编译器在每次内存访问前后插入 race 检测代码
  - 检测代码使用 TLS（Thread Local Storage）获取当前 goroutine ID
  - shadow memory 大小 = 1 shadow byte per heap byte × 5-10x 开销
```

### go fmt 的等幂性

```
gofmt 是等幂的（idempotent）：
  gofmt(gofmt(code)) = gofmt(code)

这意味着：
  1. 多次格式化结果相同
  2. 可安全用于 pre-commit hook
  3. 代码风格争议可以通过强制 gofmt 解决

gofmt 保留语义：
  gofmt 不改变程序行为，只是重新排列 token
  等价于：格式化后的代码与原代码在语义上完全相同
```

## 工具链数据流总览

```
源码 (*.go, *_test.go, go.mod, go.work)
    │
    ├── go fmt ──► 规范化源文件
    │
    ├── go generate ──► 生成代码
    │
    ├── go build ──► 可执行文件
    │
    ├── go test ──► 测试报告 + 覆盖率
    │
    ├── go vet ──► 静态警告
    │
    └── go doc ──► 文档查询
```

## 命令生态依赖关系

```
go env ──► GOROOT/GOPATH/GOMODCACHE ──► 所有命令的路径解析基础
go mod ──► go.mod ──► go get / go build / go test 依赖解析
go work ──► go.work ──► 多模块联调时覆盖 go mod
go vet ──► go build 成功后才运行（基于编译后 AST）
```
