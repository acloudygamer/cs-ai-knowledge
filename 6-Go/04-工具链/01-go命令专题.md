# Go 命令专题

## go 命令是 Go 工具链的统一入口

Go 工具链以 `go` 二进制程序为单一入口，通过子命令区分功能域：环境查看(`env`)、代码编译(`build`)、测试运行(`test`)、静态分析(`vet`)、代码格式化(`fmt`)、模块管理(`mod`)。

---

## go env：环境变量的只读查询与持久化写入接口

`go env` 是 Go 运行时与构建环境的配置中枢，通过键值对管理 Go 安装路径、模块代理、构建约束等全部配置。

```bash
go env                    # 列出所有
go env GOROOT            # 查单一变量
go env -w GOPROXY=https://proxy.golang.org,direct  # 持久化写入
go env -w                # 列出可写变量
```

<pre>
用户输入
    │
    ▼
go env [-w] KEY=VALUE
    │
    ├─── 无 -w ──▶ 读取 os.Getenv / godb.Config
    │                  │
    │                  ▼
    │              输出键值对
    │
    └─── 有 -w ──▶ 写入 $GOPATH/config/env/env.toml
                      │
                      ▼
                  后续 go 命令读取
</pre>

**机制**：Go 1.11 引入 module 模式后，`go env -w` 将配置写入 `$(go env GOMODCACHE)/../env.toml` 而非 shell profile，实现团队配置共享。`go env` 读取优先级：环境变量 > `go env -w` 写入的配置 > 编译时默认值。

---

## go build：Go 代码到平台原生二进制的编译管道

`go build` 是 Go 源代码到目标平台可执行文件的完整编译链路，包含词法解析→语法分析→类型检查→中间码生成→机器码链接。

```bash
go build -o app .                 # 输出可执行文件
go build -ldflags="-s -w" .     # 去除符号表，减小体积
CGO_ENABLED=0 go build .         # 静态编译（无 cgo 依赖）
GOOS=linux GOARCH=amd64 go build # 交叉编译
```

<pre>
.go 源文件
    │
    ▼
go build
    │
    ├─── 解析 ──▶ AST
    ├─── 类型检查 ──▶ typed AST
    ├─── 编译 ──▶ SSA (静态单例)
    └─── 链接 ──▶ 可执行文件 / 共享库 / 插件
</pre>

**机制**：`GOOS/GOARCH` 交叉编译通过重新选择编译器后端实现；`-ldflags` 在链接阶段注入版本信息，利用 linker 的 `-X` 标志修改 string 段；`-buildmode=c-shared` 生成 C 共享库，`-buildmode=plugin` 生成 Go 插件（仅 Linux）。

---

## go test：Go 测试的发现→执行→报告自动化流水线

`go test` 是 Go 内置测试框架的驱动程序，自动发现 `*_test.go` 文件，按包隔离运行，汇总覆盖率与性能数据。

```bash
go test -v -cover -race ./...                  # 详细+覆盖+竞态检测
go test -run TestFoo -bench=. ./...             # 按名过滤+基准
go test -coverprofile=out ./... && go tool cover -html=out  # 覆盖率报告
```

<pre>
*_test.go
    │
    ▼
go test
    │
    ├─── TestMain 初始化
    ├─── 逐包并行执行
    │       │
    │       ▼
    │   t.Fatal / testing.Benchmark
    │
    ▼
    ├─── -v ──▶ 标准输出
    ├─── -coverprofile ──▶ coverage.out
    └─── -race ──▶ race detector
</pre>

**机制**：Go 1.10 引入的测试缓存（`go test` 将结果哈希化，相同输入直接返回缓存）避免重复运行未变测试。`-race` 通过 shadowing 技术检测数据竞争，原理是在每次内存访问前后插入检测代码，验证无其他 goroutine 在同一时刻修改该内存。

---

## go vet：编译后 AST 的语义级问题扫描器

`go vet` 是编译器静态分析的补充，在类型检查后对 AST 做语义规则检查（错误检查、格式化字符串、不安全指针），在生成二进制前拦截常见运行时陷阱。

```bash
go vet ./...                # 全局检查
go vet -atomic -printf .   # 指定检查器
```

<pre>
源代码
    │
    ▼
go build（编译成功）
    │
    ▼
go vet（第二次 AST 遍历）
    │
    ├─── printf  ──▶ 格式化动词与实参类型匹配
    ├─── atomic ──▶ 变量是否通过竞态访问
    └─── shadow ──▶ 变量遮蔽检测
    │
    ▼
    报告问题（不阻止编译）
</pre>

**机制**：`go vet` 不是单一分析器，而是 `golang.org/x/tools/go/analysis` 框架的驱动器。每个检查器实现 `Analyze` 接口，独立遍历 AST 或类型信息。检查结果仅作警告，不阻止 `go build`。

---

## go fmt：Go 语法规范化的确定性格式化算法

`go fmt`（实为 `gofmt`）是 Go 官方代码风格规范，通过统一的缩进、换行、导入排序规则，消除团队风格争议。

```bash
go fmt ./...      # 格式化并写入
gofmt -w -l .     # 仅列出未格式化文件
```

<pre>
源文件（任意风格）
    │
    ▼
gofmt parser
    │
    ├─── 读取 token 流
    ├─── 按 Go Style 重排 token
    │       ├─── 缩进 → Tab
    │       ├─── 换行 → 按列宽规则
    │       └─── import → 按路径排序
    │
    ▼
等幂的规范化输出
</pre>

**机制**：`gofmt` 算法是等幂的——多次格式化结果相同，故可安全用于 pre-commit hook。其使用 Go 官方 parser 而非第三方，保证与编译器理解完全一致。Go 1.14 强制所有标准库代码使用 `gofmt`，确保风格绝对统一。

---

## go fix：Go 早期版本代码到当前版本迁移的自动化迁移器

`go fix` 是 Go 官方提供的版本迁移工具，通过检测代码中的旧版 API 调用模式并替换为等价的现代写法，降低升级成本。

```bash
go fix ./...     # 自动迁移
go fix -n ./...  # 预览
```

<pre>
旧版代码
    │
    ▼
go fix scanner
    │
    ├─── 检测 io/ioutil → io
    ├─── 检测 errors.New("") → errors.New("...")
    └─── 检测 sha1.Sum → sha1.New().Sum
    │
    ▼
语义等价的现代代码
</pre>

**机制**：`go fix` 自 Go 1.12 起随版本迭代持续更新迁移规则，每次 Go 大版本发布前由官方确定需要迁移的 API 集合。其本质是模式替换，不做语义推断——仅处理官方定义的已知旧 API 模式。

---

## go mod：Go 模块依赖关系的声明、解析与锁定

`go mod` 是 Go 1.11 引入的 module 模式核心，负责解析 `go.mod` 声明的依赖图、锁定版本（`go.sum`）、管理私有模块路由。

```bash
go mod init github.com/user/project  # 初始化
go mod tidy                          # 清理未用依赖
go mod download                      # 预下载
go list -m all                      # 查看完整依赖树
```

<pre>
go.mod（声明）
    │
    ▼
go mod tidy
    │
    ├─── 扫描 import 语句
    ├─── 比对 go.mod
    ├─── 添加缺失 / 删除未用
    └─── 更新 go.sum（内容哈希锁定）
    │
    ▼
可重现构建（任何机器相同的依赖图）
</pre>

**机制**：`go.sum` 每行是 `module@version h1:base64` 三元组，h1 是 `git ls-remote` 的 tree hash 而非 Package 内容哈希，保证不可伪造。`GOPRIVATE`/`GONOSUMDB` 环境变量控制私有模块绕过代理和校验。

---

## go generate：构建时代码生成的声明式触发协议

`go generate` 是 `go generate` 命令扫描源码中 `//go:generate` 注释并执行对应工具的构建时生成协议，实现 protobuf、mock、stringer 等代码的自动化生成。

```go
//go:generate stringer -type Status -linecomment
//go:generate protoc --go_out=. proto.proto
```

<pre>
go generate ./...
    │
    ▼
扫描源码中的 //go:generate 指令
    │
    ├─── 解析工具名与参数
    └─── 执行 $PATH 工具
            │
            ▼
        输出生成的 .go 文件
</pre>

**机制**：`go generate` 在标准 `go build` 流程外运行，不受 `GOPROXY` 影响，工具需预先安装或使用 `go install` 全局安装后 `$PATH` 可达。生成的代码通常加入 `.gitignore` 或版本控制，取决于项目策略。

---

## go doc：Go 包文档的本地索引与查询接口

`go doc` 是 Go 官方文档系统的命令行接口，通过解析源码注释与 `doc` 导出节提供即时的类型、函数、示例文档。

```bash
go doc fmt           # 包文档
go doc fmt.Println   # 函数签名与注释
go doc -all sql      # 包含非导出符号
```

<pre>
go doc [package].[symbol]
    │
    ▼
遍历 $GOROOT/src / $GOPATH/src
    │
    ├─── 读取源码
    ├─── 解析 package doc 注释
    └─── 格式化输出
    │
    ▼
终端文档（无网络依赖）
</pre>

**机制**：Go 1.5 引入的 `go doc` 直接解析源码而非预编译 doc 文件，保证文档与代码版本同步，无网络也能查询。其输出格式优先机器可读性，便于 IDE 集成。

---

## go work：多模块工作区的构建上下文统一管理

`go work` 是 Go 1.18 引入的工作区模式，解决多模块同时开发时的版本协调问题，通过 `go.work` 文件声明模块图，覆盖 `go.mod` 的模块解析。

```bash
go work init ./module1 ./module2  # 初始化工作区
go work use ./module3             # 添加模块
go work sync                     # 同步
```

<pre>
go.work
use (
    ./module1
    ./module2
)
    │
    ▼
go build / go test
    │
    ├─── 解析 go.work
    └─── 优先使用本地 use 路径
            │
            ▼
        构建（无需 replace 指令）
</pre>

**机制**：`go.work` 不提交到版本库（通常加入 `.gitignore`），仅用于本地多模块联调。其解析优先级高于 `go.mod` 的 `replace` 指令，使得本地替换与最终 `go.mod` 声明可以共存而不冲突。

## 工具链数据流总览

```
源码 (*.go, *_test.go, go.mod, go.work)
    │
    ├─── go fmt ──▶ 规范化源文件
    │
    ├─── go generate ──▶ 生成代码
    │
    ├─── go build ──▶ 可执行文件
    │
    ├─── go test ──▶ 测试报告 + 覆盖率
    │
    ├─── go vet ──▶ 静态警告
    │
    └─── go doc ──▶ 文档查询
```

## 命令生态依赖关系

```
go env ──▶ GOROOT/GOPATH/GOMODCACHE ──▶ 所有命令的路径解析基础
go mod ──▶ go.mod ──▶ go get / go build / go test 依赖解析
go work ──▶ go.work ──▶ 多模块联调时覆盖 go mod
go vet ──▶ go build 成功后才运行（基于编译后 AST）
```
