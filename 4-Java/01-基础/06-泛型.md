# 泛型

## 概述

泛型（Generics）是 Java 5 引入的特性，**在编译时进行类型安全检查，避免强制类型转换**。

核心优势：
- **类型安全**：编译时检查，减少 `ClassCastException`
- **代码复用**：编写适用于多种类型的通用代码
- **消除强制转换**：代码更简洁

## 类型参数命名约定

- `<E>` - Element（集合元素）
- `<K, V>` - Key, Value（键值对）
- `<T>` - Type（一般类型）
- `<N>` - Number（数字类型）
- `<R>` - Result（返回类型）

## 泛型类

```java
public class Box<T> {
    private T content;
    public Box(T content) { this.content = content; }
    public T getContent() { return content; }
    public void setContent(T content) { this.content = content; }
}
```

## 泛型接口

```java
public interface Repository<T, ID> {
    T findById(ID id);
    List<T> findAll();
    void save(T entity);
    void delete(ID id);
}
```

## 泛型方法

```java
public static <T> T findFirst(T[] array, Predicate<T> predicate) {
    for (T element : array) {
        if (predicate.test(element)) return element;
    }
    return null;
}
```

## 有界类型参数

### 上界限定

`T extends Number`：T 必须继承或实现 Number。可使用 `&` 分隔多个上界。

### 下界限定

`? super T`：T 或 T 的父类型。写入安全，返回类型是 Object。

### 通配符对比

| 符号 | 含义 | 用途 |
|------|------|------|
| `<?>` | 无界通配符 | 只读操作 |
| `<? extends T>` | 上界限定 | 读取安全（返回 T） |
| `<? super T>` | 下界限定 | 写入安全（接受 T） |

**为什么 `List<Integer>` 不是 `List<Number>` 的子类型：** 若允许 `List<Integer>` 赋值给 `List<Number>`，则可以向其中加入 `Double`，破坏 Integer 列表的类型安全。通配符 `List<? extends Number>` 只允许读取（生产者），不允许写入。

**PECS 原则（Producer Extends, Consumer Super）：** 生产者（读取数据）用 `extends`，消费者（写入数据）用 `super`。

```java
public double sum(List<? extends Number> list) {
    double sum = 0;
    for (Number n : list) sum += n.doubleValue();
    return sum;
}
```

```java
public void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
}
```

## 类型擦除

Java 泛型通过**类型擦除**实现：编译时进行类型检查，运行时移除泛型信息。`T` 被替换为 `Object` 或上界。

```java
public class Box<T> {
    private T content;
    public T getContent() { return content; }
}
// 编译后：
public class Box {
    private Object content;
    public Object getContent() { return content; }
}
```

### 类型擦除的影响

```java
E[] array = (E[]) new Object[10];
Stack<Integer> intStack;
if (obj instanceof List<String>) { }
if (obj instanceof List<?>) { }
```

**为什么不能创建泛型数组：** 泛型类型在运行时被擦除为 Object，数组协变特性会导致类型安全漏洞。`new Object[10]` 不能作为 `E[]` 使用。

**为什么不能 instanceof 泛型：** 运行时泛型信息已擦除，`List<String>` 和 `List<Integer>` 在运行时都是 `List`，无法区分。

## 泛型与继承

Integer 是 Number 的子类型，但 `List<Integer>` 不是 `List<Number>` 的子类型。使用通配符实现协变和逆变。

```java
List<? extends Number> numList = new ArrayList<Integer>();
List<? super Integer> intList = new ArrayList<Number>();
```

## 泛型擦除与桥方法

子类重写父类泛型方法时，编译器生成桥方法保持多态。

```java
public class Node<T> {
    private T data;
    public T getData() { return data; }
    public void setData(T data) { this.data = data; }
}

public class StringNode extends Node<String> {
    @Override
    public String getData() { return super.getData(); }
    @Override
    public Object getData() {
        return this.getData();
    }
}
```

**为什么需要桥方法：** 子类 `StringNode` 返回 `String`，但父类 `Node<T>` 的 `getData()` 返回 `Object`。编译器生成返回 `Object` 的桥方法，使多态调用成立。

## 泛型约束

```java
public <T> T createInstance(Class<T> clazz) {
    return clazz.newInstance();
}
public class GenericClass<T> {
    public static <T> T createInstance() { }
}
public class GenericException<T> extends Exception { }
```

**为什么静态方法不能使用类泛型参数：** 泛型参数属于实例，静态方法属于类。类加载时泛型信息尚未确定，无法推断静态方法调用所使用的具体类型。
