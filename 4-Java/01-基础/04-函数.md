# 函数

## 定义

在 Java 中，"函数"被称为**方法**（Method），因为 Java 是纯面向对象语言，所有方法都必须定义在类内部。

从计算理论视角，方法调用是**控制流的状态转移**：调用点保存当前执行上下文（PC、局部变量、 operand stack），跳转到方法入口；方法返回时恢复上下文，控制流回到调用点。

从物理层面，每次方法调用在栈上分配一个**栈帧**（Stack Frame），这是 Java 运行时内存管理的核心结构。

## 数学模型

### 栈帧大小的形式化

每次方法调用分配一个**栈帧**（Stack Frame），包含：
- 局部变量表（Local Variable Array）：参数 + 局部变量
- 操作数栈（Operand Stack）：计算中间结果
- 帧数据（Frame Data）：指向运行时常量池的引用

设局部变量数为 $n$ ，操作数栈最大深度为 $m$ ：

$\text{栈帧大小} = \underbrace{n \times 4\text{B}}_{\text{局部变量表}} + \underbrace{m \times 4\text{B}}_{\text{操作数栈}} + \text{帧数据开销}$

Java 栈帧大小是**静态确定的**（编译时分析），与运行时数据无关。

**为什么是 4 字节**：Java 栈帧中的局部变量槽和操作数栈槽的大小是 4 字节（32 位）。这是因为：
1. JVM 是基于栈的虚拟机，操作数栈中的值通常是 32 位
2. long 和 double 占用 2 个槽（64 位），但仍然是原子操作

### 方法签名的哈希冲突

方法签名（包括参数类型）经**descriptor hashing**映射到方法表的槽位。设方法名长度为 $n$ ，参数类型列表为 $T_1, T_2, ..., T_k$ ：

$\text{descriptor} = \text{returnType} + "(" + \sum_{i=1}^{k} T_i + ")"$

JVM 使用 **符号引用**（Symbolic Reference）而非直接地址调用，实现了解耦。符号引用在类加载的**解析阶段**被替换为直接引用。

**符号引用的数学结构**：符号引用是三元组 $(C, M, D)$ ，其中：
- $C$ ：所属类
- $M$ ：方法名
- $D$ ：描述符（参数类型 + 返回类型）

解析过程是将符号引用映射到直接引用的过程：
$\text{resolve}: (C, M, D) \rightarrow \text{MethodHandle}$

### 方法重载的匹配顺序（形式化）

给定实参类型 $A_1, ..., A_n$ 和候选方法 $m_i(T_{i1}, ..., T_{in})$ ，匹配优先级：

1. **精确匹配**： $A_j = T_{ij}$ 对所有 $j$
2. **加宽匹配**： $A_j \rightarrow_{widen} T_{ij}$ （byte → short → int → long → float → double）
3. **装箱/拆箱匹配**： $A_j \rightarrow_{box} T_{ij}$ 或 $A_j \rightarrow_{unbox} T_{ij}$
4. **varargs 匹配**：尝试将剩余实参打包为数组

**匹配算法的复杂度**：设候选方法数为 $m$ ，参数数为 $n$ ，最坏情况需要 $O(m \times n)$ 次类型比较。

**为什么返回类型不参与重载决策**：方法签名的哈希值必须唯一确定。若返回类型不同但参数相同，哈希冲突无法区分。

### 递归的栈帧代价

设每次递归调用分配 $S$ 字节栈帧，递归深度 $d$ ：

$\text{总栈内存} = O(d \cdot S)$

Java 不支持尾调用优化（Tail Call Optimization, TCO），因此深度递归会导致 `StackOverflowError`。

**数学约束**：栈内存是有限的。若递归深度 $d$ 使得 $d \cdot S > \text{MAX_STACK_SIZE}$ ，则触发 `StackOverflowError`。

**尾调用优化的数学解释**：尾调用优化将递归转化为迭代，避免栈帧的线性增长。设尾调用形式为：
$f(x) = g(h(x))$
其中 $g$ 是尾部调用。若 $g$ 是 $f$ 自身的调用，则为尾递归。优化后， $f$ 的栈帧被 $g$ 的栈帧复用，空间复杂度从 $O(d)$ 降为 $O(1)$。

### 方法分派的复杂度

方法调用 `obj.method(args)` 的分派过程：
1. 在对象的实际类型 $T$ 的方法表中查找 method
2. 若找到，调用；否则在父类中继续查找
3. 直到找到或到达 Object

这形成**继承链上的线性查找**，复杂度 $O(h)$ ，其中 $h$ 是继承层次深度。

**虚函数表（vtable）实现**：

| 类 | vtable 起始偏移 | method1 | method2 | ... |
|----|-----------------|---------|---------|-----|
| A | 0 | A::m1 | A::m2 | ... |
| B extends A | 偏移 | B::m1 | A::m2 | ... |

vtable 的数学定义：
$\text{vtable}[i] = \text{the ith virtual method's implementation for this type}$

动态分派通过查表实现： $\text{dispatch}(obj, m) = \text{vtable}[m]$ 。

## 数据流

<pre>
调用者栈帧                        被调用者栈帧
+------------------+              +------------------+
| ...              |              | 参数副本         |
| 调用点 PC         |              | 局部变量         |
| 返回地址         | ──────>      | 操作数栈         |
+------------------+  call        +------------------+
         │                            │
         │                            ▼
         │                      方法体执行
         │                            │
         │ <──────────────────────────┘
         │           return
         ▼
恢复执行（返回地址）
</pre>

**所有权转移**：调用者将参数副本（值复制）传递给被调用者；返回值通过 operand stack 传递；栈帧本身由线程独立管理。

**参数传递的数据形态**：
- 基本类型：位复制（bits copy），无形态变换
- 引用类型：地址复制，指向同一堆对象

## 机制

### 方法重载（Overload）的本质

同一类中方法名相同但参数列表不同，编译时确定具体调用哪个方法（**静态分派**）。

**为什么返回类型不参与重载决策**：方法签名的哈希值必须唯一确定。若返回类型不同但参数相同，哈希冲突无法区分。

```java
void foo(String s) { }
void foo(String s) { return String; }  // 编译错误：重复方法
```

### 方法引用 vs Lambda 的实现差异

Lambda 表达式在字节码中生成 **invokedynamic 调用点**（JEP 309），首次执行时由引导方法（Bootstrap Method）生成一个**闭包对象**。

方法引用直接指向已存在的方法，字节码层面使用 `invokestatic` 或 `invokevirtual`，无需生成新对象。

**性能影响**：
- 方法引用在 JIT 阶段更容易被内联（指向明确方法）
- Lambda 闭包可能有额外的堆分配（除非 escape analysis 优化）

### 解释执行 vs JIT 编译

Java 程序执行分两个阶段：

**阶段 1：解释执行**
- 字节码逐条解释执行
- JVM 维护**热点计数器**（Hotspot Counter）
- 计数器达到阈值触发 JIT 编译

**阶段 2：JIT 编译**
- 将热点字节码编译为本地机器码
- Tiered Compilation 将编译分为多个层级（见 01-安装与环境）

**方法内联（Method Inlining）**

JIT 编译器最重要的优化之一。将被调用方法的主体直接嵌入调用点：

```java
// 调用者
int result = addOne(x);

// 内联后（近似等价）
int result = x + 1;
```

**内联决策的数学约束**：
- 内联收益 = 减少的方法调用开销 - 增加的代码大小
- 方法调用开销 ≈ 10-20 周期（跳转 + 参数传递 + 栈帧操作）
- 内联阈值：热点计数 > 1500 次

### 单态 vs 多态调用点

**单态（Monomorphic）**：调用点只有一个可预期的目标类型

```java
obj.method();  // obj 始终是同一类型
```

**多态（Polymorphic）**：调用点有多个可能的目标类型

```java
((Shape)obj).draw();  // obj 可能是 Circle, Rectangle, Triangle
```

**去虚化（Devirtualization）**：若 JIT 证明调用点是单态的，可将虚方法调用转换为直接调用，消除 vtable 查找开销。

### 尾递归与迭代

尾递归（Tail Recursion）指方法返回的是自身调用的结果：

```java
// 尾递归形式
long fibonacci(int n, long a, long b) {
    if (n == 0) return a;
    return fibonacci(n - 1, b, a + b);  // 返回自身调用结果
}
```

Java **没有**尾调用优化（TCO）。但可以通过**蹦床模式**（Trampoline）模拟：

```java
sealed interface Trampoline<T> permits Done, Bounce {
    static <T> Trampoline<T> done(T value) { return new Done<>(value); }
    static <T> Trampoline<T> bounce(Supplier<Trampoline<T>> next) { return new Bounce<>(next); }
    T get();
}
```

**蹦床模式的数学解释**：蹦床模式将递归调用转化为数据累积。每次递归返回的不是最终值，而是一个 thunk（待求值表达式）。主循环不断调用 thunk，直到得到最终值（Done）。

### 构造器链的执行顺序

构造器调用链 `new Child()` 的执行顺序：

1. 分配内存（Eden 区）
2. 初始化字段为默认值（0/null/false）
3. 执行 `Child` 构造器体，第一行隐式/显式调用 `super()`
4. `super()` 调用 `Parent` 构造器，重复步骤 3-4
5. 向上递归直到 `Object` 构造器
6. 执行 `Parent` 构造器体剩余部分
7. 执行 `Child` 构造器体剩余部分

**约束**：若构造器第一行不是 `this()` 或 `super()`，编译器自动插入 `super()` 调用。`this()` 调用其他构造器，用于构造器复用。

**对象初始化的数学约束**：字段初始化按照以下顺序执行：
1. 静态字段初始化器（类加载时）
2. 实例字段默认值初始化
3. 实例字段初始化器（按源代码顺序）
4. 构造器体

这形成了一个偏序关系，必须满足依赖顺序。

### varargs 的实现机制

```java
void printAll(String... args) { }
```

编译器将其转换为：

```java
void printAll(String[] args) { }
```

调用点 `printAll("a", "b", "c")` 转换为 `printAll(new String[]{"a", "b", "c"})`。

**性能影响**：每次调用都会创建一个新数组（除非显式传递数组）。

### 静态初始化器的原子性

静态字段初始化和静态初始化块在类加载时执行，且**保证线程安全**。JVM 通过类加载锁保证静态初始化只执行一次。

**初始化时序**：
1. 触发类初始化（new、静态方法访问、静态字段访问）
2. 获取类加载锁
3. 检查是否已初始化
4. 若未初始化，执行 `<clinit>`（字节码中的构造器）
5. 释放锁

## 参考存根

```java
// 方法引用示例（静态方法引用）
Function<String, Integer> parser = Integer::parseInt;

// 递归（注意栈溢出风险）
long fibonacci(int n) {
    if (n <= 1) return n;
    return fibonacci(n - 1) + fibonacci(n - 2);  // 指数级栈使用
}

// 迭代版本（推荐）
long fibonacciIter(int n) {
    if (n <= 1) return n;
    long a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        long temp = a + b;
        a = b;
        b = temp;
    }
    return b;
}

// 蹦床模式模拟尾递归
sealed interface Trampoline<T> permits Done, Bounce {
    final class Done<T> implements Trampoline<T> {
        private final T value;
        Done(T value) { this.value = value; }
        public T get() { return value; }
    }
    final class Bounce<T> implements Trampoline<T> {
        private final Supplier<Trampoline<T>> next;
        Bounce(Supplier<Trampoline<T>> next) { this.next = next; }
        public T get() { return next.get().get(); }
    }

    // 使用蹦床计算阶乘
    static Trampoline<Long> factorialTrampoline(int n, long acc) {
        if (n <= 1) return done(acc);
        return bounce(() -> factorialTrampoline(n - 1, n * acc));
    }
}
```
