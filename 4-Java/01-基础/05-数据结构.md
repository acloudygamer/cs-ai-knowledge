# 数据结构

## Collection 框架

- `List`：ArrayList（动态数组）、LinkedList（双向链表）
- `Set`：HashSet、TreeSet、LinkedHashSet
- `Map`：HashMap、TreeMap、LinkedHashMap
- `Queue`：ArrayDeque、PriorityQueue

## ArrayList 内部实现

ArrayList 底层使用**动态数组**（`Object[] elementData`），初始容量 10，每次扩容 1.5 倍。

### 关键操作时间复杂度

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| get(index) | O(1) | 数组直接索引 |
| add(E) | O(1) amortized | 均摊 O(1)，扩容时 O(n) |
| add(index, E) | O(n) | 移动 index 后所有元素 |
| remove(index) | O(n) | 移动 index 后所有元素 |
| contains | O(n) | 遍历数组 |

**为什么 ArrayList 随机访问是 O(1)：** 数组在内存中连续存储，索引访问只需计算偏移量 `baseAddress + index * elementSize`，是常数时间操作。

**为什么 add 是均摊 O(1)：** 大多数 add 操作在已分配空间内完成（O(1)）；少数扩容操作需要复制整个数组（O(n)）。由于扩容 1.5 倍，n 次操作总成本 O(n)，均摊每次 O(1)。

```java
public class ArrayList<E> {
    private static final int DEFAULT_CAPACITY = 10;
    private Object[] elementData;
    private int size;
    private void grow(int minCapacity) {
        int oldCapacity = elementData.length;
        int newCapacity = oldCapacity + (oldCapacity >> 1);
        elementData = Arrays.copyOf(elementData, newCapacity);
    }
}
```

## LinkedList 内部实现

LinkedList 是**双向链表**，每个节点包含 `prev`、`item`、`next` 三个引用。

### 关键操作时间复杂度

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| get(index) | O(n) | 遍历链表 |
| add(E) | O(1) | 尾部插入 |
| remove(index) | O(n) | 需先定位 |
| addFirst/removeFirst | O(1) | 链表头部操作 |

**为什么 ArrayList 随机访问快而 LinkedList 慢：** ArrayList 底层是连续内存，CPU 缓存一次加载多个元素（缓存行）；LinkedList 的节点分散在堆内存中，每次访问都需要追踪指针，缓存命中低。

### ArrayList vs LinkedList

| 场景 | ArrayList | LinkedList |
|------|-----------|------------|
| 随机访问 | O(1) | O(n) |
| 头部插入/删除 | O(n) | O(1) |
| 尾部插入/删除 | O(1) amortized | O(1) |
| 内存占用 | 连续，节省指针 | 每节点 2 个指针 |

```java
private static class Node<E> {
    E item;
    Node<E> next;
    Node<E> prev;
}
```

## HashMap 内部实现（JDK 8+）

### 结构演进

- JDK 7：数组 + 链表（冲突用拉链法）
- JDK 8+：数组 + 链表 + 红黑树（链表长度 > 8 转为红黑树）

**为什么链表长度超过 8 转为红黑树：** 链表查找 O(n)，红黑树查找 O(log n)。当 n=8 时，log(8)=3，远小于 8。转为红黑树后最坏情况从 O(n) 降为 O(log n)。

### 红黑树特性

HashMap 使用红黑树保证最坏 O(log n) 查找性能：每个节点非红即黑，根节点和叶子节点（NIL）是黑色，红节点的子节点必须是黑色，从任一节点到其每个叶子的路径包含相同数量的黑色节点。

**为什么选择红黑树而不是平衡二叉树：** 红黑树是近似平衡的（最长路径不超过最短路径的 2 倍），插入和删除操作只需要 O(1) 次旋转，而严格平衡的 AVL 树需要 O(log n) 次旋转。HashMap 插入删除频繁，性能更优。

### 关键操作时间复杂度

| 操作 | 平均 | 最坏 |
|------|------|------|
| get | O(1) | O(log n)（红黑树） |
| put | O(1) | O(log n)（红黑树） |
| remove | O(1) | O(log n)（红黑树） |

### put 流程

<pre>
put(key, value)
  ↓
1. 计算 hash = hash(key)
  ↓
2. 找到桶位置 i = (n-1) & hash
  ↓
3. 桶为空 → 直接插入
   桶不为空 →
     a. key 相等 → 覆盖 value
     b. 当前是 TreeNode → 红黑树插入
     c. 当前是链表 → 遍历尾插
        - 找到相同 key → 覆盖
        - 未找到 → 插入尾部，若长度>8 → 转红黑树
  ↓
4. 检查是否需要扩容
</pre>

### 扩容机制

- 扩容因子 0.75（`loadFactor`），`threshold = capacity * loadFactor`
- 容量总是 2 的幂（方便取模）
- 扩容时容量翻倍，所有元素重新分配桶位置

<pre>
扩容前: capacity = 16, index = (n-1) & hash = 15 & hash
扩容后: capacity = 32, 新位置 = 旧位置 或 旧位置 + 16
        （取决于 hash 高位是否为 1）
</pre>

```java
public class HashMap<K, V> {
    transient Node<K, V>[] table;
    static class Node<K, V> {
        final int hash;
        final K key;
        V value;
        Node<K, V> next;
    }
    static final class TreeNode<K, V> {
        TreeNode<K, V> parent, left, right, prev;
        boolean red;
    }
}
```

## 时间复杂度汇总

### Collection

| 实现 | get | add | remove | contains |
|------|-----|-----|--------|----------|
| ArrayList | O(1) | O(1)* | O(n) | O(n) |
| LinkedList | O(n) | O(1) | O(n) | O(n) |
| HashSet | O(1) | O(1) | O(1) | O(1) |
| TreeSet | O(log n) | O(log n) | O(log n) | O(log n) |

### Map

| 实现 | get | put | remove | containsKey |
|------|-----|-----|--------|-------------|
| HashMap | O(1)* | O(1)* | O(1)* | O(1)* |
| TreeMap | O(log n) | O(log n) | O(log n) | O(log n) |
| LinkedHashMap | O(1) | O(1) | O(1) | O(1) |

\* 均摊复杂度，红黑树时为 O(log n)
