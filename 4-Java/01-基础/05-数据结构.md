# 数据结构

## 定义

Java Collection 框架是**接口-实现分离**的泛型数据结构库。核心接口（List、Set、Map、Queue）定义了抽象数据类型（ADT），具体实现（ArrayList、HashMap 等）提供了空间-时间权衡的不同配置。

从抽象代数视角，List 是**序列**（sequence），Set 是**集合**（set with uniqueness），Map 是**偏函数**（partial function K → V），Queue 是**FIFO 序列**。

## 数学模型

### ArrayList 扩容的均摊复杂度

设初始容量 $c_0 = 10$，增长因子 $k = 1.5$（即 `oldCapacity + oldCapacity >> 1`）。第 $i$ 次扩容后容量：

$$c_i = \min(c_0 \cdot k^i, \text{MAX_ARRAY_SIZE})$$

插入 $n$ 个元素的**总移动代价**：

$$T(n) = \sum_{i=0}^{\lfloor \log_k n \rfloor} c_i = c_0 \cdot \frac{k^{\lfloor \log_k n \rfloor + 1} - 1}{k - 1} = O(n)$$

**均摊代价**：$\frac{T(n)}{n} = O(1)$

### HashMap 负载因子与冲突概率

HashMap 使用**开放地址法**（链表/红黑树）解决哈希冲突。负载因子 $\alpha = \frac{n}{m}$（元素数/桶数）控制冲突概率。

查找操作的期望时间：
- 链表：$O(1 + \alpha)$
- 红黑树：$O(1 + \log \alpha)$

当链表长度超过阈值 $T = 8$ 时，转红黑树的条件：

$$\alpha > \frac{T}{\text{AVERAGE_PHI_PER_BUCKET}}$$

JVM 的对象头哈希码分布影响实际冲突率。

### 红黑树的旋转复杂度

红黑树是**近似平衡二叉搜索树**，保证最长路径 $\leq 2 \times$ 最短路径。插入/删除最多需要：
- $O(1)$ 次旋转（最多 2 次）
- $O(\log n)$ 次重新着色

对比 AVL 树（严格平衡）：插入最多 $O(\log n)$ 次旋转，但查询性能更优（更浅）。

### HashMap 的容量与取模约束

HashMap 要求容量为 $2^m$（幂 of 2），使 `(n-1) & hash` 等价于 `hash % n`，但位运算比除法快得多。

**数学约束**：对于 $n = 2^m$，$x \mod n = x \& (n-1)$。这是因为 $n-1$ 的二进制表示是 $m$ 个 1。

### PriorityQueue 的堆性质

PriorityQueue 基于**二叉堆**（binary heap），满足：
- **堆性质**：每个节点 $\leq$ 其子节点（最小堆）
- **完全二叉树**：除最后一层外，所有层都是满的

堆的数组表示中，对于索引 $i$：
- 父节点：$(i - 1) / 2$
- 左子节点：$2i + 1$
- 右子节点：$2i + 2$

**上浮/下沉操作**：$O(\log n)$，用于维护堆性质。

## 数据流

### ArrayList add 操作

<pre>
[1, 2, 3]            [1, 2, 3, 4]           扩容后
size=3, cap=4        size=4, cap=4           [1, 2, 3, 4, _, _, _, _]
         │                  │                size=4, cap=8
         │  数组内写入       │
         └──────────────────┘
              O(1) amortized
</pre>

**数据所有权**：ArrayList 的 `elementData` 数组持有元素的所有权。当扩容时，旧数组被废弃（GC 可回收），新数组持有所有权。

### HashMap put 操作

<pre>
key → hash(key) → index = (n-1) & hash
                    │
                    ▼
              ┌───────────┐
              │ bucket[0] │ → ... → bucket[i] → ...
              └───────────┘
                    │
                    ├──> null → 新建 Node
                    ├──> key 相等 → 覆盖 value
                    ├──> TreeNode → 红黑树插入
                    └──> Node → 遍历尾插，若 size>8 → 转红黑树
</pre>

### HashMap 扩容的再哈希

扩容时容量翻倍：$n_{new} = 2 \cdot n_{old}$。元素新位置计算：

$$\text{newIndex} = \text{oldIndex} \quad \text{或} \quad \text{oldIndex} + \text{oldCap}$$

取决于 `hash & oldCap` 是否为 0（hash 高位是否为 1）。这保证了每个元素只需检查一个额外位。

## 机制

### ArrayList vs LinkedList 的缓存行为

**CPU 缓存行**：现代 CPU 一次从主存加载 64B（缓存行）。访问连续内存时，下一个元素很可能已在缓存中（**空间局部性**）。

| 操作 | ArrayList | LinkedList |
|------|-----------|------------|
| 随机访问 | O(1)，缓存友好 | O(n)，缓存不友好 |
| 头部插入 | O(n)，需移动所有元素 | O(1)，但需分配节点 |
| 尾部插入 | O(1) amortized | O(1) |

**归约终点**：LinkedList 的每个节点是独立分配的（`new Node()`），在堆中不连续，导致 CPU 缓存预取失效。每次 `next` 跳转都可能触发 cache miss。

### CopyOnWriteArrayList 的写放大

CopyOnWriteArrayList 的每次写操作都复制整个底层数组。

设数组大小为 $n$，写操作代价：

$$T_{write} = O(n)$$

读操作代价：

$$T_{read} = O(1)$$

**适用场景**：读多写少且写操作不频繁（事件监听器列表）。

### HashMap 的并发问题

HashMap 不是线程安全的，并发修改可能导致：
- **数据丢失**：两个线程同时 put，hash 冲突时一个 put 被覆盖
- **死循环**：扩容时形成环形链表（JDK 7 及之前的实现）
- **ConcurrentHashMap**：JDK 8+ 使用 CAS + synchronized，每个 bucket 独立加锁

**ConcurrentHashMap 的锁粒度**：

| 版本 | 锁粒度 | 并发度 |
|------|--------|--------|
| JDK 7 | Segment（数组，每个段一把锁） | 16 |
| JDK 8+ | Node（每个 bucket 一把锁， CAS 初始化） | 数组长度/16 |

### LinkedHashMap 的访问顺序

LinkedHashMap 维护**双向链表**记录插入顺序或访问顺序：

```java
// 访问顺序模式
LinkedHashMap<Integer, String> map = new LinkedHashMap<>(16, 0.75f, true);
```

`true` 启用访问顺序（LRU 缓存）。每次 `get` 或 `put` 将该 Entry 移到链表尾部。

**LRU 缓存实现**：

```java
if (map.size() >= capacity) {
    map.remove(map.entrySet().iterator().next());  // 删除最老的
}
```

### HashSet 的数学本质

HashSet 是 HashMap 的包装：

```java
public class HashSet<E> {
    private final HashMap<E, Object> map = new HashMap<>();
    public boolean add(E e) { return map.put(e, PRESENT) == null; }
}
```

Set 的语义（元素唯一性）通过 HashMap 的 key 唯一性实现。

## 时间复杂度汇总

### Collection 接口

| 实现 | get | add | remove | contains |
|------|-----|-----|--------|----------|
| ArrayList | O(1) | O(1)* | O(n) | O(n) |
| LinkedList | O(n) | O(1) | O(n) | O(n) |
| HashSet | O(1) | O(1) | O(1) | O(1) |
| TreeSet | O(log n) | O(log n) | O(log n) | O(log n) |

### Map 接口

| 实现 | get | put | remove | containsKey |
|------|-----|-----|--------|-------------|
| HashMap | O(1)* | O(1)* | O(1)* | O(1)* |
| TreeMap | O(log n) | O(log n) | O(log n) | O(log n) |
| LinkedHashMap | O(1) | O(1) | O(1) | O(1) |
| ConcurrentHashMap | O(1)* | O(1)* | O(1)* | O(1)* |

\* 均摊复杂度，红黑树退化时为 O(log n)

## 参考存根

```java
// ArrayList 扩容机制
public class ArrayList<E> {
    private void grow(int minCapacity) {
        int oldCapacity = elementData.length;
        int newCapacity = oldCapacity + (oldCapacity >> 1);
        elementData = Arrays.copyOf(elementData, newCapacity);
    }
}

// HashMap put 核心逻辑（简化）
V put(K key, V value) {
    int hash = hash(key);
    int i = (n - 1) & hash;
    for (Node<K,V> e = table[i]; e != null; e = e.next) {
        if (e.hash == hash && e.key.equals(key))
            return e.value;
    }
    addNode(hash, key, value, i, false);
    return null;
}

// LRU 缓存实现
public class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LRUCache(int capacity) {
        super(16, 0.75f, true);
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}
```
