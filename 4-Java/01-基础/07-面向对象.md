# 面向对象

## 定义

面向对象编程（OOP）是一种将**状态**（数据）和**行为**（方法）封装在**抽象数据类型**（类）中的编程范式。核心概念是**对象**——拥有自身状态且能响应消息的实体。

从抽象代数视角，类是**代数结构**（Algebraic Structure），定义了数据的表示和操作的不变式。子类通过**扩展**（extends）或**实现**（implements）建立**子类型关系**，构成类型层次。

## 数学模型

### 封装的约束形式化

封装是**信息隐藏**的实现机制。设类 $C$ 的内部表示为 $R$ ，对外接口为 $I$ 。封装要求：

$\forall r \in R, \forall i \in I: \text{valid}(i, r) \Rightarrow \text{invariant}(r)$

即：所有通过接口的操作必须维持不变量。形式化约束：

$\forall c \in C, \forall m \in \text{methods}(C): \text{pre}(m, c) \Rightarrow \text{post}(m, c)$

**违反封装的后果**：若字段直接暴露为 public，外部代码可绕过不变量检查直接修改状态，破坏对象的不变量约束。

### 继承的谓词逻辑形式化

继承建立 **is-a** 关系：若 $S$ extends $T$ ，则：

$S \models p \Rightarrow T \models p$

其中 $p$ 是类型 $T$ 的所有可见谓词（方法规格）。子类继承父类的**规约**（Specification），但不一定继承其实现。

**行为子类型（Behavioral Subtyping）**：子类不仅要在结构上是子类型，还要在行为上也是子类型。即子类方法必须满足：

- **前置条件不加强**：子类的 pre 要比父类的 pre 更弱或相等
- **后置条件不弱化**：子类的 post 要比父类的 post 更强或相等

**Liskov 替换原则的形式化**：

Liskov 替换原则（LSP）的谓词逻辑形式化：

$\forall x: S, \forall P: \text{predicate on } T: P(x) \Rightarrow P(T(x))$

即： $S$ 的所有实例在 $T$ 出现的上下文中，必须保持 $T$ 的行为性质。

**违反 LSP 的典型案例**：正方形是矩形的子类型，但 setWidth() 和 setHeight() 的行为不一致：

```java
class Rectangle {
    void setWidth(double w) { this.width = w; }
    void setHeight(double h) { this.height = h; }
}

class Square extends Rectangle {
    @Override
    void setWidth(double w) {
        this.width = w;
        this.height = w;  // 违反矩形的不变量：width != height
    }
}
```

Square 作为 Rectangle 使用时，调用 setWidth() 会意外改变 height，违反 LSP。

### 多态的表驱动分派形式化

方法调用 `obj.method()` 的分派可建模为**虚函数表查找**：

$\text{dispatch}(obj, m) = \text{vtable}[\text{type}(obj)][m]$

其中 vtable 是类到方法实现的映射表：

$\text{vtable}: \text{Type} \times \text{Method} \rightarrow \text{Implementation}$

动态分派保证：运行时根据对象的**实际类型**（而非引用类型）选择方法实现。

**vtable 的结构**：

| 类 | vtable 起始偏移 | method1 | method2 | method3 |
|----|-----------------|---------|---------|---------|
| Object | 0 | Object::hashCode | Object::equals | Object::toString |
| Shape | 偏移 | Shape::draw | Shape::area | - |
| Circle | 偏移 | Circle::draw | Circle::area | Circle::getRadius |

### 访问修饰符的格结构

访问修饰符构成一个**格**（Lattice）结构：

```
         public
        /      \
   protected    (package-private 不在此格中)
      |
   (default/package-private)
      |
   private
```

| 修饰符 | 同类 | 同包 | 子类（不同包） | 其他包 |
|--------|------|------|----------------|--------|
| private | ✓ | ✗ | ✗ | ✗ |
| default | ✓ | ✓ | ✗ | ✗ |
| protected | ✓ | ✓ | ✓ | ✗ |
| public | ✓ | ✓ | ✓ | ✓ |

**protected 的设计语义**：子类可能在不同包，需要继承访问权；同包非子类用 default 即可。

## 数据流

<pre>
new Circle(5.0)
         │
         ▼
┌─────────────────────┐
│ 堆：Circle 对象     │
│ - color: "red"      │
│ - radius: 5.0       │
│ - (继承)Shape 字段  │
└─────────────────────┘
         │
         │ 栈：引用变量 circle
         ▼
┌─────────────────────┐
│ Circle circle       │ ──────→ 堆对象
└─────────────────────┘
</pre>

**对象创建过程**：
1. 分配内存（Eden 区）
2. 初始化字段为默认值（0/null/false）
3. 执行构造器链（super() → 字段初始化 → 构造器体）
4. 返回引用

**数据所有权**：堆对象由 GC 管理其生命周期。栈变量持有引用，引用本身在栈帧弹出时消亡，但堆对象是否回收取决于是否仍有其他引用。

## 机制

### 封装的信息隐藏

封装的本质是**不变量维护**：类对外提供受控接口，隐藏内部表示和约束条件。外部代码不能绕过不变量直接操作内部状态。

```java
public class Counter {
    private int count;  // 不变量：count >= 0
    public void increment() { count++; }
    public int getCount() { return count; }
}
```

若 count 直接暴露为 public，可以设为负数，破坏业务约束。

### 继承 vs 组合

继承建立 **is-a** 关系，组合建立 **has-a** 关系。

| 考量 | 继承 | 组合 |
|------|------|------|
| 耦合度 | 高（子类依赖父类实现） | 低（依赖接口） |
| 灵活性 | 编译时绑定 | 运行时可替换 |
| 多态 | 自动获得 | 需接口实现 |

**优先使用组合的原因**：继承使子类脆弱地依赖父类实现细节；组合允许通过接口解耦。

### 接口的默认方法与多继承冲突

Java 8 引入默认方法后，接口可以提供实现。这引入了**多继承冲突**（Diamond Problem）：

```java
interface A { default void foo() { System.out.println("A"); } }
interface B { default void foo() { System.out.println("B"); } }
interface C extends A, B { }  // 编译错误：foo() 冲突
interface C extends A, B {
    @Override
    default void foo() { A.super.foo(); }  // 消歧
}
```

**冲突解决规则**：
1. 同签名默认方法：子类必须显式覆盖
2. 抽象方法优先于默认方法
3. 若两个默认方法冲突，子类必须显式消歧

**为什么 Java 引入默认方法**：主要是为了**接口演化**。在 Java 8 之前，向接口添加新方法会导致所有实现类编译失败。引入默认方法后，可以提供默认实现，现有实现类自动继承，无需修改。

### 内部类的闭包语义

局部内部类和匿名内部类可以访问**隐式 final**（Effectively Final）的局部变量：

```java
int x = 10;  // effectively final
Func f = () -> x;  // 捕获 x 的值
// x = 20;  // 修改后，f 的闭包行为未定义
```

**为什么需要 Effectively Final**：内部类实例的生命周期可能超过方法执行。如果变量可修改，内部类持有的引用将指向不确定的值。

**数学约束**：闭包捕获的是变量的**值**，而非变量本身。这保证了函数式编程的**纯函数**性质。

### 静态内部类 vs 非静态内部类

| 维度 | 静态内部类 | 非静态内部类 |
|------|-------------|--------------|
| 实例关联 | 不持有外部类引用 | 持有外部类引用 |
| 访问外部类成员 | 只能访问 static 成员 | 可访问所有外部类成员 |
| 创建方式 | `new Outer.Inner()` | `outer.new Inner()` |
| 内存泄漏风险 | 无 | 可能（持有外部引用） |

### 密封类的穷尽性约束（Java 17）

密封类（Sealed Class）强制子类的有限集合，保证类型穷尽性：

```java
sealed interface Shape permits Circle, Rectangle, Triangle {}
```

**约束**：穷尽性检查确保 `switch (shape)` 无需 default 分支——所有可能的情况都被枚举。

** permits 列表的约束**：
- 同一包内：子类必须在 permits 列表中
- 不同包：子类必须是 final、 sealed 或 non-sealed

**穷尽性检查的工程价值**：

| 场景 | 无穷尽检查 | 有穷尽检查 |
|------|-----------|-----------|
| 新增子类型 | 运行时 `MatchException` | 编译错误 |
| 代码重构 | 需人工检查所有 switch | 编译器强制验证 |
| 遗漏分支 | 静默执行 default 或 fallthrough | 编译失败 |

### record 类型与积类型（Java 16+）

record 是**透明数据载体**：

```java
record Point(int x, int y) {}
```

编译器自动生成：
- 私有 final 字段
- 构造器（可自定义验证）
- Accessor 方法（`x()`, `y()`）
- equals/hashCode/toString

**数学本质**：record 是**积类型**（Product Type）。Point 的所有可能值构成 $\mathbb{Z} \times \mathbb{Z}$ 的笛卡尔积。

**record 的约束**：
- record 不能声明实例字段（除了编译器自动生成的）
- record 不能继承其他类（但可以实现接口）
- record 自动 final，不能被继承

### 密封接口（Java 17）

密封接口强制实现类的有限集合：

```java
sealed interface Expr permits Literal, Add, Mul {}
```

与密封类相同，所有可能的实现必须在 permits 列表中。

### 内部类与外部类的数据共享

非静态内部类可以访问外部类的所有成员，包括私有成员。这是因为编译器在生成内部类时，会创建一个隐式引用指向外部类实例。

```java
class Outer {
    private int x = 10;
    class Inner {
        int getX() { return x; }  // 实际编译为 Outer.this.x
    }
}
```

字节码层面，编译器生成：
- 外部类持有内部类的引用（通过构造器传递）
- 内部类访问外部类成员时，通过 `Outer.this` 引用

**内存语义**：非静态内部类实例持有外部类实例的引用，这可能导致**内存泄漏**——若内部类实例比外部类实例寿命长，外部类无法被 GC 回收。

## 参考存根

```java
// 抽象类 vs 接口
abstract class Shape {
    abstract double getArea();
}

interface Drawable {
    void draw();
    default void print() { System.out.println("Drawing..."); }
}

// 枚举实现接口
enum Status implements Runnable {
    IDLE { public void run() { } },
    RUNNING { public void run() { } };
}

// 密封类（Java 17）
sealed interface Result<T> permits Success, Failure {
    record Success<T>(T value) implements Result<T> {}
    record Failure<T>(Exception e) implements Result<T> {}
}

// record 类型（Java 16+）
record Range(int lo, int hi) {
    public Range {
        if (lo > hi) {
            throw new IllegalArgumentException("lo > hi");
        }
    }
}
```
