# 变量与类型

## 定义

Java 是静态类型语言：**变量类型在编译时确定**，编译器进行类型检查，提前发现类型错误。

从类型论视角，Java 的类型系统是**名义子类型（nominal subtyping）**：类型兼容性由显式声明的继承/实现关系决定，而非结构兼容性。这与 TypeScript 的结构子类型（structural subtyping）形成对比——TypeScript 检查字段是否存在，Java 检查类型名是否相同。

**名义子类型的数学定义**：设类型 $S$ 和 $T$ ， $S \preceq T$ （ $S$ 是 $T$ 的子类型）当且仅当：
1. $S = T$ （同一类型），或
2. $S$ 显式声明 `extends` 或 `implements` $T$

这意味着类型兼容性需要**显式声明**，不能仅因为结构相似就认为类型兼容。

## 数学模型

### 二进制补码算术的数学本质

Java 整数类型（byte, short, int, long）使用**二进制补码**（Two's Complement）表示。n 位有符号整数的取值范围：

$[-2^{n-1},\ 2^{n-1} - 1]$

| 类型 | n | 范围 |
|------|---|------|
| byte | 8 | $[-128,\ 127]$ |
| short | 16 | $[-32768,\ 32767]$ |
| int | 32 | $[-2^{31},\ 2^{31}-1]$ |
| long | 64 | $[-2^{63},\ 2^{63}-1]$ |

**补码的数学定义**：对于 n 位表示，整数值 x 对应于：

$x \bmod 2^n$

这意味着 Java 整数运算是**模 $2^n$ 环 $\mathbb{Z}/2^n\mathbb{Z}$ 上的算术**。加法和乘法在该环上封闭，减法是加法的逆元运算。

**溢出行为**：溢出是**无声的模运算**，即 `int i = Integer.MAX_VALUE + 1` 结果是 `Integer.MIN_VALUE`。这与 C/C++ 一致，与 JavaScript（使用 IEEE 754 双精度浮点）不同。

$\text{OVERFLOW}: x + 2^{31} \equiv x \pmod{2^{31}}$

**违反约束的后果**：
- 安全关键系统：整数溢出可能导致缓冲区分配过小
- 加密实现：溢出可能破坏密码学安全性质
- 解决方案：使用 `Math.addExact()`, `Math.multiplyExact()` 等带溢出检测的方法

**补码的归约终点**：补码表示可以归约为**模运算**。模运算的代数结构是循环群 $\mathbb{Z}_{2^n}$ ，其中每个元素都有加法逆元（负数）。这解释了为什么 `-x` 不等于 `~x + 1` 在数学上恒成立。

### 自动装箱的缓存代价

`Integer` 包装类内部维护一个**享元池**（Flyweight Pool），范围默认 `-128 ~ 127`：

```java
Integer a = 127;  // 缓存命中，不创建新对象
Integer b = 127;  // 缓存命中，a == b 为 true
Integer c = 128;  // 超出缓存，创建新对象
Integer d = 128;  // c != d
```

**JVM 参数调优**：`-XX:AutoBoxCacheMax=<size>` 可调整缓存上界。

**缓存命中率分析**：设循环次数为 $N$ ，若值均匀分布在 $[-128, 127]$ ：

 $P(\text{cache hit}) = \frac{256}{256 + (N - 256)}$（当  $N > 256$）

对于大循环（ $N >> 256$ ），缓存命中率  $\approx \frac{256}{N}$，装箱开销不可忽略。

**装箱操作的字节码路径**：
```java
Integer x = 42;
```
编译为：
```
bipush 42           // 将 42 压入操作数栈
invokestatic Integer.valueOf(int)  // 调用装箱方法
```

`valueOf()` 内部逻辑：
```java
public static Integer valueOf(int i) {
    if (i >= -128 && i <= Integer.IntegerCache.high)
        return Integer.IntegerCache.cache[i + 128];
    return new Integer(i);
}
```

**缓存的数学本质**：缓存是一种**时间局部性**（temporal locality）的应用——最近使用的值很可能再次使用。享元模式通过共享避免重复创建相同值的对象，减少堆碎片和 GC 压力。

### 字符串常量池的数学模型

字符串字面量在**运行时常量池**（Runtime Constant Pool）中唯一存储。设字面量集合 $L$ ：

$P = \{ s \in L \mid s \text{ 首次出现时创建} \}$

相同内容的字面量共享同一引用。`new String()` 每次创建新对象，即使内容相同。

**字符串驻留的三种方式**：
1. 字面量：`String s = "hello";` → 自动驻留
2. `String.intern()`：显式驻留
3. 字符串常量表达式：编译时常量折叠

**驻留的数学性质**：
```java
String s1 = "hello";
String s2 = "hel" + "lo";  // 编译时常量折叠，结果同 s1
String s3 = new String("hello");  // 新建对象
s1 == s2  // true：同一引用
s1 == s3  // false：不同对象
s1 == s3.intern()  // true：s3 内容被驻留
```

**intern() 的约束**：驻留操作将字符串放入常量池，后续相同内容的字面量共享该引用。但常量池内存有限且属于堆的一部分，过度使用 `intern()` 可能导致 PermGen/Metaspace 溢出（Java 7之前）或堆内存压力（Java 7+）。

### 浮点数精度约束

IEEE 754 双精度浮点数的精度约束：

$\text{相对精度} \approx 2^{-52} \approx 2.22 \times 10^{-16}$

**结合律失效的数学证明**：

设 $a = 1e16$, $b = 1$, $c = -1e16$ ：

$(a + b) + c = (1e16 + 1) + (-1e16) = 1 \neq a + (b + c) = 1e16 + (1 - 1e16) = 0$

**约束**：浮点数运算不满足结合律，顺序敏感。金融计算必须使用 `BigDecimal`。

**归约终点**：浮点数的这种行为源于**有限精度表示**。实数集合 $\mathbb{R}$ 是无限的，但 float/double 只有有限位表示。这导致运算结果依赖于求值顺序。

### 对象头的结构与压缩指针

64 位 JVM 的对象头包含：

| 组件 | 大小 | 内容 |
|------|------|------|
| Mark Word | 8B | 哈希码、GC 分代年龄、锁状态 |
| Klass Pointer | 4B/8B | 指向类元数据的指针 |
| Array Length | 4B | 仅数组对象 |

**UseCompressedOops**：当堆小于 ~32GB 时，JVM 启用压缩指针（CompressedOops），Klass Pointer 使用 4B 而非 8B。这使得：

$\text{对象头大小} = \text{Mark Word} + \text{Compressed Klass Pointer} = 8 + 4 = 12\text{B}$

若未启用压缩：
$\text{对象头大小} = 8 + 8 = 16\text{B}$

**压缩指针的数学约束**：4 字节指针可以寻址 $2^{32} = 4\text{GB}$ 空间。但 Java 对象按 8 字节对齐，因此 4 字节指针实际上可以寻址 $4\text{GB} \times 8 = 32\text{GB}$ 堆空间。这就是为什么 CompressedOops 的上限是 ~32GB。

**填充对齐**：JVM 要求对象大小为 8 字节对齐。因此：

$\text{对象总大小} = \lceil 12 + \sum \text{instance fields} \rceil_{8}$

## 数据流

<pre>
栈内存（Stack）                   堆内存（Heap）
+------------------+              +------------------+
| 基本类型变量      |              | 对象头（mark word + klass pointer）
| int x = 42;      |              +------------------+
| 直接存储值        |              | 实例字段           |
+------------------+              +------------------+
         │                                  │
         │                                  ▼
         │                         ┌─────────────────┐
         │                         | "Hello" (String) │
         │                         | 字符数组 + 长度   │
         │                         └─────────────────┘
         │                                    ▲
         │                                    │
+------------------+                           │
| 引用变量 str     │ ──────────────────────────┘
| (存储对象地址)   |
+------------------+
</pre>

**所有权流转**：
- 基本类型：值直接存储在栈帧局部变量区，无所有权转移
- 引用类型：引用（地址）存储在栈帧，指向堆中对象；对象所有权归 GC 管理

**数据形态变换**：
- 源代码 `int x = 42` → 字节码 `bipush 42`（立即数压栈）
- 源代码 `Integer x = 42` → 字节码 `invokestatic Integer.valueOf`（装箱操作）

## 机制

### 静态类型 vs 动态类型

**为什么静态类型优于动态类型**：

1. **类型安全可证明**：编译器可形式化证明类型错误不存在（Soundness 定理）
2. **性能优化**：编译器可基于类型信息做内联、去虚化等优化
3. **可维护性**：接口契约明确，重构时类型检查防止遗漏
4. **文档价值**：类型签名是最好的文档

动态类型语言（如 Python、JavaScript）的类型检查发生在运行时，错误发现滞后。

**Soundness 定理**：若编译器接受程序，则程序运行时不会发生类型错误。这是静态类型系统的基本保证。

### 基本类型 vs 引用类型的设计权衡

**为什么保留基本类型**：

| 维度 | 基本类型 | 包装类（引用类型） |
|------|----------|-------------------|
| 内存布局 | 内联存储，无对象头 | 对象头（12B）+ 指针 |
| 访问速度 | O(1) 无间接寻址 | O(1) 但多一次解引用 |
| 空值安全 | 不可能为 null | 可能为 null（NPE 风险） |

**归约终点**：基本类型是对**数据局部性**的优化——连续内联存储可充分利用 CPU 缓存行预取（Cache Line Prefetch），避免缓存未命中导致的流水线停顿（Pipeline Stall）。

**CPU 缓存行**：现代 CPU 一次从主存加载 64B（缓存行）。访问 `int[]` 连续元素时，下一个元素很可能已在 L1 缓存中（**空间局部性**）。

### 方法参数传递：值传递的精确语义

Java 总是按值传递，语义精确描述：

- **基本类型参数**：传递值的副本（位复制），形参是独立的副本
- **引用类型参数**：传递引用的副本（地址的位复制），形参和实参指向同一对象

```java
void increment(int x) { x = x + 1; }  // 修改副本，不影响实参
void append(StringBuilder sb, String s) { sb.append(s); }  // 修改共享对象
void reassign(StringBuilder sb) { sb = new StringBuilder("new"); }  // 只修改副本
```

**违反约束的后果**：
- 对形参重新赋值（`sb = new ...`）不影响实参，因为只修改了副本
- 但通过形参修改对象状态（`sb.append()`）对所有引用可见，因为共享同一对象

**为什么 Java 选择值传递而非引用传递**：值传递保证了**参数的非可变性**（non-mutability）——函数无法修改调用者的变量。这使得程序更容易推理，因为函数调用没有副作用。

### 密封类与类型穷尽性（Java 17）

密封类强制子类的有限集合：

```java
sealed interface Shape permits Circle, Rectangle, Triangle {}
```

**数学约束**：sealed 接口的子类型集合 $U = \{ t \mid t \in \text{permits list} \}$ 。编译器验证所有子类型都被处理，否则编译错误。这将运行时 `MatchException` 提前到编译时。

**穷尽性检查的复杂度**：设 sealed 类型的子类型数为 $n$ ，穷尽性检查需要验证所有子类型都被处理。Java 使用**完备分配检测**（Complete Assignment Detection），在 $O(n)$ 时间内完成。

### record 类型与积类型（Java 16+）

record 是**透明数据载体**：

```java
record Point(int x, int y) {}
```

**数学本质**：record 是**积类型**（product type）。Point 的所有可能值构成 $\mathbb{Z} \times \mathbb{Z}$ 的笛卡尔积。编译器自动生成 equals/hashCode/toString 基于所有组件。

## 类型转换

### 隐式转换（加宽转换）

转换链保证**无损转换**：

```
byte → short → int → long → float → double
                     ↑
                   char
```

数学上，加宽转换满足单调性： $|x|_{new} \geq |x|_{old}$ ，不会丢失数值精度（浮点除外，因为浮点精度有限）。

**隐式转换的数学约束**：对于整数到整数的加宽，值域包含关系保证：

$\forall x \in \mathbb{Z}_{old}: \exists x' \in \mathbb{Z}_{new}: x' = x$

其中 $\mathbb{Z}_{old} = [-2^{n-1}, 2^{n-1}-1]$ 。

### 显式转换（窄化转换）

$x_{narrowed} = x_{original} \mod 2^n$

窄化转换是**有损转换**，可能丢失精度或改变符号。

**窄化的数学本质**：窄化转换是**强制投影**。设原始类型为 $\mathbb{Z}_{2^{n_{old}}$ ，目标类型为 $\mathbb{Z}_{2^{n_{new}}}$ ，其中 $n_{new} < n_{old}$ 。投影映射为：

$\pi: \mathbb{Z}_{2^{n_{old}}} \rightarrow \mathbb{Z}_{2^{n_{new}}}, \quad \pi(x) = x \bmod 2^{n_{new}}$

## 参考存根

```java
// 自动装箱的缓存行为
Integer a = 1000;
Integer b = 1000;
System.out.println(a == b);  // false，超出缓存范围

// 字符串驻留
String s1 = "hello";
String s2 = "hello";
String s3 = new String("hello");
System.out.println(s1 == s2);  // true，常量池共享
System.out.println(s1 == s3);  // false，new 每次新建
System.out.println(s1.equals(s3));  // true，内容相同

// record 类型（Java 16+）
record Range(int lo, int hi) {
    public Range {
        if (lo > hi) {
            throw new IllegalArgumentException("lo > hi");
        }
    }
}

// 溢出检测
public class SafeMath {
    public static int addExact(int a, int b) {
        int result = a + b;
        if ((a ^ b) < 0 && (a ^ result) < 0) {
            throw new ArithmeticException("integer overflow");
        }
        return result;
    }
}
```
