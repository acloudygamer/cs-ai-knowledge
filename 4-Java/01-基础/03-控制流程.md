# 控制流程

## 定义

Java 的控制流程语句（if/else、switch、for、while）本质上是**有穷状态自动机**（Finite State Machine, FSM）的语法结构化表示。编译器将控制流图（Control Flow Graph, CFG）转换为基本块，用于优化和异常处理。

switch 表达式可建模为 **完备检测有限状态自动机**：每个 case 对应一个状态，null 检查是初始转移，类型测试是条件转移。

## 数学模型

### switch 的 FSM 形式化

switch 表达式可建模为五元组：

$$M = (Q, \Sigma, \delta, q_0, F)$$

- $Q$：状态集（case 分支 + 接受状态）
- $\Sigma = T \cup \{\text{null}\}$：输入符号集（类型标签或 null）
- $\delta: Q \times \Sigma \rightarrow Q$：转移函数
- $q_0$：初始状态（null 检查）
- $F$：接受状态集（各 case 分支）

**完备性条件**：对于所有 $q \in Q$ 和 $\sigma \in \Sigma$，$\delta(q, \sigma)$ 均有定义。

### switch 模式匹配的穷尽性检查

穷尽性检查的本质是**集合覆盖**。对于 sealed 接口：

$$U = \{ t \mid t \in \text{permits list} \}$$

switch 表达式必须覆盖 $U$ 的所有元素。编译器将检查建模为：

$$\bigcup_{i} P_i = U$$

其中 $P_i$ 是每个 case 的类型模式覆盖集合。若覆盖不完整，编译错误。

### 穷尽性检查的复杂度

设 sealed 类型的子类型数为 $n$，穷尽性检查需要验证所有子类型都被处理。朴素算法 $O(2^n)$，但 Java 使用**完备分配检测**（complete assignment detection），在 $O(n)$ 时间内完成。

### null 的处理语义

在模式匹配中，null 是一个特殊的**底部类型**（bottom type），不属于任何类型层次。switch 中的 `case null` 必须放在类型 case 之前，因为 null 不是任何类型的实例。

## 数据流

### switch 模式匹配的求值流程

<pre>
switch (obj) {
    case null -> E1;
    case T1 v1 -> E2;
    case T2 v2 -> E3;
    default   -> E4;
}
         │
         ▼
┌─────────────────────┐
│ q0: obj == null ?   │──yes──→ E1（匹配 null）
└─────────────────────┘
         │ no
         ▼
┌─────────────────────┐
│ q1: instanceof T1 ? │──yes──→ E2（v1 绑定为 T1）
└─────────────────────┘
         │ no
         ▼
┌─────────────────────┐
│ q2: instanceof T2 ? │──yes──→ E3（v2 绑定为 T2）
└─────────────────────┘
         │ no
         ▼
┌─────────────────────┐
│ q3: default → E4   │  （兜底分支）
└─────────────────────┘
</pre>

**类型 narrowing**：当 `case T1 v1` 分支执行时，Java 的类型系统保证 obj 静态类型为 T1，这是**类型守卫**（type guard）的语言级支持。

</pre>

## 机制

### switch 模式匹配的设计动机

传统 switch 仅支持常量匹配（int、enum、String），无法处理多态场景。模式匹配将**类型检查和值绑定**统一：

```java
// 传统方式
if (obj instanceof String) {
    String s = (String) obj;
    // 使用 s
}

// 模式匹配方式
if (obj instanceof String s) {
    // s 自动绑定，作用域限于 this if 块
}
```

**约束**：模式变量（pattern variables）在 `instanceof` 为 true 时被**确认绑定**，在代码路径不确定时为**未绑定**。

### Guarded Patterns 的求值语义

```java
case Circle c when c.radius() > 0 -> "正圆，半径 " + c.radius();
```

`when` 子句引入**运行时条件**，编译器无法静态验证穷尽性。因此 guarded patterns 只能出现在穷尽性已有保证的分支内部。

**设计约束**：guarded patterns 本质上是**模式匹配 + 断言**的组合，失败时 fallthrough 到下一个分支（若无 default 且不穷尽）。

### Record 模式匹配与解构

Record 是 JDK 16+ 的**透明数据载体**，其组件自动生成 accessor 方法。Record 模式匹配允许：

```java
record Point(int x, int y) {}

// 匹配并解构
case Point(int x, int y) p -> x + y;
```

这在代数数据类型（ADT）建模中非常有用。数学上，Record 是**积类型**（product type），其模式匹配对应投影函数。

### 穷尽性检查的工程价值

| 场景 | 无穷尽检查 | 有穷尽检查 |
|------|-----------|-----------|
| 新增子类型 | 运行时 `MatchException` | 编译错误 |
| 代码重构 | 需人工检查所有 switch | 编译器强制验证 |
| 遗漏分支 | 静默执行 default 或 fallthrough | 编译失败 |

### 循环不变式与正确性证明

循环的正确性证明依赖于**循环不变式**（loop invariant）：在每次迭代开始前和结束后都为真的命题。

```java
// 查找数组中的元素
int i = 0;
while (i < n && !arr[i].equals(target)) {
    i++;
}
// 循环不变式：arr[0..i) 中不包含 target
// 循环终止：i == n 或 arr[i] == target
```

**不变式维护**：循环体的每次执行都必须维持不变式，否则循环结束后无法保证结果正确。

### 控制流图的 基本块结构

编译器将方法体划分为**基本块**（Basic Block）：
- 入口的第一个语句
- 跳转目标
- 跳转语句的下一条

基本块之间通过**控制流边**连接，形成有向图。优化和异常处理都基于这个图结构。

## 控制流原语

### break 和 continue

- `break`：退出最近的外层循环或 switch
- `continue`：跳过本次循环迭代，继续下一次

### labeled break/continue

带标签的 break/continue 可以跳出或继续外层嵌套循环：

```java
outer:
for (int i = 0; i < 10; i++) {
    for (int j = 0; j < 10; j++) {
        if (condition(i, j)) {
            break outer;  // 跳出外层循环
        }
    }
}
```

## 参考存根

```java
// Sealed 接口的穷尽性检查
sealed interface Shape permits Circle, Rectangle {}
record Circle(double radius) implements Shape {}
record Rectangle(double width, double height) implements Shape {}

double area(Shape s) {
    return switch (s) {
        case Circle c -> Math.PI * c.radius() * c.radius();
        case Rectangle r -> r.width() * r.height();
        // 编译器确保穷尽：无需 default
    };
}
```
