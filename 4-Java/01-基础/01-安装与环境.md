# 安装与环境

## 定义：JDK 的安装与版本选择本质上是运行时能力和维护成本的权衡

Java 开发环境配置涉及 JDK（Java Development Kit）的获取和环境变量的设置。JDK 是 Java 程序的**编译和运行环境集合**，包含 javac（编译器）、java（运行器）、JRE（运行时）等组件。

## 数学模型

### LTS 版本支持周期的代价函数

令 $T_{lts}$ 为 LTS 版本的支持周期（通常 8 年），$C_{upgrade}(n)$ 为升级 n 个小版本的成本，$C_{security}(t)$ 为运行非 LTS 版本在时间 $t$ 的安全风险成本。总成本：

$$C_{total}(t) = C_{upgrade}(n) + \int_0^t C_{security}(\tau) d\tau$$

企业选择 LTS 的原因：**离散积分近似为累加**，每 6 个月升级一次的风险累积成本远超 8 年一次 LTS 的迁移成本。

### JDK/JRE/JVM 的包含关系

```
JDK = javac + tools + JRE
JRE = libraries + JVM
JVM = 解释器 + JIT 编译器 + GC + 运行时组件
```

编译时需要 javac（不在 JRE 中），运行时只需 JRE。容器化部署通常使用 JRE 以减少镜像大小。

### Maven 依赖解析的 DAG 模型

依赖关系形成**有向无环图**（DAG）：$G = (V, E)$，其中 $V$ 是依赖节点，$E$ 是依赖边（$a \rightarrow b$ 表示 a 依赖 b）。

**拓扑排序**：依赖解析需要确定一个满足约束的顺序。设 $d(v)$ 为节点 $v$ 的出度（被依赖数），解析算法：

```
topological_sort(G):
    L = []  # 排序结果
    S = {v | d(v) = 0}  # 无被依赖的节点
    while S 非空:
        v = S.pop()
        L.append(v)
        for each u in incoming(v):  # 依赖 v 的节点
            d(u) -= 1
            if d(u) == 0: S.push(u)
    return L  # 若 L.size < |V|，则存在环
```

Maven 的"最近定义"原则是 DAG 上的**最短路径优先**：当同一 artifact 多个版本出现时，选择树深度最小的版本。

### Gradle 任务图的增量执行

Gradle 任务依赖形成 DAG：$T = (tasks, dependencies)$。增量执行判断：

$$R_{changed} = \{ t \in T \mid \text{input}(t) \text{ 相比上次执行已改变} \}$$
$$R_{affected} = \{ t \in T \mid \exists p \in R_{changed}: t \in \text{dependents}(p) \}$$

只有 $R_{affected}$ 中的任务需要重新执行。这将构建时间从 $O(|T|)$ 降为 $O(|R_{affected}|)$。

## 机制

### javac 编译器

将 Java 源代码编译为字节码（.class 文件）。输入是 .java 源文件，输出是包含栈式指令集的字节码。

**编译阶段**：
1. 词法分析（tokens）
2. 语法分析（AST）
3. 语义分析（类型检查、不变量验证）
4. 字节码生成

### java 运行器

启动 JVM，加载主类，执行字节码。负责类加载、字节码验证、JIT 编译启动。

### jarsigner

JAR 文件签名工具，用于代码签名和安全部署。

### 模块系统（JDK 9+）

Java 9 引入模块化系统（Jigsaw），通过 `module-info.java` 声明模块依赖：

```java
module com.example.myapp {
    requires com.example.lib;
    exports com.example.api;
}
```

**模块化的约束**：
- 未声明 `requires` 的模块不可访问
- 未声明 `exports` 的包不可访问
- `exports ... to ...` 可限定导出目标

## 版本选择策略

| 场景 | 推荐版本 | 原因 |
|------|----------|------|
| 新项目 | Java 21 或 25 | 最新特性，长期支持 |
| 企业维护 | Java 21 LTS | 虚拟线程，长期支持稳定版 |
| Android 开发 | Java 17 | Android Studio 最低要求 |
| 学习 | Java 17 或 21 | 包含现代特性 |

**版本约束**：
- Java 版本只能向前（不能降级运行）
- 字节码版本由 javac 决定，JVM 向下兼容（高版本 JVM 可运行低版本字节码）
- 使用新语言特性需要对应版本的 javac，但编译产物可在旧版 JVM 运行

### 虚拟线程与并发模型（Java 21 LTS）

虚拟线程（JEP 444）是 Java 21 LTS 引入的**用户态协程**：

- 虚拟线程是**轻量级线程**，由 JVM 调度，不绑定 OS 线程
- 多个虚拟线程共享一个 carrier thread
- 栈大小按需增长（分段栈机制），从 OS 线程的 1MB 降到 ~1KB 级别

数学约束：若要支持 $N$ 并发任务，传统线程模型需要 $N$ 个 OS 线程（内存 $O(N \cdot 1MB)$），虚拟线程只需 $M$ 个 OS 线程（$M \ll N$，内存 $O(N \cdot 1KB)$）。

## 构建工具

### Maven（约定优于配置）

Maven 的核心是**项目对象模型（POM）** 和**生命周期阶段**。

```
validate → compile → test → package → install → deploy
```

依赖解析本质上是图遍历（拓扑排序），解决版本冲突使用"最近定义"原则（nearest definition）。

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.10.0</version>
</dependency>
```

### Gradle（增量构建）

Gradle 使用**任务图**（task graph）描述构建流程，支持增量执行和缓存。

```
A → B → D
C → D
```

任务依赖形成 DAG，Gradle 只执行受输入变更影响的任务（增量构建）。与 Maven 的线性生命周期不同，Gradle 的任务执行是**拓扑排序**结果。

## 常见问题排查

### 路径优先级

`java` 命令查找顺序：
1. `$JAVA_HOME/bin`（显式设置优先）
2. `$PATH` 中找到的第一个 `java`

```bash
which java    # 定位实际使用的 java
java -version  # 确认版本
```

### 环境变量冲突

```bash
# Windows
echo %JAVA_HOME%
echo %PATH%

# Linux/macOS
echo $JAVA_HOME
echo $PATH
```

### 编译/运行版本不匹配

```bash
javac -source 17 -target 17 Main.java  # 指定源码和字节码版本
java -version                          # 运行时版本
```

## 参考存根

```java
// Java 17 密封类示例
public sealed interface Shape permits Circle, Rectangle, Triangle {
    double area();
}

record Circle(double radius) implements Shape {
    public double area() { return Math.PI * radius * radius; }
}

record Rectangle(double width, double height) implements Shape {
    public double area() { return width * height; }
}

record Triangle(double base, double height) implements Shape {
    public double area() { return base * height / 2; }
}
```
