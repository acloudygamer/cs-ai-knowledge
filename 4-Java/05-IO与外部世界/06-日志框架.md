# 日志框架

> 前置：[05-JDBC](./05-JDBC.md) · 后续：[01-Maven](../06-构建与工程/01-Maven.md)（日志依赖在构建文件里声明）

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。JUL 示例实测环境：Temurin JDK 25.0.4.1（Windows），`javac -encoding UTF-8 --release 21` 验证；SLF4J/Logback/Log4j2 为第三方依赖，相应示例为**骨架，未实测**。

日志是程序运行事件的记录管线：产生事件（级别 + 消息 + 上下文）→ 过滤 → 格式化 → 追加到目的地（控制台/文件/网络）。它的核心约束是**不能显著拖慢被记录的程序**——这条约束塑造了分层结构（门面/实现）与异步追加器这两个主机制。

## 本质

Java 日志的三层格局：

| 层 | 角色 | 成员 |
|---|---|---|
| 门面（API） | 只定义调用接口，不输出 | **SLF4J**（事实标准）、JCL（Apache Commons Logging，遗留） |
| 实现 | 过滤、格式化、落盘 | **Logback**（SLF4J 原生实现）、**Log4j2**（经适配器接 SLF4J） |
| 内置 | JDK 自带，零依赖 | **JUL**（`java.util.logging`） |

分层回应的约束：应用代码只依赖门面，切换实现不动业务代码；第三方库各自用不同门面时，由**桥接包**（`jcl-over-slf4j`、`jul-to-slf4j`、`log4j-to-slf4j`）把调用统一导流到同一个实现。纪律：类路径上**只放一个实现**，否则输出分裂或桥接成环。

## 机制

### JUL：零依赖的底线

JUL 无需任何依赖即可用，适合工具类小程序：

```java
Logger log = Logger.getLogger("demo");
log.info("业务里程碑");
```

实测（Temurin 25.0.4.1，logger 与 handler 均放开到 ALL）：

```text
9月 27, 2026 ... J1_Jul main
严重: ERROR 级：核心流程中断
警告: WARN 级：降级处理
信息: INFO 级：业务里程碑
详细: FINE 级：调试细节
非常详细: FINEST 级：循环内部状态
```

输出里藏着 JUL 的两个默认行为：**ConsoleHandler 默认只放行 INFO 以上**（FINE 能出来是因为示例同时下调了 handler 级别——logger 与 handler 是两道独立的闸）；默认格式带时间戳与调用点。配置能力弱、生态薄，所以服务端普遍走 SLF4J 系。

### 级别与延迟求值

级别语义（SLF4J 系，从低到高 TRACE/DEBUG/INFO/WARN/ERROR）：ERROR = 功能已损坏；WARN = 异常但有兜底；INFO = 业务里程碑；DEBUG/TRACE = 诊断细节。线上常态开 INFO，排查时临时下调。

性能关键在**占位符延迟求值**：

```java
log.debug("user={} order={}", user, order);   // debug 被过滤时，拼接与 toString 都不发生
log.debug("user=" + user + " order=" + order); // 拼接永远发生，过滤只省落盘
```

`{}` 占位符把"是否值得构造消息"的判断推迟到级别检查之后——这是门面 API 设计对核心约束的直接回应。

### 异步追加器：把 I/O 挪出业务线程

同步写入意味着业务线程等磁盘。异步 Appender 在事件与落盘之间插一座有界队列：业务线程入队即返回，后台线程批量写出。

- **Logback `AsyncAppender`**：`queueSize`（默认 256）满了之后，TRACE/DEBUG/INFO 可被丢弃（`discardingThreshold`，默认队列余量低于 20% 时开始丢），WARN/ERROR 永不丢——宁可慢不可丢的是错误。
- **Log4j2 异步**：基于 LMAX Disruptor（无锁环形缓冲），吞吐更高，是 Log4j2 相对 Logback 的主打差异。

骨架（Logback，未实测）：

```xml
<appender name="ASYNC" class="ch.qos.logback.classic.AsyncAppender">
    <queueSize>512</queueSize>
    <discardingThreshold>0</discardingThreshold>  <!-- 0 = 不主动丢低级别日志 -->
    <appender-ref ref="FILE"/>
</appender>
```

代价：进程崩溃时队列里未落盘的事件丢失——异步换吞吐，丢的是崩溃现场的最后几行，这是选型时要认的账。

### MDC：给日志挂上下文

MDC（Mapped Diagnostic Context）是绑定到当前线程的键值表，格式化时可引用——典型用法是每请求塞入 `traceId`，让一条请求的全部日志可被同一 id 捞出。它是 `ThreadLocal` 实现，虚拟线程场景同样面对副本开销问题，新一代方案见 Scoped Values（[05-虚拟线程与结构化并发](../04-并发编程/05-虚拟线程与结构化并发.md)）。

## 选型

收敛到一句话：应用代码写 **SLF4J API**，类路径放 **Logback**（默认）或 **Log4j2**（要高吞吐异步），用桥接包收编第三方库的 JCL/JUL 调用，JUL 只在零依赖小工具里直接用。
