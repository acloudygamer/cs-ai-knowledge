# 方法

> 前置：[03-控制流程](03-控制流程.md) · 后续：[05-面向对象](05-面向对象.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

## 本质

Java 没有游离的函数，只有**方法**（method）——必须挂在某个类或接口内部的命名代码块。方法由**签名**和**方法体**构成：签名 = 方法名 + 参数类型列表（编译器靠它区分同名方法），方法体是一组语句。调用方法的物理动作是**栈帧的压入与弹出**：每次调用，JVM 在当前线程的栈上压入一个新栈帧（装局部变量表和操作数栈，见 [01-Java全景](../00-概览/01-Java全景.md) 的栈式字节码），方法返回时弹出，控制回到调用点。

## 参数传递：只有值传递

Java 的参数传递**只有值传递**一种——槽里的内容复制一份给形参（[02-类型与变量](02-类型与变量.md) 的两类存储语义在此分叉）：

- 基本类型：复制值，形参是独立副本；
- 引用类型：复制引用，形参与实参指向**同一个堆对象**。

实测（`--release 21`）：

```java
static void increment(int x) { x = x + 1; }          // 改副本
static void append(StringBuilder sb) { sb.append("!"); }  // 改共享对象
static void reassign(StringBuilder sb) { sb = new StringBuilder("new"); }  // 改引用副本
```

```text
n=5                  // increment 没影响实参
after append: a!     // append 通过共享引用改了对象，调用方可见
after reassign: a!   // reassign 只改了引用副本，实参仍指旧对象
```

三行输出就是全部规则：方法改不动调用方的变量，但改得动共享对象的内容。"Java 对象是按引用传递"的说法是错的——引用本身是按值复制的。

## 重载：编译期四档匹配

**重载**（overload）：同类中方法名相同、参数列表不同。签名不含返回类型——只靠返回类型区分是编译错误，实测 `javac` 报 `method f(int) is already defined in class DupSig`。

调用哪个重载在**编译期**由静态类型决定（静态分派），匹配分四档，前面的档优先（JLS §15.12）：

1. 精确匹配；
2. 加宽转换（`byte → int → long`，见 [02-类型与变量](02-类型与变量.md)）；
3. 装箱/拆箱（`int ↔ Integer`）；
4. varargs（把剩余实参打包成数组）。

实测：

```text
show(5)                  // int（精确）
show(5L)                 // long（精确）
show(Integer.valueOf(5)) // Integer（精确）
show((byte) 1)           // int（加宽优先于装箱，show(Byte) 不存在是次因）
show(1, 2)               // int...（varargs 兜底）
```

与重载相对的是**重写**（override）：子类给父类同名同签名方法换个实现，调用哪个在**运行期**按对象的实际类型决定（动态分派）。两者常被混为一谈，区分点只有一个：重载看编译期类型，重写看运行期对象。重写的机制（虚方法表）在 [05-面向对象](05-面向对象.md) 展开。

## varargs 的真身

`void printAll(String... args)` 的形参在字节码里就是 `String[]`——varargs 是编译期语法糖，调用点 `printAll("a", "b")` 被编译为 `printAll(new String[]{"a", "b"})`。推论：varargs 形参在方法体内按数组用；它必须位于参数列表末尾（只有一个"剩余打包"的位置）；每次调用隐式分配一个数组，热路径上在意这点开销就传数组复用。

## 栈帧账与递归深度

每次调用压一个栈帧，帧大小编译期确定（局部变量槽数 + 操作数栈最大深度）。线程栈总容量固定（HotSpot 默认约 512KB~1MB，可用 `-Xss` 调），深度递归把栈帧一路压上去，耗尽即 `StackOverflowError`——实测一个无终止自递归方法在默认栈下抛出该错误并被 `catch` 捕获。

Java **不做尾调用优化**（TCO）：即使递归调用是方法的最后一个动作，栈帧照样压。所以深度递归在 Java 里的标准解法不是尾递归写法，而是改迭代或显式栈。这是 JVM 的刻意留白——栈帧要服务异常栈轨迹，历史上还要服务安全管理器的栈检查（Security Manager 自 JDK 24 起已永久禁用，JEP 486），复用栈帧会破坏这套设施。

## static 方法与实例方法的分界

实例方法隐式持有 `this`（当前对象引用），能读写实例字段；`static` 方法没有 `this`，只能碰静态成员。静态成员属于类而不是对象——全类一份，随类加载创建（类加载机制见 [01-字节码与类加载](../03-JVM与运行时/01-字节码与类加载.md)）。`main` 之所以是 `static`：JVM 启动时还没有任何对象，入口必须不依赖实例。

`final` 用在方法上表示禁止重写；用在参数和局部变量上表示禁止再赋值。三者同为编译期约束，字节码待遇却不同：方法上留下 `ACC_FINAL` 标志，参数仅记入可选的 `MethodParameters` 属性，局部变量则完全无痕。
