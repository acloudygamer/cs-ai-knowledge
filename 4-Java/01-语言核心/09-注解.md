# 注解

> 前置：[08-Lambda与函数式接口](08-Lambda与函数式接口.md) · 后续：[10-现代语言特性](10-现代语言特性.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

## 本质

注解（annotation，Java 5 引入）是**贴在程序元素上的结构化元数据**：类、方法、字段、参数上挂的 `@Xxx(...)`。注解自身没有任何行为——它既不改变所贴代码的编译产物，也不在运行时自动执行；它是一份**留给消费者的标记**，由编译器、注解处理器或运行时反射读取并行动。理解注解就是理解这个三方结构：定义者声明形状，使用者打标记，消费者读取并反应。

## 定义：元注解规定形状

注解类型用 `@interface` 声明，它自己的注解（**元注解**）规定这份元数据的形状：

```java
@Retention(RetentionPolicy.RUNTIME)   // 活到什么时候
@Target(ElementType.METHOD)           // 能贴在什么元素上
@interface Tag { String value(); }    // 成员：无参方法形态，可用 default 给默认值
```

- `@Target`：限定可贴位置（`TYPE`、`METHOD`、`FIELD`、`PARAMETER`……），贴错位置是编译错误。
- `@Retention`：元数据活到哪一站——这是注解最重要的属性，单独成节（见下）。
- 成员类型受限：只能是基本类型、`String`、`Class`、枚举、注解及以上的一维数组——注解要能被常量池序列化，任意对象放不进去。

## 保留策略：谁消费决定活到哪站

`@Retention` 三档对应三类消费者，选错档的典型事故是"编译期正常、运行时拿到 null"：

| 级别 | 元数据生命周期 | 消费者 | 典型代表 |
|---|---|---|---|
| `SOURCE` | 编译后丢弃，不进 `.class` | javac、IDE | `@Override`、`@SuppressWarnings` |
| `CLASS` | 进 `.class`，但 JVM 加载后不可反射读取 | 字节码工具（ASM、Mockito 的插桩层） | 插桩标记 |
| `RUNTIME` | 随 Class 对象存活，反射可读 | 框架（Spring、JPA） | `@Autowired`、`@Entity` |

实测（`--release 21`）：同一方法上各贴一个 `RUNTIME` 级和 `SOURCE` 级注解，反射读取结果：

```text
RUNTIME 注解读取: runtime-visible
SOURCE 注解读取: null
```

SOURCE 级注解在编译后已从字节码中消失——反射拿到的是 `null` 而非异常，这个静默失败正是级别选错难以排查的原因。

## 内置注解：编译器作为消费者

JDK 自带注解展示了"编译器是消费者"这一最朴素的形态：

- `@Override`：让 javac 核验"此方法确实重写了父类/接口方法"（[05-面向对象](05-面向对象.md) 已用它防签名笔误）——纯编译期校验，`SOURCE` 级。
- `@Deprecated`：标记弃用 API，javac 对调用方给出警告；Java 9 起带 `since`/`forRemoval` 成员说明弃用时间与是否将删除。
- `@SuppressWarnings("unchecked")`：关闭指定类别的编译警告，作用于所贴元素的整个子树。
- `@FunctionalInterface`：核验接口只有一个抽象方法（[08-Lambda与函数式接口](08-Lambda与函数式接口.md)）。

## 消费方式两站

**编译期**：注解处理器（Annotation Processor，APT）挂在 javac 的语义分析阶段，读注解、生成新源文件（Lombok、MapStruct 的路数）。**运行时**：反射 API `getAnnotation()` 读 RUNTIME 级注解并据此决策——动态代理常与之配合织入行为（反射与代理机制见 [05-反射与动态代理](../03-JVM与运行时/05-反射与动态代理.md)）。两站之间，`CLASS` 级服务于不改源码、只改字节码的插桩工具。
