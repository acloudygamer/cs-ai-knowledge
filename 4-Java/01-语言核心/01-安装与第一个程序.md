# 安装与第一个程序

> 前置：[01-Java全景](../00-概览/01-Java全景.md) · 后续：[02-类型与变量](02-类型与变量.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

本篇把 [01-Java全景](../00-概览/01-Java全景.md) 的执行链在你机器上跑一遍：装 JDK、编译、运行，并用编译产物反推两个工具各自管什么。

## 本质

JDK（Java Development Kit）是编译器、类库与虚拟机三件东西的合包：`javac` 负责 `.java` → `.class`，类库提供 `java.*` API，JVM（默认 HotSpot）负责 `.class` → 进程。三者之间只隔一个 `.class` 文件格式——所以工具链的学习路径就是沿这条链走：先让 `javac` 吃下源码，再让 `java` 吐出进程。

日常说的"装 Java"就是装 JDK。JRE（Java Runtime Environment，只有 JVM 和类库、没有编译器）自 Java 11 起不再单独发布，因为模块化（Java 9 起）让 `jlink` 可以按需裁剪运行时，独立 JRE 失去了存在理由。

## 安装（Windows，实测）

winget 是 Windows 自带的包管理器，一条命令安装 Temurin（Eclipse 基金会的 OpenJDK 发行版，免费商用）：

```powershell
winget install EclipseAdoptium.Temurin.25.JDK
```

实测落盘到 `C:\Program Files\Eclipse Adoptium\jdk-25.0.4.101-hotspot\`，安装器自动把 `bin\` 加入 PATH。验证（本文全部实测均以此为准）：

```text
$ java -version
openjdk version "25.0.4.1" 2026-08-18 LTS
OpenJDK Runtime Environment Temurin-25.0.4.1+1 (build 25.0.4.1+1-LTS)
OpenJDK 64-Bit Server VM Temurin-25.0.4.1+1 (build 25.0.4.1+1-LTS, mixed mode, sharing)

$ javac -version
javac 25.0.4.1
```

`java` 与 `javac` 必须同版本且都找得到——前者是运行时，后者是编译器，两者各报各的版本，任何一个 not found 都是 PATH 没配好。JDK 根目录下的 `release` 文件记录了版本元数据（`JAVA_VERSION="25.0.4.1"`、`IMPLEMENTOR="Eclipse Adoptium"`），排查"我到底装了哪个 JDK"时看它最准。

## 第一个程序

Java 25 起，第一个程序只需要两行：

```java
void main() {
    System.out.println("hello, jvm");
}
```

存为 `Hello.java`，编译运行（实测）：

```text
$ javac -encoding UTF-8 Hello.java
$ java Hello
hello, jvm
```

产物是 389 字节的 `Hello.class`。也可以跳过编译一步直跑源码——`java Hello.java`（Java 11 起的源码文件启动模式，JVM 在内存中编译，不落盘 `.class`），输出相同。

这背后是两个 Java 25 新特性：**简化 main**（`void main()` 实例方法即可作入口，免去 `public static` 与 `String[] args`）与**隐式声明类**（不写 `class` 外壳，编译器按文件名包一层）。`javap -p Hello.class` 实测可见编译器合成的形状：

```text
final class Hello {
  Hello();
  void main();
}
```

### stable 口径（Java 21）

Java 21 不认识这两个特性。实测 `javac --release 21 Hello.java` 直接拒绝：

```text
Hello.java:1: error: implicitly declared classes are not supported in -source 21
```

stable 口径下入口必须写全传统形式：

```java
public class Hello21 {
    public static void main(String[] args) {
        System.out.println("hello, jvm");
    }
}
```

```text
$ javac -encoding UTF-8 --release 21 Hello21.java
$ java Hello21
hello, jvm
```

`--release 21` 让 JDK 25 的 javac 同时按 Java 21 的**语法**和**类库 API** 检查并生成 Java 21 字节码——它比 `-source`/`-target` 多管一件事：`-source 21` 只拦语法，`--release 21` 连"调用了 21 还不存在的 API"也拦，因为后者才是真正的兼容性炸弹。

**为什么留着两种写法**：简化 main 砍掉的三样东西——`public static`、`String[] args`、类外壳——每一项都是初学时要先囫囵吞下的概念（静态、数组、类）。Java 25 把它们推迟到需要时再学；而传统形式仍是所有正式项目的入口形态，因为它表达的是 JVM 的真实启动契约（静态方法、命令行参数），简化写法只是编译器代写这层壳。

## 两个工具各自管什么

第一个程序走完，工具链的分工可以反推出来：

- **javac**：`.java` → `.class`。词法分析（字符流 → token）→ 语法分析（token → 语法树）→ 语义分析（类型检查、注解处理）→ 字节码生成。javac 不做性能优化——优化依赖运行时画像（哪段代码热），编译期拿不到，这是 JIT 的活（见 [01-Java全景](../00-概览/01-Java全景.md) 的分层编译）。
- **java**：`.class` → 进程。启动 JVM → 类加载器找到主类字节码 → 字节码验证 → 定位 `main` 并执行。`java Hello` 的参数是**类名**而不是文件名，类从类路径（classpath，默认当前目录）里找。

链条上的其余工具各管一段：`javap` 反汇编 `.class`（本文已用）；`jar` 把多个 `.class` 打包成一个归档；`jlink` 从 JDK 模块中裁出自定义运行时镜像（交付不含完整 JDK 的产物时用）；`jpackage` 再进一步打成平台原生安装包。

## 常见故障

- **`java` 或 `javac` not found**：PATH 里没有 JDK 的 `bin\`。winget 安装后需新开终端才会刷新 PATH。
- **`UnsupportedClassVersionError`**：编译用的 javac 比运行用的 java 新。字节码只能向下兼容——高版本 JVM 能跑低版本字节码，反之不行。用 `java -version` 和 `javac -version` 对一遍。
- **中文乱码 / 编译报编码错**：javac 默认按平台编码（Windows 简体中文版是 GBK）读源码。源码文件是 UTF-8 时显式加 `-encoding UTF-8`，本文所有命令均带此参数。
