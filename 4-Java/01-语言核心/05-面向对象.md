# 面向对象

> 前置：[04-方法](04-方法.md) · 后续：[06-泛型](06-泛型.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

## 本质

类（class）是把**状态**（字段）和**行为**（方法）捆成一个抽象数据类型的声明；`new` 按这份声明在堆上造出**对象**，变量拿到的只是引用（[02-类型与变量](02-类型与变量.md)）。面向对象的三个机制各自回答一个问题：封装回答"状态谁来管"，继承回答"类型之间怎么复用"，多态回答"调用哪个实现在什么时候定"。

## 封装：不变量的守门人

字段私有化、通过方法暴露受控操作，目的是让类有能力**维护自己的不变量**：

```java
public class Counter {
    private int count;              // 不变量：count >= 0
    public void increment() { count++; }
    public int getCount() { return count; }
}
```

`count` 若为 `public`，任何代码都能写入负数，不变量守不住。访问修饰符决定"谁能在源码里指名访问这个成员"：

| 修饰符 | 同类 | 同包 | 子类（异包） | 任意 |
|---|---|---|---|---|
| `private` | ✓ | ✗ | ✗ | ✗ |
| （不写，包私有） | ✓ | ✓ | ✗ | ✗ |
| `protected` | ✓ | ✓ | ✓ | ✗ |
| `public` | ✓ | ✓ | ✓ | ✓ |

修饰符只约束源码访问；运行时另有模块系统的导出控制（Java 9 起，见 [01-安装与第一个程序](01-安装与第一个程序.md) 提到的模块化裁剪）。

## 继承：单链向上

`class Child extends Parent` 建立 **is-a** 关系：Child 的实例同时拥有 Parent 的字段和方法，凡期待 Parent 的位置都可放入 Child。Java 的类**只能单继承**——多继承的菱形冲突（两个父类同名实现选谁）被整体切除，接口的多重实现另走一套规则（见下）。

所有类的继承链终点是 `java.lang.Object`，`toString`/`equals`/`hashCode` 由此全员持有。

### 构造器链：自顶向下

`new Child()` 的初始化顺序是钉死的：先父后子，父内部先字段初始化再构造器体。实测（`--release 21`）输出顺序：

```text
Parent 字段初始化
Parent 构造器体
Child 字段初始化
Child 构造器体
```

机制：每个构造器的第一行若不是 `this(...)`（委托本类另一构造器），编译器就隐式插入 `super(...)`——所以构造器调用一路递归到 `Object` 再逐层返回执行各自的方法体。推论：构造器里调用可重写方法是危险的——此时子类字段还没初始化，重写方法读到的是默认值。

## 多态：运行期按实际类型分派

**重写**（override）：子类给继承来的方法换实现（签名相同，见 [04-方法](04-方法.md) 与重载的对照）。通过父类型引用调用被重写的方法时，JVM 按**对象的实际类型**选实现，而不是按引用的编译期类型——这就是动态分派。实测：

```java
Shape s = new Circle(1.0);     // 编译期类型 Shape
s.describe();                  // 输出 Circle, area=3.141592653589793
```

字节码层的落点就是 [01-Java全景](../00-概览/01-Java全景.md) 提到的 `invokevirtual`：调用指令只带方法符号引用，目标实现由运行时的虚方法表（vtable：每个类一张"方法 → 实现"的表，子类重写的槽位被子类实现覆盖）按实际类型查出。`@Override` 注解（见 [09-注解](09-注解.md)）让编译器帮忙核对"我确实在重写"，签名写错时当场报错而不是静默变成重载。

`instanceof` 是这条链的逆查询——问引用背后的对象实际是什么类型；Java 16 起它可以直接绑定模式变量（`if (s instanceof Circle c)`），归 [10-现代语言特性](10-现代语言特性.md)。

### LSP：继承的行为约束

**Liskov 替换原则**（LSP）：子类必须能无损顶替父类出现在任何位置。结构上的 is-a 不等于行为上的 is-a——经典反例是正方形继承矩形：调用方按"矩形"的预期分别设宽高，正方形却让两边联动，静默破坏调用方假设。违反 LSP 的继承能编译通过（编译器只查结构），后果由运行时承担，所以"能不能 extends"要问行为兼容，不是问概念上像不像。

### 组合优先于继承

继承把子类焊死在父类的实现上：父类改实现细节，子类可能无声损坏（脆弱基类问题）。**组合**（has-a：把功能对象存为字段、通过接口交互）保持低耦合、运行时可替换。经验规则：复用代码优先考虑组合，只有确实存在稳定的 is-a 且需要多态时才继承。

## 抽象类与接口

**抽象类**（`abstract class`）：可以有字段、有实现、有构造器，但含抽象方法即不能实例化——"未完工的类"，留给子类补完。**接口**（`interface`）：纯契约，方法默认 `public abstract`，字段隐式 `public static final`；一个类可实现任意多个接口。Java 8 起接口可带**默认方法**（`default` 修饰，提供实现），动机是接口演化——给老接口加方法而不砸掉所有现存实现。

多重实现带来冲突：两个接口给出同名默认方法时，实现类**必须**重写消歧，编译器不替你做选择。实测：

```java
interface A { default String who() { return "A"; } }
interface B { default String who() { return "B"; } }
class C implements A, B {
    @Override public String who() { return A.super.who() + "+" + B.super.who(); }
}
// new C().who() → "A+B"；若不重写 who()，编译错误
```

选择上的分工：要携带状态、要构造器、要非 public 成员——抽象类；纯能力声明、需要多重挂载——接口。

## 内部类一句话

类可以嵌在类里。**非静态内部类**隐式持有外部类实例引用（`Outer.this`），能碰外部类的私有成员，代价是外部实例会随内部类实例一起被拽住不放；**静态内部类**（`static class`）无此引用，行为与普通顶层类无异，只是名字空间收进外部类。匿名内部类是"当场写实现"的简写，Java 8 后单方法接口的场景大多被 Lambda 取代（见 [08-Lambda与函数式接口](08-Lambda与函数式接口.md)）。
