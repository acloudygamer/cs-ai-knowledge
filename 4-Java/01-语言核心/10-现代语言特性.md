# 现代语言特性

> 前置：[09-注解](09-注解.md) · 后续：[01-演进脉络与LTS节奏](../10-版本演进/01-演进脉络与LTS节奏.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），本篇特性均为 stable 口径（Java 21 及以前转正），以 `javac -encoding UTF-8 --release 21` 验证。Java 22–25 的新语法见 [03-Java22至25](../10-版本演进/03-Java22至25.md)。

## 本质

本篇收拢 Java 8 之后、Java 21 为止转正的语法层特性。它们的共同方向：**把样板代码交给编译器生成，把一致性检查从运行期提到编译期**。record 消灭数据载体的样板，模式匹配消灭"判断类型→强转→声明变量"的三步样板，sealed 让编译器证明分支穷尽——程序员写得更少，编译器知道得更多。

## record：透明数据载体（Java 16 转正）

`record Point(int x, int y) {}` 一行声明一个**以数据为全部语义**的类：编译器自动生成私有 final 字段、全参构造器、访问器（`x()` 而非 `getX()`）、以及基于全部组件的 `equals`/`hashCode`/`toString`。实测：

```text
Point[x=3, y=4], equals: true, x=3
```

记录的两条硬约束：record 隐式 `final`（不可继承），组件即全部状态（不能另加实例字段）——数据载体要的就是"值是什么就是什么"，继承和隐藏状态都会破坏 `equals` 的透明性。构造器入口要校验参数时用**紧凑构造器**（`Point { if (x < 0) throw ...; }`，不显式写字段赋值，编译器在校验后自动完成）。

## sealed：封闭类型族（Java 17 转正）

`sealed interface Shape permits Circle, Rect` 声明一个**封闭类型族**：允许哪些子类型，白纸黑字写在声明里。被许可的子类必须三选一封口：`final`（到此为止）、`sealed`（继续封闭下去）、`non-sealed`（重新开放）。

sealed 单独看只是访问控制，它的价值在与 switch 的联动（见下）：类型族封闭，编译器才能证明分支穷尽。

## switch 表达式与模式匹配（Java 14 / 21）

Java 14 起 switch 有了**表达式**形态：箭头分支不贯穿（对照 [03-控制流程](03-控制流程.md) 的经典 switch 贯穿语义）、多标签合一（`case 1, 2`）、语句块用 `yield` 返回值。作为表达式必须**穷尽**所有可能——对 sealed 类型族，穷尽可能性由编译器证明，不需要 `default`。实测：

```java
static double area(Shape s) {        // Shape 是 sealed，permits Circle, Rect
    return switch (s) {
        case Circle c -> Math.PI * c.r() * c.r();
        case Rect r -> r.w() * r.h();    // 无 default，编译通过
    };
}
// area(new Circle(1.0)) → 3.141592653589793
```

漏掉一个分支时编译器当场拒绝——实测报错 `the switch expression does not cover all possible input values`。这就是 sealed 的兑现：给类型族加新子类时，所有覆盖它的 switch 表达式集体编译失败，重构从"运行期祈祷"变成"编译器带你逐个修"。

Java 21 起 switch 支持**模式匹配**：case 可以带类型模式、`null` 分支、以及 record 的**解构模式**——组件在匹配处直接拆出来绑定：

```java
return switch (o) {
    case null -> "null";
    case Point(int x, int y) -> "Point(" + x + "," + y + ")";  // 解构，x/y 直接可用
    case int[] a -> "int[" + a.length + "]";
    default -> "other";
};
// describe(new Point(1,2)) → "Point(1,2)"；describe(null) → "null"
```

## instanceof 模式匹配（Java 16 转正）

老三步——判断、强转、声明——合成一步：

```java
if (obj instanceof String s) {       // 匹配则绑定 s，作用域由编译器按流分析收窄
    System.out.println(s.length());  // 实测输出 5
}
```

绑定变量 `s` 只在"确定匹配"的路径上可见，编译器做流分析保证不会用到未绑定的变量。这是 switch 模式匹配的同族能力：类型测试与绑定合并，强转从语言里消失。

## var：局部变量类型推断（Java 10 起）

`var names = List.of("a", "bb")` 让编译器从初始化表达式推断类型——**只是省写，不是动态类型**：推断结果仍是静态类型，编译后字节码与显式写法无异。边界由此而定：只用于局部变量（字段、参数、返回类型是 API 契约，必须显式）；必须有初始化表达式（没有就无从推断）；`var x = null` 不合法（null 没有类型）。适合构造器调用等类型名在右侧已经出现的场合，省的是重复，不是思考。

## 文本块（Java 15 转正）

`"""` 包裹的多行字符串：换行照字面保留、双引号免转义、结尾定界符的缩进决定公共前导空白剥多少。JSON、SQL、HTML 片段不再是一行行的 `"..." +` 拼接。实测输出保留换行与缩进结构，配合 `formatted()` 做占位插值。
