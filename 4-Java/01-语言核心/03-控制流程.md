# 控制流程

> 前置：[02-类型与变量](02-类型与变量.md) · 后续：[04-方法](04-方法.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

## 本质

控制流程语句决定**语句的执行顺序**。默认顺序是自上而下逐条执行；`if`/`switch` 按条件分叉，`for`/`while` 让一段代码反复执行，`break`/`continue`/`return` 打破当前顺序跳转。编译器把方法体切成**基本块**（basic block：内部只能顺序执行、只在入口进入、只在末尾跳出的一段指令），块之间以跳转边连接成控制流图——后面的字节码优化（[06-性能调优](../03-JVM与运行时/06-性能调优.md)）和异常分发（[07-异常处理](07-异常处理.md)）都建立在这张图上。

## 分支

### if/else

条件表达式必须是 `boolean`——Java 不像 C 那样把非零整数当 true，`if (x)`（`x` 是 `int`）是编译错误。这个收窄是故意的：C 里 `if (x = 0)` 把赋值笔误当条件的事故，在 Java 里只有 `boolean` 变量才能踩中。

### switch 语句：贯穿是默认行为

经典 `switch` 是语句：从命中的 `case` 开始执行，**一路贯穿到 `break` 或 switch 末尾**。实测（`--release 21`）：

```java
static int fallthrough(int x) {
    int r = 0;
    switch (x) {
        case 1: r += 1;
        case 2: r += 2;
        default: r += 4;
    }
    return r;
}
```

```text
fallthrough(1)   // 7：1+2+4，三个分支全部执行
fallthrough(2)   // 6：2+4
```

贯穿是 C 的遗产，偶尔有用（多个 case 共享收尾代码），但更多时候是漏写 `break` 的事故现场。Java 14 起有箭头形式的 switch（`case 1 -> ...`，不贯穿、可返回值），它连同模式匹配一起归 [10-现代语言特性](10-现代语言特性.md)；本篇只讲语句形态。

`case` 的判别值类型受限：整数类型、`char` 及它们的包装类、`String`（Java 7 起，编译为对哈希值的分支加 `equals` 复核）、枚举，以及现代的模式匹配（[10-现代语言特性](10-现代语言特性.md)）。不支持 `long` 和浮点——浮点相等判断本身就是坏的（见 [02-类型与变量](02-类型与变量.md) 的精度账）。

### 字节码层：两种 switch 指令

javac 按 case 值的分布选择指令，实测 `javap -c`：

- 值密集（1, 2, 3, 4）→ **`tableswitch`**：一张按值索引的跳转表， $O(1)$ 直达。
- 值稀疏（1, 100, 10000）→ **`lookupswitch`**：键值对按序排列，二分查找， $O(\log n)$。

跨度大时跳转表里全是空洞，体积换时间的账不划算，编译器自动改二分——跳转表的 $O(1)$ 红利因此只在密集整数场景成立；稀疏场景的 $O(\log n)$ 二分仍优于长 if-else 链的逐条比较。

## 循环

三种循环等价可互换，差别在结构与约定：

```java
for (int i = 0; i < n; i++) { ... }   // 初始化、条件、更新聚在头部；i 的作用域限于循环内
while (cond) { ... }                   // 先判后做，条件由循环体推进
do { ... } while (cond);               // 先做后判，至少执行一次
```

`for` 相对 `while` 的实质增益是**作用域收紧**：循环变量不外泄，下一个循环可以重用名字。遍历数组和集合有专用的**增强 for**：

```java
int[][] matrix = {{1, 2}, {3, 4}};
for (int[] row : matrix) { ... }       // 数组：按下标隐式迭代
for (String s : list) { ... }          // 集合：编译为 Iterator 遍历
```

增强 for 遍历集合时编译为迭代器（Iterator）调用，因此循环体内删元素会触发 `ConcurrentModificationException`——迭代器检测到结构被绕过它修改。要边遍历边删，显式用 `Iterator` 的 `remove()`。

## 跳转

`break` 退出最近一层循环或 switch；`continue` 跳过本次迭代剩余部分进入下一轮；`return` 退出整个方法（见 [04-方法](04-方法.md)）。嵌套循环中 `break` 只退一层，要退外层用**标签**（label，打在循环前的标识符），实测：

```java
outer:
for (int i = 0; i < matrix.length; i++) {
    for (int j = 0; j < matrix[i].length; j++) {
        if (matrix[i][j] == 4) {
            break outer;    // 直接退出外层循环
        }
    }
}
// 输出：found 4 at [1][1] 之后内外循环都结束
```

标签是 Java 里 goto 的唯一残留——只能标在循环上、只能配合 `break`/`continue` 使用，跳转目标被约束在"循环的出口或起点"，没有自由 goto 的任意跳转能力。

## 编译期防线：不可达语句

javac 对控制流图做静态分析，**不可达语句直接是编译错误**（`unreachable statement`）——`return` 后面的代码、恒假 `while (false)` 循环体都过不去。这逼着死代码在编译期被清理，而不是留在字节码里误导后来人。唯一例外是 `if (false)`：故意留着当条件编译开关用（历史设计决策，为了替代 C 的 `#ifdef`）。
