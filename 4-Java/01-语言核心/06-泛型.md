# 泛型

## 定义

泛型（Generics）是 Java 5 引入的**参数化多态**机制：在编译时进行类型安全检查，避免强制类型转换，同时实现代码复用。

从类型论视角，泛型提供了**参数化类型**（Parameterized Types）： $List<T>$ 、  $Map<K, V>$。类型参数 $T, K, V$ 在运行时被**擦除**（Erasure），替换为上界（默认为 `Object`）。 、  $Map<K, V>$ 。类型参数 $T, K, V$ 在运行时被**擦除**（Erasure），替换为上界（默认为 `Object`）。。类型参数 $T, K, V$ 在运行时被**擦除**（Erasure），替换为上界（默认为 `Object`）。 在运行时被**擦除**（Erasure），替换为上界（默认为 `Object`）。

Java 的泛型实现是**类型擦除**（Type Erasure），而非**具体化**（Reification）。这意味着类型参数在运行时不可知。

## 数学模型

### 类型擦除的数学描述

类型擦除是将参数化类型映射到原始类型（Raw Type）的函数：

 $E: \text{ParameterizedType} \rightarrow \text{RawType}$ 

 $E(\text{List<String>}) = \text{List}, \quad E(\text{Box<T extends Number>}) = \text{Number}$ 

擦除规则：
- 无上界： $T \rightarrow \text{Object}$ 
- 有上界： $T \rightarrow \text{UpperBound}$ 
- 数组类型： $T[] \rightarrow \text{Object}[]$ （注意：不能创建泛型数组） （注意：不能创建泛型数组）

**擦除的逆函数不存在**：给定原始类型 `List`，无法恢复 `List<String>` 和 `List<Integer>` 的区别。这是类型擦除的根本限制。

**为什么 Java 选择类型擦除**：类型擦除使得 Java 5 之前的代码可以与泛型代码互操作（向后兼容）。若选择具体化（reification），泛型类型需要在运行时存在，这需要大幅修改 JVM 和字节码格式。

### 通配子的集合论语义

| 通配符 | 集合含义 |
|--------|----------|
| `<?>` | $\bigcup_{T} List<T>$ ，所有 List 的超类型 | ，所有 List 的超类型 |
| `<? extends Number>` | $\{ List<T> \mid T \subseteq Number \}$ ，Number 的子类型列表的集合 | ，Number 的子类型列表的集合 |
| `<? super Integer>` | $\{ List<T> \mid Integer \subseteq T \}$ ，Integer 的超类型列表的集合 | ，Integer 的超类型列表的集合 |

**PECS 原则（Producer Extends, Consumer Super）**：

设 $P$ 为生产者接口（提供 T）， $C$ 为消费者接口（消费 T）： 为生产者接口（提供 T）， $C$ 为消费者接口（消费 T）： 为消费者接口（消费 T）：

 $\text{Producer-Extends}: \forall T \subseteq U: \text{Producer}(T) \rightarrow \text{Producer}(U)$ 

 $\text{Consumer-Super}: \forall T \supseteq U: \text{Consumer}(T) \rightarrow \text{Consumer}(U)$ 

- `List<? extends Number>` 是**生产者**（produces T），只能读取（你从列表中取出 T，但不能放入）
- `List<? super Number>` 是**消费者**（consumes T），只能写入（你可以放入 Number，但不能取出具体类型）

**为什么 extends 不能写入**：若允许向 `List<? extends Number>` 写入，可能导致类型污染：

```java
List<? extends Number> nums = new ArrayList<Integer>();
nums.add(3.14);  // 若允许，则 Integer 列表中混入了 Double
```

### 协变与逆变的类型兼容性

| 类型关系 | 协变 | 逆变 | 不变 |
|----------|------|------|------|
| `Number ↔ Integer` | ✓ | ✓ | ✓ |
| `List<Number> ↔ List<Integer>` | ✗ | ✗ | ✓ |
| `List<? extends Number> ↔ List<Integer>` | ✓ | ✗ | ✗ |
| `List<? super Number> ↔ List<Integer>` | ✗ | ✓ | ✗ |

**数学定义**：
- **协变**（Covariant）：若 $T \subseteq U$ ，则 $F(T) \subseteq F(U)$ ，则 $F(T) \subseteq F(U)$ 
- **逆变**（Contravariant）：若 $T \subseteq U$ ，则 $F(U) \subseteq F(T)$ ，则 $F(U) \subseteq F(T)$ 
- **不变**（Invariant）：无论 $T, U$ 关系如何， $F(T)$ 与 $F(U)$ 无继承关系 关系如何， $F(T)$ 与 $F(U)$ 无继承关系 与 $F(U)$ 无继承关系 无继承关系

**为什么数组是协变的而泛型是不变的**：

数组是协变的：`Integer[]` 是 `Number[]` 的子类型。但这导致安全问题：

```java
Integer[] arr = new Integer[1];
Number[] nums = arr;  // 协变赋值
nums[0] = 3.14;      // ArrayStoreException
```

泛型选择不变来避免这个问题。若 `List<Integer>` 是 `List<Number>` 的子类型，则可以向 `List<Number>` 中添加 `Double`，导致类型污染。

### 泛型约束的形式化

泛型类型参数必须满足的约束：

1. **不可实例化**：`new T()` 编译错误，因为 $T$ 在运行时是 `Object`，无法调用特定构造函数 在运行时是 `Object`，无法调用特定构造函数
2. **不可创建泛型数组**：`new T[n]` 编译错误，因为数组协变导致类型不安全
3. **静态上下文禁用**：`static T value` 编译错误，因为类型参数属于实例，不属于类
4. **异常捕获禁用**：`catch (T e)` 编译错误，因为 $T$ 运行时不可知 运行时不可知

**约束的数学解释**：
- `new T()` 的问题：构造函数是类型参数的成员，但类型擦除后 $T$ 变成 `Object`，而 `Object` 的构造函数签名是 `Object()`，与具体的 $T$ 构造函数无关 变成 `Object`，而 `Object` 的构造函数签名是 `Object()`，与具体的 $T$ 构造函数无关 构造函数无关
- `new T[n]` 的问题：数组协变 `Object[] ⊇ String[]` 使得 `new Object[n]` 可以赋值给 `new T[n]`，导致类型不安全

## 数据流

<pre>
源代码                        编译器                      字节码
+------------------+          +------------------+          +------------------+
| Box<T>           |  ───>   | 类型检查          |  ───>   | Box (raw type)   |
| T get()          |  擦除    | T extends Object |  擦除    | Object get()     |
+------------------+          +------------------+          +------------------+
</pre>

**桥方法生成**：子类重写泛型方法时，编译器生成桥方法以维持多态：

```java
// 源码
class StringNode extends Node<String> {
    String getData() { return data; }
}

// 字节码（编译器生成）
class StringNode extends Node {
    Object getData() { return this.getData(); }  // 桥方法
    String getData() { return data; }             // 原始方法
}
```

**数据所有权**：类型擦除后，get 方法返回 `Object`。调用方需要自行承担类型转换的风险。

## 机制

### 为什么 `List<Integer>` 不是 `List<Number>` 的子类型

若允许协变赋值：

```java
List<Integer> intList = new ArrayList<>();
List<Number> numList = intList;  // 假设允许
numList.add(3.14);  // 添加 Double 到 Integer 列表！
Integer i = intList.get(0);  // ClassCastException！
```

**类型安全违背**：协变赋值会导致**协变污染**（Contamination），在读取时产生类型错误。

### 不能创建泛型数组

```java
T[] array = new T[10];  // 编译错误
```

**数学约束**：泛型类型在运行时被擦除为 `Object[]`。若允许 `new T[10]`，由于数组协变 `Object[] ⊇ String[]`，将导致类型不安全：

```java
String[] s = (String[]) new Object[10];  // 本质上相同问题
s[0] = 3.14;  // ArrayStoreException 在运行时才检测
```

**合法替代方案**：
```java
T[] array = (T[]) Object[10];  // 警告：未检查转换
T[] array = (T[]) Array.newInstance(cls, 10);  // 反射方式
```

### 不能 instanceof 泛型类型

```java
if (obj instanceof List<String>)  // 编译错误
if (obj instanceof List<?>)       // OK，但无意义
```

运行时类型信息已擦除，`List<String>` 和 `List<Integer>` 都擦除为 `List`。

**instanceof 的数学约束**：instanceof 检查的是**运行时类型** $R(obj)$ 。类型擦除后， $R(List<String>) = R(List<Integer>) = List$ ，因此无法区分。 。类型擦除后， $R(List<String>) = R(List<Integer>) = List$ ，因此无法区分。 ，因此无法区分。

### 泛型约束

```java
// 不能实例化泛型类型
T obj = new T();  // 编译错误

// 不能创建泛型数组
T[] arr = new T[10];  // 编译错误

// 不能在静态上下文中引用类类型参数
static T value;  // 编译错误

// 不能 catch 泛型类型
try { } catch (T e) { }  // 编译错误
```

### 泛型与多态的冲突

当子类重写父类的泛型方法时，桥方法的生成可能导致签名冲突：

```java
class Parent<T> {
    T getData() { return null; }
}

class Child extends Parent<String> {
    @Override
    String getData() { return "hello"; }
}
```

字节码中实际存在两个方法：
- `String getData()`（原始方法）
- `Object getData()`（桥方法，调用 `String getData()`）

### 类型擦除对反射的影响

由于类型擦除，许多泛型相关的反射操作无法进行：

| 操作 | 结果 |
|------|------|
| `ArrayList.class.getTypeParameters()[0]` | 返回 `E`（类型参数名），但无类型信息 |
| `List<String>.class` | 编译错误，无法获取参数化类型 |
| `method.getGenericParameterTypes()` | 返回 `Type[]`，需自行解析 `ParameterizedType` |

### 泛型与 record 的结合（Java 16+）

record 可以使用泛型：

```java
record Pair<K, V>(K key, V value) {}

Pair<String, Integer> p = new Pair<>("age", 42);
```

类型擦除后，record 的组件类型被擦除到对应的上界。

### 泛型与密封类的结合

密封类可以与泛型结合：

```java
sealed interface Result<T> permits Success, Failure {
    record Success<T>(T value) implements Result<T> {}
    record Failure<T>(Exception e) implements Result<T> {}
}
```

**穷尽性检查**：使用密封类确保所有可能的泛型实例都被处理。

### 通配符捕获

通配符可以被"捕获"，但捕获后类型信息仍然丢失：

```java
List<?> list = new ArrayList<String>();
// list.add("hello");  // 编译错误：? 是未知的

// 但可以这样工作：
static <T> void helper(List<T> list) { }
helper(list);  // 捕获 ? 为 T
```

**捕获的数学解释**：通配符 `?` 代表一个未知类型。当 `List<?>` 作为参数传递时，泛型推导过程尝试找到最具体的统一类型（Most Specific Unification）。但由于 `?` 没有具体边界，无法直接操作。

## 参考存根

```java
// 泛型类的类型擦除
public class Box<T> {
    private T content;
    public T getContent() { return content; }
}

// 编译后等价于
public class Box {
    private Object content;
    public Object getContent() { return content; }
}

// 有界类型参数
public <T extends Number> T max(T a, T b) {
    return a.doubleValue() > b.doubleValue() ? a : b;
}

// PECS 原则示例
public void copyAll(List<? extends Number> from, List<? super Number> to) {
    for (Number n : from) {
        to.add(n);  // from 是生产者，to 是消费者
    }
}

// 泛型方法
public static <T> T first(List<T> list) {
    return list.isEmpty() ? null : list.get(0);
}

// 泛型与 record
record Triple<T, U, V>(T first, U second, V third) {}
```
