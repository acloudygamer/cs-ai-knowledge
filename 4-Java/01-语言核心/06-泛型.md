# 泛型

> 前置：[05-面向对象](05-面向对象.md) · 后续：[07-异常处理](07-异常处理.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

## 本质

泛型（generics，Java 5 引入）是**参数化类型**：把类型当作参数传给类、接口或方法，让同一份代码在编译期对多种类型做检查。`List<String>` 与 `List<Integer>` 共用 `List` 的一份字节码，但编译器知道前者只能装 `String`——类型错误在编译期爆炸，而不是等到运行时强转时抛 `ClassCastException`。

Java 泛型的实现策略是**类型擦除**（type erasure）：类型参数的全部检查发生在 javac 内部，字节码里类型参数被替换为它的上界（默认 `Object`）。这是理解泛型一切"怪癖"的总钥匙。

## 擦除：编译期结账，字节码无痕

实测（`--release 21` 编译，`javap -p -s` 看描述符）：

```text
class Box<T> { private T content; ... }
  → 字段 descriptor: Ljava/lang/Object;     // 无上界，T 擦成 Object

class BoundedBox<T extends Number> { private T content; ... }
  → 字段 descriptor: Ljava/lang/Number;     // 有上界，T 擦成上界
```

擦除后 `Box<String>` 和 `Box<Integer>` 在运行时是**同一个 Class**——实测 `bs.getClass() == bi.getClass()` 为 `true`。运行时拿回 `content` 时拿到的是 `Object`，编译器在调用点自动插入强转回 `String`（字节码里的 `checkcast`）。

**为什么选擦除**：历史包袱，不是理想设计。泛型在 Java 5 才入场，此前八年的字节码与类库都不认识类型参数；擦除让新旧代码共用同一 JVM、同一 class 格式、同一集合实现，代价是运行时类型信息永远丢失。后来的 JVM 语言（如 Kotlin）也只能在这笔账的约束下做修补。

擦除的直接推论，全是编译错误而非运行时惊喜：

- `new T()`——擦除后 T 是 `Object`，造不出你想要的类型；
- `new T[10]` 泛型数组——与数组协变叠加必出类型漏洞（见下）；
- `obj instanceof List<String>`——运行时 `List<String>` 与 `List<Integer>` 不可区分；
- 静态字段/静态方法引用类的类型参数——类型参数属于实例化那一下，类本身没有。

### 桥方法：擦除与多态的缝合

子类以具体类型参数继承泛型父类时，编译器额外合成**桥方法**（bridge method）维持重写的多态。实测 `StringNode extends Node<String>` 的 `javap` 输出：

```text
java.lang.String getData();    // 源码里写的重写方法
java.lang.Object getData();    // 编译器合成的桥方法：转发给上一行
```

父类擦除后的 `getData()` 返回 `Object`，而子类的方法返回 `String`——字节码层面这是两个不同方法，桥方法占住父类那个槽位并转发，动态分派（[05-面向对象](05-面向对象.md)）才不会断链。

## 型变：数组协变的教训

**数组是协变的**：`Integer[]` 是 `Number[]` 的子类型。这个 Java 1.0 就有的设计会让类型错误逃到运行时，实测：

```java
Integer[] arr = new Integer[1];
Number[] nums = arr;        // 协变赋值，编译通过
nums[0] = 3.14;             // 运行时抛 ArrayStoreException: java.lang.Double
```

**泛型吸取了教训，是不变的**：`List<Integer>` 与 `List<Number>` 没有继承关系，上面那段换成 `List` 在编译期就被拦下。数组的协变不能删（历史包袱），泛型则从一开始就不给这个口子——写入错误要么编译期拦下，要么永不发生。

需要"某种 Number 的列表"这种灵活性时，用**通配符**（wildcard）显式声明型变方向：

| 写法 | 含义 | 能做什么 |
|---|---|---|
| `List<? extends Number>` | 某个 Number 子类型的列表 | **读**出来按 Number 用；不能写（编译器不知具体是哪种） |
| `List<? super Integer>` | 某个 Integer 超类型的列表 | **写**入 Integer；读出来只能按 Object |
| `List<?>` | 未知类型的列表 | 只读为 Object |

经验规则 **PECS**（Producer Extends, Consumer Super）：从集合里往外拿数据用 `extends`，往集合里放数据用 `super`。实测可用的拷贝方法：

```java
static void copyAll(List<? extends Number> from, List<? super Number> to) {
    for (Number n : from) to.add(n);
}
// copyAll(List<Integer>, List<Number>) → 编译运行通过，输出 [1, 2, 3]
```

不能写入 `List<? extends Number>` 的原因：它背后可能是 `List<Double>`，允许写入 `Integer` 就重演了数组协变的事故——通配符把"读安全"与"写安全"拆开，各给一半能力。

## 语法速览

```java
class Box<T> { ... }                                  // 泛型类
<T extends Number & Comparable<T>> T max(T a, T b)    // 泛型方法 + 多重上界
Box<String> b = new Box<>();                          // 菱形 <>：构造器处类型推断
```

类型参数只能是引用类型——`List<int>` 不合法，用 `List<Integer>`（装箱的账见 [02-类型与变量](02-类型与变量.md)）。泛型常与 record、sealed 组合（`record Pair<K, V>(K k, V v)`），见 [10-现代语言特性](10-现代语言特性.md)。
