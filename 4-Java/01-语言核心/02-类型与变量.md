# 类型与变量

> 前置：[01-安装与第一个程序](01-安装与第一个程序.md) · 后续：[03-控制流程](03-控制流程.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

## 本质

Java 是**静态类型**语言：每个变量的类型在编译期钉死，编译器据此拒绝类型不匹配的运算——类型错误在 `javac` 阶段爆炸，而不是在运行到那一行时。变量是一个**带类型的存储槽**，类型决定两件事：槽里能放什么形状的数据，以及这块数据占多少字节、如何解释。

类型只有两类，它们的存储语义不同（这是 Java 一切赋值行为的根源）：

- **基本类型**（primitive）：八种，值直接内联在变量的存储槽里。
- **引用类型**（reference）：类、接口、数组、`String` 等，槽里放的是指向堆对象的引用，对象本体在堆里由 GC 管理（见 [01-Java全景](../00-概览/01-Java全景.md)）。

## 基本类型

| 类型 | 位宽 | 取值范围 | 字面量示例 |
|---|---|---|---|
| `byte` | 8 | $[-2^{7},\ 2^{7}-1]$ 即 -128~127 | `(byte) 42` |
| `short` | 16 | $[-2^{15},\ 2^{15}-1]$ | `(short) 1000` |
| `int` | 32 | $[-2^{31},\ 2^{31}-1]$ | `42`、`1_000_000`、`0xFF` |
| `long` | 64 | $[-2^{63},\ 2^{63}-1]$ | `42L`（`L` 不能省） |
| `float` | 32 | IEEE 754 单精度，约 7 位十进制有效数字 | `3.14f`（`f` 不能省） |
| `double` | 64 | IEEE 754 双精度，约 16 位十进制有效数字 | `3.14` |
| `char` | 16 | UTF-16 码元， $[0,\ 65535]$ 无符号 | `'中'`、`''` |
| `boolean` | — | `true` / `false`（JVM 内部按 int 处理，语言层无位宽承诺） | `true` |

整数字面量默认 `int`，小数默认 `double`；`1_000_000` 的下划线只是分组记号，编译后消失。`char` 是 UTF-16 码元而非"一个字符"——BMP 之外的字符（如 emoji）占两个 `char`，这是历史包袱：Java 诞生时 Unicode 还是 16 位的，后来 Unicode 扩到 21 位，`char` 位宽钉死改不动了。

字段与数组元素有默认值（`0` / `0.0` / `false` / `''` / `null`）；**局部变量没有默认值**，不初始化就用是编译错误——这是编译器替你把"读到垃圾值"这类 C 语言事故挡在门外。

### 补码与溢出

四种整数类型用**二进制补码**（Two's Complement）表示：n 位有符号整数的范围是 $[-2^{n-1},\ 2^{n-1}-1]$，负数 $-x$ 的位型等于 $2^n - x$。补码的工程设计是让加法和减法共用同一套电路（减法即加补码），代价是范围不对称——最小值的绝对值比最大值大 1。

算术运算是模 $2^n$ 的：溢出不报错，而是回绕。实测（`--release 21`）：

```text
int max = Integer.MAX_VALUE;          // 2147483647
max + 1                               // -2147483648（无声回绕）
Math.addExact(max, 1)                 // 抛 ArithmeticException: integer overflow
(byte) 128                            // -128（窄化截断，见下）
```

溢出无声是性能选择：每次加法都检查溢出要付出代价，Java 把它做成了显式的 `Math.addExact` / `multiplyExact` 等一族方法——涉及金额、尺寸计算的边界处用它们。

### 浮点：IEEE 754 的精度账

`float`/`double` 遵循 IEEE 754：符号位 + 指数 + 尾数。`double` 尾数 52 位，相对精度约 $2^{-52} \approx 2.22 \times 10^{-16}$——这就是 `0.1 + 0.2` 不等于 `0.3` 的原因：0.1 和 0.2 在二进制下都是无限循环小数，只能存最近似值。实测：

```text
0.1 + 0.2                  // 0.30000000000000004
```

有限精度还使加法**不满足结合律**。设 `a = 1e16`、`b = -1e16`、`c = 1`（`double` 在 $10^{16}$ 量级相邻可表示数的间隔已超过 1），实测：

```text
(a + b) + c                // 1.0
a + (b + c)                // 0.0（b + c 里的 1 被舍入吞掉）
```

推论：金额计算禁用 `double`，用 `BigDecimal`（十进制、任意精度，代价是每次运算都分配对象）；浮点累加求和注意顺序，大数先加会把小数逐个吞掉。

## 引用类型：赋值即别名

基本类型赋值复制值，引用类型赋值复制引用——两个变量指向同一个堆对象。实测：

```text
int m = 42, n = m; n = 99;         // m 仍是 42
int[] arr1 = {1}, arr2 = arr1;
arr2[0] = 99;                      // arr1[0] 也变成 99
```

引用可以为 `null`（不指向任何对象），对 null 解引用抛 `NullPointerException`——基本类型没有这个问题，这是包装类型引入的风险之一（见下）。

相等判断因此有两层：`==` 比较槽里的内容（引用类型即"是否同一对象"），`equals()` 比较对象自认的内容相等。`String`、包装类都重写了 `equals`；自己写的类不重写就继承 `Object` 的版本——等同于 `==`。

### 装箱与缓存

八种基本类型各有对应的**包装类**（`Integer`、`Double`……），泛型容器（如 `List<Integer>`，见 [06-泛型](06-泛型.md)）只能装引用类型，因此需要装箱。**自动装箱**是编译器代劳的转换：`Integer x = 42` 编译为 `Integer.valueOf(42)`；反向是拆箱 `x.intValue()`。

`Integer.valueOf` 内部有一个缓存池，默认覆盖 $[-128,\ 127]$——这个范围的小整数高频出现（循环计数、小索引），缓存它们省掉重复分配。实测：

```text
Integer x = 127, y = 127;   // x == y → true（同一缓存对象）
Integer p = 128, q = 128;   // p == q → false（超出缓存，各自新建）
```

约束推论两条：包装类之间比较**必须用 `equals`**，`==` 只在缓存范围内碰巧正确；拆箱遇到 `null` 抛 NPE——`Integer` 变量参与算术前先判空。

### 字符串与常量池

`String` 是**不可变**（immutable）对象：没有修改自身内容的方法，`concat`、`replace` 都返回新对象。不可变的收益是引用可以安全共享——没有任何一方能偷偷改掉别人手里的字符串。

共享机制是**字符串常量池**（String Pool）：内容相同的字面量在全 JVM 只有一份。实测：

```text
String s1 = "hello";
String s2 = "hel" + "lo";          // 编译期常量折叠，s1 == s2 → true
String s3 = new String("hello");   // 强制新建堆对象，s1 == s3 → false
s1 == s3.intern()                  // true：intern() 返回池中那份
```

推论与装箱相同：字符串比较用 `equals`，`==` 比较的是池内身份。`intern()` 把堆字符串驻留进池，正常代码几乎用不到——知道它的存在是为了看懂 `==` 为什么会"有时正确"。

## 类型转换

**加宽转换**（widening）自动发生，方向链是 `byte → short → int → long → float → double`，另有 `char → int`。整数之间加宽无损；`long → float/double` 形式上也自动，但 64 位整数的低几位可能被舍入丢掉——方向链上"自动"不等于"无损"。

**窄化转换**（narrowing）必须显式写强转，语义是截断位型（整数）或舍入（浮点），丢失信息由你负责：`(byte) 128` 实测得 `-128`（128 的位型 `10000000` 按补码解读恰为 -128），`(byte) 200` 得 `-56`。
