# 参数化测试

## 定义

参数化测试通过**同一测试逻辑遍历多组参数**，实现数据驱动的测试执行。其数学本质是笛卡尔积：

$$
T_{\text{executed}} = \bigcup_{i=1}^{n} \{\text{test logic} \times p_i\}
$$

其中 $p_i$ 是第 $i$ 组参数。同一测试逻辑被实例化 $n$ 次，每次使用不同参数。

**参数化的价值**：将"相同逻辑，不同数据"的测试模式从 N 个独立测试方法压缩为 1 个参数化测试方法。

---

## @ValueSource

提供单参数数组，每个元素触发一次测试执行：

```java
@ParameterizedTest
@ValueSource(ints = {0, 1, -1, Integer.MAX_VALUE, Integer.MIN_VALUE})
void testBoundaryValues(int value) {
    assertTrue(isValid(value));
}
```

支持类型：`int`、`long`、`double`、`String`、`Class`。

### 边界值注入

`Integer.MIN_VALUE`、`-1`、`0`、`1`、`Integer.MAX_VALUE`是整数类型的缺陷高发边界。

**边界缺陷的数学原因**：
- `Integer.MAX_VALUE + 1`：整数溢出
- `Integer.MIN_VALUE - 1`：整数下溢
- `-0.0 vs 0.0`：浮点零的符号差异
- `NaN`：非数值比较

---

## @NullSource、@EmptySource、@NullAndEmptySource

```java
@ParameterizedTest
@NullSource           // 注入 null
@EmptySource          // 注入 ""
@ValueSource(strings = {"  ", "a", "ab"})
void testStrings(String input) {
    assertNotNull(input);
}
```

`@NullAndEmptySource`是前两者的组合。

**语义差异**：
- `null`：空引用
- `""`：空字符串（长度为0）
- `" "`：空白字符串（长度为1但全空格）

---

## @CsvSource

逗号分隔的多参数，每行对应一次测试执行：

```java
@ParameterizedTest
@CsvSource({
    "Alice, 30, true",
    "Bob,   25, true",
    "'',    0,  false"   // 空名字非法
})
void testUser(String name, int age, boolean valid) {
    assertThat(isValid(name, age)).isEqualTo(valid);
}
```

### 自定义分隔符

```java
@CsvSource(value = {"Alice:30:100", "Bob:25:200"}, delimiter = ':')
```

---

## @CsvFileSource

从外部CSV文件读取参数，适合大量测试数据：

```java
@ParameterizedTest
@CsvFileSource(resources = "/test-data/user-valid.csv", numLinesToSkip = 1)
void testUserFromFile(String name, int age) {
    assertTrue(isValid(name, age));
}
```

CSV文件与代码分离，便于非程序员维护测试数据集。

---

## @MethodSource

引用静态工厂方法提供参数流，支持复杂对象和多参数：

```java
@ParameterizedTest
@MethodSource("provideUserArguments")
void testUser(User user, ValidationResult expected) {
    assertThat(validator.validate(user)).isEqualTo(expected);
}

static Stream<Arguments> provideUserArguments() {
    return Stream.of(
        Arguments.of(new User("Alice", 30), ValidationResult.VALID),
        Arguments.of(new User("", 0), ValidationResult.INVALID)
    );
}
```

### 外部类方法引用

```java
@MethodSource("com.example.TestDataFactory#userArguments")
```

---

## @ArgumentsSource

实现`ArgumentsProvider`接口创建自定义参数源：

```java
@ParameterizedTest
@ArgumentsSource(DatabaseArgumentsProvider.class)
void testWithDatabase(String username, String email) {
    assertTrue(isValidEmail(email));
}

public class DatabaseArgumentsProvider implements ArgumentsProvider {
    @Override
    public Stream<? extends Arguments> provideArguments(ExtensionContext ctx) {
        return Database.fetchTestUsers().stream()
            .map(u -> Arguments.of(u.getUsername(), u.getEmail()));
    }
}
```

## 多参数源组合

多个参数源组合时，测试次数为**笛卡尔积**：

$$
|T_{\text{executed}}| = \prod_{j=1}^{k} |P_j|
$$

```java
@ParameterizedTest
@ValueSource(ints = {1, 2, 3})
@ValueSource(strings = {"a", "b"})  // 3 × 2 = 6 次执行
void testCombination(int num, String letter) {
    // 会被执行 6 次
}
```

**约束**：谨慎组合，避免参数爆炸。组合测试的指数增长是参数化测试的主要风险。

## 参数转换

### 自动转换

JUnit 5内置转换器支持常见类型：

| 目标类型 | 转换规则 |
|----------|----------|
| `boolean` | `"true"`/`"false"` → `Boolean.parseBoolean()` |
| `byte` | `"123"` → `Byte.parseByte()` |
| `int/long` | 数字字符串 → 对应类型 |
| `LocalDate` | ISO日期格式字符串 → `LocalDate.parse()` |
| `UUID` | UUID字符串 → `UUID.fromString()` |
| `Enum` | 枚举名称 → 枚举常量 |

### 自定义 Converter

```java
@ParameterizedTest
@CsvSource({"2024-01-01, true", "2023-12-31, false"})
void testDate(
    @ConvertWith(DateConverter.class) LocalDate date,
    boolean expectedValid
) { }

public class DateConverter extends SimpleArgumentConverter {
    @Override
    protected Object convert(Object input, Type targetType) {
        return LocalDate.parse(input.toString());
    }
}
```

## DisplayName 自定义

```java
@ParameterizedTest(name = "User[{index}]: name={0}, age={1}")
@CsvSource({
    "Alice, 30",
    "Bob,   25"
})
void testUser(String name, int age) { }
```

输出：`User[0]: name=Alice, age=30`、`User[1]: name=Bob, age=25`

占位符：`{index}`（从0开始的序号）、`{0}`、`{1}`（对应参数值）。

## 并行执行

```java
@Execution(ExecutionMode.CONCURRENT)  // 并行执行
@ValueSource(ints = {1, 2, 3, 4, 5, 6, 7, 8})
@ParameterizedTest
void parallelTest(int value) {
    // 8次测试并行执行
}
```

**并行化的约束**：
- 测试间无共享状态
- 参数源必须是线程安全的
- 避免使用随机数（除非每次生成确定值）

## 常用场景

### 边界值测试

```java
@ParameterizedTest
@ValueSource(ints = {Integer.MIN_VALUE, -1, 0, 1, Integer.MAX_VALUE})
void testIntBoundaries(int value) {
    assertThat(calculator.divide(100, value)).isNotNull();
}
```

### 等价类划分

```java
@ParameterizedTest
@CsvSource({
    "alice@example.com, true",   // 有效邮箱
    "bob@test,        false",   // 缺少域名后缀
    "invalid,          false",   // 缺少@
})
void testEmailValidation(String email, boolean expected) {
    assertThat(validator.isValid(email)).isEqualTo(expected);
}
```

## 参数化测试的执行模型

每个参数组合对应一个**独立的测试实例**，JUnit 5为每个组合创建独立的`MethodDescriptor`：

$$
\text{TestClass} \xrightarrow{\text{参数化}} \{T_1, T_2, \dots, T_n\}
$$

这与`@RepeatedTest`不同：`@RepeatedTest`是同一逻辑重复执行N次（共享实例），参数化测试是不同参数实例。

**实例隔离**：参数化测试的每个实例类似于一个新的测试方法实例。

---

## 参数来源的选择策略

| 来源 | 适用场景 |
|------|----------|
| `@ValueSource` | 单参数，简单类型 |
| `@CsvSource` | 少量多参数，代码内维护 |
| `@CsvFileSource` | 大量数据，文件分离 |
| `@MethodSource` | 复杂对象，动态生成 |
| `@ArgumentsSource` | 非标准来源（数据库等） |

## 深度：组合测试的数学

### 全因子组合

$N$ 个布尔参数需要 $2^N$ 个测试用例：

| 参数数 | 全因子用例数 |
|--------|-------------|
| 2 | 4 |
| 3 | 8 |
| 5 | 32 |
| 10 | 1024 |

### 成对组合（Pairwise）

覆盖所有 2 元组合，复杂度 $O(N \log N)$：

**数学保证**：若每个参数的取值集合为 $V_i$，则成对组合测试覆盖所有 $(x_i \in V_i, x_j \in V_j)$ 对，其中 $i \neq j$。

**充分性**：研究表明，80%以上的缺陷可由成对组合触发。
