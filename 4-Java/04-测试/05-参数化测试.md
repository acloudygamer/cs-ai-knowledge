# 参数化测试

## 定义

参数化测试通过**同一测试逻辑遍历多组参数**，实现数据驱动的测试执行。其数学本质是笛卡尔积：

$$
T_{\text{executed}} = \bigcup_{i=1}^{n} \{\text{test logic} \times p_i\}
$$

其中 $p_i$ 是第 $i$ 组参数。同一测试逻辑被实例化 $n$ 次，每次使用不同参数。

**参数化的价值**：将"相同逻辑，不同数据"的测试模式从 N 个独立测试方法压缩为 1 个参数化测试方法，大幅减少代码重复。

---

## 数学模型

### 笛卡尔积的执行模型

设参数源 $P_1, P_2, \ldots, P_k$ 的元素个数分别为 $|P_1|, |P_2|, \ldots, |P_k|$，则测试执行次数：

$$
|T_{\text{executed}}| = \prod_{j=1}^{k} |P_j|
$$

**指数增长风险**：组合参数源时，执行次数呈指数增长。

### 全因子组合 vs 成对组合

**全因子组合**（$N$ 个布尔参数）：
$$|T_{\text{full}}| = 2^N$$

| 参数数 | 全因子用例数 |
|--------|-------------|
| 2 | 4 |
| 3 | 8 |
| 5 | 32 |
| 10 | 1024 |

**成对组合**（Pairwise）：
$$|T_{\text{pairwise}}| = O(N \log N)$$

**数学保证**：若每个参数的取值集合为 $V_i$，则成对组合测试覆盖所有 $(x_i \in V_i, x_j \in V_j)$ 对，其中 $i \neq j$。

**经验结论**：研究表明，80%以上的缺陷可由成对组合触发。

## 数据流

### @TestFactory 动态测试生成流

<pre>
外部配置/数据库
        │
        ▼
provideUserArguments() 方法
        │
        ▼
Stream<Arguments>
        │
        ├──> DynamicTest #1: name="Alice", executable
        ├──> DynamicTest #2: name="Bob", executable
        └──> ...
</pre>

**与 @ParameterizedTest 的区别**：
- `@ParameterizedTest`：同一测试逻辑，N组参数
- `@TestFactory`：N个不同测试逻辑（可动态生成）

### 参数化测试的执行流

<pre>
@CsvSource({
    "Alice, 30, true",
    "Bob,   25, false"
})
        │
        ▼
JUnit 5 实例化测试类 2 次
        │
        ├──> 实例 #1: name="Alice", age=30, expected=true
        └──> 实例 #2: name="Bob", age=25, expected=false
</pre>

每个参数组合对应一个**独立的测试实例**。

## 机制

### 参数源的选择策略

| 来源 | 适用场景 | 参数个数 |
|------|----------|----------|
| `@ValueSource` | 单参数，简单类型 | 1 |
| `@CsvSource` | 少量多参数，代码内维护 | 多 |
| `@CsvFileSource` | 大量数据，文件分离 | 多 |
| `@MethodSource` | 复杂对象，动态生成 | 多 |
| `@ArgumentsSource` | 非标准来源（数据库等） | 自定义 |

### 边界值注入的数学原因

`Integer.MIN_VALUE`、`-1`、`0`、`1`、`Integer.MAX_VALUE`是整数类型的缺陷高发边界：

| 边界值 | 潜在问题 |
|--------|----------|
| `Integer.MAX_VALUE + 1` | 整数溢出（变成负数） |
| `Integer.MIN_VALUE - 1` | 整数下溢（变成正数） |
| `-0.0 vs 0.0` | 浮点零的符号差异 |
| `NaN` | 非数值比较（NaN != NaN） |

### 链式调用的参数转换

JUnit 5 内置转换器支持常见类型：

| 目标类型 | 转换规则 |
|----------|----------|
| `boolean` | `"true"`/`"false"` → `Boolean.parseBoolean()` |
| `byte` | `"123"` → `Byte.parseByte()` |
| `int/long` | 数字字符串 → 对应类型 |
| `LocalDate` | ISO日期格式字符串 → `LocalDate.parse()` |
| `UUID` | UUID字符串 → `UUID.fromString()` |
| `Enum` | 枚举名称 → 枚举常量 |

**自定义转换器**：实现 `SimpleArgumentConverter` 或 `ArgumentConverter` 接口。

### 并行执行的约束

`@Execution(ExecutionMode.CONCURRENT)` 启用并行执行：

**约束**：
- 测试间无共享状态
- 参数源必须是线程安全的
- 避免使用随机数（除非每次生成确定值）

### DisplayName 占位符语义

| 占位符 | 含义 |
|--------|------|
| `{index}` | 从0开始的序号 |
| `{0}`, `{1}`, ... | 对应参数值 |

```java
@ParameterizedTest(name = "User[{index}]: name={0}, age={1}")
@CsvSource({"Alice, 30", "Bob, 25"})
void testUser(String name, int age) { }
```

输出：`User[0]: name=Alice, age=30`、`User[1]: name=Bob, age=25`

## 深度：组合测试的数学

### 全因子组合的穷举性

$N$ 个布尔参数的全因子组合测试覆盖所有 $2^N$ 种可能输入组合，提供**完备性保证**：

$$
\forall (b_1, b_2, \ldots, b_N) \in \{0, 1\}^N: \exists t \in T_{\text{full}}: \text{test}(t) = (b_1, b_2, \ldots, b_N)
$$

### 成对组合的最优性

成对组合测试的覆盖表生成是一个**组合优化问题**：

**目标**：用最少的测试用例覆盖所有 2 元组合。

**数学表达**：
$$
\forall i < j, \forall v_i \in V_i, \forall v_j \in V_j: \exists t \in T_{\text{pairwise}}: t[i] = v_i \land t[j] = v_j
$$

**充分性**：研究表明，80%以上的缺陷可由成对组合触发——这是经验数据，不是数学证明。

### 覆盖表（Covering Array）

成对组合的最优覆盖可由覆盖表定义：

| 参数A | 参数B | 参数C | 测试用例 |
|--------|--------|--------|----------|
| 0 | 0 | 0 | 1 |
| 0 | 1 | 1 | 2 |
| 1 | 0 | 1 | 3 |
| 1 | 1 | 0 | 4 |

3 参数、每个参数 2 个取值：需要 4 个测试用例覆盖所有 2 元组合（而非 8 个全因子用例）。

## 参考存根

```java
// 笛卡尔积执行的最小化演示
import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;

public class CartesianProduct {
    public static void main(String[] args) {
        List<Integer> nums = Arrays.asList(1, 2);
        List<String> letters = Arrays.asList("a", "b");

        // 笛卡尔积：2 × 2 = 4 种组合
        List<String> combinations = nums.stream()
            .flatMap(n -> letters.stream().map(l -> n + l))
            .collect(Collectors.toList());

        System.out.println("组合: " + combinations);
        // 输出: [1a, 1b, 2a, 2b]
    }
}
```
