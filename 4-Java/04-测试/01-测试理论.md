# 测试理论

## 测试金字塔

### 层级结构

```
        /\
       /  \      E2E (少量)
      /----\     集成测试 (适量)
     /      \    单元测试 (大量)
    /--------\
```

测试金字塔是测试策略的基础指导原则：

| 层级 | 数量 | 特点 | 速度 | 成本 |
|------|------|------|------|------|
| E2E | 少量 | 接近真实用户场景 | 慢 | 高 |
| 集成测试 | 适量 | 验证组件协作 | 中 | 中 |
| 单元测试 | 大量 | 测试独立组件 | 快 | 低 |

### 单元测试

单元测试验证最小可测试单元的行为，通常是单个类或方法。

```java
@Test
void testAdd() {
    Calculator calc = new Calculator();
    assertEquals(5, calc.add(2, 3));
}
```

### 集成测试

集成测试验证多个组件协同工作的正确性。

```java
@SpringBootTest
class UserServiceIntegrationTest {
    @Autowired
    private UserService userService;

    @Test
    void testFullWorkflow() {
        User user = userService.createUser("Alice", "alice@example.com");
        assertNotNull(user.getId());
    }
}
```

### 端到端测试

E2E 测试从用户角度验证整个系统的行为。

```java
@Test
void testLoginFlow() {
    driver.get("http://localhost:8080/login");
    driver.findElement(By.name("username")).sendKeys("alice");
    driver.findElement(By.name("password")).sendKeys("secret");
    driver.findElement(By.name("submit")).click();
    assertEquals("Welcome", driver.getTitle());
}
```

## 测试核心概念

### AAA 模式

测试应遵循 Arrange-Act-Assert 结构：

```java
@Test
void testUserCreation() {
    // Arrange - 准备测试数据
    UserService service = new UserService();

    // Act - 执行被测操作
    User user = service.createUser("Alice", "alice@example.com");

    // Assert - 验证结果
    assertNotNull(user.getId());
    assertEquals("Alice", user.getName());
}
```

### FIRST 原则

| 原则 | 说明 |
|------|------|
| Fast | 测试应快速执行 |
| Independent | 测试之间无依赖 |
| Repeatable | 测试结果可重复 |
| Self-validating | 测试自行验证结果 |
| Timely | 测试应及时编写 |

### 测试隔离

每个测试应独立运行，不依赖其他测试的状态。

```java
@SpringBootTest
@DirtiesContext(classMode = BEFORE_EACH_TEST_METHOD)
class IsolatedTest {
    // 每个测试前重建 Spring 上下文
}
```

### 测试替身 (Test Double)

| 类型 | 用途 | 特点 |
|------|------|------|
| Dummy | 填充参数列表 | 从不使用 |
| Fake | 简化实现 | 有实际逻辑但不完整 |
| Stub | 预设回答 | 返回预设值 |
| Spy | 部分模拟 | 记录调用 + 真实执行 |
| Mock | 行为验证 | 预设期望 + 验证交互 |

## 测试质量

### 好的测试特征

- **唯一性**：每个测试验证一个具体行为
- **可读性**：测试名称清晰描述被测内容
- **可靠性**：不受环境影响，结果稳定
- **独立性**：不依赖其他测试的执行顺序
- **快速性**：毫秒级执行完成

### 常见反模式

| 反模式 | 问题 | 解决方案 |
|--------|------|----------|
| 断言泥潭 | 大量断言混在一起 | 分离为多个测试 |
| 魔法值 | 数字含义不明确 | 使用命名常量 |
| 顺序依赖 | 测试必须按顺序执行 | 清理共享状态 |
| 隐藏依赖 | 测试依赖外部状态 | 使用依赖注入 |

### 测试命名规范

```java
// 推荐：描述性名称
@Test
void createUser_withEmptyName_throwsIllegalArgumentException() { }

// 推荐：given-when-then 格式
@Test
void givenNewUser_whenSave_thenReturnsCreatedUser() { }

// 避免：模糊名称
@Test
void test1() { }
@Test
void testCreate() { }
```

## 测试策略

### 边界值测试

测试应关注边界条件：

```java
@ParameterizedTest
@ValueSource(ints = {Integer.MIN_VALUE, -1, 0, 1, Integer.MAX_VALUE})
void testBoundary(int value) {
    // 边界值测试
}
```

### 等价类划分

将输入分成有效和无效等价类：

```java
@ParameterizedTest
@CsvSource({
    "alice@example.com, true",
    "bob@test.org, true",
    "invalid, false",
    "@test.com, false"
})
void testEmailValidation(String email, boolean expected) {
    assertEquals(expected, validator.isValid(email));
}
```

### 错误处理测试

验证异常场景：

```java
@Test
void testDivideByZero() {
    ArithmeticException ex = assertThrows(
        ArithmeticException.class,
        () -> calculator.divide(1, 0)
    );
    assertEquals("/ by zero", ex.getMessage());
}
```

## 测试覆盖率

### 覆盖率类型

| Counter | 说明 |
|---------|------|
| LINE | 行覆盖 |
| BRANCH | 分支覆盖 |
| CLASS | 类覆盖 |
| METHOD | 方法覆盖 |

### 覆盖率标准

| 级别 | 行覆盖率 | 分支覆盖率 |
|------|----------|------------|
| 最低 | 50% | 40% |
| 良好 | 70% | 60% |
| 优秀 | 80% | 70% |

### 覆盖率误区

- 覆盖率不是终极目标
- 高覆盖率不等于高质量测试
- 关注关键业务逻辑和边界条件
