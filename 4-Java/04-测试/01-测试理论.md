# 测试理论

## 测试金字塔

**测试金字塔是通过分层测试策略平衡成本与覆盖率的模型。**

<pre>
        /\
       /  \      E2E (少量)
      /----\     集成测试 (适量)
     /      \    单元测试 (大量)
    /--------\
</pre>

层级的数量比例反映测试成本曲线：单元测试廉价可并行，E2E 昂贵需串行执行。成本差异来自真实环境启动开销和执行速度。

| 层级 | 数量 | 特点 | 速度 | 成本 |
|------|------|------|------|------|
| E2E | 少量 | 接近真实用户场景 | 慢 | 高 |
| 集成测试 | 适量 | 验证组件协作 | 中 | 中 |
| 单元测试 | 大量 | 测试独立组件 | 快 | 低 |

### 单元测试

验证最小可测试单元的行为，通常是单个类或方法。

### 集成测试

验证多个组件协同工作的正确性。

### 端到端测试

从用户角度验证整个系统的行为。

## 测试核心概念

### AAA 模式

**测试通过 Arrange-Act-Assert 结构将测试行为显性化。**

1. **Arrange** — 构造被测系统的输入状态
2. **Act** — 对被测系统执行操作
3. **Assert** — 验证系统行为符合预期

### FIRST 原则

**FIRST 原则是单元测试的质量门禁。**

| 原则 | 说明 |
|------|------|
| Fast | 测试应毫秒级完成；慢测试降低反馈频率 |
| Independent | 测试间无状态共享；依赖导致顺序脆弱性 |
| Repeatable | 确定性结果；随机性是测试的敌人 |
| Self-validating | 自动化断言；无需人工判断 |
| Timely | 先写测试再写代码；测试先行确保可测性 |

### 测试隔离

**测试隔离通过清除副作用避免误报。**

每次测试运行前重置被测系统的状态，防止测试间隐式依赖导致间歇性失败。

### 测试替身 (Test Double)

**Test Double 是用伪对象替代真实依赖以隔离被测对象的模式。**

| 类型 | 用途 | 机制 |
|------|------|------|
| Dummy | 填充参数列表 | 从不调用 |
| Fake | 简化实现 | 有实际逻辑但不完整（内存数据库） |
| Stub | 预设回答 | 返回预设值，不验证调用 |
| Spy | 部分模拟 | 记录调用 + 真实执行 |
| Mock | 行为验证 | 预设期望 + 验证交互 |

## 测试质量

### 好的测试特征

- **唯一性**：每个测试验证一个具体行为
- **可读性**：测试名称清晰描述被测内容
- **可靠性**：不受环境影响，结果稳定
- **独立性**：不依赖其他测试的执行顺序
- **快速性**：毫秒级执行完成

### 常见反模式

| 反模式 | 问题 | 解决方案 |
|--------|------|----------|
| 断言泥潭 | 大量断言混在一起 | 分离为多个测试 |
| 魔法值 | 数字含义不明确 | 使用命名常量 |
| 顺序依赖 | 测试必须按顺序执行 | 清理共享状态 |
| 隐藏依赖 | 测试依赖外部状态 | 使用依赖注入 |

## 测试策略

### 边界值测试

**边界值测试聚焦输入范围的极端点。**

输入等价类的边界是缺陷高发区：整数边界（0、-1、1、MAX_VALUE）、字符串边界（空串、单字符、超长串）。

### 等价类划分

**等价类划分通过代表性样本降低测试成本。**

将输入空间划分为有效等价类和无效等价类，每个等价类只需一个代表性测试用例。

### 错误处理测试

验证异常场景。

## 测试覆盖率

### 覆盖率类型

| Counter | 说明 |
|---------|------|
| LINE | 行覆盖 |
| BRANCH | 分支覆盖 |
| CLASS | 类覆盖 |
| METHOD | 方法覆盖 |

### 覆盖率标准

| 级别 | 行覆盖率 | 分支覆盖率 |
|------|----------|------------|
| 最低 | 50% | 40% |
| 良好 | 70% | 60% |
| 优秀 | 80% | 70% |

### 覆盖率误区

- 覆盖率不是终极目标
- 高覆盖率不等于高质量测试
- 关注关键业务逻辑和边界条件
