# 测试覆盖率

## JaCoCo 概述

**JaCoCo 通过字节码插桩在运行时收集执行数据，度量代码覆盖程度。**

插桩发生在测试执行前，JaCoCo Agent 拦截所有类加载，记录每条指令的执行次数。

### Maven 配置

JaCoCo Maven Plugin 在 test 阶段生成报告，在 verify 阶段执行质量门禁检查。

### Gradle 配置

Gradle 插件集成更简洁，jacocoTestCoverageVerification 在构建时强制执行覆盖率阈值。

## 覆盖率类型

### Counter 类型

| Counter | 说明 |
|---------|------|
| LINE | 行覆盖 |
| BRANCH | 分支覆盖（if/while/for/switch） |
| CLASS | 类覆盖 |
| METHOD | 方法覆盖 |
| INSTRUCTION | JVM 指令覆盖 |
| COMPLEXITY | 圈复杂度覆盖 |

### 覆盖比率

| Value | 说明 |
|-------|------|
| TOTALTOTAL | 总数 |
| COVERED | 已覆盖 |
| MISSED | 未覆盖 |
| COVEREDRATIO | 覆盖率（COVERED / TOTALTOTAL） |

## 覆盖率指标

**覆盖率度量已执行代码与总代码的比例。**

$$
\text{Line Coverage} = \frac{\text{Covered Lines}}{\text{Total Lines}} \times 100\%
$$

$$
\text{Branch Coverage} = \frac{\text{Covered Branches}}{\text{Total Branches}} \times 100\%
$$

### 常见标准

| 级别 | 行覆盖率 | 分支覆盖率 |
|------|----------|------------|
| 最低 | 50% | 40% |
| 良好 | 70% | 60% |
| 优秀 | 80% | 70% |
| 严格 | 90% | 80% |

## 分支覆盖率

**分支覆盖率衡量条件分支的覆盖程度，每个 boolean 条件的结果组合都需要被测试。**

<pre>
if (age < 0 || age > 150) {  // 2 个分支
    return false;
}
return age >= 18;             // 2 个分支
</pre>

100% 分支覆盖要求：age < 0 (true/false)、age > 150 (true/false)、age >= 18 (true/false)。

### 分支覆盖与条件覆盖

- **BRANCH**：覆盖每个 boolean 表达式结果的组合
- **CONDITION**：覆盖每个条件的 true/false 独立

## 生成报告

### Maven

```bash
mvn clean verify
# 报告生成在 target/site/jacoco/index.html
```

### Gradle

```bash
./gradlew test jacocoTestReport
# 报告生成在 build/reports/jacoco/test/index.html
```

## 集成 CI/CD

### GitHub Actions

CI 流水线中执行测试并上传覆盖率报告至 Codecov，实现覆盖率趋势追踪。

### SonarQube

SonarQube 作为质量门禁，强制执行覆盖率阈值，阻断不达标构建。

## 常见问题

### 私有方法覆盖

私有方法通过反射调用测试，使用 @TestVisibleForTesting 标记测试用途。

### Lombok 问题

Lombok 生成的方法（getter、setter、builder）应从覆盖率排除，避免污染指标。

### 枚举覆盖

枚举的所有值都需要测试，确保每个枚举值都被正确处理。

## SonarQube 质量门禁

**SonarQube 质量门禁在代码质量维度之上增加覆盖率维度，强制团队保持代码质量底线。**

## 最佳实践

### 不要追求 100%

**覆盖率是发现未测试代码的工具，而非目标本身。**

关注关键业务逻辑、边界条件、异常处理路径，而非数字本身。

### 增量提升

每次新增代码时补充对应测试，逐步提升覆盖率。

### 关注分支覆盖

分支覆盖率低意味着存在未测试的条件分支，是缺陷隐藏的高风险区。
