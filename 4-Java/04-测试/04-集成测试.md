# 集成测试

## 定义

集成测试通过**启动完整或部分容器环境**，验证组件间交互的正确性——介于单元测试（隔离单个类）和E2E测试（隔离整个系统）之间。

**层次定位**：
- 单元测试：验证**组件内部**逻辑（算法、边界条件）
- 集成测试：验证**组件之间**契约（接口兼容性、数据流）
- E2E测试：验证**系统整体**用户旅程

**集成测试的本质**：在受控的集成环境中验证组件协作，核心挑战是**控制环境复杂度**与**隔离外部依赖**。

---

## 分层测试注解

Spring Boot提供分层注解，每层启动不同范围的组件：

| 注解 | 启动组件 | 测试范围 | 速度 |
|------|----------|----------|------|
| `@SpringBootTest` | 完整上下文 | 全栈 | 慢 |
| `@WebMvcTest` | MVC层 | Controller | 快 |
| `@DataJpaTest` | JPA层 | Repository | 快 |
| `@JsonTest` | JSON处理 | Jackson/ObjectMapper | 快 |
| `@WebFluxTest` | WebFlux层 | Controller | 快 |
| `@JdbcTest` | JDBC层 | SQL | 快 |

**速度与覆盖的权衡**：切片测试启动快，但只覆盖单一层；@SpringBootTest 启动慢，但覆盖全栈。

## @SpringBootTest

启动完整Spring上下文，所有Bean被创建和装配：

```java
@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
class FullIntegrationTest {
    @Autowired
    private UserService userService;
}
```

### WebEnvironment选项

| 选项 | 行为 | 适用场景 |
|------|------|----------|
| `MOCK`（默认） | Mock Servlet容器 | 快速集成测试 |
| `RANDOM_PORT` | 启动随机端口的真实容器 | 真实HTTP测试 |
| `DEFINED_PORT` | 使用application.yml中的端口 | 固定端口测试 |
| `NONE` | 不启动Web环境 | 纯业务逻辑测试 |

## MockMvc

MockMvc通过**Mock Servlet API**模拟HTTP请求，无需启动真实服务器：

```java
@Autowired
private MockMvc mockMvc;

@Test
void getUser() throws Exception {
    mockMvc.perform(get("/users/1"))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$.name").value("Alice"));
}
```

### 链式API语义

```java
mockMvc.perform(get("/users/{id}", 1L))           // HTTP方法+URL
    .andExpect(status().isOk())                   // 断言响应状态
    .andExpect(header().string("Content-Type", ...)) // 断言响应头
    .andExpect(jsonPath("$.name").value("Alice")) // 断言JSON body
    .andDo(print());                              // 打印请求/响应详情
```

**执行流程**：
```
MockMvc.perform()
    → MockHttpServletRequest
    → FilterChain（执行Controller）
    → MockHttpServletResponse
    → andExpect() 断言
```

## @DataJpaTest

仅启动JPA组件，使用**内存数据库**（默认H2）替代真实数据库：

```java
@DataJpaTest
class UserRepositoryTest {
    @Autowired
    private UserRepository repository;

    @Test
    void saveAndFind() {
        User user = new User("Alice", "alice@example.com");
        repository.save(user);
        assertTrue(repository.findByName("Alice").isPresent());
    }
}
```

### 内存数据库隔离

每个测试在独立事务中执行，测试结束后自动回滚：

```java
@Test
@Transactional  // 显式事务（@DataJpaTest已默认）
void isolatedTest() {
    repository.save(new User("Bob", "bob@example.com"));
    assertEquals(1, repository.count());  // 其他测试不受影响
}
```

**事务边界**：
$$
\text{TestMethod} \rightarrow \text{BEGIN TX} \rightarrow \text{执行测试} \rightarrow \text{ROLLBACK}
$$

## TestContainers

TestContainers通过**Docker容器**启动真实数据库，确保测试环境与生产环境一致：

### @DynamicPropertySource

将容器端口动态注入Spring配置：

```java
@Testcontainers
@DataJpaTest
class PostgresTest {
    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15");

    @DynamicPropertySource
    static void properties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
    }
}
```

**真实数据库测试价值**：
- SQL方言兼容性（PostgreSQL vs MySQL 差异）
- 索引优化器行为
- 字符集/排序规则
- 约束执行（外键、唯一索引）

### 多容器场景

```java
@Container
static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15");
@Container
static GenericContainer<?> redis = new GenericContainer<>("redis:7");
```

### 事务管理

`@Transactional`使测试在独立事务中执行，测试结束后自动回滚：

### @Rollback(false)

特定测试需要保留测试数据用于人工验证或后续测试：

```java
@Test
@Transactional
@Rollback(false)  // 事务提交，数据保留
void preserveDataForDebug() {
    repository.save(new User("DebugUser", "debug@test.com"));
}
```

### @Sql 初始化数据

通过SQL脚本在测试前初始化特定数据：

```java
@Sql(scripts = "/test-data.sql", executionPhase = Sql.ExecutionPhase.BEFORE_TEST_METHOD)
@Test
void withTestData() {
    // test-data.sql 中的数据已插入
}
```

## REST Assured

REST Assured提供BDD风格的HTTP测试API：

```java
given()
    .contentType(ContentType.JSON)
    .body(userDto)
.when()
    .post("/users")
.then()
    .statusCode(201)
    .body("name", equalTo("Alice"));
```

`given-when-then`结构使测试文档化，可读性接近自然语言。

## 异步测试

Spring MVC的`DeferredResult`/`CompletableFuture`返回类型需要异步等待：

```java
@Test
void asyncTest() throws Exception {
    MvcResult result = mockMvc.perform(get("/async/data"))
        .andExpect(request().asyncStarted())
        .andReturn();

    mockMvc.asyncDispatch(result)
        .andExpect(status().isOk())
        .andExpect(content().string("data"));
}
```

**异步分发模型**：
1. `asyncStarted()` 触发异步处理
2. `asyncDispatch()` 等待异步结果并分发到下一过滤器

## 切片测试的适用场景

| 注解 | 适用场景 | 限制 |
|------|----------|------|
| `@WebMvcTest` | Controller 层逻辑（不含Service） | Service未加载，需@MockBean |
| `@DataJpaTest` | Repository 层逻辑（不含Service） | Service未加载，需@DataJpaTest |
| `@JsonTest` | 序列化/反序列化逻辑 | 仅测JSON处理 |

**切片测试 vs @SpringBootTest**：
- 切片测试：启动快（秒级），覆盖单一层
- @SpringBootTest：启动慢（十秒级），覆盖全栈

## 深度：集成测试的环境隔离数学

集成测试的核心挑战是**环境隔离**。设：

- $E_{\text{test}}$：测试环境
- $E_{\text{prod}}$：生产环境
- $\Delta E = E_{\text{prod}} \setminus E_{\text{test}}$：环境差异

**理想目标**：$\Delta E = \emptyset$（测试环境与生产环境完全一致）

**现实约束**：
- 真实数据库：隔离成本高（每个测试独立DB实例）
- 真实外部服务：不可控（第三方API）
- 真实时间：不确定（CI环境时间漂移）

**隔离策略**：
1. **进程隔离**：每个测试在独立进程中执行
2. **事务隔离**：每个测试在独立事务中执行，测试后回滚
3. **容器隔离**：每个测试在独立Docker容器中执行
4. **网络隔离**：使用WireMock/Mockserver模拟外部服务

## 最佳实践

### @DirtiesContext

每个测试前重建Spring上下文，防止Bean状态泄漏：

```java
@DirtiesContext(classMode = ClassMode.BEFORE_EACH_TEST_METHOD)
class StatefulServiceTest {
    // 每个测试前重建上下文
}
```

### 配置文件分离

```yaml
# application-test.yml
spring:
  datasource:
    url: jdbc:h2:mem:testdb
  jpa:
    hibernate:
      ddl-auto: create-drop
```

### 测试隔离原则

$$
\forall \text{Test}_i, \text{Test}_j: i \neq j \implies \text{Test}_i.\text{state} \cap \text{Test}_j.\text{state} = \emptyset
$$

违反此原则会导致测试间隐式依赖，引起间歇性失败。
