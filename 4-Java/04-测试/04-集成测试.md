# 集成测试

## 概述

**集成测试通过启动完整或部分容器环境，验证组件间交互的正确性。**

<pre>
        /\
       /  \      E2E (少量)
      /----\     集成测试 (适量)
     /      \    单元测试 (大量)
    /--------\
</pre>

单元测试验证类，集成测试验证组件之间的契约。

## Spring Boot 集成测试

**Spring Boot 提供分层测试注解，按需启动对应层次的组件。**

### @SpringBootTest

启动完整 Spring 上下文，适用于需要完整 Bean 协作的测试场景。

### @WebMvcTest 只测 Controller

只启动 MVC 层组件（Controller、HandlerAdapter、MessageConverter），使用 MockMvc 模拟请求。Service 层用 @MockBean 替换。

### @DataJpaTest 只测 JPA

只启动 JPA 相关组件（EntityManager、JpaRepository），使用内存数据库（H2）替代真实数据库，确保测试隔离和速度。

### @JsonTest 只测 JSON 序列化

只启动 JSON 处理组件（Jackson、ObjectMapper），用于验证序列化/反序列化正确性。

## MockMvc 详解

**MockMvc 通过模拟 Servlet API，在不使用真实 HTTP 服务器的情况下验证 Controller 行为。**

### 请求构建

MockMvc 提供链式 API 构建请求，andExpect() 添加断言，链式调用使验证逻辑内联。

### 文件上传

使用 MockMultipartFile 模拟 multipart 请求，绕过真实文件系统的依赖。

## TestContainers

**TestContainers 通过 Docker 容器启动真实数据库，确保测试环境与生产环境一致。**

### @DynamicPropertySource

通过动态属性注入，将容器端口映射到 Spring 配置，使应用连接真实容器而非内存数据库。

### 多容器

一个测试可启动多个容器（PostgreSQL + Redis），覆盖依赖所有外部服务的集成场景。

## 数据库测试

### H2 内存数据库

H2 内存数据库适合快速测试，JVM 重启后数据自动丢失，确保测试间完全隔离。

### 事务管理

**@Transactional 使测试在独立事务中执行，测试结束后自动回滚。**

每个测试方法在单独事务中执行，测试间无副作用。

### @Rollback(false) 不回滚

特定测试方法可声明不回滚，保留测试数据用于人工验证或后续测试。

### @Sql 初始化数据

通过 SQL 脚本在测试前初始化特定数据，替代代码构造复杂数据状态。

## REST Assured

**REST Assured 提供 BDD 风格的 HTTP 测试 API，使 HTTP 验证语法接近自然语言。**

given-when-then 结构使测试文档化。

## 异步测试

**CompletableFuture.join() 阻塞等待结果，assertTimeout 验证超时处理。**

## 集成测试最佳实践

### 测试隔离

**@DirtiesContext 在每个测试前重建 Spring 上下文，防止测试间 Bean 状态泄漏。**

### 配置文件分离

独立测试配置文件（application-test.yml）覆盖生产配置，确保测试使用测试数据源和测试端口。
