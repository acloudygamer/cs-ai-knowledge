# Java 21

> 前置：[01-演进脉络与LTS节奏](./01-演进脉络与LTS节奏.md) · 后续：[03-Java22至25](./03-Java22至25.md)

> **版本基准**：Java 21（2023-09，LTS）= 本库 stable 口径。实测环境：Temurin JDK 25.0.4.1（Windows），示例以 `javac -encoding UTF-8 --release 21` 编译验证（预览特性需同版本 JDK + `--enable-preview`，本机仅有 25，无法实测 21 的预览特性，逐条注明）。

Java 21（2023-09 发布，LTS）是两条演进线的汇合点：并发侧，孵化预览五年的**虚拟线程**转正；类型侧，Java 14 起逐版预览的**模式匹配**在 switch 与 record 解构上收口。此外它给了集合框架一次结构补全（Sequenced Collections）和 ZGC 的分代化。

## 并发主线

### 虚拟线程转正（JEP 444）

虚拟线程（Virtual Thread）是 JVM 调度的用户态轻量级线程：M 个虚拟线程映射到 N 个平台载体线程（carrier thread，通常等于 CPU 核数），虚拟线程阻塞时 JVM 把它从载体上卸下（unmount），载体立即去跑别的虚拟线程。平台线程那一套"线程数 ≈ 并发上限"的约束就此解除——高并发 I/O 服务回到"一个请求一个线程"的朴素写法，不再需要异步回调。

演进线：Java 19 预览（JEP 425）→ 20 二次预览（JEP 436）→ 21 转正。

实测（`--release 21`，Temurin 25.0.4.1，12 核）：一万个各 sleep 100ms 的虚拟线程，若用平台线程池需分批排队，虚拟线程总耗时约 150ms：

```java
try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        exec.submit(() -> { Thread.sleep(100); return 0; });
    }
}
```

```text
10000 个虚拟线程各 sleep 100ms，总耗时 158 ms
可用载体上限(Runtime.availableProcessors)=12
```

遗留缺口：21 中虚拟线程在 `synchronized` 块内阻塞时会**钉住**（pin）载体线程，载体随它一起挂起。此问题在 Java 24 由 JEP 491 修复（见 [03-Java22至25](./03-Java22至25.md)）。

### 结构化并发预览（JEP 453）

`StructuredTaskScope`：把一组并发子任务装进一个词法作用域，作用域退出即保证所有子任务完结——并发版 try-with-resources。演进线：Java 19/20 孵化（JEP 428/437）→ 21 转预览。预览身份 + 本机仅有 JDK 25（预览特性只能用同版本 JDK 编译），本篇不实测；其 25 形态（第五预览，JEP 505）的实测见 [03-Java22至25](./03-Java22至25.md)。

### Scoped Values 预览（JEP 446）

Scoped Value 是绑定到词法作用域的不可变共享值：`ScopedValue.where(KEY, v).run(...)` 之后，`v` 在作用域内及其派生的虚拟线程中可见，出作用域即失效。它回应的约束：虚拟线程以十万计时，`ThreadLocal` 的"每线程一份可变副本"模型内存开销与泄漏风险都不可接受。演进线：Java 20 孵化（JEP 429）→ 21 预览 → 25 转正（JEP 506，实测见 [03-Java22至25](./03-Java22至25.md)）。

## 模式匹配收口

### Record Patterns 转正（JEP 440）

record patterns 把 record 从"类型"升格为"模式"：`case Point(int x, int y)` 在匹配的同时把组件解构绑定为变量，且可嵌套。演进线：Java 19 预览（JEP 405）→ 20 二次预览（JEP 432）→ 21 转正。

### Pattern Matching for switch 转正（JEP 441）

switch 的 case 标签从常量升格为模式：类型模式、record 模式、`null` 分支、`when` 卫语句；配合 sealed 层级时编译器做穷尽性证明，缺分支即编译错误。演进线：Java 17 起四次预览（JEP 406/420/427/433）→ 21 转正。

两者实测（`--release 21`）：

```java
record Point(int x, int y) {}
sealed interface Shape permits CircleShape, Rect {}
record CircleShape(Point center, int radius) implements Shape {}
record Rect(int w, int h) implements Shape {}

static String describe(Shape o) {
    return switch (o) {
        case CircleShape(Point(int x, int y), int r) when r > 10 -> "大圆，圆心(%d,%d)".formatted(x, y);
        case CircleShape(Point c, int r) -> "小圆 r=%d，圆心 x=%d".formatted(r, c.x());
        case Rect(int w, int h) -> "矩形 %dx%d".formatted(w, h);
    };
}
```

```text
嵌套解构: x=1 y=2 r=5
大圆，圆心(3,4)
小圆 r=5，圆心 x=3
矩形 2x8
```

注意 `describe` 没有 `default`：sealed 层级封闭，两个 case 穷尽，`when` 卫语句只缩小单个分支的命中范围、不破坏整体穷尽性（编译器按"无条件模式 + 兜底分支"的组合验证）。

## Sequenced Collections（JEP 431）

集合框架自 Java 1.2 起缺一个抽象：**有定义顺序的集合**（`List` 有、`LinkedHashSet`/`LinkedHashMap` 有、`SortedSet` 有，但没有共同接口表达"取第一个/最后一个/反向遍历"）。JEP 431 在类型层级中插入 `SequencedCollection` / `SequencedSet` / `SequencedMap` 三个接口，`List`、`Deque`、`LinkedHashSet`、`LinkedHashMap`、`SortedSet` 等全部归入其下，统一获得 `getFirst()`/`getLast()`/`reversed()`。

实测（`--release 21`）：

```java
SequencedSet<String> s = new LinkedHashSet<>(List.of("a", "b", "c"));
SequencedMap<String, Integer> m = new LinkedHashMap<>();
```

```text
first=a last=c
reversed=[c, b, a]
firstEntry=k1=1 lastEntry=k2=2
putFirst 后 firstEntry=k0=0
list=[0, 1, 2, 3]
```

## 分代 ZGC（JEP 439）

ZGC（Java 11 实验登场 JEP 333、15 生产就绪 JEP 377）此前不分代：每次回收扫描全堆，短生命周期对象占多数的应用浪费了"分代假说"红利。JEP 439 把 ZGC 改为**分代模式**（年轻代/老年代分开回收），21 中通过 `-XX:+UseZGC -XX:+ZGenerational` 启用，非分代模式保留为备选。后续：Java 23 分代成为默认（JEP 474），Java 24 直接删除非分代模式（JEP 490）——在 JDK 25 上 `ZGenerational` 开关已不存在（本机验证 `-XX:+PrintFlagsFinal` 无此项），分代是 ZGC 的唯一形态。

## String Templates 预览（JEP 430）

字符串模板 `STR."...\{expr}..."`：把字符串插值收编为编译器检查的语法，插值表达式先经模板处理器（`STR`、`FMT`、自定义）加工再拼串，目标之一是根治 SQL/HTML 拼接注入。21 预览后 22 二次预览（JEP 459），但模板表达式与处理器之间的安全模型始终无法收敛，**Java 23 起整体撤回**，至今未回归。这是预览机制"真会死"一面的标本（见 [01-演进脉络与LTS节奏](./01-演进脉络与LTS节奏.md)）。未实测：该特性已不存在于 JDK 25。
