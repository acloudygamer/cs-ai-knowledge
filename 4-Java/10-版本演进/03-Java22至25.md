# Java 22 至 25

> 前置：[02-Java21](./02-Java21.md) · 后续：无（本目录收官）

> **版本基准**：Java 25（2025-09，LTS）= 本库 latest 口径。实测环境：Temurin JDK 25.0.4.1（Windows）——25 的特性原生实测；22/23/24 的转正特性在 25 上验证等价行为并注明；预览特性以 `--enable-preview` 实测并注明。

Java 22/23/24 是通往 Java 25 的三个非 LTS 试验田：21 预览的一批特性在它们身上逐版迭代，到 25 集中转正，形成继 21 之后的第二次收口。按版本逐节清点。

## Java 22（2024-03）

主题：**JNI 的接班人到岗**。FFM API 转正，原生互操作第一次有了纯 Java 的安全通道。

### Foreign Function & Memory API 转正（JEP 454）

FFM API 提供两件东西：`MemorySegment` + `Arena` 管理堆外内存（作用域绑定，出作用域自动释放，杜绝泄漏与悬垂），`Linker`/`SymbolLookup` 直接调用 C 函数——全程不写 JNI 的 C 胶水层。演进线：Java 17 孵化（JEP 412）→ 19/20/21 三次预览（JEP 424/434/442）→ 22 转正。

实测（22 转正 API 在本机 JDK 25 上验证等价行为）：

```java
try (Arena arena = Arena.ofConfined()) {
    MemorySegment seg = arena.allocate(ValueLayout.JAVA_INT, 4);
    for (int i = 0; i < 4; i++) seg.setAtIndex(ValueLayout.JAVA_INT, i, i * i);
    for (int i = 0; i < 4; i++) IO.print(seg.getAtIndex(ValueLayout.JAVA_INT, i) + " ");
}
```

```text
0 1 4 9 <- 堆外内存，try 结束时由 arena 统一释放
```

### 未命名变量与模式转正（JEP 456）

`_` 成为正式的"此处值无用"记号：lambda 参数、`catch` 形参、record 解构槽位等都可用 `_` 占位，且同一作用域可出现多个 `_`。Java 21 预览（JEP 443）→ 22 转正。实测（JDK 25）：

```java
map.forEach((_, v) -> IO.print(v + " "));
try { Integer.parseInt("x"); } catch (NumberFormatException _) { ... }
```

```text
1 2 
catch 中不需要异常对象时可用 _
```

## Java 23（2024-09）

主题：无重磅转正，一批 21–22 预览项继续迭代，ZGC 完成分代化第二步。

- **ZGC 分代模式成为默认**（JEP 474）：`-XX:+UseZGC` 即分代，非分代退为 `-XX:-ZGenerational` 可选。
- **Markdown 文档注释转正**（JEP 467）：`///` 行注释写 Javadoc，直接支持 Markdown 语法，告别 HTML 标签与 `{@code}` 堆砌。
- **弃用 `sun.misc.Unsafe` 的内存访问方法**（JEP 471）：FFM 已转正，Unsafe 进入退役流程。
- 预览/孵化：模块导入声明预览（JEP 476）；基本类型模式匹配预览（JEP 455）；隐式声明类与实例 main 第三次预览（JEP 477）；构造器 `super` 前语句第二次预览（JEP 482）；Scoped Values 第三次预览（JEP 481）；结构化并发第三次预览（JEP 480）；Stream Gatherers 第二次预览（JEP 473）；Class-File API 第二次预览（JEP 466）；Vector API 第八次孵化（JEP 469）。
- **String Templates 撤回**：21/22 两轮预览后安全模型无法收敛，23 起不再携带——见 [02-Java21](./02-Java21.md)。

## Java 24（2025-03）

主题：**清障**——虚拟线程的 pinning 缺口补上，Security Manager 二十年的历史包袱落地成灰。

### 虚拟线程同步不再钉住载体（JEP 491）

Java 21 的遗留缺口：虚拟线程在 `synchronized` 块内阻塞时，载体线程被**钉住**（pin）一起挂起，高竞争下吞吐塌陷。JEP 491 重写 monitor 进入路径，虚拟线程在 `synchronized` 内阻塞时照样卸载载体，pinning 只剩 JNI/外部函数调用一种情形。对使用者的意义：不必再为虚拟线程把 `synchronized` 改写成 `ReentrantLock`。

### 其余转正

- **Stream Gatherers**（JEP 485，22/23 两次预览）：`Stream.gather(...)` 给流管道补上自定义中间操作的扩展点，`Gatherers` 内置 `windowFixed`、`fold` 等。实测（JDK 25）：

```java
Stream.of(1, 2, 3, 4, 5, 6).gather(Gatherers.windowFixed(2)).toList();
Stream.of(1, 2, 3, 4).gather(Gatherers.fold(() -> 0, Integer::sum)).toList();
```

```text
windowFixed(2): [[1, 2], [3, 4], [5, 6]]
fold(sum): [10]
```

- **Class-File API**（JEP 484，22/23 两次预览）：`java.lang.classfile` 包提供解析/生成 class 文件的标准 API，ASM 的官方替代。
- **Security Manager 永久禁用**（JEP 486）：17 弃用（JEP 411）后，24 起 `SecurityManager` 无法启用，运行时直接拒绝——agent 时代的沙箱模型正式终结。
- **ZGC 删除非分代模式**（JEP 490）：分代成为唯一形态（本机 JDK 25 验证：`PrintFlagsFinal` 中已无 `ZGenerational` 开关）。

### 实验与预览

- **Compact Object Headers 实验**（JEP 450）：对象头从 96–128 位压到 64 位，堆占用与缓存行利用率同时受益。实验身份，`-XX:+UnlockExperimentalVMOptions -XX:+UseCompactObjectHeaders` 开启。25 转正（JEP 519，见下节）。
- **分代 Shenandoah 实验**（JEP 404）。
- 预览：灵活构造器体第三次（JEP 492）、模块导入第二次（JEP 494）、简化源文件与实例 main 第四次（JEP 495）、基本类型模式匹配第二次（JEP 488）、Scoped Values 第四次（JEP 487）、结构化并发第四次（JEP 499）；Vector API 第九次孵化（JEP 489）；KDF API 预览（JEP 478）。
- 平台/安全：AOT 类加载与链接（JEP 483，CDS 的扩展，缩短启动）；准备限制 JNI（JEP 472）；后量子密码 ML-KEM/ML-DSA（JEP 496/497）。

## Java 25（2025-09，LTS）

主题：**第二次收口**。21–24 预览线集中转正，语言入门门槛与并发模型同时改写。

### 简化源文件与实例 main 转正（JEP 512）

`public class` + `public static void main(String[])` 的仪式全部可选：单文件程序可直接写 `void main()`，编译器把它包进隐式声明的类；新增 `java.lang.IO` 提供 `println` 等免 `System.out` 的入门 IO。演进线：21 预览（JEP 445）→ 22/23/24 三次预览（463/477/495）→ 25 转正。约束一处：实例 main 要求类有无参构造器供启动器实例化。

### 模块导入声明转正（JEP 511）

`import module java.base;` 一句导入整个模块的导出包，入门代码不再需要逐类 import。Java 23 预览（JEP 476）→ 24 二次预览（494）→ 25 转正。

两者实测（JDK 25 原生，`java Hello25.java` 直接运行）：

```java
import module java.base;

void main() {
    List<String> xs = List.of("module", "import", "main");
    xs.forEach(IO::println);
}
```

```text
module
import
main
```

### 灵活构造器体转正（JEP 513）

构造器允许在 `super(...)` 之前写语句：参数校验、失败快速抛出不再需要塞进静态辅助方法。演进线：22 预览（JEP 447）→ 23/24 两次预览（482/492）→ 25 转正。实测（JDK 25 原生）：

```java
PositivePoint(int x, int y) {
    if (x < 0 || y < 0) throw new IllegalArgumentException("坐标必须非负: " + x + "," + y);
    super();
    this.x = x; this.y = y;
}
```

```text
super(...) 之前的校验通过
[3, 4]
负坐标被拒: 坐标必须非负: -1,0
```

### Scoped Values 转正（JEP 506）

20 孵化（JEP 429）→ 21–24 四次预览（446/464/481/487）→ 25 转正。与 21 预览版相比 API 有调整（`getWhere` 系列移除，保留 `where(...).run(...)`/`call(...)`、`orElse`、`isBound`）。实测（JDK 25 原生）：

```java
ScopedValue<String> user = ScopedValue.newInstance();
ScopedValue.where(user, "user-42").run(() -> IO.println("作用域内: " + user.get()));
```

```text
作用域内: user-42
作用域外 isBound=false
orElse 兜底: 匿名
```

### Compact Object Headers 转正（JEP 519）

24 的实验项（JEP 450）转正为产品特性：对象头压至 64 位。25 中默认关闭，`-XX:+UseCompactObjectHeaders` 开启（不再需要解锁实验选项）。实测（JDK 25）：

```text
$ java -XX:+UseCompactObjectHeaders -XX:+PrintFlagsFinal -version
     bool UseCompactObjectHeaders = true   {product lp64_product} {command line}
```

`{product}` 标记确认它已是正式产品开关而非实验项。

### 分代 Shenandoah 转正（JEP 521）

Shenandoah（12 实验 JEP 189 → 15 生产 JEP 379）获得分代模式：24 实验（JEP 404）→ 25 转正。实测（JDK 25，Temurin 内置 Shenandoah）：

```text
$ java -XX:+UseShenandoahGC -XX:ShenandoahGCMode=generational -Xlog:gc+init -version
[0.022s][info][gc,init] Version: 25.0.4.1+1-LTS (release)
```

至此三款低延迟 GC（ZGC、Shenandoah、G1 的并发标记）中两款完成分代化。

### 仍在闸口内

- **基本类型模式匹配第三次预览**（JEP 507）：`instanceof`/`switch` 直接匹配 `int`、`long` 等。注意——25 中它**没有转正**，仍是预览（26 中为第四次预览 JEP 530）。实测（`--enable-preview`）：

```java
switch (o) {
    case int i when i > 100 -> IO.println("大整数 " + i);
    case int i -> IO.println("int 匹配: " + i * 2);
    ...
}
```

```text
int 匹配: 84
instanceof int: 42
```

- **结构化并发第五次预览**（JEP 505）：API 定型为 `StructuredTaskScope.open()` + Joiner 组合。实测（`--enable-preview`）：两个 fork 子任务 `join()` 后取结果，输出 `任务A / 任务B`。
- **Stable Values 预览**（JEP 502）：不可变但延迟初始化的值，让 JVM 像对待 `final` 常量一样做常量折叠，剑指启动性能。
- **PEM 编码加密对象预览**（JEP 470）。
