# 监控与链路追踪

## 本质断言

可观测性（Observability）的本质是通过日志（Logs）、指标（Metrics）和链路追踪（Traces）三个维度重建分布式系统的内部状态，其中日志记录离散事件，指标记录聚合数值，链路追踪记录请求在服务间的调用路径，三者结合实现问题定位的全覆盖。

## 指标体系

### RED 指标模型

<pre>
微服务 RED 指标：
Rate（请求率）：每秒请求数（QPS）
Errors（错误率）：每秒错误数 / 总请求数
Duration（延迟）：请求响应时间分布（P50/P90/P99）
</pre>

### USE 指标模型

<pre>
资源 USE 指标：
Utilization（利用率）：CPU/内存 使用百分比
Saturation（饱和度）：队列长度、CPU 排队数
Errors（错误率）：错误计数
    ↓
适用于：CPU、内存、磁盘、连接池等基础设施监控
</pre>

## Micrometer 指标

### Counter / Gauge / Timer

<pre>
Meter 类型选择：
Counter：计数（请求数、订单数）→ 只能递增
Gauge：当前值（队列长度、缓存大小）→ 可增可减
Timer：耗时（P99 延迟、吞吐量）→ 记录时间分布
</pre>

### Timer 的百分位数

<pre>
Timer.record() 执行闭包代码并记录耗时：
publishPercentiles(0.5, 0.95, 0.99) → 记录 P50/P95/P99
publishPercentileHistogram() → 记录直方图（用于 Prometheus histogram_quantile）
</pre>

## 链路追踪

### Trace / Span 模型

<pre>
Trace = 请求全流程（一个 Trace 包含多个 Span）
Span = 单个服务/操作单元
    ↓
TraceId：整个请求链路的唯一标识
SpanId：当前 Span 的唯一标识
ParentSpanId：调用方 Span 的 SpanId（形成调用树）
</pre>

### Trace 传播机制

<pre>
跨服务 Trace 传播：
服务 A（SpanId=S1）→ 调用服务 B
    ↓
在 HTTP Header 中注入：X-B3-TraceId / X-B3-SpanId
    ↓
服务 B 接收到请求，提取 Header，创建新 Span（ParentId=S1）
    ↓
TraceId 保持不变，SpanId 重新生成
</pre>

## 可观测性三大支柱

### 日志 vs 指标 vs 链路追踪

<pre>
三大支柱对比：
日志：离散事件流 → "发生了什么"
指标：聚合数值 → "表现如何"
链路追踪：请求路径 → "在哪一步出了问题"
    ↓
日志搜索（ELK）：查具体事件
指标看板（Grafana）：看趋势告警
链路追踪（Zipkin/Jaeger）：定位慢请求/错误
</pre>

### 三者结合的价值

<pre>
问题定位工作流：
1. 告警触发（指标）→ 某服务 P99 超阈值
2. 查看该时间点的错误日志（日志）
3. 放大镜：选择慢 Trace → 看到哪个 Span 耗时最长（链路追踪）
4. 定位：数据库查询慢 → 优化索引
</pre>

## 健康检查

### 存活探针 vs 就绪探针

<pre>
Kubernetes 探针区分：
livenessProbe 失败 → kubelet 重启容器
readinessProbe 失败 → 从 Endpoints 摘除（停止接收流量）
    ↓
应用启动中 → readinessProbe 失败 → 不接收流量直到就绪
应用僵死 → livenessProbe 失败 → kubelet 杀死重启
</pre>

```java
private final Counter orderCounter;
public OrderService(MeterRegistry registry) {
    this.orderCounter = Counter.builder("orders.created")
        .tag("service", "order-service")
        .register(registry);
}
public void createOrder() { orderCounter.increment(); }
```

```java
private final Timer paymentTimer;
public PaymentService(MeterRegistry registry) {
    this.paymentTimer = Timer.builder("payment.process")
        .publishPercentiles(0.5, 0.95, 0.99)
        .register(registry);
}
public PaymentResult processPayment(PaymentRequest request) {
    return paymentTimer.record(() -> doProcessPayment(request));
}
```
