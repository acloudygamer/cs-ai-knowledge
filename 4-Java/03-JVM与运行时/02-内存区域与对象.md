# 内存区域与对象

> 前置：[01-字节码与类加载](./01-字节码与类加载.md) · 后续：[03-垃圾回收](./03-垃圾回收.md)

> **版本基准**：Java 21 stable / Java 25 latest。示例实测环境：Temurin JDK 25.0.4.1（Windows x64），`--release 21` 验证。

JVM 运行时的内存按"谁的、活多久"切成几块职责不同的区域：线程私有的 **PC 寄存器**（当前字节码位置）与 **Java 栈**（每方法调用一帧，存局部变量表与操作数栈）；线程共享的**堆**（一切 `new` 出来的对象）与**方法区**（类元数据、运行时常量池、静态字段，HotSpot 自 Java 8 起用本地内存的 Metaspace 实现）。堆的自动回收归 [03-垃圾回收](./03-垃圾回收.md) 管，本篇看布局与对象本身的物理形态。

## 区域连接：一次方法调用路过谁

```text
PC 寄存器: 当前线程执行到 add() 的第 2 条字节码
Java 栈:   [main 帧][add 帧] ← add 帧里有局部变量表(a,b)和操作数栈
堆:        main 里 new 的对象、字符串常量
方法区:    BytecodeDemo 的类元数据、add 方法的字节码
```

栈帧大小编译期确定（见 [01-字节码与类加载](./01-字节码与类加载.md)），因此栈深度可预算；堆对象的生命期不可预算——它由可达性决定，这正是两块区域管理策略分裂（栈帧随方法返回自动弹掉，堆对象等 GC）的根源。

栈与堆的物理分界实测可见：递归一个帧占一槽的方法，默认栈深度 22826 帧、`-Xss256k` 下 3495 帧（Temurin 25.0.4.1 实测，见 [01-字节码与类加载](./01-字节码与类加载.md)）；而堆的对象想活到多大都行，直到 `-Xmx` 顶死。

## 对象头：每个对象的 12 字节税

HotSpot 里每个堆对象以**对象头**开头：Mark Word（8 字节，存哈希码、GC 分代年龄、锁状态——锁升级时这 8 字节被复用为不同的位域编码）加**压缩类指针**（4 字节，指向方法区的类元数据）。64 位 JVM 默认开压缩指针（`-XX:+UseCompressedOops`，PrintFlagsFinal 实测为 `true`）：堆不超过 32 GB 时引用和类指针都压成 4 字节，这是 Java 对象内存账里最重要的默认值。

对象本体之后按 8 字节对齐填充（`ObjectAlignmentInBytes = 8`）。实测推导（Temurin 25.0.4.1，分配 100 万个 `new Object()`，GC 后量堆差）：

```text
100 万个 new Object() 占 20731400 字节，平均每个 20.7 字节
```

拆账：对象本体 16 字节（8 Mark Word + 4 类指针 + 4 对齐填充），加上 `Object[]` 数组里每槽 4 字节的压缩引用，合计 20 字节/元素，与实测吻合。再看一个有字段的对象：解释模式（`-Xint`，关闭 JIT 的分配消除）下 1 亿个 `Point{int x, int y}` 分配 2,400,000,000 字节——每个 24 字节 = 12 头 + 8（两个 int）+ 4 对齐填充。空对象 16 字节、两个 int 字段 24 字节，这就是"Java 对象比 C 结构体胖"的具体出处。

## 分配路径：TLAB 与大对象

线程分配对象默认走 **TLAB**（Thread-Local Allocation Buffer，线程本地分配缓冲）：每个线程在 Eden 里预领一块私有区域，对象分配就是在这块区域里移动一次指针——无锁、纳秒级。TLAB 耗尽才同步领新块。超过 Region 一半大小的巨型对象（G1 里叫 Humongous，Region 默认 1~32 MB 按堆大小自适应）绕开 Eden 直接占整 Region，这也是 GC 日志里 `G1 Humongous Allocation` 的来源（实测见 [03-垃圾回收](./03-垃圾回收.md)）。

JIT 介入后还有一条更快的路径：逃逸分析判定对象不逃出方法时，整个对象被标量替换、根本不在堆上分配——实测同一循环解释模式分配 2.29 GB、C2 编译后分配 0 字节（见 [06-性能调优](./06-性能调优.md)）。

## 栈上溢出与堆上溢出：两种 OOM 的分工

- `StackOverflowError`：栈帧耗尽，典型于无终止递归；`-Xss` 调栈大小。
- `OutOfMemoryError: Java heap space`：存活对象超过 `-Xmx`。
- `OutOfMemoryError: Metaspace`：类元数据超限，典型于大量动态生成类（代理、字节码工具）。
- `OutOfMemoryError: unable to create native thread`：线程栈是本地内存，不归堆管——这是"堆还有空间却起不了线程"的原因。
