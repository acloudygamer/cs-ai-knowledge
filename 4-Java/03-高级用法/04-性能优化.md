# 性能优化

> Java性能优化的核心思维是"减少浪费"——减少对象创建减少GC压力，减少锁竞争减少调度开销，减少虚调用减少解释执行开销，将热点代码从解释执行提升到编译执行。

## 代码层面优化

### 减少对象创建

```java
String s = "hello";
for (int i = 0; i < 1000; i++) {
}
```

```java
StringBuilder sb = new StringBuilder();
for (String item : items) {
    sb.append(item).append(",");
}
```

### 避免自动装箱

```java
IntList list = new IntArrayList();
for (int i = 0; i < 10000; i++) {
    list.add(i);
}
```

```java
int sum = list.stream().mapToInt(Integer::intValue).sum();
```

### 合理使用集合

```java
ArrayList<String> list = new ArrayList<>(1000);
HashMap<String, Object> map = new HashMap<>(expectedSize * 2);
```

## 并发优化

### 线程池配置

```java
ExecutorService executor = new ThreadPoolExecutor(
    corePoolSize, maxPoolSize, keepAliveTime, TimeUnit.SECONDS,
    new LinkedBlockingQueue<>(queueSize)

```

### 减少锁竞争

```java
ConcurrentHashMap<String, Object> map = new ConcurrentHashMap<>();
map.put(key, value);
```

```java
private AtomicInteger count = new AtomicInteger(0);
count.incrementAndGet();
```

## JVM调优

**JVM调优的本质是在内存容量（GC频率）、停顿时间（用户体验）和吞吐量（业务吞吐）三者之间取得项目相关的最优平衡——没有通用最优解。**

### 堆内存与GC选择

<pre>
小堆（<4GB）     ──> Serial / G1（停顿可接受）
大堆（>8GB）低延迟 ──> ZGC（<1ms停顿）
大堆（>8GB）     ──> G1 / ZGC
吞吐量优先        ──> Parallel GC
</pre>

```bash
-Xms2g -Xmx2g
-XX:+UseG1GC
-XX:MaxGCPauseMillis=200
```

### 常用参数

| 参数 | 说明 |
|------|------|
| -Xms / -Xmx | 初始/最大堆 |
| -Xmn | 新生代大小 |
| -XX:+UseG1GC | 使用G1收集器 |
| -XX:MaxGCPauseMillis | 目标最大停顿时间 |
| -Xlog:gc* | 输出GC日志 |

## 优化清单

**代码层面**
- 避免循环中创建对象
- 使用StringBuilder而非String拼接
- 避免不必要的自动装箱
- 合理使用集合初始容量

**并发层面**
- 使用线程池而非直接创建线程
- 减小锁粒度
- 使用并发容器替代同步容器
- 使用volatile/原子类

**JVM层面**
- 合理设置堆大小
- 选择合适的垃圾收集器
- 启用GC日志
- 定期检查内存泄漏

**数据库层面**
- 使用批量操作
- 使用连接池
- 合理使用索引
