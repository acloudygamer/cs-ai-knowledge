# 虚拟线程深度

## 概述

虚拟线程（Virtual Threads）是 Java 21 引入的革命性特性，旨在解决传统线程的高成本问题。它是 JVM 管理的轻量级线程，与操作系统线程（平台线程）有着本质区别。

## 核心概念

### 线程模型对比

**传统线程模型（1:1映射）**：
- 应用代码 → JVM Thread → OS Thread (内核线程)
- 每个线程占用约 1MB 堆栈
- 线程切换涉及 OS 上下文切换，开销大

**虚拟线程模型（M:N映射）**：
- 应用代码 → JVM Virtual Thread → Carrier Thread (载体线程)
- 虚拟线程堆栈按需增长（通常几 KB）
- 阻塞操作挂起虚拟线程，载体线程可服务其他 VT

### 载体线程（Carrier Thread）

虚拟线程运行在载体线程上。当虚拟线程遇到阻塞操作（如 `sleep`、`Lock.lock()`、I/O 操作）时，它会从载体线程上**挂起**，载体线程可以运行其他虚拟线程。

**挂起 vs 阻塞**：

| 特性 | 阻塞（传统） | 挂起（虚拟线程） |
|------|-------------|-----------------|
| 线程状态 | BLOCKED | WAITING（但线程本身被释放）|
| OS 资源 | 占用 OS 线程 | 不占用（只占用内存）|
| 其他任务 | 无法运行 | 载体线程可运行其他 VT |

### 连续栈（Continuations）

虚拟线程基于**连续栈**（Continuations）实现。当虚拟线程挂起时，它的堆栈被**拆分为片段**（stack chunk），保存在堆内存中而不是 OS 线程栈中。

```
挂起前:
[Frame 1: main] → [Frame 2: methodA] → [Frame 3: blockingCall]
                   载体线程占用

挂起后（堆内存中）:
载体线程: 可运行其他虚拟线程

堆内存中的片段:
[Frame 1: main] → [Frame 2: methodA] → [Frame 3: blockingCall]
（作为对象保存，等待恢复）
```

## 内存模型

平台线程固定 1MB 堆栈（默认），而虚拟线程按需增长，初始约 1-2KB，最大可达数 MB。这使得创建大量虚拟线程成为可能——10 万并发虚拟线程只需数 GB 内存，而同样数量的平台线程需要约 100 GB。

## 性能对比

| 指标 | 平台线程 (200) | 虚拟线程 (10万) |
|------|---------------|----------------|
| 创建 10 万线程耗时 | 数秒+（可能 OOM）| < 1 秒 |
| 内存占用（空闲时）| ~100 GB | ~几 GB |
| 上下文切换开销 | 高（OS 切换）| 低（JVM 内部）|
| 适合场景 | 计算密集 | IO 密集 |

### 参考样例

```java
// 基准测试场景：10 万个并发 HTTP 请求
public class VirtualThreadBenchmark {

    // 平台线程池（固定 200 线程）
    ExecutorService platformExecutor = Executors.newFixedThreadPool(200);

    // 虚拟线程（每个任务一个 VT）
    ExecutorService virtualExecutor = Executors.newVirtualThreadPerTaskExecutor();

    public void testPlatformThreads() throws InterruptedException {
        long start = System.currentTimeMillis();
        List<Future<?>> futures = IntStream.range(0, 100_000)
            .mapToObj(i -> platformExecutor.submit(() -> fetchUrl(i)))
            .toList();

        for (var f : futures) f.get();  // 等待全部完成
        System.out.println("Platform: " + (System.currentTimeMillis() - start) + "ms");
    }

    public void testVirtualThreads() throws InterruptedException {
        long start = System.currentTimeMillis();
        List<Future<?>> futures = IntStream.range(0, 100_000)
            .mapToObj(i -> virtualExecutor.submit(() -> fetchUrl(i)))
            .toList();

        for (var f : futures) f.get();
        System.out.println("Virtual: " + (System.currentTimeMillis() - start) + "ms");
    }
}
```

## 深度用法

### 虚拟线程与 synchronized

虚拟线程中的 synchronized 要小心使用。如果虚拟线程长时间持有内置锁，会阻塞载体线程。

**解决方案**：使用 ReentrantLock（支持中断）或 CAS 无锁操作。

```java
// 风险示例：长时持有 synchronized 会"拖累"载体线程
public class BadExample {
    private final Object lock = new Object();
    private int count;

    public void increment() {
        synchronized (lock) {  // 风险：长时持有会"拖累"载体线程
            count++;
        }
    }
}

// 推荐方式：ReentrantLock 或 CAS
public class GoodExample {
    private final ReentrantLock lock = new ReentrantLock();
    private int count;

    public void increment() {
        lock.lock();
        try {
            count++;
        } finally {
            lock.unlock();
        }
    }

    // 或使用 CAS（无锁）
    private final AtomicInteger atomicCount = new AtomicInteger();
    public void increment() {
        atomicCount.incrementAndGet();
    }
}
```

### 虚拟线程与 ThreadLocal

ThreadLocal 在虚拟线程中的问题：100 万虚拟线程，每个都有自己的 ThreadLocal 副本，导致内存爆炸。

**解决方案**：使用 ScopedValue（Java 22）或共享的 ConcurrentHashMap。

```java
// 问题：100 万虚拟线程 = 100 万个 String 对象副本
ThreadLocal<String> context = new ThreadLocal<>();
context.set("user-123");

// 解决方案 1：ScopedValue（Java 22）- 详见现代Java特性
static final ScopedValue<String> USER_ID = ScopedValue.newInstance();

// 解决方案 2：共享的 ConcurrentHashMap（虚拟线程 ID → 值）
ConcurrentHashMap<Long, String> contextMap = new ConcurrentHashMap<>();

Thread.ofVirtual().start(() -> {
    contextMap.put(Thread.currentThread().getId(), "user-123");
});

// 解决方案 3：InheritableThreadLocal（慎用，可能导致内存泄漏）
InheritableThreadLocal<String> inherited = new InheritableThreadLocal<>();
```

### 虚拟线程与调度

虚拟线程使用 ForkJoinPool 作为默认调度器。不要将虚拟线程池化——错误做法是用固定大小线程池提交虚拟线程任务，这会限制并发能力。

```java
// 自定义调度器
ExecutorService customScheduler = Executors.newFixedThreadPool(10);  // 10 个载体线程

Thread.ofVirtual()
    .start(() -> { /* 仍然在 customScheduler 中运行 */ });

// 错误做法：池化虚拟线程
ExecutorService badPool = Executors.newFixedThreadPool(100);  // 100 个平台线程
for (int i = 0; i < 10_000; i++) {
    badPool.submit(() -> blockingIo());  // 仍然只有 100 个载体线程
}

// 正确做法：每任务一个虚拟线程
try (ExecutorService vtExecutor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        vtExecutor.submit(() -> blockingIo());
    }
}
```

## 结构化并发（Structured Concurrency）

结构化并发是虚拟线程的"黄金搭档"，将多个并发任务视为单一工作单元。核心价值在于**生命周期统一管理**——任务在同一个作用域内创建、完成、失败，无需手动管理 ExecutorService。

### 解决的问题

传统 Future 的问题：异常处理分散，容易忘记关闭 executor。

### 参考样例

```java
// 问题：使用传统 Future 的痛苦
public List<User> getUsers(List<Long> ids) throws ExecutionException, InterruptedException {
    ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor();
    try {
        List<Future<User>> futures = ids.stream()
            .map(id -> executor.submit(() -> fetchUser(id)))
            .toList();

        List<User> users = new ArrayList<>();
        for (Future<User> future : futures) {
            try {
                users.add(future.get());
            } catch (ExecutionException e) {
                logger.error("Failed to fetch user", e);
            }
        }
        return users;
    } finally {
        executor.shutdown();  // 容易忘记！
    }
}
```

```java
// 使用 StructuredTaskScope
import java.util.concurrent.StructuredTaskScope;

public List<User> getUsers(List<Long> ids) throws InterruptedException {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        // fork 创建子任务
        List<Future<User>> futures = ids.stream()
            .map(id -> scope.fork(() -> fetchUser(id)))
            .toList();

        scope.join();  // 等待所有任务完成

        // 统一异常处理
        scope.throwIfFailed();

        // 收集结果
        return futures.stream()
            .map(StructuredTaskScope.Subtask::get)
            .toList();
    }
}
```

### StructuredTaskScope 两种模式

**ShutdownOnSuccess<T>**：任意一个任务成功即返回第一个成功结果，适用于"尽早返回"场景。

**ShutdownOnFailure**：所有任务失败才结束，适用于"全部成功才能继续"场景。

```java
// 模式 1：ShutdownOnSuccess<T>
public Optional<User> findFirstAvailable(List<Long> ids) throws InterruptedException {
    try (var scope = new StructuredTaskScope.ShutdownOnSuccess<User>()) {
        ids.forEach(id ->
            scope.fork(() -> checkUserAvailable(id)));

        scope.join();  // 等待任意一个成功

        return scope.result();  // 获取第一个成功结果
    }
}

// 模式 2：ShutdownOnFailure
public void processAll(List<Task> tasks) throws InterruptedException {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        tasks.forEach(task ->
            scope.fork(() -> process(task)));

        scope.join();
        scope.throwIfFailed();  // 如果有任何一个失败，抛出异常
    }
}
```

### 实际应用：并行获取订单详情

```java
@Service
public class OrderService {

    public record OrderDetails(
        Order order,
        User user,
        List<Item> items,
        Payment payment
    ) {}

    public OrderDetails getOrderDetails(Long orderId) throws InterruptedException {
        try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {

            Future<Order> orderFuture = scope.fork(() ->
                orderRepository.findById(orderId));

            Future<User> userFuture = scope.fork(() ->
                userService.findByOrderId(orderId));

            Future<List<Item>> itemsFuture = scope.fork(() ->
                itemService.findItemsByOrderId(orderId));

            Future<Payment> paymentFuture = scope.fork(() ->
                paymentService.getPayment(orderId));

            scope.join();  // 等待所有并行任务

            return new OrderDetails(
                orderFuture.resultNow(),
                userFuture.resultNow(),
                itemsFuture.resultNow(),
                paymentFuture.resultNow()
            );
        }
    }
}
```

## 最佳实践

### 何时使用虚拟线程

```
推荐使用虚拟线程的场景:
- HTTP 客户端（高并发 HTTP 请求）
- 数据库访问（大量并发查询）
- 文件 I/O（大量并发文件操作）
- 消息队列消费者（大量并发消费）
- Web 服务器（处理大量并发请求）
- 爬虫（大量并发抓取任务）

不推荐使用的场景:
- 计算密集型任务（CPU-bound）
- 需要长时间持有 CPU 的任务
- 需要精确控制线程数量的场景
```

### 虚拟线程编程规范

```java
// 规范 1：不要池化虚拟线程
// 错误
ExecutorService bad = Executors.newFixedThreadPool(100);
for (int i = 0; i < 1000; i++) {
    bad.submit(() -> doIo());
}

// 正确
try (ExecutorService good = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 1000; i++) {
        good.submit(() -> doIo());
    }
}

// 规范 2：避免 ThreadLocal 滥用
// 使用 ScopedValue 替代
static final ScopedValue<String> REQUEST_ID = ScopedValue.newInstance();

// 规范 3：谨慎使用 synchronized
// 优先使用 ReentrantLock 或并发类

// 规范 4：不要在线程池中提交虚拟线程任务
ExecutorService executor = Executors.newFixedThreadPool(10);
executor.submit(() -> {
    // 不要在这里创建大量虚拟线程
    Thread.ofVirtual().start(() -> {});
});
```

## 常见问题

### Q: 虚拟线程和线程池哪个好？

A: 它们解决不同问题。**线程池**复用线程，**虚拟线程**让创建大量线程变得廉价。虚拟线程本身不需要池化（每个任务一个线程）。在 IO 密集场景，虚拟线程 + `newVirtualThreadPerTaskExecutor()` 是最佳实践。

### Q: 虚拟线程会影响现有代码吗？

A: 大部分代码**无需修改**即可在虚拟线程中运行。但需要注意：
- 过度使用 ThreadLocal 可能导致内存问题
- synchronized 块中的长时操作可能影响载体线程
- ThreadPoolExecutor 不适合运行虚拟线程

### Q: 虚拟线程和 Project Loom 是什么关系？

A: Project Loom 是虚拟线程的项目代号，经过多年开发，虚拟线程在 Java 21 中正式发布。除虚拟线程外，Loom 还带来了结构化并发（StructuredTaskScope）和 ScopedValue。

### Q: 虚拟线程的载体线程数量是多少？

A: 默认等于 CPU 核心数。可以通过系统属性调整：

```java
// 设置载体线程数量
System.setProperty("jdk.virtualThreadScheduler.parallelism", "10");
System.setProperty("jdk.virtualThreadScheduler.maxPoolSize", "100");
```

## 总结

虚拟线程是 Java 并发模型的重大革新，它让"每任务一线程"成为可能，显著简化了高并发应用的开发。

```
核心要点:
1. 虚拟线程 = JVM 管理的轻量级线程
2. 阻塞操作会挂起虚拟线程，释放载体线程
3. 适合 IO 密集型，不适合 CPU 密集型
4. 不要池化虚拟线程
5. 配合 ScopedValue 使用，而非 ThreadLocal
6. 结合 StructuredTaskScope 实现结构化并发
```

> Scoped Values 详解请参考：[现代Java特性 - Scoped Values](./07-现代Java特性.md#scoped-values)
