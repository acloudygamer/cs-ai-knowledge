# 虚拟线程深度

## 概述

虚拟线程（Virtual Threads）是 Java 21 引入的革命性特性，旨在解决传统线程的高成本问题。它是 JVM 管理的轻量级线程，与操作系统线程（平台线程）有着本质区别。

## 核心概念

### 线程模型对比

传统线程模型采用 1:1 映射：应用代码经 JVM Thread 直达 OS Thread，每个线程占用约 1MB 堆栈，上下文切换涉及 OS 层面，开销大。

虚拟线程模型采用 M:N 映射：应用代码经 JVM Virtual Thread 到 Carrier Thread（载体线程），虚拟线程堆栈按需增长（通常几 KB），阻塞操作挂起虚拟线程，载体线程可服务其他 VT。

### 载体线程（Carrier Thread）

虚拟线程运行在载体线程上。当虚拟线程遇到阻塞操作（如 sleep、Lock.lock()、I/O 操作）时，它会从载体线程上挂起，载体线程可以运行其他虚拟线程。

挂起与阻塞的本质区别在于：阻塞时线程状态为 BLOCKED 且占用 OS 线程资源；挂起时虚拟线程处于 WAITING 但不占用 OS 线程，只占用内存。

| 特性 | 阻塞（传统） | 挂起（虚拟线程） |
|------|-------------|-----------------|
| 线程状态 | BLOCKED | WAITING（但线程本身被释放）|
| OS 资源 | 占用 OS 线程 | 不占用（只占用内存）|
| 其他任务 | 无法运行 | 载体线程可运行其他 VT |

### 连续栈（Continuations）

虚拟线程基于连续栈实现。当虚拟线程挂起时，它的堆栈被拆分为片段（stack chunk），保存在堆内存中而不是 OS 线程栈中。恢复时再将片段重新组装。

```
挂起前:
[Frame 1: main] → [Frame 2: methodA] → [Frame 3: blockingCall]
                   载体线程占用

挂起后（堆内存中）:
载体线程: 可运行其他虚拟线程

堆内存中的片段:
[Frame 1: main] → [Frame 2: methodA] → [Frame 3: blockingCall]
（作为对象保存，等待恢复）
```

## 内存模型

平台线程固定 1MB 堆栈（默认），而虚拟线程按需增长，初始约 1-2KB，最大可达数 MB。这使得创建大量虚拟线程成为可能：10 万并发虚拟线程只需数 GB 内存，而同样数量的平台线程需要约 100 GB。

## 性能对比

| 指标 | 平台线程 (200) | 虚拟线程 (10万) |
|------|---------------|----------------|
| 创建 10 万线程耗时 | 数秒+（可能 OOM）| < 1 秒 |
| 内存占用（空闲时）| ~100 GB | ~几 GB |
| 上下文切换开销 | 高（OS 切换）| 低（JVM 内部）|
| 适合场景 | 计算密集 | IO 密集 |

## 创建方式

### Thread.ofVirtual()

```java
// 1. Thread.ofVirtual()
Thread virtual = Thread.ofVirtual()
    .name("my-vt-")
    .start(() -> System.out.println("Hello"));

// 2. Executors.newVirtualThreadPerTaskExecutor()
try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
    Future<String> future = executor.submit(() -> "Hello");
    String result = future.get();
}

// 3. 自定义 ThreadFactory
ThreadFactory factory = Thread.ofVirtual()
    .name("vt-pool-", 0)
    .factory();

ExecutorService executor = Executors.newThreadPerTaskExecutor(factory);

// 4. VirtualThread.startVirtualThread() - 快速创建
Thread.startVirtualThread(() -> System.out.println("Quick start"));
```

## 深度用法

### 虚拟线程与 synchronized

虚拟线程中长时间持有 synchronized 内置锁会阻塞载体线程。解决方案是使用 ReentrantLock（支持中断）或 CAS 无锁操作。

```java
// 风险示例：长时持有 synchronized 会"拖累"载体线程
public class BadExample {
    private final Object lock = new Object();
    private int count;

    public void increment() {
        synchronized (lock) {
            count++;
        }
    }
}

// 推荐方式：ReentrantLock 或 CAS
public class GoodExample {
    private final ReentrantLock lock = new ReentrantLock();
    private int count;

    public void increment() {
        lock.lock();
        try {
            count++;
        } finally {
            lock.unlock();
        }
    }

    private final AtomicInteger atomicCount = new AtomicInteger();
    public void increment() {
        atomicCount.incrementAndGet();
    }
}
```

### 虚拟线程与 ThreadLocal

ThreadLocal 在虚拟线程中的问题：100 万虚拟线程，每个都有自己的 ThreadLocal 副本，导致内存爆炸。解决方案是使用 ScopedValue（Java 22）或共享的 ConcurrentHashMap。

```java
// 问题：100 万虚拟线程 = 100 万个 String 对象副本
ThreadLocal<String> context = new ThreadLocal<>();
context.set("user-123");

// 解决方案 1：ScopedValue（Java 22）
static final ScopedValue<String> USER_ID = ScopedValue.newInstance();

// 解决方案 2：共享的 ConcurrentHashMap
ConcurrentHashMap<Long, String> contextMap = new ConcurrentHashMap<>();

Thread.ofVirtual().start(() -> {
    contextMap.put(Thread.currentThread().getId(), "user-123");
});

// 解决方案 3：InheritableThreadLocal（慎用）
InheritableThreadLocal<String> inherited = new InheritableThreadLocal<>();
```

### 虚拟线程与调度

虚拟线程使用 ForkJoinPool 作为默认调度器。不要将虚拟线程池化——错误做法是用固定大小线程池提交虚拟线程任务，这会限制并发能力。

```java
// 错误做法：池化虚拟线程
ExecutorService badPool = Executors.newFixedThreadPool(100);
for (int i = 0; i < 10_000; i++) {
    badPool.submit(() -> blockingIo());
}

// 正确做法：每任务一个虚拟线程
try (ExecutorService vtExecutor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        vtExecutor.submit(() -> blockingIo());
    }
}
```

## 结构化并发（Structured Concurrency）

结构化并发是虚拟线程的"黄金搭档"，将多个并发任务视为单一工作单元。核心价值在于生命周期统一管理：任务在同一个作用域内创建、完成、失败，无需手动管理 ExecutorService。

### StructuredTaskScope 两种模式

ShutdownOnSuccess<T> 适用于任意一个任务成功即返回第一个成功结果；ShutdownOnFailure 适用于所有任务失败才结束的场景。

```java
// 模式 1：ShutdownOnSuccess<T>
public Optional<User> findFirstAvailable(List<Long> ids) throws InterruptedException {
    try (var scope = new StructuredTaskScope.ShutdownOnSuccess<User>()) {
        ids.forEach(id ->
            scope.fork(() -> checkUserAvailable(id)));

        scope.join();
        return scope.result();
    }
}

// 模式 2：ShutdownOnFailure
public void processAll(List<Task> tasks) throws InterruptedException {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        tasks.forEach(task ->
            scope.fork(() -> process(task)));

        scope.join();
        scope.throwIfFailed();
    }
}
```

### 实际应用：并行获取订单详情

```java
@Service
public class OrderService {

    public record OrderDetails(
        Order order,
        User user,
        List<Item> items,
        Payment payment
    ) {}

    public OrderDetails getOrderDetails(Long orderId) throws InterruptedException {
        try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {

            Future<Order> orderFuture = scope.fork(() ->
                orderRepository.findById(orderId));

            Future<User> userFuture = scope.fork(() ->
                userService.findByOrderId(orderId));

            Future<List<Item>> itemsFuture = scope.fork(() ->
                itemService.findItemsByOrderId(orderId));

            Future<Payment> paymentFuture = scope.fork(() ->
                paymentService.getPayment(orderId));

            scope.join();

            return new OrderDetails(
                orderFuture.resultNow(),
                userFuture.resultNow(),
                itemsFuture.resultNow(),
                paymentFuture.resultNow()
            );
        }
    }
}
```

## 框架集成

### Spring Boot 集成

Spring 6.1+ 支持虚拟线程，需要正确配置线程池。

```yaml
# application.yml - Spring 6.1+
spring:
  task:
    execution:
      pool:
        core-size: 0
        max-size: 250000
      name-prefix: "spring-vt-"
    virtual:
      enabled: true
```

```java
// 配置虚拟线程 Executor
@Configuration
public class VirtualThreadConfig {
    @Bean("virtualThreadExecutor")
    public ExecutorService virtualThreadExecutor() {
        return Executors.newVirtualThreadPerTaskExecutor();
    }
}

@Async("virtualThreadExecutor")
public CompletableFuture<User> fetchUserAsync(Long id) {
    return CompletableFuture.supplyAsync(() -> userRepository.findById(id));
}
```

虚拟线程挂起时不占连接，载体线程可服务其他虚拟线程，所以连接池可以更小。

### HTTP 客户端集成

```java
// Java 11 HttpClient + 虚拟线程
HttpClient client = HttpClient.newBuilder()
    .executor(Executors.newVirtualThreadPerTaskExecutor())
    .build();

HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/data"))
    .build();

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List<HttpRequest> requests = IntStream.range(0, 10_000)
        .mapToObj(i -> HttpRequest.newBuilder()
            .uri(URI.create("https://api.example.com/data/" + i))
            .build())
        .toList();

    List<CompletableFuture<HttpResponse<String>>> futures = requests.stream()
        .map(req -> client.sendAsync(req, HttpResponse.BodyHandlers.ofString()))
        .toList();

    CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
}
```

## 最佳实践

### 何时使用虚拟线程

推荐场景：HTTP 客户端（高并发 HTTP 请求）、数据库访问（大量并发查询）、文件 I/O（大量并发文件操作）、消息队列消费者（大量并发消费）、Web 服务器（处理大量并发请求）、爬虫（大量并发抓取任务）。

不推荐场景：计算密集型任务（CPU-bound）、需要长时间持有 CPU 的任务、需要精确控制线程数量的场景。

### 虚拟线程编程规范

不要池化虚拟线程，使用 ScopedValue 替代 ThreadLocal，谨慎使用 synchronized，优先使用 ReentrantLock 或并发类，不要在线程池中提交虚拟线程任务。

```java
// 规范 1：不要池化虚拟线程
try (ExecutorService good = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 1000; i++) {
        good.submit(() -> doIo());
    }
}

// 规范 2：使用 ScopedValue 替代 ThreadLocal
static final ScopedValue<String> REQUEST_ID = ScopedValue.newInstance();

// 规范 3：谨慎使用 synchronized
// 优先使用 ReentrantLock 或并发类
```

## 常见问题

### Q: 虚拟线程和线程池哪个好？

它们解决不同问题。线程池复用线程，虚拟线程让创建大量线程变得廉价。虚拟线程本身不需要池化（每个任务一个线程）。在 IO 密集场景，虚拟线程 + newVirtualThreadPerTaskExecutor() 是最佳实践。

### Q: 虚拟线程会影响现有代码吗？

大部分代码无需修改即可在虚拟线程中运行。但需要注意：过度使用 ThreadLocal 可能导致内存问题；synchronized 块中的长时操作可能影响载体线程；ThreadPoolExecutor 不适合运行虚拟线程。

### Q: 虚拟线程的载体线程数量是多少？

默认等于 CPU 核心数。可以通过系统属性调整：

```java
System.setProperty("jdk.virtualThreadScheduler.parallelism", "10");
System.setProperty("jdk.virtualThreadScheduler.maxPoolSize", "100");
```
