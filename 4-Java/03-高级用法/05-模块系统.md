# 模块系统（Java Platform Module System）

## 概述

Java 9 引入模块系统（JPMS），提供更精细的依赖管理和封装。

### 解决的问题

1. **JAR 地狱**：多版本依赖冲突
2. **隐藏实现**：只暴露必要的 public 类
3. **明确依赖**：显式声明模块依赖
4. **可重复构建**：确定性构建

## 模块定义

### module-info.java

```java
// 位于 src/main/java/module-info.java
module com.example.myapp {
    // 导出（公开）包
    exports com.example.api;
    exports com.example.service;

    // 依赖其他模块
    requires java.base;  // 可省略，隐式依赖
    requires com.example.library;

    // 动态模块（可选依赖）
    requires static org.slf4j;  // 编译时需要，运行时可选

    // 服务提供（ServiceLoader）
    provides com.example.api.Service with com.example.impl.ServiceImpl;

    // 服务消费
    uses com.example.api.Service;
}
```

## 模块声明

### exports（导出）

```java
// 导出包，使其对其他模块可见
module com.example.myapp {
    exports com.example.publicapi;
    exports com.example.utils;
}

// 未导出的包对其他模块不可见
module com.example.internal {
    // com.example.internal 包不可见
}
```

### requires（依赖）

```java
module com.example.app {
    // 必需依赖
    requires java.base;           // 默认依赖，可省略
    requires java.sql;
    requires com.google.guava;

    // 可选依赖（编译时需要，运行时不需要）
    requires static org.slf4j.api;
}
```

### opens（开放）

```java
module com.example.myapp {
    // 反射访问（仅运行时）
    opens com.example.config;
    opens com.example.internal to com.example.tool;

    // 深度反射（允许 opens 的模块再打开）
    opens com.example.deep to com.example.testing;
}
```

## 服务加载

### ServiceLoader 机制

```java
// 定义服务接口
package com.example.plugin;

public interface Plugin {
    String getName();
    void execute();
}

// 实现服务
package com.example.impl;

public class MyPlugin implements Plugin {
    @Override
    public String getName() {
        return "MyPlugin";
    }

    @Override
    public void execute() {
        System.out.println("Plugin executing");
    }
}

// 模块声明
module com.example.impl {
    exports com.example.plugin;
    provides com.example.plugin.Plugin with com.example.impl.MyPlugin;
}

// 加载服务
module com.example.app {
    requires com.example.plugin;
    uses com.example.plugin.Plugin;  // 声明使用
}

// 运行时加载
ServiceLoader<Plugin> loader = ServiceLoader.load(Plugin.class);
for (Plugin plugin : loader) {
    System.out.println(plugin.getName());
    plugin.execute();
}
```

## 模块路径

### 编译和运行

```bash
# 编译模块
javac -d out --module-source-path src \
    $(find src -name "*.java")

# 运行模块化应用
java --module-path out \
    --module com.example.app/com.example.app.Main

# 创建模块化 JAR
jar --create \
    --file=lib/com.example.app.jar \
    --main-class=com.example.app.Main \
    -C out/com.example.app .
```

### 打包为 JMOD

```bash
# 创建 JMOD（包含原生代码和配置）
jar --create \
    --file=lib/com.example.app.jmod \
    --module-version=1.0 \
    -C out/com.example.app .
```

## 迁移到模块化

### 自动模块

非模块化 JAR 放入模块路径后变为自动模块：

```java
// 自动模块名 = JAR 名（.jar 扩展名）
// 自动导出所有包
// 隐式 requires 所有其他自动模块
```

### 未命名模块

类路径上的代码属于未命名模块：

```java
// 未命名模块可以访问所有自动模块
// 自动模块可以访问未命名模块的 public 类型
```

### 命令行选项

```bash
# 添加模块
--add-modules <module>[,<module>...]

# 添加导出
--add-exports <module>/<package>=<target-module>

# 添加 opens
--add-opens <module>/<package>=<target-module>

# 示例
java --add-opens java.base/java.lang=ALL-UNNAMED \
     --add-exports java.base/java.util=com.example.app \
     --add-modules java.sql \
     --module-path out \
     --module com.example.app/com.example.app.Main
```

## 反射与模块化

### 为什么需要 opens

```java
// Spring、Hibernate 等框架需要反射
// 但模块系统默认禁止深度反射

// 解决方案1：运行时打开
opens package to target;

// 解决方案2：命令行打开
--add-opens module/package=ALL-UNNAMED
```

### Spring Boot 3.x 兼容

```xml
<!-- maven-compiler-plugin 配置 -->
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <compilerArgs>
            <arg>--add-opens</arg>
            <arg>java.base/java.lang=ALL-UNNAMED</arg>
            <!-- 更多 opens -->
        </compilerArgs>
    </configuration>
</plugin>
```

## 常见问题

### 类路径 vs 模块路径

| 特性 | 类路径 (ClassPath) | 模块路径 (Module Path) |
|------|-------------------|----------------------|
| 依赖管理 | 隐式 | 显式 requires |
| 封装 | 无 | exports 限制 |
| 多版本 | 可能冲突 | 自动模块隔离 |
| 可发现性 | MANIFEST | module-info.java |

### 模块名冲突

```java
// 同一模块不能声明两次
// 同一包不能属于多个模块
module com.example.app {
    // 错误：包 com.example.shared 已由另一模块导出
    exports com.example.shared;
}
```

### require vs require static

```java
// require：运行时也需要
module com.example.app {
    requires guava;  // 运行和编译都需要
}

// require static：仅编译时需要
module com.example.app {
    requires static guava;  // 仅编译时需要，运行时可选
}
```

## 检测模块化

```java
// 检查是否模块化
public static boolean isModular() {
    return ModuleLayer.boot().modules().stream()
        .anyMatch(m -> m.getName().equals("com.example.myapp"));
}

// 获取当前模块
Module current = MyClass.class.getModule();
System.out.println(current.getName());
```
