# 模块系统（JPMS）

> Java 9引入的模块系统（JPMS）的本质是**显式封装边界**——通过module-info.java声明模块名、导出包、依赖关系，让JAR从"一堆class文件的集合"升级为"有明确接口和依赖声明的计算单元"。

## 核心价值

**JPMS解决四个问题：JAR地狱（多版本共存）、实现隐藏（只暴露必要public类）、隐式依赖显式化（requires替代classpath无序）、可重复构建（模块图确保确定性）。**

<pre>
module com.example.app {
    exports com.example.api;        ──> 其他模块可见
    requires com.example.library;   ──> 显式依赖
    provides X with Y;              ──> 服务提供
    uses X;                         ──> 服务消费
}
</pre>

## module-info.java结构

```java
module com.example.myapp {
    exports com.example.api;
    exports com.example.service;
    requires java.base;
    requires com.example.library;
    requires static org.slf4j;
    provides com.example.api.Service with com.example.impl.ServiceImpl;
    uses com.example.api.Service;
}
```

## 模块声明

### exports（导出）

**exports声明哪些包对其他模块可见。未导出的包对其他模块完全不可见——即使类型是public，其他模块也无法访问。**

```java
module com.example.myapp {
    exports com.example.publicapi;
}
```

### requires（依赖）

**requires声明模块依赖。java.base是隐式依赖，所有模块都自动依赖它。**

```java
module com.example.app {
    requires java.sql;
    requires com.google.guava;
    requires static org.slf4j.api;
}
```

### opens（开放）

**opens允许运行时反射访问模块内部。默认只允许浅层反射（访问public成员），opens to允许指定模块深度反射。**

```java
module com.example.myapp {
    opens com.example.config;
    opens com.example.internal to com.example.tool;
}
```

## 服务加载（ServiceLoader）

**ServiceLoader是JDK的插件机制——服务接口模块exports接口，实现模块provides接口，使用模块uses接口。运行时通过ServiceLoader.load()动态发现并加载实现。**

```java
ServiceLoader<Plugin> loader = ServiceLoader.load(Plugin.class);
for (Plugin plugin : loader) {
    plugin.execute();
}
```

## 模块路径与编译运行

```bash
javac -d out --module-source-path src $(find src -name "*.java")
java --module-path out --module com.example.app/com.example.app.Main
```

```bash
jar --create --file=lib/com.example.app.jar --main-class=com.example.app.Main -C out/com.example.app .
```

## 常见JDK模块

| 模块 | 说明 |
|------|------|
| java.base | 核心API（默认） |
| java.sql | JDBC |
| java.xml | XML处理 |
| java.management | JMX |
| java.httpclient | HTTP Client |
| jdk.internal.jvmstat | JVM监控（仅JDK内部） |

## 反射与模块化

**Spring、Hibernate等框架依赖反射，但模块系统默认禁止深度反射。opens或--add-opens在运行时开放模块。**

```bash
--add-opens module/package=ALL-UNNAMED
--add-exports module/package=target-module
```

## 迁移策略

### 自动模块

非模块化JAR放入模块路径后成为自动模块：模块名=JAR名，自动导出所有包，隐式requires所有其他自动模块。

### 未命名模块

类路径上的代码属于未命名模块，可以访问所有自动模块。

## 类路径 vs 模块路径

| 特性 | 类路径 | 模块路径 |
|------|--------|---------|
| 依赖管理 | 隐式 | 显式requires |
| 封装 | 无 | exports限制 |
| 多版本 | 可能冲突 | 自动模块隔离 |
| 可发现性 | MANIFEST | module-info.java |

## 检测模块化

```java
public static boolean isModular() {
    return ModuleLayer.boot().modules().stream()
        .anyMatch(m -> m.getName().equals("com.example.myapp"));
}
```

```java
Module current = MyClass.class.getModule();
```
