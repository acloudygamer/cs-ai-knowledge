# 并发与异步

> Java并发体系是围绕"资源稀缺性"这一核心矛盾展开的：CPU核数有限但任务无限，线程是抢占资源的最小单位，锁/原子操作/CAS是解决资源争用的手段，而异步是让阻塞任务释放线程以承接更多工作的策略。

## 线程基础

**线程是CPU调度的最小单位，其本质是一个函数调用栈与CPU寄存器状态的组合——创建成本约1MB栈空间，切换成本约数千CPU周期。**

### 线程状态机

<pre>
NEW ──start()──> RUNNABLE ──synchronized获取锁失败──> BLOCKED
  │                  ↑                                 │
  │                  └── synchronized释放 ──────────────┘
  │                                                   (wait/notify)
  │                  (sleep/yield) ──────> TIMED_WAITING
  │                  (Object.wait) ──────> WAITING
  │                              └── ──> RUNNABLE
  └─run()结束──> TERMINATED
</pre>

| 状态 | 触发条件 |
|------|---------|
| NEW | Thread对象创建但未start |
| RUNNABLE | start()调用后（可能正在CPU上运行） |
| BLOCKED | 等待获取synchronized内置锁 |
| WAITING | Object.wait / Thread.join / LockSupport.park |
| TIMED_WAITING | Thread.sleep / Object.wait(timeout) / Thread.join(timeout) |
| TERMINATED | run()执行完毕 |

### 创建线程

```java
Thread thread = new Thread(() -> System.out.println("Running"));
thread.start();
```

```java
Thread virtual = Thread.ofVirtual().name("my-vt-").start(() -> System.out.println("Running"));
```

## ExecutorService

**线程池是将"创建线程的高昂成本"摊销到"多次任务复用同一线程"的管理模式——核心参数是核心线程数、最大线程数、队列容量、拒绝策略的组合。**

<pre>
提交任务 ──> 是否 < 核心线程数？ ──是──> 创建核心线程执行
           │
           └─否──> 队列不满？ ──是──> 放入队列等待
                  │
                  └─否──> 是否 < 最大线程数？ ──是──> 创建临时线程
                         │
                         └─否──> 执行拒绝策略
</pre>

### 线程池类型

```java
ExecutorService fixed = Executors.newFixedThreadPool(4);
ExecutorService single = Executors.newSingleThreadExecutor();
ExecutorService cached = Executors.newCachedThreadPool();
ScheduledExecutorService scheduled = Executors.newScheduledThreadPool(4);
```

### 任务提交与获取结果

```java
Future<Integer> future = executor.submit(() -> {
    return 42;
});
Integer result = future.get();
```

### 批量提交

```java
List<Callable<Task>> tasks = List.of(
    () -> processA(),
    () -> processB(),
    () -> processC()
);
List<Future<Task>> futures = executor.invokeAll(tasks);
```

## CompletableFuture

**CompletableFuture是Java 8引入的异步编程模型，其本质是将"命令式代码"转换为"声明式数据流"——每个操作都返回新的CompletableFuture，形成链式调用。**

### 创建与链式操作

```java
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> "Hello")
    .thenApply(s -> s + " World")
    .thenApply(String::toUpperCase);
```

### 组合与等待

```java
CompletableFuture.allOf(f1, f2, f3).join();
CompletableFuture.anyOf(f1, f2, f3).join();
```

## Concurrent Collections

**并发集合的内部通过分段锁（Segmentation）或CAS操作替代全局锁，在保证线程安全的同时允许更高并发——代价是部分操作（如size()）可能不精确或需要额外同步。**

### 常用并发集合

```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
map.putIfAbsent("b", 2);
map.computeIfAbsent("c", k -> compute(k));
```

### 生产者-消费者模式

```java
BlockingQueue<Integer> queue = new LinkedBlockingQueue<>(10);
queue.put(i);
Integer value = queue.take();
```

## Synchronizers

**同步器是通过共同状态（计数器、信号量、屏障）协调多个线程执行节奏的工具，其内部实现依赖AQS（AbstractQueuedSynchronizer）框架。**

### CountDownLatch

```java
CountDownLatch latch = new CountDownLatch(3);
latch.countDown();
latch.await();
```

### Semaphore

```java
Semaphore semaphore = new Semaphore(3);
semaphore.acquire();
accessResource();
semaphore.release();
```

### CyclicBarrier

```java
CyclicBarrier barrier = new CyclicBarrier(3, () -> System.out.println("All done"));
barrier.await();
```

## 原子类

**原子类的本质是通过CAS（Compare-And-Swap）指令实现非阻塞的线程安全操作——在硬件层面保证"读取-修改-写入"三步的原子性，无需锁定。**

```java
AtomicInteger counter = new AtomicInteger(0);
counter.incrementAndGet();
counter.updateAndGet(x -> x * 2);
```

## ThreadLocal

**ThreadLocal为每个线程提供独立变量副本，解决跨线程隔离问题——但虚拟线程场景下，每个VT都有独立副本，百万VT即百万副本，造成内存爆炸。Java 22引入的ScopedValue替代方案在载体线程中共享数据。**

```java
ThreadLocal<String> threadLocal = new ThreadLocal<>();
threadLocal.set("value");
String value = threadLocal.get();
threadLocal.remove();
```

## 最佳实践

```java
ExecutorService executor = Executors.newFixedThreadPool(4);
CompletableFuture.supplyAsync(() -> doStuff(), executor);
ConcurrentHashMap<> map = new ConcurrentHashMap<>();
AtomicInteger counter = new AtomicInteger(0);
```
