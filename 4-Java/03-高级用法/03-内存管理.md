# 内存管理

> JVM内存管理的本质是分代假设——大多数对象朝生夕灭，少数存活久远。基于此假设的垃圾回收器用不同策略处理不同代龄对象，在吞吐量和停顿时间之间取得平衡。

## JVM内存结构

<pre>
堆 (Heap)                    方法区 (Method Area)
├─ Eden区                    ├─ 类信息
├─ Survivor S0/S1            ├─ 运行时常量池
└─ Old Generation             └─ 静态变量

栈 (Stack)                   程序计数器 (PC)
├─ 栈帧 x N                  └─ 当前执行字节码行号
└─ 每个线程独有               (无GC)

本地方法栈 (Native)
└─ native方法调用
</pre>

- **堆**：对象实例、数组，GC主要管理区域
- **栈**：方法调用、局部变量，线程私有，随线程消亡而释放
- **方法区**：类元数据、JIT编译产物（JDK 8前为永久代，JDK 8+为Metaspace）
- **程序计数器**：记录当前线程执行位置，线程切换后恢复
- **本地方法栈**：JNI调用native方法使用的栈

## 对象头结构（Object Header）

**对象头包含Mark Word（对象自身状态）和Klass Pointer（指向类元数据的指针），在64位JVM中占用12字节（未开启指针压缩时为16字节含对齐填充）。**

### Mark Word状态位

$$
\text{Mark Word} = \begin{cases}
\text{hashCode}(25) + \text{age}(4) + \text{biased\_lock}(1) + \text{lock}(2) & \text{无锁} \\
\text{ThreadID}(54) + \text{Epoch}(2) + \text{age}(4) + \text{biased\_lock}(1) + \text{lock}(2) & \text{偏向锁} \\
\text{ptr\_to\_lock\_record}(62) + \text{lock}(2) & \text{轻量级锁} \\
\text{ptr\_to\_monitor}(62) + \text{lock}(2) & \text{重量级锁} \\
\text{unused}(62) + \text{lock}(2) & \text{GC标记}
\end{cases}
$$

查看对象布局：

```java
import org.openjdk.jol.info.ClassLayout;
Object obj = new Object();
System.out.println(ClassLayout.parseInstance(obj).toPrintable());
```

## G1收集器（Garbage First）

**G1将堆划分为大小相等的Region（1MB-32MB），每次回收计算各Region的回收价值（回收获得的空间+回收所需时间），优先回收价值最高的Region——这使其能控制停顿时间上限。**

### G1 GC阶段

<pre>
Young GC ── Eden满 ──> 回收年轻代Region ──> Survivor填充
        │
        └─> Mixed GC（老年代比例超过阈值）
                    │
                    └─> Old GC（回收失败/空间不足）
</pre>

| 收集器 | 线程模型 | 内存整理 | 停顿时间 | 算法 |
|--------|---------|---------|---------|------|
| Serial | 单线程 | 整堆复制 | 长 | 复制 |
| Parallel | 多线程 | 整堆复制 | 中等 | 复制 |
| CMS | 并发 | 多数整理 | 短 | 标记-清除 |
| G1 | 并发 | Region局部 | 可控 | 标记-整理+复制 |
| ZGC | 并发 | 并发整理 | <1ms | 标记-整理 |
| Shenandoah | 并发 | 并发整理 | 低 | 标记-整理 |

## ZGC（Z Garbage Collector）

**ZGC的核心机制是着色指针（Colored Pointers）——将对象状态编码在64位指针的未使用高位上，GC时通过读屏障（Load Barrier）拦截引用读取，在读取对象引用时即时获取GC状态，无需停顿。**

着色指针的GC标记阶段全程并发，因为引用读取时由硬件和读屏障协同处理，对象状态在指针自身中携带。

## Shenandoah

**Shenandoah使用Brooks Pointer（转发指针）实现并发整理——在对象头添加一个指针域，存活对象移动后更新此指针，旧位置的指针指向新位置。GC时通过检查此指针判断对象是否已移动。**

与ZGC的区别：Shenandoah不依赖着色指针技术，对象头有额外指针开销；且与引用更新并发进行时需要更复杂的同步。

## GC基础

GC Roots（根集合）包括：栈帧中的本地变量表引用的对象、方法区中静态属性引用的对象、方法区中常量引用的对象、JNI引用对象。

对象引用判断：
- **引用计数**：无法处理循环引用，已废弃
- **可达性分析**：从GC Roots向下搜索，不可达则回收

### 分代假设与GC策略

$$
\text{Eden区回收死亡率} \approx 90\%-99\%
$$

大多数对象在Young GC时即可回收，只有少部分进入老年代——这是分代收集的理论基础。

### GC算法

- **标记-清除**：产生内存碎片，适合存活对象多、回收少的场景
- **复制**：无碎片，但浪费一半空间，适合存活对象少、回收多的Young区
- **标记-整理**：无碎片，整理有停顿，适合老年代

## 收集器演进

| 收集器 | 引入版本 | 定位 |
|--------|---------|------|
| Serial | Java 1.3 | 小型应用，单线程 |
| Parallel（Throughput） | Java 1.5 | 吞吐量优先 |
| CMS | Java 7 | 低停顿（已移除） |
| G1 | Java 9 | 平衡吞吐与停顿，默认 |
| ZGC | Java 11 | 超大堆低延迟（<1ms） |
| Shenandoah | Java 12 | 低延迟，OpenJDK实现 |

## JVM内存参数

```bash
-Xms256m -Xmx256m
-XX:+UseG1GC
-XX:+UseZGC
```

Object.finalize() 在 Java 9 已废弃，不应使用。
