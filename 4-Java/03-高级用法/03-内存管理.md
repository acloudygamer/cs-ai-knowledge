# 内存管理

## JVM 内存结构

- 堆（Heap）：对象实例、数组，GC 管理的主要区域
- 栈（Stack）：方法调用、局部变量，每个线程独有
- 方法区（Method Area）：类信息、常量池、静态变量（JDK 8+ 元空间替代）
- 程序计数器（PC Register）：当前线程执行的字节码行号
- 本地方法栈（Native Method Stack）：native 方法调用

## 对象头结构（Object Header）

HotSpot JVM 中，每个对象由三部分组成：

```
+------------------+---------------------+-------------------+
|   Mark Word (64bit) |   Klass Pointer    |   Instance Data   |
+------------------+---------------------+-------------------+
       8 bytes              4 bytes             variable
```

### Mark Word（64位 JVM）

| 状态 | 存储内容（51bit） |
|------|-------------------|
| 无锁 | 对象 hashCode(25bit) + 分代年龄(4bit) + 偏向锁标志(1bit) + 锁标志(2bit) |
| 偏向锁 | Thread ID(54bit) + Epoch(2bit) + 分代年龄(4bit) + 偏向锁标志(1bit) + 锁标志(2bit) |
| 轻量级锁 | 指向栈中锁记录的指针(62bit) + 锁标志(2bit) |
| 重量级锁 | 指向 Monitor 的指针(62bit) + 锁标志(2bit) |
| GC 标记 | 空(62bit) + 锁标志(2bit) |

### Klass Pointer

指向方法区中的类元数据（Klass 对象），开启压缩指针（-XX:+UseCompressedClassPtr）后为 4 字节，否则 8 字节。

### 查看对象布局

```java
// 添加 JVM 参数：-XX:+PrintGC -XX:+PrintGCDetails -XX:+UseSerialGC
// 使用 jol-core 查看对象布局
import org.openjdk.jol.info.ClassLayout;

public class ObjectLayoutDemo {
    public static void main(String[] args) {
        Object obj = new Object();
        System.out.println(ClassLayout.parseInstance(obj).toPrintable());

        // 带 padding 和 reference
        class Simple { int a; }
        System.out.println(ClassLayout.parseInstance(new Simple()).toPrintable());
    }
}
```

## G1 收集器（Garbage First）

G1（JDK 9+ 默认）是面向服务器的收集器，将堆划分为多个大小相等的 Region。

### Region 结构

```
堆内存 = 2048 个 Region（默认）
每个 Region 大小 = 堆大小 / 2048（1MB~32MB）

Region 类型：
┌─────────────────────────────────────────────┐
│  Eden Region (S) │  Survivor Region (S)      │
├─────────────────────────────────────────────┤
│              Old Region (O)                  │
├─────────────────────────────────────────────┤
│            Humongous Region (H)             │  // 大对象（> 50% Region）
└─────────────────────────────────────────────┘
```

### G1 GC 阶段

```
Young GC → Mixed GC → Old GC（Full GC 兜底）
   ↓            ↓            ↓
eden空间不足   老年代比例    疏散失败/
              达到阈值       内存分配失败
```

1. **Young GC**：回收年轻代（Eden + Survivor）
2. **Mixed GC**：回收年轻代 + 部分老年代
3. **Old GC/Fallback**：G1 无法回收时触发（单线程标记-整理）

### G1 关键参数

```bash
# 堆设置
-Xms4g -Xmx4g                   # 初始/最大堆
-XX:+UseG1GC                     # 使用 G1

# Region 大小（需为 2 的幂）
-XX:G1HeapRegionSize=2m          # 默认自动计算

# 阈值
-XX:MaxGCPauseMillis=200         # 最大停顿时间目标
-XX:G1NewSizePercent=5           # 年轻代最小比例
-XX:G1MaxNewSizePercent=60      # 年轻代最大比例
-XX:InitiatingHeapOccupancyPercent=45  # 触发 Mixed GC 的老年代比例
```

### G1 vs Previous Collectors

| 特性 | Serial | Parallel | CMS | G1 |
|------|--------|----------|-----|-----|
| 线程模型 | 单线程 | 多线程 | 并发 | 并发 |
| 内存整理 | 整堆 | 整堆 | 多数整理 | Region 局部 |
| 停顿时间 | 长 | 中等 | 短 | 可控 |
| 吞吐量 | 低 | 高 | 中 | 中高 |

## ZGC（Z Garbage Collector）

ZGC 是一种可扩展的低延迟垃圾收集器，目标停顿时间 < 1ms（但吞吐量会降低）。

### 核心特性

1. **并发执行**：GC 的大部分阶段与应用线程并发
2. **着色指针**：使用 Colored Pointers 标记对象状态
3. **读屏障**：在读操作时轻量处理

### 着色指针（Colored Pointers）

ZGC 使用 64 位指针中的 4 位作为着色位：

```
64位指针
├─ 保留位(18bit) ─┼─ 着色位(4bit) ─┼─ 地址位(42bit) ─┤
                  M0, M1, remapped, marked
```

- **Marked0/Marked1**：标记阶段使用（双色标记交替）
- **Remapped**：对象已移动到新位置
- **Finalizable**：对象仅通过终结器可达

### ZGC 阶段

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  Pause  │→→→│  Concurrent   │→→→│  Pause  │→→→│  Concurrent   │
│  Start  │   │  Mark        │   │  Relink │   │  Relocate     │
└─────────┘   └─────────────┘   └─────────┘   └──────────────┘
              STW极短            STW极短        （可并发）
```

### ZGC 配置

```bash
# 启用 ZGC
-XX:+UseZGC -Xmx16g

# 设置 GC 线程数
-XX:ConcGCThreads=8

# 启用大页面支持（提升性能）
-XX:+UseLargePages -XX:LargePageSizeInBytes=2m
```

## Shenandoah

Shenandoah 是 Red Hat 开发的低延迟 GC，与 ZGC 类似但实现不同。

### 核心特性

1. **并发压缩**：不 STW 就能移动对象
2. ** Brooks Pointer**：每个对象有一个转发指针
3. **读屏障**：所有读操作需检查对象是否已移动

### Brooks Pointer

```
Original Object          After Move
┌─────────────┐         ┌─────────────┐
│ Forwarding  │────────→│  New Location│
│  Pointer    │         └─────────────┘
├─────────────┤
│  Object     │
│   Data      │
└─────────────┘
```

### Shenandoah vs ZGC

| 特性 | ZGC | Shenandoah |
|------|-----|------------|
| 着色指针 | 使用 | 不使用（Brooks Pointer） |
| 堆容量 | 16TB+ | < 128GB（受限于指针） |
| 性能 | 略优 | 相当 |
| JDK 支持 | JDK 11+ | JDK 8u9+, JDK 11+ |

### Shenandoah 配置

```bash
# 启用 Shenandoah
-XX:+UseShenandoahGC -Xmx16g

# 调优停顿时间
-XX:ShenandoahGapBufferSize=2m
```

## 垃圾回收（GC）算法

### 引用计数（已废弃）

- 每个对象有个计数器，引用+1，失效-1
- 无法处理循环引用（导致内存泄漏）
- Python 曾使用，JVM 从未采用

### 标记-清除（Mark-Sweep）

```
1. 标记阶段：从 GC Roots 遍历，标记可达对象
2. 清除阶段：扫描堆，回收未标记对象

缺点：产生内存碎片，效率不高
```

### 复制（Copying）

```
将内存分为两半，每次只用一半
存活对象复制到另一半，然后整体清除

优点：速度快，无碎片
缺点：浪费一半内存
```

### 标记-整理（Mark-Compact）

```
1. 标记可达对象
2. 整理：将存活对象向一端移动
3. 清除：清理边界外的对象

结合了标记-清除和复制的优点
```

### 分代收集（Generational）

根据对象生命周期采用不同策略：

```
年轻代（Eden + S0 + S1）
  ↓ 轻量级 GC（复制算法）
老年代（Old Generation）
  ↓ 重 GC（标记-整理）
```

### GC Roots（根集合）

可达对象的起点：
- 栈帧中的本地变量
- 静态变量（类）
- 活跃的 Java 线程
- JNI 引用

## GC 收集器演进

- Serial：单线程，适用于小型应用
- Parallel（Throughput）：多线程，关注吞吐量
- CMS：并发标记清除，关注停顿时间（JDK 14 移除）
- G1（JDK 9+ 默认）：分Region，平衡吞吐和停顿
- ZGC（JDK 11+）：超大堆低延迟
- Shenandoah（JDK 12+）：低延迟

```java
// JVM 内存参数示例
// -Xms256m -Xmx512m     初始堆和最大堆
// -Xmn128m              新生代大小
// -XX:+UseG1GC          使用 G1 收集器
// -XX:+UseZGC           使用 ZGC 收集器
// -XX:+UseShenandoahGC  使用 Shenandoah 收集器
// 注意：Object.finalize() 在 Java 9 已废弃，勿再使用

// 对象创建和引用
public class MemoryDemo {
    public static void main(String[] args) {
        // 对象创建在堆上
        String str = new String("Hello");  // str 在栈上，对象在堆上

        // 引用传递
        String s = str;
        s = null;  // str 仍然引用着那个字符串对象

        // 手动建议 GC（不保证立即执行）
        System.gc();
    }
}
```
