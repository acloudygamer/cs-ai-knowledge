# 正则表达式

> 前置：[03-日期时间](./03-日期时间.md) · 后续：[03-JVM与运行时](../03-JVM与运行时/01-字节码与类加载.md)

> **版本基准**：Java 21 stable / Java 25 latest。示例实测环境：Temurin JDK 25.0.4.1（Windows），`--release 21` 验证。

Java 正则（`java.util.regex`）是一台**带记忆回溯的 NFA（非确定性有限自动机）引擎**：`Pattern.compile` 把正则文本编译成一棵匹配节点（`Node`）链表——`CharProperty` 消费字符、`Branch` 试分支、`Loop` 管重复，节点间靠 `next` 指针衔接；`Matcher` 在输入串上以深度优先搜索走这棵树，走不通就回到最近的分叉点换条路（回溯）。选 NFA 回溯而非 DFA（确定性有限自动机）路线，是因为反向引用、环视这些特性在自动机模型里不存在——表达力换最坏情况时间。

## 机制：Pattern 与 Matcher 的分工

两个类的职责切分对应"编译一次、匹配多次"的用法：

- `Pattern` 是编译产物，不可变、线程安全，应在循环外定义成 `static final` 复用——`String.matches()` 每次调用都重新编译，热路径上是浪费。
- `Matcher` 是一次匹配会话，持有输入串引用、当前位置、捕获组边界，**有状态、不可共享**。

实测（命名捕获组，`--release 21`）：

```text
Pattern.compile("(?<y>\\d{4})-(?<m>\\d{2})-(?<d>\\d{2})") 匹配 "2024-04-13"
命名捕获组: y=2024 m=04 d=13
```

## 回溯：从指数灾难到 JDK 9 的修复

贪婪量词（`*`、`+`）先吞掉尽量多，匹配失败再逐个吐回。当**嵌套量词的划分方案数随输入指数增长**且输入最终无法匹配时，引擎被迫穷举所有方案——这就是灾难性回溯（catastrophic backtracking），也是 ReDoS 漏洞的来源。

但"Java 正则会指数爆炸"这句话在今天需要加版本限定。实测（Temurin 25.0.4.1，输入为 n 个 `a` 加一个不匹配的 `!`）：

```text
(a+)+$        n=31:  104 us   ← 经典教科书炸弹，线性
(a|a)+$       n=31:   35 us   ← 分支重叠炸弹，线性
(\w+\s?)*$    n=31:  177 us   ← ReDoS 典型案例，线性
```

原因是 JDK 9 的一次引擎修复（OpenJDK core-libs，2016 年 3 月 RFR，对应 JDK-6693451 等历史报告）：对**顶层贪婪分组循环**（`(…)*`、`(…)+` 这类 `Loop` 节点），引擎把"从位置 i 出发、已经穷尽失败"的 i 记进一个 `IntHashSet`，回溯回到同一位置时直接判负，不再重试。JDK 25 的 `Pattern.java` 源码里注释写得很直白：

```text
// Let's check if we have already tried and failed
// at this starting position "i" in the past.
// If yes, then just return false without trying
// again, to stop the exponential backtracking.
```

**但修复有边界**：缓存只挂在顶层循环节点上，嵌套在内层分组的指数路径不受影响。实测同一份 RFR 里明确"仍无法解决"的嵌套模式 `(h|h|ih(((i|a|c|c|a|i|i|j|b|a|i|b|a|a|j))+h)ahbfhba|c|i)*`，输入用 RFR 原串（403 个 `h`/`c`/`i` 混合字符）时运行超过 60 秒无结果（超时强杀）——注意这类炸弹对输入敏感，纯 `'a'` 重复串反而毫秒级返回，复现时输入不能随意替换。灾难性回溯在现代 JDK 里仍然真实存在，只是门槛从"常见写法"抬高到了"嵌套写法"。

防御手段仍是老三样，全部实测可验：

1. **独占量词** `*+`、`++`：吞掉后不吐回、不回溯。`(a++)+$` 对百万字符输入 8.8 ms 返回失败。
2. **固化分组** `(?>…)`：组内匹配完成后删除组内全部回溯点。
3. **改写模式**：把嵌套量词 `(a+)+` 摊平成 `a+`，语义等价时优先改写——这是治本。

另有一条工程纪律：对外部输入跑正则就是暴露在 ReDoS 攻击面下，复杂模式应配合超时隔离（如单独线程加 future 超时取消）或改用线性时间引擎。

## 语法要点速查

| 特性 | 写法 | 说明 |
|---|---|---|
| 贪婪/勉强/独占 | `.*` / `.*?` / `.*+` | 匹配策略：尽量多 / 尽量少 / 多且不回溯 |
| 捕获组 | `(...)`、`(?<name>...)` | `Matcher.group(n)`/`group("name")` 读取 |
| 非捕获组 | `(?:...)` | 只分组不记录 |
| 固化分组 | `(?>...)` | 组内不留回溯点 |
| 环视 | `(?=X)`、`(?!X)`、`(?<=X)`、`(?<!X)` | 零宽断言，不消费字符 |
| 反向引用 | `\1`（模式内）、`$1`（替换串） | 回溯模型特有的能力，DFA 引擎给不了 |
| 内联标志 | `(?i)`、`(?s)`、`(?m)` | 忽略大小写 / `.` 匹配换行 / 多行锚点 |
