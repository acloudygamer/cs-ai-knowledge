# 数据结构

## 定义

Java Collection 框架是**接口-实现分离**的泛型数据结构库。核心接口（List、Set、Map、Queue）定义了抽象数据类型（ADT），具体实现（ArrayList、HashMap 等）提供了空间-时间权衡的不同配置。

从抽象代数视角：
- List 是**序列**（Sequence）
- Set 是**集合**（Set with uniqueness）
- Map 是**偏函数**（Partial Function K → V）
- Queue 是**FIFO 序列**

理解这些抽象类型，有助于选择合适的数据结构。

## 机制

### ArrayList vs LinkedList 的缓存行为

**CPU 缓存行**：现代 CPU 一次从主存加载 64B（缓存行）。访问连续内存时，下一个元素很可能已在缓存中（**空间局部性**）。

| 操作 | ArrayList | LinkedList |
|------|-----------|------------|
| 随机访问 | O(1)，缓存友好 | O(n)，缓存不友好 |
| 头部插入 | O(n)，需移动所有元素 | O(1)，但需分配节点 |
| 尾部插入 | O(1) amortized | O(1) |

**归约终点**：LinkedList 的每个节点是独立分配的（`new Node()`），在堆中不连续，导致 CPU 缓存预取失效。每次 `next` 跳转都可能触发 cache miss（缓存未命中）。

**False Sharing**：在多线程场景下，若多个线程访问同一缓存行上的不同变量，一个线程的写操作会使其他线程的缓存行失效，即使它们访问的是逻辑上不相关的数据。

### HashMap 的并发问题

HashMap 不是线程安全的，并发修改可能导致：
- **数据丢失**：两个线程同时 put，hash 冲突时一个 put 被覆盖
- **死循环**：扩容时形成环形链表（JDK 7 及之前的实现）

**并发修改的数据竞争**：设两个线程同时执行 put。若两个 key 的 hash 相同且映射到同一桶，可能发生：
1. 线程 A 读取桶头节点
2. 线程 B 也读取桶头节点
3. 线程 A 插入新节点到桶头
4. 线程 B 插入新节点到桶头（覆盖线程 A 的修改）

### LinkedHashMap 的访问顺序

LinkedHashMap 维护**双向链表**记录插入顺序或访问顺序：

```java
// 访问顺序模式
LinkedHashMap<Integer, String> map = new LinkedHashMap<>(16, 0.75f, true);
```

`true` 启用访问顺序（LRU 缓存）。每次 `get` 或 `put` 将该 Entry 移到链表尾部。

**LRU 缓存实现**：

```java
if (map.size() >= capacity) {
    map.remove(map.entrySet().iterator().next());  // 删除最老的
}
```

**LRU 的数学约束**：最近访问时间越近，未来被访问的概率越高（**时间局部性**）。LRU 缓存利用这一性质，淘汰最久未使用的元素。

### 内存屏障与并发语义

Java 的 `volatile` 和 `synchronized` 关键字背后是**内存屏障**（Memory Barrier）：

| 屏障类型 | 作用 |
|----------|------|
| LoadLoad | 禁止屏障前的读与后的读重排 |
| StoreStore | 禁止屏障前的写与后的写重排 |
| LoadStore | 禁止屏障前的读与后的写重排 |
| StoreLoad | 禁止屏障前的写与后的读重排 |

`synchronized` 块获取锁时插入 **Acquire 屏障**，释放锁时插入 **Release 屏障**。这保证了临界区内的读写对其他线程可见。

**内存屏障的数学形式化**：设多核处理器的内存模型为顺序一致性（SC）、TSO、PSO、RQO 等。内存屏障的作用是约束指令重排：

- Acquire 屏障：禁止屏障后的读与屏障前的读写重排
- Release 屏障：禁止屏障前的读写与屏障后的读重排
