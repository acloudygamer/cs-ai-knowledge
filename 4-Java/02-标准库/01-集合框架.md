# 集合框架

> 前置：[06-泛型](../01-语言核心/06-泛型.md)、[08-Lambda与函数式接口](../01-语言核心/08-Lambda与函数式接口.md) · 后续：[02-Stream-API](./02-Stream-API.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows，12 核），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

没有任何一种数据结构能在所有操作上同时最优——随机访问要连续内存，任意位置插入要指针链接，按键查找要哈希或有序树。集合框架的应对是**接口与实现分离**：`List`、`Set`、`Map`、`Queue` 四个接口定义抽象数据类型（能做什么），`ArrayList`、`HashMap` 等实现各选一组时间-空间权衡（怎么做）。本篇给出每个主流实现的真实机制与适用边界。

## 接口层：四个抽象角色

| 接口 | 抽象 | 关键约束 |
|---|---|---|
| `List` | 有序序列，按下标访问，允许重复 | 索引语义 |
| `Set` | 去重集合 | 唯一性靠 `equals`/`hashCode` 或比较器 |
| `Map` | 键到值的映射（不是 `Collection` 的子接口） | 键唯一 |
| `Queue`/`Deque` | 消费队列，FIFO 或双端 | 提供 `offer`/`poll` 等非异常式 API |

接口之外 Java 21 补齐了 `SequencedCollection`（JEP 431）：为有 encounter order 的集合统一了首/尾访问与反向视图。实测（`--release 21`）：

```text
首/尾: z / d
反向视图: [d, c, b, a, z]
```

此前 `List.get(0)`、`Deque.getFirst()`、`SortedSet.first()` 各说各话，这一接口是历史碎片的收口。

## List：数组还是链表

### ArrayList：连续数组，扩容 1.5 倍

`ArrayList` 是一段连续对象引用数组加长度计数。随机访问是一次下标计算， $O(1)$；尾部追加在容量未满时也是 $O(1)$，容量满时扩容——实测（反射读取内部 `elementData` 长度，需 `--add-opens java.base/java.util=ALL-UNNAMED`，原因见 [05-反射与动态代理](../03-JVM与运行时/05-反射与动态代理.md)）：

```text
初始容量（new ArrayList<>() 后）: 0
size=1  扩容: 0 -> 10
size=11 扩容: 10 -> 15
size=16 扩容: 15 -> 22
size=23 扩容: 22 -> 33
...  size=74 扩容: 73 -> 109
```

增长因子是 `oldCapacity + (oldCapacity >> 1)`，即 1.5 倍。因为容量按几何级数增长， $n$ 次追加的总复制量是等比数列求和、量级 $O(n)$，摊到每次追加是均摊 $O(1)$——这是"扩容很贵"与"追加很快"同时成立的原因。选 1.5 而非 2 是空间账：扩容后容量超出实际需求的幅度上限约为 50%，翻倍则是 100%。代价是中间位置插入/删除要搬移后续全部元素， $O(n)$。

### LinkedList：指针链，缓存的敌人

`LinkedList` 的每个节点是独立堆对象（前后指针加元素引用），节点在堆里不连续。`get(i)` 从近端逐个跳转， $O(n)$，且每跳一个节点都是一次潜在的缓存未命中。实测（10 万元素，10 万次随机 `get`，Temurin 25.0.4.1）：

```text
ArrayList  10万次随机get: 4.1 ms
LinkedList 10万次随机get: 5966.8 ms
```

差三个数量级——这不只是 $O(1)$ 对 $O(n)$ 的账，还叠加了连续内存对指针跳转的缓存局部性优势。`LinkedList` 唯一占优的操作是"拿到迭代器后在当前位置插入/删除"，但这个场景在实际代码里极少出现；需要队列或栈时用 `ArrayDeque`（环形数组，两端 $O(1)$），`LinkedList` 在现代代码中几乎没有主场。

## Map：哈希还是有序

### HashMap：桶数组加冲突链

`HashMap` 把键的哈希码映射到容量为 $2^m$ 的桶数组：容量是 2 的幂时 `(n-1) & hash` 与取模等价但只需一次位与。实测：

```text
hash=3436774  (16-1)&hash=6  floorMod(hash,16)=6
```

冲突的键在同一桶里挂成链表；链表长度到 8 且表容量不小于 64 时转红黑树，把退化的查找从 $O(n)$ 拉回 $O(\log n)$。默认负载因子 0.75（元素数/桶数超过它即扩容翻倍）是时间与空间的折中点，一般不需要动。由此得到边界：键必须正确实现 `hashCode` 与 `equals`（`Object` 上这对方法的相等-哈希契约：相等的对象必须有相等哈希码），且 `HashMap` 不是线程安全的——并发写会丢数据，并发场景用 `ConcurrentHashMap`。

### LinkedHashMap 与 TreeMap：顺序的两种来源

哈希表不保证迭代顺序；需要顺序时有两个方向。实测同一份插入序列：

```text
HashMap:       [date, banana, apple, pear, kiwi, fig]
LinkedHashMap: [pear, apple, fig, date, kiwi, banana]
TreeMap:       [apple, banana, date, fig, kiwi, pear]
```

`LinkedHashMap` 在哈希表上叠一条双向链表，按插入序（或访问序）迭代；访问序模式加 `removeEldestEntry` 即 LRU 缓存。实测（容量 3，访问 1 后插入 4）：

```text
LRU 后剩余: [3, 1, 4]   ← 最久未用的 2 被淘汰
```

`TreeMap` 是红黑树（近似平衡的二叉搜索树，靠着色约束保证最长路径不超过最短的两倍），键按比较器排序，所有操作 $O(\log n)$，还支持 `floorKey`、`subMap` 等范围查询。选型规则：不需要顺序用 `HashMap`（ $O(1)$ 均摊），需要插入序/LRU 用 `LinkedHashMap`，需要排序或范围查询用 `TreeMap`。

### ConcurrentHashMap：桶级并发

Java 8 起 `ConcurrentHashMap` 废弃了 Java 7 的分段锁（16 个 Segment 各持一把锁），改为**桶级加锁**：空桶用 CAS 直接写入（无锁），非空桶只 `synchronized` 锁该桶的头节点，`get` 全程无锁（读 volatile 桶槽）。锁粒度从"整表的 1/16"细化到"单个桶"，并发度随表容量增长；红黑树化同样适用。代价是 `size()` 这类全局操作只能给近似值（`LongAdder` 式分片计数），跨桶复合操作要调用方自己保证原子性（用 `merge`/`compute` 等原子方法，而不是 `get` 后 `put`）。

## 其余实现的边界

- `HashSet`/`LinkedHashSet`/`TreeSet`：分别是对应 Map 的键视图包装（`HashSet.add(e)` 内部就是 `map.put(e, PRESENT)`），复杂度随行。
- `PriorityQueue`：数组表示的二叉堆（堆性质：父不大于子），`offer`/`poll` 为 $O(\log n)$，`peek` 为 $O(1)$；不是有序容器，只是每次弹出最小者。
- `CopyOnWriteArrayList`：每次写复制整个底层数组，写 $O(n)$、读 $O(1)$ 且无锁。只适用于读极多、写极少（如事件监听器列表）；写频繁时写放大不可接受。
- `ArrayDeque`：环形数组实现的双端队列，两端操作均摊 $O(1)$，是栈和队列场景的默认选择。

迭代器层面还有一个横切机制：**fail-fast**——`ArrayList`/`HashMap` 等的迭代器持有修改计数，迭代期间集合被结构性修改（绕过迭代器自身）即抛 `ConcurrentModificationException`。它不是并发保证，只是尽早暴露 bug 的栅栏。

## 选型速查

| 实现 | get | 增/删 | 有序性 | 并发 | 适用边界 |
|---|---|---|---|---|---|
| ArrayList | $O(1)$ | 尾 $O(1)$ 均摊 / 中间 $O(n)$ | 插入序 | 否 | 默认 List |
| LinkedList | $O(n)$ | 头尾 $O(1)$ | 插入序 | 否 | 几乎没有主场 |
| ArrayDeque | — | 两端 $O(1)$ 均摊 | — | 否 | 栈/队列默认 |
| HashMap/HashSet | $O(1)$ 均摊 | $O(1)$ 均摊 | 无 | 否 | 默认 Map/Set |
| LinkedHashMap | $O(1)$ | $O(1)$ 均摊 | 插入/访问序 | 否 | LRU、保序 |
| TreeMap/TreeSet | $O(\log n)$ | $O(\log n)$ | 排序 | 否 | 范围查询 |
| PriorityQueue | — | $O(\log n)$ | 弹出序 | 否 |  Top-K、调度 |
| ConcurrentHashMap | $O(1)$ 均摊 | $O(1)$ 均摊 | 无 | 桶级锁 + CAS | 并发默认 Map |
| CopyOnWriteArrayList | $O(1)$ | 写 $O(n)$ | 插入序 | 写时复制 | 读多写极少 |
