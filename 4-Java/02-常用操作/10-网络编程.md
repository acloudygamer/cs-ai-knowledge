# 网络编程

## 定义

TCP 是在不可靠的 IP 层之上通过**序列号（SEQ）递增 + 确认应答（ACK）滑动窗口**构建的可靠字节流传输协议。UDP 则仅在 IP 层之上添加端口复用（`SO_REUSEPORT`）和校验和，是无连接的数据报协议。Java NIO 通过 Selector 实现 I/O 多路复用，将 O(n) 的线程同步阻塞转换为 O(1) 的就绪事件通知。

## 数学模型

### TCP 滑动窗口协议

设发送窗口大小为 $W$，发送方维护三个指针：
- `SND.UNA`： oldest unacknowledged byte（窗口左界）
- `SND.NXT`： next byte to send（窗口右界 + 1）
- `SND.WND`：窗口大小

发送约束：$SND.NXT - SND.UNA \le W$

接收方维护 `RCV.NXT`（期望收到的下一个字节）和 `RCV.WND`（接收窗口大小）。确认应答采用**累计 ACK**（cumulative acknowledgment）：ACK=n 表示"已收到所有序列号 < n 的字节"。

### 超时重传定时器

$$RTO = \max(MinTimer, \min(MaxTimer, \beta \cdot RTTVAR + 0.5 \cdot SRTT))$$

其中 SRTT 是平滑往返时延估计，RTTVAR 是往返时延变化估计（RFC 6298）。Java Socket 的默认连接超时通过 `Socket.connect(endpoint, timeout)` 实现。

### NIO Selector 的时间复杂度

- 传统阻塞 I/O：$O(n)$ 线程数，每线程等待一个 fd
- select/poll：$O(fds)$ 线性扫描所有文件描述符
- epoll (Linux) / kqueue (macOS)：$O(\text{ready fds})$，仅返回就绪事件

Java NIO Selector 封装了平台特定的实现（Linux 用 epoll，Windows 用选择性等待），对上层暴露统一的 `select()` 语义。

**归约终点**：TCP 可靠传输可归约为**确认应答自动机**——每发送一个字节块，等待 ACK，超时重传；UDP 则是**数据报匿名投递**，无状态无确认。

## 数据流

<pre>
TCP 三次握手:
Client                      Server
   │                           │
   │─── SYN(SEQ=x) ──────────►│  Client 发送初始序列号
   │◄── SYN+ACK(SEQ=y,ACK=x+1)│  Server 确认并发送自己的 ISN
   │─── ACK(ACK=y+1) ─────────►│  Client 确认 Server 的 ISN
   │                           │
   │     双方进入 ESTABLISHED  │
   │                           │
TCP 数据传输:
   │─── DATA(SEQ=x, len=100) ─►│
   │◄── ACK(x+100) ───────────│  累计确认：已收到所有 < x+100
   │                           │
TCP 四次挥手:
   │─── FIN ──────────────────►│
   │◄── ACK ──────────────────│
   │◄── FIN ──────────────────│
   │─── ACK ──────────────────►│
</pre>

**Socket 生命周期**：
```
ServerSocket.bind(port) → listen() → accept() → Socket fd
                                     ↑
                              阻塞直到客户端连接

Socket fd:
  ├─ InputStream (read, readFully)
  ├─ OutputStream (write, flush)
  └─ 生命周期 = TCP 连接生命周期
```

**NIO Selector 数据流**：
```
Channel A (OP_ACCEPT)      Channel B (OP_READ)
      │                          │
      └──────── Selector ─────────┘
                │
                ▼ select() 阻塞
         Set<SelectionKey> readyKeys
                │
                ▼ 遍历就绪键
         处理对应 Channel 事件
```

## 机制

### TCP 可靠传输的状态机

TCP 通过有限状态机管理连接生命周期：

```pre>
CLOSED → SYN_SENT → ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → CLOSED
    │                                              ↑
    └─ LISTEN ← SYN_RECEIVED ←──────────────────────┘
```

每个状态转换由特定事件触发（发送/接收 SYN、ACK、FIN）。Java Socket 对底层状态机做了抽象，但某些行为（如 `close()` 后的 linger）仍受状态机约束。

### 为什么 TCP 是字节流而非消息流

- 序列号按字节编号而非消息编号，ACK 表示"已收到所有字节 < n"
- 应用层必须自行解决消息边界（黏包/半包）
- 常见解决方案：固定长度前缀 + length field / 特殊分隔符 / 协议头包含长度

### TCP 拥塞控制

算法（cubic/reno，由内核实现）：
- 慢启动：指数增长 cwnd（拥塞窗口）
- 拥塞避免：线性增长
- 快速重传：收到 3 个重复 ACK 时触发
- 快速恢复：减半 cwnd 后线性恢复

Java Socket 不直接暴露拥塞控制参数，应用层只能通过设置 socket 选项间接影响（如 `SO_SNDBUF`）。

### NIO Selector 的幽灵键泄漏

Selector 的键集合（`keys`）与已就绪集合（`selectedKeys`）是分离的：

```pre>
Selector.keys()     →  所有注册的键（含未就绪）
Selector.selectedKeys() → 仅已就绪的键
```

**幽灵键产生**：当 Channel 关闭但未正确 deregister 时，Selector 仍保留键在 `keys` 中，导致：
1. `select()` 返回值虚高（包含已关闭 Channel 的无效就绪事件）
2. `selectedKeys` 迭代时可能处理无效键

**正确做法**：
```java
Iterator<SelectionKey> it = selector.selectedKeys().iterator();
while (it.hasNext()) {
    SelectionKey key = it.next();
    if (!key.isValid()) {
        key.cancel();  // 立即取消
        continue;
    }
    // 处理有效键
    it.remove();  // 处理后移除
}
```

### Selector 的线程安全约束

**约束**：Selector 必须单线程操作。

- `select()`、`selectNow()`、`wakeup()` 可并发调用
- 但多线程同时 `select()` 会导致 `ClosedByInterruptException`
- 键的 `interestOps` 修改必须在同步块内进行

```java
// 线程安全的 interestOps 修改
synchronized (key) {
    key.interestOps(ops);
}
```

### NIO 与阻塞 I/O 的性能权衡

| 维度 | 阻塞 I/O | NIO Selector |
|------|----------|--------------|
| 线程数 | $O(n)$ 连接数 | $O(\text{core})$ |
| 内存 | $n \times 1MB$ 栈 | 固定大小堆 |
| 延迟 | 线程切换 ~1μs | 事件分发 ~100ns |
| 复杂度 | 简单 | 需要非阻塞处理 |

NIO 适合高并发低计算场景（如代理服务器），不适合计算密集型（线程不会被阻塞，selector 无法提升吞吐量）。

```java
// NIO Selector 服务器（≤20行）
ServerSocketChannel ch = ServerSocketChannel.open();
ch.bind(new InetSocketAddress(8080));
ch.configureBlocking(false);
Selector sel = Selector.open();
ch.register(sel, SelectionKey.OP_ACCEPT);
while (true) {
    sel.select();
    for (SelectionKey k : sel.selectedKeys()) {
        if (k.isAcceptable()) {
            SocketChannel c = ((ServerSocketChannel)k.channel()).accept();
            c.configureBlocking(false);
            c.register(sel, SelectionKey.OP_READ);
        }
        if (k.isReadable()) { /* handle */ }
    }
}
```
