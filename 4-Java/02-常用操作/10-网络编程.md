# 网络编程

> **本质断言**：TCP 是面向字节流的可靠传输协议，通过序列号、确认应答和重传机制在不可靠的 IP 层之上构建可靠通信；UDP 则在 IP 之上仅添加端口复用和校验和，是无连接的尽力而为协议。

## TCP 可靠性机制

<pre>
发送方                          接收方
   │                               │
   │──── SEQ=100, 10bytes ───────►│  发送数据，序列号100
   │◄─── ACK=110 ─────────────────│  确认已收到110之前所有数据
   │                               │
   │──── SEQ=110, 10bytes ───────►│  重传丢失的数据
   │◄─── ACK=120 ─────────────────│
</pre>

**为什么 TCP 是字节流而非消息流**：序列号是按字节编号而非按消息编号，确认应答（ACK）表示"已收到该序列号之前的所有字节"。这意味着应用层需要自行解决消息边界问题——这正是黏包/半包问题的根源。

## TCP 三次握手 / 四次挥手

<pre>
三次握手:
Client ── SYN(SEQ=x) ───────────► Server
Client ◄── SYN+ACK(SEQ=y,ACK=x+1) ── Server
Client ── ACK(ACK=y+1) ─────────► Server
  │                                  │
  │       双方交换初始序列号           │
  │       可开始传输数据              │

四次挥手:
Client ── FIN ─────────────────► Server
Client ◄── ACK ──────────────── Server
Client ◄── FIN ───────────────── Server
Client ── ACK ─────────────────► Server
</pre>

## Socket 抽象

`ServerSocket` 绑定端口并监听连接请求（`accept()` 阻塞直到客户端连接），返回 `Socket` 对象代表已建立的连接。每个 `Socket` 持有输入流和输出流，对象生命周期即连接生命周期。

## UDP 无连接特性

<pre>
UDP 发送:
DatagramSocket ──► DatagramPacket(目标IP+端口) ──► 网络

特点:
- 无连接建立延迟 (无 SYN/SYN-ACK/ACK)
- 无状态维护 (服务器可向任意客户端发送)
- 消息有边界 (每个 DatagramPacket 独立)
- 无拥塞控制 (可能丢包/乱序)
</pre>

## Java NIO Selector

<pre>
Selector 监听多个 Channel 的就绪事件:
         ┌──── Selector ────────┐
         │                      │
    ┌────┼────┐           ┌────┼────┐
    │OP_ACCEPT│           │OP_READ│
    │ServerCh │           │SocketCh│
    └─────────┘           └─────────┘

单线程处理多路复用:
select() 阻塞 → 返回就绪 Channel 列表 → 处理 → 回到 select()
</pre>

NIO 的优势：相比为每个连接创建线程（`Thread per connection`），Selector 使单线程可以处理数千连接，将 I/O 密集型场景的线程切换开销从 O(n) 降到 O(1)。

## 参考样例

```java
// TCP 服务器（≤20行）
try (ServerSocket ss = new ServerSocket(port)) {
    while (true) {
        Socket s = ss.accept();
        new Thread(() -> handle(s)).start();
    }
}
```
