# 正则表达式

## 定义

Java 正则引擎基于**非确定性有限自动机（NFA）**，通过回溯（backtracking）在输入字符串的所有可能匹配路径上搜索。量词（quantifier）的匹配范围构成指数级分支因子，当输入无法匹配时，引擎必须回溯尝试所有可能的分配组合——这在最坏情况下导致 $O(2^n)$ 时间复杂度，其中 $n$ 为量词嵌套深度。

NFA 相比 DFA 的核心权衡：支持捕获组（capturing group）和反向引用（back-reference），代价是回溯带来的指数级最坏情况。

## 数学模型

设正则表达式含 $m$ 个量词，每个量词 $q_i$ 的可匹配长度区间为 $[l_i, r_i]$（$l_i \ge 0$，$r_i$ 可能为 $\infty$）。对于长度为 $n$ 的输入字符串，NFA 回溯的最坏尝试次数上界为：

$$T(n, m) \le \prod_{i=1}^{m}(r_i - l_i + 1)$$

当 $r_i - l_i + 1 = k$（固定量词宽度）且 $m$ 个量词顺序嵌套时：
$$T(n, m) \le k^m$$

对于 `a{1,3}a{1,3}a{1,3}`（$k=3, m=3$），输入 8 个 `a` 的最坏尝试次数为 $3^3 = 27$ 次分配尝试。灾难性回溯（catastrophic backtracking）发生在 $k^m$ 随输入规模指数增长时。

**归约终点**：NFA 回溯可归约为**状态机的深度优先搜索**，每次回溯本质上是状态机的分叉点的重试。

## 数据流

<pre>
输入字符串 "aaaaaaaac"（9个a + 1个c）
        │
        ▼
┌──────────────────────────────────────────────────────┐
│                   NFA 状态机                          │
│  状态节点：s0 → (a+) → s1 → (a+) → s2 → (a+) → s3 → s4 │
│                ↑         ↑         ↑                  │
│               / \       / \       / \    ← 分叉点     │
│            l=1 r=∞  l=1 r=∞  l=1 r=∞                  │
└──────────────────────────────────────────────────────┘
        │
        ▼ 贪婪匹配：第一个(a+)吞掉全部8个a
   尝试路径：s0→[8个a]→s1→[0个a]→s2→[0个a]→s3→s4
        │
        ▼ 发现下一个字符是'c'而非'b'，回溯
   回溯点：s3 释放部分字符，尝试不同分配
        │
        ▼ 逐层回退：(a+)从8→7→6→...→0
   2^8 = 256 次尝试后失败
</pre>

**所有权流转**：
- 输入字符串本身只读，由 `Matcher` 对象持有引用
- 每次回溯尝试释放已匹配的字符引用，尝试新的分组分配
- `Pattern` 编译后的 NFA 状态机是 immutable 的，可被多个 `Matcher` 共享

## 机制

**为什么 Java 选择 NFA 而非 DFA**：
- DFA 的状态数随输入线性增长（$O(n)$），但无法记忆捕获组的历史——"第 $i$ 个分组从哪段开始"需要额外的数据结构
- NFA 通过**括号建立捕获边界**，每个分组对应栈帧，支持 `group(1)`、`group("name")` 等API
- 正向预查（lookahead）、负向预查（negative lookahead）、反向引用依赖 NFA 的状态记忆

**量词匹配策略**：
- **贪婪（greedy）** `.*`：优先匹配尽可能多，回溯时逐字符放弃
- **勉强（reluctant）** `.*?`：优先匹配尽可能少，逐步扩展
- **独占（possessive）** `.*+`：贪婪但不回溯，匹配失败直接终止

独占量词是 Java 特有的灾难性回溯防御机制——它相当于"获取后不释放"，一旦匹配失败不返还字符。

**固化分组（Atomic grouping）** `(?>...)`：也是防御手段，组内匹配完成后不保存回溯点，等价于独占量词的推广形式。

**约束条件**：
- 输入规模过大时，指数级回溯可能导致 CPU 100% 和 OOM
- 量词嵌套层级是灾难性回溯的主要风险因子，深度 ≥ 3 时风险显著上升

**违反约束的后果**：
- 正则匹配永不终止（实际表现为超时）
- 线程挂起，堆栈快速膨胀，最终抛出 `StackOverflowError` 或 OOM

## 参考存根

```java
// 预编译+捕获组（≤20行）
Pattern p = Pattern.compile("(?<year>\\d{4})-(?<month>\\d{2})-(?<day>\\d{2})");
Matcher m = p.matcher("2024-04-13");
if (m.matches()) {
    System.out.println(m.group("year"));  // 2024
}
```

```java
// 独占量词防御灾难性回溯
Pattern possessive = Pattern.compile("<div>.++</div>");  // 不回溯
Pattern greedy     = Pattern.compile("<div>.*</div>");  // 可能回溯
```

```java
// 固化分组防御
Pattern atomic = Pattern.compile("(?>([a-z]+))([a-z]+)");  // 第一组不保存回溯点
```
