# 正则表达式

## 定义

Java 正则引擎基于**非确定性有限自动机（NFA）**，通过回溯（backtracking）在输入字符串的所有可能匹配路径上搜索。量词（quantifier）的匹配范围构成指数级分支因子，当输入无法匹配时，引擎必须回溯尝试所有可能的分配组合——这在最坏情况下导致 $O(2^n)$ 时间复杂度，其中 $n$ 为量词嵌套深度。 时间复杂度，其中 $n$ 为量词嵌套深度。 为量词嵌套深度。

NFA 相比 DFA 的核心权衡：支持捕获组（capturing group）和反向引用（back-reference），代价是回溯带来的指数级最坏情况。

## 数据流

<pre>
输入字符串 "aaaaaaaac"（9个a + 1个c）
        │
        ▼
┌──────────────────────────────────────────────────────┐
│                   NFA 状态机                          │
│  状态节点：s0 → (a+) → s1 → (a+) → s2 → (a+) → s3 → s4 │
│                ↑         ↑         ↑                  │
│               / \       / \       / \    ← 分叉点     │
│            l=1 r=∞  l=1 r=∞  l=1 r=∞                  │
└──────────────────────────────────────────────────────┘
        │
        ▼ 贪婪匹配：第一个(a+)吞掉全部8个a
   尝试路径：s0→[8个a]→s1→[0个a]→s2→[0个a]→s3→s4
        │
        ▼ 发现下一个字符是'c'而非'b'，回溯
   回溯点：s3 释放部分字符，尝试不同分配
        │
        ▼ 逐层回退：(a+)从8→7→6→...→0
   2^8 = 256 次尝试后失败
</pre>

**所有权流转**：
- 输入字符串本身只读，由 `Matcher` 对象持有引用
- 每次回溯尝试释放已匹配的字符引用，尝试新的分组分配
- `Pattern` 编译后的 NFA 状态机是 immutable 的，可被多个 `Matcher` 共享

## 机制

### NFA 的状态机模型

Java 正则引擎将正则表达式编译为 NFA。NFA 由以下要素构成：

- **状态节点**：表示正则表达式中的位置
- **ε-转换**：不消耗输入字符的转移
- **字符转移**：消耗一个字符的转移

```pre>
正则: a(b|c)*d
NFA:
    s0 --a--> s1 --ε--> s2 --b--> s3 --ε--> s2
                   |              ↑
                   └────c─────────┘
    s3 --ε--> s4 --d--> s5
```

NFA 执行通过**ε-闭包**计算和**子集构造**模拟：当前活跃状态集通过 ε-转换扩展，再根据输入字符转移到下一状态集。

### 捕获组的栈帧机制

NFA 维护一个捕获组栈，用于记录匹配的子串范围：

```pre>
正则: (\w+)@(\w+)\.(\w+)
输入: "user@domain.com"

栈帧:
  Group 0: [0, 13]  (整体匹配)
  Group 1: [0, 4]   "user"
  Group 2: [5, 11]  "domain"
  Group 3: [12, 15] "com"
```

每遇到左括号 `(` 时压入新栈帧，记录当前输入位置；遇到右括号 `)` 时弹栈，记录匹配的结束位置。

### 量词匹配策略的语义差异

| 量词类型 | 记法 | 匹配策略 | 回溯行为 |
|----------|------|----------|----------|
| 贪婪 | `.*` | 优先匹配尽可能多 | 匹配失败时逐字符回退 |
| 勉强 | `.*?` | 优先匹配尽可能少 | 匹配失败时逐字符扩展 |
| 独占 | `.*+` | 贪婪但不回溯 | 匹配失败直接终止 |

独占量词是 Java 特有的灾难性回溯防御机制——它相当于"获取后不释放"，一旦匹配失败不返还字符。

### 固化分组（Atomic Grouping）的原理

固化分组 `(?>...)` 是另一种防御机制。组内匹配完成后，不保存任何回溯点：

```java
// 固化分组示例
Pattern p = Pattern.compile("(?>([a-z]+))([a-z]+)");
Matcher m = p.matcher("ab");
// ([a-z]+) 匹配 "ab" 后固化
// ([a-z]+) 尝试匹配但失败（因为固化组已消耗所有字符）
// 整体匹配失败，不回溯到 ([a-z]+)
```

固化分组的效果等价于：匹配完成后，将组内所有回溯点删除。这避免了组内匹配被外部回溯撤销。

### 回溯与贪婪/勉强的数学描述

设量词 $q$ 匹配的子串长度为 $l$ ，输入剩余长度为 $r$ 。 匹配的子串长度为 $l$ ，输入剩余长度为 $r$ 。 ，输入剩余长度为 $r$ 。 。

**贪婪模式**：
 $l = \min(r, r_i^{max}), \text{ 然后逐步回退 } l \to l-1, l-2, \ldots, l_i^{min}$ 

**勉强模式**：
 $l = l_i^{min}, \text{ 然后逐步扩展 } l \to l+1, l+2, \ldots, \min(r, r_i^{max})$ 

两种模式在匹配成功时行为相同，但失败时的搜索路径不同。贪婪模式先尝试最长匹配，失败后逐步缩短；勉强模式先尝试最短匹配，失败后逐步延长。

### 正则表达式的死循环风险

以下正则组合极易导致灾难性回溯：

| 正则 | 问题 |
|------|------|
| `(a+)+b` | 嵌套量词 |
| `(a*)*b` | 双重克林闭包 |
| `(a\|a*)+b` | 不必要嵌套 |

设输入为 `aaaa...ac`（大量 a 后跟其他字符），`(a+)+` 的嵌套导致指数级回溯。

## 参考存根

```java
// 预编译+捕获组（≤20行）
Pattern p = Pattern.compile("(?<year>\\d{4})-(?<month>\\d{2})-(?<day>\\d{2})");
Matcher m = p.matcher("2024-04-13");
if (m.matches()) {
    System.out.println(m.group("year"));  // 2024
}
```

```java
// 独占量词防御灾难性回溯
Pattern possessive = Pattern.compile("<div>.++</div>");  // 不回溯
Pattern greedy     = Pattern.compile("<div>.*</div>");  // 可能回溯
```

```java
// 固化分组防御
Pattern atomic = Pattern.compile("(?>([a-z]+))([a-z]+)");  // 第一组不保存回溯点
```
