# 日期时间

## 定义

Java `java.time`（JSR-310）是以**国际原子时（TAI）Timeline 模型为底座**的不可变日期时间 API。`Instant` 表示 timeline 上的一个点，精确到纳秒；`LocalDateTime` 是不含时区的人类感知时间；`ZonedDateTime` 通过 `ZoneId` 规则将两者绑定为唯一时刻。

`java.time` 的设计解决了两大历史遗留问题：`Date` 的可变性和 1900 年偏移，以及 `Calendar` 混乱的时区处理。

## 数学模型

### Timeline 模型

`Instant` 以 Unix Epoch（1970-01-01T00:00:00Z）为零点，存储为 `seconds + nanos` 的二元组：

$t_{\text{Instant}} = (\text{epochSecond}, \text{nano}) \in \mathbb{Z} \times [0, 999999999]$

任意 `Instant` 可映射为连续统上的唯一点，两个 `Instant` 之差为 `Duration`（物理时间单位：秒/纳秒）：

$\Delta t = t_2 - t_1 = \text{duration in seconds} + \frac{\text{nanos}_2 - \text{nanos}_1}{10^9}$

### 夏令时偏移函数

时区转换不是简单加减固定偏移量，而是历史分段函数：
$\text{offset}(zone, t) = \sum_{i} \text{offset}_i \cdot \mathbb{1}_{[t_i^{\text{start}}, t_i^{\text{end}})}(t)$

`ZoneId` 维护 IANA tz database 中的历史记录，每个时区的 offset 变化历史被完整保留——这解释了为何 `ZoneId.of("America/New_York")` 能正确处理 100 年前的夏令时。

**归约终点**：`Instant` 可归约为实数轴上的点（+ 离散纳秒精度），`ZonedDateTime` 是该点通过分段常数函数的投影。

## 数据流

<pre>
输入: "2024-04-13T14:30:00[Asia/Shanghai]"
        │
        ▼ 解析
TemporalAccessor  ──→  年=2024, 月=4, 日=13, 时=14, 分=30, 秒=0
                              │
                              ▼ withZoneSameLocal()
                       ZonedDateTime(2024-04-13T14:30:00, Asia/Shanghai)
                              │
                              ▼ toInstant()  应用偏移规则
                       Instant = Epoch秒 + 纳秒
                       Asia/Shanghai 在2024-04-13的offset = +08:00
                       实际 UTC = 06:30:00Z
</pre>

**不可变转换链**：
- 每次操作（`plusDays`、`withZoneSameInstant`）返回新实例
- 旧对象引用计数不变，无竞态条件
- `DateTimeFormatter` 是无状态函数式对象，线程安全

### Duration vs Period 的数学区别

```
Duration.between(Instant.A, Instant.B)  →  Δ秒（物理时间）
Period.between(LocalDate.A, LocalDate.B)  →  (年, 月, 日) 三元组（人类日历）
```

1 小时 + 1 小时 = 2 小时（Duration 可加）
1 月 + 1 月 在 "2024-01-31" 上 = 2 月 31 日 → 修正为 "2024-02-29"（闰年）

## 机制

### 为什么 `java.time` 是不可变的

`Date` 的 `setTime()` 等方法允许任意线程修改内部 `long milliseconds`，多线程访问产生数据竞争。不可变对象的优势：

1. **线程安全**：不可变对象的引用一旦发布，所有后续操作均安全，无需同步
2. **防御性拷贝消失**：无需克隆即可自由传递
3. **中间状态不可变**：管道转换过程中状态不会被意外修改

```java
// 可变（Date）
Date now = new Date();
process(now);  // process 可能修改 now
Date later = now;  // 引用共享，后续操作可能相互影响

// 不可变（Instant）
Instant now = Instant.now();
Instant later = now.plusSeconds(3600);  // now 完全不受影响
```

### 时区转换的物理正确性

```java
// 错误方式：LocalDateTime 直接相减
Duration.between(
    LocalDateTime.of(2024, 1, 1, 0, 0),  // 北京时间
    LocalDateTime.of(2024, 1, 2, 0, 0)   // 北京时间
).toHours();  // = 24，忽略时区变化
```

正确方式应先转换为同一时区的 `Instant` 或使用 `ZonedDateTime`：

```java
// 北京时间转换为 UTC 再相减
ZonedDateTime beijing1 = zdt1.withZoneSameInstant(ZoneOffset.UTC);
ZonedDateTime beijing2 = zdt2.withZoneSameInstant(ZoneOffset.UTC);
// 差值正确反映物理时间
```

### 时区偏移的分区常数性质

设 `ZoneOffset` 为分段常数函数。以 "America/New_York" 为例：

| 时间范围 | UTC 偏移 |
|----------|----------|
| 2024-03-10 02:00 至 2024-11-03 02:00 | -04:00（夏令时） |
| 其他时间 | -05:00（标准时） |

`withZoneSameInstant` 保证转换前后的绝对时间线位置相同，仅改变人类感知表示：

```java
ZonedDateTime zdt = ZonedDateTime.of(2024, 6, 15, 12, 0, 0, 0,
    ZoneId.of("America/New_York"));
// zdt: 2024-06-15T12:00-04:00[America/New_York]

ZonedDateTime utc = zdt.withZoneSameInstant(ZoneOffset.UTC);
// utc: 2024-06-15T16:00Z[UTC]
```

两者表示同一时刻（Unix Epoch 秒数相同）。

### 闰秒的数学处理

TAI（国际原子时）与 UTC 的关系：

$UTC = TAI - \text{leap\_seconds}$

截至 2024 年，闰秒约为 37 秒。`Instant` 基于 TAI 线性增长，不包含闰秒信息。这意味着：

- `Instant` 之间的 `Duration` 是精确的物理时间
- 但 `ZonedDateTime` 在闰秒时刻的显示可能出现重复（如 "23:59:59" 出现两次）

Java 的 `Clock.systemUTC()` 提供带闰秒支持的 `TickClock`，但普通 `Instant` 不处理闰秒。

### Instant 的精度与误差

`Instant` 内部存储为 `epochSecond`（long，64位）和 `nano`（int，0-999999999）。

$t_{\text{Instant}} = \text{epochSecond} + \frac{\text{nano}}{10^9} \text{ 秒}$

精度：纳秒（ $10^{-9}$ 秒）
范围：约 $\pm 2^{63} / (365.25 \times 24 \times 3600) \approx \pm 2.9 \times 10^8$ 年

**误差**：在 292 年的跨度上，纳秒舍入累积约 1 天的误差，但 `Period` 类通过日历算法处理人类日历的误差。

## 参考存根

```java
// Instant 与 Unix 时间戳（≤20行）
Instant now = Instant.now();
long unixSeconds = now.getEpochSecond();           // 1713000000
long unixMillis  = now.toEpochMilli();            // 1713000000000
Instant fromEpoch = Instant.ofEpochSecond(0);     // 1970-01-01T00:00:00Z
```

```java
// ZonedDateTime 转换
ZonedDateTime shanghai = ZonedDateTime.of(2024, 4, 13, 20, 0, 0, 0,
    ZoneId.of("Asia/Shanghai"));
ZonedDateTime utc = shanghai.withZoneSameInstant(ZoneOffset.UTC);
// shanghai: 2024-04-13T20:00+08:00[Asia/Shanghai]
// utc:      2024-04-13T12:00Z
```

```java
// Period vs Duration
LocalDate start = LocalDate.of(2024, 1, 31);
LocalDate end   = LocalDate.of(2024, 3, 31);
Period p = Period.between(start, end);  // P2M0D (2个月)
Duration d = Duration.between(start.atStartOfDay(), end.atStartOfDay());  // PT1440H
```
