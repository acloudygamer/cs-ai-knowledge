# 日志框架

## 定义

日志框架是记录程序运行事件的抽象层。SLF4J 作为门面（Facade），将日志 API 与日志实现解耦；Logback/Log4j2 作为实现，处理日志的过滤、格式化和输出。日志的核心价值在于运行时诊断，其约束是**不影响被记录程序的性能**。

## 数学模型

### 日志过滤的布尔代数

日志过滤链本质上是对日志事件 $e$ 求布尔表达式：

$f(e) = f_1(e) \land f_2(e) \land \dots \land f_n(e)$

每个过滤器 $f_i$ 返回 `ACCEPT`（真）、`DENY`（假）或 `NEUTRAL`（不影响结果）。

- `ACCEPT` + `DENY` = `DENY`
- `ACCEPT` + `NEUTRAL` = `ACCEPT`
- `DENY` + `NEUTRAL` = `DENY`
- `NEUTRAL` + `NEUTRAL` = `NEUTRAL`

这种三值逻辑设计使过滤器可以组合：LevelFilter 检查级别，MDCFilter 检查上下文，ThresholdFilter 检查消息内容。

**归约终点**：多过滤器组合本质上是合取范式（CNF），满足布尔代数的德摩根定律。

### 异步日志的队列模型

异步 Appender 将日志事件写入阻塞队列：

$T_{async} = O(1)$

每个日志调用仅入队，不等待写入磁盘。若队列满（默认容量 `queueSize = 256`），调用线程阻塞直到队列有空间。

队列类型影响行为：
- **有界队列** (`ArrayBlockingQueue(capacity)`)：满时阻塞，保证不丢日志但可能影响性能
- **无界队列**：无限等待直到内存耗尽，理论不丢日志但可能导致 OOM

**丢日志风险**：若应用崩溃前队列未 flush，有界队列尾部的日志丢失。无界队列理论上可保留所有日志直到 OOM。

### 异步日志的丢弃阈值机制

Logback 的 AsyncAppender 提供 `discardingThreshold` 参数控制丢弃策略：

- 当队列空闲率 > `discardingThreshold`（默认 20%）时，TRACE/DEBUG/INFO 日志被丢弃
- 当队列空闲率 ≤ `discardingThreshold` 时，所有日志保留

设队列容量为 $Q$ ，当前元素数为 $n$ ：

$\text{idleRatio} = \frac{Q - n}{Q}$

丢弃条件：
$\text{discard} \iff \text{idleRatio} > \text{discardingThreshold} \land \text{level} \in \{TRACE, DEBUG, INFO\}$

**约束**：ERROR 级别永不丢弃（即使队列满也会阻塞等待）。这确保关键错误不被遗漏。

### 占位符延迟求值

`log.info("user={}", name)` 中 `{}` 是延迟求值占位符。相比字符串拼接：

$T_{concat}(n) = O(n) \quad \text{vs} \quad T_{placeholder}(n) = O(1) \text{（若日志被过滤）}$

若 `INFO` 级别被过滤，延迟求值完全不执行 `name.toString()`，而字符串拼接已执行。

## 数据流

<pre>
同步日志数据流：

App Thread(s)                      Logback/Log4j2
    │                                    │
    │ log.info("msg={}", obj)            │
    ├──────────────────────────────────▶ │
    │                                    │
    │          ┌──────────────────┐       │
    │          │ Logger           │       │
    │          │ - 过滤（Level）  │       │
    │          └────────┬─────────┘       │
    │                   │ 通过            │
    │          ┌────────▼─────────┐      │
    │          │ AppenderChain    │      │
    │          │ - ConsoleAppender│      │
    │          │ - FileAppender   │      │
    │          └────────┬─────────┘       │
    │                   │                │
    │          ┌────────▼─────────┐     │
    │          │ Layout/Encoder   │     │
    │          │ (PatternLayout)  │     │
    │          └────────┬─────────┘     │
    │                   │               │
    │          ┌────────▼─────────┐    │
    │          │ I/O Write        │    │
    │          │ (磁盘/控制台)     │    │
    │          └──────────────────┘    │
    │                                    │
    ◀────────────────────────────────────│
    返回（同步阻塞直到写入完成）

异步日志数据流：

App Thread(s)                      AsyncAppender
    │                              │
    │ log.info("msg={}", obj)       │
    ├──────────────────────────────▶│
    │                              │ 入队（不阻塞）
    ◀───────────────────────────────│ 返回
                                    │
                        ┌───────────▼───────────┐
                        │ Disruptor/BlockingQueue│
                        │ ( RingBuffer size=256 ) │
                        └───────────┬───────────┘
                                    │
                        ┌───────────▼───────────┐
                        │ Worker Thread          │
                        │ (独立日志写入线程)      │
                        └───────────────────────┘
</pre>

**所有权变换**：
- 同步模式：日志事件从 App Thread 转移到 Appender，Appender 完成 I/O 后释放
- 异步模式：事件入队后 App Thread 立即释放，Worker Thread 持有并在处理完成后释放

## 对比参照

| 属性 | Logback | Log4j2 (sync) | Log4j2 (async) |
|------|---------|---------------|----------------|
| **同步吞吐量** | ~100k msg/s | ~80k msg/s | ~1M msg/s |
| **延迟 (p99)** | ~50μs | ~60μs | ~5μs |
| **队列模型** | 阻塞队列 | 阻塞队列 | Disruptor (CAS) |
| **实现机制** | 继承 SLF4J | 桥接到 SLF4J | LMAX Disruptor |

## 机制

### SLF4J 桥接器的类加载隔离

SLF4J 不实现日志逻辑，依赖绑定器（`logback-classic`, `log4j-slf4j2-impl`）提供实现。桥接器（如 `jcl-over-slf4j`）将 Commons Logging API 调用重定向到 SLF4J：

```
Commons Logging (JCL)
        │
        ▼
jcl-over-slf4j.jar
(重新实现 LogFactory，复写为 SLF4J 调用)
        │
        ▼
SLF4J API
        │
        ▼
绑定器实现
```

**约束**：必须避免类路径中存在多个日志实现（`logback` + `log4j` + `jul`），否则可能发生桥接循环或日志无法到达实现。

### Log4j2 Disruptor 的无锁设计

Log4j2 异步日志使用 LMAX Disruptor 实现无锁队列：

- 生产者：单线程写入，使用 CAS 更新 RingBuffer 指针
- 消费者：独立 Worker 线程批量读取
- 避免了传统阻塞队列的锁竞争

**关键约束**：Disruptor 要求单生产者+单消费者的严格约束才能保证无锁特性。多生产者场景需要额外同步。

### Disruptor 的 RingBuffer 机制

RingBuffer 是预分配的循环数组，大小为 2 的幂：

```pre>
sequence: 0  1  2  3  4  5  6  7  (mod 8)
slots:   [A][B][C][D][E][F][G][H]

写入: sequence++ → 写入 slot[sequence % 8]
读取: 读取 slot[sequence % 8] → sequence++
```

预分配避免了 GC 压力；序号操作是原子的；消费者通过 `sequence - cursor` 计算可用元素数量。

### MDC 的线程局部存储

MDC（Mapped Diagnostic Context）使用 `ThreadLocal<Map<String, String>>` 存储上下文：

```java
MDC.put("traceId", "abc123");  // 仅当前线程
log.info("request={}", "start");
// MDC 自动随线程传递（若使用 ThreadLocal 的 MDCFilter）
MDC.remove("traceId");
```

**约束**：默认情况下 `ThreadLocal` MDC 不会传播到子线程。Logback 的 `AsyncAppender` 会在线程创建时复制父线程 MDC（`inheritMDCFromCopy=true`），但若自行创建子线程则需显式调用 `MDC.getCopy()` 并在新线程中 `MDC.set()`。

### 日志级别的语义约束

| 级别 | 语义 | 典型场景 |
|------|------|----------|
| ERROR | 功能不可用，需立即关注 | 异常导致核心流程中断 |
| WARN | 潜在问题，不影响功能 | 降级处理、重试成功 |
| INFO | 关键业务里程碑 | 请求开始/结束、批处理进度 |
| DEBUG | 开发调试信息 | 函数入口/出口、变量值 |
| TRACE | 详细追踪 | 循环迭代、中间状态 |

**约束**：日志级别影响性能——DEBUG/TRACE 级别的字符串求值即使被过滤也会消耗 CPU（若不使用占位符）。

## 参考存根

```java
// SLF4J + Logback 配置（≤20行）
public class PaymentService {
    private static final Logger log = LoggerFactory.getLogger(PaymentService.class);

    public void pay(Order order) {
        MDC.put("orderId", order.id());
        try {
            log.debug("Processing payment for {}", order.amount());
            // ... payment logic
            log.info("Payment completed");
        } catch (PaymentException e) {
            log.error("Payment failed: {}", e.getMessage(), e);
            throw e;
        } finally {
            MDC.remove("orderId");
        }
    }
}
```
