# 错误处理

> **本质断言**：Java 异常机制是基于异常表（Exception Table）的非本地跳转，异常表在字节码层记录每个 try 块的起止位置和对应异常处理器，查找时间复杂度为 O(log n)。

## 异常表机制

<pre>
public void foo() {
    try {
        // bytecode指令地址 0-10
    } catch (IOException e) {
        // 异常处理器地址 20
    } catch (RuntimeException e) {
        // 异常处理器地址 30
    }
}

编译后异常表：
+-----------------+-----------------+-----------------+-----------------+
| start_pc        | end_pc          | handler_pc      | catch_type      |
+-----------------+-----------------+-----------------+-----------------+
| 0               | 10              | 20              | IOException     |
| 0               | 10              | 30              | RuntimeException|
+-----------------+-----------------+-----------------+-----------------+

查找过程：指令抛出异常 → 二分查找异常表 → 跳转到 handler_pc
</pre>

**为什么异常表用二分查找**：方法内 try-catch 块通常按声明顺序排列，JVM 编译器按 handler_pc 有序生成异常表，确保 O(log n) 定位。

## 受检异常 vs 非受检异常

`RuntimeException` 及其子类在字节码中不需要 `throws` 声明，因为 JVM 本身不验证方法签名——这是编译器（javac）强制的语义约束，而非运行时强制。这种设计的原意是：受检异常表示可恢复的外部错误（非程序 Bug），调用者必须处理；非受检异常表示程序 Bug，无需强制处理。

```java
// 以下两行字节码等效（运行时），但 javac 对受检异常会报错
void m1() { throw new IOException(); }           // 编译错误
void m2() { throw new RuntimeException(); }      // 编译通过
```

## try-with-resources 原理

`AutoCloseable.close()` 在 `finally` 之前执行，且所有 `close()` 调用被包装在 `Throwable.addSuppressed()` 中——当主路径和关闭路径都抛异常时，主异常被保留，关闭异常被抑制。

<pre>
try (Resource r = acquire()) {
    use(r);
} // 编译器生成: finally { if(r!=null) r.close(); suppress(e); }

执行顺序：use() → close() → 抛出 close异常 → close异常被抑制 → 抛出 use异常
</pre>

## 异常链与原因保留

`Throwable.getCause()` 返回构造时传入的原始异常；`addSuppressed()` 用于在 try-with-resources 中累积被关闭操作抑制的异常。使用异常链而非字符串拼接保存原因，是为了保留完整的堆栈信息——堆栈追踪（Stack-Walking）是 Java 诊断的核心，字符串消息无法提供。

## 参考样例

```java
// 受检异常声明
public void readFile() throws IOException { }
```

```java
// 自定义非受检异常
public class BizException extends RuntimeException {
    private final String code;
    public BizException(String code, String msg) { super(msg); this.code = code; }
    public String getCode() { return code; }
}
```

```java
// 异常链
try { /* 操作 */ }
catch (IOException e) { throw new ServiceException("服务失败", e); }
```

```java
// 获取被抑制的异常
Throwable[] suppressed = e.getSuppressed();
```

```java
// try-with-resources
try (Connection conn = ds.getConnection()) { }
```

```java
// 全局异常处理
@RestControllerAdvice
public class Handler {
    @ExceptionHandler(BizException.class)
    public ResponseEntity<ErrorResp> handle(BizException e) {
        return ResponseEntity.badRequest()
            .body(new ErrorResp(e.getCode(), e.getMessage()));
    }
}
```
