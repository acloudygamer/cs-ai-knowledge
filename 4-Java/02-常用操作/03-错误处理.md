# 错误处理

## 定义

Java 异常机制是基于异常表（Exception Table）的非局部跳转。编译器将 try-catch 块编译为异常表，运行时通过抛出异常触发表查找，跳转到匹配的异常处理器。异常表的查找复杂度为 $O(\log n)$，其中 $n$ 为异常处理器数量。

## 数学模型

### 异常表查找

设方法 $M$ 有 $n$ 个异常处理器，异常表按 `handler_pc` 升序排列。抛出异常时，JVM 执行：

$$\text{handler} = \text{binary\_search}(\text{exceptions}, \text{pc}, \text{exceptionType})$$

二分查找满足：
$$T_{\text{lookup}} = O(\log n)$$

当 $n=1$ 时，查找为 $O(1)$。当存在嵌套 try 块时，异常表项数增加，但编译器会合并相邻 handler 以保持效率。

### 异常传播的栈展开代价

异常从抛出位置向上传播到捕获位置，需经历栈展开（Stack Unwinding）。设栈深度为 $d$，每个栈帧需：
- 恢复寄存器状态：$O(1)$
- 调用 finally 块：$O(f_i)$，其中 $f_i$ 为 finally 块复杂度

总代价：
$$T_{\text{unwind}} = O(d + \sum_{i=1}^{d} f_i)$$

finally 块若无 try-catch，其自身不抛异常，展开代价线性于栈深度。

### 受检异常的语义约束

受检异常 (Checked Exception) 是 javac 强制的方法签名约束，JVM 层面不存在。设方法 $m$ 声明抛出类型集 $E$：

$$\text{compile-time: } \forall e \in E, \text{caller 必须处理或继续声明}$$
$$\text{runtime: } \text{JVM 不验证签名，异常可传播到未声明的调用者}$$

这意味着 `throws IOException` 在字节码中不存在，仅存在于 .class 文件的 `ExceptionIndexTable`（用于 javac 验证）。

## 数据流

<pre>
异常抛出与处理数据流：

    ┌──────────────────────────────────────────────────────┐
    │  throw new IOException();                            │
    └──────────────────────┬───────────────────────────────┘
                           │
                           ▼
              ┌────────────────────────┐
              │  查找当前方法的异常表     │◀──────────┐
              │  binary_search(pc, type) │            │
              └──────────┬───────────────┘            │
                         │ 找到                       │ 未找到
                         ▼                            │
              ┌────────────────────────┐            │
              │  复制异常到handler局部变量 │            │
              │  跳转到 handler_pc       │            │
              └──────────┬───────────────┘            │
                         │                            │
                         ▼                            │
              ┌────────────────────────┐            │
              │  执行异常处理器          │            │
              │  (记录 suppressed, cause)│            │
              └──────────┬───────────────┘            │
                         │ 正常完成 / 重新抛出          │
                         ▼                            │
              ┌────────────────────────┐            │
              │  栈展开: 恢复上一个栈帧  │────────────┘
              │  重复直到找到handler    │
              │  或到达栈顶 → uncaught  │
              └────────────────────────┘
</pre>

**所有权变换**：
- 异常对象从构造者转移到抛出点
- 栈展开时，异常对象作为值沿调用链传递
- 被捕获后，所有权转移给 catch 局部变量
- 若未捕获，异常对象被 JVM 的 uncaught handler 处理

## 机制

### try-with-resources 的抑制异常链

`try-with-resources` 编译后等效为：

```java
Resource r = acquire();
Throwable primary = null;
try {
    use(r);
} catch (Throwable t) {
    primary = t;
    throw t;
} finally {
    if (r != null) {
        Throwable suppressed = null;
        try {
            r.close();
        } catch (Throwable t) {
            suppressed = t;
        }
        if (primary != null) {
            primary.addSuppressed(suppressed);
        } else if (suppressed != null) {
            throw suppressed;
        }
    }
}
```

**执行序列**：
1. `acquire()` → `use()` → `close()`
2. 若 `use()` 抛异常 A，`close()` 抛异常 B → A 被保留，B 被抑制
3. 若 `use()` 正常，`close()` 抛异常 C → C 直接抛出

**约束**：只有通过 `addSuppressed()` 添加的异常才被保留。直接调用 `suppressedExceptions.add()` 无效。

### 异常链的完整性保证

`Throwable.getCause()` 返回构造时传入的原始异常，形成单向链表：

```
ServiceException
  .initCause(IOException)
    .initCause(SocketException)
      .initCause(NullPointerException)  // 根因
```

这个链保留了完整的因果信息。堆栈追踪 (Stack-Walking) 由 JVM 的 `StackTraceElement[]` 构成，在异常构造时冻结。

**为什么用异常链而非字符串**：字符串消息无法保留堆栈结构，且容易被截断或修改。异常链使诊断工具（如 JStack、IDE debugger）能够完整展示错误传播路径。

### 违反约束的后果

- **在 finally 中抛异常**：若 try 块也抛异常，该异常被抑制（try-with-resources 语义）。若 try 块正常，finally 的异常成为主异常。
- **在构造器中抛异常**：对象构造失败，已分配的子资源不会被自动释放（构造器无法执行 try-with-resources），需显式清理或使用静态工厂方法。
- **吞掉异常** (`catch { }`)：调用者无法感知异常发生，数据一致性需依赖其他机制保证。

## 参考存根

```java
// 受检异常转非受检（≤20行）
public void legacyMethod() throws IOException {
    if (Math.random() < 0.5) throw new IOException("simulated");
}
// 包装为非受检
public void modernWrapper() {
    try { legacyMethod(); }
    catch (IOException e) { throw new IllegalStateException(e); }
}
```

```java
// 抑制异常链（Java 17+）
try (var conn = driver.connect(url, props)) {
    conn.createStatement().execute(sql);
} catch (SQLException primary) {
    var suppressed = primary.getSuppressed();
    var cause = primary.getCause();
    throw new BusinessException("DB operation failed", cause, suppressed);
}
```

```java
// 栈帧截取（Java 17+ record 安全异常）
public record Result<T>(T value, Throwable error) {
    public static <T> Result<T> of(ThrowingSupplier<T> s) {
        try { return new Result<>(s.get(), null); }
        catch (Throwable t) { return new Result<>(null, t); }
    }
}
```
