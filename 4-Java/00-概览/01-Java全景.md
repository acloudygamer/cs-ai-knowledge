# Java 全景

> 前置：无（全库起点） · 后续：[01-安装与第一个程序](../01-语言核心/01-安装与第一个程序.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。示例实测环境：Temurin JDK 25.0.4.1（Windows），stable 口径示例以 `javac -encoding UTF-8 --release 21` 验证。

本篇建立贯穿全库的两个锚点：Java 由哪三块构成，以及一段源码从文本到进程的执行链。后续各篇的"为什么"几乎都能回溯到这里——异常（[07-异常处理](../01-语言核心/07-异常处理.md)）是 JVM 栈展开机制的展开，泛型擦除（[06-泛型](../01-语言核心/06-泛型.md)）是"编译期结账、字节码无痕"的展开，虚拟线程（[05-虚拟线程与结构化并发](../04-并发编程/05-虚拟线程与结构化并发.md)）是"JVM 调度权回收"的展开。

## 本质

Java 是静态类型、编译为**字节码**（bytecode：一种面向栈式虚拟机的中间指令集）、由 JVM（Java Virtual Machine）执行的面向对象语言。它不是一个东西，而是三块各自独立演进的规范的合称：

| 构成 | 规范 | 物理实体 | 换一块的实例 |
|---|---|---|---|
| 语言 | Java 语言规范（JLS） | javac 编译器 | Kotlin、Scala：不同语言，同一 JVM |
| 虚拟机 | JVM 规范（JVMS） | HotSpot（OpenJDK 默认实现） | GraalVM、OpenJ9：不同实现，同一字节码 |
| 类库 | Java SE API | JDK 自带的 `java.*`/`javax.*` 包 | Android：同一语言，不同类库与运行时（ART） |

三块之间的接口是 `.class` 文件格式。这个中间层是 Java 全部特性的来源，也是全部代价的来源：

- **平台无关**：字节码不绑定任何操作系统/CPU，移植的是 JVM 而不是程序——"一次编译，到处运行"。
- **自动内存管理**：对象死在堆里由 GC（垃圾回收，Garbage Collection）回收，不归程序员。代价：GC 暂停与内存占用（见 [03-垃圾回收](../03-JVM与运行时/03-垃圾回收.md)）。
- **默认引用语义**：除八种基本类型（`int`、`double` 等）外一切皆堆对象引用，赋值即别名。与 C++ 的值语义默认值相反。
- **启动与峰值性能分两笔账**：JVM 先解释执行、热点代码再由 JIT（Just-In-Time，运行时编译为机器码）逐层优化。启动慢、热身后的峰值可以逼近原生码——这笔账的细节见 [06-性能调优](../03-JVM与运行时/06-性能调优.md)。

## 机制

### 执行链：源码到进程

```text
Hello.java ──javac──> Hello.class ──类加载──> JVM ──解释+JIT──> 机器码
  文本                 字节码         验证/链接      执行引擎
```

实测（Temurin 25.0.4.1）：传统形式（`public class Hello` 包裹 `public static void main`）编译出 414 字节的 `Hello.class`——简化 main 形式的产物是 389 字节，两种写法的口径对照见 [01-安装与第一个程序](../01-语言核心/01-安装与第一个程序.md)。`javap -c` 反汇编可见 `main` 的字节码只有 4 条指令：

```text
0: getstatic     #7   // 取 System.out（静态字段）
3: ldc           #13  // 从常量池载入字符串 "hello, jvm"
5: invokevirtual #15  // 调用 PrintStream.println
8: return
```

三点推论：

1. **字节码是栈式指令**：操作数走操作数栈而非寄存器，`getstatic`/`ldc` 把值压栈，`invokevirtual` 弹栈调用。这与物理 CPU 的寄存器模型不同，执行由 JVM 解释器逐条模拟，热点再交给 JIT。
2. **常量池是类的数据中心**：`#7`、`#13` 指向 class 文件内的常量池表项——字符串字面量、方法符号引用都集中在这里，类加载时解析（见 [01-字节码与类加载](../03-JVM与运行时/01-字节码与类加载.md)）。
3. **`invokevirtual` 是动态分派的入口**：调用目标在运行时按对象的实际类型确定，这是多态（[05-面向对象](../01-语言核心/05-面向对象.md)）在字节码层的落点。

### 分层编译：解释器与 JIT 的分工

JVM（HotSpot）的执行引擎是三层流水线：解释器立即开始执行（零等待），执行次数越阈值的代码由 **C1**（客户端编译器，快编译、浅优化）接管，最热的代码交给 **C2**（服务端编译器，慢编译、激进内联与逃逸分析）。这就是 Java"启动慢、越跑越快"的机制来源；GraalVM 的 AOT（运行前整体编译为机器码，牺牲峰值换启动）是对这笔账的另一种解法（见 [11-GraalVM与云原生](../08-生态与框架/11-GraalVM与云原生.md)）。

### 版本节奏

2017 年起 Java 改为**每半年一个特性版本**（3 月、9 月）；**LTS**（Long-Term Support，长期支持版，厂商提供多年更新）最初三年一版（8→11→17），2021 年起改为两年一版（17→21→25）。本库的两个口径就是其中最近两个 LTS——Java 21 stable、Java 25 latest；LTS 节奏的来历与逐版本特性清单归 [10-版本演进](../10-版本演进/) 管，本篇不复述。

非 LTS 版本（22、23、24……）是通往下一个 LTS 的试验田：特性以**预览**（preview）身份入场，收集反馈后在后续版本转正或修改。

## 版图与边界

**版图**。Java SE 是核心（本库 01~07 目录覆盖）；其上是 Jakarta EE（企业级规范，Servlet/JPA 等；2017 年 9 月 Oracle 宣布将 Java EE 移交 Eclipse 基金会，遂改现名）与 Spring 生态（事实标准的企业开发栈，见 [08-生态与框架](../08-生态与框架/)）；Android 用 Java 语言但跑在 ART（Android Runtime）上，类库与运行时都不同，不算 JVM 阵营。Kotlin/Scala 等 JVM 语言共享字节码与类库生态。

**边界**（Java 不做什么）：

- 无裸指针、无手动内存管理——写不了内核驱动，也免掉了悬垂引用这一整类 bug。
- 无运算符重载（`+` 的字符串拼接是唯一例外）、无类的多继承（接口可多重实现）——刻意收窄的表达力，换代码的可读性下限。
- 启动时间与内存常驻高于原生编译语言——微服务冷启动场景的短板，GraalVM 与 CRaC（Coordinated Restore at Checkpoint，检查点协调恢复：把预热后的 JVM 状态快照存档、启动时直接恢复）在补。
