# 单例模式

## 定义

**单例模式是一种确保一个类仅有一个实例，并提供全局访问点的创建型设计模式。**

## 本质断言

- 唯一性保证来自构造函数私有化 + 类加载机制
- 全局访问点由静态方法提供，实例生命周期由JVM管理

## 机制解释

### 饿汉式：类加载即创建实例

类加载时直接创建实例，JVM类加载器保证线程安全，无需同步开销。代价是即使从未使用也会占用内存——这是以空间换时间的确定性策略。

### 懒汉式：延迟初始化的代价

延迟加载只在首次调用时创建实例，但普通写法存在线程安全问题。两个线程同时判断`instance == null`会产生两个实例。解决线程安全需要同步，但同步方法每次调用都有性能开销——这是时间换空间的权衡。

### 双重检查锁定：精准同步

```java
public class Singleton {
    private static volatile Singleton instance;
    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

`volatile`防止指令重排：`new Singleton()`在字节码层是三个操作（分配内存、调用构造器、写入引用），不加volatile可能发生重排导致其他线程看到未构造完成的对象。

### 静态内部类：利用类加载顺序

```java
public class Singleton {
    private Singleton() {}
    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

类加载时内部类不加载，只有调用`getInstance`时JVM才会加载`Holder`并创建实例。这是利用JVM类加载机制的惰性设计。

### 枚举单例：JVM层面的保证

```java
public enum Singleton { INSTANCE; }
```

枚举实例在JVM中是`Singleton`类的static final字段，JVM保证仅被实例化一次，且自动防止反射攻击和反序列化创建新实例。

### 序列化问题

反序列化会调用`readObject`，默认行为会创建新实例。实现`readResolve()`方法返回单例实例，可以让JVM在反序列化时使用原有实例——这是覆盖默认行为的hook机制。

### 反射攻击防护

构造器检查`instance != null`并抛出异常，阻止第二次构造。这是防御性编程，在单例模式中需要显式防护。

## 数据流

<pre>
getInstance() 调用
    │
    ├─ 静态内部类式：触发 Holder 类加载 → 创建 INSTANCE → 返回
    │
    └─ 双重检查：检查 instance → 加锁 → 再次检查 → 创建 → 返回
</pre>

## 版本基准

- Stable: Java 21
- Latest: Java 25

## 技术正确性

- ✅ `volatile`正确防止指令重排
- ✅ 枚举单例正确防止反射和反序列化
- ✅ `readResolve()`正确覆盖反序列化行为

## 适用场景

<pre>
全局唯一资源
    │
    ├─ 日志对象（避免重复打开文件句柄）
    ├─ 配置管理器（避免重复解析配置文件）
    ├─ 连接池（限制数据库连接数量）
    └─ Spring Bean（默认单例，减少对象创建开销）
</pre>

## 不适用场景

- 有状态对象（多线程环境下状态同步复杂）
- 需要多实例的类（如原型Bean每次需要新实例）
