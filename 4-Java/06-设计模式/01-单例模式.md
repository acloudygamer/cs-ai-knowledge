# 单例模式

## 定义

单例模式是一种确保一个类仅有一个实例，并提供全局访问点的创建型设计模式。其本质是**资源独占**——将实例数量压缩至集合 $S$ 的势 $|S| \leq 1$ ，通过确定性状态机保证这一约束不被破坏。 的势 $|S| \leq 1$ ，通过确定性状态机保证这一约束不被破坏。 ，通过确定性状态机保证这一约束不被破坏。

## 数学模型

### 实例空间的状态不变量

设单例实例集合为 $S$ ，不变量（Invariant）为： ，不变量（Invariant）为：
 $\forall s \in S: |S| = 1 \lor |S| = 0$ 

状态机描述：
```
UNINITIALIZED --(首次访问)--> INITIALIZING --(构造完成)--> INITIALIZED
                                                    |
 INITIALIZED <--(JVM GC回收)-------------------------+
```

### 双重检查锁定（DCL）的形式化证明

设线程 $T_1$ 执行构造，线程 $T_2$ 执行读取。`volatile` 保证以下 happens-before 链： 执行构造，线程 $T_2$ 执行读取。`volatile` 保证以下 happens-before 链： 执行读取。`volatile` 保证以下 happens-before 链：

 $T_1: \text{构造函数写} \xrightarrow{\text{hb}} T_1: \text{volatile写}(instance) \xrightarrow{\text{volatile}} T_2: \text{volatile读}(instance) \xrightarrow{\text{hb}} T_2: \text{使用实例}$ 

**顺序一致性的两个保证**：
1. **写-读顺序**：对 `volatile` 变量的写操作 happens-before 后续对该变量的读操作（JLS 17.4.5）
2. **读-读重排禁止**：禁止对 `volatile` 变量的读取操作被重排到写操作之前

**指令重排的危险性**：

`instance = new Singleton()` 在字节码层面是三个操作的重排：
```
1. allocate memory        // 分配内存（堆上分配对象头+字段空间）
2. invoke constructor     // 调用构造器（初始化字段）
3. assign reference       // 写入引用（instance 变量指向新对象）
```

JVM 可能重排为 `1 → 3 → 2`（逃逸分析优化），此时：
- $T_2$ 读取到的是**已分配但未构造的对象** 读取到的是**已分配但未构造的对象**
- 对象字段处于零值状态，而非构造后的预期状态
- 这称为**悬空引用（Dummy Object）**问题

**所有权流转**：
- 实例创建后，`instance` 引用持有对象所有权
- 所有线程通过 `getInstance()` 间接访问，不直接持有引用
- GC 在无引用时回收，释放所有权

## 机制

### 饿汉式的类加载安全性

```java
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() { return INSTANCE; }
}
```

**线程安全性来源**：JVM 类加载过程由 `Class` 对象的初始化锁保护，是串行化的。类加载器在加载阶段会获取该锁，确保 `<clinit>` 方法的互斥执行。

**代价**：即使从未使用，实例也会在类加载时创建。这是**空间换确定性**——以确定性的内存占用换取确定性的初始化时机。

**类加载时机的不确定性**：类在首次**主动使用**时加载。主动使用包括：`new`、`getstatic`、`putstatic`、`invokestatic`。这意味着首次访问任何静态成员都会触发类加载，单例实例随之创建。

### 静态内部类的惰性初始化

```java
public class Singleton {
    private Singleton() {}
    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() { return Holder.INSTANCE; }
}
```

**惰性原理**：JVM 规范保证类的初始化在**首次主动使用**时才执行。`Holder.INSTANCE` 首次被访问时，触发 `Holder` 的类加载和初始化，此时创建 `Singleton` 实例。

**线程安全性来源**：JVM 类初始化由 `Class` 对象的初始化锁保护（JLS 12.4.2）。多线程同时触发初始化的场景下，只有一个线程执行 `<clinit>`，其他线程阻塞等待。

**对比饿汉式**：饿汉在类加载时立即创建，静态内部类在首次访问时才创建，且初始化完成后 `Holder` 类的初始化锁被释放。

### 枚举单例的 JVM 底层保证

```java
public enum Singleton {
    INSTANCE;
}
```

枚举实例在 JVM 中是 `Singleton` 类的 `static final` 字段，JVM 提供三层保护：

1. **反射攻击防护**：`Constructor.newInstance()` 在实例化前检查 `class.getModifiers() & Modifier.ENUM`，若为枚举类型则抛出 `IllegalArgumentException: Cannot reflectively create enum objects`

2. **反序列化防护**：`ObjectInputStream.readObject()` 调用 `ObjectStreamClass.lookup()` 时，若检测到枚举类型，强制走 `readEnum()` 路径，直接返回 `Enum.valueOf()` 结果，不走普通反序列化流程

3. **线程安全**：由 JVM 类加载器的锁保证

**为何枚举是"最佳实践"**：单例模式的核心约束是"实例唯一性 + 全局访问"。枚举天然满足这两点，且由 JVM 底层保证，比任何手写方案都难以被破坏。

### 序列化漏洞与 readResolve

反序列化默认会创建新实例，违反单例不变量：

```java
// 反序列化流程
ObjectInputStream.readObject()
    → ObjectStreamClass.lookup()  // 查询类的序列化描述符
    → readOrdinaryObject()       // 读取普通对象
        → desc.isEnum() ? getEnumConstant() : newInstance()
```

若 Singleton 实现了 `Serializable` 但未重写 `readResolve()`，反序列化会通过 `newInstance()` 创建新实例。

```java
// 防护措施
protected Object readResolve() throws ObjectStreamException {
    return INSTANCE;  // 替换为已有实例，维持单例不变量
}
```

**原理**：`readResolve()` 在 `newInstance()` 之后调用，返回值替换反序列化新建的对象（原对象成为不可达垃圾）。

### 单例模式的适用场景与反模式警示

**适用场景**（全局资源管理器）：
- 全局唯一配置对象（`Runtime.getRuntime()` 是典型案例）
- 日志管理器（但 SLF4J 更推荐通过绑定而非单例）
- 连接池管理器（但连接池生命周期管理比单例更复杂）

**反模式警示**：
- **全局状态耦合**：单例持有可变状态后，所有访问点形成隐式依赖，难以追踪数据流
- **测试困难**：单例持有内部状态后，无法在不重启 JVM 的情况下重置
- **并行开发隐式依赖**：多个开发者可能无意间依赖同一个单例，形成隐藏耦合
- **生命周期模糊**：单例何时创建、何时销毁不明确，与模块化原则冲突

## 参考存根

```java
// DCL 单例（完整 volatile 语义，Java 21）
public final class Singleton {
    private static volatile Singleton instance;  // volatile 禁止重排
    private final byte[] data;  // 确保实例有实际状态

    private Singleton() {
        this.data = new byte[1024];
    }

    public static Singleton getInstance() {
        if (instance == null) {              // 第一次检查（快速路径，避免加锁开销）
            synchronized (Singleton.class) {   // 获取类锁
                if (instance == null) {        // 第二次检查（防止重复创建）
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

// 静态内部类单例（Java 21 推荐）
public class Singleton {
    private Singleton() {}

    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}

// 枚举单例（最简，JVM 底层保证）
public enum Singleton {
    INSTANCE;

    public void doSomething() {
        // 业务方法
    }
}
```
