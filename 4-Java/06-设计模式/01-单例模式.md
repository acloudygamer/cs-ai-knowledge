# 单例模式

## 定义

单例模式是一种确保一个类仅有一个实例，并提供全局访问点的创建型设计模式。

## 数学模型

### 线程安全的约束条件

设 $S$ 为单例实例集合，$|S| \leq 1$ 是不变量（Invariant）。

在多线程环境下，若初始化过程不是原子操作，可能出现 $|S| > 1$ 的状态违反不变量。设线程 $T_i$ 执行：

```
if (instance == null) {          // 检查
    synchronized(LOCK) {          // 获取锁
        if (instance == null) {   // 再次检查
            instance = new Singleton(); // 写入
        }
    }
}
```

**DCL（双重检查锁定）的正确性证明**：

设 `instance` 变量的写入和读取满足 **顺序一致性**（Sequential Consistency），即happens-before关系保证。`volatile` 确保：

1. **写-读顺序**：对 `volatile` 变量的写操作happens-before后续对该变量的读操作
2. **读-读重排禁止**：禁止对 `volatile` 变量的读取操作被重排到写操作之前

因此，当线程 $T_2$ 读取到 `instance != null` 时，$T_1$ 的构造函数必然已完全执行。

**指令重排的危险**：

`instance = new Singleton()` 在字节码层面是三个操作：
```
1. allocate memory       // 分配内存
2. invoke constructor    // 调用构造器
3. assign reference       // 写入引用
```

若无 `volatile`，JVM 可能重排为 1 → 3 → 2。此时 $T_2$ 读取到的是已分配内存但未构造的对象（**悬空引用**）。

### 单例模式的时序状态机

```
线程视角的状态转换：

T1: [初始化中] → [已完成]
T2: [检查instance] → [等待锁] → [再次检查] → [使用已有实例]

单例初始化的 happens-before 关系：
    write(instance) → read(instance)
         ↑                ↑
      T1 的构造函数    T2 的 instance 读取
```

## 机制

### 饿汉式的类加载安全性

```java
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() { return INSTANCE; }
}
```

类加载时 `INSTANCE` 的初始化由 **JVM 类加载器的锁机制** 保证线程安全。JVM 类加载过程本身是串行的，不存在并发问题。

**代价**：即使从未使用，实例也会在类加载时创建，占用内存。这是 **空间换时间** 的确定性策略。

### 静态内部类的惰性初始化

```java
public class Singleton {
    private Singleton() {}
    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() { return Holder.INSTANCE; }
}
```

**惰性原理**：Java 虚拟机规范保证类的初始化在**首次主动使用**时才执行。`Holder.INSTANCE` 首次被访问时，触发 `Holder` 的类加载初始化，此时创建 `Singleton` 实例。

**线程安全性来源**：JVM 的类初始化机制本身是线程安全的，由 `Class` 对象的初始化锁保护。

### 枚举单例的 JVM 保证

```java
public enum Singleton {
    INSTANCE;
}
```

枚举实例在 JVM 中是 `Singleton` 类的 `static final` 字段。JVM 保证：
1. **反射攻击防护**：`Constructor.newInstance()` 会检查 `enum` 修饰符，拒绝实例化
2. **反序列化防护**：`readObject` 特殊处理枚举，返回原有实例
3. **线程安全**：由 JVM 类加载器的锁保证

### 序列化漏洞与 readResolve

反序列化默认会创建新实例：
```java
// 反序列化流程
ObjectInputStream.readObject()
    → ObjectStreamClass.lookup()
    → new ObjectInputStream()
    → readOrdinaryObject()
    → obj = desc.isEnum() ? getEnumConstant() : newInstance()
```

若 Singleton 实现了 `Serializable`，但未重写 `readResolve()`，反序列化会创建新实例，违反单例不变量。

```java
protected Object readResolve() throws ObjectStreamException {
    return INSTANCE; // 返回原有实例
}
```

### 单例模式的适用场景与反模式

**适用场景**：
- 全局唯一配置对象
- 日志管理器
- 连接池管理器

**反模式警示**：
- 滥用单例导致全局状态耦合
- 难以测试（单例持有状态后难以重置）
- 并行开发时的隐式依赖

## 参考存根

```java
// DCL 单例（完整 volatile 语义）
public final class Singleton {
    private static volatile Singleton instance;
    private final byte[] data; // 确保实例有实际状态

    private Singleton() {
        this.data = new byte[1024]; // 模拟构造开销
    }

    public static Singleton getInstance() {
        if (instance == null) {              // 第一次检查（快速路径）
            synchronized (Singleton.class) {    // 获取类锁
                if (instance == null) {        // 第二次检查（防止重复创建）
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

// 静态内部类单例（推荐）
public class Singleton {
    private Singleton() {}

    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```
