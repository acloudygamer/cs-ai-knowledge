# 建造者模式

## 定义

**建造者模式是一种将复杂对象的构建过程与其表示分离，使相同的构建过程可以创建不同表示的对象创建型设计模式。**

## 本质断言

- 构建过程标准化（step-by-step），但每步可选择具体值
- 产品（最终对象）与构建器（创建过程）解耦
- 链式调用提供流畅接口（Fluent Interface），代码可读性高

## 机制解释

### 核心问题：构造函数参数过多

当一个类有超过4个构造参数时，构造函数面临两个问题：参数顺序难以记忆，且无法表达参数含义。`new User("John", "Doe", 30, "123-456", true, false, ...)`这类代码无法让人一眼看出哪个boolean是什么意思。

### 建造者如何解决

建造者将每个参数转化为一个链式调用方法，参数名就是方法名：`User.builder().firstName("John").lastName("Doe").age(30).build()`。这解决了可读性问题，同时保持了不可变对象的创建能力（build()后才创建最终对象）。

### 必填 vs 可选参数的分离

通过构造函数强制必填参数，方法链处理可选参数并提供默认值。这比Telescoping Constructor（ telescoping constructor anti-pattern，多个构造函数层层嵌套）更清晰，比JavaBeans模式（setter方法破坏不可变性）更安全。

### build()验证的意义

在build()方法中进行参数验证，确保创建的对象始终处于有效状态。这是因为建造者可能在多处被使用（直接调用build()而非通过完整链），必须有防御性验证。

### 链式调用的内部机制

每个setter方法返回this，方法链结束时调用build()创建实际对象。这种模式叫做Fluent Interface（流式接口），本质上是一种方法链式调用的API设计风格。

## 数据流

<pre>
User.builder() 创建 Builder 实例
    │
    ├─ Builder("John", "Doe") ← 必填参数在构造时传入
    │
    ├─ .age(30) ← 可选参数通过方法链设置
    ├─ .phone("123-456")
    └─ .build() ← 验证 → 创建不可变 User
</pre>

## 版本基准

- Stable: Java 21
- Latest: Java 25

## 技术正确性

- ✅ 链式调用方法正确返回this
- ✅ build()方法应进行参数验证
- ✅ Lombok @Builder自动生成建造者

## Lombok @Builder

```java
@Builder
public class User {
    private final String firstName;
    private final String lastName;
    private final int age;
}
```

编译时Lombok自动生成`UserBuilder`类和`User.builder()`静态工厂方法。

## 适用场景

<pre>
复杂对象创建
    │
    ├─ 参数 ≥ 5 个
    ├─ 参数分为必填和可选
    ├─ 需要创建不可变对象
    └─ 构建步骤固定但可配置
</pre>

## 建造者 vs 其他模式

| 模式 | 解决的问题 |
|------|------------|
| 工厂模式 | 产品创建（what） |
| 建造者模式 | 构建过程（how） |
| 抽象工厂 | 产品族一致性 |
