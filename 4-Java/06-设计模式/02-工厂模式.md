# 工厂模式

## 定义

工厂模式是一种将对象创建逻辑封装到专用类型中，使客户端代码无需了解具体类实现细节的创建型设计模式。其本质是**依赖倒置**——客户端依赖抽象接口而非具体实现，将"如何创建"的责任从客户端转移至工厂。

## 数学模型

### 开闭原则的形式化

开闭原则（Open-Closed Principle）：软件实体应对扩展开放，对修改关闭。

设软件实体 $M$（模块/类），扩展操作 $ext$，修改操作 $mod$：
$$\forall ext: M \rightarrow M' \quad \nexists mod: M \rightarrow M''$$

即：扩展 $M$ 后得到 $M'$，不应通过修改 $M$ 本身，而应通过添加新代码实现。

**工厂模式的 OCP 分析**：

若使用简单工厂，新增产品 $P_{new}$ 需要修改工厂类 $F$：
$$F \xrightarrow{mod} F' \quad \Rightarrow \text{违反 OCP}$$

若使用工厂方法，新增产品 $P_{new}$ 只需新增工厂 $F_{new}$：
$$F_{new} \xrightarrow{ext} \text{FactoryFamily} \quad \Rightarrow \text{符合 OCP}$$

工厂方法将变更的副作用隔离在新增文件中。

### 抽象工厂的产品族兼容性约束

产品族 $\{P_i\}$ 内各产品必须相互兼容。设产品族 $A$（Windows 风格）和产品族 $B$（Mac 风格）：
$$A = \{Button_A, TextField_A\}$$
$$B = \{Button_B, TextField_B\}$$

抽象工厂的**核心约束**：同一工厂创建的产品来自同一族。
$$\forall f \in \{Factory_A, Factory_B\}: \text{产品族}(f) = \text{常量}$$

**违反兼容性的后果**：混用 $Button_A$ 和 $TextField_B$ 导致 UI 风格不一致。

### 工厂方法的复杂度分析

设工厂方法模式有 $n$ 个产品，$m$ 个工厂子类：

| 指标 | 简单工厂 | 工厂方法 |
|------|---------|---------|
| 新增产品修改量 | $O(1)$（但违反 OCP） | $O(1)$ 新增文件 |
| 客户端耦合度 | $O(n)$（需知道所有产品） | $O(1)$（依赖抽象接口） |
| 违反 OCP | 是 | 否 |

**工厂方法将变更的副作用从修改转为扩展**。

**所有权流转**：
- 工厂负责创建产品对象，并将所有权转移给客户端
- 客户端仅持有抽象接口引用，不知道具体产品类名
- 创建逻辑的变更不影响客户端代码

## 机制

### 简单工厂的耦合问题

简单工厂的问题本质：**产品创建逻辑与产品类型数量绑定在同一位置**。

```java
class SimpleFactory {
    static Product create(String type) {
        return switch (type) {
            case "A" -> new ConcreteProductA();
            case "B" -> new ConcreteProductB();
            default -> throw new IllegalArgumentException(type);
        };
    }
}
```

每当产品族 $|ProductFamily|$ 变化时，`SimpleFactory` 必须修改。这违反了 OCP。

**耦合度的度量**：
$$C(F, P_i) = \begin{cases} 1 & \text{if } F \text{ 包含 } P_i \text{ 的创建逻辑} \\ 0 & \text{otherwise} \end{cases}$$

简单工厂的总耦合度随产品数线性增长：$C_{\text{total}} = \sum_i C(F, P_i) = O(n)$。

### 工厂方法的扩展性

工厂方法定义创建产品的抽象接口，将"如何创建"推迟到子类：

```java
interface ProductFactory {
    Product create();
}

class ConcreteFactory implements ProductFactory {
    public Product create() {
        return new ConcreteProduct();  // 子类决定创建什么
    }
}
```

**扩展时不需要修改现有代码**：只需添加新的工厂子类和对应的产品类。现有代码对修改关闭，对扩展开放。

### Lambda 工厂的函数式表达

当工厂接口只有一个方法时，可用 `Supplier<T>` 替代：

```java
// Java 21 Map.of 不可变注册表
Map<String, Supplier<Product>> factory = Map.of(
    "A", ConcreteProductA::new,
    "B", ConcreteProductB::new
);

Product p = factory.get(type).get();
```

**数学本质**：工厂从 **类型→对象** 的映射变为 **字符串→工厂函数** 的映射，消除了工厂接口的语法开销。

**优点**：
- 无需定义接口
- 创建逻辑集中管理
- 支持运行时注册（`HashMap` 版本）

### 抽象工厂的一致性约束

抽象工厂的核心约束：**同一产品族的产品必须配套使用**。

```java
interface GUIFactory {
    Button createButton();
    Menu createMenu();
}

class WindowsFactory implements GUIFactory {
    public Button createButton() { return new WindowsButton(); }
    public Menu createMenu() { return new WindowsMenu(); }
}

class MacFactory implements GUIFactory {
    public Button createButton() { return new MacButton(); }
    public Menu createMenu() { return new MacMenu(); }
}
```

**一致性保证**：每个工厂子类内部定义产品族，跨工厂不混用：
$$\forall f \in \{WindowsFactory, MacFactory\}: \text{产品族}(f) = \text{常量}$$

### 工厂方法与抽象工厂的选择

| 场景 | 推荐模式 | 原因 |
|------|---------|------|
| 产品等级单一，需要灵活扩展 | 工厂方法 | 产品等级单一，只需工厂等级扩展 |
| 产品等级多个，产品族需要一致性 | 抽象工厂 | 保证同族产品配套使用 |
| 简单对象创建，无复杂扩展需求 | 简单工厂 | 开销最小 |

## 参考存根

```java
// 抽象工厂示例：跨数据库访问（Java 21）
interface ConnectionFactory {
    Connection createConnection();
    Statement createStatement();
}

class MySQLFactory implements ConnectionFactory {
    public Connection createConnection() {
        return new MySQLConnection();  // 假设已有实现
    }
    public Statement createStatement() {
        return new MySQLStatement();
    }
}

class OracleFactory implements ConnectionFactory {
    public Connection createConnection() {
        return new OracleConnection();
    }
    public Statement createStatement() {
        return new OracleStatement();
    }
}

// 使用
ConnectionFactory factory = new MySQLFactory();
Connection conn = factory.createConnection();
Statement stmt = factory.createStatement();  // 保证与 Connection 来自同一族

// 函数式工厂注册表（Java 21）
public class ProductFactory {
    private static final Map<String, Supplier<Product>> REGISTERED = new HashMap<>();

    public static void register(String id, Supplier<Product> factory) {
        REGISTERED.put(id, Objects.requireNonNull(factory));
    }

    public static Product create(String id) {
        Supplier<Product> factory = REGISTERED.get(id);
        if (factory == null) {
            throw new IllegalArgumentException("Unknown product: " + id);
        }
        return factory.get();
    }
}

// 使用
ProductFactory.register("A", ConcreteProductA::new);
ProductFactory.register("B", ConcreteProductB::new);
Product p = ProductFactory.create("A");
```
