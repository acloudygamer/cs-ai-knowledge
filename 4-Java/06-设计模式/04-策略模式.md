# 策略模式

## 定义

**策略模式是一种将一系列算法封装为独立类，使它们可以相互替换，让算法独立于使用它的客户端变化的行为型设计模式。**

## 本质断言

- 算法封装在策略类中，与使用算法的上下文分离
- 策略可以运行时替换，客户端无需修改
- 符合开闭原则：新增算法无需修改已有代码

## 机制解释

### 核心问题：避免条件分支

当代码中存在大量`if-else`或`switch`根据类型选择不同算法时，每新增一种算法都需要修改这段代码。这违反了开闭原则——对扩展开放，对修改关闭。

条件分支的根源是：把"做什么"（算法）与"谁来做"（上下文选择）混在一起。

### 策略模式如何解决

将每种算法提取为独立的策略类，策略接口定义算法签名。上下文持有策略引用，调用策略的方法执行算法。客户端决定使用哪种策略，上下文无需关心具体是哪个策略。

<pre>
Context (上下文)
    │
    ├─ 持有 Strategy 引用
    └─ 调用 strategy.execute()
            │
            ├─ ConcreteStrategyA
            ├─ ConcreteStrategyB
            └─ ConcreteStrategyC
</pre>

### 为什么策略模式符合开闭原则

新增算法时，只需新增一个策略类，无需修改已有的策略接口、上下文和客户端代码。上下文对策略封闭，对扩展开放——这正是开闭原则的核心。

### Lambda简化策略

当策略接口只有一个方法时（如`Predicate<T>`、`Comparator<T>`），可以用Lambda表达式替代完整策略类。这减少了类文件数量，但本质上仍是策略模式——只是策略的表示从类变成了函数对象。

## 版本基准

- Stable: Java 21
- Latest: Java 25

## 技术正确性

- ✅ 策略接口应该是细粒度的（单一方法或高度相关方法组）
- ✅ 策略之间应是无状态的或状态隔离的
- ✅ 策略选择可以由工厂或客户端决定

## 策略 vs 状态模式

| 维度 | 策略模式 | 状态模式 |
|------|----------|----------|
| 意图 | 算法互换 | 状态转换自动切换 |
| 切换者 | 客户端外部决定 | 状态内部决定 |
| 策略关系 | 互相独立，可替换 | 有转换关系，按序切换 |

状态模式中，当前状态决定下一个状态和转换行为；策略模式中，客户端决定使用哪个策略，策略之间无顺序关系。

## 适用场景

<pre>
需要多种可互换算法
    │
    ├─ 排序策略（升序、降序、按某字段）
    ├─ 验证策略（邮箱、密码强度、格式）
    ├─ 支付策略（信用卡、PayPal、加密货币）
    ├─ 折扣策略（VIP、学生、节日）
    └─ 压缩策略（ZIP、RAR、GZIP）
</pre>

## 何时不用策略模式

- 算法极少（只有1-2个），且几乎不扩展
- 所有算法总是一起使用，无法独立替换
- 算法极其简单，Lambda足以表达
