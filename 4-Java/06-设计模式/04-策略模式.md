# 策略模式

## 定义

策略模式是一种将一系列算法封装为独立类，使它们可以相互替换，让算法独立于使用它的客户端变化的行为型设计模式。其本质是**算法选择与算法实现的解耦**——将"使用什么算法"的决策权从调用方转移至 Context。

## 数学模型

### 条件分支的复杂度增长

设业务有 $n$ 种可替换算法。若用 `if-else` 或 `switch` 实现：
$$C_{\text{branch}}(n) = O(n) \quad \text{（最坏情况遍历所有分支）}$$

每次新增算法必须修改已有代码，违反 OCP。

若用策略模式：
$$C_{\text{strategy}}(n) = O(1) \quad \text{（Map 查找）}$$

选择逻辑从 $O(n)$ 降为 $O(1)$，新增策略只需新增代码文件。

### 策略组合的代数结构

策略接口构成**幺半群（Monoid）**：

- **结合律**：$S_1 \circ (S_2 \circ S_3) = (S_1 \circ S_2) \circ S_3$
- **单位元**：空策略（什么都不做，返回原值）

```java
interface Strategy<T> {
    T execute(T input);  // 结合律：a.execute(b.execute(c.execute(x)))
    static <T> Strategy<T> identity() { return x -> x; }  // 单位元
}
```

### 策略选择的代价模型

设策略集合 $S = \{s_1, s_2, \ldots, s_n\}$：

| 选择方式 | 时间复杂度 | 空间复杂度 | 特性 |
|---------|-----------|-----------|------|
| if-else | $O(n)$ | $O(1)$ | 违反 OCP |
| Map 查找 | $O(1)$ | $O(n)$ | 运行时可扩展 |
| 策略工厂 | $O(1)$ | $O(n)$ 注册表 | 依赖注入友好 |
| 策略注册表 | $O(1)$ | $O(n)$ | 最灵活 |

## 机制

### 策略与状态模式的本质区别

| 维度 | 策略模式 | 状态模式 |
|------|---------|---------|
| **决策权** | 外部（客户端/Context）决定使用哪个策略 | 内部（状态对象）决定下一个状态 |
| **对象关系** | 策略之间互相独立，无转换关系 | 状态之间有转换关系，按序切换 |
| **可替换性** | 任意时刻可替换 | 转换是确定的，由状态内部逻辑决定 |
| **意图** | 算法可互换 | 对象行为随状态自动变化 |

```
状态模式的状态转换（确定性）：
StateA ──→ StateB（StateA 自己决定，转换逻辑内聚）
StateB ──→ StateC（StateB 自己决定）

策略模式的策略选择（随意性）：
Context ──→ StrategyA（由 Context 或外部决定）
Context ──→ StrategyB（策略之间无转换关系，可任意切换）
```

**关键区分问题**：若切换算法的决策来自对象外部，是策略；若来自对象内部状态，是状态。

### Lambda 对策略模式的简化

当策略接口只有一个方法时，Lambda 表达式将策略从**类**降级为**函数对象**：

```java
// 策略接口
interface ValidationStrategy<T> {
    boolean validate(T value);
}

// 策略实现（类）
class EmailValidator implements ValidationStrategy<String> {
    public boolean validate(String email) {
        return email.contains("@");
    }
}

// 策略实现（Lambda）
ValidationStrategy<String> emailValidator = email -> email.contains("@");
ValidationStrategy<String> lengthValidator = email -> email.length() <= 50;

// 组合验证
List<String> emails = List.of("a@b.com", "invalid");
emails.stream()
    .filter(emailValidator::validate)
    .filter(lengthValidator::validate)
    .forEach(System.out::println);
```

**函数式策略的优势**：
- 语法开销低（无需创建类）
- 可组合（`.andThen()`、`.compose()`）
- 闭包捕获自由变量

### 策略的组合与管道

多个策略可以组合成验证管道：

```java
public class ValidationPipeline<T> {
    private final List<ValidationStrategy<T>> strategies;

    public ValidationPipeline(List<ValidationStrategy<T>> strategies) {
        this.strategies = List.copyOf(strategies);  // 防御性复制
    }

    public boolean validate(T value) {
        for (ValidationStrategy<T> s : strategies) {
            if (!s.validate(value)) {
                return false;  // 短路求值
            }
        }
        return true;
    }

    // 函数式组合
    public static <T> ValidationPipeline<T> allOf(List<ValidationStrategy<T>> strategies) {
        return new ValidationPipeline<>(strategies);
    }
}

// 使用
ValidationPipeline<String> pipeline = ValidationPipeline.allOf(List.of(
    email -> email.contains("@"),
    email -> email.length() <= 50,
    email -> email.matches("^[\\w.-]+@[^\\s]+$")
));
```

### Java 17 模式匹配与策略模式

Java 17 的 pattern matching for `switch` 可视为策略模式的语法糖：

```java
sealed interface PaymentMethod permits CreditCard, PayPal, Crypto {}
record CreditCard(String number) implements PaymentMethod {}
record PayPal(String email) implements PaymentMethod {}
record Crypto(String wallet) implements PaymentMethod {}

PaymentResult pay(PaymentMethod method, double amount) {
    return switch (method) {  // 策略选择的语法糖
        case CreditCard cc -> processCard(cc, amount);
        case PayPal pp -> processPayPal(pp, amount);
        case Crypto c -> processCrypto(c, amount);
    };
}
```

**模式匹配的本质**：编译器生成策略选择的字节码，但语法更简洁。

## 参考存根

```java
// 支付策略完整示例（Java 17）
sealed interface PaymentStrategy permits CreditCardStrategy, PayPalStrategy, CryptoStrategy {
    PaymentResult pay(Order order);
}

final class CreditCardStrategy implements PaymentStrategy {
    private final String cardNumber;
    private final String cvv;

    public CreditCardStrategy(String cardNumber, String cvv) {
        this.cardNumber = cardNumber;
        this.cvv = cvv;
    }

    public PaymentResult pay(Order order) {
        // 信用卡处理逻辑
        return new PaymentResult(true, "paid-by-card:" + cardNumber);
    }
}

final class PayPalStrategy implements PaymentStrategy {
    private final String email;

    public PayPalStrategy(String email) {
        this.email = email;
    }

    public PaymentResult pay(Order order) {
        // PayPal 处理逻辑
        return new PaymentResult(true, "paid-by-paypal:" + email);
    }
}

final class CryptoStrategy implements PaymentStrategy {
    private final String wallet;

    public CryptoStrategy(String wallet) {
        this.wallet = wallet;
    }

    public PaymentResult pay(Order order) {
        // 加密货币处理逻辑
        return new PaymentResult(true, "paid-by-crypto:" + wallet);
    }
}

// Context（支付上下文）
class PaymentContext {
    private PaymentStrategy strategy;

    public PaymentContext(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    public void setStrategy(PaymentStrategy strategy) {
        this.strategy = Objects.requireNonNull(strategy);
    }

    public PaymentResult checkout(Order order) {
        return strategy.pay(order);
    }
}

// 使用
PaymentContext ctx = new PaymentContext(new CreditCardStrategy("1234", "123"));
ctx.checkout(order);

// 运行时切换
ctx.setStrategy(new PayPalStrategy("user@example.com"));
ctx.checkout(order);

// Spring DI 环境
@Service
class PaymentService {
    private final Map<String, PaymentStrategy> strategies;

    public PaymentService(Map<String, PaymentStrategy> strategies) {
        this.strategies = Map.copyOf(strategies);
    }

    public PaymentResult checkout(Order order, String type) {
        PaymentStrategy strategy = strategies.get(type);
        if (strategy == null) {
            throw new IllegalArgumentException("Unknown payment: " + type);
        }
        return strategy.pay(order);
    }
}
```
