# 责任链模式

## 定义

**责任链模式是一种通过将请求沿着处理者链传递，直到某个处理者处理它，从而解除请求发送者与接收者之间耦合的行为型设计模式。**

## 本质断言

- 每个处理者持有下一个处理者的引用
- 处理者决定：自己处理请求，或把请求传递给下一个
- 请求发送者不知道最终由哪个处理者处理

## 机制解释

### 核心问题：请求者与接收者强耦合

当一个请求可能被多个对象之一处理时（如审批流程：经理→总监→总经理），常见的反模式是在请求者中硬编码处理顺序。这导致请求者需要知道所有处理者的存在和顺序，违背了单一职责原则。

### 责任链如何解耦

把"由谁处理"的决策从请求者转移到处理者。请求者只发出请求，不知道也不关心谁会处理它。每个处理者持有下一个处理者的引用，可以选择处理请求或传递给下一个。

<pre>
Request → AuthHandler → LoggingHandler → ValidationHandler
              │                │                  │
         能处理则处理      继续传递            继续传递
         不能处理则传递     不能处理则传递
</pre>

### 两种处理方式

| 方式 | 描述 | 适用场景 |
|------|------|----------|
| 选择性传递 | 处理者判断能否处理，能则处理，不能则传递 | 审批流程、权限校验 |
| 全部处理 | 每个处理者都执行自己的逻辑，然后传递 | 日志记录、性能监控 |

### 为什么比直接调用更灵活

- 新增/移除处理者只需修改链的构建方式，不影响请求者
- 处理者可以动态调整顺序
- 单个处理者可以独立测试

## 版本基准

- Stable: Java 21
- Latest: Java 25

## 技术正确性

- ✅ Servlet Filter是责任链模式的企业级应用
- ✅ Spring Security Filter Chain是责任链模式的典型案例
- ✅ 链的顺序很重要，需要明确

## 适用场景

<pre>
请求需要多个处理者之一处理
    │
    ├─ Web请求过滤（认证、日志、编码）
    ├─ 审批流程（经理→总监→总经理）
    ├─ 权限校验（功能权限→数据权限）
    └─ 事件传播（冒泡捕获）
</pre>

## 责任链 vs 命令模式

| 维度 | 责任链 | 命令模式 |
|------|--------|----------|
| 意图 | 请求传递 | 请求封装 |
| 传递 | 链式传递 | 单次执行 |
| 处理 | 处理者决定处理或传递 | 命令对象持有接收者 |
</pre>
