# 安全编码

> 前置：[11-GraalVM与云原生](11-GraalVM与云原生.md)、[05-JDBC](../05-IO与外部世界/05-JDBC.md)（SQL 注入的防御机制所在层） · 后续：无（08 目录末篇）

> **版本基准**：OWASP Top 10 以 2025 版为现行口径（RC 2025-11 发布，2026-01 定稿）；Security Manager 状态以 JEP 486（JDK 24，2025-03）为准。代码示例为**骨架，未实测**。

本篇讨论的漏洞共享同一个成因结构：**攻击者控制的输入越过了数据与代码之间的边界，被当成了代码执行**。SQL 注入、命令注入、反序列化漏洞、XSS 是同一家族的四个物种——防御也都指向同一方向：让边界重新变得清晰（结构与数据分离、最小权限、默认拒绝）。

## 机制

### SQL 注入：拼接突破词法边界

`"SELECT * FROM user WHERE name = '" + input + "'"` 中，`input` 先被拼进字符串，再整体送进 SQL 词法分析器——输入里的 `'` 闭合了字面量，后续文本升格为 SQL 语法。攻击的本质是**数据通道与代码通道的合并**。

`PreparedStatement` 的防御不是"转义得更聪明"，而是把两个通道物理分开（[05-JDBC](../05-IO与外部世界/05-JDBC.md)）：SQL 文本先编译（结构定型），参数后绑定（只作字面数据，永不进词法分析器）。两个推论：

- MyBatis 里 `#{}` 走参数绑定（安全），`${}` 是文本替换（拼接，等同裸 JDBC 字符串拼接）——`${}` 的唯一合法用途是表名/列名/排序方向这类**无法参数化的标识符**，且必须配白名单校验（见 [02-持久化框架](02-持久化框架.md)）。
- ORM 不免疫：手写 JPQL 里字符串拼接照样可注入，绑定参数是唯一解。

### 命令注入：shell 是那层多出来的解释器

`Runtime.exec("ping " + host)` 在 Windows/Unix 都会经过一层命令解释，`host` 里的 `;` `&&` `|` 被解释器当语法。防御链：

1. `ProcessBuilder` 以**参数数组**传参，不经 shell——每个数组元素是一个字面参数；
2. 输入仍要白名单校验（参数数组防得住 shell 语法，防不住被调程序自身的选项注入，如 `host` 变成 `-oProxyCommand=...`）。

### 反序列化：readObject 是隐藏的代码执行面

Java 原生序列化的危险在机制深处：`ObjectInputStream.readObject()` 恢复对象时**绕过构造器**直接重建字段，并回调类自定义的 `readObject()`——而攻击者控制字节流，等于可以指定"实例化哪些类、按什么顺序、触发哪些回调"。只要 classpath 上存在可被串联成危险动作（最终执行命令/任意文件写）的类——**gadget chain（利用链）**——攻击载荷就能远程执行代码。fastjson/Jackson 的多态反序列化、Apache Commons Collections 链、Log4Shell（CVE-2021-44228，Log4j2 的 JNDI 查找把日志内容变成远程类加载）都是这个机制的不同触发点。

防御按可靠性排序：

1. **不用 Java 原生序列化传不可信数据**——跨边界传输一律 JSON 等纯数据格式；
2. 必须用时启用**反序列化过滤器**（JEP 290，JDK 9+；JEP 415 上下文过滤器，JDK 17+）：`ObjectInputFilter` 按类名白名单、图深度、字节数限制反序列化范围；
3. Jackson 等库关闭默认多态（`enableDefaultTyping` 永不开），用显式的多态类型注册。

### Security Manager：一个时代的落幕

Security Manager 本是"在 JVM 内给代码划权限"的沙箱机制（为 Applet 时代设计）：JDK 17 标记废弃，**JDK 24（2025-03）经 JEP 486 永久禁用**——`System.setSecurityManager` 直接抛异常，`System.getSecurityManager()` 恒为 `null`。教训有两层：

- 依赖 SecurityException 拦截敏感操作的旧代码**静默失效**（不再抛异常，直接放行）——升级 JDK 24+ 前必须审计这类隐式依赖；
- 代码级隔离的职责整体移交平台层：容器（[09-容器与K8s](09-容器与K8s.md) 的 namespace/cgroup）、OS 用户权限、seccomp——"别把不可信代码和自己的代码放进同一进程"成为唯一可靠边界。

### OWASP Top 10 的 Java 落点

2025 版相对 2021 版：A01 访问控制失效蝉联榜首；安全配置错误升至 A02；新增 A03 软件供应链失效（扩展了"含漏洞组件"）；A10 异常状况处理不当（fail-open 逻辑）首次入选；SSRF 并入 A01。逐项的 Java 落点：

| OWASP 2025 | Java 侧的典型落点 | 防线 |
|---|---|---|
| A01 访问控制失效 | 只在前端藏按钮、后端不鉴权；URL 参数改 id 越权 | 服务端逐请求授权（[07-SpringSecurity](07-SpringSecurity.md) 的方法级 `@PreAuthorize`）；对象归属校验 |
| A02 安全配置错误 | Actuator 端点裸奔、默认口令、生产开 `show-sql` | 配置基线审计；Actuator 单独端口 + 认证 |
| A03 供应链失效 | 传递依赖带洞（Log4Shell 即此类） | 依赖锁定 + OWASP Dependency-Check / SBOM；私有仓库代理审核 |
| A04 加密失效 | MD5/SHA-1 存口令、ECB 模式、硬编码密钥 | BCrypt/Argon2 存口令；AES-GCM（随机 IV）；密钥进 KMS/环境注入 |
| A05 注入 | 上文三小节 | 参数化/白名单/格式化输出 |
| A10 异常处理不当 | `catch` 后默认放行、错误页泄露栈/SQL | 默认拒绝；对外通用错误信息，细节只进日志 |

### 清单（每次提交前自问）

1. 所有 SQL 走参数绑定？`${}`/字符串拼接处有没有白名单？
2. 外部输入（含 Header、Cookie、文件名、反序列化体）都过了显式校验？
3. 口令用 BCrypt/Argon2？密钥不在代码与配置仓库里？
4. 越权检查在服务端每个入口？还是只在网关/前端？
5. 依赖有没有锁定版本并过漏洞扫描？新引入的传递依赖看过了吗？
6. 错误响应对外是否脱敏（无栈、无 SQL、无内部路径）？
7. 日志里有没有口令、令牌、身份证号这类不该出现的字段？
8. 跑在 JDK 24+？代码里是否残留 SecurityManager/AccessController 的隐式依赖？
