# 观察者模式

## 定义

观察者模式是一种定义对象间一对多依赖关系，当一个对象（主题）状态改变时，所有依赖它的对象（观察者）都会自动收到通知的响应型设计模式。其本质是**状态变化的事件传播**——将"状态变化"这一事件广播给所有订阅者，无需知晓订阅者的具体身份。

## 数学模型

### 订阅关系的集合论建模

设主题集合 $S$ ，观察者集合 $O$ 。订阅关系是笛卡尔积的子集： ，观察者集合 $O$ 。订阅关系是笛卡尔积的子集： 。订阅关系是笛卡尔积的子集：
 $\text{Subscribe} \subseteq S \times O$ 

主题 $s$ 广播通知时： 广播通知时：
 $\forall o \in O: (s, o) \in \text{Subscribe} \Rightarrow o.\text{notify}()$ 

订阅/取消订阅操作：
 $\text{subscribe}(s, o) \Rightarrow \text{Subscribe} \cup \{(s, o)\}$ 
 $\text{unsubscribe}(s, o) \Rightarrow \text{Subscribe} \setminus \{(s, o)\}$ 

### 通知顺序的不确定性

在并发环境下，观察者集合的迭代顺序不确定：
 $\text{order}(\text{observers}) \neq \text{deterministic}$ 

不应依赖观察者的通知顺序——这是**时序耦合**的陷阱。

### 发布-订阅的拓扑结构

| 维度 | 观察者模式 | 发布-订阅 |
|------|-----------|----------|
| 拓扑 | 星型（主题-观察者直接通信） | 中间件介导的网状拓扑 |
| 耦合 | 同步，紧耦合 | 异步，解耦 |
| 消息路径 | $O(n)$ 直接通知 | $O(n)$ 经由 Broker | 直接通知 | $O(n)$ 经由 Broker | 经由 Broker |
| 位置关系 | 同进程 | 可跨进程/机器 |

发布-订阅是观察者模式的**分布式变体**，通过引入消息中间件（Kafka、RabbitMQ）解耦发布者和订阅者。

**数据所有权**：
- Subject 持有观察者列表的所有权（通过引用）
- 观察者不持有 Subject 的引用（单向依赖）
- 通知传递的是数据副本或只读引用，避免观察者修改影响 Subject 状态

## 机制

### 推模式 vs 拉模式

**推模式（Push）**：主题主动推送变化数据
```java
void update(Data data) {  // 接收推送的数据
    this.data = data;    // 直接使用推送的数据
}
```

**拉模式（Pull）**：主题只通知变化，观察者按需获取
```java
void update() {
    Data data = subject.getData();  // 主动拉取所需数据
}
```

| 维度 | 推模式 | 拉模式 |
|------|--------|--------|
| 效率 | 高（推送具体数据） | 低（可能多次查询） |
| 耦合 | 紧（观察者需知道数据结构） | 松（只依赖主题接口） |
| 适用 | 数据量小、变化频繁 | 数据量大、变化少 |

### 发布-订阅与观察者模式的拓扑区别

| 维度 | 观察者模式 | 发布-订阅 |
|------|-----------|----------|
| 通信方式 | 直接通信（同步） | 通过中间件（可异步） |
| 拓扑 | 星型（主题-观察者） | 网状（发布者-订阅者-中间件） |
| 部署 | 同进程 | 可跨进程/机器 |
| 中间件 | 无 | Kafka/RabbitMQ/Redis |

**发布-订阅的核心优势**：
- 物理解耦：发布者和订阅者无需知道对方存在
- 空间解耦：无需同时在线
- 时间解耦：消息可暂存于 Broker

### Java Observable 的设计缺陷与替代

`java.util.Observable`（已废弃）的设计缺陷：

1. **非线程安全**：观察者列表的修改在并发下不安全
2. **单继承限制**：`Observable` 是类，Java 单继承导致使用时必须继承它
3. **方法 protected**：只有子类能调用 `setChanged()`，无法在外部控制状态变化

**推荐替代**：`PropertyChangeSupport`（JavaBeans 规范的一部分）

```java
public class ObservableBean {
    private final PropertyChangeSupport support = new PropertyChangeSupport(this);
    private String value;

    public void addPropertyChangeListener(PropertyChangeListener l) {
        support.addPropertyChangeListener(l);
    }

    public void removePropertyChangeListener(PropertyChangeListener l) {
        support.removePropertyChangeListener(l);
    }

    public void setValue(String newValue) {
        String old = this.value;
        this.value = newValue;
        support.firePropertyChange("value", old, newValue);
    }
}
```

### 观察者的责任与取消订阅

观察者的**单一职责**：观察者只负责响应通知，不应承担额外业务逻辑。

**取消订阅的重要性**：

若 $o \in \text{Subscribe}$ 但不再需要通知： 但不再需要通知：
 $o.\text{notify}() \text{ 浪费计算资源}$ 

长期不取消订阅会导致**内存泄漏**：
- 主题持有观察者引用
- 主题生命周期长于观察者
- 观察者无法被 GC 回收

**Java 21 WeakHashMap 方案**：使用弱引用持有观察者，自动避免内存泄漏。

## 参考存根

```java
import java.beans.PropertyChangeListener;
import java.beans.PropertyChangeSupport;
import java.util.concurrent.CopyOnWriteArrayList;

// 基础观察者接口
interface Observer {
    void update(String message);
}

// 主题实现（线程安全）
class Subject {
    private final CopyOnWriteArrayList<Observer> observers = new CopyOnWriteArrayList<>();

    public void subscribe(Observer o) {
        observers.add(o);
    }

    public void unsubscribe(Observer o) {
        observers.remove(o);
    }

    public void notifyObservers(String message) {
        for (Observer o : observers) {
            o.update(message);  // 迭代快照，线程安全
        }
    }
}

// 观察者实现
class NewsAgency implements Observer {
    private final String name;

    NewsAgency(String name) {
        this.name = name;
    }

    public void update(String message) {
        System.out.println(name + " received: " + message);
    }
}

// 使用
Subject subject = new Subject();
Observer alice = new NewsAgency("Alice");
Observer bob = new NewsAgency("Bob");

subject.subscribe(alice);
subject.subscribe(bob);
subject.notifyObservers("Breaking: Java 21 released!");
// 输出顺序不确定

// PropertyChangeSupport 实现（JavaBeans 风格，推荐）
class ObservableBean {
    private final PropertyChangeSupport support = new PropertyChangeSupport(this);
    private String value;

    public void addPropertyChangeListener(PropertyChangeListener l) {
        support.addPropertyChangeListener(l);
    }

    public void removePropertyChangeListener(PropertyChangeListener l) {
        support.removePropertyChangeListener(l);
    }

    public void setValue(String newValue) {
        String old = this.value;
        this.value = newValue;
        support.firePropertyChange("value", old, newValue);
    }

    public String getValue() {
        return value;
    }
}

// 使用 PropertyChangeSupport
ObservableBean bean = new ObservableBean();
bean.addPropertyChangeListener(evt ->
    System.out.println("Changed: " + evt.getPropertyName() +
        " from " + evt.getOldValue() + " to " + evt.getNewValue())
);
bean.setValue("newValue");
```
