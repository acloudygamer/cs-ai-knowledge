# 设计模式总览

> 前置：[05-面向对象](../01-语言核心/05-面向对象.md)（封装/继承/多态）、[08-Lambda与函数式接口](../01-语言核心/08-Lambda与函数式接口.md) · 后续：[02-单例模式](./02-单例模式.md)

> **版本基准**：Java 21 stable / Java 25 latest（均为 LTS）。设计模式的问题域大体版本无关，但实现手法随语言特性演进——本篇各例以 `javac -encoding UTF-8 --release 21`（Temurin JDK 25.0.4.1，Windows）实测。

## 本质

设计模式（Design Pattern）是对**反复出现的结构问题**的命名解法：GoF（Gang of Four，1994 年《设计模式》四位作者）归纳了 23 个。每个模式的内核是同一个动作——**找到代码里会变的那个点，把它封装到一个可以替换的位置上**。变化点不同，模式不同：

- 实例的**数量**会变（全局只许一个）→ 单例
- 实例的**类型**会变（创建哪个子类）→ 工厂
- 构造的**参数组合**会变 → 建造者
- 执行的**算法**会变 → 策略
- 状态变化后的**通知对象集合**会变 → 观察者
- 对象的**附加职责**会变 → 装饰器
- 对接的**接口形状**会变 → 适配器
- 请求的**处理器序列**会变 → 责任链

所以模式不是背诵的类图，而是"变化点 → 封装方向"的对照表。判断一个模式用没用对，问一句：它封装的变化点真的存在吗？不存在的变化点套上模式，得到的是没有收益的中间层。

## 三分法的问题域

GoF 按变化点所在的位置把 23 个模式分为三类：

| 类别 | 封装的层次 | 回答的问题 | 本目录覆盖 |
|---|---|---|---|
| 创建型 | 对象怎么来 | 实例化逻辑与使用逻辑分离 | [02-单例](./02-单例模式.md)、[03-工厂](./03-工厂模式.md)、[04-建造者](./04-建造者模式.md) |
| 结构型 | 对象怎么拼 | 类与对象的组合方式（接口转换、职责叠加） | [07-装饰器](./07-装饰器模式.md)、[08-适配器](./08-适配器模式.md) |
| 行为型 | 对象怎么交互 | 算法、通知、请求在对象间的流动 | [05-策略](./05-策略模式.md)、[06-观察者](./06-观察者模式.md)、[09-责任链](./09-责任链模式.md) |

三类的边界就是变化点的边界：创建型管"new 谁"，结构型管"谁包谁"，行为型管"谁通知谁"。

## 模式与语言特性的关系：一批模式被语言吃掉了

GoF 写书时的语境是 C++98/Smalltalk——没有 Lambda、没有接口默认方法、没有模式匹配。Java 每吸收一种语言特性，就有一批模式从"手写骨架"退化为"一次调用"：

| 语言特性（转正版本） | 被内化的模式 | 内化后的形态 |
|---|---|---|
| Lambda / 函数式接口（Java 8） | 策略、命令 | 策略从"类"退化为函数对象：`Comparator.comparing(String::length)` 就是一个策略（实测对比见 [05-策略模式](./05-策略模式.md)） |
| 接口 `default` 方法（Java 8） | 适配器的"空实现基类"写法 | 接口自带默认空实现，不再需要 `XxxAdapter` 抽象类（见 [08-适配器模式](./08-适配器模式.md)） |
| record（Java 16） | 建造者的部分场景 | 参数少且全必填的对象，record 一行取代 Builder（见 [04-建造者模式](./04-建造者模式.md)） |
| sealed + switch 模式匹配（Java 21） | 访问者、策略的"按类型分派"形态 | `switch` 直接对密封层级穷尽分派，编译器检查遗漏分支（见 [05-策略模式](./05-策略模式.md)） |

没被打勾的模式（观察者、装饰器、责任链、工厂）不是写得不好，而是它们的复杂度来自**运行时的对象拓扑**——订阅关系在运行时增删、装饰层数在运行时决定、处理器链在运行时组装——编译期的语言特性帮不上忙，它们至今仍是活模式。

## 本目录的读法

每篇的结构相同：先给一句话本质定义（它封装哪个变化点），再给 JDK/框架里的真实实例（模式不是教科书玩具，`java.io`、`Arrays.asList`、Servlet Filter 都是），最后给 Java 21 实测的可运行 demo。模式之间的辨析（装饰器 vs 代理 vs 适配器、策略 vs 状态）放在各自篇内，不在此重复。
