# 类与接口

> 前置：[02-枚举与字面量类型](./02-枚举与字面量类型.md) · 后续：[04-类型收窄与控制流分析](./04-类型收窄与控制流分析.md)

> **版本基准**：**TypeScript 7.0.2**（`tsgo`），Node v24.13.1，Windows x64。

## 本质

TypeScript 给 JavaScript 的 `class`（见 [5-JavaScript/01-语言核心/05-对象与类](../5-JavaScript/01-语言核心/05-对象与类.md)）加了两类东西：**纯类型层的约束**（`implements`、访问修饰符、`abstract`、`satisfies`——全部擦除）与**改变产物的语法**（参数属性——会在产物里生成字段声明与赋值）。区分的标准仍是 [02-枚举与字面量类型](./02-枚举与字面量类型.md) 的那句：它在产物里留不留东西。

## 机制

### `implements`：声明处的形状检查

```console
$ npx typescript@latest --noEmit impl.ts
impl.ts(2,7): error TS2420: Class 'User' incorrectly implements interface 'Serializable'.
  Property 'toJSON' is missing in type 'User' but required in type 'Serializable'.
```

```typescript
interface Serializable { toJSON(): string }
class User implements Serializable {
  constructor(public name: string) {}
}
```

`implements` 不做任何继承——`User` 不会从 `Serializable` 得到任何成员。它只是在**声明处**加一次形状核对：你承诺这个类有这个形状，编译器当场验收。由于类型系统本身是结构式的（见 [01-类型系统基础](./01-类型系统基础.md)），不写 `implements` 也不影响赋值兼容性；`implements` 的价值是**把笔误拦在类定义现场**，而不是等它流到使用处。

### 访问修饰符 vs `#`：谁真的私有

```console
$ npx typescript@latest cls.ts --target es2022 --outDir out && node out/cls.js
0
undefined
[ 'id', 'balance' ]
```

```typescript
class Account {
  private balance: number = 0;
  #pin: string = "1234";
  constructor(public readonly id: string) {}
  deposit(n: number) { this.balance += n; }
}
const a = new Account("a1");
console.log((a as any).balance);      // 0——private 擦除后运行时可访问
console.log((a as any)["#pin"]);      // undefined——# 字段不是字符串键
console.log(Object.keys(a));          // [ 'id', 'balance' ]——#pin 不可枚举
```

`private` 是类型层护栏：编译产物里 `balance` 是普通字段，运行时随意访问。`#pin` 是 ECMA-262 的**真私有字段**（见 [5-JavaScript/01-语言核心/05-对象与类](../5-JavaScript/01-语言核心/05-对象与类.md)），由引擎强制，产物里原样保留。**编译期防护用 `private`，运行时防护用 `#`**。`readonly` 同理——只在编译期禁止赋值，产物无痕迹。

### 参数属性：会改产物的简写

```console
$ npx typescript@latest pp.ts --target es2022 --outDir out && cat out/pp.js
"use strict";
class Vec {
    x;
    y;
    constructor(x, y) {
        this.x = x;
        this.y = y;
    }
}
```

```typescript
class Vec { constructor(public x: number, public y: number) {} }
```

构造参数上的 `public` 让编译器**生成字段声明与赋值**——产物比手写标注多出行。所以参数属性与 `enum` 一样被 `--erasableSyntaxOnly` 拒绝（error TS1294，见 [02-枚举与字面量类型](./02-枚举与字面量类型.md)）：单文件转译器只做逐行擦除，处理不了"参数变字段"这种重排。

### `satisfies`：检查而不拓宽

```typescript
const palette = { red: [255, 0, 0], green: "00ff00" }
  satisfies Record<string, [number, number, number] | string>;
const g: string = palette.green;   // 通过：green 的类型仍是字面量 "00ff00"
```

直接写标注 `const palette: Record<string, ...> = {...}` 会把每个属性拓宽到标注类型，`palette.green` 只剩 `string | number[]`；`satisfies` 只做**兼容性验收**，推断结果保持精确。配置对象、主题表这类"既要符合协议、又要保留每个键的精确类型"的场景用它。

### 接口合并：interface 独有

```typescript
interface Box { w: number }
interface Box { h: number }        // 合并：Box = { w, h }
const b: Box = { w: 1, h: 2 };     // 通过
```

同名 `interface` 自动合并，同名 `type` 别名报错。这条不对称决定了分工：**库的公共类型用 `interface`**——使用方可以通过声明合并往上面补成员（`@types` 包给全局对象打补丁就靠它，见 [07-声明文件与互操作](./07-声明文件与互操作.md)）；组合变换用 `type`（交叉、联合、映射都在 `type` 一侧，见 [06-泛型与类型编程](./06-泛型与类型编程.md)）。

### `abstract`：只活在编译期的契约

`abstract class` 与抽象方法全部擦除，产物里就是普通类。它阻止的只有一件事：`new` 一个抽象类在编译期报错。运行时没有对应的实体。

## 连接：两层防护的分工

| 写法 | 层 | 产物 | 防护生效时机 |
|---|---|---|---|
| `implements` | 类型层 | 零 | 类声明处 |
| `private` / `readonly` | 类型层 | 零 | 编译期 |
| `#` 私有字段 | 语言层（ECMA-262） | 保留 | 运行时，引擎强制 |
| 参数属性 | **改产物** | 生成字段 | —（是语法糖不是防护） |
| `satisfies` | 类型层 | 零 | 表达式现场 |
| `interface` 合并 | 类型层 | 零 | 编译期 |

## 边界

- **`private` 不防运行时**：反射、序列化、`as any` 都穿得过；要真私有用 `#`。
- **`implements` 不继承实现**：它只是一次声明处验收。
- **参数属性不是纯类型语法**：产物会多出字段，单文件转译链（`erasableSyntaxOnly`、Node strip-only）下禁用。
- **接口合并只对 `interface` 生效**：`type` 别名重名即报错。
- **抽象类运行时是普通类**：`abstract` 拦不住运行时的 `new`（如反序列化框架绕过类型直接构造）。
