# 泛型与类型编程

> 前置：[05-装饰器](./05-装饰器.md) · 后续：[07-声明文件与互操作](./07-声明文件与互操作.md)

> **版本基准**：TypeScript 7.0.2。本篇示例实测环境：Node v24.13.1，`npx typescript@latest`，Windows x64。

## 本质

TypeScript 的类型层不是"标注"，而是一套**完整的编程语言**，与值层平行存在：

| 值层的概念 | 类型层的对应物 |
|---|---|
| 变量 | 类型参数 `<T>` |
| 函数 | 泛型类型 / 泛型函数 |
| 参数约束 | `T extends U` |
| 条件分支 | 条件类型 `T extends U ? X : Y` |
| 循环 | 递归类型 |
| 字符串操作 | 模板字面量类型 |
| 解构 | `infer` |

它在**编译期求值**，产物中不留任何痕迹（见 [01-类型系统基础](./01-类型系统基础.md) 的类型擦除）。所以类型编程的收益是"把约束前移到编译期"，代价是**类型本身的可读性与编译耗时**。

## 机制

### 泛型与约束

```typescript
function pick<T, K extends keyof T>(o: T, k: K): T[K] { return o[k]; }
const r = pick({ a: 1, b: "x" }, "b");   // r 推断为 string
```

`<T, K extends keyof T>` 表达的是"`K` 必须是 `T` 的键之一"。返回类型 `T[K]` 是**索引访问类型**——取 `T` 上键 `K` 对应的类型。三者合起来的效果是：`pick(obj, "b")` 返回 `string`，而 `pick(obj, "c")` 直接报错。

**`extends` 在类型层的含义是"可赋值给"，不是继承**。这与 [01-类型系统基础](./01-类型系统基础.md) 的结构化类型同源。

### 条件类型与分发

```typescript
type IsString<T> = T extends string ? true : false;
```

条件类型有一个反直觉的行为：**传入联合类型时会逐个分发**。

```typescript
type ToArray<T> = T extends unknown ? T[] : never;
// ToArray<"a" | "b"> 得到 "a"[] | "b"[]，而不是 ("a" | "b")[]

type ToArrayNoDist<T> = [T] extends [unknown] ? T[] : never;
// 用元组包裹，阻止分发，得到 ("a" | "b")[]
```

分发在需要时很有用（对联合的每个成员分别处理），不需要时是个陷阱。**用 `[T] extends [U]` 包裹即可关闭**。

### 映射类型与修饰符

映射类型对对象类型的每个键做变换：

```typescript
type Optional<T> = { [K in keyof T]?: T[K] };            // 加可选
type Mutable<T> = { -readonly [K in keyof T]-?: T[K] };  // 去 readonly、去可选
```

`-` 前缀**移除**修饰符（`-readonly`、`-?`），`+` 或不写是添加。标准库里的 `Partial`、`Required`、`Readonly`、`Pick`、`Omit` 都是这一族。

**键重映射**（`as` 子句）让键本身也能被改写：

```typescript
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
// Getters<{ name: string }> 得到 { getName: () => string }
```

### `infer`：在类型里做模式匹配

`infer` 声明一个"待推断的类型变量"，从结构里把它提取出来：

```typescript
type Unwrap<T> = T extends Promise<infer U> ? U : T;          // Unwrap<Promise<string>> = string
type UnwrapArr<T> = T extends (infer U)[] ? U : never;        // UnwrapArr<number[]> = number
```

它是"从已有类型反推组成部分"的唯一手段，标准库的 `ReturnType`、`Parameters`、`Awaited` 都基于它。

### 递归类型

类型可以引用自身，实现"对每个嵌套层级做同样处理"：

```typescript
type DeepReadonly<T> = { readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K] };
```

递归深度有上限，且**深度越大编译越慢**——这是类型编程的主要成本。

### 模板字面量类型

```typescript
type Ev = `on${Capitalize<"click" | "focus">}`;   // "onClick" | "onFocus"
```

类型层的字符串操作（`Capitalize`、`Uppercase`、`Lowercase`、`Uncapitalize` 与 `infer` 配合）能解析字符串结构，常用于给事件名、路由路径、CSS 属性名做类型。

### 可辨识联合与穷尽检查

给联合的每个成员一个**字面量判别属性**，分支里就能收窄：

```typescript
type Shape = { kind: "circle"; r: number } | { kind: "square"; s: number };

function area(sh: Shape): number {
  switch (sh.kind) {
    case "circle": return Math.PI * sh.r ** 2;
    case "square": return sh.s ** 2;
    default: { const _never: never = sh; return _never; }   // 穷尽检查
  }
}
```

`default` 分支里把 `sh` 赋给 `never`——**只有当所有成员都被处理过时，`sh` 的类型才会收窄为 `never`**。将来给 `Shape` 加一个新成员，这个赋值会立刻报错，逼你补上分支。这是"新增枚举值时漏处理"这类 bug 的编译期防线。

### 验证方法：类型层断言

类型编程的结果**没有运行时输出可看**，怎么验证？用一组类型层断言：

```typescript
type Expect<T extends true> = T;
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;

type _1 = Expect<Equal<IsString<"x">, true>>;
```

`Expect` 要求参数必须是 `true`——断言不成立时参数是 `false`，直接编译失败。实测：

```console
$ npx typescript@latest --strict --noEmit tp.ts
（退出码 0，11 条断言全部成立）

$ # 故意把 Equal<IsString<1>, false> 改成 Equal<IsString<1>, true>
$ npx typescript@latest --strict --noEmit tp_bad.ts
tp_bad.ts(12,18): error TS2344: Type 'false' does not satisfy the constraint 'true'.
```

**这是验证复杂类型工具的唯一可靠手段**，应随类型工具一起维护。`Equal` 用双重泛型比较（而非 `A extends B` 双向）是为了区分 `any`、`never` 与具体类型——双向 `extends` 在这些边界上会误判。

## 连接：类型编程能力对照

| 需求 | 手段 |
|---|---|
| 参数类型由另一个参数决定 | 泛型 + `keyof` |
| 按类型分派 | 条件类型 |
| 批量变换对象键 | 映射类型 |
| 改名或增删键 | 键重映射（`as`） |
| 从既有类型提取部分 | `infer` |
| 处理嵌套结构 | 递归类型 |
| 约束字符串格式 | 模板字面量类型 |
| 保证分支完整 | 可辨识联合 + `never` |

## 边界

- **类型编程有可读性成本**：一段复杂的条件类型比等价的运行时逻辑更难懂。**只在收益明确时使用**。
- **递归有深度上限，且越深编译越慢**：深递归类型会让编辑器卡顿。
- **分发行为需要留意**：不确定时用 `[T] extends [U]` 关闭。
- **`extends` 是"可赋值给"不是继承**：与名义类型语言的直觉不同。
- **类型工具必须有测试**：用类型层断言覆盖，否则改动后无从验证。
- **类型不能替代运行时校验**：外部数据仍需验证（见 [01-类型系统基础](./01-类型系统基础.md)）。
