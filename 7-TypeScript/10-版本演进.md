# 版本演进

> 前置：[09-项目组织与增量编译](./09-项目组织与增量编译.md) · 后续：（章末）

> **版本基准**：写作时（2026-09）npm `typescript@latest` = 7.0.2；`next` = 7.1 nightly。本篇日期均以 npm 发布记录为锚。

## 本质

TypeScript 的版本演进围绕一条主轴：**类型系统表达力的扩张已经放缓，近年的大动作在编译器本身**——5.x 把语言特性补齐到"够用"，6.0 做行为对齐的过渡，7.0 换掉实现（Go 重写的 `tsgo`）。读变更的顺序因此是：先看动的是语言层还是实现层，语言层的变化影响你怎么写，实现层的变化影响你等多长时间。

## 机制

### 5.x：补齐表达力（2023-03 ~ 2025-07）

| 版本 | 发布 | 关键变化 |
|---|---|---|
| 4.9 | 2022-11 | `satisfies`——检查而不拓宽（见 [03-类与接口](./03-类与接口.md)） |
| 5.0 | 2023-03 | TC39 标准装饰器落地（见 [05-装饰器](./05-装饰器.md)）；`const` 类型参数 |
| 5.2 | 2023-08 | `using` / `await using`（ES2027 提案的提前落地） |
| 5.5 | 2024-06 | 推断类型谓词——`filter` 等回调的收窄不再要求手写 `x is T`（见 [04-类型收窄与控制流分析](./04-类型收窄与控制流分析.md)） |
| 5.8 | 2025-02 | `--erasableSyntaxOnly`——只允许可擦除语法（见 [02-枚举与字面量类型](./02-枚举与字面量类型.md)） |
| 5.9 | 2025-07 | 5.x 收官；`tsc --init` 生成的配置转向现代默认 |

这条线索的形状很清楚：越到后期，变化越偏向**工具链契约**（erasableSyntaxOnly、init 默认值）而非新类型语法——为实现的替换清场。

### 6.0：过渡版本（2026-03）

6.0 是最后一个 TypeScript 编译器（自托管代码库）的版本，使命是**把行为对齐到 7.0**：废弃项集中移除、默认值向新编译器靠拢。从 5.9 升级到 7.0 的官方路径是先过 6.0——它把破坏性变化分批释放，避免一次性断裂。

### 7.0：Go 重写（2026-07）

微软 2025-03 公布重写计划（"Project Corsa"），2026-07-08 发布 7.0.2。编译器从 TypeScript 自托管实现换成 Go 原生实现（`tsgo`），官方口径是**约 10 倍编译提速**——收益来自原生代码加共享内存并行，自托管实现受 JavaScript 单线程与 GC 的双重限制（约束链见 [5-JavaScript/07-引擎与性能/01-引擎架构与 JIT](../5-JavaScript/07-引擎与性能/01-引擎架构与JIT.md)）。

伴随重写的默认值变更（本篇写作时生效，实测见各篇）：

- **`strict` 默认 `true`**（见 [08-编译配置与严格模式](./08-编译配置与严格模式.md)）
- **`target` 默认提升至 esnext 之前的稳定 ES 版本**
- **`types` 默认 `[]`**——`@types` 包不再自动加载（见 [07-声明文件与互操作](./07-声明文件与互操作.md)）

## 连接：变化落在哪一层

| 层 | 代表变化 | 影响面 |
|---|---|---|
| 语言（类型语法） | `satisfies`、const 类型参数、推断谓词 | 怎么写代码 |
| 语言（运行时语法） | 标准装饰器、`using` | 产物形状、运行时行为 |
| 工具链契约 | `erasableSyntaxOnly`、默认值变更 | 构建链、配置 |
| 编译器实现 | 7.0 Go 重写 | 编译耗时，不改语义 |

实现层的替换刻意不动语义——7.0 的检查结果与 6.0 对齐，差异收敛于错误信息与边角行为。**升级的风险在默认值与废弃项，不在类型语义**。

## 边界

- **"10 倍提速"是官方典型口径**：实际收益随项目形状（文件数、类型编程密度）浮动，巨型项目复测才有自己的数。
- **版本事实会老化**：本篇日期锚定 2026-09 的 npm 记录；`latest` 与废弃清单以官方发布页为准。
- **6.0 不是长期停留点**：它是迁移台阶，新工程直接上 7.x。
- **重写不改语言语义**：类型行为的演进仍随次要版本推进，与实现解耦。
