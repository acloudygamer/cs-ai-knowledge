# 枚举与字面量类型

> 前置：[01-类型系统基础](./01-类型系统基础.md) · 后续：[03-类与接口](./03-类与接口.md)

> **版本基准**：**TypeScript 7.0.2**（`tsgo`），Node v24.13.1，Windows x64。

## 本质

"这个值只能取固定的几个"有两种表达：**字面量联合**（纯类型层，编译后什么都不剩）与 **`enum`**（类型与值的双层声明，编译后留下一个真实对象）。TypeScript 的默认规则是类型语法全部擦除（见 [01-类型系统基础](./01-类型系统基础.md)），`enum` 是少数例外。判断一个写法的性质，只需问一句：**它在产物里留不留东西**。

## 机制

### 字面量类型与拓宽

`let` 声明的推断会**拓宽**（widen）——值可变，类型就按最宽的可能算；`const` 不可变，推断停在字面上：

```console
$ npx typescript@latest --noEmit widen.ts
widen.ts(3,7): error TS2322: Type 'string' is not assignable to type '"hello"'.
```

```typescript
let a = "hello";              // 推断为 string（拓宽）
const b = "hello";            // 推断为 "hello"（字面量类型）
const c: "hello" = a;         // 报错：string 装不进 "hello"
const d: "hello" = b;         // 通过
```

对象属性同样拓宽（对象可变），这是 [01-类型系统基础](./01-类型系统基础.md) 里 `kind` 变成 `string` 的原因。

### 字面量联合：enum 的零产物替代

```typescript
type Direction = "up" | "down" | "left" | "right";

function move(d: Direction) {
  if (d === "up") { /* 此分支 d 收窄为 "up" */ }
}
```

联合里的每个成员是独立的字面量类型，`===` 比较即可收窄（收窄机制见 [04-类型收窄与控制流分析](./04-类型收窄与控制流分析.md)）。编译产物中**不留任何痕迹**——这正是类型层的本职。作为对象的判别属性使用时，就是可辨识联合（见 [06-泛型与类型编程](./06-泛型与类型编程.md)）。

### `as const`：把推断冻结在字面上

```console
$ npx typescript@latest --noEmit asconst.ts
asconst.ts(3,8): error TS2540: Cannot assign to 'home' because it is a read-only property.
```

```typescript
const routes = { home: "/", about: "/about" } as const;
const arr = [1, 2, 3] as const;
routes.home = "/x";    // 报错：属性变为 readonly
```

`as const` 做三件事：字面量不拓宽、属性全变 `readonly`、数组变 `readonly` 元组。产物就是普通对象，`as const` 一个字节都不留。路由表、配置表这类"值即类型"的场景用它。

### `enum`：编译出真实对象

```console
$ npx typescript@latest enum1.ts --target es2022 --outDir out && cat out/enum1.js
"use strict";
var Direction;
(function (Direction) {
    Direction[Direction["Up"] = 0] = "Up";
    Direction[Direction["Down"] = 1] = "Down";
    Direction[Direction["Left"] = 2] = "Left";
    Direction[Direction["Right"] = 3] = "Right";
})(Direction || (Direction = {}));
const d = Direction.Up;
```

```typescript
enum Direction { Up, Down, Left, Right }
const d: Direction = Direction.Up;
```

数值枚举的产物是一个**双向映射**对象：名字到数值、数值到名字都在。所以运行时可以反查：

```console
$ node out/rev.js
Up
0
```

```typescript
console.log(Direction[0]);   // "Up"——反查
console.log(Direction.Up);   // 0
```

字符串枚举的产物只有正向映射（`Color["Red"] = "RED"`），不能反查。

### `const enum`：全内联，零产物

```console
$ npx typescript@latest enum3.ts --target es2022 --outDir out && cat out/enum3.js
"use strict";
const f = 1 /* Flag.Read */ | 2 /* Flag.Write */;
```

```typescript
const enum Flag { Read = 1, Write = 2 }
const f = Flag.Read | Flag.Write;
```

`const enum` 在编译期把每个引用**替换成立即数**，产物里连枚举对象都没有。代价：内联要求编译器看到声明本身，跨文件做单文件转译的工具（esbuild、SWC、`isolatedModules` 模式）拿不到被导入的 `const enum` 的值，行为退化为保留引用——同一源码在不同工具链下产物不同。

### 数值枚举的类型漏洞

```typescript
enum Direction { Up, Down }
const n: number = 999;
const d: Direction = n;    // 编译通过——任何 number 变量都能赋给数值枚举
```

直接写字面量 `const d: Direction = 999` 会报错，但经 `number` 变量中转就放行（TS 5.9 与 7.0 行为一致）。数值枚举类型对 `number` 是**敞开**的——这是位标志（`Flag.Read | Flag.Write`）用法的副产品，设计上放行，安全性让位。字符串枚举没有这个洞：`"RED"` 字符串赋不进 `Color`。

### `erasableSyntaxOnly`：把例外关掉

TypeScript 5.8 起提供 `--erasableSyntaxOnly`：只允许**可擦除**的类型语法。开启后 `enum`、`const enum`、参数属性（见 [03-类与接口](./03-类与接口.md)）全部报错：

```console
$ npx typescript@latest enum1.ts --erasableSyntaxOnly --noEmit
enum1.ts(1,6): error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.
```

这个选项回应的约束是**单文件转译**：Node 24 直接运行 `.ts` 文件时工作在 strip-only 模式（只擦除、不转换），enum 会被拒绝：

```console
$ node direct.ts
SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode

$ node direct2.ts        # 只有类型标注的文件
类型标注可擦除: 1

$ node --experimental-transform-types direct.ts
enum 直接运行: 0
```

Node 的类型擦除由 `--experimental-transform-types`（实验性）才肯做语法转换（见 [5-JavaScript/06-Node.js平台/01-运行时与模块系统](../5-JavaScript/06-Node.js平台/01-运行时与模块系统.md)）。生态的方向很清楚：**新代码优先字面量联合，把 enum 留给确实需要运行时枚举对象的场景**。

## 连接：留不留产物对照

| 写法 | 编译产物 | 类型检查 | 运行时可用 | 适用 |
|---|---|---|---|---|
| 字面量联合 | 零 | 严格 | 值本身是字符串/数值 | 默认选择 |
| `as const` 对象 | 零 | 严格（readonly） | 对象本身 | 路由表、配置表 |
| 字符串 `enum` | 单向映射对象 | 严格 | 可枚举成员名 | 需要运行时列出成员 |
| 数值 `enum` | 双向映射对象 | **对 number 变量敞开** | 可反查数值 | 位标志、历史代码 |
| `const enum` | 内联，零产物 | 同 enum | 无 | 全程单一编译器 |

## 边界

- **字面量联合在运行时不存在**：不能遍历它的成员，不能用它做运行时分支的完整名单。
- **数值枚举接受任何 `number` 变量**：防外部脏数据要靠运行时校验，不靠类型。
- **`const enum` 依赖全量编译**：单文件转译工具链下导入的 `const enum` 无法内联。
- **Node strip-only 模式拒绝 enum**：直接跑 `.ts` 时只有可擦除语法可用。
- **`as const` 冻结的是推断不是对象**：属性嵌套对象仍受 `readonly` 保护，但这是类型层的，运行时照样可改。
