# 类型系统基础

> 前置：[5-JavaScript/01-语言核心](../5-JavaScript/01-语言核心/)~[03-标准库](../5-JavaScript/03-标准库/) · 后续：[02-泛型与类型编程](./02-泛型与类型编程.md)

> **版本基准**：**TypeScript 7.0.2**（`tsgo`，编译器已由 Go 重写）。本篇示例实测环境：Node v24.13.1，`npx typescript@latest`，Windows x64。
> **注意**：TypeScript 7 把 `strict` 改为**默认开启**（见 [04-编译配置与严格模式](./04-编译配置与严格模式.md)），本篇所有命令都按默认值运行。

## 本质

TypeScript 是**编译到 JavaScript 的独立语言**——不是 JavaScript 的语法扩展（见 [5-JavaScript/00-概览/01-JavaScript 全景](../5-JavaScript/00-概览/01-JavaScript全景.md) 的三层构成表）。它加的全部东西只有一个：**编译期的类型检查**。类型在编译后**完全消失**：

```console
$ npx typescript@latest t.ts --target es2022 && cat out/t.js
"use strict";
const p = { x: 1, y: 2 }; // 字面量直接满足
class Vec {
    x;
    y;
    constructor(x, y) {
        this.x = x;
        this.y = y;
    }
}
```

源文件里的 `interface Point`、参数标注、返回类型标注**一个都不剩**。这条性质称为**类型擦除**（type erasure），它推出三条必须记住的结论：

- **运行时没有类型信息**：不能在运行时判断"这个值是不是 `User` 接口"（接口名在产物里不存在）。
- **类型错误只在编译期拦住**：编译产物是普通 JavaScript，运行时行为与手写的 JavaScript 完全一致。
- **类型不影响性能**：引擎看到的是擦除后的代码（见 [5-JavaScript/07-引擎与性能/01-引擎架构与 JIT](../5-JavaScript/07-引擎与性能/01-引擎架构与JIT.md)）。

运行时验证仍然必要——`JSON.parse` 的结果、网络返回的数据，类型标注只是**断言**，不构成检查（见 [5-JavaScript/03-标准库/06-JSON](../5-JavaScript/03-标准库/06-JSON.md)）。

## 机制

### 结构化类型：看形状，不看声明

TypeScript 的类型兼容性由**结构**决定，不由继承关系决定。这与 Java、C# 的名义类型系统相反：

```console
$ npx typescript@latest --strict --noEmit t.ts   # 退出码 0
```

```typescript
interface Point { x: number; y: number }
const p: Point = { x: 1, y: 2 };        // 字面量直接满足
class Vec { constructor(public x: number, public y: number) {} }
const v: Point = new Vec(3, 4);         // 类实例也满足，没有 implements
```

`Vec` 从未声明 `implements Point`，但它有 `x` 与 `y` 两个 `number` 属性，因此可以赋给 `Point`。这条规则与 [5-JavaScript/02-对象模型与运行时/05-迭代协议与生成器](../5-JavaScript/02-对象模型与运行时/05-迭代协议与生成器.md) 里"实现 `Symbol.iterator` 即可迭代"同源——**JavaScript 生态普遍是结构式的**。

### 多余属性检查：只查字面量

```console
$ npx typescript@latest --strict --noEmit err.ts
err.ts(2,35): error TS2353: Object literal may only specify known properties, and 'z' does not exist in type 'Point'.
```

```typescript
const bad1: Point = { x: 1, y: 2, z: 3 };   // 报错
const extra = { x: 1, y: 2, z: 3 };
const ok: Point = extra;                     // 不报错
```

**直接写字面量时检查多余属性，经变量中转就不检查**。这条规则针对的是"拼错属性名"这类错误——`{ x: 1, y: 2, z: 3 }` 很可能本意是 `y` 打错了。中转之后 TypeScript 假定你知道自己在做什么。

### `any`、`unknown`、`never`

| 类型 | 含义 | 能做什么 |
|---|---|---|
| `any` | **关闭检查** | 任何操作都不报错 |
| `unknown` | 类型未知 | 什么都不能做，除非先收窄 |
| `never` | 不可能有值 | 只能赋给任何类型 |

```console
$ npx typescript@latest --strict --noEmit err.ts
err.ts(4,1): error TS18046: 'u' is of type 'unknown'.
```

```typescript
let a: any = 1;
a.foo.bar();          // 不报错——检查被关闭
let u: unknown = 1;
u.foo;                // 报错——unknown 必须先收窄
```

**`any` 的代价是传染性的**：任何与 `any` 交互的值都失去检查，错误会推迟到运行时。**优先用 `unknown`**——它同样能接收任意值，但强制你在使用前收窄（`typeof`、`instanceof`、类型谓词），把检查保留下来。

`never` 的两个用途：标注**永不正常返回**的函数（总是抛错），以及做**穷尽检查**（见 [02-泛型与类型编程](./02-泛型与类型编程.md)）。

### 类型推断与收窄

```typescript
const inferred = [1, 2, 3];               // number[]
const literal = { kind: "circle" };       // kind 被拓宽为 string

function area(s: Point | null) {
  if (s === null) return 0;
  return s.x * s.y;                       // 此分支内收窄为 Point
}
```

**推断**让大多数局部变量不必写标注。**收窄**（narrowing）让联合类型在分支里变成具体类型——靠 `typeof`、`instanceof`、`=== null`、`in`、判别属性等条件。这两条合起来是"写起来像 JavaScript，检查得像静态语言"的基础。

`const literal = { kind: "circle" }` 里 `kind` 的类型是 `string` 而不是 `"circle"`，因为对象属性**可变**，推断会**拓宽**（widen）。需要保留字面量类型时加 `as const`（见 [02-泛型与类型编程](./02-泛型与类型编程.md)）。

### 类型标注是断言，不是验证

```console
$ npx typescript@latest rt.ts --outDir out3 && node out3/rt.js
编译后对象的键: name
运行时能否拿到接口名: undefined
```

接口名 `User` 在运行时**不存在**。所以：

```typescript
const data: User = await fetch(url).then(r => r.json());   // 编译通过，但没有任何检查
```

`fetch` 返回的 JSON 结构与 `User` 是否一致，**编译期无从知晓**。需要真正校验时用运行时校验库（Zod、Valibot 一类），它们从校验规则**推导出**类型，让"运行时检查"与"编译期类型"来自同一处定义。

## 连接：与静态类型语言对照

| | TypeScript | Java / C# |
|---|---|---|
| 类型兼容判据 | 结构（形状相同即可） | 名义（必须显式声明） |
| 运行时类型信息 | **擦除后无** | 保留（反射可用） |
| 类型错误 | 编译期，可用 `any` 绕过 | 编译期，不可绕过 |
| 空值 | `strictNullChecks` 下 `null` 单独成类型 | `@Nullable` 注解或 `Optional` |
| 目标 | 编译到 JavaScript | 编译到字节码 / IL |
| 类型与值 | 类型只在编译期 | 类型与对象共存 |

## 边界

- **类型在运行时不存在**：不能用它做校验或分支。
- **`any` 会关闭检查且会传染**：优先 `unknown`。
- **类型标注不能替代运行时校验**：外部数据必须验证。
- **多余属性检查只对字面量生效**：中转后不再检查。
- **推断会拓宽字面量类型**：需要精确类型时用 `as const`。
- **编译产物是普通 JavaScript**：类型不带来任何运行时保证。
