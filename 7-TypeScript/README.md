# TypeScript

**编译到 JavaScript 的独立语言**——加的全部东西是编译期的类型检查，产物是普通 JavaScript，类型一个不留（类型擦除）。前置：[5-JavaScript/01-语言核心](../5-JavaScript/01-语言核心/)~[03-标准库](../5-JavaScript/03-标准库/)。

版本口径：**stable = TypeScript 7.0 / latest = TypeScript 7.0**（见 [versions.json](../versions.json)）。7.0 是 Go 重写的编译器（`tsgo`），**`strict` 默认为 `true`**（见 [08-编译配置与严格模式](./08-编译配置与严格模式.md)）；7.1 目前仅 nightly，故 latest 同 stable。

### 骨架的依据

**擦除线是主线。** 判断每个写法的性质只问"它在产物里留不留东西"：01~04 与 06~08 的机制全部在类型层（零产物），例外集中在一处讲透——`enum` 与参数属性改产物（02、03），装饰器生成运行时代码（05）。这条线同时解释了 Node strip-only 模式与 `erasableSyntaxOnly` 的存在理由。

**先类型后工程。** 类型层机制（01~07）讲完才到配置与工程（08~09）：`strict` 族的意义依赖 01 的类型观，`composite` 强制 `.d.ts` 依赖 07 的声明文件。版本演进（10）放在最后，因为它引用前面每一篇的实测结论。
