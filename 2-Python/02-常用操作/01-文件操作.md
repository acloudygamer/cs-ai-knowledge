# 文件操作

> **版本基准**：Python 3.12 stable（latest=3.14，新特性章节保留并标注）

## 本质

文件操作是进程通过文件描述符与操作系统内核页缓存交互，以字节序列为单位进行持久化存储读写的过程。核心资源是有限的文件描述符（ulimit 上限）和内核页缓存，约束边界由缓冲区大小、文件系统块大小和进程文件描述符上限共同决定。

## 数学模型

### 文件描述符资源约束

文件描述符是整数索引，指向进程级文件描述符表中的条目。设进程可用的最大 fd 数为 $N_{fd}$ （由 `ulimit -n` 或 `RLIMIT_NOFILE` 限制），则并发打开文件数严格受限于此上界：

 $N_{open} \leq N_{fd}$ 

当 $N_{open} = N_{fd}$ 时，再次调用 `open()` 会返回 `EMFILE`（进程 fd 表满）或 `ENFILE`（系统 inotify fd 表满）。

**Python 3.14 增量特性**：Python 3.14 新增 `os.RLIMIT_NOFILE` 作为 `RLIMIT_NOFILE` 的别名，提升跨平台一致性。

### 缓冲区拷贝代价

设读取 $B$ 字节，缓冲区大小为 $b$，系统调用次数为：

 $N_{syscall} = \left\lceil \frac{B}{b} \right\rceil$ 

对于 `read(fd, buf, BUFSIZ)`（通常 BUFSIZ=8192），读取 1MB 数据需要约 128 次系统调用。每次系统调用涉及用户态内核态切换，典型开销为 $0.5\!-\!2\,\mu s$。 。

### mmap 零拷贝条件

`mmap` 将文件映射到进程虚拟地址空间，通过页故障（page fault）按需加载页面。设页大小为 $P$ （通常 4096 字节），文件大小为 $F$ 字节，物理内存充足时总 I/O 量为：

 $I/O_{mmap} = F \quad (\text{首次全量加载})$ 

 $I/O_{mmap} = \min(F, \text{实际访问字节数}) \quad (\text{按需加载})$ 

相比 `read/write` 的固定 $F$ 次拷贝，mmap 在部分访问场景下可减少 I/O 量。

### 文件锁的数学表示

`flock(fd, LOCK_EX)` 实现为三元状态机：

 $S = \{\text{UNLOCKED}, \text{SHARED}, \text{EXCLUSIVE}\}$

状态转移函数 $\delta: S \times \text{ops} \rightarrow S$，转移规则：

| 当前状态 | 操作 | 结果 | 约束 |
|---------|------|------|------|
| UNLOCKED | LOCK_SH | SHARED | 成功 |
| UNLOCKED | LOCK_EX | EXCLUSIVE | 成功 |
| SHARED | LOCK_SH | SHARED | 成功（锁升级/累积） |
| SHARED | LOCK_EX | — | **失败**，返回 `EWOULDBLOCK` |
| EXCLUSIVE | 任意 LOCK_* | — | **失败**，返回 `EWOULDBLOCK` |
| 任意 | LOCK_UN | UNLOCKED | 成功，释放所有锁 |

**关键约束**：锁从 `SHARED` 升级为 `EXCLUSIVE` 需要先 `LOCK_UN` 再重新 `LOCK_EX`（非原子操作，中间存在竞态窗口）。

> **洞察**：文件锁是建议性锁，本质是内核内存中的标记位（`struct file` 的 `flock` 字段），不涉及磁盘 I/O。锁的生命周期绑定到 `struct file` 对象——`dup(fd)` 创建的新 fd 指向同一 `struct file`，共享同一锁状态。

## 数据流

<pre>
用户态进程                    内核页缓存                    磁盘
    |                            |                          |
    |  fd = open(path, flags)    |                          |
    |--------------------------->|                          |
    |  [分配 fd, 创建 file struct] |                          |
    |<---------------------------|                          |
    |                            |                          |
    |  read(fd, buf, n)          |                          |
    |--------------------------->|                          |
    |         [页缓存查找]         |                          |
    |              |------------->|                          |
    |              | 命中 <-------| 磁盘读取(缺页时)         |
    |              |<-------------|                          |
    |<===========================| [内核拷贝到用户 buf]      |
    |  [返回读取字节数]           |                          |
    |                            |                          |
    |  mmap(fd, offset, length)  |                          |
    |--------------------------->|                          |
    |  [建立映射, 不立即加载]      |                          |
    |<---------------------------|                          |
    |  首次访问页面               |                          |
    |--------------------------->| [触发 page fault]        |
    |              |------------->| [读取对应磁盘块]          |
    |              |<-------------|                          |
</pre>

**形态变换**：
- 磁盘块（固定大小 $P$）→ 页缓存（同一 $P$ 对齐）→ 用户 buf（应用指定大小）
- mmap 路径：磁盘块 → 页缓存（内核） → 进程虚拟地址空间（通过 page fault 懒加载）

**所有权流转**：
1. `open()` 创建 `struct file`，引用计数 = 1
2. `fork()` 子进程继承 fd，引用计数 +1
3. `dup(fd)` 创建新 fd 指向同一 `struct file`，引用计数 +1
4. `close(fd)` 引用计数 -1，归零时释放 `struct file` 和底层资源

**关键不变量**：fd 是进程级资源，跨 fork 边界时子进程获得独立的 fd 副本（指向同一 `struct file`），但 fd 编号是子进程局部的。这解释了为何 `fork()` 后父子进程的 `read()` 会相互影响文件偏移——因为共享的是 `struct file` 中的偏移量。

## 机制

### 文件描述符生命周期

`open()` 分配一个当前未用的最小非负整数 fd。fd 在进程级文件描述符表中指向 `struct file`，后者包含指向 inode 的指针和文件偏移量。`close(fd)` 释放 fd 并调用 `fput()` 减少文件引用计数，计数为零时关闭底层文件。

**关键约束**：
- fork 子进程继承 fd（引用计数 +1），exec 后 fd 保持打开
- `O_CLOEXEC` 标志在 exec 时自动关闭 fd，避免 fd 泄漏到不该有的进程
- fd 0/1/2 通常被占用（stdin/stdout/stderr），`open()` 总会返回最小可用编号

**违反约束的后果**：
- fd 泄漏：若 `close()` 未被调用，进程持有的 fd 数量持续增长，达到 $N_{fd}$ 上限后 `open()` 失败
- fd 耗尽检测：`ulimit -n` 查看软限制，`ulimit -Hn` 查看硬限制

**Python 3.14 增量**：`os.path.realpath(strict=True)` 新增 `strict` 参数，路径不存在时抛出 `FileNotFoundError`。

### 页缓存与写回策略

Linux 默认不立即将脏页写回磁盘，而是由 `pdflush/flush` 守护进程周期性写回（通常 30 秒）或当脏页占比超过 `dirty_ratio` 时触发写回。这意味着 `write()` 返回成功仅保证数据到达页缓存，崩溃可能导致丢失（最多 30 秒数据）。

**约束边界**：写回策略由以下内核参数控制：
- `dirty_ratio`：脏页占可用内存的比例阈值（默认 20%），超过则进程被阻塞直到写回
- `dirty_expire_centisecs`：脏页被视为"可写回"的超时时间（默认 30 秒）
- `dirty_writeback_centisecs`：`flush` 守护进程的唤醒间隔（默认 5 秒）

**违反约束的后果**：
- 进程崩溃：最多丢失 30 秒数据（dirty_ratio 未触发的部分）
- 系统断电：取决于文件系统 journaling 模式，ext4 有数据模式（保证元数据+数据）和日志模式（仅保证元数据）
- `O_SYNC` 标志：每次 `write()` 阻塞直到数据落盘，开销大（每次 I/O 等待磁盘旋转）

**持久性保证层级**：
```
write()         → 数据到达页缓存（最多 30s 丢失）
fsync(fd)       → 强制页缓存写磁盘（进程阻塞）
fdatasync(fd)   → 仅强制数据页写磁盘（不强制元数据）
O_SYNC          → 每个 write() 同步等待完成（最高开销）
```

### 流式读取的缓冲区机制

`read()` 从 fd 读取数据到用户 buf，实际读取量受三者最小值约束：`BUFSIZ`（stdio 缓冲区）、用户 buf 大小、文件剩余长度。循环读取直到返回 0（EOF）的模式：
```python
while True:
    data = f.read(BUFSIZ)
    if not data:
        break
    process(data)
```
这将 $O(N)$ 的总 I/O 量分摊到 $N/BUFSIZ$ 次系统调用，每次调用内部仍有至少一次用户态内核态拷贝。

**stdio 缓冲层级**：
- 全缓冲（文件）：满了才系统调用
- 行缓冲（终端）：遇到 `\n` 才系统调用
- 无缓冲（stderr）：直接系统调用

### mmap 的竞态与约束

`mmap` 创建文件与虚拟地址空间的映射，访问映射区域触发 page fault 加载对应磁盘块。

**约束边界**：
- 文件大小上限受进程虚拟地址空间限制（32 位进程最大约 3GB 映射）
- 映射区域必须是页对齐的（`offset` 也必须页对齐）
- 多个进程映射同一文件时各有一份独立的页表项，但物理页帧共享（copy-on-write 可用于私有映射）
- 对映射区域写入导致脏页，进程崩溃后脏页丢失（不自动写回，除非 `MAP_SHARED` + `msync`）

**违反约束的后果**：
- `MAP_SHARED` 写入后不 `msync`：`write()` 返回成功，但数据仅在页缓存中，进程崩溃后丢失
- `MAP_PRIVATE` 写入：修改仅在进程的私有页表中可见，不影响底层文件
- 越界访问：触发 SIGSEGV（段错误），进程被终止

**Python 3.14 增量**：`mmap.mmap` 新增 `MADV_DONTNEED` 支持（通过 `mmap.madvise()`），允许显式丢弃页缓存，释放物理内存。

### 文件锁的语义

`flock(fd, LOCK_EX)` 在内存中的 `struct file` 的 `flock` 字段设置锁标记，是建议性锁而非强制锁——它只阻止其他进程获取相同锁，不阻止读写。

**非原子性陷阱**：锁的获取和释放是非原子的，存在竞态窗口：
```python
# 竞态：检查-获取不是原子操作
if flock(fd, LOCK_SH | LOCK_NB) == 0:  # 检查
    # 另一个进程可能在这里获取 EXCLUSIVE 锁
    do_something()
    flock(fd, LOCK_UN)  # 释放
```

**违反约束的后果**：非合作进程忽略 flock，直接读写文件导致数据不一致。`fcntl(F_SETLKW)` 实现 POSIX 记录锁，可锁定文件字节范围，但同样为建议性锁。

**原子性边界**：
- `flock` 锁在 `fork()` 时继承，但父子进程是独立锁持有者（各自持有锁的引用）
- `dup(fd)` 创建的新 fd 共享同一锁（同一 `struct file`）
- 锁不随 exec 关闭（除非 `O_CLOEXEC`）

### pathlib 的路径解析

`pathlib.Path` 对象不持有打开的文件描述符，仅解析路径字符串。`Path("a/b/c")` 逐段解析，每次 `/` 操作生成新 Path 对象不触发文件系统访问。只有调用 `exists()`、`open()`、`read_bytes()` 等方法时才触发实际 I/O。这使路径组合操作零开销，直到真正需要时才懒触发系统调用。

**Python 3.14 增量**：`pathlib.PurePath.is_junction()` 新增，用于检测路径是否为 Windows junction（NTFS 重解析点）。

## 代码示例

```python
import mmap

# mmap 零拷贝读取：按页懒加载，不经过用户缓冲区拷贝
with open("data.bin", "r+b") as f:
    with mmap.mmap(f.fileno(), 0) as mm:
        # 访问 mm[0:4096] 触发一次 page fault 加载第一页
        chunk = mm[0:4096]
```

```python
# 文件描述符泄漏检测：确认 close() 在所有路径上被调用
def read_safely(path: str) -> bytes:
    fd = open(path, "rb")
    try:
        return fd.read()
    finally:
        fd.close()  # 异常路径也保证关闭
```

```python
# 使用 os.preadv 进行原子性 pread（Python 3.7+）
import os

# pread 从文件指定偏移读取，不改变文件偏移量
# preadv 批量读取多个 buffers
buf1 = bytearray(100)
buf2 = bytearray(200)
fd = os.open("data.bin", os.O_RDONLY)
n = os.preadv(fd, [buf1, buf2], offset=0)  # 从偏移 0 读取到两个 buffer
```
