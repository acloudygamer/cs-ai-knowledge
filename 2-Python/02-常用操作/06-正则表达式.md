# 正则表达式

> **版本基准**：Python 3.12 stable（latest=3.14，新特性章节保留并标注）

## 本质

正则表达式是正则文法的有穷表示，通过有限状态自动机（FSA）在文本中识别符合模式的字符串序列。Python 的 `re` 模块将正则表达式编译为 NFA（不确定有限自动机），通过回溯算法在文本上执行模式匹配。

## 数学模型

### 正则文法的形式定义

正则表达式 $\alpha$ 按如下文法递归定义（正则文法，Chomsky 3型文法）：

 $\alpha ::= \varepsilon \mid a \mid \alpha_1 \alpha_2 \mid \alpha_1 \mid \alpha_2 \mid \alpha^*$ 

其中 $\varepsilon$ 是空串， $a$ 是字符集中的原子， $|$ 是并， $*$ 是 Kleene 星闭包。

正则语言集合记为 $\mathcal{L}(\alpha)$，满足： ，满足：
- $\mathcal{L}(\varepsilon) = \{\varepsilon\}$ 
- $\mathcal{L}(a) = \{a\}$ 
- $\mathcal{L}(\alpha_1 \alpha_2) = \mathcal{L}(\alpha_1) \cdot \mathcal{L}(\alpha_2) = \{xy \mid x \in \mathcal{L}(\alpha_1), y \in \mathcal{L}(\alpha_2)\}$ 
- $\mathcal{L}(\alpha_1 | \alpha_2) = \mathcal{L}(\alpha_1) \cup \mathcal{L}(\alpha_2)$ 
- $\mathcal{L}(\alpha^*) = \{\varepsilon\} \cup \mathcal{L}(\alpha) \cup \mathcal{L}(\alpha\alpha) \cup \cdots$> **洞察**：正则表达式归约为确定有限自动机（DFA），DFA 可归约为状态转移矩阵，最终归约为硬件层面的比特操作。

### Thompson 构造：正则表达式 → NFA

Python 的 `re.compile` 使用 Thompson 构造法将正则表达式转换为 $\epsilon$-NFA。该构造保证：状态数最多为正则表达式长度的线性函数，匹配时间最坏 $O(mn)$ （m=模式长度，n=文本长度）。

构造规则：
- 原子 $a$：`a` 转换为一个两状态 NFA：起始 →（a）→ 接受
- 并 $\alpha_1 | \alpha_2$：新建起始和接受状态，通过 $\epsilon$ 弧连接两个子 NFA
- 连接 $\alpha_1 \alpha_2$：将 $\alpha_1$ 的接受状态与 $\alpha_2$ 的起始状态通过 $\epsilon$ 合并
- 闭包 $\alpha^*$：新建起始和接受状态， $\epsilon$ 弧旁路和循环

### 回溯导致的指数复杂度

NFA 模拟有两条并行路径：进程（processes）集合随输入字符扩展。贪婪量词 `\d+` 在 `"123"` 上匹配时，引擎尝试 `\d+` 消耗全部 `"123"` 然后让后续模式匹配（失败），然后回退减少 `\d+` 消耗量直到找到匹配。设 `\d+` 有 $n$ 种可能长度，后继模式有 $m$ 种回退点，最坏复杂度为 $O(n \times m)$。

**灾难性回溯**（catastrophic backtracking）：当模式有交叉重叠的重复组时，如 `(a+)+b` 匹配 `"aaaa...ac"`，引擎对每种 `a+` 长度组合都尝试一遍，导致指数级探索。

 $T(n) = 2^n \quad \text{（在特定输入下）}$ 

**ReDoS 攻击的数学模型**：
设模式 $P = (a+)+b$，输入 $S = a^n c$。NFA 在状态转移时维护进程集 $Q_i$ （当前位置可接受的 NFA 状态集合）。每个 `a+` 量词维护一个计数器 $k \in [0, n]$，表示已匹配的 `a` 数量。

探索空间的大小为：
 $|Q_i| = \sum_{k=0}^{n} 1 = O(n)$ 

每次回溯都产生新的进程，导致总时间复杂度指数增长。

## 数据流

<pre>
正则表达式              NFA (ε-NFA)                文本扫描
   |                      |                          |
   |  re.compile(r"...")  |                          |
   |--------------------> |  Thompson 构造           |
   |  [返回 Pattern]      |------------------------>|
   |                      |                          |
   |  Pattern.match(text) |                          |
   |--------------------> |  [ε-closure 初始化]      |
   |                      |                          |
   |                      |  [逐字符输入]            |
   |                      |  每字符：                |
   |                      |    - 对当前进程集        |
   |                      |    - 应用字符转移        |
   |                      |    - 计算 ε-closure     |
   |                      |    - 记录回溯状态        |
   |                      |<-------------------------|
   |  [返回 Match/None]   |                          |

进程集演化示例（"abc" 对模式 "a(b|c)*"）：
  初始：{0}  (起始状态)
  'a' 后：{1}  (a转移)
  'b' 后：{2, 0}  (b转移，或从0通过ε回到1重试)
  'c' 后：{2, 0}  (c转移，同上)
</pre>

**所有权/变换**：
- Pattern 对象是不可变编译产物，可安全跨线程共享（无状态）
- Match 对象引用原始文本（不拷贝），记录匹配的位置区间 `(start, end)`
- 每次 `match/search/findall` 调用执行一次新的 NFA 模拟

## 机制

### 量词的语义差异

| 量词 | 语义 | 备选量词 | 说明 |
|------|------|----------|------|
| `*` | 0 次或多次 | `*?`（非贪婪） | 贪婪先尝试最多，非贪婪先尝试最少 |
| `+` | 1 次或多次 | `+?` | 至少一次 |
| `?` | 0 或 1 次 | `??` | 至多一次 |

**贪婪 vs 非贪婪**：贪婪量词在回溯时释放已匹配的字符，非贪婪量词先尝试最小匹配再扩展。例如 `<.*>` 在 `<a><b>` 上匹配整个 `<a><b>`（贪婪），`<.*?>` 匹配 `<a>`（非贪婪）。

**Python 3.14 增量**：`re.Pattern` 新增 `match` 和 `fullmatch` 的只读属性：`pattern`（原始字符串）、`groups`（捕获组数）、`groupindex`（命名组字典）。

### 分组与捕获

`(...)` 创建捕获组，匹配内容被存储为 Match 对象的分组。分组编号按左括号从外到内、从左到右排序（1, 2, 3...）。`(?P<name>...)` 创建命名捕获组。`(?:...)` 为非捕获组，不影响编号：

```python
import re
m = re.match(r"(\d{4})-(\d{2})(?:-(\d{2}))?", "2024-06-15")
m.group(1)   # '2024'（第一个捕获组）
m.group(2)   # '06'
m.group(3)   # '15'（可选组不匹配时为 None）
m.group(0)   # '2024-06-15'（完整匹配）
```

### 零宽断言

零宽断言匹配位置（0 宽度），不消耗字符：

| 断言 | 含义 | 示例 |
|------|------|------|
| `(?=...)` | 正向先行 | `\w+(?=\.)` 匹配 `.` 前的单词 |
| `(?!...)` | 负向先行 | `\d+(?!\.)` 匹配非小数点后的数字 |
| `(?<=...)` | 正向后行 | `(?<=\$)\d+` 匹配 `$` 后的数字 |
| `(?<!...)` | 负向后行 | `(?<!\w)\d+` 匹配非单词字符后的数字 |

**约束**：后行断言 `(?<=...)` 必须是固定长度（`\d{4}` 合法，`\d+` 不合法），因为 NFA 模拟不支持宽度不定的回顾。

### 编译与缓存

`re.compile(pattern)` 将正则表达式字符串编译为 Pattern 对象，包含有限自动机的内部表示和缓存查找表。Python 3.11+ 还维护了一个模块级 LRU 缓存（默认大小 500），用于缓存近期编译的模式。直接调用 `re.findall(pattern, text)` 每次都进行编译+匹配；重复使用同一模式时，`re.compile` + Pattern 方法更高效。

**Python 3.14 增量**：`re.compile()` 的 `type` 参数允许指定返回的 Pattern 类型（如 `re.Pattern[str]` vs `re.Pattern[bytes]`）。

### Unicode 与 `.` 的行为

在 `re` 模块中（Python 3），`.` 默认匹配 Unicode 字符，包括中文和 emoji。`re.DOTALL`（或 `re.S`）使 `.` 匹配换行符 `\n`。`[\s\S]` 或 `(?s).` 可在任何模式下匹配包括换行在内的任意字符：

```python
re.findall(r'<.*>', '<a>\n<b>', re.DOTALL)  # ['<a>\n<b>']
re.findall(r'<.*?>', '<a><b>')              # ['<a>', '<b>'] 非贪婪
```

### 正则表达式的优化策略

**防止 ReDoS 的设计原则**：
1. 避免嵌套量词：`(a+)+` → `(a+)` 或 `a+`
2. 使用非贪婪量词减少回溯空间
3. 使用 `re.match()` 而非 `re.search()` 当模式在字符串开头
4. 预编译常用模式避免重复编译开销

**Python 3.14 增量**：`re.compile()` 新增 `timeout` 参数（实验性），防止 ReDoS 导致程序无限期挂起：

```python
try:
    pattern = re.compile(r'(a+)+b', timeout=1.0)
    pattern.match('a' * 30 + 'c')
except TimeoutError:
    print("Pattern matching timed out")
```

## 代码示例

```python
import re

# 编译后复用：避免每次调用重复编译
pattern = re.compile(r'\b(\d{4})-(\d{2})-(\d{2})\b')
dates = ["2024-06-15", "2023-12-01", "invalid"]
for d in dates:
    m = pattern.search(d)
    if m:
        print(f"年={m.group(1)}, 月={m.group(2)}, 日={m.group(3)}")
```

```python
# 零宽断言：提取小数点前的数字（不包括小数点本身）
text = "价格: 19.99元, 折扣: 8.5折"
prices = re.findall(r'\d+(?=\.)', text)   # ['19', '8']
before_dot = re.findall(r'(?<=\.)\d+', text)  # ['99', '5']
```

```python
# 使用命名捕获组
pattern = re.compile(r'(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})')
m = pattern.search("2024-06-15")
print(m.groupdict())  # {'year': '2024', 'month': '06', 'day': '15'}
```

```python
# 预编译 + LRU 缓存
import functools

@functools.lru_cache(maxsize=128)
def cached_match(pattern: str, text: str):
    return re.match(pattern, text)

# 第一次调用编译，后续使用缓存
result = cached_match(r'\d+', '123')
```
