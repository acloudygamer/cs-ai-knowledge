# 网络请求

## 定义

网络请求是客户端通过传输层（TCP/UDP）连接远程主机，以应用层协议（HTTP/WebSocket）交换数据的通信过程。核心资源是 socket 缓冲区（接收/发送各一对）、TCP 连接状态机、文件描述符；约束边界由超时配置、重试策略、连接池大小共同决定。

## 数据流

<pre>
Client                      TCP Stack                   Server
  |                            |                          |
  |  socket()                  |                          |
  |------------->              |                          |
  |  connect()                 |                          |
  |--------------------------->| SYN                      |
  |              |<===========>|==========================>|
  |              |  (1.5 RTT)   |  SYN-ACK                 |
  |              |<===========>|==========================<|
  |              |             |  ACK                      |
  |<-------------|             |                          |
  |  HTTP Request              |                          |
  |--------------------------->|-------------------------->|
  |              |             |  [处理请求]               |
  |              |             |  HTTP Response           |
  |              |             |  [RST_STREAM 或 finish]  |
  |              |             |  [RST_STREAM 或 finish]  |
  |<=========== |<------------|<==========================|
  |  [连接关闭/复用]            |                          |

发送缓冲区满时背压链：
  发送方 send() ---> 内核缓冲区 --X--> 网络 --/--> 接收方
                        [满] = EAGAIN
</pre>

**形态变换**：
- Python dict/list → HTTP Request Body（bytes，Content-Length 确定长度）
- TCP 流 → 应用层协议解析 → Python dict（response.json()）
- 连接从 CLOSED → ESTABLISHED → CLOSED（或保持 ESTABLISHED 用于 keep-alive）

**所有权流转**：
1. `socket()` 创建 fd，分配内核 socket 缓冲区
2. `connect()` 执行三次握手，连接进入 ESTABLISHED 状态
3. `send()/recv()` 数据在内核缓冲区与应用 buf 间拷贝
4. `close()` 发送 FIN，等待对方 ACK，进入 TIME_WAIT（通常 2*RTT）

**TIME_WAIT 的约束**：主动关闭方在连接关闭后进入 TIME_WAIT 状态（持续 2×RTT），期间无法立即用同一端口建立新连接。这是 TCP 的设计约束，确保所有旧连接的数据报在网络中消散。

## 机制

### 连接池的约束边界

`requests.Session` 维护一个 `HTTPAdapter` 池（默认每个 host 10 个连接）。当并发请求超过池大小时，多余请求排队等待可用连接。

**约束边界**：
- 连接池是有限资源，过度并发导致请求排队甚至超时
- httpx 的 `AsyncClient` 默认限制每 host 100 连接，通过 `limits` 参数可进一步配置
- 池中连接有存活超时（通常 120 秒），超时后连接被关闭并从池中移除

**饥饿与死锁场景**：
- 连接池耗尽：所有连接被占用且未释放，新请求排队超时
- 连接泄漏：`close()` 未被调用，连接无法归还池
- keep-alive 超时：连接久不使用被服务器关闭，发送时收到 `ConnectionResetError`
- 线程安全：Session 对象不是线程安全的，跨线程使用需要锁或每个线程独立 Session

### 超时的双重语义

- **硬超时**（`timeout.connect`）：TCP SYN 重试次数耗尽后强制关闭连接，抛出 `ConnectTimeout`。
- **软超时**（`timeout.read`）：在数据读取过程中计时，若超过指定时间无任何数据到达，抛出 `ReadTimeout`。

**约束边界**：两超时独立计时，可同时配置。当服务器响应了但响应体非常大时，软超时无法保护，需配合流式读取和外部计时器。

**超时的精确语义**：
- `timeout=None`：无限等待
- `timeout=10`：同时作为 connect 和 read 的上限
- `timeout=(3.05, 27)`：分别设置 connect（3.05s）和 read（27s）上限

### 重试的边界条件

`urllib3.Retry` 默认对所有 HTTP 状态码重试（`status_forcelist` 默认包含 413/429/500/502/503/504）。

**幂等性假设**：幂等性假设是重试的前提：
- GET/HEAD/OPTIONS：天然幂等
- POST/PUT/DELETE：默认不幂等（除非配置 `raise_on_status=False`）

**违反约束**：对非幂等请求盲目重试可能导致重复执行（如重复扣款），需业务层保证幂等（如通过 idempotency key）。

**重试的数学边界**：
- 指数退避确保重试间隔指数增长，避免惊群效应
- 最大重试次数受 $T_{max}$ 约束： $n \leq \lfloor \log_b(T_{max}/T_{base}) \rfloor + 1$ 约束： $n \leq \lfloor \log_b(T_{max}/T_{base}) \rfloor + 1$ 

### HTTP/2 多路复用

HTTP/2 在单一 TCP 连接上并发多个流（stream），每个流有唯一 ID。帧（frame）是基本传输单元，DATA 帧承载应用数据，HEADERS 帧承载元数据。

**多路复用使多个请求/响应 interleaving 在同一连接上**，避免了 HTTP/1.1 的 HOL（Head of Line）阻塞，但共享 TCP 拥塞窗口——当单个流丢包时，所有流都被阻塞。

**帧解析状态机**：
```
连接状态: IDLE → OPEN → HALF-CLOSED → CLOSED
流状态:   IDLE → OPEN → RESERVED → CLOSED
```

### WebSocket 的握手机制

WebSocket 以 HTTP Upgrade 握手开始，客户端发送 `Upgrade: websocket` 和 `Sec-WebSocket-Key`，服务器返回 `Sec-WebSocket-Accept = base64(SHA1(key + GUID))`。成功后协议从 HTTP 切换为 WebSocket 帧协议。

**帧结构**：
- FIN=1：消息完整
- opcode：0x0(continuation), 0x1(文本), 0x2(二进制), 0x8(关闭), 0x9(PING), 0xA(PONG)
- 掩码：客户端→服务器帧必须掩码（XOR with frame mask）
- 载荷长度：7-bit / 7+16-bit / 7+64-bit 扩展

**帧解析状态机**：
```
FIN=1, opcode=0x1 → 文本消息完整
FIN=0, opcode=0x1 → 文本消息起始/continuation
FIN=1, opcode=0x0 → continuation 结束
FIN=1, opcode=0x8 → 关闭握手
```

### 连接复用的 HTTP/1.1 keep-alive

HTTP/1.1 默认启用 keep-alive（`Connection: keep-alive`）。服务器通过 `Keep-Alive: timeout=5, max=1000` 告知连接复用策略。连接在以下情况关闭：
- 服务器 `timeout` 超时
- 客户端发送 `Connection: close`
- 请求数达到 `max`
- 任何一方 TCP 连接断开

**Python 3.14 增量**：`urllib.request` 模块对 HTTP/1.1 keep-alive 超时处理更严格，避免连接复用导致的资源泄漏。

import httpx

# 连接池与流式读取：避免大响应体一次性加载
with httpx.Client() as client:
    with client.stream("GET", "https://example.com/large.json") as response:

```python
import asyncio, httpx

# 异步并发请求：单线程多协程共享一个连接池
async def fetch_all(urls: list[str]) -> list[httpx.Response]:
    async with httpx.AsyncClient() as client:
        tasks = [client.get(url) for url in urls]
        return await asyncio.gather(*tasks)
```

```python
# 指数退避重试：urllib3.Retry
from urllib3.util.retry import Retry
from requests.adapters import HTTPAdapter
from requests import Session

session = Session()
retry = Retry(
    total=5,
    backoff_factor=0.5,  # 0.5s, 1s, 2s, 4s, 8s
    status_forcelist=[429, 500, 502, 503, 504],
    allowed_methods=["HEAD", "GET", "OPTIONS"]
)
adapter = HTTPAdapter(max_retries=retry)
session.mount("http://", adapter)
session.mount("https://", adapter)
```
