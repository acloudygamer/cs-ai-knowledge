# 配置文件处理

## 定义

配置文件是程序启动时从外部存储加载的静态声明式数据，用于将运行时参数与代码逻辑分离。配置处理的本质是一个**从字节序列到 Python 数据结构的有偏函数** $P: \Sigma^* \rightharpoonup D$，在语法错误或类型错误时无定义（抛出异常）。

## 数学模型

配置合并操作构成一个**交换半格**（commutative semilattice）。设配置为键值映射 $C: K \to V$，合并操作 $\oplus$：
$$(C_1 \oplus C_2)(k) = \begin{cases} C_2(k) & k \in \text{keys}(C_2) \\ C_1(k) & k \notin \text{keys}(C_2) \end{cases}$$

层叠合并（文件配置 + 环境变量）满足交换律、结合律、幂等性——配置系统是可序列化推理的，不存在合并顺序歧义。

**归约终点**：配置解析可归约为**上下文无关文法（CFG）的解析**——每个配置格式（TOML、YAML、JSON）定义一个 CFG，解析器通过 LL/LALR 等算法将 token 序列规约为抽象语法树（AST），再将 AST 映射为 Python 数据结构。TOML 的歧义消除（键唯一性、表不重复）使得其 CFG 是**无歧义的**，JSON 和 YAML 的某些构造则存在歧义（键重复行为流式解析器与标准解析器不一致）。

## 数据流

<pre>
磁盘文件 (字节序列)
       │
       ▼
  文件描述符 ──> 操作系统读取 ──> 字节流
       │
       ▼
  文本解码 (encoding) ──> str (Unicode)
       │
       ▼
  词法分析器 (Lexer) ──> Token 序列
  TOML: [ TABLE KEY VALUE STRING ... ]
  YAML: [ KEY VALUE INDENT DEDENT ... ]
  JSON: [ LBRACE KEY STRING ... ]
       │
       ▼
  语法分析器 (Parser) ──> AST
  TOML: TomlDocument { tables, key-values }
  YAML: dict / list / primitive
  JSON: dict (as Python object)
       │
       ▼
  语义验证 ──> 唯一键检查、类型检查
       │
       ▼
  Python 数据结构 (dict / list)
       │
       ▼
  配置合并 (浅合并) ──> 环境变量覆盖
       │
       ▼
  程序访问 config["section"]["key"]
</pre>

**所有权流转**：
1. 操作系统持有文件内容（磁盘上）
2. `open()` 返回文件对象，程序持有文件描述符
3. 解析器持有文件内容副本，生成 AST 后原文件可关闭
4. 配置字典由解析器构造，所有权归调用方
5. 环境变量覆盖：调用方在字典上原地修改

## 机制

### TOML vs JSON vs YAML 的设计哲学对比

| 维度 | JSON | TOML | YAML |
|------|------|------|------|
| **设计目标** | 数据交换格式 | 配置文件格式 | 数据序列化格式 |
| **歧义策略** | 允许重复键（取最后） | 禁止重复键/表 | 允许重复键（行为因解析器而异） |
| **可读性** | 一般（无注释） | 优秀（人类友好） | 优秀（缩进友好） |
| **类型安全** | 严格（6种类型） | 严格（8种类型） | 宽松（隐式转换） |
| **Python 内置** | `json` (3.0+) | `tomllib` (3.11+) | 需安装 `pyyaml` |

**TOML 的歧义消除**：TOML 的核心设计约束——每个键、每个表只能定义一次。这消除了 JSON 中 `{a: 1, a: 2}` 的歧义，使得 TOML 配置文件的行为可预测。

**YAML 的隐式类型风险**：YAML 的 `yes/no`、`on/off`、`null` 等值会自动转换为布尔/空值。若配置期望字符串类型但 YAML 解析为布尔，可能导致后续逻辑判断出错：
```yaml
debug: yes    # YAML 解析为 True（布尔），而非 "yes"（字符串）
```

### 分层配置加载机制原理

典型的三层配置合并：

```python
# 第1层：默认配置（固定值）
with open("config.toml", "rb") as f:
    config = tomllib.load(f)   # 返回 dict

# 第2层：环境特定配置（浅合并）
if os.path.exists("config.dev.toml"):
    with open("config.dev.toml", "rb") as f:
        dev = tomllib.load(f)
        config.update(dev)      # 浅合并，仅覆盖顶层键

# 第3层：环境变量（精确键覆盖，类型保持）
def apply_env(config, prefix="APP_"):
    for section, values in config.items():
        if not isinstance(values, dict):
            continue
        env_prefix = f"{prefix}{section.upper()}_"
        for key, value in values.items():
            env_key = f"{env_prefix}{key.upper()}"
            if env_key in os.environ:
                values[key] = type(value)(os.environ[env_key])
    return config
```

**合并操作的数学性质**：
- 交换律：$C_1 \oplus C_2 = C_2 \oplus C_1$
- 结合律：$(C_1 \oplus C_2) \oplus C_3 = C_1 \oplus (C_2 \oplus C_3)$
- 幂等性：$C \oplus C = C$

这些性质保证合并顺序不影响最终结果——无论先加载哪个配置文件，最终配置对象都是确定的。

**类型保持约束**：环境变量覆盖必须保持原始类型。若原配置 `port: int`，环境变量传入字符串 `"8080"`，必须转换为 `int("8080")` 而非直接赋值。

### 敏感信息的处理原则

配置系统不应对明文敏感信息承担保护责任——这是运维边界。正确做法：配置文件只存占位符（如 `password = ""`），运行时从环境变量或密钥管理服务注入。

## 参考存根

```python
import tomllib
import yaml
import os

# TOML：Python 3.11+ 内置
def load_toml_config(path: str) -> dict:
    with open(path, "rb") as f:
        return tomllib.load(f)

# YAML：需 PyYAML
def load_yaml_config(path: str) -> dict:
    with open(path) as f:
        return yaml.safe_load(f)  # safe_load 禁用任意代码执行

# 分层配置合并
def layered_config(base_path: str, env: str = None) -> dict:
    with open(base_path, "rb") as f:
        config = tomllib.load(f)

    if env:
        env_path = f"config.{env}.toml"
        if os.path.exists(env_path):
            with open(env_path, "rb") as f:
                config.update(tomllib.load(f))

    return apply_env_overrides(config)

# 环境变量覆盖（类型保持）
def apply_env_overrides(config: dict, prefix: str = "APP_"):
    for section, values in config.items():
        if not isinstance(values, dict):
            continue
        env_prefix = f"{prefix}{section.upper()}_"
        for key, value in values.items():
            env_key = f"{env_prefix}{key.upper()}"
            if env_key in os.environ:
                values[key] = type(value)(os.environ[env_key])
    return config
```
