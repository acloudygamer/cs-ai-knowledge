# 模块与包

## 定义

模块是 Python 字节码执行的最小隔离单位，每个 `.py` 文件对应一个 module 对象，存储在 `sys.modules` 字典中。包是通过目录层级组织模块的命名空间容器，其根目录必须包含 `__init__.py`。import 机制是延迟求值的符号解析过程：模块代码在首次 import 时执行一次，后续 import 直接返回已缓存的 module 对象。

## 数学模型

### 模块缓存的语义

`sys.modules` 建模为从模块名（字符串）到 module 对象的偏函数 $M: \text{str} \rightharpoonup \text{ModuleObject}$。import 语义为：

$$\text{import}(name) = \begin{cases} M[\text{name}] & \text{if } name \in \text{dom}(M) \\ \text{load\_and\_execute}(name); M[\text{name}] & \text{otherwise} \end{cases}$$

加载后 $M[\text{name}]$ 永久存在于缓存中，直到进程结束或手动 `del sys.modules[name]`（后者会使后续 import 重新加载，但已持有的引用保持不变）。

### import 的图遍历

模块依赖图 $G=(V,E)$，顶点为模块名，边 $E$ 表示 `import` 关系。加载模块 $v$ 时，解释器执行 $v$ 的顶层代码，递归触发所有可达顶点的加载。由于 $G$ 可能存在环（循环导入），解释器在遇到已在加载中（`sys.modules` 中但未完成初始化）的模块时返回不完整的模块对象（部分初始化的状态）：

$$\text{circular\_import}(v) = M[v] \text{ where } M[v] \text{ is partially initialized}$$

这导致如果循环导入的模块在部分初始化状态下被访问，可能触发 `AttributeError`。

**归约终点**：import 缓存机制可归约为哈希表查找，$O(1)$ 平均时间复杂度。循环导入问题是图遍历中灰色节点问题的变体。

### 包命名空间的维度

设包路径深度为 $d$，同级模块数为 $n_i$（第 $i$ 层），则最大模块数为：

$$N_{modules} = \prod_{i=1}^{d} n_i$$

Python 的命名空间由 `sys.modules` 的键前缀实现，而非嵌套字典。

## 数据流

<pre>
import 语句
    |
    v
sys.modules 查找
    |
    +--> 命中（已加载）--------> 返回缓存 module 对象
    |
    未命中
    |
    v
sys.path 顺序搜索模块文件
    |
    v
[.py 文件] → 编译 → PyCodeObject → 创建 module 对象
    |
    v
module.__dict__ 初始化
    |
    v
执行模块顶层代码（可能触发递归 import）
    |
    v
module 对象存入 sys.modules
    |
    v
import 语句的结果绑定到当前命名空间
</pre>

**sys.path 搜索顺序**：
1. 脚本所在目录（或当前目录）
2. `PYTHONPATH` 环境变量中的目录
3. Python 安装目录的 `lib`（与平台相关）
4. 第三方包目录（site-packages）

**所有权**：
- module 对象在 `sys.modules` 中被引用
- import 语句在局部命名空间中创建额外引用
- 所有引用消失后，module 对象变为垃圾（由 GC 回收，但通常不会真正回收，因为 `sys.modules` 持有引用）

## 对比参照

| 维度 | import X | from X import y | import X as Z |
|------|----------|----------------|---------------|
| sys.modules 查询 | `X` | `X` | `X` |
| 命名空间绑定 | `X` 绑定到当前模块 | `y` 绑定到当前模块 | `Z` 绑定到当前模块 |
| 模块级属性访问 | `X.attr` | `attr`（直连） | `Z.attr` |

## 机制

### 相对导入的约束

`from .submodule import x` 是相对导入，只在包内部使用。`..` 表示父包，`...` 表示上两级。**约束**：相对导入必须满足 `__package__` 已设置（解释器自动设置），且导入语句必须在包内代码中执行。直接运行 `python -m package.submodule` 时 `__package__` 正确设置；直接运行 `python package/submodule.py` 时 `__package__` 为 `None`，相对导入失败。

**Python 3.14 增量**：`importlib.resources` 模块改进，对资源文件的访问更一致（替代 `pkg_resources`）。

### `__all__` 的导出控制

`from module import *` 只导出 `__all__` 中列出的名称；若 `__all__` 未定义，则导出所有不以 `_` 开头的名称。这是一种白名单机制，控制公共 API：
```python
# module.py
__all__ = ["PublicClass", "public_function"]  # 只导出这两个
_private_class = 1  # 不会被 from module import * 导出
```

### 模块级锁与并发 import

Python 解释器在 import 模块时持有内部 import lock（`imp.lock`），防止同一模块被并发重复初始化（这对于多线程程序至关重要）。但这是解释器级别的粗粒度锁，不防止应用层的死锁（如果两个模块互相 import 且其中一个模块在初始化中尝试获取其他锁）。**设计建议**：避免在模块顶层代码中获取应用层锁或在导入时执行耗时 I/O。

### 虚拟环境的隔离原理

虚拟环境（venv）通过 `sys.prefix` 和 `sys.base_prefix` 的分离实现隔离：
- `sys.base_prefix` 指向原始 Python 安装路径（不变）
- `sys.prefix` 在虚拟环境中指向 `venv` 路径
- 虚拟环境的 `site-packages` 通过修改 `sys.path`（添加在 `sys.path` 前部）优先于系统包被搜索

激活脚本（`activate`）通过修改 `PATH` 和设置 `VIRTUAL_ENV` 环境变量来改变子 shell 的行为，但不修改当前进程的 `sys.path`（激活脚本在子 shell 中执行）。

### 模块重新加载

`importlib.reload(module)` 重新执行模块的字节码，用新的 module 对象替换 `sys.modules` 中的条目。**约束**：
- 旧对象被替换，但所有已持有该 module 引用的变量仍指向旧对象
- 模块依赖图中的循环引用可能导致只重载部分模块
- 使用 reload 前模块必须已被正常 import 过

### namespace package 的机制

PEP 420 引入的 namespace package 不需要 `__init__.py`，允许多个 distribution 贡献同一包的子模块：

```python
# pkg/__init__.py 不存在
# pkg/submodule.py 可以来自不同的包
from pkg import submodule  # 运行时合并所有 namespace package 的 submodule
```

**搜索顺序**：namespace package 的合并发生在文件系统层面，而非 `sys.modules` 层面。

## 参考存根

```python
import sys

# 延迟导入：避免循环导入，在函数内导入
def heavy_computation():
    import numpy as np  # 仅在函数调用时导入
    return np.dot([1, 2], [3, 4])

# 动态导入：模块名在运行时确定
module_name = "math"
math_mod = __import__(module_name)
print(math_mod.sqrt(2))
```

```python
# 模拟 importlib.reload 的效果：强制重新执行模块代码
import importlib, my_module
importlib.reload(my_module)  # my_module 变量本身被重新赋值
```

```python
# 使用 importlib.metadata 获取包元信息（Python 3.8+）
from importlib.metadata import version, requires, metadata

print(version("requests"))  # '2.31.0'
print(requires("pip"))  # ['flask>=2.0', ...]
info = metadata("numpy")
print(info["Summary"])  # 'Fundamental package for array computing'
```

```python
# Python 3.14: 使用 importlib.resources 访问包内资源
from importlib import resources

# 读取包内的数据文件
with resources.files("my_package") as res:
    data_file = res / "data.json"
    print(data_file.read_text())
```

```python
# 处理循环导入的延迟导入模式
# module_a.py
def func_a():
    from module_b import func_b  # 延迟导入避免循环
    return func_b()

# module_b.py
def func_b():
    from module_a import func_a  # 延迟导入避免循环
    return func_a()
```

```python
# 使用 __all__ 控制导出
# mymodule.py
__all__ = ['PublicClass', 'public_function']

class _PrivateClass:
    pass

class PublicClass:
    pass

def public_function():
    pass

def _private_function():
    pass

# main.py
from mymodule import *  # 只导入 PublicClass 和 public_function
```
