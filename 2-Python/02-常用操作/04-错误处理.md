# 错误处理

错误处理是程序在异常情况下的响应机制，通过异常机制将错误信息从错误发生点传递到处理点。

## 核心机制

Python 的异常机制基于控制流的非局部跳转，当异常被抛出时，解释器沿调用栈向上传播直到找到匹配的 except 处理器。`try/except` 块创建一个异常检查点，匹配类型后执行处理代码。`finally` 块无论是否异常都会执行，用于资源清理。异常链 `raise ... from e` 通过 `__cause__` 属性保留原始异常上下文，便于调试时追溯根因。自定义异常应继承合适的基类（`ValueError`、`RuntimeError` 等），形成有层次的异常体系。断言 `assert` 用于检查"不可能发生"的条件，在 Python -O 优化模式下会被忽略。

## 定义断言

> 异常是程序执行过程中打破正常控制流的信号，错误处理是通过异常传播机制在错误发生点与处理点之间传递错误信息的机制。

    |      |      | +-----------+
    |      |      |             |
    |      |  [搜索 except]     |
    |      |<----------+        |

    |      |                    |
</pre>

## try/except/finally

### 参考样例

```python
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"不能除零: {e}")
finally:
    print("总是执行")
```

## 异常链

### 参考样例

```python
try:
    int("not_a_number")
except ValueError as e:
    raise RuntimeError("转换失败") from e
```

## 自定义异常

### 参考样例

```python
class AppError(Exception):
    pass

class ValidationError(AppError):
    pass

raise ValidationError("age must be positive")
```

## 断言

### 参考样例

```python
assert b != 0, "除数不能为零"
return a / b
```

## 常见问题

| 问题 | 解决方案 |
|------|----------|
| 异常不用于控制流 | 用边界检查替代 |
| 资源泄漏 | 使用 finally 或上下文管理器 |
| 异常链断裂 | 使用 `raise ... from e` |
