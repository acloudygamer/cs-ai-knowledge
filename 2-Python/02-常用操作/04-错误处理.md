# 错误处理

## 定义

错误处理是程序通过异常机制实现的非局部控制流转移：异常从抛出点到传播路径上的匹配处理器之间，携带错误信息（类型、消息、栈帧）沿调用栈逆向传播，直到被捕获或到达顶层导致进程终止。异常是 Python 对象的实例，本质是一个被标记为"携带控制流"的特殊对象。

## 数学模型

### 异常传播的计算模型

将 Python 调用栈建模为一个栈结构 $S = [f_1, f_2, \dots, f_n]$，其中 $f_1$ 是最外层（`__main__`），$f_n$ 是当前执行帧。设异常类型为 $E$，处理器按栈帧顺序从 $f_n$ 向 $f_1$ 搜索匹配的 `except E:` 子句：

$$\text{handler}(E, S) = \begin{cases} f_i & \exists i: f_i \text{ has } except \ clause \ matching \ E \\ \text{terminate} & \text{no handler found} \end{cases}$$

搜索从栈顶开始，首次匹配即停止搜索（最内层优先）。这意味着外层 `except Exception` 无法捕获内层 `except KeyError` 已处理的同名异常（因为处理后不再上抛）。

### try/except 的栈帧开销

`try` 块本身无显著开销，解释器将 `try` 翻译为字节码指令 `SETUP_FINALLY`，在异常发生时才触发栈展开（stack unwinding）。没有异常时，try 块的性能与普通块几乎相同。异常发生时，解释器遍历调用栈为每个栈帧调用 `PyErr_Restore()`，此开销与栈深度 $D$ 成正比：$O(D)$。

## 数据流

<pre>
调用栈（从上到下）              异常传播方向            异常对象属性
main()                          |                      __traceback__（栈帧链表）
    |                           |                      __context__（隐式链）
    |  func_a()                |                      __cause__（显式链 from）
    |      |                    |                      args（消息元组）
    |      |  func_b()         |                     
    |      |      |             |                     
    |      |      | raise ValueError("invalid")        
    |      |      | +-------------------------------+
    |      |      | (exception object created)       |
    |      |      |         ↓                        |
    |      |      | [栈展开: 释放局部变量]            |
    |      |      |         ↓                        |
    |      |      | [到达 func_a: 搜索 except]       |
    |      |      |<----------+ (匹配 ValueError)     |
    |      |      |                                |
    |      |  [处理: print(e)]                      |
    |      |      |                                |
    |      | return  # 恢复常规控制流               |
    |                           |                   |
异常属性访问:                                           
    exc.__traceback__.tb_frame  → 引发异常的栈帧    
    exc.__traceback__.tb_next   → 外层栈帧           
</pre>

**形态变换**：
- 异常抛出：`raise ValueError(msg)` 创建 `ValueError` 实例，args=(msg,)
- 栈展开：解释器遍历栈帧，调用 `__exit__`（with 块）和 `finally` 块，释放局部变量引用（触发 `__del__` 如果存在）
- 处理器匹配：`except ValueError as e` 将异常对象绑定到变量 `e`，`e` 的作用域仅在 except 块内

## 机制

### 异常链的语义

- `raise X from Y`：设置 `X.__cause__ = Y`（显式链），`X.__suppress_context__ = True`，打印时只显示 `X` 和 `__cause__`
- `raise X`（无 from）：若当前帧正在处理另一异常，`X.__context__ = 当前异常`，`X.__suppress_context__ = False`，打印时显示完整嵌套链

**设计意图**：`__cause__` 表示"故意替代"（如业务层异常替代底层网络异常），`__context__` 表示"无意中附带"（如错误处理中又出错）。`raise ... from None` 故意切断上下文链，用于安全相关的异常（不希望泄露内部实现细节）。

### 异常类的层次设计

Python 内置异常形成树形层次，捕获父类会自动匹配所有子类：

```
BaseException
├── SystemExit / KeyboardInterrupt / GeneratorExit（不推荐捕获）
└── Exception
    ├── ValueError / TypeError / KeyError / IndexError（常见逻辑错误）
    ├── RuntimeError / NotImplementedError
    ├── OSError（文件系统、socket 错误）
    ├── AttributeError（属性访问错误）
    └── ...
```

自定义异常应继承 `Exception` 而非 `BaseException`，否则会被 `except Exception` 漏掉。外层库应定义业务异常基类，内部捕获并重新抛出业务异常，避免实现细节泄漏。

### 资源清理的确定性

`finally` 块在异常传播前一定会执行（即使异常被 `except` 捕获），这是 RAII 模式在 Python 的等价实现。但 finally 中的 `return` 会覆盖已抛出的异常——异常对象被丢弃，函数正常返回。这是一类隐蔽 bug：

```python
def bad():
    try:
        raise ValueError("original")
    finally:
        return 42  # ValueError 被丢弃，返回 42
```

### 异常与上下文的隔离

`contextvars.ContextVar`（Python 3.7+）提供了线程本地存储的协程版本，适合在异步代码中传递请求级上下文（如 trace ID），而不依赖异常链。异常链适合同进程内错误传递；跨进程/服务边界的错误传播需要将异常信息序列化（如 `traceback.format_exception`）。

### 断言的语义与约束

`assert condition, message` 在 `__debug__` 为 True 时等价于 `if not condition: raise AssertionError(message)`；在 `-O`（optimize）模式下 `__debug__ = False`，assert 语句被完全移除，不产生任何运行时开销。这决定了断言只适用于"开发期检查不可能发生的内部不变量"，而非"用户输入验证"。验证用户输入应使用 `if ... raise ValueError(...)` 而非 assert。

## 参考存根

```python
import traceback

# 异常链的正确用法：保留原始错误便于调试，但对外暴露业务异常
def load_config(path: str) -> dict:
    try:
        with open(path) as f:
            return json.load(f)
    except FileNotFoundError as e:
        raise ConfigError(f"配置文件不存在: {path}") from e
    except json.JSONDecodeError as e:
        raise ConfigError(f"配置文件格式错误: {path}") from e
```

```python
# 自定义异常体系：业务异常基类 + 细分子类
class AppError(Exception):
    """业务异常基类，捕获 Exception 即覆盖所有业务异常"""
    pass

class ValidationError(AppError):
    """验证失败"""
    pass

class ResourceNotFoundError(AppError):
    """资源不存在"""
    pass
```
