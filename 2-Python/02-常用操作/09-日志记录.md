# 日志记录

## 定义

日志是程序运行时通过采样关键事件节点生成的结构化时间序列数据。日志记录的本质是一个**有条件采样的发布-订阅管道**：Logger（Subject）产生 LogRecord 事件，经 Handler（Observer）链过滤和消费。

## 数学模型

### 日志级别的偏序结构

日志级别构成一个布尔代数偏序集 $\{L, \leq\}$ ，其中 $L = \{\text{DEBUG}=10,\ \text{INFO}=20,\ \text{WARNING}=30,\ \text{ERROR}=40,\ \text{CRITICAL}=50\}$ ，偏序关系为数值大小。 ，其中 $L = \{\text{DEBUG}=10,\ \text{INFO}=20,\ \text{WARNING}=30,\ \text{ERROR}=40,\ \text{CRITICAL}=50\}$ ，偏序关系为数值大小。 ，偏序关系为数值大小。

过滤谓词 $P(l) = (l \geq \text{threshold})$ 对应集合的**上闭包**。 对应集合的**上闭包**。

**布尔代数性质**：
- 封闭性：任意两级别的高低比较结果仍在集合内
- 反对称性：若 $l_1 \leq l_2$ 且 $l_2 \leq l_1$ ，则 $l_1 = l_2$ 且 $l_2 \leq l_1$ ，则 $l_1 = l_2$ ，则 $l_1 = l_2$ 
- 传递性：若 $l_1 \leq l_2$ 且 $l_2 \leq l_3$ ，则 $l_1 \leq l_3$ 且 $l_2 \leq l_3$ ，则 $l_1 \leq l_3$ ，则 $l_1 \leq l_3$ 
- 下界：NOTSET = 0（最小级别，匹配所有）
- 上界：CRITICAL = 50（最大级别）

### Logger 树的事件传播

**传播的数学表示**：

**归约终点**：日志系统可归约为**观察者模式（Observer Pattern）的具体实现**——Logger 是 Subject，维护订阅者列表（Handler 集合）并主动通知；Handler 是 Observer，通过 `handle()` 方法消费 LogRecord。发布-订阅的解耦使得日志输出可以随时增减，无需修改产生日志的代码。

## 数据流

<pre>
调用点 (logger.info(...))          Logger (Subject)
    │                                    │
    │  LogRecord{timestamp, level,       │ 1. 构造 LogRecord
    │             name, msg, args}       │    LogRecord 被创建
    │ ─────────────────────────────────>│    （引用计数 = 1）
    │                                    │
    │                              Filter 链
    │ 2. 检查 level >= logger.threshold? │ 条件采样
    │ ─────────────────────────────────>│
    │    是 ───────────────────────────>│
    │                                    │
    │                              Handler 链 (Observer 列表)
    │ 3. 每个 Handler.handle(record)    │
    │ ─────────────────────────────────>│
    │    ConsoleHandler                  │
    │    └─> Formatter.format(record)   │ 4. 格式化：解耦格式/输出
    │        └─> sys.stderr.write()     │
    │    FileHandler                     │
    │    └─> Formatter.format(record)   │
    │        └─> f.write()              │
    │    (record 引用计数 -1)            │
    │                                    │
    │ 4. 若 propagate=True               │
    │    复制 record ──> 父 Logger       │ 传播给订阅者
    │ ─────────────────────────────────>│
</pre>

**所有权流转**：
1. 调用者通过 `logger.info()` 构造 `LogRecord`（持有 `msg` 字符串和 `args` 元组的引用）
2. Logger 持有 LogRecord 引用，将 record 向下传递给 Filter
3. Filter 通过后，record 被复制（引用计数 +1）分发给每个 Handler
4. Handler 委托 Formatter 将 LogRecord 转换为字符串对象（数据形态转换）
5. Handler 输出后释放 record 引用（引用计数 -1），计数归零则立即回收

**关键不变量**：`propagate=False` 是**截断传播**——事件在当前 Logger 的 Handler 链处理完毕后终止，不向父节点复制。这是避免日志重复输出的正确方式，而非关闭 propagate。

## 机制

### Observer 模式的 Logger-Hierarchical 结构

Logger 树是观察者模式的层级变体：每个 Logger 节点既是被观察者（处理自身事件），也是观察者（将事件向上传播给父节点）。这形成了一种**树形发布-订阅链**：

```python
# 典型配置：子模块 logger 用 propagate=False 避免重复
root = logging.getLogger()           # 根 Logger，配置全局 Handler
root.addHandler(StreamHandler())      # Observer 1: 控制台

mylib = logging.getLogger("mylib")  # 子 Logger
mylib.setLevel(logging.DEBUG)        # 细粒度阈值
mylib.propagate = False              # 关键：阻止向上传播
mylib.addHandler(FileHandler(...))   # 仅在此 Handler 输出，不重复到 root
```

**约束**：`propagate=False` 的存在原因：子模块的 Handler 链与根 Logger 的 Handler 链是**独立的订阅链**。若 `propagate=True`（默认值），同一事件会在两条链上各输出一次，造成重复。

### Formatter 的解耦意义

Formatter 承担两个职责：**数据抽取**（从 LogRecord 提取字段）和**文本组装**（按格式规格符拼接）。这实现了**格式逻辑与输出逻辑的完全解耦**——Handler 只需调用 `formatter.format(record)`，无需了解格式规则；同一 Handler 可随时更换 Formatter 而无需修改 Handler 本身。

**Formatter 的接口契约**：
```python
class Formatter:
    def format(self, record: LogRecord) -> str:
        """将 LogRecord 转换为字符串，不涉及任何 I/O 操作"""
```

**约束**：Formatter 必须处理 LogRecord 所有字段的序列化，包括可能抛出异常的 `record.exc_info`（异常信息序列化）。若格式化过程中抛出异常，Handler 有责任捕获并记录（防止格式化失败导致日志丢失）。

### 日志与业务线程的隔离

日志系统应当是**非阻塞或有限阻塞**的。设计原则：
- 异步日志：`QueueHandler` + 独立 `Listener` 进程，将日志写入与业务线程解耦
- 缓冲日志：`MemoryHandler` + 条件 flush，减少同步 I/O 次数

**约束违反的后果**：若日志写入阻塞（如磁盘满了），业务线程的 `logging` 调用会卡住。磁盘满导致 write() 系统调用无限期等待。

### 结构化日志与 ELK 集成

JSON 格式日志的数学本质是**同构序列化**：将 LogRecord 的异构字段映射为同构字节流。`python-json-logger` 将 `logrecord.__dict__` 经 `json.dumps()` 序列化。

**约束**：JSON 日志单条过长会导致日志聚合系统缓冲区压力，建议在 Formatter 中对 `exc_info` 截断。

## 参考存根

```python
import logging
import logging.handlers

# Logger 树：子模块 logger 自动向上冒泡至 root
lib_logger = logging.getLogger("mylib")
lib_logger.setLevel(logging.DEBUG)
lib_logger.propagate = False           # 避免向 root 重复传播

# Handler 链：Stream + RotatingFile + MemoryHandler
console = logging.StreamHandler()
file_rot = logging.handlers.RotatingFileHandler(
    "app.log", maxBytes=10_000_000, backupCount=3
)
memory_buf = logging.handlers.MemoryHandler(
    capacity=100, target=file_rot, flushLevel=logging.ERROR
)

fmt = logging.Formatter("%(asctime)s %(levelname)s %(name)s: %(message)s")
console.setFormatter(fmt)
file_rot.setFormatter(fmt)

lib_logger.addHandler(console)
lib_logger.addHandler(memory_buf)

# Formatter 解耦示例：同一 Handler 可更换不同 Formatter
import json
class JSONFormatter(logging.Formatter):
    def format(self, record):
        return json.dumps({
            "ts": record.created,
            "level": record.levelname,
            "logger": record.name,
            "msg": record.getMessage()
        })

json_handler = logging.StreamHandler()
json_handler.setFormatter(JSONFormatter())
logging.getLogger().addHandler(json_handler)
```
