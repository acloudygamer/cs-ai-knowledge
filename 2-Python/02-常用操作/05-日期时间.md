# 日期时间处理

## 定义

datetime 是时间轴上某个瞬间的数学表示，通常以 UTC 为基准加上时区偏移。timedelta 是两个时间点之间的有向时间间隔，以微秒为基本计量单位。Python 的 datetime 模块区分无时区信息（naive）和有时区信息（aware）两种对象，两者在算术运算和比较操作上存在语义差异。

## 数学模型

### 时间轴的数学表示

设时间轴为连续统 $\mathbb{R}$ ，每个实数 $t$ 对应一个 UTC 瞬间。Unix 纪元 $t=0$ 定义为 `1970-01-01 00:00:00 UTC`。naive datetime 是从纪元起的秒数映射，但缺少时区信息时无法唯一确定UTC瞬间：

$\text{naive\_datetime} \xrightarrow{\text{未知时区}} \{ t + \Delta \mid \Delta \in \text{可能的偏移集合} \}$

同一 naive datetime 在北京时区（UTC+8）和东京时区（UTC+9）对应 UTC 瞬间相差 1 小时。

**这是 naive datetime 的根本歧义**：字面值相同不代表同一时刻。

### aware datetime 的映射

aware datetime 通过 `tzinfo` 指定相对于 UTC 的偏移 $\Delta$ ，则 UTC 瞬间唯一确定：

$t_{\text{utc}} = t_{\text{local}} - \Delta$

Python 的 `timestamp()` 方法要求 aware datetime（否则抛出 `ValueError`），其转换公式为：

$\text{timestamp} = (t_{\text{utc}} - \text{epoch}).total\_seconds()$

`fromtimestamp(ts, tz)` 将 Unix 秒数转回 aware datetime：

$t_{\text{local}} = t_{\text{utc}} + \Delta = \text{epoch} + \Delta + \text{ts}$

### timedelta 的算术约束

timedelta 的内部表示是 `days * 86400 + seconds * 3600 + microseconds`（微秒分辨率），因此：

- 任意两个 datetime 相减得到 timedelta（无歧义）
- timedelta 与 datetime 相加得到新的 datetime（timedelta 被解释为有向时间间隔）
- **timedelta 之间相加**： $d_1 + d_2$ 产生新 timedelta，可能溢出 days 字段（999999999 天上限）
- **timedelta 乘除以标量**： $2 \times d$ 合法，$d / 2$ 可能损失微秒精度（整除时）

**约束**：timedelta 不支持月份或年份运算，因为月份天数不固定（28/29/30/31），年份秒数不固定（365/366 天 + 闰秒）。

**归约终点**：timedelta 可归约为以微秒为基本单位的整数对偶 $(D, \mu)$ ，其中 $D$ 为天数， $\mu$ 为微秒数，满足 $|\mu| < 86400 \times 10^6$。

### 闰秒的处理

UTC 是通过插入或删除闰秒来保持与地球自转同步的时间标尺。Unix 时间（POSIX time）忽略闰秒，每天精确 86400 秒。Python 的 `datetime` 和 `time.time()` 均基于 POSIX time，不处理闰秒。

**约束**：这意味着 `datetime.fromtimestamp(N)` 在闰秒时刻附近与实际 UTC 可能有 1 秒误差。若需要闰秒感知，需使用 `astropy.time` 等专用库。

## 数据流

<pre>
naive datetime                      aware datetime
     |                                    |
     | timestamp()                        | astimezone()
     | [抛出 ValueError]                  | [转换到另一时区]
     v                                    v
     --                                   --
     |                                    |
     | 只能 + timedelta                   | 减法 → timedelta（无歧义）
     | 只能 - datetime                    | 比较（同 absolute time）
     | 比较（implementation-defined）     |
     v                                    v
Unix 秒数 (仅 aware 可直接转换)         另一时区的 aware datetime
     |                                    |
     | fromtimestamp(ts)                  | 互相转换时通过 UTC
     v                                    v
naive datetime ← 不推荐，丢失时区        aware datetime（内部转 UTC 再加偏移）
</pre>

**所有权/生命周期**：
- aware datetime 的 `tzinfo` 对象通常是不可变 stateless 对象（如 `zoneinfo.ZoneInfo`）
- `datetime.now()` 返回 naive（取决于系统 local timezone），生产环境应使用 `datetime.now(zoneinfo.UTC)` 或 `datetime.now(tzlocal())`
- `datetime.utcnow()` 已废弃（返回 naive，名称又含 utc，易误导）

**Python 3.14 增量**：`datetime.time` 新增 `fromisoformat()` 的严格模式（`strict=True`），对无效时间戳抛出 `ValueError`。

## 机制

### 时区对象的构造与查询

`zoneinfo.ZoneInfo("Asia/Tokyo")` 从 IANA 时区数据库加载时区规则，返回一个固定偏移时区对象（在 Python 3.9+）。该对象是 stateless：给定 UTC 瞬间和日期，确定本地时间。

**约束**：夏令时（DST）转换由 IANA 数据库的规则决定，`zoneinfo` 缓存已查过的转换规则，但首次查询需解析规则文件（约 1-5ms）。

**IANA 时区数据库的数学表示**：
设 $T$ 为 UTC 瞬间， $Z$ 为时区名，$R(T, Z)$ 为 IANA 规则计算出的本地偏移。则本地时间 $L$ 为：

$L = T + R(T, Z)$

$R$ 是分段常数函数，跳跃点发生在 DST 切换时刻。

### 字符串解析的歧义性

`strptime(format, timestr)` 按固定格式解析，是确定性解析（无歧义）。`fromisoformat(timestr)` 解析 ISO 8601 扩展格式，但：
- `2024-03-10T02:30:00+08:00`：解析为 aware，偏移固定
- `2024-03-10T02:30:00`：解析为 naive（**注意**：这在 DST 切换时刻可能对应不存在的时间，如美国东部夏令时切换日凌晨 2 点不存在）

**Python 3.14 增量**：`datetime.fromisoformat()` 新增对 `Z` 后缀（Zulu = UTC）的原生支持，无需手动转换。

### timedelta 与月份运算

月份运算（加一个月）是语义上不确定的：1月31日加一个月是2月31日（不存在）还是3月2日/3日？Python 标准库选择抛出 `ValueError`。`dateutil.relativedelta` 通过 `relativedelta(months=+1)` 实现月份运算，采用"溢出回绕"策略（2月31日 → 3月2日/3日，取决于年份）。

### aware datetime 的比较

两个 aware datetime 比较时，Python 首先将两者都转换到 UTC（通过 `utcoffset()` 获取偏移），然后比较 UTC 瞬间。这确保了不同时区的 datetime 可以正确比较：

```python
dt_tokyo = datetime(2024, 6, 15, 14, 30, tzinfo=ZoneInfo("Asia/Tokyo"))
dt_utc = datetime(2024, 6, 15, 5, 30, tzinfo=zoneinfo.UTC)
# dt_tokyo == dt_utc 为 True（同一 UTC 瞬间）
```

**约束**：naive datetime 与 aware datetime 比较抛出 `TypeError`。

### 时间戳的数值稳定性

`datetime.timestamp()` 对极端日期的处理：
- `datetime(1970, 1, 1, 0, 0, 0, tzinfo=UTC).timestamp()` 精确为 0.0
- `datetime(0001, 1, 1, 0, 0, 0, tzinfo=UTC).timestamp()` 为负数（使用儒略日转换）
- `datetime(3000, 12, 31, 23, 59, 59, tzinfo=UTC).timestamp()` 在 int64 范围内

**Python 3.14 增量**：`datetime.timestamp()` 对 naive datetime 的处理更一致（假设本地时区而非 UTC）。

## 参考存根

```python
import zoneinfo
from datetime import datetime, timedelta

# aware datetime 的正确创建：所有时间存储为 UTC，转换在显示层做
def to_utc(dt: datetime) -> datetime:
    """将任意 datetime 转为 UTC aware datetime"""
    if dt.tzinfo is None:
        return dt.replace(tzinfo=zoneinfo.UTC)
    return dt.astimezone(zoneinfo.UTC)

# 时间段计算：timedelta 精确到微秒
delta = timedelta(days=7, hours=12, minutes=30)
future = datetime.now(zoneinfo.UTC) + delta
```

```python
# 检测 DST 切换：tzname() 返回时区名（带 DST 标记）
import tzlocal
local_tz = tzlocal.get_localzone()
dt = datetime(2024, 3, 10, 2, 30)  # 美国东部夏令时切换日凌晨
print(dt.astimezone(local_tz).tzname())  # 'EST' 或 'EDT'
```

```python
# Python 3.11+: 时区感知的时间计算
from datetime import datetime, timezone
now_utc = datetime.now(timezone.utc)  # 推荐写法
later = now_utc + timedelta(hours=24)
print(later.isoformat())  # 包含 +00:00
```

```python
# Python 3.14: UTC 时间的简化创建
from datetime import datetime, UTC  # UTC 在 3.11+ 是 timezone.utc 的别名

# 直接使用 UTC 而非 timezone.utc
dt = datetime(2024, 6, 15, 12, 0, 0, tzinfo=UTC)
print(dt.timestamp())  # 正确转换
```

```python
# 使用 dateutil 处理月份运算（第三方库）
from dateutil.relativedelta import relativedelta
from datetime import datetime

dt = datetime(2024, 1, 31) + relativedelta(months=+1)
print(dt)  # 2024-03-02（回绕策略）
```
