# 代码检查工具

## 定义

代码检查工具通过静态分析在运行前发现代码中的错误、漏洞和风格问题，在错误进入生产前拦截。

## 数据流

<pre>
源代码 ──▶ 词法/语法分析 ──▶ AST ──▶ 规则引擎 ──▶ 问题报告
                                       │
                               ┌───────┴───────┐
                               │ 类型检查      │
                               │ 风格规则      │
                               │ 安全规则      │
                               │ 活跃度分析    │
                               └───────────────┘
</pre>

linting 工具运行在代码**执行前**，属于静态分析；类型检查在 AST 基础上额外进行类型注解一致性验证。

## 机制

代码检查的核心价值是**将错误发现时机前移**：错误在 CI 阶段发现比在生产中发现代价低 10-100 倍。检查器的约束来自其规则集——规则越严格，误报率越高；规则越宽松，漏检率越高。

Ruff 用 Rust 重写规则引擎，将 Python 的 linting 从分钟级压缩到毫秒级，代价是规则数量受限（500+ 对比 Pylint 的 3000+）。Mypy 和 Pyright 在 AST 基础上额外执行类型注解一致性检查，要求代码显式声明类型。

**类型检查的约束**：Python 类型注解是**渐进式**——可选择不使用、使用部分、使用严格模式。严格程度越高，类型安全越强，但迁移成本越高。

速度对比：Ruff (~0.1s) vs Flake8 (~30s) vs Pylint (~120s)，Rust 实现带来 300-1200 倍加速。

## 参考存根

```python
import subprocess, sys
r = subprocess.run(["ruff", "check", "src/"], capture_output=True)
sys.exit(r.returncode)
```
