# 代码质量工具

## 目录

- [01-代码质量工具](01-代码质量工具.md)

## 概述

代码质量工具链分为两类核心工具：

| 类型 | 功能 | 代表工具 | 是否修改代码 |
|------|------|---------|-------------|
| **格式化工具** | 统一代码风格 | Black, Ruff Format, isort | 是（生成格式化后代码） |
| **检查工具** | 发现错误和漏洞 | Ruff, Pylint, Mypy, Pyright | 否（仅报告问题） |

**组合策略**：格式化工具（isort + Black/Ruff Format）→ Linter（Ruff）→ 类型检查（Mypy/Pyright）。这个顺序确保格式化优先，消除风格问题后再进行深度静态分析。

## 核心约束

### 幂等性（格式化工具）

同一代码格式化多次，输出必须完全相同：

 $F(F(s)) = F(s)$ 

这保证格式化脚本可重复运行，不会产生累积效应。幂等性是格式化工具的**本质约束**，而非可选特性——非幂等的格式化工具在 CI 环境中会导致不可预测的 diff。

### 精确率与召回率（检查工具）

- **精确率**：报告的问题中，真正有问题的比例（误报率 = 1 - 精确率）
- **召回率**：所有问题中，工具发现的比例（漏报率 = 1 - 召回率）

工具设计在精确率和召回率之间权衡。Ruff 选择高精确率（快且误报少），Pylint 选择高召回率（全面但慢）。

**F1 分数**： $F_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$，综合衡量工具性能。 ，综合衡量工具性能。

### 类型安全（类型检查器）

Python 是渐进式类型语言——类型注解提供额外约束，类型检查器在运行时前验证这些约束。严格模式要求所有函数都有注解，基础模式仅检查有注解的调用。

**约束满足的本质**：类型检查是**一阶谓词逻辑的模型检测**——给定函数签名（公理）和调用（查询），验证查询是否满足公理约束。

### 版本基准

| 版本 | 说明 |
|------|------|
| Python 3.12 | 稳定版本，工具完全兼容 |
| Python 3.14 | 前沿版本，工具可能尚未完全适配新语法 |

## 工具选择

| 场景 | 推荐工具链 |
|------|-----------|
| 新项目 | Ruff (格式化 + 检查) + Pyright |
| 遗留代码 | Black + Ruff + Mypy (基础模式) |
| 大型代码库 | Ruff Format + Ruff + Pyright (增量分析) |
| 严格类型安全 | Black + isort + Ruff + Mypy (strict) |
