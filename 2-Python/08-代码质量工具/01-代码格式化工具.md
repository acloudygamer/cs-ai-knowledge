# 代码格式化工具

## 定义

代码格式化工具通过将源代码解析为抽象语法树（AST），再按确定性规则重新生成风格一致的等价表示，消除人工风格决策，降低协作摩擦。其核心约束是**幂等性**：同一输入无论格式化多少次，输出必须完全相同（`fmt(src) = fmt(fmt(src))`）。

## 数学模型

### AST 变换的不动点

设格式化函数为 $F: S \to S$（$S$ 为源代码字符串空间）。幂等性要求：

$$F(F(s)) = F(s) \quad \forall s \in S$$

即 $F$ 的不动点构成所有格式化后代码的集合。Black 等严格工具的规则设计保证代码在首次格式化后即进入不动点，再次格式化零改动。

### 树形变换的组合复杂度

代码格式化涉及多层 AST 变换：

$$\text{source} \xrightarrow{\text{parse}} \text{AST} \xrightarrow{\text{transform}} \text{modified AST} \xrightarrow{\text{unparse}} \text{output}$$

每层变换的复杂度：
- 解析：$O(n)$（线性扫描tokens）
- AST 节点修改：$O(1)$（局部替换）
- 代码生成：$O(n)$（树遍历）

总复杂度 $O(n)$，与源文件长度线性相关。

## 数据流

<pre>
源代码（文本）
    │
    ▼
词法分析器（Lexer）──▶ Token 流
    │  逐字符扫描，识别关键字/标识符/字面量
    │
    ▼
解析器（Parser）──▶ AST（抽象语法树）
    │  按语法规则组织 tokens，检测语法错误
    │
    ▼
格式化规则引擎
    │
    ├── 行长度约束（Black: 88字符）
    ├── 缩进（4空格 vs 2空格）
    ├── 引号风格（单引号 vs 双引号）
    ├── 尾随逗号（trailing commas）
    └── import 分组和排序（isort）
    │
    ▼
代码生成器（Unparser）──▶ 风格化代码
    │
    ▼
确定性输出（幂等）
</pre>

**关键性质**：格式化是**语义保持的纯外观变换**——AST 的语义结构（表达式求值顺序、变量作用域）完全不变。

## 机制

### AST 表示与代码生成

Python 代码解析为 AST 后，每个节点携带位置信息（行号、列偏移）。格式化工具遍历 AST 时，按节点类型应用对应规则：

```python
# 源代码
x = [1, 2, 3]

# AST 表示（简化）
Module(body=[
  Assign(targets=[Name(id='x')], value=List(elts=[
    Constant(value=1), Constant(value=2), Constant(value=3)
  ]))
])
```

Black 的代码生成器从 AST 重新构建文本，遵循Black 的行长度（默认88字符）和空行规则。生成的代码在语义上完全等价于原始代码。

### 确定性约束的工程价值

**确定性** 是格式化工具的核心工程约束：

- **CI 友好**：每次运行结果相同，格式检查不会因工具版本不同产生 diff
- **幂等保证**：格式化脚本可安全重复运行，无需担心累积效应
- **可预测性**：团队成员无论何时运行工具，输出稳定

Black 通过严格限制配置选项（"没得选就是最好的"）来保证确定性。选项越多，不同样本组合爆炸越多，维护成本越高。

### 多工具组合：isort + Black

isort 负责 import 分组和排序，Black 负责其余格式约束。两者必须协同：

- isort 的 `force_single_line=True`（单行 import）可能违反 Black 的行长度
- 正确组合：`isort --profile black`，自动对齐两工具的冲突规则

组合后处理顺序：**isort 先规范化 import → Black 格式化其余**。若顺序颠倒，isort 可能重新引入 Black 已格式化的换行。

### Python 版本的 target-version

Python 语法在不同版本间有差异（如 `match...case` 在 3.10+）。`pyproject.toml` 中的 `target-version` 告诉格式化工具按哪个 Python 版本解析代码：

```toml
[tool.black]
target-version = ["py312"]
```

这确保工具不会把旧版本的有效语法格式化为新版本语法。

## 参考存根

```python
import subprocess

# 检查（不修改）
r = subprocess.run(["black", "--check", "."], capture_output=True)
print(r.returncode)  # 0 = 已格式化，非0 = 需要格式化

# 格式化
r = subprocess.run(["black", "."], capture_output=True)

# isort + Black 组合
r = subprocess.run(["isort", "--profile", "black", "."], capture_output=True)
r = subprocess.run(["black", "."], capture_output=True)
```
