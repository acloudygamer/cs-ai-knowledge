# 代码格式化工具

## 定义

代码格式化工具将源代码解析为抽象语法树（AST），再按确定性规则重建风格一致的等价表示。核心约束是**幂等性**：`fmt(src) = fmt(fmt(src))` —— 同一输入无论格式化多少次，输出完全相同。

**本质**：格式化是**语义保持的纯外观变换**。解析为 AST 后重建代码文本，语义结构（表达式求值顺序、变量作用域）完全不变，仅改变视觉呈现。

## 数学模型

### 幂等变换的不动点定理

设格式化函数为 $F: S \to S$（$S$ 为源代码字符串空间）。幂等性要求：

$$F(F(s)) = F(s) \quad \forall s \in S$$

即 $F$ 的所有不动点构成格式化后代码的集合。Black 等严格工具的规则设计保证代码在首次格式化后即进入不动点，再次格式化零改动。

**不动点收敛性证明**：若 $F$ 是有限状态自动机上的单调映射（每次迭代输出长度不增），则 $F$ 必有不动点。Black 的行长度约束 $L_{\max} = 88$ 保证每次迭代输出长度不增，因此必然收敛至不动点。

大多数文件一次迭代即可到达不动点。极少数学公式化后仍超长的代码可能需要两次迭代（首次换行后产生新的可优化模式）。

### AST 变换的线性复杂度

代码格式化涉及多层 AST 变换：

$$\text{source} \xrightarrow{\text{parse}(O(n))} \text{AST} \xrightarrow{\text{transform}(O(n))} \text{modified AST} \xrightarrow{\text{unparse}(O(n))} \text{output}$$

- 解析（词法分析）：$O(n)$，线性扫描 tokens
- AST 节点修改：$O(n)$，局部替换
- 代码生成：$O(n)$，树遍历

总复杂度 $O(n)$，与源文件长度线性相关。这是格式化工具能处理超大代码库的理论基础。

### Black 行长度决策模型

Black 默认行长 88 字符（可配置），决策模型为：

$$L_{\text{output}} = \min(L_{\text{config}}, \text{自然行长}) \quad \text{若超出则换行}$$

### isort import 排序的分组代数

isort 的排序规则基于**有限群作用**：

$$G = \{(\text{分组置换}, \text{组内排序}) | \text{组间顺序固定}\}$$

默认分组序列（偏序关系）：

$$\text{__future__} \prec \text{标准库} \prec \text{第三方} \prec \text{本地}$$

同组内按字典序排列，形成全序。`force_single_line=True` 将每个 import 强制拆成单行，改变了群作用的结构，可能与 Black 行长约束冲突。

## 数据流

<pre>
源代码（文本字符串）
    │
    ▼
词法分析器（Lexer）──▶ Token 流
    │  逐字符扫描，识别关键字/标识符/字面量
    │  正则匹配，O(n) 线性复杂度
    │
    ▼
解析器（Parser）──▶ AST（抽象语法树）
    │  按语法规则组织 tokens，检测语法错误
    │  递归下降或 LALR(1) 解析
    │
    ▼
格式化规则引擎
    │
    ├── 行长度约束（Black: 88字符）
    │    ├─ 约束违反检测：无法自动换行 → 报告错误（不是自动修复）
    │    └─ 换行决策：函数调用参数超长 → 逐行堆叠
    ├── 缩进（固定宽度）
    ├── 引号风格（单引号 vs 双引号）
    ├── 尾随逗号规则
    ├── import 分组和排序（isort）
    └── 空行规则
    │
    ▼
代码生成器（Unparser）──▶ 风格化代码
    │  按遍历顺序输出节点，累积为字符串
    │  输出长度 ≤ 输入长度（单调不增 → 收敛保证）
    │
    ▼
幂等输出（不动点）
</pre>

**所有权/形态变换**：
- 源代码（文本字符串） → Token 流（扁平结构） → AST（树结构） → 重建文本（字符串）
- 每个阶段的数据结构不同，但底层语义完全保持
- 数据从不执行，仅被解析和重建

## 机制

### AST 表示与语义保持边界

Python 代码解析为 AST 后，每个节点携带位置信息（行号、列偏移）。格式化工具遍历 AST 时，按节点类型应用对应规则：

```python
# 源代码
x = [1, 2, 3]

# AST 表示
Module(body=[
  Assign(targets=[Name(id='x')], value=List(elts=[
    Constant(value=1), Constant(value=2), Constant(value=3)
  ]))
])
```

**语义保持的精确含义**：格式化不改变程序的执行行为。但这并不意味着格式化前后代码"看起来相同"——引号风格、缩进、空行可以完全不同，只要代码在语义上等价。

**语义保持的失效场景**：
- 隐式字符串拼接：`"Hello" "World"` 解析为单个字符串，但 Black 可能重排导致不同字面量拼接结果
- 含有注释的代码：注释在 AST 中丢失（AST 不保留注释），格式化后会丢失注释内容
- 三引号字符串的缩进处理：Black 会在多行字符串前加前缀以匹配缩进层级

### 幂等性的工程约束

**幂等性**保证了格式化工具的**可预测性**和**CI 友好性**：

- 每次运行结果相同，格式检查不会因工具版本不同产生 diff
- 格式化脚本可安全重复运行，无需担心累积效应
- 团队成员无论何时运行工具，输出稳定

Black 通过**严格限制配置选项**来保证幂等性。"没有选择就是最好的选择" —— 选项越少，不同样本的组合越少，不动点越容易达到。

**违反幂等性的场景**：
- 工具版本不一致：旧版本 `black-23.x` 和新版本 `black-24.x` 可能对同一代码产生不同输出
- 配置文件变更：`pyproject.toml` 修改后，格式化结果改变

### isort 与 Black 的冲突仲裁

isort 负责 import 分组和排序，Black 负责其余格式约束。两者必须协同：

**冲突场景**：`isort` 的 `force_single_line=True`（每个 import 单行）可能超出 Black 的 88 字符限制。

**仲裁规则**：使用 `isort --profile black`，自动对齐两工具的冲突规则。具体来说：
- isort 的单行/多行决策遵循 Black 行长
- import 内部换行由 Black 而非 isort 控制
- 组合后处理顺序：**isort 先规范化 import → Black 格式化其余**。若顺序颠倒，isort 可能重新引入 Black 已格式化的换行。

### Ruff Format 的架构优势

Ruff Format（Rust 实现）定位与 Black 相同，但性能更高：

| 工具 | 10k 行文件 | 100k 行代码库 |
|------|-----------|---------------|
| Black（Python） | ~0.5s | ~5s |
| ruff format（Rust） | ~0.01s | ~0.1s |

**性能差异来源**：
- Rust 无 GIL，天然并行处理多文件
- Rust 的 arena 分配模式：AST 节点内存分配一次性批量进行，减少碎片
- Rust 的 `rowan` AST 库设计更高效

**输出兼容性**：Ruff Format 与 Black 共享大部分格式化决策，可作为直接替代。差异主要在边缘情况（如长字符串的处理策略）。

### target-version 的类型解析约束

Python 语法在不同版本间有差异（如 `match...case` 仅在 3.10+）。`pyproject.toml` 中的 `target-version` 告诉格式化工具按哪个 Python 版本解析代码：

```toml
[tool.black]
target-version = ["py312"]
```

**约束**：若代码库的 `target-version` 设置低于实际运行环境，格式化工具可能拒绝新语法；若设置过高，可能将旧版本无效语法格式化为有效代码（这是 bug 而非特性）。

## 参考存根

```python
import subprocess

# 格式检查（不修改）
r = subprocess.run(["black", "--check", "."], capture_output=True)
print(r.returncode)  # 0 = 已格式化，非0 = 需要格式化

# 格式化
r = subprocess.run(["black", "."], capture_output=True)

# isort + Black 组合（正确顺序）
r = subprocess.run(["isort", "--profile", "black", "."], capture_output=True)
r = subprocess.run(["black", "."], capture_output=True)

# Ruff Format 替代 Black
r = subprocess.run(["ruff", "format", "."], capture_output=True)

# pyproject.toml 配置示例
# [tool.black]
# line-length = 88
# target-version = ['py312']
# [tool.isort]
# profile = "black"
```
