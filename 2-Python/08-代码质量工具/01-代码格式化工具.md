# 代码格式化工具

## 定义

代码格式化工具通过将源代码转换为风格一致的等价表示，消除人工风格决策，降低协作摩擦。

## 数据流

<pre>
源代码 ──▶ 解析器 ──▶ AST ──▶ 格式化引擎 ──▶ 风格化代码
                                      │
                              ┌───────┴───────┐
                              │ line-length   │
                              │ indent-style  │
                              │ quote-style   │
                              │ trailing-commas│
                              └───────────────┘
</pre>

格式化是**无损变换**：语义保持不变，仅改变外观形式。

## 机制

代码格式化的核心约束是**确定性**：同一输入必须产生唯一输出，无需配置或人工判断。Black 贯彻这一理念，默认值即最优解，以换取团队间零格式争议。

**违反约束的后果**：若工具输出不确定，每次 CI 运行可能产生不同结果，格式检查变成随机失败。

多工具组合时（isort + Black），必须保证输出兼容：isort 的 import 分组与 Black 的行长度约束协同，否则两者互相覆盖。Ruff-format 出现前，Black 是唯一满足"确定性 + 零配置"双重约束的工具。

Python 版本通过 `pyproject.toml` 的 `target-version` 配置，而非 pre-commit hook 的 `language_version` 参数——后者是 Black hook 的无效参数。

## 参考存根

```python
import subprocess, sys
r = subprocess.run(["black", "--check", "."], capture_output=True)
sys.exit(r.returncode)
```
