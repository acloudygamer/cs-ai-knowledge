# 02-性能优化与剖析

> 前置：[02-内建数据结构](../01-语言核心/02-内建数据结构.md)（复杂度选型）、[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)（流式）、[01-内存管理与垃圾回收](01-内存管理与垃圾回收.md)（内存账） · 后续：[03-并发与异步](03-并发与异步.md)（并行/并发两轴）、[05-数据分析与机器学习](../06-应用领域/05-数据分析与机器学习.md)（向量化主战场）

优化的第一定律：**先测后改**。第二定律：**算法与数据结构赢了，微优化就没必要**。本篇的主线是剖析工具链（定位真瓶颈）→ 优化杠杆的优先级表（按投入产出排序）→ 边界逃生舱（什么时候离开纯 Python）。

## 本质

- 剖析回答"时间去了哪"：CPU 时间（cProfile / py-spy）、内存驻留（tracemalloc / memray，见 [01-内存管理与垃圾回收](01-内存管理与垃圾回收.md)）、启动时间（`-X importtime`）。三类瓶颈用三把尺，拿错尺是常见的第一错误。
- 优化杠杆的收益量级（经验序）：换算法 $O(n^2) \to O(n \log n)$（千倍级）> 换数据结构（list 查找变 set，百倍级）> 向量化/批处理（数十倍）> 解释器版本与内建 C 路径（常数因子）> 微优化属性访问/局部变量（个位数百分比）。

## 机制

### 测量工具箱

| 工具 | 测什么 | 形态 |
|---|---|---|
| `time.perf_counter()` | 手动计时段 | 微基准的钟（见 [04-日期与时间](../02-IO与工程实践/04-日期与时间.md) 单调钟） |
| `timeit` | 语句级微基准 | 多次取最优，避免一次抖动 |
| `cProfile` | 函数级累计/自身耗时 | `python -m cProfile -s cumulative app.py` |
| `py-spy` | 线上进程非侵入采样 | 无需重启、火焰图——生产排障首选 |
| `python -X importtime` | 导入耗时树 | 启动慢（CLI/CLI 工具）的定位尺（见 [10-模块与导入系统](../01-语言核心/10-模块与导入系统.md)） |
| `tracemalloc` / `memray` | 内存分配点/火焰图 | 见 [01-内存管理与垃圾回收](01-内存管理与垃圾回收.md) |

纪律：cProfile 有观测开销（逐调用计数），数字看相对占比不看绝对值；微基准必须用 timeit（它禁用 GC 并重复取样）。

### 杠杆一：算法与数据结构

典型修复对照（承接 [02-内建数据结构](../01-语言核心/02-内建数据结构.md) 的复杂度表）：

| 反模式 | 复杂度 | 修复 | 复杂度 |
|---|---|---|---|
| `if x in big_list` 循环内 | $O(n)$ × 循环 | 预建 `set` | 均摊一次构建，查询 $O(1)$ |
| 逐行字符串 `+=` | $O(n^2)$ | `''.join` / io 缓冲 | $O(n)$ |
| `list.pop(0)` 队列 | 每步 $O(n)$ | `collections.deque` | $O(1)$ |
| 手写计数循环 | $O(n)$ Python 层 | `collections.Counter` | C 层 $O(n)$ |
| 嵌套循环找配对 | $O(n^2)$ | dict 索引一次遍历 | $O(n)$ |

### 杠杆二：批处理与向量化

解释器循环的每步都付字节码分派税——把 N 次 Python 层操作压成 1 次 C 层操作是结构性加速：内建聚合（`sum`/`min`/`sorted`）、推导式优于 append 循环、`str.join` 优于 +=。数值密集负载越过临界点就该上 NumPy（连续内存 + SIMD，见 [05-数据分析与机器学习](../06-应用领域/05-数据分析与机器学习.md)）——"循环里逐元素算"转成"整列运算"通常是一个数量级。

### 杠杆三：缓存与惰性

- `functools.lru_cache` / `cache`（见 [05-函数](../01-语言核心/05-函数.md)）：纯函数 + 重复参数的场景零成本收益；缓存必须有上界（内存账，见 [01-内存管理与垃圾回收](01-内存管理与垃圾回收.md)）。
- 惰性求值：不需要的不算（生成器管道，见 [06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)）；导入也惰性（函数内 import 重依赖）。
- IO 合并：N 次小读写成 1 次批量（数据库 `executemany` 见 [06-数据库操作](../02-IO与工程实践/06-数据库操作.md)；HTTP 合并端点见 [05-网络请求](../02-IO与工程实践/05-网络请求.md)）。

### 逃生舱：离开纯 Python 的时机与形态

| 形态 | 适用 | 成本 |
|---|---|---|
| 换库（NumPy/polars/PyTorch） | 数值、表、张量 | 学习 API |
| Cython / mypyc（类型注解编译） | 现有纯 Python 热路径 | 构建链复杂化 |
| PyO3（Rust 扩展） | 极致热点 + 生态分发 | 双语言维护 |
| Nuitka / PyInstaller 打包编译 | 部署形态需求为主 | 编译收益有限 |

判据：剖析证明热点 < 10% 的代码占 > 90% 时间，且算法杠杆已用尽，才动逃生舱——否则维护成本吞掉收益。

### 常识纠偏

- 3.11+ 的自适应解释器让"旧 Python 慢"的印象过期一档（见 [01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)）——升级版本常是最便宜的性能投资。
- 局部变量绑定、`__slots__`、避免属性查找：真实但小（个位数 %）；放在结构决策之后。
- 多线程不加速 CPU 密集（GIL，见 [03-并发与异步](03-并发与异步.md)）——"加线程"不是性能优化，是并发模型选择。

## 示例

```python
import timeit

setup = "data = list(range(10_000)); probe = range(9_000, 10_000)"

t_list = timeit.timeit(
    "hits = sum(1 for x in probe if x in data)", setup, number=10)   # O(n) 查找 × m 次
t_set = timeit.timeit(
    "s = set(data); hits = sum(1 for x in probe if x in s)", setup, number=10)

print(f"list: {t_list:.2f}s  set: {t_set:.4f}s")   # 典型差距 2~3 个数量级
```

```python
# cProfile 的正确读法：按 cumtime 找大头，按 tottime 找自身热点
# python -m cProfile -s cumtime app.py
#          ncalls  tottime  percall  cumtime  ...
#   1    0.001    0.001    8.213    parse_feed      ← cumtime 大：自己或其调用链贵
# 5000   7.800    0.0016   7.900    normalize       ← tottime 大：函数体本身是热点
```
