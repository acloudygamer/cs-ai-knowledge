# 05-版本演进

> 前置：[01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)（解释器版本语境） · 后续：各篇行内标注的"增量"汇合处

本库基准 Python 3.12 stable、latest 3.14（见 [versions.json](../versions.json)）。本篇是各篇"（3.13/3.14 增量）"标注的集中展开：按主题归并跨版本变化，给出升级纪律——**读变更不是背特性清单，而是知道每条变化动的是哪一层**（语言 / 标准库 / 实现）。

## 本质

- 版本节奏：每年 10 月一版，各版支持 5 年。stable（3.12）与 latest（3.14）的间距决定"生产保守、预研激进"的双轨策略。
- 每条变更落在三层之一：**语言层**（语法/语义，影响兼容性）、**标准库层**（新模块、废弃、移除）、**实现层**（CPython 性能与运行时机制，不改语义但改性能特征）。分层决定跟进成本：实现层白拿（升级即得）、标准库层看依赖、语言层看 `requires-python` 下限。

### 升级纪律

1. **先锁行为再升级**：测试与类型检查（[04-测试与质量](../04-测试与质量/README.md)）是升级的安全网；裸升级 = 盲飞。
2. **读两份清单**：What's New（特性）+ Deprecations/Removals（破坏面）。破坏面主要来自标准库层（模块移除、默认值变化）。
3. **`requires-python` 与 CI 矩阵先行**：版本支持范围是承诺（[04-打包与分发](04-打包与分发.md)），矩阵跑通（[07-CI-CD集成](../04-测试与质量/07-CI-CD集成.md)）再动代码。
4. **废弃警告当期处理**：`-W error::DeprecationWarning`（[08-错误与异常](../01-语言核心/08-错误与异常.md)）把"两年后的移除"提前到"今天的报错"。
5. **新特性采用阈值**：语言层特性等下限版本自然抬到后才进库代码；实现层收益（性能）随升级免费到账。

## 连接

**延伸**：官方 What's New 逐版清单是本篇的事实源；跟踪新 PEP 的入口是 peps.python.org。语言层历史的分水岭参考：3.0（unicode 默认）、3.5（async/await 与类型提示诞生）、3.10（模式匹配与 `|` 联合）、3.11（性能档位 + except*）、3.12（本库基线）。
