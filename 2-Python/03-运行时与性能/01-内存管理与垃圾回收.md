# 01-内存管理与垃圾回收

> 前置：[01-对象模型与变量](../01-语言核心/01-对象模型与变量.md)（PyObject 与引用语义）、[01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)（代价表里"对象头开销"的出处） · 后续：[03-并发与异步](03-并发与异步.md)（GIL 与引用计数的共生）、[05-数据分析与机器学习](../06-应用领域/05-数据分析与机器学习.md)（ndarray 为何省内存）

Python 的内存管理是两级结构：**引用计数**管绝大多数对象的即时生死，**分代 GC** 只负责引用计数管不了的一类死角（循环引用）。理解这两级的分工，"内存泄漏"在 Python 里就不再神秘——因为引用计数下泄漏几乎不是"忘释放"，而是"被谁偷偷引用着"。

## 本质

- 每个对象的引用计数归零即**立刻**释放（确定性，非等待 GC 周期）——`del x` 只是删名字（引用 -1），不是释放对象。
- 引用计数的天生死角：**循环引用**（`a.b = b; b.a = a`，互相持有则计数永不归零）。分代 GC（`gc` 模块）周期性扫描**容器对象**（list/dict/set/实例——int/str 等原子类型不参与），识别不可达环并回收。
- 内存来自 pymalloc 分配器（256 字节以下的小对象走 arena/pool/block 三级池），大块直接进系统堆——这解释了"百万小对象"场景的碎片与开销结构。

## 机制

### 对象开销的量级感

任何对象 ≥ 两个机器字（refcnt + type 指针）：空对象 `object()` 约 16 字节起步，`int` 28 字节（3.12 基准，小整数有缓存池）、空 `dict` 64 字节、空 `str` 49 字节。`sys.getsizeof(x)` 只给**浅层**大小——容器不算元素（1000 个元素的 list ≈ 8KB 指针 + 元素自身的百 KB）。真实驻留用 `tracemalloc`（见下文工具）。

省内存的三个正规杠杆：

| 杠杆 | 效果 | 代价 |
|---|---|---|
| `__slots__`（见 [07-面向对象](../01-语言核心/07-面向对象.md)） | 实例免 `__dict__`，每实例省约 40% | 失去动态加属性 |
| 生成器替代 list（见 [06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)） | $O(n)$ → $O(1)$ 工作集 | 单遍消费 |
| `array` / ndarray 紧凑存储（见 [02-内建数据结构](../01-语言核心/02-内建数据结构.md)） | 数据连续无对象头 | 失去泛型与协议 |

### 分代 GC 的行为参数

三代（0/1/2），新对象进 0 代；阈值默认 `gc.get_threshold() == (700, 10, 10)`——0 代分配净增 700 触发 0 代收集，幸存者晋升。含义：**GC 只扫描容器**且为了摊薄成本按代递减频率。工程后果：大量长寿命容器（缓存、注册表）会让 2 代收集越来越贵——这是"进程越跑越卡顿"的一类根因。`gc.freeze()`（fork 前冻结）与 `gc.disable()`（确认无环引用的场景，如纯 NumPy 管线）是两个逃生阀；禁用前必须确认没有循环引用产生。

### `__del__` 与弱引用

- `__del__` 在对象释放时调用：能做，但坑深——异常被吞、执行顺序不确定、 resurrection（`__del__` 里把 self 存到别处）会搞乱 GC。资源释放的正确工具是上下文管理器（[09-上下文管理器](../01-语言核心/09-上下文管理器.md)），`__del__` 只做兜底。
- `weakref.ref(obj)` / `weakref.WeakValueDictionary`：持有"不计入引用计数"的引用——缓存场景的正解（对象可正常死亡，缓存自动失效），打破循环引用的设计手段。

### 泄漏排查：Python 式的方法论

引用计数下"泄漏" = 对象被意外存活引用挂住。四大惯犯：模块级缓存/注册表只增不减；闭包与回调捕获大对象（[05-函数](../01-语言核心/05-函数.md) 的 cell）；**traceback 对象持有整条调用帧链**（异常记日志后仍长期持有 `e.__traceback__`——[08-错误与异常](../01-语言核心/08-错误与异常.md) 的隐性代价）；全局容器在异常路径漏清理。工具链：`tracemalloc`（标准库，快照 diff 定位分配点）、`objgraph`（按类型计数增长）、`memray`（火焰图级剖析，见 [02-性能优化与剖析](02-性能优化与剖析.md)）。

（Python 3.13 增量）free-threaded 构建里引用计数改为偏向计数（多线程安全），GIL 与引用计数的共生关系见 [03-并发与异步](03-并发与异步.md)。

## 连接

| 现象 | 根因 | 去 |
|---|---|---|
| 内存只涨不落 | 存活引用挂住（本篇四大惯犯） | 本篇 tracemalloc 方法论 |
| 偶发卡顿 | 2 代 GC 扫描大容器集 | 本篇阈值/禁用；数据外移到 ndarray |
| dict 键失效/缓存不释放 | 强引用缓存 | weakref 本篇；`lru_cache` 上限 |
| 大数据内存爆 | 全量物化 | 生成器管道（[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)） |
| 数值数组内存 | 对象头税 | ndarray（[05-数据分析与机器学习](../06-应用领域/05-数据分析与机器学习.md)） |

**延伸**：进程级隔离（内存故障域）见 [03-并发与异步](03-并发与异步.md) 的多进程一节；分配器的硬件背景（页/缓存）见 [0-计算机基础](../../0-计算机基础/README.md)。

## 示例

```python
import gc, sys, tracemalloc, weakref

class Node:
    def __init__(self):
        self.other: Node | None = None

a, b = Node(), Node()
a.other, b.other = b, a                 # 循环引用
del a, b                                # 引用计数不归零——等 gc 收
collected = gc.collect()                # 手动全代收集，返回回收数
print("cycles collected:", collected)

class Cache:
    _store: weakref.WeakValueDictionary = weakref.WeakValueDictionary()
```

```python
tracemalloc.start()                      # 泄漏定位：快照对比
snap1 = tracemalloc.take_snapshot()
leak = [{"payload": "x" * 1024} for _ in range(1000)]
snap2 = tracemalloc.take_snapshot()
for stat in snap2.compare_to(snap1, "lineno")[:3]:
    print(stat)                          # 文件:行号 + 增量字节——直指分配点
```
