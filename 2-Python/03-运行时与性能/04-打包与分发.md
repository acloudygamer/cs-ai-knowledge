# 04-打包与分发

> 前置：[10-模块与导入系统](../01-语言核心/10-模块与导入系统.md)（src 布局防遮蔽的伏笔）、[02-开发环境与工具链](../00-概览/02-开发环境与工具链.md)（声明与锁） · 后续：[07-CI-CD集成](../04-测试与质量/07-CI-CD集成.md)（发布流水线）、[08-CLI应用](../02-IO与工程实践/08-CLI应用.md)（入口命令）

从"能跑的目录"到"别人 `pip install` 一条命令拿到的包"，中间隔着打包体系。好消息是 PEP 621 之后全部事实收敛到一个 `pyproject.toml`；本篇讲清它的三个段（构建系统 / 项目元数据 / 工具配置）、wheel 与 sdist 的分发形态、src 布局的理由，以及发布流程。

## 本质

- **构建后端**（hatchling / setuptools / flit）负责把源码目录变成**发行物**：sdist（源码 tar，最后手段）与 **wheel**（预展开的二进制格式，安装器默认首选——装 wheel 免执行 setup，快且安全）。
- **安装器**（pip / uv）只消费发行物与元数据，按 `Requires-Dist` 拉依赖闭包。声明（pyproject）→ 构建（backend）→ 分发（PyPI）→ 安装（pip/uv）四段解耦，每段可替换——这是 PEP 517/518/621 十年收敛的结果。

## 机制

### pyproject.toml 三段式

```toml
[build-system]                      # 段一：怎么构建
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]                           # 段二：项目元数据（PEP 621）
name = "mylib"
version = "0.3.1"                   # 或 dynamic 动态提取
requires-python = ">=3.12"
dependencies = ["httpx>=0.27,<1"]   # 直接依赖（PEP 508）
[project.optional-dependencies]
dev = ["pytest>=8", "ruff>=0.6"]    # extras：可选功能组
[project.scripts]                   # 入口点：安装后生成命令
mycli = "mylib.cli:main"            # 命令 = 模块:函数
```

段三是各工具自己的表（`[tool.ruff]`、`[tool.pytest.ini_options]`）——一个文件承载全部配置是它取代 setup.py/setuptools.cfg 的直接原因。CLI 入口点即 [08-CLI应用](../02-IO与工程实践/08-CLI应用.md) 的交付形态；插件发现也走 entry points（`[project.entry-points."mylib.plugins"]`，配合 [10-模块与导入系统](../01-语言核心/10-模块与导入系统.md) 的 import_module 动态装载）。

### src 布局：防的就是 sys.path 遮蔽

```text
mylib/               # 仓库根
├── pyproject.toml
├── src/
│   └── mylib/       # 包在 src 下
│       ├── __init__.py
│       └── core.py
└── tests/
```

不加 src 时，项目根在 `sys.path`（[10-模块与导入系统](../01-语言核心/10-模块与导入系统.md) 的第 1 项），**本地源码永远遮蔽已安装版本**——测试跑的可能是残缺的本地树、漏打包的文件测得出来测不进去。src 布局强制"先安装（可编辑模式）再测试"，打包完整性由构建器保证。可编辑安装（PEP 660）：`uv pip install -e .` / `pip install -e .`——改动即时生效，机制回到 [02-开发环境与工具链](../00-概览/02-开发环境与工具链.md)。

### 版本约束语义（给依赖与被依赖两侧）

| 写法 | 含义 | 使用纪律 |
|---|---|---|
| `>=1.2` | 下界 | 常规 |
| `~=1.2.3` | `>=1.2.3, ==1.2.*`（兼容版本） | 库的常规选择 |
| `==1.2.3` | 精确锁定 | 只出现在锁/应用，不出现在库 |
| `^1.2`（poetry 系） | 同主版本 | uv/poetry 生态语法，PEP 508 之外 |

应用锁死（lock 文件）换可复现；**库必须留约束弹性**（下游要能解出共存版本）——两侧角色不可错位。语义化版本（SemVer）是弹性成立的社会契约：破坏性改动升主版本。

### 发布：从构建到 PyPI

```bash
uv build                # 产出 dist/mylib-0.3.1-py3-none-any.whl + .tar.gz
uv publish              # 上传 PyPI（或 twine upload dist/*）
```

工程要点：**纯 Python 包 wheel 是 `py3-none-any`**（全平台通用）；含 C/Rust 扩展才需要按平台出多 wheel（cibuildwheel 自动化，见 [07-CI-CD集成](../04-测试与质量/07-CI-CD集成.md)）。认证用 Trusted Publishing（OIDC，CI 里免令牌）优于长期 API token。发布不可撤回（同名版本号永不复用）——版本号发布前过一遍：CHANGELOG、git tag、`--dry-run` 检查。

### 私有分发与不分发

- 私有包：内部 index（devpi / PyPI 私有镜像 / Git+SSH 直装 `pip install git+ssh://…@v0.3.1`）。
- 不分发（单文件/内部工具）：`uv run --with httpx script.py`（临时依赖）与 [PEP 723 内联元数据]（脚本头声明依赖）覆盖"脚本想要包体验"的场景——不必为一个脚本建包。

## 示例

```toml
# 完整可用的最小库 pyproject.toml（hatchling + src 布局 + CLI + 插件点）
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "feedkit"
version = "0.3.1"
description = "Feed parsing toolkit"
requires-python = ">=3.12"
dependencies = ["httpx>=0.27,<1", "pydantic>=2.7"]

[project.optional-dependencies]
cli = ["typer>=0.12"]
dev  = ["pytest>=8", "ruff>=0.6", "mypy>=1.11"]

[project.scripts]
feedkit = "feedkit.cli:main"

[tool.hatch.build.targets.wheel]
packages = ["src/feedkit"]
```

```bash
uv venv && uv pip install -e ".[cli,dev]"   # 可编辑安装 + extras
feedkit --help                              # 入口点生效
uv build && ls dist/                        # wheel + sdist
```
