# 03-并发与异步

> 前置：[01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)（GIL 最小陈述）、[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)（生成器的暂停/恢复血缘）、[09-上下文管理器](../01-语言核心/09-上下文管理器.md)（锁的 with 形态） · 后续：[02-FastAPI](../06-应用领域/02-FastAPI.md)（async 服务）、[05-网络请求](../02-IO与工程实践/05-网络请求.md)（异步客户端）

并发的第一决策不是选库，是回答一个问题：**你的负载在等什么**？等网络/磁盘（IO 密集）与等 CPU（计算密集）走向完全不同的三套模型。本篇主线：GIL 为什么存在 → 三模型各自的机制与边界 → 统一 API（concurrent.futures）→ asyncio 的事件循环心智模型 → 三模型对比总表。

## 本质

- GIL（全局解释器锁）保护的是**引用计数的原子性**（见 [01-内存管理与垃圾回收](01-内存管理与垃圾回收.md)）：无锁的 `ob_refcnt += 1` 在多线程下会丢更新、对象提前死亡。代价：进程内同一时刻只有一个线程执行字节码。它限制的是**CPU 并行**，不限制**IO 并发**——阻塞式系统调用在 C 层释放 GIL。
- 三模型的本质：**多进程**换内存空间买真并行；**多线程**共享内存买 IO 并发（受 GIL 约束）；**asyncio** 单线程协作式调度——并发靠"主动让出"（await），切换成本最低但要求全链路非阻塞。

## 机制

### 先判断负载类型

```python
# 粗判：满 CPU 还是干等？
# 纯计算（解析、加密、图像） → CPU 密集 → 多进程 / free-threading
# 请求 API、读盘、查库各占比高、CPU 闲 → IO 密集 → 线程 或 asyncio
```

### threading：共享内存 + 锁纪律

```python
from concurrent.futures import ThreadPoolExecutor
import httpx

def fetch(url: str) -> int:
    r = httpx.get(url, timeout=5)          # 阻塞在 C 层，GIL 已释放
    return r.status_code

with ThreadPoolExecutor(max_workers=32) as pool:    # IO 密集：几十线程常态
    codes = list(pool.map(fetch, urls))             # 阻塞点交叠 = 并发
```

- 竞态：`counter += 1` 非原子（读-改-写三步）；共享可变状态要么上锁（`with lock:`，[09-上下文管理器](../01-语言核心/09-上下文管理器.md)），要么用队列解耦（`queue.Queue` 线程安全——生产者/消费者是默认架构答案）。
- 线程安全容器清单很短：`queue.Queue`、`list.append`（单操作原子）——复合操作（check-then-act）全部不安全（TOCTOU 见 [08-错误与异常](../01-语言核心/08-错误与异常.md) 的 EAFP 对照）。

### multiprocessing：真并行，按进程付账

```python
from concurrent.futures import ProcessPoolExecutor

with ProcessPoolExecutor(max_workers=8) as pool:    # CPU 密集：≈ 核数
    results = list(pool.map(heavy_parse, chunks))   # 参数/结果经 pickle 跨进程
```

三笔账：**序列化税**（任务与结果走 pickle，[03-序列化与配置格式](../02-IO与工程实践/03-序列化与配置格式.md)——传大对象不如传文件路径）；**启动税**（spawn 每进程重新 import，重依赖时显著）；**内存税**（每进程独立解释器）。收益边界：纯 CPU 任务且单任务足够大（毫秒级以上）才划算，细碎任务被税吃光。启动方式：Windows/macOS 默认 spawn；Linux fork 在 3.12 起与线程共用时弃用、3.14 起默认也转向 spawn/forkserver——新代码一律写 spawn 兼容（模块级可 pickle 的入口函数）。

### asyncio：事件循环与协作式调度

```python
import asyncio, httpx

async def fetch(client: httpx.AsyncClient, url: str) -> int:
    resp = await client.get(url)          # await：让出控制权，事件循环切去跑别的任务
    return resp.status_code

async def main(urls: list[str]) -> list[int]:
    async with httpx.AsyncClient(timeout=5) as client:
        async with asyncio.TaskGroup() as tg:       # 3.11+：结构化并发
            tasks = [tg.create_task(fetch(client, u)) for u in urls]
    return [t.result() for t in tasks]

asyncio.run(main(urls))                   # 事件循环的入口与出口
```

心智模型三条：

1. **`await` 是唯一让出点**：没有 await 的"协程"会独占循环（单线程里的霸占）；CPU 密集任务要用 `asyncio.to_thread` / `run_in_executor` 挪出去。
2. **全链路必须非阻塞**：一个同步 `time.sleep(1)` / `httpx.get`（同步版）混进 async 函数就冻结整个循环——这是 async 代码的头号事故；阻塞库的替代品必须成套换（[05-网络请求](../02-IO与工程实践/05-网络请求.md) 的 AsyncClient）。
3. **并发原语的 async 对应物**：`asyncio.Lock`/`Semaphore`/`Queue`、`async with`/`async for`（异步生成器，[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md) 的 async 同构）——同步版带进 async 世界是死锁制造机。

TaskGroup（3.11+）取代裸 `gather` 的理由：子任务异常时**取消其余兄弟任务**并抛 `ExceptionGroup`（`except*` 接收，见 [08-错误与异常](../01-语言核心/08-错误与异常.md)）——"一败俱撤"的结构化并发，没有任务泄漏。

### 三模型总对比

| 维度 | threading | multiprocessing | asyncio |
|---|---|---|---|
| 并行（多核 CPU） | 无（GIL） | 有 | 无（单线程） |
| IO 并发 | 有（阻塞释放 GIL） | 有（浪费） | 有（最优） |
| 切换成本 | 内核级（~μs 十级） | 进程级（最贵） | 函数级（最便宜） |
| 内存模型 | 共享 + 锁 | 隔离 + 消息（pickle） | 共享（单线程无抢占） |
| 故障隔离 | 差（一崩全崩） | 好（进程边界） | 差 |
| 生态约束 | 任意库 | 入口须可 pickle | 全链路 async 库 |
| 编程模型 | 抢占式（竞态暗处） | 显式分发 | 协作式（让出点显式） |
| 典型负载 | 中低并发 IO、封装不了的阻塞库 | CPU 密集 | 高并发 IO（百~万级连接） |

混合形态：**asyncio 驱动 + 线程池接阻塞库 + 进程池接 CPU 任务**是大型应用的常规拼法（FastAPI 的运行时即如此，见 [02-FastAPI](../06-应用领域/02-FastAPI.md)）。

### 前沿：free-threading 与子解释器

（Python 3.13 增量）free-threaded 构建实验性移除 GIL——多线程真并行，代价是单线程约慢一档（引用计数改偏向方案）；（Python 3.14 增量）free-threading 达到官方支持级别（PEP 779），`sys._is_gil_enabled()` 可探测。子解释器（PEP 734，3.14 增量）给"进程太重、线程太混"的中间态：单进程内多隔离解释器各持 GIL。两者均属"知道边界、按需跟进"的前沿，主线工程仍是三模型。

| 场景 | 走 |

## 示例

```python
"""同一负载的三模型对照：10 个慢请求（每个 1s）"""
import asyncio, time, httpx
from concurrent.futures import ThreadPoolExecutor

URLS = [f"https://httpbin.org/delay/1?i={i}" for i in range(10)]

def threaded() -> None:
    with ThreadPoolExecutor(10) as pool:
        list(pool.map(lambda u: httpx.get(u, timeout=10), URLS))

async def asynced() -> None:
    async with httpx.AsyncClient(timeout=10) as c:
        async with asyncio.TaskGroup() as tg:
            for u in URLS:
                tg.create_task(c.get(u))

t0 = time.perf_counter(); threaded(); t1 = time.perf_counter()
asyncio.run(asynced());   t2 = time.perf_counter()
print(f"线程池 {t1 - t0:.1f}s / asyncio {t2 - t1:.1f}s")   # 两者都 ≈ 1s（串行 ≈ 10s）
```
