# 07-日志与调试

> 前置：[08-错误与异常](../01-语言核心/08-错误与异常.md)（异常对象与 traceback）、[03-字符串与格式化](../01-语言核心/03-字符串与格式化.md)（惰性格式化） · 后续：[01-pytest基础](../04-测试与质量/01-pytest基础.md)（日志断言）、[07-CI-CD集成](../04-测试与质量/07-CI-CD集成.md)（日志即运维接口）

日志与调试是同一个问题的两半：**程序在运行时到底发生了什么**。日志是留给未来的自己的遥测，调试是当下的现场勘查。主线：logging 的"记录器-处理器-格式器"三件分离 → 结构化日志的工程形态 → 调试工具的梯度（print → breakpoint → 事后取证）。

## 本质

- `logging` 的架构是三级流水：**Logger**（按名字成树，调用方只管 `log.info(...)`）→ **Handler**（去哪：控制台/文件/网络）→ **Formatter**（长什么样）。调用点与输出配置彻底解耦——库只记录、应用统一配置，这条契约让三方库的日志能汇进你的系统。
- 级别是**过滤协议**：DEBUG < INFO < WARNING < ERROR < CRITICAL。记录器的有效级别沿树继承（自身未设则用父级）；Handler 各自再过滤一次——"库的 DEBUG 进文件、只把 WARNING 以上推终端"就是两次过滤的组合。

## 机制

### 记录器树与 root

`logging.getLogger(__name__)` 是唯一正确的取法——模块名即记录器名，天然按包结构成树。约束与后果：库代码**永不配置 root**（`basicConfig` 是应用入口的专属）；库的默认噪音用 `logging.getLogger("noisy.lib").setLevel(WARNING)` 压制，而不是全局调高。

### 惰性格式化：logging 不用 f-string

```python
log.info("order %s shipped, qty=%d", order_id, qty)   # 正确：延迟到真的要输出
log.info(f"order {order_id} shipped")                  # 反面：级别不够也先格式化
```

`%` 占位让格式化发生在"该条日志确定要输出"之后（承接 [03-字符串与格式化](../01-语言核心/03-字符串与格式化.md) 的四代对比——logging 是 `%` 风格的现代保留地）。

### 异常的归宿：exception()

```python
try:
    process(order)
except Exception:
    log.exception("order %s failed", order_id)   # ERROR 级 + 完整 traceback 自动附带
    raise                                        # 记录后原样上抛（见 08-错误与异常）
```

`log.exception` 只在 except 块内有效（捕获 `sys.exc_info()`）；`log.error(..., exc_info=True)` 是等价的显式形态。

### 配置：dictConfig 一步到位

`logging.config.dictConfig(...)` 用字典描述整套流水线（记录器/处理器/格式器/过滤器），从配置文件加载即得（[03-序列化与配置格式](03-序列化与配置格式.md)）。轮转件：`RotatingFileHandler`（按大小）与 `TimedRotatingFileHandler`（按天）——无轮转的文件日志终会吃满磁盘，这是运维事故的高发格式。

### 结构化日志：从 grep 到查询

传统一行文本对人是可读的，对机器是正则的（[02-正则与文本处理](02-正则与文本处理.md) 的无奈场景）。结构化方案：`structlog` 或 JSON formatter，把字段（`event`、`order_id`、`latency_ms`）作为一等公民输出 JSON lines——采集端（Loki/ELK）按字段过滤，正则退位。判据：服务有采集管线就上结构化；本地脚本 `basicConfig(format="%(levelname)s %(name)s %(message)s")` 足矣。

### 调试梯度

| 梯度 | 工具 | 场景 |
|---|---|---|
| 0 | `print` / `log.debug` | 一次性确认（易留垃圾，用后即删） |
| 1 | `breakpoint()`（3.7+，内置 pdb） | 断点交互：`n` 单步、`s` 步入、`c` 继续、`p expr` 打印、`l` 看代码 |
| 2 | IDE 断点 / `debugpy` | 常规开发主力（条件断点、变量视图） |
| 3 | 事后取证：`faulthandler`、`sys.excepthook`、core dump | 崩溃已发生、无法复现时 |
| 4 | `python -X importtime` / `py-spy` | 非侵入剖析：启动慢/线上卡顿（见 [02-性能优化与剖析](../03-运行时与性能/02-性能优化与剖析.md)） |

pdb 的两个救命件：**post-mortem**（`python -m pdb -c continue script.py` 崩溃后自动停在异常现场）与 `breakpoint()` 任意处植入。断言（`assert`）是调试的亲戚但语义不同：它验证**内部不变量**，失败即 bug，可被 `-O` 剥离（见 [01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)）；用户输入校验用异常（[08-错误与异常](../01-语言核心/08-错误与异常.md)），两者不可互换。

## 连接

| 现象 | 去 |

## 示例

```python
import logging

logging.basicConfig(level=logging.INFO,
                    format="%(asctime)s %(levelname)-7s %(name)s: %(message)s")
log = logging.getLogger(__name__)

def ship(order_id: int, qty: int) -> None:
    log.info("order %s shipping, qty=%d", order_id, qty)
    try:
        assert qty > 0, "invariant broken: qty must be positive"
    except AssertionError:
        log.exception("order %s invalid", order_id)
        raise

# 结构化升级（structlog 形态示意）：
# log.info("order_shipped", order_id=order_id, qty=qty, latency_ms=12.3)
```
