# 04-日期与时间

> 前置：[03-序列化与配置格式](03-序列化与配置格式.md)（ISO 8601 作为交换格式） · 后续：[07-日志与调试](07-日志与调试.md)（时间戳）、[02-性能优化与剖析](../03-运行时与性能/02-性能优化与剖析.md)（计时另有一套钟）、[06-数据库操作](06-数据库操作.md)（时间字段的存取）

日期时间的全部复杂度来自一件事：**时区与夏令时是人定的，不是数学**。语言层的 API 反而简单。本篇的主线是"naive 与 aware 之分 + UTC 纪律"——掌握这两条，datetime 模块就没有暗坑了。

## 本质

- `datetime` 的对象分两族：**naive**（无时区 attached，"墙上时钟"）与 **aware**（携带 tzinfo，绝对时刻）。两族不可直接比较/运算——`TypeError` 是语言在救你。
- 时间的三种语义必须分清：**时刻**（instant，`datetime` aware / `time.time()`）、**日期**（`date`，生日这种"每年重复"的概念）、**时长**（`timedelta`）。混用语义（拿时刻相减当日程用）是设计错误的源头。

## 机制

### 对象家族速查

| 类 | 表达 | 备注 |
|---|---|---|
| `datetime` | 时刻（含日期时间） | 主角；naive/aware 之分 |
| `date` / `time` | 纯日期 / 纯时间 | `time` 也可带 tzinfo（少用） |
| `timedelta` | 时长 | 任意两 date/datetime 相减的产物 |
| `timezone` | 固定偏移时区 | `timezone.utc` |
| `zoneinfo` | IANA 数据库时区（3.9+） | `"Asia/Shanghai"` 按名取，**处理 DST 的唯一正道** |

### UTC 纪律

存储与计算一律 aware UTC，仅在**展示层**转本地时区——这条纪律消灭八成时区 bug：

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

now_utc = datetime.now(timezone.utc)             # aware：绝对时刻
shanghai = now_utc.astimezone(ZoneInfo("Asia/Shanghai"))   # 同一时刻的本地表达
print(shanghai.tzname())                          # CST / UTC+8（按数据给出）
```

反模式：`datetime.now()`（naive 本地时间）入库——跨时区部署、DST 边界、服务器搬家时全部变成悬案。历史数据的 naive 值用 `replace(tzinfo=...)` **标注**假设时区（不是转换），再统一 `astimezone(timezone.utc)`。

### 解析与格式化：ISO 8601 是默认契约

- `dt.isoformat()` / `datetime.fromisoformat(s)`：机器交换的标准形态（序列化边界的首选，见 [03-序列化与配置格式](03-序列化与配置格式.md)；3.11 起 `fromisoformat` 放宽到接受大多数 ISO 变体，含 `Z` 后缀）。
- `dt.strftime(fmt)` / `strptime(s, fmt)`：人读格式的兜底（`%Y-%m-%d %H:%M:%S`）；格式指令与 f-string 的日期格式段同源（见 [03-字符串与格式化](../01-语言核心/03-字符串与格式化.md)）。
- 自由文本解析（"Aug 24, 2026"）用 `dateutil`（第三方）——strptime 写格式串写不完的交给它。

### 算术与 DST 边界

`timedelta` 算的是**物理时长**（绝对时间轴上的距离）。在 DST 时区里，"加一天"（日历语义）与"加 24 小时"（物理语义）在切换日相差一小时——日历运算用 `dateutil.relativedelta` 或显式的年/月/日字段运算。aware 对象相减自动穿越 DST 给出真实物理时长，这正是 aware 的价值。

### 两套钟：墙上时间 vs 单调时钟

| 需求 | 工具 | 特性 |
|---|---|---|
| 日志/业务时间戳 | `datetime.now(tz)` / `time.time()` | 墙上时钟：NTP 校时会让它**跳变**（前后甚至倒退） |
| 计时/性能测量 | `time.perf_counter()` | 单调递增、高分辨率——绝不会倒退 |

约束与后果：用 `time.time()` 算耗时会在校时瞬间给出负数；`perf_counter` 无绝对语义（起点任意），只做差值。剖析方法见 [02-性能优化与剖析](../03-运行时与性能/02-性能优化与剖析.md)。

### 时间戳的浮点细节

`time.time()` 返回 float 秒：2038 年以前精度足够，但 float 尾数在微秒级抖动——**顺序编号或排序键不要用时间戳**，用数据库自增、UUID（见 [06-数据库操作](06-数据库操作.md)）或 `time.time_ns()`。

## 示例

```python
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo

meeting = datetime(2026, 8, 24, 9, 0, tzinfo=ZoneInfo("Asia/Shanghai"))
utc = meeting.astimezone(timezone.utc)
ny = meeting.astimezone(ZoneInfo("America/New_York"))
print(f"UTC {utc:%H:%M} / NY {ny:%H:%M}")        # 同一时刻的三个表达

flight = timedelta(hours=13)
arrival = (meeting + flight).astimezone(ZoneInfo("America/Los_Angeles"))
print(arrival.isoformat())                        # 物理时长 + 落地本地时间

dt = datetime.fromisoformat("2026-08-24T09:00:00+08:00")   # 机器交换：ISO 直进
print(dt == meeting)                              # True：aware 比较看绝对时刻
```
