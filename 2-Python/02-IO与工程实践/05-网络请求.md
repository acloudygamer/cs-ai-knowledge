# 05-网络请求

> 前置：[08-错误与异常](../01-语言核心/08-错误与异常.md)（异常边界设计）、[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)（流式消费） · 后续：[03-并发与异步](../03-运行时与性能/03-并发与异步.md)（异步客户端与连接池）、[02-FastAPI](../06-应用领域/02-FastAPI.md)（对侧：服务端）

HTTP 客户端是业务代码与外部世界的接口层。本篇以 `httpx` 为主线（API 与 `requests` 几乎同形、同步异步双模、现代默认），讲清四件工程要件：**超时、重试、会话复用、流式处理**——这四件齐了，客户端代码的故障面就收敛了。

## 本质

- 请求/响应模型：方法 + URL + 头 + 体 → 状态码 + 头 + 体。库的选择只影响人体工学，不影响模型；`httpx` 与 `requests` 共享 API 形状是刻意的（迁移成本低）。
- 客户端的可靠性 = **把"网络天然不可靠"翻译成明确的异常与策略**：超时定义"等多久"、重试定义"失败后怎么办"、连接池定义"复用到什么程度"（见 [03-并发与异步](../03-运行时与性能/03-并发与异步.md)）。

## 机制

### 超时：必须显式

```python
import httpx

resp = httpx.get("https://api.example.com/v1/ping",
                 timeout=httpx.Timeout(5.0, connect=3.0))   # 总 5s、连接 3s
```

默认超时的历史包袱：`requests` 不设（无限等待挂死 worker）、`httpx` 全局 5s（仍应按端点细化）。约束与后果：不设超时的客户端在服务端抖动时会耗尽上游线程/任务——这是级联故障的标准起点。长轮询/下载另配 `timeout=httpx.Timeout(10, read=60)`。

### 重试：只重可重试的

- 可重试：连接错误、`5xx`、`429`（读 `Retry-After`）。不可重试：`4xx`（重试同样再错）、已发出非幂等请求（`POST` 可能已生效）。
- 两条路线：`httpx.HTTPTransport(retries=N)` 只管连接级重试；应用级重试用 `tenacity`（指数退避 + 抖动——并发重试风暴的解药）：

```python
from tenacity import retry, stop_after_attempt, wait_exponential_jitter

@retry(stop=stop_after_attempt(3), wait=wait_exponential_jitter(1, 8), reraise=True)
def fetch(url: str) -> httpx.Response:
    with httpx.Client(timeout=5.0) as client:
        return client.get(url)
```

### 会话复用：Client 是一等公民

每请求新建连接 = 每次 TCP + TLS 握手（数十毫秒级税）。`httpx.Client` / `AsyncClient` 维护连接池与 cookie jar，跨请求复用——**任何脚本超过一次请求都该用 Client 上下文**（协议化清理见 [09-上下文管理器](../01-语言核心/09-上下文管理器.md)）：

```python
with httpx.Client(base_url="https://api.example.com",
                  headers={"Authorization": f"Bearer {token}"},
                  timeout=5.0) as client:
    user = client.get("/v1/user").json()
    client.post("/v1/events", json={"type": "login"})
```

### 流式处理：大响应不过内存

`client.stream("GET", url)` 返回惰性响应体——下载/处理 GB 级内容时逐块消费（承接 [06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md) 的管道思路）：

```python
with client.stream("GET", "/export/big.csv") as resp:
    for chunk in resp.iter_bytes(65536):      # 按块拿，工作集 O(1)
        sink.write(chunk)
```

### 异常分层与边界转换

`httpx` 异常树：`TransportError`（连接/超时，网络层）→ `HTTPStatusError`（`raise_for_status()` 触发，协议层）。客户端库的对外纪律：把这两层翻译成**自己领域的异常**（`raise APIError(...) from e`，见 [08-错误与异常](../01-语言核心/08-错误与异常.md) 的异常链），调用方不应被迫 import httpx 才能写 except。

### TLS 与安全基线

- 证书校验默认开启——`verify=False`（忽略证书错误）只许出现在抓包调试，进生产是事故隐患；自签内网证书用 `verify="corp-root.pem"` 指定 CA bundle。
- 永不手拼 URL 查询串（编码语义易错）：`params={"q": "a&b"}` 交给库转义（承接 [03-字符串与格式化](../01-语言核心/03-字符串与格式化.md) 的注入防线）。
- 密钥走环境变量（[03-序列化与配置格式](03-序列化与配置格式.md)），不进代码。

## 连接

| 任务 | 去 |
|---|---|
| 高并发 IO（成百上千请求） | `AsyncClient` + asyncio（[03-并发与异步](../03-运行时与性能/03-并发与异步.md)） |
| 自己暴露 HTTP API | [01-Web开发总览](../06-应用领域/01-Web开发总览.md) |
| JSON 响应的类型化 | pydantic `model_validate`（[11-类型提示](../01-语言核心/11-类型提示.md)） |

## 示例

```python
import httpx
from tenacity import retry, stop_after_attempt, wait_exponential_jitter

class APIError(Exception):
    pass

@retry(stop=stop_after_attempt(3), wait=wait_exponential_jitter(1, 8), reraise=True)
def fetch_user(uid: int) -> dict:
    with httpx.Client(base_url="https://api.example.com", timeout=5.0) as c:
        try:
            r = c.get(f"/v1/users/{uid}")
            r.raise_for_status()
        except httpx.HTTPStatusError as e:
            raise APIError(f"user {uid}: HTTP {e.response.status_code}") from e
        except httpx.TransportError as e:
            raise APIError(f"user {uid}: unreachable") from e
        return r.json()
```
