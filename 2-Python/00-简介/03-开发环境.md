# 开发环境

## 定义

Python 开发环境是**字节码执行 + 包解析 + 符号表管理**的运行时基础。安装 Python 本质是将 CPython 解释器（`python.exe`）及其标准库部署到本地文件系统，并通过 `PATH` 环境变量使解释器可被发现。虚拟环境通过目录隔离 + `sys.path` 调整实现依赖隔离。

## 数学模型

### 路径解析的形式化

当执行 `python script.py` 时，shell 查找 `python` 可执行文件的过程是**首个匹配原则**：

$$\text{python\_path} = \min \{ p_i \in PATH \mid \exists \text{python.exe} \in p_i \}$$

其中 $\min$ 按 $PATH$ 中的顺序定义（返回第一个匹配）。若有多个 Python 安装，后加入 PATH 的目录优先级更高（因为从左到右扫描）。

### 虚拟环境隔离的数学描述

虚拟环境的隔离效果可形式化为：

$$\forall \text{package } pkg \in \text{venv}_A.\text{site-packages}: \text{import }(pkg) \Rightarrow \text{venv}_A.\text{namespace}$$
$$\forall \text{package } pkg \in \text{venv}_B.\text{site-packages}: \text{import }(pkg) \Rightarrow \text{venv}_B.\text{namespace}$$

且 $\text{venv}_A.\text{site-packages} \cap \text{venv}_B.\text{site-packages} = \emptyset$（若使用 `--copies` 选项则例外）。

隔离的本质是 **sys.path 的有序优先**：

$$\text{import}(pkg) \iff \exists p \in \text{sys.path}: p = \text{venv\_A}/Lib/site-packages \land pkg \in p$$

### pip 依赖解析的约束

pip 使用**贪婪版本匹配**策略：

$$\text{selected\_version}(pkg) = \max \{ v \in \text{available\_versions}(pkg) \mid v \succeq \text{constraint} \}$$

其中 $\succeq$ 是满足约束的偏序关系。贪婪策略可能导致依赖冲突：

$$\exists pkg_A, pkg_B: \text{constraint}(pkg_A) \cap \text{constraint}(pkg_B) = \emptyset$$

当冲突发生时，pip 尝试找到兼容的版本组合，或报错退出。

### site-packages 的物理布局

<pre>
venv/
├── Lib/
│   └── site-packages/          # 第三方包
│       ├── mypackage-1.2.3.dist-info/
│       └── otherpkg-0.1.0.dist-info/
└── Scripts/                    # Windows 可执行文件
    ├── python.exe              # 入口点
    └── pip.exe                 # 包管理
</pre>

## 数据流

### Python 安装的数据流

<pre>
安装包 (.exe/.pkg)           文件系统                环境变量
+------------------+          +------------------+    +------------------+
| 解压标准库       | --------> | {prefix}/Lib/    |    | PATH += {prefix}|
| 复制 python.exe | --------> | {prefix}/Scripts/|    +------------------+
| 写入 pyvenv.cfg | --------> | pyvenv.cfg       |
+------------------+          +------------------+

pip 安装:
+------------------+          site-packages/      pip 缓存
| pip install pkg  | --------> | pkg/             | --------> pip-selfcheck.json
| (PyPI 查询)     |          | pkg-x.x.x.dist-info/
+------------------+          +------------------+
</pre>

### 虚拟环境隔离的数据流

<pre>
激活虚拟环境 (myenv)
1. PATH 修改: PATH = myenv/Scripts:原始 PATH
2. VIRTUAL_ENV = myenv
3. sys.path 被调整（插入 myenv/Lib/site-packages）

sys.path 调整逻辑:
+------------------+          +------------------+
| sys.path[0]     | = 脚本目录（保持不变）       |
| sys.path[1:]    | = myenv 的 site-packages 优先搜索
+------------------+

隔离效果:
- import mypackage 时，优先从 myenv/site-packages 加载
- 不同虚拟环境的同名包可共存（版本可能不同）
</pre>

### pip 安装的数据流

<pre>
pip install requests==2.28.0
1. PyPI 查询 → 获取包元数据 + wheel URL
2. 下载 wheel → 缓存到 ~/.cache/pip/
3. 解压到 site-packages/
4. 创建 .dist-info/ 目录（包含元数据）
5. 更新 pip-selfcheck.json

冲突检测:
pip install pkg_a pkg_b
若 pkg_a 依赖 (pkg_c >= 1.0) 且 pkg_b 依赖 (pkg_c < 1.0)
→ 依赖冲突，pip 会报错
</pre>

## 机制

### 虚拟环境的三层隔离

虚拟环境通过**三层隔离**实现：

1. **解释器副本**：通过 symlink 或 copy 指向原始 Python
2. **site-packages 隔离**：独立的第三方包目录
3. **sys.path 调整**：优先搜索虚拟环境的包

关键约束：`pyvenv.cfg` 中的 `home` 指向原始 Python 安装路径，解释器本身的 stdlib 来自原始安装，仅 site-packages 来自虚拟环境。

### pip 的包解析机制

pip 从 PyPI（默认）或镜像源下载包。三种分发格式：

| 格式 | 特点 | 安装速度 |
|------|------|----------|
| sdist (.tar.gz) | 源码，需编译 | 慢 |
| wheel (.whl) | 预编译，直接安装 | 快 |
| binary wheel | 平台特定 | 最快 |

pip 的版本解析使用**语义版本**（Semantic Versioning）：
- `>=1.0,<2.0`：兼容版本约束
- `~=1.4`：至少 1.4，向上兼容（`>=1.4,<2.0`）
- `==1.4.2`：精确版本

### pyvenv.cfg 的配置约束

```ini
home = /usr/local/python3.12
include-system-site-packages = false
version = 3.12.0
```

- `home`：指向原始 Python 安装，解释器从此处加载 stdlib
- `include-system-site-packages`：是否包含系统 site-packages（默认 false）
- `version`：Python 版本号

### 版本约束（Python 3.12 stable / Python 3.14 latest）

本目录底座为 Python 3.12，前沿为 Python 3.14。

约束：Python 3.14 是前沿版本，可能存在不稳定因素。生产环境应使用 Python 3.12 稳定版。
