# 函数

## 定义

函数是**可调用对象**，本质是代码对象（`codeobject`）与命名空间（`globals`）的绑定。`def` 是创建函数对象的语法糖——它在运行时创建 `function` 对象并绑定到当前命名空间。函数调用通过 `CALL_FUNCTION` 字节码触发，参数传递本质是命名空间中的名称绑定。

## 数学模型

### 闭包的 λ 演算形式语义

闭包是 **λ 演算的工程实现**。设外层函数的自由变量为 $v_1, v_2, \dots, v_n$ ，闭包函数为 $f$ ：

$f = \lambda x . \text{body}(x, v_1, v_2, \dots, v_n)$

CPython 实现中，闭包变量存储在 `cell` 对象中。多个函数可共享同一 `cell` 对象（若它们捕获同一外层变量）。

### 递归深度约束

Python 不做尾递归优化，调用栈深度约 1000 层（可调但有限）：

$\text{recursion\_depth} \leq \text{sys.getrecursionlimit()} \approx 1000$

超出限制会触发 `RecursionError`。这是 CPython 的设计决策，与 Scheme 等语言不同。

### 高阶函数的形式化

高阶函数是**以函数为输入或输出的函数**：

$f: (A \to B) \to C \quad \text{或} \quad g: A \to (B \to C)$

例如 `map`：

$\text{map}(f, [a_1, a_2, \dots, a_n]) = [f(a_1), f(a_2), \dots, f(a_n)]$

`reduce` 的形式语义：

$\text{reduce}(f, [a_1, a_2, \dots, a_n], init) = \begin{cases} \text{reduce}(f, [f(init, a_1), a_2, \dots, a_n]) & n > 1 \\ f(init, a_1) & n = 1 \end{cases}$

## 数据流

### 函数定义与调用的数据流

<pre>
def add(a, b):
    return a + b

# 定义时：
1. 编译函数体为 codeobject
2. 创建 function 对象 {codeobject, globals}
3. 将 "add" 绑定到 function 对象

add(1, 2)
# 调用时：
1. 创建新帧（frame）
2. 绑定实参到形参（位置/关键字）
3. 在新帧中执行 codeobject 字节码
4. 返回时帧被销毁
</pre>

### LEGB 作用域查找的数据流

<pre>
x = "built-in"
def outer():
    x = "enclosing"
    def inner():
        x = "local"  # 写入 local 槽
        print(x)     # 查找顺序：local → enclosing → global → built-in
    inner()

# inner() 执行时，x 的查找路径：
LEGB 查找链：
1. Local（inner 的局部作用域）：找到 "local"，停止查找
2. 若未找到，继续 Enclosing（outer 的作用域）
3. 若未找到，继续 Global（模块作用域）
4. 若未找到，继续 Built-in（builtins 模块）
</pre>

### 闭包捕获的数据流

<pre>
def make_adder(n):  # n 是自由变量，被闭包捕获
    def adder(x):
        return x + n
    return adder

add5 = make_adder(5)
add5(3)  # n=5 被捕获在 adder 的 __closure__ 中

闭包捕获过程：
1. make_adder(5) 被调用，n=5 绑定到外层帧
2. adder 函数被创建，n 不在 adder 的局部作用域
3. n 作为"自由变量"被捕获，存储在 adder.__closure__ 中
4. adder.__code__.co_freevars = ('n',)
</pre>

### 函数调用的参数绑定数据流

<pre>
def f(a, b, c=1, *args, d=2, **kwargs): pass

f(1, 2, 3, 4, d=5, e=6)

绑定过程：
1. 位置参数: a=1, b=2, c 被 *args 收集前暴露: c=3
2. *args: args=(4,)
3. 关键字参数-only: d=5
4. **kwargs: kwargs={'e': 6}
</pre>

## 机制

### 位置参数与关键字参数的绑定算法

当调用 `f(a, b, c=1, d=2)` 时：

1. **位置参数**：按顺序绑定到形参（`a`→第一个形参，`b`→第二个形参）
2. **关键字参数**：按名字匹配形参
3. `*args` 收集剩余位置参数
4. `**kwargs` 收集剩余关键字参数

Python 3.8+ 支持**位置参数-only**（`/` 左侧）和**关键字参数-only**（`*` 右侧）。

参数绑定的约束：
- 位置参数在关键字参数之前
- `*args` 必须在 `**kwargs` 之前

**违反约束**：位置参数在关键字参数之后会报 `SyntaxError`；`*args` 在 `**kwargs` 之后也会报 `SyntaxError`。

### 装饰器的组合原理

`@decorator` 是语法糖：

```python
@decorator
def target(): ...
# 等价于
target = decorator(target)
```

多个装饰器从内到外组合：

```python
@a
@b
@c
def target(): ...
# 等价于
target = a(b(c(target)))
```

装饰器链的执行顺序：先执行最外层，再执行内层，最后执行原函数。

**设计意图**：装饰器是一种 AOP（面向切面编程）机制，允许在不修改原函数的情况下添加横切关注点（日志、缓存、权限等）。

### 闭包的实现机制

CPython 中，闭包通过 `cell` 对象实现：

1. 外层函数的局部变量存储在 `cell` 中
2. 内层函数的 `__closure__` 指向外层 `cell` 对象的 tuple
3. 访问 `cell.cell_contents` 获取实际值

可变闭包变量（通过列表等封装）：

```python
def make_counter():
    count = [0]  # 封装为可变对象
    def inc():
        count[0] += 1
        return count[0]
    return inc
```

**约束**：闭包只能捕获外层函数的局部变量（而非全局变量）。若尝试在闭包内修改外层局部变量，会创建新的局部变量（Python 3+）。

### nonlocal 声明的语义

Python 3 引入了 `nonlocal` 关键字，允许闭包修改外层函数的变量：

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc
```

**语义**：`nonlocal x` 声明 `x` 是外层函数的局部变量，而非新的局部变量。这避免了创建一个新的 `count` 局部变量遮蔽外层 `count`。

### 尾递归的缺失

Python 不优化尾递归的原因：
- CPython 使用 C 风格的栈帧管理
- 尾递归优化需要运行时分析和技术支持
- Guido 认为栈跟踪对调试更重要

**尾递归示例**：
```python
def factorial(n, acc=1):
    return factorial(n-1, n*acc) if n > 1 else acc  # 尾递归位置
```

**约束**：在 CPython 中，深度递归会导致 `RecursionError`。即使函数处于尾递归位置，也不会被优化。

### 函数对象的内部结构

CPython 中 `function` 对象的结构：

```c
typedef struct {
    PyObject_HEAD
    PyObject *func_code;      // codeobject
    PyObject *func_globals;    // globals dict
    PyObject *func_defaults;   // 默认参数 tuple
    PyObject *func_closure;   // cell 对象 tuple
    PyObject *func_doc;       // __doc__
    PyObject *func_name;      // __name__
    // ...
} PyFunctionObject;
```

**设计意图**：函数对象将代码（codeobject）与执行环境（globals, closure）分离，使得同一段代码可以在不同的全局命名空间中执行。

### Frame 对象的生命周期

每次函数调用创建一个新的 Frame 对象：

1. **创建**：在堆上分配 frame 对象
2. **执行**：在 frame 中执行字节码
3. **销毁**：函数返回或异常时，frame 被释放

Frame 栈的结构：
```
Call Stack:
+---------+
| frame 0 |  (模块级 frame)
+---------+
| frame 1 |  (函数 A)
+---------+
| frame 2 |  (函数 B，当前执行位置)
+---------+
```

**约束**：递归调用创建多个 frame，frame 数量受 `sys.getrecursionlimit()` 限制。

```python
def timer(f):
    def wrapper(*args, **kwargs):
        import time
        t = time.time()
        result = f(*args, **kwargs)
        print(f"{f.__name__} took {time.time() - t}s")
        return result
    return wrapper

@timer
def slow_func(): pass

# nonlocal 示例
def outer():
    x = 1
    def inner():
        nonlocal x
        x = 2
    inner()
    print(x)  # 打印 2
```
