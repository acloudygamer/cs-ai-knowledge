# 面向对象编程

> **版本基准**：Python 3.12 stable（latest=3.14，新特性章节保留并标注）

## 本质

Python 的面向对象是**基于协议的结构化子类型**系统。类（class）是创建实例的模板，通过 `__init__` 构造器初始化实例状态。继承建立"是-a"关系，通过 C3 线性化算法确定方法解析顺序（MRO）。Protocol 定义结构子类型——只要对象有指定方法，即使不继承也算兼容。

## 数学模型

### 继承层次结构的 is-a 关系形式化

继承关系建立**子类型偏序** $(\mathcal{C}, \preceq)$：

 $C_1 \preceq C_2 \iff C_1 \text{ 继承自 } C_2$ 

is-a 关系的语义：
- **替代性**：若 $C_1 \preceq C_2$，则 $C_1$ 的实例可用于 $C_2$ 期望的任何上下文
- **可逆性不成立**： $C_2$ 的实例不一定能用于 $C_1$ 的上下文

### C3 线性化算法

设类 $C$ 继承自父类 $B_1, B_2, \dots, B_n$，MRO 通过合并所有父类的线性化结果得到：

 $\text{MRO}(C) = C + \text{merge}(\text{MRO}(B_1), \text{MRO}(B_2), \dots, B_1, B_2, \dots)$ 

合并规则：
1. 取每个列表的首元素
2. 若某元素是安全的（出现在所有列表的首位或不在任何列表的后面位置），则该元素被加入线性化结果
3. 重复直到所有列表为空

### Protocol 的结构子类型形式化

 $T \preceq_{\text{structural}} P \iff \forall \text{method } m \in P: m \in T$ 

即只要对象有 Protocol 要求的方法，即使不显式继承也算兼容。这是**鸭式类型**（Duck Typing）的静态类型化版本。

### dataclass 的自动生成约束

`@dataclass` 的字段数 $n$ 决定生成的代码量：

| 生成的特殊方法 | 复杂度 |
|---------------|--------|
| `__init__` | $O(n)$ |
| `__repr__` | $O(n)$ |
| `__eq__` | $O(n)$ |
| `__lt__`, `__le__`, etc. | $O(n)$ |

## 数据流

### 类实例化的数据流

<pre>
class Dog:
    species = "Canis"  # 类属性

    def __init__(self, name):
        self.name = name  # 实例属性

dog = Dog("Buddy")

执行流程：
1. 在 Heap 分配 Dog 实例（instance.__dict__ = {}）
2. 调用 Dog.__init__(dog, "Buddy")
3. 在 instance.__dict__ 中存储 {"name": "Buddy"}
4. 返回实例引用

对象布局：
+------------------+
| PyObject_HEAD   |  (type pointer + refcount)
+------------------+
| __dict__ = {}   |  (实例属性字典)
+------------------+
</pre>

### MRO 查找的数据流

<pre>
class D(B, C): pass

假设继承关系：
class A: pass
class B(A): pass
class C(A): pass

D 的 MRO: D → B → C → A → object

d.greet() 查找路径：
1. D.__dict__ 中查找 "greet"
2. B.__dict__ 中查找
3. C.__dict__ 中查找
4. A.__dict__ 中查找
5. object.__dict__ 中查找
6. 若未找到，抛出 AttributeError
</pre>

### property 的描述符协议数据流

<pre>
class T:
    @property
    def c(self): return self._c

# 等价于：
class T:
    def c(self): return self._c
    c = property(lambda self: self._c)

# 属性访问 dog.c 时：
1. 在 T.__dict__ 中找到 property 对象
2. 调用 property.__get__(dog, T)
3. 返回 self._c 的值

描述符协议：
__get__(self, instance, owner) → value
__set__(self, instance, value) → None
__delete__(self, instance) → None
</pre>

### 多继承的菱形问题与 C3 线性化

<pre>
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

菱形继承：
    A
   / \
  B   C
   \ /
    D

C3 线性化确保：
- D 的 MRO 中，B 在 C 之前（A 也在 B 和 C 之后）
- 同一个 A 子类不会出现两次
- 满足局部优先级原则

D 的合法 MRO: [D, B, C, A, object]
</pre>

## 机制

### 实例属性的存储

实例属性存储在 `instance.__dict__`（本质是 dict）中，而非存储在类中。这使得：
- 每个实例可独立拥有属性
- 后期可动态添加属性
- 相同类的实例可拥有不同属性

类属性存储在 `Class.__dict__` 中，实例通过 `instance.__dict__` 或 `type(instance).__dict__` 查找。

**设计权衡**：将实例属性存在 `__dict__` 中而非固定偏移位置，使 Python 对象的属性访问比 C++ 慢，但增加了灵活性。

### dataclass 的自动生成

`@dataclass` 是语法糖，自动生成：
- `__init__`：根据字段初始化
- `__repr__`：显示字段值
- `__eq__`：按字段比较

生成的代码等价于手动编写的样板代码。

### property 的描述符协议

描述符协议：`__get__`, `__set__`, `__delete__`。当访问属性时，若属性是描述符对象，解释器调用描述符的相应方法。

property 是实现 getter/setter 的便捷方式，内部通过描述符协议工作。

**描述符优先级**（从高到低）：
1. 数据描述符（定义了 `__set__` 或 `__delete__`）
2. 实例 `__dict__`
3. 非数据描述符（仅定义 `__get__`）
4. 类属性

### ABC 的运行时检查

抽象基类（ABC）通过 `__init_subclass__` 或 `register()` 实现虚拟子类。`isinstance` 检查会遍历类的 MRO，包括注册的虚拟子类。

约束：不能实例化抽象类（包含未实现的抽象方法的类）。

### 元类（Metaclass）的本质

元类是**创建类的类**。类定义是**元类实例化**的过程：

 $Class = MetaClass(\text{name}, \text{bases}, \text{attrs})$ 

默认元类是 `type`。自定义元类可控制类的创建过程：

```python
class Meta(type):
    def __new__(cls, name, bases, attrs):
        # 在类创建前修改 attrs
        return super().__new__(cls, name, bases, attrs)
```

**应用场景**：
- ORM 框架：自动将类属性映射到数据库列
- API 框架：自动注册路由
- 验证：检查类属性是否符合特定模式

### MRO 的 C3 线性化约束

C3 线性化必须满足以下约束：

1. **单调性**：子类的 MRO 必须在父类的 MRO 之前
2. **局部优先级**：父类列表中左边的类优先
3. **一致性**：同一个类不出现在线性化结果中多次

**违反约束**：若继承关系导致无法满足 C3 约束，Python 抛出 `TypeError`。

### 上下文管理器与 `__enter__`/`__exit__`

上下文管理器协议：

```python
with obj as value:
    # body

# 等价于：
value = obj.__enter__()
try:
    # body
finally:
    obj.__exit__(*exc_info)
```

**设计意图**：确保资源获取后一定被释放，即使发生异常。实现 RAII（Resource Acquisition Is Initialization）模式。

### slots 的内存优化

默认情况下，Python 对象通过 `__dict__` 存储实例属性，内存开销较大。`__slots__` 声明允许在类定义时固定属性集：

```python
class Point:
    __slots__ = ('x', 'y')
    def __init__(self, x, y):
        self.x = x
        self.y = y
```

**内存节省**：使用 `__slots__` 的对象不创建 `__dict__`，每个实例节省数十字节的内存。

**约束**：
- 只能使用 `__slots__` 中声明的属性
- 无法动态添加新属性
- 多继承时所有父类都必须有 `__slots__`

## 代码示例

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

p = Point(1.0, 2.0)

# Protocol 示例
from typing import Protocol

class Closeable(Protocol):
    def close(self) -> None: ...

class Resource:
    def close(self) -> None: ...  # 隐式满足 Protocol

r: Closeable = Resource()  # OK，不需显式继承

# slots 内存优化
import sys
class WithDict:
    def __init__(self):
        self.x = 1
        self.y = 2

class WithSlots:
    __slots__ = ('x', 'y')
    def __init__(self):
        self.x = 1
        self.y = 2

print(sys.getsizeof(WithDict()))  # 通常更大
print(sys.getsizeof(WithSlots()))  # 通常更小
```
