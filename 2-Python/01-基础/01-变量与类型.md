# 变量与类型

## 定义

Python 的变量是**命名对象引用**，采用引用语义而非值语义——变量名存储在命名空间（本质是 dict）中，绑定到堆上的对象。类型注解是**语法承诺**，解释器在解析阶段将注解字符串存入 `__annotations__`，不生成任何运行时检查代码。

## 数学模型

### 类型系统的形式化（集合论描述）

Python 的类型系统可形式化为**带标签的联合类型**：

$\tau ::= \text{int} \mid \text{str} \mid \text{list}[\tau] \mid \tau \to \tau \mid \dots$

类型层次结构是一个**偏序集** $(\mathcal{T}, \preceq)$ ，以 `object` 为上界：

$\forall \tau \in \mathcal{T}: \tau \preceq \text{object}$

子类型关系 $\preceq$ 满足：
- **自反性**： $\tau \preceq \tau$
- **传递性**：若 $\tau_1 \preceq \tau_2$ 且 $\tau_2 \preceq \tau_3$ ，则 $\tau_1 \preceq \tau_3$

### isinstance 的形式化

isinstance 检查的本质是**类型层次中的子类型判定**：

$\text{isinstance}(x, T) \iff \text{type}(x) \preceq_{\text{Python}} T$

这与 `type(x) == T` 不同——后者要求精确匹配，不考虑继承。

### 引用计数的数学描述

CPython 的引用计数是**确定性资源管理**：

$\text{bind}(v, o): rc(o) \leftarrow rc(o) + 1$
$\text{unbind}(v, o): rc(o) \leftarrow rc(o) - 1$
$\text{destruct}(o): rc(o) = 0 \implies \text{立即析构}$

这与 tracing GC（非确定性）的区别：
- **引用计数**：析构时机可精确预测
- **Tracing GC**：析构时机依赖 GC 触发条件

引用计数的**循环引用盲区**：

$\exists o_1, o_2: o_1 \rightarrow o_2 \land o_2 \rightarrow o_1 \land rc(o_1) > 0 \land rc(o_2) > 0$

此时两个对象的 rc 均不为零，但无法从全局 namespace 到达，需要 tracing GC 介入回收。

### 类型注解的语义

类型注解在 Python 3.5+ 中引入，本质是**注释而非约束**：

$\text{Ann}(x: \tau) \implies \text{存入 } \text{__annotations__}[\text{"x"}] = \tau$

运行时无任何检查。类型检查需通过 `mypy`/`pyright` 等静态分析工具实现。

## 数据流

### 赋值执行的数据流

<pre>
x = 10                    int 对象 (Heap)          namespace (dict)
+------------------+       +------------------+      +------------------+
| 1. eval(10)     | ----> | value: 10       |      | "x" → int_obj   |
| 2. 创建 int_obj |       | type: int       |      +------------------+
| 3. rc(int)=1   |       | rc: 1           |
| 4. ns["x"]=ref |       +------------------+
+------------------+

x = "hello"              int 对象              str 对象 (Heap)
+------------------+       +--------+           +------------------+
| 1. eval("hello")| ----> | rc: 0  | (析构)  | value: "hello"   |
| 2. rc(str)=1   |       +--------+           | type: str        |
| 3. rc(int)→0   |                             | rc: 1            |
| 4. ns["x"]=str |                             +------------------+
+------------------+
</pre>

### isinstance 执行的数据流

<pre>
isinstance(x, int)
1. 获取 x.__class__（实际类型）
2. 检查 type(x) 是否为 int 或 int 的子类（MRO 遍历）
3. 返回 True/False

isinstance(x, int | str)  # Python 3.10+ 联合类型
→ 分解为 isinstance(x, int) or isinstance(x, str)
→ 短路求值
</pre>

### 类型注解执行的数据流

<pre>
def f(x: int) -> str: ...
1. 解释器解析语法，将 "int" 和 "str" 作为字符串存入 __annotations__
2. 不生成任何运行时检查字节码
3. 字节码与注解完全分离

f.__annotations__  # {'x': <class 'int'>, 'return': <class 'str'>}
</pre>

### 引用语义下的 mutable 默认参数陷阱

<pre>
def append_to(item, target=[]):  # 默认参数 [] 在函数定义时求值
    target.append(item)
    return target

append_to(1)  # target = [1], rc(target) > 0，不会被回收
append_to(2)  # 共享同一个默认 list！ → [1, 2]
</pre>

**约束**：默认参数在函数定义时求值一次，存储在 `__defaults__` 中。若该对象可变，则所有调用共享同一对象。

## 机制

### 变量引用的本质

Python 对象存储在堆上，包含：
- 对象头（`PyObject_HEAD`）：类型指针 + 引用计数
- 对象体：实际数据

变量名存储在**命名空间**（本质是 dict）中，条目是指向堆对象的指针。重新赋值只改变指针指向，不改变对象本身。

这解释了 `x = 1; x = 2` 不冲突——两个整数对象独立存在，变量 `x` 依次指向它们。

**CPython 实现细节**：`PyObject_HEAD` 结构：
```c
typedef struct _object {
    _PyObject_HEAD_EXTRA
    PyTypeObject *ob_type;
    Py_ssize_t ob_refcount;
} PyObject;
```

### 引用语义 vs 值语义

| 特性 | Python (引用语义) | C/Java (值语义) |
|------|-------------------|-----------------|
| 变量存储 | 指针 | 值（栈上）或指针（引用类型） |
| 赋值行为 | 复制引用 | 复制值或引用 |
| 比较行为 | `==` 比较值，`is` 比较身份 | `==` 通常比较值 |
| 函数参数 | 引用传递 | 值传递或引用传递 |

### 动态类型的代价

动态类型使 Python 灵活，但每次属性访问需要：

$\text{attr\_lookup}(obj, name) = \underbrace{O(1)}_{\text{解引用}} + \underbrace{O(1)}_{\text{类型查找}} + \underbrace{O(1)}_{\text{属性表查找}}$

相比之下，C 的结构体访问是 $O(1)$ 直接偏移计算（类型在编译时确定）。

**性能影响**：动态查找导致 Python 的属性访问比 C 结构体字段访问慢 2-10 倍（取决于实现和缓存状态）。

### isinstance 的真正作用

`isinstance` 是 Python 运行时类型检查的唯一**显式**手段。对于 ABC（抽象基类），`isinstance` 还支持**虚拟子类**检查（通过 `register()` 注册的类）。

**设计意图**：`isinstance` 检查的是"对象能否被视为 T 的实例"，而非"对象是不是 T 的实例"。这包括继承和 ABC 注册。

### 数字类型的层次结构

<pre>
object
  │
  └── int / float / complex / bool
        │
        └── bool 是 int 的子类（True=1, False=0）

数值运算时的类型提升：
int + float → float
int + complex → complex
float + complex → complex
</pre>

### 引用计数的实现与循环引用

CPython 的引用计数是**确定性析构**——对象的生命周期由引用计数决定：

1. `rc = 0` 时立即调用 `__del__`（若有）并释放内存
2. **循环引用**：对象间相互引用但无法从外部访问时，`rc > 0` 但对象已不可达

**循环引用示例**：
```python
class Node:
    def __init__(self, next=None):
        self.next = next

a = Node()
b = Node()
a.next = b  # a 引用 b
b.next = a  # b 引用 a
del a
del b  # a 和 b 的 rc 均不为零，但已无外部引用
```

**约束**：循环引用的对象需要 tracing GC 在后续垃圾回收阶段回收。GC 触发时机不确定。

### 字符串驻留与 intern 机制

Python 对短字符串和标识符使用**驻留（interning）**：

$\text{intern}(s) = \begin{cases} \text{返回已存在的同一对象} & \text{若 } s \in \text{StringTable} \\ s \text{ 加入 StringTable} & \text{其他} \end{cases}$

**驻留范围**：
- 标识符（变量名、函数名）自动驻留
- 短字符串（通常 < 20 字符）在某些实现中驻留
- 运行时拼接的字符串通常不驻留

**设计原因**：字符串驻留可以节省内存，并使 `is` 比较在常见情况下成立，加速字典查找。

## 参考存根

```python
x = 1
x = "str"  # 类型改变，x 指向新对象

# 验证 isinstance
isinstance(42, int)        # True
isinstance(True, int)      # True（bool 是 int 的子类）
isinstance("42", str)      # True

# 类型注解不运行时检查
def f(x: int) -> str:
    return x  # 类型错误，但运行时只返回 x

# mypy 可检测：
# def f(x: int) -> str:
#     return x  # error: Return type "int" is incompatible with "str"

# 循环引用示例
class Node:
    def __init__(self):
        self.next = None

a = Node()
b = Node()
a.next = b
b.next = a
# del a; del b 后，对象仍在内存中等待 GC
```
