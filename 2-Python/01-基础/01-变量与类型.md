# 变量与类型

**变量是命名对象的引用，类型注解仅作提示，解释器在运行时推断实际类型。**

## 定义

- **变量**是名字到对象的绑定引用，同一名可在不同生命周期绑定不同类型对象
- **类型注解**是承诺而非约束——解释器不验证，仅 mypy/pyright 等静态检查工具使用
- **`isinstance()`** 是 Python 运行时类型检查的唯一手段

## 数据流

<pre>
赋值执行流程：
1. eval(右侧表达式) → 产生对象 → 引用计数 +1
2. 查变量名绑定槽
3. 槽指向新对象 → 旧对象引用计数 -1
4. 若计数归零 → 对象被 GC 回收
</pre>

<pre>
isinstance() 执行流程：
1. 检查 obj.__class__ 与 cls 是否相同或为子类
2. 对于联合类型 int | str → 递归检查每个分支
3. 返回 True/False
</pre>

<pre>
类型注解执行流程：
1. 解释器解析语法 → 将注解字符串存入 __annotations__
2. 不生成任何运行时检查代码
3. get_type_hints() 间接访问（可能触发延迟导入）
</pre>

## 机制

### 变量引用机制

Python 对象存储在堆上，变量名存储在局部/全局符号表中，表中条目是指向堆对象的指针。重新赋值只改变指针指向，不改变对象本身。这解释了为何 `x = 1; x = 2` 不冲突——两个整数对象独立存在。

### 动态类型为何存在

Python 采用引用语义加对象头（包含类型指针），使同一个变量名可在运行时指向不同类型对象。这与 C/Java 的值语义/静态类型不同——Python 的灵活性以每次属性访问需解引用为代价。

### 类型注解不做运行时检查的原因

类型注解在语法解析阶段就被处理成字符串存入 `__annotations__` 字典，不生成任何字节码。若需要运行时检查，必须用 `isinstance()` 或 `typing.cast()` 显式调用。

### isinstance 的工作原理

`isinstance` 检查对象的 `__class__` 属性是否与目标类型相同或为其子类。对于 `int | str` 这种联合类型，Python 3.10+ 会分解为 `isinstance(x, int) or isinstance(x, str)`。

## 数学模型

类型检查的子类型关系可形式化为：

$$
\text{isinstance}(x, T) \iff \text{type}(x) \preceq T
$$

其中 $\preceq$ 表示"是...的子类型"（包括自身）。

Python 的类型层次：

$$
\text{object} \succ \text{int}, \text{str}, \text{list}, \dots
$$
