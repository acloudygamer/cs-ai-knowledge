# 迭代器与生成器

## 定义

迭代器是**惰性数据的抽象协议**，通过 `__iter__` 和 `__next__` 两个方法控制数据消费。生成器是**惰性数据的工程实现**，通过函数体内的 `yield` 关键字自动创建状态机。两者的本质都是"按需计算"，通过延迟求值节省内存，适用于处理大数据集或无限序列。

## 数学模型

### 迭代器协议的形式化描述

迭代器是一个**有穷状态自动机**，带有终止状态：

$M = (S, s_0, \Sigma, \delta, F)$

其中：
- $S$ ：状态集合（迭代器的内部状态）
- $s_0 \in S$ ：初始状态（`__iter__` 返回的起点）
- $\Sigma$ ：输入字母表（`next()` 调用）
- $\delta: S \times \Sigma \to S \cup F$ ：状态转移函数
- $F$ ：接受状态集（`StopIteration`）

对于每次 `next()` 调用：

$\delta(s_{i-1}, \text{next}) = \begin{cases} s_i \in S & \text{若有下一元素，转移至新状态} \\ \text{StopIteration} \in F & \text{若无下一元素} \end{cases}$

### 生成器惰性求值的复杂度建模

对于处理 $N$ 个元素的序列：

| 实现 | 时间复杂度 | 空间复杂度 |
|------|------------|------------|
| 列表 | $O(N)$ | $O(N)$ |
| 生成器 | $O(N)$ | $O(1)$ |

生成器的时间仍然是线性的，但空间复杂度降为常数，因为只存储**当前状态**和**生成函数代码**。

### yield from 的委托语义

`yield from` 实现生成器委托，其语义等价于：

$\text{yield\_from}(g) \iff \text{for } x \text{ in } g: \text{yield } x$

形式化：

$\text{flatten}([x_1, [x_2, x_3], x_4]) = [x_1, x_2, x_3, x_4]$

`yield from` 还建立了**双向通信通道**——调用者可通过 `send()` 向生成器注入值：

$\text{send}(v) \iff \text{yield 表达式返回值} = v$

### itertools 的惰性组合语义

`itertools` 的函数返回迭代器对象，不一次性计算所有结果：

$S_{\text{infinite}} = (f(0), f(1), f(2), \dots)$

这些组合形成**数据流管道**，内存占用恒定：

$|S_{\text{pipeline}}| = O(1) \quad \text{无论处理多少元素}$

## 数据流

### for 循环的迭代器协议执行

<pre>
for item in iterable:
    # body

等价的执行流：
1. iterator = iter(iterable)  # 调用 __iter__
2. while True:
3.     try:
4.         item = next(iterator)  # 调用 __next__
5.         # body
6.     except StopIteration:
7.         break
</pre>

### 生成器执行的数据流

<pre>
def countdown(n):
    while n > 0:
        yield n
        n -= 1

gen = countdown(3)

状态转换：
gen = countdown(3)
  → 创建生成器对象，gen.__state__ = (n=3), gen.__frame__ = None
  → 未执行函数体

next(gen) 第一次
  → 创建 frame，执行直到 yield n
  → yield 3，frame 冻结，gen.__state__ = (n=2)
  → 返回 3

next(gen) 第二次
  → 恢复 frame 执行，yield 2
  → frame 冻结，gen.__state__ = (n=1)
  → 返回 2

next(gen) 第三次
  → yield 1，gen.__state__ = (n=0)

next(gen) 第四次
  → n=0，while 条件为假，函数返回
  → 抛出 StopIteration，frame 被清理
</pre>

### send() 的双向通信数据流

<pre>
def echo():
    while True:
        received = yield
        print(received)

gen = echo()
next(gen)        # 启动到第一个 yield，received 未被赋值
gen.send("hi")   # "hi" 被传递给 yield 表达式，作为其值
                 # 继续执行直到下一个 yield
</pre>

原理：`send(value)` 的参数被作为上一个 `yield` 表达式的值返回。

### yield from 的委托数据流

<pre>
def inner():
    yield 1
    yield 2

def outer():
    yield from inner()

list(outer())  # [1, 2]

数据流：
1. next(outer()) 调用 inner().__next__()，yield 1
2. next(outer()) 调用 inner().__next__()，yield 2
3. next(outer()) 触发 inner 抛出 StopIteration
   → outer 结束
</pre>

## 机制

### 生成器状态机的实现

CPython 中，生成器通过 **frame 对象**实现：

1. 生成器函数创建时，编译函数体为 codeobject
2. 首次 `next()` 时，创建 frame 对象并执行字节码
3. 遇到 `yield` 时，frame 暂停（冻结），yield 值通过 `gi_yieldvalue` 传递
4. 再次 `next()` 时，frame 恢复执行

生成器对象存储：
- `gi_frame`：frame 引用
- `gi_code`：codeobject
- `gi_running`：是否运行中
- `gi_yieldfrom`：当前委托的子生成器（若有）

### 生成器只能迭代一次的原因

生成器是**状态消耗型**对象：

$S_{\text{final}} = \emptyset \quad \text{（所有状态被消耗）}$

状态存储在 frame 对象中，一旦 `StopIteration` 抛出，frame 被清理，状态不可恢复。若需重新迭代，必须重建生成器对象。

**设计原因**：生成器的惰性求值意味着一旦元素被消费，它就不再存在于内存中。这是时间换空间的设计选择。

### StopIteration 的自动处理

`for` 循环自动处理 `StopIteration`：

```python
for x in gen:
    # 等价于：
try:
    while True:
        x = next(gen)
        # body
except StopIteration:
    pass
```

这意味着生成器的终止是隐式处理的，调用者无需关心。

### 生成器表达式 vs 列表推导式

| 特性 | 生成器表达式 | 列表推导式 |
|------|-------------|-----------|
| 语法 | `(x for x in iter)` | `[x for x in iter]` |
| 立即求值 | 否 | 是 |
| 内存占用 | $O(1)$ | $O(n)$ |
| 类型 | generator | list |

**设计意图**：生成器表达式延迟计算，适用于大数据集或无限序列；列表推导式立即计算，适用于需要多次迭代或需要索引/切片操作的场景。

### itertools 的惰性组合

`itertools` 的函数返回迭代器对象，不一次性计算所有结果：

```python
# 惰性管道示例
from itertools import count, islice

squares = (x**2 for x in count())  # 无限平方序列
first_10 = list(islice(squares, 10))  # 取前 10 个
# 只计算前 10 个，后续不计算
```

**常用 itertools 函数**：

| 函数 | 作用 | 复杂度 |
|------|------|--------|
| `count()` | 无限计数 | $O(1)$ 空间 |
| `cycle()` | 无限循环 | $O(n)$ 空间 |
| `chain()` | 连接多个迭代器 | $O(1)$ 空间 |
| `islice()` | 切片迭代器 | $O(1)$ 空间 |
| `filterfalse()` | 过滤 False 值 | $O(1)$ 空间 |

### 生成器的异常处理

生成器中的异常会传播到调用者：

```python
def gen():
    yield 1
    raise ValueError("error")
    yield 2

g = gen()
next(g)  # 1
next(g)  # ValueError 传播到此处
```

**约束**：异常在生成器的 `next()` 调用点传播，而非在生成器创建时。

### throw() 与 close() 的行为

生成器支持注入异常和强制终止：

```python
gen = some_generator()

# 注入异常到生成器内部
gen.throw(ValueError, ValueError("injected"))

# 强制终止生成器
gen.close()  # 在 yield 点抛出 GeneratorExit
```

**设计约束**：`close()` 在 `yield` 点抛出 `GeneratorExit` 异常，生成器必须处理或让它传播。忽略 `GeneratorExit` 会导致生成器被垃圾回收。

### 生成器与协程的关系

Python 的生成器和协程共享同一底层机制（frame 对象）：

| 特性 | 生成器 | 协程（asyncio） |
|------|--------|-----------------|
| 核心机制 | `yield` | `yield from` |
| 启动方式 | `next()` | `send()` |
| 用途 | 惰性数据生产 | 异步 I/O |

**历史演变**：Python 2.5 引入了 `send()` 方法，使生成器可用于协程；Python 3.5+ 的 `async/await` 语法将协程与生成器分离。

## 生成器 vs 列表

| 特性 | 生成器 | 列表 |
|------|--------|------|
| 内存占用 | $O(1)$ | $O(n)$ |
| 迭代次数 | 一次 | 多次 |
| 索引访问 | 不支持 | 支持 |
| 长度 | 未知 | 已知 |
| 适用场景 | 大数据、无限序列 | 小数据、需随机访问 |

## 参考存根

```python
def flat(lst):
    for item in lst:
        if isinstance(item, (list, tuple)):
            yield from flat(item)
        else:
            yield item

list(flat([1, [2, 3]]))  # [1, 2, 3]

# 双向通信
def echo():
    while True:
        received = yield
        print(received)

gen = echo()
next(gen)
gen.send("hello")  # 打印 "hello"

# itertools 示例
from itertools import count, islice, cycle

# 无限序列
squares = (x**2 for x in count())
list(islice(squares, 5))  # [0, 1, 4, 9, 16]

# 循环
c = cycle([1, 2, 3])
list(islice(c, 7))  # [1, 2, 3, 1, 2, 3, 1]
```
