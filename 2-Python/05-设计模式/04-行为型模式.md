# 04-行为型模式

> 前置：[05-函数](../01-语言核心/05-函数.md)（一等函数/singledispatch）、[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)（迭代器协议）、[04-控制流程与表达式](../01-语言核心/04-控制流程与表达式.md)（match 状态机） · 后续：[01-Web开发总览](../06-应用领域/01-Web开发总览.md)（中间件的责任链实例）

行为型模式管理"对象之间怎么协作"。Python 的一等函数吃掉了这里的半壁江山：策略=传函数、命令=可调用对象、观察者=回调注册。剩下值得手写的是**状态**（显式状态机）、**责任链**（中间件）与**中介者**（事件总线）。本篇按"已消失的（一行形态）→ 仍必要的（手写形态）"组织。

## 本质

- 半数行为型的共同意图是"**把'做什么'做成可传递的值**"——Python 直接把函数当值（[05-函数](../01-语言核心/05-函数.md)），这些模式的骨架就塌缩成参数与回调。
- 剩下的一半管理**协作拓扑**：状态的迁移规则、请求的传递链、多对多的消息网——拓扑本身是复杂度所在，语言帮不上忙，值得显式建模。

## 机制

### 已消失的四个：一行形态

| GoF | Python 一行形态 | 备注 |
|---|---|---|
| 策略 | `sort(data, key=fn)` / 构造注入可调用 | 排序 key 是策略注入的最日常形态 |
| 命令 | 可调用对象（`__call__`，[07-面向对象](../01-语言核心/07-面向对象.md)） | 需要撤销栈/序列化命令时才有类形态（下节示例） |
| 观察者 | `hooks: list[Callable]` + 注册/通知 | 事件名→回调表的 dict 即可成器 |
| 访问者 | `functools.singledispatch`（按类型分派，[05-函数](../01-语言核心/05-函数.md)） | 双分派需求（两个维度）才手写 |

迭代器（Iterator）是彻底的语言内建——协议即模式（[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)），GoF 原文六个方法在 Python 剩 `__iter__`/`__next__` 两个。模板方法（父类定骨架、子类填钩子）仍存在于框架基类（unittest、ASGI app），但**组合的替代写法**（骨架函数接 hook 参数）通常更松——继承钩子与注入钩子的取舍同 [07-面向对象](../01-语言核心/07-面向对象.md) 的 mixin 判据。

### 仍必要一：状态机（State/Strategy 的状态版）

隐式状态（`if self.status == "PAID" and ...` 散落各处）是业务代码的腐化温床。显式化的两档：

```python
from enum import Enum, auto
class OrderState(Enum):
    NEW = auto(); PAID = auto(); SHIPPED = auto(); CLOSED = auto()

# 档一（轻量）：迁移表 —— 状态 × 事件 → 新状态
TRANSITIONS: dict[tuple[OrderState, str], OrderState] = {
    (OrderState.NEW, "pay"): OrderState.PAID,
    (OrderState.PAID, "ship"): OrderState.SHIPPED,
    (OrderState.SHIPPED, "close"): OrderState.CLOSED,
}

def step(state: OrderState, event: str) -> OrderState:
    if (next_state := TRANSITIONS.get((state, event))) is None:
        raise InvalidTransition(state, event)      # 非法迁移显式失败（见 08-错误与异常）
    return next_state

# 档二（重量）：状态类族 —— 每状态一个类，行为随状态换（GoF State 原形态）
```

档一覆盖大多数业务（迁移表可测试、可打印——[04-参数化测试](../04-测试与质量/04-参数化测试.md) 对表全量扫描非法组合）；档二只在"每状态行为差异大"时才值得。match 结构模式（[04-控制流程与表达式](../01-语言核心/04-控制流程与表达式.md)）是解析层状态机的利器。

### 仍必要二：责任链（中间件）

请求沿链传递、每环可短路或加工——HTTP 中间件是它最大规模的工业实践（ASGI/WSGI 的洋葱模型，[01-Web开发总览](../06-应用领域/01-Web开发总览.md)）：

```python
from collections.abc import Awaitable, Callable

Handler = Callable[[dict], dict]

def mw(h: Handler) -> Handler:                  # 中间件：接下一环，返回新环
    def wrapped(request: dict) -> dict:
        if request.get("auth") is None:
            raise PermissionError("no auth")     # 短路
        request["audit"] = True                  # 加工
        return h(request)
    return wrapped

pipeline = mw(mw(mw(core)))                      # 组链：装饰器堆叠的运行时形态
```

### 仍必要三：中介者与事件总线（Observer 的多对多版）

观察者（一对多广播）够用时用回调表；**多对多、跨模块、双向解耦**才上事件总线/消息中间形态：

```python
class EventBus:
    def __init__(self): self._subs: dict[str, list[Callable]] = {}
    def on(self, event: str, fn: Callable): self._subs.setdefault(event, []).append(fn)
    def emit(self, event: str, **payload):
        for fn in self._subs.get(event, []):
            fn(**payload)                        # 订阅方异常策略要显式定（谁都不想广播被一个坏订阅者炸掉）
```

纪律：事件总线是**解耦的最后手段**不是默认——调用关系被藏进字符串后，静态追踪消失（IDE 跳转、类型检查双双失效，[11-类型提示](../01-语言核心/11-类型提示.md) 的负资产）；跨模块通信用显式接口，"事件风暴"才引入总线。

### 空对象（Null Object）

`None` 检查散落时，给"什么都不做"一个真实现（`NullLogger`、空缓存）——标准库的 `contextlib.nullcontext`（[09-上下文管理器](../01-语言核心/09-上下文管理器.md)）就是该模式的库内样本。

## 示例

```python
"""命令模式的"有撤销"版本：可调用对象 + 逆操作栈"""
class Command:
    def do(self, model: dict) -> None: ...
    def undo(self, model: dict) -> None: ...

class SetTitle(Command):
    def __init__(self, new: str): self._new, self._old = new, None
    def do(self, model): self._old = model.get("title"); model["title"] = self._new
    def undo(self, model): model["title"] = self._old

history: list[Command] = []
def apply(model, cmd): cmd.do(model); history.append(cmd)     # 执行并入栈
def undo(model): history.pop().undo(model) if history else None
```
