# 02-创建型模式

> 前置：[01-Python视角下的设计模式](01-Python视角下的设计模式.md)（判决表）、[07-面向对象](../01-语言核心/07-面向对象.md)（classmethod/dataclass） · 后续：[03-结构型模式](03-结构型模式.md)

创建型模式管理"对象从哪来"。Python 的动态性让多数创建问题不存在（直接调类），本篇的实际内容是三个仍然成立的场景：**真全局状态**（单例）、**构造语义分裂**（备选构造/工厂）、**参数爆炸**（建造者）。

## 本质

- **单例**：`import` 系统已经是单例工厂——模块对象在 `sys.modules` 缓存、全进程共享（[10-模块与导入系统](../01-语言核心/10-模块与导入系统.md)）。90% 的"我需要单例"实际需要的是模块级实例。
- **工厂方法**：备选构造的正确形态是 `@classmethod`（[07-面向对象](../01-语言核心/07-面向对象.md)），多态构造靠类方法被子类覆写——不需要 GoF 的 Creator 类族。
- **建造者**：参数超过可读上限（约 5 个、或可选参数矩阵大）时，分步收集再一次性构造；dataclass 已消掉一半需求（关键字参数 + 默认值）。

## 机制

### 单例：三档答案

```python
# 档一（默认答案）：模块级实例 —— config.py
settings = Settings(env="prod")     # import config; config.settings 全进程同一对象

# 档二：真需要类形态（多态单例、懒加载）
class Singleton:
    _instance: "Singleton | None" = None
    def __new__(cls, *a, **kw):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

# 档三：注册表/依赖容器（"多例"按 key 单例）
_REGISTRY: dict[str, Engine] = {}
def get_engine(name: str) -> Engine:
    return _REGISTRY.setdefault(name, make(name))
```

约束与后果：单例 = 隐式全局状态——测试隔离的敌人（[02-Fixture](../04-测试与质量/02-Fixture.md) 每测试重建 vs 单例钉死）；多线程下 `__new__` 检查-创建有竞态（需锁，或接受 import 期完成的饿汉式）。Borg（共享 `__dict__` 的"状态单例"）知道即可：它共享状态而非身份，`is` 语义更反直觉。

### 工厂：从备选构造到注册工厂

```python
class Config:
    @classmethod
    def from_toml(cls, path): ...       # 备选构造：classmethod 是工厂方法的 Python 形态
    @classmethod
    def from_env(cls): ...

# 按 key 的多态构造：注册表 + entry points（插件形态，见 10-模块与导入系统/04-打包与分发）
LOADERS: dict[str, Callable[..., Loader]] = {}
def register(fmt: str):
    def deco(fn):
        LOADERS[fmt] = fn
        return fn
    return deco

@register("parquet")
def _load_parquet(path): ...
```

Abstract Factory（整族产品的一致创建）在鸭子类型下几乎不出现——族约束交给 Protocol + 一个工厂函数返回打包的命名元组即可。

### 建造者：两步走

```python
@dataclass
class Query:
    table: str
    columns: list[str] = field(default_factory=list)
    where: list[str] = field(default_factory=list)
    limit: int | None = None

class QueryBuilder:                     # 可变收集器（dataclass 默认冻结不了流式拼装）
    def __init__(self, table): self._q = {"table": table, "columns": [], "where": []}
    def select(self, *cols): self._q["columns"].extend(cols); return self
    def where(self, cond: str): self._q["where"].append(cond); return self
    def limit(self, n: int): self._q["limit"] = n; return self
    def build(self) -> Query:
        return Query(**self._q)         # 一次性产出不可变成品
```

判据：构造参数能一次写成可读的关键字调用 → 不需要 builder（`Query(table=..., columns=[...])` 即终态）；需要**条件分步 + 校验后置**才上 builder。SQL/HTTP 请求/图表配置是它的经典主场。原型（Prototype=深拷贝母本）在 Python 里就是 `copy.deepcopy`（[01-对象模型与变量](../01-语言核心/01-对象模型与变量.md)），单独成模式的理由已消失。

## 连接

| 需求 | Python 答案 |
|---|---|
| 全局配置/日志入口 | 模块级实例（本篇档一；logging 即此设计，[07-日志与调试](../02-IO与工程实践/07-日志与调试.md)） |
| 同一资源的受控复用 | 注册表/池（连接池，[06-数据库操作](../02-IO与工程实践/06-数据库操作.md)） |
| 插件式构造 | entry points + 注册表（[04-打包与分发](../03-运行时与性能/04-打包与分发.md)） |
| 测试中的"单例烦恼" | fixture 作用域重新供给（[02-Fixture](../04-测试与质量/02-Fixture.md)） |
| 参数爆炸 | dataclass 关键字参数优先，builder 兜底（本篇） |

## 示例

```python
"""注册工厂的完整闭环：open/extension 解耦 + 测试替身注入"""
from typing import Callable
import gzip, json
from pathlib import Path

_LOADERS: dict[str, Callable[[bytes], dict]] = {"json": json.loads}

def loader_for(suffix: str) -> Callable[[bytes], dict]:
    if handler := _LOADERS.get(suffix):
        return handler
    raise KeyError(f"no loader for .{suffix}")

def load(path: Path) -> dict:
    return loader_for(path.suffix.lstrip("."))(path.read_bytes())

_LOADERS["gzjson"] = lambda raw: json.loads(gzip.decompress(raw))   # 运行时注册
print(loader_for("json"))     # 测试注入：monkeypatch.setitem 改 _LOADERS（见 03-Mock与替身）
```
