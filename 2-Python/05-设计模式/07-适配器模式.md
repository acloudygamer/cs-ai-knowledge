# 适配器模式

## 定义

适配器模式是一种**接口兼容层抽象**：当已有接口（Adaptee）与调用方期望接口（Target）不匹配时，在两者之间插入适配器（Adapter）做双向转换，使两者能正常交互。从类型论角度看，适配器在两个接口类型之间建立了**同构映射**。

## 数学模型

**接口同构映射**：设 Target 接口类型为 $T_A$，Adaptee 接口类型为 $T_B$。适配器建立双向同构：

$$h: T_A \xrightarrow{\cong} T_B$$

具体地，Target 侧调用 $t: T_A$ 经适配器转换后映射为 Adaptee 侧调用 $a: T_B$：

$$h_T: T_A \rightarrow T_B,\quad h_B: T_B \rightarrow T_A$$

两者互为逆映射：

$$h_T \circ h_B = \text{id}_{T_B},\quad h_B \circ h_T = \text{id}_{T_A}$$

**参数映射的形式化**：设 Target 方法签名为 $t: X_T \rightarrow Y_T$，Adaptee 方法签名为 $a: X_A \rightarrow Y_A$。适配器实现转换函数：

$$f_T(x) \triangleq g_T(a(h_T(x))),\quad f_A(y) \triangleq g_A(t(h_A(y)))$$

其中：
- $h_T: X_T \rightarrow X_A$（参数结构转换）
- $h_A: Y_A \rightarrow Y_T$（返回值结构转换）
- $g_T: Y_A \rightarrow Y_T$（Target 侧返回值适配）
- $g_A: Y_T \rightarrow Y_A$（Adaptee 侧返回值适配）

**约束**：适配器是**被动转换器**——它不改变 Adaptee 的行为，只改变其外观。如果 Adaptee 本身行为不符合调用方预期，适配器无法修复。

**适配器的代数分类**：
- **对象适配器**：使用组合，$Adapter \xrightarrow{\text{持有}} Adaptee$
- **类适配器**：使用继承，$Adapter \leftarrow \text{继承} \rightarrow Adaptee$

**双向适配器的约束**：双向适配器同时实现两个接口，要求 $T_A$ 和 $T_B$ 的方法集合可互表示：

$$\text{MethodSet}(T_A) \subseteq \text{MethodSet}(Adapter) \cap \text{MethodSet}(T_B)$$

**归约终点**：适配器本质是**正交分解**的具体应用——将"接口不匹配"与"功能实现"分离，适配器处理接口层，Adaptee 处理功能层。在范畴论中，适配器是一个**函子**（functor）——它保持结构，将 $T_A$ 的对象映射到 $T_B$ 的对象，保持箭头（方法调用）。

## 机制

### 类适配器：多重继承的接口桥接

类适配器通过多重继承同时拥有 Target 接口和 Adaptee 的实现。可以**直接覆盖** Adaptee 的方法（通过 `super()`），但不支持同时适配多个 Adaptee。

```python
class Adapter(Target, Adaptee):
    def request(self):
        # 调用 Adaptee 的特殊方法
        return self.specific_request()[::-1]
```

**约束**：多重继承在 Python 中通过 MRO（方法解析顺序）处理，复杂继承层级可能导致方法解析不直观。类适配器要求 Adapter 同时继承 Target 和 Adaptee，这在 Adaptee 是类（非接口）时改变对象的类型层次。

### 对象适配器：组合持有的委托转发

对象适配器持有 Adaptee 实例（组合），将调用转发。可适配 Adaptee 的所有子类（多态适配）。

```python
class Adapter(Target):
    def __init__(self, adaptee: Adaptee):
        self._adaptee = adaptee

    def request(self):
        return self._adaptee.specific_request()[::-1]
```

**约束**：对象适配器不能直接调用 Adaptee 的 protected 方法（需要通过 public 接口）。但可以适配多个 Adaptee（通过组合多个 Adaptee 实例）。

**适配器选择策略**：
- 需要调用 Adaptee 的内部方法 → 类适配器
- 需要适配 Adaptee 的所有子类 → 对象适配器
- 需要同时适配多个 Adaptee → 对象适配器

### 双向适配器：双向翻译

双向适配器同时实现两个接口，使两个本不兼容的系统可以互相调用。需要同时了解两个接口的语义，职责较重，易成为维护热点。

```python
class BidirectionalAdapter(Target, Adaptee):
    def __init__(self):
        self._target = TargetImpl()
        self._adaptee = AdapteeImpl()

    def request(self):
        return self._adaptee.specific_request(self._target.request())

    def specific_request(self):
        return self._target.request(self._adaptee.request())
```

**职责过重的警示**：双向适配器同时知道两个接口的语义，违反单一职责原则。当任一接口变化时，双向适配器都需要修改。

### 适配器 vs 门面模式

| | 适配器 | 门面（Facade） |
|--|-------|--------------|
| 目的 | 使不兼容接口可交互 | 简化复杂子系统接口 |
| 转换方向 | 双向翻译 | 单向简化 |
| 接口暴露 | 暴露 Adaptee 的完整接口 | 只暴露必要接口，隐藏细节 |
| 转换逻辑 | 参数/返回值映射 | 封装多个调用为一个 |
| 设计视角 | 适配已有接口 | 简化新设计的接口 |

**门面模式是适配器的对偶**：适配器将不兼容的接口变得兼容，门面将复杂的接口变得简单。两者都在接口层做转换，但方向和目的不同。

### 适配器的使用时机

适配器适用于以下场景：
1. **遗留代码集成**：已有类库的接口不符合新系统要求
2. **第三方库集成**：不同第三方库的接口风格不一致
3. **接口标准化**：将不同实现统一到同一接口下

**不适用场景**：若 Adaptee 的行为本身不符合需求，适配器无法修复——此时应考虑**装饰器**（改变行为）或**策略模式**（替换算法）。

class Target:
    def request(self) -> str:
        return "Target: Default"

class Adaptee:
    def specific_request(self) -> str:

class ObjectAdapter(Target):
    def __init__(self, adaptee: Adaptee):
        self._adaptee = adaptee

    def request(self) -> str:
        return self._adaptee.specific_request()[::-1]
