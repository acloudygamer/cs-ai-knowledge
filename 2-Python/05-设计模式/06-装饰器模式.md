# 装饰器模式

装饰器模式是一种结构型模式，它动态给对象添加额外职责，比继承更灵活，支持运行时组合。

## 本质

```
原始对象 ──→ WrappedObject
              │
              └── WrappedObject.operation()
                  └─→ self._wrapped.operation() + 额外行为

装饰器链：
  Whip(Sugar(Milk(Coffee())))
  ──→ Whip → Sugar → Milk → Coffee
      每层 .operation() 调用内层，结果向外传播
```

**为什么需要装饰器**：继承在编译时静态绑定，且子类数量爆炸（每种功能组合都需要一个新子类）；装饰器通过组合替代继承，在运行时按需叠加功能。

**装饰器本质**：接受一个 callable（被装饰对象），返回一个包装后的 callable。装饰后的对象与原对象满足同一接口，调用者无感知差异。

## 类装饰器

装饰器类实现与被装饰类相同的接口，内部持有被装饰对象。

```python
class Coffee:
    def cost(self) -> float:
        return 5.0

class CoffeeDecorator:
    def __init__(self, coffee: Coffee):
        self._coffee = coffee

    def cost(self) -> float:
        return self._coffee.cost()

class Milk(CoffeeDecorator):
    def cost(self) -> float:
        return self._coffee.cost() + 1.5

class Sugar(CoffeeDecorator):
    def cost(self) -> float:
        return self._coffee.cost() + 0.5
```

## 函数装饰器

接受函数、返回包装函数，通过 `functools.wraps` 保留原函数元信息。

```python
import functools

def retry(max_attempts: int):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_attempts):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == max_attempts - 1:
                        raise
        return wrapper
    return decorator

@retry(3)
def call_api():
    pass
```

## 类作为装饰器

通过 `__init__` 接收被装饰函数，`__call__` 添加行为并转发调用。

```python
class CountCalls:
    def __init__(self, func):
        self._func = func
        self._count = 0
        functools.update_wrapper(self, func)

    def __call__(self, *args, **kwargs):
        self._count += 1
        return self._func(*args, **kwargs)
```

## 带参数的装饰器工厂

闭包嵌套：外层接收参数，内层接收函数，最内层才是包装器。

```python
def repeat(times: int):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator
```

## 装饰器 vs 继承

| | 装饰器 | 继承 |
|---|---|---|
| 功能添加时机 | 运行时动态 | 编译时静态 |
| 类数量 | 按需组合，不爆炸 | 2^n 种组合需要 2^n 个子类 |
| 可撤销 | 可在调用链中去掉某层 | 无法撤销 |
| 适用场景 | 可选功能、交叉关注点 | 永久性扩展 |
