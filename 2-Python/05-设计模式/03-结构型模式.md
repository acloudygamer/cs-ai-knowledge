# 03-结构型模式

> 前置：[05-函数](../01-语言核心/05-函数.md)（装饰器语法）、[07-面向对象](../01-语言核心/07-面向对象.md)（`__getattr__` 与描述符）、[10-模块与导入系统](../01-语言核心/10-模块与导入系统.md)（`__init__.py` 门面） · 后续：[04-行为型模式](04-行为型模式.md)

结构型模式回答"对象怎么拼装"。Python 里它们的三个主力替代件是：**装饰器语法**（@ 就是 Decorator 模式）、**协议**（鸭子类型让 Adapter 变薄）、**`__getattr__` 委托**（代理的通用机制）。仍需认真手写的是 Composite（树形结构）与中间件链（责任链，行为型篇但结构上同源）。

## 本质

- **装饰器**：GoF 意图的"运行时给对象加职责"，在 Python 里语法化成 `@deco`（实现与 `functools.wraps` 纪律见 [05-函数](../01-语言核心/05-函数.md)）——注意区分语言机制（函数装饰器）与模式意图（层层包裹的对象），后者仍出现在 `io` 流包装（`TextIOWrapper(BufferedReader(FileIO))` 就是活的 Decorator 链）。
- **适配器**：接口转换。鸭子类型下"接口"本来就是形状（Protocol），多数适配只剩"包一层改方法名"；对外部系统做防腐层是它最有工程价值的形态（[03-Mock与替身](../04-测试与质量/03-Mock与替身.md) 的"mock 你自己的封装层"是同一设计决策）。
- **门面**：给复杂子系统一个窄入口——`__init__.py` 的 API 收口（[10-模块与导入系统](../01-语言核心/10-模块与导入系统.md)）就是包级门面；函数本身就是"一行逻辑的门面"。

## 机制

### 代理：`__getattr__` 委托是通用件

```python
class LazyProxy:
    """惰性代理：首次使用才建真身（重依赖、远端连接的常驻形态）"""
    def __init__(self, factory: Callable[[], T]):
        self._factory, self._target = factory, None
    def _get(self) -> T:
        if self._target is None:
            self._target = self._factory()      # 首次访问触发
        return self._target
    def __getattr__(self, name):                 # 一切属性转发
        return getattr(self._get(), name)
```

`__getattr__` 只在常规查找失败时触发（查找链见 [07-面向对象](../01-语言核心/07-面向对象.md)），所以代理自身字段（`_factory`）不冲突——这是它能当"通用委托"的机制原因。代理的四个正当变体：**虚代理**（惰性，上例）、**保护代理**（权限/限流检查后转发）、**远代理**（RPC 客户端对象）、**智能引用**（引用计数/日志）。越界的信号：代理类里业务逻辑越积越多——那是门面或真对象的职责，不是转发层的。

### 适配器：防腐层的最小实现

```python
class WeatherProvider(Protocol):                 # 我方接口（形状）
    def temp_c(self, lat: float, lon: float) -> float: ...

class OpenMeteoAdapter:                          # 三方 API → 我方接口
    def __init__(self, client: httpx.Client): self._c = client
    def temp_c(self, lat, lon):
        r = self._c.get("/v1/forecast", params={"latitude": lat, "longitude": lon})
        return r.json()["hourly"]["temperature_2m"][0]
```

防腐层的价值随时间显现：三方 API 改字段/换版本，改一个 Adapter 文件；业务层与测试替身（按 Protocol 造假）全部不动——依赖倒置（[01-Python视角下的设计模式](01-Python视角下的设计模式.md)）的落地形态。

### 组合（Composite）：树形结构的自相似

```python
from dataclasses import dataclass, field

@dataclass
class Node:                                       # 叶与枝同接口 —— 组合模式的全部
    name: str
    size: int = 0
    children: list["Node"] = field(default_factory=list)

    def total(self) -> int:
        return self.size + sum(c.total() for c in self.children)
```

Composite 的本质是**递归自相似**：容器与元素同协议，客户端无需区分（文件系统、AST、UI 组件树、组织架构）。Python 里它通常是 dataclass + 递归方法；`__iter__` 生成器遍历（[06-迭代器与生成器](../01-语言核心/06-迭代器与生成器.md)）与 match 的类模式解构（[04-控制流程与表达式](../01-语言核心/04-控制流程与表达式.md)）是它的两大配套。享元（Flyweight=共享细粒度对象）在 Python 里的对应物是驻留/缓存（小整数与 identifier 驻留，[01-对象模型与变量](../01-语言核心/01-对象模型与变量.md)）——语言已在做的优化，业务层通常不需要再发明。

### 桥接与外观的"不需要证明"

Bridge（抽象与实现两维独立变化）在动态语言里通常就是"两个独立的组合参数"——构造函数接一个 Strategy 对象即完成解耦，无需类层次 surgery。Facade 的判断标准是**宽度**：子系统公共面收窄到一个模块/类（`__init__.py` 导出、`Service` 类聚合），门面不增加能力只收窄可见性。

## 示例

```python
"""保护代理 + 防腐层：限流的 API 客户端（结构模式的一次合用）"""
import time, httpx

class RateLimitedClient:
    def __init__(self, client: httpx.Client, rate: float):   # 组合注入真身（代理）
        self._c, self._rate, self._last = client, rate, 0.0
    def get(self, url: str) -> httpx.Response:
        wait = self._rate - (time.monotonic() - self._last)  # 保护逻辑（保护代理）
        if wait > 0:
            time.sleep(wait)
        self._last = time.monotonic()
        return self._c.get(url)

class RepoAdapter:                                            # 防腐层（适配器）
    def __init__(self, client: RateLimitedClient): self._c = client
    def default_branch(self, owner: str, repo: str) -> str:
        return self._c.get(f"/repos/{owner}/{repo}").json()["default_branch"]
```
