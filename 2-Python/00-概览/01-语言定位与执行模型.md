# 01-语言定位与执行模型

> 前置：无（全库起点） · 后续：[02-开发环境与工具链](02-开发环境与工具链.md)、[01-对象模型与变量](../01-语言核心/01-对象模型与变量.md)

本篇建立贯穿全库的两个锚点：Python 在语言光谱上的位置，以及一行代码从文本到结果的执行路径。后续各篇的"为什么"几乎都能回溯到这里——对象模型是"一切皆对象"这一执行模型事实的展开，GIL 是执行模型的并发约束（[03-并发与异步](../03-运行时与性能/03-并发与异步.md)），类型提示是对动态类型的工程补救（[11-类型提示](../01-语言核心/11-类型提示.md)）。

## 本质

Python 是动态强类型、多范式的字节码解释型语言，全部设计围绕一个取舍：**用机器时间换开发者时间**。性能缺口由 C/C++/Rust 扩展生态填补——NumPy 模式（Python 做调度、C 做计算）是这门语言在数据科学领域立足的结构性原因，而非巧合。

执行链三步，且对用户几乎透明：源码一次性编译为字节码（平台无关），缓存在 `__pycache__/*.pyc`，由 CPython 虚拟机（基于值栈的解释循环，`ceval.c` 的巨型 switch）逐指令执行。没有产品级 JIT（3.13 起的实验性 JIT 见 [05-版本演进](../03-运行时与性能/05-版本演进.md)）。"Python 慢"的准确表述是双层税：解释执行 + 一切皆对象的对象头开销——展开见下方代价表。

## 机制

### 语言光谱上的坐标

| 维度 | Python 的选择 | 意味着什么 |
|---|---|---|
| 类型系统 | 动态 + 强类型 | 类型运行时检查且不隐式跨类转换（`1 + "1"` 直接 `TypeError`）；对照 JS 的弱类型隐式转换 |
| 类型标注 | 可选、渐进（gradual typing） | 注解不改变运行时语义，由外部工具消费——见 [11-类型提示](../01-语言核心/11-类型提示.md) |
| 内存管理 | 引用计数为主 + 分代 GC 兜底 | 多数对象确定性释放，引用循环靠 GC——见 [01-内存管理与垃圾回收](../03-运行时与性能/01-内存管理与垃圾回收.md) |
| 并发 | GIL：进程内同一时刻仅一个线程执行字节码 | CPU 并行靠多进程，IO 并发靠异步——见 [03-并发与异步](../03-运行时与性能/03-并发与异步.md) |
| 范式 | 过程式 / 面向对象 / 函数式混用 | 函数是一等公民，类是运行时可改的对象——见 [05-函数](../01-语言核心/05-函数.md)、[07-面向对象](../01-语言核心/07-面向对象.md) |
| 实现 | CPython 为基准实现 | PyPy（JIT）、MicroPython（嵌入式）是替换实现而非方言；本库以 CPython 为准 |

### 执行模型：源码到字节码到结果

- **编译时机**：`import` 触发模块整体编译；REPL 逐单元编译；`compile()` 与 `ast.parse()` 可手动驱动。产物是字节码（`dis` 可反汇编）而非机器码。
- **`.pyc` 缓存**：按源文件 mtime + 大小校验失效。约束与后果：时间戳异常或直接替换 `.pyc` 会出现"改了代码行为没变"的幽灵问题，部署产物应编译后校验完整性（见 [04-打包与分发](../03-运行时与性能/04-打包与分发.md)）。
- **AST 是工具链地基**：ruff、格式化器、重构工具都工作在 `ast` 层——这也是它们能做"语义感知"而正则做不到的原因（对照 [02-正则与文本处理](../02-IO与工程实践/02-正则与文本处理.md)）。
- **解释循环**：帧对象（`PyFrameObject`）持有值栈与局部变量表；3.11 起解释器自适应特化（PEP 659，热点指令替换为类型特化版本），这是 3.11 整体提速约一档的主因。
- **`import` 即执行**：导入会运行模块顶层代码——库与入口必须分离、导入尽量无副作用，机制展开见 [10-模块与导入系统](../01-语言核心/10-模块与导入系统.md)。

### GIL 的最小陈述

同一进程内，任一时刻只有一个线程执行 Python 字节码；线程切换发生在解释器周期检查点（默认间隔 5 ms，`sys.setswitchinterval` 可调）。三条直接推论：

1. CPU 密集任务开多线程不加速，反而付线程切换与竞争开销；
2. IO 阻塞调用（`read`/`recv`/`time.sleep` 等）在 C 层显式释放 GIL，故 IO 并发用线程仍有效；
3. C 扩展可手动释放 GIL——NumPy 大数组运算期间其他线程可跑。

（Python 3.13 增量）free-threaded 构建实验性移除 GIL；（Python 3.14 增量）free-threading 升为官方支持（PEP 779），详见 [03-并发与异步](../03-运行时与性能/03-并发与异步.md)。

### 设计哲学及其代价

`import this`（Tim Peters 的 Zen of Python）浓缩了语言美学：显式优于隐式、扁平优于嵌套、可读性计数。两条需要展开的哲学，因为它们塑造了后续多篇的行为：

- **EAFP**（Easier to Ask Forgiveness than Permission）：先做，失败再接异常——异常是控制流而非耻辱，见 [08-错误与异常](../01-语言核心/08-错误与异常.md)；
- **鸭子类型**：关心对象"能做什么"（协议）而非"是什么"（血统），见 [07-面向对象](../01-语言核心/07-面向对象.md) 的协议小节。

每个设计选择都有结构对称的代价与工程对策，这张表是全库目录的另一种视角：

| 设计选择 | 收益 | 代价 | 工程对策（对应篇） |
|---|---|---|---|
| 动态类型 | 原型速度、灵活 | 类型错误运行时才暴露 | [11-类型提示](../01-语言核心/11-类型提示.md) + [04-测试与质量](../04-测试与质量/README.md) |
| 解释执行 + 一切皆对象 | 即时反馈、统一反射模型 | 比 AOT 编译慢一至两个数量级 | [02-性能优化与剖析](../03-运行时与性能/02-性能优化与剖析.md) |
| GIL | 引用计数免锁、单线程心智模型简单 | 进程内 CPU 并行受限 | [03-并发与异步](../03-运行时与性能/03-并发与异步.md) |
| 标准库"电池 included" | 开箱即用 | 边界处质量参差、演进受制于版本节奏 | 第三方选型见 [06-应用领域](../06-应用领域/README.md) |

## 连接

**何时选 Python，何时别选**：

| 场景 | 判断 |
|---|---|
| 数据/AI、脚本与胶水、测试与工具链、Web 业务后端 | 主场：生态与迭代速度压倒原始性能 |
| 系统编程、游戏引擎、实时音视频、微秒级延迟 | 别选：换 C++/Rust（本仓库 [3-C++](../../3-C++/README.md)）；热路径局部混合（Cython/PyO3）是折中 |
| 大团队长期维护的动态类型代码库 | 可选，但类型提示与质量门禁必须先行（[06-代码质量工具](../04-测试与质量/06-代码质量工具.md)） |

## 示例

```python
import dis, sys

def clip(x: float, lo: float, hi: float) -> float:
    return lo if x < lo else hi if x > hi else x

# def 执行时函数体已编译为字节码；dis 展示栈机指令流
dis.dis(clip)   # LOAD_FAST / COMPARE_OP / POP_JUMP_IF_FALSE / ...

print(sys.implementation.name)  # cpython —— 本库的基准实现
print(sys.version_info[:3])     # (3, 12, x)；3.13/3.14 特性各篇行内标注
```

```python
# 编译产物可见、可缓存：import 即触发编译并写 __pycache__
import ast, py_compile

py_compile.compile("mymodule.py")   # 生成 __pycache__/mymodule.cpython-312.pyc

tree = ast.parse("x = 1 + 2")       # AST 是工具链（ruff/格式化/重构）的地基
print(ast.dump(tree.body[0], annotate_fields=False))
# Assign([Name('x', Store())], BinOp(Constant(1), Add, Constant(2)))
```
