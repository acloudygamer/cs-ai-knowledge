# 内存管理

## 定义

Python 内存管理的核心是**引用计数**（reference counting）——每个堆对象维护一个整数计数器，记录指向该对象的引用数量，当计数归零时对象被立即回收。引用计数使 Python 拥有确定性的内存回收延迟：对象死亡的确切时刻就是引用计数归零的时刻，无需等待 GC 扫描。

## 数学模型

设对象 $o$ 的引用计数为 $rc(o) \in \mathbb{N}$。引用计数的操作语义：

| 操作 | $rc$ 变化 | 触发者 |
|------|-----------|--------|
| `o = expr`（创建引用） | $rc(o) \leftarrow rc(o) + 1$ | 赋值语句 |
| `del o`（删除引用） | $rc(o) \leftarrow rc(o) - 1$ | `del` 语句 |
| 变量超出作用域 | $rc(o) \leftarrow rc(o) - 1$ | 控制流 |
| 函数参数传入 | 调用方 $rc$ 不变；被调用方 $rc + 1$ | 调用约定 |

当 $rc(o) = 0$ 时，对象立即进入析构序列（调用 `__del__`，若存在）并释放内存。

**循环引用检测的约束**：设对象图 $G = (V, E)$，其中 $V$ 是对象集合、$E$ 是引用边。引用计数无法检测的子图满足：$G$ 内所有顶点入度 $\geq 1$，但 $G$ 整体无外部入边。GC 的标记-清除算法对此进行补充，时间复杂度 $O(|V| + |E|)$。

**归约终点**：Python 内存分配器可归约为**分层的 arena 分配器**——小块（$\leq 256$ 字节）由内存池（pool）管理，大块直接调用系统 `malloc`。

## 数据流

<pre>
对象创建                         引用计数更新
  │                                 │
  ▼                                 ▼
  PyObject_Malloc              rc(o) = rc(o) ± 1
  │                                 │
  ├── 小对象 (<=256B) ──→  pool: 预先分配的内存块
  │                                 │  (管理 4KB 页面)
  └── 大对象 (>256B) ──→  malloc: 系统堆直接分配
                                  │
                                  ▼
                            rc(o) == 0 ?
                             /          \
                          是            否
                           │              │
                           ▼              ▼
                       立即释放       保留在堆
                       (无 GC)           │
                                          ▼
                                      分代 GC 扫描
                                      (循环引用检测)
</pre>

**所有权流转**：
1. 对象创建：分配器分配内存，`rc = 1`
2. 引用传递：发送方 $rc + 1$，接收方接收引用
3. 引用销毁：$rc - 1$
4. $rc = 0$：析构函数调用（若存在），内存返还分配器
5. 分配器：小块返还 pool（不归还系统），大块归还系统

## 机制

### 引用计数的局限性

引用计数无法处理循环引用的根本原因：**引用计数是有向图的局部属性，入度为 0 是回收的必要条件，但非充分条件**。循环引用子图内每个对象入度 $\geq 1$，但子图整体无外部引用——所有局部计数 $> 0$，全局却应被回收。

Python 的分代 GC 通过**标记-清除**（mark-and-sweep）算法处理此问题：
1. **标记阶段**：从根集合（全局变量、栈帧）出发，DFS 标记所有可达对象
2. **清除阶段**：扫描整个堆，未被标记的对象判定为死亡，执行析构并释放

### 分代假说与 GC 触发

分代假说（Generational Hypothesis）：大多数对象生命周期很短——创建后很快变成垃圾，只有少数对象存活较长时间。因此 GC 应当频繁扫描年轻代（generation 0），少扫描老年代。

Python GC 的代际配置：
- Generation 0：新建对象放入此代
- Generation 1：经历一次 GC 仍存活的对象移至此代
- Generation 2：经历两次 GC 仍存活的对象移至此代

GC 触发阈值：代际 $i$ 的阈值为 `gc.get_threshold()[i]`（默认 700/10/10）。这意味着创建 700 个新对象后才触发 gen 0 扫描——而非每创建一个对象就扫描。

### Python 3.14 内存管理改进

Python 3.14 在 3.11-3.13 的自由线程模式（PEP 703）基础上继续完善内存管理：

**自由线程模式下的引用计数**：移除 GIL 后，引用计数的增减操作需要线程安全的原子操作。`Py_INCREF` / `Py_DECREF` 在自由线程模式下使用原子递增/递减指令（`__atomic_fetch_add` 等）。这引入了额外的同步开销，但允许多线程真正并行执行 Python 字节码。

**GC 的角色变化**：自由线程模式下，循环引用问题更加严重（多线程可能同时创建相互引用的对象图），GC 的稳定性成为关键约束。

### obmalloc 的三层架构

CPython 的 `obmalloc` 分配器分为三层：

| 层 | 对象大小 | 策略 | 内存来源 |
|---|---------|------|---------|
| `pool` | 8–256 字节 | 固定大小池（每 pool 4KB） | 预分配 arena |
| `arena` | 多个 pool | 64 pool / arena = 256KB | `mmap` (Linux) / `VirtualAlloc` (Windows) |
| `malloc` | > 256 字节 | 直接系统分配 | 系统堆 |

**设计意图**：避免频繁系统调用——小对象复用预先分配的 pool，只有 pool 耗尽才向系统申请新 arena。

**约束违反后果**：若程序大量分配 >256 字节的对象（ fragmentation 导致实际无法复用 pool），会导致内存向系统持续增长，因为大于 arena 大小的块直接调用 `malloc` 分配。

### 弱引用的机制

弱引用不增加引用计数：`weakref.ref(obj)` 返回一个包装对象，调用 `ref()` 返回被引用对象或 `None`。实现原理：

```python
class weakref:
    def __init__(self, obj):
        self._obj_id = id(obj)   # 存储对象 ID，而非引用
        # 对象注册到全局 __weakrefs__ 字典
    def __call__(self):
        # 通过 ID 查找对象是否仍存在
        # 若不存在（已被回收），返回 None
```

弱引用用于缓存场景：缓存应允许被缓存对象被回收，否则缓存会阻止对象死亡导致内存泄漏。

## 参考存根

```python
import gc
import weakref
import sys

# 引用计数观察
obj = [1, 2, 3]           # rc = 1
ref = obj                 # rc = 2
del obj                   # rc = 1（ref 仍存活）
del ref                   # rc = 0 → 立即回收

# 循环引用（引用计数无法处理）
class Node:
    def __init__(self):
        self.next = None

a, b = Node(), Node()
a.next = b                # b.rc += 1
b.next = a                # a.rc += 1
del a; del b              # a.rc = 1, b.rc = 1（循环！）
# 此时引用计数均为 1，但无外部引用
# 需等待 GC 标记-清除才能回收

# GC 手动触发
gc.collect()              # 强制全代扫描

# 弱引用缓存
cache = {}

def get_cached(key, factory):
    ref = cache.get(key)
    obj = ref() if ref else None
    if obj is None:
        obj = factory(key)
        cache[key] = weakref.ref(obj)
    return obj

# __slots__ 内存优化
class Point:
    __slots__ = ('x', 'y')   # 消除 __dict__，每个实例减少 ~56 字节
    def __init__(self, x, y):
        self.x = x
        self.y = y
```
