# 类型提示深入

## 定义

Python 类型提示是**渐进式类型系统的注解层**，在静态分析阶段（mypy、pyright）提供契约验证，在运行时通过 `__annotations__` 字典存储但**不强制执行**。类型检查器基于注解执行约束求解，类型提示的核心价值是将"类型契约"从隐式约定显式化为可机械验证的断言。

## 数学模型

### 类型环境与替换

令 $\Gamma$ 为类型环境（变量名→类型的映射），$e$ 为表达式。类型推断递归定义：

$$\Gamma \vdash e : T \iff \text{类型检查器在环境 } \Gamma \text{ 下推导出 } e \text{ 的类型为 } T$$

`TypeVar` $T$ 在泛型调用时进行替换。令 $\sigma$ 为类型替换（TypeVar → 具体类型）：

$$\text{instantiate}(\forall T.\, \tau) = \tau[T / \alpha] \quad \text{其中 } \alpha \text{ 是新鲜的类型变量}$$

对于 `list[T]` 调用 `list[int]`，替换 $\sigma = \{T \mapsto \text{int}\}$ 产生具体类型 `list[int]`。

### Protocol 结构子类型

结构子类型关系 $\leq_P$：若类 $C$ 实现了 Protocol $P$ 的所有方法（方法签名兼容），则 $C \leq_P P$。形式化：

$$C \leq_P P \iff \forall m \in P.\text{methods},\ m \in C.\text{methods} \land \text{signature}(C.m) \preceq \text{signature}(P.m)$$

其中 $\preceq$ 表示参数类型协变、返回类型逆变的子类型关系。

**协变/逆变规则的形式化**：

| 位置 | 子类型关系方向 | 示例 |
|------|---------------|------|
| 返回类型 | 协变：$A \leq B \implies T_A \leq T_B$ | `子类方法返回更具体类型` |
| 参数类型 | 逆变：$A \leq B \implies T_B \leq T_A$ | `子类方法接受更通用参数` |
| 协变位置（Python） | 注解处允许协变 | `-> int` 返回值 |
| 逆变位置（Python） | 参数处默认不变性 | `x: T` 参数 |

**不变性**：泛型容器默认不变（`list[int]` 不是 `list[Any]` 的子类型），因为双向协变会导致类型安全破坏：

```python
# 若 list 协变：
# def append_int(l: list[int]): l.append("str")  # 类型安全破坏
# list[int] <: list[Any] 允许上述调用

# 因此泛型默认不变：list[int] 与 list[Any] 无子类型关系
```

### NewType 的语义

`NewType` 创建语义区分类型。令 $N_T(x)$ 为 NewType 构造函数，$U_T$ 为底层类型：

$$\Gamma \vdash N_T(x) : N_T \quad \text{当且仅当} \quad \Gamma \vdash x : U_T$$

类型检查器视 $N_T$ 和 $U_T$ 为不同类型，但运行时 $N_T(x) = x$（恒等函数）。

**NewType 的语义图**：

```
类型检查时：                    运行时：
UserId(int) ──→ int           UserId(x) = x
  │                              │
  └── 视为不同类型                └── 恒等函数，无开销
```

### Union 与 Optional

$$\text{Optional}[T] \equiv \text{Union}[T, \text{None}] \equiv T | \text{None}$$

Union 成员满足分配律和交换律，但不满足幂等律（`Union[int, int]` 不等于 `int`，尽管可归约为 `int`）。

### 类型收窄的状态机模型

`isinstance` 分支的类型收窄可以建模为类型状态机：

$$Q = \{\text{full}, \text{ narrowed}_1, \text{ narrowed}_2, \dots\}$$

从 `full`（完整联合类型）出发，进入 `isinstance(x, int)` 分支后，类型收窄为 `int` 或抛异常。分支外恢复到 `full`（或 `int | str`）。

```python
x: int | str | None

# narrow to int in this branch
if isinstance(x, int):
    reveal_type(x)  # int
else:
    reveal_type(x)  # str | None
```

    │              ▼

    │
    └── 静态分析时：
              │
              ├── 词法/语法分析 → AST
              │
              ├── 类型注解解析 → TypeEnv（类型环境映射）
              │              │
              │              ▼
              │         约束收集：遍历 AST，为每个带注解表达式生成类型约束

              │              │
              │              ▼
              │         泛型实例化：为每个泛型调用执行替换 σ = {T ↦ α}
              │
              ├── Protocol 检查 → 结构子类型验证
              │              │
              │              ▼
              │         验证 C ≤_P P（类 C 是否实现 Protocol P 的所有方法）
              │
              ├── NewType 检查 → 语义类型区分
              │              │
              │              ▼

              │
              ├── 约束系统求解：联合求解所有类型方程
              │
              ├── 满足 → 类型正确，报告无错误
              └── 不满足 → 错误报告（含具体文件位置和行号）
</pre>

## 机制

### 类型检查器本质

类型检查器（如 mypy、pyright）执行的是**约束求解**而非解释执行。它将类型注解转为类型约束（如 "参数类型必须是 int"），收集所有约束后检查是否可满足。这决定了：

- **注解是合约，非执行**：即便注解声明参数为 `str`，传入 `int` 不会在运行时崩溃（除非检查器介入）
- **Any 是类型系统的黑洞**：`Any` 与任何类型双向兼容，使用 `Any` 的代码压制了该位置的静态检查
- **类型收窄是路径敏感的**：`isinstance` 分支内类型被收窄，分支外恢复为联合类型

**约束求解的复杂度**：类型检查的复杂度在最坏情况下是指数级的（取决于类型表达式复杂度），但实践中通常是线性的。

### TypeVar 约束的数学本质

`TypeVar('T', int, float)` 定义了类型变量的**可取值集合** $S_T = \{\text{int}, \text{float}\}$。类型检查器将约束求解限制在 $S_T$ 内：

$$\Gamma, T \in S_T \vdash f(x : T) : \tau \quad \Rightarrow \quad \forall \alpha \in S_T,\ \Gamma \vdash f(x : \alpha) : \tau[\alpha / T]$$

违反约束时（如传入 `str`），约束系统无解，检查器报错。

### Protocol 的结构子类型优势

相比 nominal subtyping（必须显式继承），结构子类型允许**事后协议化**——无需修改被测类，只需定义 Protocol，检查器自动验证接口兼容性。这对于第三方库和已有代码的模式化极为重要。

**约束**：Protocol 方法签名必须兼容（参数类型协变或逆变），否则结构子类型关系不成立。

### TypedDict 的运行时无强制

TypedDict 的类型检查仅在静态分析时生效：

```python
class User(TypedDict):
    name: str
    age: int

# 运行时：完全是普通 dict，键名由调用方保证
user: User = {"Name": "Alice", "age": 30}  # 检查器检查
user = {"name": "Bob"}  # 运行时完全合法，编辑器可能警告
```

### NewType 的编译时保护

NewType 的类型保护发生在静态分析阶段：

```python
UserId = NewType('UserId', int)
OrderId = NewType('OrderId', int)

def get_user(uid: UserId) -> str: ...

uid = UserId(123)
get_user(uid)        # OK：类型检查器接受
get_user(OrderId(123))  # ERR：即使底层值相同，语义类型不同
```

运行时：`UserId(123)` 就是 `123`，无任何额外开销。

### 违反约束的行为

| 约束类型 | 违反后果 |
|----------|----------|
| TypeVar 约束违例 | 类型检查器报错：`TypeError: Type variable must be X` |
| Protocol 方法缺失 | 类型检查器报错：类未实现 Protocol 方法 |
| NewType 混用 | 类型检查器报错：不能将 OrderId 传给需要 UserId 的函数 |
| TypedDict 键不匹配 | 类型检查器警告；运行时无异常 |
| Union 成员错误 | 类型检查器报错 |

## 参考存根

```python
from typing import TypeVar, Protocol, Union, NewType, TypedDict

T = TypeVar('T')

class Closable(Protocol):
    def close(self) -> None: ...

UserId = NewType('UserId', int)
OrderId = NewType('OrderId', int)

class User(TypedDict):
    name: str
    age: int

def process(x: Union[int, str]) -> Union[int, str]:
    return x

# TypeVar 泛型函数
def first(lst: list[T]) -> T | None:
    return lst[0] if lst else None

first([1, 2])      # T=int
first(['a', 'b'])  # T=str
```
