# 11-类型提示

> 前置：[05-函数](05-函数.md)（签名与注解位置）、[07-面向对象](07-面向对象.md)（Protocol 与 ABC 的对照） · 后续：[06-代码质量工具](../04-测试与质量/06-代码质量工具.md)（mypy/pyright 工程化）、[02-FastAPI](../06-应用领域/02-FastAPI.md)（注解的运行时消费）

类型提示是 Python 对动态类型的工程补救：**注解不改变运行时语义，静态检查器在运行前消费它们**。但要立刻补上另一半事实：注解是运行时可读的真实对象——pydantic、FastAPI 靠这半边吃饭。理解"两种消费端"（静态检查器 / 运行时框架）是本篇的主线。

## 本质

- 渐进类型化（gradual typing）：标注可以从无到有逐函数推进；未标注处检查器保守放行。类型系统的安全收益与标注覆盖率成正比。
- 注解存于函数的 `__annotations__`（PEP 3107 语义），运行时从不校验——`def f(x: int)` 传 str 照常执行。欺骗注解没有运行时惩罚，只有检查器报错。
- （Python 3.14 增量，PEP 649/749）注解默认惰性求值（按需计算描述符），`__annotations__` 语义迁移到注解 API——进口成本与前向引用问题双双缓解。

## 机制

### 语法演进：三代写法，工程只认最新

| 时代 | 泛型 | 可选/联合 | 备注 |
|---|---|---|---|
| ≤3.8 | `List[int]` / `Dict[str, int]`（typing 模块） | `Optional[X]` / `Union[X, Y]` | 遗留代码 |
| 3.9+ | `list[int]` / `dict[str, int]`（内建可下标） | 同上 | 内建泛型化 |
| 3.10+ | 同上 | `X \| None` / `X \| Y` | 管道联合 |
| 3.12+（PEP 695） | `def first[T](xs: list[T]) -> T`、`class Repo[T]` | 同上 | 类型参数原生语法，替代 TypeVar 样板 |

```python
def first[T](xs: list[T]) -> T: ...          # 3.12：无 TypeVar 声明行
def pair[K, V](k: K, v: V) -> dict[K, V]: ... # 多参数同理
class Repository[T]:                          # 泛型类：save(item: T) / get(id) -> T
    ...
```

### 常用构造速查

| 构造 | 语义 | 典型用法 |
|---|---|---|
| `X \| None` | 可空 | 返回可能失败的查找 |
| `Iterable[T]` / `Iterator[T]` / `Sequence[T]` | 协议分级（见 [06-迭代器与生成器](06-迭代器与生成器.md)） | 参数收最宽、返回给最窄 |
| `Callable[[int, str], bool]` | 可调用签名 | 回调参数 |
| `Literal["r", "w"]` | 字面量集 | 代替枚举的轻量约束 |
| `TypedDict` | dict 的字段级形状 | JSON 边界（见 [03-序列化与配置格式](../02-IO与工程实践/03-序列化与配置格式.md)） |
| `NewType("UserId", int)` | 语义化别名（运行时仍是 int） | 防止 id 串用 |
| `Protocol` | 结构类型（鸭子类型的静态化） | 接口约定，见 [07-面向对象](07-面向对象.md) |
| `cast(T, x)` | 无运行时效果的断言 | 检查器看不见的边界 |
| `Final` / `@final` | 禁止重绑定 / 禁止继承 | 常量与密封类 |

### 任类型的坑与窄化

`Any` 关闭检查（传染：`Any` 参与的表达式结果是 `Any`）——它是"此处放弃了"的标记，不是偷懒的借口。`object` 才是"任意值但只许 object 操作"。窄化来源：`if x is None` / `isinstance` / `assert` / `match` 的类模式（见 [04-控制流程与表达式](04-控制流程与表达式.md)）——检查器沿控制流缩窄类型，这是"标注 + 分支判断"组合成完整安全网的方式。

### 两种消费端

- **静态**（mypy / pyright）：CI 门禁的常规军——严格度分级配置、随代码演进收紧，工程化见 [06-代码质量工具](../04-测试与质量/06-代码质量工具.md)。
- **运行时**（pydantic / FastAPI / typer）：读 `__annotations__` 做验证、序列化、路由生成——**校验发生在框架边界而非语言层**，FastAPI 的请求解析即此机制（见 [02-FastAPI](../06-应用领域/02-FastAPI.md)）。混淆两者会得出"注解能防错"或"注解毫无用处"两种都错的结论。

### 纪律

- 公开 API（入口函数、类属性）优先标注，内部实现随改随标；`py.typed` 标记是库对外发布类型的前提（见 [04-打包与分发](../03-运行时与性能/04-打包与分发.md)）。
- 前向引用：类体内引用自身用字符串 `"Node"`；仅类型用的导入进 `if TYPE_CHECKING:` 块（兼治循环导入，见 [10-模块与导入系统](10-模块与导入系统.md)）。
- 注解必须真实：`-> int` 实际返回 None 是负资产——检查器、IDE、调用方三端被骗。

## 示例

```python
from typing import Literal, Protocol, TypedDict

Mode = Literal["r", "w", "a"]

class Source(Protocol):                 # 结构类型：不要求继承
    def read(self, n: int) -> bytes: ...

class Job(TypedDict):                   # dict 的字段级形状：JSON 边界建模
    id: int
    state: Literal["queued", "done"]

def drain(src: Source, chunk: int = 8192) -> int:
    total = 0
    while chunk_bytes := src.read(chunk):   # 窄化 + 海象（见 04-控制流程）
        total += len(chunk_bytes)
    return total

def route(job: Job, mode: Mode = "r") -> str | None:
    if job["state"] == "queued":
        return f"{mode}:{job['id']}"
    return None
```
