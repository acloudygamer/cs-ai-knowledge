# 06-迭代器与生成器

> 前置：[04-控制流程与表达式](04-控制流程与表达式.md)（for 的语法糖）、[02-内建数据结构](02-内建数据结构.md)（被遍历的容器） · 后续：[03-并发与异步](../03-运行时与性能/03-并发与异步.md)（async 迭代与协程的血缘）、[01-文件与路径](../02-IO与工程实践/01-文件与路径.md)（逐行流式读）、[02-性能优化与剖析](../03-运行时与性能/02-性能优化与剖析.md)（内存收益）

迭代协议是 Python 最深的一根管线：for、解包、推导式、`zip`/`enumerate`、`sum`/`min`/`max`，全部只认协议不认类型。本篇讲清协议两端（可迭代者 / 迭代器）与第三种角色（生成器），然后给出"管道化数据处理"的完整方法——它是"大数据放不进内存"的标准答案。

## 本质

- **可迭代者**（iterable）：实现 `__iter__`，能被 `iter()` 变成迭代器（容器们都属于此类；`__getitem__` 是兼容退路）。
- **迭代器**（iterator）：实现 `__next__`（取下一个，耗尽抛 `StopIteration`），且 `__iter__` 返回自身——迭代器是一次性游标。
- **生成器**（generator）：含 `yield` 的函数被**调用**时不执行，返回生成器对象；每次 `next` 执行到 `yield` 暂停，帧（局部变量 + 指令位置）完整冻结——语言级的暂停/恢复，正是它后来演化出协程的血缘（见 [03-并发与异步](../03-运行时与性能/03-并发与异步.md)）。

```python
for x in xs:            # 等价于：
    ...
# it = iter(xs)         # 容器 → 游标
# while True:
#     try: x = next(it)
#     except StopIteration: break
```

## 机制

### 一次性：最常踩的静默坑

迭代器耗尽后再迭代**不报错**，只是空。`it = map(...)` 后 `list(it)` 拿到结果、`sum(it)` 得 0——"结果神秘消失"几乎都源于迭代器被消费过两次。纪律：迭代器只 `list()` 物化一次；需要反复用就物化成 list（这正是 `map` 对象与 list 的本质区别）。`itertools.tee` 可分叉游标，但有缓冲代价。

### 生成器：管道的积木

- 生成器表达式 `(f(x) for x in xs if p(x))`：惰性、单遍、省内存——物化需求才升级成列表推导（承接 [04-控制流程与表达式](04-控制流程与表达式.md)）。
- 生成器函数：适合**多步骤有状态**的生产逻辑（读文件块、解析状态机）——状态存帧里，不存对象字段里。
- `yield from sub`：委托子生成器，等价 `for v in sub: yield v` 且透传 `send`/`throw`——管道级联的正确写法。
- 内存账：管道每级 $O(1)$ 工作集 vs 列表中转 $O(n)$；吞吐损失一级函数调用，数据量大时交换永远划算（剖析方法论见 [02-性能优化与剖析](../03-运行时与性能/02-性能优化与剖析.md)）。

### itertools：标准库的算法兵器架

| 类别 | 件 | 语义 |
|---|---|---|
| 组合 | `chain` / `chain.from_iterable` | 串接多个可迭代 |
| 切流 | `islice` / `takewhile` / `dropwhile` | 惰性切片/截断（生成器不能下标，用 islice） |
| 聚形 | `pairwise` / `batched`（3.12 增量） | 相邻对 / 定长批（分块处理的标配） |
| 分组 | `groupby` | **连续**相同键分组——输入必须先按同键排序，否则同键多段（最著名误用） |
| 无穷 | `count` / `cycle` / `repeat` | 与 islice 配对使用 |
| 折叠 | `accumulate` | 前缀和/累积函数 |

### 协程侧写（为什么生成器能 send）

`send(value)` 把值注入暂停点成为 `yield` 表达式的值、`throw` 注入异常、`close` 关闭——生成器是双向通道。这一机制曾是 `asyncio` 的实现底座（`yield from` 时代），今天直接写 `async def` 即可，但理解血缘有助于理解 `async for`（异步生成器）为何与普通生成器同构。

### __getitem__ 退路

无 `__iter__` 但有 `__getitem__` 的旧式对象仍可被 for 遍历：解释器从 0 起按下标取直到 `IndexError`——知道它是兼容行为即可，新代码一律写 `__iter__`（协议优先的正式讨论见 [07-面向对象](07-面向对象.md)）。

## 连接

| 场景 | 选择 |
|---|---|
| 数据放得进内存、要反复用 | list/容器（见 [02-内建数据结构](02-内建数据结构.md)） |
| 单遍流式变换（过滤/映射/聚合） | 生成器管道（本篇） |
| 逐行读大文件 | 文件对象本身可迭代（见 [01-文件与路径](../02-IO与工程实践/01-文件与路径.md)） |
| IO 密集的多源流 | 异步生成器 + `async for`（见 [03-并发与异步](../03-运行时与性能/03-并发与异步.md)） |
| 需要中途暂停/回溯的解析 | 显式状态机类（生成器适合单向流） |

**延伸**：惰性求值与求值策略的语言学对照见 [01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)；`range` 为何不是 list——它是"可迭代者"而非容器，同一协议的又一样本。

## 示例

```python
from itertools import batched, chain, groupby, islice

def read_rows(path):                       # 生成器：状态在帧里
    with open(path, encoding="utf-8") as f:
        for line in f:                     # 文件对象本身可迭代（惰性）
            if line.strip():
                yield line.rstrip("\n").split(",")

rows = read_rows("data.csv")               # 尚未打开文件
sample = islice(rows, 3)                   # 尚未读取
for batch in batched(sample, 2):           # 真正消费时才逐级拉动
    print(batch)
```

```python
# groupby 前置排序：连续分组语义
from itertools import groupby
data = [("a", 1), ("b", 2), ("a", 3)]
for key, grp in groupby(sorted(data, key=lambda t: t[0]), key=lambda t: t[0]):
    print(key, [v for _, v in grp])    # a [1, 3] / b [2]——不排序则 'a' 出现两段
```
