# 09-上下文管理器

> 前置：[08-错误与异常](08-错误与异常.md)（finally 的语义与吞噬陷阱）、[07-面向对象](07-面向对象.md)（协议方法） · 后续：[01-文件与路径](../02-IO与工程实践/01-文件与路径.md)、[03-并发与异步](../03-运行时与性能/03-并发与异步.md)（锁与 async with）、[03-Mock与替身](../04-测试与质量/03-Mock与替身.md)（patch 即上下文管理器）

上一篇的 `finally` 解决"清理必须执行"，但写起来啰嗦、且容易踩"finally 里的 return 吞异常"。`with` 把这整件事协议化：**进入时拿资源、退出时无条件归还——不管退出方式是正常、break、还是异常穿越**。它是 RAII 在 Python 里的形态。

## 本质

```python
mgr = EXPR
val = mgr.__enter__()
try:
    BODY                 # 使用资源
finally:
    mgr.__exit__(exc_type, exc, tb)   # 无条件清理；参数非 None 即"异常穿越中"
```

`__exit__` 返回 `True` 表示"异常已处理、就地吞掉"（控制流恢复正常）；返回 `None`/`False` 表示"异常继续传播"。**抑制是显式且危险的**——默认必须放行。

## 机制

### 类形式：协议两件套

适合有状态、可复用的资源类型（连接、锁、事务）。标准库的样例：`open()` 返回的文件对象、`threading.Lock`、`unittest.mock.patch`。

```python
class Timer:
    def __enter__(self):
        self._t0 = time.perf_counter()
        return self                       # as 后面拿到的就是返回值
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self._t0
        return None                       # 不吞异常
```

### 生成器形式：临时场景的默认答案

`@contextmanager` 把"yield 前后"映射到"enter/exit"——yield 的值即 `as` 拿到的值；body 抛出的异常会在 yield 点**注入生成器**，可就地 try/except 决定吞或放。

```python
from contextlib import contextmanager

@contextmanager
def transaction(conn):
    conn.execute("BEGIN")
    try:
        yield conn
        conn.execute("COMMIT")
    except Exception:
        conn.execute("ROLLBACK")
        raise                             # 回滚后放行异常——见 08-错误与异常
```

### contextlib 工具箱

| 工具 | 语义 | 场景 |
|---|---|---|
| `suppress(E)` | 吞掉指定异常 | 替代"try/except: pass"三行 |
| `closing(x)` | 退出时调 `x.close()` | 对象有 close 但没实现协议 |
| `ExitStack` | 动态数量资源的统一出口 | 数量运行时才知的文件/锁；`enter_context` 逐个登记 |
| `nullcontext(x)` | 什么都不做的占位 | "可选资源"的签名统一（传 None 时兜底） |
| `redirect_stdout(f)` | 临时改道标准输出 | 捕获打印（测试/CLI） |

`ExitStack` 是本篇的深水件：`with ExitStack() as stack:` 后在循环里 `stack.enter_context(open(p))` 打开 N 个文件——退出顺序自动逆序（后进先出），等价手写 N 层嵌套 with。Python 3.10+ 多上下文可括号合写：`with (open(a) as fa, open(b) as fb):`。

### 纪律

- 抑制三思：`__exit__` 返回 True / `suppress` 都会把 bug 一起吞——抑制范围必须窄到具体异常类型（承接 [08-错误与异常](08-错误与异常.md) 的"接什么"）。
- `as` 拿到的是 `__enter__` 的返回值，不是管理器本身（文件对象场景两者恰好同一，锁场景拿到的是 None）。
- async 版协议是 `__aenter__`/`__aexit__` 配 `async with`——异步资源（连接池取连接）必须走这套，见 [03-并发与异步](../03-运行时与性能/03-并发与异步.md)。

## 连接

| "必须归还的东西" | 对应管理器 |
|---|---|
| 文件描述符 | `open()`——编码与缓冲细节见 [01-文件与路径](../02-IO与工程实践/01-文件与路径.md) |
| 线程锁/信号量 | `threading.Lock` 等——GIL 与锁粒度见 [03-并发与异步](../03-运行时与性能/03-并发与异步.md) |
| 数据库事务 | 引擎自带（`sqlite3` 连接、`psycopg` 事务块）——见 [06-数据库操作](../02-IO与工程实践/06-数据库操作.md) |
| 测试中的临时替换 | `mock.patch`——见 [03-Mock与替身](../04-测试与质量/03-Mock与替身.md) |
| cwd/环境变量临时切换 | 自己写 `@contextmanager`（chdir + 回切） |

**判据**：一段代码出现"try/finally 只为成对操作"（开/关、进/出、设/还原）三次以上，就该沉淀成上下文管理器——这正是它作为结构型复用件的位置（见 [03-结构型模式](../05-设计模式/03-结构型模式.md) 的代理/Facade 合流处）。

## 示例

```python
import os, time
from contextlib import ExitStack, suppress, contextmanager
from pathlib import Path

files = ["a.log", "b.log", "c.log"]
with ExitStack() as stack:                       # 数量动态：n 层 with 的平写法
    handles = [stack.enter_context(open(p)) for p in files]
    total = sum(len(h.read()) for h in handles)
print(total)

@contextmanager
def chdir(path):
    old = Path.cwd()
    os.chdir(path)
    try:
        yield
    finally:
        os.chdir(old)                            # 还原型清理

with suppress(FileNotFoundError):                # 三行 try/except pass 的一行替身
    os.remove("stale.tmp")
```
