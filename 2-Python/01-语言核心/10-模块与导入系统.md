# 10-模块与导入系统

> 前置：[01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)（import 即执行）、[02-开发环境与工具链](../00-概览/02-开发环境与工具链.md)（site-packages 与环境） · 后续：[04-打包与分发](../03-运行时与性能/04-打包与分发.md)（src 布局与安装）、[06-代码质量工具](../04-测试与质量/06-代码质量工具.md)（import 排序/lint）

模块是 Python 的物理复用单元：一个 `.py` 文件即一个模块对象，一个含 `__init__.py` 的目录即一个包。本篇讲导入系统的三层机制（查找 → 执行 → 缓存），以及它派生的两大工程问题：`ModuleNotFoundError` 的排查路径与循环导入的解法。

## 本质

- `import m` 做三件事：**查找**（沿 `sys.path` 找 `m.py` 或 `m/`）、**执行**（顶层代码跑一遍，构建模块命名空间）、**缓存**（`sys.modules["m"]` 记住模块对象）。再次 import 只查缓存不重执行——模块级状态因此天然单例。
- 导入是**运行时代码执行**，不是声明：可以有条件导入、函数内延迟导入、循环内动态导入——灵活的代价是依赖关系静态不可见（`__init__.py` 里乱导入是模块图失控的开端）。

## 机制

### 查找：sys.path 与三finder

`sys.meta_path` 上的查找器依次认领：内建（`sys`、`builtins`）→ 冻结模块 → `PathFinder`（沿 `sys.path` 逐项找包/模块）。`sys.path` 的组成（顺序即优先级）：

1. 入口脚本所在目录（`python app.py`）或当前目录（`python -m app`）——脚本直跑与 `-m` 的行为差异就在这一项；
2. `PYTHONPATH` 环境变量；
3. 虚拟环境的 `site-packages`（环境隔离的落点，见 [02-开发环境与工具链](../00-概览/02-开发环境与工具链.md)）。

约束与后果：第 1 项意味着**项目根下的同名文件会遮蔽已安装包**（本地 `json.py` 让 `import json` 全局翻车）——src 布局防的就是这个（见 [04-打包与分发](../03-运行时与性能/04-打包与分发.md)）。`ModuleNotFoundError` 的标准排查：`python -c "import sys; print(sys.path)"` + 确认跑的是哪个解释器。

### 执行与缓存：一次性保证

- 首次导入执行顶层（含 `def`/`class` 语句——它们本就是可执行语句，见 [05-函数](05-函数.md)）；产物 `.pyc` 缓存与失效规则见 [01-语言定位与执行模型](../00-概览/01-语言定位与执行模型.md)。
- `__name__ == "__main__"`：直跑/`-m` 时模块名为 `__main__`，被导入时为真实模块名——库与入口分离的语言机制。推论：模块会因"以两种身份加载"而执行两遍（`__main__` 一遍、自身名一遍），靠该守卫隔离副作用。
- `__all__ = [...]`：约束 `from m import *` 的范围，同时是"这是公开 API"的文档；无 `__all__` 时下划线开头者除外。

### 相对导入与包语义

- `from . import x`（本包）/ `from ..pkg import y`（父包）基于 `__package__` 解析，**只在包内合法**；脚本直跑（`__package__` 为空）时报 `attempted relative import with no known parent package`——解法是 `python -m pkg.mod` 或入口放包外。
- 无 `__init__.py` 的目录是命名空间包（PEP 420）：可跨目录拼合同名包——用于插件拆分，但普通项目老老实实放 `__init__.py`（显式初始化 + 公开 API 转出口：`from .core import Thing`）。

### 循环导入：成因与四个解法

成因：A 导入 B 时 B 反过来导入 A，而 A 还执行到一半（部分初始化的模块对象）——`AttributeError: partially initialized module`。按代价排序的解法：

1. **重构**（根治）：把共享部分抽到第三个模块，依赖图变无环；
2. **延迟导入**：把 `import a` 挪进函数体（首次调用才执行）；
3. **TYPE_CHECKING 守卫**：仅为类型注解的导入放 `if TYPE_CHECKING:` 块（见 [11-类型提示](11-类型提示.md)）；
4. **调整导入粒度**：`from pkg import mod` 代替 `from pkg.mod import thing`（前者只触发包初始化）。

### importlib 与动态导入

`importlib.import_module("pkg.mod")` 按字符串导入——插件系统的地基（entry points 机制见 [04-打包与分发](../03-运行时与性能/04-打包与分发.md)）；`importlib.reload(m)` 重执行模块（仅交互调试用，重载后的新对象与旧引用脱节，勿入生产代码）。

## 示例

```python
# mypkg/__init__.py —— 包的门面：公开 API 在此收口
from mypkg.core import Engine, Config      # 调用方只需 from mypkg import Engine
from mypkg import _impl                    # 下划线成员不进 __all__ 即视为内部

__all__ = ["Engine", "Config"]
```

```python
# 插件式动态导入：按配置装载，缺件降级而非崩溃
from importlib import import_module

def load_backend(name: str):
    try:
        return import_module(f"mypkg.backends.{name}")
    except ModuleNotFoundError:
        return import_module("mypkg.backends.memory")   # 兜底实现

# 启动剖析：找出最贵的传递依赖（输出每层导入耗时）
# python -X importtime -c "import mypkg" 2> profile.txt
```
