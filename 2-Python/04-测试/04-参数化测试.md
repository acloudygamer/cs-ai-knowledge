# 参数化测试

Parametrization generates multiple test invocations from a single test function definition, each with different input values. The test function body runs unchanged; only the inputs vary.

## 生成模型

<pre>
parametrize(("x", "y"), [(1,2), (3,4), (5,6)])
    |
    v
test_func(x=1, y=2)  --> invocation 1
test_func(x=3, y=4)  --> invocation 2
test_func(x=5, y=6)  --> invocation 3
</pre>

pytest collects the parametrized test once, then expands it into N distinct test items during collection. Each item has a distinct node ID reflecting its parameter values.

Why parametrization over copy-paste:
- One test function body; N invocations
- Adding new cases requires editing only the parameter list
- Test naming reflects parameters, aiding failure diagnosis

## 笛卡尔积

Stacking `@pytest.mark.parametrize` decorators produces the Cartesian product of all parameter sets:

```
@pytest.mark.parametrize("x", [1, 2])
@pytest.mark.parametrize("y", [10, 20])
    |
    v
(x=1, y=10), (x=1, y=20)
(x=2, y=10), (x=2, y=20)
```

The number of generated invocations is $|X| \times |Y|$. Each stack adds one dimension to the product space.

## indirect 参数传递

When `indirect=True`, the parameter is passed to a fixture with the same name rather than directly to the test function. This defers parameter resolution to the fixture, enabling fixture-level logic (e.g., creating client instances per endpoint URL).

```
@pytest.mark.parametrize("base_url", [...], indirect=True)
def test_api(http_client):
    pass
    |
    v
Fixture "base_url" receives parameter value
Fixture "http_client" depends on "base_url"
Test receives resolved http_client
```

## ids 自定义名称

Each parametrized invocation gets a generated node ID. The `ids` parameter overrides these with human-readable names:

```
ids=["alice_valid", "bob_valid", "empty_invalid"]
```

Without `ids`, the node ID is derived from the parameter value (e.g., `test_email[alice@example.com]`). Custom `ids` make pytest output scannable during failures.

## 负向测试组合

Parametrization is particularly effective for boundary and error case coverage:

$$
valid\_inputs = \{x \in D | predicate(x) = True\} \\
invalid\_inputs = \{x \in D | predicate(x) = False\}
$$

One parametrized test covers all invalid inputs; each raises the expected exception. This avoids separate test functions for each error case.

## 参考样例

```python
@pytest.mark.parametrize("input,expected", [
    (1, 1),
    (2, 4),
    (3, 9),
])
def test_square(input, expected):
    assert input ** 2 == expected
```

```python
@pytest.mark.parametrize("x", [1, 2, 3])
@pytest.mark.parametrize("y", [10, 20])
def test_combinations(x, y):
    assert x + y > 0
```

```python
@pytest.mark.parametrize("email", [
    "user@example.com",
    "admin@company.co.uk",
])
def test_email_valid(email):
    assert "@" in email
```

```python
@pytest.fixture
def client(base_url):
    return Client(base_url)

@pytest.mark.parametrize("base_url", [
    "https://api.example.com",
    "https://staging.example.com",
], indirect=True)
def test_endpoints(client):
    assert client.get("/users").status == 200
```

```python
@pytest.mark.parametrize("invalid", ["", "abc", "@"], ids=["empty", "no_tld", "no_at"])
def test_invalid_email(invalid):
    with pytest.raises(ValueError):
        validate(invalid)
```

```python
def pytest_param_id(val):
    if isinstance(val, dict):
        return val.get("name", str(val))

@pytest.mark.parametrize("val", [{"name": "a", "v": 1}], ids=pytest_param_id)
def test_named(val):
    assert val["v"] > 0
```
