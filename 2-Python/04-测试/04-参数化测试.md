# 参数化测试

> **版本基准**：Python 3.12 stable（latest=3.14，新特性章节保留并标注）

## 本质

参数化测试从单一测试函数定义生成多个测试实例，每个实例使用不同输入值。测试函数体保持不变，仅输入参数变化。这避免了针对每个输入值编写重复测试函数的 Boilerplate。

## 数学模型

### 参数化展开

令 $P$ 为参数名列表， $V(p)$ 为参数 $p$ 的取值集合：

$$
\text{expand}(f, P, V) = \{f(p_1=v_1, \ldots, p_k=v_k) \mid v_i \in V(p_i)\}
$$

笛卡尔积展开（多装饰器叠加）：

$$
\text{expand}(\text{decoration-stack}, f) = \bigcup_{v_1 \in V_1} \bigcup_{v_2 \in V_2} \ldots f(\ldots)
$$

$$
|\text{结果集}| = \prod_{i} |V_i|
$$

**展开示例**：

```python
@pytest.mark.parametrize("x", [1, 2, 3])      # |V_x| = 3
@pytest.mark.parametrize("y", [10, 20])        # |V_y| = 2
def test_func(x, y): ...
# |结果集| = 3 × 2 = 6
```

### 节点 ID 生成

每个参数化实例被分配唯一节点 ID：

$$
\text{node-id}(f, \text{params}) = f.\text{name} + "[" + \text{repr}(\text{params}) + "]"
$$

**ID 生成算法**：

```python
def node_id(func_name, params):
    param_str = ",".join(f"{k}={v!r}" for k, v in params.items())
    return f"{func_name}[{param_str}]"
```

自定义 `ids` 函数覆盖默认生成：

$$
\text{id-override}(v) = \text{ids-fn}(v) \quad \text{若提供}
$$

**ID 冲突检测**：若 `ids` 列表中产生重复 ID，pytest 会发出警告并自动添加数字后缀消解冲突。

### 负向测试覆盖

参数化可系统覆盖合法输入和非法输入空间：

$$
D = \text{输入域} \\
V = \{x \in D \mid \text{predicate}(x) = \text{True}\} \\
I = \{x \in D \mid \text{predicate}(x) = \text{False}\}
$$

一个参数化测试覆盖所有 $I$，每个实例验证不同非法输入抛出预期异常。

**测试覆盖的数学完备性**：

$$
\text{coverage} = \frac{|V \cup I|}{|D|} = 1 \iff V \cup I = D
$$

理想情况下，测试应覆盖输入域的所有等价类。

**等价类划分**：输入域 $D$ 的等价类是 $D$ 的一个划分 $\{C_1, C_2, \ldots, C_n\}$，使得：
- $\bigcup_i C_i = D$ 
- $C_i \cap C_j = \emptyset$ for $i \neq j$ for $i \neq j$ 
- $\forall x, y \in C_i: \text{系统对 } x \text{ 和 } y \text{ 的行为相同}$ 

每个等价类只需测试一个代表元素。

### pytest_generate_tests 的生成模型

`pytest_generate_tests` 是 pytest 暴露给用户的参数化生成 Hook，允许在收集阶段动态生成测试参数：

$$
\text{dynamic-expand}(f) \xrightarrow{\text{hook}} \text{param-sets}
$$

用户通过在 `conftest.py` 中定义该函数，向 pytest 的参数化注册表动态添加参数集。

### 组合爆炸的数学界

笛卡尔积的参数化可能导致测试数量指数增长：

$$
N = \prod_{i} |V_i|
$$

**控制策略**：

1. **正交分析**：识别真正独立的参数，仅对独立参数做笛卡尔积
2. **配对测试**（pairwise testing）：用所有参数的两两组合替代全集，复杂度从 $O(\prod |V_i|)$ 降为 $O(|V_{\max}|^2 \cdot n)$
3. **随机抽样**：从参数空间中随机抽样固定数量

### indirect 参数化的数据流

<pre>
@pytest.fixture
def http_client(base_url):    ←─── fixture 依赖 indirect 参数
    return Client(base_url)

@pytest.mark.parametrize("base_url", [...], indirect=True)
def test_endpoints(http_client):  ←─── 接收 resolved fixture（而非 raw param）
    ...
</pre>

数据流：

$$
\text{parametrize}("base\_url", [...]) \xrightarrow{\text{indirect}} \text{fixture}("base\_url") \rightarrow \text{test-function}("http\_client")
$$

**indirect 语义**：当 `indirect=True` 时，参数值不直接传递给测试函数，而是作为参数名传递给同名 fixture，由 fixture 处理参数的转换和验证。

## 机制

### indirect 参数化

`indirect=True` 将参数值传给同名 fixture，而非直接传给测试函数：

```python
@pytest.fixture
def http_client(base_url):  # base_url 由 parametrize 提供
    return Client(base_url)

@pytest.mark.parametrize("base_url", [
    "https://api.example.com",
    "https://staging.example.com",
], indirect=True)
def test_endpoints(http_client):  # 接收 resolved fixture
    ...
```

这允许 fixture 在接收到参数值后执行初始化逻辑（如创建不同环境的客户端实例）。

**何时使用 indirect**：
- 参数值需要经过处理才能使用（环境创建、连接建立）
- 参数化影响 fixture 的初始化行为
- 同一参数需要在多个 fixture 中使用

### pytest_generate_tests 动态生成

`pytest_generate_tests` 允许在收集阶段动态决定测试参数：

```python
def pytest_generate_tests(metafunc):
    if "browser" in metafunc.fixturenames:
        browsers = ["chrome", "firefox", "safari"]
        metafunc.parametrize("browser", browsers)
```

该 Hook 在每个测试函数收集时被调用，`metafunc.parametrize` 的效果与装饰器 `@pytest.mark.parametrize` 相同。

**与装饰器的比较**：

| 特性 | @pytest.mark.parametrize | pytest_generate_tests |
|------|-------------------------|----------------------|
| 声明位置 | 测试函数上 | conftest.py |
| 参数来源 | 静态列表 | 动态计算 |
| 条件参数化 | 需配合 if 语句 | 天然支持 |

### ids 的可读性优化

默认节点 ID 对复杂对象不可读：

```python
# 默认：test_email[user@example.com]
# 自定义 ids：
ids=["alice_valid", "bob_valid", "empty_invalid"]
# 自定义函数：
def pytest_param_id(val):
    if isinstance(val, dict):
        return val.get("name", str(val))
    return str(val)
```

**ids 函数签名要求**：`ids` 可以是列表（与 params 等长）或单参数函数。

### 标记继承

参数化装饰器在类上时，类内所有测试函数继承该参数化：

```python
@pytest.mark.parametrize("x", [1, 2])
class TestMath:
    def test_add(self, x):
        assert x + 1 > 0
    # 两个测试函数 × 2 个参数值 = 4 个实例
```

**继承语义**：类级 parametrize 将参数与类中每个测试函数组合，但不同测试函数独立展开。

### 负向参数化的正确姿势

```python
# 错误：所有参数放在同一个测试
@pytest.mark.parametrize("email", [
    "valid@example.com",  # 正向
    "", "abc", "@"  # 负向混在一起
])
def test_email(email):
    validate(email)  # 无法区分正向负向

# 正确：正负分离
@pytest.mark.parametrize("email", [
    "valid@example.com",
], ids=["valid"])
def test_email_valid(email):
    assert validate(email) is True

@pytest.mark.parametrize("email", [
    "",
    "abc",
    "@",
], ids=["empty", "no_tld", "no_at"])
def test_email_invalid(email):
    with pytest.raises(ValueError):
        validate(email)
```

**正负测试分离的原因**：正负测试的验收标准不同（正向验证返回值，负向验证异常），混合会导致断言逻辑混乱。

### 组合爆炸控制

笛卡尔积的参数化可能导致测试数量指数增长：

$$
N = \prod_{i} |V_i|
$$

**控制策略**：
1. **正交分析**：识别真正独立的参数，仅对独立参数做笛卡尔积
2. **配对测试**（pairwise testing）：用所有参数的两两组合替代全集
3. **随机抽样**：从参数空间中随机抽样固定数量

**配对测试的复杂度**：对于 $n$ 个参数，每个参数取值 $|V_i|$，配对测试的用例数为 $O(|V_{\max}|^2 \cdot n)$，而非 $\prod |V_i|$。

### 跨类参数化继承

子类不自动继承父类的 parametrize：

```python
class Base:
    @pytest.mark.parametrize("x", [1, 2])
    def test_add(self, x):
        assert x + 1 > 0

class Derived(Base):
    def test_sub(self, x):  # x 不可用，未继承 parametrize
        assert x - 1 >= 0
```

子类需显式声明 parametrize 以继承参数。

### 等价类划分的判定条件

每个等价类需要满足：
- 类内所有元素触发相同的代码路径
- 类内所有元素有相同的预期输出或行为

$$
\forall x, y \in C_i:\quad \text{path}(x) = \text{path}(y) \land \text{output}(x) = \text{output}(y)
$$

**边界值分析**：等价类划分的代表元素应选择边界值（最小值、最大值、零点、临界值），因为边界是最容易出错的地方。

## 约束与违反后果

| 约束 | 违反后果 |
|------|---------|
| 参数值类型导致 fixture 无法解析 | `indirect=True` 时参数传给 fixture，若 fixture 签名不匹配，报 `fixture not found` |
| ids 列表长度不匹配 | `len(ids) != len(params)`，pytest 报参数数量不匹配 |
| 间接参数依赖未声明 | fixture 依赖 indirect 参数，但测试函数签名中未声明该参数，pytest 收集时报错 |
| parametrize 叠加导致的组合爆炸 | 测试实例数 = ∏|V_i|，大量参数导致测试时间指数增长 |
| ID 冲突未处理 | pytest 警告并自动添加后缀，但意图不明确 |
| 等价类代表元素选择不当 | 遗漏边界条件或特殊值，导致测试盲区 |

## 代码示例

```python
import pytest

# 基础参数化
@pytest.mark.parametrize("input,expected", [
    (1, 1),
    (2, 4),
    (3, 9),
])
def test_square(input, expected):
    assert input ** 2 == expected

# 笛卡尔积
@pytest.mark.parametrize("x", [1, 2, 3])
@pytest.mark.parametrize("y", [10, 20])
def test_combinations(x, y):
    assert x + y > 0

# 自定义 ids
@pytest.mark.parametrize("email", [
    "user@example.com",
    "admin@company.co.uk",
], ids=["valid_1", "valid_2"])
def test_email_valid(email):
    assert "@" in email

# 负向测试
@pytest.mark.parametrize("invalid", [
    "",
    "abc",
    "@",
], ids=["empty", "no_tld", "no_at"])
def test_invalid_email(invalid):
    with pytest.raises(ValueError):
        validate(invalid)

# indirect 参数化
@pytest.fixture
def client(base_url):
    return Client(base_url)

@pytest.mark.parametrize("base_url", [
    "https://api.example.com",
    "https://staging.example.com",
], indirect=True)
def test_endpoints(client):
    assert client.get("/users").status == 200

# 自定义 id 函数
def pytest_param_id(val):
    if isinstance(val, dict):
        return val.get("name", str(val))
    return str(val)

@pytest.mark.parametrize("val", [
    {"name": "alice", "v": 1},
    {"name": "bob", "v": 2},
], ids=pytest_param_id)
def test_named(val):
    assert val["v"] > 0

# 等价类划分
@pytest.mark.parametrize("age", [
    -1,      # 无效：负数
    0,       # 边界：最小有效
    1,       # 边界：幼儿
    17,      # 边界：未成年
    18,      # 边界：成年
    65,      # 边界：老年
    150,     # 无效：超出人类寿命
], ids=["neg", "zero", "infant", "minor", "adult", "senior", "invalid"])
def test_age_validation(age):
    if 0 <= age <= 120:
        assert validate_age(age) is True
    else:
        with pytest.raises(ValueError):
            validate_age(age)
```
