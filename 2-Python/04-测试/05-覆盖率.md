# 测试覆盖率

Coverage measures which code paths were executed during test runs. It is a proxy metric for test completeness, not a guarantee of correctness.

## 覆盖率指标体系

| metric | definition |
|--------|------------|
| statement | each line of code executed at least once |
| branch | each conditional fork (True and False branches) taken |
| function | each function called at least once |
| line | equivalent to statement coverage |

Statement coverage is necessary but not sufficient. A function with 100% statement coverage may have untested branches:

$$
branch\_coverage = \frac{branches\_taken}{branches\_total}
$$

## 分支覆盖与语句覆盖差异

```
if condition:
    return a
return b
```

Achieving 100% statement coverage requires calling the function once. But branch coverage requires two calls: one where `condition = True` and one where `condition = False`. Two different execution paths through the same code.

This distinction matters for security-critical code: a missing False branch may be an exploitable path.

## 覆盖率作为代理信号

<pre>
high coverage + good assertions --> likely well-tested
low coverage --> definitely untested
high coverage + no assertions --> likely superficial
</pre>

Coverage cannot distinguish between:
- Tests that assert correct behavior vs. tests that merely exercise code
- Tests that verify error handling vs. tests that avoid errors by accident

The goal is not 100% coverage; it is verified coverage of the paths that matter.

## 增量覆盖率

CI pipelines use incremental coverage to enforce that new code has tests:

$$
coverage_{delta} = coverage_{new} - coverage_{baseline}
$$

`coverage diff` compares two runs: the baseline (main branch) and the new code (PR branch). PRs that reduce coverage are flagged.

This prevents coverage erosion: the aggregate percentage can remain flat while untested code is added if new tests are added elsewhere.

## 排除规则

Coverage tools automatically exclude:
- `if __name__ == "__main__":` blocks
- `if TYPE_CHECKING:` blocks
- Code in `site-packages/`

Manual exclusions via `# pragma: no cover` indicate intentional untested paths. Overuse of exclusions signals that code is being protected from its own tests.

## 参考样例

```bash
pytest --cov=mypackage --cov-report=term-missing tests/
pytest --cov=mypackage --cov-fail-under=80 tests/
```

```python
if False:  # pragma: no cover
    unreachable_code()

def _private():  # pragma: no cover
    pass
```

```toml
[tool.coverage.run]
source = ["mypackage"]
branch = true
omit = ["*/tests/*", "*/migrations/*"]

[tool.coverage.report]
exclude_lines = [
    "pragma: no cover",
    "raise NotImplementedError",
]
```

```bash
coverage xml
coverage diff -m --compare-mode=incremental
```
