# 05-覆盖率与测试策略

> 前置：[01-pytest基础](01-pytest基础.md) 至 [04-参数化测试](04-参数化测试.md)（怎么写测试） · 后续：[06-代码质量工具](06-代码质量工具.md)（静态防线与测试互补）、[07-CI-CD集成](07-CI-CD集成.md)（门禁落点）

会写测试之后的问题是**测什么、测到什么程度、怎么防止测试腐化**。本篇给三把尺：覆盖率（测了多少）、变异测试（测得够不够狠）、测试分层（把力气花在哪）；最后是 flaky 治理——测试套件最大的慢性病。

## 本质

- 覆盖率的正确读法：它只可靠地告诉你**什么没被测过**（未覆盖 = 必缺测试），不能告诉你测过的部分测得好不好（覆盖 ≠ 断言存在更 ≠ 正确）。因此它是**反向指标**：用未覆盖清单找洞，而不是用百分比邀功。
- 测试的价值密度排序（通用经验）：回归测试（抓住过 bug 的）> 边界与异常路径 > 核心领域逻辑 > 粘合代码。覆盖率相同的两套测试，价值可以差一个量级——差异就在断言落在哪。

## 机制

### 覆盖率工具与口径

```bash
pytest --cov=mylib --cov-branch --cov-report=term-missing
# 行覆盖 + 分支覆盖；term-missing 列出未覆盖行号——这张清单才是产物
```

- 分支覆盖 > 行覆盖：`if a and b:` 行被走过不代表两个真假组合都走过——分支口径补上这条路。
- 总量门禁（`--cov-fail-under=85`）的副作用：凑覆盖的空测试（跑过即覆盖、断言为零）。替代做法是**diff 覆盖**（新增/修改行必须覆盖）——增量不欠新债，存量慢慢还。

### 变异测试：给测试照镜子

变异工具（`mutmut` / `cosmic-ray`）系统性地改坏源码（换比较符、删语句），跑测试看能不能抓住每个变异体。**存活的变异体 = 测试的盲点**：改了代码测试还绿，说明那段逻辑根本没有有效断言。用法定位在关键模块的周期性体检，不适合常态门禁（贵）。覆盖率问"跑到没有"，变异测试问"跑到了但发现得了吗"——它是测试质量的更严苛定义。

### 测试分层：力气分配

| 层 | 占比（经验） | 测什么 | 速度/环境 |
|---|---|---|---|
| 单元 | 多数 | 领域逻辑、纯函数、解析器 | 毫秒级、零外部依赖 |
| 集成 | 中间 | 模块拼装、真库、真文件系统（[02-Fixture](02-Fixture.md) 的容器 fixture） | 秒级、需环境 |
| 端到端 | 少数 | 关键用户路径、发布冒烟 | 分钟级、全栈 |

判据串起来：单元层用 [04-参数化测试](04-参数化测试.md) 扫数据面、[03-Mock与替身](03-Mock与替身.md) 的 fake 隔离边界；集成层测"接缝"（序列化 roundtrip、SQL 真执行、httpx 真往返——[03-序列化与配置格式](../02-IO与工程实践/03-序列化与配置格式.md)、[06-数据库操作](../02-IO与工程实践/06-数据库操作.md)、[05-网络请求](../02-IO与工程实践/05-网络请求.md) 各自的边界就是集成测试的主战场）；端到端只保关键路径——**覆盖率最高的层应该是单元层，但信心来源是分层的组合**。

### 属性化测试：hypothesis 一瞥

```python
from hypothesis import given, strategies as st

@given(st.lists(st.integers()))
def test_sort_roundtrip(xs):
    assert sorted(sorted(xs)) == sorted(xs)           # 幂等性

@given(st.text())
def test_json_text_roundtrip(s):
    assert json.loads(json.dumps(s)) == s             # 不变量：编码-解码恒等
```

按类型策略生成随机输入、失败时**自动收缩到最小反例**——不变量式属性（roundtrip、幂等、单调、守恒）比手写边界更难漏。纯函数模块接入成本最低，复杂状态机用 `@st.composite` 组合策略。

### flaky 治理

随机失败的测试比没有测试更糟（红着的小丑看多了，没人再理红灯）。三大来源与根治：**时间依赖**（注入时钟，[04-日期与时间](../02-IO与工程实践/04-日期与时间.md)）、**顺序依赖**（共享状态，[02-Fixture](02-Fixture.md) 隔离）、**外部依赖**（真网络——mock 或本地容器）。纪律：发现 flaky 当日要么修、要么 `skip` 注明原因——绝不放任"重跑就绿"成为团队肌肉记忆（`-p no:randomly`、pytest-rerunfailures 是缓解不是治疗）。

## 连接

| 问题 | 去 |
|---|---|
| 覆盖率涨但 bug 还漏 | 本篇价值密度 + 变异测试 |
| 门禁怎么设 | diff 覆盖 + 分层跑（[07-CI-CD集成](07-CI-CD集成.md)） |
| 静态层能消掉哪些测试负担 | [06-代码质量工具](06-代码质量工具.md)（类型检查消参数形态错误） |
| bug 修复的流程 | 复现测试先行（回归用例）→ 修 → 全绿（[01-pytest基础](01-pytest基础.md) 的 --lf） |

## 示例

```python
"""回归测试的模板：bug 编号进名字与注释，参数化进数据表"""
import pytest

@pytest.mark.parametrize("user_input", [
    "CONNECTION\x00header",          # bug #351：NUL 字节穿透头部解析
    " " * 10_000,                    # bug #417：超长空白触发 O(n^2) 折叠
], ids=["nul-bytes", "long-blank"])
def test_header_parse_survives_bad_input(user_input):
    result = parse_header(user_input)      # 不抛异常 + 输出有界
    assert len(result) <= 1024
```
