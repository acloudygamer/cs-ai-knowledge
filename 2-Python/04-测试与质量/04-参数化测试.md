# 04-参数化测试

> 前置：[01-pytest基础](01-pytest基础.md)（断言与 marker）、[02-Fixture](02-Fixture.md)（fixture params 的分界） · 后续：[05-覆盖率与测试策略](05-覆盖率与测试策略.md)（参数从哪来：手写 vs 生成）

同一个逻辑、一组输入输出——手写 N 个几乎相同的测试函数是最普遍的测试噪音。参数化把"用例数据"与"断言逻辑"分离：一份逻辑、一张数据表，每行一个独立测试（独立报告、独立失败、独立重跑）。本篇讲透 `@pytest.mark.parametrize` 的全部形态与边界。

## 本质

- `@parametrize` 是**测试函数的 for 展开**：装饰器参数表每一行生成一个测试实例，id 自动取参数 repr（可用 `ids=` 定制可读名）——失败列表就是用例清单，`pytest -k` 可单跑任意一行。
- 与 fixture params 的分界：数据差异（同环境、不同值）用 `@parametrize`；环境差异（不同后端/配置）用 [02-Fixture](02-Fixture.md) 的 `params=`。

## 机制

### 基本形态与 id 纪律

```python
import pytest

@pytest.mark.parametrize("x, lo, hi, expected", [
    (15, 10, 20, 15),      # 区间内
    (5, 10, 20, 10),       # 低于下界
    (25, 10, 20, 20),      # 高于上界
], ids=["inside", "below", "above"])
def test_clip(x, lo, hi, expected):
    assert clip(x, lo, hi) == expected
```

`ids` 不是装饰——CI 输出、`-k` 过滤、失败定位全靠它；无 ids 时 pytest 用参数 repr（长对象名会糊成一团）。数据表用**元组行**（位置明确）还是 pydantic/dataclass 行（字段自名）按行数与复杂度取舍。

### 多个 parametrize 叠加 = 笛卡尔积

```python
@pytest.mark.parametrize("mode", ["r", "w"])
@pytest.mark.parametrize("size", [0, 1, 8192])
def test_buffer(mode, size): ...        # 2 × 3 = 6 个用例，全覆盖组合
```

组合爆炸的对策：无关维度拆成多个测试函数；真相关的组合显式列全量行（每行一个具名 id），不要让笛卡尔积替你发明没意义的组合。

### 行内标记：xfail 与异常用例

```python
@pytest.mark.parametrize("raw,expected", [
    ("1,2", [1, 2]),
    pytest.param("edge,case", None, marks=pytest.mark.xfail(reason="known bug #42")),
])
def test_parse_row(raw, expected):
    assert parse_row(raw) == expected

@pytest.mark.parametrize("bad", ["", "a,b,c,", "||"])
def test_parse_row_rejects(bad):
    with pytest.raises(ValueError, match="row"):      # 异常侧独立成表（见 08-错误与异常）
        parse_row(bad)
```

正常路径与异常路径**分两个测试函数**：断言形态不同（值 vs raises），混在一张表里要塞分支，违背"一个测试证一件事"（[01-pytest基础](01-pytest基础.md)）。

### 类与模块级展开

装饰器同样作用于类（类里每个测试方法都按表展开）与 `pytest_generate_tests` 钩子（元编程按外部数据源生成参数——配置驱动/数据文件驱动的入口，数据从 [03-序列化与配置格式](../02-IO与工程实践/03-序列化与配置格式.md) 读入后喂给 `metafunc.parametrize`）。

### 参数从哪来：三层来源

| 来源 | 形态 | 适用 |
|---|---|---|
| 手写表 | 本篇全部示例 | 边界值、代表性值（选择见 [05-覆盖率与测试策略](05-覆盖率与测试策略.md)） |
| 生成器 | `range`/推导式喂给 parametrize | 规律性规模（size 0/1/8192/10**6） |
| 属性化 | `hypothesis`：按类型自动生成 + 收缩反例 | 纯函数的不变量（roundtrip、单调性）——见 [05-覆盖率与测试策略](05-覆盖率与测试策略.md) |

## 示例

```python
import pytest
from datetime import datetime, timezone

@pytest.mark.parametrize("iso,expected_hour", [
    ("2026-08-24T09:00:00+08:00", 1),     # 北京 9 点 = UTC 1 点
    ("2026-08-24T00:30:00+08:00", 16),    # 跨日回退
    ("2026-08-24T00:00:00Z", 0),          # Z 后缀（3.11+ fromisoformat）
], ids="cn-morning cn-crossday utc".split())
def test_to_utc_hour(iso, expected_hour):
    dt = datetime.fromisoformat(iso)
    assert dt.astimezone(timezone.utc).hour == expected_hour    # 见 04-日期与时间
```
