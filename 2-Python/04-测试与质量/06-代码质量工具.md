# 06-代码质量工具

> 前置：[02-开发环境与工具链](../00-概览/02-开发环境与工具链.md)（工具谱系总表）、[11-类型提示](../01-语言核心/11-类型提示.md)（检查器消费的类型系统） · 后续：[07-CI-CD集成](07-CI-CD集成.md)（门禁流水线）

测试是运行时防线，质量工具是**写代码时**的防线：lint 抓代码坏味道、格式化统一风格、类型检查在运行前抓类型错误、pre-commit 把三者挂进提交流。主线是"每个工具抓什么错、配置收敛在哪、严格度如何渐进"。

## 本质

- 工具三件套各管一层：**ruff**（lint：未用变量、可疑比较、坏实践规则 + format：风格统一）、**mypy/pyright**（类型层：运行前推演类型错误）、**pre-commit**（流程层：提交前强制跑前两者）。风格争论被格式化器终结（[Zen](../00-概览/01-语言定位与执行模型.md) 的"一种明显的方式"），剩下的规则都是可论证的缺陷捕获。
- 配置全部收敛进 `pyproject.toml`（[04-打包与分发](../03-运行时与性能/04-打包与分发.md) 的段三）——单一事实源，编辑器/CI/本地跑同一套规则。

## 机制

### ruff：一个二进制吃掉一个生态

```toml
[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "SIM"]   # 错误/pyflakes/import排序/bugbear/现代化/简化
ignore = ["E501"]                             # 行宽交给 formatter 软处理

[tool.ruff.lint.isort]
known-first-party = ["mylib"]
```

值得开的规则族：`B`（bugbear，真 bug 嗅觉：可变默认参数——[05-函数](../01-语言核心/05-函数.md) 的坑在 lint 层拦截）、`UP`（pyupgrade，语法现代化：`Optional[X]` → `X | None`——[11-类型提示](../01-语言核心/11-类型提示.md) 的代际清理）、`I`（import 排序与分组——[10-模块与导入系统](../01-语言核心/10-模块与导入系统.md) 的分组纪律自动化）、`SIM`（可简化模式）。`ruff check --fix` 自动修一类，`ruff format` 替代 black。

### 类型检查：严格度阶梯

```toml
[tool.mypy]
python_version = "3.12"
strict = true                 # 目标形态；存量代码从松档渐进
# 渐进路线：先 disallow_untyped_defs + check_untyped_defs，再开 strict
```

| 严格度 | 抓到 | 适合 |
|---|---|---|
| 默认 | 显式标注处的错误 | 存量代码起步 |
| `disallow_untyped_defs` + `check_untyped_defs` | 未标注函数（含隐性） | 迁移期 |
| `strict` | Any 渗漏、Optional 未处理、泛型不完整 | 新项目/核心库 |

mypy（渐进、可定制）与 pyright（快、IDE 友好、推断激进）二选一为门禁，另一个可作编辑器即时反馈——两个都上门禁会因推断差异产生永久分歧。类型层消掉的测试负担（参数形态错误）与测试层的分工见 [05-覆盖率与测试策略](05-覆盖率与测试策略.md)。

### pre-commit：把门禁前移到本地

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff            # lint + autofix
      - id: ruff-format     # 格式化
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: end-of-file-fixer
      - id: check-merge-conflict
      - id: check-toml      # 配置文件语法先于 CI 挂
```

`pre-commit install` 挂进 git hook；被拦的提交在本地改掉，而不是等 CI 红十分钟才发现——**反馈延迟决定修复成本**。本地拦不住的（忘记 install）由 CI 兜底（[07-CI-CD集成](07-CI-CD集成.md) 跑同一份配置）。

### 其他值得知道的件

| 工具 | 抓什么 | 位置 |
|---|---|---|
| `vulture` | 死代码（未用函数/属性） | 周期性清理 |
| `deptry` / `uv` | 依赖健康：未用依赖、缺失声明 | CI 周期任务 |
| `semgrep` | 安全模式（硬编码密钥、危险调用） | 安全扫描一环 |
| `pydoclint` | docstring 与签名漂移 | 文档重的库 |

安全扫描与依赖漏洞（OSV/pip-audit）的流水线位置见 [07-CI-CD集成](07-CI-CD集成.md)。

## 连接

| 需求 | 去 |
|---|---|
| 编辑器即时反馈 | LSP（pyright/ruff-lsp）——与门禁同配置 |
| CI 强制同一套规则 | [07-CI-CD集成](07-CI-CD集成.md) |
| 规则压不住的设计问题 | [05-设计模式](../05-设计模式/README.md) 与 [07-面向对象](../01-语言核心/07-面向对象.md) 的结构判据 |
| 团队风格争议 | ruff format 定案（本篇），把讨论留给结构 |

## 示例

```bash
uv add --dev ruff mypy pre-commit
ruff check . && ruff format --check .    # 本地同 CI
mypy src/
pre-commit run --all-files              # 一次性全量验证钩子
```
