## 一、行内 `$` 边界（规范一.1；525 例一维扫描，2026-08-22）

一维扫描设计：测开侧时闭侧固定空格、测闭侧时开侧固定空格；公式统一 `x+y`（排除转义与斜体干扰）。

### 总结论

| 位置 | 合法（公式被提取） | 阻断（`$` 原样输出） |
|---|---|---|
| 开 `$` **前** | 空格、行首、半角 `(` | 其余一切：可见 ASCII 93 个（字母/数字/下划线/全部标点，含 `[` `{` `<`）、全角 `（`、CJK 汉字、CJK 标点、日韩文字与符号 |
| 闭 `$` **后** | 除 ASCII 词字符外的一切：ASCII 标点（含 `$` `*` `` ` ``）、CJK 汉字/标点、日韩文字符号、空格、行尾 | ASCII 字母 52 + 数字 10 + 下划线 1（共 63，恰为 `\w` 词字符集） |
| 开 `$` **后**（内侧 padding） | —— | 空白，无条件阻断（`$ x+y$`） |
| 闭 `$` **前**（内侧 padding） | 空白可容忍：闭 `$` 后是非空白字符（` $后`、` $。`）或行尾时存活 | 闭 `$` 前是空白**且**后也是空白且其后仍有文字（` $ ` 三明治）时阻断 |

计数：开侧 263 例仅 1 例存活（`(`）；闭侧 262 例存活 199、阻断 63。

## 二、容器与标签（规范一.2）

### 正向：公式在容器内（36 例重验零冲突）

| 提取被跳过（公式死） | 提取正常（公式活） |
|---|---|
| `em`（`*`/`_` 斜体的产物）、`b`、`a`（含 markdown 链接 `[..](..)`）、`code`（代码 span） | `i`、`strong`（`**`）、`del`（`~~`）、`span`、`u`、`s`、`sub`、`sup`、`mark`、`q`、`kbd`、`var`、`cite`、`abbr`、`small`、`li`、`blockquote`、表格单元格、标题、`p` |

em 死 i 活、b 死 strong 活——跳过集合与样式/语义无关，闭源实现按实测记录。注意：`u`/`cite`/`abbr`/`small` 四例的"活"是标签被 sanitizer 剥除、容器从未存在，并非"容器内可提取"的证据。

### 反向：元素边界落进 `$…$` 内（25 例完整嵌入 + 9 例横跨，全死）

- 凡**真实生成**的行内元素嵌进 `$…$` 内部必死（含不在跳过集合的 strong/del、void `<br>`、空元素、元素占满公式）；被剥除的标签不生成元素、不致死。机制：`$…$` 须在连续文本节点上，元素边界切断即死。
- 横跨场景（开/闭标签只有一个在公式内）：手写 `<i>`/`<em>` 两向 + markdown `*` 配对横跨全死；markdown 配对与手写标签同构（返回逐字节相同）。
- markdown 斜体配对吞公式（2026-08-22 旧批）：`前 _甲 $x_1$ 乙_ 后` → em 吞掉公式 → 死；斜体对先闭合（`前 _甲_ $x_1$ 乙 后`）→ 公式活。
- `<u>` 剥除后两侧文本**重连**，公式以重连后的文本激活（`$a <u>b$ 后 c</u>` → inner `$a b$`）。
- 孤立闭标签在公式内同样被丢弃（`$a </i> b$` 活，原地留空格）。

### 未闭合标签自动补全（U 组 14 例 + 2026-08-22 批次）

| 写法 | 公式结果 |
|---|---|
| 单个 `*` / `**`（未配对） | 活（不生成元素，星号原样成文本） |
| 未闭合 `<em>` / `<b>` | 双补跨段：标签之后全部死；标签之前不受影响 |
| 未闭合 `<i>`（非跳过集合） | 双补跨段但公式照活 |
| 未闭合 `<a>` / `<span>` | 仅补闭合、不重开：污染不出段 |
| 孤立闭合标签 `</em>` / `</b>` / `</div>` | 活（标签静默丢弃、原地留一个空格；`</div>` 不触发 HTML 块） |

双补机制（API 返回 HTML 直接可见）：先在段尾补闭合，紧接着**重开一个同名元素**包住后续所有块（段落/标题/列表全覆盖），直到文档末尾再补闭合（`…</em></p><em><p>二段 $x+y$ 公式</p>…</em>`）。污染从标签所在段的**下一段**开始。

排查提示：手写标签后公式死亡，先看标签是否未闭合（本表），再看标签后是否紧邻全角标点（开侧规则）。后者曾致误判：测试文本里的全角冒号 `注：` 先触发了开侧阻断，与标签无关。

## 三、块结构层：HTML 块（规范一.3）

行首标签按名单分三路：`<script>`/`<pre>`/`<style>` 行首即开、到闭合标签结束（空行不结束，标签被转义成纯文本）；内建块级名单（div/p/table/article/section 等）行首即开、同行可有文字、到空行；名单外标签须独占整行才开块（`<custom-tag>` 后跟文字 → 段落 + 剥除 → 活）。

原始 HTML 死亡区复验（2026-08-24，5 例）：

| 写法 | 公式结果 |
|---|---|
| `<div>前 $x+y$ 后</div>`（单行独占） | 死（整行 = HTML 块，不经行内解析） |
| `<div>`＋内容＋`</div>` 多行无空行 | 死（HTML 块到空行才结束） |
| `<div>`＋空行＋段落＋空行＋`</div>` | 活（空行分段，中间恢复正常段落） |
| `<span>前 $x+y$ 后</span>`（单行） | 活（span 不触发 HTML 块，整行是段落；span 也不在跳过集合） |
| `文字 <div>前 $x+y$ 后</div>`（行首有文字） | 死（div 被 DOM 提出劈开段落，公式随之切断） |

**表格裸 `|`（规范一.3 末段）**：表格行解析先于行内解析、先于代码 span——行内裸 `|` 先把行切成多格，超出表头列数的格被整体丢弃，公式右半连同闭 `$` 直接从文档消失（`$a|b$` 切后单元格只剩 `$a`；`` $`a|b`$ `` 同样救不了，反引号残片原样残留说明代码 span 未及形成）。`\|` 不切格且送达为裸 `|`（`\\|` 相同，代码包裹内同样有效）；单元格内单行 `$$` 退化按行内提取。

## 四、内容级过滤（规范一.4）

- **杀手子串仅两个**：`select`、`begin`——连续子串、大小写不敏感、无词边界；`begin` 不带反斜杠也死（`begins`/`beginning` 同死）。块级与 `` $`…`$ `` 免疫，退化形态不免疫。
- **安全词扫描全活**：HTML 标签名 11（style/form/input/iframe/object/embed/link/meta/button/textarea/option）、脚本安全词 7（eval/exec/alert/javascript/onerror/function/constructor）、SQL 词 12（from/where/join/grant/truncate/alter/commit/rollback/transaction/end/start/declare）、TeX 命令 8（`\input`/`\def`/`\newcommand`/`\usepackage`/`\include`/`\write`/`\label`/`\section`）。
- **过滤时机 = 送达前的最终文本**（实体解码后）：`$a &#98;egin b$` 死（源码无连续 `begin`，解码拼出后照杀）；`$a &#98;egi n b$` 活（解码后仍断开）。旧证据 `s\elect`/`\begin` 对纯字母子串无判别力，已废弃。
- **`[x](y)` 改判**：不是文本过滤，是真实生成 `<a>` 元素——行内死于元素切段（反向场景），块级死于 `<a>` 子树不能序列化。块内 `![b](u)` 不致死但图片子树被序列化整体丢弃。
- **纯字符串判定三证据**：死例输出无元素生成；词内命中死（标签需 `<` 与词边界）；实体伪装死（纯字母不构成标签）。

## 五、转义层（规范二）

### 反斜杠吃一层与双写修复

- `\%`→`%`、`\_`→`_`、`\{`→`{`、`\\`→`\`：凡 ASCII 标点前的 `\` 单写必被吃一层；`\\%`、`\\{` 双写修复实测有效。
- **间距命令同命中（2026-08-31 工作版重验新发现）**：`\,`→`,`、`\;`→`;`、`\!`→`!`、`\:`→`:`、`\.`→`.`（行内块级同命中）；`\\,` 双写送达 `\,`，修复成立。此前清单只列 `%` `_` `{` `}` `&` `$` `#`，遗漏了这一高频真实写法（`\int_0^1 x^2 \, dx$` 送达变 `x^2 , dx`）。

### `\_` 与 `\\_` 的配对证据（13 例）

- `\_` → 字面 `_`、永不配对：`$x\_i$ 和 $y\_j$` 同段双活无 `<em>`；`\_$x+y$\_` 死但无 `<em>`（死因是 `_` 属 `\w` 触发开侧边界规则，非配对）；对照 `_$x+y$_` 死于 `<em>`。`\*` 同理（`$a \* b$` 送达 `$a * b$`）。
- `\\_` → 修复成立（行内块级送达均为 `\_`），但留下的 `_` 恢复配对资格：`$a\\_b$ 与 $_{j}$` 同段死，返回 `$a\<em>b$ 与 $</em>{j}$`——两个公式被同一对 `<em>` 一网打尽。

### 行内包装的多余实体转义（7 例）

管线共有三步转义，分属不同阶段：Phase 2 反斜杠转义（`\%`→`%`）、Phase 3 实体转义（`&`→`&amp;`、`<`→`&lt;`）、Phase 3.5 **行内包装时再做一次实体转义**。实测：行内 `&`/`\&`/`\\&` 三种写法的 inner HTML 源均为 `&amp;amp;`（textContent `&amp;`）；行内 `$a < b$`/`$a > b$` inner 源为 `&amp;lt;`/`&amp;gt;`；块级无此层（inner 源 `&lt;`，textContent `<` 正确）。引号不受影响。结论"行内对齐符与比较符不可得"成立，机制为 Phase 3+3.5 双重实体转义。

## 六、块级 `$$…$$`（规范三）

### 段落成形与容器（Z 组 30 例，规范三.1/三.3）

- 前文组：空行/标题/围栏闭合行/分隔线后 display；正文无空行 → 多行死、单行退化（`$$` 不打断段落）；列表项/引用行无空行 → 懒延续并入，多行死、单行退化；表格行后 → 多行被吞成单元格死、单行退化。
- 后文组：无空行正文 → 多行死、单行退化；空行 display。
- 块内组：空行拆散死；空行后 ≥4 缩进行成缩进代码块；`$$$x+y$$$` 提取为 display，多余 `$` 一个进内容、一个留在 renderer 外；`$$$$` 空块死。
- 容器组：引用标准写法 display；缺 `> ` 空行或块后跟裸文字行 → 懒延续死。列表项内单独成文 display；**文档级毒害精确化**：前文有行内公式或正文块级公式均触发，列表内块**死而非退化**（`$$` 原样残留）；列表之后的公式无害。

### 解析层致死边界（K 组 6 例，规范三.1 块内表）

- 解析层（Phase 2）本身不判死，只做转换；判死在 Phase 1（块结构）与 Phase 3.5（提取）。
- 配对跨过定界符致死：`$$`⏎`a *b`⏎`$$`⏎`c*` → `<em>` 吞掉闭 `$$`，块毁死；块外配对跨不过段落边界（前后有空行则活）。
- 块内块级语法致死：行首 `<div>` 开 HTML 块切断段落（`<p>$$</p>` + `<div>` + 裸 `$$`）；`---` 触发 Setext 把 `$$`⏎`x+y` 变标题。
- 块内未闭合 `<em>`：自动补闭合并序列化为悬挂 `_`——活但内容坏。
- 块内未配对单 `*`：无害（`a * b` 原样送达）。

### 序列化层（规范三.2，8 + 15 + 跟进 10 例）

- 块内含各元素的确切行为：`<em>`（含手写）→ `_…_`（特例，成对 `*` 同化为 `_`：`a*b*c`→`a_b_c`）；`<strong>`/`<del>`/`<i>`/`<span>`/`<sub>`/`<sup>`/`<kbd>`/`<q>` → 标记整对丢弃、文本保留、块存活；`<a>`/`<b>`/`<code>` → 整块提取失败（`$$` 原样残留，不退化）；`<img>` → 整体丢弃、块存活。
- 行尾：`\\`→`\\`（塌成字面 `\` 后重建时重新转义），前提贴行尾；行尾孤 `\` 是硬换行被消耗、送达消失（旧说"加倍回 `\`"证伪）；换行后一行的行首空格被序列化丢弃（对 TeX 排版无影响）。
- 单行 `$$…\\$$`：`\\` 后随定界符按行中规则塌缩，尾部多出一对 `$$`（异常）。
- **`_` 实践边界（7 例常用公式）**：`\sum_{i=1}^n x_i + y_j`、`\lim_{x \to 0} \frac{\sin x}{x} = 1`、`_{a} x_{b} + y_{i}`（边界 `_` 确实配上对）、`\frac{a_{i}}{b_{j}} \cdot c_k`、`f^{(n)}_{i}(x_0) = a_n`、`x_{i} + _{j}y`（配不上）——全部 display 存活且逐字送达。结论：em 序列化回 `_…_` 是完美往返，块级 `_` 无需 `\_`。
- **`__` 实践边界（8 例）**：`a __b__ c`/`a **b** c` → `a b c`（压扁、静默消失）；`x__i__` intraword 不配对原样穿透；`\text{__}`、`\text{____}` 落单存活；**`\text{__} + \text{__}` → `\text{} + \text{}`**——两个 `__` 跨内容配对后被整对丢弃，TeX 合法填空位照样被吃（行内同写法直接判死）；`\_\_` 转义版送达正确。
- **配对空行的精确条件（跟进 10 例）**：多行块 em 配对 → 送达首尾各多一空行（`$$\n_{a} x_{b}\n$$` → `$$\n\n_{a} x_{b}\n\n$$`）；strong 配对 → 首端一；单行块配对、多行块无配对 → 字节级原样（对照成立）。
- **工作版全规则重验（65 例：`test_workspec_full.py` 55 + `test_workspec_followup.py` 10）**：《公式排版规范-工作版》每条规则逐条实测——边界六例（两端空格活/贴中文死/半角 `(` 活/全角 `（` 死/闭后贴数字死/内侧空白死）、正反向容器、未闭合污染、杀手子串、退化 class（`js-inline-math` 且保留 `$$`）、兜底 `` $`…`$ ``（存活，送达为去反引号的 `$x+y$`）等全部符合；两个真发现（间距命令被吃、配对空行）已分别并入第五节与本节。
