# Markdown 渲染管线研讨

> 用途：从"原始文本 → 网页显示"的渲染管线出发，推导公式排版正文（`公式排版规范.md`）
> 已定约束：
> - **可迁移性优先**：只使用跨渲染器（GitHub/MathJax、KaTeX 系工具、Pandoc 系）通用的语法。GitHub 专属语法（`` $`...`$ ``、```math 围栏块）不进入正文写法，仅作对照研究。
> - 引擎事实：GitHub 使用 MathJax（2022 changelog 与现行官方文档一致）。
> - 管线事实（2026-08-22 API 实验确立）：数学提取在服务端 HTML 后处理步骤完成（见 Phase 3.5），网页端 MathJax 只排版已包好的 `<math-renderer>` 元素。
> - 消毒顺序（2026-08-31 实测确立）：白名单消毒先于数学提取——被剥除的标签（`<u>` 等）内/外的公式均正常提取。

## Phase 0｜原始文本

一行说明：`.md` 文件的 UTF-8 字节流；此层没有任何结构概念，`#`、`>`、`$` 都只是普通字符。

## Phase 1｜块结构解析

cmark-gfm 逐行扫描，**看行首**把文档切成块序列；行内容（强调、链接、`$` 公式）这一阶段不看。
块分两类：**叶块**（装文字）和**容器块**（装别的块）。下面按语法从简到繁列出全部块，每块只记与公式相关的行为。

### 1. ATX 标题（叶块，最简单）

`#` 开头。标题文本照常跑行内解析，公式存活（2026-08-31 实测 h1–h6 全部活）。

### 2. 主题分隔线（叶块）

`---` 独占行。无内容；作为 `$$` 块的前邻时自然结束前块，`$$` 行起新段（display 的前置条件之一）。

### 3. 段落（叶块）

**最重要的块——`$$` 块的载体**。两条延续规则决定块级公式生死：`$$` 行不能打断已开始的段落（并入同段 → 多行块死、单行退化）；引用/列表的懒延续会把无前缀的 `$$` 行吸入前块。段内出现空行即拆散（多行 `$$` 块内空行必死）。

### 4. Setext 标题（叶块）

文字行下跟 `===`/`---` 下划线。`---` 与分隔线同形，优先认作 Setext——会把前一行段落变成标题。

### 5. 缩进代码块（叶块）

≥4 空格缩进的行。内容原样输出，`$` 是普通字符；多行 `$$` 块被空行拆散后，其后 ≥4 缩进的行落进此块。

### 6. 围栏代码块（叶块）

```` ``` ```` 围栏。内容原样输出，不做行内解析；作为前邻时闭合行后 `$$` 行正常起新段。```` ```math ```` 围栏是 GitHub 专属写法（对照研究，不进正文）。

### 7. 表格（GFM，叶块）

行内解析**之前**先按 `|` 切分单元格——公式内裸 `|` 把单元格切开，超出表头列数的格整体丢弃，公式右半连同闭 `$` 消失（`` $`…`$ `` 也救不了，切分更早）；对策 `\|`（不切格、送达为裸 `|`，代码包裹内同样有效）。单元格本身对公式安全（2026-08-31 实测）；单行 `$$…$$` 在单元格内按行内提取（退化）。

### 8. HTML 块（叶块，块家族中的异类）

**块结构层唯一非 Markdown 语法的块**。其他九种块的识别依据都是 Markdown 自己的标记（`#`、`>`、``` 围栏、缩进、空行）；只有它由另一种语言的语法识别——"行首是不是 HTML 标签"，标签名单是 HTML 的块级元素概念，不是 Markdown 概念。内容的解释权同样不归 Markdown：不解释、只透传，直接交给 Phase 3 消毒。它是 Markdown 给 HTML 留的逃逸舱口，不是 Markdown 设计的容器。三个由此而来的特殊性：

- **开启按标签名单分三路**（2026-08-31 实测）：`<script>`/`<pre>`/`<style>` 行首即开、**到闭合标签结束**——空行不结束，这是唯一结束条件由内容语言决定的块；内建块级名单（`<div>`/`<p>`/`<table>`/`<article>`/`<section>` 等）行首即开、到空行结束；名单外标签（`<span>`/`<custom-tag>` 等）须独占整行才开块，后面跟文字则按普通段落走行内规则。
- **内容跳过 Phase 2**：不跑行内解析，`$` 从未成为候选——与"跳过集合"是两种死因：这里是没有文本节点可提取，不是被跳过。
- **内容跳过 HTML 生成**：段落文本要经"文本 → 元素"的生成，HTML 块的内容已经是 HTML，直接进消毒——消毒剥除只影响手写标签、不影响 Markdown 语法生成的元素，原因在此。

公式结论：成块即死；没成块的行内标签归 Phase 3 消毒 + Phase 3.5 元素规则管（规范一.3 的三路判定表）。

### 9. 引用块（容器块）

逐行 `>` 前缀。内层块照常解析，`$$` 块可正常 display；两条懒延续死法：引用文字紧邻 `> $$`（缺 `>` 空行）、`$$` 段后跟裸文字行，均被吸入。

### 10. 列表（容器块）

项内块需缩进到内容列。**项内 `$$` 块有文档级毒害**：文档更早处存在任何已提取公式即静默失效（闭源，按实测）——列表内只用行内公式，块级移正文。

### 11. `$$` 数学块——**不存在**

`$$…$$` 在块结构层不是独立语法，就是一个普通段落（内容恰为 `$$…$$`）。识别发生在 Phase 3.5。规范三.1 的全部死/退化矩阵都能从"它是段落"推出：段落延续规则（第 3 项）决定它能不能保持纯净。

## Phase 2｜行内解析

对叶块的文本内容跑行内规则（代码块与 HTML 块除外——前者转义成展示文本，后者是异语言透传，见 Phase 1 第 5/6/8 项），输出段内 HTML。公式相关的四件事：

- **反斜杠转义消耗**：Markdown 中部分 ASCII 标点身兼两职（普通字符 + 语法标记）；标点前加 `\` 即向解析器声明"取字面义、不取语法义"——解析器消耗 `\`，字符以字面身份进入文本、不再参与语法判定（`\%`→`%`、`\{`→`{`、`\_`→`_`、`\\`→`\`）。仅对 ASCII 标点有效；字母前的 `\` 不构成转义、原样保留。这是规范第二节"转义吃一层"的发生点——TeX 的 `\` 是给 MathJax 的指令，却被 Markdown 当作自己的转义声明先行消耗，损失在此定型，后续阶段救不回来。
- **emphasis 配对**：成对 `*`/`_` → `<em>`，成对 `**`/`__` → `<strong>`，GFM 成对 `~~` → `<del>`。`_` 受 intraword 规则豁免（两侧字母/数字时不配对），`*` 不受。这些元素是 Phase 3.5 两个方向死因的来源；配对**跨过 `$$` 定界符**则直接毁块（块级死，2026-08-31 实测），但配对跨不过段落边界。
- **硬换行**：行尾孤 `\`（或两空格）→ `<br>`，反斜杠当场消耗。
- **其余行内语法**：代码 span（`<code>`）、链接/autolink/图片（`<a>`/`<img>`）、行内 HTML 标签原样保留到下一阶段。

## Phase 3｜HTML 生成与消毒

块结构与行内结果序列化为 HTML 字符串，然后过白名单消毒：

- **实体转义**：HTML 中 `<`/`>`/`&` 是结构字符（标签定界符、实体引导符），要在内容里表示它们本身须写成实体引用 `&lt;`/`&gt;`/`&amp;`——与反斜杠转义同旨异体：都是声明"此字符是数据不是语法"，只是面向的解析器不同（HTML 解析器而非 Markdown 解析器）、记号不同。这是表示层编码：浏览器解码后读者看到的仍是原字符，内容不变（DOM 文本仍是 `&`，MathJax 读 textContent 不受影响）。
- **白名单剥除**：不在白名单的标签被剥除、**标签内文本保留**（开源实现为 html-pipeline 的 SanitizationFilter；生产名单窄于 gem 默认，以实测为准）。2026-08-31 实测剥除：`u`、`cite`、`abbr`、`small`；保留：`i`、`em`、`b`、`strong`、`del`、`span`、`s`、`sub`、`sup`、`mark`、`q`、`kbd`、`var`、`code` 等。
- **未闭合标签补全**（2026-08-31 实测）：`<em>`/`<b>`/`<i>` 双补——段尾补闭合 + 重开同名元素包住后续所有块直到文末（规范一.2 跨段污染的来源）；`<a>`/`<span>` 只补闭合、不重开，污染不出段；孤立闭合标签（`</em>`/`</b>`/`</div>`）静默丢弃、原地留一个空格。
- **顺序**：消毒在本阶段完成，先于 Phase 3.5——证据：被剥除的 `<u>` 无论包裹公式还是嵌在公式内，公式都正常提取（2026-08-31 实测）。

### Phase 3.5｜服务端数学提取

闭源步骤，全部结论按实测（判据 = `<math-renderer>` 元素）。行内与块级是两套判定，共用一个包装元素、以 class 分流。

**行内 `$…$` 提取**：

1. 边界扫描定候选：开 `$` 前只许空格/行首/半角 `(`；闭 `$` 后不许 `\w` 词字符；内侧不贴空白（规范一.1，525 例全量）。
2. 按元素名跳过四个子树：`em`、`b`、`a`、`code`——公式落进这四个子树即死（与样式语义无关：em 死 i 活、b 死 strong 活）。
3. 任何**真实生成**的元素，其边界落进 `$…$` 内部 → 死（完整嵌入或横跨同死；本质：`$…$` 须在连续文本节点上，边界切断即死。2026-08-31 实测：完整嵌入 25 例 + 横跨 6 例无一存活）；被消毒剥除的标签不生成元素、两侧文本重连、不致死。
4. 内容级过滤：`select`、`begin` 子串命中即死（机制闭源，仅此两项——其余 HTML 标签名/脚本安全词/SQL 词/TeX 命令 32 词扫描全活；子串是 `begin` 本身，不带反斜杠、词内、大写均死；过滤作用于**送达前的最终文本**——实体解码后拼出的子串也杀：`&#98;egin` 源码无连续 `begin` 仍死，2026-08-31 实测；`[x](y)` 已于 2026-08-31 改判——它真实生成 `<a>` 元素，归第 3 步）。
5. 产出 `<math-renderer class="js-inline-math">$…$</math-renderer>`，定界符保留。**注意行内包装多做一次实体转义**：`&`/`<`/`>` 在 Phase 3 已转为 `&amp;`/`&lt;`/`&gt;`，写入行内 math-renderer 时再转一次——DOM textContent 为 `&amp;`/`&lt;`/`&gt;`，MathJax 收到的是字面实体文本（对齐符、比较符行内不可得；块级无此层，2026-08-31 实测）。

**块级 `$$…$$` 提取**：

1. 段落纯净度判定：整段内容恰为 `$$…$$` 且段内无破坏性元素 → display（段内含跳过集合的 `<a>`/`<b>`/`<code>` 直接失败；`<em>` 与其余元素被序列化容忍，2026-08-31 实测）；段落被破坏（并入、吞噬、拆散）→ 死；`$$` 与文字同行或单行落在脏上下文 → **退化**（照常提取但包成 `js-inline-math`，行内公式没有的失败形态）。
2. 过关后把段内 HTML **重新序列化回文本**再包装——这是块级与行内的本质差异：行内遇 `<em>` 切断文本节点（公式死），块级带着元素序列化（公式活、内容被改写）。
3. 序列化规则（2026-08-31 实测）：`<em>` 一律输出 `_…_`（成对 `*` 同化为 `_`，`a*b*c`→`a_b_c`）；`<strong>`/`<del>`/`<i>`/`<span>`/`<sub>`/`<sup>`/`<kbd>`/`<q>` 等其余元素标记整对丢弃、文本保留；跳过集合的 `<a>`/`<b>`/`<code>` 不能序列化——块内含有即整块提取失败（`$$` 原样残留），`<img>` 则被整体丢弃而块存活；`<br>` → 纯换行（行尾孤 `\` 就此消失）；行尾字面 `\` 重新转义回 `\\`（净效果行尾 `\\`→`\\`，`aligned` 可靠）；`<em>` 配对过的块送达内容首尾各多一个空行。
4. 产出 `<math-renderer class="js-display-math" style="display: block">$$…$$</math-renderer>`，定界符保留。

## Phase 4｜浏览器端 MathJax 排版

MathJax 读取 `<math-renderer>` 的 textContent（实体已还原为字符），按 class 分行内/display 排版，定界符 `$`/`$$` 由 MathJax 配置识别。本阶段不做任何"公式在哪"的判定——生死全在 Phase 3.5。未覆盖项：送达文本中的异常空行/字符对 MathJax 排版的影响（规范已标"未验"）。
