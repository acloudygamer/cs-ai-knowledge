# 公式排版规范

> 定位：公式排版的正文规范。实测记录见 `全量验证.md`，管线推导见 `Markdown渲染管线研讨.md`。
>
> **判据**：一个公式"活着"的唯一标志，是服务端把它包进 `<math-renderer>` 元素——行内与块级共用这一元素、以 class 分流：行内 `js-inline-math`，内容 `$x+y$`；块级 `js-display-math` 加 `display: block`，内容 `$$x+y$$`（定界符保留）。包装发生在服务端，网页端 MathJax 只负责排版——它不做任何"公式在哪"的判定，生死全在服务端。全部判据经 GitHub `POST /markdown` API 实测取得（与 github.com 网页端同一条管线）。

## 一、行内 `$…$`：服务端到底返不返回我的公式

> **验证方法**：按上述判据逐例渲染。**一维扫描**：一次只动一侧——测开侧时闭侧固定空格，测闭侧时开侧固定空格；公式统一 `x+y`，排除转义与斜体的干扰。

### 1. 边界字符（525 例一维扫描，两侧不对称）

| 位置 | 合法（公式被提取） | 阻断（`$` 原样输出） |
|---|---|---|
| 开 `$` **前** | 空格、行首、半角 `(` | 其余一切：可见 ASCII 93 个（字母/数字/下划线/全部标点，含 `[` `{` `<`）、全角 `（`、CJK 汉字、CJK 标点、日韩文字与符号 |
| 闭 `$` **后** | 除 ASCII 词字符外的一切：ASCII 标点（含 `$` `*` `` ` ``）、CJK 汉字/标点、日韩文字符号、空格、行尾 | ASCII 字母 52 + 数字 10 + 下划线 1（共 63，恰为 `\w` 词字符集） |
| 开 `$` **后**（内侧 padding） | —— | 空白，无条件阻断（`$ x+y$`） |
| 闭 `$` **前**（内侧 padding） | 空白可容忍：闭 `$` 后是非空白字符（` $后`、` $。`）或行尾时存活 | 闭 `$` 前是空白**且**后也是空白且其后仍有文字（` $ ` 三明治）时阻断 |

实操：两侧各留一个半角空格——`值为 $x+y$ 个`；公式内侧不贴空白。一条规则覆盖全部场景，其余合法边界（闭 `$` 后贴中文、开 `$` 前贴半角 `(`）上表备查、不必记。

### 2. 容器与标签：公式死在哪个元素里

提取步骤按元素名跳过四个子树：`em`、`b`、`a`、`code`——与样式语义无关（em 死 i 活、b 死 strong 活，闭源实现按实测记录）。四种元素各有来路：`*`/`_` 斜体的产物是 `em`，markdown 链接是 `a`，代码 span 是 `code`，再加上直接手写的标签。哪些元素安全（下表同一文本 `前 $x+y$ 后`、干净边界，只变容器）：

| 提取被跳过（公式死） | 提取正常（公式活） |
|---|---|
| `em`（`*`/`_` 斜体的产物）、`b`、`a`（含 markdown 链接 `[..](..)`）、`code`（代码 span） | `i`、`strong`（`**`）、`del`（`~~`）、`span`、`u`、`s`、`sub`、`sup`、`mark`、`q`、`kbd`、`var`、`cite`、`abbr`、`small`、`li`、`blockquote`、表格单元格（公式内裸 `|` 例外，见第 3 节末段）、标题、`p` |

（2026-08-31 全量重验 36 例，死活与上表零冲突；唯一修正："活"列的 `u`/`cite`/`abbr`/`small` 四例是标签被 sanitizer 剥除、容器从未存在——math-renderer 直接落在裸段落里，并非"容器内可提取"的证据。真实生成且公式存活的容器是其余各项。）

手写标签的坑在**未闭合**：结尾由服务端自动补（API 返回的 HTML 里直接可见），且补法分两类（2026-08-31 重验 14 例）：

- **`<em>`/`<b>`/`<i>`："双补"**——先在段尾补闭合，紧接着**重开一个同名元素**把后续所有块包住（段落、标题、列表全覆盖），直到文档末尾再补闭合（`…</em></p><em><p>二段 $x+y$ 公式</p>…</em>`）。污染从标签所在段的**下一段**开始，标签之前的公式不受影响。死活仍由容器表决定：em/b 是跳过集合——标签之后公式全死；i 是安全容器——结构相同但公式照活。
- **`<a>`/`<span>`：只补闭合、不重开**——污染不出段，后续段落正常。

| 写法 | 公式结果 |
|---|---|
| 单个 `*` / `**`（未配对） | 活（不生成元素，星号原样成文本） |
| 未闭合 `<em>` / `<b>` | 双补跨段：标签之后全部死；标签之前不受影响 |
| 未闭合 `<i>` | 双补跨段但公式照活（i 是安全容器） |
| 未闭合 `<a>` / `<span>` | 仅补闭合不重开：不跨段 |
| 孤立闭合标签 `</em>` `</b>` `</div>` | 活（标签被丢弃、原地留个空格；`</div>` 也不触发 HTML 块） |

**反向场景：元素边界落进 `$…$` 内部**——规则与上表不同且更严：凡**真实生成**的行内元素，其边界落在公式内部即死，不分元素名、不分形态（2026-08-31 实测）：完整嵌入（`$a **b** c$`，25 例无一存活：`/`_`/`**`/`__`/`~~` 配对、代码 span、markdown 链接、autolink、`![img]`、手写 `i`/`em`/`b`/`strong`/`del`/`span`/`s`/`sub`/`sup`/`mark`/`q`/`kbd`/`var`/`code`、void `<br>`、空元素、元素占满整个公式）；**横跨边界**（开/闭标签只有一个在公式内：`$a <i>b$ 后 c</i>`、`前 <i>$a b</i> c$ 后`；markdown 配对横跨：`$a *b$ 后 c*`——6 例全死，返回 HTML 里 `$…$` 在元素边界处被切成两个文本节点）。本质：提取要求 `$…$` 落在连续文本节点上，元素边界落进公式内部即切断。唯一例外是标签从未生成：`<u>`/`<cite>`/`<abbr>`/`<small>` 被 sanitizer 剥除、两侧文本重连（上表"活"列里的这四个也是同一原因——不是容器安全，是标签不存在）；孤立闭合标签在公式内同样被丢弃（`$a </i> b$` 活），HTML 注释同被剥除。

对策两条：**别让公式落进 em/b/a/code 子树**——斜体改用 `<i>`、链接文字不放公式、手写标签必须闭合；**也别让任何元素嵌进公式内部**——公式内不写成对的 `*`/`_`/`**`/`~~`、不写行内标签、不放链接。排查：公式死了但旁边没有定界符，先往回找未闭合的手写标签，再看是否紧邻全角标点（第 1 节开侧规则）。

### 3. 块结构层：候选根本没机会出现

第 1、2 节的前提是公式文本已跑完行内解析、成为候选；本节的死法更早——发生在块结构层（管线 Phase 1），候选从未形成。

**HTML 块**：与围栏代码块同类的"写什么就显示什么"的块——期间整块原样输出、不跑行内解析，`$` 只是普通字符。公式死因与第 2 节不同：不是落进跳过集合（被跳过），而是没有文本节点（候选从未形成）。

行首出现标签时，按标签名单分三条路，决定这一行是 HTML 块还是普通段落（2026-08-31 实测）：

| 行首标签 | 成块条件 | 块结束条件 |
|---|---|---|
| `<script>`/`<pre>`/`<style>` | 行首即开 | **到闭合标签**——空行不结束 |
| 内建块级名单：`<div>`/`<p>`/`<table>`/`<article>`/`<section>` 等 | 行首即开，同行后面有文字也开 | 到空行 |
| 名单外标签：`<span>`/`<custom-tag>` 等 | **须独占整行**；后面跟文字则不开块，按普通段落走行内规则 | 到空行 |

判定分两步看。

**第一步：成没成块。** 成了 HTML 块 → 公式**必死，无例外**。死因不在标签、不在消毒，而在时机：块结构判定在管线最前（Phase 1），成块的内容从未被当作 Markdown 文本处理，`$` 只是普通字符。消毒剥除也救不回来——实测 `<article>前 $x+y$ 后</article>`：标签被剥除、输出只剩裸文本，公式照样死，因为行内解析的时机已经过去。

**第二步：没成块的，标签作为行内 HTML 留在段落里**，公式回到第 1、2 节的常规判定，三种命运：

1. **标签被消毒剥除**（`u`/`cite`/`abbr`/`small`/`<custom-tag>`）→ 视同没写，公式按裸段落判定，边界干净就活——`<custom-tag>前 $x+y$ 后</custom-tag>` 实测活。
2. **标签真实生成、公式整体在元素内** → 看第 2 节容器表：em/b/a/code 里死，其余活——`<span>前 $x+y$ 后</span>` 实测活。
3. **元素嵌进公式内部**（`$a <span>b</span> c$`）→ 第 2 节反向场景，死。

另：`<script>` 标签即使没成块也不会生成元素——消毒把它转义成纯文本。

**表格单元格内的裸 `|`**：单元格对公式是安全容器（第 2 节表），例外在更早的表格行解析阶段——行内裸 `|` 先把行切成多格（先于行内解析、先于代码 span），超出表头列数的格被**整体丢弃**：公式右半连同闭 `$` 直接从文档里消失（2026-08-31 实测：`$a|b$` 切后单元格只剩 `$a`；`` $`a|b`$ `` 同样救不了，反引号残片原样残留说明代码 span 未及形成）。对策：公式内 `|` 一律写 `\|`——不切格，且送达为裸 `|`（`\\|` 送达相同；代码包裹内 `\|` 同样有效）。另：单行 `$$…$$` 写在单元格内按行内提取（退化），与正文独立段落的 display 不同。

### 4. 内容级过滤：两个杀手子串

行内 `$…$` 的内容含 `select` 或 `begin` 子串即死——词内也算（`xselected`、`beginning` 同死）、大小写不敏感、`begin` 不带反斜杠也死（`\text{beginning}` 这种正常英文也踩雷）。块级 `$$…$$` 与 `` $`…`$ `` 免疫；退化形态（单行 `$$` 落脏上下文）按行内处理、不免疫。机制闭源，按实测（40+ 嫌疑词扫描仅此两个，考据见 `全量验证.md`）。

对策：避开子串（标识符改名、`\begin{cases}` 移块级），或 `` $`…`$ `` 兜底。转义打断子串（`s\elect`）虽能过提取，但反斜杠送达 TeX 成未知控制序列，不是对策。

## 二、提取成功 ≠ 送达正确：转义层——`\` 的双重身份

根源一句话：**TeX 数学公式里大量字符必须加 `\`（`\%`、`\{`、`\_`……），而 CommonMark 也用 `\` 做转义，且 Markdown 转义发生在公式判定之前**——于是"为 TeX 写的反斜杠"先被 Markdown 吃掉一层。公式照常提取（边界合法、`math-renderer` 正常生成），但送达 MathJax 的 TeX 源已经坏了：失败模式从"公式不见了"变成"公式在、内容错"，更隐蔽。

| 源码写法 | 送达 TeX | 后果 |
|---|---|---|
| `$M_1 = 10\%$` | `$M_1 = 10%$` | `%` 是 TeX 注释符：静默吃掉其后一切，不报错、百分号消失 |
| `$\text{per\_channel}$` | `$\text{per_channel}$` | `\text{}` 内裸 `_`：TeX 语法错（MathJax 红字） |
| `$\{x\}$` | `${x}$` | 字面花括号变分组符：渲染出来括号消失（2026-08-23 实测） |
| `$a \& b$` | `$a &amp; b$` | 行内包装多一层实体转义：`&` 送达（textContent）为 `&amp;`，对齐符不可得；`<`、`>` 同理（`$a < b$` 送达 `&lt;`）。块级无此层，送达正常（2026-08-31 实测） |
| `\$` | 裸 `$` | TeX Misplaced $；还会连带改写开侧边界字符 |
| `$a \\ b$` | `$a \ b$` | `\\` 塌成 `\`（行内公式内本就少见） |
| `$\int_0^1 x^2 \, dx$` | `$\int_0^1 x^2 , dx$` | 细间距 `\,` 被吃成裸逗号——间距命令 `\;` `\!` `\:` `\.` 同命中（行内块级均实测），真实公式高频中招；`\\,` 双写修复成立 |

规律：凡 TeX 要求加 `\` 的 ASCII 标点（`%` `_` `{` `}` `&` `$` `#` `,` `;` `!` `:` `.` 等全部），单写必被吃一层。

对策（从简到繁）：

1. **字符移出公式**：`$M_1 = 10$%`——单位与数值分离，最干净。
2. **双写反斜杠**：`$M_1 = 10\\%$`、`$\\{x\\}$`——Markdown 吃一层后恰剩 TeX 需要的 `\%`、`\{`（实测有效）。
3. `\text{}` 里的 `_` 首选改写法（`per-channel`）；`\\_` 只有同段无其他可配对 `_` 时才安全（原因见下）。
4. 硬场景兜底：`` $`x+y`$ `` 代码包裹——内容不经转义层、`_` 不参与配对，第一节与第二节的坑基本免疫；唯一例外是 `&`/`<`/`>`：行内一切写法（裸写、`\&`、`\\&`、代码包裹）都被行内包装多做一次实体转义，送达 textContent 为 `&amp;`/`&lt;`/`&gt;`（2026-08-31 实测），对齐符与比较符均不可得——需这些字符用块级 `$$…$$`（无此层，送达正常）。GitHub 专属语法，可迁移性差。

### `\\_` 的副作用：修好了转义，制造了元素

`\_` 与 `\\_` 是一对互补的坑，分属两节：`\_` 被转义层整体消耗成裸 `_`，送达 TeX 即语法坏——这是本节的转义问题；`\\_` 按对策 2 修好了反斜杠（`\\`→`\`），但剩下的 `_` **没有转义保护**，是一个活的配对候选——若同段还有另一个词首/词尾位的 `_`（`$_{j}$`、`_foo`、`foo_`），两者配对生成 `<em>`。从这里起问题性质变了：公式的死活不再归转义层管，而是被第一节的元素规则接管——被吞进 em 子树（一.2 跳过集合）或被元素切段（反向场景），都是死（实测：`$a\\_b$ 与 $_{j}$` 同段，返回 `$a\<em>b$ 与 $</em>{j}$`，两个公式同死于一个 `<em>`）。

转义"去掉语义"的直接证据（2026-08-31 实测）：`$x\_i$ 和 $y\_j$` 同段双双存活、无 `<em>` 生成——被转义的 `_` 永不配对；`$a \* b$` 送达 `$a * b$`，同理。注意一个叠加坑：转义后的 `_` 仍是 `\w` 词字符——`\_$x+y$\_` 虽不配对（无 `<em>`），但贴开 `$` 的 `_` 触发第 1 节开侧边界规则，公式照样死。

好消息是普通下标的 `_` 天生惰性：`x_i`、`M_1` 的 `_` 两侧都是字母/数字（intraword），永不参与配对——段落里最常见的下标都在豁免之列。所以"`\\_` 修复安全"的确切条件是：**同段没有词首/词尾位的 `_`**（`\\_` 与 `x_i` 同段活，实测）。

## 三、块级 `$$…$$`：同一套管线的另一套答案

前两节的两个问题——"服务端返不返回"（第一节）、"送达内容对不对"（第二节）——对块级公式同样要问，但答案几乎全部改变。核心模型：**`$$` 块不是独立语法，它就是一个"整段内容恰为 `$$…$$`"的普通段落**。由此，块级公式走三段旅程，各对应管线一个阶段、各管一种失败形态：**段落成形**（Phase 1 块结构，本节第 1 小节——决定成不成块）→ **段内解析**（Phase 2 行内规则，同第一、二节——决定内容损失）→ **判定与序列化**（Phase 3.5，本节第 2 小节——决定 display/死/退化与送达文本）。全部结论经 2026-08-31 全量重验（结构 30 例零冲突）；专项实测记录见 `全量验证.md`，管线行为见 `Markdown渲染管线研讨.md`。

### 1. 段落成形：不看边界，看结构

边界与内侧空白**一律不查，全部存活**：`$$ x+y $$`、内容贴定界符行（`$$x+y`）、内容行缩进、界行尾随空格、整块 ≤3 空格缩进——全部正常 display。第一节的开侧/闭侧/padding 规则对独占段落的 `$$` 块一概不适用。

判定只看一件事：`$$…$$` 是否保持为一个完整、纯净的段落。背后的统一原理是**段落连续性规则**（管线 Phase 1 的段落行为）：`$$` 行不能打断已开始的段落（前文无空行 → 并入）、段落不能被块内空行拆散、后文无空行的文字行会被并入——下面矩阵里所有死与退化都能从这一条推出（2026-08-31 重验 30 例：懒延续、表格吞噬、缩进代码块各形态全部复现）。结果有三种，先定义再看表：

- **display**——整段纯净，包成 `js-display-math`，正常块级排版。
- **死**——多行块（`$$` 独占行）的段落被破坏（并入、吞噬、拆散），不提取，`$$` 原样输出。
- **退化**——`$$` 与文字同行（`值 $$x+y$$ 值`），或单行 `$$x+y$$` 落在不干净的上下文里（前后行正文无空行、列表项/引用/表格单元格内）：服务端**照常提取**，但包成 `js-inline-math`、内容保留 `$$` 定界符——MathJax 收到 `$$x+y$$`，视觉异常、不报错、没有任何"提取失败"的迹象。**"公式还在"不等于"块级写法生效"**，判定必须看 renderer 的 class。这是行内公式没有的失败形态。

**死与退化的分野就是多行与单行**：同样的脏上下文（前后行正文无空行、表格行之后、引用懒延续），多行块死，单行不死、一律退化。

实测矩阵按上下文分三组，多行块与单行并列、直接对照死/退化分野：

**前文（`$$` 行之上）**

| 前文 | 多行块（`$$` 独占行） | 单行 `$$x+y$$` |
|---|---|---|
| 空行（标准写法） | display | display |
| 标题行 / 围栏闭合行 / 分隔线（无空行） | display——前块自然结束，`$$` 行起新段 | display |
| 正文（无空行） | 死——`$$` 行并入段落（`$$` 不能打断段落） | 退化——并入同段，按行内提取 |
| 列表项 / 引用行（无空行） | 死——懒延续并入 | 退化——懒延续并入后按行内提取 |
| 表格行 | 死——`$$` 行被吞成表格单元格 | 退化 |

**后文（`$$` 行之下）**

| 后文 | 多行块 | 单行 |
|---|---|---|
| 空行（标准写法） | display | display |
| 正文（无空行） | 死——文字行并入块段落，段不再纯 | 退化——文字并入同段，按行内提取 |

**块内**（仅多行块）

| 写法 | 结果 |
|---|---|
| 含空行 | 死——段落拆散；空行后 ≥4 缩进行还会变缩进代码块 |
| `$$$x+y$$$`（定界符多写） | 提取但内容带多余 `$`（TeX 错） |
| `$$$$`（空块） | 死 |
| 配对跨过定界符（`$$`⏎`a *b`⏎`$$`⏎`c*`） | 死——`<em>` 吞掉闭 `$$`，块被毁（2026-08-31 实测；块外配对跨不过段落边界，无害） |
| 块内含块级语法（行首 `<div>`、`---` Setext 线） | 死——段落在 Phase 1 被 HTML 块/标题切断 |

### 2. 判定与序列化：解析一遍，再序列化一遍

段落成形后，送达的 TeX 还要过两轮（2026-08-31 全量实测；机制推导见 `Markdown渲染管线研讨.md` Phase 3.5）。

**第一轮·解析（Phase 2）：规则与行内完全相同，此处只记块内特有的三点**

- 转义吃一层、`\\X` 修复、行中 `\\` 塌成 `\`——同第二节，不重复。
- 行尾孤 `\` 被解析为硬换行、当场消耗——多行块特有的损失。
- emphasis 配对照常生成 `<em>`/`<strong>`/`<del>`，但**块级不判死**——元素带进第二轮处理（行内同场景必死，见第一节反向场景）。

**第二轮·判定与序列化（Phase 3.5，块级独有）：段内 HTML 被重新序列化回文本再包装——输出全看序列化器约定，与源码写法无关**

| 段内形态 | 送达结果 |
|---|---|
| `<em>`（成对 `*` 或 `_` 配对而来） | `_…_`——单行块**字节级原样往返**：常用公式的下标 `_` 即使配上对也原样送达（2026-08-31 实测），**块级无需 `\_` 去语义**；多行块配上对则首尾多出空行（见表末行）。唯一真坑是成对 `*` 同化为 `_`：`a*b*c` → `a_b_c`，乘号一律 `\cdot` |
| `<strong>`/`<del>`/`<i>`/`<span>`/`<sub>`/`<sup>`/`<kbd>`/`<q>` 等 | 标记整对丢弃、文本保留：`a **b** c` → `a b c`——**`__`/`**` 是最隐蔽的损失**：块照活、不报错、字符静默消失；配对的 `__` 会把中间内容一并卷走——`\text{__} + \text{__}` → `\text{} + \text{}`，TeX 合法的填空位照样被吃 |
| `<a>`/`<b>`/`<code>`（跳过集合其余三者） | 整块提取失败——`$$` 原样残留，连退化都没有 |
| `<img>` | 整体丢弃、块照常 display——送达内容只剩空白 |
| 行尾字面 `\`（源码行尾 `\\` 塌缩而来） | 重新转义回 `\\`——净效果行尾 `\\`→`\\`，`\begin{aligned}` 可靠；前提：`\\` 贴行尾换行，单行 `$$…\\$$` 里按行中规则塌缩且尾部异常；注意换行后一行的行首空格被序列化丢弃（对 TeX 排版无影响） |
| 硬换行 `<br>`（源码行尾孤 `\` 或两空格） | 纯换行——行尾孤 `\` 就此消失 |
| `&`（裸写或 `\&`） | 送达为 `&`——块级无行内的双层实体转义，对齐符可用 |
| 多行块内发生 em/strong 配对 | 送达内容首尾多出空行（em 两端各一、strong 首端一，2026-08-31 实测复现；单行块无此现象；对 MathJax 排版的影响未验） |

对策汇总：块级公式内不写 `**`、`__`、`~~`，不放链接、代码 span、图片；乘号一律 `\cdot`；多行对齐 `\begin{aligned}` + 行尾 `\\`。

### 3. 容器：引用可用，列表有毒

- **引用内**：逐行 `>` 前缀即可，正常 display（2026-08-31 重验）。两条懒延续死法：引用文字紧邻 `> $$`（缺 `>` 空行）死；`$$` 段后直接跟裸文字行（无 `>` 前缀）被吸入、死。
- **列表项内：不放 `$$` 块**。"空行 + 缩进到内容列"的写法单独成文时有效，但实测存在**文档级毒害**（2026-08-31 重验）：文档更早处存在任何已提取公式——行内公式、正文块级公式均触发——列表内块静默失效，且死法是**死而非退化**（`$$` 原样残留）；列表整体之后的公式无害；正文与引用内的块免疫。真实文档几乎必有行内公式 → 列表内块级实际不可靠：列表内用行内 `$…$`，块级移到正文。
- em/b/a/code 容器内死（第一节容器表对 `$$` 同样适用）。
