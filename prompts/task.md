# 概念文档任务

## 输入

- **概念名称**：需要文档化的核心概念
- **版本环境**：stable / latest（参考 versions.json）

## 输出要求

每个概念文档必须包含以下五章节，顺序不可调换：

### 1. 定义

一句话断言本质。不是描述，是断言。

### 2. 数学模型

若有计算/复杂度/概率，必须给出 LaTeX 公式。公式本身即为解释。

### 3. 数据流

ASCII 图或分步列表，标记数据从入口到出口的每一次形态变换和所有权转移。

### 4. 机制

高密度文字，解释"为什么这样设计""约束条件是什么""违反约束会怎样"。不描述 API，不描述用法。

### 5. 参考存根

仅当概念有明确的可执行证明价值时出现。代码不超过 20 行，不含错误处理、不含日志、不含注释。

---

## 对比参照

当章节中涉及易混淆的相关概念时，在"数据流"或"机制"章节中通过链接引用并用对比表格对齐三列：

| 对比维度 | 说明 |
|----------|------|
| 内存模型 | 地址空间隔离级别 |
| 调度权 | 谁控制执行权 |
| 数据交换代价 | 通信/同步开销 |

---

## 执行原则

1. `定义` 是一句话本质断言，`机制` 讲为什么
2. `数学模型` 强制化：涉及计算/复杂度必须给 LaTeX
3. `对比参照` 内嵌对齐：在数据流或机制章节中遇到相关概念时触发
4. `参考存根` 触发条件：仅有明确的可执行证明价值时才出现
5. `机制` 禁止描述 API 和用法，防止写成使用手册
