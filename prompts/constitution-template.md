# [概念名称]

## 定义
- 允许从一句话断言扩展为**段落式本质说明**，浓缩机制的高层次解释。
- 当机制深入时，定义可延伸，不强行固守一句；但开头必须给出概念的精确核心。
- 避免空洞的“是一种...的技术”，直指本质。

### 数学模型
- 必须存在，除非确实无量化维度。
- 涉及计算/复杂度时必须给 LaTeX 公式；涉及概率时给分布假设。
- **归约终点**：归约到软件层中概念最清晰、最不可约的那一层。优先给出量化公式；量化困难时，必须给出**概念层面的精确描述**，使读者能据此判断边界行为（如 RAII：获取和释放严格绑定于词法作用域，释放时机可预测）。

## 数据流

- 用 ASCII 图或编号分步列表，显式标记数据在系统内的形态变换和所有权流转。
- 与数学模型并列，两者都需存在，不可取舍。

> **ASCII 图**：用 `<pre>` 标签包裹，防止空格被 Markdown 渲染器忽略导致对齐错乱。

### 对比参照
- 独立块，不属于数据流。置于数据流之后、机制之前。
- 仅当存在易混淆概念（如协程/线程/进程）时出现，用三列对比表格：内存模型、调度权、数据交换代价。
- 若无易混淆概念，直接省略此块，无需显式说明。

## 机制

高密度文字，解释"为什么这样设计""约束条件是什么""违反约束会怎样"。不描述 API，不描述用法。

## 参考存根

仅当概念有明确的可执行证明价值时出现。代码不超过 20 行，不含错误处理、不含日志、不含注释。

---

**执行原则**：
- `定义` 是一句话本质断言作为开头，可延伸为段落式本质说明；`机制` 讲为什么（约束条件、违反后果）
- `数学模型` 强制化：涉及计算/复杂度必须给 LaTeX
- `对比参照` 强制对齐：协程/线程/进程等易混淆概念必须三列对比
- `参考存根` 触发条件：仅有明确的可执行证明价值时才出现
- `机制` 禁止描述 API 和用法，防止写成使用手册
