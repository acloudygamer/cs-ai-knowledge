## 示例 1：std::vector 扩容机制

# std::vector 扩容机制

## 定义

`std::vector` 的扩容是在堆上分配新内存、移动旧元素、释放旧内存的 $O(N)$ 操作，通过指数增长策略将单次插入均摊为 $O(1)$。

## 数学模型

设容量序列为 $\{c_0, c_1, c_2, \dots\}$，增长因子为 $k$（通常 $k=2$）：
$$c_{i+1} = \max(c_i \times k, 1)$$

第 $i$ 次扩容触发时，已插入元素数 $n = c_i$，移动代价 $O(c_i)$。总移动次数为：
$$T(N) = \sum_{i=0}^{\log_k N} c_i = \sum_{i=0}^{\log_k N} k^i = \frac{k^{\log_k N + 1} - 1}{k - 1} = \frac{kN - 1}{k - 1} = O(N)$$

均摊复杂度：
$$\frac{T(N)}{N} = O(1)$$

## 数据流

<pre>
+---------------+      +---------------+      +---------------+
| 旧内存 (堆)   | ---> | 新内存 (堆)   | ---> | 旧内存 free   |
| [A][B][C][ ]  | 移动 | [A][B][C][ ][ ]|      |               |
+---------------+      +---------------+      +---------------+
        |                        |
    size=3, cap=4          size=3, cap=8
</pre>

触发条件：size == capacity.

## 参考存根

```cpp
template<typename T>
void vector<T>::push_back(const T& val) {
    if (size_ == cap_) {
        size_t new_cap = cap_ ? cap_ * 2 : 1;
        T* new_data = alloc(new_cap);
        for (size_t i = 0; i < size_; ++i)
            new (new_data + i) T(std::move(data_[i]));
        dealloc(data_);
        data_ = new_data;
        cap_ = new_cap;
    }
    new (data_ + size_) T(val);
    ++size_;
}
```

## 示例 2：Scaled Dot-Product Attention

# Scaled Dot-Product Attention

## 定义

注意力是一个可微的键值查找：Query 检索所有 Key 的匹配度，经 Softmax 归一化后对 Value 加权求和。

## 数学模型

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

除以 $\sqrt{d_k}$ 的原因：假设 $q_i, k_j$ 独立且均值为 0、方差为 1，则点积 $q_i \cdot k_j = \sum_{t=1}^{d_k} q_{it} k_{jt}$ 的方差为 $d_k$。Softmax 在输入方差大时趋于独热分布，梯度近乎 0。除以 $\sqrt{d_k}$ 将方差压回 1，保持梯度稳定。

## 数据流

<pre>
Q (B, L, d_k)  ──┐
                  ├──> QK^T (B, L, L) ──> /√d_k ──> softmax (B, L, L)
K (B, L, d_k)  ──┘                                    │
                                                       └──> · V (B, L, d_v) ──> Output (B, L, d_v)
V (B, L, d_v)  ────────────────────────────────────────┘
</pre>

矩阵乘法的行/列视角：
- QK^T: Q 的第 i 行与 K^T 的第 j 列做点积，得 (i,j) 位置的相似度。
- ×V: 注意力矩阵第 i 行是权重向量，对 V 的各列做加权和，即 Output 的第 i 行 = Σ_j attn(i,j) · V[j]。

## 机制

三个矩阵的物理含义：
- Q：当前 token "需要什么信息"
- K：当前 token "能提供什么信息"
- V：当前 token "实际存储什么内容"

Q 和 K 做点积求出"需求"与"供给"的匹配度，Softmax 将其转为概率，再对 V 加权求和——等价于以概率分布软寻址 V 的行空间。除以 √d_k 是让 Softmax 工作在温和的非饱和区，避免梯度消失。

## 示例 3：进程、线程、协程 对比

# 进程、线程、协程 对比

## 定义

三者是执行流的三种抽象层次，区别在于调度权归属、内存隔离级别和上下文切换代价。

## 数学模型

令 $T_{ctx}$ 为单次上下文切换耗时：

| 执行单元 | $T_{ctx}$ 典型值 | 调度权 | 内存模型 |
|----------|------------------|--------|----------|
| 进程     | $\mu s$ 级 (含页表切换) | 内核 | 独立虚拟地址空间 |
| 线程     | $ns$ 级 | 内核 | 共享地址空间, 独立栈 |
| 协程     | 函数调用级 | **用户态** | 共享地址空间, 共享栈/独立栈 |

协程切换不涉及特权级切换和 TLB 刷新，因此 $T_{ctx}$ 逼近普通函数调用。

## 数据流

<pre>
+-------------------+    +-------------------+    +-------------------+
|      进程 A       |    |      线程 B        |    |      协程 C        |
| (独立页表)        |    | (共享页表,独立栈)  |    | (共享页表,共享栈)  |
|                   |    |                   |    |                   |
| 数据交换:         |    | 数据交换:          |    | 数据交换:          |
| 管道/共享内存     |    | 直接读写堆内存     |    | 直接读写, 无同步开销|
| 需内核介入        |    | 需同步原语         |    | 单线程, 无竞争     |
+-------------------+    +-------------------+    +-------------------+
</pre>

> **关键区分**：协程不是并发原语，是**协作式调度的可挂起函数**。它不解决多核问题，只解决单核上的阻塞等待问题。

## 机制

线程的本质是内核态的可抢占调度单元，时间片耗尽时被强制挂起。协程的本质是用户态的协作调度单元，只在显式 await/yield 时出让执行权。这导致一个结果：协程之间不存在真正的数据竞争，因为同一时刻只有一个协程在执行。
