# Markdown 写作契约检查

这里放确定性的只读检查。两个入口均不修改文档，也不需要网络或第三方包。运行环境为 Python 3.10+，命令从仓库根目录执行。

| 入口 | 唯一职责 | 输入 |
| --- | --- | --- |
| `check_numbering.py` | 校验节与小节编号连续性 | 一个或多个 `.md` 文件，或章目录 |
| `check_terms.py` | 校验术语表声明与正文首现、全称次数 | 一个或多个章目录 |

章目录只扫描直接子级的 `NN-*.md`，按数字前缀排序，不递归扫描其他目录。

## 编号连续检查

```bash
# 单篇改稿
python -m tools.markdown_checks.check_numbering "0-计算机基础/01-计算机体系/05-数据表示与字节序.md"

# 收章闸门：没有规范编号节也视为失败
python -m tools.markdown_checks.check_numbering --require-numbered "0-计算机基础/01-计算机体系"
```

检查口径：

- `## 一、` 从 1 开始连续递增，支持十、十一、二十一等规范中文整数；`一二`、`一十` 和单位重复会报 `E_SECTION_NUMBER`。
- `### 1.` 在每个编号节内从 1 重新开始。
- 编号小节必须隶属于编号节。
- 代码围栏中的示例标题不参与检查。
- 无编号标题不参与序列；旧式 `### 4.1` 也不会被当成 `### 1.`。
- 普通模式没有编号节时输出 `SKIP` 并返回 0。收章必须加 `--require-numbered`，避免把“未校验”当成“通过”。

该入口不检查标题措辞、标题层级是否美观或其他写作规则。

## 术语首现与全称检查

```bash
python -m tools.markdown_checks.check_terms "0-计算机基础/01-计算机体系"
```

章 README 末尾需要提供下表。首次出现的篇必须写完整的直接子级文件名，不写篇名标题或链接。

```markdown
## 本章术语表

| 术语（最简形式） | 全称 | 首次出现的篇 |
| --- | --- | --- |
| CF | Carry Flag | 01-硬件组成.md |
| NaN | Not a Number | 05-数据表示与字节序.md |
```

表头、分隔行和数据行必须按原始行连续排列。脚本不会跨过正文、空行或代码围栏把多段 pipe 行重新拼成一张表。缩进 4 个空格或 Tab 的代码示例也不会被当成术语表。

同一缩写有多种含义时，在术语单元格追加中文括号标签，三列结构不变：

```markdown
| CAS（内存列访问） | Column Access Strobe | 01-硬件组成.md |
| CAS（比较并交换） | Compare-And-Swap | 07-并行与并发.md |
```

标签只用于消歧，正文仍写裸缩写。同一裸术语的所有条目必须带不同标签，不能与无标签条目混用。带标签条目按各自全称定位该含义的首现篇，再检查声明篇确实出现裸术语；这不会推断裸缩写在其他上下文中属于哪种含义。

每个已登记术语执行四项核对：

1. 声明篇目确实存在于本章。
2. 首现篇与声明一致；无标签条目按裸术语定位，带标签条目按该条全称定位。
3. 全称在全章正文中恰好出现一次。
4. 全称位于声明的首现篇目。

ASCII 图、表格和代码示例中的最简术语都计入出现顺序，因为图表首现仍属于首现。全称按单元格中的字面文本匹配；若一个全称只是另一个更长全称的子串，例如 `Virtual Address` 落在 `Unified Virtual Address Space` 内，两者按各自的完整字符串分别计数，不把嵌套出现当成重复。ASCII 术语使用标识符边界，`Inf` 不会误配 `Infinity`，`CF` 不会误配 `SCF`。

该入口**不自动发现未登记术语，也不判断某个缩写是否值得登记**。它只验证“章 README 的声明”与“正文实际位置”是否一致，从而避免把指令名、单位和十六进制文本猜成术语。新增术语时先登记，再运行检查。

## 输出与退出码

诊断格式为 `文件:行号: 错误码 说明`。两个入口统一使用：

| 退出码 | 含义 |
| --- | --- |
| 0 | 所有实际执行的检查通过；普通编号检查可能包含显式 `SKIP` |
| 1 | 发现规则问题，或收章编号检查没有可校验的编号节 |
| 2 | 路径、读取或命令输入错误，未完成检查 |

## 测试

```bash
python -m unittest discover -s tools/markdown_checks/tests -t . -v
```

`test_check_numbering.py` 只测编号入口，`test_check_terms.py` 只测术语入口。共享解析行为通过对应入口的测试覆盖，不另造一套业务规则。
