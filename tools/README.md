# 仓库小工具

本目录按领域组织小工具。不要在本目录根部堆放零散脚本。

| 目录 | 用途 | 可执行入口 |
| --- | --- | --- |
| `markdown_checks/` | Markdown 写作契约的只读检查 | `check_numbering.py`、`check_terms.py` |

## 目录契约

每个工具目录采用同一套结构：

```text
<领域>_<用途>/
├── README.md                 # 输入、输出、退出码、能力边界
├── check_<对象>.py            # 一个文件只负责一个可执行检查
├── _shared/                  # 私有共享解析代码，不是独立工具
│   └── <共享主题>.py
└── tests/
    ├── test_check_<对象>.py   # 与入口同名对应
    └── test_<另一个入口>.py
```

`__init__.py` 只提供包标记，不写业务逻辑。检查规则留在对应 `check_*.py`，只有确实被多个入口复用的解析代码才进入 `_shared/`。这样按文件名即可判断职责，按测试文件名即可找到验证位置。

## 新增工具的顺序

1. 先选择或新建领域目录，并在其 README 写清工具不处理什么。
2. 新增单一职责入口。`check_` 前缀只用于只读检查；会改文件的工具不得使用该前缀。
3. 添加同名测试，再在本页索引登记入口。
4. 从仓库根目录用 `python -m` 运行。默认只用 Python 标准库；新增依赖必须先写明原因和版本边界。
