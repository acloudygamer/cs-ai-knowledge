# 分支限界

## 定义

分支限界（Branch and Bound）是对解空间树进行系统搜索的算法范式，通过**限界函数**（bound function）估计每个分支的最优解上界或下界，剪去无法产生更优解的分支，从而在指数级解空间中高效搜索最优解。与回溯的深度优先不同，分支限界通常采用最佳优先（best-first），用优先队列按估计值扩展最有希望的节点。

## 数学模型

### A\* 算法的估计函数

A\* 是分支限界的特例，其限界函数为：
$$f(n) = g(n) + h(n)$$

- $g(n)$：从起始节点到节点 $n$ 的实际代价（已知的累积成本）
- $h(n)$：从节点 $n$ 到目标节点的启发估计（需人为设计）
- $f(n)$：经过节点 $n$ 的最优路径总代价的上界估计

### 可采纳性（Admissibility）

若对所有节点 $n$，$h(n) \leq h^*(n)$（$h^*$ 为真实最小代价），则称 $h$ 是可采纳的。可采纳性保证 A\* 不会错过最优解。

### 一致性（Consistency / 单调性）

若对所有边 $(u, v)$ 有 $h(u) \leq c(u, v) + h(v)$（其中 $c(u,v)$ 为边代价），则称 $h$ 一致。一致性保证启发式估计在每条边上都是"不下坡"的，从而避免重复扩展已有更优路径的节点。

### 最优性证明

设 $S^*$ 为最优解路径（代价 $C^*$），$S$ 为 A\* 输出的解路径。设 $n$ 为 $S^*$ 上第一个被 A\* 跳过的节点（$f(n) > C^*$）。由于 $h(n) \leq h^*(n)$，有 $f(n) = g(n) + h(n) \leq g(n) + h^*(n) = C^*$。矛盾，因为优先队列中代价严格小于 $C^*$ 的节点应先于 $n$ 弹出。故不存在这样的 $n$，A\* 返回最优解。

**归约终点**：分支限界是**在指数级解空间树中的最优路径搜索问题**。限界函数提供剪枝依据，可采纳启发函数保证最优性。问题可归约为"在约束条件下最小化/最大化目标函数"的优化问题。

### 八数码问题（8-Puzzle）的 A\* 搜索树

  open = [(4, 0, 初始状态, None)]  # f=0+4=4

  邻居 A (h=3, g=1, f=4) → open

  邻居 C (h=4, g=1, f=5) → open
  邻居 D (h=3, g=1, f=4) → open
  open 按 f 排序: [(4,A), (4,D), (5,C), (6,B), ...]

Step 3: 弹出 f=4 的 A（按插入顺序或 FIFO tie-break）
  ... 继续扩展 ...

closed 集合记录已扩展节点（避免重复扩展）

数据形态变换:
  状态元组 (tuple) → 计算 f 值 → 入优先队列 → 弹出扩展 → 生成新状态元组 → ...

### 分支限界中的限界与剪枝（以 0/1 背包为例）

<pre>
问题: 容量=10，物品=[(价值:60,重量:5), (价值:100,重量:10), (价值:120,重量:20)]
       贪心上界: 取物品1 (价值60) + 容量剩余5取物品0的一部分 (60+30=90)

解空间树 (每个节点表示对物品的选择状态):
        [root: 未选任何物品, 价值=0, 重量=0]
              │
       ┌──────┴──────┐
  [选物品0]      [不选物品0]
  v=0,w=0         v=0,w=0
      │                │
  ┌───┴───┐       ┌───┴───┐
[选物品1][不选1] [选物品1][不选1]
v=60,w=5  ...     v=100,w=10 ...

剪枝规则:
  若当前重量 > 容量 → 该分支不可行，剪掉
  若当前价值 + 剩余物品价值上界 ≤ 已知最优解 → 剪掉（无法超越）
  上界用分数背包计算: 价值 + Σ(剩余物品价值/重量 * 剩余容量)

例如: 在节点(选物品0,重量=5,价值=60)处
  剩余容量=5，剩余物品=[(100,10),(120,20)]
  上界 = 60 + min(5,10)*100/10 = 60 + 50 = 110 > 当前最优(0)，继续
</pre>

## 机制

### 分支限界的核心思想

解空间树中，大多数分支不可能产生比当前已知最优解更好的解。限界函数提供该分支最优解的上界估计（对最大化问题）或下界估计（对最小化问题）。若上界 ≤ 当前最优可行解，则剪去该分支。

### 分支策略 vs. 限界策略

- **分支**：如何将一个问题分解为子问题（分叉方式）。常用策略有按变量分支（如 0/1 背包的选/不选）、按约束分支。
- **限界**：如何估计子问题最优解的界。界越紧，剪枝越多；但计算界本身有成本。

### A\* 何时退化为穷举搜索

若 $h(n) = 0$ 对所有 $n$，则 $f(n) = g(n)$，A\* 退化为 Dijkstra 算法（对无权图退化为 BFS），仍保证最优性，但无启发引导。

若 $h(n) > h^*(n)$（不可采纳），则 $f(n)$ 可能低估真实代价，导致 A\* 跳过最优解——返回的解可能次优。

### A\* 的内存问题

A\* 需存储所有扩展过的节点（closed 集）和所有已知但未扩展的节点（open 集）。在最坏情况下，节点数指数增长。对于大规模问题，可采用**迭代加深 A\***（IDA\*）或**递归最佳优先搜索**（RBFS）来节省内存。

### 分支限界的上界/下界函数设计

| 问题 | 下界估计 | 上界估计 |
|------|----------|----------|
| TSP（最小化） | 最便宜插入 | 贪心路径构造 |
| 0/1 背包（最大化） | 已选物品价值 | 已选 + 分数背包（取剩余物品的价值密度上界） |
| 作业调度 | 已排程作业成本 | 贪心调度剩余作业 |

### 违反约束的后果

- 上界估计过大（过宽松）：剪枝效率低，搜索节点数接近指数级。
- 上界估计过小（过激进）：可能剪掉实际最优解的分支（仅当估计不可采纳时会发生）。对可采纳的 $h$，上界永远不会低估真实最优代价。
- 计算界函数成本过高：可能抵消剪枝带来的搜索量减少。

import heapq

def astar(start, goal, h, neighbors):
    """
    A* 算法通用实现
    start: 起始状态
    goal: 目标检测函数 (state -> bool)
    h: 启发函数 (state -> float), 须可采纳
    neighbors: (state -> list[(next_state, cost)])
    """
    open_set = [(h(start), 0, start)]
    g_score = {start: 0}
    came_from = {start: None}
    while open_set:
        _, g, cur = heapq.heappop(open_set)
        if goal(cur):
            # 重建路径
            path = []
            while cur is not None:
                path.append(cur)
                cur = came_from[cur]
            return path[::-1]
        for nxt, cost in neighbors(cur):
            tentative_g = g + cost
            if tentative_g < g_score.get(nxt, float('inf')):
                came_from[nxt] = cur
                g_score[nxt] = tentative_g
                f = tentative_g + h(nxt)
                heapq.heappush(open_set, (f, tentative_g, nxt))
    return None  # 无解
