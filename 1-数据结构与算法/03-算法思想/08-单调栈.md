# 单调栈

## 定义

> **版本基准**: universal

单调栈是维护序列单调性的栈结构，每个元素最多入栈一次、出栈一次，在 $O(n)$ 时间内解决"下一个更大/更小元素"问题。其本质是利用栈的 LIFO（后进先出）特性，在一次遍历中完成所有元素的答案计算。 时间内解决"下一个更大/更小元素"问题。其本质是利用栈的 LIFO（后进先出）特性，在一次遍历中完成所有元素的答案计算。

## 数学模型

### 时间复杂度分析

令 $n$ 为序列长度。每个元素最多执行一次 push 和一次 pop，总操作数为 $2n$ ，故时间复杂度为 $O(n)$ 。 为序列长度。每个元素最多执行一次 push 和一次 pop，总操作数为 $2n$ ，故时间复杂度为 $O(n)$ 。 ，故时间复杂度为 $O(n)$ 。 。

均摊分析：
 $\sum \text{push} = n, \quad \sum \text{pop} \leq n$ 
 $\text{总操作} = O(n)$ 

### 空间复杂度

最坏情况：序列单调（递增或递减），所有元素压在栈中，空间为 $O(n)$ 。 。

最优情况：每次 push 后立即 pop，空间为 $O(1)$ 。 。

### 单调性的形式化定义

对于递增栈 $S = [s_0, s_1, ..., s_k]$ （ $s_0$ 为栈底， $s_k$ 为栈顶）： （ $s_0$ 为栈底， $s_k$ 为栈顶）： 为栈底， $s_k$ 为栈顶）： 为栈顶）：
 $s_0 < s_1 < ... < s_k \quad \text{或} \quad s_0 > s_1 > ... > s_k \text{（递减栈）}$ 

栈内保存的是**下标**，但隐含了值的单调性约束。

### 状态机形式化

单调栈可建模为确定有限状态自动机（DFA）：

- **状态集**： $\{ \text{栈内容} \}$ ，每个状态是当前栈中的下标序列 ，每个状态是当前栈中的下标序列
- **输入字母表**：序列中的每个元素值 $x$ 
- **转移函数**：
  - 若栈空或 $a[\text{top}] > x$ （递增栈），push 当前下标 （递增栈），push 当前下标
  - 若 $a[\text{top}] < x$ ，弹出栈顶并记录答案，重复直到条件不满足 ，弹出栈顶并记录答案，重复直到条件不满足

**归约终点**：单调栈是**状态机的一种特例**。栈的状态表示"当前未找到答案的元素序列"，新元素的到来触发状态转移（pop/push），弹出瞬间即为该元素找到答案。

### 下一个更大元素（NGE）的执行流

<pre>
问题：求下一个更大元素 (Next Greater Element)
nums = [2, 1, 2, 4, 3]

遍历过程:
i=0, val=2:  stack=[]         → push(0),    stack=[0]
i=1, val=1:  nums[0]=2 > 1    → 不pop      → push(1),   stack=[0,1]
i=2, val=2:  nums[1]=1 < 2    → pop(1),    next[1]=2  → stack=[0]
              nums[0]=2 == 2   → 不pop      → push(2),   stack=[0,2]
i=3, val=4:  nums[2]=2 < 4    → pop(2),    next[2]=4  → stack=[0]
              nums[0]=2 < 4    → pop(0),    next[0]=4  → stack=[]
              push(3),                     stack=[3]
i=4, val=3:  nums[3]=4 > 3    → 不pop      → push(4),   stack=[3,4]

栈剩余元素（无更大右侧元素）:
next[3]=-1, next[4]=-1

输出: next = [4, 2, 4, -1, -1]

数据形态变换:
nums[i] (输入值) → 与栈顶元素比较 (比较) → pop触发时记录答案 (更新) → push下标 (入栈)

所有权转移:
nums 数组只读
栈中存储的是下标（引用），非元素拷贝
答案数组 next 在 pop 瞬间被写入（所有权从"未确定"变为"已确定"）
</pre>

nums = [2,1,2,4,3], 求每个元素的下一个更大元素（含循环）

第一遍：同普通遍历

### 遮挡效应（Masking Effect）的几何解释

当 $x$ 入栈后，所有比 $x$ 小的栈内元素被 $x$ "遮挡"——它们不会再成为任何后续元素的"下一个更大"，因为 $x$ 更近且更大。 入栈后，所有比 $x$ 小的栈内元素被 $x$ "遮挡"——它们不会再成为任何后续元素的"下一个更大"，因为 $x$ 更近且更大。 小的栈内元素被 $x$ "遮挡"——它们不会再成为任何后续元素的"下一个更大"，因为 $x$ 更近且更大。 "遮挡"——它们不会再成为任何后续元素的"下一个更大"，因为 $x$ 更近且更大。 更近且更大。

**几何视角**：将数组元素想象为高度，递增栈维护一个"可见山峰"序列。任何比当前山峰矮的山峰，从当前观察点永远不可见（被遮挡）。

```
        x=4
       /  \
      /    \
  2 /      \ 3
   /   4    \
  1----------2  （下标）
```

这意味着：
1. 每个元素最多 pop 一次（不可能被 pop 两次，因为 pop 后立即获得答案）
2. pop 发生时，当前遍历的元素就是被 pop 元素的答案

### 栈内存储下标的必要性

栈内存储值会导致"相等元素"的答案计算出现歧义。若存储下标：
- 可以区分元素的先后位置
- 可以计算"距离"（答案与原元素的索引差）
- 可以处理相等元素（严格单调 vs 非严格单调）

存储下标的另一个原因：答案数组需要用索引赋值，而非值。

### 循环数组的处理机制

3. 第二遍遍历只弹栈不 push（避免重复入栈）

**关键约束**：循环数组中，每个元素只能作为"下一个更大"被查找一次，不能在第二遍被重复处理。

**违反约束的后果**：若第二遍仍 push，会导致元素被重复处理，答案覆盖错误。

def next_greater(nums):
    n = len(nums)
    res = [-1] * n
    stack = []
    for i in range(n):
        while stack and nums[stack[-1]] < nums[i]:
            res[stack.pop()] = nums[i]
        stack.append(i)
    return res

def next_greater_circular(nums):
    n = len(nums)
    res = [-1] * n
    stack = []
    for i in range(2 * n):
        idx = i % n
        while stack and nums[stack[-1]] < nums[idx]:
            if stack[-1] < n:
                res[stack.pop()] = nums[idx]
            else:
                stack.pop()
        if i < n:
            stack.append(i)
    return res

def largest_rectangle_in_histogram(heights):
    heights = [0] + heights + [0]
    stack = [0]
    max_area = 0
    for i in range(1, len(heights)):
        while stack and heights[stack[-1]] > heights[i]:
            h = heights[stack.pop()]
            w = i - stack[-1] - 1
            max_area = max(max_area, h * w)
        stack.append(i)
    return max_area
