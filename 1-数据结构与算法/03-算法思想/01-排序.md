# 排序

## 定义

> **版本基准**: universal

排序是将有限元素集合按确定的全序关系调整为有序序列的过程。全序关系要求满足**自反性**（ $a \leq a$ ）、**反对称性**（若 $a \leq b$ 且 $b \leq a$ 则  $a = b$）和**传递性**（若 $a \leq b$ 且 $b \leq c$ 则  $a \leq c$）。排序算法的输入是 $n$ 个可比较大小的元素，输出是这 $n$ 个元素按非递减顺序排列的序列。

排序的本质是**信息论意义上的状态压缩**： $n$ 个元素的任意排列共有 $n!$ 种可能，排序算法通过比较操作逐步排除不可能的排列，最终将 $n!$ 种状态压缩为唯一的有序状态。比较操作是排序算法获取信息的主要手段。

## 数学模型

### 比较排序的信息论下界

比较排序模型将排序过程抽象为**决策树**。每个内部节点对应一次比较操作，两个分支对应比较的两种结果（ $\leq$ 或 $>$ ）。决策树的每个叶节点对应一种最终的排列顺序。

设排序算法在长度为 $n$ 的输入上的比较次数为 $h$ （决策树高度）。由于 $n$ 个元素有 $n!$ 种可能的排列，而高度为 $h$ 的二叉树至多有 $2^h$ 个叶节点：

$2^h \geq n! \Rightarrow h \geq \log_2(n!)$

由 Stirling 近似： $\log_2(n!) = \Theta(n \log n)$ 。因此：

$T_{\text{compare}}(n) = \Omega(n \log n)$

这是比较排序的**信息论下界**——任何基于比较的排序算法在最坏情况下都需要 $\Omega(n \log n)$ 次比较。

### 复杂度分类

| 算法 | $T_{\text{avg}}$ | $T_{\text{worst}}$ | 空间 | 稳定 |
|------|-----------------|-------------------|------|------|
| 归并排序 | $n \log n$ | $n \log n$ | $n$ | 是 |
| 快速排序 | $n \log n$ | $n^2$ | $\log n$ （递归栈） | 否 |
| 堆排序 | $n \log n$ | $n \log n$ | $1$ | 否 |
| 计数排序 | $n + k$ | $n + k$ | $k$ | 是 |
| 桶排序 | $n + k$ | $n^2$ （最坏情况） | $n + k$ | 是 |
| 基数排序 | $O(d(n + k))$ | $O(d(n + k))$ | $O(n + k)$ | 是 |

其中 $k$ 是值域范围， $d$ 是位数。

### 快速排序的期望比较次数

设元素两两独立等概率比较。快速排序在划分时，选择的 pivot 将数组分为左右两部分。设 $X$ 为比较次数， $I_i$ 为第 $i$ 小的元素在划分中作为 pivot 的指示变量：

$E[X] = 2(n-1) - \sum_{i=2}^{n-1} \frac{1}{i} = 2n \ln n - O(n)$

因此快速排序的平均比较次数为 $\Theta(n \log n)$ ，但最坏情况下（划分极度不均衡）退化为 $\Theta(n^2)$ 。

### 堆排序的复杂度证明

建堆： $T_{\text{build}}(n) = O(n)$ （见堆章节的分析）。

排序：执行 $n$ 次 pop 操作，每次 $O(\log n)$ ，总 $O(n \log n)$ 。

空间：原地排序，只需 $O(1)$ 的辅助空间用于交换，不计递归栈（若用递归实现快排）。

**归约终点**：排序问题可归约为**比较决策树的高度最小化问题**。信息论下界 $\Omega(n \log n)$ 源自 $n!$ 种排列状态需要被叶节点区分。堆排序通过保持堆性质实现 $O(n \log n)$ 最坏情况，其比较次数的常数因子大于快排，但在随机输入下仍保持 $n \log n$ 期望。

## 数据流

### 归并排序的分治过程

<pre>
输入: [3, 1, 4, 1, 5, 9, 2, 6]  (list[int])
         │
    ┌────┴────┐
  [3,1,4,1]   [5,9,2,6]        (半分问题)
    │           │
  ┌─┴─┐       ┌─┴─┐
 [3,1] [4,1] [5,9] [2,6]       (继续半分)
   │     │     │     │
  [3] [1] [4] [1] [5] [9] [2] [6]  (原子：单元素)
   │     │     │     │
  [1,3]   [1,4]   [5,9]   [2,6]   (治：小规模有序)
         │           │
    [1,1,3,4]      [2,5,6,9]       (治：归并)
         │
输出: [1,1,2,3,4,5,6,9]  (完全有序)
</pre>

**数据所有权变换**：分过程创建子数组的引用（无拷贝），治过程将两个有序数组合并到新数组。归并排序的核心操作是**将两个有序区间合并为一个更长有序区间**，这一操作在线性时间内完成。

### 快速排序的原地分区过程

<pre>
选择 pivot = 5 (首元素):
[3, 1, 4, 1, 5, 9, 2, 6]
 → 划分后:
[3, 1, 4, 1, 2]  pivot=5  [9, 6]
   (≤ pivot)       (≥ pivot)

对左半递归:
  选择 pivot = 3
  [1, 1, 2]  pivot=3  [4]
  → ...
</pre>

划分算法的关键在于**原地分区**：通过两个指针从两端向中间扫描，将元素按 pivot 分到左右两侧，空间复杂度 O(1)。

### 计数排序的桶映射

<pre>
输入: [2, 5, 3, 0, 2, 3]
k = 6 (值域 0~5)

统计计数:
  index:  0  1  2  3  4  5
  count:  1  0  2  2  0  1

累计前缀和（确定输出位置）:
  index:  0  1  2  3  4  5
  sum:    1  1  3  5  5  6

放置元素（从后往前保证稳定性）:
  2 → position 3 → output[2] = 2, sum[2] = 2
  3 → position 5 → output[4] = 3, sum[3] = 4
  0 → position 1 → output[0] = 0, sum[0] = 0
  3 → position 4 → output[3] = 3, sum[3] = 3
  5 → position 6 → output[5] = 5, sum[5] = 5
  2 → position 2 → output[1] = 2, sum[2] = 1

输出: [0, 2, 2, 3, 3, 5]
</pre>

计数排序的核心是**桶计数的累计和**：前缀和数组的第 $i$ 个值表示值 $i$ 的元素在输出数组中的结束位置（加1为长度）。

| 属性 | 归并排序 | 快速排序 | 堆排序 |
|------|----------|----------|---------|

## 机制

### 为什么比较排序需要 $\Omega(n \log n)$ 下界

从信息论角度： $n$ 个元素的 $n!$ 种排列中，只有一种是有序的。每次比较操作最多消除一半的可能性（将决策树的叶节点数翻倍）。要精确消除到只剩一种排列，需要至少 $\log_2(n!)$ 次比较。

从决策树模型角度：任何正确的比较排序算法必须能够区分所有 $n!$ 种可能的输入排列，因此其决策树必须有至少 $n!$ 个叶节点，而叶节点数 $2^h$ 约束了树高 $h$ 。

### 稳定排序的语义约束

稳定排序要求**相等元素的相对顺序在排序后保持不变**。这一性质在以下场景中至关重要：

1. **多级排序**：先按主键排序，再按次键排序时，稳定排序保证主键相等时的次键顺序不会被打乱。
2. **记录排序**：当元素是包含多个字段的记录时，仅按某一字段排序，稳定排序保证其他字段的相对顺序不被破坏。
3. **非比较排序的前置要求**：基数排序等算法依赖计数排序的稳定性来实现按位排序后的全局有序。

归并排序通过**先递归后合并**的顺序天然稳定（合并时相等元素先取左半部分）。快速排序在原地划分时，若不额外处理会破坏稳定性（元素可能跨过相等 pivot 移动到另一侧）。

### 快速排序最坏情况的触发条件与对策

最坏情况发生在每次划分极度不均衡时（逆序输入且总是选首元素为 pivot）。

**对策**：
- **随机化 pivot**：期望划分均匀，概率避免最坏情况
- **三数取中**：取首、中、尾三个元素的中位数作为 pivot
- **混合排序**：小区间（如 $n \leq 10$ ）使用插入排序，利用其小规模时的高常数因子优势

### 非比较排序的约束边界

**计数排序**：要求值域 $k = O(n)$ ，即元素取值范围不能远大于元素数量，否则计数数组过大。当 $k \gg n$ 时，复杂度退化为 $O(n + k)$ 而非线性。

**桶排序**：要求数据大致均匀分布，以便元素均匀分配到 $k$ 个桶中。最坏情况下（所有元素落入同一个桶）退化为 $O(n^2)$ 。

**基数排序**：要求可以用计数排序按"位"处理。位数 $d$ 必须足够小，使得 $d(n + k) < n \log n$ 成立时才有优势。通常用于整数或字符串排序。

### 排序算法的工程选择

- **数据量小**（ $n \leq 50$ ）：插入排序，其低开销和 Cache 友好性占优
- **数据量中**（ $n \leq 10^4$ ）：快速排序（随机化版本），平均性能优秀
- **数据量大且要求稳定**：归并排序，或外部排序（分块读写）
- **整数键值且 $k = O(n)$**：计数排序或基数排序
- **最坏情况要求 $O(n \log n)$**：堆排序，不存在最坏退化问题

### 违反约束的后果

- **比较排序声称优于 $O(n \log n)$**：违反信息论下界，不可能实现。
- **不稳定的堆排序用于依赖稳定性的场景**：会导致下游计算出现微妙错误（如多级排序失效）。
- **快速排序用于递归深度可能很大的场景**：最坏情况下递归深度达到 $n$ ，可能导致栈溢出。
- **对 $k \gg n$ 的数据使用计数排序**：空间开销过大（ $O(k)$ ），实际性能可能远差于 $O(n \log n)$ 的比较排序。

### 排序算法的Cache效应

现代CPU的Cache层级对排序算法性能有显著影响：

- **空间局部性**：归并排序顺序访问数组，Cache命中率较高；堆排序按父子节点跳转（步长不固定），Cache效率低。
- **Cache行利用率**：归并排序合并时读写连续内存块，充分利用预取机制；堆排序的pop操作每次交换首尾元素（跨距大），预取效果差。
- **TLB命中率**：顺序访问模式的归并排序TLB miss率低；堆排序的随机访问模式TLB压力大。

**量化分析**：设Cache行大小为 $B$ 字节，矩阵乘法中每个Cache行可容纳 $B/sizeof(element)$ 个元素。归并排序每个Cache行可连续读入约 $B/8$ 个64位整数，而堆排序每次sift-down操作可能跨越多个Cache行。

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(a, b):
    c = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            c.append(a[i])
            i += 1
        else:
            c.append(b[j])
            j += 1
    c.extend(a[i:])
    c.extend(b[j:])
    return c
```

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    mid = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + mid + quick_sort(right)
```

```python
def counting_sort(arr, max_val):
    count = [0] * (max_val + 1)
    for x in arr:
        count[x] += 1
    result = []
    for i, c in enumerate(count):
        result.extend([i] * c)
    return result
```
