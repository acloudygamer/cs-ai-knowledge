# 双指针

## 定义

> **版本基准**: universal

双指针是一种在数组、链表或字符串上通过两个指针协同遍历来降低算法复杂度的技巧。核心思想是利用数据的有序性或对称结构，使每步操作都能排除一批候选元素，将朴素的 $O(n^2)$ 或 $O(n^3)$ 暴力枚举降至 $O(n)$ 或 $O(n \log n)$ 。双指针不增加额外空间（ $O(1)$ 空间），但要求对数据结构有一定约束（有序、对称、可分治等）。

## 数学模型

### 碰撞指针（Collision / Mounting Pointers）

在有序数组中查找两数之和为目标值。设左指针 $l$ ，右指针 $r$ ：
$S_{l,r} = a[l] + a[r]$

单调性保证：
- 若 $S_{l,r} < target$ ，则所有 $l' \leq l$ 的组合均 $< target$ （ $a[l'] \leq a[l]$ ），因此只能增大 $l$。
- 若 $S_{l,r} > target$ ，则所有 $r' \geq r$ 的组合均 $> target$ （ $a[r'] \geq a[r]$ ），因此只能减小 $r$。

每步至少移动一个指针，故总步数 $\leq 2n = O(n)$ 。

**正确性证明**：设目标数对 $(l^*, r^*)$ 存在。对于任意中间状态 $(l, r)$ ：
- 若 $l \leq l^*$ 且 $r \geq r^*$ ，则 $a[l] \leq a[l^*]$ ， $a[r] \geq a[r^*]$ ，故 $S_{l,r} \geq a[l^*] + a[r^*] = target$，必执行 $r$--。
- 若 $l \geq l^*$ 且 $r \leq r^*$ ，则 $a[l] \geq a[l^*]$ ， $a[r] \leq a[r^*]$ ，故 $S_{l,r} \leq target$，必执行 $l$++。
- 最终收敛到 $(l^*, r^*)$ 。

### 快慢指针（Floyd's Cycle Detection）

检测链表环。设慢指针每次走 1 步，快指针每次走 2 步。

设 $\mu$ 为环前长度（从头节点到环入口的节点数）， $\lambda$ 为环长。快指针与慢指针第一次相遇时：

- 慢指针走了 $t$ 步： $t = \mu + a$ （$a$ 为相遇时在环内的步数）
- 快指针走了 $2t$ 步： $2t = \mu + b\lambda + a$ （$b$ 为快指针绕环的整圈数）

消去得： $t = b\lambda$ ，即 $t$ 是环长的整数倍。代入得 $\mu + a = b\lambda$，即相遇点距离环入口 $a = (b-1)\lambda + (\lambda - \mu)$。

数学保证：若链表有环，快慢指针必在 $O(\mu + \lambda)$ 步内相遇；若链表无环，快指针先到 $\text{NULL}$ 。

**环入口检测定理**：第一次相遇后，将慢指针重置到头节点，快指针留在相遇点，两者均每次走 1 步，再次相遇处即为环入口。

**证明**：设相遇时慢指针走了 $t = \mu + a$ 步，快指针走了 $2t$ 步。 $2t = t + b\lambda \Rightarrow t = b\lambda$ 。从相遇点走到环入口需 $\lambda - a$ 步，从头节点走到环入口需 $\mu$ 步。由 $t = b\lambda$ 得 $\mu + a = b\lambda \Rightarrow \mu = b\lambda - a = (b-1)\lambda + (\lambda - a)$。故两者同步走会在环入口相遇。

### 三路指针（Dutch National Flag）

将数组分为三个区域： $[0..\text{zero}) = 0$ ，$[\text{zero}..i) = 1$，$[i..\text{two}) = \text{待处理}$，$[\text{two}..n) = 2$。

**不变量定理**：在每次交换后，以上四个区域的不变性被保持。当 $i == \text{two}$ 时，分区完成。

**时间复杂度证明**：
- $i$ 每次前进 1 或被 two 交换后不变，每次最多前进 $n$ 步
- $two$ 每次后退 1，每次最多后退 $n$ 步
- 总操作 $O(n)$

**归约终点**：双指针技巧可归约为**在有序集或循环结构上的搜索问题**。碰撞指针利用单调性进行候选排除；快慢指针利用速度差检测环路结构。

## 数据流

### 碰撞指针：两数之和 II（有序数组）

<pre>
输入: numbers=[1,2,4,6], target=10

初始: l=0, r=3
sum = a[0]+a[3] = 1+6 = 7 < 10
→ l++ (因为 sum < target，所有 l' ≤ 0 的组合都不够大)

Step 1: l=1, r=3
  sum = a[1]+a[3] = 2+6 = 8 < 10 → l++

Step 2: l=2, r=3
  sum = a[2]+a[3] = 4+6 = 10 == target → return [l+1, r+1] = [3,4]

数据形态变换:
numbers (只读) + 指针对(l,r) → sum 比较 → 指针移动(l++ 或 r--) → 新指针对 → ...

所有权: numbers 数组内容不变（只读），指针仅为索引引用
</pre>

### 快慢指针：链表环检测

<pre>
链表: 1 → 2 → 3 → 4 → 5 → 3 (环入口在节点3)

初始: slow=1, fast=1 (都在头节点)
Step 1: slow=2, fast=3 (slow走1步, fast走2步)
Step 2: slow=3, fast=5 (slow=3, fast走2步: 3→4→5)
Step 3: slow=4, fast=3 (fast走2步: 5→3相遇！)
  相遇节点=3，在环内

检测到环后找环入口:
  slow 重置到头节点，fast 留在相遇节点
  两者均每次走1步，再次相遇处即为环入口

找环入口的数学依据:
  设环前长度=μ, 环长=λ
  第一次相遇时 slow 走了 μ+a 步, fast 走了 μ+bλ+a 步
  2(μ+a) = μ+bλ+a → μ+a = bλ
  即: 从相遇点走 μ 步 = 从头节点走 μ 步 (同余 λ)
  所以再次同步走会在环入口相遇
</pre>

### 三路指针：荷兰国旗问题（颜色分类）

<pre>
输入: nums = [2,0,2,1,1,0]  → 输出: 全0在前，全1居中，全2在后

维护三个指针:
  zero: 已处理区域 [0..zero) 全为 0 (初始 0, 表示空区域)
  i:   正在处理的位置 (初始 0)
  two: 已处理区域 [two..n) 全为 2 (初始 n, 表示空区域)

invariant: [0..zero) = 0, [zero..i) = 1, [two..n) = 2, [i..two) 未处理

Step i=0, nums[0]=2:
  交换 nums[i] 和 nums[two-1] → nums[5]=0, two=5
  i 不变 (因为从 two 换过来的元素还未处理)
  nums = [2,0,2,1,1,0] → [0,0,2,1,1,2]

Step i=1, nums[1]=0:
  交换 nums[i] 和 nums[zero] → zero=1
  i++ → i=2
  nums = [0,0,2,1,1,2]

Step i=2, nums[2]=2:
  交换 nums[i] 和 nums[two-1] → nums[4]=1, two=4
  i 不变
  nums = [0,0,1,1,2,2]

Step i=3, nums[3]=1:
  i++ → i=4 (1 已在正确区域)

i=4, i==two → 结束
结果: [0,0,1,1,2,2]

时间复杂度: O(n), 每次 i 或 two 至少前进1步，最多前进 n 步
</pre>

## 机制

### 碰撞指针的单调性保证

**关键前提**：数组必须**严格升序**（或严格降序）。若数组无序，必须先排序（ $O(n \log n)$ ），但排序会破坏原数组的原始顺序。若数组有重复元素而我们关心的是索引而非值，排序可能丢失信息。

单调性来自： $a[l'] \leq a[l] < a[r] \leq a[r']$ 对所有 $l' < l < r < r'$。两数之和随 $l$ 增大而增大，随 $r$ 减小而减小。这使得每步排除都是安全的——被排除的元素绝不可能是解。

### 快慢指针相遇的数学必然性

快指针相对慢指针的速度为 1（每步追上 1 格）。在环中，慢指针进入环时，快指针已在环内。若快指针每次走 2 步，则每一步快指针相对慢指针多走 1 步。由于环长 $\lambda$ 有限，经过 $\lambda$ 步后快指针必定"追上"慢指针（此时快指针比慢指针多走完整一圈）。

无环时，快指针最终会到达 $\text{NULL}$ （对有终点的链表）。

**为何选步长 2**：步长必须满足 $\gcd(\Delta v, \lambda) = 1$ 才能保证相遇。步长 2 简单且常用。若选步长 3，则需 $\lambda$ 与 2 互素才能保证必定相遇。

### 三路指针的分区不变量

$[0..\text{zero}) = 0$ 、 $[\text{zero}..i) = 1$ 、$[i..\text{two}) = \text{待处理}$、$[\text{two}..n) = 2$。这个不变量在每次交换后保持。关键点：当 $i$ 和 $\text{two}$ 相遇时（$i == \text{two}$），所有未处理区域已为空，分区完成。

**交换的三种情况**：
| 情况 | nums[i] | 动作 | zero | i | two |
|------|---------|------|------|---|-----|
| 0 | 0 | 交换 i 和 zero，zero++，i++ | +1 | +1 | 不变 |
| 1 | 1 | i++ | 不变 | +1 | 不变 |
| 2 | 2 | 交换 i 和 two-1，two-- | 不变 | 不变 | -1 |

### 双指针的失败场景

| 场景 | 失败原因 | 后果 |
|------|---------|------|
| 碰撞指针用于无序数组 | 单调性不成立 | 排除逻辑错误，可能漏解或死循环 |
| 快慢指针步长不当 | 如快指针每次走 3 步且链长度为奇数 | 可能跳过 NULL 永远找不到相遇点 |
| 三路指针交换逻辑错误 | 交换后错误推进 i | 漏处理某些元素 |

### 快慢指针在无环链表上的行为

对于无环链表（有终点），快指针最终会到达 $\text{NULL}$ 。快指针每次走 2 步，在链表长度为奇数时直接到达 NULL，长度为偶数时到达最后一个节点的 next（即 NULL）。因此检测逻辑正确。

### 双指针与其他算法的归约

| 问题 | 归约 |
|------|------|
| 两数之和 | 在有序集上的单淘汰搜索 |
| 链表环检测 | 在循环结构上的速度差检测 |
| 荷兰国旗 | 三分区间的在线维护 |

### 碰撞指针的变体：链表两数之和

对于有序链表的两数之和（返回节点而非索引），指针操作替换为链表遍历：
1. 用快慢指针找到链表中点（拆分为两个链表）
2. 反转右半链表
3. 双指针从两端遍历，计算和并重建原链表

此变体的复杂度仍为 $O(n)$ ，但需要额外的 $O(1)$ 指针操作空间。

## 参考存根

```python
# 碰撞指针: 两数之和 II（返回 1-indexed 位置）
def two_sum_sorted(numbers, target):
    l, r = 0, len(numbers) - 1
    while l < r:
        s = numbers[l] + numbers[r]
        if s == target:
            return [l + 1, r + 1]
        if s < target:
            l += 1
        else:
            r -= 1
    return []

# 快慢指针: 检测链表环
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            return True
    return False

# 快慢指针: 找环入口
def detect_cycle_start(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            # 找到相遇点，第二次相遇处为环入口
            slow2 = head
            while slow != slow2:
                slow = slow.next
                slow2 = slow2.next
            return slow
    return None

# 三路指针: 荷兰国旗
def sort_colors(nums):
    zero = i = 0
    two = len(nums) - 1
    while i <= two:
        if nums[i] == 0:
            nums[zero], nums[i] = nums[i], nums[zero]
            zero += 1
            i += 1
        elif nums[i] == 2:
            nums[i], nums[two] = nums[two], nums[i]
            two -= 1
            # i 不变，因为从 two 换过来的元素还未处理
        else:
            i += 1
    return nums
```
