# 滑动窗口

## 定义

> **版本基准**: universal

滑动窗口是维护连续子数组/子串的可伸缩区间结构，通过双指针（left, right）将嵌套循环 $O(n^2)$ 优化为 $O(n)$ 单次遍历。右指针扩展窗口、左指针收缩窗口，保证窗口始终满足约束条件。

## 数学模型

### 固定窗口时间复杂度

设序列长度为 $n$ ，窗口大小为 $k$ 。右指针从 0 移动到 $n-1$ ，左指针在右指针到达 $k-1$ 后开始跟随：
$T(n) = O(n) + O(n-k) = O(n)$

每次指针移动 $O(1)$ ，总移动次数为 $O(n)$ 。

### 可变窗口时间复杂度

右指针单调不减（只向右扩展），左指针单调不减（只向右收缩）。每个指针最多移动 $n$ 步，总计 $2n = O(n)$ 次指针移动。

### 窗口状态转移

令 $W(l, r)$ 表示以 $l$ 为左边界、 $r$ 为右边界的窗口。每次扩展或收缩都是对 $W$ 的状态转移：
$W(l, r) \xrightarrow{\text{右移 right}} W(l, r+1) \quad \text{若约束仍满足}$
$W(l, r) \xrightarrow{\text{右移 left}} W(l+1, r) \quad \text{若约束不再满足}$

### 单调性保证 O(n)

指针的单调性是关键。每次 while 循环收缩 left 时，left 只会增加，不会回退。因此总指针移动次数有上界 $2n$ 。

若窗口扩张后可能回退（如暴力解中 right 回退），总操作数为 $O(n^2)$ 。

**约束的数学形式**：设约束条件为 $C(W(l, r))$ （布尔谓词）。收缩仅在 $C(W(l, r)) = \text{false}$ 时发生，此时 left 必增。由于 left 只增不减，总收缩次数 $\leq n$ 。

### 窗口的几何解释

滑动窗口可视为在序列坐标轴上的一个可移动区间：

```
坐标轴:  0   1   2   3   4   5   6   7
数组:    a   b   c   a   b   c   b   b
窗口:        [-----]
            left    right
窗口区间: [left, right]，长度为 right - left + 1
```

窗口的移动受约束条件 $C$ 约束：每当 $C$ 被破坏，左边界右移直到 $C$ 重新满足。

**归约终点**：滑动窗口是**带约束的在线问题求解算法**。本质是维护一个"最近合法区间"的区间收缩/扩张状态机，在线算法中无法预知未来（右指针只能右移），但可通过左指针收缩满足约束。

### 无重复字符最长子串的执行流

问题：无重复字符最长子串
s = "abcabcbb"

状态转移过程:
初始: left=0, right=0, window={}, max_len=0

  → left收缩: left=0→1, window={b,c,a}, len=3, max_len=3
right→4, ch='b': window={b,c,a,b} → 重复b
  → left收缩: left=1→2, window={c,a,b}, len=3, max_len=3
right→5, ch='c': window={c,a,b,c} → 重复c
  → left收缩: left=2→3, window={a,b,c}, len=3, max_len=3
right→6, ch='b': window={a,b,c,b} → 重复b
  → left收缩: left=3→4, window={c,a,b}, len=3, max_len=3
right→7, ch='b': window={c,a,b,b} → 重复b
  → left收缩: left=4→5, window={a,b}, len=2, max_len=3

最终: max_len=3

数据形态变换:
原始字符串 s → 窗口字符集 (dict/set) → 收缩后更新 → max_len 更新

   s[left] 从 window 移除

## 机制

### 为何 O(n)：指针单调性的约束保证

暴力解中 right 指针每次扩展后可能回退（当 left 右移时），导致 $O(n^2)$ 。

滑动窗口要求：left 只能右移（左边界只能扩大，不能缩小）。这通过约束条件的设计实现：只有当窗口不再满足约束时，才收缩 left。

因此每个元素最多被 right 访问一次（入窗口），最多被 left 访问一次（出窗口），总 $2n = O(n)$ 。

**形式化证明**：
- right 从 0 增至 $n-1$ ，共移动 $n$ 次
- left 从 0 最多增至 $n-1$ ，共移动 $\leq n$ 次
- 总移动 $\leq 2n = O(n)$

### 窗口合法性约束

收缩条件必须正确设计。若收缩过慢：
- 窗口包含非法元素（如重复字符）
- 结果不正确（漏掉合法解的最优窗口）

若收缩过快：
- 可能过早收缩，漏掉更优解
- 但通常收缩条件是确定性的，不会漏解

### 固定窗口 vs 可变窗口

| 类型 | 窗口大小 | 收缩触发 | 典型应用 |
|------|---------|---------|---------|
| 固定窗口 | $k$ 恒定 | right 达 $k$ 后每次扩展都收缩 | 子数组最大值、子数组平均值 |
| 可变窗口 | 动态变化 | 约束破坏时 | 最短子串、最长子串 |

### 单调队列优化最值查询

朴素滑动窗口中，求窗口最大值需要 $O(k)$ 扫描。使用单调队列可在 $O(1)$ 求窗口最值：

维护递减双端队列（队首为当前窗口最大值）：
1. 新元素入队：从队尾弹出所有小于新元素的元素（它们永不成最大值）
2. 队首元素若已离开窗口（左边界超过），弹出队首
3. 队首即为当前窗口最大值

**正确性证明**：
- 递减队列中，队首是最大元素（队列单调递减保证）
- 被弹出的元素右侧有更大元素（因为是从队尾弹出小于新元素的），故永不成最大值
- 队首若已离开窗口（左边界超过），弹出后新的队首即为当前窗口最大

**复杂度分析**：
- 每个元素最多入队一次、出队一次
- 总操作 $2n = O(n)$
- 每次查询最大值 $O(1)$

### 典型应用场景

| 应用 | 窗口类型 | 约束条件 | 答案计算 |
|------|---------|---------|---------|
| 无重复字符最长子串 | 可变 | 当前字符不在窗口中 | max_len |
| 最小覆盖子串 | 可变 | window 包含 t 中所有字符 | 更新最小窗口 |
| 子数组最大和（长度 ≥ k） | 固定 | 窗口大小 = k | max_sum |
| 字符串排列 | 固定 | window 字符计数 = t 字符计数 | 检查是否匹配 |
| 最大平均子数组 | 固定 | 窗口大小 = k | max_avg |

### 约束条件与违反后果

| 约束 | 违反后果 |
|------|---------|
| left 指针不可左移 | 若 left 回退，总复杂度退化为 $O(n^2)$ |
| 窗口约束必须可逆检测 | 如"无重复"可通过 hash set 检测收缩 |
| 单调队列中，入队元素值比较符号必须正确 | 若为 ≤ 而非 <，会导致相等元素处理错误 |

### 滑动窗口与队列论的关系

滑动窗口可视为**有限容量队列**的特殊情况：
- 队列容量 = 窗口最大长度
- 入队 = right 右移（加入新元素）
- 出队 = left 右移（移除旧元素）
- 约束条件 = 队列必须满足的性质

在队列论中，这对应于**马尔可夫过程**的瞬态分析，窗口最大值对应于队长分布的极值。

### 在线问题的本质约束

滑动窗口是**在线算法**——它不知道未来的输入（右指针只能右移，不能左退）。因此：
- 可变窗口的 left 收缩是**被动响应**而非主动优化
- 最优解可能需要"等待"才能发现（因为不知道未来）
- 若允许预读全部数据，可先预处理（如排序）再窗口滑动，但预读本身破坏了在线假设

```python
def length_of_longest_substring(s):
    char_idx = {}
    left = max_len = 0
    for right, ch in enumerate(s):
        if ch in char_idx and char_idx[ch] >= left:
            left = char_idx[ch] + 1
        char_idx[ch] = right
        max_len = max(max_len, right - left + 1)
    return max_len

def min_window_substring(s, t):
    from collections import Counter
    need = Counter(t)
    window = Counter()
    left = 0
    result = ""
    matched = 0
    for right, ch in enumerate(s):
        if ch in need:
            window[ch] += 1
            if window[ch] <= need[ch]:
                matched += 1
        while matched == len(t):
            if not result or right - left + 1 < len(result):
                result = s[left:right+1]
            if s[left] in need:
                window[s[left]] -= 1
                if window[s[left]] < need[s[left]]:
                    matched -= 1
            left += 1
    return result

def max_sliding_window(nums, k):
    from collections import deque
    dq = deque()
    result = []
    for i in range(len(nums)):
        while dq and nums[dq[-1]] <= nums[i]:
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()
        if i >= k - 1:
            result.append(nums[dq[0]])
    return result
```
