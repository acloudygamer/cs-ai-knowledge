# 贪心

## 定义

> **版本基准**: universal

贪心是一种求解优化问题的算法范式：在每一步选择当前局部最优（greedy choice），期望该选择序列构成全局最优解。贪心算法不回溯，不考虑当前选择对未来步骤的影响。贪心有效的充分条件是**贪心选择性质**（greedy-choice property）和**最优子结构**（optimal substructure）同时成立。

## 数学模型

### 贪心选择性质的形式化

设原问题的最优解为 $S^*$ ，贪心在第 $i$ 步做出选择 $g_i$ 。贪心选择性质要求：
$\exists \text{最优解 } S^* : g_1 \in S^* \text{ 且 } S^* \setminus \{g_1\} \text{ 是子问题的最优解}$

即：存在某个最优解，其第一步就是贪心选择。这意味着贪心选择不排除任何最优解——所有最优解都在贪心决策的"射程"内。

### 最优子结构的形式化

令 $S = \{g_1, g_2, \ldots, g_n\}$ 为贪心选择序列， $C(S)$ 为解的目标代价。则：
$C(S^*) = C(\{g_1\}) + C(S^* \setminus \{g_1\})$

且 $S^* \setminus \{g_1\}$ 必须是子问题的最优解（与原问题同类结构）。

### 交换论证（Exchange Argument）

设 $S_{OPT}$ 为任意最优解， $S_G$ 为贪心解。用贪心的第一步 $g_1$ 替换 $S_{OPT}$ 的第一步  $o_1$，不增大目标值：
$C(o_1) \geq C(g_1) \quad \text{(由贪心选择定义)}$

迭代替换，最终得到贪心解，且每步不差于原最优解，故 $C(S_G) = C(S_{OPT})$ 。

**归约终点**：贪心算法可归约为**在偏序集上寻找极大元**的问题。贪心选择性质保证存在一个最优解以贪心选择开头；最优子结构保证剩余子问题仍保持原问题结构。

## 数据流

### 区间调度问题（Maximum Cardinality Interval Scheduling）

<pre>
输入: intervals = [(1,4), (2,3), (3,5), (4,6)]

贪心策略: 选择结束时间最早的区间

Step 1: 按结束时间排序
  排序结果: [(2,3), (1,4), (3,5), (4,6)]
              ↑ 最早结束

Step 2: 贪心选择
  选择 (2,3), current_end = 3
  检查 (1,4): 1 < 3 (冲突) → 跳过
  检查 (3,5): 3 >= 3 (不冲突) → 选择, current_end = 5
  检查 (4,6): 4 >= 5 (不冲突) → 选择, current_end = 6

输出: 选择 [(2,3), (3,5), (4,6)] → 3 个区间（最优）

状态变换:
  S = ∅ → 选择 (2,3) → S = {(2,3)} → 选择 (3,5) → S = {(2,3),(3,5)} → 选择 (4,6) → S = {(2,3),(3,5),(4,6)}
  每个选择都使 end 更新为所选区间的结束时间
</pre>

### 哈夫曼编码（最优前缀码）

<pre>
输入字符频率: {a:45, b:13, c:12, d:16, e:9, f:5}

贪心策略: 小根堆不断合并频率最小的两棵树

初始堆: [5(f), 9(e), 12(c), 13(b), 16(d), 45(a)]
        均为单节点树 (叶节点)

Step 1: 弹出 f(5) 和 e(9)，合并 → 节点(14)，push 回堆
  堆: [12(c), 13(b), 14(node), 16(d), 45(a)]

Step 2: 弹出 c(12) 和 b(13)，合并 → 节点(25)，push 回堆
  堆: [14(node), 16(d), 25(node), 45(a)]

Step 3: 弹出 14(node) 和 16(d)，合并 → 节点(30)，push 回堆
  堆: [25(node), 30(node), 45(a)]

Step 4: 弹出 25(node) 和 30(node)，合并 → 节点(55)，push 回堆
  堆: [45(a), 55(node)]

Step 5: 弹出 45(a) 和 55(node)，合并 → 根节点(100)

每步合并的代价 = 两棵树频率之和，累加到总编码代价

状态: 树的根节点频率表示以该节点为根的子树所有叶节点频率之和
</pre>

### Kruskal 最小生成树（另一种贪心视角）

<pre>
边集合 E，按权值升序排列
贪心策略: 按权值从小到大选边，若形成环则跳过

每步状态: 已选边集合 S (森林)，检查新边 e = (u,v)
  若 u 和 v 在 S 的不同连通分量中 → 选择 e，合并两个分量
  否则 → 跳过（选 e 会形成环）

本质: 在所有生成树中，权值最小的边一定在某个最小生成树中
      (切分性质: 任何横跨两个顶点集的最小权边必在某个 MST 中)
</pre>

## 机制

### 贪心为何可能失败——无最优子结构

贪心失败的根本原因是问题不满足最优子结构。最优子结构要求：原问题的最优解包含子问题的最优解。典型的反例是**0/1 背包问题**（物品不可分）：若选择价值高的物品 A（局部最优），可能因重量限制无法放入更优组合 B+C（全局最优），而 A 的选择已经排除了 B 和 C 的组合空间。

**分数背包**（物品可分）却可以用贪心——因为选择 A 不会排除选择 B 和 C 的部分，只要总重量不超限即可。

### 贪心选择性质的验证方法

1. 假设存在某个最优解 $S_{OPT}$ 不包含贪心选择 $g_1$ 。
2. 设 $S_{OPT}$ 的第一步是 $o_1$ （不是 $g_1$ ）。
3. 证明 $C(g_1) \leq C(o_1)$ （由排序键定义可得）。
4. 构造新最优解 $S'_{OPT} = (S_{OPT} \setminus \{o_1\}) \cup \{g_1\}$ ，其代价不增。
5. 重复迭代，最终得到一个以 $g_1$ 开头且不差于原最优解的最优解。

若步骤 3 不成立（ $C(g_1) > C(o_1)$ ），则贪心选择性质不满足，贪心算法无法保证最优。

### 贪心 vs. 动态规划的本质区别

| 维度 | 贪心 | 动态规划 |
|------|------|----------|
| 选择策略 | 只看当前，不考虑子问题 | 考虑所有子问题的最优解再做选择 |
| 子问题关系 | 子问题的最优解必须包含在原问题最优解中 | 子问题可以重叠 |
| 时间复杂度 | 通常 $O(n \log n)$ 或 $O(n)$ | 通常 $O(n^2)$ 或更高 |
| 最优性保证 | 需证明贪心选择性质 + 最优子结构 | 表格化证明更强 |
| 典型问题 | 区间调度、哈夫曼编码、Kruskal | 最短路径、背包、编辑距离 |

### 贪心适用场景总结

- **区间调度**：按结束时间排序的选择，在所有最优解中可行。
- **哈夫曼编码**：每次合并频率最小的两棵树，切分性质保证最优。
- **Kruskal (MST)**：切分性质，所有横跨切分的最小权边构成某个 MST。
- **Dijkstra (单源最短路，正权图)**：每次选当前最近的未访问节点，性质类似 BFS + 优先队列。

### 违反约束的后果

若将分数背包的贪心策略（选价值/重量比最高的物品）用于 0/1 背包，不满足最优子结构，最优解可能不含价值比最高的物品——贪心返回的是近似解而非最优解。

### 切分性质（Cut Property）的形式化

在最小生成树问题中，切分性质表述为：

> 对任意非空集合 $S \subset V$ ，设 $e$ 是横跨切分 $(S, V \setminus S)$ 的最小权边，则必存在某个最小生成树包含 $e$ 。

**证明**：设 $T$ 是任意 MST。若 $T$ 已包含 $e$ ，证毕。否则将 $e$ 加入 $T$ 形成环，该环必存在另一条横跨同一切分的边 $e'$ 。由于 $e$ 是最小横跨边， $w(e) \leq w(e')$ 。用 $e$ 替换 $e'$ 得到的生成树 $T'$ 权值不超过  $T$，故 $T'$ 也是 MST 且包含  $e$。

### 哈夫曼编码的最优性证明

哈夫曼编码的最优性可由**交换论证**证明：设最优前缀码树为 $T$ ，频率最小的两字符 $a$ 和 $b$ 在 $T$ 中必是兄弟叶节点（否则可交换位置不增加加权路径长度）。将 $a$ 和 $b$ 合并为新节点 $c$ ，频率为 $f(c) = f(a) + f(b)$ ，得到规模减一的子问题。对子问题递归应用相同论证，最终得到哈夫曼树是最优的。

```python
# 区间调度（最多不重叠区间数）
def interval_scheduling(intervals):
    if not intervals:
        return 0
    intervals.sort(key=lambda x: x[1])  # 按结束时间排序
    count, end = 0, float('-inf')
    for s, e in intervals:
        if s >= end:
            count += 1
            end = e
    return count

# 哈夫曼编码
import heapq
from collections import Counter

def huffman(freq):
    heap = [[w, [ch, '']] for ch, w in freq.items()]
    heapq.heapify(heap)
    while len(heap) > 1:
        lo = heapq.heappop(heap)
        hi = heapq.heappop(heap)
        for pair in lo[1:]:
            pair[1] = '0' + pair[1]
        for pair in hi[1:]:
            pair[1] = '1' + pair[1]
        heapq.heappush(heap, [lo[0] + hi[0]] + lo[1:] + hi[1:])
    return dict(heap[0][1:])

# Kruskal (MST)
def kruskal(vertices, edges):
    edges.sort(key=lambda x: x[2])  # edges = (u, v, weight)
    parent = {v: v for v in vertices}
    def find(v):
        while parent[v] != v:
            parent[v] = parent[parent[v]]  # 路径压缩
            v = parent[v]
        return v
    mst = []
    for u, v, w in edges:
        if find(u) != find(v):
            parent[find(u)] = find(v)
            mst.append((u, v, w))
    return mst
```
