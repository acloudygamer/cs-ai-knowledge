# 回溯与分支限界

八皇后有 $8!=40320$ 种列排列，逐个检查能不能放得下；十六皇后有 $16!\approx2\times10^{13}$ 种，再多算力也不够。实际解法不枚举排列，它逐行放皇后，一旦某一行放不下就退回上一行换位置——大部分分支根本没有走下去。

回溯就是这种"试到底、退回来、换一个"的搜索框架；分支限界是它在"求最优"场景下的变体，靠一个界把没有希望的分支整棵剪掉。

## 一、解空间是一棵树

### 1. 每个节点是一个部分解

把构造解的过程画成一棵树：根是空解，每一层做一个决策，节点是做到这一步的部分解，叶子是完整解或死路。

全排列的解空间树：第一层选第一个元素，第二层选第二个……共 $n!$ 个叶子。N 皇后的解空间树同理：第 $i$ 层决定第 $i$ 行的皇后放在哪一列。

```text
全排列 [1,2,3] 的解空间：
              (空)
        /       |       \
       1        2        3
      / \      / \      / \
    12  13   21  23   31  32
    |   |    |   |    |   |
   123 132  213 231  312 321
```

### 2. 深度优先枚举加撤销

回溯沿这棵树深度优先走：选一个分支下去，走不通就退回，退回时把这一步做的修改撤销，再试下一个分支。

深度优先的空间是树高，不是节点数。这一点与 BFS 相反：BFS 要保存一整层的节点，回溯只保存当前路径。

## 二、撤销是回溯的必要动作

### 1. 选与撤销必须对称

回溯的每一步都成对：选入时修改状态，退回时恢复状态。写成代码是两行，必须严格对称。

```python
used[i] = True
path.append(nums[i])
backtrack(...)          # 递归下探
path.pop()              # 撤销：顺序与选入相反
used[i] = False
```

不对称的撤销不会报错，只会让后续分支看到被污染的状态，结果是漏解或重复解。

### 2. 共享状态要恢复干净

状态可能是多个容器：路径数组、使用标记、约束计数。撤销要把每一个都恢复，且恢复顺序不能影响中间结果。

N 皇后用三个集合记录已被占用的列、主对角线、副对角线。放置时加入三个集合，撤销时移除三个——漏掉任何一个，后续行的判断就会误判冲突。

## 三、剪枝必须是"无解"的充分条件

### 1. 可行性剪枝：已经违反约束，下面全是死路

若当前部分解已经违反约束，那么它的所有扩展都违反约束，整棵子树可以剪掉。这是最安全的一类剪枝，因为约束是局部可判定的。

N 皇后的剪枝就属于这一类：新放的皇后与已放的皇后同列或同对角线，可以立即剪掉。

```text
4 皇后的一步（行、列、主对角线 r-c、副对角线 r+c）：
  第 0 行放列 0 → 占用列 0、主对角线 0、副对角线 0
  第 1 行试列 0 → 同列，剪
  第 1 行试列 1 → 同主对角线，剪
  第 1 行试列 2 → 合法，下探
```

### 2. 剪枝条件不充分就会漏解

剪枝判据必须是"此子树必无解"的充分条件。判宽了（把可能有解的分支剪掉）会漏解，判窄了只是没剪到，不会错。

这也是回溯实现里最容易出错的地方：判据写成必要条件（"此子树可能有解"）就会误剪。检查方法是想清楚"这个条件成立时，能否构造出一个解"。

## 四、分支限界：用界剪掉没希望的分支

### 1. 限界函数给每个分支估一个上界

求最优解时，"违反约束"不足以剪枝——很多分支合法但不可能更优。分支限界给每个部分解算一个界：这个分支最好能到什么程度。

若这个界不优于当前已知的最优解，整棵子树可以剪掉。0/1 背包的常用界是"剩余容量按最高价值密度装满"——它一定不小于实际能达到的价值，所以是安全的上界。

### 2. 可采纳性：界不能低估

界的正确性只有一条要求：**不能低估**当前分支可能达到的最优值（求最大时），或**不能高估**剩余成本（求最小时）。

低估会让本可以更优的分支被剪掉，结果是错解而不是慢解。这条要求与 A* 的启发函数可采纳性完全一致——A* 就是分支限界在路径搜索上的特例， $f=g+h$ 里的 $h$ 是不高估剩余距离的启发值。

| 场景 | 界的方向 | 违反的后果 |
| --- | --- | --- |
| 求最大价值 | 上界不能低估 | 剪掉更优分支，得错解 |
| 求最短路径 | 下界不能高估 | 同上 |
| 只求可行解 | 只需可行性剪枝 | 不存在界的问题 |

### 3. 优先队列把最有希望的分支提前

分支限界通常配合优先队列：每次扩展界最优的节点，而不是像回溯那样按顺序深度优先。这样一旦找到解，它很可能就是最优解，剩下的分支可以大量剪掉。

代价是内存：优先队列要保存所有待扩展节点，最坏情况与节点总数同阶。回溯只保存当前路径。这是"用空间换剪枝效果"的又一次置换。

## 五、边界

### 1. 递归深度就是解的长度

回溯的深度等于解的规模：全排列深度 $n$，N 皇后深度 $n$，子集枚举深度 $n$。 $n=10^5$ 时递归直接爆栈，只能改写成显式栈。

显式栈把路径与选择状态搬进堆，空间从调用栈转到堆，深度不再受线程栈限制。代价是要自己管理"回到上一层时该撤销什么"，比递归更容易写错。

### 2. 子问题重叠时应该换 DP

回溯会重复访问相同的子问题。子集枚举里，不同的选择顺序可能到达同一个集合；若问题只关心"这个集合的最优值"，重复访问就是浪费。

一旦确认子问题重叠，就该换成动态规划：把"集合"或"前缀"作为状态，记忆化结果。回溯适合"解之间不共享子结构"或"需要枚举全部解"的场景。

判据是：如果只需要一个最优值、且不同路径会到达相同状态，用 DP；如果需要枚举所有解、或状态难以压缩，用回溯。

### 3. 剪枝效果决定可行性

回溯的理论复杂度是指数级，实际能不能跑取决于剪枝强度。八皇后剪枝后只探索约两千个节点，远小于 $8!=40320$ 个叶子；同样的框架不做剪枝，十六皇后就是 $2\times10^{13}$ 个分支。

剪枝强度又取决于约束的局部性：约束越能在早期判定，剪枝越早生效。这是回溯问题选型时最该先看的一点。
