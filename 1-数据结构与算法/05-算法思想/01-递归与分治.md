# 递归与分治

求 $x^{10^9}$，朴素做法要乘 $10^9$ 次；分治做法把指数按二进制拆开，约 45 次乘法——30 次平方，加上十几次按位相乘。规模没有被"算小"，而是被组织成了一棵树：树上的每个内部节点只做一次平方，叶子是基例。

递归把一次计算压成一棵调用树，分治规定这棵树怎么长。两者的收益与代价都写在这棵树上：调用次数决定时间，最大深度决定空间。

## 一、递归把一次计算压成一棵树

### 1. 栈帧记的是"还没做完的部分"

递归调用时，当前函数的局部变量、参数与返回地址被压进栈帧，控制权交给下一层。子问题返回后，栈帧弹出，上层接着做完剩下的工作。

```text
fact(4)
 ├─ 4 × fact(3)
 │    ├─ 3 × fact(2)
 │    │    ├─ 2 × fact(1)
 │    │    │    └─ cat 返回 1
 │    │    └─ 返回 2
 │    └─ 返回 6
 └─ 返回 24
```

栈帧里存的是"这一刻之后还要做什么"。整个递归过程的空间峰值等于同时存在的栈帧数，也就是最大深度，不是总调用次数。

### 2. 深度是空间，调用次数是时间

一次递归的总调用次数由递推式决定，最大深度由"每层缩小多少"决定。两者常被混为一谈。

二分查找的调用次数与深度都是 $\log_2 n$；归并排序的调用次数是 $O(n)$，深度是 $\log_2 n$；没有记忆化的斐波那契调用次数是 $O(2^n)$，深度只有 $n$。同一个"递归"，三个量级。

栈空间的量级按深度算：每帧数十字节，深度 $10^6$ 就是数十 MB，超过默认 8 MB 的线程栈。这是递归在大规模输入上最直接的失效方式——不是算错，是栈溢出。

## 二、分治三段：分解、求解、合并

### 1. 分解要能不重不漏

分治要求把原问题拆成若干子问题，子问题覆盖原问题且互不重叠。归并排序把数组对半切开，覆盖且不重叠；快速排序按枢轴分成两段，同样覆盖且不重叠。

不重不漏保证了"子问题的解拼起来就是原问题的解"，这是分治正确性的第一层要求。

### 2. 合并的代价决定总代价

分治的递推式是 $T(n)=aT(n/b)+f(n)$： $a$ 路子问题、每路规模 $n/b$、合并要 $f(n)$。总代价由三者谁占主导决定——同章《复杂度分析》§四.2 的 Master 定理给出三情形，这里只用它的结论。

| 分解方式 | 递归式 | 合并代价 | 总代价 |
| --- | --- | --- | --- |
| 对半切 + 线性合并 | $2T(n/2)+n$ | 线性 | $O(n\log n)$ |
| 对半切 + 常数合并 | $2T(n/2)+1$ | 常数 | $O(n)$ |
| 减半 + 常数合并 | $T(n/2)+1$ | 常数 | $O(\log n)$ |
| 分七路 + 平方合并 | $7T(n/2)+n^2$ | 平方 | $O(n^{2.81})$ |

最后一行是 Strassen 矩阵乘法：把 8 次子矩阵乘法减到 7 次，指数从 3 降到 $\log_2 7\approx2.81$。它说明分治的收益可以来自"减少子问题数"，而不只是"缩小规模"。

## 三、合并必须满足代数要求

### 1. 可结合才能任意切分

合并操作必须可结合： $(a\oplus b)\oplus c=a\oplus(b\oplus c)$。只有可结合，切分位置才不影响结果，分治才有意义。

加法、乘法、最值、集合并都满足；减法不满足，所以"区间减"不能直接分治，必须先转成加法（例如差分）。

这条要求解释了为什么线段树只接受可合并的聚合：它的每个节点都在做一次合并，合并不可结合，树上的结果就依赖切分方式。

### 2. 子问题独立才能并行

分治的子问题之间没有数据依赖，这是它天然可并行的原因。归并排序的两半可以交给两个核同时排序，最后合并；快速排序的两段同理。

并行的收益受合并阶段限制：排序可以并行到 $O(n\log n/p)$，但最后一步合并仍要 $O(n)$。阿姆达尔定律在这里的直接体现是：串行的合并段决定了加速比的上限。

## 四、递归可以直接换成迭代

### 1. 显式栈与尾递归

任何递归都能用显式栈改写：把"待处理的子问题"压进自己维护的栈，循环取出。改写后空间从调用栈转到堆，深度不再受线程栈限制。

尾递归是特例：递归调用是函数的最后一个动作、返回值直接透传时，编译器可以复用当前栈帧，空间从 $O(\text{深度})$ 降到 $O(1)$。这条优化依赖语言与编译选项，不能当作可移植的保证。

### 2. 快速幂把递归压成位循环

$x^n$ 的分治写法是： $n$ 为偶数时算 $(x^{n/2})^2$，为奇数时多乘一个 $x$。递归深度 $\log_2 n$。

这个递归可以完全消掉，因为"还需要乘哪些因子"由 $n$ 的二进制位决定：

```python
def power(x, n):
    result = 1
    while n:
        if n & 1:            # 当前最低位为 1，把这个因子乘进去
            result *= x
        x *= x               # 平方，对应往高一位走
        n >>= 1
    return result
```

$n=10^9$ 时循环 30 次、乘法约 45 次；朴素做法要 $10^9$ 次乘法。递归版本与迭代版本做同样多的乘法，差别只在栈空间与常数。

## 五、分治的边界

### 1. 子问题重叠时退化成动态规划

分治要求子问题互不重叠。斐波那契的朴素递归违反这条：`fib(n-1)` 与 `fib(n-2)` 会重复计算同一批子问题，调用次数涨到 $O(2^n)$。

补上记忆化，重复的子问题只算一次，调用次数降到 $O(n)$。这一步改动把"分治"变成了"动态规划"——两者的结构相同，区别只在子问题是否重叠、是否复用结果。

### 2. 分解代价过高时不如不分

分治不是免费的。分解要切分数据，合并要扫描数据，两者都要时间与空间。

阈值效应很常见：子问题小到一定程度时，递归调用的开销超过直接求解。实际实现会在规模低于阈值时切到插入排序或直接循环，理由与"小区间用插入排序"相同——常数在小区间上压过了渐近优势。

另一个边界是数据布局。归并排序的合并要额外 $O(n)$ 缓冲，快速排序原地分区不额外分配。两者时间同阶，空间差一个量级，内存受限时选择由空间决定。
