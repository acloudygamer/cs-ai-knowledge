# 动态规划

两个一千字符的字符串，求编辑距离。朴素递归枚举所有插入、删除、替换的组合，可能的编辑序列有指数级；动态规划（Dynamic Programming，DP）把它压到 $10^6$ 个格子，每格算一次加法。

省下来的计算全部来自一件事：同一个子问题被反复求解。动态规划把这些重复的答案记下来，代价是要先把"子问题"定义得足够清楚。

## 一、重叠子问题让朴素递归指数爆炸

### 1. 同一子问题被算很多遍

斐波那契的朴素递归是最小的例子：`fib(5)` 要算 `fib(4)` 与 `fib(3)`，而 `fib(4)` 又要算 `fib(3)` 与 `fib(2)`。`fib(3)` 被算了两遍，`fib(2)` 被算了三遍，重复量随 $n$ 指数增长。

```text
fib(5)
├─ fib(4)
│  ├─ fib(3)      ← 第一次
│  │  ├─ fib(2)   ← 第一次
│  │  └─ fib(1)
│  └─ fib(2)      ← 第二次
└─ fib(3)         ← 第二次
   ├─ fib(2)      ← 第三次
   └─ fib(1)
```

### 2. 记忆化把重复计算压成一次

加一张表，算过的子问题直接返回。每个不同的子问题只算一次，`fib(n)` 的调用次数从 $O(2^n)$ 降到 $O(n)$。

记忆化不改变递归的结构，只改变"算过就查表"。这一步足以把指数级问题压成线性，因为它消掉的正是重复。

### 3. 与分治的分界

分治要求子问题互不重叠，动态规划处理它们重叠的情形。同一份递归式，子问题独立时是分治，有重叠时是动态规划。

这条分界解释了为什么归并排序不需要记忆化（两半不重叠），而斐波那契需要（子问题大量重复）。

## 二、状态必须自包含

### 1. 状态定义决定转移

动态规划的核心工作是定义状态：用哪些变量能唯一确定"当前面临的子问题"。

状态定义错了，转移就写不出来，或者写出来是错的。常见的错误是漏掉一个影响后续决策的量——比如做背包时只记"已用容量"，忘了记"已经选到第几件"。

### 2. 无后效性要求状态携带全部历史

无后效性的意思是：一旦状态确定，未来的最优决策只依赖这个状态，不依赖到达它的路径。

这条要求很硬。若两个不同的到达方式在状态里看起来一样、但未来的最优选择不同，状态就定义得不够。补上一个维度，或者换一组状态变量。

编辑距离的状态是 $(i,j)$：第一个串的前 $i$ 个字符变成第二个串的前 $j$ 个字符的最小代价。这个状态自包含——不论前面怎么变过来的，剩下的工作只取决于这两个前缀。

## 三、递推就是按拓扑序填表

### 1. 备忘录与递推等价

记忆化是自顶向下的：从大问题出发，遇到没算过的子问题就递归下去。递推是自底向上的：先算子问题，再算大问题。

两者算的是同一批状态、同一组转移，结果必然相同。选择哪一种取决于依赖形状：依赖有环时只能用记忆化（递归栈保证不重入），依赖是 DAG 时递推更省栈空间。

### 2. 递推顺序就是拓扑序

状态之间的依赖构成一个有向无环图：`dp[i][j]` 依赖 `dp[i-1][j]`、`dp[i][j-1]`、`dp[i-1][j-1]`。按 $i$ 从小到大、 $j$ 从小到大填表，每个格子用到的前驱都已经算好。

```text
编辑距离的填表顺序（"world" → "hello"）：
      ""  h  e  l  l  o
  ""   0  1  2  3  4  5
  w    1  1  2  3  4  5
  o    2  2  2  3  4  4
  r    3  3  3  3  4  5
  l    4  4  4  3  3  4
  d    5  5  5  4  4  4

dp[i][j] = min(
  dp[i-1][j] + 1,        # 删
  dp[i][j-1] + 1,        # 插
  dp[i-1][j-1] + (不同 ? 1 : 0)   # 改
)
```

拓扑序写错是动态规划最常见的错误：用到了还没算的格子，结果依赖上一轮的残留值。它不会崩溃，只会给出错误答案。

### 3. 滚动数组把空间降一维

很多转移只依赖"上一行"，不依赖更早的行。此时可以把二维表压成一维，每轮覆盖。

编辑距离依赖上一行与当前行的左侧，可以压成两行；0/1 背包依赖上一行，可以压成一行，但容量必须逆序扫——正序会让同一件物品被选两次。

空间从 $O(nW)$ 降到 $O(W)$。时间不变，这正是"用空间换时间"的反向操作：用结构的性质换空间。

## 四、两族范式

### 1. 背包：维度是物品与容量

0/1 背包的状态是 `dp[i][w]`：前 $i$ 件物品、容量 $w$ 下的最大价值。转移只有两种选择——不选第 $i$ 件（继承 `dp[i-1][w]`），或选它（`dp[i-1][w-w_i] + v_i`）。

一维写法 `dp[w]` 必须逆序扫容量：

```python
for w in range(W, weight - 1, -1):     # 逆序，保证每件只用一次
    dp[w] = max(dp[w], dp[w - weight] + value)
```

正序扫时 `dp[w - weight]` 可能已经包含当前这件物品，等于允许重复选，那是完全背包的语义。

### 2. 序列：状态是前缀或区间

最长递增子序列的状态是 `dp[i]`：以第 $i$ 个元素结尾的最长递增子序列长度。转移要扫前面所有更小的元素， $O(n^2)$。

这个状态有多余信息——它只记"以谁结尾"，不记长度。用"长度为 $L$ 的递增子序列的最小结尾"作状态，配合二分，可以压到 $O(n\log n)$。二分的原语在同章《二分搜索》§二.2，这里只用它的结论。

| 问题 | 状态 | 转移 | 时间 | 空间 |
| --- | --- | --- | --- | --- |
| 0/1 背包 | 前 $i$ 件、容量 $w$ | 选 / 不选 | $O(nW)$ | $O(W)$ 滚动 |
| 完全背包 | 同上 | 选若干次 | $O(nW)$ | $O(W)$，正序 |
| 最长递增子序列 | 以 $i$ 结尾 | 扫前驱 | $O(n^2)$ | $O(n)$ |
| 最长递增子序列（优化） | 长度到最小结尾 | 二分插入 | $O(n\log n)$ | $O(n)$ |
| 编辑距离 | 两个前缀 | 删 / 插 / 改 | $O(mn)$ | $O(\min(m,n))$ 滚动 |

## 五、边界

### 1. 状态爆炸时靠换状态降维

状态不是越多越好。状态维度每加一，表的规模乘一个量级： $n$ 个物品、容量 $W$、再要求"恰好选 $k$ 件"，就变成 $O(nWk)$。

降维有两条路：找等价的状态（LIS 的"最小结尾"），或者用其他结构替代表（滚动数组、单调队列、线段树优化转移）。

### 2. 动态规划也吃空间

$10^6$ 个状态、每个 8 B，就是 8 MB；三维状态轻易超过内存。表放在内存里还是外存里，决定它还能不能跑。

滚动数组是最常用的解法，但它要求转移只依赖有限几行。依赖形状一旦变成"任意前驱"，滚动就失效，只能换思路。

动态规划的账很直白：它用"记下所有子问题答案"的空间，换掉"重复计算"的时间。空间给不出来时，这条路就走不通。
