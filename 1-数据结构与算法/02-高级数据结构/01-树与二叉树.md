# 树与二叉树

## 定义

> **版本基准**: universal

树是节点间具有层次关系的数据结构，从图论角度它是连通无环图：从任一节点沿父向边可达根，从根可达所有节点。根节点唯一，父向边构成从任意节点到根的唯一路径。

二叉树是每个节点最多有两个子节点的树结构，是树结构研究的基础模型——任何有根有序树都可唯一地二叉化表示。

**本质操作**：树的遍历（先序/中序/后序/层序）本质是对树节点的**线性化重排**，通过控制递归/迭代的顺序将层级结构压平为一维序列。中序遍历在 BST 中产生排序序列，是 BST 查找性质的直接推论。

**资源视角**：树结构消耗两类资源——**内存**（节点指针和值存储）和**计算时间**（遍历/查找的路径长度）。所有平衡机制的约束条件都服务于控制树高，从而控制这两类资源的消耗。

## 数学模型

### 形式化定义

$$
T = (V, E, r),\quad V = \{v_1, v_2, \ldots, v_n\},\quad |V| = n,\quad |E| = n-1
$$

连通无环图 $\Rightarrow$ 树的边数恒为 $|E| = n-1$ （由连通性和无环性共同约束）。

**树的等价定义**（递归基）：空树；或一个根节点加上 $k$ 棵不相交的子树。

### 约束体系的形式化

| 约束类型 | 形式化描述 | 约束目的 | 违反后果 |
|----------|-----------|----------|----------|
| 二叉树 | $\forall v \in V,\ \deg(v) \leq 2$ | 度数上界 | 失去二叉结构等价性 |
| BST 有序性 | $\forall u \in \text{left}(x),\ u.key < x.key$ ； $\forall v \in \text{right}(x),\ v.key > x.key$ | 搜索单调性 | 查找退化为线性扫描 |
| AVL 平衡 | $\forall v,\ |h(\text{left}(v)) - h(\text{right}(v))| \leq 1$ | 高度平衡 | 树高失控， $O(n)$ 查找 |
| 红黑树颜色 | 根黑、叶黑、红子必黑 | 黑色高度平衡 | 最长路径 $\leq 2 \times$ 最短路径 的约束失效 |

### BST 查找的下界与上界

含 $n$ 个节点的二叉树的高度 $h$ 满足：
$\lfloor \log_2 n \rfloor \leq h \leq n-1$

**下界推导**：完全二叉树的节点数与高度关系为 $n \leq 2^{h+1} - 1$ ，因此 $h \geq \lfloor \log_2 n \rfloor$ 。

**上界推导**：退化为链表时（每次插入都落在最左或最右），高度为 $n-1$ 。

**退化的触发条件**：按排序顺序插入（升序或降序），每次都落在叶节点的最左或最右路径上。这是平衡树必须解决的核心问题。

### 归约终点

树结构的本质是**偏序集合的层次化组织**：

1. **偏序层**：通过"父子"偏序关系组织节点，从根到叶定义了全序（先序/后序）或偏序（中序）
2. **层次化层**：节点按到根的距离（深度）分层，每层节点无横向联系
3. **线性化层**：遍历操作将树压平为序列

所有平衡树（AVL、红黑、B树）都是在"如何保持偏序结构稳定"这一约束下的不同工程折中——它们通过不同的约束形式（高度差、黑色高度、多路分支）来控制树高。

## 数据流

### 遍历的数据形态变换

<pre>
输入: 二叉树节点结构 (val, left, right)
遍历过程的数据形态变换:

先序 (根→左→右):
  读取根节点 → 递归左子树 → 递归右子树
  输出序列中根节点值最先被消费（先序之名由来）
  所有权：递归调用栈持有当前节点的访问权

中序 (左→根→右):
  最左路径深入（压栈） → 弹栈读值 → 转向右子树
  对 BST 而言，中序输出即为升序序列
  所有权：栈帧从持有转为释放，值被消费

后序 (左→右→根):
  两次弹栈判重防重复 → 读值
  用于拓扑排序、释放资源等依赖左右子树已处理完毕的场景
  所有权：子树的资源释放在父节点读取之前完成

层序 (BFS):
  队列入根 → 出队访问 → 入队左右子 → 循环
  层级分离，依赖队列的 FIFO 顺序
  所有权：节点从队列转移到已访问集合
</pre>

### BST 中序遍历的排序性质的数据流证明

<pre>
输入序列: [7, 2, 9, 1, 5] 依次插入 BST

插入过程（所有权转移：外值 → 树节点）：
  7 作为根
  2 < 7，插入左子树
  9 > 7，插入右子树
  1 < 7 → < 2，插入左左
  5 > 2 → < 7，插入左右

中序遍历路径: 1 → 2 → 5 → 7 → 9
数据形态: 二叉树结构 → 线性升序序列
变换原理: BST 定义的偏序保证中序序列单调

关键不变量：对于 BST 中任意节点 x，
  左子树所有节点 < x.val < 右子树所有节点
  因此中序遍历时，左子树全部输出后才输出 x，再输出右子树
  输出序列必单调递增
</pre>

## 对比参照

| 属性 | BST | AVL | 红黑树 | B/B+ 树 |
|------|-----|-----|--------|---------|
| 平衡标准 | 无（自然高度） | 高度差 ≤ 1 | 黑色高度平衡 | 多路平衡 |
| 查找复杂度 | $O(h)$ | $O(\log n)$ | $O(\log n)$ | $O(\log_m n)$ |
| 插入成本 | $O(h)$ | ≤ 2 次旋转 | ≤ 2 次旋转 | 分裂/合并 |
| 删除成本 | $O(h)$ | $O(\log n)$ 次旋转 | $O(\log n)$ | $O(\log_m n)$ |
| 适用场景 | 内存小数据 | 读密集 | 写密集 | 磁盘/外部存储 |

## 机制

### 平衡的本质：为什么需要平衡？

BST 的查找性能由树高决定。下界 $\Omega(\log n)$ （含 $n$ 个节点的二叉树的最小高度），上界 $O(n)$ （退化为链表）。

**退化触发条件**：按排序顺序插入（升序/降序），每次都落在最右/最左路径上。

**约束条件**：为保证 $O(\log n)$ 查找，所有平衡树都对"树高"或"黑色高度"设置了硬约束。

**退化后果**：查找从 $O(\log n)$ 退化到 $O(n)$ ，性能劣化与线性扫描无异。

### AVL：高度平衡的严格约束

- 约束： $\forall v,\ |h_L - h_R| \leq 1$
- **插入**：沿查找路径回溯，最多两次旋转（单旋或双旋）恢复平衡
- **删除**：可能需 $O(\log n)$ 次旋转向上修复——这是 AVL 的主要弱点
- **设计权衡**：严格平衡 $\Rightarrow$ 查找最优，但删除代价高；适合读密集场景

**AVL 删除的旋转传播**：删除节点后，沿路径向上回溯，每遇到一个失衡节点就旋转。若旋转后子树高度降低，需继续向上处理，直到根或遇到不再失衡的节点。

**旋转传播的代价分析**：设树高为 $h$ ，删除操作最多涉及 $h$ 个祖先节点的检查和可能的旋转，每次旋转 $O(1)$ ，总代价 $O(h) = O(\log n)$ 。但最坏情况下（每次旋转都导致高度降低），需要传播到根。

### 红黑树：黑色高度平衡的松弛约束

- 约束：路径上黑色节点数相同 + 红子必黑
- **效果**：最长路径 $\leq 2 \times$ 最短路径（不如 AVL 严格）
- **插入**：最多两次旋转；删除最多三次
- **设计权衡**：放松平衡要求 $\Rightarrow$ 删除成本降低，换取更稳定的写性能；适合写密集场景

**红黑树的黑色高度**：从任一节点到其每个叶子的路径上，黑色节点数相同。这个约束比 AVL 的高度差约束弱，但保证了任意路径长度不超过最短路径的两倍。

**松弛的设计动机**：AVL 的严格平衡在删除时需要 $O(\log n)$ 次旋转，而红黑树通过允许路径长度在 2:1 范围内波动，将删除旋转次数限制在常数次（最多三次）。

### B/B+ 树：多路分支的外部存储优化

- **核心动机**：磁盘 IO 代价远大于内存访问，树高每降一层意味着一次磁盘页加载
- **约束**： $m$ 阶 B 树，每个节点最多 $m$ 个子指针， $\lceil m/2 \rceil$ 个子指针保证不空
- **B+ 树变种**：所有数据聚在叶子层，叶子间用链表串联，范围查询只需扫描叶子链
- **约束违反**：若节点过满（超过 $m$ 个 key）则分裂；若过疏（低于 $\lceil m/2 \rceil$ 个 key）则合并或从兄弟节点借

**B+ 树的 cache 优化**：由于内部节点只存 key（不含 data 指针），一个磁盘页能容纳更多 key，降低树高。同时叶子层用链表串联，使得范围查询（扫描一段连续 key）只需沿链表遍历，避免频繁的随机 IO。

**磁盘 IO 的数学约束**：设磁盘页大小为 $B$ 字节，每个 key 占 $k$ 字节，则每个内部节点可容纳 $\lfloor B/k \rfloor$ 个 key。对于 $n$ 个 key，树高 $h \approx \lceil \log_{\lfloor B/k \rfloor} n \rceil$ 。若 $B/k = 100$ ，则 $h \approx \log_{100} n$——比二叉树的 $\log_2 n$ 小约 6 倍。

### 旋转的机制：高度重平衡的原子操作

旋转（左旋/右旋）是在保持 BST 有序性约束的前提下，单纯改变子树高度分布的操作：

<pre>
        x                  y
       / \      右旋       / \
      y   T₃   ───→     T₁  x
     / \                   / \
    T₁  T₂                T₂  T₃

中序遍历不变: T₁ y T₂ x T₃（旋转前后完全一致）
高度变化:    h(x) → h(y) + 1，h(y) → max(h(T₁), h(T₂)) + 1
</pre>

**旋转的约束**：
- 左旋：当前节点的右子变为父节点，原父节点变为左子
- 右旋：当前节点的左子变为父节点，原父节点变为右子
- 旋转后中序遍历序列不变，这是 BST 有序性的直接保证

**旋转是局部操作**：只涉及常数个指针修改， $O(1)$ 时间。但旋转可能改变子树高度，从而沿路径向上传播失衡。

**旋转的几何解释**：旋转将较深的子树"向上提"，同时将较浅的子树"向下压"。对于 AVL 的 LL/RR 失衡，单旋即可恢复；对于 LR/RL 失衡，需双旋（相当于两次单旋）。

### 平衡树的归约视角

所有平衡树都可以归约为"在偏序约束下维护树高的工程折中"：
- **AVL**：严格高度差约束 $\Rightarrow$ 查找最优，但删除时重平衡成本高
- **红黑树**：放松到黑色高度约束 $\Rightarrow$ 删除更便宜，但查找稍慢（常数因子）
- **B树**：多路分支 $\Rightarrow$ 降低树高，但每个节点的比较成本增加

**统一视角**：平衡树 = BST 偏序约束 + 某种高度/平衡约束 + 维护这个约束的重平衡算法。

## 参考存根

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def bst_insert(root, val):
    if not root:
        return TreeNode(val)
    if val < root.val:
        root.left = bst_insert(root.left, val)
    else:
        root.right = bst_insert(root.right, val)
    return root

def bst_search(root, target):
    while root:
        if target == root.val:
            return True
        root = root.left if target < root.val else root.right
    return False

def avl_rotate_right(y):
    """右旋：y 的左子 x 成为父节点，y 变为 x 的右子"""
    x = y.left
    T2 = x.right
    x.right = y
    y.left = T2
    return x

def avl_rotate_left(x):
    """左旋：x 的右子 y 成为父节点，x 变为 y 的左子"""
    y = x.right
    T2 = y.left
    y.left = x
    x.right = T2
    return y
```
