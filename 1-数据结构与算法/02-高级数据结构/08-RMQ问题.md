# RMQ 问题

## 定义

Range Minimum (Maximum) Query（RMQ）：给定数组 $A[1..n]$，预处理后可在 $O(1)$ 或 $O(\log n)$ 时间内回答区间 $[l, r]$ 的最小值（或最大值）的位置/值。

RMQ 是许多字符串问题（如 LCA 最近公共祖先）的基础构件——LCA 问题可归约为 RMQ，RMQ 也可归约为 LCA，两者的预处理方案可以互相转化。

## 数学模型

### 稀疏表（Sparse Table）：$O(n \log n)$ 预处理，$O(1)$ 查询

**DP 递推**：

$$
\text{st}[i][j] = \min\ (A[i],\ A[i+2^{j-1}])
$$

含义：区间 $[i,\ i+2^{j}-1]$ 的最小值等于左半区间 $[i,\ i+2^{j-1}-1]$ 和右半区间 $[i+2^{j-1},\ i+2^{j}-1]$ 最小值的较小者。

**查询** $[l, r]$：令 $k = \lfloor \log_2(r-l+1)\rfloor$

$$
\text{RMQ}(l,r) = \min\left(\text{st}[l][k],\ \text{st}[r-2^{k}+1][k]\right)
$$

原理：两段长度为 $2^k$ 的区间恰好覆盖 $[l,r]$，但可能重叠——对最小值查询，重叠不会影响正确性（$\min(a, a) = a$）。

**预处理复杂度**：
$$
T_{\text{build}} = \sum_{j=0}^{\lfloor \log_2 n \rfloor} \sum_{i=1}^{n-2^j+1} O(1) = O(n \log n)
$$

**空间复杂度**：$n \times (\lfloor \log_2 n \rfloor + 1) = O(n \log n)$

### 线段树方案：$O(n)$ 预处理，$O(\log n)$ 查询

适合动态场景（数组值会修改）。详见线段树词条，此处仅给出与稀疏表的对比。

### 笛卡尔树法：RMQ $\leftrightarrow$ LCA

构造数组 $A$ 的笛卡尔树（满足堆性质 + 中序遍历为原数组），则：

$$
\text{RMQ}_A(l, r) = \text{LCA}_{\text{cartesian}}(\text{node}_l,\ \text{node}_r)
$$

笛卡尔树可在 $O(n)$ 时间内构建（单调栈），LCA 可用 Tarjan 离线 $O(n+q)$ 或 Euler Tour + RMQ $O(1)$ 查询。

### 不同方案的权衡

| 方案 | 预处理 | 查询 | 更新 | 空间 |
|------|--------|------|------|------|
| 稀疏表 | $O(n \log n)$ | $O(1)$ | 不支持 | $O(n \log n)$ |
| 线段树 | $O(n)$ | $O(\log n)$ | $O(\log n)$ | $O(n)$ |
| 笛卡尔树 + RMQ | $O(n)$ | $O(1)$ | 不支持 | $O(n)$ |
| 笛卡尔树 + LCA | $O(n)$ | $O(1)$ | 不支持 | $O(n)$ |

**归约终点**：RMQ 的本质是**区间极值查询**，可归约为"区间合并操作的单调半环"问题——任何满足结合律的操作（min、max、sum、gcd）都可以用相同的稀疏表框架解决。

  st[0][1] = min(st[0][0], st[1][0]) = min(1,3) = 1

  st[2][1] = min(2,7) = 2
  st[3][1] = min(7,9) = 7
  st[4][1] = min(9,5) = 5

  st[6][1] = min(1,4) = 1
  st[7][1] = 无（超出边界）

  st[0][2] = min(st[0][1], st[2][1]) = min(1,2) = 1

  st[2][2] = min(st[2][1], st[4][1]) = min(2,5) = 2

## 机制

### 为什么稀疏表查询是 $O(1)$ 而不是 $O(\log n)$？

关键在于预处理阶段已经将**所有长度为 $2^k$ 的区间**的极值记录下来。查询时，只需根据区间长度选择对应的 $k$，然后合并两个重叠的 $2^k$ 区间。

这不是真正的 $O(1)$ 计算，而是将计算代价转移到了预处理阶段。这是一种**空间换时间**的策略。

### 重叠区间为何不影响最小值？

对于 $\min$ 操作，重叠是安全的：$\min(a, b) = a$ 当 $b \geq a$。对于 $\max$ 操作同样。

但注意：这仅对**幂等操作**成立。对于 sum（和），重叠会导致重复计数；对于 gcd，重叠也会导致错误。因此稀疏表仅适用于**幂等、半环上的单调归约操作**。

### 为什么需要 $\lfloor \log_2(r-l+1) \rfloor$？

这个选择确保两段区间 $[l, l+2^k-1]$ 和 $[r-2^k+1, r]$ 都能完全落入 $[l,r]$，且它们的并集覆盖 $[l,r]$。取更大的 $k$ 会导致区间越界，取更小的 $k$ 则两段不能完全覆盖。

### 动态 RMQ 的必要性

静态场景（数组不变）：稀疏表最优。
动态场景（数组元素会更新）：线段树更适合，因为稀疏表的单点更新需要更新所有 $j$（$\log n$ 层）的对应位置，共 $O(\log n)$ 条记录，且范围更新同样困难。

## 参考存根

```python
class SparseTable:
    def __init__(self, arr):
        self.n = len(arr)
        self.log = [0] * (self.n + 1)
        for i in range(2, self.n + 1):
            self.log[i] = self.log[i // 2] + 1
        k = self.log[self.n] + 1
        self.st = [[0] * k for _ in range(self.n)]
        for i in range(self.n):
            self.st[i][0] = arr[i]
        j = 1
        while (1 << j) <= self.n:
            for i in range(self.n - (1 << j) + 1):
                self.st[i][j] = min(self.st[i][j-1],
                                    self.st[i + (1 << (j-1))][j-1])
            j += 1

    def query(self, l, r):
        k = self.log[r - l + 1]
        return min(self.st[l][k], self.st[r - (1 << k) + 1][k])
```
