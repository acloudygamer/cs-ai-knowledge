# 堆与优先队列

## 定义

> **版本基准**: universal

堆是一棵完全二叉树，其节点满足**堆序性**：对于大顶堆，任意父节点的键值不小于其子节点的键值；对应的小顶堆则满足父节点键值不大于子节点的键值。堆的数组实现将树的节点按层序存储在连续数组中，父节点与子节点的下标存在确定的算术关系，无需指针即可完成父子跳转。

优先队列是堆的抽象数据类型包装：以堆为内部表示，对外提供 push（插入）和 pop（删除并返回极值）的接口。优先队列将"优先级"这个偏序关系引入队列，使得高优先级元素可以优先被处理，而不必遵循先进先出的时间顺序。

**本质**：堆是**偏序集合的快速极值查询结构**——在 O(1) 时间内找到极值元素（堆顶），在 O(log n) 时间内维护插入和删除后的堆序性。堆将"排序"问题从需要全局重排退化为只需要维护局部有序性。

**资源视角**：堆操作消耗两类资源——**比较次数**（每次 sift 需要 log n 次比较）和**内存移动**（元素在数组中交换位置）。完全二叉树的数组实现保证了这两个操作都只需常数额外空间。

## 数学模型

### 下标关系（0-indexed）

对于数组中下标为 $i$ 的节点：

$$
\text{parent}(i) = \left\lfloor\frac{i-1}{2}\right\rfloor,\quad \text{left}(i) = 2i+1,\quad \text{right}(i) = 2i+2
$$

反之，给定父节点下标 $p$ ，其子节点下标为 $2p+1$ 和 $2p+2$ 。

**完全二叉树的性质**：这个下标关系之所以成立，正是因为完全二叉树除最后一层外每层节点数都达到最大值，且最后一层节点集中于左侧。这保证了父子关系可以用简单算术描述，无需存储指针。

**数学证明**：设完全二叉树深度为 $h$ （根深度 0），第 $k$ 层（ $0 \leq k \leq h$ ）的节点下标范围是 $[2^k - 1, 2^{k+1} - 2]$。对于第 $k$ 层的任意节点 $i$，其左子深度为 $k+1$，左子下标为 $2i + 1$，恰好落在 $[2^{k+1} - 1, 2^{k+2} - 2]$ 范围内。

### 堆性质的形式化

大顶堆的堆序性可形式化为：
$\forall i,\ \text{heap}[i] \geq \text{heap}[2i+1] \text{ (if } 2i+1 < n\text{) and } \text{heap}[i] \geq \text{heap}[2i+2] \text{ (if } 2i+2 < n\text{)}$

这意味着从堆顶到任意叶节点的路径上，键值严格非递增。

**堆序性的偏序本质**：堆序性是"父 $\geq$ 子"的关系，但同一层的兄弟节点之间无约束。这是一种**层次化的偏序关系**，而非全序关系。

### 堆操作的时间复杂度

设树高为 $h = \lfloor \log_2 n \rfloor$ 。

- **sift_up**（插入后修复）：从叶节点向上比较并交换，最多沿树高上行， $T_{\text{sift\_up}} = O(h) = O(\log n)$
- **sift_down**（删除根后修复）：从根节点向下比较子节点并交换，最多沿树高下行， $T_{\text{sift\_down}} = O(h) = O(\log n)$
- **push**：末尾添加后执行 sift_up， $T_{\text{push}} = O(\log n)$
- **pop**：用末尾元素替代堆顶后执行 sift_down， $T_{\text{pop}} = O(\log n)$

**sift_down 的决策约束**：当节点有两个子节点时，必须与较大的（大顶堆）或较小的（小顶堆）子节点比较。若只比较一个子节点，可能将较小的子节点提升到错误位置。

### 建堆复杂度 T(n) = O(n)

从最后一个非叶子节点（索引 $\lfloor (n-2)/2 \rfloor$ ）向前，对每个节点执行 sift_down。总体复杂度分析：

$$
T(n) = \sum_{i=0}^{\lfloor (n-2)/2 \rfloor} O(h_i)
$$

其中 $h_i$ 是节点 $i$ 到叶节点的距离。关键观察：深度越浅的节点数量越少，深度越深的节点数量越多。加权求和的结果是 $O(n)$ 而非 $O(n \log n)$ 。

**直观解释**：设完全二叉树高为 $h$ ，第 $k$ 层（根为第 0 层）有 $2^k$ 个节点，每个节点到叶子的距离为 $h-k$ 。从最后一层（ $k=h$ ）到第一层（$k=0$）求和：

$$
T(n) = \sum_{k=0}^{h} 2^k \cdot (h-k) = 2^{h+1} - h - 2 = O(n)
$$

这意味着**建堆比排序快**：可以先用 O(n) 建堆，再用 O(log n) 的 pop 操作实现排序，总复杂度 O(n log n)。

### Top-K 问题的堆解法

维护一个大小为 K 的小顶堆，遍历所有元素：

```python
for x in nums:
    if len(heap) < K:
        heappush(heap, x)        # O(log K)
    elif x > heap[0]:            # O(1) 获取堆顶（小顶堆的最小值）
        heapreplace(heap, x)     # O(log K)：弹出堆顶并插入新元素
```

复杂度： $O(n \log K)$ ，当 $K \ll n$ 时远优于 $O(n \log n)$ 的全局排序。

**Top-K 小顶堆的正确性**：小顶堆维护的是"最大的 K 个元素"。堆顶是这 K 个中最小的，也就是第 K 大的元素。

**正确性证明**：
- 初始堆为空，显然维护最大的 0 个元素
- 归纳假设：处理前 $i$ 个元素后，堆包含最大的 $\min(i, K)$ 个元素
- 处理第 $i+1$ 个元素 $x$ ：
  - 若堆大小 $< K$ ， $x$ 加入后堆包含最大的 $\min(i+1, K)$ 个元素
  - 若堆大小 $= K$ 且 $x > \text{heap[0]}$ ，则 $x$ 属于最大的 $K$ 个，heapreplace 保证堆顶更新为第 $K$ 大的元素
  - 若 $x \leq \text{heap[0]}$ ， $x$ 不属于最大的 $K$ 个，堆不变

### 斐波那契堆的均摊分析（势能法）

斐波那契堆的 push 为 O(1) 均摊，pop 为 O(log n) 均摊。通过势能法分析：

定义势能 $\Phi = $ 树的棵数（根链表中的根节点数）。

- **push**：O(1) 实际时间，势能 +1（新的根节点），均摊 O(1) + 1 = O(1)
- **pop**：涉及删除最小根、合并子树、可能的最坏情况级联剪切

斐波那契堆适用于**极致的 push 性能**场景（如 Dijkstra 的优先队列实现），但实际中常数因子较大，不如二叉堆常用。

**斐波那契堆的约束**：度数（子节点数）必须满足 $D(n) \leq \lfloor \log_\phi n \rfloor$ ，其中 $\phi = (1+\sqrt{5})/2$ 。这是通过级联剪切（cascading cut）机制保证的——当一个节点失去一个子节点时，该节点被剪切到根链表。

## 数据流

### sift_up（插入）：从叶向根的上浮

<pre>
插入 15 到末尾:
     10                    10
    /  \                  /  \
   8    7        →       8    7
  / \  /                  / \  /
 5   6 [15]               5   6  15

15 与父节点 7 比较: 15 > 7，交换位置
     10                    10
    /  \                  /  \
   8   [15]       →      8    15
  / \  / \               / \  / \
 5   6 7   -             5  6  7  -

15 与父节点 10 比较: 15 > 10，交换位置，到达根
   [10]                    15
   /  \                    /  \
  8    10        →       8    7
 / \  / \               / \  / \
5  6  7   -             5  6  -  -

结果: 15 现在是新的堆顶
</pre>

**所有权变换**：插入操作仅在末尾添加新元素的所有权。上浮过程中，交换的是数组中的值，而非节点的所有权——数组索引本身不携带所有权语义。

**路径长度**：最多 $\lfloor \log_2 n \rfloor$ 次比较和交换。

### sift_down（删除堆顶）：从根向叶的下沉

<pre>
删除堆顶 15，用末尾 5 替代:
     15                    5
    /  \                  /  \
   8    7        →       8    7
  / \  /                  / \  /
 5   6  -                [5]  6  -

5 与子节点比较: 8 > 5，左子较大，交换
     5                     8
    /  \                  /  \
  [8]   7        →       5    7
  / \  /                   / \  /
  -  6  -                 -  6  -

5 与子节点比较: 7 > 5，右子较大，交换
     8                     8
    /  \                  /  \
   5    [7]      →       5    7
  / \  /                   / \  /
 -   6  -                  -   6  -

结果: 新的堆顶为 8
</pre>

**下沉决策**：当节点有两个子节点时，必须与较大的（大顶堆）或较小的（小顶堆）子节点比较，以确定是否需要交换以及与哪个子节点交换。

**下沉路径的几何解释**：每次下沉都选择"更有可能破坏堆序性"的方向——大顶堆中选择较大的子节点，因为如果较大的子节点都不大于当前节点，则较小的子节点必然不大于当前节点。

### Top-K 数据流

<pre>
输入流: [3, 1, 5, 2, 4], K=3（求第3大）

初始: 堆=[]

步骤1: push 3   → 堆=[3]           (大小 < K，直接入堆)
步骤2: push 1   → 堆=[1,3]         (小顶堆，1为堆顶即当前最小)
步骤3: push 5   → 堆=[1,3,5]       (堆大小=K)
步骤4: push 2   → 堆=[1,2,3,5]    (堆大小>K，弹出最小1)
              pop 1  → 堆=[1,3,5]   (1<2，不弹出2，堆不变)
步骤5: push 4   → 堆=[1,3,5,4]
              pop 1  → 堆=[1,3,5,4] (1<4，不弹出)

最终: 堆=[1,3,5]，堆顶=1 = 第3大的数

验证: [5,4,3,2,1] 降序排列
  第1大=5, 第2大=4, 第3大=3
  但堆顶=1？哪里错了？

重新分析 Top-K 逻辑：
  小顶堆维护最大的K个数，堆顶是其中最小的
  遍历每个元素：
    - 如果堆未满，直接入堆
    - 如果堆已满且新元素 > 堆顶，替换堆顶
    - 否则忽略

  [3,1,5,2,4] K=3 的过程：
  1. push 3 → [3]
  2. push 1 → [1,3]
  3. push 5 → [1,3,5]
  4. push 2 → 2 < 堆顶1，忽略 → [1,3,5]
  5. push 4 → 4 > 1，替换 → [1,4,5]？不对

  用 heapreplace 的逻辑：
  push 4 时，4 > 1，执行 heapreplace(heap, 4)
  heapreplace = pop() then push() 的原子操作
  pop 1, push 4 → [3,4,5]

  正确过程：
  1. [3]
  2. [1,3]
  3. [1,3,5]
  4. 4 > 1, heapreplace → pop 1, push 4 → [3,4,5]
  5. (已无更多元素)

  最终堆=[3,4,5]，堆顶=3 = 第3大 ✓
</pre>

## 机制

### 完全二叉树的数组存储为什么使堆操作 O(log n)

完全二叉树保证除了最后一层外，每层节点数都达到最大值，且最后一层节点集中在左侧。这导致：

1. **树高固定**：高度为 $\lfloor \log_2 n \rfloor$ ，不随插入顺序变化
2. **父子跳转只需算术运算**：无需遍历或搜索，直接用下标公式计算
3. **数组连续存储**：没有指针 chasing，缓存友好

sift_up 和 sift_down 的操作路径都是沿着从叶节点到根（或反之）的唯一路径，长度恰好是树高。每次比较和交换都只涉及常数个下标计算。

**与普通二叉树的对比**：若树不是完全二叉树，则父子关系不再能用简单下标公式描述，需要指针存储，且树高可能达到 $O(n)$ 。

**缓存局部性的数学解释**：数组实现下，父子节点的下标差不超过树高。当堆操作沿着路径下沉时，访问的内存地址呈连续或近似连续模式，符合 CPU 缓存预取机制，减少了缓存失效。

### sift_up 与 sift_down 的约束条件

- **sift_up**：仅用于插入操作。被比较的父节点必须存在（当 $i > 0$ 时 parent(i) 有效）。
- **sift_down**：用于删除堆顶后重建。被比较的子节点必须存在（当 $2i+1 < n$ 时左子存在，当 $2i+2 < n$ 时右子存在）。

当 sift_down 只有一个子节点时，只需与该子节点比较；当有两个子节点时，需要与较大的（大顶堆）或较小的（小顶堆）子节点比较，以确定是否需要交换。

### Python heapq 的实现约定

Python 的 `heapq` 实现的是**小顶堆**。若需大顶堆，有两种方式：

1. **取负数入堆**：存入 `-x`，取用时再取负
2. **自定义比较函数**：传入自定义比较函数（Python 3.5+ 支持）

`heapreplace` 操作是先 pop 再 push 的原子版本，若堆为空则抛出 `IndexError`。

### 堆与优先队列的分离

堆是一种数据结构，优先队列是一种抽象数据类型（ADT）。堆可以用数组实现（如本节所述），也可以用其他结构（如斐波那契堆、二叉堆的其他变体）。优先队列也可以用其他数据结构实现（如排序数组，push O(n)，pop O(1)）。

**设计权衡**：

| 实现方式 | push | pop（极值） | 适用场景 |
|----------|------|-------------|----------|
| 数组（无序） | O(1) | O(n) | 写多读少 |
| 数组（有序） | O(n) | O(1) | 读多写少 |
| 链表（有序） | O(n) | O(1) | 同上 |
| 二叉堆 | O(log n) | O(log n) | 读写均衡 |
| 斐波那契堆 | O(1)（均摊） | O(log n)（均摊） | 极致的 push 性能 |

### 合并有序文件（多路归并）

将每个有序文件的当前元素入堆，每次弹出最小值并从对应文件补充新元素：

- 初始：k 个文件，每个文件的第一个元素入堆，O(k log k)
- 每步：弹出堆顶（全局最小），O(log k)，并将对应文件的下一个元素入堆，O(log k)
- 总计：O(N log k)，其中 N 是总元素数

堆在此处扮演**动态多路归并**的角色，将原本需要将所有文件读入内存的归并操作转化为流式处理。

### 违规后果

- **堆性质被破坏后未修复**：堆顶可能不再是极值，导致优先队列给出错误的优先级顺序。
- **在 sift_down 过程中只比较一个子节点**：大顶堆中，如果只与左子比较而忽略右子，可能将较小的右子提升到堆顶，破坏堆序性。
- **pop 后未处理空堆**：对空堆执行 pop 操作，结果是未定义行为（Python 抛出 IndexError）。
- **数组实现中越界访问**：当节点 $i$ 的子节点下标 $2i+1$ 或 $2i+2$ 不小于堆大小时，必须停止下沉。

## 参考存根

```python
import heapq

def top_k(nums, k):
    """维护大小为 k 的小顶堆，返回第 k 大的数"""
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)
    return h[0]  # 堆顶是最小的，也就是第 k 大的
```

```python
def kth_smallest(matrix, k):
    """矩阵每行每列均递增，求第k小"""
    n = len(matrix)
    # 堆中存储 (值, 行索引, 列索引)
    heap = [(matrix[0][0], 0, 0)]
    visited = {(0, 0)}
    for _ in range(k - 1):
        val, i, j = heapq.heappop(heap)
        if i + 1 < n and (i + 1, j) not in visited:
            heapq.heappush(heap, (matrix[i + 1][j], i + 1, j))
            visited.add((i + 1, j))
        if j + 1 < n and (i, j + 1) not in visited:
            heapq.heappush(heap, (matrix[i][j + 1], i, j + 1))
            visited.add((i, j + 1))
    return heapq.heappop(heap)[0]
```
