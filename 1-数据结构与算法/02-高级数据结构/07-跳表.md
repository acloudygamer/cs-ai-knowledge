# 跳表

## 定义

> **版本基准**: universal

跳表是一种概率型数据结构，以**有序链表为底层结构，上层以概率 $p$ 建立快速通道**（指向更远节点的指针），使搜索从 $O(n)$ 降到期望 $O(\log n)$。

核心洞察：利用随机层高模拟平衡树的平衡效果，却无需复杂的旋转维护。随机性替代确定性平衡，是空间换时间的经典工程折中。

**与平衡树的本质区别**：平衡树通过旋转维护确定性平衡（树高有最坏保证），跳表通过概率分布维护期望平衡（树高期望 $O(\log n)$ 但存在退化极低概率）。

**资源视角**：跳表消耗**内存**（多层指针）和**随机数生成**。层高越高，搜索越快但内存越多。

## 数学模型

### 随机层高的分布

设最大层高为 $h$（实际实现中为常数上限，如 16 或 32）。每个新节点的层高 $h_i$ 服从几何分布：

$$
P(h_i = k) = p^{k-1}(1-p),\quad k = 1, 2, \ldots, h_{\max}
$$

通常取 $p = 0.5$，即每层有 50% 概率向上扩展。

**几何分布的物理含义**：每次"抛硬币"决定是否向上扩展一层，直到失败或达到最大层高。期望层高 $E[h_i] = \frac{1}{1-p}$。

**第 $k$ 层节点数的期望**：

$$
E[N_k] = n \cdot p^{k-1}
$$

这是因为每个节点独立有 $p^{k-1}$ 概率达到第 $k$ 层。

### 最大层高的集中不等式

当 $h_{\max} = \lceil \log_{1/p} n \rceil + c$ 时，由 Chernoff bound：

$$
P(\text{实际层高} > h_{\max}) \leq e^{-c}
$$

即层高关于 $n$ 呈对数增长，且高度集中——实际层高超过 $\log_{1/p} n + O(1)$ 的概率指数小。

**Chernoff bound 回忆**：若 $X_i \sim \text{Bernoulli}(p)$，则 $X = \sum X_i$ 偏离均值 $\mu = np$ 的概率 $P(X > (1+\delta)\mu) \leq e^{-\delta^2\mu/3}$。

应用到跳表：将每层是否"满"建模为 Bernoulli 过程，可证明最大层高的指数尾部。

### 期望查找路径长度

从最高层开始，每层最坏需遍历同层所有节点，但层内节点数期望为 $n \cdot p^{k-1}$，所以每层期望遍历 $\frac{1}{p}$ 个节点：

$$
E[\text{查找长度}] = \sum_{k=1}^{h_{\max}} \frac{1}{p} = \frac{h_{\max}}{p} = O\left(\frac{\log n}{p}\right) = O(\log n)
$$

**直观理解**：每向下一层，节点数减少为原来的 $p$（期望），所以每层只需遍历常数个节点（当 $p=0.5$ 时约 2 个）。

### 归约终点

跳表的本质是**以概率为权重的多级快速通道**，可归约为"带跳转的多层链表"——每层链表是下层链表的子集，按 rank（排名）组织。查找时从最高层出发，逐层逼近目标。

**与平衡树的关系**：跳表可视为"概率版本的平衡树"。平衡树的旋转维护平衡不变量，跳表的随机层高维护期望平衡。这两者的权衡：平衡树保证最坏 $O(\log n)$，跳表保证期望 $O(\log n)$ 但有极低概率退化。

## 数据流

### 跳表的多层结构

<pre>
Level 3 (最高层): HEAD ──────────────────────────────→ NIL
Level 2:         HEAD ──→ [1] ────────→ [5] ──────→ NIL
Level 1:         HEAD → [1] → [3] → [5] → [7] → [9] → NIL
Level 0 (底层):  HEAD → [1] → [2] → [3] → [4] → [5] → [6] → [7] → [8] → [9] → NIL

查找 7 的路径（用 ★ 标记遍历节点）:
  L3:  HEAD → ★[1] → ★NIL  (7 > 1, NIL > 7, 下降到 L2)
  L2:  ★[1] → ★[5]         (7 < 5, 下降到 L1)
  L1:  ★[1] → ★[3] → ★[5] → ★[7]  (找到)

实际遍历节点: [1, 1, 5, 1, 3, 5, 7] 共 7 次
理想遍历（无快通道）: 7 次；跳表遍历: 7 次（在此例中无显著优势，但随 n 增长优势明显）
</pre>

### 插入操作的数据形态变换

<pre>
插入 8.5 (新节点层高=2):
  1. 自底向上记录每层前驱指针: prev[0..2]
  2. 创建新节点 [8.5]，层高=2
  3. 每层执行插入: prev[k].forward[k] = new_node.forward[k]; prev[k].forward[k] = new_node

  prev[0] = 7  →  new_node.next = 8 → 7.next = new_node
  prev[1] = 5  →  new_node.next = 7 → 5.next = new_node
  prev[2] = NIL (无需修改，超出当前层高)

所有权: 新节点接管前驱的后继指针指向关系
</pre>

## 机制

### 为什么跳表比红黑树更适合并发？

**局部性修改**：插入/删除只影响 $O(\log n)$ 个节点，且只修改这些节点的最多 2 个指针域（forward 和 backward）。红黑树的平衡操作（旋转、重新染色）涉及父节点、祖父节点、叔节点等多个指针的联动修改。

**锁粒度**：在多线程跳表中，可以对每个节点单独加锁（乐观并发控制），而非对整棵树加锁。删除操作只需锁定要删除的节点及其前驱，而非像红黑树那样锁定多个祖先。

**Redis 的选择**：Redis Sorted Set 使用跳表而非红黑树，原因正是跳表的实现更简单（无旋转）、实现代码与 ziplist（压缩列表）相当，且可方便地支持范围操作（如 ZRANGEBYSCORE）。

### 层高的随机性：为什么是几何分布而非均匀分布？

几何分布保证了每升高一层概率指数衰减，从而自然地限制了最大层高。如果使用均匀分布（如每个节点等概率选择层 1..h），则期望有更多节点堆积在高层次，反而退化为普通链表。

**对比**：
- 均匀分布 $P(h_i = k) = 1/h$：第 $k$ 层期望节点数 $n/h$（常数），层高不退化
- 几何分布 $P(h_i = k) = p^{k-1}(1-p)$：第 $k$ 层期望节点数 $np^{k-1}$（指数衰减）

**几何分布的必要性证明**：设跳表有 $h$ 层，若每层节点数期望为常数 $c$，则总节点数为 $O(ch)$，而非 $\Theta(n)$。因此必须有某种机制使得高层次的节点数指数衰减。

### 跳表的删除：为什么需要 backward 指针？

跳表通常实现为双向链表（每节点有 forward 和 backward）。删除时：
1. 自底向上查找目标节点，每层记录前驱
2. 每层执行前驱的 forward 绕过目标节点
3. 更新各层前驱的 backward

若只有单向指针，删除时无法快速修改前驱的 forward 指向，必须自顶向下重新查找或从底层逐层向上锁定。

### 约束与违反后果

- **约束**：层高上限必须固定，否则内存分配不可预测
- **约束**：$p$ 值影响时间/空间权衡；$p$ 越大层高期望越大，空间开销增加但查找可能更快（$p=0.5$ 是典型选择）
- **违反后果**：若 $p=1$（每节点层高无限增长），跳表退化为底层链表 + 多层冗余副本（空间爆炸）
- **概率保证**：期望 $O(\log n)$ 而非最坏 $O(n)$；存在极低概率的退化路径（与红黑树的最坏保证不同）

### 跳表与平衡树的统一视角

两者都是有序集合的实现，权衡不同：

| 维度 | 跳表 | 红黑树 |
|------|------|--------|
| 最坏查找 | $O(n)$ | $O(\log n)$ |
| 期望查找 | $O(\log n)$ | $O(\log n)$ |
| 插入/删除 | $O(\log n)$ 期望 | $O(\log n)$ 最坏 |
| 实现复杂度 | 低（无旋转） | 高（旋转+染色） |
| 并发友好度 | 高（局部修改） | 低（跨节点锁） |
| 内存开销 | $O(n \cdot E[h_i])$ | $O(n)$（指针开销小） |

## 参考存根

```python
import random

class SkipNode:
    def __init__(self, val, level):
        self.val = val
        self.forward = [None] * (level + 1)
        self.backward = None

class SkipList:
    def __init__(self, max_level=16, p=0.5):
        self.max_level = max_level
        self.p = p
        self.hdr = SkipNode(float('-inf'), max_level)
        self.level = 0

    def _random_level(self):
        lvl = 1
        while random.random() < self.p and lvl < self.max_level:
            lvl += 1
        return lvl

    def search(self, target):
        path = [None] * (self.max_level + 1)
        cur = self.hdr
        for i in range(self.level, -1, -1):
            while cur.forward[i] and cur.forward[i].val < target:
                cur = cur.forward[i]
            path[i] = cur
        cur = cur.forward[0]
        return cur and cur.val == target

    def insert(self, val):
        lvl = self._random_level()
        new_node = SkipNode(val, lvl)
        path = [None] * (self.max_level + 1)
        cur = self.hdr
        for i in range(self.level, -1, -1):
            while cur.forward[i] and cur.forward[i].val < val:
                cur = cur.forward[i]
            path[i] = cur
        for i in range(lvl + 1):
            new_node.forward[i] = path[i].forward[i]
            path[i].forward[i] = new_node
        if lvl > self.level:
            self.level = lvl
        # 设置 backward 指针
        if new_node.forward[0]:
            new_node.forward[0].backward = new_node
        new_node.backward = path[0]
```
