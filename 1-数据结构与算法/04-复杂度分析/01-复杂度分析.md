# 复杂度分析

## 定义

复杂度分析是用**渐进记号**描述算法性能随输入规模增长的尺度定律：通过忽略硬件/编译器/语言相关的常数因子，将算法性能抽象为输入规模 $n$ 的函数 $T(n)$，实现在数学上严格比较不同算法的增长趋势。

与实验测量不同，复杂度分析不依赖具体运行环境——$O(n \log n)$ 的归并排序在任何硬件上始终优于 $O(n^2)$ 的冒泡排序（对足够大的 $n$）。这一保证来源于**极限的阶的比较**，而非经验观测。

## 数学模型

### 渐进记号的约束系统

设 $f(n)$ 和 $g(n)$ 为定义在自然数集 $\mathbb{N}$ 上的**非负**函数。渐进记号本质上是**存在性量词约束的不等式系统**。

**紧确界 $\Theta(g(n))$**——双向夹逼：

$$
\Theta(g(n)) = \left\{ f(n) : \exists c_1, c_2, n_0 > 0,\ \forall n \geq n_0,\ 0 \leq c_1 g(n) \leq f(n) \leq c_2 g(n) \right\}
$$

约束条件：$c_1, c_2$ 是与 $n$ 无关的正常数，$n_0$ 是收敛起始点。违反约束时：若不存在这样的常数对，则 $f(n) \notin \Theta(g(n))$——例如 $f(n) = n(1 + \sin n)$ 无法被任何 $g(n)$ 双向夹逼，因为其在 $n$ 轴附近无限振荡。

**上界 $O(g(n))$**——单向夹逼（上侧）：

$$
O(g(n)) = \left\{ f(n) : \exists c, n_0 > 0,\ \forall n \geq n_0,\ 0 \leq f(n) \leq c g(n) \right\}
$$

**下界 $\Omega(g(n))$**——单向夹逼（下侧）：

$$
\Omega(g(n)) = \left\{ f(n) : \exists c, n_0 > 0,\ \forall n \geq n_0,\ 0 \leq c g(n) \leq f(n) \right\}
$$

**非紧确上界 $o(g(n))$**——严格小于（无常数倍关系）：

$$
o(g(n)) = \left\{ f(n) : \forall c > 0,\ \exists n_0,\ \forall n \geq n_0,\ f(n) < c g(n) \right\}
$$

注意 $O$ 是存在性量词（$\exists c$），$o$ 是全称量词（$\forall c$）。$f(n) = O(n^2)$ 意味着"存在常数使 $f$ 被 $n^2$ 控制"，而 $f(n) = o(n^2)$ 意味着"无论多小的正常数 $c$，$n$ 足够大时 $f(n)$ 总小于 $c n^2$"。

**归约终点**：四种渐进记号（$\Theta, O, \Omega, o$）均可归约为**集合包含关系**——$f(n) \in O(g(n))$ 当且仅当 $\exists c, n_0: f(n) \leq c g(n)$ 对所有 $n \geq n_0$ 成立。这将算法复杂度比较转化为实数不等式系统的可满足性判定。

### 复杂度等级的全序结构

$$
O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
$$

**约束**：此全序关系在 $n \to \infty$ 时成立。对任意两个不同的复杂度等级 $a(n)$ 和 $b(n)$，若 $\lim_{n \to \infty} a(n)/b(n) = 0$，则 $a(n) = o(b(n))$。在足够大的 $n$ 下，低等级算法必然优于高等级算法。

**工程含义**：实际应用中，$O(n!)$ 和 $O(2^n)$ 仅在小规模问题中可接受；$O(n^3)$ 是矩阵运算的分水岭；$O(n^2)$ 对 $n > 10^4$ 通常不可接受；$O(n \log n)$ 是排序问题的理论下界（比较排序）。

### Master 定理（递归复杂度分析的约束边界）

对于形如 $T(n) = aT(n/b) + f(n)$ 的递归式，$a \geq 1,\ b > 1$，共有三种情况：

| 条件（约束） | 结论 | 物理含义 |
|---|---|---|
| $f(n) = O(n^{\log_b a - \varepsilon}),\ \varepsilon > 0$ | $T(n) = \Theta(n^{\log_b a})$ | 叶子节点的计算量主导，递归树的叶节点数增长抵消了每叶计算量的下降 |
| $f(n) = \Theta(n^{\log_b a} \log^k n),\ k \geq 0$ | $T(n) = \Theta(n^{\log_b a} \log^{k+1} n)$ | 合并代价与递归代价在所有层上保持同阶 |
| $f(n) = \Omega(n^{\log_b a + \varepsilon}),\ \varepsilon > 0)$ 且正则条件 | $T(n) = \Theta(f(n))$ | 根节点（合并操作）的计算量主导，递归深度足够大时压制叶子增长 |

**正则条件**：$a f(n/b) \leq c f(n)$ 对某个 $c < 1$ 成立（_subadditivity condition_）。违反此条件时，即使 $f(n)$ 增长快于 $n^{\log_b a}$，也不能直接应用第三种情况，需用递归树或代入法分析。

**不适用场景**：
- 子问题规模不对等（如 $T(n) = T(n-1) + T(n/2) + O(n)$，两子问题规模不同）
- 合并代价含对数因子（如 $T(n) = 2T(n/2) + n \log n$，不满足任何一种条件）
- 非多项式分裂（$b$ 不是常数）

### 摊还分析的势能守恒模型

摊还分析的本质是**跨时间步的能量守恒定律**：某些操作的"过度消耗"预先以势能形式存储，供后续操作"免费"使用，使单次最坏代价与长期平均代价解耦。

**聚合分析**（无势能显式建模）：对 $n$ 次操作总代价 $T(n)$，摊还代价 $\hat{c} = T(n)/n$。

**势能方法**（显式守恒量）：

设 $\Phi(D_i)$ 为第 $i$ 次操作后数据结构 $D$ 的势能。摊还代价：

$$
\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1}) = c_i + \Delta \Phi_i
$$

其中 $c_i$ 是第 $i$ 次操作的实际代价。$\Phi$ 的设计需满足：

- **有界性**：$\Phi(D_i) \geq 0$（势能非负）
- **初始条件**：$\Phi(D_0) = 0$（空结构势能为零）
- **上界性质**：总摊还代价 $\sum \hat{c}_i \geq$ 总实际代价 $\sum c_i$（保证上界）

**违反约束**：若 $\Phi$ 设计不当（如无下界），则 $\sum \hat{c}_i$ 可能小于 $\sum c_i$，摊还上界失效。正确设计下，总实际代价不超过总摊还代价。

**核算法**（预付费能量）：每次操作预先支付固定费用，存入"信用"账户；实际代价从信用中扣除。若某操作实际代价高于预付额，信用账户不得为负——这等价于势能函数的另一种表述。

时间复杂度 $T(n)$ 描述算法执行步数随输入规模的增长；空间复杂度 $S(n)$ 描述算法使用的存储单元数量。两者在递归型算法中具有不对称性：时间复杂度取决于递归树的总节点数（指数级可达 $O(2^n)$），而空间复杂度仅取决于树的最大深度（通常是 $O(\log n)$ 或 $O(n)$）。

### 递归树展开（时间代价的数据流视角）

$T(n) = 2T(n/2) + n$ 的递归树展开——每层总代价恒为 $n$：

<pre>
层号 i:    节点数              每节点代价           该层总代价
─────────────────────────────────────────────────────────
i = 0:     2^0 = 1            n                   n
i = 1:     2^1 = 2            n/2                 n
i = 2:     2^2 = 4            n/4                 n
...
i = L:     2^L = n            n/n = 1             n
─────────────────────────────────────────────────────────
树高 L = log₂n，总层数 log₂n + 1
总代价 = n · (log₂n + 1) = Θ(n log n)
</pre>

**数据形态变换**：递归树每下沉一层，子问题规模减半（$n \to n/2$），同时节点数翻倍（$1 \to 2$），两者乘积保持常数——这是分治算法能否达到线性对数阶的关键约束。子问题规模衰减与节点数增长的精确平衡决定了总代价的阶。

### 势能方法的数据流（以栈的 multipop 为例）

<pre>
操作序列: push(x1), push(x2), push(x3), multipop(3)

势能函数 Φ(栈) = 栈中元素个数

步骤      实际代价 c_i    势能变化 ΔΦ_i    摊还代价 ĉ_i = c_i + ΔΦ_i
──────────────────────────────────────────────────────────────────
push(x1)      1           +1              2
push(x2)      1           +1              2
push(x3)      1           +1              2
multipop(3)   3           -3              0
──────────────────────────────────────────────────────────────────
总实际代价 = 6    总摊还代价 = 6（摊还 O(1) = 6/4）
</pre>

**关键观察**：multipop 的高实际代价（3）被之前 push 操作预先支付的势能（+1 each）完全覆盖，使得单次操作的摊还代价降至 0。这体现了跨操作序列的代价转移机制——某一时刻的高代价操作，其成本实际上由之前多个低代价操作共同承担。

### 空间复杂度的数据流（递归调用栈）

<pre>
输入数据（堆/全局区）
    │

│  │ 栈帧 0: main()                   ││

**时间与空间的不对称性**：递归算法中，时间复杂度取决于递归树的总节点数（指数级可达 $O(2^n)$），而空间复杂度仅取决于树的最大深度（通常是 $O(\log n)$ 或 $O(n)$）。例如无 memo 的斐波那契递归——时间 $O(2^n)$，空间 $O(n)$。

## 机制

### 渐进记号为何能忽略常数和低阶项？

**数学必然性**：渐进记号的核心是**极限的阶的比较**。设 $f(n) = 1000n + 3$，$g(n) = n^2$：

$$
\lim_{n \to \infty} \frac{f(n)}{g(n)} = \lim_{n \to \infty} \frac{1000n + 3}{n^2} = 0
$$

因此 $1000n + 3 = o(n^2)$，无论常数 1000 有多大，当 $n > 1000$ 时 $1000n < n^2$。

**约束**：渐近优势只在 $n \to \infty$ 时成立。实际工程中存在**交叉点 $n^*$**，在 $n < n^*$ 时低阶算法反而更快。复杂度分析给出的是 $n \to \infty$ 的理论保证，不考虑实际数据分布。

**违反约束的后果**：对小规模固定数据集盲目套用渐进分析，可能选出一个常数因子极差的高阶算法。例如 $O(n^2)$ 的快速排序（实际常数小）常优于 $O(n \log n)$ 的归并排序（Cache 不友好）。

### 复杂度分析的类型体系（为何需要区分 worst/average/best）

同一算法对不同输入表现差异巨大，复杂度分析用三类 case 捕获这个光谱：

**最坏情况 $T_{worst}(n) = \max_{x \in D_n} T(x)$**：输入空间中使代价最大的那个输入。这提供了算法性能的上界承诺——"无论输入如何，运行时间不会超过 $T_{worst}(n)$"。

**平均情况 $T_{avg}(n) = \mathbb{E}_{x \in D_n}[T(x)]$**：假设输入服从某分布（通常为均匀分布）的期望代价。这依赖输入分布假设，适用范围受限。

**最好情况 $T_{best}(n) = \min_{x \in D_n} T(x)$**：输入空间中使代价最小的那个输入。描述算法对最优输入的处理能力。

**约束**：最好情况和平均情况不提供与最坏情况相同的工程保证。最坏情况分析是算法选型的标准，因为它无需输入分布假设。

**典型例子**：快速排序的最坏情况 $T_{worst}(n) = \Theta(n^2)$（已排序输入），但平均情况 $T_{avg}(n) = \Theta(n \log n)$，且随机化快速排序通过打乱输入使最坏情况在实际中几乎不出现。

### Master 定理的三种情况的物理图像

递归式 $T(n) = aT(n/b) + f(n)$ 的递归树中：

**第一种情况**（$f(n) = O(n^{\log_b a - \varepsilon})$）：每层递归节点数增长的速度（$a^i$）快于每节点代价下降的速度（$(n/b^i)$），最终叶子节点（$n^{\log_b a}$ 个）的计算量之和主导总代价。物理图像：递归树的"重量"集中在最底层。

**第二种情况**（$f(n) = \Theta(n^{\log_b a} \log^k n)$）：每层总代价恒为 $n^{\log_b a} \log^i n$ 量级，递归深度 $\log n$ 乘以每层代价得到 $n^{\log_b a} \log^{k+1} n$。物理图像：递归树每一层都同等重要。

**第三种情况**（$f(n) = \Omega(n^{\log_b a + \varepsilon})$ 且正则）：根节点的合并代价 $f(n)$ 增长快于子问题递归代价的叠加，使得递归树顶层的少数节点贡献了大部分代价。物理图像：递归树的"重量"集中在最顶层。

**违反正则条件的后果**：若 $a f(n/b) > c f(n)$ 对所有大 $n$ 成立（如 $f(n) = n!$），则第三种情况不适用，此时需用递归树做显式求和。

### 摊还分析与概率分析的根本区别

两者都给出"平均"意义上的界限，但保证的性质不同：

**摊还分析**（确定性的）：对**任意输入序列**（worst-case sequence），总代价有上界 $\sum \hat{c}_i$。不依赖输入分布，提供确定性保证。

**概率分析**（随机的）：对**随机抽取的输入**，期望代价为 $\mathbb{E}[T(x)]$。依赖输入分布模型，若实际分布偏离假设，保证失效。

一个算法可以同时满足"摊还 $O(1)$"（确定性地每个操作均摊常数）和"最坏情况 $O(n)$"（某个单次操作代价高达 $n$）。摊销 $O(1)$ 不意味着每个操作都是 $O(1)$，而是序列总代价被常数控制。

### 空间复杂度的递归栈约束

递归调用栈的空间消耗由**最大递归深度**决定，而非总递归调用次数：

- 二分查找：递归深度 $O(\log n)$，每次调用 $O(1)$ 空间（仅栈帧），总空间 $O(\log n)$
- 归并排序：递归深度 $O(\log n)$，另需 $O(n)$ 的归并缓冲区，总空间 $O(n + \log n) = O(n)$
- 无 memo 斐波那契：递归深度 $O(n)$，但每次递归后返回并释放栈帧，所以最大栈深度就是 $O(n)$

**约束**：尾递归优化可将 $O(n)$ 递归深度降至 $O(1)$ 空间（若语言/编译器支持），但这改变了算法结构（不再是显式递归）。

**违反约束**：递归深度超过系统栈大小（Linux 默认约 8MB，对应约百万级递归深度）时触发栈溢出（stack overflow）。

## 参考存根

```python
# 斐波那契递归：时间指数爆炸，空间线性
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)
# T(n) = T(n-1) + T(n-2) + O(1) = O(2^n)
# 最大递归深度 = n（每条路径走到最深处才返回），空间 O(n)

# 归并排序：递归树深度对数，时间线性对数，空间线性
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])   # T(n/2)
    right = merge_sort(arr[mid:])  # T(n/2)
    return merge(left, right)      # O(n) 合并
# T(n) = 2T(n/2) + O(n) → Master 定理第二种情况：Θ(n log n)
# 递归深度 = log n，每层需 O(n) 临时空间存合并结果，总空间 O(n)

# 摊还分析示例：二进制计数器递增
def increment(counter):  # counter 为 k 位二进制数组
    i = 0
    while i < len(counter) and counter[i] == 1:
        counter[i] = 0   # 进位
        i += 1
    if i < len(counter):
        counter[i] = 1   # 设最低的 0 为 1
# 最坏情况代价 = k（全1时进位k次），但n次操作总代价 = O(n + k)
# 每次 0→1 支付信用，1→0 由之前积累的信用支付，摊还代价 O(1)
```
