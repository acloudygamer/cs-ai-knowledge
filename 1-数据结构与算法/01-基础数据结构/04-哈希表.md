# 哈希表

## 定义

哈希表是键值对存储结构，通过哈希函数 $h: \text{Key} \rightarrow [0, m-1]$ 将键映射为桶索引，在均匀分布假设下实现平均 O(1) 的查找、插入、删除。冲突不可避免，但可通过扩容和冲突解决策略将冲突概率控制在可接受范围内。

## 数学模型

### 哈希函数均匀性假设

设哈希函数 $h$ 将键空间 $\mathcal{K}$ 均匀映射到 $m$ 个桶，则每个桶期望容纳 $\alpha = n/m$ 个元素（负载因子）。

### 负载因子与冲突概率

对于均匀哈希，单个键查到特定桶的概率为 $1/m$。插入 $n$ 个键后，特定桶为空桶的概率：
$$P(\text{桶为空}) = \left(1 - \frac{1}{m}\right)^n \approx e^{-n/m} = e^{-\alpha}$$

### 扩容决策

令 $n$ 为元素数，$m$ 为桶数。设扩容阈值为 $\tau$（通常 $\tau = 0.75$）。当 $\alpha > \tau$ 时触发扩容：
$$m_{\text{new}} = m \cdot k \quad (k > 1, \text{通常取 } 2)$$

扩容后负载因子降为 $\alpha/k$，冲突概率指数下降。

### 布隆过滤器假阳性率

设位数组大小为 $m$，插入 $n$ 个元素，使用 $k$ 个独立哈希函数。某一位在插入后仍为 0 的概率：
$$P(0) = \left(1 - \frac{1}{m}\right)^{kn} \approx e^{-\frac{kn}{m}}$$

假阳性（某不在集合中的元素，其 $k$ 位全为 1）的概率：
$$p = (1 - e^{-\frac{kn}{m}})^k$$

最优哈希函数数量（使 $p$ 最小）：
$$k_{\text{opt}} = \frac{m}{n} \ln 2 \approx 0.7 \frac{m}{n}$$

给定目标假阳性率 $p$，所需位数组大小：
$$m_{\text{opt}} = -\frac{n \ln p}{(\ln 2)^2}$$

**归约终点**：哈希表的时间复杂度归约为哈希函数计算 $O(1)$ + 冲突解决（链地址法 O(1+α) 或开放地址法 O(1/(1-α))）。当 $\alpha$ 维持在对数倒数级别时，均摊操作常数为 $O(1)$。

**数据形态变换**：

1. 键（任意可哈希对象）→ 哈希值（整数，通过 hash 函数）
2. 哈希值 → 桶索引（取模 $m$）
3. 桶内查找：索引 → 链表/红黑树/连续槽位 → 精确键比较
4. 扩容时：所有键重新计算哈希 → 重新分配桶数组（所有权整体转移）

**布隆过滤器数据流**：

<pre>
添加 "example":
  输入字符串 → 哈希函数1 → 位位置 h1
  输入字符串 → 哈希函数2 → 位位置 h2
  输入字符串 → 哈希函数3 → 位位置 h3
  位数组: [0,0,1,0,0,1,0,1]  (位置2,5,7置1)

查询 "example":
  计算 h1,h2,h3 → 检查位数组对应位置
  全为1 → 报告"可能存在"（真阳性或假阳性）
  任一位为0 → 报告"必定不存在"（真阴性）

数据所有权：位数组原地修改，无复制
</pre>

## 机制

### 哈希函数的设计原则

均匀性：哈希值应均匀分布在桶数组上。若分布不均（聚集），部分桶过长，退化为链表查找 O(n)。

雪崩效应：输入微小变化应导致哈希值大幅变化，防止特定模式键聚集到少数桶。

计算成本：复杂哈希函数（如加密哈希）虽分布好，但每次操作均有代价。在性能和均匀性间取平衡是工程决策。

### 负载因子与扩容时机

当 $\alpha$ 过大时，桶内冲突加剧。链地址法下 $\alpha > 1$ 时链表平均长度 $> 1$；开放地址法下 $\alpha > 0.7$ 时探测序列显著增长。

扩容代价：$O(n)$ 重新计算所有键的哈希并分配新桶数组。这是不可避免的，但通过指数扩容（每次容量翻倍），使均摊代价为 $O(1)$。

### 冲突解决：链地址法 vs 开放地址法

链地址法：桶内用链表（$O(\alpha)$ 查找）或红黑树（$O(\log \alpha)$ 查找）存储冲突元素。优点：删除简单，聚集不传播。缺点：指针间接访问，缓存不友好。

开放地址法：冲突时按探测序列（线性 $h(k)+i$、二次 $h(k)+i^2$、双重哈希 $h_1(k)+i\cdot h_2(k)$）寻找空桶。优点：连续内存，缓存友好。缺点：删除复杂（墓碑标记），聚集效应（一次聚集：线性探测；二次聚集：二次探测），探测序列增长。

### 布隆过滤器的语义保证

允许假阳性：查询返回"可能存在"时，该元素可能实际不在集合中。
不允许假阴性：查询返回"必定不存在"时，该元素必定不在集合中。

这源于位数组的位只能从 0 置 1、从不能从 1 置 0 的单调性。删除操作无法实现（将位从 1 改回 0 会影响其他元素）。

### 违反约束的后果

- 哈希函数不均匀：负载因子正常但查找退化至 O(n)，性能劣化不可预测。
- 开放地址法删除不当：墓碑过多导致探测序列膨胀，查找性能退化为 O(n)。
- 布隆过滤器位数组过小：假阳性率飙升，存储校验失效（应用逻辑需容忍假阳性）。
- 扩容时未重新哈希：部分键仍映射到旧桶索引，查找时键"丢失"（永久数据丢失）。

## 对比参照

| 特性 | 链地址法 | 开放地址法 |
|------|----------|------------|
| 查找复杂度 | $O(1+\alpha)$ | $O(1/(1-\alpha))$（近似） |
| 删除 | O(1)（链表节点摘除） | O(1)（墓碑，需定期重建） |
| 缓存友好性 | 差（指针跳转） | 好（连续内存） |
| 聚集效应 | 无 | 一次聚集/二次聚集 |
| 负载因子上限 | 可 $> 1$ | 通常 $< 0.75$ |

```python
class HashMap:
    def __init__(self, capacity=4, load_factor=0.75):
        self.capacity = capacity
        self.load_factor = load_factor
        self.size = 0
        self.buckets = [[] for _ in range(capacity)]

    def _hash(self, key):
        return hash(key) % self.capacity

    def _resize(self):
        old_buckets = self.buckets
        self.capacity *= 2
        self.buckets = [[] for _ in range(self.capacity)]
        self.size = 0
        for bucket in old_buckets:
            for k, v in bucket:
                self.put(k, v)

    def put(self, key, value):
        if self.size / self.capacity > self.load_factor:
            self._resize()
        idx = self._hash(key)
        bucket = self.buckets[idx]
        for i, (k, _) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, value)
                return
        bucket.append((key, value))
        self.size += 1

    def get(self, key):
        idx = self._hash(key)
        for k, v in self.buckets[idx]:
            if k == key:
                return v
        return None
```

class BloomFilter:
    def __init__(self, n, p):
        import math
        m = int(-n * math.log(p) / math.log(2)**2)
        k = int(m / n * math.log(2))
        self.bits = [0] * m
        self.m, self.k = m, k

    def _hashes(self, item):
        import hashlib
        h = int(hashlib.md5(str(item).encode()).hexdigest(), 16)
        return [(h + i * h) % self.m for i in range(self.k)]

    def add(self, item):
        for idx in self._hashes(item):
            self.bits[idx] = 1

    def might_contain(self, item):
        return all(self.bits[idx] for idx in self._hashes(item))
