# 哈希表

## 定义

哈希表通过哈希函数将键映射到桶索引，在理想情况下实现 O(1) 平均查找、插入、删除。

## 数学模型

**布隆过滤器假阳性率**

设位数组大小为 $m$，插入 $n$ 个元素，使用 $k$ 个哈希函数。

某一位在插入后仍为 0 的概率：

$$
P(0) = \left(1 - \frac{1}{m}\right)^{kn} \approx e^{-\frac{kn}{m}}
$$

假阳性率（k 位全为 1）：

$$
p = (1 - e^{-\frac{kn}{m}})^k
$$

**最优参数**

$$
k_{opt} = \frac{m}{n} \ln 2 \approx 0.7\frac{m}{n}
$$

$$
m_{opt} = -\frac{n \ln p}{(\ln 2)^2}
$$

## 数据流

**哈希表插入**

<pre>
插入 "hello":
  hash("hello") % 4 = 2
  桶2: [("hello", val)]
冲突: hash("world") % 4 = 2
  桶2: [("hello", v1), ("world", v2)]  ← 链地址法
</pre>

**布隆过滤器添加与查询**

<pre>
添加 "example":
  计算 3 个哈希位置: h1=2, h2=5, h2=7
  位数组: [0,0,1,0,0,1,0,1]

查询 "example":
  位置 2=1, 5=1, 7=1 → 可能存在（真阳性或假阳性）

查询 "other":
  位置 3=0 → 必定不存在
</pre>

## 机制

**哈希函数决定键分布**

好的哈希函数使键均匀分布到各桶，冲突少，效率趋近 O(1)。

**负载因子影响性能**

$\alpha = n/m$，$\alpha$ 过大时冲突加剧，需要扩容（通常 $\alpha > 0.75$ 触发）。

**冲突解决策略**

- 链地址法：桶内用链表/红黑树存储冲突元素
- 开放地址法：线性探测/二次探测寻找空桶

**布隆过滤器空间换时间**

允许假阳性（报告存在但实际不存在），不允许假阴性（报告不存在但实际存在）。

**违规后果**

- 哈希函数设计差：所有键聚集到少数桶，退化为 O(n)
- 扩容时未正确重新哈希：键丢失
- 布隆过滤器位数组过小：假阳性率飙升

```python
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []
```

```python
class BloomFilter:
    def __init__(self, n, p):
        import math
        m = int(-n * math.log(p) / math.log(2)**2)
        self.k = int(m / n * math.log(2))
        self.bits = [0] * m

    def _hash(self, item, i):
        import hashlib
        h = int(hashlib.md5(str(item).encode()).hexdigest(), 16)
        return (h + i * h) % len(self.bits)

    def add(self, item):
        for i in range(self.k):
            self.bits[self._hash(item, i)] = 1

    def might_contain(self, item):
        return all(self.bits[self._hash(item, i)] for i in range(self.k))
```
