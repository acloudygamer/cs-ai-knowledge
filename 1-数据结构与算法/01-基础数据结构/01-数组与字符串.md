# 数组与字符串

## 定义

> **版本基准**: universal

数组是连续内存中同构元素的空间排列，支持 O(1) 随机访问；字符串是不可变的字符序列，对其操作需创建新副本。两者共享同一物理模型——连续内存地址空间——但字符串在语言层施加了只读约束，导致数据流行为与可变数组截然不同。

**本质区别**：数组通过公式 $\text{addr}(i) = B + i \times s$ 实现直接寻址；字符串通过不可变语义将写操作转化为"分配-复制-销毁"的数据流。

## 数学模型

### 一维前缀和

设原数组为 $arr[0..n-1]$ ，构造辅助数组 $prefix[0..n]$ ，其中 $prefix[0] = 0$ 为哨兵：

$prefix[i+1] = prefix[i] + arr[i], \quad i \in [0, n-1]$

区间 $[l, r]$ （含端点）的和：

$S(l, r) = prefix[r+1] - prefix[l]$

**正确性证明**（归纳）：

- 基准： $l = r$ 时，  $S(l, l) = prefix[l+1] - prefix[l] = arr[l]$，成立。
- 归纳：假设对所有区间长度 $< k$ 成立，对长度 $k$ 的区间 $[l, r]$ 有：

$prefix[r+1] - prefix[l] = \sum_{i=0}^{r} arr[i] - \sum_{i=0}^{l-1} arr[i] = \sum_{i=l}^{r} arr[i] \quad \blacksquare$

查询时间复杂度 O(1)，构建时间 O(n)。若执行 $Q$ 次区间查询，总代价 $O(n + Q)$ ，均摊 $O(1)$ 。

**归约终点**：前缀和查询本质是**阿贝尔群上的区间求和**，通过预计算将每次查询从 $O(n)$ 降至 $O(1)$ 。

### 二维前缀和

设原矩阵 $A[r][c]$ ，构造 $prefix[r+1][c+1]$ ：

$prefix[i+1][j+1] = A[i][j] + prefix[i][j+1] + prefix[i+1][j] - prefix[i][j]$

子矩阵 $(r_1, c_1)$ 到 $(r_2, c_2)$ （含端点）的和：

$S = prefix[r_2+1][c_2+1] - prefix[r_1][c_2+1] - prefix[r_2+1][c_1] + prefix[r_1][c_1]$

包含-排除原理的几何意义：将大矩形减去左、上两个伸出部分，加上左上角被重复减去的部分。

**归约终点**：二维前缀和是**包含-排除原理在离散网格上的直接应用**，其数学本质是有限域上的二重求和。

### 差分数组

对数组 $arr$ 构造差分数组 $diff$ ：

$diff[i] = \begin{cases} arr[0] & i = 0 \\ arr[i] - arr[i-1] & i > 0 \end{cases}$

区间 $[l, r]$ 加 $\Delta$ 的等价操作：

$diff[l] += \Delta, \quad diff[r+1] -= \Delta$

还原： $arr[i] = \sum_{j=0}^{i} diff[j]$ （前缀和）。差分使区间更新从 O(r-l) 降至 O(1)，代价是查询从 O(1) 变为 O(n)。

**归约终点**：差分是**离散微分算子**，还原是**离散积分算子**。两者互为逆操作，对应连续数学中 $\frac{d}{dx}$ 和 $\int dx$ 的关系。

### 数组随机访问的地址公式

设数组基地址为 $B$ ，元素大小为 $s$ 字节，元素 $i$ 的地址：

$\text{addr}(i) = B + i \times s$

此为物理寻址公式，仅在连续内存假设下成立。推导：第 0 个元素地址为 $B$ ，第 1 个为 $B+s$ ，归纳可得通式。

**归约终点**：随机访问的 O(1) 理论上限归约到**整数的加法与乘法**，在现实硬件上受限于内存层次（缓存行、预取）的实际访存延迟。

### 字符串不可变的数学约束

字符串不可变本质是对操作集合的约束：任意字符串操作 $f: \text{String} \rightarrow \text{String}$ 必须满足 $f(s) \neq s$ 蕴含 $f(s)$ 是新分配对象。

设字符串内容为 $c$ ，引用计数为 $ref$ 。不可变语义保证：
$| \{ c \mid \text{所有指向该内容的引用观察到相同值} \} | = 1$

这等价于**事件顺序的偏序关系**：所有读操作必须在任何写操作之前（写操作不存在，因此偏序退化为全序）。

## 数据流

### 数组物理内存布局

<pre>
内存地址  B      B+s      B+2s    B+3s     ...   B+(n-1)s
          ┌────────┬────────┬────────┬────────┐
数组 arr  │ arr[0] │ arr[1] │ arr[2] │ arr[3] │  ...  │ arr[n-1] │
          └────────┴────────┴────────┴────────┘
          └── 元素大小 s 字节，连续排列，无间隔 ──┘
                              │
              读取 arr[i] 只需一次地址计算：
              物理地址 = B + i*s  ──→  直接访存
                              │
                  ┌───────────┴───────────┐
                  │ CPU 缓存行加载 (64B)   │
                  │ 一次加载 连续 s*8 个元素│
                  │ 空间局部性：访问 arr[i] │
                  │ 很可能 arr[i+1..i+7]  │
                  │ 已在缓存中             │
                  └───────────────────────┘
</pre>

**数据所有权转移**：
- 栈上数组：所有权随函数调用栈帧的销毁自动释放
- 堆上数组：所有权通过引用计数或 GC 管理

### 字符串拼接的数据流

<pre>
字符串 "hello" (不可变对象)
  地址: 0x1000，内容: ['h','e','l','l','o']
  引用计数: N (多个引用指向同一对象)

执行 s += "world"：
  1. 在堆上分配新对象 0x2000
  2. 复制 "hello" + "world" → "helloworld"
  3. s 现在指向 0x2000
  4. 原 0x1000 引用计数 -1（若归零则 GC 回收）
  5. 所有权从原对象转移给新对象

关键约束：拼接不修改原对象，任何持有引用的其他变量不受影响。
这正是"不可变"的核心语义保证。
</pre>

### 数据形态变换总结

| 操作 | 输入形态 | 中间形态 | 输出形态 | 所有者 |
|------|---------|---------|---------|--------|
| `arr[i]` 读取 | 下标 i | 物理地址 B+i*s | 数据值 | 调用者 |
| `arr[i] = x` 写入 | 值 x | 物理地址 B+i*s | 覆盖原值 | 数组结构 |
| `s1 + s2` 拼接 | 两个不可变对象 | 分配新堆对象 | 新字符串对象 | 调用者 |
| `s.hash()` | 字符串对象 | 计算哈希 | 哈希值（可缓存） | 调用者 |

## 对比参照

| 属性 | 数组（可变） | 链表 | 字符串 |
|------|-------------|------|--------|
| **内存模型** | 连续物理地址 | 离散节点，通过指针链接 | 连续地址（或引用数组）+ 不可变约束 |
| **随机访问** | O(1)（地址公式） | O(n)（需遍历） | O(1)（视为字符数组） |
| **插入/删除** | O(n)（需移动后续元素） | O(1)（修改指针） | O(n)（需创建新副本） |
| **空间开销** | 无额外指针开销 | 每个节点需存储 next 指针 | 无指针开销，但拼接需全量复制 |
| **缓存友好性** | 高（连续加载，缓存行有效） | 低（节点可能散落各处） | 高（连续），但写操作缓存污染严重 |
| **数据流** | 可变：写操作直接覆盖，无复制 | 可变：指针重定向实现 O(1) 插入/删除 | 不可变：所有写操作产生新副本 |

## 机制

### 连续内存与 O(1) 随机访问

数组的核心物理保证是**逻辑连续性**：逻辑上下标 $i$ 到物理地址的映射是线性函数，而非查找表或遍历。这意味着 CPU 无需沿链表逐节点跳转，只需一次乘法+一次加法即可直接计算目标地址。

**关键约束**：此保证依赖数组大小在编译期或分配时确定，且分配后不可改变。若需要动态增长，必须分配新数组并复制——这正是 `vector`/`list` 在动态场景下分叉的根本原因。

**违反约束的后果**：若在已分配的数组范围外写入（越界访问），行为未定义——可能覆盖相邻内存（缓冲区溢出），这是 C/C++ 中最常见的漏洞根因之一。

**数学建模**：越界访问可建模为地址公式的外推：
$\text{addr}(i) = B + i \times s, \quad i \notin [0, n-1]$
结果指向数组外的任意地址，写入会破坏其他变量的值。

### 缓存行效应与空间局部性

连续内存的另一个关键优势是**缓存行预取**。现代 CPU 缓存行宽度为 64 字节。当访问 `arr[i]` 时，整个缓存行（含 `arr[i]` 所在位置及其后若干元素）被加载到 L1 缓存。若顺序访问 `arr[i], arr[i+1], ...`，后续访问命中缓存的概率大幅提升，实践中比理论 O(1) 更快。

**数学描述**：设缓存行可容纳 $C$ 个元素，顺序访问 $n$ 个元素时，缓存未命中次数约为 $\lceil n/C \rceil$ ；而链表访问 $n$ 个元素，未命中次数为 $n$ （每次都是随机内存访问）。

**违反约束的后果**：随机访问模式（如每 $k$ 个元素访问一次， $k$ 与缓存行宽度互质）会导致缓存行反复失效，在内存带宽受限场景下性能退化至接近内存延迟上限，比顺序访问慢数个数量级。

### 字符串不可变的设计动机

字符串不可变不是语言设计的偶然，而是深思熟虑的结果：

1. **并发安全**：多个线程读取同一字符串无需同步（无数据竞争），天然避免死锁和可见性问题。
2. **字符串驻留（String Interning）**：相同内容的字符串字面量可共享同一对象（如 Python 的字符串池、Java 的 `String.intern()`），减少内存占用，加速相等性比较。
3. **哈希缓存**：字符串可安全地预计算并缓存哈希值，因其内容永不改变。
4. **安全边界**：在权限检查后传递字符串引用，无需担心调用方在检查与使用之间篡改内容（如 Java 的 `SecurityManager` 场景）。

**违反不可变约束的后果**（以 C 中 `char*` 字符串为例）：
- 多个指针指向同一缓冲区，一个指针释放后，其他指针悬空（use-after-free）。
- 多线程并发写入同一缓冲区导致数据竞争（无锁保护）。
- 字符串内容在"哈希计算后、使用前"被修改，导致安全检查失效（TOCTOU）。

### 前缀和的空间换时间策略

前缀和的核心洞察是：用 O(n) 额外空间将区间查询从 O(n) 降至 O(1)。这是一种**空间换时间**的经典策略，适用于静态数据（写少读多）场景。

**约束条件**：
- 数据静态：若数组频繁更新，每次更新需 O(n) 更新所有受影响的前缀和元素，失去均摊优势。此时应使用二叉索引树（BIT）或线段树，支持 O(log n) 点更新+区间查询。
- 空间预算充足：需额外 O(n) 空间，在极端稀疏数据场景可能得不偿失。

### 差分数组的逆向思维

差分数组将"区间更新，单点查询"转化为"单点更新，区间查询"（通过前缀和）。其数学本质是**微分-积分逆操作在离散域的应用**：差分是离散微分，还原是离散积分。

**约束条件**：差分数组适合"区间更新多，单点查询少"的场景。若查询和更新各占一半，差分数组均摊 O(n) 而朴素方法也 O(n)，优势消失。

## 参考存根

```python
class PrefixSum:
    """前缀和：静态数组区间查询 O(1)，构建 O(n)"""
    def __init__(self, nums):
        self.prefix = [0]
        for num in nums:
            self.prefix.append(self.prefix[-1] + num)

    def range_sum(self, left, right):
        # 区间 [left, right] 含端点
        return self.prefix[right + 1] - self.prefix[left]
```

```python
def diff_range_add(diff, left, right, delta):
    """差分数组的区间加操作：O(1)"""
    diff[left] += delta
    if right + 1 < len(diff):
        diff[right + 1] -= delta

def diff_recover(diff):
    """差分数组还原为原数组：O(n)"""
    arr = [0] * len(diff)
    arr[0] = diff[0]
    for i in range(1, len(diff)):
        arr[i] = arr[i-1] + diff[i]
    return arr
```
