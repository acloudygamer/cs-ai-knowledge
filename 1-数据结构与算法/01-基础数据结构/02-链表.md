# 链表

> **版本基准**：universal —— 代码示例同时使用 Python 3.12 与 C++20

## 本质

链表把离散的内存节点用指针串成一条线性序列。它的核心权衡是：用"必须从头逐个找"的遍历代价，换来了"哪里都能插、哪里都能删"的灵活——因为节点不必挨在一起，增删时只改几根指针即可，无需搬动整片内存。

## 为什么需要链表

- 数组靠"下标 × 元素大小"的公式直接算出地址，所以随机访问 $O(1)$；但中间插入要搬移其后所有元素，是 $O(n)$。
- 链表把"位置"从**物理地址**解耦到**指针关系**：节点的位置不再由内存偏移决定，而由"谁指向谁"决定。插入/删除只改常数个指针， $O(1)$。
- 代价：访问第 $i$ 个节点无法用公式算地址，必须从表头沿指针逐个跳转， $O(n)$ ——而且这个 $O(n)$ 在真实硬件上比数组的 $O(n)$ 慢得多（见下文缓存模型）。

> **本质转移**：链表用"遍历时间"换来了"插入灵活"和"无需连续内存"。地址计算从数组的**算术求址**退化为**沿指针遍历**。

## 数学模型

### Floyd 环检测（快慢指针）

设表头到环入口的距离为 $F$ （节点数），环长为 $L$。快指针每次走两步、慢指针每次走一步，两者首次相遇时：

- 慢指针走过： $F + a$ （$a$ 为相遇点在环内距入口的步数）
- 快指针走过： $F + a + kL$ （$k \geq 1$，快指针在环内多转了 $k$ 圈）

快指针速度是慢指针的 2 倍：

$$2(F + a) = F + a + kL \;\Rightarrow\; F + a = kL$$

由此 $F = kL - a = (k-1)L + (L - a)$。把快指针重置到表头并改为每次一步、慢指针原地继续，两者再次相遇的位置恰好是环入口。

**为什么快指针步长必须是 2**：设快步长 $v$、慢步长 $1$，相遇条件 $v \cdot t \equiv t \pmod{L}$。只有 $v=2$ 时化简为 $t \equiv 0 \pmod{L}$，才保证在 $t=F$ 时首次相遇于环入口； $v \neq 2$ 时 $t$ 的解不保证为整数，首次相遇位置不确定，算法失效。

> 一句话洞察：Floyd 算法是**模 $L$ 同余**——快慢相遇，等价于快指针相对慢指针在环上多走了整数圈。

### 缓存命中的代价模型

链表遍历慢，不只是"跳 $n$ 次"这个抽象代价，而是**每次跳转几乎都是一次缓存未命中**。

- **数组**：元素连续排列，CPU 的硬件预取器识别出顺序访问模式，提前把下一缓存行（通常 64 字节）拉进 L1。一次 L1 命中约 1 ns 量级，且一个缓存行能装下多个元素。
- **链表**：节点分散在堆上、地址无规律，预取器失效，每次 `next` 跳转都可能是 cache miss，要回主存取数——一次未命中约数十到上百 ns。

遍历 $n$ 个元素的总时间近似：

$$T_{\text{数组}} \approx n \cdot t_{\text{hit}},\qquad T_{\text{链表}} \approx n \cdot t_{\text{miss}}$$

由于 $t_{\text{miss}} / t_{\text{hit}} \approx 50\text{–}100$，同样是 $O(n)$ 的遍历，链表可比数组慢数十倍。这才是工程上"链表遍历贵"的真正来源。

## 数据流

### 单链表反转

<pre>
初始:  head → [1] → [2] → [3] → NULL
        prev  curr

第1步:  NULL ← [1]    [2] → [3] → NULL     (先存 nxt=curr.next，再 curr.next=prev)
              prev  curr

第2步:  NULL ← [1] ← [2]    [3] → NULL
                     prev  curr

第3步:  NULL ← [1] ← [2] ← [3]
                            prev  curr=NULL → 停

最终:  new_head = prev → [3] → [2] → [1] → NULL
</pre>

**所有权变换**：每个节点的 `next` 从指向后继改为指向前驱；旧表头成为新表尾（`next=NULL`）。整条链通过指针重连转移给新头节点，零拷贝。

### 快慢指针找中点

<pre>
1 → 2 → 3 → 4 → 5 → NULL
↑           ↑
s(慢,1步)   f(快,2步)

迭代: s=2,f=3 → s=3,f=5(NULL) → 中点为 s=3
奇数长度: 快指针撞到 NULL，慢恰在中点
偶数长度: 快指针越过 NULL，慢在后半段起点
</pre>

快指针速度是慢指针的 2 倍，故 $2 \cdot d_{\text{slow}} = d_{\text{fast}}$。

### LRU 缓存（哈希表 + 双向链表）

<pre>
get(key):
  hash_map[key] ──指向──> node ──移到尾部──> (成为最新)

put(key, val):
  新 node ──接尾部──> 若超容: 摘除头部(最久未用) ──> 同步删 hash_map 条目

内部双向链表:
  head ↔ [最新] ↔ ... ↔ [最旧] ↔ tail
</pre>

哈希表给 $O(1)$ 键查找，链表维护访问顺序。移到尾部只改 3 个节点的 4 个指针， $O(1)$；摘除最旧节点同样 $O(1)$。

### 双向链表删除

<pre>
删 curr（已知其 prev、next）:
  [prev] ←→ [curr] ←→ [next]
       1. prev.next = curr.next
       2. next.prev = curr.prev
       3. 释放 curr
顺序铁律: 1、2 必须先做完，再访问 curr 的指针，否则读到无效地址。
</pre>

## 对比参照

| 属性 | 单链表 | 双链表 | 数组 |
|------|--------|--------|------|
| 内存布局 | 离散节点，1 指针串联 | 同左 + 前驱指针 | 连续内存 |
| 插入/删除（已知节点） | $O(1)$ | $O(1)$ | $O(n)$ （搬移元素） |
| 随机访问 | $O(n)$ 遍历 | $O(n)$ 遍历 | $O(1)$ 公式寻址 |
| 空间开销 | 数据 + 1 指针/节点 | 数据 + 2 指针/节点 | 仅数据 |
| 缓存友好性 | 差（节点分散，频繁 miss） | 差 | 优（连续，预取命中） |

## 机制

### 为什么插入/删除是 $O(1)$

链表的"位置"由指针关系定义，与物理地址解耦。插入只需改前驱的 `next`；删除只需改前驱的 `next` 和被删节点的 `next`（双向再加 `prev`）。常数个指针操作 = $O(1)$。

**约束**： $O(1)$ 的前提是**已知插入/删除位置的指针**。若只知节点值，要先 $O(n)$ 遍历定位。

### 随机访问慢的工程真相

抽象复杂度只说"链表访问是 $O(n)$"，但工程上更要命的是**每一次跳转都几乎是一次缓存未命中**：链表节点分散在堆上、地址无规律，CPU 的硬件预取器无法识别出顺序模式，于是一路 miss 回主存。数组正相反，连续排列让预取器提前拉下一缓存行，命中在 L1。

这就是上一节缓存代价模型的机制对应：同样是 $O(n)$ 遍历，链表比数组慢的不是常数倍，而是数十倍量级。**选数据结构时，"是否需要遍历"在链表上是一个比抽象复杂度更重的砝码。**

### 哨兵节点消除边界判断

哨兵（dummy head/tail）是不存数据的虚拟节点，把边界条件统一为内部情况：插空表 = 插到哨兵后；删尾节点 = 删哨兵前。表头/表尾操作无需特判。代价是两个虚节点的内存（各两个指针宽）。

### 双向链表指针更新的原子性

删一个节点要改四个指针（`curr.prev.next`、`curr.next.prev`、及 curr 自身的 `prev`/`next`）。关键约束：四个指针必须保持一致，否则链表断裂。正确顺序：先 `curr.prev.next = curr.next`，再 `curr.next.prev = curr.prev`。若先改 `curr.prev`，就丢了前驱，删除无法完成 → 节点不可达 → 内存泄漏 + 悬挂指针。

### 违规后果

| 违规行为 | 后果 | 适用 |
|---------|------|------|
| 忘记释放已删节点 | 内存泄漏 / use-after-free | C/C++（Python 由 GC 管，无此问题） |
| 遍历时删除当前节点 | 迭代器失效，漏检或死循环 | 通用 |
| 双链表指针更新顺序错 | 链表断裂，节点丢失 | 通用 |
| 快指针步长非 2 | Floyd 失效，漏检环 | 通用 |

## 代码示例

**Python 3.12**：

```python
class ListNode:
    def __init__(self, val=0, nxt=None):
        self.val, self.next = val, nxt

# 反转：把每个节点的 next 指向前驱；先存后继 nxt，再改向，再前进
def reverse_list(head):
    prev, curr = None, head
    while curr:
        curr.next, prev, curr = prev, curr, curr.next
    return prev

# 环检测：快慢指针，相遇即有环
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False

# 合并有序链表：哨兵统一空表边界，避免对头节点特判
def merge_lists(l1, l2):
    dummy = ListNode()
    tail = dummy
    while l1 and l2:
        if l1.val <= l2.val:
            tail.next, l1 = l1, l1.next
        else:
            tail.next, l2 = l2, l2.next
        tail = tail.next
    tail.next = l1 or l2        # 接上未耗尽的剩余段
    return dummy.next

# —— 简易输入输出 ——
def to_list(*vals):              # 数组 → 链表
    d = ListNode(); t = d
    for v in vals:
        t.next = ListNode(v); t = t.next
    return d.next

def show(h):                     # 链表 → 数组（便于观察结果）
    out = []
    while h:
        out.append(h.val); h = h.next
    return out

print(show(reverse_list(to_list(1, 2, 3))))          # [3, 2, 1]
print(has_cycle(to_list(1, 2, 3)))                   # False
print(show(merge_lists(to_list(1, 3, 5),
                       to_list(2, 4, 6))))          # [1, 2, 3, 4, 5, 6]
```

**C++20**（算法题场景常用裸指针，最简；生产环境用 `std::unique_ptr` 管 RAII）：

```cpp
#include <iostream>
#include <vector>
#include <initializer_list>

struct ListNode {
    int val{};
    ListNode* next{};
    ListNode(int x = 0, ListNode* n = nullptr) : val(x), next(n) {}
};

// 反转：逐步反转 next 指向，O(n) 时间 O(1) 空间
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    for (ListNode* curr = head; curr; ) {
        ListNode* nxt = curr->next;   // 先存后继，再改向
        curr->next = prev;
        prev = curr;
        curr = nxt;
    }
    return prev;
}

// 环检测：Floyd 快慢指针，相遇即有环
bool hasCycle(ListNode* head) {
    for (ListNode *slow = head, *fast = head; fast && fast->next; ) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}

// 合并有序链表：哨兵统一边界
ListNode* mergeLists(ListNode* l1, ListNode* l2) {
    ListNode dummy;
    ListNode* tail = &dummy;
    while (l1 && l2) {
        if (l1->val <= l2->val) { tail->next = l1; l1 = l1->next; }
        else                    { tail->next = l2; l2 = l2->next; }
        tail = tail->next;
    }
    tail->next = l1 ? l1 : l2;       // 接上剩余
    return dummy.next;
}

// —— 简易输入输出 ——
ListNode* to_list(std::initializer_list<int> vals) {  // 数组 → 链表
    ListNode dummy; ListNode* t = &dummy;
    for (int v : vals) { t->next = new ListNode(v); t = t->next; }
    return dummy.next;
}
std::vector<int> show(ListNode* h) {                  // 链表 → 数组
    std::vector<int> out; for (; h; h = h->next) out.push_back(h->val); return out;
}

int main() {
    auto r = reverseList(to_list({1, 2, 3}));
    for (int v : show(r)) std::cout << v << ' ';      // 3 2 1
    std::cout << "| cycle=" << hasCycle(to_list({1, 2, 3})) << '\n';  // cycle=0
    auto m = mergeLists(to_list({1, 3, 5}), to_list({2, 4, 6}));
    for (int v : show(m)) std::cout << v << ' ';      // 1 2 3 4 5 6
}
```
