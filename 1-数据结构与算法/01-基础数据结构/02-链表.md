# 链表

## 定义

> **版本基准**: universal

链表是离散的节点通过指针串联的链式结构，节点在内存中不必连续分布。每一个节点持有数据负载和指向后继节点的指针（单链表），或同时持有指向前驱和后继的指针（双链表）。插入和删除操作只需修改相邻节点的指针引用，时间复杂度 O(1)；但访问任意位置需要从表头逐节点遍历，时间复杂度 O(n)。

链表的本质是**状态机式的线性访问**：数据不再像数组那样通过公式映射实现随机访问，而是通过指针链的**接力式状态转移**实现顺序访问。地址计算从解析几何问题（数组下标的算术运算）退化为图的遍历问题（图的深度优先搜索的线性特例）。

## 数学模型

### Floyd 环检测（快慢指针）

设从表头到环入口的距离为 $F$（以节点数计），环长为 $L$。快指针每次前进一步，慢指针每次前进一步；当两者第一次相遇时：

- 慢指针走过的距离：$F + a$（$a$ 为相遇点在环内距入口的步数）
- 快指针走过的距离：$F + a + kL$（$k \geq 1$，快指针可能在环内多转了 $k$ 圈）

快指针速度是慢指针的 2 倍：
$$2(F + a) = F + a + kL \Rightarrow F + a = kL$$

由此推得环入口距表头的距离：$F = kL - a = (k-1)L + (L - a)$。

重置快指针至表头并改为每次一步，慢指针留在原地，两者再次相遇的位置恰好是环入口。这是**状态机同步启动**的经典应用。

### 约瑟夫问题递推

$f(1) = 0,\quad f(i) = (f(i-1) + k) \bmod i$

其中 $k$ 为报数上限。此递推反映了**等价关系下的商空间收缩**：每次剔除一个节点后，剩余问题与原问题结构同构，只是编号发生了循环移位。

### 链表遍历的状态机模型

链表遍历可形式化为有限状态自动机：

$$M = (Q, \Sigma, \delta, q_0, F)$$

- $Q = \{ \text{节点}_0, \text{节点}_1, \ldots, \text{节点}_n, \text{NULL} \}$（节点状态集合加终止态）
- $\Sigma = \{ \text{next} \}$（单比特输入：是否继续）
- $\delta(q, \text{next}) = q.\text{next}$（状态转移函数）
- $q_0 = \text{head}$（初始状态）
- $F = \{ \text{NULL} \}$（唯一接受态）

每次指针跳转对应一次状态转移，遍历完整个链表恰好完成一次从 $q_0$ 到接受态的路径。

**归约终点**：链表遍历问题可归约为**有向图的深度优先遍历**的线性特例，其时间复杂度 O(n) 是图的遍历复杂度下界。

## 数据流

### 单链表反转

<pre>
初始状态:
  head
    │
    ▼
  [1] → [2] → [3] → NULL
  prev  curr  next

第1步翻转 (curr=1):
  NULL  [1]   [2] → [3] → NULL
  prev  curr  next
  ──────────── 指针反转
  curr.next = prev

第2步翻转 (curr=2):
  NULL ← [1]   [2] → [3] → NULL
         prev  curr  next
  ──────────── 指针反转

第3步翻转 (curr=3):
  NULL ← [1] ← [2]   [3] → NULL
                prev  curr
  ──────────── 指针反转

最终状态:
  [3] → [2] → [1] → NULL = new_head
</pre>

**所有权变换**：反转过程中，每个节点的 `next` 指针从指向后继变为指向前驱。旧链表的所有权通过指针重连转移给新链表的头节点，原表头成为新链表的尾节点（其 `next` 变为 NULL）。

### 快慢指针找中点

<pre>
1 → 2 → 3 → 4 → 5 → NULL
↑           ↑
s (slow)    f (fast 每次两步)

第1次迭代: s=2, f=3
第2次迭代: s=3, f=5 (到达NULL，中点为s)

奇数长度: 快指针先到达NULL，慢指针恰好在中点
偶数长度: 快指针越过NULL，慢指针在后半段起点
</pre>

快指针以速度 2 遍历，慢指针以速度 1 遍历。当快指针到达 NULL（偶数长）或最后一个节点（奇数长）时，慢指针位置即为中点。快指针走过的距离是慢指针的 2 倍：$2 \cdot d_{\text{slow}} = d_{\text{fast}}$。

### LRU 缓存（哈希表 + 双向链表）

<pre>
get(key):
  hash_map[key] ──指向节点──> [node] ──移动到尾部──> [node]（最新）

put(key, val):
  新node ──添加到尾部（与头节点建立双向指针）
  如果超容：移除头部节点（最久未使用）
               │
               └──> 从 hash_map 中删除对应条目

数据结构内部:
  head ↔ [最新] ↔ ... ↔ [最旧] ↔ tail
  （头部为最新，尾部为最旧）
</pre>

**关键约束**：哈希表提供 O(1) 的键查找，链表维护访问顺序。移动节点到尾部是 O(1)（只需修改前后三个节点的四个指针）。移除最旧节点是 O(1)（tail 前移，解除头部指针）。

**数据形态变换**：键值对 → 哈希表映射 → 链表节点移动 → 访问顺序更新

## 对比参照

| 属性 | 单链表 | 双链表 | 数组 |
|------|--------|--------|------|
| 内存布局 | 离散的节点，指针串联 | 同左，额外前驱指针 | 连续内存 |
| 插入/删除 | O(1)（已知节点） | O(1)（已知节点） | O(n)（需移动元素） |
| 随机访问 | O(n) 遍历 | O(n) 遍历 | O(1) 公式寻址 |
| 空间开销 | 仅数据 + 1 指针/节点 | 数据 + 2 指针/节点 | 仅数据 |
| 缓存友好性 | 差（节点可能任意分散） | 差（同左） | 优（连续内存，缓存行对齐） |

## 机制

### 指针链接实现 O(1) 插入删除

链表的插入/删除操作只需要修改常数个指针（插入：前驱的 next；删除：前驱的 next 和当前节点的 next）。**本质原因**：链表将"位置"这个概念从物理地址编码中解耦——节点的位置不再由其在内存中的物理地址决定，而是由节点间的指针关系决定。

对比数组：插入元素需要将被插入位置后的所有元素向后移动一位，时间复杂度 O(n)，这是因为数组的物理连续性要求保持"下标 = 内存偏移"的映射关系。

### O(n) 访问是遍历的代价

节点在内存中不必连续，意味着无法通过算术运算直接计算第 i 个节点的物理地址。必须从表头出发，沿着指针链逐节点跳转，直到到达目标。这种**地址的延迟绑定**是链表 O(n) 访问的根本原因。

### 哨兵节点消除边界判断

哨兵节点（dummy head/tail）是逻辑上的虚拟节点，不存储实际数据。它的存在将**边界条件统一为内部情况**：

- 插入到空表：变成插入到哨兵之后
- 删除最后一个节点：变成删除哨兵之前的节点
- 表头/表尾操作：无需单独处理

**约束**：哨兵节点的存在使链表的"首"和"尾"成为相对概念，简化了代码但增加了两个虚节点的内存开销（通常为两个指针的宽度）。

### 双向链表的指针更新原子性

在双链表中删除一个节点需要同时修改该节点的 prev 和 next 指针，以及前后相邻节点的指针。**关键约束**：这四个指针的修改必须保持一致，否则链表结构会断裂。

正确顺序：
1. 待删节点的 prev.next = 待删节点的.next
2. 待删节点的.next.prev = 待删节点的.prev

如果调换顺序（如先修改待删节点的.prev），会导致无法找到待删节点的后继，从而无法完成删除。

### 违规后果

- **忘记释放已删除节点的内存**：内存泄漏。在手动管理内存的语言（如 C）中，每次删除节点必须显式释放其内存。
- **环检测中快指针步长错误**：若快指针不是每次走两步而是走三步或更多，Floyd 算法不再保证有效。快指针步长必须恰好是慢指针的 2 倍才能满足 $2(F+a) = F + a + kL$ 的推导。
- **多线程并发修改链表未加锁**：数据竞争。一个线程正在遍历链表时，另一个线程删除了当前节点，会导致野指针解引用。链表操作本身不是原子性的。
- **在遍历时修改链表**：迭代器失效。常见的"在遍历链表时删除当前节点"会导致迭代器状态不一致。

## 参考存根

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def reverse_list(head):
    prev, curr = None, head
    while curr:
        curr.next, prev, curr = prev, curr, curr.next
    return prev
```

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False
```

```python
def merge_lists(l1, l2):
    dummy = ListNode()
    curr = dummy
    while l1 and l2:
        if l1.val <= l2.val:
            curr.next, l1 = l1, l1.next
        else:
            curr.next, l2 = l2, l2.next
        curr = curr.next
    curr.next = l1 or l2
    return dummy.next
```
