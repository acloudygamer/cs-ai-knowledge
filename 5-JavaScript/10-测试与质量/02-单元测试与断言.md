# 单元测试与断言

> 前置：[01-测试理论](./01-测试理论.md) · 后续：[03-端到端与组件测试](./03-端到端与组件测试.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1，Windows x64。

## 本质

单元测试有两条规定：**隔离**被测单元（依赖用替身替换，见 [01-测试理论](./01-测试理论.md)），以及**用断言表达期望**。

断言是"期望"的可执行形式。它的选择直接影响测试能否发现错误——**比较方式太宽松，测试就永远不会失败**。本篇的核心是一条实测结论：`node:assert/strict` 与 `node:assert` 的 `deepEqual` 行为完全不同。

Node 内置了测试运行器（`node:test`）与断言库（`node:assert`），**无需任何第三方依赖**即可开始。对大多数项目来说这已经够用。

## 机制

### 运行

```bash
node --test              # 自动发现 *.test.js / *-test.js / test/ 下的文件
node --test path/to/x.test.js
node --test --watch      # 监听改动重跑
```

### 结构：`describe` 与 `it`

```javascript
import { test, describe, it, mock } from "node:test";
import assert from "node:assert/strict";
import { add, div } from "./math.js";

describe("add", () => {
  it("相加", () => assert.equal(add(1, 2), 3));
  it("负数", () => assert.equal(add(-1, 1), 0));
});
describe("div", () => {
  it("正常相除", () => assert.equal(div(6, 3), 2));
  it("除零抛错", () => assert.throws(() => div(1, 0), /除零/));
});
```

`describe` 只做分组（影响输出的层级与 `--test-name-pattern` 的过滤），`it` 与 `test` 是同一个东西的两种写法。**测试名要描述"期望的行为"，不是"被调用的函数"**——`"除零抛错"` 比 `"test div 2"` 在失败时有用得多。

### 断言：`strict` 版改变了 `deepEqual`

这是最容易踩的一处。实测对照：

| 比较 | `node:assert`（宽松） | `node:assert/strict` |
|---|---|---|
| `Object.create(null)` vs `{}` | 通过 | **失败** |
| `1` vs `"1"` | 通过 | **失败** |
| `[1, 2]` vs `[1, 2]` | 通过 | 通过 |

```console
$ node assert-cmp.mjs
  assertStrict.deepEqual === assertStrict.deepStrictEqual ? true
  assertLoose.deepEqual === assertLoose.deepStrictEqual ? false
```

**在 `node:assert/strict` 里，`deepEqual` 就是 `deepStrictEqual`**（同一个函数）。宽松版的 `deepEqual` 会做类型转换与原型忽略，严格版不会。

**始终用 `import assert from "node:assert/strict"`**。宽松版的 `deepEqual` 把 `1` 与 `"1"` 视为相等，这类"测试通过但代码是错的"最难发现。

三种相等断言的选择：

| 断言 | 用于 |
|---|---|
| `assert.equal` | 原始值比较（内部是 `===`） |
| `assert.deepStrictEqual` | 对象/数组的**结构与类型**比较 |
| `assert.ok` | 真值判断 |

### 浮点比较

`0.1 + 0.2 !== 0.3`（见 [01-语言核心/02-绑定与类型](../01-语言核心/02-绑定与类型.md)），所以浮点结果不能直接相等比较：

```javascript
it("浮点用近似比较", () => assert.ok(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON));
```

按"绝对误差小于某个容差"判断。**容差要按场景选**——`Number.EPSILON` 适合单次运算，多次累积运算需要更大的容差。

### 异步测试

```javascript
it("async 测试", async () => assert.equal(await Promise.resolve("ok"), "ok"));
it("断言拒绝", async () => {
  await assert.rejects(async () => { throw new Error("失败"); }, /失败/);
});
```

`it` 的回调返回 Promise 时，运行器会等待它。**断言拒绝要用 `assert.rejects`，不能只写 `try` / `catch`**——后者在"本该拒绝但没拒绝"时会静默通过。

`assert.rejects` 的第二个参数是匹配器（正则、错误类、对象），用来确认**拒绝的是预期的那个错误**，而不是碰巧抛出的别的错。

### 替身与 `mock`

```javascript
const fn = mock.fn(() => 42);
fn(); fn();
assert.equal(fn.mock.callCount(), 2);
```

`node:test` 的 `mock` 提供 `fn`（函数替身）、`method`（替换对象方法）、`timers`（控制时间）。时间相关的测试用它，避免依赖真实时钟——这是 [01-测试理论](./01-测试理论.md) 里"测试要可重复"的具体落实。

### 组织与命名

| 约定 | 理由 |
|---|---|
| 测试文件与被测文件同目录或平行目录 | 找得到、改得动 |
| 文件名 `<被测>.test.js` | 运行器的自动发现规则 |
| `describe` 按被测单元分组 | 失败时定位快 |
| `it` 描述行为而非实现 | 重构时不需要改测试名 |

**测试名描述行为**（"空数组返回 0"）而不是实现（"调用 reduce"）。前者在重构后依然成立，后者会让每次重构都变成改测试。

## 连接：断言选择

| 期望 | 断言 |
|---|---|
| 值相等 | `assert.equal` / `assert.strictEqual` |
| 对象结构相等 | `assert.deepStrictEqual` |
| 抛错 | `assert.throws(fn, matcher)` |
| Promise 拒绝 | `await assert.rejects(p, matcher)` |
| 真值 | `assert.ok` |
| 浮点近似 | `assert.ok(Math.abs(a - b) < tol)` |

## 边界

- **用 `node:assert/strict`**：宽松版的 `deepEqual` 会做类型转换。
- **`deepEqual` 在 strict 下就是 `deepStrictEqual`**：两者不是"宽松/严格"的关系，是同一个。
- **断言拒绝要用 `assert.rejects`**：手写 `try` / `catch` 会漏掉"没有拒绝"的情况。
- **浮点不能用相等比较**：按容差判断。
- **一个测试只做一次 Act**：多次执行会让失败无法归因。
- **时间与随机数要注入或 mock**：否则测试不可重复。
- **测试名描述行为**：避免与实现耦合。
