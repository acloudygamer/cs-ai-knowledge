# 测试覆盖率

> **版本基准**: Node24+ES2024 (stable) | Node26+ES2026 (latest)

## 定义

测试覆盖率是代码被执行路径占总路径比例的量化指标，用于**识别测试盲区而非衡量测试质量**。覆盖率是必要条件而非充分条件——100% 覆盖的代码仍可能有逻辑错误、边界 bug 或语义错误。

覆盖率本质是一个**路径可达性矩阵**：给定代码图 $G = (V, E)$（顶点为基本块，边为控制流），覆盖率为从入口到出口的可达路径中，被测试套件覆盖的路径比例。

## 数学模型

### Istanbul 覆盖率模型

Istanbul 在代码编译时通过 `babel-plugin-istanbul` 插入计数器，跟踪每个基本块的命中状态。

设代码的基本块集合为 $B = \{b_1, b_2, ..., b_n\}$，测试执行后命中的块集合为 $H \subseteq B$。覆盖率指标定义为：

| 指标 | 公式 | 含义 |
|------|------|------|
| Statements | $\frac{|H_s|}{|B_s|}$ | 执行过的语句占总语句的比例 |
| Branches | $\frac{|H_b|}{|B_b|}$ | 执行过的分支占总分支的比例 |
| Functions | $\frac{|H_f|}{|B_f|}$ | 被调用过的函数占总函数的比例 |
| Lines | $\frac{|H_l|}{|B_l|}$ | 被覆盖行占总行数的比例 |

**分支的计算**：每个 `if/else` 产生 2 个分支；`&&`、`||` 的短路也算分支。

**归约终点**：覆盖率归结为基本块的命中计数问题。插桩代码在每个基本块入口插入计数器，测试运行时累加。

### 覆盖率阈值约束

`coverageThreshold` 配置将覆盖率从"观测指标"变为"质量门槛"：

$$
\text{threshold}(m) = \begin{cases} \text{pass} & \text{if } \text{actual}(m) \geq \text{config}(m) \\ \text{fail} & \text{otherwise} \end{cases}
$$

其中 $m \in \{\text{statements}, \text{branches}, \text{functions}, \text{lines}\}$。

**约束**：阈值设置过低（如 0%）无意义；设置过高（如 100%）可能导致开发者添加无意义的覆盖而非真正测试。

## 数据流

<pre>
源代码 (.js)
    │
    ▼
babel-plugin-istanbul 插桩
    │
    ├── 遍历 AST
    ├── 每个基本块前插入计数器
    └── 输出带计数器的代码
    │
    ▼
Jest 运行测试
    │
    ▼
执行被插桩的代码
    │
    ├── 每个语句执行 → 对应计数器 +1
    ├── 每个分支执行 → 分支计数器 +1
    └── 每个函数调用 → 函数计数器 +1
    │
    ▼
覆盖率数据汇总 (coverage/)
    │
    ├── lcov.info (行覆盖详情)
    ├── coverage-summary.json (汇总)
    └── index.html (人工审查)
    │
    ▼
coverageThreshold 比对
    │
    ├── actual >= threshold ──► 构建继续
    └── actual < threshold ──► 构建失败 (exit code 1)
</pre>

### 分支覆盖追踪

<pre>
源代码:
if (x > 0) {      // 分支 A (x > 0)
  doSomething();
} else {           // 分支 B (x <= 0)
  doOther();
}

插桩后:
if (x > 0) {
  __coverage__['A']++;  // 分支 A 计数
  doSomething();
} else {
  __coverage__['B']++;  // 分支 B 计数
  doOther();
}

// 覆盖率为 0%: 0/2 (一个分支都没执行)
// 覆盖率为 50%: 1/2 (只执行了 A 或 B)
// 覆盖率为 100%: 2/2 (两个分支都执行)
</pre>

## 机制

### 插桩的基本块划分

Istanbul 的基本块定义：每个**没有内部分支的连续语句序列**。例如：

```javascript
const a = 1;        // 块 1
const b = 2;        // 块 2（同一块）
if (condition) {    // 块 3（分支入口）
  foo();            // 块 4
} else {            // 块 5
  bar();            // 块 6
}
baz();              // 块 7
```

每行的尾端标识一个基本块边界。空行和注释不影响基本块。

### 覆盖率阈值的设计意图

`coverageThreshold` 的存在防止覆盖率随时间劣化（"测试腐化"）：

```javascript
// jest.config.js
module.exports = {
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 80,
      lines: 80,
      statements: 80,
    },
  },
};
```

**约束**：覆盖率阈值是**下界约束**，通过不意味着测试质量高；未通过意味着存在明确的测试盲区。

### 覆盖率假象

覆盖率反映的是**执行路径**而非**逻辑正确性**：

```javascript
function divide(a, b) {
  return a / b;  // 100% 覆盖，但 b=0 时会返回 Infinity 而非抛出错误
}
```

`expect(divide(1, 0)).toThrow()` 才能捕获这个 bug，即使这不影响覆盖率。

**根本局限**：覆盖率无法检测"做了错误的事情"——只能检测"某些路径没跑到"。

### 未覆盖分支的危害

未覆盖的分支是潜在的 bug 盲区：

```javascript
function calculate(a, b, op) {
  if (op === 'add') return a + b;      // 分支 1
  if (op === 'sub') return a - b;      // 分支 2 (未覆盖)
  return 0;                             // 分支 3 (未覆盖)
}

// 只测试 add → 覆盖率 33%
// 未覆盖分支 2, 3 可能隐藏实现错误
```

**风险量化**：设未覆盖分支比例为 $r$，则潜在 bug 密度期望为 $r \times D$，其中 $D$ 为每个分支的平均 bug 密度。

---

## 对比参照

| 指标 | 含义 | 假阳性风险 |
|------|------|-----------|
| Statements | 多少语句被执行 | 三元表达式内部只算一语句 |
| Branches | 多少分支被执行 | 每个条件算 2 分支 |
| Functions | 多少函数被调用 | 可能有未测试的内部逻辑 |
| Lines | 多少行被执行 | 空行、注释不计入 |

```javascript
// 识别未覆盖分支示例
function calculate(a, b, op) {
  if (op === 'add') return a + b;      // 分支1
  if (op === 'sub') return a - b;      // 分支2（未覆盖）
  return 0;                             // 分支3（未覆盖）
}
// 需补充：calculate(1, 2, 'sub') 和 calculate(1, 2, 'other')
```

```javascript
// 边界条件：b === 0 分支
function divide(a, b) {
  if (b === 0) throw new Error('div by zero');
  return a / b;
}
// 需覆盖 throw 分支：divide(1, 0)
```

```javascript
// 循环覆盖 0/1/多次
const arr = [];
process(arr);     // 0次
process([1]);     // 1次
process([1, 2, 3]); // 多次
```

```javascript
// 避免假覆盖率：mock 外部依赖
jest.mock('./api');
// 而非真实调用 fetchUser（网络/数据库）
```

```javascript
// LCOV 格式（用于 CI 集成）
// jest --coverage --coverageReporters=lcov
```

```javascript
// 条件覆盖的完整路径
function test(x) {
  if (x > 0) return 'positive';    // T 分支
  if (x < 0) return 'negative';    // T 分支（x <= 0 时不进入）
  return 'zero';                    // 隐含分支
}
// 完整覆盖需要：test(1), test(-1), test(0)
```
