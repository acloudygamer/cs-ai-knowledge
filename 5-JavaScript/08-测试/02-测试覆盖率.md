# 测试覆盖率

> **版本基准**：Node24+ES2024 | Node26+ES2026

## 本质断言

**测试覆盖率是代码被执行路径占总路径比例的量化指标，用于识别测试盲区而非衡量测试质量。**

---

## 设计机制

### Istanbul 覆盖率模型

Jest 内置 Istanbul（基于 `babel-plugin-istanbul`），在代码编译时插入计数器，跟踪每个基本块是否被命中。

```
源代码 ──► AST ──► 插桩节点 ──► 覆盖率计数 ──► 报告生成
             ↑
      babel-plugin-istanbul
```

### 四大指标计算

| 指标 | 计算方式 | 设计原因 |
|------|---------|---------|
| Statements | 已执行语句数 / 总语句数 | 最粗粒度，单行即一语句 |
| Branches | 已执行分支数 / 总分支数 | `if/else`、`&&`、`\|\|` 各占 2 分支，漏路径即低覆盖 |
| Functions | 已调用函数数 / 总函数数 | 可能有函数未被调用 |
| Lines | 已覆盖行数 / 总行数 | 区别于 Statements：空行、注释不计入 Statements 但计入 Lines |

**陷阱**：100% 覆盖率不等于 100% 正确性——覆盖仅代表路径被执行，不代表断言正确。

### 覆盖率阈值强制机制

`coverageThreshold` 在覆盖率低于设定值时使构建失败——此设计将覆盖率从"观测指标"变为"质量门槛"。

---

## 分步流程

<pre>
1. 配置 collectCoverageFrom 指定要分析的文件
2. Jest 运行测试，Istanbul 记录每个文件覆盖率
3. 汇总到 coverage/lcov.info / coverage/coverage-summary.json
4. coverageThreshold 比对实际值与阈值
   ├── 通过 ──► 构建继续
   └── 失败 ──► 构建终止（退出码 1）
</pre>

---

## 参考实现

```javascript
// jest.config.js 最小配置
module.exports = {
  collectCoverage: true,
  collectCoverageFrom: ['src/**/*.js', '!src/**/*.test.js'],
};
```

```javascript
// 阈值配置
module.exports = {
  coverageThreshold: {
    global: {
      branches: 80,
      functions: 80,
      lines: 80,
      statements: 80,
    },
  },
};
```

```javascript
// 识别未覆盖分支示例
function calculate(a, b, op) {
  if (op === 'add') return a + b;      // 分支1
  if (op === 'sub') return a - b;      // 分支2（未覆盖）
  return 0;                             // 分支3（未覆盖）
}
// 需补充：calculate(1, 2, 'sub') 和 calculate(1, 2, 'other')
```

```javascript
// 边界条件：b === 0 分支
function divide(a, b) {
  if (b === 0) throw new Error('div by zero');
  return a / b;
}
// 需覆盖 throw 分支：divide(1, 0)
```
