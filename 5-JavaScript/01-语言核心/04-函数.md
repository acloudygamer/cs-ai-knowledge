# 函数

> 前置：[03-控制流程](./03-控制流程.md) · 后续：[05-对象与类](./05-对象与类.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

函数是**可调用的对象**——它有属性（`name`、`length`），能被赋给变量、作为参数传递、作为返回值返回。它同时是 JavaScript 里唯一的**作用域与闭包的载体**：每调用一次，就产生一个独立的执行环境。

这两点合起来决定了 JavaScript 的编程形态：函数是**一等公民**（first-class citizen，即"值的一种"，能出现在任何值能出现的位置），所以回调、高阶函数、Promise 链、`Array.prototype.map` 这些结构才有立足点。在 Java 里把函数当值传需要函数式接口包装，在 C++ 里需要 `std::function` 或模板；这里不需要任何额外包装。

## 机制

### 三种定义形式

| | 写法 | 提升 | `this` | `arguments` | 可 `new` |
|---|---|---|---|---|---|
| 函数声明 | `function f() {}` | **可先用后定义** | 调用时决定 | 有 | 是 |
| 函数表达式 | `const f = function () {}` | 不提升（变量本身按 `let`/`var` 规则） | 调用时决定 | 有 | 是 |
| 箭头函数 | `const f = () => {}` | 同上 | **取定义处外层的** | **无** | 否 |

提升的差异可以直接观察到：

```console
$ node -e 'console.log(hoisted()); function hoisted(){ return "已提升" }'
已提升
$ node -e 'try { expr() } catch(e){ console.log(e.constructor.name + ": " + e.message) } var expr = function(){}'
TypeError: expr is not a function
```

函数声明整体提升（名字与函数体一起）；函数表达式只提升变量名，调用时该变量仍是 `undefined`——错误是 `TypeError`（不是函数）而非 `ReferenceError`（不存在）。

### 参数

**默认值只在实参为 `undefined` 时生效**，传 `null` 不触发：

```console
$ node -e 'function g(a, b = 2, ...rest){ return [a,b,rest.length] } console.log(g(1,null), g(1,undefined))'
[ 1, null, 0 ] [ 1, 2, 0 ]
```

**剩余参数**（`...rest`）把多余的实参收成真数组（不是类数组），且必须是最后一个参数。函数对象的 `length` 属性统计**第一个默认值或剩余参数之前**的形参个数：

```console
$ node -e 'function g(a, b = 2, ...rest){} console.log(g.length)'
1
```

`arguments` 是函数体内的隐式绑定，**是类数组对象而非数组**——没有 `forEach`、`map`，需要转换或改用剩余参数：

```console
$ node -e 'function f(){ return [Array.isArray(arguments), typeof arguments.forEach] } console.log(f(1,2))'
[ false, undefined ]
```

箭头函数**没有自己的 `arguments`**，它引用外层函数的：

```console
$ node -e 'const arrow = () => { try { return arguments.length } catch(e){ return e.constructor.name } }; console.log(arrow(1,2,3))'
ReferenceError
```

### 箭头函数的三处不同，源头只有一个

箭头函数没有 `this`、没有 `arguments`、不能 `new`：

```console
$ node -e 'const A = () => {}; try { new A() } catch(e){ console.log(e.message) }'
A is not a constructor
```

这三条不是三个独立的设计选择，而是同一件事的三个面：**箭头函数没有自己的调用上下文**。普通函数每次调用都会建立一个新的执行环境，`this` 与 `arguments` 都挂在这个环境上；箭头函数直接沿用定义处的那个环境，于是既没有自己的 `this` / `arguments`，也就没有可供 `new` 构造的对象。`this` 的完整规则见 [03-this 与调用约定](../02-对象模型与运行时/03-this与调用约定.md)。

### 闭包

函数**记住了它被定义时所处的词法环境**——即使外层函数已经返回，外层绑定的变量依然存活，只有该函数能访问。这个组合体称为**闭包**（closure）：

```javascript
function counter() {
  let n = 0;                 // 这个绑定被下面的函数记住
  return () => ++n;
}
const next = counter();
next(); next();              // 2
```

`n` 不在任何全局位置，却在 `counter()` 返回后继续存在，且外界无法直接读写——**这是 JavaScript 实现私有状态的机制**，也是 [06-模块](./06-模块.md) 之前的模块模式、以及所有回调能"记住"上下文的原因。作用域链如何保存这些绑定、何时释放，见 [02-闭包与作用域链](../02-对象模型与运行时/02-闭包与作用域链.md)。

### 函数即值：高阶函数

参数或返回值为函数的函数称为**高阶函数**。它是把控制流程交给调用方的机制：

```javascript
const twice = (f, x) => f(f(x));
const nums = [1, 2, 3];
nums.map(n => n * 2);              // 每个元素过一遍 f，返回新数组
nums.filter(n => n > 1);           // f 返回真值则保留
nums.reduce((acc, n) => acc + n, 0);
```

这三个方法把"遍历"从调用方手里拿走，只留"对每个元素做什么"——所以它们不需要 `for` 循环的下标管理。数组方法的完整清单见 [02-数组](../03-标准库/02-数组.md)。

## 连接：与静态类型语言对照

| | JavaScript | Java | C++ |
|---|---|---|---|
| 函数是一等值 | 是，无包装 | 需函数式接口 | 需 `std::function` 或模板参数 |
| 参数个数检查 | 运行时无检查，缺参得 `undefined` | 编译期 | 编译期 |
| 重载 | 无（同名后者覆盖前者） | 有 | 有 |
| 闭包捕获 | 按引用，隐式 | 只捕获 final 局部变量 | 显式捕获列表 |
| 默认参数 | 有（仅 `undefined` 触发） | 无（用重载） | 有 |

"无重载"是 JavaScript 的边界之一：同名函数后定义的覆盖先定义的。需要按参数个数分派时，在函数体内判断，或用选项对象。

## 边界

- **函数声明与 `var` 一样提升，但函数表达式不**：把 `function f(){}` 写成 `const f = function(){}` 会改变提升行为。
- **箭头函数不适合所有回调**：需要动态 `this`（如事件处理器、对象方法）时必须用普通函数。
- **闭包会延长变量的生命周期**：被闭包引用的变量无法回收，这是 [07-引擎与性能/02-垃圾回收与内存](../07-引擎与性能/02-垃圾回收与内存.md) 里内存泄漏的常见来源。
