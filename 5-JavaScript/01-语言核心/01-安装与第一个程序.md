# 安装与第一个程序

> 前置：[00-概览/01-JavaScript 全景](../00-概览/01-JavaScript全景.md) · 后续：[02-绑定与类型](./02-绑定与类型.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：**Node v24.13.1（V8 13.6.233.17-node.40），npm 11.8.0，Windows x64**。

## 本质

JavaScript 的"第一个程序"要先回答一个问题：**在哪里跑**。ECMA-262 只定义语言，不定义 I/O（见 [全景](../00-概览/01-JavaScript全景.md)），所以"运行 JavaScript"必然意味着"选一个宿主"。本库以 **Node.js** 为默认宿主——它是命令行程序，装一次就能跑，且提供文件、网络、进程这些语言本身没有的能力。浏览器是另一个宿主，对照见下。

**Node.js 由三部分构成**：V8 引擎（执行 ECMA-262 定义的语言）、libuv（提供事件循环与异步 I/O）、Node 标准库（`node:fs`、`node:http` 等模块）。它是宿主，不是语言实现——换掉 V8 它仍是 Node.js，换掉 libuv 它就不是了。

## 机制

### 安装

用版本管理器而非直接装安装包——因为 Node 的**奇数版本是非 LTS 试验版、偶数版本才是 LTS**，多版本共存是常态：

```bash
# nvm（macOS / Linux）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
nvm install 24 && nvm use 24

# nvm-windows / fnm 同理；Windows 亦可直接用官方 .msi
```

验证：

```console
$ node -v
v24.13.1
$ node -p "process.versions.v8"
13.6.233.17-node.40
```

`process` 是 Node 注入的全局对象，承载进程级信息；`-p` 让 Node 求值表达式并打印结果——这两样都是宿主提供的，语言本身没有。

### 三种运行方式

| 方式 | 命令 | 用途 |
|---|---|---|
| REPL | `node` | 交互式试算，逐行求值 |
| 脚本 | `node hello.js` | 常规方式 |
| 求值 | `node -e "console.log(1)"` | 一行验证，不落文件 |

### 第一个程序与它的执行链

```javascript
// hello.js
const who = "world";
console.log(`hello, ${who}`);
```

```console
$ node hello.js
hello, world
```

从文本到输出的链条，正是 [全景](../00-概览/01-JavaScript全景.md) 那条执行链的实例化：

```text
hello.js ──扫描/解析──> AST ──Ignition──> 字节码 ──解释执行──> 输出
```

用 `--print-bytecode` 可以看到这条链的中间产物：

```console
$ node --print-bytecode hello.js
[generated bytecode for function:  (0x03ba4b4ceb59 <SharedFunctionInfo>)]
Bytecode length: 5
Parameter count 1
Register count 0
Frame size 0
    0 E> 000002547DA813C8 @    0 : 89 00 00 00       CreateClosure [0], [0], #0
 1265 S> 000002547DA813CC @    4 : b3                Return
```

这段字节码属于**顶层包装函数**，不是 `hello.js` 里那三行——Node 把每个 CommonJS 文件包进一个函数再交给 V8（包装函数的存在与形状见 [06-模块](./06-模块.md)）。它只做两件事：`CreateClosure` 建出真正的函数对象，`Return` 返回。文件里那三行代码在 `CreateClosure` 建出的闭包里，等到被调用时才解析执行——这是 [全景](../00-概览/01-JavaScript全景.md) 所述**预解析器**把解析成本推迟到首次调用的直接后果。

### 模块类型：`.js` 到底是哪种模块

Node 有两套模块系统（CommonJS 与 ESM），`.js` 后缀不指明用哪套。判定顺序是：

1. 后缀 `.mjs` → 恒为 ESM；`.cjs` → 恒为 CommonJS；
2. 否则看最近的 `package.json` 的 `"type"` 字段（`"module"` 或 `"commonjs"`）；
3. **都没有时，Node 按源码语法自动判定**——检测到 `import` / 顶层 `await` 就当 ESM，否则当 CommonJS。

第 3 条是实测确认的行为（Node 24）：

```console
$ node det.js          # 内容含 import，且无 package.json
当作 ESM 运行，platform = win32

$ echo '{"type":"commonjs"}' > package.json
$ node det.js          # 同一个文件，显式声明 CJS 后失败
Warning: Failed to load the ES module: .../det.js.
Make sure to set "type": "module" ... or use the .mjs extension.
```

自动判定只覆盖"语法上有唯一答案"的情形；显式声明与自动判定冲突时，**显式声明赢**，代价是报错而非回退。这条规则的完整展开见 [06-模块](./06-模块.md) 与 [09-工程化/02-模块解析与产物格式](../09-工程化/02-模块解析与产物格式.md)。

## 连接：与浏览器对照

同一个 `hello, world`，两个宿主的写法与运行方式都不同：

| | Node.js | 浏览器 |
|---|---|---|
| 运行入口 | `node hello.js` | `<script src="hello.js">` |
| 输出去向 | `console.log` → 终端 | `console.log` → DevTools 控制台 |
| 直接输出的 API | `process.stdout.write` | `document.body.textContent = ...` |
| 语言之外的能力 | 文件、网络、进程 | DOM、渲染、用户事件 |
| 模块加载 | 从磁盘读，由 Node 解析 | 从网络取，由 HTML 规范解析 |

`console` 两个宿主都有——它是被双方共同采纳的 Web 平台 API，不属于 ECMA-262。**"这个 API 有没有"永远是在问宿主，不是在问语言。**

## 边界

- **Node.js 不是浏览器**：没有 `document`、`window`、DOM 事件。写浏览器代码要用浏览器跑（或 [09-工程化/03-打包与转译](../09-工程化/03-打包与转译.md) 里的开发服务器）。
- **浏览器不是 Node.js**：没有 `fs`、`process`、`require`。也不能执行 `node` 命令。
- **安装的是宿主，不是语言**：升级 Node 版本改变的是引擎与宿主 API（能"用"什么），不改变 ECMA-262 的语义（代码"写"成什么样）。两者的错位见 [13-版本演进](../13-版本演进/)。
