# 模块

> 前置：[05-对象与类](./05-对象与类.md) · 后续：[07-错误处理](./07-错误处理.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

**模块**是文件级的封装单元：文件内的绑定默认对外不可见，只有显式导出的部分能被外部取用。它解决的是"多个文件拼成一个程序时，名字如何不互相污染、依赖如何表达"。

JavaScript 有两套模块系统，差异不在语法糖，而在**绑定何时确定**：

| | CommonJS | ESM（ECMAScript Modules） |
|---|---|---|
| 绑定确定时机 | **运行时**——`require` 执行到才加载 | **解析时**——静态结构，执行前已知 |
| 加载方式 | 同步（读完才继续） | 异步（浏览器要能边取边解析） |
| 规范归属 | Node.js 定义 | ECMA-262 定义（加载算法由宿主补充） |

这条"何时确定"的差异是后面所有具体区别的源头——静态结构让 ESM 能做 tree-shaking（打包时删除未使用的导出）、能在加载前发现拼写错误；动态加载让 CommonJS 能按条件 `require`、能读到运行期才知道的路径。

## 机制

### CommonJS：一个被包装的函数

Node 执行 `.cjs`（或判定为 CommonJS 的 `.js`）文件时，把整个文件包进一个函数再交给 V8。包装函数的形参列表是 Node 的公开接口：

```console
$ node -e 'console.log(require("node:module").wrapper)'
[ '(function (exports, require, module, __filename, __dirname) { ',
  '\n});' ]
```

这正是 [01-安装与第一个程序](./01-安装与第一个程序.md) 里 `--print-bytecode` 看到的那个"顶层包装函数"。五个形参就是 CommonJS 模块能用的全部隐式绑定：

- `module`：模块对象，`module.exports` 是导出内容的**唯一真相**；
- `exports`：初始时与 `module.exports` 指向同一对象的**别名**；
- `require`：加载函数；
- `__filename` / `__dirname`：当前文件的绝对路径与所在目录。

`exports` 是别名，所以**给它加属性有效、给它整体赋值无效**：

```javascript
// a.js
exports.x = 1;                 // 有效：改的是 module.exports 指向的对象
module.exports = { y: 2 };     // 整体换掉 module.exports
```

```console
$ node -e 'console.log(JSON.stringify(require("./a.js")))'
{"y":2}
```

`x` 丢了——`exports` 仍指着**旧**对象，而外部拿到的是 `module.exports` 现在指的新对象。**要么只用 `exports.x = …`，要么只用 `module.exports = …`，不要混。**

**`require` 带缓存**，同一路径只执行一次：

```console
$ node -e 'console.log(require("./counter.js"), require("./counter.js"))'
1 1
```

缓存键是**解析后的绝对路径**。删除 `require.cache` 里的条目才能重新执行——这既是性能来源（模块体只跑一次），也是状态共享的来源（单例即由此实现）。

`require` 也能直接读 JSON，返回解析后的对象：

```console
$ node -e 'console.log(require("./d.json"))'
{ k: 1 }
```

### ESM：静态结构与活绑定

ESM 的 `import` / `export` **只能出现在顶层**，不能在 `if` 里、不能在函数里。这不是限制而是前提：解析器在**执行任何代码之前**就能扫出完整的依赖图。需要按条件加载时用动态 `import()`——它返回 Promise（异步结果的句柄，见 [04-异步与并发/02-回调到Promise](../04-异步与并发/02-回调到Promise.md)），可以出现在任何位置。

ESM 导出的是**绑定本身，不是值的拷贝**。这称为**活绑定**（live binding）：

```javascript
// lib.mjs
export let count = 0;
export function bump() { count++; }
```

```javascript
// use.mjs
import { count, bump } from "./lib.mjs";
console.log(count);   // 0
bump();
console.log(count);   // 1  ← 导入方看到的是最新值
```

```console
$ node use.mjs
0
1
```

对比 CommonJS：`require` 拿到的是导出对象的**快照引用**，重新赋值 `module.exports.x` 对已导入方不可见（改对象的属性可见，换整个对象不可见）。

ESM 顶层还有三处与 CommonJS 不同：

```console
$ node esm.mjs
顶层 this = undefined
__dirname -> ReferenceError
import.meta.url 存在: string
顶层 await 可用
```

- **顶层 `this` 是 `undefined`**（CommonJS 里是 `module.exports`）；
- **没有 `__dirname` / `__filename`**——它们由 CommonJS 的包装函数提供，ESM 改用 `import.meta.url`（一个 `file://` URL），需要路径时自行转换；
- **支持顶层 `await`**（CommonJS 不支持，见 [01-安装与第一个程序](./01-安装与第一个程序.md) 的实测）。

### 哪种模块：判定顺序

`.mjs` 恒为 ESM，`.cjs` 恒为 CommonJS，`.js` 则看最近的 `package.json` 的 `"type"` 字段，都没有时按源码语法自动判定。判定规则与实测见 [01-安装与第一个程序](./01-安装与第一个程序.md)；解析算法与条件导出的完整展开见 [09-工程化/02-模块解析与产物格式](../09-工程化/02-模块解析与产物格式.md)。

### 互操作

两套系统在同一个进程里要能互相调用。被测的 `cjs-lib.cjs`（注意写法：`exports.xxx = …` 的形式才能被静态分析出具名导出）：

```javascript
// cjs-lib.cjs
exports.name = "cjs-lib";
exports.extra = "额外属性";
```

两个方向都已实测（Node 24.13.1）：

```console
$ node esm-use.mjs          # ESM 导入 CommonJS
默认导入 = {"name":"cjs-lib","extra":"额外属性"}
具名导入 extra = 额外属性

$ node cjs-use.cjs          # CommonJS require ESM
require(ESM) 成功: {"__esModule":true,"default":"默认导出","v":42}
```

- **ESM 导入 CommonJS**：`module.exports` 整体成为**默认导出**；其属性同时可作为具名导入（Node 靠静态分析 `exports.xxx = …` 实现，分析不出的属性只能用默认导入取）。
- **CommonJS `require` ESM**：Node 24 已默认支持，返回一个含 `default` 与各具名导出的对象。早期 Node 版本会抛错——这是宿主能力，不是语言规则。

## 连接：CommonJS 与 ESM 对照

| | CommonJS | ESM |
|---|---|---|
| 导入写法 | `const m = require("./m")` | `import m from "./m.mjs"` |
| 导出写法 | `module.exports = …` / `exports.x = …` | `export default …` / `export const x = …` |
| 位置限制 | 任意位置，可条件加载 | 必须顶层，静态 |
| 导出内容 | 值（对象引用快照） | 绑定（活绑定） |
| 加载时机 | 同步，执行到才加载 | 异步，先建依赖图 |
| 顶层 `await` | 不支持 | 支持 |
| `this`（顶层） | `module.exports` | `undefined` |
| `__dirname` | 有 | 无（用 `import.meta.url`） |
| Tree-shaking | 难（结构动态） | 可行（结构静态） |

**新代码用 ESM**。CommonJS 仍需理解，因为 `node_modules` 里大量既有包是 CommonJS，互操作不可避免。

## 边界

- **`import` 的路径解析规则与 `require` 不同**：ESM 要求写全扩展名（`./m.js` 而非 `./m`），目录导入也不自动找 `index.js`——这些差异归 [09-工程化/02-模块解析与产物格式](../09-工程化/02-模块解析与产物格式.md)。
- **模块只执行一次**，无论被导入多少次。模块顶层的副作用因此只发生一次——这是共享状态的机制，也是意外的全局初始化的来源。
- **循环依赖在 ESM 里可用，在 CommonJS 里容易拿到半成品**：ESM 的活绑定允许"先引用后定义"，CommonJS 拿到的是执行到一半的 `module.exports`。避免循环依赖仍是首选。
