# 控制流程

> 前置：[02-绑定与类型](./02-绑定与类型.md) · 后续：[04-函数](./04-函数.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

控制流程回答三个问题：**哪些语句执行**（分支）、**执行几次**（循环）、**从哪里跳出去**（跳转）。JavaScript 在这里没有独有的构造——`if`、`for`、`while`、`try` 都是 C 系语言的通用形状。

它真正区别于 C 系语言的是两处：**条件位置接受任意值**（没有"必须是布尔"的约束，靠隐式转换），以及**多了一类循环**——`for...of` 走的是[迭代协议](../02-对象模型与运行时/05-迭代协议与生成器.md)，而不是下标或键名。后者是理解"为什么数组、`Map`、`Set`、生成器能用同一种循环"的入口。

## 机制

### 分支

`if` / `else` 的条件位置接受任意值，按**真值性**（truthiness）判定：`false`、`0`、`-0`、`0n`、`""`、`null`、`undefined`、`NaN` 这八个为假，**其余全为真**（包括 `[]`、`{}`、`"0"`、`"false"`）。

`switch` 的比较用**严格相等**（`===`），不做隐式转换：

```console
$ node -e 'switch("1"){ case 1: console.log("命中"); break; default: console.log("未命中"); }'
未命中
```

字符串 `"1"` 与数字 `1` 类型不同，不匹配。这是 `switch` 最常见的失手点——`==` 会在别处静默通过，这里不会。

### 循环：迭代类四种，判据是"谁提供下一个值"

| 写法 | 值从哪来 | 遍历对象 | 能否 `await` |
|---|---|---|---|
| `for (let i…)` | 计数器 | 任意，自己索引 | 否 |
| `for...in` | 对象的**可枚举字符串键** | 对象（含继承来的键） | 否 |
| `for...of` | **迭代器协议** | 任何实现了 `Symbol.iterator` 的值 | 否（用 `for await...of`） |
| `for await...of` | 异步迭代器协议 | 异步可迭代对象 | 是 |

`for...in` 与 `for...of` 的差异不是风格问题，是遍历的东西根本不同：

```console
$ node -e 'const a=[10,20]; a.extra="x"; const k=[]; for(const i in a) k.push(i); console.log(k.join(","));'
0,1,extra
$ node -e 'const a=[10,20]; a.extra="x"; const v=[]; for(const x of a) v.push(x); console.log(v.join(","));'
10,20
```

`for...in` 给出的是**键名字符串**（数组的键就是下标字符串，外加挂上去的 `extra`）；`for...of` 给出的是**值**。数组用 `for...of`（或 `forEach`），`for...in` 留给需要枚举对象键的场合——但它会带上原型链上的可枚举键，通常不是想要的结果。

`for await...of` 的机制归 [03-async/await 与异步模式](../04-异步与并发/03-async-await与异步模式.md)。

`while` / `do...while` 不进这张表——它们不由"下一个值"驱动，由**条件**驱动：条件为真就继续，差异只在 `do...while` 先执行一次再判断。条件位置同样按真值性判定。条件表达式（三元）`cond ? a : b` 是同一判定的表达式形态：能出现在赋值与参数位置，这是它与 `if` 的唯一分工。

### 跳转

`break` 退出最近一层循环，`continue` 跳过本次迭代，`return` 退出函数，`throw` 抛出一个值。要跳出**多层**循环需要标签：

```console
$ node -e 'outer: for(let i=0;i<3;i++){ for(let j=0;j<3;j++){ if(i===1&&j===1){ console.log("跳出外层"); break outer; } } }'
跳出外层
```

标签是唯一能让 `break` 指定目标的写法。若不写标签，内层 `break` 只退出内层循环，外层继续。

### 短路求值与空值合并

`&&` 和 `||` **不返回布尔值**，返回参与运算的那个操作数——这是它们能当默认值用的原因，也是误用的来源：

```console
$ node -e 'console.log(0||5, "|", 0??5, "|", ""??5, "|", null??5)'
5 | 0 |  | 5
```

`||` 把**所有假值**当作"没有值"，于是 `0`、`""` 也会被替换掉；`??`（空值合并）只在 `null` 与 `undefined` 时替换。**默认值场景用 `??`**，除非确实想连 `0` 和 `""` 一起替换。

`?.`（可选链）在左侧为 `null` / `undefined` 时**短路整条链**——不只是这一步返回 `undefined`，后续的调用与属性访问都不发生：

```console
$ node -e 'let n=0; const f=()=>{n++;return {}}; f()?.g?.(); f()?.g?.(); console.log(n)'
2
```

`f()` 执行了两次（它是链的起点，未被短路），但 `g` 不存在，`?.()` 没有调用任何东西。这个区别在副作用存在时很关键。

三个逻辑赋值运算符是上述规则的复合形式：`a ??= b` 等价于 `a ?? (a = b)`，同理 `||=`、`&&=`：

```console
$ node -e 'let a=null; a??=7; let b=0; b||=7; let c=1; c&&=7; console.log(a,b,c)'
7 7 7
```

### 异常作为控制流

`try` / `catch` / `finally` 的语义有一条容易忽略的规则：**`finally` 里的 `return` 会覆盖 `try` 里的 `return`**。因为 `finally` 在控制权离开 `try` 块之前执行，此时它若再指定一个返回值，就以它为准。

`catch` 绑定的参数在不需要时可以省略（`catch {}`，ES2019）。抛出与捕获的完整机制——错误对象、自定义错误、`cause`、栈展开——归 [07-错误处理](./07-错误处理.md)。

## 连接：与静态类型语言对照

| | JavaScript | Java / C++ |
|---|---|---|
| 条件位置 | 任意值，按真值性判定 | 必须是布尔 |
| `switch` 比较 | `===`，不转换 | 整型/枚举相等 |
| 多值匹配 | 无（用 `if` 链或 `switch` 穿透） | `switch` 可枚举 |
| 遍历集合 | `for...of` 走迭代协议，与容器解耦 | 迭代器模式需显式实现 |
| 默认值 | `??` 运算符 | 函数重载或三元 |

## 边界

- **`switch` 的穿透是默认行为**：不写 `break` 会继续执行后续 `case`。这是 C 的遗留，偶尔被刻意利用（多个 `case` 共享一段代码），但默认形态容易出错。
- **`for...in` 不适合数组**：它枚举键名（字符串），且包含原型链上的可枚举属性。数组用 `for...of`。
- **`try` 不是性能陷阱，但也不是免费**：现代引擎对不抛异常的 `try` 块几乎零开销，成本发生在真正抛出并展开栈时（见 [07-错误处理](./07-错误处理.md)）。
