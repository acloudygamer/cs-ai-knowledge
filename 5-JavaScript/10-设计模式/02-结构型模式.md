## 装饰器模式

### 定义

**装饰器模式是一种通过包装已有对象动态添加职责的结构。**

### 数据流

<pre>
client ──new Milk(coffee)──▶ CoffeeDecorator
                                   │
                              this.coffee = coffee
                                   │
                              coffee.cost() + 1.5
</pre>

### 机制

Decorator 与原对象实现相同接口，在转发调用前后可以增加额外行为。优于继承之处在于：装饰顺序可以自由组合，继承层次不会膨胀，且可以运行时动态增删。ES7 装饰器语法是语言层面的语法糖，本质仍是方法拦截。

### 代码

```javascript
class Coffee {
  cost() { return 5; }
}

class CoffeeDecorator {
  constructor(coffee) { this.coffee = coffee; }
  cost() { return this.coffee.cost(); }
}

class Milk extends CoffeeDecorator {
  cost() { return this.coffee.cost() + 1.5; }
}
```

```javascript
class Sugar extends CoffeeDecorator {
  cost() { return this.coffee.cost() + 0.5; }
}
```

## 适配器模式

### 定义

**适配器模式是一种将不兼容接口转换为调用方期望接口的结构。**

### 数据流

<pre>
client ─adaptee.method(args)──▶ Adapter
                                      │
                                 translate args
                                      │
                                 target.adaptedMethod(transformed)
                                      │
                                 translate result
                                      │
                                 ◀─── result
</pre>

### 机制

适配器解决"接口不匹配"问题：第三方库或旧系统接口与当前代码不兼容时，不需要改动两边代码，只需增加一层转换。参数格式、返回值格式、调用约定都可以在适配器内处理。代理与适配器的区别在于：代理与原对象接口相同只是控制访问，适配器接口不同做格式转换。

### 代码

```javascript
class OldPaymentSystem {
  processPayment(amount, userId) { return { id: 'OLD_123' }; }
}

class PaymentAdapter {
  constructor() { this.newAPI = new NewPaymentAPI(); }
  processPayment(amount, userId) {
    const details = { amount, method: 'credit_card', userId };
    return this.newAPI.pay(details).then(r => ({ id: r.id, status: r.status }));
  }
}
```

```javascript
class UserServiceAdapter {
  constructor() { this.service = new ExternalUserService(); }
  async getUser(id) {
    const xml = await this.service.fetchUser(id);
    return {
      name: xml.getElementsByTagName('name')[0],
      email: xml.getElementsByTagName('email')[0]
    };
  }
}
```

## 代理模式

### 定义

**代理模式是一种通过替代目标对象来控制对其访问的结构。**

### 数据流

<pre>
client ──proxy.display()──▶ ImageProxy
                                  │
                         realImage?──no──▶ new Image(url)
                                  │              │
                         realImage──────────────┘
                                  │
                         realImage.display()
</pre>

### 机制

代理与真实对象实现相同接口，但在调用真实对象前后可以插入额外逻辑：懒加载（虚拟代理）、权限检查（保护代理）、结果缓存（缓存代理）、日志记录等。代理不修改真实对象的逻辑，只在访问层面做 Gatekeeping。

### 代码

```javascript
class Image {
  constructor(url) { this.url = url; }
  display() { return `Displaying ${this.url}`; }
}

class ImageProxy {
  constructor(url) { this.url = url; this.realImage = null; }
  display() {
    if (!this.realImage) this.realImage = new Image(this.url);
    return this.realImage.display();
  }
}
```

```javascript
class BankAccountProxy {
  constructor(account, role) { this.account = account; this.role = role; }
  withdraw(amount) {
    if (this.role !== 'admin' && amount > 1000) throw Error('unauthorized');
    return this.account.withdraw(amount);
  }
}
```

```javascript
class CalculatorProxy {
  constructor() { this.calc = new Calculator(); this.cache = new Map(); }
  calculate(expr) {
    if (this.cache.has(expr)) return this.cache.get(expr);
    const result = this.calc.calculate(expr);
    this.cache.set(expr, result);
    return result;
  }
}
```
