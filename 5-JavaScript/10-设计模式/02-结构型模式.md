## 装饰器模式

### 定义

**装饰器模式通过包装已有对象动态添加职责，被装饰对象与装饰器实现相同接口，调用方无感知差异。**

### 数学模型

设被装饰对象 $C$ 的原始方法为 $f: X \rightarrow Y$，装饰器 $D$ 包装 $C$ 后，新方法 $f'$ 可表示为：

$$
f' = g \circ f \circ h
$$

其中 $h: X \rightarrow X$（参数预处理，如验证、转换）、$g: Y \rightarrow Y$（返回值后处理，如缓存、日志）。装饰器可嵌套，设装饰器链 $(D_1, D_2, \dots, D_n)$：

$$
f_n' = D_n(D_{n-1}(\dots D_1(C) \dots ))
$$

复合效果等价于 $h_n \circ \dots \circ h_1 \circ f \circ g_1 \circ \dots \circ g_n$。注意装饰顺序影响最终行为（如 `Milk(Sugar(coffee))` vs `Sugar(Milk(coffee))`），因为 $g_i \circ g_j \neq g_j \circ g_i$ 通常不成立。

### 数据流

<pre>
client ──new Milk(coffee)──▶ CoffeeDecorator
                                   │
                              this.coffee = coffee
                                   │
                              coffee.cost() + 1.5
</pre>

### 机制

Decorator 与原对象实现相同接口，在转发调用前后可以增加额外行为。优于继承之处在于：装饰顺序可以自由组合，继承层次不会膨胀，且可以运行时动态增删。

**ES7 装饰器语法的本质**：装饰器 `@decorator` 是编译时语法糖，等价于 `Class = decorator(Class)`。它允许在类定义时附加元编程行为，但底层仍是方法属性描述符的读写——没有引入新的运行时能力，只是让写法更简洁。

**违反约束的后果**：
- 装饰器链过长时，每次方法调用都要穿越整个调用链，性能开销线性累积。
- 若装饰器忘记调用 `super.method()` 或忘记返回，链条会断裂或返回 `undefined`。
- 装饰器与 `this` 绑定问题：若原始方法内部使用 `this`，装饰器若不显式 `.call(this)` 绑定，`this` 会指向装饰器代理而非原对象。

### 参考存根

```javascript
class Coffee {
  cost() { return 5; }
}
class CoffeeDecorator {
  constructor(coffee) { this.coffee = coffee; }
  cost() { return this.coffee.cost(); }
}
class Milk extends CoffeeDecorator {
  cost() { return this.coffee.cost() + 1.5; }
}
```

## 适配器模式

### 定义

**适配器模式将不兼容接口转换为调用方期望的接口，使原本接口不匹配的双方能够协同工作。**

### 数学模型

适配器是一个函数 $A: X_{adaptee} \rightarrow X_{client}$，它将 adaptee 的输入空间 $X_{adaptee}$ 映射为 client 期望的输入空间 $X_{client}$，并同时将返回值从 $Y_{adaptee}$ 映射回 $Y_{client}$：

$$
A = \phi_{out} \circ f_{adaptee} \circ \phi_{in}
$$

其中 $\phi_{in}: X_{client} \rightarrow X_{adaptee}$（参数翻译），$\phi_{out}: Y_{adaptee} \rightarrow Y_{client}$（返回值翻译）。适配器本身不改变被包装系统的语义，只做表示层的转换。

### 数据流

<pre>
client ─adaptee.method(args)──▶ Adapter
                                      │
                                 translate args
                                      │
                                 target.adaptedMethod(transformed)
                                      │
                                 translate result
                                      │
                                 ◀─── result
</pre>

### 机制

适配器解决"接口不匹配"问题：第三方库或旧系统接口与当前代码不兼容时，不需要改动两边代码，只需增加一层转换。参数格式、返回值格式、调用约定都可以在适配器内处理。

**代理与适配器的本质区别**：代理接口与原对象相同，只做访问控制（如懒加载、权限检查）；适配器接口与原对象不同，做格式转换。这是两种不同方向的重塑——代理保留接口，适配器改变接口。

**违反约束的后果**：
- 若适配器的翻译逻辑有误（如单位转换错误、字段映射缺失），调用方会收到错误数据且难以调试。
- 若 adaptee 抛出异常而适配器未做转换，调用方需了解 adaptee 的异常体系，泄露了底层实现细节。

### 参考存根

```javascript
class OldPaymentSystem {
  processPayment(amount, userId) { return { id: 'OLD_123' }; }
}
class PaymentAdapter {
  constructor() { this.newAPI = new NewPaymentAPI(); }
  processPayment(amount, userId) {
    const details = { amount, method: 'credit_card', userId };
    return this.newAPI.pay(details).then(r => ({ id: r.id, status: r.status }));
  }
}
```

## 代理模式

### 定义

**代理模式通过替代目标对象来控制对它的访问，代理与真实对象实现相同接口，调用方无感知差异。**

### 数学模型

代理对外暴露的接口 $P$ 与真实对象接口 $R$ 相同，即 $P = R$（同构）。代理在调用 $R$ 的方法前后插入额外逻辑 $g$ 和 $h$：

$$
\text{method}_{proxy} = g \circ \text{method}_R \circ h
$$

与装饰器的关键区别在于：装饰器添加新行为（职责），代理做访问控制（gatekeeping）。代理方法通常不是简单地转发，而是根据前置条件（权限检查、缓存判断）决定是否调用真实对象，或直接返回缓存结果。

### 数据流

<pre>
client ──proxy.display()──▶ ImageProxy
                                  │
                         realImage?──no──▶ new Image(url)
                                  │              │
                         realImage──────────────┘
                                  │
                         realImage.display()
</pre>

### 机制

代理与真实对象实现相同接口，但在调用真实对象前后可以插入额外逻辑：懒加载（虚拟代理）、权限检查（保护代理）、结果缓存（缓存代理）、日志记录等。代理不修改真实对象的逻辑，只在访问层面做 Gatekeeping。

**虚拟代理的数学描述**：设真实对象初始化代价为 $C_{init}$，代理模式下初始化被延迟到首次方法调用。若对象从未被访问，总初始化代价为 $0$；若被访问 $n$ 次，初始化代价均摊为 $C_{init} / n$。

**违反约束的后果**：
- 缓存代理若缓存失效策略不完善，会导致调用方获得过期数据（缓存污染）。
- 保护代理若权限检查逻辑有漏洞，可能让未授权调用穿透。
- 代理对象与真实对象的状态若不同步（如保护代理修改了对象状态但真实对象未被通知），会产生数据不一致。

### 参考存根

```javascript
class ImageProxy {
  constructor(url) { this.url = url; this.realImage = null; }
  display() {
    if (!this.realImage) this.realImage = new Image(this.url);
    return this.realImage.display();
  }
}
```
