## 策略模式

### 定义

**策略模式将一系列可互换算法封装为同一接口，调用方在运行时选择具体策略，无需修改上下文对象。**

### 数学模型

设策略接口定义方法签名 $f: X \rightarrow Y$，具体策略集合 $S = \{s_1, s_2, \dots, s_n\}$ 各实现 $f$。上下文对象维护一个指向当前策略的引用 $p \in S$，调用时执行：

$$
\text{context.execute}(x) = p.f(x)
$$

策略切换的时间复杂度为 $O(1)$（单纯指针替换）。与 if/switch 分支相比，策略模式将条件判断的复杂度从 $O(n)$（线性扫描分支）降为 $O(1)$，代价是增加策略类数量和虚表查找开销。

策略可组合：设复合策略 $s_{composite} = \text{compose}(s_a, s_b)$，复合结果仍满足接口 $f$，调用方无需知道内部是单策略还是组合策略——这是**策略的闭合性**。

### 数据流

<pre>
client ──setStrategy(strategy)──▶ ShoppingCart
                                        │
                                   cart.checkout()
                                        │
                                   strategy.pay(total)
</pre>

### 机制

将"使用哪个算法"的责任交给客户端（调用方），而不是在类内部 hardcode。策略类实现统一接口，客户端在运行时切换算法。优于 if/switch 分支在于：新增策略只需新增类，无需修改现有代码，符合开闭原则。

**策略模式与依赖注入的关系**：策略模式是依赖注入的其中一种表现形式——上下文对象不直接创建策略，而是由外部注入。这使得策略的替换可以在不修改上下文代码的情况下完成，也便于单元测试时注入 mock 策略。

**违反约束的后果**：
- 若策略接口定义了过多方法，添加新策略时需要实现所有方法，即使新策略与某些方法无关（接口臃肿）。
- 若策略之间需要共享状态，而接口设计未考虑，强行共享会破坏策略的独立性。

### 参考存根

```javascript
class PaymentStrategy {
  pay(amount) { throw Error('not implemented'); }
}
class CreditCardPayment extends PaymentStrategy {
  pay(amount) { return { success: true, method: 'credit_card' }; }
}
class ShoppingCart {
  setStrategy(strategy) { this.strategy = strategy; }
  checkout() { return this.strategy.pay(this.getTotal()); }
}
```

## 观察者模式

### 定义

**观察者模式在对象状态变更时自动通知依赖对象列表，被通知者无需了解发布者详情，实现发布-订阅解耦。**

### 数学模型

设 Subject 维护观察者集合 $O = \{o_1, o_2, \dots, o_n\}$。状态变更触发通知，通知操作的时间复杂度：

$$
T_{\text{notify}} = O(|O|)
$$

通知是**无事务性**的——若某个观察者的 `update()` 抛出异常，后续观察者仍会被通知（在大多数实现中）。设通知可靠性参数 $\rho \in [0, 1]$，实际到达率随观察者链中途异常而降低。

**推模式 vs 拉模式**：推模式（push）由 Subject 将变更数据直接推送给观察者，数据传输量 $D_{\text{push}}$ 固定但可能多余；拉模式（pull）只通知观察者状态已变更，观察者按需从 Subject 拉取，数据传输量按需分配但增加一次额外调用。

### 数据流

<pre>
Subject.setState(newState)
         │
    observers.forEach
         │
    ┌────┴────┐
    ▼         ▼
 Observer   Observer
  .update()  .update()
</pre>

### 机制

Subject 维护 observers 列表，状态变更时遍历通知。核心价值是松耦合：Subject 无需知道观察者具体是谁，只负责"有变化就通知"。常用于事件系统、响应式数据流、消息推送等场景。

**违反约束的后果**：
- 若观察者列表在通知过程中被修改（如 `update()` 内调用 `attach/detach`），会导致迭代器失效（ConcurrentModificationException 语义），部分观察者可能漏通知或重复通知。
- 若 Subject 状态变更过于频繁，观察者通知开销会成为性能瓶颈（发布者频率过高问题）。
- 若观察者依赖通知顺序，但实现中列表遍历顺序不确定，会导致不可重复的行为。

### 参考存根

```javascript
class Subject {
  constructor() { this.observers = new Set(); this.state = null; }
  attach(o) { this.observers.add(o); }
  notify() { this.observers.forEach(o => o.update(this.state)); }
  setState(s) { this.state = s; this.notify(); }
}
```

## 命令模式

### 定义

**命令模式将请求封装为对象，使请求发送者与接收者解耦，支持参数化、队列化、撤销/重做操作。**

### 数学模型

设命令历史栈 $H$ 和撤销栈 $U$。执行命令 `cmd` 的效果建模为状态转移：

$$
\text{state}' = \text{cmd.execute}(\text{state}),\quad H.\text{push}(\text{cmd}),\quad U.\text{clear}()
$$

撤销操作从 $H$ 弹出最近命令并调用其 `undo()`：

$$
\text{state} = \text{cmd.undo}(\text{state}),\quad U.\text{push}(\text{cmd}),\quad H.\text{pop}()
$$

撤销栈 $U$ 支持重做操作。设 $|H| = n$，$|U| = m$，撤销/重做的最坏时间复杂度为 $O(1)$。

命令可组合为宏命令 $C = \text{MacroCommand}(c_1, c_2, \dots, c_k)$，其 execute 序列执行 $\sum_i c_i.\text{execute}$，undo 逆序执行 $\sum_i c_{k-i}.\text{undo}$。

### 数据流

<pre>
client ──execute(cmd)──▶ Invoker
                              │
                         cmd.execute()
                              │
                         Receiver.action()
</pre>

### 机制

每个 Command 实现 execute/undo 接口，Invoker 持有命令历史队列。调用方与接收方解耦，命令可以序列化后排队、日志记录、撤销/重做。MacroCommand 组合多个命令实现批操作。

**命令模式的撤销语义**：撤销不是简单回滚状态，而是执行与原操作语义相反的操作。例如打开文件的命令对应关闭文件的撤销操作。这要求每个命令的 `undo()` 必须精确对应对称操作，否则多次撤销会导致状态偏移。

**违反约束的后果**：
- 若命令的 `execute()` 不是幂等的，撤销后再重做可能产生与首次执行不同的结果（违反幂等性原则）。
- 若命令持有外部资源（文件句柄、网络连接），撤销后资源已释放但历史栈仍持有命令引用，长时间运行可能导致资源泄漏。
- 若 `undo()` 抛出异常，撤销链会中断，用户无法继续撤销或重做。

### 参考存根

```javascript
class RemoteControl {
  constructor() { this.history = []; this.undone = []; }
  execute(cmd) { this.history.push(cmd); this.undone = []; return cmd.execute(); }
  undo() { const cmd = this.history.pop(); if (cmd) { this.undone.push(cmd); cmd.undo(); } }
  redo() { const cmd = this.undone.pop(); if (cmd) { this.history.push(cmd); cmd.execute(); } }
}
```
