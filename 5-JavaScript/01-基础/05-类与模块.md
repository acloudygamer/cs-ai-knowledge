# 类与模块

## 定义

ES6 的 `class` 语法是**原型继承的语法糖**。类声明的本质是构造函数 + 原型方法的组合定义。ES6 模块（ESM）是**编译时静态分析的导出-导入契约**，导入绑定是对导出值的**只读引用**（live binding）。

## 数学模型

### 类声明的 TDZ 建模

类声明的提升与 `let` 类似，但存在差异：
$$
\text{class } C \{\ldots\} \text{ 在词法上被提升，但存在 TDZ}
$$

与函数声明的对比：
| 声明类型 | 提升 | TDZ | 声明前调用 |
|----------|------|-----|------------|
| 函数声明 | 完全提升 | 无 | 可调用（返回 undefined） |
| 类声明 | 词法提升 | 有 | ReferenceError |

### 原型链的长度约束

原型链长度过长会影响属性查找性能：
$$
O(\text{链长}) = O(h) \text{，其中 } h \text{ 是原型链深度}
$$

V8 对短原型链（< 4 层）有优化，超过后性能显著下降。

### 模块的静态分析建模

ESM 的 `import`/`export` 在**解析阶段**确定依赖图，而非运行时：
$$
\text{依赖图} = \text{StaticAnalysis}(\text{源代码})
$$

这意味着：
- 条件导入 `if (cond) import(...)` 是**语法错误**
- 循环依赖可能导致未初始化的绑定（值为 undefined）

## 数据流

### new Person() 的执行流程

<pre>
new Person(args)
    │
    ▼
创建空对象 {}
    │
    ▼
设置 [[Prototype]] → Person.prototype
    │
    ▼
Person 构造函数调用，this = 新对象
    │
    ▼
构造函数返回（若无显式返回对象，返回 this）
</pre>

### ESM 导入-导出数据流

<pre>
模块 A (export)
    │
    ▼
导出绑定（live binding，原值可被重新赋值）
    │
    ▼
模块 B (import)
    │
    ▼
导入绑定是对导出值的只读引用
    │
    ▼
模块 C 导入 B，B 再导入 A → 间接依赖追踪
</pre>

## 机制

### class 的本质：构造函数 + 原型链

```javascript
class Person {
    constructor(name) {
        this.name = name;  // 实例属性
    }
    greet() {             // 原型方法
        return `Hello, ${this.name}`;
    }
}
// 等价于：
function Person(name) { this.name = name; }
Person.prototype.greet = function() { return `Hello, ${this.name}`; };
```

`class` 语法不改变 JavaScript 的原型继承模型，只是提供更清晰的声明语法。

### extends 的原型链构造

```javascript
class Dog extends Animal {
    constructor(name, breed) {
        super(name);  // 调用 Animal 构造函数
        this.breed = breed;
    }
}
```

`extends` 建立以下原型链：
$$
\text{Dog.prototype.[[Prototype]]} \rightarrow \text{Animal.prototype}
$$
实例继承的查找路径：`dog → Dog.prototype → Animal.prototype → Object.prototype → null`

### 私有字段（#）的实现机制

`#` 前缀私有字段在**编译阶段**通过语法变换实现：
```javascript
class BankAccount {
    #balance = 0;  // 编译后：this.#balance → [[PrivateMap]].get(this)
}
```

私有字段存储在对象的 **PrivateMap** 中，键为 `#field` Symbol，外部访问在语法阶段就被拒绝。

### ESM vs CommonJS 的本质差异

| 维度 | ESM | CommonJS |
|------|-----|----------|
| 加载时机 | 编译时（静态分析） | 运行时（执行时加载） |
| 导入绑定 | 只读引用（live binding） | 值拷贝 |
| 顶层级 | 必须在模块顶层 | 可在函数内 |
| this | undefined | module.exports |
| 循环依赖 | 支持，但可能未初始化 | 支持 |

**live binding 的含义**：
```javascript
// lib.js
export let count = 0;
setTimeout(() => count++, 100);

// main.js
import { count } from './lib.js';
console.log(count);  // 0
setTimeout(() => console.log(count), 200);  // 1（可见更新）
```

CommonJS 是值拷贝，导出值变化不会影响导入者。

## 参考存根

```javascript
// 类声明 TDZ
// const p = new Person('Bob');  // ReferenceError
class Person {
    constructor(name) { this.name = name; }
}

// 原型链演示
class Animal { speak() { return '...'; } }
class Dog extends Animal {
    speak() { return 'Woof'; }
}
const dog = new Dog();
dog instanceof Dog      // true
dog instanceof Animal   // true
dog instanceof Object   // true

// ESM 循环依赖
// a.js
import { b } from './b.js';
export const a = b ? 'A' : undefined;

// b.js
import { a } from './a.js';
export const b = a ? 'B' : undefined;
// 结果：a 和 b 都可能是 undefined（取决于求值顺序）
```
