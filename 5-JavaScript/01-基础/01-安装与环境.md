# 安装与环境

## 定义

JavaScript 运行时环境是执行 JavaScript 代码的容器。Node.js 是基于 V8 引擎的服务器端运行时，npm 是其包管理器，npx 允许直接执行包命令，nvm/n 是 Node.js 版本管理器。这些工具构成 JavaScript 开发的基础设施层，负责代码的解析、执行、依赖管理和调试。

## 数学模型

### nvm 的符号链接切换

nvm 通过**符号链接切换**实现多版本管理：
$$
\text{node}_{\text{current}} \rightarrow \text{Link}(v_{\text{selected}}) = \text{~/.nvm/versions/node/vX.Y.Z/bin/node}
$$

版本切换本质是重定向 `node` 命令的查找路径（$PATH$ 环境变量），不影响已运行的进程。

### npm 的依赖解析

npm 使用**语义版本（SemVer）** + **package-lock.json** 锁定精确版本：
$$
\text{spec} = \text{major}.\text{minor}.\text{patch}[-\text{pre-release}][+\text{build}]
$$

版本范围解析规则：
$$
\text{兼容更新}(\hat{})\rightarrow \text{major} = \text{frozen}, \quad \text{minor}, \text{patch} \in \mathbb{N}
$$
$$
\text{补丁更新}(\tilde{})\rightarrow \text{major.minor} = \text{frozen}, \quad \text{patch} \in \mathbb{N}
$$

### node_modules 的目录结构

node_modules 的安装策略可建模为**层次约束满足问题**：
$$
\forall \text{package } p: \quad \text{parent}(p) \in \mathbb{P} \cup \{\text{root}\}
$$
- **扁平化**：无冲突时安装到顶层
- **嵌套**：版本冲突时安装到父包目录
- **提升**：共用依赖出现在多个子包时提升到顶层

## 机制

### Node.js 与浏览器的执行模型对比

| 维度 | Node.js | 浏览器 |
|------|---------|--------|
| 引擎 | V8 | V8 / SpiderMonkey / JavaScriptCore |
| 全局对象 | global, process | window, document |
| 模块系统 | ESM + CommonJS | ESM（需打包工具） |
| I/O 模型 | 异步非阻塞 | 异步非阻塞 |
| 入口 | `node index.js` | `<script>` 或 ESM |
| 文件系统 | fs 模块完整访问 | 受限（File System Access API） |
| 网络 | http/net 模块 | fetch/WebSocket |

### npm install 的安装策略

**三层安装规则**：
1. **版本解析**：根据 SemVer 规则确定满足条件的版本
2. **依赖展开**：递归解析所有传递依赖
3. **目录安置**：根据冲突检测结果决定安装位置

**违反约束的后果**：
- **幽灵依赖**：未在 package.json 声明但实际可 require 的包。Hoisting 使子包的依赖出现在顶层，升级可能丢失。
- **依赖三角**：嵌套导致的深路径增加 Windows 长路径问题（260 字符限制）
- **平面复杂度**：扁平化使同一包的多版本共存于不同路径

### VS Code 的 JavaScript 支持原理

VS Code 内置 TypeScript 语言服务（基于 TSServer），通过以下管道提供智能提示：

**解析阶段**：
1. 词法分析 → Token 流
2. 语法分析 → AST
3. 语义分析 → 类型检查

**推理阶段**：
- **JSDoc 注解**：从 `@type`, `@param` 提取类型信息
- **类型推断**：基于变量赋值、函数返回值推断类型
- **控制流分析**： narrowing 推导

**补全阶段**：
1. 查询类型图
2. 匹配符号
3. 返回候选列表（含文档）

### Chrome DevTools 的调试模型

Chrome DevTools 通过 **CDP（Chrome DevTools Protocol）** 与 V8 引擎通信：

| 操作 | CDP 命令 | 底层机制 |
|------|----------|----------|
| 断点 | `Debugger.setBreakpoint` | 字节码插入 `debugger` 指令 |
| 变量观察 | `Runtime.getProperties` | 读取 V8 堆快照 |
| 调用栈 | `Debugger.getCallStack` | 遍历执行上下文链 |
| 单步执行 | `Debugger.stepInto/Over/Out` | 控制 V8 执行流 |

**源码映射**（Source Maps）：编译后的代码（如 TypeScript/Bundler）映射回原始源码，使断点调试可行。

## 参考存根

```javascript
// package.json 的 engines 字段限制 Node 版本
{
  "engines": {
    "node": ">=26.0.0"
  }
}

// .nvmrc 文件锁定项目 Node 版本
// 在项目根目录执行：
// echo "26" > .nvmrc
// nvm use (自动读取 .nvmrc)

// 验证 Node 和 npm 版本
console.log(process.version);    // v26.0.0
console.log(process.platform);  // darwin / linux / win32
console.log(process.arch);      // x64 / arm64

// 查看 npm 包搜索路径
console.log(require.resolve.paths('lodash'));
```
