# 安装与环境

## 定义

JavaScript 运行时环境是执行 JavaScript 代码的容器。Node.js 是基于 V8 引擎的服务器端运行时，npm 是其包管理器，npx 允许直接执行包命令，nvm 是 Node.js 版本管理器。这些工具构成 JavaScript 开发的基础设施层。

## 数学模型

### nvm 的版本切换机制

nvm 通过**符号链接切换**实现多版本管理：
$$
\text{node\_symlink} \rightarrow \text{~/.nvm/versions/node/vX.Y.Z/bin/node}
$$

版本切换本质是重定向 `node` 命令的查找路径，不影响已运行的进程。

### npm 的依赖解析

npm 使用**语义版本（SemVer）** + **package-lock.json** 锁定精确版本：
$$
\text{spec} = \text{major}.\text{minor}.\text{patch}[-\text{pre-release}][+\text{build}]
$$

- `^1.2.3`：兼容更新（允许 minor 和 patch 升级）
- `~1.2.3`：补丁更新（只允许 patch 升级）
- `1.2.3`：精确版本

## 数据流

<pre>
package.json
    │
    ├──> dependencies (运行时依赖)

    │
    ▼
node_modules/
    │
    ├──> .bin/ (可执行文件链接)
    │
    ▼

</pre>

## 机制

### Node.js 与浏览器的执行模型对比

| 维度 | Node.js | 浏览器 |
|------|---------|--------|
| 引擎 | V8 | V8 / SpiderMonkey / JavaScriptCore |
| 全局对象 | global, process | window |
| 模块系统 | ESM + CommonJS | ESM (需打包工具) |
| I/O 模型 | 异步非阻塞 | 异步非阻塞 |
| 入口 | `node index.js` | `<script>` 或 ESM |

### npm install 的安装策略

1. **扁平化**：优先将包安装到顶层 `node_modules`
2. **嵌套**：冲突版本或 `"nest": true` 时嵌套到各自父包的 `node_modules`
3. **hoisting**：子包共用的依赖提升到顶层，减少重复安装

**违反约束的后果**：
- 幽灵依赖：未在 package.json 声明但实际可 require 的包，升级可能丢失
- 依赖三角：嵌套导致的深路径增加 Windows 长路径问题

### VS Code 的 JavaScript 支持原理

VS Code 内置 TypeScript 语言服务（基于 TSServer），通过以下方式提供智能提示：

1. **语义分析**：解析 TypeScript/JavaScript 代码，生成 AST
2. **类型推断**：基于 JSDoc 注解和类型推断构建类型图
3. **自动补全**：查询类型图，返回成员列表

### Chrome DevTools 的调试模型

Chrome DevTools 通过 **CDP（Chrome DevTools Protocol）** 与 V8 通信：
- 断点：在指定行号插入 `debugger` 指令（字节码层）
- 变量观察：读取 V8 的堆快照
- 调用栈：记录 JavaScript 引擎的执行上下文链

## 参考存根

```javascript
// package.json 的 engines 字段限制 Node 版本
{
  "engines": {
    "node": ">=26.0.0"
  }
}

// .nvmrc 文件锁定项目 Node 版本
// echo "26" > .nvmrc
// nvm use (自动读取 .nvmrc)

// 验证 Node 和 npm 版本
console.log(process.version);  // v26.0.0
console.log(process.platform); // darwin / linux / win32
```
