# JavaScript 语言简介

## 定义

JavaScript 是一门基于原型继承的动态类型脚本语言，其核心执行模型是**事件循环驱动的单线程非阻塞 I/O**。1995 年 Brendan Eich 用 10 天设计，最初命名 Mocha，历经 LiveScript，最终因 Java 商业合作更名为 JavaScript。运行时环境（浏览器/Node.js）提供宿主 API，内存管理依赖垃圾回收器。

## 数学模型

### JIT 编译的热点检测

JavaScript 引擎（V8）的即时编译（JIT）策略基于函数调用频率：
$$
f_{\text{JIT}}(c_f) = \begin{cases}
\text{TurboFan编译} & c_f > T_{\text{hot}} \\
\text{字节码解释} & c_f \le T_{\text{hot}}
\end{cases}
$$
其中 $c_f$ 为函数 $f$ 的调用计数器，$T_{\text{hot}}$ 为热点阈值（V8 典型值为 2）。

### 隐藏类的结构化偏移查找

V8 的隐藏类（Hidden Class）机制将动态属性访问建模为**常数时间偏移查找**：
$$
\text{offset}(p, k) = \text{lookup}(\text{HC}(p), k) = O(1)
$$
相同结构的对象共享同一隐藏类，使 V8 能生成高效的机器码。对象的隐藏类在属性添加顺序改变时会发生**形状转换**（shape transition）。

### 事件循环的优先级模型

令 $t$ 为事件循环任意时刻，调度序列满足偏序关系：
$$
\text{Microtask} \prec \text{Macrotask} \prec \text{Rendering}
$$
微任务队列必须完全清空才会执行宏任务，渲染只在宏任务之间进行。

## 数据流

<pre>
源代码 (文本字符串)
    │
    ▼
┌──────────────────────────────┐
│  Parser (解析器)             │ ──→ AST（抽象语法树）
│  词法分析 + 语法分析          │
└──────────────────────────────┘
    │
    ▼
┌──────────────────────────────┐
│  Ignition (解释器)           │ ──→ Bytecode + 类型反馈
│  字节码执行 + 热点计数        │
└──────────────────────────────┘
    │
    ▼ (热点阈值触发)
┌──────────────────────────────┐
│  TurboFan (优化编译器)        │ ──→ 优化机器码
│  投机性优化 (Speculative)     │   基于类型反馈假设
└──────────────────────────────┘
    │
    ▼ (类型反馈失效时)
┌──────────────────────────────┐
│  Deoptimization              │ ──→ 回退字节码
│  撤销优化，恢复解释执行       │
└──────────────────────────────┘
</pre>

**所有权流转**：
1. 源代码（字符串）→ Parser（所有权归引擎）→ AST
2. AST → Ignition（解释执行，收集类型反馈）→ 热点函数标记
3. 热点函数 → TurboFan（生成优化机器码）
4. 类型失效 → Deoptimization → 回退字节码

## 机制

### 事件循环调度模型

JavaScript 的事件循环是**基于调用栈的任务调度器**，由以下组件协同工作：

**调用栈**（Call Stack）：同步代码按 LIFO 顺序执行，栈帧包含函数上下文、局部变量、PC 指针。

**微任务队列**（Microtask Queue）：Promise.then、queueMicrotask、MutationObserver。**清空全部**后再执行宏任务。

**宏任务队列**（Macrotask Queue）：setTimeout、setInterval、I/O、UI Rendering。**每次取一个**执行。

```javascript
while (true) {
    // 1. 执行调用栈中的所有同步代码
    while (callStack.notEmpty()) {
        execute(callStack.pop());
    }
    // 2. 清空微任务队列（全部）
    while (microtaskQueue.notEmpty()) {
        execute(microtaskQueue.dequeue());
    }
    // 3. 取一个宏任务执行
    if (macrotaskQueue.notEmpty()) {
        execute(macrotaskQueue.dequeue());
    }
    // 4. 渲染（浏览器环境）
    if (shouldRender()) {
        requestAnimationFrame();
        updateRendering();
    }
}
```

**关键约束**：微任务优先于宏任务。Promise.resolve().then() 会在 setTimeout 之前执行，即使 setTimeout 先入队。

### 内存模型与垃圾回收

JavaScript 堆内存分为**新生代**（Young Generation）和**老生代**（Old Generation）：

**Scavenge 算法**（新生代）：Cheney 算法，将活对象从 From 空间复制到 To 空间。
$$
T_{\text{Scavenge}} = O(N_{\text{live}})
$$
空间利用率 50%，适合生命周期短的对象。

**Mark-Sweep & Mark-Compact**（老生代）：
- 标记（Mark）：三色标记法（白/灰/黑），增量标记避免 Stop-the-World
- 清理（Sweep）：回收白色对象
- 压缩（Compact）：移动存活对象解决碎片

**违反约束的后果**：
- 内存泄漏：持有不需要的对象引用导致老生代快速填满，触发频繁 GC 停顿
- 意外全局变量：隐式全局变量绕过函数作用域，增加 GC 压力
- 大对象分配：大对象直接进入老生代，可能导致内存碎片

### JavaScript 与 ECMAScript 的关系

| 层次 | 实体 | 职责 |
|------|------|------|
| ECMAScript | ECMA-262 标准 | 语法、类型、语义、内置对象 |
| JavaScript 实现 | V8 / SpiderMonkey / JavaScriptCore | 解析器 + 解释器 + JIT 编译器 + 运行时 |
| 宿主环境 | 浏览器 / Node.js | 提供 DOM/BOM / 文件系统等宿主 API |

ECMAScript 定义了语言规范，JavaScript 是其主要实现。宿主 API（DOM、fetch、fs 等）不在 ES 规范范围内。

### 浏览器 JS vs Node.js JS 的本质差异

两者核心引擎相同（ES 规范一致），差异在于**宿主 API**：

| 宿主 API | 浏览器 | Node.js |
|----------|--------|---------|
| DOM | document、DOM 树操作 | 无（无 DOM） |
| BOM | window.location、navigator | 无 |
| 用户交互 | click、input 事件 | 无 |
| 网络 | fetch、WebSocket、XMLHttpRequest | http、net 模块 |
| 文件系统 | 受限（File System Access API） | fs 模块（完整） |
| 加密 | Web Crypto API | crypto 模块 |

**模块系统差异**：
- Node.js 默认 CommonJS（package.json 默认 `"type": "commonjs"`），需显式设置 `"type": "module"` 才启用 ESM
- 浏览器依赖打包工具（webpack、vite）处理 ESM

## JavaScript 优缺点的本质分析

### 优点

| 优点 | 本质原因 |
|------|----------|
| 无处不在 | 浏览器的唯一原生脚本语言，WASM 只是补充 |
| 全栈能力 | Node.js 将 V8 引擎移植到服务器端，复用同一语言生态 |
| 异步模型 | 事件循环天然适合 I/O 密集型（而非 CPU 密集型）场景 |
| 生态丰富 | npm 的去中心化包管理 + package.json 锁定版本 |

### 缺点

| 缺点 | 本质原因 |
|------|----------|
| 类型系统薄弱 | 弱类型 + 动态类型组合，设计哲学是"灵活优先"而非"安全优先" |
| 回调地狱 | 异步回调的组合逻辑缺乏线性结构，Promise 解决了这个问题 |
| 浮点精度 | IEEE 754 双精度浮点，0.1 + 0.2 !== 0.3 是规范行为 |

## 版本演进的里程碑

| 年份 | 版本 | 核心改进 |
|------|------|----------|
| 1997 | ES1 | 首个标准化 |
| 2009 | ES5 | JSON、严格模式、数组新方法 |
| 2015 | ES6 (ES2015) | class、Promise、箭头函数、let/const、模块、生成器 |
| 2016+ | ES2016~ES2026 | 每年一个小版本，持续补充语法糖和内建对象 |

## 适用场景

JavaScript 的**设计边界**：
- **擅长**：事件驱动 I/O、实时交互、跨平台脚本
- **不擅长**：CPU 密集型计算（应使用 Web Worker 或 WASM）、强类型安全场景

## 参考存根

```javascript
// 最小化事件循环演示
console.log('1');                                    // 同步：立即执行
setTimeout(() => console.log('3'), 0);             // 宏任务
Promise.resolve().then(() => console.log('2'));     // 微任务
// 输出顺序：1, 2, 3
// 原因：同步代码 → 微任务队列全部 → 宏任务队列一个
```
