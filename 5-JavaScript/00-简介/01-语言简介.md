# JavaScript 语言简介

## 定义

JavaScript 是一门基于原型继承的动态类型脚本语言，由 Brendan Eich 于 1995 年在 10 天内设计，最初命名为 Mocha，随后更名为 LiveScript，最终因与 Java 的商业合作更名为 JavaScript。其核心执行模型是**事件循环驱动的单线程非阻塞 I/O**，运行时环境（浏览器/Node.js）提供宿主 API，内存管理依赖垃圾回收器。

## 数学模型

JavaScript 引擎（以 V8 为例）的即时编译（JIT）策略可用以下模型近似：

设函数 $f$ 的调用频率为 $c_f$，热点阈值 $T_{hot}$：
$$
\text{if } c_f > T_{hot} \text{ then JIT-compile } f
$$

V8 的隐藏类（Hidden Class）机制将动态属性访问建模为**结构化偏移查找**：
$$
\text{offset}(p, k) = \text{lookup}(\text{HC}(p), k)
$$
其中 $\text{HC}(p)$ 是对象 $p$ 的隐藏类，$k$ 是属性键。相同结构的对象共享同一隐藏类，使 V8 能生成高效的机器码。

## 数据流

<pre>
源代码 (文本)
    │
    ▼
┌─────────────────────┐
│  Parser (解析)       │ ──→ AST（抽象语法树）
└─────────────────────┘
    │
    ▼
┌─────────────────────┐
│  Ignition (解释器)    │ ──→ Bytecode（字节码）+ 热点函数计数
└─────────────────────┘
    │
    ▼ (热点函数触发)
┌─────────────────────┐
│  TurboFan (优化编译器) │ ──→ 优化机器码 (Speculative Optimization)
└─────────────────────┘
    │
    ▼ (优化失败时去优化)
┌─────────────────────┐
│  Deoptimization      │ ──→ 回退到字节码解释执行
└─────────────────────┘
</pre>

**所有权流转**：源代码 → Parser（所有权归引擎）→ AST → Ignition（解释执行，收集类型反馈）→ 热点函数 → TurboFan（生成优化机器码）

## 机制

### 事件循环调度模型

JavaScript 的核心调度机制是**事件循环**（Event Loop），它基于调用栈和任务队列的协同工作：

1. **调用栈**（Call Stack）：同步代码在此按 LIFO 顺序执行
2. **微任务队列**（Microtask Queue）：Promise.then、queueMicrotask，**清空全部**后再执行宏任务
3. **宏任务队列**（Macrotask Queue）：setTimeout、setInterval、I/O，**每次取一个**执行

```
while (true) {
    // 1. 执行调用栈中的所有同步代码
    while (callStack.notEmpty()) {
        execute(callStack.pop());
    }
    // 2. 清空微任务队列
    while (microtaskQueue.notEmpty()) {
        execute(microtaskQueue.dequeue());
    }
    // 3. 取一个宏任务执行
    if (macrotaskQueue.notEmpty()) {
        execute(macrotaskQueue.dequeue());
    }
    // 4. 重复
}
```

**关键约束**：微任务优先于宏任务。这意味着 Promise.resolve().then() 会在 setTimeout 之前执行，即使 setTimeout 先入队。

### 内存模型与垃圾回收

JavaScript 堆内存分为**新生代**（Young Generation）和**老生代**（Old Generation）：

- **Scavenge 算法**（新生代）：Cheney 算法，将活对象从 From 空间复制到 To 空间，复杂度 O(N)，但内存利用率 50%
- **Mark-Sweep & Mark-Compact**（老生代）：三色标记 + 增量标记 + 懒清理，解决 Stop-the-World 问题

**违反约束的后果**：
- 内存泄漏：持有不需要的对象引用导致老生代快速填满，触发频繁 GC 停顿
- 意外全局变量：隐式全局变量绕过函数作用域，增加 GC 压力

### JavaScript 与 ECMAScript 的关系

| 层次 | 实体 | 职责 |
|------|------|------|
| ECMAScript | ECMA-262 标准 | 语法、类型、语义、内置对象 |
| JavaScript 实现 | V8 / SpiderMonkey / JavaScriptCore | 解析器 + 解释器 + JIT 编译器 + 运行时 |
| 宿主环境 | 浏览器 / Node.js | 提供 DOM/BOM / 文件系统等宿主 API |

ECMAScript 定义了语言规范，JavaScript 是其主要实现。宿主 API 不在 ES 规范范围内。

### 浏览器 JS vs Node.js JS 的本质差异

两者核心引擎相同（ES 规范一致），差异在于**宿主 API**：

- **浏览器**：DOM（document）、BOM（window.location）、用户交互（click 事件）、Web API（fetch、WebSocket）
- **Node.js**：文件 API（fs）、网络 API（net/http）、操作系统（os）、加密（crypto）

模块系统上，两者都支持 ESM（import/export）和 CommonJS（require/module.exports），但 Node.js 默认 CommonJS（package.json 默认 `"type": "commonjs"`），需显式设置 `"type": "module"` 才启用 ESM，浏览器环境依赖打包工具处理 ESM。

## JavaScript 优缺点的本质分析

### 优点的底层逻辑

| 优点 | 本质原因 |
|------|----------|
| 无处不在 | 浏览器的唯一原生脚本语言，WASM 只是补充 |
| 全栈能力 | Node.js 将 V8 引擎移植到服务器端，复用同一语言生态 |
| 异步模型 | 事件循环天然适合 I/O 密集型（而非 CPU 密集型）场景 |
| 生态丰富 | npm 的去中心化包管理 + package.json 锁定版本 |

### 缺点的底层逻辑

| 缺点 | 本质原因 |
|------|----------|
| 类型系统薄弱 | 弱类型 + 动态类型组合，设计哲学是"灵活优先"而非"安全优先" |
| 回调地狱 | 异步回调的组合逻辑缺乏线性结构，Promise 解决了这个问题 |
| 浮点精度 | IEEE 754 双精度浮点，0.1 + 0.2 !== 0.3 是规范行为，非 bug |

## 版本演进的里程碑

| 年份 | 版本 | 核心改进 |
|------|------|----------|
| 1997 | ES1 | 首个标准化 |
| 2009 | ES5 | JSON、严格模式、数组新方法 |
| 2015 | ES6 (ES2015) | class、Promise、箭头函数、let/const、模块、生成器 |
| 2016+ | ES2016~ES2026 | 每年一个小版本，持续补充语法糖和内建对象 |

## 适用场景

JavaScript 的**设计边界**：
- **擅长**：事件驱动 I/O、实时交互、跨平台脚本
- **不擅长**：CPU 密集型计算（应使用 Web Worker 或 WASM）、强类型安全场景

## 参考存根

```javascript
// 最小化事件循环演示
console.log('1');
setTimeout(() => console.log('3'), 0);
Promise.resolve().then(() => console.log('2'));
// 输出顺序：1, 2, 3（微任务先于宏任务）
```
