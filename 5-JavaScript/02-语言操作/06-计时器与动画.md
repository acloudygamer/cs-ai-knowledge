# 计时器与动画

## 定义

JavaScript 的定时机制分为两类：`setTimeout`/`setInterval` 是基于**宏任务队列**的延迟/周期执行；`requestAnimationFrame` 是与浏览器**渲染帧同步**的回调调度。两者都面临主线程阻塞问题——主线程繁忙时，定时器回调会被延迟。

## 数学模型

### 防抖与节流的时间模型

设事件流为时间序列 $\{t_i\}$，事件触发时刻为 $t_i$，延迟参数为 $\Delta t$：

**防抖（Debounce）**：

$$
T_{debounce}(t) = \begin{cases}
t + \Delta t & \text{重置计时器} \\
\text{不变} & \text{等待中}
\end{cases}
$$

防抖的输出函数在**最后一次触发**后 $\Delta t$ 时间执行。若事件在 $(t_{last}, t_{last}+\Delta t)$ 内再次触发，计时器重新开始。

**防抖的数学本质**：防抖是**时间窗口上的吸收态 Markov 链**——在窗口内任何新事件都重置计时器，直到窗口期结束才输出。

**应用场景**：用户停止输入后才执行搜索（`oninput`）、窗口调整结束后重新计算布局（`resize`）。

**节流（Throttle）**：

$$
T_{throttle}(t) = \begin{cases}
\text{执行} & t - T_{last} \geq \Delta t \\
\text{跳过} & t - T_{last} < \Delta t
\end{cases}
$$

节流的输出函数每 $\Delta t$ 时间**最多执行一次**。超出间隔后的第一次触发必然执行。

**节流的数学本质**：节流是**固定间隔采样的阶梯函数**——在每个长度为 $\Delta t$ 的时间窗口内，输出函数至多执行一次。

**应用场景**：滚动事件处理（每 16ms 最多执行一次）、拖拽位置更新。

### requestAnimationFrame 的帧同步

显示器刷新率通常为 60Hz（$\approx 16.67ms$/帧），部分高刷屏可达 120Hz（$\approx 8.33ms$/帧）：

$$
T_{frame} = \frac{1000}{fps} \quad \text{ms}
$$

`requestAnimationFrame` 回调在**下一帧渲染前**执行，保证动画更新与屏幕刷新同步，避免撕裂和卡顿。

**撕裂（Tearing）原因**：若动画更新与屏幕刷新不同步，显示器可能在绘制到一半时接收新数据，导致上下部分显示不同帧。这是由于显示器的刷新是逐行进行的，若在刷新过程中更新帧缓冲区，就会出现撕裂。

**帧同步的数学约束**：设渲染周期为 $T_{frame}$，回调执行时间为 $t_{cb}$，则必须满足 $t_{cb} < T_{frame}$ 才能保证不掉帧。

### setTimeout/setInterval 的精度约束

`setTimeout(fn, 0)` 不保证立即执行，而是将 `fn` 调度到**下一个宏任务队列**：

$$
T_{actual} = T_{set} + T_{idle} + T_{macroqueue}
$$

其中：
- $T_{set}$：设置的延迟
- $T_{idle}$：主线程空闲时间
- $T_{macroqueue}$：宏任务队列排队时间

**嵌套定时器延迟提升**（HTML 规范）：嵌套（5层以上）定时器的最小延迟提升到 4ms，防止恶意网页占用过多资源。

**定时器精度约束的形式化**：设定时器模块的最小分辨率为 $\epsilon$（通常约 4ms），则实际触发时间 $t_{trig}$ 满足：

$$
t_{trig} \geq t_{set} + \max(\Delta t_{min}, \epsilon)
$$

其中 $\Delta t_{min}$ 为设置的延迟。

## 数据流

```
setTimeout 流程：
setTimeout(fn, ms) → 浏览器定时器模块（独立于主线程）
                            ↓
                    ms 后 → fn 加入宏任务队列
                            ↓
                    主线程空闲时 → 执行 fn

setInterval 流程：
setInterval(fn, ms) → 浏览器定时器模块（独立于主线程）
                            ↓
                    每次 ms 间隔 → fn 加入宏任务队列
                            ↓
                    主线程空闲时 → 执行 fn
                    （若上次 fn 未执行完，新 fn 仍入队，不等待）

requestAnimationFrame 流程：
requestAnimationFrame(fn) → 注册下一帧回调
                                  ↓
                            浏览器渲染 pipeline（style → layout → paint → composite）
                                  ↓
                            fn(timestamp) 执行

防抖流程：
触发 → clearTimeout(timer) → setTimeout(fn, delay)
（若 delay 内再次触发，重新开始上述流程）

节流流程：
触发 → 检查 now - lastTime >= interval
                    ├── 是 → fn() → lastTime = now
                    └── 否 → 忽略

动画循环：
requestAnimationFrame(step)
    ↓
step(now):
    计算 p = (now - start) / duration
    更新 DOM 属性（transform/opacity）
    若 p < 1 → requestAnimationFrame(step)
    若 p >= 1 → 动画结束
```

## 机制

### 防抖与节流的选择

| 场景 | 策略 | 原因 |
|------|------|------|
| `oninput` 搜索建议 | 防抖 | 用户停止输入后才查询，减少服务器压力 |
| `onscroll` 滚动事件 | 节流 | 每 16ms 最多执行一次（60fps），避免帧丢失 |
| 窗口 `resize` | 防抖或节流 | resize 事件频繁，需控制处理频率 |
| 按钮防双击 | 防抖 | 等待操作完成后才能再次触发 |
| 拖拽位置更新 | 节流 | 每帧最多更新一次位置 |

### setInterval 的堆积问题

**`setInterval` 不保证执行间隔**：若 `fn` 执行时间超过 `ms`，或主线程长时间阻塞，下次 `fn` 会立即执行（无等待），导致**堆积**：

```javascript
// 危险：若 doWork 耗时超过 1000ms，将发生堆积
setInterval(doWork, 1000);

function doWork() {
  // 假设这里耗时 1500ms
  // 第 1 次：0ms 执行
  // 第 2 次：1000ms 入队（但主线程忙）
  // 第 3 次：2000ms 入队
  // 0ms → 1000ms → 2000ms → ... → 主线程最终执行多次
}
```

**堆积后果**：可能导致"动画一口气执行完"、"请求并发爆炸"。

**堆积量的数学分析**：设间隔为 $ms$，函数执行时间为 $t_{exec}$。若 $t_{exec} > ms$，则在时间 $T$ 内堆积的任务数为：

$$
N_{堆积}(T) = \left\lfloor \frac{T}{ms} \right\rfloor - \left\lfloor \frac{T}{t_{exec}} \right\rfloor
$$

**解决方案：链式 setTimeout**：

```javascript
(function loop() {
  doWork();
  setTimeout(loop, 1000); // 等待上一次执行完成后才设置下一次
})();
```

### requestAnimationFrame 的优势

| 维度 | setInterval | requestAnimationFrame |
|------|-------------|----------------------|
| 执行时机 | 宏任务队列 | 下一帧渲染前 |
| 屏幕同步 | 不同步 | 同步（避免撕裂）|
| 页面不可见 | 继续执行 | 暂停（节省 CPU/GPU）|
| 时间戳 | 无 | `DOMHighResTimeStamp`（约 1ms 精度）|
| 电池友好 | 否 | 是（不可见时暂停）|

### 动画性能优化

**触发重排的属性**（高成本）：改变几何属性

| 属性 | 影响 |
|------|------|
| `width`, `height` | 宽高变化触发重排 |
| `margin`, `padding` | 边距变化触发重排 |
| `top`, `left`, `right`, `bottom` | 定位变化触发重排 |
| `fontSize`, `lineHeight` | 字体变化触发重排 |
| `borderWidth` | 边框变化触发重排 |

**仅触发重绘的属性**（中等成本）：改变视觉样式

| 属性 | 影响 |
|------|------|
| `color` | 颜色变化触发重绘 |
| `background` | 背景变化触发重绘 |
| `visibility` | 显隐变化触发重绘 |
| `opacity` | 透明度变化（若在合成层）仅触发合成 |

**transform/opacity（合成层）**（最低成本）：

```javascript
// 使用 transform 而非 left/top
el.style.transform = `translateX(${x}px)`; // 合成层动画
el.style.left = `${x}px`; // 触发重排
```

**will-change 提示**：

```javascript
// 提前告知浏览器元素将变化
el.style.will-change = 'transform';
// 浏览器为元素创建独立合成层
```

### IntersectionObserver + 懒加载

滚动监听若使用 `throttle(scrollHandler, 16)`，当元素进入视口时可能已延迟一帧。使用 `IntersectionObserver` 可在元素交叉状态变化时**立即回调**（异步，不阻塞主线程）：

```javascript
const io = new IntersectionObserver((entries, obs) => {
  entries.forEach(e => {
    if (e.isIntersecting) {
      img.src = img.dataset.src; // 懒加载
      obs.unobserve(img);       // 停止观察
    }
  });
}, { rootMargin: '50px' }); // 提前 50px 触发
```

## 参考存根

```javascript
// 防抖
const debounce = (fn, ms) => {
  let t;
  return (...a) => { clearTimeout(t); t = setTimeout(() => fn(...a), ms); };
};

// 节流
const throttle = (fn, ms) => {
  let last = 0;
  return (...a) => {
    const now = Date.now();
    if (now - last >= ms) { last = now; fn(...a); }
  };
};

// leading/trailing 防抖（lodash 风格）
const debounceLR = (fn, ms, { leading = false, trailing = true } = {}) => {
  let t;
  return (...a) => {
    if (!t && leading) fn(...a);
    clearTimeout(t);
    t = setTimeout(() => { fn(...a); t = null; }, ms);
  };
};

// leading/trailing 节流
const throttleLR = (fn, ms, { leading = true, trailing = true } = {}) => {
  let last = 0, t;
  return (...a) => {
    const now = Date.now();
    if (!last && leading) last = now;
    const remaining = ms - (now - last);
    if (remaining <= 0) {
      if (t) clearTimeout(t), t = null;
      last = now;
      fn(...a);
    } else if (!t && trailing) {
      t = setTimeout(() => { fn(...a); last = leading ? Date.now() : 0; t = null; }, remaining);
    }
  };
};

// requestAnimationFrame 动画
const animate = (el, targetX, duration) => {
  const startX = el.offsetLeft;
  const start = performance.now();
  const step = now => {
    const p = Math.min((now - start) / duration, 1);
    el.style.transform = `translateX(${startX + (targetX - startX) * p}px)`;
    if (p < 1) requestAnimationFrame(step);
  };
  requestAnimationFrame(step);
};

// 链式 setTimeout（精确间隔，不堆积）
(function loop() {
  doWork();
  setTimeout(loop, 1000);
})();

// 滚动 + IntersectionObserver 懒加载
const io = new IntersectionObserver((entries, obs) => {
  entries.forEach(e => {
    if (e.isIntersecting) {
      img.src = img.dataset.src;
      obs.unobserve(img);
    }
  });
}, { rootMargin: '50px' });
document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));
```
