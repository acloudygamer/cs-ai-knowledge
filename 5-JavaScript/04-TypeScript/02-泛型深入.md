# TypeScript 泛型深入

> 泛型是 TypeScript 在编译时参数化类型的机制，使类型本身成为函数的输入，实现类型层面的 DRY。

## 定义

泛型的本质是**类型层面的参数多态**。在值层面，函数通过值参数实现参数化；在类型层面，泛型通过类型参数实现参数化。两者遵循相同的抽象原则：同一段代码可以操作多种数据类型，而无需为每种类型重复编写。

## 数学模型

**类型构造器**：泛型本身是一个从类型到类型的函数。设类型构造器 $G$ 的签名为 $G: \text{Type} \rightarrow \text{Type}$，则 $G<T>$ 的语义是：将类型 $T$ 映射为新类型 $G_T$。

**条件类型的语义**：
$$F<T> = \begin{cases} X & \text{if } T \subtype U \\ Y & \text{otherwise} \end{cases}$$

**分布式条件类型**：当 $T = T_1 | T_2 | ... | T_n$ 时，条件类型满足分配律：
$$F<T_1 | T_2 | ... | T_n> = F<T_1> | F<T_2> | ... | F<T_n>$$

这意味着 `ToArray<string | number>` 等价于 `string[] | number[]`——联合类型的每个成员独立经过条件类型变换后再合并。

**归约终点**：泛型类型检查最终归约为对基本类型（string、number、boolean、object）的成员访问检查，以及 extends 关键字定义的约束验证，全部在编译时完成。

## 数据流

<pre>
类型参数 T
    │
    ▼
泛型函数 <T> ──► 类型检查（编译器推导具体类型）
    │                 │
    │                 ▼
    │           Γ ⊢ T := concrete_type
    │                 │
    ▼                 ▼
类型擦除          编译产物（无泛型信息）
    │
    ▼
JavaScript (.js)  ← 泛型仅用于静态检查，不进入运行时
</pre>

**关键约束**：TypeScript 泛型采用**类型擦除**（type erasure）策略，与 C++ template 的 monomorphization（具象化）相反。C++ 为每个具体类型参数生成独立机器码；TypeScript 仅保留一个代码路径，靠运行时类型信息分派。

## 机制

**为什么要用 extends 约束**：
- 若 `<T extends HasLength>` 则 T 必有 `.length` 属性，编译器允许访问 `arg.length` 而不报错
- 约束同时限制了合法调用：传入不含 `.length` 的类型会导致编译错误
- `extends keyof T` 进一步约束为 T 的键的子集，保证 `obj[key]` 返回有效属性

**infer 的工作原理**：
- `infer U` 在条件类型的 true 分支中声明类型变量 U，暂时搁置其具体类型的确定
- 编译器通过模式匹配从 P 中"提取" U 的候选类型
- 例如 `T extends Promise<infer U> ? U : T`：若 T 是 `Promise<string>`，则 U 被推断为 `string`

**映射类型的物理含义**：
- `{ [P in keyof T]: T[P] }` 遍历 T 的每个属性键 P，保留原属性值类型
- `as` 子句在 TypeScript 4.1+ 允许对键进行变换（重命名、过滤），实现了键的函数式变换

**违反约束的后果**：
- 传入不满足约束的类型参数 → 编译错误 "Type 'X' does not satisfy constraint 'Y'"
- 在泛型函数内部访问未在约束中声明的属性 → 编译错误 "Property 'Z' does not exist on type 'T'"

## 泛型函数与接口

```typescript
function identity<T>(arg: T): T { return arg; }
identity<string>('hello');
identity(42);

function pair<K, V>(key: K, value: V): [K, V] { return [key, value]; }
pair<string, number>('age', 25);

interface Container<T> { value: T; get(): T; }
class Box<T> implements Container<T> {
  constructor(public value: T) {}
  get(): T { return this.value; }
}
```

## 泛型约束

```typescript
interface HasLength { length: number; }
function logLength<T extends HasLength>(arg: T): T {
  console.log(arg.length);
  return arg;
}

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; }
```

## 条件类型

**分布式条件类型**：当 T 为联合类型时，条件类型会自动分发：

```typescript
type ToArray<T> = T extends any ? T[] : never;
type Result = ToArray<string | number>;  // string[] | number[]
```

这是因为 `string | number extends any` 等价于 `(string extends any ? string[] : never) | (number extends any ? number[] : never)`。

**infer 关键字**：在条件类型中声明一个待推断的类型变量，用于从复杂类型中提取部分类型：

```typescript
type UnwrapPromise<T> = T extends Promise<infer U> ? U : T;
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
```

## 映射类型

映射类型通过 `[P in keyof T]` 遍历类型键，对每个键进行变换：

```typescript
type Partial<T> = { [P in keyof T]?: T[P] };
type Required<T> = { [P in keyof T]-?: T[P] };
type Readonly<T> = { readonly [P in keyof T]: T[P] };
```

**键重新映射**（TypeScript 4.1+）使用 `as` 表达式：

```typescript
type Getters<T> = {
  [P in keyof T as `get${Capitalize<string & P>}`]: () => T[P];
};
```

## 模板字面量类型

```typescript
type EventName = 'click' | 'focus';
type HandlerName = `on${Capitalize<EventName>}`;  // 'onClick' | 'onFocus'

type ApiPath = `/api/${'v1' | 'v2'}/${string}`;
```

## 泛型递归与默认类型

```typescript
type Flatten<T> = T extends (infer U)[] ? Flatten<U> : T;
type DeepPartial<T> = { [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P] };

interface Response<T = any> { code: number; data: T; message: string; }
```

## 参考存根

*展示条件类型分发机制的可执行证明：*

```typescript
// 编译：tsc --noEmit app.ts
// 预期：type Result = string[] | number[]
type ToArray<T> = T extends any ? T[] : never;
type Result = ToArray<string | number>;

// 预期：type Unwrapped = string
type Unwrapped = ToArray<string> extends string[] ? string : never;
```
