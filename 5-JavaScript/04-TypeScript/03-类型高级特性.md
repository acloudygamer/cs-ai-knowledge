# TypeScript 类型高级特性

> 类型守卫通过在运行时提供类型证明，使 TypeScript 能在编译时安全地收窄联合类型的范围。

## 定义

类型收窄的本质是**在控制流中逐步消除类型的非确定性**。联合类型 $T = A | B | C$ 在编译时包含多种可能性，类型守卫通过在代码路径上逐步排除不可能的分支，使 TypeScript 在特定代码块内"相信"变量属于更具体的子类型。

## 数学模型

**类型守卫的形式化**：设守卫函数 $g$ 的类型签名为 $value \rightarrow value \text{ is } X$，当 $g(value)$ 返回 true 时，类型环境更新为 $\Gamma \vdash value: X$。

**协变与逆变**：设函数类型 $F = (p: P) \rightarrow R$，则：
- 返回类型 $R$ 是**协变**的：$R_1 \subtype R_2 \implies F_1 \subtype F_2$
- 参数类型 $P$ 是**逆变**的：$P_1 \subtype P_2 \implies F_2 \subtype F_1$

这意味着"更窄"的返回类型和"更宽"的参数类型是允许的。TypeScript 默认使用**双向协变**（用于兼容性），在 `strictFunctionTypes` 模式下启用逆变检查。

## 数据流

<pre>
联合类型 T = A | B | C
    │
    ├──► if (guard) ──▶ 类型收窄为 A
    │    │
    │    ▼
    │    在 true 分支：Γ ⊢ value: A
    │
    └──► else 分支 ──▶ 类型仍为 B | C
         │
         ▼
    穷尽检查：若 A|B|C 覆盖所有可能，else 不存在
</pre>

**守卫的语义链**：运行时守卫表达式（typeof、instanceof、in、===、自定义 predicate）在字节码层面是真实的条件分支；TypeScript 编译器利用这一信息进行**控制流分析**（Control Flow Analysis），将运行时的类型信息"提升"到编译时。

## 机制

**类型守卫的物理本质**：TypeScript 编译器执行控制流分析（Control Flow Analysis），跟踪每个变量的赋值和条件分支。每当执行到守卫检查点，编译器根据守卫的布尔值在各个分支中更新对变量类型的推断。

**可辨识联合的设计意图**：
- 使用公共字面量类型（如 `status: 'success'`）作为"标签"，本质上是将枚举的穷尽性检查引入联合类型
- 当 switch 处理所有标签分支后，default 分支的类型被收窄为 never——这利用了 never"永远不可到达"的语义实现穷尽性检查

**never 的穷尽检查**：
- 若 switch 遗漏了某个 `status` 字面量，default 分支类型不是 never，编译报错
- 这使得向联合类型添加新成员时，所有使用该联合的地方都会在编译时报错（若未处理新分支）

**声明合并的语义**：
- 同名接口合并时，非冲突成员直接叠加，冲突成员（相同键但类型不同）形成交叉类型
- 本质是 TypeScript 的"渐进式扩展"策略：允许通过 .d.ts 文件为无类型声明的 JS 库添加类型

**逆变在 UnionToIntersection 中的应用**：
- `UnionToIntersection<U>` 利用逆变性质将联合类型转换为交叉类型
- `(k: U) => void` 对参数类型逆变，使得 `{a} | {b}` 变成 `{a} & {b}`

## 映射类型

映射类型遍历 keyof T 的结果，对每个键进行变换：

```typescript
type Partial<T> = { [P in keyof T]?: T[P] };
type Readonly<T> = { readonly [P in keyof T]: T[P] };
```

**键重新映射**（TypeScript 4.1+）用 `as` 表达式变换键：

```typescript
type Getters<T> = {
  [P in keyof T as `get${Capitalize<string & P>}`]: () => T[P];
};
type RemoveKind<T> = { [P in keyof T as Exclude<P, 'kind'>]: T[P] };
```

**条件映射**：根据属性类型选择性地包含属性：

```typescript
type Stringify<T> = { [P in keyof T]: T[P] extends string ? string : never };
```

## 条件类型与 infer

**分布式条件类型**：联合类型自动分发，这是因为条件类型本质上是遍历联合类型的每个成员。

**infer 关键字**：在条件分支中声明待推断的类型变量，用于从复杂类型中提取部分：

```typescript
type UnwrapPromise<T> = T extends Promise<infer U> ? U : T;
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
```

## 模板字面量类型

```typescript
type Event = 'click' | 'focus';
type Handler = `on${Capitalize<Event>}`;  // 'onClick' | 'onFocus'

type ApiPath = `/api/${'v1' | 'v2'}/${string}`;
```

**infer 在模板中**：从字符串字面量中提取部分：

```typescript
type Capitalize<T extends string> =
  T extends `${infer First}${infer Rest}` ? `${Uppercase<First>}${Rest}` : T;
```

## 声明合并与模块增强

**声明合并**：同名接口自动合并为单一接口。这使得向第三方类型添加成员成为可能：

```typescript
interface Window { myProp: string; }
declare global { interface String { reverse(): string; } }
```

**模块增强**：`declare module 'module-name'` 扩展第三方模块类型：

```typescript
declare module 'express-session' {
  interface SessionData { userId?: string; }
}
```

## 装饰器

两套装饰器系统：

| 特性 | 实验性（TypeScript） | TC39 Stage 3（ES2026） |
|------|---------------------|------------------------|
| 签名 | `(target, property, descriptor)` | `(value, context)` |
| 参数装饰器 | 支持 | 移除 |
| 编译器选项 | `experimentalDecorators` | 默认启用 |

Stage 3 装饰器移除了参数装饰器，简化了设计，采用统一的 `(value, context)` 签名。

## 分布式条件类型与逆变

```typescript
type UnionToIntersection<U> =
  (U extends any ? (k: U) => void : never) extends ((k: infer I) => void) ? I : never;
type A = UnionToIntersection<{ a: string } | { b: number }>;
// { a: string } & { b: number }
```

## 参考存根

*展示类型守卫收窄与穷尽检查的可执行证明：*

```typescript
// 编译：tsc --strict app.ts
type ApiResponse =
  | { status: 'success'; data: any }
  | { status: 'error'; message: string }
  | { status: 'loading' };

function assertNever(value: never): never {
  throw new Error('Unexpected value: ' + JSON.stringify(value));
}

function handle(resp: ApiResponse) {
  if (resp.status === 'success') { console.log(resp.data); }
  else if (resp.status === 'error') { console.log(resp.message); }
  else if (resp.status === 'loading') { console.log('loading'); }
  else { assertNever(resp); }  // 若遗漏分支，此处报错
}
```
