# 正则表达式

## 定义

正则表达式是描述**字符串模式**的形式语言，通过 `RegExp` 对象在 JavaScript 中使用。`/pattern/flags` 字面量语法在解析阶段即编译正则，性能优于 `new RegExp()` 构造函数（运行时编译）。正则表达式的核心是**有限状态自动机**（NFA/DFA），引擎通过正则模式构造自动机，在输入字符串上运行。

## 数学模型

### 正则引擎模型

正则表达式可编译为**非确定有限状态自动机（NFA）**或**确定有限状态自动机（DFA）**。JavaScript 引擎（V8 采用改进的 Lauthrop 算法）结合两者优势。

正则操作复杂度：

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| `test()` / `exec()` | $\mathcal{O}(m \cdot n)$ | $\mathcal{O}(m)$ |
| `match()` 无 g | $\mathcal{O}(m \cdot n)$ | $\mathcal{O}(m)$ |
| `match()` 有 g | $\mathcal{O}(m \cdot n)$ | $\mathcal{O}(n)$ |

其中 $m$ 为模式长度，$n$ 为输入字符串长度。

**回溯风险**：带有重复量词（`*`, `+`, `{n,}`）的分支在**最坏情况**下可导致指数级回溯。例如 `/^(a+)+b$/` 对 `aaaa...ax` 的匹配复杂度为 $\mathcal{O}(2^m)$。

### 量词语义

```
贪婪（默认）：匹配尽可能长的字符串，失败时回溯缩短
非贪婪（?）：匹配尽可能短的字符串
```

对于字符串 `"aaaa"`：
- `/a+/` 匹配 `"aaaa"`（贪婪）
- `/a+?/` 匹配 `"a"`（非贪婪）

## 数据流

<pre>
正则解析 → AST（抽象语法树）→ 编译为内部表示
                                    ↓
                          字符串输入 → 引擎执行
                                    ↓
                          匹配成功：返回结果 + 更新 lastIndex（有 g）
                          匹配失败：返回 null

String.match 流程：
/g 无 → exec() 首次调用 → 返回完整结果（数组 + groups + index）
/g 有 → 循环 exec() → lastIndex 推进 → 全部匹配直到 null

String.replace 流程：
无函数 → 字符串替换（每次匹配替换一次）
有函数 → 每次匹配调用函数(replacement, p1, ..., pn, offset, str)
                           ↓
                    函数返回值作为替换字符串

String.split 流程：
正则分隔符 → 按匹配点切分字符串
带捕获组 → 捕获组内容也被包含在结果数组中

回溯流程（输入 "aaaa" 正则 /a+a/）：
a+ 贪婪匹配 "aaaa" → 尝试 a/ 失败
                   → 回溯 a+ 匹配 "aaa"
                   → 尝试 a/ 失败
                   → 回溯...
                   → 最终找到匹配或完全失败
</pre>

## 机制

### 标志（flags）的语义

| 标志 | 作用 |
|------|------|
| `g` | 全局搜索，`lastIndex` 属性控制搜索起点 |
| `i` | 不区分大小写（NFA 字符类扩展）|
| `m` | 多行模式，`^`/`$` 匹配行首/行尾 |
| `s` | dotAll 模式，`.` 匹配换行符 `\n` |
| `u` | Unicode 模式，启用完整 Unicode 字符类（`\p{}`）|
| `v` | ES2024，Unicode 字符集操作，改进 `\p{}` 性能 |

### 捕获组与引用

捕获组按左括号从左到右编号（1-based）。`\1` 到 `\9` 在模式中反向引用捕获组内容。具名组 `(?<name>...)` 通过 `match.groups.name` 访问。

**非捕获组 `(?:...)`** 不创建捕获组编号，适合仅用于分组但不需要引用的场景（如 `(?:ab)+` 匹配一个或多个 "ab" 而不捕获 "ab"）。

### 断言（Lookahead/Lookbehind）

断言是**零宽度**的，它们不消耗字符，仅检查位置：

- `(?=...)` 正向先行：当前位置右侧匹配 `...`
- `(?!...)` 负向先行：当前位置右侧**不**匹配 `...`
- `(?<=...)` 正向后行：当前位置左侧匹配 `...`
- `(?<!...)` 负向后行：当前位置左侧**不**匹配 `...`

**典型应用**：密码验证（需包含多种字符类型）使用多个正向先行，每个断言独立检查，互不干扰。

### 具名组（ES2018）

具名组提供**自文档化**的正则，增加可读性和可维护性：
```javascript
const re = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const { groups: { year, month, day } } = re.exec('2024-03-15');
```

### 回溯陷阱与优化

**灾难性回溯**（Catastrophic Backtracking）：嵌套量词（如 `(a+)+b`）在匹配失败时产生指数级回溯。攻击者可通过构造特定输入（ReDoS 攻击）使正则引擎长时间阻塞。

**防御策略**：
1. 优先使用字符类替代嵌套量词（如 `(a|a)+` → `[a]+`）
2. 使用**原子组**（JS 不支持，但可用 `(?=...)` 模拟）减少回溯
3. 使用固化分组（possessive quantifier，JS 不支持）

### exec 的 lastIndex 行为

`RegExp.prototype.exec()` 在非全局模式（无 `g`）下忽略 `lastIndex`，每次从字符串开头匹配。在全局模式（有 `g`）下，`lastIndex` 控制搜索起点，匹配成功后 `lastIndex` 更新为下一个搜索位置。

## 参考存根

```javascript
// 具名组
const { groups: { year, month } } = /(?<year>\d{4})-(?<month>\d{2})/.exec('2024-03');

// 先行断言密码验证
const pwdRe = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/;
pwdRe.test('Pass1234'); // true

// 后行断言提取价格
'$100'.match(/(?<=\$)\d+/); // ['100']

// 邮箱验证（简化版）
/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test('a@b.cc'); // true

// exec + g 循环
const re = /(\d+)-(\w+)/g;
let m;
while ((m = re.exec('1-a 2-b 3-c')) !== null) {
  console.log(m[1], m[2]);
}

// matchAll 迭代
const matches = [...'1-a 2-b'.matchAll(/(\d+)-(\w+)/g)];
matches[0][1]; // '1'

// 非贪婪匹配 HTML 标签
'<div><span>x</span></div>'.match(/<[^>]+>/g); // ['<div>', '<span>', '</span>', '</div>']

// 避免回溯：使用固化分组模拟（先看断言）
// 原: /^(a+)+b/  改进: /^(?=a+)a+b/ （先看断言不产生回溯）
```
