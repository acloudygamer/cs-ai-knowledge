# 正则表达式

## 定义

正则表达式是描述**字符串模式**的形式语言，通过 `RegExp` 对象在 JavaScript 中使用。`/pattern/flags` 字面量语法在解析阶段即编译正则，性能优于 `new RegExp()` 构造函数（运行时编译）。正则表达式的核心是**有限状态自动机**（NFA/DFA），引擎通过正则模式构造自动机，在输入字符串上运行。

## 数学模型

### 正则引擎模型

正则表达式可编译为**非确定有限状态自动机（NFA）**或**确定有限状态自动机（DFA）**：

| 自动机类型 | 特点 | JavaScript 引擎 |
|------------|------|-----------------|
| DFA | 确定状态转移，线性时间，线性空间 | 无直接支持 |
| NFA | 非确定状态转移，最坏指数级回溯 | V8（改进的 Lauthrop 算法）|

JavaScript 引擎结合两者优势：先通过 NFA 构造自动机，再通过模拟执行匹配。

**正则操作复杂度**：

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| `test()` / `exec()` 无 g | $\mathcal{O}(m \cdot n)$ | $\mathcal{O}(m)$ |
| `match()` 无 g | $\mathcal{O}(m \cdot n)$ | $\mathcal{O}(m)$ |
| `match()` 有 g | $\mathcal{O}(m \cdot n)$ | $\mathcal{O}(n)$ |
| `replace()` | $\mathcal{O}(m \cdot n)$ | $\mathcal{O}(n)$ |

其中 $m$ 为模式长度，$n$ 为输入字符串长度。

**回溯风险**：带有重复量词（`*`, `+`, `{n,}`）的分支在**最坏情况**下可导致指数级回溯：

$$
T_{backtrack}(pattern, input) = \mathcal{O}(k^m) \quad \text{其中 } k \text{ 为分支数，} m \text{ 为重复次数}
$$

例如 `/^(a+)+b$/` 对 `a^n x` 的匹配复杂度为 $\mathcal{O}(2^n)$。

### 量词语义

| 量词类型 | 语义 | 回溯行为 |
|----------|------|----------|
| `*` | 0 次或多次 | 贪婪回溯 |
| `+` | 1 次或多次 | 贪婪回溯 |
| `?` | 0 次或 1 次 | 贪婪回溯 |
| `{n}` | 恰好 n 次 | 无回溯 |
| `{n,}` | 至少 n 次 | 贪婪回溯 |
| `*?` / `+?` / `??` | 非贪婪（惰性）| 最小匹配 |

**贪婪 vs 非贪婪**：对于字符串 `"aaaa"`：
- `/a+/` 匹配 `"aaaa"`（贪婪，先尝试最长匹配）
- `/a+?/` 匹配 `"a"`（非贪婪，先尝试最短匹配）

## 数据流

```
正则解析 → AST（抽象语法树）→ 编译为内部表示
                                    ↓
                          字符串输入 → 引擎执行
                                    ↓
                          匹配成功：返回结果 + 更新 lastIndex（有 g）
                          匹配失败：返回 null

String.match 流程：
/g 无 → exec() 首次调用 → 返回完整结果（数组 + groups + index）
/g 有 → 循环 exec() → lastIndex 推进 → 全部匹配直到 null

String.replace 流程：
无函数 → 字符串替换（每次匹配替换一次）
有函数 → 每次匹配调用函数(replacement, p1, ..., pn, offset, str)
                           ↓
                    函数返回值作为替换字符串

String.split 流程：
正则分隔符 → 按匹配点切分字符串
带捕获组 → 捕获组内容也被包含在结果数组中

回溯流程（输入 "aaaa" 正则 /a+a/）：
a+ 贪婪匹配 "aaaa" → 尝试 a/ 失败
                   → 回溯 a+ 匹配 "aaa"
                   → 尝试 a/ 失败
                   → 回溯...
                   → 最终找到匹配或完全失败
```

## 机制

### 标志（flags）的语义

| 标志 | 作用 | 示例 |
|------|------|------|
| `g` | 全局搜索，`lastIndex` 属性控制搜索起点 | `/a/g.test("aaa") // true true` |
| `i` | 不区分大小写（NFA 字符类扩展）| `/a/i.test("A") // true` |
| `m` | 多行模式，`^`/`$` 匹配行首/行尾 | `/^a/m.test("a\nb") // true` |
| `s` | dotAll 模式，`.` 匹配换行符 `\n` | `/a.b/s.test("a\nb") // true` |
| `u` | Unicode 模式，启用完整 Unicode 字符类（`\p{}`）| `/\p{L}/u.test("中") // true` |
| `v` | ES2024，Unicode 字符集操作，改进 `\p{}` 性能 | `/\p{ASCII}/v.test("abc") // true` |

### 捕获组与引用

**编号规则**：捕获组按**左括号**从左到右编号（1-based）：

```javascript
/((\w+)_(\d+))_(\w+)/.exec("abc_123_def");
// [
//   "abc_123_def",  // 完整匹配
//   "abc_123",      // 组1: ((\w+)_(\d+))
//   "abc",          // 组2: (\w+) 第一字
//   "123",          // 组3: (\d+)
//   "def"           // 组4: (\w+) 第三段
// ]
```

**反向引用**：`\1` 到 `\9` 在模式中引用捕获组内容：

```javascript
// 匹配引号内的内容（支持单引号或双引号）
/(['"])[^\1]*?\1/.exec("'hello'")[0] // "'hello'"
```

**具名组（ES2018）**：`(?<name>...)` 提供自文档化：

```javascript
const re = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const { groups: { year, month, day } } = re.exec('2024-03-15');
```

**非捕获组** `(?:...)`：仅用于分组，不创建捕获组编号。

### 断言（Lookahead/Lookbehind）

断言是**零宽度**的，它们不消耗字符，仅检查位置：

| 断言 | 名称 | 检查条件 |
|------|------|----------|
| `(?=...)` | 正向先行 | 当前位置**右侧**匹配 `...` |
| `(?!...)` | 负向先行 | 当前位置**右侧不**匹配 `...` |
| `(?<=...)` | 正向后行 | 当前位置**左侧**匹配 `...` |
| `(?<!...)` | 负向后行 | 当前位置**左侧不**匹配 `...` |

**典型应用**：密码验证（需包含多种字符类型）使用多个正向先行：

```javascript
const pwdRe = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/;
pwdRe.test('Pass1234'); // true
```

### 回溯陷阱与 ReDoS 攻击

**灾难性回溯**（Catastrophic Backtracking）：嵌套量词在匹配失败时产生指数级回溯。

**攻击示例**：

```javascript
// 构造 ReDoS 攻击
const malicious = 'aaaaaaaaaa!'; // 10 个 a + 一个 !
const evilRegex = /^(a+)+$/;

// 匹配时间随 a 的数量指数增长
// m = 10 时，约需 2^10 = 1024 次尝试
```

**防御策略**：

1. **避免嵌套量词**：用字符类替代嵌套分支
   - `/a+/` 替代 `/a|a|a.../`

2. **使用原子组**（JavaScript 不支持，但可用 `(?=...)` 模拟）：
   ```javascript
   // 原灾难性回溯: /^(a+)+b/
   // 改进（固化分组效果）: /^(?=a+)a+b/
   // 断言 `(?=a+)` 先检查，但不在匹配中保留
   ```

3. **固化分组**（Possessive Quantifier，JavaScript 不支持）：用 `*+`、`++` 替代 `*`、`+`

### exec 的 lastIndex 行为

| 模式 | `lastIndex` 行为 |
|------|-----------------|
| 非全局（无 `g`）| 忽略，每次从位置 0 开始 |
| 全局（有 `g`）| 控制搜索起点，匹配成功后推进到下一个搜索位置 |

```javascript
const re = /\d/g;
re.lastIndex; // 0
re.exec('123'); // ['1'], lastIndex → 1
re.exec('123'); // ['2'], lastIndex → 2
re.exec('123'); // ['3'], lastIndex → 3
re.exec('123'); // null, lastIndex → 0
```

### matchAll 的迭代语义

`matchAll` 返回一个**迭代器**（而非数组），每次 `next()` 调用执行一次 `exec`：

```javascript
const matches = [...'1-a 2-b'.matchAll(/(\d+)-(\w+)/g)];
matches[0][1]; // '1'
matches[0][2]; // 'a'
matches[1][1]; // '2'
matches[1][2]; // 'b'
```

## 参考存根

```javascript
// 具名组
const { groups: { year, month } } = /(?<year>\d{4})-(?<month>\d{2})/.exec('2024-03');

// 先行断言密码验证
const pwdRe = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/;
pwdRe.test('Pass1234'); // true

// 后行断言提取价格
'$100'.match(/(?<=\$)\d+/); // ['100']

// 邮箱验证（简化版）
/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test('a@b.cc'); // true

// exec + g 循环
const re = /(\d+)-(\w+)/g;
let m;
while ((m = re.exec('1-a 2-b 3-c')) !== null) {
  console.log(m[1], m[2]);
}

// matchAll 迭代
const matches = [...'1-a 2-b'.matchAll(/(\d+)-(\w+)/g)];
matches[0][1]; // '1'

// 非贪婪匹配 HTML 标签
'<div><span>x</span></div>'.match(/<[^>]+>/g); // ['<div>', '<span>', '</span>', '</div>']

// 避免回溯：使用断言固化匹配
// 原: /^(a+)+b/  改进: /^(?=a+)a+b/
// (?=a+) 先检查 a+ 是否存在，检查不消耗字符，不产生回溯

// 固化分组模拟（用先行+贪婪）
// 目标：匹配 "ab" 或 "ac" 或 "ad"，但不回溯
// 原: /(a[bcd])+/ → 改进: /(?=(a[bcd]))a\1+/  （仅示意，实际需调整）
```
