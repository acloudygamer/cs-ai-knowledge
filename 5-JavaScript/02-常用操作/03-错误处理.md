# 错误处理

## 定义

JavaScript 错误处理是基于**异常抛出与捕获**的控制流机制。同步代码通过 `try/catch/finally` 拦截异常；Promise 链通过 `.catch()` 处理拒绝；`async/await` 同样使用 `try/catch`。异常的本质是**控制流的非局部跳转**，将执行流从抛出位置转移到最近的匹配 `catch` 块。

## 数学模型

### 异常传播模型

异常传播是栈展开（stack unwinding）过程：

$$
E_{throw}(ctx, err) = \begin{cases}
ctx_{catch}(err) & \text{if } ctx \text{ has try/catch} \\
E_{throw}(parent(ctx), err) & \text{otherwise}
\end{cases}
$$

从 `throw` 语句所在栈帧向上逐层查找 `catch` 块，找到则将控制权转交给 `catch`；若到达调用栈顶端（全局上下文）仍未找到，程序终止。

**Promise 拒绝的异步语义**：Promise rejection 不展开调用栈，而是通过微任务队列将处理函数调度到当前执行上下文之后。`Promise.allSettled` 的语义为：
$$R_{allSettled}(promises) = \forall p \in promises, \begin{cases} \{ status: 'fulfilled', value \} & p \ resolves \\ \{ status: 'rejected', reason \} & p \ rejects \end{cases}$$

### 错误类型层次

```
Error
├── TypeError       // 属性不存在、类型不匹配
├── ReferenceError  // 标识符未定义
├── SyntaxError    // 代码语法错误（解析时抛出）
├── RangeError     // 数值超出范围
├── URIError       // encodeURI/decodeURI 错误
└── 自定义 Error   // extends Error
```

## 数据流

<pre>
同步异常流程：
throw new Error() → 栈展开（unwinding）
                        ↓
              查找当前帧 try/catch 块
                        ↓
              有 → 执行 catch(err)，继续执行
              无 → 展开到父调用帧

Promise 拒绝流程：
promise.reject(reason) → 微任务队列
                              ↓
                        .catch(handler) 注册
                              ↓
                        微任务执行 → handler(reason)

async/await 异常流程：
throw err → await 表达式值变为 rejected Promise
                ↓
          await 抛出异常 → 传播到外层 try/catch
                ↓
          有 → catch(err)
          无 → async 函数返回 rejected Promise

Promise.allSettled 流程：
[Promise1, Promise2, ...] → 全部 settled（resolved 或 rejected）
                ↓
          返回结果数组 [{ status, value/reason }, ...]

unhandledrejection 全局捕获：
Promise.reject() 无 .catch → 全局 unhandledrejection 事件
                ↓
          浏览器控制台警告 + 事件触发
</pre>

## 机制

### try/catch/finally 的执行语义

`finally` 块在 `try` 和 `catch` 之后**无条件执行**（即使 `try`/`catch` 中有 `return`、`throw`、或循环控制语句）。若 `finally` 中也有 `throw`，该异常会**覆盖**前面未处理的异常。

`try` 块中的变量作用域仅限于 `try` 块内部，`catch(e)` 中绑定的 `e` 作用域仅限于 `catch` 块。

### 错误类型判断

不应依赖 `instanceof` 跨 realm 判断（不同 iframe 的 `TypeError` 是不同的构造函数）。跨域错误仅提供有限信息（`DOMException` 的 `name` 和 `message`），堆栈信息可能不可用。

### async/await 错误传播

`async` 函数始终返回 `Promise`。函数内 `throw` 导致返回的 Promise 进入 rejected 状态。外层 `await` 若 await 一个 rejected Promise，则 `await` 表达式本身抛出该错误。

```javascript
// 外层 try/catch 捕获 async 函数内所有同步异常和被等待的 Promise 拒绝
try {
  await fetchData(); // 若 fetchData 返回 rejected Promise，await 抛出
} catch (e) {
  console.error(e);
}
```

### Promise.allSettled 的适用场景

`Promise.all` 在任意一个 Promise 拒绝时立即 reject，不适合需要"收集所有结果"的场景。`Promise.allSettled` 等待所有 Promise settle 后返回完整结果数组，保证所有输入 Promise 的处理结果都可访问。

### 自定义错误的设计约束

- 自定义错误应 `extends Error`，否则不会被 `instanceof Error` 识别。
- `Error.captureStackTrace(this, this.constructor)` 在 V8 引擎中正确记录堆栈，跳过构造函数本身。
- 错误应携带足够上下文（字段），使处理者能根据错误类型和上下文做出恢复决策。

### unhandledrejection 的触发条件

当 Promise 被 reject 且未注册相应 `.catch` 处理器时，浏览器在事件循环的当前微任务完成后触发 `unhandledrejection`。若在 rejection 之后同步注册了 `.catch`，则不触发。

## 参考存根

```javascript
// 自定义错误
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
    Error.captureStackTrace(this, this.constructor);
  }
}

// async 错误处理
const fetchData = async (url) => {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
};

try {
  const data = await fetchData(url);
} catch (e) {
  console.error(e.message);
}

// Promise.allSettled
const results = await Promise.allSettled(urls.map(fetch));
results.forEach((r, i) => r.status === 'rejected' && console.error(`${urls[i]}: ${r.reason}`));

// 全局捕获
window.addEventListener('unhandledrejection', e => {
  console.error('Unhandled rejection:', e.reason);
});
```
