# 错误处理

## 定义

JavaScript 错误处理是基于**异常抛出与捕获**的控制流机制。同步代码通过 `try/catch/finally` 拦截异常；Promise 链通过 `.catch()` 处理拒绝；`async/await` 同样使用 `try/catch`。异常的本质是**控制流的非局部跳转**，将执行流从抛出位置转移到最近的匹配 `catch` 块。

## 数学模型

### 异常传播模型

异常传播是栈展开（stack unwinding）过程。设调用栈为 $S = [f_1, f_2, ..., f_n]$，$f_n$ 为栈顶（当前执行帧）：

$$
E_{throw}(ctx, err) = \begin{cases}
ctx_{catch}(err) & ctx \text{ has try/catch} \\
E_{throw}(parent(ctx), err) & ctx \text{ has no try/catch}
\end{cases}
$$

从 `throw` 语句所在栈帧向上逐层查找 `catch` 块，找到则将控制权转交给 `catch`；若到达调用栈顶端（全局上下文）仍未找到，程序终止（unhandled exception）。

**同步异常 vs 异步拒绝的传播差异**：

| 维度 | 同步异常 | Promise 拒绝 |
|------|----------|--------------|
| 传播机制 | 调用栈展开 | 微任务队列调度 |
| 传播时机 | 立即展开 | 当前执行上下文完成后 |
| 处理位置 | 调用栈上最近的 catch | rejection handler |

### Promise 拒绝的异步语义

Promise rejection 不展开调用栈，而是通过**微任务队列**将处理函数调度到当前执行上下文之后：

$$
R_{reject}(promise, reason) \rightarrow \text{microtask\_queue.enqueue}(handler(reason))
$$

`Promise.allSettled` 的语义为：
$$
R_{allSettled}(promises) = \forall p \in promises, \begin{cases} \{ status: 'fulfilled', value \} & p \ resolves \\ \{ status: 'rejected', reason \} & p \ rejects \end{cases}
$$

无论输入 Promise 如何 settled，结果数组按输入顺序返回所有结果。

### 错误类型层次

```
Error
├── RangeError       // 数值超出范围（递归深度超限、数组长度超限）
├── ReferenceError   // 标识符未定义（访问不存在的变量）
├── SyntaxError     // 代码语法错误（解析时抛出，代码未执行）
├── TypeError       // 类型不匹配（null/undefined 上调用方法）
├── URIError        // encodeURI/decodeURI 错误
├── EvalError       // eval() 使用不当（现代 JS 已不使用）
├── DOMException     // DOM 操作错误（安全限制等）
└── 自定义 Error    // extends Error
```

## 数据流

```
同步异常流程：
throw new Error() → 栈展开（unwinding）
                        ↓
              查找当前帧 try/catch 块
                        ↓
              有 → 执行 catch(err)，继续执行
              无 → 展开到父调用帧
                  ...
                  无 → 全局 uncaughtexception → 程序终止

Promise 拒绝流程：
promise.reject(reason) → 微任务队列
                              ↓
                        .catch(handler) 注册
                              ↓
                        微任务执行 → handler(reason)
                        或：全局 unhandledrejection

async/await 异常流程：
throw err → await 表达式值变为 rejected Promise
                ↓
          await 抛出异常 → 传播到外层 try/catch
                ↓
          有 → catch(err)
          无 → async 函数返回 rejected Promise

Promise.allSettled 流程：
[Promise1, Promise2, ...] → 全部 settled（resolved 或 rejected）
                ↓
          返回结果数组 [{ status, value/reason }, ...]

unhandledrejection 全局捕获：
Promise.reject() 无 .catch → 全局 unhandledrejection 事件
                ↓
          浏览器控制台警告 + 事件触发
```

## 机制

### try/catch/finally 的执行语义

**finally 的无条件执行**：

`finally` 块在 `try` 和 `catch` 之后**无条件执行**，即使：
- `try`/`catch` 中有 `return` → finally 执行后返回值
- `try`/`catch` 中有 `throw` → finally 执行后抛出新异常（**覆盖**原异常）
- `try`/`catch` 中有循环控制（break/continue）→ finally 仍执行

```javascript
// finally 覆盖异常的示例
try {
  throw new Error('original');
} finally {
  throw new Error('finally overrides');
}
// 实际抛出的是 'finally overrides'
```

**作用域约束**：
- `try` 块中的变量作用域仅限于 `try` 块内部
- `catch(e)` 中绑定的 `e` 作用域仅限于 `catch` 块

### 错误类型判断

**跨 realm 问题**：不应依赖 `instanceof` 跨 realm 判断。不同 iframe 的 `TypeError` 是**不同的构造函数**（不同 realm）：

```javascript
// 跨 iframe 的 instanceof 失败
const iframe = document.createElement('iframe');
document.body.appendChild(iframe);
iframe.contentWindow.Array; // 不同于 window.Array
```

**跨域错误限制**：跨域错误仅提供有限信息（`DOMException` 的 `name` 和 `message`），堆栈信息不可用。

**可靠的类型判断**：

```javascript
// 对于 Error 子类
const isError = (e) => e instanceof Error;

// 对于跨 realm 场景，使用 constructor name
const getErrorType = (e) => e.constructor?.name ?? Object.prototype.toString.call(e);
```

### async/await 错误传播

`async` 函数始终返回 `Promise`。函数内 `throw` 导致返回的 Promise 进入 rejected 状态：

$$
async\ f() \ \{ throw\ err \} \Rightarrow Promise.reject(err)
$$

外层 `await` 若 await 一个 rejected Promise，则 `await` 表达式本身抛出该错误（自动解包 rejection）：

```javascript
// 外层 try/catch 捕获 async 函数内所有同步异常和被等待的 Promise 拒绝
try {
  await fetchData(); // 若 fetchData 返回 rejected Promise，await 抛出
} catch (e) {
  console.error(e); // 可捕获同步异常或 Promise rejection
}
```

### Promise.allSettled 的适用场景

| 方法 | 行为 | 适用场景 |
|------|------|----------|
| `Promise.all` | 任意一个 reject → 立即 reject | 需要全部成功才继续 |
| `Promise.allSettled` | 等待所有 settled | 收集所有结果（成功/失败）|
| `Promise.any` | 任意一个 fulfill → 立即 fulfill | 只需一个成功（ES2021）|
| `Promise.race` | 任意一个 settled → 立即 settled | 超时控制 |

`Promise.allSettled` 适合"无论如何都需知道每个请求结果"的场景（如批量发送通知）。

### 自定义错误的设计约束

```javascript
class ValidationError extends Error {
  constructor(message, field, value) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
    this.value = value; // 携带上下文
    Error.captureStackTrace(this, this.constructor); // V8 堆栈截断
  }
}
```

**设计原则**：
1. `extends Error` 以被 `instanceof Error` 识别
2. `Error.captureStackTrace(this, this.constructor)` 跳过构造函数本身在堆栈中
3. 携带足够上下文（字段），使处理者能根据错误类型和上下文做出恢复决策

### unhandledrejection 的触发条件

当 Promise 被 reject 且未注册相应 `.catch` 处理器时：

1. 浏览器在事件循环的**当前微任务完成后**触发 `unhandledrejection`
2. 若在 rejection 之后**同步**注册了 `.catch`，则不触发
3. 浏览器控制台显示警告（`PromiseRejectionEvent`）

```javascript
// 触发 unhandledrejection
Promise.reject('oops');

// 不触发（rejection 已被处理）
Promise.reject('oops').catch(() => {});
```

**防御措施**：在应用入口注册全局处理器作为最后防线：

```javascript
window.addEventListener('unhandledrejection', e => {
  e.preventDefault(); // 阻止默认行为（控制台警告）
  logError(e.reason);
  return false;
});
```

### Error boundary 与 React 错误处理

在 React 中，`ErrorBoundary` 组件通过 `componentDidCatch` 捕获子树中的 JavaScript 错误：

```javascript
class ErrorBoundary extends React.Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, info) {
    logError(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback;
    }
    return this.props.children;
  }
}
```

Error boundary **无法捕获**：
- 事件处理器中的错误（需用 try/catch）
- 异步代码中的错误（setTimeout、Promise.reject）
- 服务端渲染（SSR）错误
- Error boundary 自身的错误

## 参考存根

```javascript
// 自定义错误
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
    Error.captureStackTrace(this, this.constructor);
  }
}

// async 错误处理
const fetchData = async (url) => {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
};

try {
  const data = await fetchData(url);
} catch (e) {
  console.error(e.message);
}

// Promise.allSettled
const results = await Promise.allSettled(urls.map(fetch));
results.forEach((r, i) => {
  if (r.status === 'rejected') console.error(`${urls[i]}: ${r.reason}`);
  else console.log(`${urls[i]}: ${r.value}`);
});

// 全局捕获
window.addEventListener('unhandledrejection', e => {
  e.preventDefault();
  console.error('Unhandled rejection:', e.reason);
});

// 全局异常捕获（同步）
window.addEventListener('error', e => {
  console.error('Uncaught error:', e.error);
});

// Error cause（ES2022）
const readData = () => {
  try {
    return JSON.parse(data);
  } catch (e) {
    throw new Error('Failed to read data', { cause: e });
  }
};
```
