# 计时器与动画

## 定义

JavaScript 的定时机制分为两类：`setTimeout`/`setInterval` 是基于**宏任务队列**的延迟/周期执行；`requestAnimationFrame` 是与浏览器**渲染帧同步**的回调调度。两者都面临主线程阻塞问题——主线程繁忙时，定时器回调会被延迟。

## 数学模型

### 防抖与节流的时间模型

设事件流为时间序列 $\{t_i\}$，延迟为 $\Delta t$：

**防抖（Debounce）**：
$$T_{debounce}(t) = \begin{cases} t + \Delta t & \text{重置计时器} \\ \text{不变} & \text{等待中} \end{cases}$$

防抖的输出函数在最后一次触发后 $\Delta t$ 时间执行。若事件在 $(t_{last}, t_{last}+\Delta t)$ 内再次触发，计时器重新开始。

**节流（Throttle）**：
$$T_{throttle}(t) = \begin{cases} \text{执行} & t - T_{last} \geq \Delta t \\ \text{跳过} & t - T_{last} < \Delta t \end{cases}$$

节流的输出函数每 $\Delta t$ 时间最多执行一次。超出间隔后的第一次触发必然执行。

### requestAnimationFrame 的帧同步

显示器刷新率通常为 60Hz（16.67ms/帧），部分高刷屏可达 120Hz（8.33ms/帧）。`requestAnimationFrame` 回调在**下一帧渲染前**执行，保证动画更新与屏幕刷新同步，避免撕裂和卡顿。

### setTimeout/setInterval 的精度约束

`setTimeout(fn, 0)` 不保证立即执行，而是将 `fn` 调度到**下一个宏任务队列**。HTML 规范要求浏览器将嵌套（5层以上）定时器的最小延迟提升到 4ms（防止占用过多资源）。

实际延迟 = 设置延迟 + 主线程空闲时间 + 宏任务队列排队时间。

## 数据流

<pre>
setTimeout 流程：
setTimeout(fn, ms) → 浏览器定时器模块
                            ↓
                    ms 后 → fn 加入宏任务队列
                            ↓
                    主线程空闲时 → 执行 fn

setInterval 流程：
setInterval(fn, ms) → 浏览器定时器模块（独立于主线程）
                            ↓
                    每次 ms 间隔 → fn 加入宏任务队列
                            ↓
                    主线程空闲时 → 执行 fn
                    （若上次 fn 未执行完，新 fn 仍入队，不等待）

requestAnimationFrame 流程：
requestAnimationFrame(fn) → 注册下一帧回调
                                  ↓
                            浏览器渲染 pipeline（style → layout → paint）
                                  ↓
                            fn(timestamp) 执行

防抖流程：
触发 → clearTimeout(timer) → setTimeout(fn, delay)
（若 delay 内再次触发，重新开始上述流程）

节流流程：
触发 → 检查 now - lastTime >= interval
                    ├── 是 → fn() → lastTime = now
                    └── 否 → 忽略

动画循环：
requestAnimationFrame(step)
    ↓
step(now):
    计算 p = (now - start) / duration
    更新 DOM 属性（transform/opacity）
    若 p < 1 → requestAnimationFrame(step)
    若 p >= 1 → 动画结束
</pre>

## 机制

### 防抖与节流的选择

| 场景 | 策略 | 原因 |
|------|------|------|
| `oninput` 搜索建议 | 防抖 | 用户停止输入后才查询，减少服务器压力 |
| `onscroll` 滚动事件 | 节流 | 每 16ms 最多执行一次（60fps），避免帧丢失 |
| 窗口 `resize` | 节流 |  resize 事件频繁，固定间隔处理即可 |
| 按钮防双击 | 防抖 | 等待操作完成后才能再次触发 |

### setTimeout/setInterval 的副作用

**setInterval 不保证执行间隔**：若 `fn` 执行时间超过 `ms`，或主线程长时间阻塞，下次 `fn` 会立即执行（无等待），导致**堆积**。这与"每 ms 执行一次"的语义不同。

**堆积问题**：连续多次 `setInterval` 回调堆积后，可能导致"动画一口气执行完"的现象。解决方案：使用**链式 setTimeout**：
```javascript
(function loop() {
  doWork();
  setTimeout(loop, ms);
})();
```

### requestAnimationFrame 的优势

相比 `setInterval`：
- 与屏幕刷新同步，避免动画帧与屏幕刷新不同步导致的**撕裂**（tearing）
- 当标签页不可见时，`requestAnimationFrame` 暂停（节省 CPU/GPU）
- 回调接收高精度时间戳（`DOMHighResTimeStamp`），精度约 1ms

### 动画性能优化

**触发重排的属性**（高成本）：
- `width`, `height`, `margin`, `padding`, `top`, `left`, `right`, `bottom`
- `fontSize`, `lineHeight`

**仅触发重绘的属性**（中等成本）：
- `color`, `background`, `border`, `visibility`, `opacity`

**transform/opacity（合成层）**（最低成本）：
- `transform: translateX/Y/Z()`、`scale()`、`rotate()`
- `opacity`

`will-change: transform` 将元素提升为独立**合成层**（Composite Layer），动画仅在 GPU 合成阶段完成，不触发重排/重绘。

### IntersectionObserver + 懒加载

滚动监听若使用 `throttle(scrollHandler, 16)`，当元素进入视口时可能已延迟一帧。使用 `IntersectionObserver` 可在元素交叉状态变化时**立即回调**（异步，不阻塞主线程），实现更精确的懒加载。

## 参考存根

```javascript
// 防抖
const debounce = (fn, ms) => {
  let t;
  return (...a) => { clearTimeout(t); t = setTimeout(() => fn(...a), ms); };
};

// 节流
const throttle = (fn, ms) => {
  let last = 0;
  return (...a) => {
    const now = Date.now();
    if (now - last >= ms) { last = now; fn(...a); }
  };
};

// requestAnimationFrame 动画
const animate = (el, targetX, duration) => {
  const startX = el.offsetLeft;
  const start = performance.now();
  const step = now => {
    const p = Math.min((now - start) / duration, 1);
    el.style.transform = `translateX(${startX + (targetX - startX) * p}px)`;
    if (p < 1) requestAnimationFrame(step);
  };
  requestAnimationFrame(step);
};

// 链式 setTimeout（精确间隔）
(function loop() {
  doWork();
  setTimeout(loop, 1000);
})();

// 滚动 + IntersectionObserver 懒加载
const io = new IntersectionObserver((entries, obs) => {
  entries.forEach(e => {
    if (e.isIntersecting) {
      img.src = img.dataset.src;
      obs.unobserve(img);
    }
  });
}, { rootMargin: '50px' });
document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));
```
