# 结构型模式

> 前置：[02-创建型模式](./02-创建型.md) · 后续：[04-行为型模式](./04-行为型.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1，Windows x64。

## 本质

结构型模式解决**"怎么把对象组合起来"**：在不修改原有代码的前提下，改变接口、附加行为、控制访问、统一对待单个与整体。

经典分类有七种，JavaScript 里最常用的四个是**适配器、外观、代理、组合**——其中代理被语言内建（`Proxy`），组合被对象模型内建（原型链与属性查找）。

## 机制

### 适配器：转换接口

适配器让**接口不兼容的两方能够协作**——它不改变任何一方的实现，只做形状转换：

```console
$ node -e 'const legacy=()=>({user_name:"甲",user_id:7}); const adapt=(u)=>({name:u.user_name,id:u.user_id}); console.log("  旧:", JSON.stringify(legacy())); console.log("  新:", JSON.stringify(adapt(legacy())))'
  旧: {"user_name":"甲","user_id":7}
  新: {"name":"甲","id":7}
```

旧接口返回 `user_name` / `user_id`，新代码期望 `name` / `id`——适配器把前者转成后者。

**适配器与外观的区别**：适配器**转换**接口（一对一），外观**简化**接口（多对一）。

**何时不该用适配器**：当你有权修改其中一方时，直接统一命名比加一层适配更好。适配器适用于**第三方代码或历史遗留接口**——那是你改不动的一方。

### 外观：为一组调用提供简单入口

外观把多个子系统的调用打包成一个简单接口：

```javascript
// facade.mjs
// 五个子系统，各自只做一件事
const cache = {
  store: new Map(),
  get(k) { return this.store.get(k); },
  set(k, v) { this.store.set(k, v); },
};
const db = {
  connect() { return this; },
  query(sql) { return `结果(${sql})`; },
};
const log = (msg) => { /* 记日志：真实系统里写文件或上报 */ };

// 外观：把上面五个子系统的调用打包成一个入口
const facade = {
  fetchUser(id) {
    const key = `user:${id}`;
    let u = cache.get(key);                                   // 1. 查缓存
    if (u === undefined) {
      const conn = db.connect();                              // 2. 连数据库
      u = conn.query(`SELECT * FROM users WHERE id=${id}`);   // 3. 查询
      cache.set(key, u);                                      // 4. 写缓存
    }
    log(`fetchUser(${id})`);                                  // 5. 记日志
    return u;
  },
};

console.log(` ${facade.fetchUser(7)}`);
```

```console
$ node facade.mjs
 结果(SELECT * FROM users WHERE id=7)
```

上例里 `facade.fetchUser` 内部做了五件事（查缓存、连数据库、查询、写缓存、记日志），调用方只需要一句。

**外观的价值是降低耦合**：调用方不必知道有缓存、有日志、有几个子系统。**风险是它会长成一个什么都做的"上帝对象"**——外观应当只暴露**调用方真正需要的组合**，而不是把子系统的所有能力都转发一遍。

### 代理：控制访问

代理与目标实现**同一个接口**，在转发前后插入逻辑。JavaScript 用 `Proxy` 内建了它（见 [02-对象模型与运行时/04-属性描述符与元编程](../02-对象模型与运行时/04-属性描述符与元编程.md)）：

```javascript
// memo.mjs
let computations = 0;
const square = (x) => { computations++; return x * x; };

// apply 陷阱：同样的参数只真正计算一次
const memo = new Proxy(square, {
  cache: new Map(),
  apply(target, thisArg, args) {
    const key = args[0];
    if (!this.cache.has(key)) this.cache.set(key, target(...args));
    return this.cache.get(key);
  },
});

const results = [memo(5), memo(5), memo(5), memo(3)];
console.log(`  ${results.length} 次调用，实际计算次数: ${computations} （5 只算一次）`);
```

```console
$ node memo.mjs
  4 次调用，实际计算次数: 2 （5 只算一次）
```

上例用 `apply` 陷阱实现了**记忆化**——同样的参数只真正计算一次。

代理的常见用途：

| 用途 | 机制 |
|---|---|
| 缓存 / 记忆化 | 查缓存命中则直接返回 |
| 惰性初始化 | 首次访问时才创建真实对象 |
| 访问控制 | 检查权限后再转发 |
| 日志 / 埋点 | 转发前后记录 |

**代理的代价**：被代理的对象无法进入引擎的快速属性访问路径（见 [07-引擎与性能/01-引擎架构与 JIT](../07-引擎与性能/01-引擎架构与JIT.md)），热路径上不要用。

### 组合：统一对待单个与整体

组合模式让**叶子节点与容器节点实现同一接口**，调用方不必区分：

```javascript
// composite.mjs
// 叶子与容器实现同一接口：total() 与 size()
const leaf = (v) => ({
  total: () => v,
  size: () => 1,
});
const node = (...children) => ({
  total: () => children.reduce((s, c) => s + c.total(), 0),
  size: () => children.reduce((s, c) => s + c.size(), 0),
});

const tree = node(leaf(1), node(leaf(2), leaf(3)), leaf(4));
console.log(`  叶子与组合节点同一接口: total = ${tree.total()} size = ${tree.size()}`);
```

```console
$ node composite.mjs
  叶子与组合节点同一接口: total = 10 size = 4
```

`leaf` 与 `node` 都有 `total()` 与 `size()`，因此 `node(leaf(1), node(leaf(2), leaf(3)), leaf(4))` 这样的嵌套结构可以直接求值——递归由结构本身承担。

**DOM 树就是组合模式**：`appendChild` 既能接元素也能接文档片段，遍历时不必区分；[11-前端框架与状态管理/01-框架原理](../11-前端框架与状态管理/01-框架原理.md) 里的虚拟 DOM 树同理。

**组合与对象模型的关系**：JavaScript 的属性查找天然支持"沿链向上找"，所以组合常常不需要显式的容器类——一个对象的原型链或属性引用就能表达"部分-整体"。

### 其余三个

| 模式 | JavaScript 中的状态 |
|---|---|
| **桥接** | 用**函数参数**替代：把"变化的部分"作为参数传入，比建继承层次简单 |
| **享元** | 引擎已在做（字符串驻留、隐藏类共享）；应用层常用对象池或缓存实现 |
| **装饰器** | 退化为**高阶函数**，见 [04-行为型模式](./04-行为型.md) 的对照 |

## 连接：四个常用结构型模式对照

| | 目的 | 接口 | 典型场景 |
|---|---|---|---|
| **适配器** | 转换接口 | 与目标不同 | 对接第三方/遗留 API |
| **外观** | 简化接口 | 比子系统更简单 | 封装一组复杂调用 |
| **代理** | 控制访问 | 与目标**相同** | 缓存、权限、惰性加载 |
| **组合** | 统一单个与整体 | 叶子与容器**相同** | 树形结构、嵌套组件 |

**适配器与代理都"包一层"，差别在目的**：适配器改接口形状，代理保持接口不变并插入控制逻辑。

## 边界

- **适配器适用于改不动的一方**：能改就统一命名，别加层。
- **外观会膨胀**：只暴露调用方需要的组合。
- **代理影响性能**：热路径不用（见 [07-引擎与性能/01](../07-引擎与性能/01-引擎架构与JIT.md)）。
- **组合依赖统一接口**：叶子与容器的方法签名必须一致，否则调用方仍要区分。
- **桥接常被函数参数取代**：不要为"两个维度的变化"建继承层次。
- **享元多由引擎承担**：应用层只在确实有大量重复对象时才需要。
