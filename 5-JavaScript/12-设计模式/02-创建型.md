# 创建型模式

> 前置：[01-设计模式总览](./01-设计模式总览.md) · 后续：[03-结构型模式](./03-结构型.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1，Windows x64。

## 本质

创建型模式解决**"怎么造对象"**：把"造什么、怎么造"与"用它的代码"分开。经典分类有五种（单例、工厂方法、抽象工厂、建造者、原型），JavaScript 里前四种都退化了，只有第五种被语言直接内建。

判据仍是 [01-设计模式总览](./01-设计模式总览.md) 那条：**模式是否在补偿语言缺陷**。

## 机制

### 单例 → 模块

**诉求**（全局唯一实例）仍在，但表达它不再需要类结构。**模块的顶层代码只执行一次**，导入方拿到的是同一个对象：

```javascript
// counter.mjs
let n = 0;                     // 模块私有，外部拿不到
export let evals = 0;          // 模块体每求值一次，这里 +1
evals++;
export const counter = { inc: () => ++n, get: () => n };
```

```javascript
// main.mjs
import { counter as a, evals } from "./counter.mjs";
import { counter as b } from "./counter.mjs";          // 第二次静态导入：同一模块
const { counter: c } = await import("./counter.mjs");  // 动态导入：仍命中缓存
console.log(`  三次导入同一实例: ${a === b && b === c} | 模块求值次数: ${evals}`);
```

```console
$ node main.mjs
  三次导入同一实例: true | 模块求值次数: 1
```

三次导入（两次静态 + 一次动态）得到同一个实例，模块体只求值了一次。`n` 是模块私有绑定，外部只能经 `counter` 的方法触达——经典单例的完整形态（私有构造器、静态实例字段、`getInstance()`）全部由模块系统代劳。

**要重置单例做测试**时，模块缓存反而是障碍——需要 `delete require.cache[...]`（CommonJS）或依赖注入把状态从模块里挪出来。

### 工厂 → 返回对象的函数

工厂的诉求是"调用方只说要什么，不关心怎么造"。JavaScript 里不需要工厂类：

```javascript
const makeUser = (name, role = "user") => ({ name, role, createdAt: "固定值" });
```

一个函数就够了——它天然把构造细节封装在函数体内，且返回值可以是任意形状。

**什么时候仍需要"抽象工厂"**：当存在**多套相关产品**且要整体替换时（如"生产一套 UI 组件" vs "生产另一套"）。这时用一个返回对象集合的工厂函数即可，仍不需要类层次：

```javascript
const themes = {
  light: () => ({ button: LightButton, input: LightInput }),
  dark:  () => ({ button: DarkButton,  input: DarkInput }),
};
```

### 建造者 → 链式调用 + 分步构造

当一个对象有很多可选部分、构造过程需要分步时，用链式调用累积状态，最后一次 `build()`：

```javascript
// builder.mjs
class QueryBuilder {
  #select = "*";
  #from = null;
  #where = [];
  #limit = null;
  select(...cols) { this.#select = cols.join(", "); return this; }
  from(table)     { this.#from = table; return this; }
  where(cond)     { this.#where.push(cond); return this; }
  limit(n)        { this.#limit = n; return this; }
  build() {
    let sql = `SELECT ${this.#select} FROM ${this.#from}`;
    if (this.#where.length) sql += ` WHERE ${this.#where.join(" AND ")}`;
    if (this.#limit != null) sql += ` LIMIT ${this.#limit}`;
    return sql;
  }
}

const q = new QueryBuilder()
  .select("id", "name").from("users")
  .where("age > 18").where("active = 1").limit(10);
console.log(`  ${q.build()}`);

// base 建好后可以派生出多个变体
const makeBase = () => new QueryBuilder().from("orders");
const v1 = makeBase().build();
const v2 = makeBase().where("status = 'paid'").build();
console.log(`  分步构造可复用中间态: ${v1} | ${v2}`);
```

```console
$ node builder.mjs
  SELECT id, name FROM users WHERE age > 18 AND active = 1 LIMIT 10
  分步构造可复用中间态: SELECT * FROM orders | SELECT * FROM orders WHERE status = 'paid'
```

**两个收益**：

| 收益 | 说明 |
|---|---|
| 避免长参数列表 | 每个可选部分一个方法，不必记参数顺序 |
| 中间态可复用 | `base` 建好后可以派生出多个变体（实测第二行） |

代价是**需要一次额外的 `build()`**，且对象在 `build()` 之前处于半成品状态。**参数不多时不要用**——直接传对象字面量更简单。

### 原型 → `Object.create`

原型模式是唯一**被语言直接内建**的创建型模式：`Object.create(proto)` 创建新对象并指定其原型。

```console
$ node -e 'const proto={describe(){return "我是 "+this.name}}; const a=Object.create(proto), b=Object.create(proto); a.name="甲"; b.name="乙"; console.log("  共享方法:", a.describe(), "|", b.describe()); console.log("  方法只在原型上存一份:", a.describe===b.describe); console.log("  自身属性:", Object.keys(a).join(","), "| 原型:", !Object.hasOwn(a,"describe"))'
  共享方法: 我是 甲 | 我是 乙
  方法只在原型上存一份: true
  自身属性: name | 原型: true
```

两个对象共享同一份方法（`a.describe === b.describe` 为 `true`），各自的 `name` 是自身属性。这正是 [02-对象模型与运行时/01-原型链与继承](../02-对象模型与运行时/01-原型链与继承.md) 讲的委托式继承——**JavaScript 的对象模型本身就是原型模式**。

`class` 是它的语法封装（见 [01-语言核心/05-对象与类](../01-语言核心/05-对象与类.md)），`Object.create(null)` 则用于创建无原型的纯字典。

### 四种创建方式对照

| 方式 | 形态 | 适用 |
|---|---|---|
| 对象字面量 | `{ a: 1 }` | 大多数情况 |
| 工厂函数 | `makeX(...)` 返回对象 | 需要封装构造逻辑 |
| 构造函数 / `class` | `new X(...)` | 需要原型共享方法、`instanceof` 判断 |
| `Object.create(proto)` | 直接指定原型 | 无类的原型继承、纯字典 |

## 连接：与经典创建型模式

| 经典模式 | JavaScript 对应 | 是否仍需要 |
|---|---|---|
| 单例 | 模块 | 诉求保留，形态消失 |
| 工厂方法 | 返回对象的函数 | 诉求保留，形态消失 |
| 抽象工厂 | 返回对象集合的工厂函数 | 多套产品时才需要 |
| 建造者 | 链式调用 | 参数多且可选时仍有用 |
| 原型 | `Object.create` / 原型链 | **语言内建** |

## 边界

- **单例就是模块**：不要为它写类结构。
- **工厂只在需要隐藏构造细节时用**：`{ a: 1 }` 能表达的就别包函数。
- **建造者只在可选参数多时用**：参数少时对象字面量更直接。
- **`Object.create(null)` 没有原型**：连 `toString` 都没有，适合做字典。
- **模块缓存会让"重置单例"变难**：测试需要独立状态时，把状态从模块里挪出来用依赖注入。
- **不要为了模式而抽象**：只有一个产品时不需要工厂。
