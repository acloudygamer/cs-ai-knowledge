# Node.js 数据库操作

## 定义

数据库在 Node.js 中的本质是**进程外持久化存储的客户端抽象**。无论 SQL 还是 NoSQL，数据库暴露的是键值或文档的读写接口，数据本身驻留在独立进程（数据库服务）中，通过网络协议（TCP/Unix Socket）与 Node.js 进程通信。

## 数学模型

**连接池的队列模型**：设池大小为 $N$，并发请求数为 $R$。当 $R \le N$ 时，所有请求立即分配连接；当 $R > N$ 时，第 $N+1$ 至 $R$ 个请求在队列中等待可用连接。

平均响应时间 $T$ 随并发增加而增长，瓶颈在 $N$。合理的池大小应等于数据库服务的最大连接数限制。

**Redis 操作的原子性**：Redis 单命令执行是原子的，但复合操作（如先 GET 再 SET）不是。Lua 脚本在 Redis 中原子执行，因为 Redis 会将整个 Lua 脚本作为单一命令执行。

$$T_{\text{Lua script}} = T_{\text{eval}} = \text{单个 Redis 命令耗时}$$

## 数据流

<pre>
SQL: B+ Tree ──────────▶ 磁盘页 ──▶ 索引覆盖
     (读优化)             随机 I/O

NoSQL (LSM): MemTable ──▶ WAL ──▶ SSTable
   (写优化)              顺序写
</pre>

**数据库查询的数据形态变换**：
1. Node.js 发送 SQL/NoSQL 协议消息（TCP 字节流）
2. 数据库进程解析消息、执行查询（可能涉及磁盘 I/O）
3. 结果集通过网络返回（序列化字节流）
4. Node.js 驱动将字节流反序列化为 JS 对象/数组

## 机制

**为什么 SQL 数据库用 B+ 树**：B+ 树的所有数据节点都在同一深度，确保任意查询的磁盘 I/O 次数相近（$\log_{fanout} N$）。范围查询（如 `BETWEEN`）在 B+ 树中可以顺序遍历叶子节点，开销最低。

**为什么 NoSQL 用 LSM 树**：LSM 树的写入是顺序的（先写 WAL，再写 MemTable，定期合并为 SSTable），适合高写入场景。代价是读取需要检查多层结构（MemTable → 多个 SSTable），读性能低于 B+ 树。

**连接池的约束**：
- 每个数据库连接占用服务器资源（内存、文件描述符）
- 若池大小超过数据库最大连接数，部分连接会被拒绝
- 连接长时间空闲会被数据库服务端断开（timeout），客户端需要重连机制

**分布式锁的设计约束**：
- `SET NX EX` 保证加锁和设置过期时间是原子操作，防止死锁（锁持有者崩溃后锁无法释放）
- 释放锁时必须校验值（Lua 脚本），否则可能误删他人持有的锁
- 过期时间应大于正常操作时长，防止误删

**违反约束的后果**：
- 分布式锁过期时间设太短 → 业务还未完成锁已释放，其他客户端获取同一把锁 → 数据竞争
- 连接池耗尽 → 新请求排队或报错；数据库服务可能拒绝新连接

## SQL 数据库连接

连接池的本质是**有限资源的复用**：预先建立 N 个连接，请求借出、用完归还，避免频繁创建/销毁连接的开销，同时限制最大并发数保护数据库。

```javascript
const { Pool } = require('pg');
const pool = new Pool({ max: 20, host: 'localhost' });
const { rows } = await pool.query('SELECT * FROM users WHERE id = $1', [id]);
await pool.end();
```

## MongoDB 文档模型

MongoDB 的本质是**无 Schema 的 BSON 文档集合**：文档自行包含完整结构，通过 MMAPv1/WiredTiger 引擎映射到磁盘，支持嵌套文档减少 JOIN 操作。

```javascript
const { MongoClient } = require('mongodb');
const client = new MongoClient('mongodb://localhost:27017');
const db = client.db('mydb');
await db.collection('users').insertOne({ name: 'Alice', email: 'a@b.com' });
```

## Redis 数据结构

Redis 的本质是**内存中的持久化字典**：每种数据结构（string/hash/list/set/zset）都有对应的编码实现（int/embstr/hashtable/ziplist/quicklist），在内存效率和操作复杂度间动态选择。

```javascript
const { createClient } = require('redis');
const client = createClient();
await client.set('key', 'value');
await client.hSet('user:1', { name: 'Alice' });
await client.lPush('queue', 'job1');
```

## 分布式锁

分布式锁的本质是**外部协调者的原子性承诺**：利用 Redis SET NX EX 原子操作获取锁，Lua 脚本保证释放锁时的值校验，防止误删他人持有的锁。

```javascript
const lockKey = `lock:${resourceId}`;
const lockValue = Date.now().toString();
await client.set(lockKey, lockValue, { NX: true, EX: 10 });
```

## 参考存根

*展示连接池和分布式锁的最简可执行证明：*

```javascript
// 依赖：npm install pg ioredis
// 执行：node app.js
const { Pool } = require('pg');
const pool = new Pool({ max: 2 });
async function query(sql) {
  const client = await pool.connect();
  try { return await client.query(sql); }
  finally { client.release(); }
}
query('SELECT 1').then(r => console.log('rows:', r.rows));

// 分布式锁示例（需 Redis）
const { createClient } = require('redis');
const redis = createClient();
async function acquireLock(key, ttlSec) {
  const val = Date.now().toString();
  const ok = await redis.set(key, val, { NX: true, EX: ttlSec });
  return ok ? val : null;
}
acquireLock('test-lock', 5).then(v => console.log('lock:', v));
```
