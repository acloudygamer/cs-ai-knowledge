# 包管理深入

## 包管理器的本质

包管理器的本质是**依赖图的解析与构建**：解析 package.json 中的依赖声明，按版本规则（semver）确定具体版本，处理依赖的依赖，最终将产物安装到 node_modules。

<pre>
package.json ──▶ 依赖图解析 ──▶ 版本求解 ──▶ 目录结构
     │                                  │
     └── lock 文件 ─────────────────────┘ 确定性重建
</pre>

## npm vs yarn vs pnpm

三者的核心差异在于**依赖解析策略**：npm 扁平化（可能存在重复副本）、yarn 同样扁平化但确定性更强、pnpm 坚持非扁平化（严格隔离 + 硬链接）。

| 特性 | npm | yarn | pnpm |
|------|-----|------|------|
| 安装速度 | 慢 | 中等 | 快 |
| node_modules | 扁平 | 扁平 | 非扁平 |
| 锁文件 | package-lock.json | yarn.lock | pnpm-lock.yaml |

---

## 依赖版本语义

semver 的本质是**API 兼容性承诺**：^1.2.3 表示 "兼容 1.x.x"，~1.2.3 表示 "兼容 1.2.x"。版本号递增规则：major（破坏性变更）/ minor（新增功能）/ patch（修复）。

```json
{ "lodash": "^4.17.21" }
```

---

## package.json exports

exports 字段的本质是**条件导出**：根据导入方式（import/require）和运行环境（node/browser）选择不同的入口文件，实现同一个包支持多种使用方式。

```json
{
  "exports": {
    ".": {
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  }
}
```

---

## 锁文件的本质

锁文件的本质是**依赖图的快照**：记录每个包的具体版本、下载地址、校验和，确保任何时间 `npm ci` 都能重建完全相同的依赖图。

---

## monorepo 工作区

monorepo 的本质是**代码共享与独立版本的平衡**：workspaces 允许同一个代码仓库中的多个包相互依赖，同时各自维护独立的版本号。

```yaml
# pnpm-workspace.yaml
packages:
  - 'packages/*'
```
