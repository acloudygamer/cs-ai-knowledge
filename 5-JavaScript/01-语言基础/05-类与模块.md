# 类与模块

## 定义

ES6 的 `class` 语法是**原型继承的语法糖**。类声明的本质是构造函数 + 原型方法的组合定义。ES6 模块（ESM）是**编译时静态分析的导出-导入契约**，导入绑定是对导出值的**只读引用**（live binding）。

## 数学模型

### 类声明的 TDZ 建模

类声明的提升与 `let` 类似：
$$
\forall C \in \text{class declarations}: \quad \text{TDZ}(C) = [\text{lexical-start}(C), \text{evaluation-reaches}(C))
$$

类声明在词法层面被提升，但存在 TDZ——在声明行之前访问类会触发 ReferenceError：

| 声明类型 | 提升 | TDZ | 声明前调用 |
|----------|------|-----|------------|
| 函数声明 | 完全提升 | 无 | 可调用（返回函数体） |
| 类声明 | 词法提升 | 有 | ReferenceError |

**约束条件**：类声明不是函数声明的两阶段提升，而是词法声明，存在 TDZ。

### 原型链的性能约束

原型链长度过长会影响属性查找性能：
$$
T_{\text{lookup}} = O(h)
$$
其中 $h$ 是原型链深度。V8 对短原型链（< 4 层）有快速路径优化，超过后性能显著下降。

**归约终点**：原型链查找可归约为**链表的线性搜索**，内联缓存（Inline Cache）将常见路径的查找压缩为 $O(1)$ 。

### ESM 的静态依赖图

ESM 的 `import`/`export` 在**解析阶段**确定依赖图，而非运行时：
$$
G = (V, E), \quad V = \text{模块集合}, \quad E = \text{import关系}
$$

**约束条件**：
- 条件导入 `if (cond) import(...)` 是**语法错误**
- 循环依赖 $A \rightarrow B \rightarrow A$ 可能导致未初始化的绑定（值为 undefined）

**违反约束的后果**：
- 循环依赖导致模块绑定在使用时可能尚未初始化
- 循环依赖图中若模块 A 导入模块 B 的绑定，而 B 尚未完成执行，导入的值为 undefined

### ESM 的 live binding 语义

导出绑性的值可被重新赋值，所有导入该绑性的模块都能看到新值：
$$
\forall \text{export } x: \quad \text{修改}(x) \Rightarrow \forall \text{imports of } x: \text{可见新值}
$$

这是值拷贝（CommonJS）与引用绑定的本质区别。

## 数据流

### new Person() 的执行流程

<pre>
new Person(args)
    │
    ▼
创建空对象 {}
    │
    ▼
设置 [[Prototype]] → Person.prototype
    │
    ▼
Person 构造函数调用，this = 新对象
    │
    ▼
构造函数返回：
    ├── 显式返回对象 → 返回该对象
    └── 无/返回基本类型 → 返回 this
</pre>

### ESM 导入-导出数据流

<pre>
模块 A (export)
    │
    ├──> export let count = 0;
    │
    ▼
导出绑定（live binding：值可被重新赋值）
    │
    ▼
模块 B (import { count } from './A')
    │
    ▼
导入绑定是对导出值的只读引用
    │
    ▼
模块 C 导入 B，B 再导入 A → 间接依赖追踪
</pre>

**live binding 的含义**：模块 A 修改 `count++` 后，所有导入 `count` 的模块都能看到新值。

## 机制

### class 的本质：构造函数 + 原型链

```javascript
class Person {
    constructor(name) {
        this.name = name;  // 实例属性
    }
    greet() {
        return `Hello, ${this.name}`;
    }
}
// 等价于：
function Person(name) { this.name = name; }
Person.prototype.greet = function() { return `Hello, ${this.name}`; };
```

`class` 语法不改变 JavaScript 的原型继承模型，只是提供更清晰的声明语法。

**约束条件**：class 内方法不可枚举（enumerable: false），与构造函数 prototype 方法行为一致。

### extends 的原型链构造

```javascript
class Dog extends Animal {
    constructor(name, breed) {
        super(name);  // 调用 Animal 构造函数
        this.breed = breed;
    }
}
```

`extends` 建立以下原型链：
$$
\text{Dog.prototype.[[Prototype]]} \rightarrow \text{Animal.prototype}
$$

实例继承的查找路径：
$$
\text{dog} \rightarrow \text{Dog.prototype} \rightarrow \text{Animal.prototype} \rightarrow \text{Object.prototype} \rightarrow \text{null}
$$

**约束条件**：
- 子类构造函数必须调用 `super()` 才能使用 `this`
- `super()` 必须在 `this` 使用之前调用

**违反约束的后果**：在调用 `super()` 之前访问 `this` 抛出 ReferenceError。

### 私有字段（#）的实现机制

`#` 前缀私有字段在**编译阶段**通过语法变换实现：
```javascript
class BankAccount {
    #balance = 0;  // 编译后：this.#balance → [[PrivateMap]].get(this)
}
```

私有字段存储在对象的 **PrivateMap** 中，键为 `#field` Symbol，外部访问在语法阶段就被拒绝（不是运行时检查）。

**约束条件**：
- 私有字段必须在类体内声明时使用 `#` 前缀
- 外部任何访问方式（包括反射 `Reflect.ownKeys()`）都无法访问私有字段

**违反约束的后果**：访问私有字段导致 SyntaxError（编译时）或 TypeError（通过 `eval` 等动态访问）。

### ESM vs CommonJS 的本质差异

| 维度 | ESM | CommonJS |
|------|-----|----------|
| 加载时机 | 编译时（静态分析） | 运行时（执行时加载） |
| 导入绑定 | 只读引用（live binding） | 值拷贝 |
| 顶层级 | 必须在模块顶层 | 可在函数内 |
| this | undefined | module.exports |
| 循环依赖 | 支持，但可能未初始化 | 支持 |
| 异步 | 原生支持 | 需额外工具 |

**CommonJS 是值拷贝**：导出值变化不会影响导入者，因为导入时已经完成拷贝。

**约束条件**：CommonJS 的 `require()` 是同步的，不适合浏览器端动态加载。

**违反约束的后果**：
- ESM 顶层 `await` 在 CommonJS 中使用是语法错误
- CJS 模块导入 ESM 模块需要动态 `import()`（异步）

**ESM vs CommonJS 互操作**：
```javascript
// ESM 导入 CJS：值拷贝
import cjs from './cjs-module';  // default export 是 module.exports

// CJS 导入 ESM：动态 import()
const esm = await import('./esm-module');
```

## 参考存根

```javascript
// 类声明 TDZ
// const p = new Person('Bob');  // ReferenceError
class Person {
    constructor(name) { this.name = name; }
}

// 原型链演示
class Animal { speak() { return '...'; } }
class Dog extends Animal {
    speak() { return 'Woof'; }
}
const dog = new Dog();
dog instanceof Dog      // true
dog instanceof Animal   // true（沿着原型链）
dog instanceof Object   // true

// ESM 循环依赖
// a.js
import { b } from './b.js';
export const a = b ? 'A' : undefined;

// b.js
import { a } from './a.js';
export const b = a ? 'B' : undefined;
// 结果：a 和 b 都可能是 undefined（取决于模块求值顺序）
```
