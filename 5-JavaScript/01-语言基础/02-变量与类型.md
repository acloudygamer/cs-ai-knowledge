# 变量与类型

## 定义

JavaScript 的变量是**词法作用域的命名绑定**。`let` 和 `const` 在 ES6 引入，提供块级作用域和暂时性死区（TDZ）保护；`var` 是函数作用域，存在变量提升。JavaScript 的类型系统是**弱类型 + 动态类型**：类型在运行时确定，且算术运算时允许隐式类型转换（coercion）。

## 数学模型

### 变量提升的行为建模

`var` 的提升可建模为**两阶段声明**：
$$
\forall x \in \text{function scope}: \quad \text{hoist}(x) = \begin{cases}
\text{undefined} & \text{if evaluation hasn't reached declaration} \\
\text{value} & \text{if evaluation has passed declaration}
\end{cases}
$$

数学等价于在函数体顶部插入 `var x;`，但赋值位置不变。

### let/const 的 TDZ 数学定义

TDZ（暂时性死区）是**词法作用域中的动态错误检测**：
$$
\forall x \in \text{block scope}: \quad \text{TDZ}(x) = [ \text{lexical-start}(x), \text{evaluation-reaches}(x) )
$$
在 TDZ 区间内访问 $x$ 触发 ReferenceError。

### IEEE 754 浮点精度问题

JavaScript 使用 IEEE 754 双精度浮点（float64）：
$$
0.1 + 0.2 = \text{float64}(0.1) + \text{float64}(0.2) \neq \text{float64}(0.3)
$$

原因：十进制 0.1 和 0.2 无法精确表示为二进制浮点：
$$
0.1_{10} = 0.0001100110011..._{2} \quad \text{（无限循环）}
$$
截断导致精度损失。

**归约终点**：浮点精度问题可归约为**有理数到二进制浮点表示的截断误差**，这是 IEEE 754 规范的固有行为。

### 类型强制转换的抽象操作建模

隐式类型转换通过一组抽象操作定义：

$$
\text{ToPrimitive}(x) \rightarrow \text{调用 } x.\text{valueOf}() \text{ 或 } x.\text{toString}()
$$
$$
\text{ToNumber}(x) \rightarrow \begin{cases}
\text{true} \rightarrow 1 \\
\text{false} \rightarrow 0 \\
\text{string} \rightarrow \text{parseFloat/parseInt} \\
\text{...} &
\end{cases}
$$

**约束条件**：转换失败返回 `NaN`，`NaN` 与任何值比较（包括自身）均为 false。

## 数据流

### 变量声明的执行模型

<pre>
源代码声明 `let x = 1;`
    │
    ▼
词法分析：标识符 `x` 注册到当前作用域环境
    │
    ▼
执行阶段到达声明语句：
    │
    ├──> 创建绑定（TDZ 状态）
    │
    ▼
求值表达式 `1`
    │
    ▼
绑定初始化（TDZ 结束）
    │
    ▼
后续访问：读取绑定值
</pre>

### 类型转换的数据流

<pre>
值 A (类型 T₁)
    │
    ├──> 隐式转换（运算符语义触发）
    │       │
    │       ▼
    │   ToPrimitive(A) → 尝试 valueOf() / toString()
    │
    ├──> 显式转换（Number(), String(), Boolean()）
    │
    ▼
值 B (类型 T₂) 或抛出 TypeError
    │
    ▼
运算执行（若 T₁ ≠ T₂，隐式转换后执行）
</pre>

## 机制

### 变量声明的本质差异

| 声明 | 作用域 | TDZ | 重复声明 | 重新赋值 | 特性 |
|------|--------|-----|----------|----------|------|
| `var` | 函数作用域 | 无 | 允许 | 允许 | 提升至函数顶部，初始值 undefined |
| `let` | 块级作用域 | 有 | 禁止 | 允许 | 提升但不可访问（TDZ） |
| `const` | 块级作用域 | 有 | 禁止 | 禁止 | 必须在声明时初始化 |

**TDZ 的本质**：变量声明在词法上被提升，但在实际执行到声明语句前，任何访问都抛出 ReferenceError。这与 `var` 的"undefined"行为不同——TDZ 是**硬错误**，不是隐式 undefined。

**为什么设计 TDZ**：避免在声明前访问变量（常见 bug 源），强制开发者明确变量顺序，使代码更可预测。

**约束条件**：
- `const` 变量必须在声明时初始化
- `const` 变量不可重新赋值，但对象属性可修改（除非使用 `Object.freeze`）

**违反约束的后果**：
- 对 `const` 重新赋值 → TypeError: Assignment to constant variable
- 在 TDZ 内访问 `let`/`const` → ReferenceError
- 重复声明 `let`/`const` → SyntaxError

### 基本类型与对象类型的本质差异

| 维度 | 基本类型 | 对象类型 |
|------|----------|----------|
| 存储方式 | 值直接存在栈上 | 引用（指针）存在栈上，对象在堆 |
| 比较方式 | 值比较 | 引用比较（`{ } === { }` 为 false） |
| 可变性 | 不可变（字符串的部分操作返回新串） | 可变 |
| typeof 结果 | `'number'`, `'string'`, `'boolean'`, `'bigint'`, `'symbol'`, `'undefined'` | `'object'`, `'function'` |

**基本类型的包装对象**：基本类型在必要时自动装箱（boxing）为包装对象（`Number`, `String`, `Boolean`），但装箱后 `===` 仍然比较引用。

**约束条件**：基本类型的装箱操作是自动的，但装箱后的对象比较是引用比较，与基本类型值的相等性比较不同。

### 隐式类型转换的触发条件

JavaScript 的隐式转换发生在以下运算符：

| 运算符 | 转换规则 |
|--------|----------|
| `+` | 若有操作数为字符串，另一操作数转字符串后拼接 |
| `-`, `*`, `/`, `%` | 两操作数转数字（ToNumber） |
| `==` | 类型不同时尝试类型 coercion |
| `&&`, `\|\|` | 返回原值（非布尔） |
| `!`, `!!` | 转布尔后取反 |

**`==` 的类型转换规则**（抽象操作）：
```
ToPrimitive(A) == ToPrimitive(B)
  → 若有一方是对象，调用 valueOf() 或 toString()
  → 若类型相同，比较值
  → null == undefined（两者相等，与自身相等）
  → number vs string，string 转 number
  → boolean vs non-boolean，boolean 转 number
```

**违反约束的后果**：
- `==` 的隐式转换导致意外的真值判断（如 `'' == false` 为 true）
- `+` 运算符在操作数为对象时触发 ToPrimitive，可能调用自定义 valueOf/toString 产生意外结果

### Symbol 的本质

Symbol 是**唯一的、不可枚举的属性键**：
```javascript
const s1 = Symbol('desc');
const s2 = Symbol('desc');
s1 === s2  // false——即使描述相同，也是不同的 Symbol
```

**约束条件**：Symbol 创建后不可更改，是唯一性标识。

**Symbol 的使用场景**：
- 私有属性（外部无法通过 `for...in` 或 `Object.keys()` 枚举）
- 避免属性名冲突
- 内置 Symbol（`Symbol.iterator`, `Symbol.toStringTag`）

### BigInt 的本质

BigInt 是 ES2020 引入的任意精度整数类型：
```javascript
const big = 123456789012345678901234567890n;
big + 1n  // 123456789012345678901234567891n
```

**约束**：BigInt 与 Number 混合运算是**硬错误**，必须显式转换：
```javascript
BigInt(1) + Number(1)  // TypeError
```

**违反约束的后果**：BigInt 与 Number 混合运算直接抛出 TypeError。

### 类型守卫的 narrowing 机制

类型守卫是**运行时类型 narrowing** 机制，在条件分支内缩小类型范围：

```javascript
function process(value: string | number) {
    if (typeof value === 'string') {
        // value 在此分支被 narrowing 为 string
        console.log(value.toUpperCase());
    } else {
        // value 在此分支被 narrowing 为 number
        console.log(value.toFixed(2));
    }
}
```

**narrowing 的数学本质**：在条件分支内，类型系统将联合类型 $T = T_1 \cup T_2$ 缩小为子类型 $T_1$ 或 $T_2$。

## 参考存根

```javascript
// var 提升演示
console.log(hoisted);  // undefined（不是 ReferenceError——var 提升但赋值未提升）
var hoisted = 'hello';

// let TDZ 演示
// console.log(tdz);  // ReferenceError: Cannot access 'tdz' before initialization
let tdz = 'hello';

// 浮点精度问题与解决方案
0.1 + 0.2 === 0.3  // false
Number.EPSILON      // 2^-52 ≈ 2.22e-16，用于浮点比较
function epsEqu(x, y) {
    return Math.abs(x - y) < Number.EPSILON;
}
epsEqu(0.1 + 0.2, 0.3)  // true

// Symbol 唯一性
const s1 = Symbol('key');
const s2 = Symbol('key');
const obj = { [s1]: 'value1', [s2]: 'value2' };
Object.keys(obj).length  // 0——Symbol 属性不可枚举

// BigInt 与 Number
const big = 9007199254740993n;
const num = 9007199254740993;
big === num    // false（类型不同）
Number(big)    // 9007199254740992（精度丢失！）
big + 1n       // 9007199254740994n
```
