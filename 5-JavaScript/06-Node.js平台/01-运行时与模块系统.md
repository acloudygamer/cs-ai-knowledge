# 运行时与模块系统

> 前置：[05-浏览器平台/05-浏览器安全模型](../05-浏览器平台/05-浏览器安全模型.md) · 后续：[02-文件系统与流](./02-文件系统与流.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6.233.17-node.40，libuv 1.51.0），Windows x64。

## 本质

Node.js 是**宿主**——它让 JavaScript 能在浏览器之外运行（见 [00-概览/01-JavaScript 全景](../00-概览/01-JavaScript全景.md)）。它由三部分构成：

| 构成 | 提供什么 |
|---|---|
| **V8** | 执行 ECMA-262 定义的语言（见 [07-引擎与性能](../07-引擎与性能/)） |
| **libuv** | 事件循环与异步 I/O（文件、网络、DNS、定时器） |
| **Node 标准库** | `node:fs`、`node:http`、`node:crypto` 等模块 |

```console
$ node rt.mjs
node: v24.13.1 | v8: 13.6.233.17-node.40 | uv: 1.51.0
platform/arch: win32 x64 | pid: number
```

**语言本身没有 I/O**，所以文件、网络、进程这些能力全部来自 Node 标准库。本篇讲两件事：运行时暴露了什么（`process` 与全局对象），以及"`require("x")` 到底去哪找"（模块解析）。

模块系统的**语义**（CommonJS 与 ESM 的行为差异、活绑定、包装函数）已在 [01-语言核心/06-模块](../01-语言核心/06-模块.md) 讲过；本篇讲 Node 侧的**解析算法**。

## 机制

### `process`：进程的门面

`process` 是 Node 注入的全局对象，承载进程级信息与操作：

| 属性 / 方法 | 用途 |
|---|---|
| `process.version` / `versions` | Node 版本；`versions.v8`、`versions.uv` 等各组件版本 |
| `process.platform` / `arch` | 运行平台（`win32`、`linux`、`darwin` / `x64`、`arm64`） |
| `process.pid` | 进程号 |
| `process.argv` | 命令行参数数组 |
| `process.env` | 环境变量 |
| `process.cwd()` | 当前工作目录 |
| `process.exitCode` | 退出码（设置它比调用 `process.exit()` 更安全） |
| `process.nextTick` | 见 [04-异步与并发/01-事件循环与任务队列](../04-异步与并发/01-事件循环与任务队列.md) |
| `process.stdout` / `stderr` / `stdin` | 标准流 |

`process.exit()` 会**立即终止**，不等未完成的 I/O 与 `finally` 块执行。需要"优雅退出"时设置 `process.exitCode` 并让事件循环自然结束。

`process.env` 是环境变量在进程内的快照：**启动时注入，运行中修改不影响子进程以外的任何东西**（子进程见 [04-进程与集群](./04-进程与集群.md)）。

### 全局对象

```console
$ node rt.mjs
global === globalThis: true | 浏览器等价物 window 是否存在: undefined
```

`globalThis` 是跨宿主的标准全局对象（浏览器里等于 `window`，Node 里等于 `global`）。Node 独有的全局有：`process`、`Buffer`、`setImmediate`、`__dirname` / `__filename`（仅 CommonJS，见 [01-语言核心/06-模块](../01-语言核心/06-模块.md)）。

### `node:` 前缀

```console
$ node rt.mjs
裸名 'fs' === 'node:fs': true
```

`node:fs` 与 `fs` 解析到**同一个模块对象**——内置模块永远优先于 `node_modules` 里的同名第三方包，不存在被劫持的路径。前缀的价值是**消除阅读歧义**（一眼区分内置与第三方），且部分内置模块只有 `node:` 形式（如 `node:test` 没有裸名等价物）。**新代码统一用 `node:` 前缀。**

### 模块解析算法

`require("x")` 与 `import "x"` 按不同的规则解析 `x`：

**以 `./` 或 `../` 开头（相对路径）**：

| 步骤 | 规则 |
|---|---|
| 1 | 若有扩展名，直接找该文件 |
| 2 | 无扩展名，依次尝试 `.js` / `.json` / `.node`（CommonJS） |
| 3 | 若是目录，读其 `package.json` 的 `main` 字段 |
| 4 | 仍无，尝试目录下的 `index.js` / `index.json` |

```console
$ node -e 'console.log(require("./a"), "|", require("./sub"))'
从 a.js 加载 | 从 index.js 加载
```

**裸名（`x` 不以 `./` 开头）**：从当前目录开始，**逐级向上**查找 `node_modules/x`，直到文件系统根。这是"依赖可以嵌套安装"的机制来源。

**ESM 的差异**：`import` **要求写全扩展名**，不做目录 `index` 查找，也不做扩展名补全——因为它的解析规则来自规范而非 Node 的历史约定。

### `package.json` 的三个关键字段

| 字段 | 作用 |
|---|---|
| `"type"` | `"module"` 或 `"commonjs"`，决定 `.js` 文件按哪种模块处理 |
| `"main"` | 包的入口（旧机制） |
| `"exports"` | 包的入口与**封装边界**（新机制，优先于 `main`） |

`exports` 有三条容易误解的语义，实测如下：

**一、只对裸名解析生效。** 用相对路径 require 一个目录时，`exports` 被**完全忽略**：

```console
$ node -e 'console.log(require("demo"))'
CJS 入口
$ node -e 'require("./pkg")'
MODULE_NOT_FOUND
```

同一个包，通过 `node_modules` 的裸名 `demo` 能解析到 `exports` 指定的入口；直接 `require("./pkg")` 则走旧的目录解析，找不到 `main` 也没有 `index.js`，于是失败。

**二、条件是按顺序匹配的。**

```json
{ "exports": { ".": { "node": "./node.js", "default": "./browser.js" } } }
```

```console
$ node -e 'console.log(require("demo"))'
node 条件命中
```

条件对象**从上往下匹配，第一个命中的生效**。`node` / `import` / `require` / `default` 是常用条件；`default` 应放在最后兜底。

**三、声明了 `exports` 就成了封装边界。** 未列出的路径**一律不可访问**：

```console
$ node -e 'require("demo/browser.js")'
ERR_PACKAGE_PATH_NOT_EXPORTED
```

文件明明存在，但从包外拿不到——这正是 `exports` 相对 `main` 的核心改进：**包的内部结构可以自由重组，只要 `exports` 承诺的入口不变**。

### 子路径导出

```console
$ node -e 'console.log(require("demo/feature"))'
子路径 feature
```

`"./feature": "./feature.js"` 显式开放一个子路径。需要暴露多个入口的包（如 `lodash/merge`）靠它实现。

## 连接：两套解析规则对照

| | CommonJS | ESM |
|---|---|---|
| 扩展名 | 可省略，自动补全 | **必须写全** |
| 目录导入 | 找 `index.js` | **不支持** |
| `exports` 字段 | 支持 | 支持 |
| `main` 字段 | 支持 | 忽略（有 `exports` 时） |
| 相对路径的基准 | 文件所在目录 | 同左 |
| 裸名查找 | `node_modules` 逐级向上 | 同左 |
| 顶层 `await` | 不支持 | 支持 |

**新项目用 ESM**，但要清楚它的严格性：路径写错就是加载失败，没有"帮我找找看"的兜底。

## 边界

- **`node:` 前缀消除歧义**：内置模块一律加前缀。
- **ESM 不补扩展名、不找 `index.js`**：与 CommonJS 的差异必须记住。
- **`exports` 只对裸名生效**：路径导入绕过它。
- **`exports` 一旦声明就是封闭的**：没列出的子路径从外部不可达（这正是它的价值）。
- **`process.env` 是启动时的快照**：运行中的修改影响本进程后续的读取，也会传播给之后派生的子进程，但影响不到其他已在运行的进程。
- **`process.exit()` 不等清理**：优先用 `process.exitCode`。
