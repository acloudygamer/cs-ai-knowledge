# 文件系统与流

> 前置：[01-运行时与模块系统](./01-运行时与模块系统.md) · 后续：[03-HTTP 服务](./03-HTTP服务.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

文件系统 API 要同时回答两个问题：**用什么风格调用**（回调 / Promise / 同步），以及**一次处理多少数据**（整个文件 / 分块）。

第一个问题有三代 API 并存，不是新旧替代而是各有位置。第二个问题决定了内存占用——**数据量可能超过内存时就必须用流**，这一点与 [04-异步与并发/06-流](../04-异步与并发/06-流.md) 是同一件事，本篇讲文件侧的具体形态。

还要先建立一条基本认识：**文件里存的是字节，不是字符串**。`readFile(p, "utf8")` 是"读字节再按 UTF-8 解码"的合并写法，省略编码拿到的是 `Buffer`（字节序列）。

## 机制

### 三代 API

| 风格 | 导入 | 形态 |
|---|---|---|
| 回调 | `node:fs` | `fs.readFile(p, cb)` |
| **Promise** | `node:fs/promises` | `await readFile(p)` |
| 同步 | `node:fs` | `readFileSync(p)` |

**默认用 `node:fs/promises`**：与 `async` / `await` 自然配合，错误处理统一（见 [04-异步与并发/03-async/await 与异步模式](../04-异步与并发/03-async-await与异步模式.md)）。

**同步版本只有一个正当用途：进程启动时的初始化**（读配置、探测环境）。此时阻塞无害，且同步代码更简单——因为顶层 `await` 在 CommonJS 里不可用。**绝不要在请求处理路径上调用同步 API**：它会阻塞事件循环，让整个进程停止响应（见 [04-异步与并发/01-事件循环与任务队列](../04-异步与并发/01-事件循环与任务队列.md)）。

### 一次性读写 vs 流式

| | 一次性 | 流式 |
|---|---|---|
| API | `readFile` / `writeFile` | `createReadStream` / `createWriteStream` |
| 内存 | 整个文件 | 一块（默认 64 KB） |
| 何时开始处理 | 全部读完 | 第一块到达 |
| 适用 | 配置文件、小文件 | 日志、上传下载、大文件转换 |

判断依据只有两条（同 [04-异步与并发/06-流](../04-异步与并发/06-流.md)）：**数据量是否可能超过内存**，以及**首块数据是否在末块到达前就有用**。都不满足时一次性读写更简单也更快。

流式的完整用法（`pipeline`、背压、转换段）见 [04-异步与并发/06-流](../04-异步与并发/06-流.md)。文件侧最常见的一段是：

```javascript
await pipeline(
  createReadStream("big.log"),
  zlib.createGunzip(),
  createWriteStream("big.txt")
);
```

### `Buffer`：字节序列

```console
$ node fs.mjs
字符串长度: 5 | 字节长度: 9
按字节切会切坏: "中�"
toString('hex'): e4b8ade69687616263
```

`"中文abc"` 有 5 个字符、9 个字节——UTF-8 是**变长编码**，一个汉字占 3 字节。由此产生两条实践规则：

- **`length` 的含义取决于对象**：字符串的 `.length` 是码元数（见 [03-标准库/01-字符串与数字](../03-标准库/01-字符串与数字.md)），`Buffer.length` 是字节数。算文件大小时用后者。
- **不要按字节位置切分 UTF-8 文本**：上例切在第 4 字节，把一个汉字劈成两半，解码出替换字符 `�`。按**行**或按**字符**切，不要按字节。

`Buffer` 是 `Uint8Array` 的子类，可以直接用类型化数组的方法（见 [04-异步与并发/05-Worker 与共享内存](../04-异步与并发/05-Worker与共享内存.md)）。

### 错误用 `code` 而不是异常类型

```console
$ node fs.mjs
code: ENOENT | errno: number | syscall: open
wx 已存在: EEXIST
```

文件系统的错误**都是同一种异常类型**（`Error` 或 `SystemError`），靠 `e.code` 区分：

| 码 | 含义 |
|---|---|
| `ENOENT` | 文件或目录不存在 |
| `EEXIST` | 已存在（配合 `flag: "wx"` 做"不存在才创建"） |
| `EACCES` / `EPERM` | 权限不足 |
| `EISDIR` / `ENOTDIR` | 期望文件/目录与实际不符 |
| `ENOSPC` | 磁盘满 |
| `EBUSY` | 被占用（Windows 上常见） |

`syscall` 字段说明是哪个操作失败的（`open`、`read`、`rename`……），排查时比 `message` 更有用。

**判"文件是否存在"用 `access()` 或直接操作并捕获 `ENOENT`**，不要用 `existsSync` 做"检查后再操作"——那中间存在竞态窗口，文件可能在两步之间被删除。**直接做，捕获错误**。

### `path`：跨平台路径

```console
$ node fs.mjs
join: a\c
dirname: /x/y | extname: .txt
resolve 是绝对路径: true
```

| 方法 | 作用 |
|---|---|
| `path.join(...)` | 拼接并规范化分隔符 |
| `path.resolve(...)` | 解析成绝对路径 |
| `path.dirname` / `basename` / `extname` | 拆解路径 |
| `path.sep` | 平台分隔符（Windows `\`，POSIX `/`） |
| `path.posix` / `path.win32` | 强制按指定平台规则处理 |

**不要手工拼路径字符串**：`"a" + "/" + "b"` 在 Windows 上得到混合分隔符，且 `..` 不会被规范化。注意 ESM 里没有 `__dirname`，需要它时用 `path.dirname(fileURLToPath(import.meta.url))`（见 [01-语言核心/06-模块](../01-语言核心/06-模块.md)）。

### 目录操作

```console
$ node fs.mjs
recursive mkdir 成功: true
readdir: deep
recursive rm 后存在: false
```

`mkdir(p, { recursive: true })` 创建整条路径（已存在也不报错）；`rm(p, { recursive: true, force: true })` 递归删除且不存在也不报错。这两个选项是"幂等"语义，适合放在初始化与清理代码里。

### 原子写入

`writeFile` 不是原子的：进程在写入中途崩溃会留下**半个文件**。需要"要么完整、要么不变"时，写临时文件再改名：

```javascript
await writeFile(tmp, data);
await rename(tmp, target);
```

同一文件系统内的 `rename` 是原子操作，读者要么看到旧文件、要么看到新文件，不会看到中间状态。注意 Windows 上目标存在时的 `rename` 行为与 POSIX 不同，跨平台场景需先处理。

## 连接：API 选择

| 场景 | 选择 |
|---|---|
| 读配置、启动初始化 | `readFileSync` 或 `await readFile` |
| 请求路径上的小文件读写 | `node:fs/promises` |
| 大文件、日志、上传下载 | 流 + `pipeline` |
| 需要"要么全成要么不变" | 临时文件 + `rename` |
| 判存在 | `access()` 或捕获 `ENOENT` |
| 遍历目录树 | `readdir(p, { recursive: true })` |

## 边界

- **同步 API 会阻塞事件循环**：只在启动路径上用。
- **不要按字节切 UTF-8 文本**：会切坏多字节字符。
- **错误靠 `e.code` 区分**：异常类型区分不出来。
- **`existsSync` 后接操作有竞态**：直接操作并捕获错误。
- **`writeFile` 非原子**：关键数据用临时文件 + `rename`。
- **路径用 `path` 模块拼**：手工拼接在 Windows 上会出错。
- **文件句柄要关闭**：流与 `open()` 都要保证关闭，`pipeline` 与 `try` / `finally` 是两种方式。
