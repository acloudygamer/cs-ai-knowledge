# 属性描述符与元编程

> 前置：[03-this 与调用约定](./03-this与调用约定.md) · 后续：[05-迭代协议与生成器](./05-迭代协议与生成器.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

前面几篇把属性当成"键 → 值"。更准确的说法是：**属性是"键 → 描述符"**，值只是描述符里的一个字段。描述符决定这个属性可不可写、能不能被 `for...in` 看见、能不能被删除，以及读取时到底执行什么代码。

把"属性"提升为可编程的对象，是 JavaScript 元编程的第一层。三层依次是：

| 层 | 操作对象 | 手段 |
|---|---|---|
| 属性级 | 单个属性的行为 | 属性描述符 |
| 对象级 | 对象的所有操作（读、写、删、枚举、调用） | `Proxy` |
| 行为级 | 上述操作的**默认实现** | `Reflect` |

## 机制

### 描述符的两个家族

| | 数据描述符 | 访问器描述符 |
|---|---|---|
| 专有字段 | `value`、`writable` | `get`、`set` |
| 共有字段 | `enumerable`、`configurable` | 同左 |

两族**互斥**：一个属性要么有值，要么有 getter/setter，不能兼有。`enumerable` 决定它是否出现在 `for...in`、`Object.keys`、展开运算符里；`configurable` 决定它能否被删除、能否改描述符（把它从数据改成访问器也算改）。

### 默认值：字面量与 `defineProperty` 不同

这是最容易踩的一处：

```console
$ node -e 'const o={a:1}; Object.defineProperty(o,"b",{value:2}); console.log(JSON.stringify(Object.getOwnPropertyDescriptor(o,"a"))); console.log(JSON.stringify(Object.getOwnPropertyDescriptor(o,"b")))'
{"value":1,"writable":true,"enumerable":true,"configurable":true}
{"value":2,"writable":false,"enumerable":false,"configurable":false}
```

**字面量创建的属性三个标志全为 `true`；`Object.defineProperty` 未指定的标志一律为 `false`。** 后者是规范规定的"最保守默认"——但结果是：用 `defineProperty` 加的属性默认**不可写、不可枚举、不可配置**，忘了写 `writable: true` 就会得到一个赋值静默失败的属性。

### 三个标志的效果

```console
$ node -e 'const o={}; Object.defineProperty(o,"x",{value:1,writable:false}); o.x=99; console.log(o.x)'
1
```

赋值没有报错也没有生效——**宽松模式下对不可写属性赋值静默失败**（严格模式抛 `TypeError`）。这类"什么都没发生"的行为是最难排查的。

```console
$ node -e 'const e={hidden:1,shown:2}; Object.defineProperty(e,"hidden",{enumerable:false}); console.log(Object.keys(e).join(","), e.hidden)'
shown 1
```

不可枚举的属性**仍然可读**，只是不出现在枚举中——它没有消失，只是藏起来了。`Array.prototype` 上的方法、`class` 里定义的方法都是不可枚举的，所以 `for...in` 遍历数组不会遍历出 `map`、`filter`。

不可配置的属性无法再改描述符：

```console
$ node -e 'const c={}; Object.defineProperty(c,"y",{value:1,configurable:false}); try{ Object.defineProperty(c,"y",{value:2}) }catch(e){ console.log(e.constructor.name) }'
TypeError
```

### 访问器：读与写可以执行代码

```console
$ node -e 'let _v=0; const g={get v(){return _v}, set v(x){_v=x*2}}; g.v=21; console.log(g.v)'
42
```

`get` / `set` 让"读取属性"变成"调用函数"。它是 `Vue` 响应式、`Object.defineProperty` 时代的模块导出（`module.exports` 的 getter 形态）等机制的底层工具。**访问器不存储值**——`_v` 是另一个绑定，由闭包持有（见 [02-闭包与作用域链](./02-闭包与作用域链.md)）。

### 整对象的三级封锁

| 操作 | 加属性 | 删属性 | 改值 | 改描述符 |
|---|---|---|---|---|
| `Object.preventExtensions(o)` | ✗ | ✓ | ✓ | ✓ |
| `Object.seal(o)` | ✗ | ✗ | ✓ | ✗（`configurable` 全置 false） |
| `Object.freeze(o)` | ✗ | ✗ | ✗ | ✗（`writable` 也置 false） |

```console
$ node -e 'const f=Object.freeze({a:1}), s=Object.seal({a:1}); console.log(Object.isExtensible(f), Object.isExtensible(s)); f.a=9; s.a=9; console.log(f.a, s.a)'
false false
1 9
```

三级都是**浅操作**：`freeze` 冻结的是对象自身的属性，嵌套对象不受影响。深冻结需要递归。

### `Proxy`：拦截对象的所有内部操作

`Proxy` 包住一个目标对象，用一组**陷阱**（trap）替换掉默认行为：

```console
$ node -e 'const t={a:1}, log=[]; const p=new Proxy(t,{ get(o,k,r){ log.push("get:"+String(k)); return Reflect.get(o,k,r) }, set(o,k,v,r){ log.push("set:"+String(k)); return Reflect.set(o,k,v,r) } }); p.a; p.b=2; console.log(log.join(" | "), JSON.stringify(t))'
get:a | set:b {"a":1,"b":2}
```

三个要点：

- **陷阱覆盖的是"内部方法"**，不是"属性"。`get` 陷阱拦截一切**取值**路径——直接读、方法调用前的取方法、展开、`JSON.stringify` 的读取，全都走它；而 `in` 运算符走的是另一个陷阱（`has`）。
- **`Proxy` 不复制、不改变目标**，它是转发层。上例中写入 `p.b` 最终落在 `t` 上。
- **`Proxy` 对性能不友好**：被代理的对象无法进入引擎的快速属性访问路径，热路径上不要用。这条账记在 [07-引擎与性能/01-引擎架构与 JIT](../07-引擎与性能/01-引擎架构与JIT.md)。

### `Reflect`：默认行为的函数形式

`Reflect` 的每个方法对应一个内部操作，且**就是默认行为**：

```console
$ node -e 'console.log(Reflect.get({x:1},"x"), Reflect.ownKeys({x:1}).join(","))'
1 x
```

它存在的意义是让陷阱能"转发到默认行为"——上例里 `Reflect.get(o, k, r)` 就是"按默认规则读"。没有 `Reflect` 时只能写 `o[k]`，而后者在 `get` 陷阱里可能递归触发代理（当 `o` 也是代理时）。**陷阱 + `Reflect` 是标准配对**。

### 弱引用：`WeakMap` 与 `WeakRef`

`WeakMap` 的键是**弱引用**——键对象不被引用时，整个条目可被回收，不阻止垃圾回收：

```console
$ node -e 'const priv=new WeakMap(); class C{ constructor(){ priv.set(this,{n:0}) } inc(){ return ++priv.get(this).n } } const c=new C(); c.inc(); console.log(c.inc(), Object.keys(c).length)'
2 0
```

上例用 `WeakMap` 实现了真正的私有状态，且不污染实例的可见属性——这是 [`#` 私有字段](../01-语言核心/05-对象与类.md) 之前的做法，至今仍用于需要**跨实例共享**或**给外部对象挂私有数据**的场景。

`WeakRef` 与 `FinalizationRegistry`（均已在 Node 24 可用）提供显式的弱引用与回收回调，但**回收时机不确定**，规范不保证何时触发——只能用于缓存这类"没了也能重建"的场景。

## 连接：三层的分工

| 需求 | 用什么 | 代价 |
|---|---|---|
| 属性只读 / 隐藏 | `defineProperty` 描述符 | 无 |
| 对象整体不可变 | `freeze` | 浅操作，深冻结要递归 |
| 拦截读写并加逻辑 | `Proxy` + `Reflect` | 失去引擎快速路径 |
| 调用/构造拦截 | `Proxy` 的 `apply` / `construct` | 同上 |
| 私有数据不污染实例 | `WeakMap` 或 `#` 字段 | `#` 更快，`WeakMap` 更灵活 |

## 边界

- **`defineProperty` 的默认值是陷阱**：忘写 `enumerable: true` 会让属性从 `JSON.stringify`、展开、`Object.keys` 里消失。
- **`Object.freeze` 是浅的**，且对 `Map` / `Set` 的**内容**无效（冻结的是对象自身属性，集合元素另存）。
- **`Proxy` 的 `this` 语义会变**：通过代理调用方法时 `this` 是代理而非目标，某些依赖 `this` 私有槽位的内建方法（如 `Map.prototype.get`）会因此报错。
- **不要在热路径上用 `Proxy`**：属性访问是最频繁的操作，代理会把每次访问变成函数调用。
