# 迭代协议与生成器

> 前置：[04-属性描述符与元编程](./04-属性描述符与元编程.md) · 后续：[03-标准库/01-字符串与数字](../03-标准库/01-字符串与数字.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

"可遍历"在 JavaScript 里不是继承来的能力，而是**约定两个方法**。这套约定称为**迭代协议**（iteration protocol），由两个互补的协议组成：

| 协议 | 要求对象提供 | 含义 |
|---|---|---|
| **可迭代协议** | `[Symbol.iterator]()` 方法，返回一个迭代器 | "我能被遍历" |
| **迭代器协议** | `next()` 方法，返回 `{ value, done }` | "我能一个一个地给" |

```text
可迭代对象 ──[Symbol.iterator]()──> 迭代器 ──next()──> { value, done }
   (range)                              (指针)
```

用**协议**而非基类，意味着任何对象都能变成可遍历的——不需要继承、不需要注册。这是 `for...of` 能同时遍历数组、`Map`、`Set`、字符串、生成器、以及你自己写的任何东西的原因（见 [01-语言核心/03-控制流程](../01-语言核心/03-控制流程.md) 那张循环表）。

`Symbol.iterator` 是 [01-语言核心/02-绑定与类型](../01-语言核心/02-绑定与类型.md) 里那个 `symbol` 类型的**主要用途**：符号作键名不会与字符串键冲突，因此"约定的方法名"可以安全地加进任何对象。

## 机制

### 协议的最小实现

```javascript
const range = {
  from: 1, to: 3,
  [Symbol.iterator]() {
    let n = this.from, to = this.to;
    return {
      next: () => n <= to ? { value: n++, done: false } : { value: undefined, done: true }
    };
  }
};
```

```console
$ node -e '…; console.log([...range].join(","))'
1,2,3
```

三个要点：

- **`[Symbol.iterator]()` 每次调用返回一个新迭代器**，迭代器自己持有游标 `n`。可迭代对象与迭代器是两个角色，前者"能造出"后者。
- **`done: true` 之后迭代器耗尽**，再调 `next()` 仍返回 `{ done: true }`——迭代器是**一次性**的。
- **`done: true` 时的 `value` 是"返回值"**，`for...of` 会丢弃它（见下文生成器）。

### 生成器：协议由语言代写

`function*` 定义的函数返回一个**生成器对象**，它自动同时满足两个协议：

```console
$ node -e 'function* gen(){ yield 1; yield 2; return "结束值" } const g=gen(); console.log(JSON.stringify(g.next()), JSON.stringify(g.next()), JSON.stringify(g.next()))'
{"value":1,"done":false} {"value":2,"done":false} {"value":"结束值","done":true}
```

```console
$ node -e 'function* gen(){} const g=gen(); console.log(typeof g.next, typeof g[Symbol.iterator])'
function function
```

**生成器对象既是迭代器（有 `next`）又是可迭代对象（有 `Symbol.iterator`）**——后者返回它自己。这个设计让生成器能被 `for...of` 直接消费，也能被展开、解构。

`yield` 与 `return` 的分工：`yield` 产出的值进入 `{ value, done: false }`；`return` 的值进入 `{ value, done: true }`，**但 `for...of` 不会把它交给你**——它只处理 `done: false` 的值。

`yield*` 把迭代**委托**给另一个可迭代对象：

```console
$ node -e 'function* i(){yield 1;yield 2} function* o(){yield 0;yield* i();yield 3} console.log([...o()].join(","))'
0,1,2,3
```

### 惰性：生成器是"按需生产"的

生成器的函数体**不执行到 `next()` 时才推进**。这带来一个别的结构给不了的能力：表示无限序列。

```console
$ node -e 'let p=0; function* inf(){ let i=0; while(true){ p++; yield i++ } } const r=[]; for(const x of inf()){ if(r.length>=3) break; r.push(x) } console.log(r.join(","), "实际生产:", p)'
0,1,2 实际生产: 4
```

取 3 个值，生成器推进了 **4** 次——`for...of` 在判断是否退出之前，已经把下一个值取了出来。这条细节说明惰性是**逐步推进**而非"恰好取到用完为止"；也说明生成器的内存占用与序列长度无关，只与当前状态有关。

### 消费迭代器的所有位置

一旦某对象可迭代，下面这些语法/API 全部可用（它们都只依赖同一个协议）：

| 用法 | 形态 |
|---|---|
| 循环 | `for (const x of it)` |
| 展开 | `[...it]`、`f(...it)` |
| 解构 | `const [a, b] = it` |
| 转换 | `Array.from(it)` |
| 批处理 | `Promise.all(it)`、`new Map(it)`、`new Set(it)` |
| 异步 | `for await (const x of asyncIt)`（机制见 [04-异步与并发/03](../04-异步与并发/03-async-await与异步模式.md)） |

这就是"实现一次协议、处处可用"的收益——**协议是接口，不是工具函数**。

### 异步迭代

把 `Symbol.iterator` 换成 `Symbol.asyncIterator`、`next()` 返回 Promise，就得到异步迭代器；`for await...of` 消费它。生成器也有异步版本（`async function*`）。这条链的完整展开见 [04-异步与并发/03-async/await 与异步模式](../04-异步与并发/03-async-await与异步模式.md) 与 [06-流](../04-异步与并发/06-流.md)。

## 连接：协议式接口与继承式接口

| | JavaScript 迭代协议 | Java `Iterator` / `Iterable` |
|---|---|---|
| 成为可遍历的条件 | 有 `[Symbol.iterator]()` 方法 | 实现 `Iterable` 接口 |
| 是否需声明 | 否，结构满足即可 | 是，编译期检查 |
| 内置类型 | 数组、字符串、`Map`、`Set`、生成器…… | 集合框架 |
| 自定义类型 | 加一个方法即可 | 声明 `implements` |
| 语言集成 | `for...of`、展开、解构直接可用 | 增强 `for` 循环 |

**结构式而非名义式**——这与 [08-TypeScript](../08-TypeScript/) 的类型系统同源：判断"是不是"看形状，不看声明。

## 边界

- **迭代器一次性**：耗尽后再遍历得到空结果，需要重新调用 `[Symbol.iterator]()`。
- **生成器函数体在第一次 `next()` 前不执行**：把副作用放在生成器开头会让它比预期晚发生。
- **`for...of` 丢弃 `return` 的值**：要拿到它得手动 `next()` 到最后。
- **对象默认不可迭代**：`for...of {}` 抛 `TypeError`——普通对象没有 `Symbol.iterator`。要遍历对象的键值，用 `Object.entries` / `Object.keys` 先转成数组。
