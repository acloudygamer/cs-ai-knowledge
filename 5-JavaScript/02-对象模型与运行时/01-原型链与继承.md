# 原型链与继承

> 前置：[01-语言核心/05-对象与类](../01-语言核心/05-对象与类.md) · 后续：[02-闭包与作用域链](./02-闭包与作用域链.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

每个对象除了自己的属性之外，还持有一个隐藏的引用，指向另一个对象（或 `null`）。这个引用称为**原型**（prototype），规范里记作内部槽 `[[Prototype]]`。访问一个属性时，引擎先在自己身上找，找不到就沿原型引用向上找，直到 `null`。

```text
leaf ──[[Prototype]]──> mid ──[[Prototype]]──> base ──[[Prototype]]──> Object.prototype ──> null
```

这条链就是**原型链**。它决定了 JavaScript 继承的本质：**继承是委托，不是复制**。子类不持有父类成员的副本，方法只在父类的原型对象上存一份，所有实例共享，运行时沿链去找。

这一条推出三个反直觉但必然的结论：

- **方法不在实例上**。`arr.map` 不在 `arr` 里，在 `Array.prototype` 上——所有数组共用同一个函数对象。
- **运行时改原型会影响已存在的实例**。因为查找发生在访问时，不在创建时。
- **`instanceof` 不是类型比较，是"是否在链上"**。

## 机制

### 读与写原型

| 操作 | 写法 | 说明 |
|---|---|---|
| 读 | `Object.getPrototypeOf(o)` | 标准方法 |
| 写 | `Object.setPrototypeOf(o, p)` | 会破坏已有优化，**创建后不要改原型** |
| 读/写（历史） | `o.__proto__` | 网页遗产，被规范收编为访问器属性；新代码不用 |
| 创建时指定 | `Object.create(p)` | 唯一推荐的"无类建对象"方式 |

`Object.create(null)` 造出的对象**没有原型**，因此连 `toString` 都没有：

```console
$ node -e 'const b = Object.create(null); console.log(Object.getPrototypeOf(b), typeof b.toString)'
null undefined
```

这类对象适合做纯字典——不会意外继承到 `toString`、`constructor` 这些键。

### 查找算法与遮蔽

查找沿链向上，**遇到第一个匹配即停**。子对象的同名属性会**遮蔽**（shadow）原型上的：

```console
$ node -e 'const base={who:"base"}; const mid=Object.create(base); mid.who="mid"; const leaf=Object.create(mid); console.log(leaf.who); delete mid.who; console.log(leaf.who)'
mid
base
```

删除 `mid.who` 后 `leaf.who` 落回 `base`——链本身没变，只是中间那一层不再拦截。注意**写操作不沿链**：`leaf.who = "x"` 是在 `leaf` 上新建属性，不会修改原型上的同名属性。

### `new` 做的三件事

```javascript
function F() { this.a = 1; }
const f = new F();
```

`new F()` 展开为三步：**建一个空对象、把它的原型设为 `F.prototype`、以它为 `this` 调用 `F`**。第一步的结果可直接验证：

```console
$ node -e 'function F(){this.a=1} const f=new F(); console.log(Object.getPrototypeOf(f) === F.prototype)'
true
```

还有一条容易忽略的规则：**构造器若返回对象，该对象取代 `this` 成为 `new` 的结果**；返回原始值则被忽略：

```console
$ node -e 'function G(){this.a=1; return {b:2}} function H(){this.a=1; return 42} console.log(JSON.stringify(new G()), JSON.stringify(new H()))'
{"b":2} {"a":1}
```

这就是为什么构造器不应该有"顺手 return 一个对象"的写法——它会静默丢弃整个 `this`。

### `class` 与原型链的对应

[01-语言核心/05-对象与类](../01-语言核心/05-对象与类.md) 已经说明 `class` 是语法封装。落到原型链上，它的映射是：

| `class` 写法 | 原型链上的落点 |
|---|---|
| `class B extends A {}` | `B.prototype.[[Prototype]] = A.prototype`（实例链） |
| 同上 | `B.[[Prototype]] = A`（构造器链，供 `static` 继承） |
| `m() {}` | 定义在 `B.prototype` 上，**不可枚举** |
| `x = 1` | 每个实例自己的属性，在构造器体之前初始化 |

```console
$ node -e 'class A{} class B extends A{} console.log(new B() instanceof A, Object.getPrototypeOf(B) === A)'
true true
```

`instanceof` 走的是**实例链**：判断 `A.prototype` 是否出现在对象的原型链上。所以它无法跨 realm 工作（各 realm 的 `A.prototype` 不是同一个对象），也不能用于原始值。

### 链的终点

所有普通对象的链最终汇入 `Object.prototype`，再指向 `null`。数组的链多一层：

```console
$ node -e 'let p=Object.getPrototypeOf([]); const c=[]; while(p){ c.push(p.constructor.name); p=Object.getPrototypeOf(p) } console.log(c.join(" -> "))'
Array -> Object
```

`Array.prototype` 上挂着 `map`、`filter` 等方法，`Object.prototype` 上挂着 `toString`、`hasOwnProperty`。**链长直接决定最坏查找代价**——深层继承（四五层以上）会拖慢属性访问，也更容易撞上遮蔽意外。

## 连接：委托式继承与复制式继承

| | JavaScript（委托） | Java / C++（复制/布局） |
|---|---|---|
| 成员存放 | 只在原型上存一份，实例共享 | 每个实例内含（或指向虚表） |
| 查找时机 | 运行时沿链查 | 编译期定偏移量 |
| 运行时可改 | 可（但破坏优化） | 不可 |
| 类型判断 | `instanceof` 查链 | 类型系统编译期保证 |
| 多继承 | 单链（用混入模拟） | C++ 可多继承，Java 单继承 + 接口 |

"运行时沿链查"是这套模型全部灵活性与全部性能代价的来源：引擎为了不每次都真去遍历链，会给每个对象的**形状**（隐藏类）建缓存，把"沿链找 `map`"编译成一次固定偏移的读取。一旦原型被修改，缓存失效，代码退回慢路径——这是 [07-引擎与性能/01-引擎架构与 JIT](../07-引擎与性能/01-引擎架构与JIT.md) 的内容。

## 边界

- **不要在创建后 `Object.setPrototypeOf`**：会让引擎已有的隐藏类与内联缓存全部作废。需要自定义原型就用 `Object.create` 或 `class`。
- **原型上的属性会被所有实例共享**：在原型上放可变对象（数组、对象）是共享状态 bug 的常见来源。
- **`for...in` 会枚举原型链上的可枚举属性**（见 [01-语言核心/03-控制流程](../01-语言核心/03-控制流程.md)）；判断"是不是自己的属性"用 `Object.hasOwn(o, k)`。
- **`__proto__` 不是普通属性**：它是 `Object.prototype` 上的访问器，能读写原型。把不可信输入的键名直接写进对象（如递归合并配置）时，`__proto__` 键会造成原型污染，见 [05-浏览器平台/05-浏览器安全模型](../05-浏览器平台/05-浏览器安全模型.md)。
