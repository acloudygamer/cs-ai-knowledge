# 闭包与作用域链

> 前置：[01-原型链与继承](./01-原型链与继承.md) · 后续：[03-this 与调用约定](./03-this与调用约定.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

上一篇讲的是**属性查找链**：写 `obj.foo`，引擎沿原型链找 `foo` 这个属性。本篇讲的是与之对偶的另一条链——**名字查找链**：写 `foo`（不带点），引擎沿作用域链找 `foo` 这个绑定。

```text
属性查找：对象 ──[[Prototype]]──> 对象 ──> … ──> null
名字查找：当前作用域 ──外层引用──> 外层作用域 ──> … ──> 全局作用域
```

两条链都是"从近到远、遇到即停"，但**建立时机相反**：

| | 原型链 | 作用域链 |
|---|---|---|
| 建立于 | 对象**创建**时 | 函数**定义**时 |
| 由什么决定 | `Object.create` / `class` / 字面量 | 源码里的**书写位置** |
| 可改吗 | 可以（`setPrototypeOf`，但破坏优化） | 不可以 |

"函数定义时确定"就是**词法作用域**（lexical scoping）：一个函数能看见哪些名字，看它在源码里写在哪里，与它被谁调用、在哪里调用都无关。**闭包**是这条规则的自然产物——函数记住了它定义时的作用域链，于是即使外层函数已经返回，链上的绑定依然可达。

## 机制

### 三种作用域

| 作用域 | 边界 | 谁产生 |
|---|---|---|
| 全局 | 整个程序 | 宿主创建 |
| 函数 | 函数体 | 每次**调用**新建一个 |
| 块 | `{}` | `let` / `const` / `class` 声明所在块 |

`var` 忽略块边界（绑定到最近函数），`let` / `const` 尊重它——这是 [01-语言核心/02-绑定与类型](../01-语言核心/02-绑定与类型.md) 那张表的机制面。

**函数作用域每次调用都是新的**，这是"同一函数多次调用得到互不干扰的状态"的原因：

```console
$ node -e 'function counter(){ let n=0; return ()=>++n } const c1=counter(), c2=counter(); c1(); c1(); console.log(c1(), c2())'
3 1
```

`c1` 与 `c2` 是两个独立的闭包，各自持有**自己那次调用**产生的 `n`。

### 闭包：函数 + 它记住的环境

```javascript
function make() {
  const box = { v: 0 };
  return { get: () => box.v, set: x => { box.v = x; } };
}
const m = make();
m.set(9);
m.get();   // 9
```

`make()` 已经返回，`box` 却仍然存在——因为返回的两个箭头函数的作用域链上挂着它。

**闭包捕获的是绑定，不是值的快照**（按引用捕获）：

```console
$ node -e 'function make(){ const box={v:0}; return {get:()=>box.v, set:x=>{box.v=x}} } const m=make(); m.set(9); console.log(m.get())'
9
```

若捕获的是快照，`m.set(9)` 之后 `get` 仍会读到 `0`。捕获绑定意味着**多个闭包共享同一份状态**——这正是"用闭包做私有状态"能工作的原因，也是下面那个经典陷阱的根源。

### 循环里的闭包：`var` 与 `let` 的分野

```console
$ node -e 'const a=[]; for(var i=0;i<3;i++) a.push(()=>i); console.log(a.map(f=>f()))'
3 3 3
$ node -e 'const a=[]; for(let j=0;j<3;j++) a.push(()=>j); console.log(a.map(f=>f()))'
0 1 2
```

`var` 版本全部输出 `3`：`i` 只有一个绑定（函数作用域），三个闭包捕获的是同一个绑定，循环结束时它是 `3`。

`let` 版本输出 `0 1 2`：**`for` 循环里的 `let` 每次迭代创建一个新绑定**，并把上一次的值复制进去。这不是"闭包捕获快照"，而是"每轮一个新绑定"——规范为循环头部声明单独规定了这条行为。

在 `let` 出现之前，绕过 `var` 陷阱靠 IIFE（立即调用函数表达式）手工造出新作用域：

```javascript
for (var i = 0; i < 3; i++) {
  (function (n) { callbacks.push(() => n); })(i);   // 形参 n 是新的绑定
}
```

`let` 让这段样板不再必要。**现代代码不需要 IIFE**。

### 闭包延长变量生命周期

被闭包引用的绑定无法回收，即使外层函数早已返回：

```console
$ node -e 'function outer(){ const big=new Array(1e6).fill(0); return ()=>big.length } const keep=outer(); console.log(keep())'
1000000
```

这里 `big` 是 800 万个元素的数组，`outer()` 返回后仍可达——因为 `keep` 的作用域链上挂着它。**这是内存泄漏最常见的一类来源**：不是忘记释放，而是无意中留下了引用。什么时候能回收、为什么引擎不能更聪明地只保留用到的变量，见 [07-引擎与性能/02-垃圾回收与内存](../07-引擎与性能/02-垃圾回收与内存.md)。

## 连接：闭包能做什么

闭包是 JavaScript 实现**私有状态**与**状态携带**的原生手段，不需要类的支持：

| 用途 | 形态 |
|---|---|
| 私有变量 | 外层函数的局部绑定，只由返回的函数读写 |
| 工厂 / 柯里化 | 外层函数接收部分参数，返回的函数接收其余 |
| 记忆化 | 闭包持有缓存对象，函数体内先查缓存 |
| 回调携带上下文 | 回调函数记住发起时的环境 |
| 模块模式 | 用 IIFE 造一个只暴露接口的作用域（`class` 与 [模块](../01-语言核心/06-模块.md) 之前的做法） |

对照静态类型语言：Java 的 lambda 只能捕获**事实上的 final** 局部变量（因为实现上捕获的是值），C++ 需要显式写捕获列表（`[&]` / `[=]`）。JavaScript 没有这些限制——**默认按引用捕获全部可见绑定**，代价是生命周期分析更难，泄漏更隐蔽。

## 边界

- **闭包捕获的是绑定而非值**，多个闭包会共享状态；需要独立副本就在外层多包一层函数。
- **不要为性能而回避闭包**：现代引擎只保留真正被引用的变量，闭包本身开销很小；真正的代价是**延长生命周期**导致的内存占用。
- **闭包里的 `this` 取决于外层函数**：箭头函数没有自己的 `this`，机制见下一篇。
- **模块顶层也是一种作用域**：ESM 的顶层绑定不挂到全局对象上（CommonJS 的会挂到 `module.exports`），这是 [01-语言核心/06-模块](../01-语言核心/06-模块.md) 那条"顶层 `this` 是 `undefined`"的同一件事。
