# 正则表达式

> 前置：[04-日期与时间](./04-日期与时间.md) · 后续：[06-JSON](./06-JSON.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

正则表达式描述的是**字符串上的模式**，引擎把它编译成一个自动机，在输入串上推进状态。它不是一个函数，而是一个**可复用的模式对象**——这一点决定了它最著名的行为：带 `g` 标志的正则**有自己的游标状态**，同一个正则对象在不同调用之间会"记住"上次匹配到哪。

正则对象有两种创建方式，两种匹配模式（全局 / 单次），多种调用方式（`test`、`exec`、`match`、`replace`…）。它们之间的组合规则是本节的主要内容——绝大多数正则 bug 不在模式写错，而在**选错了 API 组合**。

## 机制

### 两种创建方式

| 写法 | 时机 | 适用 |
|---|---|---|
| 字面量 `/\d+/g` | 解析时编译，**只编译一次** | 模式固定——绝大多数情况 |
| `new RegExp("\\d+", "g")` | 每次调用编译 | 模式来自变量或用户输入 |

字面量不共享状态的问题常被误解：`/\d+/g` 出现在循环里，每次求值得到的是**同一个正则对象**（字面量在解析时创建一次），所以它的 `lastIndex` 会跨迭代累积——这正是下面那个陷阱。

用变量构造时要**双写反斜杠**（`"\\d"` 而非 `"\d"`，因为字符串字面量先消耗一层转义）。

### 标志

| 标志 | 作用 |
|---|---|
| `g` | 全局：找所有匹配，**且使正则有状态** |
| `i` | 忽略大小写 |
| `m` | 多行：`^` / `$` 匹配每行的开头结尾 |
| `s` | dotAll：`.` 也匹配换行 |
| `u` | Unicode 模式：按**码点**而非码元处理（见 [01-字符串与数字](./01-字符串与数字.md)） |
| `v` | Unicode 集合模式（ES2024），`u` 的超集，支持集合运算 |
| `y` | 粘性：只从 `lastIndex` 处匹配，不向前搜索 |
| `d` | 记录匹配位置（`indices`） |

```console
$ node r.mjs
i: true | m: true | s: true | u: true | y: false
```

### `lastIndex`：带 `g` 的正则是有状态的

```console
$ node r.mjs
test: true lastIndex: 2
test: true lastIndex: 5
test: true lastIndex: 9
test: false lastIndex: 0 （归零，重新开始）
```

同一个正则对象连调四次 `test`，前三次为真、第四次为假——因为每次成功后 `lastIndex` 前移，最后一次找不到匹配，`lastIndex` 归零。**下一轮又从真开始。**

```console
$ node r.mjs
true 0 | true 0
```

不带 `g` 时无状态，每次都从头匹配。

这条规则造成的经典 bug 是：把带 `g` 的正则放在循环外复用，或作为模块级常量在多次调用间共享，匹配结果会莫名其妙地时真时假。**两种规避方式**：

- 只在确实要遍历全部匹配时用 `g`，且用 `matchAll` 这类不暴露状态的方法；
- 需要复用时就地重建（`new RegExp(re.source, re.flags)`）或去掉 `g`。

### 方法矩阵：谁看 `g`，谁不看

| 方法 | 无 `g` | 有 `g` |
|---|---|---|
| `re.test(s)` | 是否含匹配，**无状态** | 是否含匹配，**有状态**（推进 `lastIndex`） |
| `re.exec(s)` | 返回首个匹配及其分组 | 从 `lastIndex` 继续，逐个返回 |
| `s.match(re)` | 返回首个匹配及分组 | 返回**所有匹配的字符串数组**（丢失分组） |
| `s.matchAll(re)` | — | 返回所有匹配（含分组）的**迭代器**，不受 `lastIndex` 干扰 |
| `s.replace(re, r)` | 替换**首个**匹配 | 替换**全部**匹配 |
| `s.replaceAll(re, r)` | 要求带 `g`，否则抛错 | 替换全部 |
| `s.search(re)` | 返回首个匹配下标 | 同左（忽略 `g`） |
| `s.split(re)` | 按匹配切分 | 同左 |

```console
$ node r.mjs
match(g) = 1,22,333
matchAll = 1,22,333
```

`match` 带 `g` 时**只返回匹配到的字符串，拿不到捕获组**——需要分组信息就用 `matchAll`（返回迭代器，见 [02-对象模型与运行时/05-迭代协议与生成器](../02-对象模型与运行时/05-迭代协议与生成器.md)）。

### 捕获组

```console
$ node r.mjs
groups = {"year":"2026","month":"09"}
```

- **编号组** `(…)`：按左括号顺序编号，`$1`、`$2` 引用；
- **命名组** `(?<name>…)`：出现在结果的 `groups` 属性上，替换时用 `$<name>` 引用；
- **非捕获组** `(?:…)`：只分组不捕获，省一次记录开销；
- **反向引用** `\1`、`\k<name>`：匹配"与前面某个组相同的内容"。

```console
$ node r.mjs
$&: a[b]c | $1: a<1> | 命名: 2026年-09
```

替换串里的 `$&` 是"整个匹配"，`$1` 是第一个捕获组，`$<name>` 是命名组。字面量 `$` 要写 `$$`。

### 断言：不消耗字符的条件

```console
$ node r.mjs
前瞻 ?=: 1
后顾 ?<=: 1,2
```

- **前瞻** `(?=…)` / `(?!…)`：要求后面是 / 不是某模式，但不计入匹配；
- **后顾** `(?<=…)` / `(?<!…)`：要求前面是 / 不是某模式。

上例中 `\d(?=[a-z])` 在 `"a1b2"` 上只匹配到 `1`——`2` 后面没有字母。断言是"零宽"的：匹配位置前进，但断言部分不进入结果。

### `RegExp.escape`：安全构造动态正则

```console
$ node r.mjs
function | \x61\.b\*c
```

把用户输入拼进正则时，输入里的 `.`、`*`、`(` 会被当成元字符——这是注入类漏洞的一种。`RegExp.escape()` 转义所有元字符，是 **ES2025 的十项特性之一**，Node 24 已支持。**动态构造正则必须经过它**。

### 性能：灾难性回溯

正则引擎按回溯匹配，嵌套量词会引发指数级尝试。`(a+)+$` 在 `"aaaaaaaaaaaaaaaaaaaaaaaaaaaaX"` 上会尝试 $2^{29}$ 量级的分支组合——**输入越长越慢，不是线性变慢**。

规避手段：

- 避免嵌套量词（`(a+)+`），改用不重叠的写法（`a+`）；
- 用更精确的字符类（`[^"]*` 优于 `.*`）；
- 对超长输入或不可信输入，考虑不用正则（手写解析器），或限制输入长度。

## 连接：按需求选方法

| 需求 | 方法 |
|---|---|
| 是否存在 | `re.test(s)`（无 `g`） |
| 首个匹配的详细信息 | `re.exec(s)` 或 `s.match(re)`（无 `g`） |
| 所有匹配（不需要分组） | `s.match(/\w+/g)` |
| 所有匹配 + 分组 | `s.matchAll(re)` |
| 替换全部 | `s.replaceAll(re, r)`（需 `g`） |
| 按模式切分 | `s.split(re)` |
| 安全拼接用户输入 | `RegExp.escape(input)` |

## 边界

- **带 `g` 的正则有状态**：跨调用复用会得到不一致的结果。
- **`match` 带 `g` 时丢失分组**：要分组用 `matchAll`。
- **`replace` 不带 `g` 只替换第一个**：全替换用 `replaceAll` 或加 `g`。
- **不加 `u` 时按 UTF-16 码元匹配**：`.` 会把一个 emoji 拆成两个字符，正则的字符类也不认码点。
- **回溯是指数级的**：不可信输入上的复杂正则可被用来做拒绝服务（ReDoS）——病态输入让回溯量爆炸，单线程的事件循环被独占（见 [04-异步与并发/01-事件循环与任务队列](../04-异步与并发/01-事件循环与任务队列.md)）。
