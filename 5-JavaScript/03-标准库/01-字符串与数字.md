# 字符串与数字

> 前置：[02-对象模型与运行时/05-迭代协议与生成器](../02-对象模型与运行时/05-迭代协议与生成器.md) · 后续：[02-数组](./02-数组.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

**字符串**是不可变的 UTF-16 **码元**序列。两个限定词都重要：不可变意味着所有"修改"方法都返回新串；"码元"意味着 `.length` 数的是 16 位单元，不是人眼看到的字符。

**数字**只有一种类型 `number`，即 IEEE 754 双精度浮点（64 位）；整数超出 $2^{53}$ 后需要 `bigint`。这不是"缺少整型"的疏忽——见 [01-语言核心/02-绑定与类型](../01-语言核心/02-绑定与类型.md) 里那条精度悬崖。

原始类型却能用方法（`"abc".toUpperCase()`），机制是引擎在访问属性时**临时装箱**成 `String` 对象再调用，调用完丢弃。这个机制与原型链同在 [02-对象模型与运行时/01-原型链与继承](../02-对象模型与运行时/01-原型链与继承.md)。

## 机制

### 不可变性

```console
$ node t.mjs
TypeError: Cannot assign to read only property '0' of string 'abc'
s 仍为 abc
```

（ESM 恒为严格模式，赋值抛 `TypeError`；宽松模式下静默失败。）字符串的每个"修改"方法都返回**新串**，原串不变：`replace`、`replaceAll`、`slice`、`toUpperCase`、`trim` 全部如此。这意味着链式调用会创建多个中间串——在热路径上拼接大量字符串时，用数组 `join` 或模板字符串减少中间产物。

### 码元与码点

```console
$ node t.mjs
length = 2 | [...emoji].length = 1 | codePointAt(0) = 1f600
```

`"😀"` 的 `.length` 是 **2**——它在 UTF-16 里占两个码元（一个代理对）。`[...emoji].length` 是 **1**，因为展开运算符走**迭代协议**，而字符串的迭代器按**码点**切分（见 [02-对象模型与运行时/05-迭代协议与生成器](../02-对象模型与运行时/05-迭代协议与生成器.md)）。

推论：凡是按 `.length` 或下标处理字符串的地方，遇到 emoji、生僻汉字都会出错。按字符切分用 `[...str]` 或 `Array.from(str)`。

### 截取三兄弟的差异

| 方法 | 负值参数 | 说明 |
|---|---|---|
| `slice(start, end)` | 从末尾倒数 | 推荐；`start > end` 返回空串 |
| `substring(start, end)` | **负数当作 0** | 参数顺序会自动交换 |
| `substr(start, len)` | 从末尾倒数 | **已废弃**，第二个参数是长度不是下标 |

```console
$ node t.mjs
slice(-2) = ef | substring(-2) = abcdef
```

`slice(-2)` 取最后两个字符；`substring(-2)` 把 `-2` 当作 `0`，于是返回整个串。**新代码统一用 `slice`**，另两个只在读旧代码时认识。

`at(i)` 支持负索引，是下标访问的补充：

```console
$ node t.mjs
at(-1) = c | [-1] = undefined
```

### 常用方法速查

| 目的 | 方法 |
|---|---|
| 查找 | `includes`、`startsWith`、`endsWith`、`indexOf`、`search` |
| 截取 | `slice`、`at`、`split` |
| 变换 | `replace`、`replaceAll`、`toUpperCase`、`toLowerCase`、`trim`、`normalize` |
| 补齐 | `padStart`、`padEnd`、`repeat` |
| 码点 | `codePointAt`、`String.fromCodePoint` |

`replace` 只替换第一个匹配，要全替换用 `replaceAll`（ES2021）或带 `g` 标志的正则（见 [05-正则表达式](./05-正则表达式.md)）：

```console
$ node t.mjs
a-b-c -> a+b+c | padStart -> 005
```

### 数字格式化与它的精度陷阱

```console
$ node t.mjs
(0.1+0.2).toFixed(2) = 0.30
(1.005).toFixed(2) = 1.00
(1.45).toFixed(1) = 1.4
```

`toFixed` 按**二进制实际存储值**四舍五入，不是按你写下的十进制字面量。`1.005` 在二进制里略小于 1.005，因此 `toFixed(2)` 得到 `1.00` 而非 `1.01`。**涉及金额时不要用浮点**：用整数（以分为单位）或 `bigint`。

| 方法 | 作用 |
|---|---|
| `toFixed(n)` | 保留 n 位小数，返回**字符串** |
| `toPrecision(n)` | 保留 n 位有效数字 |
| `toString(radix)` | 转成指定进制 |
| `Number.isInteger` / `isFinite` / `isNaN` | 判定（**优于**全局 `isNaN`，后者会先做类型转换） |
| `Number.parseInt` / `parseFloat` | 解析（**优于**全局版本，语义一致但不会隐式全局化） |

### 排序默认是字典序

```console
$ node t.mjs
[10,9,1].sort() = 1,10,9 | 比较器 = 1,9,10
```

`sort()` **默认把元素转成字符串按码元比较**，于是 `10 < 9`。数字数组必须传比较器 `(a, b) => a - b`。字符串比较同理按码元，不是按语言习惯：

```console
$ node t.mjs
'Z' < 'a' ? true | localeCompare(en) = 1
```

大写字母的码元小于小写字母，所以 `"Z" < "a"`。要按人类语言排序用 `localeCompare`（见 [07-Intl 国际化](./07-Intl国际化.md)）。`sort` 的完整行为（稳定性、原地修改）见 [02-数组](./02-数组.md)。

### `bigint`

字面量加 `n` 后缀，或用 `BigInt()` 转换。任意精度，但**不能与 `number` 混算**（会抛 `TypeError`），也没有 `Math` 方法：

```console
$ node t.mjs
1000000 bigint 18446744073709551616
```

`1_000_000` 是数字分隔符（ES2021），纯粹的可读性语法，不影响值。`2n ** 64n` 精确得到 18446744073709551616——同样的算式用 `number` 会丢精度。

## 连接：与静态类型语言对照

| | JavaScript | Java |
|---|---|---|
| 字符串编码 | UTF-16 码元序列 | UTF-16（`String`），码点 API 独立 |
| 可变性 | 不可变 | 不可变 |
| 数值类型 | `number`（float64）+ `bigint` | `int`/`long`/`float`/`double`/`BigDecimal` |
| 整数溢出 | 静默丢精度 | 静默回绕（`int`）或抛错（`Math.addExact`） |
| 格式化 | `toFixed` / `Intl.NumberFormat` | `String.format` / `DecimalFormat` |
| 字符串拼接 | `+` 与模板字符串 | `+` 与 `StringBuilder` |

## 边界

- **`.length` 不是字符数**：按码元计数，emoji 与部分汉字会被算作 2。
- **`sort()` 默认字典序**：数字数组不传比较器必然出错。
- **`toFixed` 按实际存储值舍入**：涉及金额改用整数分或 `bigint`。
- **字符串方法返回新串**：大量拼接会产生大量中间对象；循环内拼接用数组累积再 `join`。
- **`Intl.NumberFormat` 优于手写格式化**：货币、千分位、百分比都有现成实现，见 [07-Intl 国际化](./07-Intl国际化.md)。
