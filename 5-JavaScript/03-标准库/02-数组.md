# 数组

> 前置：[01-字符串与数字](./01-字符串与数字.md) · 后续：[03-Object 与 Map/Set](./03-Object与Map-Set.md)

> **版本基准**：Node 24 stable / Node 26 latest。本篇示例实测环境：Node v24.13.1（V8 13.6），Windows x64。

## 本质

数组是**特殊的对象**：索引是字符串键（`"0"`、`"1"`），另有一个自动维护的 `length` 属性。它不是连续内存块，而是引擎会特殊优化的对象——当索引是密集的连续整数时，V8 用紧凑的存储后端，让它接近 C 数组的性能；一旦变成稀疏或混入非索引键，就退化为普通对象（见 [07-引擎与性能/01-引擎架构与 JIT](../07-引擎与性能/01-引擎架构与JIT.md)）。

这个双重身份解释了数组的两个常见困惑：为什么 `typeof [] === "object"`，以及为什么稀疏数组的方法行为与"空值"不同（见下文）。

## 机制

### 原地修改 vs 返回新数组

这是用数组时最容易出错的一条分界线：

| 原地修改（改原数组） | 返回新数组（原数组不变） |
|---|---|
| `push`、`pop`、`shift`、`unshift` | `slice`、`concat`、`flat`、`flatMap` |
| `splice` | `toSpliced`、`with` |
| `sort`、`reverse` | `toSorted`、`toReversed` |
| `fill`、`copyWithin` | `map`、`filter`、`reduce` |

```console
$ node a.mjs
sort 原地: true | src = 1,2,3
toSorted 不改原: 1,2,3 | orig = 3,1,2
```

`sort` 直接改写原数组并返回它（所以 `src === sorted` 为 `true`）；`toSorted` 返回新数组，原数组保持 `3,1,2`。ES2023 补齐了四个"不可变版本"：

| 可变 | 不可变替代 | 作用 |
|---|---|---|
| `sort` | `toSorted` | 排序 |
| `reverse` | `toReversed` | 反转 |
| `splice` | `toSpliced` | 增删 |
| `a[i] = v` | `a.with(i, v)` | 替换单个元素 |

React 等要求"状态不可变"的框架里，这组方法让代码不必先 `[...arr]` 再改。

### 增删与截取

```console
$ node a.mjs
splice 移除: 2,3 | 剩余: 1,4
```

`splice(start, deleteCount, ...items)` 同时承担删除、插入、替换——**返回值是被删除的元素**，不是剩余数组。`slice(start, end)` 只读取，返回副本。两者名字相近、语义相反，是常见笔误来源。

`push` / `pop` 在尾部操作，`shift` / `unshift` 在头部操作。后者需要移动所有元素，在长数组上是 $O(n)$——需要队列语义时考虑用索引游标或 [03-Object 与 Map/Set](./03-Object与Map-Set.md) 里的 `Map`。

### 遍历与聚合

| 方法 | 返回 | 短路 |
|---|---|---|
| `forEach` | `undefined` | 否（不能用 `break`） |
| `map` | 等长新数组 | 否 |
| `filter` | 长度 ≤ 原数组的新数组 | 否 |
| `reduce` | 累积值（任意类型） | 否 |
| `some` | `boolean` | **是**（遇到真值即停） |
| `every` | `boolean` | **是**（遇到假值即停） |
| `find` / `findLast` | 元素或 `undefined` | **是** |
| `findIndex` / `findLastIndex` | 下标或 `-1` | **是** |

`forEach` 无法提前退出——需要 `break` 时用 `for...of`（见 [01-语言核心/03-控制流程](../01-语言核心/03-控制流程.md)）或 `some`。

`reduce` 在**空数组且无初值**时抛错：

```console
$ node a.mjs
TypeError: Reduce of empty array with no initial value
```

传初值是更稳的写法：`arr.reduce(f, 0)`。

### 查找：`includes` 与 `indexOf` 的差异

```console
$ node a.mjs
[NaN].includes(NaN) = true | [NaN].indexOf(NaN) = -1
```

`indexOf` 用 `===` 比较，因此找不到 `NaN`（`NaN !== NaN`，见 [01-语言核心/02-绑定与类型](../01-语言核心/02-绑定与类型.md)）；`includes` 用 `SameValueZero`，能找到。**判断"是否包含"用 `includes`**，需要下标才用 `indexOf`。

### 展平

```console
$ node a.mjs
[1,[2,[3]]].flat(2) = 1,2,3 | flat(Infinity) = 1,2,3
flatMap: 1,10,2,20
```

`flat(depth)` 按层展平，默认 1 层；`flatMap(f)` 等价于 `map(f).flat(1)`，但只遍历一次——在"每个元素映射成 0 个或多个元素"的场景（如过滤 + 映射合并）比 `map` + `filter` 高效。

### 稀疏数组：洞不是 `undefined`

```console
$ node a.mjs
length = 3 | forEach 跳过洞: 0,2
```

`[1,,3]` 长度为 3，但下标 1 处**没有属性**。遍历方法会**跳过洞**（`forEach` 只在 0、2 上调用回调），而 `map` **保留洞的位置**。这与"下标 1 处存了 `undefined`"是两回事——后者回调会被调用。稀疏数组会让引擎退回慢速存储，实践中应避免。

### 构造数组

| 写法 | 结果 |
|---|---|
| `[1, 2, 3]` | 字面量，推荐 |
| `Array.from(iterable, mapFn?)` | 从可迭代对象或类数组转换，可带映射 |
| `Array.of(3)` | `[3]`（对比 `new Array(3)` 得到三个洞） |
| `Array.from({length: 3}, (_, i) => i * 2)` | 生成序列，`[0, 2, 4]` |

```console
$ node a.mjs
Array.from({length:3}, (_,i)=>i*2) = 0,2,4
a,b,c | Array.of(3) = 3
```

**避免 `new Array(n)`**：单参数时它创建的是长度为 n 的**稀疏数组**，不是 `[n]`。用 `Array.of` 或字面量。

## 连接：方法速查

| 目的 | 不可变 | 可变 |
|---|---|---|
| 尾部增删 | `concat` | `push` / `pop` |
| 头部增删 | `slice` 组合 | `unshift` / `shift` |
| 任意位置增删 | `toSpliced` | `splice` |
| 排序 | `toSorted` | `sort` |
| 反转 | `toReversed` | `reverse` |
| 替换元素 | `with` | `a[i] = v` |
| 变换 | `map` / `filter` / `flatMap` | — |

## 边界

- **`sort` 默认字典序且原地修改**：数字数组必须传 `(a, b) => a - b`。
- **`forEach` 不能中断**：需要提前退出用 `for...of` 或 `some`。
- **`splice` 返回被删元素**：不是剩余数组。
- **稀疏数组拖慢引擎**：避免 `new Array(n)` 与 `delete arr[i]`。
- **数组不能用作查找表**：按值查找是 $O(n)$，键值映射用 `Map`（见下一篇）。
