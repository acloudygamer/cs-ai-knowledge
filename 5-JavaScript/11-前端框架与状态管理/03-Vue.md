# Vue

> 前置：[02-React](./02-React.md) · 后续：[04-状态管理](./04-状态管理.md)

> **版本基准**：Vue 3.5。
> **实测范围说明**：**本篇无本机实测**——组件渲染依赖浏览器 DOM 环境。响应式的底层机制（`Proxy` 拦截读写、依赖收集）已在 [01-框架原理](./01-框架原理.md) 本机实测，本篇引用该结果。

## 本质

Vue 走的是**响应式**路线（见 [01-框架原理](./01-框架原理.md) 的两条路线对照）：用 `Proxy` 拦截状态的读写，读取时收集依赖、写入时通知更新。

```text
状态读取 ──记录──▶ 谁在用这个值
状态写入 ──通知──▶ 用到它的地方重新计算/渲染
```

与 React 的差别可以概括成一句：**React 重新算出整棵树再比对；Vue 直接知道哪块要更新**。

这条差异的来源是 Vue 使用**模板**而非 JSX：模板是受限的、可静态分析的，编译器能在构建期就确定"这段渲染依赖哪些状态"。React 的 JSX 是完整的 JavaScript 表达式，只能等运行时执行才知道读了什么。

## 机制

### 响应式的三个 API

| API | 用于 | 访问方式 |
|---|---|---|
| `ref(v)` | 任意值（含原始类型） | 脚本里 `x.value`，模板里自动解包 |
| `reactive(obj)` | 对象/数组 | 直接访问属性 |
| `computed(fn)` | 派生值 | `c.value`（有缓存） |

`ref` 需要一个 `.value` 是因为**原始类型无法被 `Proxy` 代理**——`Proxy` 只能包对象。所以 `ref` 把值装进一个带 `value` 属性的对象再代理它。模板里自动解包是为了书写方便。

`computed` 的**缓存**是它的核心价值：依赖不变时直接返回上次结果，不重新计算。这与普通函数每次调用都执行不同——把昂贵计算放进 `computed` 是 Vue 里的标准优化。

### 组合式 API 与选项式 API

| | 选项式（Options） | 组合式（Composition） |
|---|---|---|
| 组织方式 | 按**选项**分组（`data` / `methods` / `computed`） | 按**逻辑关注点**分组 |
| 逻辑复用 | 混入（mixin），来源不清晰 | 组合式函数，来源明确 |
| 类型推断 | 较弱 | 与 TypeScript 配合好 |
| 心智模型 | 与组件实例绑定（`this`） | 与函数作用域绑定 |

**组合式 API 解决了"同一功能的代码被拆散在多个选项里"的问题**：一个功能的 `data`、`methods`、`watch` 分散在三处，读代码要在文件里跳。组合式把同一个关注点的代码写在一起。

代价是**必须理解响应式的作用域规则**——见下文"响应式丢失"。

### 模板编译

模板在构建期被编译成渲染函数。编译器能做 JSX 做不到的静态分析：

| 优化 | 内容 |
|---|---|
| **静态提升** | 不含动态绑定的节点只创建一次，后续渲染复用 |
| **补丁标记** | 编译期标出哪些节点含动态内容，运行时只检查这些 |
| **静态节点外置** | 整个静态子树跳过比对 |

这些是 Vue 相对于通用虚拟 DOM 的性能来源：**把"哪里可能变"的判断从运行时提前到编译期**。

### `watch` 与 `watchEffect`

| | `watch` | `watchEffect` |
|---|---|---|
| 依赖 | **显式指定** | 自动收集 |
| 执行时机 | 依赖变化时 | 立即执行一次，之后依赖变化时执行 |
| 能拿到旧值 | 是 | 否 |

`watchEffect` 的自动收集依赖的是"**同步执行期间**读取到的状态"——这与 [01-框架原理](./01-框架原理.md) 里实测的惰性收集是同一机制。所以在 `watchEffect` 里 `await` 之后读取的状态**收集不到**：

```javascript
watchEffect(async () => {
  const id = props.id;        // 同步读取，能收集到
  const data = await fetch(id);
  console.log(state.name);    // 异步之后读取，收集不到
});
```

这条限制是响应式路线的固有代价。需要监听异步中才确定的状态时，用 `watch` 显式指定。

### 响应式丢失

把 `reactive` 对象的属性解构出来，会**失去响应性**：

```javascript
const state = reactive({ count: 0 });
let { count } = state;        // count 是一个普通数字，不是响应式的
```

因为解构复制的是**当时的值**，而不是"指向状态的引用"。`ref` 不会丢失（它是对象，解构拿到的是同一个 ref 对象）。需要解构时用 `toRefs` / `toRef` 转换。

同类问题还有：把 `reactive` 对象整体传给函数没问题（传的是代理对象），但把它的属性传出去就会失去响应。

### 生命周期

| 组合式 API | 时机 |
|---|---|
| `onBeforeMount` / `onMounted` | 挂载前 / 后（DOM 已可用） |
| `onBeforeUpdate` / `onUpdated` | 更新前 / 后 |
| `onBeforeUnmount` / `onUnmounted` | 卸载前 / 后 |

`onUnmounted` 是**清理副作用的地方**：取消订阅、清除定时器、中止请求。与 React 的 `useEffect` 清理函数职责相同（见 [02-React](./02-React.md)）。

### 单文件组件

`.vue` 文件把模板、脚本、样式放在一起，由构建工具编译。`<style scoped>` 通过给元素加唯一属性实现样式隔离——**这是构建期的重写，不是运行时的 Shadow DOM**。

## 连接：Vue 与 React

| | Vue | React |
|---|---|---|
| 更新机制 | 响应式（精确追踪） | 虚拟 DOM（比对整棵树） |
| 描述界面 | 模板（受限，可静态分析） | JSX（完整表达式） |
| 状态更新 | 直接改（响应式对象） | 产生新值（不可变） |
| 组件状态 | `ref` / `reactive` | `useState` |
| 派生值 | `computed`（有缓存） | 渲染时直接算 + `useMemo` |
| 副作用 | `watch` / `watchEffect` / 生命周期 | `useEffect` |
| 学习曲线 | 模板语法上手快 | 需要理解闭包与快照 |
| 类型支持 | 组合式 API 下良好 | 原生契合 |

**选择依据是团队与生态，不是性能**：两者在常见场景下的差异远小于代码组织方式的差异。

## 边界

- **解构 `reactive` 会丢失响应性**：用 `toRefs`。
- **`watchEffect` 收集不到异步中的依赖**：用 `watch` 显式指定。
- **`ref` 在脚本里要 `.value`**：模板里自动解包，容易混淆。
- **`computed` 应该是纯的**：不要在里头发请求或改状态。
- **`scoped` 样式是编译期重写**：不隔离子组件根元素，也不阻止全局样式渗透。
- **模板的静态分析有边界**：`v-html` 注入的内容不参与编译优化，且有 XSS 风险（见 [05-浏览器平台/05-浏览器安全模型](../05-浏览器平台/05-浏览器安全模型.md)）。
