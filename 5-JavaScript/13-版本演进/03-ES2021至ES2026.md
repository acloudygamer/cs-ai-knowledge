# ES2021 至 ES2026

> 前置：[02-ES2015 至 ES2020](./02-ES2015至ES2020.md) · 后续：无（全库终点）

> **版本基准**：Node 24 stable（V8 13.6）/ Node 26 latest（V8 14.6）。
> **本篇的支持矩阵为本机实测**：Node v24.13.1（V8 13.6.233.17-node.40），Windows x64，特性探测脚本逐项运行。ES2025 与 ES2026 的特性清单取自 TC39 finished-proposals 表的 `Expected Publication Year` 列。

## 本质

ES2021 之后的版本都以**补完既有抽象**为主，不再出现 ES2015 那样的大跃进：

| 时期 | 特征 |
|---|---|
| ES2015 | 补齐十年欠账，引入模块、类、Promise、迭代协议 |
| ES2021–2026 | 在既有抽象上补细节：数组的不可变操作、集合的运算方法、迭代器的辅助方法 |

**变化的性质也变了**：早年的特性解决"语言缺某个能力"（没有模块、没有 Promise），近年的特性解决"这个能力用起来不够顺手"（数组排序要复制、迭代器没有 `map`）。前者会改变编程方式，后者只是减少样板代码。

## 机制

### ES2021：小补丁与逻辑赋值

| 特性 | 作用 |
|---|---|
| 逻辑赋值 `??=` / `\|\|=` / `&&=` | 复合赋值形式（见 [01-语言核心/03](../01-语言核心/03-控制流程.md)） |
| `String.prototype.replaceAll` | 全替换，此前要用带 `g` 的正则 |
| 数字分隔符 `1_000_000` | 纯可读性 |
| `Promise.any` | 第一个**兑现**的；全拒绝才拒绝（见 [04-异步与并发/02](../04-异步与并发/02-回调到Promise.md)） |
| `WeakRef` / `FinalizationRegistry` | 显式弱引用与回收回调 |

### ES2022：类的补完与顶层 await

| 特性 | 作用 |
|---|---|
| **类字段** `x = 1` | 不必再在构造器里逐个赋值 |
| **私有字段** `#x` | 真正的私有（见 [01-语言核心/05](../01-语言核心/05-对象与类.md)） |
| **静态块** `static {}` | 类的静态初始化逻辑 |
| **顶层 `await`** | 模块顶层直接 await（仅 ESM） |
| `Object.hasOwn` | 替代 `hasOwnProperty`（见 [02-对象模型与运行时/01](../02-对象模型与运行时/01-原型链与继承.md)） |
| `Error.cause` | 错误链（见 [01-语言核心/07](../01-语言核心/07-错误处理.md)） |
| `Array.prototype.at` | 支持负索引 |

### ES2023：数组的不可变方法

这一版的核心是**给可变方法配上不可变版本**（见 [03-标准库/02-数组](../03-标准库/02-数组.md)）：

| 可变 | 不可变替代 |
|---|---|
| `sort` | `toSorted` |
| `reverse` | `toReversed` |
| `splice` | `toSpliced` |
| `a[i] = v` | `with(i, v)` |

在要求状态不可变的框架里（见 [11-前端框架与状态管理/02](../11-前端框架与状态管理/02-React.md)），这组方法省掉了"先复制再改"。另有 `findLast` / `findLastIndex`。

### ES2024：分组与正则的集合运算

| 特性 | 作用 |
|---|---|
| `Object.groupBy` / `Map.groupBy` | 按返回值分组，替代手写 `reduce` |
| `Promise.withResolvers` | 把 `resolve` / `reject` 暴露到外部 |
| 正则 `v` 标志 | `u` 的超集，支持**字符类集合运算**（`&&`、`--`） |
| `ArrayBuffer.prototype.resize` / `transfer` | 可调整大小的缓冲区 |
| `String.prototype.isWellFormed` / `toWellFormed` | 检测/修复孤立代理项 |

`v` 标志的集合运算可测：

```console
$ node vflag.mjs
  v 集合运算 &&                  可用
  [\w&&[^_]] 匹配 'a': true | 匹配 '_': false
  \p{L} 匹配 '中': true
```

### ES2025：十项特性（TC39 已定稿）

| 特性 | 作用 |
|---|---|
| **Iterator helpers** | 迭代器上的 `map` / `filter` / `take` 等，**惰性求值** |
| **Set 方法** | `union` / `intersection` / `difference` / `isSubsetOf` 等七个 |
| `Promise.try` | 把可能同步抛错的函数纳入 Promise 链 |
| `RegExp.escape` | 安全转义用户输入构造正则 |
| `Float16Array` | 16 位浮点类型化数组 |
| Import attributes | `import x from "./d.json" with { type: "json" }` |
| JSON modules | 直接导入 JSON |
| RegExp 内联标志 | `(?i:…)` 局部生效的标志 |
| 重复命名捕获组 | 不同分支可复用组名 |
| 可重声明 `eval` 引入的 `var` | 规范一致性修正 |

### ES2026：七项特性

| 特性 | 作用 |
|---|---|
| **Upsert**（`Map.prototype.getOrInsert`） | 一次完成"取或插入" |
| `JSON.parse` 源文本访问 | reviver 能拿到原始文本，大整数不丢精度 |
| **Iterator Sequencing**（`Iterator.concat`） | 惰性拼接多个迭代器 |
| `Uint8Array` 的 Base64 / Hex | 原生编解码，不再用 `btoa` 拼凑 |
| `Math.sumPrecise` | 无累积误差求和 |
| `Error.isError` | 跨 realm 可靠的错误判断 |
| `Array.fromAsync` | 从异步可迭代对象建数组 |

### 支持矩阵：本机实测

**Node v24.13.1（V8 13.6.233.17-node.40）**：

| 版本 | 支持情况 |
|---|---|
| ES2021 | **全部** |
| ES2022 | **全部**（含类字段、私有字段、静态块、顶层 `await`） |
| ES2023 | **全部**（含四个不可变数组方法） |
| ES2024 | **全部**（含 `v` 标志、`groupBy`、`withResolvers`） |
| ES2025 | **全部**（含 import attributes、`RegExp.escape`、`Float16Array`） |
| ES2026 | **部分**：有 `Error.isError`、`Array.fromAsync`、`JSON.parse` 源文本；**缺** `Map.getOrInsert`、`Iterator.concat`、`Math.sumPrecise`；`Uint8Array.toBase64` 需 `--js-base-64` |

```console
$ node -e 'console.log(typeof Math.sumPrecise, typeof Error.isError)'
undefined function
```

**这张表说明了两件事**：

- **ES2025 在 Node 24 已完全落地**——而它才刚在 2025 年 6 月定稿。引擎的跟进速度是很快的。
- **ES2026 在 Node 24 只落地了一部分**，其中 `Math.sumPrecise` 是**规范已批准但引擎未实现**的实例，截至 Node 26（V8 14.6）仍未实现。

### 引擎领先规范：ES2027 的提案已经可用

```console
$ node --js-base-64 -e 'console.log(typeof Uint8Array.prototype.toBase64)'
function
$ node --harmony-temporal -e 'console.log(typeof Temporal, typeof Temporal.PlainDate)'
object function
$ node -e 'class R{ [Symbol.dispose](){} } using r = new R(); console.log("using 可用")'
using 可用
```

| 特性 | 规范归属 | Node 24 状态 |
|---|---|---|
| `Temporal` | ES2027 | 需 `--harmony-temporal`；**Node 26 默认开启** |
| `using` / `await using` | ES2027 | **已可用** |
| `Atomics.pause` | ES2027 | 缺 |
| `Uint8Array` Base64/Hex | ES2026 | 需 `--js-base-64` |

**"已可用但未定稿"与"已定稿但不可用"同时存在**——这正是 [01-演进脉络与 TC39 流程](./01-演进脉络与TC39流程.md) 那条结论的完整形态：**规范状态与引擎状态是两条独立的时间线**。

## 连接：支持矩阵的使用方式

| 判断 | 依据 |
|---|---|
| 语法能不能写 | 引擎支持矩阵（本篇） |
| 目标环境是否支持 | 打包工具的 `target` + 运行时特性检测 |
| 是否需要转译 | 目标环境的最低版本（见 [09-工程化/03](../09-工程化/03-打包与转译.md)） |
| 特性是否稳定 | TC39 阶段（见 [01](./01-演进脉络与TC39流程.md)） |

## 边界

- **规范批准 ≠ 引擎可用**：`Math.sumPrecise` 已进 ES2026，Node 26 仍未实现。
- **引擎可用 ≠ 已成标准**：`using` 在 Node 24 可用，但属 ES2027。
- **支持矩阵随版本变化**：本篇数据锚定在 Node 24.13.1 / V8 13.6，升级 Node 后需重新核对。
- **部分特性需要启动标志**：`--js-base-64`、`--harmony-temporal`；标志形式会随版本变化。
- **"能用"还要看目标浏览器**：Node 支持不代表浏览器支持。
- **新版特性通常有等价的老写法**：`toSorted` 可以用 `[...arr].sort()` 替代，迁移不是非此即彼。
